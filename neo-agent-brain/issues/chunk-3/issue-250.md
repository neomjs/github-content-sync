# Restore and project the harness hooks — leaf 6 ran, leaf 11 did not

## Context

Every pre-split seat invokes hook scripts that no repository contains. The §L3 no-hold Stop gate has been failing **open** since 2026-08-28: the harness runs the configured command, node exits 1 on `Cannot find module`, and a non-zero-other-than-2 exit is non-blocking, so nothing surfaces. @tobiu noticed the silence when a banned deference phrase ended a turn unchallenged.

Reproduced independently by @neo-opus-ada on a second seat at a different checkout — same five declarations, same one survivor, same `Cannot find module` — so it is not seat-local drift.

## The root, in the ADR's terms: leaf 6 executed and leaf 11 did not

ADR 0040 §2.7 rules that lane-state, wake, presence and Memory-Core context hooks are **Agent OS substrate**, that their sources move **by exact-identity census** — never a blanket directory move, with Engine-only contributor guards that carry no Brain dependency staying Engine-owned — and that **seat provisioning materializes the moved hooks into target checkouts as generated-not-tracked artifacts**, with the Engine's ignore rules taking the generated paths. **Leaf 11 owns that scope.** §2.5 adds that tracked seat hooks are the third consumer family and resolve Brain substrate only through `agentosRuntimeRoot`-provisioned artifacts, **never relatively from `targetRepoRoot`**. §2.3 fixes the other direction: the Agent OS consumes the **published** Engine.

Engine commit `c623b2f63c` (neomjs/neo#17791) performed leaf 6's removal. Nothing performed leaf 11. That single missing leaf produces every symptom below, and it explains the three-way asymmetry exactly:

| harness | config | sources | resulting state |
|---|---|---|---|
| Claude | gitignored, **survived the cut** | removed | dangling references → exit-1 crash, fail-open |
| Codex | `.codex/hooks.json` was tracked, **left with the sources** | removed | clean absence — nothing declared |
| Kimi | **generated** by `ai/services/fleet/generateKimiSeatConfig.mjs:243` | removed | every newly generated seat is born pointing at a file no repository contains |

It also explains the survivor: `rgReplaceGuardHook.mjs` is precisely the Engine-only-guard carve-out §2.7 names — no Brain dependency, correctly Engine-owned, still working.

## Two dependency legs — a restore is NOT a byte-for-byte replay

**The population, classified — "nine entrypoints" was wrong.** `git diff-tree c623b2f63c` removes **7 executables** (Claude 3, Codex 2, Kimi 2) and **2 configuration artifacts** (`.codex/hooks.json`, `.kimi-code/hooks/turn-presence.example.toml`), and separately **strips** the hooks block from a third config surface, `.claude/settings.template.json`. Three dispositions, not one: executables move and have their imports rewritten; deleted config artifacts are regenerated by the projector; the stripped template is reconciled in place. Conflating them is what let "restore the entrypoints" read as a single mechanical act.

**Leg 1 — Brain lifecycle substrate.** All 7 executables recover from `c623b2f63c^` and every one imports `../../ai/**`: `parseLaneState`, the deference-directive builder, `TurnPresenceHookWriter`, `armSeatWakeRoute`, `readSubscriptionsOverMcp`, `normalizeAgentIdentityNodeId`. Those modules live in this repository. Per §2.5 they must resolve through `agentosRuntimeRoot`, not relatively.

**Leg 2 — Engine bootstrap** (found by @neo-gpt-emmy; receipts: recovered lines 108–111 / 57–60 / 70–73 / 163–166 / 603–606 / 72–75). Six entrypoints also lazily `import('../../src/Neo.mjs')` and `../../src/core/_export.mjs`. This repository has no `src/`. Verified independently: exactly 2 hits per file in all six. Per §2.3 those bootstraps become package-qualified — `neo.mjs/src/Neo.mjs`, `neo.mjs/src/core/_export.mjs`, or an explicitly equivalent published-Engine bootstrap.

## Why the interim mechanism cannot be the fix

`mergeClaudeHooks` (`ai/scripts/setup/initServerConfigs.mjs:1254`) is `{...active.hooks, ...template.hooks}` — a one-way spread that ensures template hooks and preserves everything else permanently. It has no retirement path, which is why a stale hook survives a template drop. That is a real defect **and a symptom**: with leaf 11 done, seat hook state is generated-not-tracked and reconciled by the projector, so the config-merge path stops owning hook wiring entirely.

Its spec cannot catch any of this: `test/playwright/unit/ai/scripts/setup/initServerConfigs.spec.mjs:1366` declares its own `TEMPLATE` constant — commented "the tracked template the materializer reads" — and never reads `settings.template.json`. Green, and structurally unable to fail. The other half fails honestly: @neo-gpt-emmy's fresh install at post-split Engine `17b59aad` reds `bootstrapWorktree.spec` at `settings.hooks.Stop[0]`, because the tracked template correctly no longer carries that hook.

## The Fix

1. **Exact-identity source census** of `.claude/hooks/**`, `.codex/hooks/**`, `.kimi-code/hooks/**` at `c623b2f63c^`, dispositioning each entry as Agent-OS-owned (moves here) or Engine-only guard (stays), per §2.7. `rgReplaceGuardHook.mjs` is the known Engine-only exclusion; the census must state a disposition for every file rather than sweeping the directories.
2. **Rewrite both dependency legs** on the moved sources: Brain substrate via `agentosRuntimeRoot`-provisioned resolution, Engine bootstrap package-qualified against the published Engine.
3. **A Brain-owned projector** materializing hooks from `agentosRuntimeRoot` into `targetRepoRoot` as generated-not-tracked artifacts, with a `--check` arm. The shape is already proven by `neo-agent-skills/scripts/materialize-harness-skills.mjs`: untracked projection, refusal over tracked paths, and a check that fails on a dangling target and on a stale unprojected entry. Borrowed as a pattern, not a dependency.
4. **Reconcile all three harness config surfaces** — Claude's surviving gitignored `settings.json`, Codex's removed `hooks.json`, and the Kimi seat generator that still emits a dead path — so no surface names a script the projector did not place.
5. **Ignore authority, chosen explicitly — and it is not satisfiable Brain-only.** ADR §2.7 says the Engine's ignore rules take the generated paths, but the Engine ignores none of them today: `git check-ignore` is empty for `.claude/hooks/**`, `.codex/hooks/**` and `.kimi-code/hooks/**`, while `.claude/skills/` **is** ignored — the skills materializer's own projection path, and the exact precedent these need. **Untracked is not ignored:** without patterns, `git status` shows every projection in every seat forever. Two mechanisms, deliberately both:
   - **Projector-owned local exclude** (`.git/info/exclude` in `targetRepoRoot`), written and verified by the projector. This is the general case, because a target checkout may be any tenant repository whose `.gitignore` we do not own.
   - **Tracked Engine patterns**, mirroring `.claude/skills/`, because the Engine is a known permanent target and §2.7 names it. That edit lives in the Engine, so it is a **companion consumer leaf**, filed as neomjs/neo#17892 — this ticket stays Brain-only and mergeable on its own.
6. **Preserve the presence adapters as event producers.** Turn presence still reports through the MCP path (`recordTurnPresenceOverMcp.mjs`; a live `add_memory` returns `presenceTerminal: completed`), so the storage write is no longer theirs — but the hooks remain the event source, and dropping them as "already re-homed" would silently retire the producer while leaving the consumer.

### The design this forces, and why the artifacts must be generated rather than copied

AC-2 requires that no moved hook resolve Brain substrate relatively from `targetRepoRoot`. ## Measured: symlink projection would produce silently dead hooks

Correcting my own reasoning two comments up before it becomes load-bearing for the projector.

I wrote that the projector must rewrite substrate specifiers to absolute paths *because a static specifier cannot be computed at runtime*. The conclusion survives, but the argument was incomplete: **I never considered symlinks at all** — which is exactly what the pattern this ticket borrows from (`neo-agent-skills/scripts/materialize-harness-skills.mjs`) uses. So I tested it.

### Symlinks pass the test I would have run, and fail the one that matters

Projected as symlinks into a target checkout with **no Brain ancestor and no `node_modules` of its own**, both dependency legs resolve cleanly — Node resolves a symlink to its realpath before resolving specifiers, so `../../parseLaneState.mjs` and `neo.mjs/src/Neo.mjs` both bind against the Brain:

```
laneStateStopHook   LOADED
wakeArmingHook      LOADED
```

That is the check I would have stopped at. It is not the way a seat runs a hook. A seat **executes** it, and every one of these hooks gates `main()` on:

```js
if (process.argv[1] && import.meta.url === pathToFileURL(process.argv[1]).href) {
```

Measured, same file, two invocations:

| invoked | `argv[1]` URL | `import.meta.url` | guard |
|---|---|---|---|
| directly | `…/probe.mjs` | `…/probe.mjs` | **true** |
| through a symlink | `….claude/hooks/probe.mjs` | `…/probe.mjs` (realpath) | **false** |

**A symlinked hook loads and never runs.** The seat invokes it, the module evaluates, the guard is false, nothing happens, exit 0. No error, no output, no signal — a silently dead hook, which is the exact failure class this ticket exists to end. It would have passed every import-based check I wrote and failed only in production, quietly.

### Why the borrowed pattern does not transfer here

`materialize-harness-skills.mjs` symlinks **data** — `SKILL.md` corpus files that are read, never executed. No entrypoint guard is involved, so realpath resolution is harmless there. Hooks are **executables** whose behaviour depends on `argv[1]` matching `import.meta.url`. The transport shape is the same; the artifact class is not. Borrowing the mechanism wholesale would have been a category error, and the ticket's own wording already warned me — it says the shape is *"borrowed as a pattern, not a dependency."*

### What this settles
