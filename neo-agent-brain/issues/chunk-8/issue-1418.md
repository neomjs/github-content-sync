# Add committed codeql-analysis.yml workflow for external fork PRs

## Context

## The Problem

Unlike `neomjs/neo` (which uses a committed `.github/workflows/codeql-analysis.yml` under GitHub CodeQL **Advanced Setup**, `id: 8120268`, where external fork PRs like `neomjs/neo#20191` queue under `action_required` and run `Analyze` when a maintainer clicks **"Approve and run"**), `neomjs/neo-agent-brain` was configured on `2026-10-10` with GitHub's UI-managed **CodeQL Default Setup** (`path: "dynamic/github-code-scanning/codeql"`, `id: 380165962`, `event: "dynamic"`).

By GitHub platform design, CodeQL **Default Setup** explicitly excludes pull requests originating from forks (`isCrossRepository: true`) and never queues a run when **"Approve and run"** is clicked. Combined with ruleset `Protect dev` (`#21247408`) requiring `code_scanning` (`CodeQL`), any external fork PR on `neomjs/neo-agent-brain` is permanently deadlocked.

Furthermore, `refs/heads/dev` on `neomjs/neo-agent-brain` currently stores three CodeQL analysis categories generated by Default Setup (`6f28d0c64f`):
- `category: "/language:javascript-typescript"` (`id: 2071124526`, `build-mode: none`)
- `category: "/language:actions"` (`id: 2071108391`, `build-mode: none`)
- `category: "/language:c-cpp"` (`id: 2071108572`, `build-mode: none`)

If an Advanced Setup workflow does not emit those exact category strings (`/language:${{ matrix.language }}`), GitHub Code Scanning marks the PR check neutral (`N configurations not found`) and blocks the ruleset.

## The Architectural Reality

- `.github/workflows/` in `neomjs/neo-agent-brain` enforces explicit minimal `permissions:` blocks across workflows (`#1408` / `35daa2f8`) to satisfy CodeQL's `actions/missing-workflow-permissions` rule.
- `neomjs/neo/.github/workflows/codeql-analysis.yml` provides the canonical precedent (`actions/checkout@v7`, `github/codeql-action/init@v4`, `github/codeql-action/analyze@v4` on `push: [dev]`, `pull_request: [dev]`, and `schedule`).
- Matching `refs/heads/dev`'s three existing category slugs (`/language:javascript-typescript`, `/language:actions`, `/language:c-cpp`) with `build-mode: none` prevents any `"configuration not found"` category mismatch during and after transition from Default Setup.

## The Fix

Add `.github/workflows/codeql-analysis.yml` to `neomjs/neo-agent-brain`:
1. Trigger on `push: branches: [dev]`, `pull_request: branches: [dev]`, and weekly `schedule: - cron: '24 9 * * 3'`.
2. Declare explicit top-level `permissions: contents: read` and job-level `permissions: actions: read, contents: read, security-events: write`.
3. Configure `strategy.matrix.language: ['javascript-typescript', 'actions', 'c-cpp']` with `build-mode: none` on `github/codeql-action/init@v4` and `category: "/language:${{ matrix.language }}"` on `github/codeql-action/analyze@v4`.
