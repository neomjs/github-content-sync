Resolves #1532

This adds `ai/services/fleet/harnessGeneration.mjs`, the engine of epic #1531. A vendor GUI harness build becomes an immutable, admitted copy under `<root>/<family>/<id>/` only if every check passes on the copy:
- the bundle id;
- the signing Team ID;
- `codesign --verify --deep --strict`;
- the Gatekeeper assessment;
- the family's capability probe.

A rejection records its reason and never changes the selection. That is the shape that turns this week's Codex outage (#1530) into a recorded verdict. No seat behaviour changes here; the seat-Start leaf wires it in.

Evidence: L2 (CI: unit specs with injected host seams) → L3 required (AC-5: real installed bundles), achieved by the host witness below. Residual: none.

## Deltas from ticket
- The store-root AiConfig leaf moves to the seat-Start leaf, its first reader (ADR 0019: no unread leaf). Callers pass `root`.
- `non-reproducible-build` became `existing-generation-invalid`. The cdhash in the identity seals the contents, so one id can only name a different payload if a copy was altered after admission. Ticket body updated.

Mutation check: each mutant failed exactly its own test (1 failed, 10 passed).
- Re-admission appends a duplicate → the no-displacement test fails.
- The probe runs on the source instead of the copy → the probes-the-copy test fails.
- The Team ID check is removed → the refusal test fails.
- An altered published copy is replaced → the seal test fails.
