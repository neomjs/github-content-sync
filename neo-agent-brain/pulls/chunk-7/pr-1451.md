Resolves #1440

🌿 *After this, no message is too old for recall to find.*

The WAL keeps only its retention window, but the graph keeps every message. `backfillMessageEmbeddings.mjs` walks the graph's `MESSAGE` nodes in send order and embeds each one the A2A message index lacks.
- **Same metadata as the drain.** Both mappers now share `toMessageEmbedMetadata`, so admission reads one shape whichever source wrote a row.
- **The collection is the cursor.** Ids it already holds are skipped, so an interrupted run resumes without a cursor file.
- **Dry run first.** By default the script writes nothing and projects the vector bytes, which the plane's sizing check reads before `--apply`.

A retraction now finds its record through the pending-embed reader, and marks it only while the record is still pending embed. Related: #35 (parent), #1439 (the drain), #1445 (the read surface).

Evidence: L2 (unit specs at `45c6ec5b`: graph↔WAL parity, the backfill over an in-memory graph and a fake collection, retraction) → L3 required (AC-5: the run inside the Memory Core container against the serving graph). Residual: AC5, Residual-Owner: #35.

## Deltas from ticket

The ticket was amended at intake, before code: no cursor file, and Fix 5 / AC-7 dropped under ADR 0019 B3. Beyond that:
- **Where the audience comes from.** The graph mapper reads it from the `DELIVERED_TO` edges, which `getMessage` admits by. The `SENT_TO` cohort stamp only separates a known-zero broadcast from a legacy one, so parity holds on repaired and unstamped messages too.
- **Maryam's two invariants from the #1450 review are now code.**
  - `admissionWhere`'s legacy branch requires `kind: 'broadcast'`, like its known-zero branch, and a spec pins that a direct row tagged legacy stays closed.
  - `queryMessages`' JSDoc states that recall never repairs a projection gap; `getMessage` stays the repair path.
