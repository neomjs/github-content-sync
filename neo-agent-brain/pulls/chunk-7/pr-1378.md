Resolves #1377

Every daily backup since 2026-10-29 failed its row-count parity. `JSON.stringify` leaves U+2028/U+2029 raw, and `readline` breaks a line at both, so one record read as two. `openBundlePayload` now passes the decoded payload through `escapeLineSeparators`, which hands readline both characters as their JSON escapes. Inside a JSON string those parse to the same value. Backup counts and restore read records whole again. Errors and teardown follow `decodeThrough`, so torn-file rejection and early close are unchanged.

Evidence: L2 (spec per encoding plus a chunk-straddling run, red on base and green at head; the readline split also measured in the plane's own Node) → L2 required for AC-1..AC-4, which are unit-suite properties. AC-5 needs the live plane after a cut and is listed under Post-Merge Validation. Residual: none.
