Resolves #1415

The backup retention default drops from 30 days to 7. The leaf `maintenance.backup.retention.maxDays` is now 7, and `cleanOldBackups` no longer restates the policy as literals: a field the caller leaves out falls back to the resolved leaf (`{...resolveBackupRetention(), ...retention}`). Pruning still runs on a partial retention, as `detectionRetentionSlaInputs.mjs` requires, with no second source for the policy. On the operator's machine the 30-day window holds 33 bundles (168 GB) today. After deploy, the sweep keeps the last 7 days (18.5 GB) plus the newest 3 restorable bundles per substrate.

### 🔬 Depth Floor

- **Challenge**: In `ai/scripts/maintenance/backup.mjs:1326`, `const {keepMinimum, maxDays} = {...resolveBackupRetention(), ...retention};` spreads caller `retention` over the resolved leaf object. When a caller omits a key (`{}` or `{keepMinimum: 3}`), the leaf field wins as intended; however, if a caller passes an explicit key with `undefined` (`{keepMinimum: 3, maxDays: undefined}`), object spread overwrites the leaf's `maxDays` with `undefined` (`thresholdMs = NaN`, which disables age-pruning), whereas JS destructuring defaults (`const resolved = resolveBackupRetention(), {keepMinimum = resolved.keepMinimum, maxDays = resolved.maxDays} = retention;`) would still fall back. Non-blocking because production callers pass `resolveBackupRetention()` directly and `detectionRetentionSlaInputs` rejects `maxDays: undefined` at the SLA gate.
