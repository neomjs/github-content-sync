Resolves #1488

`manage_discussion` gains `action: 'close'`, with a required `reason` of `RESOLVED`, `OUTDATED` or `DUPLICATE`. The behaviour:
- One read (`GET_DISCUSSION_CLOSE_TARGET`) resolves the discussion and the authenticated viewer before anything mutates.
- An already-closed discussion returns its state with `alreadyClosed: true` and no mutation.
- A caller who is not the author is refused with `FOREIGN_CLOSE_FORBIDDEN`, unless `acknowledgedForeignClose` states why. The stated reason is echoed in the result. This mirrors `IssueService#updateIssueBody`'s `acknowledgedForeignBody`.
- `body` stops being schema-required: `update_body` still requires it in the service.

Evidence: L2 (unit spec with a stubbed `GraphqlService`, plus the github-workflow listTools/handbook smoke and openapi validator specs) → L2 required (#1488's ACs are service-contract behaviour). A real GitHub close needs the deployed MCP server, so the first one happens in the neomjs/neo#20358 sweep.
