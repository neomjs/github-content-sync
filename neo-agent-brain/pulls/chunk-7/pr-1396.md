Resolves #1384

A bundle payload whose file fails to open now rejects at `endBundlePayload`, whenever the open fails. The compressing writer pipes its compressor into the file, the way the reader's `decodeThrough` already pipes the file into its decompressor, and `endBundlePayload` settles on the writer and on the file. Two failures go: a `.jsonl.br` or `.jsonl.gz` payload whose open failed late no longer reads as written, and an open that fails while the exporter awaits its next page no longer crashes the process with an unhandled `'error'`. `stream.compose` leaves the module.

Evidence: L2 (unit specs over the writer, with an injected late-failing open and a real missing directory) → L2 required: the writer is a pure Node module and every AC is a spec. Residual: none.

## Deltas from ticket

- AC-2 is new: the second failure was found while measuring the first, at the same boundary. The ticket body records both.
- The ticket said to keep `compose` for the data path. The measurement showed the composed duplex itself settles while its file is still opening, so the writer moved to the reader's pipe shape instead.
- `agent-preflight`'s block alignment realigned the module's imports (one name shorter) and one `const` block in `escapeLineSeparators`.

### 🔬 Depth Floor

**Challenge OR documented search (per guide §7.1):**

- **Challenge**: Non-blocking symmetry note between `decodeThrough` (`L181`) and `encodeThrough` (`L272`): in `decodeThrough`, `decompressor.on('close', () => file.destroy())` closes the underlying `ReadStream` if a caller aborts early; in `encodeThrough`, `file.on('error', error => compressor.destroy(error))` propagates file errors to the compressor, while normal completion flows through `.pipe(file)`'s default `{end: true}` into `endBundlePayload`. Because all callers terminate writers via `endBundlePayload(stream)` (never `stream.destroy()`), `file` always closes on normal end or file error; if a future caller ever aborts a compressed export mid-stream via `stream.destroy()` without calling `endBundlePayload`, adding `compressor.on('close', () => !file.closed && file.destroy())` would guard the file descriptor on caller-initiated abort as well.
