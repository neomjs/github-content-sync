Resolves #25

Backfill and tenant ingestion now consult the shared lease's original acquisition clock, including inherited leases. Backfill preserves committed rows; ingestion releases its owned lease and retains replayable input privately under the plane data root. A yield exits 75 with a machine-readable resume command. A returned or thrown batch failure exits 1 and retains the whole failed batch plus unread input. Replay uses the existing incremental diff, preserving chunk identities and skipping landed work.

Evidence: L2 (real temporary lease files, isolated SQLite/Chroma fixtures, actual expansion/diff/embed loop with a fake provider) → L2 required by the six fixture-based ACs. No live deployment or provider interruption is claimed.

### 🔬 Depth Floor

- **Challenge**: Two non-blocking edge behaviors worth noting for future callers:
  1. **Prior `parseError` lines before a subsequent batch yield (`ai/scripts/maintenance/ingestTenant.mjs:196-204`, `319-335`):** If an earlier line in the stream fails `JSON.parse` (`totals.parseErrors++`, `totals.errors.push(...)`), batch 1 flushes cleanly, and the run then yields before batch 2, `reportIngestOutcome` exits `75` (`status: 'yielded'`) with `parseErrors: 1` recorded on the yielded receipt while `retainIngestRemainder` writes only the remaining unread lines after the cursor into `input.jsonl`. A caller that resumes solely from `resumeCommand` without inspecting the yielded receipt's `errors` array will see the resumed run exit `0` because the malformed line was already consumed prior to the cursor.
  2. **Multi-`repoSlug` batch in `IngestionService.embedChunkGroups` (`ai/services/knowledge-base/IngestionService.mjs:626-650`):** When a single `ingestSourceFiles` batch spans multiple `repoSlug` groups and group 1 yields, the loop still invokes `vectorService.embed` for group 2 with `shouldYield` already `true`. Because `VectorService.embedChunks` gates `shouldYield()` on `batchIndex > 0` to guarantee forward progress per call, group 2 will still embed its first 50-chunk sub-batch before yielding its remainder into `unfinished`. Custody remains exact (unsettled records from both groups are retained), so this is non-blocking.
