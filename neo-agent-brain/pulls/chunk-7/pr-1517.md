Resolves #1495

Object output schemas now admit the structured error receipt `BaseServer#formatToolResult` emits, so an SDK client returns a `BODY_CHANGED` or `FOREIGN_BODY_FORBIDDEN` refusal as `isError: true` with its full metadata instead of throwing `-32602`. The new `withErrorReceipt` helper in `ai/mcp/validation/openApiValidator.mjs` keeps every declared property at the root (field types are still checked) and moves `required` into `anyOf: [{required: <success fields>}, {required: ['error']}]`, so a malformed success without an `error` key still fails.

Evidence: L1 (unit tier, stubbed SDK transport, no live server) → L1 required (AC-1 to AC-4). Residual: none.

## AC Evidence
| AC-1 | CI-covered: `test/playwright/unit/ai/mcp/validation/OutputSchemaErrorReceipt.spec.mjs` (both refusals through the generated listing, the real `formatToolResult` and the real SDK `listTools` → `callTool`) |
| AC-2 | CI-covered: `OutputSchemaErrorReceipt.spec.mjs` (complete success passes, malformed non-error success rejected) |
| AC-3 | CI-covered: `test/playwright/unit/ai/mcp/validation/OutputWrapperAgreement.spec.mjs` and `OpenApiValidatorCompliance.spec.mjs` unchanged and green (wrapper and composition listings untouched) |
| AC-4 | CI-covered: `OutputSchemaErrorReceipt.spec.mjs` (stubbed `Client#request`, no GitHub mutation or shared infrastructure) |

## Deltas from ticket
- Scope is object output schemas only. Wrapper (`result`) and composition listings are unchanged; compositions already declare their own error branches.
- `test/playwright/unit/ai/mcp/server/github-workflow/ToolRegistration.spec.mjs` pinned the old root `required` list of `update_issue_body`; updated to the new contract (the same fields as an `anyOf` branch next to `{required: ['error']}`).

## Test Evidence
Mutation check: with the validator change stashed, both refusal tests fail with the reported `-32602 Structured content does not match the tool's output schema`; restored, all 4 pass.
Environment: run locally on Windows x64 with `--no-deps` (the Chroma setup project rejects x64, and `better-sqlite3` needs the VC++ toolset). Other `ai/mcp` failures on this machine (symlink EPERM, `/bin/sh`, fsync, path separators) reproduce identically without this change.
