Resolves #1466

Support `x-neo-strict-input: true` (at the OpenAPI document or operation level, alongside `requestBodySchema.additionalProperties === false`) in `buildZodSchema` (`ai/mcp/validation/openApiValidator.mjs`) and enable `x-neo-strict-input: true` in `ai/mcp/server/github-workflow/openapi.yaml` so unknown or misspelled top-level tool arguments (such as `repository` instead of `repo` across all 22 `github-workflow` operations) fail fast at runtime with `unrecognized_keys` instead of being silently stripped onto the default repository, while preserving strip-at-boundary semantics on `knowledge-base` and `memory-core` operations that withhold internal/tenant authority fields (`tenantId`, `materializationAttempt`, `staleStrategy`, `viaMcp`, `custodian`, `depth`).

Evidence: L1 (unit-test suite verified locally across all 5 MCP server specs) → L1 required (AC-1, AC-2, AC-3).

| AC-2 | `test/playwright/unit/ai/mcp/validation/OpenApiValidatorCompliance.spec.mjs` (`every emitted input schema stays strict at the root` + `github-workflow: rejects unknown top-level alias keys (e.g. repository vs repo) with unrecognized_keys (#1466)`) |
| AC-3 | `test/playwright/unit/ai/mcp/validation/OpenApiValidatorCompliance.spec.mjs`, `test/playwright/unit/ai/services/graph/GoldenPathSynthesizer.spec.mjs`, `test/playwright/integration/KBCrossTenantIsolation.integration.spec.mjs` |

## Deltas from ticket
Scoped runtime `.strict()` root enforcement via `x-neo-strict-input: true` (enabled on `ai/mcp/server/github-workflow/openapi.yaml`) rather than flipping `strictRoot` unconditionally across `knowledge-base` and `memory-core`, where `KBCrossTenantIsolation.integration.spec.mjs` (`query_documents` / `ask_knowledge_base` stripping forged `tenantId`) and `GoldenPathSynthesizer.mjs` (`Memory_GraphService.getContextFrontier({ depth: 1 })` via `makeSafe`) intentionally rely on strip-at-boundary behavior when `additionalProperties: false` is omitted.

## Evolution
CI on `d19ec09f` surfaced two intentional strip-at-boundary contracts outside `github-workflow`: `KBCrossTenantIsolation.integration.spec.mjs` (which asserts `query_documents` and `ask_knowledge_base` strip a caller-supplied `tenantId` without returning `isError`) and `GoldenPathSynthesizer.mjs` (`Memory_GraphService.getContextFrontier({ depth: 1 })` routed through `makeSafe`). Scoping runtime `.strict()` via `x-neo-strict-input: true` on `ai/mcp/server/github-workflow/openapi.yaml` (plus `requestBodySchema.additionalProperties === false`) makes all 22 `github-workflow` operations (including `operation.parameters` GET tools) fail closed on unknown keys like `repository` while keeping `knowledge-base` and `memory-core` strip-at-boundary contracts intact.
