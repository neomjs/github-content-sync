Resolves #1466

Support `x-neo-strict-input: true` (at the OpenAPI document or operation level, alongside `requestBodySchema.additionalProperties === false`) in `buildZodSchema` (`ai/mcp/validation/openApiValidator.mjs`) and enable `x-neo-strict-input: true` in `ai/mcp/server/github-workflow/openapi.yaml` so unknown or misspelled top-level tool arguments (such as `repository` instead of `repo` across all 25 `github-workflow` operations) fail fast at runtime with `unrecognized_keys` instead of being silently stripped onto the default repository, while preserving strip-at-boundary semantics on `knowledge-base` and `memory-core` operations that withhold internal/tenant authority fields (`tenantId`, `materializationAttempt`, `staleStrategy`, `viaMcp`, `custodian`, `depth`).

Evidence: L1 (unit-test suite verified locally across all 5 MCP server specs) → L1 required (AC-1, AC-2, AC-3).

| AC-2 | `test/playwright/unit/ai/mcp/validation/OpenApiValidatorCompliance.spec.mjs` (`every emitted input schema stays strict at the root` + `github-workflow: rejects unknown top-level alias keys (e.g. repository vs repo) with unrecognized_keys (#1466)`) |
