Resolves #1253

A fresh seat can now ask the handoff what the business needs from it this week. The memory-core config base gains one declarative leaf, `businessFocusSourcePath` (env `NEO_BUSINESS_FOCUS_SOURCE_PATH`, empty by default, no plane membership), read once per pass by `GoldenPathSynthesizer` where it runs. When it is set, the new `ai/services/graph/businessFocusSection.mjs` reads the dashboard's first screen (the text before a `<!-- focus:end -->` marker, the whole file without one), binds it to the file's sha256 and the mirror's commit, upserts it as the first populated `BUSINESS_GOAL` node `business-goal-focus` (`publicFlag: false`, `claimClass: derived`, validated by the business schema), and renders `## Business focus` as the first level-two section of the handoff, ahead of `## Consolidation Gaps`, with the block's own headings demoted to bold lines so the splitter never sees a second `## `. A block over 1,200 bytes truncates nothing: the previous in-cap node stays, flagged `stale: over-cap` with the byte count and the source, and the section renders that previous block; with no previous node it renders `unknown` with the reason. An empty leaf writes no section and no node, with no error, so a deployment without a business dashboard is unchanged byte for byte. `sandmanHandoffSections` maps the heading to the `businessFocus` slug; the default read stays `['goldenPath']`, so the section is requested, never imposed.

Evidence: L2 (unit arms on the pure reader, renderer, node builder and splitter; the config lint with the parity snapshot updated in this commit) → L2 required (every close-target AC is a unit-visible contract). Residual: the deployment binding of the leaf to the business repository's tenant mirror, which no commit in this repository can deliver and which the ticket's Post-Merge Validation names with its owner, Residual-Owner: #123. The business repository's own byte-cap guard landed 2026-10-30 (business PR #23) and is no longer residual.

agent-preflight: `capability` → `feat`; the ticket-archaeology, block-alignment and PR-body gates ran on the staged files.

## Deltas from ticket
The leaf lives beside `focusV1ProjectionPath` in the memory-core config base, not under `orchestrator.*` in the Tier-1 base: the synthesizer reads the memory-core config where it runs, and the sibling projection leaf set the shape. The slug is `businessFocus`, because `focus` was taken by the shipped Focus (v1) section; the default read set is unchanged so other deployments never see a missing-section nag. The section is the first `## ` heading after the gap preamble rather than ahead of the gap audit: the preamble is the `gaps` slug by position, and a section before it would swallow the audit or break byte-exact reassembly. The first screen's end is a marker the writer owns; without it the whole file is the block and reports honestly. The ticket's AC list was amended at intake to these five; the business guard and the deployment binding moved to its Post-Merge Validation with owners.
