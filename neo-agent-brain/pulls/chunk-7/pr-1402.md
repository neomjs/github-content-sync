Resolves #1400

🌿 *A seat at work can no longer read as idle to every peer but itself.*

`who_is_online` rescues a mid-turn seat whose `add_memory` has aged out by its fresh turn-presence beacon, but the rescue only fired for the caller's own row. `TurnPresenceService.getFreshTurnPresence` found the newest active turn with an unscoped SQL read, then re-read the node through `GraphService.getNodeRecord`, whose RLS check hides a beacon from everyone but its writer (`recordTurnPresence` stamps `userId` and `sharedEntity: false`). The finder already holds the row, so `_findNewestActiveTurn` now returns its properties and the projection comes from that one read. The six projected fields are unchanged and the beacon's `note` stays in the service; `_getTurnPresenceProperties` remains the write path's own-row merge.

Evidence: L2 (unit specs on the real graph store, red on `dev` first) → L3 required for AC-5 only (a `who_is_online` reading on a plane running this head). Residual: AC-5, Residual-Owner: #31.

## Deltas from ticket
- The `who_is_online` spec's `seedBeacon` fixture wrote beacons with no owner key, so any reader could see them, and the existing rescue tests passed with the reader blind. It now stamps the key `recordTurnPresence` stamps; on `dev` that alone turns the mid-turn rescue test red.
- The class JSDoc said turn-presence records are "NOT the `who_is_online` liveness signal". It now names the rescue.
