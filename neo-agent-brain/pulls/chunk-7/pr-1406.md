Resolves #1405

🌿 *A ticket that quotes a line separator can no longer stall the knowledge base.*

`VectorService.embed` reads its JSONL through `openBundlePayload` (#1378), which hands readline U+2028 and U+2029 as their JSON escapes, and `closeBundlePayload` releases the file on every exit. The bare readline it replaces split any record quoting either character, and `JSON.parse` threw before `Loaded N knowledge chunks`. #1377's own body is such a record, so every `github-content-sync` embed on the plane has failed this way since 2026-10-30 18:51Z.

Evidence: L2 (unit spec, red on `dev` first) → L3 required for AC-2 only (a plane running this head). Residual: AC-2, Residual-Owner: #64.

Prescription checked: `ai/services/shared/bundlePayload.mjs` owns the concern. It is the shared reader that decides where a JSONL line ends; its bundle-scoped name is a question for the follow-up on the remaining readers, not a different owner.
