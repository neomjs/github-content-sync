Resolves #1441

Related: #133 · #1432

Turn rows written before turns stopped storing a document still hold their text twice: in the split metadata fields, and as the Chroma document that also feeds the full-text index. `ai/scripts/migrations/dropTurnDocuments.mjs` clears that document wherever `composeTurnDocumentText(metadata)` rebuilds it byte for byte. It keeps every row's vector, and `resolveTurnDocumentForRead` rebuilds the text on read.

The run is dry by default. `--apply` snapshots each batch to a flushed JSONL file before clearing it, `--restore` writes a snapshot back, and a rerun skips rows that are already empty.

Evidence: L3 (real Chroma: the run-scoped test server for the spec, and a scratch server for the entrypoint `main()` → `ChromaManager.getMemoryCollection()`) → L4 required (the operator's run against the plane and its byte measurement). Residual: the two Post-Merge Validation items below, Residual-Owner: #133.

## Deltas from ticket
- **A failed batch is read back before anything is decided.** AC-1 found that a request killed after it commits still errors on the client.
- **`--apply` requires an explicit `--snapshot` path.** The snapshot is about the size of the freed text, so the operator picks a disk with room; nothing defaults onto the plane's disk.
- **`main()` opens the collection through `ChromaManager.getMemoryCollection()`,** the Memory Core's own path: config, test-database guard, collection name. It does so lazily, so the spec never imports a connect-on-init singleton.
- **No `--host`/`--port` flags.** The `NEO_CHROMA_HOST`/`NEO_CHROMA_PORT` leaves already bind the endpoint (ADR 0019 §5).

### 🔬 Depth Floor

- **Challenge**: In `clearBatch` (`ai/scripts/migrations/dropTurnDocuments.mjs:115-128`), `const present = rows.filter(row => vectorOf.has(row.id))` checks key presence in `vectorOf` (`stored.ids`), rather than verifying `Array.isArray(vectorOf.get(row.id)) && vectorOf.get(row.id).length > 0` (and if `present` were ever empty, `fs.writeSync` would write a bare `'\n'` and `collection.update` would be called with empty arrays). In practice, every Chroma row in `neo-agent-memory` is written with a vector (and `openJsonlStream` ignores empty lines on restore), so this is non-blocking, but guarding `present` on a non-empty vector array (and returning `0` early if `!present.length`) is a cheap extra defense if this helper is ever reused on a partially-corrupted store.
