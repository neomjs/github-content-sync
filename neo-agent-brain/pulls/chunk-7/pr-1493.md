Resolves #1491

`update_issue_body` gains an optional `expectedBodySha256`, the SHA-256 hex of the body the caller read.
- **The check:** `IssueService#updateIssueBody` compares it against the live body it already reads for `byteDelta` and the authorship guard, so the check costs no extra request.
- **On a mismatch:** the call refuses with `BODY_CHANGED` and `currentBodySha256`, and sends no mutation.
- **On a match:** the body is written, and the result carries `bodySha256` for the next guarded write.
- **On an unusable value:** a supplied hash that is blank, not 64 hex characters, or not a string is refused with `INVALID_EXPECTED_BODY_SHA256` before any GitHub request.
- **Without the field:** nothing changes, and the result carries no hash. Only omission keeps a write unconditional.

It closes the silent lost update on shared tracker bodies: four seats ticked rows on neomjs/neo#20358 within half an hour today. GitHub's mutation takes no precondition, so this narrows the window to the gap between the service's read and its write rather than closing it. The ticket and the tool description both say so.

Evidence: L2 (unit spec with a stubbed `GraphqlService`, plus the github-workflow listTools/handbook smoke and openapi validator specs) → L2 required (#1491's ACs are service-contract behaviour).

## Deltas from ticket
- `bodySha256` is returned only for guarded writes. Returning it always would change every existing result shape, against AC-3.
- The expected hash is trimmed and compared case-insensitively, with its own case.
- A supplied hash opts in to the guard, so an unusable one is refused (`INVALID_EXPECTED_BODY_SHA256`) instead of being read as omitted (review RA-1).
- The `update_issue_body` description is 966 characters, under the 1,024 cap; it was 1,105 on `dev` before this PR (review RA-2).
- Prescription checked: `ai/services/github-workflow/IssueService.mjs` owns the concern. The read the guard needs already happens there, before the mutation.
