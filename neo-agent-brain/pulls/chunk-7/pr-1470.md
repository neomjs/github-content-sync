Resolves #216

`resolveServiceScopes()` in `ai/scripts/maintenance/migrateDeployment.mjs` now derives each service's scope from the target Compose profile's per-service `environment` placement (`collectComposeEnvironment` from `ai/scripts/lint/lint-config-template-ssot.mjs`) backed by the profile's declared config templates, rather than attributing every inherited `ai/configBase.mjs` leaf to every service.

## Deltas from ticket
- Reused `collectComposeEnvironment` from `ai/scripts/lint/lint-config-template-ssot.mjs` on the target Compose profile (`deploy/cloud/docker-compose.yml`) rather than introducing a second static per-service list in `config-leaf-parity.json`. This also closes three false negatives on `orchestrator` (`NEO_HANDOFF_FILE_PATH`, `NEO_MEMORY_DB_PATH`, `NEO_MEMORY_WAL_DIR`), which live in `ai/mcp/server/memory-core/config.template.mjs` and were previously omitted from `orchestrator`'s scope when `resolveServiceScopes()` only inspected `ai/config.template.mjs`.
