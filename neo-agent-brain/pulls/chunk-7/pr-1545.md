Resolves #1542
Related: #1531

Generalizes `System Events` numeric `application process id` (`targetAutomationId`) wake targeting from `addressedCodex` to every `osascript` GUI wake and lifecycle resume with a resolved `instancePid` (`Antigravity`, `Claude`, `Codex`, `OpenCode`) via a shared `processAutomationIdLines` helper across `ai/daemons/wake/localWakeAdapters.mjs`, `ai/daemons/wake/daemon.mjs`, and `ai/scripts/lifecycle/resumeHarness.mjs`, removing LaunchServices `tell application "<appName>" to activate`, `id of application "<appName>"`, bundle-ID frontmost fallback, and `first application process whose unix id is <pid>` name-aliasing (`43104 -> 39747` on multi-instance `Antigravity`; `34587 -> 59823` on multi-instance `Claude`), and clarifies `GUI_WAKE_DISPATCH` JSDoc in `ai/services/fleet/armFleetSeatWake.mjs`.

Why the prior `activate`-first comment in `daemon.mjs` is retired: that comment recorded that `set frontmost` alone lost to a frontmost same-bundle sibling, which was measured when the script targeted `first application process whose unix id is <pid>` — a filtered specifier that AppleScript serializes by name and aliases back to the first instance (`#1372` subsequently proved that `set frontmost of application process id targetAutomationId to true` raises the intended Codex instance without `tell application "<appName>" to activate`).

Evidence: L3 (live-host read-only `System Events` multi-instance aliasing probe + `osacompile` compilation + Playwright mock-dispatch unit suites) → L4 required (live Electron background-sibling raise under the merged receiver). Residual: live addressed Antigravity background-sibling raise, Residual-Owner: #1531.
