Resolves #1498

A logs read now returns the log text without Docker's stream frame headers. A container without a TTY sends `/containers/{id}/logs` multiplexed: each write carries an 8-byte header (stream byte, three zero bytes, big-endian size). `readTargetLogs` used to decode the whole body as one UTF-8 string, so the deployment snapshot published those headers as text.

The change has three parts:
- `dockerSocketRequest` gains an opt-in `binary` flag. Every other caller still gets text.
- `readTargetLogs` asks for bytes.
- A pure helper (`dockerLogStream.mjs`) cuts the frames before decoding, with one `StringDecoder` per stream. The response's declared framing decides: `Content-Type` multiplexed-stream, or raw-stream from API 1.42. Only an undeclared response falls back to the byte chain, so a declared raw TTY stream keeps every byte even when it looks framed. A stream-3 frame (a daemon error sent after HTTP 200) fails the read with the daemon's message. A string body, which the injected test seams return, passes through.

Evidence: L2 (unit: the real `dockerSocketRequest` against a fake Docker socket, red on base and green at head) → L2 required for AC-1/AC-2. Residual: AC-3 is the deployed snapshot, under Post-Merge Validation.
