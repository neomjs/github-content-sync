Resolves #128

New turns now reach Chroma once. The embed drain embeds each WAL turn explicitly and adds it as `{ids, embeddings, metadatas}`, without the derived document. A turn no longer stores its text twice, and no longer feeds Chroma's full-text index a third copy. Every path that copies, imports, heals or audits a memory row now accepts a turn with no stored document, and keeps it that way. Existing rows and the measured reclaim are #1441.

Evidence: L3 (a real Chroma in the unit suite and in `integration-unified`) → L3 required (AC-1, AC-3). Residual: none on this ticket; the live-store migration and its byte measurements are #1441.

## Deltas from ticket

- **Only a turn goes without its document.** #1443, merged into `dev` while this PR was open, sends A2A messages through the same drain. A message's document (subject and body) is its content, so the drain now drops a document only when `metadata.type === 'agent-interaction'`. A message keeps its document, and is embedded explicitly like everything else.
- **`CollectionProxy.embed` is new.** `StorageRouter.getMemoryCollection()` always returns the proxy, and the proxy had no `embed`. It now delegates to its primary collection, as `get()` does. Without it no turn would have reached the store; the full unit suite caught that.
- **Collection doubles now provide `embed`.** Four Memory Core specs stub the memory collection with an `add`-only spy. In the `WriteAhead` attribution test, the provider event is now recorded in `embed`, because that is where the provider call now happens.
- **The repair extractor carries the stored document.** `extractMemoryCoreCollectionData` now passes the stored document through (`null` when absent), never a reconstruction. Before this change, a heal or a defrag repair would have written the reconstruction back as a stored document.
- **The integrity probe counts a reconstructable turn as recoverable**, which means all three split fields are present, not just the turn type. The recovery classifier uses this probe to tell a WAL stall from a wipe, so a gutted turn row now routes to re-embed rather than restore.
- **The quarantine export needed no change.** It already writes `document: null`.
- **The real-Chroma witness is new.** `drainCycle.realChroma.spec.mjs` runs in the unit suite against its run-scoped Chroma. It complements the integration suite AC-3 names.
- **Out of scope, noted in a defect-note:** `importDatabase({reEmbed: true})` deletes each record's vector but still passes `embeddings: [undefined…]`. chromadb 3.5.0 rejects that, so the mode imports nothing. This PR leaves it as it was.
