Resolves #1003

Pending Neural Link calls now distinguish explicit loss from an ordinary timeout. An App disconnect rejects only that session's calls with `NEURAL_LINK_TARGET_DISCONNECTED` and `sessionId`; closing a Bridge socket rejects its calls with `NEURAL_LINK_BRIDGE_CLOSED`. Replies, deadlines and both loss paths share one settlement method that removes the entry and clears its timer before notifying the caller. Each entry records its sending socket, so a delayed close cannot clear a replacement connection or cancel its calls.

The stable fields belong to `ConnectionService.call()` rejections. The existing MCP envelope forwards the error message only; structured tool-error forwarding needs its own concrete consumer.

Evidence: L2 (real service handlers and isolated loopback WebSocket close events in tests) → L2 required (the ticket's handler-path controls). No residual close-target checks. These errors report client-side loss, not renderer-side cancellation.

Each pending entry additionally retains its socket identity. This is necessary to scope cleanup when a retired socket closes after a replacement connects; it changes no reconnect policy or wire format. No configuration leaves or standalone helper module were added.
