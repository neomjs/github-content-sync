Resolves #1183

🌿 A recovered seat's saved app path can no longer vanish on its way to the helper cleanup.

#1172's recovery read the saved Start's `launchCommand` as an array (`Array.isArray(start.launchCommand) ? start.launchCommand[0] : null`), but the seat runtime record stores it as one absolute path (`isSeatRuntimeRecord` requires `absolute(value.launchCommand)`). The recovered record got `null`, `probeCrashpadExecutable(null)` found no helper, and Emmy's Start on the c25e1015 FM refused 0.85 s after reserving admission (11:40:57Z). Maryam traced it (A2A 11:47Z). The recovery now takes `start.launchCommand` as the codec gives it. #1172's arm passed only because its hand-made saved Start used an array, a shape the codec never produces; the arm now uses the record's own shape (string `launchCommand`, separate `profileArg`), and its probe stub finds the helper only from the saved app path.

Evidence: L2 (unit, recovery from a codec-shaped saved Start through the next Start) → L3 required (AC-3, Emmy's Start). Residual: AC-3, the next FM candidate. Residual-Owner: neomjs/neo-agent-institution#736.
