Resolves #1018

This adds `ai/scripts/migrations/attributePreIdentityMemories.mjs`, which attributes a returning agent's pre-identity raw memories to it on recorded evidence only. Those are the rows with `userId: 'shared'` and no `agentIdentity`. The operator names the identity, its aliases and its harness markers. A row is attributed when a marker opens its prompt at the trusted envelope prefix, or a wake header there addresses the identity. It is also attributed when it shares a session with such a row or with one already attributed to the identity. A session beside another identity stays shared as a whole. Each re-keyed Chroma row journals its rule, its evidence and the graph state it replaced. So a re-run completes an interrupted apply, and `--reverse` restores the prior state. The default is a dry run, and writes require `--offline`.

Evidence: L3 (unit specs through the real `MemoryService` read paths, plus a read-only dry run against the plane's Chroma) → L4 required for AC-2 and AC-7 (the operator's `--apply` on the canonical plane, then the bearer's review). Both run on the approved head before the merge, so nothing is left owed after it.

## Deltas from ticket
- The rules are generic, through `--identity`, `--alias` and `--harness` (intake 6194216448). The Gemini mapping is the operator's invocation, not repository code.
- The envelope prefix admits one wrapper, the Gemini CLI's `<session_context>` line, which real rows open with from 2026-03. Behind any other tag, a marker or wake header is quoted content.
- A row whose `sessionId` is absent, empty or blank carries only its own evidence.
- The inputs, refusals, write order and recovery are the [Contract Ledger on #1018](https://github.com/neomjs/neo-agent-brain/issues/1018#issuecomment-6199487027).
- A dry run plans from Chroma alone and opens the graph only for a write. On the canonical local plane, the graph file sits in a Docker volume that a host dry run cannot reach.

## Test Evidence
- **Mutations, 5/5 killed against the spec:** the envelope ignored, conflicts ignored, the graph pass skipping the journal, the reverse skipping its graph restore, and `userId` left un-re-keyed. Each turns at least one spec red, and the tree was clean afterwards.
- **Round-1 arms, red first:** against `10526b75`'s module, the `<example>` / `<blockquote>` wrappers around a marker and a wake, and the empty-session rows, turn both specs red (2 failed). At `1de6e8ac` all pass.

There were 0 conflicts. 6,552 rows in 770 sessions stay shared for lack of evidence. No founding-era wake matched the current wake header. Refreshed at `1de6e8ac`, every count is unchanged: both fixes only narrow the evidence, and with no conflict to unmask, the attributed set is the same.
- **Reviewed sample of 12, spread from 2025-11-02 to 2026-03-09:** every row is a Gemini CLI session start, or an operator turn inside a session one opened. No false attribution was found.
