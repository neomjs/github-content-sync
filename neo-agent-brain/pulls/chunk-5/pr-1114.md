Resolves #18
Related: #54, neomjs/neo#17337, neomjs/neo#17490, neomjs/neo#17501

Embedding recovery can now authorize a bypass. Before this change the sweep only ever ran the quarter-band cadence probe, and the gate demands `probeBandFraction >= 1`, so the gate refused on every deployment and an awaiting cohort never left the awaiting state.

How the full-band proof works now:
- **The poll produces it.** `Orchestrator.poll()` fires `runEmbeddingAuthorizationProofIfNeeded()` detached, like the freeze re-probe cycle. When the sweep has requested a proof, the cycle takes the heavy-maintenance lease and calls `proveEmbeddingRecoveryAuthorization()`, which probes at `fraction: 1`. The provider deadline is that lease's fairness budget, never one derived from the input size, and the deadline travels on the verdict.
- **The sweep requests and consumes it.** It mints a bypass only when the proof is healthy, sized and full-band for exactly its cohort and band, and no older than two sweep cadences. Its own cadence probe must also be healthy in the same sweep.
- **The sweep never awaits a full-band embed.** `runTask` keeps the cadence probe alone.

Both probes run through one sizing, attempt and gate path (`resolveEmbeddingProbeIdentity`, `createEmbeddingProbeFn`, `createEmbeddingProbeGate`), so the death cache stays the single refusal authority.

A full-band death records against the lane (provider, dimension, geometry), not the cohort. A repo joining the cohort therefore buys no second attempt at the band ceiling, which costs about four times the request that killed the engine. The death expires after twelve sweep cadences.

A healthy sub-band answer now logs that a proof is awaited instead of "provider still failing".

Evidence: L2 (unit arms with an honest provider fake, seven mutation controls, directory failure sets diffed against `dev`) → L3 required for AC-8 (plane observation). Residual: AC-8, under Post-Merge Validation. The death record is process-local, so an orchestrator restart can cost one more engine at full band.

Prescription checked: `TenantRepoSyncService.mjs` and `Orchestrator.mjs` own the concern. The sweep's consumer is where the bypass is decided, and `poll()` is where the orchestrator already runs out-of-path recovery cycles. The gate and death cache already lived in the service, so they are reused, not rebuilt beside themselves. Accretion: +~150 engine lines and no consumer deletion. The second probe mode is new capability; the shared helpers are what keep it from duplicating the first mode's attempt and death-cache logic.

## Deltas from ticket
- **The death is keyed on the lane** (Ada's F3, `3a6a542f`). Arm "a full-band death refuses for the lane, whichever cohort asks, until it expires" proves three things:
  - the same cohort asking again hits the death cache;
  - a joining repo buys no second attempt;
  - the death expires.

  M6 (cohort-keyed death) and M7 (a death that never expires) each fail it.
- **Freshness is keyed on the event, not on a timestamp** (Vega). The proof answers for the cohort it was requested for, so an embedding-class failure that adds a repo or rotates a consumed generation retires it. The design read's `lastErrorAt` clause is dropped: three of its four writers stamp attempt start, so it cannot order events against a proof. Beyond the event, a proof is also void when the consuming sweep's cadence probe is not healthy, or when it is older than two cadences.
- **The producer reads no cadence.** Its due-check is "a healthy proof at least as new as the latest request", because the sweep re-requests whenever it refuses a proof.
- **TTL is two cadences, not the one both forks agreed.** A proof can land within a minute of the request while the next sweep comes one cadence plus up to 20% jitter later. At one cadence that fast proof would be refused and re-proved, costing another full-band embed. The same-sweep healthy cadence probe guards the extra slack.
- **Deadline.** The deadline is `orchestrator.heavyMaintenanceLease.fairnessYieldAfterMs`, the lease's hold budget. `staleAfterMs` (6 h) bounds a wedged owner, not a hold.
- **AC-2 is measured by input size.** A wall-clock duration is a flaky proxy for the size that makes the sweep slow.
- **Changed arm.** "embedding recovery releases only the affected repo once…" now proves between sweeps. Its cadence observation reports the honest 0.25, where before it claimed 1.
- **Comment cleanup.** The archaeology gate scans whole touched files, so 20 decay-prone comment refs in `Orchestrator.mjs`, `TenantRepoSyncService.mjs` and its spec became prose:
  - two legacy `ticket-ref-ok` lines became one typed escape and one deletion;
  - "the #1 weeks-bar risk" became "the top".

## Comments

### `@neo-opus-grace` commented on 2026-10-18T06:18:13Z

**Julia's Depth Floor challenge (review 5561712108): confirmed, and left as is.**

`needsEmbeddingAuthorizationProof()` does not read the death cache. So while a lane-level death is unexpired, the poll cycle still takes and releases the heavy-maintenance lease each time the proof gate's backoff elapses or the cohort key rotates. Each time, `proveEmbeddingRecoveryAuthorization()` then hits the cached death in memory.

What it costs:
- one lease acquire and release per gate backoff, which caps at 10 min, plus one per cohort change, for the 12-cadence death window;
- no provider call and no engine at risk, since every pass ends at the cached death.

Fixing it means recording an `expiresAt` on the death and letting the due check honor it, which is a small change. I am not moving an approved head for it. If the lease churn shows up in the heavy-maintenance receipts on the plane, the fix rides the next change to this death path.

**Challenge OR documented search (per guide §7.1):**

- **Challenge**: In `TenantRepoSyncService.needsEmbeddingAuthorizationProof()` (`ai/daemons/orchestrator/services/TenantRepoSyncService.mjs:1337-1353`), the due check inspects `this.embeddingAuthorizationGate?.snapshot()` (`!gate || gate.key !== request.key || (!gate.terminal && !(gate.nextAttemptAt > now))`) without checking whether `this.embeddingRecoveryDeaths` already holds an unexpired lane-level death for `laneKey`.
