Resolves #1094

`npm run ai:pin-drift` answers two questions for any consumer checkout: which engine it runs, and which engine commits since its pin touch the files it loads. Fixes print first. Each one carries the chain from the touched file to the consumer file that reaches it, so a reader can see whether it matters. `--module <path>` asks the narrower question for a single file, loaded or not: is the behaviour I am about to work around already fixed upstream?

Evidence: L3 (live runs on the Brain, neo-stage and Institution checkouts against neo `origin/dev` at `e0704c93bb`) → L3 required (AC-6 and AC-7 name live checkouts). Residual: none.

- A missing `--ref` fails with the fetch command, as a missing pin does.

### 🔬 Depth Floor

- **Challenge**: Non-blocking observations on `scanImports` (`ai/scripts/diagnostics/pinDrift.mjs:55-82`) answering your review-request question on statement-start regexes vs. `import()` sites after inspecting the 3 engine files flagged in `.closure.unfollowed` on Brain (`src/data/Store.mjs`, `src/component/Base.mjs`, `src/container/Base.mjs`):
  1. **Inline bundler comments and no-substitution template literals inside `import(...)`:** `src/data/Store.mjs:1245` (`import(/* webpackIgnore: true */ 'fs/promises')`) and `src/component/Base.mjs:825` (`import(`../../src/plugin/Responsive.mjs`)`) are counted as `computedEngine` because `LITERAL_IMPORT` (`/\bimport\(\s*(['"])(.+?)\1\s*\)/g`) and `COMPUTED_IMPORT` (`/\bimport\(\s*(?!['"\s)])/g`) do not allow optional inline block comments (`(?:\s|\/\*[\s\S]*?\*\/)*`) or backtick strings without `${`.
  2. **Dynamic `import(...)` inside JSDoc comments:** Unlike `STATIC_IMPORT` and `BARE_IMPORT` (which anchor to `^[ \t]*` and therefore skip ` * import ...` JSDoc lines), `LITERAL_IMPORT` and `COMPUTED_IMPORT` match anywhere on a line. Once Brain's engine pin advances past `7f16355a` to include `src/container/Base.mjs:656` (`* A lazy config (\`{module: () => import('...')}\`)`), `LITERAL_IMPORT` will match `import('...')` inside that JSDoc line unless comment lines (`^[ \t]*(?:\*|\/\/)`) are stripped or skipped before dynamic-import scanning. Neither affects the current closure or ACs, and erring toward surfacing `computed` counts is the right trade for a zero-dependency relevance filter.
