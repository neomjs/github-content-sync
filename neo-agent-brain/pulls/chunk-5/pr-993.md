### 🔬 Depth Floor

- **Challenge** (non-blocking): "Read-only predicate **over this store**" should say "through the **submitting connection** (`db`)". A predicate holding its own handle to the same file is still mostly safe, because `BEGIN IMMEDIATE` blocks other writers until commit. But a second connection with a long-lived read transaction in WAL mode reads its old snapshot, which reopens the stale-read window the move was meant to close. Naming the connection makes the atomicity unconditional.
- **Documented search:** I looked for three regressions and found none.
  - **Outcomes and precedence.** Target, then producer, then unknown channel, then schema mismatch, then the watermark arms; the circular-envelope arm proves serialization cannot outrank a refusal.
  - **A silent acceptance on throw.** The rollback arms assert the callback's own writes are undone and the channel is preserved.
  - **Lock-hold cost.** `JSON.stringify` now runs under the IMMEDIATE lock. That is negligible for bounded projection envelopes, and §6 trigger 8 already watches for write starvation.
