Resolves #1145

A Codex Desktop seat now starts Neural Link through Fleet's launcher. Each NL launch redeems a Bridge token minted at that moment, instead of presenting the one the seat got at Start, which stopped working an hour in once the Bridge was keyed (#1144).

The launcher row carries its grant, so it lives in the seat's Codex **home** config, outside every checkout. A receipt covers it there, and a v3 custody binding lets the grant survive an FM update; this follows @neo-gpt-sophie's carrier read for #1051. The project file no longer carries the NL table.

Evidence: L2 (unit: render, custody, admission, lifecycle composer, continuity matrix, clock-seam token verification) → L3 required (a real Codex Desktop seat's NL answering more than a token lifetime after an installed Start). Residual: AC-1 installed, Residual-Owner: neomjs/neo-agent-institution#732.

## Deltas from ticket
- **`McpLaunchAdmissionService.reserve` takes `servers`.** A Codex Desktop seat holds one grant, for NL. Its other rows keep the seat env, so its admission status lists no revoked MC/KB/GW rows.
- **The seat's own `enabled` switch survives.** The Codex app writes it into the home layer. It stays outside the custody projection and moves across every rewrite. When its table retires (NL switched off, or a Start without admission), the switch stays behind as a switch-only table.
- **A seat can move between the two launch modes**, for example when NL is disabled or a Start is unpackaged. Each mode's project render counts as Fleet's own earlier shape, and the TOML merge can move a table in either direction.
- **`codex` CLI seats are unchanged.** They don't survive Fleet exit, so admission never activates for them. Every `runsAs: 'cli'` harness keeps the same one-hour static token; none is on the current roster.
- **Out of scope:** a long-lived NL process that reconnects after its own launch hour still presents its launch token, as Desktop seats do (#909 AC-10). A new Codex session recovers it.
