Resolves #1158

`FleetLifecycleService.spec` now hands the singleton back after its last test. Before this, the next spec file in the worker read the stubs that test left behind. The issuer stub has no `revocationMark`, and `FleetManager.startAgent` calls it, so `onboardPeer.spec:553` went red whenever CI put the two files in one worker.

`install()`'s 27 seams are one object (`testSeams`). Their originals are read off its keys before the first test, and a file-level `afterAll` assigns them back, together with the two `McpLaunchAdmissionService` fields. The change is spec-only.

Evidence: L2 (unit: the two-file run in one worker, red on `origin/dev`, green at head, plus a mutation check) → L2 required.
