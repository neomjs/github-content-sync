Resolves #1143

The FM's continuity handoff no longer refuses the whole update when a surviving seat cannot prove something; it revokes only what that seat cannot prove.
- **A server that cannot prove** loses only its grant.
- **A seat that cannot prove its original Start** loses its generation and is carried unresolved, with its runtime retained.
- **A stale generation** crosses as stale.
- **Still refused:** a pending Start, a legacy seat, and every issuer-level stage.

The change has two parts:
- **`McpLaunchAdmissionService.revokeServerGrant(agentId, key, reason, {generation})`** ends one server's launch admission inside an active generation. It is bound to the generation it names, as `revoke(..., {generation})` is, so a newer Start is never hit. It persists before it returns.
- **`FleetLifecycleService.handoffRuntimeCustody`** computes each seat's verdict in a new private `verifySurvivor` and applies the revocations outside it. A lost durable write therefore still refuses the handoff.

Decision authority: the ADR 0034 §2.5 item 4 amendment, neomjs/neo#19858 (for neomjs/neo#19857). **It merges first.**

Evidence: L2 (unit: the AC-1–3 arms fail on `dev` and pass at head; the AC-4 arms pass on both) → L2 required (AC-1–4). Residual: none.

## Deltas from ticket

The late-proof control extends "the checks after the proof decide…": a handoff revocation that lands while a redemption's proof runs refuses that redemption.
- **Every revocation reuses an existing reason**, so `LAUNCH_ADMISSION_REASONS` is unchanged. `credential-missing` covers a missing credential or resident input; `recovery-unverified` covers a failed proof or an unprovable seat.
