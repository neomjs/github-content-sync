Resolves #1075

The Neural Link's session namespace stays shared by design; what a peer joining a shared app instance lacked was knowing whose scene it is. The Bridge now records who addressed each App (first, last, per agent) in the `appState` it already keeps, tells every Agent with an `app_addressed` frame, and replays the snapshot on `app_connected` to an Agent joining later. The per-seat server folds that into its session rows: `healthcheck().sessions[]` names the app (`appName`, `environment`, `userAgent`, `isSharedWorker`) and its addressers (`firstAddressedBy`, `lastAddressedBy`, `addressedBy`, `addressedByMe`), and the auto-target refusal lists each live session with its app and last addresser so a caller can pick in the same turn. Nothing refuses and nothing is removed; the consumer saved is the second `healthcheck` call and the guess after a refusal — the shape of what happened on the avatar lab on 2026-10-16 (neo-stage#93 receipt 6226483181; Grace picked a session from a list that said nothing).

Evidence: L2 (unit: the Bridge, ConnectionService and resolveCallTarget specs, CI runs the tier) → L3 required (AC-5: two seats' servers against one live bridge, which needs the merged Bridge installed). Residual: AC-5, Residual-Owner: #144.

## Deltas from ticket
`isSharedWorker` joins the row beside `environment` and `userAgent` (the register message carries it; same cost). The `app_connected` frame broadcast at connect carries `addressed: null` so both shapes of the frame agree. `describeSessions()` is the service's one row shape for the resolver; `getStatus()` builds the fuller row. `BRIDGE_PROTOCOL_FEATURES` is not bumped: the frame is additive — a stale Bridge yields rows without addressers, and a newer Bridge is read by an older server without harm.
