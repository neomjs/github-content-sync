Resolves #1077

The Fleet now keeps a GUI seat's window where the operator left it. `stop(id)` and the adopted-seat stop read the seat's front window by pid through one System Events query before the signal and write `.neo-fleet-window.json` beside the seat lease; `start(id)` waits for the new window, keeps it when the harness restored it itself, places it once otherwise, reads the frame back, and reports `windowPlacement {state, requested, observed, reason, at}` on the lifecycle row. Nothing is written into a vendor's own state files; every host effect is an injectable seam in the new `ai/services/fleet/seatWindowRect.mjs`.

Evidence: L2 (unit arms with injected window seams; the osascript adapter is exercised only through fakes, never against a host window) → L4 required (AC-5: the installed Stop fleet → Start fleet cycle with all seats). Residual: AC-5, Residual-Owner: #1074 (its AC-4 is the same Stop fleet → Start fleet cycle on the same walk).

## Deltas from ticket
- The host seam is a sibling module, `ai/services/fleet/seatWindowRect.mjs`, not `hostEffects.mjs`: that module is the first run's effects writer (its own receipt contract), while this seam is a lifecycle read/set by pid. The structure map's `ai/services/fleet` owner is unchanged.
- An internal cleanup stop (`cancelPending: false` — a failed lease or Start) captures nothing: no window was placed yet, and the failed-start stop keeps its synchronous signal (the lease-failure arm asserts it).
- The GUI gate is the lease's own predicate (`keepsWindowRect`: an `instanceHome` and an app-bundle harness type), read from the record so an adopted seat qualifies; the record is written whether or not a lease exists (intake input on the ticket).
- Two states beside the ticket's four: `none` (no record yet) and `pending` (the window not yet seen); `windowPlatform` is a plain-field test seam so the `unsupported` arm runs on macOS.

## Test Evidence
The System Events read and set were not exercised live on this host: a first `osascript` call from this seat would raise a TCC prompt on the operator's screen during his release session, and the production path runs inside the Neo Harness app, which already holds the grant the wake adapter's dialog gate uses. AC-5 is that live proof. Everything else runs in CI.
