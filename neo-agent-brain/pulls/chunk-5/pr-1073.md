Resolves #1072

The Neural Link server now delivers declared image artifacts as MCP image content. An artifact is a plain object with an image `mimeType` (png, jpeg, webp or gif) and base64 `data`, the way a draw receipt carries its frame. Its bytes go into an image block after the JSON text block, and the JSON keeps the artifact's other fields plus a `contentIndex` pointer. A model therefore sees the frame in the answer to the call that produced it. Results without artifacts, and every error, format exactly as `BaseServer` formats them. The walk lives in a pure helper, `imageContent.mjs`, a sibling of `verifyBridgeToken.mjs`. `Server.formatToolResult` delegates to it in one line.

Evidence: L3 (a Neural Link MCP server built from this branch answered a live Stage `waitForSceneDraw` with `[text, image, image]`; witness comment below) → L3 required (AC-5). Residual: none.

## Deltas from ticket
- No depth or image-count cap. The walk visits each node once, as `JSON.stringify` already does, and a cap would strand a deep or late artifact without any signal. The size bound and the base64 check remain, because those protect the caller's turn. I corrected the ticket's Fix and AC-4 in place.
- A declared width or height above 2000 px stays inline (the second commit). Once a request carries more than 20 images, Anthropic's API refuses any image larger than that ([vision docs](https://platform.claude.com/docs/en/build-with-claude/vision)). A long session reaches 20 images, and a hi-DPI frame would then fail every later turn. The byte bound alone did not cover this.
- `formatWithImages(result, format)` carries the envelope logic, so the spec drives it with the real `BaseServer` formatter. Importing `Server.mjs` would construct the Bridge connection singleton.
