Resolves #1023

Two connections under one agent id are ordinary in the fleet: a seat running two sessions opens two, and a reconnect can race its predecessor's close. `registerAgent`'s close handler deleted the id and told every agent `agent_disconnected` whichever socket closed, so the replaced connection's close evicted its successor. The live agent then received no App traffic, and every peer heard it leave. Now only the registered socket's close evicts and announces, the guard `registerApp`'s close already carries. Apps still hear every close, keyed by its `sessionId`, so each session's locks release. The newest registration keeps the route, as before.

Evidence: L2 (unit, through the recorded `close` handlers of the real `registerAgent`) → L2 required (AC-1 to AC-4).
