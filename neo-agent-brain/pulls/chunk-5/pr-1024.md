Resolves #1016

🌿 *Another seat's last pick can no longer decide, unseen, which model this seat works on.*

Claude Desktop seats now refuse to work on a model family their account picked for another seat. The new `seatModelGuardHook` runs on `UserPromptSubmit`. It reads the session's current model from the app's session record, joined on `cliSessionId`, and blocks the prompt with exit 2 while that model's family differs from the family the seat last ran. The message names the fix: switch the picker and resend. A prompt starting with `model-ok` runs anyway. On `Stop`, the hook records the family that actually ran. Every missing or unexpected input lets the prompt through, and each block appends one log line with no session ids.

Evidence: L2 (unit decision table, the hook as a process, and a live control against a copy of this seat's real session record) → L3 required for AC-1b and AC-7 (a picker flip on a logged-in Desktop seat, and a real wrong-model boot). Residual: AC-1b, AC-7, Residual-Owner: #571.
