<summary>Release notes</summary>
<p><em>Sourced from <a href="[QUARANTINED_URL: github.com]">express's releases</a>.</em></p>
<blockquote>
<h2>v5.3.0</h2>
<h2>Highlights</h2>
<h3>🐞 Bug fixes</h3>
<ul>
<li>
<p>Fixed HTTP header conflict between Content-Length and Transfer-Encoding in res.send - by <a href="[QUARANTINED_URL: github.com]"><code>@​YuryShkoda</code></a> in <a href="[QUARANTINED_URL: redirect.github.com]">#4893</a></p>
<p>Fixed the behavior of <code>res.send()</code> to prevent conflicts between <code>Content-Length</code> and <code>Transfer-Encoding</code> HTTP headers in responses. The <code>Content-Length</code> header in <code>res.send()</code> is now only added when a <code>Transfer-Encoding</code> header is not present, complying with the HTTP specification that states both headers should not coexist in the same response. ETag generation is unaffected by the presence of a <code>Transfer-Encoding</code> header - by <a href="[QUARANTINED_URL: github.com]"><code>@​cuishuang</code></a> in <a href="[QUARANTINED_URL: redirect.github.com]">#7459</a></p>
</li>
</ul>
<ul>
<li>
<p>Upgrade <code>qs</code> to <code>^6.16.0</code>, which fixes <a href="[QUARANTINED_URL: cve.org]">CVE-2026-2391</a> (<a href="[QUARANTINED_URL: github.com]">GHSA-w7fw-mjwx-w883</a>), <a href="[QUARANTINED_URL: cve.org]">CVE-2026-82417</a> (<a href="[QUARANTINED_URL: github.com]">GHSA-4mjr-xmp4-gh2g</a>) and <a href="[QUARANTINED_URL: cve.org]">CVE-2026-82562</a> (<a href="[QUARANTINED_URL: github.com]">GHSA-x5fp-wj9c-mxmx</a>): <code>arrayLimit</code> bypasses in comma parsing and a denial of service via an attacker-controlled <code>isBuffer</code> - by <a href="[QUARANTINED_URL: github.com]"><code>@​davetashner</code></a> in <a href="[QUARANTINED_URL: redirect.github.com]">#7057</a> and <a href="[QUARANTINED_URL: redirect.github.com]">#7478</a>, and <a href="[QUARANTINED_URL: github.com]"><code>@​cyphercodes</code></a> in <a href="[QUARANTINED_URL: redirect.github.com]">#7305</a></p>
</li>
<li>
<p>Upgrade <code>proxy-addr</code> to <code>^2.0.8</code>, which fixes <a href="[QUARANTINED_URL: cve.org]">CVE-2026-90711</a> - by <a href="[QUARANTINED_URL: github.com]"><code>@​lazerg</code></a> in <a href="[QUARANTINED_URL: redirect.github.com]">#7474</a></p>
</li>
</ul>
<h3>🚀 Improvements</h3>
<ul>
<li>
<p>Allow conditional revalidation for QUERY requests. <code>req.fresh</code> previously only validated freshness for GET and HEAD requests, so QUERY responses never returned 304 despite a matching validator. Since QUERY is a safe, idempotent, and cacheable method that supports conditional requests, it is now included in the freshness check - by <a href="[QUARANTINED_URL: github.com]"><code>@​Cherry</code></a> in <a href="[QUARANTINED_URL: redirect.github.com]">#7366</a></p>
<pre lang="js"><code>// QUERY /reports with If-None-Match: &quot;12345&quot;
app.query('/reports', (req, res) =&gt; {
  res.set('ETag', '&quot;12345&quot;');
  res.send(results); // now responds 304 Not Modified
});
</code></pre>
</li>
<li>
<p>Improve HTML structure in <code>res.redirect()</code> responses when HTML format is accepted by adding <code>&lt;!DOCTYPE html&gt;</code>, <code>&lt;title&gt;</code>, and <code>&lt;body&gt;</code> tags for better browser compatibility - by <a href="[QUARANTINED_URL: github.com]"><code>@​Bernice55231</code></a> in <a href="[QUARANTINED_URL: redirect.github.com]">#5167</a></p>
</li>
<li>
<p>When calling <code>app.render</code> with options set to null, the locals object is handled correctly, preventing unexpected errors and making the method behave the same as when options is omitted or an empty object is passed - by <a href="[QUARANTINED_URL: github.com]">AkaHarshit</a> in <a href="[QUARANTINED_URL: redirect.github.com]">#6903</a></p>
<pre lang="js"><code>app.render('index', null, callback); // now works as expected
</code></pre>
</li>
<li>
<p>Upgrade <code>content-type</code> to <code>^2.0.0</code>, bringing a faster parser (~1.5x quicker <code>Content-Type</code> parsing/formatting in <code>res.send()</code>) along with a behavior change: <code>res.send()</code> now keeps any existing parameters when adding the charset and no longer throws on a <code>Content-Type</code> that fails to parse. <code>type-is</code> is upgraded to <code>^2.1.0</code> as part of the same change - by <a href="[QUARANTINED_URL: github.com]"><code>@​blakeembrey</code></a> in <a href="[QUARANTINED_URL: redirect.github.com]">#7234</a></p>
<pre lang="js"><code>res.set('Content-Type', 'text/plain; foo=bar').send('hey');
// -&gt; Content-Type: text/plain; foo=bar; charset=utf-8
</code></pre>
</li>
<li>
<p>The default error handler now logs the full error object instead of only its stack trace, so nested details such as <code>Error.cause</code> and library-specific properties (e.g. Sequelize's <code>parent</code>/<code>original</code>) are no longer swallowed - by <a href="[QUARANTINED_URL: github.com]"><code>@​Nitin-Mohapatra</code></a> in <a href="[QUARANTINED_URL: redirect.github.com]">#6464</a></p>
</li>
<li>
<p>Upgrade <code>content-disposition</code> to <code>^2.0.1</code>, which changes the <code>Content-Disposition</code> header emitted by <code>res.download()</code>, <code>res.attachment()</code>, and <code>res.sendFile()</code>: file names that are valid HTTP tokens are no longer wrapped in quotes. This is equivalent per RFC 6266, but applications asserting on the exact header bytes should update their expectations - by <a href="[QUARANTINED_URL: github.com]"><code>@​blakeembrey</code></a> in <a href="[QUARANTINED_URL: redirect.github.com]">#7233</a></p>
<pre lang="js"><code>res.attachment('user.html');
// before -&gt; Content-Disposition: attachment; filename=&quot;user.html&quot;
// after  -&gt; Content-Disposition: attachment; filename=user.html
</code></pre>
</li>
</ul>
