Resolves #1026

🌿 *A deliberate switch on a seat's own account no longer reads as somebody else's pick.*

The seat model guard from #1024 now blocks only where the problem it targets can happen: on a Claude account that another seat also uses. On an account no other seat uses, the picker's remembered choice is always the seat's own, so a family change there is a deliberate switch. Before this change, a seat rotating Opus and Fable on purpose had to resend with `model-ok` after every switch. The record read now returns the session's account folder beside its model. `accountSharedWithAnotherSeat` checks, by directory name only, whether a sibling seat under the same agents root has `claude-code-sessions/<account>`. An unrecognized user-data layout never blocks.

Evidence: L2 (unit tests in Fleet's real seat layout, plus a live control on this seat, which no other seat shares an account with) → L3 required for AC-5 (a real weekly switch and a real shared-account mismatch after hydrate). Residual: AC-5, Residual-Owner: #571.
