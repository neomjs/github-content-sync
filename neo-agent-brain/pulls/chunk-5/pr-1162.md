Resolves #1148

A backup can no longer publish a bundle whose heal ledger copy is torn.

- **`pruneHealLedger` replaces the ledger atomically,** so a backup copying it mid-prune reads the whole old file.
- **The backup runs restore's own ledger rule before publication.** A copy restore would reject is refused, and the previous bundle stays newest.

Evidence: L2 (unit: a held reader across a prune and a torn-ledger backup run, both red on `dev`; restore's probe verdicts, including the compound content + I/O ones) → L2 required.

## AC Evidence

It is red on `dev`, where the held reader sees the rewritten two-line file. At head it reads the six-line original, the path holds events 4–5, and no scratch file remains. The backup root afterwards holds only the predecessor: nothing is published and no staging is left, so no receipt reads restorable. Red on `dev`, where the backup published |
| AC-3 | `restore.spec` "the probe validates the LEDGER members it attests…" keeps its `heal-attempts.json` and `recovery-runs` arms (`BUNDLE_INVALID`) and gains a torn top-level `heal-events.jsonl` row (`BUNDLE_INVALID`, line 2), plus the positive control (`RESTORABLE`). Restore's verdicts are unchanged, including the compound ones: "an unreadable receipt beside a malformed nested member reads BUNDLE_UNVERIFIABLE", and "…beside a torn top-level payload reads BUNDLE_INVALID". The maintenance, ledger-store and atomic-writer specs pass together: 811 |

## Deltas from ticket
- **The prune keeps the ledger's permission bits under any umask.** `writeFileAtomic` and `writeFileAtomicSync` gain an opt-in `preserveMode`. An existing target's bits go onto the scratch by `chmod` before the rename, because creating the file lets the umask narrow them; a missing target takes `mode`. The other callers are unchanged.
- **Restore's check order is unchanged.** `validateIncidentLedgers` is one rule in two halves. `validateBundle` runs the top-level payloads where its streaming pass reaches `ledgers/`, its last subdirectory, and the nested members after `bundle-meta.json`; both are the positions they had before. A backup runs both halves.
- **IO failures are not refusals.** The backup gate converts only `BundleContentError` into `INCIDENT_LEDGER_INVALID`. An unreadable copy propagates as itself, so an IO fault is not mislabelled as a torn ledger.
