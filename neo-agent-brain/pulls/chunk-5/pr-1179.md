Resolves #1178

🌿 An FM update can no longer make a Codex seat's own project file look foreign.

After the FM moved to Brain 5701fa7c this morning, every Codex Desktop Start refused with `refusing unauthenticated MCP transport transition … (non-transport managed keys differ)` (Euclid, Emmy, 10:52Z). The project-config convergence recognizes a seat's earlier render under a runtime an install has since moved by re-rendering `[plan, vocabularyPrevious, formerPlan]` with that runtime. Since #1156 a seat whose Neural Link runs through Fleet's launcher renders `projectPlan`, the plan without Neural Link, so its own file was never among the candidates. The fix adds `projectPlan` to them. The runtime-upgrade merge then walked all five servers and refused Neural Link as `managed table is missing`, although a launched server is in neither project file. `mergeCodexTransport` now lets a server other than MC and KB be absent from both sides; the merged result is still checked against Fleet's desired projection, and MC/KB keep the guard.

Evidence: L2 (unit, two packaged runtimes in the installed shape) → L3 required (AC-3, the GPT seats' Starts). Residual: AC-3, the next FM candidate. Residual-Owner: neomjs/neo-agent-institution#736.
