Resolves #1164

A seat's life now runs end to end in the unit job against a real fleet server: define, Start, Stop, Start again, an unclean Fleet restart with the seat gone, then Start once more. It covers Claude Desktop and Codex Desktop. Seats launch `ai/scripts/fleet/seatStandIn.mjs`, a stand-in that reads the family's config where the app reads it, starts every MCP row and asks each `initialize`, `tools/list` and `healthcheck`. So launch admission, the Fleet's process proof and Neural Link all run through real collaborators, with no window. `ai/services/fleet/seatJourney.mjs` owns no process; neomjs/neo-agent-institution#736 reuses it unchanged on a packaged candidate.

Evidence: L2 (a real `devFleetServer`, its own keyed Bridge and stand-in seats, in the unit job) → L2 required (#1164's ACs are checkout-mode properties). The 10-18 P0s live on the runtime-generation path, which needs the Electron host's materialization, so neomjs/neo-agent-institution#736 covers them on a packaged candidate.

## Deltas from ticket
- The spec sits in the unit tier, not the integration tier, because it needs no compose stack. #1164 was updated.
- `NEO_MEMORY_DB_PATH_TEST` points the run's graph at a shared file. Under `UNIT_TEST_MODE` the graph is `:memory:` per process, so the fleet never saw the seeded viewer.
- The stand-in launcher is a module behind an absolute shebang, not a shell `exec`. `runsSeatLaunch` treats anything else as `process-unknown`, and the launch admission service then refuses every MCP launch.

## Test Evidence
- Red, generation path: with #1139 reverted on a throwaway branch, the journey still passed. Checkout-mode recovery infers `stopped`; the `exited` path is generation-only, which is why neomjs/neo-agent-institution#736 owns it.
- Live finding: before #1156, Codex Desktop NL rows ignored the Fleet's `NEO_NL_PORT`. Two local runs reached this machine's host Bridge on 8081, which refused them. The port guard now fails such a row by name, before anyone has to notice it.
