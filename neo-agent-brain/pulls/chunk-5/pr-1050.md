Resolves #1049

`syncGithubWorkflow.mjs --corpus-only` accepts `--refetch-issues=<n,…>`. The issues facet force-refetches the named numbers in the same emission. They go through the set that `IssueSyncer#pullFromGitHub` already force-refetches, the related issues, so `_index.json`, `.sync-metadata.json` and the facet's rollback cover them. Every token is checked as a positive integer before the emitter loads. A named issue that does not come back fails the facet. This is the runtime half of the publisher's refetch input, neomjs/github-content-sync#22, which heals #1038's 25 stale issues.

Evidence: L2 (the actual CLI in child processes, against a stubbed GraphQL and a real temporary corpus; red-first on `dev`) → L4 required for the remediation itself (the publisher dispatch, input in github-content-sync#22). Residual: the dispatch, recorded on github-content-sync#3.
