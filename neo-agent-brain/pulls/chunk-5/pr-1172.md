Resolves #1169

🌿 A seat that is gone can no longer stay "alive but unidentified" forever.

Boot recovery cleared a seat's `ownershipUnresolved` only when its process was gone *and* no helper cleanup was owed, and the record it rebuilt carried no Electron profile or app executable. A Codex Desktop seat whose Stop could not prove its helper cleanup therefore stayed unidentified across every FM restart. Start refused it first (`refusing to spawn agent … leased seat process is alive but cannot be identified`), and neither Stop nor Start could ever run `finalizeCodexDesktopHelpers`, the one path that clears the flag. That is Emmy's row at issuer epoch 14 (`stopped, ownershipUnresolved: true, cleanupUnresolved: true`), and it made the old FM refuse every continuity handoff on 2026-10-19. Now a gone seat's ownership resolves. A `codex-desktop` record still owing its cleanup gets its profile from `guiProfileDir`, now exported so launch, wake route and recovery read one value, and its app from the saved Start's `launchCommand[0]`, so the next Start runs the existing helper cleanup and spawns.

Evidence: L2 (unit, recovery from a recorded journal row through the next Start) → L3 required (AC-4, Emmy's Start). Residual: AC-4, the installed Start on the next FM candidate. Residual-Owner: neomjs/neo-agent-institution#736.

- **Challenge**: In `recoverRuntimeCustodyUnderGuard` (`ai/services/fleet/FleetLifecycleService.mjs:2346-2358`), `record.runtimeUnresolved` is initialized to `true` (`line 2346`) and only cleared to `false` inside `if (!record.cleanupUnresolved)` (`line 2353`). When the next action on a recovered `codex-desktop` record is `start(id)` (the `#1169` path), `start()` runs `finalizeCodexDesktopHelpers(priorRecord)` and then replaces `priorRecord` with a fresh record in `this.processes`, so `runtimeUnresolved` is reset cleanly. Non-blocking for `#1169` (whose scope and ACs target `Start`), and worth noting if standalone `stop()`-after-recovery pin release is ever relied upon.
