Resolves #1616

🌿 After this, no seat can say of its own finished ticket: *the verdict is posted, and the close waits for a click that is not mine.*

The github-workflow server gets `manage_issue_state` with one action, `close`. It closes an issue with a required reason when the caller is its author or a current assignee, refuses anyone else without `acknowledgedForeignClose`, answers an already-closed issue unchanged, and for `DUPLICATE` resolves the surviving issue first. The contract and its error shapes are `manage_discussion`'s close (PR #1489) applied to issues.

Evidence: L2 (stubbed GraphQL dispatch; both documents also validated against GitHub's live schema) → L3 required (AC3: a close through the tool on a plane that runs the merge). Residual: AC3, Residual-Owner: #132.

## Deltas from ticket

- **`stateReason(enableDuplicate: true)`.** GitHub reports a duplicate as `NOT_PLANNED` unless the field is asked with that argument, so the read and the mutation both pass it. Found by introspection, not in the ticket.
- **`duplicate_of` is strict.** It is required for `DUPLICATE`, refused when it names the issue itself, and refused with any other reason, so a caller cannot believe a link was recorded that was not.
- **Unknown numbers.** GitHub answers a number that is no issue, unknown or a pull request's, with a `NOT_FOUND` error beside the null field, and `GraphqlService.query` throws on it. Both lookups turn that one thrown error into `NOT_FOUND`; any other lookup error stays `GRAPHQL_API_ERROR`. Found in review.
- **Input bounds.** `issue_number` and `duplicate_of` are positive integers in the schema and in the service, and a call without arguments is refused instead of throwing.
- **A spec file of its own** instead of more arms in the 2,474-line `IssueService.spec.mjs`, following `PullRequestServiceReviewers.spec.mjs`. The ticket's first criterion names the file.
- **Censuses.** Five existing assertions moved by one: the server's tool count (25 to 26) and its repository-target operations (20 to 21).
