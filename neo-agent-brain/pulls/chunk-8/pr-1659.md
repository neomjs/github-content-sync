Resolves #1651

A holder whose open-work wake the receiver recorded `delivered` now escalates to one rotation seat as `holder-silent` when its action is still open four hours later. Silence is certified from the receiver's record of that one message, never from an attempt. The round keeps each intake receipt's message id on its admitted slot. It reads the verdicts back through a new operator-admitted plane read, `read_open_work_wake_delivery`, which answers from the same records reader as `who_is_online`. The escalation goes out once per head and never to the holder. Once sent, it stays held through a round whose read fails, so it is never sent twice.

Evidence: L2 (pure planner, projection and round specs with injected receipts and verdicts; the reader and the plane tool against real record files) → L2 required (AC-1 to AC-3 are unit ACs). Residual: AC-4, Residual-Owner: #759.

## Deltas from ticket

- **No host-mode path.** The wake round exists only with a plane client (`devFleetServer.mjs` wires it behind `planeClient`), so an in-process read would have no caller.
- **One reader, per-caller ids.** `readWakeDelivery` takes `messageIds`. Joined calls still share one directory read, and each projects its own ids, so a call without ids gets the same shared answer as before.
- **A sent escalation survives a failed read.** Without this, a failed read followed by a good one sent the escalation twice (found in self-review, red-first).
- **A bounded read that still covers everyone.** The round asks only about slots first observed at least four hours ago, since a wake cannot arrive before its action was observed. It asks about every one of them each round, at most 100 ids per call (the plane's bound), so a wake behind a hundred older ones is still read; a failed call leaves only its own ids unknown.

## Test Evidence

- **Red-first:** each new arm failed before its implementation, including the second-send arm before its fix. The batched-read regression (101 receipts, the delivered one read in the second batch) failed at `74dbf37f` with a single read of 100 ids and no escalation.
- **Live join-key witness:** the installed receiver's record for the open-work wake `MESSAGE:43aa5803` carries that exact id in `sourceEventIds`, `state: delivered` ([#759 receipt](https://github.com/neomjs/neo-agent-brain/issues/759#issuecomment-6841703543)). The intake receipt's id is the key the receiver records a delivery under, which the unit specs inject rather than prove.
