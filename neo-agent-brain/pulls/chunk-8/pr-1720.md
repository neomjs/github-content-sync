Resolves #1712

The rotation now names a sunset's successor by its marker: the quiet self-DM tagged `sunset-successor` whose `inReplyTo` is the receipt. It no longer uses the Memory Core session ids saved after the receipt, which an MCP reconnect changes inside the old transcript.
- Before a request, a marker refuses with `successor-present`. After one, the earliest marker completes the rotation. It also releases the wake hold.
- Markers never count as the receipt's newest self-message, so a marker cannot switch its own receipt off. A `sunset-rescinded` note still does.
- The rotation prompt names the marker and the receipt id, so a fresh session sends it before Skills #386 teaches `context-recovery` to.

## Deltas from ticket
- **Fix item 4.** The marker carries no sender session: `originSessionId` is caller-supplied, and a fresh session does not know its Memory Core id before its first save. A memory saved after the marker may be another session's, so the completed record persists `newSessionId: null` and names the successor by `successorMessageId`. Every `newSessionId` reader is null-safe (`readActiveWakeSubscriptionIdentities`, `fleetRotationActivityAdapter`, `fleetWakeRoutesSource`).
- **`inReplyTo` matching.** The match ignores a `MESSAGE:` prefix, so a marker that names the receipt by its bare id counts too.
- **The tag constant.** `SUNSET_SUCCESSOR_TAG` lives in the import-free `wake/sessionRotation.mjs`, so the receiver's dependency closure does not widen.
