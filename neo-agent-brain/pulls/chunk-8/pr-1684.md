Resolves #1677

🌿 Home can no longer tell a returning operator that a question from July still waits for a word.

An ask to a human now always has a deadline. A Task addressed to a human principal without `expiresAt` is stored with `sentAt` plus `mailbox.humanAskTtlMs` (7 days). The expiry sweep applies the same span to an open ask that carries no usable deadline, so the asks already open end at the first pulse after the cut. Each originator gets one message that names its expired asks with the fallback each one stated. That notice stays owed until a message is accepted: the sweep marks each expired ask in the transaction that expires it, every sweep sends what is owed, and a failed send is retried by the next one. Tasks to agents, broadcasts and `requestPublish` Tasks are stored and swept as before.

This branch was built on 2026-11-13 and held, because the rule lets a question to a human lapse without the human acting. The operator answered the ticket's first question the same day: yes, an ask to him may expire ([receipt](https://github.com/neomjs/neo-agent-brain/issues/1677#issuecomment-6861670460)). The 7 days and the notice to the asker are this branch's choices; the span is the config leaf `mailbox.humanAskTtlMs`. The ticket's second question, whether Home also counts what expired, has the design seat's yes and no word from him, and is not part of this diff.

Change class: capability (`feat`).

Evidence: L2 (unit: the real service on its SQLite store) → L3 required (AC-6: the installed count on the plane). Residual: AC-6, Residual-Owner: neomjs/neo-agent-institution#951.

**Config key added:** `mailbox.humanAskTtlMs` (`NEO_MAILBOX_HUMAN_ASK_TTL_MS`, default 604800000) in the Memory Core config. A local `config.mjs` overlay needs no change: it inherits the default. The rule takes effect when the Memory Core process starts on this revision.

## Deltas from ticket

- "No usable deadline" covers an unparsable `expiresAt` on an ask to a human as well as a missing one. A stated, parsable deadline is kept, whatever its distance.
- The stamp applies to the states the sweep can expire (`Submitted`, `Working`, `InputRequired`). A Task sent to a human in a terminal state gets none. The `task.expiresAt` tool description names that boundary and the publish request.
- Every ask to a human that expires is named to its originator, also one with a stated deadline.
- A notice lists at most 100 asks and counts the rest.
- An expired ask to a human carries `expiryNotice` on its node: `owed` from the sweep, `sending:` plus the notice's id while that notice is sent, then the id itself. The notice is sent from that stored state, never from the sweep's memory, so a send that fails is retried by the next sweep and after a restart. The expiry is never rolled back.
- A notice stays owed until it is accepted; every sweep tries again, however long ago the ask expired.
- The notice's id is fixed before the send (`addMessage` takes it as an internal option). A mark still `sending:` is settled from the stores that prove an acceptance, the graph node or the pending message WAL, and never by sending again: neither a failed send, nor a failed id write, nor a process that dies between them sends one notice twice.
- Two existing arms change with the contract. `#859 AC-4` asserted that an ask to a human reads without `expiresAt`; it now reads the stored default. `#922 AC-4` asserted that the asker receives nothing at expiry; it now receives the notice.
- The sweep's row predicate existed twice, once in the SELECT and once in the UPDATE. It is one function now, and that is where the new clause lives.
- Found while building this: on the canonical plane no process runs the sweep today (#1679). The rule is correct and tested here, and it acts on the plane once #1679 has landed too.
