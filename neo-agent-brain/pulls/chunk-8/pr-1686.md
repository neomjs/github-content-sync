Resolves #1681

A Claude turn that ends on an API error runs `StopFailure` instead of `Stop`. The seat kept no wake listener, and the wake that had started the turn was already past its watermark, so its events were lost too. Now:

- the listener re-arms on `StopFailure` after a transient error, and the lost events are delivered once more;
- a seat it cannot re-arm reads `undeliverable` in `who_is_online`, which sends its held work to rotation;
- Fleet reads an auth-class failure as `authRequired`.

Evidence: L3 (unit specs red on `dev` first; a headless probe of the real Claude Code engine) → L4 required (AC-6: an installed Claude Desktop seat whose woken turn is made to fail). Residual: AC-6, Residual-Owner: #759.

## Deltas from ticket

- **AC-1 has one arm, `listener silent`, not two.** After an auth failure the listener is gone and the turn is closed `aborted`, so the seat reaches the same verdict as a crash. The `error` reaches Fleet through the listener record (AC-4), not the plane's reason. A `turn-aborted:<error>` arm would need a terminal-turn query that `TurnPresenceService` does not have.
- **Only transient errors re-arm:** `rate_limit`, `overloaded`, `server_error`, `unknown`. The ticket said "any other value". `invalid_request`, `model_not_found` and `max_output_tokens` would fail every rewake the same way an auth failure does, so they wait for the next turn that reaches `Stop`. A held error also stands down a listener that is already running, so its in-flight poll does not wake a session that fails the same way.
- **The re-arm backs off.** It waits one poll interval, doubling up to two minutes, because each rewake costs a model call. The retry-bounds registry classifies it as a capped retry whose count persists in the listener record.
- **A failed turn settles only for the seat's owner.** A session that lost the seat settles just the delivery it received. Its presence names its own turn: the hook mints the turn id at the prompt and keeps it per session in the OS temp directory, so its end never closes the newer session's turn. Without a stored id (the file missing or unreadable) a failed turn's end records nothing, and the turn expires on its own; progress without one still joins the newest turn.
- **A non-auth failure reads `null` in Fleet, not "turn failed".** A transient one re-arms; a lasting one reads `listener silent` in `who_is_online`. In `status()` a recorded auth failure outranks the credentials file, which proves a credential exists, not that it works.
- **Pull verdicts need no receiver record.** With the records unconfigured or unreadable, the rows still carry what a seat's pull routes concluded. Push routes stay unknown, the wake axis reads degraded, and the terse `undeliverable` map stays omitted.
- **The listener record gains `delivered` and `failure`.** Fleet reads `failure` from the host the seat runs on. The route rows gain `pull` and `lastPollAt`, read in-process only.
- **Folded in: a teardown race in `sessionRotation.spec.mjs`** (from #1683, defect-note 744e6363). A `202` answers before the receiver writes its record, so the `afterEach` could remove the directory under a write still in flight. It failed once on Brain #1684's CI, and it can red this PR's unit job too, so the fix rides here rather than in a new ticket.
