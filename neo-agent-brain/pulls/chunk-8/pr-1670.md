Resolves #1630

An outside contributor's comment on an open PR now wakes the seat that owes the reply, beside whatever else holds the PR. The snapshot reads each PR's latest 10 comments and 10 submitted reviews as `turns`: time, author, member or outside, and no text. `responderOf`, beside `holderOf` in `openWorkHolder.mjs`, names the earliest outside turn after the latest member turn and the seat that answers it. The planner holds that reply in its own `respond-comment` slot, keyed by the owed turn's time, so each episode wakes once, across pushes too. The branch is rebased onto `dev` after #1663 and #1659 merged, so its diff is this ticket's alone.

Evidence: L2 (pure reducer, holder and planner units, red on the base; one live GraphQL read measured the new snapshot at cost 4) → L2 required for AC-1 to AC-4 (reducer and planner behavior). Residual: AC-5, Residual-Owner: #759.

## Deltas from ticket

- **Who decides.** The reducer carries raw `turns`, and `responderOf` in the holder module decides. It sits beside `holderOf`, not inside it, because the reply coexists with whatever holds the PR (AC-3). The engaged-seat order stays in one module, as my intake comment on #1630 records.
- **The episode is the owed turn's time, not the comment id.** The plane admits an open-action episode only as an ISO instant (`openWorkWakeMessage.mjs`), and a time carries no text.
- **An untouched outside PR's reply goes to the seat the triage woke**, not a second rotation pick. Its triage already covers the turns before it, and two rotation seats on one PR would duplicate the work. A comment before the triage wakes nobody extra.
- **A push alone wakes nobody twice:** the new head's slot keeps what the same episode already settled.
- **A silent reply escalates like a silent holder.** #1659 put its `holder-silent` branch in the seat loop this PR had moved into `holdSeat`; the rebase moved the branch there, so the holder and the owed reply share one path. A reply its seat leaves unanswered four hours after a delivered wake wakes one rotation seat, as an unreachable seat already did.
- **Query:** `comments(last: 10)` and `reviews(last: 10)` without `id`. The cost note and the one retained generation follow the table's own rule: the previous snapshot hash replaces the older one.
- **Not in this PR, from my specimen comment on #1630:** a member's comment newer than the head still leaves an outside PR untouched. Changing that trades a duplicate triage for a PR nobody triages again, so it needs its own decision.
