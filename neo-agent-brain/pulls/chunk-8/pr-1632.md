Resolves #1627

The fleet's half of the Nightshift toggle. `setOperatorPresence` joins the wire as a `lifecycle-write` verb: it writes the mode through the plane's `set_operator_presence` (#1625), under the FM's proven operator identity. When the write answers `changed`, it sends one non-wake `[operator-presence]` notice to `AGENT:*`; a repeated click announces nothing, and a failed notice never undoes the write. `fleetRoster` hands the cockpit `operatorPresence` from the `who_is_online` read it already makes. The value is `null` when that read did not answer, so the toggle shows unknown, never present. A plane older than the record reads `present`.

Evidence: L2 (unit: the verb against a stub writer, the roster through the real presence adapter) → L4 required for AC-1's "through the plane" (the boot wiring's `planeClient.callTool('set_operator_presence')` on a live plane). Residual: AC-1 live, Residual-Owner: #1508.

## Deltas from ticket
- **An older plane reads `present`, not `null`.** `operatorPresenceOf` gives an answered report without the field the plane contract's default ("absent field = present", #1625's ledger). It keeps `null` for an unanswered read or a mode outside `present | away`.
