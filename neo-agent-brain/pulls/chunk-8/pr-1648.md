Resolves #1647

`run-bridge.mjs` now defines `shutdown` and registers its SIGINT/SIGTERM handlers before its first `await`. A SIGTERM that lands between the port's `listen()` and `startServer()`'s resolution now closes the server and exits 0, where it used to end the process by signal. A new deterministic arm pins the case: a preload makes the bridge's own server send SIGTERM the moment it emits `listening`.

Evidence: L2 (unit arms; the new arm is red on `dev` and green with the move) → L2 required (AC-1 to AC-3 are unit-observable).

Intake: ticket authored this session. Prescription checked: `ai/mcp/server/neural-link/run-bridge.mjs` owns the concern. Signal disposition belongs to the process entrypoint; `Bridge.mjs` is a service hosts reuse in-process, and a readiness poll in the spec would only hide the gap.
