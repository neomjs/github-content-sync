Resolves #1689

🌿 Home can say how many of the operator's asks expired unanswered, and a plane that cannot window them can no longer pass off every expiry it ever saw as that number.

The sweep stamps `task.expiredAt` in the statement that expires a Task. `list_messages` takes `expiredWithinSpan` beside `taskStates: ['Expired']`: the Memory Core applies its own `mailbox.humanAskTtlMs`, lists the Tasks that expired within it newest first, and answers the window start as `expiredSince`, on the plain read and on the observer read the Fleet uses. The Fleet's open-work read gains `questions.expired: {state, count, since, reason}`, and `fleetOwnQuestions({expired: true})` lists those asks on the mirror's body-free rows. An expired-view answer without `expiredSince` comes from a plane that ignored the window, and is refused as unavailable.

This is the producer for neomjs/neo-agent-institution#959 (the consumer). The expiry runner (#1679, merged in PR #1687) goes live in this order: this PR, neomjs/neo-agent-institution#959, both installed, then the plane cut that carries them.
