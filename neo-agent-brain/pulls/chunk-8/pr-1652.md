Resolves #807

An open-work action whose holder cannot act now wakes one rotation seat; before this, it woke nobody.
- An `unowned` PR owes its author an action, and no seat is that author.
- A `holder-unreachable` slot is a holder wake that waits on a dead route.

`pickRotationSeat` never picks the escalated holder, even while that holder's route answers. The round's route map now reads the verbose presence rows, so a dead route is actually seen.

Evidence: L2 (unit: the planner, the intake contract, the wired round over a verbose presence payload, the entrypoint's wiring seam) → L2 required (AC-1, AC-2 and AC-3 are unit ACs). Residual: none.

Deploy order: cut the plane before the FM host update, because an older intake refuses the new kinds and the `holder` token.

## Deltas from ticket

That answer carries `wake.state` on each row and has no top-level map, so every route read `unknown` and AC-2 could never fire live.
- **Split:** the per-message receipt and `holder-silent` (AC-2's second half and the old AC-3) moved to #1651. This PR unblocks #1651.
- **`holderOf`:** a green, unrouted unowned PR is now its author's `route-review`; it used to read `none`. AC-1 therefore covers the most common unowned state, and the cockpit projection shows it too.
- **`pickRotationSeat` is exported** for its direct AC-3 arm, the same way `failedChecksOf` is exported for its spec.
- **AC numbering:** the split left #807 with AC-1, AC-2 and AC-4, so the exclusion AC is now AC-3.
