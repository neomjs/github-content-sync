The `taskId` description and the `Task not found` hint are what #1637 asks for. Your cross-tenant arm is a nice touch: it pins that the hint never reveals whether another tenant's message exists.

Since it's still a draft, here is one shape note before you mark it ready.

**The unauthorized hint re-encodes the transition table.** `allowedStates` repeats the `authorized` rules a few lines above it, and the copy has already drifted. Take a `requestPublish` task in `Working` that is not yet published. The hint lists `Completed`, but the later `isRequestPublish && newState === 'Completed' && !isPublished` override refuses it. So the error recommends a move that the next call refuses. A seat that is both originator and assignee also sees only the originator's list, even though both role checks ran.

A shape that cannot drift: one function returns the allowed next states, something like `allowedNextStates({currentState, isOriginator, isAssignee, isHumanAssignee, isRequestPublish, isPublished})`. Then `authorized = allowed.has(newState)`, and the hint prints that same set. The rules then exist once, and an arm for the `requestPublish` case pins it.

A nit: the `Task not found` message now ends in a period even when there is no hint (`Task not found: MESSAGE:….`). `FleetControlBridge` matches the prefix only, so nothing breaks.

Mark it ready when you're done, and I'll review it formally. Questions are welcome.

### 🔬 Depth Floor

- **Challenge**: `ai/services/fleet/FleetControlBridge.mjs:237` recognizes `MailboxService.transitionTask` refusals via:
  ```js
  {code: 'transition-refused', pattern: /^Unauthorized: \S+ as (originator|assignee) cannot transition `(\w+) → (\w+)`$/, reason: ([, role, from, to]) => `the ${role} cannot move this Task from ${from} to ${to}`}
  ```
  With this PR (`MailboxService.mjs:6548-6552`), two live refusal shapes no longer match that regex:
  1. Any refusal with at least one allowed next state appends `; allowed next state(s) for ...` (e.g. `'Unauthorized: @bob as assignee cannot transition `Submitted → Completed`; allowed next state for assignee: Working'`), which fails the trailing `$` anchor.
  2. A self-addressed task (`isOriginator && isAssignee`) formats role as `'originator and assignee'` (e.g. `'Unauthorized: @tobiu as originator and assignee cannot transition `Submitted → Completed`; allowed next states for originator and assignee: Canceled, Working'`), which fails `(originator|assignee)`.
  In both cases `taskRefusalOf(error)` (`FleetControlBridge.mjs:247-257`) returns `null`, so `FleetControlBridge#transitionOwnTask` (`:1705`) rejects with a generic `operation-failed` fault instead of `{success: false, rowsAffected: 0, code: 'transition-refused', reason}`. CI stayed green only because `wireOperatorComposeWriter.spec.mjs:361` checks `.toContain('Unauthorized: ${me} as ${role} cannot transition \\`${currentState} → ${newState}\\`')` (a prefix substring match!) and `:330,377` mock the old suffix-less string.
