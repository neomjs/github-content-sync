Resolves #1615

🌿 A rule the template withdrew can no longer stay in force on a seat.

`mergeClaudeHooks` becomes `mergeClaudeSettings`. The template now owns a seat's hook events and its `permissions`. Every other key stays, `autoMode` included, and a rule local to one checkout goes in `.claude/settings.local.json`. The installed Engine template stays the only source (`prepareManagedAgentWorkspace` → `hydrateCurrentWorktree` → `initClaudeSettings`): a checked-out branch never writes its own policy. The seat's own revision is the witness: its tracked template, or the template of the Engine it installed. An existing settings file syncs only while that witness declares the same hook events and permissions as the installed template. Until then the file stays as it is (`deferred`), so an older installed Engine never rolls a seat back. A settings file git tracks, or one whose custody git cannot report, keeps its own permissions. neo #20797's `ask: []` therefore reaches the Claude seats at their next Start after the harness installs an Engine that carries it, with no copy by hand.

Evidence: L2 (unit arms over real temporary settings files and git checkouts) → L2 required for AC-1 and AC-2; AC-3 is the ticket's own post-merge census, open-ended verification. No residuals before merge.

The witness and the tracked-file rule above answer both. `bootstrapWorktree.spec.mjs` keeps its "hydration reads the INSTALLED Engine template, never the worktree's own", because the worktree's template is only compared, never read into the file. A fresh target clones the installed template whole, one consistent set rather than a mix.
- Round 2 (Emmy, review 5879940953): with git unavailable to the writer, the ownership probe failed and the file read as untracked. Only exit status 1 of `git ls-files --error-unmatch` means untracked now; any other failure answers `unknown`, and the permissions stay.

- `initClaudeSettings` lost its Stop-hook paragraph. The template carries no Stop event.
- Three existing arms pinned "permissions preserved"; they now pin the template's permissions.
