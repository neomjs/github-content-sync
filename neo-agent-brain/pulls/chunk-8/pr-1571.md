Resolves #1543

A GUI family that opts in through `fleet.harnessGenerations` (every opt-in defaults to `false`) now starts its seats from an admitted harness generation. The first Start admits a new installed build once. Every Start launches the selected copy, and for Codex Desktop the bundled CLI comes from the same copy. A family with no admitted generation refuses by name, with its latest rejection, and never falls back to `/Applications`. The seat's lifecycle record and `status()` carry the pin, the lease carries its id, and the readers of the binary path follow it: the Antigravity context, Fleet-restart adoption, the profile-in-use check and the Codex model catalog.

Evidence: L2 (unit specs with store doubles and fake binaries, and the AiConfig guards) → L4 required (AC-9: a host Codex seat launched from a generation, operator-gated). Residual: AC-9, Residual-Owner: #1531.

## Deltas from ticket

- A Start that brings no capability proof (no repository, or no remote MCP) takes the selection in `start()`. The ticket's census said every Start passes a proof; the body now lists both paths.
- Admission runs at the top of `startAgentProvisioned`, before the model catalog reads the harness. `assertRemoteMcpCapability` and the Antigravity context call the same `resolveHarnessGeneration`, which only re-selects once the build is known.
- The pin lives on the lifecycle record and in `status()`, not in `seatRuntimeRecord.mjs`: that record accepts exactly its version-2 keys, so a new key would make an older Fleet reject every record after a rollback. The ticket's Fix 4 and AC-5 now say so.
- A lease gets `harnessGenerationId` only when the seat is pinned, so a seat of a family that has not opted in writes the same lease as before.
- Engine: `listHarnessGenerations` lists every admitted copy with its paths, and `selectHarnessGeneration` is its first entry. Adoption and the profile check read that list, so every path derives from the store root and a ledger entry, never from a lease value.
- Validating an Antigravity context compares its pin with the current selection, so an admission between resolve and validate refuses that Start; the next Start takes the new build.
- Plain-field seams (`harnessGenerationOptIns`, `harnessGenerationRoot`, `harnessGenerationStore`), so no spec writes to AiConfig (ADR 0019 B4).
