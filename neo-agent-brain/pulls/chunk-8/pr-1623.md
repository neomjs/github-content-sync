Resolves #1622

When a presence read times out, the roster now keeps serving the last late-settled answer for `fleet.rosterRetainedMaxAgeMs` (120 s, a new leaf). Before, the window was #1592's `4 * timeoutMs` (16 s). The cockpit reads the roster once a minute, so the 16 s window dropped every late answer before the next read could use it. Every seat's participation read `unread`: Hide benched matched nothing, and the start summary counted all 13 seats UNKNOWN.

Evidence: L2 (unit: the 60 s-gap spec is red on `dev` and green here) → L4 required (AC-3: the live roster on an FM built and installed from this fix). Residual: AC-3, Residual-Owner: #1508.
