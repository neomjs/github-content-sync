Resolves #721

`setRepo` and `setRepos` now answer like `configureAgent`. An updated definition comes back as `{status: 'accepted', agent}`. A refusal the manager names, or an unknown agent, comes back as `{status: 'rejected', reason}` inside the wire `result`. Before this, every refusal arrived as a bare `operation-failed`, so neither the add form nor the Accounts repo picker (neomjs/neo-agent-institution#407) could show why. `FleetManager` still throws, and any failure that is not a refusal still reaches the dispatcher's sanitizer.

`onboardPeer` used to stop its commit on the thrown `setRepo` refusal. It now stops on the rejection with the Fleet's reason (`commitRepoSegment`) instead of launching past it.

Evidence: L2 (unit: the real `FleetManager` behind the real bridge and `dispatchFleetRequest`, with a stub registry; `onboardPeer`'s repo commit against a stub Fleet) → L2 required. Residual: none. neomjs/neo-agent-institution#407 owns the Institution's adoption: the pin that carries this, and `AddAgentFlow` reading the new `setRepo` answer (its AC-5). Its branch was verified locally against this head: bound unit 1269, and the Brain-bound e2e including the add form and a Repositories arm.

intake: self-authored this session. The drift probe is clean (`origin/dev` unchanged since filing). Prescription checked: `ai/services/fleet/FleetControlBridge.mjs` owns the concern, because the manager's Node callers rely on throws and a dispatcher-wide change would reshape every verb. Scope revised at 19:10Z to fold `setRepo` in; the ticket body records why.
