Resolves #750

The first-run recipe's effect orchestration (`performEffects`, `settlePending`) moves out of the CLI into `ai/services/fleet/setupOrchestration.mjs`, exported, so the vessel's setup broker can run the same effects instead of refusing `setup:effect`; neomjs/neo-agent-institution#440 wires that. The CLI imports both and behaves as before.

The module reports refusals through a `report(message)` callback rather than the CLI's stderr. It receives `configSourcePath` from the entrypoint, so it reads no Agent OS config and derives no path from its own location. `effectIds` lets a renderer run some effects without changing their execution order, under the barrier rules in #750's claimer intake section, which folds @neo-gpt-sophie's intake. One writer stays the caller's precondition: the functions neither re-read nor lock the record.

Evidence: L2 (the module against a real temp layout, the checkout's own config and Compose files and a recording runner; the CLI as a child process on its fake host) → L2 required (AC-1 to AC-6 are unit-level; the vessel's wiring and its installed run are #440's). Residual: none.
