Resolves #755

A GitLab seat's repository now lands on the seat's own instance when the caller names only its slug. `setRepo` and `setRepos` already read the seat and its `forgeHost` (`assertOnSeatForge`, since #729). Until now, though, a GitLab entry without a clone URL was composed as `https://github.com/<slug>.git` and refused, so every client had to compose the GitLab URL itself.

- **`seatRepoEntry(entry, seat)`** runs before `repoCoordinates` in both verbs. An entry with no clone URL takes the seat's forge, and on a GitLab seat its clone URL is `<forgeHost>/<repoSlug>.git`, nested groups included.
- **Unchanged:** an entry naming its clone URL, and every entry of a GitHub seat. `repoCoordinates` stays seat-free, so a bare call still refuses a GitLab entry without a clone URL.
- **Consumer:** neomjs/neo-agent-institution#448. Its intake moved the composition here, so the cockpit sends slugs only and deletes its own GitHub composition.

Evidence: L2 (unit, red by mutation on each call site). Residual: none. The installed sitting stays in #684.
