Resolves #642

Fleet now seeds the selected repository's two documented Codex context defaults into a fresh or existing MCP-only project config. Either explicit project/home context key preserves the resident's policy, and later template changes cannot overwrite it. The same path serves Codex CLI and Desktop.

Only `model_context_window` and `model_auto_compact_token_limit` are copied. A real TOML parser distinguishes root settings from quoted keys, tables and multiline strings. Missing templates remain supported; malformed policy is refused by filename without echoing its contents. Existing project text, MCP ownership and login files remain intact.

Evidence: L3 (packaged Electron preparer, independent TOML parse and native Codex readback) achieved → L3 required. Live-seat rollout remains neomjs/neo-agent-institution#12.

## Deltas from ticket

Seeding is absence-based: if both context keys are removed from the project and isolated home, the next preparation seeds the repository defaults again. An existing explicit key preserves the resident's chosen policy; there is no separate one-time seed marker.

No scope changes. `smol-toml@1.9.0` is a pinned runtime dependency so bootstrap does not grow a partial TOML parser. The existing preparer owns this behavior; no new configuration service or generic template-copy mechanism is introduced.
