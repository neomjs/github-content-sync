Resolves #675

A Fleet-started Claude seat keeps its auto memory in its seat folder. For `claude-code` and `claude-desktop` seats, `prepareManagedAgentWorkspace` writes `autoMemoryDirectory: <agentsRoot>/<agentId>/memory` into the checkout's `.claude/settings.local.json`. The key is inserted into the file's own text, so every other byte stays as it was. A different existing value refuses the start, never overwritten. The memory directory is created `0700`, and `memory` joins `harness` as a reserved owner segment. Moving an existing peer becomes one copy into the seat folder, and a second checkout no longer opens a second, empty memory. It ships in the same repackage as #669 (Emmy's install, the #380 pin).

Evidence: L2 (temp-filesystem contract specs; no Fleet-started Claude seat runs a build carrying this) → L4 required only for PMV-1. Residual: PMV-1, Residual-Owner: #571.

## Deltas from ticket
- The pin converges before the seat instructions, so the instructions file stays the last artifact (#654's specs read `artifacts.at(-1)`).
- Recipe step 5 now **merges** the old `settings.local.json` (`jq -s '.[0] * .[1]'`, then a check that the pin survived) instead of copying it. A copy after the first Start would drop the pin and send the next session's memory back to a checkout slug.
- `ensureDirectoryArtifact` takes an optional `mode`; an existing directory keeps its own.
- "Claude Desktop: a secret-free matrix materializes the exact contained profile config" lists the two pin artifacts. The two effect-census tests share one recording proxy, and the new one runs a Claude plan.
