Resolves #79

🌿 A seat the Fleet launches no longer depends on anyone remembering to subscribe it, so "nobody armed its route" stops being a state it can reach.

When the Fleet starts a Codex Desktop or Claude Desktop seat on the plane it is attached to, it now arms that seat's wake route **as the seat**:
1. It proves the seat's plane credential is the seat's own identity, using the tenant credential already resolved before spawn and `createPlaneMailboxClient().init({expectedIdentity})`.
2. It subscribes the seat's one route: `SENT_TO_ME`, no filters, this receiver's URL. The Memory Core's route key answers a repeat with the row it already holds.
3. It publishes the route through the existing manifest builder.

The route's address is the window's own `--user-data-dir`, taken from the same derivation the launch argv uses. The receiver and the launch therefore cannot disagree about which window to wake. The outcome lands on the seat's lifecycle `wakeRoute`, but only for the launch that armed it. It is `ready` only when the publish carries the route just subscribed; otherwise it is `unarmed` with a redacted reason. Arming never fails a start. #79's body carries the design and ACs; they were restated for this caller on 10-01 and confirmed by Grace (edit trail in the [claimer comment](https://github.com/neomjs/neo-agent-brain/issues/79#issuecomment-5917907807)).

Evidence: L2 (unit specs over the composer, the launch derivation, the publish tuple, FleetManager and the lifecycle slot; plane, tenant service and builder injected) → L4 required for AC-9 (a real Fleet-started seat woken by a peer). Residual: AC-9, Residual-Owner: #571.

## Deltas from ticket

- **One new config leaf**, `fleet.wakeReceiverBase` ← `NEO_WAKE_RECEIVER_BASE`: the receiver as the plane reaches it. `devFleetServer` injects it through `FleetManager.wakeStateOptions` beside `wakeReceiverManifestPath`. Empty means seats stay unarmed with that reason; there is never a guessed `host.docker.internal` default. ADR 0019 has been read, and `ai:lint-config-template-ssot` is OK.
- **The plane decides reuse.** Round 1 judged an existing row by its window alone, so a row on an old receiver, another trigger or a filter could stand in for the route. That client predicate is deleted. `armSeatWakeRoute` now reports the `subscriptionIds` it published, and `ready` requires the one just subscribed.
- **`armSeatWakeRoute` accepts a caller-known tuple** (`validateKnownTuple`), so a launcher never falls back to the convention directories. The Claude hook path is unchanged.
- **Launch-bound recording.** `setWakeRoute(id, route, {pid, startedAt})` refuses a launch the seat has since replaced. These are the two facts the lifecycle already uses to tell launches apart.
- **`deriveHarnessWakeAddress`** shares `guiProfileDir` with `deriveHarnessLaunchSpec`, so the launch argv and the route come from one function.
- **The runbook** declares `NEO_WAKE_RECEIVER_BASE` and says Fleet-launched seats need no manual recipe. It also corrects the stale "restart the receiver after publishing" advice: `receiver.mjs` watches its manifest, sweeps as a backstop, and reloads on `SIGHUP`.
- **No consumer deletion.** This automates the runbook's manual recipe for Fleet-launched seats; the recipe stays for seats the Fleet does not launch. Placement is a structural fast-path, with siblings `startAgentProvisioned.mjs` and `fleetWakeFanout.mjs`.
