Resolves #725

`receiver.spec`'s shared `write` helper now publishes the way `buildReceiverManifest` does: a staged file in the same directory, renamed into place. The startup arm ("a publish during startup is still adopted") publishes while boot is reading. Written in place, boot could read the file between truncate and write, and the start failed with `SyntaxError: Unexpected end of JSON input` (`receiver.mjs:89`, via `loadManifestWithRevision`). A rename can't be read half-written.

Spec-only, +9/−2. `receiver.mjs` is unchanged. The two arms that write malformed content in place on purpose (`:380`, `:547`) stay as they are.
