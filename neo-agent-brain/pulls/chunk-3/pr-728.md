Resolves #699

🌿 A seat the Fleet starts beside its peers can no longer keep memories they never read.

On a Fleet that serves a plane (`fleet.planeBase`), a seat's Memory Core and Knowledge Base are now that plane's. `resolveSeatPlaneTarget` places each seat at start:

- a tenant row keeps its tenant;
- any other seat reaches the plane;
- a Fleet that serves no plane keeps per-seat servers;
- a seat that cannot get to the plane refuses.

A plane seat presents its own stored plane credential, never its checkout PAT. `startAgentProvisioned` proves it again before any checkout: it must resolve to the seat, on the plane it was stored against. Wake arming subscribes plane seats with the same credential, so they no longer read as "resident". The wire gains `setPlaneCredential` (`{id, credential}`), a credential-bearing verb like `connectTenant`. The caller names only the seat; the plane and the identity to prove come from the Fleet.

**The plane is bound, not just its URL** (ADR 0041 §2.4, Euclid's read). The store captures the `plane.id` and `plane.dataRoot` that the plane's `healthcheck` serves, and Memory Core and Knowledge Base must name the same plane. Both are proven again before the credential is used: a fresh start before any checkout, and wake arming before it subscribes, which also covers a Start on a seat that is already running (Emmy's RA-1). A plane recreated behind the same URL therefore does not inherit a credential proven on the old one; setting the credential again rebinds the seat. The probe reads the served plane only when asked (`servedPlane`), so tenant probes are unchanged.

**Transition.** Once a Brain pin carries this, every repo-bearing seat that the Fleet starts on the local plane refuses until its plane credential is set: under `github-pat`, one identity-only PAT per seat, created by the operator. The Institution half is neomjs/neo-agent-institution#411 (PR neomjs/neo-agent-institution#413): the shell's credential prompt, the `{id}` intent projection, and the card's "Plane credential · Set". It merges before any pin that carries this, and it is inert on earlier pins. Without it, the verb fails closed as "malformed public intent". The contract is in #699's Contract Ledger.

Evidence: L2. Unit arms cover the start path over the real workspace planner for every launchable harness; the store and its start proof, including the default probe end to end against a fetch stub; wake arming; and the wire. L4 is post-merge, on the installed FM.

## Deltas from ticket

- **Antigravity refuses on a plane** rather than staying resident. AC-1 covers every launchable harness, and Fix 3 rules out a fallback.
- **The verb is `setPlaneCredential`** (`{id, credential}`), not the plan's `storeSeatPlaneCredential`. It joins the per-seat setter family (`setRepo`, `setRepos`, `setAvatar`). The service method keeps the internal name.
- **Wake arming handles plane seats** and proves the stored binding before it subscribes. Without the first, a plane seat would read "runs a resident Memory Core"; without the second, a Start on a running seat could re-arm on a recreated plane (RA-1).
- **The default probe names another identity.** Before, only a stub produced that reason; the real probe reported "readiness failed (200)". The other identity is flagged, never carried.
- **Not done here:** tenants stay endpoint-keyed; binding them to the served plane is the same ADR 0041 §2.4 gap. The Institution prompt is the transition PR above.

## Decision Record impact

ADR 0041 §2.4 applies to seat credentials: an attach binds to the served identity, id and root. ADR 0019: `FleetManager.planeBase` is set by `devFleetServer` only after the plane admits the viewer. It is the named bootstrap seam beside `managedRoot`, and it is passed down as `managedRoot` already is. There is no new leaf, `AiConfig` read or env read.
