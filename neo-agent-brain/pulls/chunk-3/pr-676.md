Resolves #674

A Fleet-launched Codex seat's own MCP switch now works. The Codex app writes `mcp_servers.<name>.enabled` into the seat's Codex home (the user layer), and the Fleet's project tables carried `enabled = <matrix>`, which outranks it. Now a project table says `enabled = false` only for a server the Fleet switches off; a server the Fleet leaves on carries no `enabled`, so the seat's switch decides.

- **The Fleet never writes the home.** A home-only `[mcp_servers."…"] enabled = false` makes Codex refuse to load any configuration whenever the project layer isn't loaded (measured; #674's Architectural Reality).
- **`convergeCodexProjectSwitches` converges the `enabled` lines before the table bodies.** A cockpit change of the matrix now lands; until now it failed the next Start as "non-transport managed keys differ". A seat rendered by the previous Fleet migrates in one Start, and its tenant transport receipt is re-issued for the converged tables first.

Evidence: L2 (unit arms red against dev's source) + L3 (the installed codex-cli 0.159.2 reads the Fleet-rendered layers: the home switch turns Neural Link off, the cockpit matrix turns GitHub on) → L3 required for AC-2. Residual: the Codex desktop app itself was not clicked; its switch's write path is read from `app.asar` (#659 comment 5931565012).
