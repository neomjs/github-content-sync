Refs #714 — formerly stacked on #743 (its instrument's hosted arms change here); #743 landed on `dev` as `1a6903a`, and this PR is now one commit on `dev`, rebased with `--onto` (the leaf alone replayed; `git range-diff` shows no content change against the approved head `17726fa`).

The hosted preset's graph lane is Gemini's OpenAI-compatible endpoint. Graph generation dispatches to `ollama` or an OpenAI-compatible endpoint only, so the preset now says `NEO_GRAPH_PROVIDER: openAiCompatible` and points the overlay's own inputs at `https://generativelanguage.googleapis.com/v1beta/openai` / `gemini-3.5-flash`, while chat and embeddings keep the Gemini client. No client change: Google routes the client's `${host}/v1/chat/completions` like the documented `/chat/completions` (a wrong bearer answers 400 "Please pass a valid API key" on both, a nonsense path 404s — measured 2026-10-02). The credential step writes the key once and emits a third `_FILE` value, `NEO_OPENAI_COMPATIBLE_API_KEY_FILE`, at the same mount; the overlay forwards it. Gemini's documentation lists `reasoning_effort: none` (the leaf's default, the local gemma's no-think pass) for 2.5 models only, so the overlay forwards `NEO_LOCAL_MODELS_CHAT_GRAPH_REASONING_EFFORT` and the hosted preset sets `low`. The instrument drops its own copy of the dispatch's list: the table's parity arm proves every preset's graph provider is one the dispatch serves, and the child's refusal stays the runtime answer.
