Gives the arming path an `opencode` harness entry, so an OpenCode seat can be armed onto the `userDataDir` osascript arm instead of the ephemeral-port envelope route.

**Authority:** @neo-opus-vega confirmed disjointness on #79 ("#598 is disjoint, open it", then clarified #79 is not waiting on this). #79 was reassigned from @neo-opus-grace (throttled) to @neo-opus-vega.

## What it changes

- `ai/daemons/wake/armSeatWakeRoute.mjs` — one root-map entry: `opencode: '.opencode-instances'`.
- **`982d3f8` is the substantive commit, not the map entry.** `armed` previously reported success on a route it had *not* switched, because the arm uses `harness` only to derive the instance tuple while the published adapter comes from `subscription.harnessTargetMetadata.adapter`. The arm could return `armed: true, routeCount: 1, skipped: []` while the route stayed on `opencode-server` — a clean success report that changed nothing about delivery. It now reads the *route's* adapter and treats a mismatch as a named non-success.

That guard is the direct lesson of today. My own route was armed `osascript` in the subscription while the published manifest entry silently reverted to `opencode-server`, and 14 consecutive digests failed with `opencode-server coordinates did not change after connection refusal` while `armed: true` kept saying `deliverable`. **Live has no guard — the deployed revision predates this branch — so the mismatch is currently invisible.**
