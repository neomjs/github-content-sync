Resolves #616

🌿 *A seat's first poll can no longer answer "nothing unread" over a broadcast it has not read.*

The watermark-less `pollDigest` (#610) answers from current state. It enumerates the owner's inbound edges and hands each one to the shared `match()`, but it kept only `SENT_TO` edges. A receipt-backed broadcast is unread on its per-recipient `DELIVERED_TO` edge, so it never surfaced. The next watermarked poll then walks from the snapshot head, past it.

The enumeration now keeps `DELIVERED_TO` beside `SENT_TO`. `match()` already decides what "unread" means for each shape, so the service gains no second copy of that rule.

Out of scope, as the ticket says: legacy `SENT_TO → AGENT:*` broadcasts without receipts, and the delta walk.

Evidence: L2. The unit arms are red on dev, and a mutation kills each one. No residual.

Micro-review eligible: logic-narrow. One enumeration condition, its docblock, and two spec arms.
