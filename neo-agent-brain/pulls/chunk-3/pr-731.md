Resolves #730

A provisioned start's per-repository outcome (`[{repoSlug, state: 'prepared' | 'failed', reason?}]`) no longer ends with the start's answer:
- `FleetLifecycleService.setRepoOutcomes` keeps it on the launch's process record, bound by `pid` + `startedAt` exactly like #705's `setWakeRoute`;
- `status(id)` reports it as `repos` (`null` before a start);
- `fleetRuntimeStatus` passes it through like `failureReason`;
- the cockpit roster row carries it as `repoOutcomes`.

The record lives in the Fleet owner process, so a roster read or an app reload still sees it, and a fresh start writes a fresh record. The start's own answer is unchanged.

Evidence: L2 (unit: the lifecycle record, the start hand-off, the runtime producer, the roster row) → L2 required. Residual: none. The Institution card that renders it is neomjs/neo-agent-institution#408.
