Resolves #722

🌿 The Wake routes pane can no longer show a seat as unarmed without saying why, when the Fleet already knows.

Built on #705, now merged (`05dd559`). The branch is one commit on `dev` (`77ad23a`).

The armed axis of the wake-routes source came from the receiver manifest alone. A seat whose arming failed showed `armed: none` with no reason, while #705 had recorded the reason on its lifecycle `wakeRoute`, for example "no wake receiver is declared". The source now takes `readFleetArming`. When the manifest carries no route for a seat and the Fleet's last arming of it reported `unarmed`, the row carries that reason through the source's own `redactReason`. The manifest stays the authority for *armed*, and an unobserved or unknown axis keeps its own reason. `wireFleetWakeRoutesSource` forwards the reader, and `devFleetServer` supplies it from `FleetLifecycleService.status(id).wakeRoute`. The Institution pane already renders `armedReason` (`apps/agentos/view/fleet/wake/Container.mjs`), so nothing changes there.

Evidence: L2 (the source spec over the axis rules, plus the wiring spec) → L3 for the visible pane once the installed FM carries this. The entrypoint line is covered by the running-server e2e, like its sibling read paths. No residual is claimed beyond that.
