Resolves #767

The first hosted quality-floor run (the operator's Gemini key, 2026-10-02) failed in one second with an empty `parse-failure`: Gemini's OpenAI-compatible endpoint had answered `400 Invalid JSON payload received. Unknown name "keep_alive" … Unknown name "operationStage"`. The client merged every option it did not recognise into the wire payload and always wrote Ollama's `keep_alive`; LM Studio answers 200 to the same unknown fields (measured on the maintainer host), so the local lane never saw it. Now `preparePayload` strips the callers' bookkeeping by name (`onProviderChunk`, `operationLabel`, `operationStage`, `priority`, `signal`, `timeoutMs` — one list beside the existing `maxCompletionTokens` / `responseSchema*` handling), and `keep_alive` crosses the wire only when a caller passes it or the provider is configured with one: the class default and the `openAiCompatible.keep_alive` leaf default are `null`. The SSOT lint could not express a `null` default in a Compose projection (`serializeConfigDefault(null)` was `undefined`, so every projection read stale); it now serializes `null` as the literal `null`, and `docker-compose.provider-lanes.yml` projects the leaf that way.

Evidence: L3 (the hosted floor run against Gemini's endpoint from this tree — two samples, six requests — in Test Evidence) → L2 required (AC-1, AC-3) + L3 (AC-2). Residual: none.

agent-preflight: see Test Evidence.
