Resolves #613

🌿 A wake sent to a session that no longer exists can no longer pass for an ordinary failed dispatch.

An OpenCode server answers `prompt_async` with 404 when it has no session by the id the envelope carries: the seat ended or replaced that session, so the coordinates are stale. That used to read "expected HTTP 204, received 404", the same as any other failure. `openCodePromptRefusal` (`ai/daemons/wake/localWakeAdapters.mjs`) names it: "opencode-server coordinates are stale: the server has no session by the id the envelope names (HTTP 404)". Both producers of the error use it: the receiver's `opencode-server` adapter and the wake daemon's legacy path (`daemon.mjs`), which the orchestrator still defines as a task. No retry follows, because the route never retargets another session on its own. That is the same reason the connection-refusal rebind refuses a changed session id.

Evidence: L2 (red-first adapter arm) for AC-1. AC-2 is met by #510's projection, observed live on the plane (below). Residual: the L3 plane read, Residual-Owner: #503, which owns the delivery projection.

## Deltas from ticket

- **No `session.created` probe before dispatch** (the ticket's third point, not an AC). The 404 itself is now the named, authoritative answer, and a pre-flight probe would cost a request on every wake to learn the same thing.
