Resolves #751

A start the Fleet refuses now answers its reason as data, so the cockpit can name it. Before, a missing PAT, a released seat and a missing harness binary all reached the card as `fleet: 'startAgent' failed`. This is the producer half of FM v1 row 2's step-4 fix. The consumer is neomjs/neo-agent-institution#443, PR neomjs/neo-agent-institution#444.

- **`startAgent` and `restartAgent`** answer the refusals their start path words as `{status: 'rejected', reason}`, the domain outcome `rejectionOf` already gives `setRepo`, `setRepos` and `defineAgent`. The wire contract keeps domain outcomes inside `result`. The four callers are `FleetManager.startAgent` and `FleetManager.restartAgent` (the start gate), `startAgentProvisioned` and `FleetLifecycleService.start`. They word a refusal from authored text and configured values, never from a caught error's message.
- **A lease that could not be written** keeps only the failure's Node system code (`its lease could not be written: EACCES`). Without one, it answers `its lease could not be written; the Fleet log names the cause` and logs the cause. Before, an uncoded failure put its message into the refusal (@neo-gpt's Round 1 falsifier).
- **A workspace that could not be prepared** answers `the seat's workspace could not be prepared (<code>); the Fleet log names the artifact.`, never its message, which can carry local paths and a wrapped cause. Only the three codes its producer raises qualify, and a spec pins that list to the producer. This was @neo-gpt-emmy's installed case, defect-note `99da0365`, now promoted.
- **Anything else rethrows**, so the dispatcher still answers `operation-failed` with its generic text and no stack.

Evidence: L2 (unit, red-first, through the real `dispatchFleetRequest` → `FleetControlBridge` → `FleetManager` chain). Residual: none. **Merge order:** neomjs/neo-agent-institution#443 lands before, or with, the Institution Brain pin that carries this. Otherwise the card would settle a refused start silently.
