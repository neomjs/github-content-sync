Resolves #650

Brain Unit now runs the whole unit config twice, once on the change and once on its base, and fails only on a test the change breaks. Before this it executed a hand-kept list of 121 of the 793 spec files, so a green `unit` said nothing about the rest, including a spec the PR itself adds.

- **`suite (head)` / `suite (base)`** run `npm run test-unit` and keep the JSON report the unit config already writes. The base is the tested merge commit's first parent on a pull request, and `github.event.before` on a push. Neither leg fails its own job, so the base's known reds never reach the defect ledger's CI ingest.
- **`unit`** keeps the check name. `test/playwright/compareUnitFailures.mjs` keys each test by project, file and title path, never by line. The job:
  - fails on any test that fails on head and not on base;
  - writes the introduced, fixed and pre-existing tests to the job summary;
  - prints the introduced tests in the reporter's failure grammar, so `CiFailureIngestor` files exactly those.
- **A pass that needed a retry counts as failing**, matching the unit config's `failOnFlakyTests` in CI.
- **The run is bounded, and a head cut short is refused.** On CI the last test ends about 6.5 minutes in, and the run then never exits because its teardown never starts. That is recorded as a defect-note; see Deltas. `--global-timeout=600000` ends the run with the report written. A test the base ran and the head never reached refuses the comparison, so the bound can never trade coverage for time silently.

Evidence: L3 (this PR's own CI runs the new workflow on both sides) → L3 required (AC-1 to AC-6). Residual: AC-7, Residual-Owner: #201.
