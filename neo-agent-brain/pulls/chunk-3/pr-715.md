Resolves #686
Refs #685 — stacked on PR #707: its commit sits underneath this one until it merges.

The three supported first-run presets as data. `ai/services/fleet/placementPresets.mjs` exports `presets` — `hosted` (Gemini, 3072 dims), `local-small` (gemma-4-26b-a4b + the 0.6b Qwen3 embedder, 1024 dims), `local-full` (gemma + the 8b embedder, 4096 dims) — each an env set over the `local-agent-os` profile's declared leaves with `authorityProfile: 'container-plane'`, what the recipe must still ask for (`requires`), the birth decision (`vectorDimension`, `embedder`, `chatModel`), the `workload` the placement probe's `fitsPreset()` compares (the 2026-09-23 fixture plane's 0.39 / 2.5 GiB, the models' loaded-weight bytes summed once, a recommended VM cap), and `qualityFloor` — the 2026-09-23 gemma floor for the two local presets, `null` for hosted so `presetStatus()` reads `candidate`. `reembedPath(from, to)` names the consequence of a dimension change: a new Chroma store (`chroma/unified-<dim>d`), the two env values that select it, and the re-embed steps, with the old store untouched; `null` when the dimension is unchanged. `declaredEnvBindings()` scans `ai/configBase.mjs` for `leaf(…, 'ENV_NAME')` bindings and `unknownPresetEnvKeys()` is the leaf-parity lint the spec runs over every preset — a typo'd key fails the suite. Nothing here is a leaf default and nothing writes config.

**Stacked on #707** (the probe): the cross-module arm and the `GiB` import come from `probePlacement.mjs`, so this PR's diff includes #707's commit until it merges; opened as a draft against `dev` for that reason, rebased and un-drafted when #707 lands.
