Resolves #686
Refs #685 — built on the merged probe (PR #707, dev 78366b7): the cross-leaf arm and the `GiB` import come from `probePlacement.mjs`.

The three supported first-run presets as data, honoured by the profile they name. `ai/services/fleet/placementPresets.mjs` exports `presets` — `hosted` (Gemini, 3072 dims), `local-small` (gemma-4-26b-a4b + the 0.6b Qwen3 embedder, 1024 dims), `local-full` (gemma + the 8b embedder, 4096 dims) — each an env set of the `local-agent-os` profile's CONSUMED inputs: the three provider selectors, the dimension, and for the locals the overlay's own `NEO_LOCAL_AGENT_OS_{PROVIDER_HOST,MODEL,EMBEDDING_MODEL}` inputs (the overlay maps them onto the openAiCompatible leaves), for hosted the base's Gemini model pass-throughs. Each preset carries `authorityProfile: 'container-plane'`, what the recipe must still ask for (`requires`), the birth decision (`vectorDimension`, `embedder`, `chatModel`), the `workload` the placement probe's `fitsPreset()` compares (the 2026-09-23 fixture plane's 0.39 / 2.5 GiB, the models' loaded-weight bytes summed once, a recommended VM cap), and `qualityFloor` — the 2026-09-23 gemma floor for the two local presets, `null` for hosted so `presetStatus()` reads `candidate`.

The review (Emmy, 5385288341) found both consumed contracts broken and this head repairs them: **the profile.** `deploy/cloud/docker-compose.local-agent-os.yml`'s provider anchor fixed all three providers to openAiCompatible and neither Compose file forwarded `NEO_VECTOR_DIMENSION` or `NEO_CHROMA_DATABASE`, so a preset's provider and dimension never reached a container. The anchor now takes `NEO_MODEL_PROVIDER` / `NEO_GRAPH_PROVIDER` / `NEO_EMBEDDING_PROVIDER` as inputs with the local default (an unset plane stays local) and forwards the dimension and the database to the Memory Core, Knowledge Base and orchestrator with the base profile's empty-default convention. `profileInputs(composeTexts)` reads what the profile consumes — every `${INPUT}` with the last file to feed an env name winning, as the anchor merge does — and `unconsumedPresetEnvKeys(preset, profile, declared)` is the effective-profile parity the spec runs beside the leaf-name parity (`declaredEnvBindings` / `unknownPresetEnvKeys`). **Storage.** `reembedPath(from, to, {currentDatabase, freshDatabase})` derives no store from a dimension any more: a dimension change needs an explicit fresh database name the deployment chose, refuses the current one and the config default (`DEFAULT_CHROMA_DATABASE`), validates the name, emits exactly the two env values the profile forwards (`NEO_VECTOR_DIMENSION`, `NEO_CHROMA_DATABASE`), names the verification of non-existence in Chroma as the deployment's own step, and keeps the current database untouched in Chroma's volume; `null` when the dimension is unchanged. `chromaStoreFor` and the data-dir env are gone. Nothing here is a leaf default and nothing writes config.

Evidence: L2 (pure data + pure readers over the real Compose and config sources; the four ACs are unit ACs) → L2 required (AC-1…AC-4). Residual: none.

Change class: capability — one new module, one spec, and the overlay's provider anchor (two forwarded inputs, three constants turned into inputs with the same defaults).
