**Challenge OR documented search (per guide §7.1):**

- **Challenge**: The new default is a wrapper, not the binary. `bin/codex` is a 328-byte `sh` script that ends in `exec "$bin_dir/../CodexCLI.app/Contents/MacOS/codex" "$@"`. Spawning through it keeps the PID, since `exec` replaces the process in place, but the running process's command line then names `CodexCLI.app/Contents/MacOS/codex`, not the configured leaf. I looked for a consumer that identifies a Codex CLI process by the configured path and found none. The `ps -o command=` reader in `fleetWakeStateAdapter.mjs:223` checks the wake daemon's PID file. `instanceResolver.mjs` matches the Desktop bundle (`ChatGPT.app/…/ChatGPT`). `manageCodexDesktopRuntime.mjs` keys on the crashpad basename and `lsof`. Launch, the auth command, `send-message-v2` and `resumeHarness` only spawn the path. It is safe today. A future "is this Codex process ours?" check must not match on the leaf's path. Non-blocking.
