Resolves #660

Quitting the Fleet Manager no longer ends the app-bundle seats Fleet launched. `claude-desktop`, `codex-desktop` and `antigravity` seats spawn detached into their own process group, with no stdio held by the Fleet server, and leave a lease in their harness home. A restarted Fleet server re-adopts a seat whose live process still matches its lease, shows it `running` with `adopted: true`, and Stop ends it by pid. CLI families keep the held stdin they need to stay alive, and still end with the server.

Evidence: L3 (a real Fleet stand-in process running this branch's `FleetLifecycleService`, its process group torn down the way `stopBrainChild` does on quit, macOS 27.0.1) → L4 required for AC-6 (the installed Fleet Manager with Sophie's seat). Residual: AC-6, Residual-Owner: #571.

## Deltas from ticket

- **The lease holds only what nothing else knows:** the pid, its `ps` start time, `startedAt` and the checkout. The seat can write its own lease, so at adoption the launch command, auth command, profile, homes and the Codex Crashpad helper are re-derived from the registry and AiConfig, as `start` derives them. A lease that names its own `launchCommand` is ignored (spec arm).
- **Three adoption outcomes, not one "stale":**
  - A free pid, a pid now owned by a newer process, or a zombie means the seat exited (below).
  - An unreadable or foreign lease is invalid: it is removed, and the agent reads `the seat lease is invalid`.
  - A pid that answers but cannot be identified is held: `failed` with its reason, lease kept, Start refused, Stop signals nothing, and it is probed again on each read.
- **Identity is exact and renewed before every signal.** The launch binary must be `argv[0]`; a launched script is accepted only behind the exact interpreter line its own shebang names. The profile argument must appear as a whole word.
- **A seat that cannot be leased does not run.** It is stopped while this server holds its handle, and its Start fails with the reason.
- **Reported exited means a `stopped` record** whose `failureReason` reads `the seat exited while no Fleet server supervised it`. It keeps the leased `startedAt`, so `FleetManager.fleetRuntimeStatus` reports an observed stop with that reason. It is not reported as an agent outside fleet supervision (spec arm at the fleet-view level).
- **`adopted` stays on the lifecycle `status`; the cockpit row contract is unchanged.** On the roster an adopted seat reads `running` (observed) with a working Stop, which is what AC-6 now checks. Before this change, the same seat after a restart read `unmanaged`.
- **The `ps` read pins `LC_ALL=C` and `TZ=UTC`**, so the start-time text is identical in the server that writes the lease and the one that checks it.
- **An adopted seat holds no pipe:** its `stderrBytes` stays `0` and its exit code is `null`, as stated in the `status` JSDoc.
