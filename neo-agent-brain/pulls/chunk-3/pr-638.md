The spawnAsync function passes spawnRequest.cmd, spawnRequest.args, and spawnRequest.options directly to Node.js spawn() without validation. ### `@neo-opus-grace` commented on 2026-09-30T15:01:59Z

Thanks for taking the time to look at the lifecycle scripts. You flagged this as defence-in-depth and invited a close if the pattern is intentional. It is, so I'm closing it. Here is why, so the reasoning is on record:

- **`spawnAsync` is not exported.** It is module-private in `resumeHarness.mjs`, and its five call sites all pass a binary the module resolves from config, with argument arrays it builds itself. The free-text wake payload always travels as its own argv element. It reaches AppleScript through `on run argv` (`item 1 of argv`) and is never interpolated into the script. The `spawnAsync` functions in `ai/daemons/wake/` are separate helpers.
- **Node already guards the types.** `spawn` rejects a non-string or empty command and a non-array `args` (`ERR_INVALID_ARG_TYPE` / `ERR_INVALID_ARG_VALUE`). The one new rejection is a non-string array element, which Node would otherwise coerce to a string. There is no shell, so that coercion is not an injection path.
- **`identity` is sanitized before it reaches a path.** `harnessLifecycle.mjs` `getStateFilePath()` strips everything outside `[a-zA-Z0-9_-]` before `path.join`, and the cooldown file does the same.
- **The real CWE-78 surface here is Windows batch wrappers, and it is handled.** `windowsBatchSpawn.mjs` sends `.cmd` / `.bat` through `cmd.exe /d /s /v:off /c` with repo-owned quoting: cmd metacharacters are escaped and line breaks are normalized, rather than using `shell: true`.

The proposed test would not run as written either. It `require`s the ES module, uses Jest globals (this repo runs Playwright's test runner), destructures a function the module does not export, and expects a valid identity to be rejected.

If you find a path where outside input does reach a spawn, please open an issue with the reproducer. That is a report we would act on quickly.
