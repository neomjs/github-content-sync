Resolves #614

🌿 *A store's page cache can no longer pass for its exhaustion.*

The container memory percent now counts `usage − inactive_file`, as `docker stats` does. The kernel drops that file cache before it OOM-kills a cgroup, so counting it as used memory made Chroma, which reads its files through the cache, read 84.42 % of its 16 GiB against the store threshold of 80 %, while the memory it held was 70.45 %. From that one reading the loop diagnosed exhaustion at every check the heal ledger holds, and asked for a raise the knob's cap refuses three times an hour.

- `calculateDockerMemoryInUseBytes` (new, exported): usage minus `inactive_file`. A sample without the counter, or with one at or past the usage, keeps its raw usage.
- `calculateDockerMemoryPercent` reads it, so the diagnosis and the snapshot's `memoryPercent` both count the in-use share.
- The deployment snapshot publishes `memoryInUseBytes` beside the unchanged raw `memoryUsageBytes`, so the System view can say "11.3 of 16 GiB in use, plus 2.2 GiB file cache" (the neomjs/neo-agent-institution#317 design).

No threshold, service class or actuator changes. Heap-scoped Node services read their heap, not this percent, and are unaffected.

Evidence: L2 (unit arms on the helper, the diagnosis with Chroma's measured split, and the snapshot summary; each red under a mutation) → L4 for AC-4 (the live plane leaves exhaustion). Residual: AC-4, Residual-Owner: #60 (Chroma's ceiling, whose current state records the loop this stops).
