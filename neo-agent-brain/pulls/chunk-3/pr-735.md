Resolves #734

🌿 A seat no wake can reach can no longer read as merely online.

`who_is_online` reported presence from activity and nothing about whether a wake could land. That is #503's AC-4, split out as #734. Since #510, the wake receiver's dispatch records have a projection (`wakeDeliveryProjection`), and `healthcheck` reads it per subscription. This PR joins that projection to each rostered identity's active subscriptions and serves the result beside the existing axes:

- a `wake` capability envelope: `wired/observed` from the receiver's records (plane `host`), `degraded/none` with its reason when they cannot be read;
- terse: a sparse `undeliverable` map (identity → the receiver's last outcome reason) for rostered seats whose routes all fail, omitted whole when the records are unreadable, so absence never reads reachable;
- verbose: each row's `wake`, which is `reachable` (one route that lands is enough), `undeliverable` (with reason and streak), `unknown` (nothing concluded, or unreadable records) or `unsubscribed`.

The join is `projectIdentityWakeReachability`, beside `projectWakeDelivery` in the pure module. Its input comes from `readActiveWakeSubscriptionIdsByIdentity`, one per-subscription query that reuses the active-status predicate of the existing observation query, whose `GROUP BY` aggregation its spec pins and this PR leaves alone. The OpenAPI response schema declares the new key, the row field and the wake axis.

Evidence: L2 (red-first service arms over real graph nodes and receiver record files, plus pure projection and reader arms) → L3 on the plane once it carries this. Residual: the plane read, Residual-Owner: #503, which keeps AC-6 and AC-7 regardless.
