Submit immediately after pasting, and stop retrying. Small diff, and the reasoning is @tobiu's: a successful keystroke into the target's text field *is* the confirmation, so a focus race inside the sub-second gap to submit is not worth the damage the machinery caused on every ordinary message.

**The retry loop was a cause of the symptom, not a mitigation.** The script pastes and only afterwards reaches steps that can abort, so a retried attempt can leave attempt N's text in the field while attempt N+1 aborts at an earlier guard. Text present, no submit, no error — and retrying makes that *more* likely. `deliverOsascriptWithRetry` → `spawnOsascriptOnce`: one attempt, no loop, no 800ms backoff.

**What I deliberately did not touch, and why:** the ten `assertTargetFrontmost` sites. They gate **typing** and are what stops a wake being pasted into another seat's window — a real harm this path's own history records. Guards stay; only the retry goes.

**One classification I kept against my own first instinct:** a failure at a *post-submit* guard (user-input restore) still reports `delivered`, because `key code 36` has already fired and the wake was submitted. My first pass removed that too, on the theory that `delivered` should mean "the script ran clean." That was me over-applying the directive into a correctness regression — it would turn real deliveries into `failed`, and an existing spec pins it. Caught before pushing.
