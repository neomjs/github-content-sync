Resolves #729

A seat's forge decides which workflow server it starts with. A GitLab seat's defaults turn on `gitlab-workflow` and turn off `github-workflow`; a GitHub seat's defaults are today's. This is the last Brain leaf of #684.

- **`mcpCatalogFor(forge)`** in the shared contract (`src/fleet/contract/mcpServers.mjs`, exported through `neo-agent-brain/fleet-contract`) derives each forge's catalog from the workflow entries' `forge`. An unknown forge throws, prototype names included.
- **Every Brain matrix call site** resolves and normalizes a seat against its forge's catalog: `defineAgent`, `configureAgent`, `resolveResidentMcpEnvironment`, and `prepareManagedAgentWorkspace`. One catalog both ways means a GitLab seat's explicit GitHub toggle is stored as an override instead of being normalized away.
- **`setRepo`** keeps the working repository on the seat's forge, and on its exact GitLab instance: an `https` clone by exact origin (another port is another instance; IPv6 normalized), an `ssh` or scp-style clone by host.
  - The reasons are written for the operator, and they keep the `FleetManager.setRepo:` prefix that #724 carries into Accounts.
  - An unknown seat is left to `updateAgent`'s `null`.
- **One predicate, `provisionAgentRepo.isOnInstance`,** serves this rule and #727's project derivation. It moved there from `FleetLifecycleService`, which now imports it.

Evidence: L2 (unit, red-first). Residual: none (the cockpit's calls are the Institution's).
