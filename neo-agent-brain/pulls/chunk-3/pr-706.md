Resolves #704

The registry now remembers where a seat's files live, and a start whose agents root derives a different path refuses instead of provisioning a second, empty seat. `FleetRegistryService` gains the row field `seatHome` (`<agentsRoot>/<id>`), written at birth by `defineAgent` under `getAgentsRoot()` (the `fleet.agentsRoot` leaf, injectable for isolation), and one writer after that: `relocateSeatHome` — compare-and-set from the current record, `null` for a row that has none — for the deliberate move and for the one-time bind of a row registered before the record existed. `startAgentProvisioned` compares the derived seat home with the record for **every seat the Fleet launches itself, repo or not** (the managed clone, the harness home and the survivor lease all live under that directory; only a raw `metadata.launch` override derives no home), before the resident MCP envelope, the PAT read and any checkout: a mismatch throws `FLEET_SEAT_HOME_MISMATCH` naming the recorded path, the derived path and both remedies (restore the previous agents root, or move the seat deliberately and relocate its record); a row that records none throws `FLEET_SEAT_HOME_UNBOUND` naming the derived path and the bind. Nothing is created on either refusal, and nothing is adopted from the filesystem — a directory that happens to exist under the current root carries no binding authority (today's stray `~/.neo-ai/agents/neo-gpt-sophie` satisfies an existence test as well as the real home does), so only the explicit act names a home (@neo-gpt's three refinements on the ticket, all folded). Today's incident (an ordinary FM restart after Institution #379 minted that stray while her real home sat under the previous root) becomes a refusal with the way out in its message.

Evidence: L2 (pure composer + registry unit arms; the four ACs are unit ACs, no installed Fleet launch is claimed) → L2 required (AC-1…AC-4). Residual: none.

Change class: capability — one new registry field, one registry writer, two refusals in the start composer.

## Deltas from ticket

- The record is a first-class row field, not `metadata`: a Brain-written binding gets a named field with one writer per transition, like `launchOwner`; `metadata` is caller-owned and extensible.
- Recorded at registration, not at first materialization: a row born after this change is never unbound, so the legacy rule below applies exactly to rows that predate it.
- AC-4 replaced per @neo-gpt's refinements (ticket comments 5936002857 and 5936243327): a row without a record does not record the derived home at its next start — latching it would have blessed the fresh empty home the moment the root changed, and an existence test cannot tell the stray from the real one. Such a row is refused until bound explicitly: `relocateSeatHome(id, {from: null, to})`. The move tooling that calls it stays with #571.
- The guard is not conditional on `metadata.repo` (@neo-gpt's third falsifier, comment 5936940542): a repo-less GUI seat still gets its harness home and survivor lease from the current root, so it is guarded like a repo-bearing one; `managedRoot` is therefore required for every curated seat, and a raw `metadata.launch` override — the one row that derives no home — is the only exception.
- The refusal fires on any mismatch between the record and the derivation, not only "where the recorded home still exists": the registry is the declaration (ADR 0041), and a deleted home is relocated deliberately, never re-derived silently.
- `learn/agentos/OwnAgentTeam.md` § *Bring an existing agent into a Fleet seat* gains one sentence: the record, the refusal, the first bind, and that a later move ends with the record rewritten.
