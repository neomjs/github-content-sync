Resolves #589

`FleetManager.setRepo` is now the boundary for a seat's working repo, not its callers.

- The slug must pass the checkout path's own rule. That rule moves out of `deriveAgentRepoPath` into an exported `assertRepoSlug`, which both use: exactly `<owner>/<repo>`, lowercase seat segments, never `.`, `..` or the `harness` owner.
- The clone URL must be a remote naming that repo: https, ssh, or the SCP-like `git@host:owner/repo`. Embedded credentials, plain http, a query or a local source (`file:` or a path) are refused. Without a URL, the verb stores the GitHub URL of the slug.
- A refusal throws before the registry is touched. `{id}` alone still clears the repo.

This closes Eos's action 1 on neomjs/neo-agent-institution#297: no caller can point a seat's harness at a directory or repo it chose. The host stays open by design, because `onboardPeer` onboards non-GitHub remotes (its SCP-like path). Restricting hosts would need a configured allowlist, which this change does not take on.

Evidence: L2 (unit arms drive the verb with every accepted and refused shape against a recording registry) → L2 required. No residuals.

## Deltas from ticket
- The ticket said to derive the URL and refuse any other. The verb instead accepts any remote that names the slug's repo. `onboardPeer` deliberately supports non-GitHub and SCP-like remotes, and a GitHub-only verb would break it. Local sources, credentials and a mismatched repo are still refused.
- The slug rule is the checkout path's own (`assertRepoSlug`), rather than a second regex. It is stricter than the FM's: lowercase only.
