Resolves #579

🌿 *A probe can no longer give up before the timeout it was given.*

`mcpHealthcheck.mjs` bounds connect and the tool call by `--timeout-ms`, which defaults to 8 s, and no compose file passed it. So the 15 s timeout on the base and local planes never applied, and a tool call slower than 8 s failed the check. Every probe command now passes its block's timeout less one second, which bounds each of the probe's operations: the connect, then the tool call. Docker's timeout still bounds the whole check. After the usual sub-second connect, a slow tool call gets about 14 s, and a hung one trips the probe's own timeout, with its timing split, before Docker's. After a slow connect, Docker can end the check first.

Evidence: L2 (unit arms over every real compose command) → L2 required for AC-1 and AC-2. AC-3 is the recreated plane's, post-merge.

## Deltas from ticket

- The dev parity file restates both probes too, so it gets `--timeout-ms 9000`, one second inside its own 10 s. The ticket's sweep named only the base and the overlay. With parity included, one rule holds in every file, and the arm covers them all.
- AC-2 is proven by the deadlines the probe arms when each real command drives it, not by a fake tool call that waits 10 s. That would cost 10 s of wall time per arm, and with a hand-passed flag it would never read the compose files. The ticket's AC text is updated to match.
- The arms sit in the probe spec's every-compose-file sweep, beside `--expected-status`, rather than in DeclaredHeapCeilings' cadence describe. The sweep already strips the overlay's `!override` tags, which a plain `yaml.load` rejects.
- #64's AC-9 now names the 14 s budget.
- The Brain Unit smoke step now executes `mcpHealthcheck.spec.mjs`. Its `--list` step had only collected the spec, so the new arms never ran in CI (Emmy's review).
- The budget is per operation, not for the whole check. The compose rationale, the arms' wording and this body say so, rather than promising the probe always reports before Docker ends the check.
