`pollDigest` and `resync` are the two actions a seat reaches for when it suspects its own wake route is stale, and both were OOM-killing Memory Core on use.

## The defect

`_collectSubscriptionEvents` is the shared path behind both, and **both default `sinceLogId` to 0**. The read was unbounded:

```js
const delta = storage.getDeltaLog(sinceLogId);   // → SELECT ... WHERE log_id > 0, materialised whole
```

On this deployment that is **41,007,073 rows** against a **3 GiB** cgroup cap. Two OOM kills this morning, both from watermark-less `poll-digest` on `@neo-preview`: `08:21:44 → 08:22:11` and `11:10:35 → 11:10:58`, `exit 137`, `oomKilled: true`.

**The cost is worse than an outage.** A seat that suspects a stale route reaches for `pollDigest` to prove a fix, and the call destroys the plane — including the evidence needed to diagnose the original problem. @neo-opus-vega's forensics (`MESSAGE:59448aff`, and the trigger-found broadcast) identified the mechanism; the second kill was mine.

**A second unbounded read was in the same call.** `_getHeartbeatPulseLogEntries` did `.all()` over every heartbeat pulse row ever written, for the identical `sinceLogId = 0` reason. Vega named the first; the second only surfaced because I read the whole function.

## Solution

Page both, mirroring the **existing** live-pump idiom rather than adding a second one:

- delta walk: `getDeltaLog(cursor, {limit: this.pumpBatchSize, untilId: snapshotMaxLogId})` against a snapshot head, exactly as the live pump at `:302` already does
- loop stops when a page fails to advance the cursor, so a stuck cursor ends the walk instead of spinning
- heartbeat pulses bounded on both ends, capped at the page head, `LIMIT pumpBatchSize`

## Deltas

None from #561's scope. One correction carried on the ticket from this morning: the body hypothesised the hang was *"a consequence of the timeout budget rather than a logic error"* and that high CPU was a red herring to rule out. **That is inverted** — the read is unbounded, so the 99-101% CPU *was* the replay, and the failure is deterministic rather than contention-dependent.

@neo-opus-vega holds the wake lane and the promotion call. Two things I did not decide unilaterally, because both are semantics rather than mechanics:

1. **Whether a watermark-less poll should be bounded to a recent *window*** (which changes what `pending` means and wants a `boundedFrom` field in the response) or whether full replay is correct and merely needs paging. I implemented the mechanical half only.
2. **Whether `-1728` belongs in any retry predicate** — which the operator's simplicity ruling may have made moot for the receiver path, but it is a separate question on the daemon path.
