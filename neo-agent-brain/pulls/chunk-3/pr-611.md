Resolves #603

🌿 *A strategic anchor the Brain computed can no longer be lost on the way to the Observatory.*

`get_graph_scene` now answers three node columns aligned with `nodes.ids`. The values are named, never the property bag:
- `gravityWell`: 1 for a REM strategic anchor.
- `strategicWeight`: a number or null.
- `lastActivityAt`: epoch ms, read from the field `GraphService#sceneActivitySources` names for the node's kind.

The answer states that map as `activitySources`: each kind with its `field`, and `sourceCapturedAt: null`. The store keeps no capture time for any source, so each value's freshness is stated unknown (D#19317 B1's "or explicitly unknown"). The Fleet envelope's `capturedAt` is the read's time and never stands in for it. A null `lastActivityAt` reads as a kind without a source when the map omits the kind, and otherwise as a node without a readable field. `projectScene` forwards the columns sparsely and the map as the Brain states it. An answer without them projects exactly as before, so the Observatory on an older Brain stays on W2 (the fallback of neomjs/neo-agent-institution#311).

Evidence: L2 (unit arms over a real SQLite store and the OpenAPI schema) plus a live-store measurement in a sibling probe container (read-only, 1 CPU, 3 GiB, viewer `neo-opus-ada`). L4 after deploy: see Post-Merge Validation.

## Deltas from ticket
- **The source is one per-kind map on the answer, not a per-node `lastActivitySource` column.** The source is a function of kind, so a per-node code could only disagree with it, and the map costs a few hundred bytes instead of a column. #603's Contract Ledger now names this wire.
- **Capture time is stated unknown, per kind.** The store records no per-node or per-source sync time: issues and PRs carry only GitHub's `updatedAt` (census below), and no writer stamps a capture time. Heat can use the event time, and it must treat each source's freshness as unknown.
- **The map covers the kinds the census shows with an event time:** D#19317's four (issues/PRs `updatedAt`, files/directories `mtimeMs`, memories `timestamp`, retrospectives `discoveredAt`), plus DISCUSSION `updatedAt`, TOOLING_GAP/KB_GAP `discoveredAt` and MESSAGE `sentAt`.
- **The cost is +14.0 % on the answer, not the +5.6 % estimated.** The answer grows from 20.7 to 23.6 MiB, and the fleet scene from 47.4 to 51.7 MiB of its 64 MiB budget. A graph about 24 % larger than today's reaches the byte cut.
- **The fleet node carries the columns only where they hold a value.** `gravityWell: true` appears on wells only, `strategicWeight` where it is not null, and `lastActivityAt` on every node of a mapped kind, null included. The scene-level `activitySources` marks a Brain that answers them.
