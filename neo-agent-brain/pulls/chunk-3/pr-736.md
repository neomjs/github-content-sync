The `*File` sibling for the provider keys and the first run's file-writing credential step — the custody shape the recipe needs so no secret value ever crosses the env carrier, the host record, a Compose render or a log:

- **Two leaves** in `ai/configBase.mjs`: `openAiCompatible.apiKeyFile` (`NEO_OPENAI_COMPATIBLE_API_KEY_FILE`) beside `apiKey`, `geminiApiKeyFile` (`GEMINI_API_KEY_FILE`) beside `geminiApiKey` — documented like `providerBootstrapPatFile`, parity snapshot updated in the same commit.
- **One adapter**, `ai/services/shared/secretCarrier.mjs` — `readSecretCarrier({value, file, valueName, fileName, required})`: exactly one carrier may be set (both → an error naming both leaves), the file is read at the call and never at module load, an unreadable or empty file fails naming the file leaf (never the path or the contents), neither set is `''` unless the caller requires a credential. The bootstrap-PAT shape the auth service already keeps, generalized — no fourth custody shape.
- **Read at the use site**: the five `openAiCompatible.apiKey` consumers (`ConfiguredTaskDefinitionsService`, `ConceptDiscoveryService`, `TopologyInferenceEngine`, `SemanticGraphExtractor`, `buildChatModel`'s provider construction and dispatch) and the two `geminiApiKey` consumers (`MemoryService`, `SessionService`) resolve the pair through the adapter; the provider-lane election's exact-receipt guard treats a set file as the mismatch it treats a set value as. No export, no alias, no `?.`, no `process.env`.
- **The credential step**, `ai/services/fleet/credentialStep.mjs` (pure): `composeCredentialEffects({preset, pat, providerKey, secretsDir})` → the secret files (the operator's PAT as the `mcp-auth-token` admission file — bootstrap PAT and healthcheck token, one class; a DISTINCT minted Fleet plane bearer as `fleet-plane-token` — the credential-class ledger forbids one secret serving both; a hosted preset's key as `gemini-api-key`) and the `_FILE` env values (`NEO_MCP_AUTH_TOKEN_FILE`, `NEO_FLEET_PLANE_TOKEN_FILE`, and for hosted `NEO_GEMINI_API_KEY_FILE` + `GEMINI_API_KEY_FILE=/run/secrets/gemini-api-key`); refusals before any write for a missing PAT, a missing required key, a key offered to a local preset, a relative secrets dir. `presetEnvRefusals({preset, configSource, composeTexts})` is the refuse-before-mutation control over the real config and Compose sources (an unconsumed, shadowed or undeclared key refuses with its reason).
- **The profile's custody**: `deploy/cloud/docker-compose.local-agent-os.yml` declares the `gemini-api-key` secret (`${NEO_GEMINI_API_KEY_FILE:-/dev/null}` — a local plane mounts nothing and the leaf stays empty), mounts it on the three provider consumers, and the provider anchor forwards `GEMINI_API_KEY_FILE` as an input.
- **The recipe and the CLI** (#732's surfaces): a `provider-key` question decided by the consented preset (`requiredBy: 'providerKey'` — pending until a preset is chosen, `ok: not needed` for a local one; `answer: 'file'`, so the CLI admits the reference before recording it, the plane credential's rule since #732's Round-1 repair, inherited at the 2026-10-02 rebase), and the CLI's effect block refuses the preset's env set before any write, composes the credentials from the operator's two files, writes the secrets first, then the carrier (paths only), then compose-up. The carrier no longer holds `GH_TOKEN`.

Evidence: L2 (pure adapter, pure step, text-level profile checks; the CLI runs as a child process on a fake host) → L2 required (AC-1…AC-4). Residual: AC-5, Residual-Owner: neomjs/neo-agent-institution#384.

**Edited 2026-10-02 (Round 1, `ab00006`):** the Gemini *embedding* owner (`TextEmbeddingService`) was the one provider-key consumer outside the adapter — its construct and both request guards now read through `readSecretCarrier`, witnessed in four config-isolated child processes (file-only · direct · neither · both); and the CLI's interactive pass re-evaluates after every consent, so a local preset never asks for a provider key (`answerQuestions` exported, witnessed in-process over a prompt stream and as a child-process arm).

## Deltas from ticket

- The plane credential is the ADMISSION token (`mcp-auth-token`: bootstrap PAT and healthcheck token, the overlay's own words), not the Fleet bearer; the Fleet bearer is a distinct mint the step generates, per the credential-class ledger the overlay cites. #732's CLI wrote the PAT as the Fleet bearer — corrected here.
- `GH_TOKEN` leaves the carrier: the corpus-ingestion token is a separate credential from the plane credential and gets its own leaf; the recipe's v1 plane has no ingestion token until then (named on #679's epic).
- Compose custody uses `/dev/null` as the secret's default source so a local plane renders without a key file; the leaf, not the mount, decides whether a key is read — the compose `config` witness is the overlay's text (secret entry, three mounts, the forwarded input), not a Docker run.
- `profileInputs` (from #715) now distinguishes bare inputs (a secret's source path) from env-feeding inputs: a bare input needs no leaf landing; `unconsumedPresetEnvKeys` honours it.
- The guide paragraph lands in `learn/agentos/ModelProviders.md` beside the Gemini credential text.
