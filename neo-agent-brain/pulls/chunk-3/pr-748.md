Resolves #746

The graph-provider readiness probe now presents the lane's key, so an OpenAI-compatible endpoint behind a key can read as ready (measured on Gemini's compat endpoint: a keyless enumeration gets 404 there, before routing).

- **`fetchOpenAiCompatibleModelIds`** takes an optional `apiKey` and sends it as `Authorization: Bearer` (the embedding canary's shape). A failure carries the HTTP `status`.
  - It asks `${host}/v1/models`, composed as the client composes `${host}/v1/chat/completions`, so a hosted prefix (`/v1beta/openai`) stays. `new URL('/v1/models', host)` dropped it.
  - The discovery cache and in-flight coalescing are scoped by a fingerprint of the key (`anonymous` without one), so a credential is never served another's answer. The key itself never enters the cache key.
- **`checkProvider`** and **the identity axis** (`DeploymentStateBridgeService.collectProviderModelIdentity`) read the key through `readSecretCarrier` where they use it (ADR 0019 §5.1).
  - Both carriers set is the carrier's own error, never folded into "not ready". `checkProvider` throws it; the identity axis reports it verbatim as `unobservable`, without asking the endpoint.
  - The identity axis names a 401/403 as the key: either "refused the lane's key" or "wants a key, and the lane has none".
  - Its key comes through a `providerModelIdentityKey` seam beside `providerModelIdentityProbe` (`null` reads the carriers), so its spec writes no shared AiConfig.
- The LM Studio liveness probe and the model-load path stay keyless, as the ticket scopes.
- Three pre-existing `#29` references in `providerReadinessHelper.mjs` comments are reworded, because the archaeology gate audits whole changed files.

Evidence: L2 (unit, red-first, against a local HTTP endpoint that answers 401 without the bearer) → L4 required for AC-3 and AC-4 (an operator key on a hosted plane). Residual: AC-3 and AC-4, owned by neomjs/neo-agent-institution#351 (see Post-Merge Validation).

## Deltas from ticket

- **The cache is scoped per credential.** The ticket didn't name this. The routine cache and force coalescing share answers by key, so without the scope one key's 401 (or another key's model list) could answer a different caller (Round 1 RA-2).
- **The enumeration keeps the host's path** (Round 1 RA-1). Out of scope, noted in defect-note `0a5c8120`: the embedding canary's `new URL('/v1/embeddings', host)` drops the same prefix.
