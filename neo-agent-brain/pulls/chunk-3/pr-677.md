Resolves #621

The drain-loop arm in `drainCycle.spec.mjs` ("the loop host runs the after-cycle hook once per completed cycle") waited a fixed 80 ms and then demanded two published cycles. A loaded runner can spend that window inside the first poll, and #620's `unit` job read it as a failure the PR never caused. The arm now polls the summaries the loop has published (`expect.poll`, the suite's idiom in 13 spec files) and stops the loop once two have landed. It was the file's only wall-clock wait.

Evidence: L2 (the arm under a simulated slow cycle: dev's form red, this form green) → L2 required. Residual: none.
