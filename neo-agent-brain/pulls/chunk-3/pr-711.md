Resolves #710

A seat's repository now says which forge it lives on, and a GitLab project in nested groups can be registered. This is leaf 1 of #684 (the Fleet's GitLab parity), with @neo-opus-ada's three amendments built in.

- **`FleetManager.repoCoordinates`**, the rule `setRepo` and `setRepos` share, takes `forge`:
  - `github` is the default and is never written. It is exactly `owner/repo`, with the `github.com` clone URL as default.
  - `gitlab` is recorded, may name nested groups, and must name its clone URL, because a self-hosted host cannot be derived.
  - An unknown forge refuses.
- **`deriveAgentRepoPath`** accepts any validated depth (`<root>/<agentId>/group/sub/project`), so its three callers (`ensureAgentRepo`, `inspectFleetRepos`, `removeAgentRepo`) are unchanged. How deep a forge may go is the registration rule's job, not the path's.
- **`assertNoCheckoutCollision`**: `setRepo` and `setRepos` refuse a seat set whose checkouts would share a path or nest one inside another, across the working repository and the extras, and across forges. The refusal names the rule, never the values.

Evidence: L2 (unit, red-first against dev's sources). Residual: none. This leaf has no installed surface; leaves 2 and 3 carry one.

## Deltas from ticket

- **GitHub's forge is implicit:** AC-1 reads "records its forge (`github` by default)". Writing `github` explicitly would change every existing record and GitHub arm, so only `gitlab` is written, and readers treat an absent forge as GitHub.
- **The path helper's contract widens on purpose.** `deriveAgentRepoPath.spec`'s "exactly `<owner>/<repo>`" arm becomes "`<owner>/<repo>` or deeper". `neomjs/neo/extra` moves from the refused list to a derived nested path, and `group//project` joins the refusals. A GitHub registration still refuses three segments (AC-2's arm).
- **The `setRepo` arms' registry stub gains a non-recording `getAgent: () => null`,** because `setRepo` now reads the seat's other repositories for the collision rule. No assertion changed.
