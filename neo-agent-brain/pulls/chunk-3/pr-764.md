Resolves #760

The first leaf of #759 (graduated from neomjs/neo#19122). One producer observes every open pull request on the repositories the Fleet's seats work on, and projects each seat's open work. It is observe-only: it holds no mailbox client and wakes no one. Its first real day gates the wake leaf, #761.

- **`openWorkReducer`** is pure: no fetch, no clock, no mailbox.
  - **Normalizing.** It turns the search nodes into rows. Each row's owner is the body's `Authored by` seat. An org account without that line is `unowned`, never silently its login.
  - **Transitions.** Two snapshots become the transitions between them, and a transition's identity is its observation. So red → green → red is two red episodes, and an identical poll records nothing.
  - **Merges and closes** come only from the terminal read, once each, and only when they happened since the watermark. A PR missing from the open read is never one.
- **`openWorkProducer`** runs the pulses.
  - **The reads** are page-budgeted: open PRs, then merged or closed PRs since the watermark.
  - **Coverage:** a cut-off page or a truncated review-request list leaves the pulse `partial` and holds the watermark. A failed read is `stale` over a snapshot and `unavailable` without one.
  - **The record** is a bounded window of transitions plus each pulse's cost and per-seat counts. The state survives a restart through a JSON file beside the registry.
- **`fleetOpenWorkSource`** projects each seat's authored PRs and requested reviews under the producer's own freshness: `ok`, then `stale`, then `unavailable`, never "no open work".
- **The wiring.** `wireFleetOpenWorkSource` starts the producer in `devFleetServer` (the host edge) and serves the new read verb `fleetOpenWork`. The verb is classified `read-observe` / `awaiting-s3`, like `fleetTasks`.

Evidence: L2 (unit; the GitHub reads are stubbed at the injected `query`) → L2 required for AC-1–AC-4. Residual: AC-5's real observe-only day is Post-Merge Validation.

## Deltas from ticket

- **The scope is the registry's GitHub repositories, not a fixed list.** The Brain serves other tenants, so the producer reads the repositories its seats work on (`metadata.repo` + `metadata.repos`, GitHub only). For this deployment that is the same five repositories.
- **Seat identity:** a login resolves from the registry's seats first (`@<githubUsername>`), then `identityRoots`; a social name resolves through `identityRoots` (the registry stores no display name).
- **The GitHub token is resolved at the entrypoint** with the existing `resolveGithubToken` (`GH_TOKEN`, then `GITHUB_TOKEN`). No AiConfig leaf binds it. Checked against ADR-0019's catalog, A1/C1 do not apply. Without a token, every pulse answers its reason.
- **A failed read follows the fleet convention:** a constant `reason` plus a `redactReadFailure` detail.
- **The read verb needed both policy ledgers** (`FLEET_S1_METHOD_POLICY`, `FLEET_METHOD_SCOPE_CLASSES`) and the pinned allowlist spec.
