Resolves #760

The first leaf of #759 (graduated from neomjs/neo#19122). One producer observes every open pull request on the repositories the Fleet's seats work on, and projects each seat's open work. It is observe-only: it holds no mailbox client and wakes no one. Its first real day gates the wake leaf, #761.

- **`openWorkReducer`** is pure: no fetch, no clock, no mailbox.
  - **Normalizing.** It turns the search nodes into rows. Each row's owner is the body's `Authored by` seat. An org account without that line is `unowned`, never silently its login. A row carries each reviewer's latest review and whether it judged the current head.
  - **Transitions.** Two snapshots become the transitions between them, and a transition's identity is its observation. So red → green → red is two red episodes, and an identical poll records nothing.
  - **New rows.** A new PR reports the reviews already requested on it. A row first seen after a read that missed pages may only have been unread, so it is no `opened`.
  - **Partial request lists.** A truncated or missing list adds to the last complete list and removes no one.
  - **Merges and closes** come only from the terminal read, once per close time; a reopening retires the marker. A PR missing from the open read is never one. One that leaves complete reads with no terminal row is recorded as `vanished` on its pulse.
- **`openWorkProducer`** runs the pulses.
  - **No overlap.** One pulse runs at a time: a pulse asked for while one runs is that pulse.
  - **The reads** are page-budgeted: open PRs, then the PRs closed in a fixed window of close times. The window resumes at its cursor across pulses and restarts. The watermark moves only once the window completes, and then to 10 minutes before its end: GitHub's search index can lag a close past the window that should have read it.
  - **Coverage:** an answer without its page structure is a failed read. A cut-off page or a truncated list leaves the pulse `partial`; the first pulse starts the watermark either way. A failed read is `stale` over a snapshot and `unavailable` without one, and its pulse keeps the cost of the requests that answered.
  - **The record** is a bounded window of transitions plus each pulse's cost and per-seat counts, kept in a JSON file beside the registry. An existing file that can't be read leaves the producer `unavailable` and is never saved over.
- **`fleetOpenWorkSource`** projects each seat's authored PRs and requested reviews under the producer's own freshness: `ok`, then `stale`, then `unavailable`, never "no open work". Each row is aged by its own observation, and a carried row past the unavailable bound leaves the projection and is counted in `unobserved`.
- **The wiring.** `wireFleetOpenWorkSource` starts the producer in `devFleetServer` (the host edge) and serves the new read verb `fleetOpenWork`. The verb is classified `read-observe` / `awaiting-s3`, like `fleetTasks`.

Evidence: L2 (unit; the GitHub reads are stubbed at the injected `query`) → L2 required for AC-1–AC-4. Residual: AC-5's real observe-only day is Post-Merge Validation.
