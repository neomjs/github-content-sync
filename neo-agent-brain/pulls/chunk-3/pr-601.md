Migrates the two retired `ticket-ref-ok` escapes in `src/composition/orchestrator/hostEdgeProfile.mjs` to the typed, token-bound form. First leaf of #599, filed as the pattern-proving leaf because it is the smallest site in the tree.

## What was actually here

Neither site excuses a numeric ref. Both defend a prose `ADR 0019`, and the file contains **no `#N` token at all** — so the obvious find-and-replace has no anchor to bind to, and the section number (`§10.8`, `§10.7`) is prose the author wrote rather than part of the bound token. `ADR NNNN` is a supported typed-escape token via `NAMED_ADR_REF_SOURCE`, so both migrate with the section number moved inside the reason.

## Two constraints the tickets did not state, found by running the guard

1. **The escape must be contained on one line.** The guard splits comments per line, so a reason that wraps leaves the token unexcused and the site still reports. Isolated with a four-way control — whole-escape-on-one-line, minimal-escape, escape-on-its-own-line, and the original legacy form — where only the original-legacy variant reports. My first probe tested nothing (it moved a word but left the closing bracket on the next line) and I only caught it because the control still went red.
2. **The guard cannot see prose integrity.** An intermediate edit deleted the subject `This module is a` from the following sentence and the guard reported **0 violations**. AC6 exists because the gate is blind to it; it was verified by reading the whole docblock, not a window.
