Resolves #727

A GitLab seat runs `gitlab-workflow` with its own token, instance and project, and never sees `GH_TOKEN`. This leaf of #684 lands before the default flip (#729), which would otherwise turn on a server the plan refused and the envelope could not place.

- **Spawn (`FleetLifecycleService.start`):**
  - A GitLab seat's PAT goes to `NEO_GITLAB_PAT`, beside `NEO_GITLAB_HOST` (its `forgeHost`) and `NEO_GITLAB_PROJECT`. The project is set only when the working clone is on that instance: an `https` clone by exact origin (scheme, host, port; IPv6 normalized), an `ssh` or scp-style clone by host, since SSH has its own port.
  - A GitHub seat is unchanged.
  - The three slots join the reserved set, so a launch env cannot pre-load them, and an envelope that carries one refuses the start.
- **Envelope (`resolveResidentMcpEnvironment`):** `gitlab-workflow` maps to its config module. Every descriptor now declares `seatEnv`, the values the Fleet injects per seat, and their union replaces the hard-coded exclusion list. So `exportEnv` sends the plane slots and never the host's own `NEO_GITLAB_*`.
- **Plan (`managedAgentWorkspacePlan`):** the descriptor's `unsupportedReason` is gone, and `mcpDeclarationRefusal` takes the seat's `forge`. It refuses `gitlab-workflow` on a seat not bound to GitLab, and on Kimi and OpenCode, whose seat configs filter a fixed list that lacks it. The plan's agent intent carries `forge` only for a GitLab seat, so a GitHub plan is unchanged.
- **Catalog:** the two workflow entries name their `forge`. #729 derives the defaults from it.

ADR 0019 was read in full before this touch. Per-seat values are injected at spawn, and plane slots travel through `exportEnv` as process serialization.

Evidence: L2 (unit, red-first). Residual: AC-4 (installed, owned by #684).
