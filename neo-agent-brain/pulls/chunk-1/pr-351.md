Refs neomjs/neo#17783 — non-closing: the owning ticket lives in the engine repository, and this is the first of its R3 steps.

Run against its **correct** root, `lint-guard-ci-parity` produced exactly one finding against `neomjs/neo`, and that finding was false. `check-relative-links.mjs` is mirrored by `.github/workflows/check-relative-links.yml:51`. The guard could not see it, for two compounding reasons.

## Deltas

**npm-script indirection.** Only `run:` steps spelling out a direct `node … <script>.mjs` counted, so `npm run check-relative-links` read as *no mirror at all*. `npm run <name>` now resolves through `package.json`, and the resolved command faces the **same** single-statement, unmasked, direct-`node` classifier. The indirection is followed; nothing is relaxed. A chained (`a && b`), masked (`${{ … }}`) or multi-line script still counts as nothing, so the false-**green** family the original note protects against stays closed. A `seen` set stops a script that runs itself.

**Filename as eligibility.** Only `*-lint.yml` workflows were inspected. That filter was a **proxy** for *"gates dev pull requests"* — which the guard already checks directly one line later. The name bought nothing and cost a false red on every correctly-mirrored guard whose workflow is named for its subject (`check-relative-links.yml`) rather than its category.

Both header notes are updated. The original stated the false-green risk it was avoiding and left the false-red cost unstated; when a tool documents which error it chose to avoid, it is telling you which error it chose to accept, so the new text names both.

**The first two commits of this PR reported "before 1, after 0" and that was wrong.** @neo-opus-vega's RA-1 found it: the mirror the widening newly credited, `check-relative-links.yml`, is filtered to `learn/**` and `*.md`, so a PR moving a link target in `buildScripts/**` matches nothing and the workflow never runs — the filter defeats the motivating case its own header states. **The finding was real; the guard's reason for it was wrong.** Both are now fixed rather than one masking the other.

The honest count against `neomjs/neo` is **eight** guards whose only mirrors are path-filtered:

`check-content-logical-identity` · `check-engine-brain-boundary` · `check-fixed-sleeps` · `check-jsdoc-types` · `check-relative-links` · `check-theme-coverage` · `check-theme-value-files` · `check-ticket-archaeology`

**Not all eight are defects, and this guard cannot tell which are.** `ticket-archaeology-lint.yml` filters to exactly that guard's own `DEFAULT_SCAN_PATHS`, carrying a comment that a wider trigger would pass vacuously — correct scoping, not a gap. Adequacy is judged against a guard's *effective scope*, which is guard-specific knowledge this tool does not have and should not guess.

So the resolution uses the mechanism that already exists rather than inventing a category: **each conditional mirror earns a registry row with a reason and a witness, or a fix.** Nothing is credited silently, nothing is red without being named, and whether a given path filter is adequate lands with the consuming repository. That authoring happens in `neomjs/neo` at relocation, where the knowledge lives.
