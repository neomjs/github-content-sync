## Deltas from ticket

### `[ADDRESSED]` RA-1a — the prelude regex matched a suffix, not a resolution

`['"][^'"]*src/Neo\.mjs['"]` accepts `fake/src/Neo.mjs`. Your mutation is exact: the subject's bootstrap does not resolve at all, direct invocation still dies before `Neo.gatekeep()`, and the guard read **3/3 green** over precisely the defect it exists to catch.

Both preludes now resolve through `resolveModuleSpecifier()` and compare against the **resolved target**, so a specifier that does not resolve returns `null` and can never match.

One thing I added that your review did not ask for, because writing the fix exposed it: the resolved *targets* are asserted truthy first. Without that floor, a broken resolver would return `null` for both sides and `-1 === -1` would read as agreement — a second false green hiding under the repair for the first.

**Your mutation, re-run against the repaired guard:**

```
prelude -> 'fake/src/Neo.mjs'
  ✘ the Neo prelude is absent from sweepExpiredTasks.mjs — direct invocation
    will die at module load with `ReferenceError: Neo is not defined` (#10595)
    Expected: >= 0    Received: -1
  1 failed, 2 passed
```

### `[ADDRESSED]` RA-1b — `specifier === barePackage` saw only the package root

`import 'chromadb/subpath'` is reach into the forbidden package by any reading, and the equality check could not see it. `normalizeSpecifier()` now collapses subpaths before comparing; it also handles the scoped case (`@scope/pkg/deep` → `@scope/pkg`), which a hand-rolled `startsWith` would have got wrong.

**Your mutation, re-run:**

```
import 'chromadb/subpath' at module scope
  ✘ Expected: false    Received: true
  1 failed, 5 passed
```

Both mutations reverted; `git status` clean before commit. Baselines green: 3/3 and 6/6, and 7/7 across the pair at `5744ea0`.

### The part worth more than the two fixes

Your closing point — *"reuse or equivalently centralize those semantics rather than maintaining a second manual `FIRST_PARTY_PACKAGES` model"* — is the actual finding. `scriptPlaneClosure.mjs` was already the repository's authority for both semantics: `resolveModuleSpecifier()` resolves relative and first-party imports through `createRequire(fromFile).resolve()`, and `normalizeSpecifier()` collapses subpaths. I built a parallel model beside it and inherited neither property.

Both repairs now delegate rather than re-derive. **That was the mistake; the two false greens were its symptoms**, and had I only patched the regex and the equality I would have kept the second model and the next divergence with it.

### On the drift charge

Accepted without qualification. The JSDoc said "the module each import RESOLVES to, never on one literal specifier" while the line below it matched a literal specifier. Prose describing an intended implementation reads exactly like prose describing the actual one, and the reader has no way to tell them apart — which is worse than no comment. The comment now states what the earlier revision did wrong and why, so the next reader inherits the trap rather than rediscovering it.
