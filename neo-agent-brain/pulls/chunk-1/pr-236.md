### 🔬 Depth Floor

**Challenge OR documented search (per guide §7.1):**

- **Challenge**: *Does the manifest audit retire any capability something still depends on?* This is exactly where a "declarative-only" PR can quietly remove working surfaces. I enumerated all 26 `ai:*` scripts dropped from the Host root, then grepped `.github/`, `ai/scripts/` and both manifests at exact head for every one:

```

 3 present in cloud/package.json   ai:fleet-healthcheck · ai:provider-lane-composition · ai:provider-lane-election
23 present in no manifest
 0 dangling references anywhere    <- nothing breaks; ai:structure-map survives
```

**Two things worth watching, neither blocking.**

**(1) Six guards lose their only handle.** Of the de-aliased set, ten are lint/check scripts whose files all still exist. For six — `lint-npm-script-entrypoints`, `lint-agents`, `lint-guides`, `check-front-door-fingerprint`, `lint-tree-json`, `check-identity-facts` — nothing at head reaches them by alias or by path. **I ran the control before concluding: on `origin/dev` the npm alias was already their only handle.** So this is *not* an enforcement regression — they were never CI-wired and no working guard is being retired. What changes is that the last way to run them by name is gone. The honest reading is the one the audit surfaced: **a guard nobody can run is not a guard.** Worth a follow-up that CI-wires or explicitly retires them, so the next reader does not find six lint files and infer coverage. (Three others — `lint-identity-engine-coherence`, `lint-fleet-vocabulary-parity`, `check-substrate-size` — *are* reachable through callers and a registry, which is what made the instrument trustworthy rather than uniformly negative.)

**(2) The `cloud/` self-pin will drift silently.** `cloud/package.json` depends on `neo-agent-brain` at archive `c7be03eae…`, **33 commits behind `origin/dev`** as of this review. Nothing — no lint, no spec, no body line — asserts that pin tracks anything. CI is immune via the HEAD-tarball override noted in the Evidence Audit, but a non-CI `npm ci` in `cloud/` installs a 33-commit-old Brain. Deliberate pinning of a known-good revision is legitimate; the gap is that it is *undeclared*, so a reader cannot distinguish a deliberate pin from a stale one. One body line or one assertion closes it. I am carrying this into #12 rather than asking for it here.
