Resolves #371

🪢 *Two Neural Link tools failed on first contact, and both errors pointed away from the cause: `get_route_history` rejected every window id it was ever given, and `manage_connection start` answered with a refused socket for a Bridge whose spawn had already recorded why it died.*

## What changes

- **`openapi.yaml`, `get_route_history`:** the response `windowId` is a `string`. It was the only `windowId` in the document typed `integer`; window ids are UUIDs, so the MCP output gate rejected every call.
- **`ConnectionService#ensureBridgeAndConnect`:** when the connect after a spawn fails and that spawn recorded a failure, the start fails with `createSpawnFailureError()` — the code (`BRIDGE_EXIT_1`), the script, the cwd and ADR-0040's `--cwd` rule, with the socket error kept as `cause`. With no recorded failure the connection error passes through untouched.
- **`ConnectionService#getCwdFinding`:** an assigned `cwd` whose `package.json` was read and defines no `ai:server-neural-link` is `BRIDGE_CWD_MISSING_SCRIPT`. It rides `getStatus()` and the healthcheck's `bridge.cwdFinding` before any spawn, and `spawnBridge` refuses there with the same rule. One read per assigned cwd.
- **`openapi.yaml`, `execute_dock_operation`:** the description names no operation list and points at `get_dock_topology`'s `operations` (verified: `src/ai/client/DockService.mjs#getDockTopology` returns that field). `HealthCheckResponse.bridge` now declares `spawnFailure` and `cwdFinding`.

No AiConfig leaf is read, added or threaded: `--cwd` stays the entrypoint-injected value it was (ADR-0019 read before the first edit; ADR-0040 `agentosRuntimeRoot` row).

Evidence: L3 (the real Neural Link entrypoint as a child process, driven over its real stdio MCP transport — run locally, see the CI note below) → L3 required (AC-2, AC-3); AC-1 and AC-4 are properties of the OpenAPI document and are checked against it. Residual: none.

**What CI executes, stated plainly:** `Brain Unit` runs a fixed smoke list of 8 specs (`.github/workflows/brain-unit.yml`). Of the three specs this PR touches only `ConnectionService.spec.mjs` is on it. The arms in `bridgeAutoConnectOrdering.spec.mjs` and `OpenApiValidatorCompliance.spec.mjs` are **outside CI** until the retained suite runs there (#201) — a green check here says nothing about them, so their receipts are under Test Evidence.

## Deltas from ticket

- **An unreadable `package.json` is no finding.** The ticket's check is "its `package.json` must define the script". A first cut made every unreadable manifest a finding, and that silently changed `#16429`'s survivability witness: an absent `--cwd` was refused before the spawn, so healthcheck lost `spawnFailure: 'ENOENT'`. A finding now needs a manifest that WAS read and lacks the script; a directory that does not exist keeps the attribution its spawn already has. No existing arm had to change.
- **The healthcheck carries a code, the error carries the path.** `getStatus()` documents that the payload holds no host paths, so `cwdFinding` is `BRIDGE_CWD_MISSING_SCRIPT`; the cwd itself appears only in the refusal and the start error, as the ticket's ledger asks. An arm asserts the payload does not contain the path.
