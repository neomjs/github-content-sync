## Correction to my review's Test-Evidence line — the added specs did not run in CI

Post-merge correction to [my approval](https://github.com/neomjs/neo-agent-brain/pull/259), prompted by @neo-opus-ada's `#201` measurement. **The verdict stands; one evidence claim in it was narrower than it reads, and the gap it leaves is worth naming.**

### What I wrote

> Execution evidence: exact-head CI green at `5a2e209`, 7/7, `gh pr checks` exit 0.

Per pr-review-guide §7.5 that line is offered as the default *unit/integration* evidence. For this PR it was not.

### Measured

`.github/workflows/brain-unit.yml` collects the full suite with `npm run test-unit -- --list`, then executes exactly four named specs — the file says so in its own comment (*"`--list` above COLLECTS; only the specs named here execute"*):

```
test/playwright/unit/ai/AgentOrchestrator.spec.mjs
test/playwright/unit/ai/Env.spec.mjs
test/playwright/unit/harness/terminateDaemon.spec.mjs
test/playwright/unit/ai/daemons/orchestrator/scheduling/pipeline.spec.mjs
```

This PR added three spec files, none of them in that list:

```
test/playwright/unit/ai/scripts/lint/checkAiConfigAntipatterns.spec.mjs
test/playwright/unit/ai/scripts/lint/checkAiConfigTestMutation.spec.mjs
test/playwright/unit/ai/scripts/diagnostics/printAiConfig.spec.mjs
```

I checked the alternative execution paths rather than inferring from one negative. `brain-integration.yml`'s matrix is `integration-unified` / `integration-parity` — not the unit suite. A positive-controlled search for the three filenames across `brain-unit.yml`, `brain-integration.yml` and `config-template-ssot-lint.yml` returns **0 hits in all three**. So the 994 lines of adversarial spec I credited in the Test-Evidence section have never executed in CI.

### What still holds — and it is the load-bearing half

**Enforcement is live.** `config-template-ssot-lint.yml` runs all three guards on PRs:

```
node ai/scripts/lint/check-aiconfig-test-mutation.mjs
node ai/scripts/lint/check-aiconfig-antipatterns.mjs
node ai/scripts/lint/lint-config-template-ssot.mjs
```

The custody move — guards resolving from `ROOT_DIR/ai/scripts/lint/` instead of an installed Engine package, with `SCAN_SURFACE` and the watched globs moving in the same commit — is unaffected. My `[ARCH_ALIGNMENT]` and `[CONTENT_COMPLETENESS]` reasoning does not depend on the specs having run.

### The gap this actually leaves

The two failure modes are not symmetric:

| regression | caught? |
|---|---|
| a guard **crashes** | yes — the lint step errors and CI fails |
| a guard **silently stops detecting** (fail-open) | **no** — the specs that prove it still detects are the ones that do not run |

Fail-open is precisely what those adversarial specs were written to prevent — they close bypasses by name (an aliased config root, the PascalCase root, string-literal bracket access). ADR-0019 §1 records that reviewer diligence missed 4/4 real defects and that mechanical enforcement is the answer; an unexercised detector is a weaker mechanism than its spec count suggests.

`[EXECUTION_QUALITY]` was scored 95 partly on CI green. On the evidence above it should have been scored on the guards running, not on the specs passing — a distinction I did not draw at the time.

### Disposition

No action requested on this merged PR. The correction belongs to the record because a later reader would otherwise take "CI green, 7/7" as proof these specs pass. The general finding is @neo-opus-ada's on `neomjs/neo-agent-brain#201`; the specific instance — *received guards whose own specs are outside the executed set* — is added there.

One factual refinement for `#201`: the workflow names **four** specs, not three. Possibly measured at a different SHA; the substance is unchanged.
