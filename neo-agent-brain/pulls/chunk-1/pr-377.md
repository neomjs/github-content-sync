Resolves #375

The fleet registry records who launches a seat, so the cockpit can start a fleet-launched seat the first time. Blocking half of neomjs/neo-agent-institution#171, the v13.2 FM §04 bar; the decision between the candidates is [comment 5742353369](https://github.com/neomjs/neo-agent-institution/issues/171#issuecomment-5742353369).

- **`launchOwner: 'fleet' | 'external'`** is a first-class registry field. An absent value reads `external` in `toPublic`, which covers every existing row and `onboardPeer`'s Phase A. It is kept out of `metadata`: it enables a Brain-credentialed spawn, and `metadata` is a merge surface.
- **`defineAgent`** takes it as creation intent. Only the cockpit's define intent will send `fleet`; any value other than `fleet` or `external` is refused before a write.
- **`setLaunchOwner(id, owner)`** is the one write after birth, and records `launchOwnerSince`. `FleetManager#adoptAgent` / `#releaseAgent` expose it as facet verbs beside `setRepo`, on `FleetControlBridge` and in `FLEET_WIRE_METHODS`. `updateAgent` cannot reach the field, and `configureAgent`'s curated allowlist refuses it.
- **`fleetRuntimeStatus`** reads a fleet-owned seat with no process record as `stopped`, `confidence: 'inferred'`, with a reason saying why. External rows stay `unmanaged` / `none`, and a process record, once present, wins as `observed`. `fleetCockpitStatus` already treats any non-`unmanaged` row as supervised, so the cockpit side needs no Brain change.

Evidence: L1 (unit, the registry on a temp `dataDir`, the manager and the bridge on recording stubs) → L1 required (a registry fact, two delegating verbs, one status rule). Residual: the cockpit's §04 journey, Residual-Owner: neomjs/neo-agent-institution#171.

agent-preflight (`--change-class capability`, check-only): all requested gates passed — ticket archaeology 0 violations over the 5 source files, `feat` matches the declared class for both subjects, body anchors present, stacked tickets consistent.
