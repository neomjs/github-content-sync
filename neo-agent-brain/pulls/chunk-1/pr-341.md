### 🔬 Depth Floor

**Challenge — the finding, and it is the whole review:**

`InstanceService.mjs:355`

```js
async forwardTransaction(method, {sessionId, groupId, ...payload}) {
    if (groupId !== undefined) {
        sessionId ??= ConnectionService.getDefaultSessionId();   // ← here
```

`getDefaultSessionId()` is `Array.from(this.sessionData.keys()).pop()` — **the most-recent session, chosen silently.** `ConnectionService.call` normally routes every target through `resolveCallTarget`, which says:

```js
if (liveSessionIds.length > 1) {
    throw new Error(
        `Auto-targeting is disabled with ${liveSessionIds.length} live sessions: pass an explicit ` +
        'sessionId. Silent most-recent targeting is unsafe with concurrent writers.'
    )
}
```

**The guard forbids by name exactly what `getDefaultSessionId` does.** And because the default is assigned *before* `call`, `resolveCallTarget` sees a truthy explicit target and returns at its line 19 — the ambiguity branch is never reached.

**Concrete failure:** two live App Worker sessions, `undo({groupId})` with no `sessionId`. On `dev` this throws *"Auto-targeting is disabled with 2 live sessions"*. On this head it silently undoes against whichever session was registered last. **A refusal becomes a coin flip.**

It matters more than a generic hazard because it lands on the **dock Group** path. Dock groups are the multi-window feature — concurrent writers are the normal case there, not the edge case, which is the exact condition the guard's own error message names.

The non-`groupId` branch is unaffected: it passes `sessionId` through untouched, so `undefined` still reaches `resolveCallTarget` and is still refused correctly. **The bypass exists only on the new path.**

`saveTransaction:244` does the same thing (`sessionId ?? getDefaultSessionId()`) for `appSessionId`, and additionally resolves the session **twice by two different rules** in one method — that one is cosmetic today but will diverge.

**Rhetorical-Drift Audit:** N/A — no architectural prose added beyond `@summary` lines, which describe behaviour accurately.
