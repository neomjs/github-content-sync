Resolves #305

Related: #29, #253

Repeated equivalent LM Studio additive-load failures now have a terminal disposition. The process-shared guard records failures only after identifier-collision adoption declines, opens after three equal failures for the same host/model/load shape, suppresses further load children, and admits one half-open probe after 15 minutes. Admission reserves the next cooldown before caller code runs, so a required authority/effect rethrow cannot leave the elapsed window open to every later cycle. Sufficient residency, a successful load, a changed load shape, or an observed runtime-selection change re-arms it; an unreadable runtime table does not. The readiness result carries bounded failure/circuit evidence, and the provider-agnostic supervisor forwards the task-owned operator summary into its normal log without restarting a live LM Studio server.

Evidence: L2 (unit composition + mutation control; an unmerged Brain branch cannot run on the pre-cut host edge) → L3 required (live host-edge circuit receipt). Residual: AC9, Residual-Owner: #253.

### 📋 Required Actions

- [ ] **The half-open cooldown is not enforced by the guard.** `recordFailure` is the only writer of `nextAttemptAt`. `beforeAttempt` admits a half-open attempt (`!state.terminal || currentTime >= state.nextAttemptAt`) and returns `{admitted: true, halfOpen: true}` **without mutating state**, so the documented *"one half-open load is admitted per cooldown"* holds only while every admitted attempt terminates in `recordFailure` or `clear`.

  It does not. At the call site, the `catch` rethrows before either:

  ```js
  if (error?.reason?.startsWith('runtime-authority-') || error?.reason?.startsWith('runtime-effect-')) {
      throw error;
  }
  ```

  **Failure scenario:** a model reaches terminal state; `halfOpenAfterMs` elapses; the next readiness run is admitted half-open; `invokeLoadModel` throws a `runtime-authority-*` error. Nothing is recorded, nothing cleared, `nextAttemptAt` stays in the past and the state stays terminal — so **every subsequent readiness run is admitted again**, indefinitely. The circuit stops bounding precisely the failure class that recurs identically, which is what it exists to bound.

  The rethrow itself is correct and should stay — a runtime-authority violation must propagate, not be absorbed into a retry budget. Per the `#14275` precedent the fix belongs in the guard: advance `nextAttemptAt` at admit time when `state.terminal`, so the cooldown rides out regardless of how the attempt ends. That makes the invariant guard-owned, which is what the JSDoc already claims.

- [ ] **Add the arm that would have caught it.** The five new arms cover half-open → `recordFailure` and collision → adopted, but none covers *admitted-then-neither*. An arm that calls `beforeAttempt` on a terminal state past its cooldown, records nothing, and asserts the next `beforeAttempt` is **refused** would fail today. Absence-of-side-effect is the only shape that proves a terminal path did not quietly re-admit.
