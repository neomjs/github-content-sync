Resolves #360

🌿 A gate can no longer answer *"is the binding here?"* by naming the output of a build step that no longer runs.

`hasBrainTier` required `build/Release/better_sqlite3.node`. `better-sqlite3@13.0.3` deleted the `install` script that created it — and the `prebuild-install` dependency behind it — in favour of eight prebuilt binaries shipped in the tarball at `prebuilds/<target>.node`. So the gate read a complete, healthy tier as a partial one and failed #357 before collection: a guard whose entire purpose is refusing a silent skip, raising a silent false alarm instead. It now names every location the package's own loader tries, which makes it version-agnostic in both directions rather than correct for one major at a time.

Evidence: **L2** (the exact CI smoke invocation run locally — 136 passed, exit 0, all 8 arms executing; every arm mutation-verified against the pre-fix implementation; full local unit suite run twice for a like-for-like control) → L2 required — the close-target ACs are all about what the gate admits and rejects, which is exercisable in this checkout. Residual: none on the close target; the post-merge row below is observation, not deferred work.

## Deltas from ticket

**One scope addition, one prescription rejected, one AC amended** — all three recorded on #360 itself rather than only here.

- **Added: smoke-list inclusion.** `brain-unit.yml` runs `npm run test-unit -- --list` (collection only) plus seven named specs; `playwrightConfigUnit.spec.mjs` was not among them. The ticket's Out-of-Scope clause said touching this workflow "would mix a workflow edit into a guard fix" — written about a cosmetic step rename, and it does not survive contact with a guard that would never execute where the false negative happened. The workflow states the criterion one line above the list: *"A cross-PR drift detector is worthless outside this list, so it belongs in it."*
- **Rejected: delegating to `better-sqlite3`'s exported `getPrebuildPath()`.** Circular — the gate exists to answer *"is this package installed?"*, so importing from that package to find out fails exactly when the answer is no. It must also stay sync and non-throwing before collection, and it removes nothing: `getPrebuildPath()` returns `null` when no prebuild matches, so the `build/` fallbacks are needed either way. The target string is mirrored instead, with upstream named in the JSDoc as the authority and the arms pinning it against literals.
- **Not added: an arm asserting this spec's own presence in the smoke list.** It cannot produce the failing result for the case it would guard — removed from the list, CI never runs the spec, so the arm never fires. A guard blind to its own removal is worse than none, because it reads as coverage.
