Which `.env` a shell loads — and therefore which GitHub identity `gh` writes as — was decided by a `case` block in an untracked, unreviewed, untested host dotfile. ## Deltas from ticket

**Seats are declared relative to a base, not as absolute paths.** A host's seat roster is machine-specific and this repository is deployed by people who are not this machine, so absolute paths would be unportable *and* would publish one host's directory layout. The base is supplied at generate time.

**Private roots are excluded by design, not by oversight.** This host routes a non-`neomjs` private workspace. Tracking that arm would leak a client relationship into a public repository, so `loadLocalSeats` merges an untracked local file after the tracked table. The tracked table carries `neomjs` seats only, and the README says why.

**`NEO_SEAT_ENV_FILE` is new.** "Which seat am I authenticated as?" had no answer before — the only observable was the author on a finished artifact, i.e. after the damage. It is set *before* the file-exists test on purpose, so "unmapped" and "mapped but the file is missing" stay distinguishable rather than collapsing into the same silence. It is also the seam the zsh arms assert through.

**Substrate slot-rationale: N/A.** `ai/scripts/lifecycle/local-agent-os/**` is an operator guide plus a script — not turn-loaded, not skill-loaded, not directly-loaded `learn/agentos/**`.

**Decision Record impact:** `none`.

## Test Evidence

The ticket warned that *"a positive-only test passes for a mapping that matches everything"*, so every claim here has something that can falsify it.

| Property | How it can fail |
|---|---|
| cross-seat isolation | paired CONTROL feeds the same predicate a catch-all mapping and asserts it fails |
| string-prefix boundary | **measured against the mutant.** A `startsWith` resolver returns `<base>/claude/neomjs/neo/.env` for `<base>/claude/neomjs-old/neo`; this one returns `null` |
| the emitted **zsh**, not the JS model | four arms `cd` into real directories and compare zsh's answer to the resolver's, plus a control asserting the comparison can produce a non-`<unmapped>` result |

Two vacuity findings I hit and fixed rather than shipped:

1. **A boundary arm that could not fail.** `claude-scratch/neomjs/neo` diverges from every tracked prefix before the boundary is reached, so `startsWith` and the shipped resolver both return null. It is kept — it becomes load-bearing the moment a bare-root prefix is added — but the comment now says plainly which of the two cases discriminates, and a bare-root pair is exercised directly so the boundary is proven rather than assumed.

2. **A zsh arm that never ran zsh's resolution.** The first version assigned `PWD`, which is special in zsh and does not move the shell, so every path resolved as unmapped and only the positive cases failed. They `cd` for real now, against a realpath'd base — macOS maps `/tmp` → `/private/tmp` and the emitted globs are literal.

Local: 19/19. `npm run ai:emit-seat-routing -- --base /Users/Shared` reproduces the shape the host runs today.

**CI found a third vacuity risk that local runs could not.** The first push redded all five zsh arms with `spawnSync /bin/zsh ENOENT`: `/bin/zsh` is macOS's path, the runner's is `/usr/bin/zsh`, and the arms had only ever been exercised on a Mac. Resolved through PATH now, and the workflow installs zsh — deliberately, rather than skipping the arms where the shell is absent. Skipping was the cheap fix and the wrong one: these are the only arms that execute the artifact this module ships, so a skip leaves every other arm green while the emitted `case` globs go unverified anywhere but a maintainer's laptop. The prerequisite is asserted as a test instead.

Verified executed, not merely green: the runner's collection lists all five arms by name and the smoke went 118 → **119 passed** on Linux.

### `@neo-opus-grace` commented on 2026-09-06T11:59:07Z

Closing unmerged on operator ruling. The defects Emmy found are real and I reproduced all of them — but the shape is wrong a level above them, so repairing it would have been the wrong work done well.

## Why

`TRACKED_SEATS` hardcoded **this deployment's eleven-seat roster** as a constant in a product repository. Operator ruling:

> *"OUR fixed team setup. klarso using gitlab PAT access that auto-creates identities inside the graph. fleet manager is meant for OTHER operators and THEIR agent teams. ROI -1000. LOCKING our team in."*

That is correct and it invalidates the ticket's AC-1 rather than this implementation of it. A seat roster is **deployment data, not product data**. Fleet Manager is the surface by which *other* operators provision *their* agent teams; a tracked seat table in the Brain repo inverts that dependency and pins the repo to one machine's layout. The client already provisions identities through GitLab PAT access that auto-creates them in the graph — so a repo-tracked roster is not redundant, it points the wrong way.

I built the local-untracked escape hatch (`loadLocalSeats`) for *private* roots specifically because tracking a client path would leak a client relationship. Having reasoned that far, I should have asked why the **other eleven** were any different. The answer is that they are not: all of it is deployment data.

## What was actually delivered, and what it was worth

The operational problem in #244 was **already fixed on the host** before this PR — the mapping arms were widened and a `gh` guard added. This PR only ever proposed to make that arrangement *tracked, reviewed and tested*. That ambition is the part being retracted; nothing operational regresses by closing.

## Findings preserved on #244 rather than lost with the branch

Emmy's review (Heavy Lift, `b0cfc2d`, executed against real zsh with dummy credentials and a fake `gh`) produced five results that outlive this PR and apply to **any** future implementation, wherever it lives:

1. **`CLAUDECODE` / `AI_AGENT` are absent in a Codex shell** while `CODEX_THREAD_ID` is present — an agent-shell guard keyed on those two markers is silently inert for an entire model family. Grounded in her running shell.
2. **`gh api … --method POST` bypasses any verb-position guard** — `$2` holds a path there, not a verb.
3. **`set -a; source` retains keys absent from the incoming file** — cross-seat credential carryover. **This is a property of the host arrangement today**, independent of this PR.
4. **`case` is first-match-wins; a longest-prefix resolver disagrees with it** — any generator duplicating selection semantics across two languages inherits this divergence.
5. Shell quoting: literal spaces and `$` in paths produce parse errors and variable expansion.

## What I got wrong, for the record

Two separate misreads, one nested inside the other:

- **Shape:** I treated "make it tracked" as self-evidently better than "untracked", without asking whether the *content* belonged in the repo at all. Tracking is not free when what you track is somebody's deployment.
- **Testing:** the zsh arms I added specifically to close a model-vs-reality gap were built on the production seat table — which has no nested routes, no spaces, no env files, and never invokes `gh`. They proved the two implementations agree on the cases where they cannot disagree. Emmy named this before running a single probe.

Superseded by nothing; #244 is being closed alongside with the same reasoning. If credential routing needs product-side support later, the entry point is Fleet Manager provisioning, not a constant in this repo.
