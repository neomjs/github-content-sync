Resolves #380

A Round 2 that wrote its Round-1 Review ID as a Markdown link was refused, because the check took any leading `[` for the template placeholder. An empty value got through by borrowing the ` · ` separator or the next line. The check now reads the value on the anchor's own line. A placeholder is a `[…]` that no `(` follows, and `·` is never a value.

**Land with neomjs/neo#18988**, the Engine's post-submit review lint, which keeps this predicate byte for byte. Either one alone makes the managed path and CI disagree.

Evidence: L2 (the spec's service arm, plus its workflow harness run against the Engine lint through an untracked link) → L2 required (a body-shape predicate). Residual: none.

## Deltas from ticket

- **The oracle is one table with two consumers.** `REVIEW_ID_VALUES` drives the service arm and a second arm, `#380: workflow lint reads the Round-1 Review ID like the service does`. That arm runs the Engine lint through `runAgentPrReviewBodyLintWorkflow()`. Like its twelve siblings, the new arm reads `.github/workflows/agent-pr-review-body-lint.yml` from the working directory, so a Brain-only checkout fails it with ENOENT.

## Test Evidence

- `PullRequestService.spec.mjs`, Brain-only checkout: 184 passed, 13 failed. The 13 are the twelve pre-existing workflow-lint arms plus the new one, all with ENOENT on the Engine workflow file.
- Same spec, with the Engine lint from neomjs/neo#18988 linked in (the link removed before commit): **197 passed, 0 failed**. Against the Engine's dev lint, the workflow arm fails on exactly the three changed rows.
- Mutants on the predicate, each killed by exactly its own row:
  - `[ \t]*` back to `\s*`: the end-of-line row.
  - `[^\s·]` back to `\S`: the separator row.
  - The link-aware lookahead back to `(?!\[)`: the link row.
  - No placeholder guard: the placeholder row.
