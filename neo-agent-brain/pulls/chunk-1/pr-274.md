Resolves #250

Leaf 6 removed the seat hooks from the Engine and leaf 11 never materialized them anywhere, so every Claude seat has been running a Stop gate that exits 1 on `Cannot find module` — non-blocking, therefore silent — since 2026-08-28. This restores the seven Agent-OS-owned hooks under Brain ownership, rewrites both dependency legs, adds the projector ADR 0040 §2.7 requires, **and has seat provisioning invoke it**: `projectSeatHooks.mjs` materializes the hooks into a target checkout as generated-not-tracked artifacts, and both `hydrateCurrentWorktree` and the `bootstrapWorktree` CLI call it with explicit roots, so a hydrated seat receives the hooks rather than merely becoming a checkout something *could* project into. The census is asserted by count (7 executables + 2 deleted config artifacts + 1 stripped template) so a future re-read cannot silently re-conflate the kinds, and the Claude settings surface gets projector-owned reconciliation because a manifest that cannot be reconciled must fail the projection rather than leave a seat half-provisioned.

**What "all-or-nothing" means here, precisely** — narrowed after Round 2, because the phrase was doing more work than the implementation. The projector refuses **as a whole, before its first write**, on four conditions: an invalid runtime-root binding, a tracked file at a projection path, a source whose specifier escapes the runtime root, and a declared Claude manifest that cannot be reconciled. Each is preflighted as a dry run and each asserts zero mutation. It is **not** a transaction: it does not roll back a write that fails mid-loop for a reason outside those four (a disk error, a permission change between preflight and write). The guarantee is "refuse before touching anything for every failure mode we detect", not "every possible failure leaves the seat untouched".

Evidence: L3 (the real projector runs as a process against real temp seat trees; `--check` exit codes, the exclude block, the reconciliation refusals and the root-binding refusals are all observed on disk, and provisioning is driven end-to-end against a real git seat) → L3 on a host-provisioned seat required (AC-3's second half: the six package-qualified bootstraps loading in a seat with no Engine checkout above them — this sandbox has no seat outside a checkout). Residual: AC-3, Residual-Owner: #184 — **and the transfer is now durable rather than promised**: #250 AC-3 is annotated as an explicit L3-deferred operator handoff, and #184 carries the projected-hook load proof as its own AC plus a Contract Ledger row.

## Evolution

The first shape treated this as a restore — put the seven files back and re-point their imports. That is wrong in the way the ticket's own table shows: a restore leaves the Kimi generator still emitting configs that point at nothing, because the sources were never the whole dependency. What §2.7 actually requires is a *projector*, and once the work is a projector rather than a copy, the interesting surface stops being the seven files and becomes the four ways a projection rots. The `--check` arm and its mutants are the real deliverable; the restored hooks are its input.

The second pivot came from @neo-gpt-emmy's fork on custody: with the Claude settings surface shared between operator edits and projected entries, either the projector owns reconciliation or nobody does. A-custody was chosen, which is why "preserves an operator hook on an event the manifest also declares" and "deletes a bucket emptied by retirement instead of leaving `[]`" are both assertions here.

The third came from Round 2, and it is the one worth keeping: every defect Emmy found was invisible to a spec that drives *authored fixtures*. The suite was thorough about the projector's logic and silent about the projector's effect — no fixture happened to hold a relative literal outside specifier position, no fixture bound a wrong root, and no test asked whether anything called the thing. Fixtures answer "does this function behave", and all three blockers lived in the gap between that and "does a seat end up wired". The Round 2 tests are deliberately built the other way: over the real corpus, through the real provisioning entrypoint, and via the real process for exit codes.
