Resolves #353

`#294` moved this repository to `neo-agent-skills@0.1.3`. Four releases have shipped since — 0.1.4, 0.1.5, 0.1.6, 0.1.7 — and the lockfile has held 0.1.3 through all of them.

## Deltas

```
package.json      "neo-agent-skills": "^0.1.3"  →  "^0.1.7"
package-lock.json  0.1.3                        →  0.1.7
```

**A caret does not float once a lockfile exists.** The range permitted every one of those releases and the lock froze the first, so every seat installing from this repository got 0.1.3 *deterministically* — stale rather than variable. That distinction matters: a floating range would have healed itself on the next install, and this could not.

**This repository is a consumer, and I recorded otherwise earlier today.** My org-wide sweep called the Brain *"range only, not a baseline consumer"* — true of the reusable PR baseline, **false of skills tooling**, which is the half that decides what agents read:

- `package.json:59` — `"postinstall": "neo-agent-skills-materialize"`
- `.github/workflows/substrate-sync.yml:42` — `npx --no-install neo-agent-skills-materialize --check`

So agents working here have been reading a skill corpus four releases old, and CI has been asserting that corpus current against an equally old materializer. @neo-opus-vega refused the claim and measured it; the correction is hers.

**The caret stays.** Pin *shape* is a live policy question she is holding on `#352` and deliberately scoped out of her dependabot lane. Changing it here would fork that decision from under her, so this moves the version and not the convention.

## AC Evidence

**AC-1** — `node -p "require('./package.json').devDependencies['neo-agent-skills']"` → `^0.1.7`; the lock's `node_modules/neo-agent-skills` entry resolves 0.1.7. Both read 0.1.3 before this branch.

**AC-2** — the check `substrate-sync.yml` actually runs, exit code read directly rather than through a pipe:

Evidence: `npx --no-install neo-agent-skills-materialize --check` → exit 0
```
neo-agent-skills: 37 skill link(s) materialized from node_modules, none tracked, none shadowed (v0.1.7)
```

The banner echoing `v0.1.7` is the one direct receipt available that the new release is what ran, rather than an inference from the lockfile.

**AC-3** — `git status --porcelain` after a full `npm install` showed exactly `package.json` and `package-lock.json`. `.claude/skills/` is a gitignored projection, so a newer materializer wanting to commit bytes would have surfaced here as a finding; it did not.

**AC-4** — the `package.json` diff is **one line**. npm preserved the file's 4-space formatting; verified in the diff rather than assumed.

## Test Evidence

The materializer check above is the behavioural evidence and it is non-vacuous: 37 links projected, none tracked, none shadowed, under the new release.

**What this PR deliberately does not claim:** no guard behaviour is exercised here, because this repository calls no reusable baseline — the payload is the skill corpus projected into `.claude/skills`, not the guard binaries. A green `substrate-sync` proves the projection is producible and current; it does not exercise archaeology, substrate-size or the PR-body gate, none of which run in this repository.

Between 0.1.3 and 0.1.7 that corpus gained the archaeology rules for colour literals, leading zeros and numeric HTML entities, the typed reference escape, and 0.1.7's premise pre-flight row — *"the premise pre-flight asks the inverse question, so a diff cannot quietly reverse what was ratified"* — which is review discipline this repository's agents are meant to be running and have not been.
