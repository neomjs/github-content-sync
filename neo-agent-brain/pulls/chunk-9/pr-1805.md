Resolves #1803

A managed Codex Start selects the executable hook declared by its held Fleet generation. A later package can select the same immutable artifact. Changing the nonce consumer, executable, protocol or a declared dependency gives the native hook a new address and a new trust decision. The host publisher is [Institution #1005](https://github.com/neomjs/neo-agent-institution/issues/1005).

Evidence: L3 (disposable sealed Fleet packages and genuine Codex hook inventory) → L4 required (installed managed Starts and a model-side receipt). Residual: AC-4, Residual-Owner: #571.

## Deltas from ticket

The generation manifest authenticates the hook declaration and fixed runtime inputs. An unrelated product or Engine revision in the organism package metadata leaves the address stable. The macOS launcher, its framework and Info.plist are executable inputs. Their bytes can change on a signed release.

On admission, Fleet compares the full shared tree to the selected generation's inventory. Each attempted Codex send rechecks the original live process and the kernel identities of the verified tree, including its directories and dependencies. The proof belongs to the original Start's in-memory record. A restarted Fleet host verifies the artifact before its first send.

### 🔬 Depth Floor

**Challenge OR documented search (per guide §7.1):**

- **Challenge**: four notes, none blocking.
  1. **The gate is optional below the pump.** `dispatchFleetPrimarySessionWake` skips the check when no `verifyCodexRoute` is passed, and `drainFleetPrimaryWakeRecord` forwards `undefined`. Only `startFleetPrimaryWakePump`'s default refuses. At `7bf63ea6a9` no production path is open: the pump is the one Codex caller, and `dispatchAntigravitySidecarRecords` drains Antigravity routes only. A later direct caller would send unproven. Refusing a Codex send without a verifier at the dispatch layer would close it where the send happens.
  2. **Two expressions for one state folder.** The launch path reads the preparation receipt from `optIn.stateDir`; `verifyCodexWakeRoute` reads it from `wakeStateOptions.wakeReceiverStateDir`, whose config default is an empty string while the pump starts on the manifest path alone. With that option unset, the re-verify path after a host restart reads a cwd-relative file and skips the receipt comparison. The route comparison against the manifest still binds both paths, so this weakens a check and opens nothing.
  3. **`hypothesis — needs V-B-A before implementation`: the per-send stamp includes `ctime`.** A metadata-only change (an extended attribute written by the system or a backup tool) would move it, and the Start then refuses every later send without a log line. On this macOS 27.2.1 a sealed copy keeps its `ctime` across a read and gets `com.apple.provenance` at creation, not later; my probe could not exercise a real execution (the copied binary was killed on launch), so this stays unverified. AC-4's installed validation is where it would show. Re-running the content inventory once when the stamp differs, and logging the refusal, would turn a false positive into 0.2–0.7 s.
  4. **One failure message for every cause.** `readCodexWakeArtifact` collapses a missing artifact, a malformed declaration and a tampered file into one error without `cause`, and the callers map it to a reason string. The seat should not learn more; the host log should.
