## Deltas from ticket
- **Cross-container `bootId` + `pid` namespace handling:** `inspectHeavyMaintenanceLease` / `isLeaseStale` gain `crossNamespace: true` so `kb-server` reading `orchestrator`'s `:ro` mount across separate container UTS/PID namespaces evaluates deadline liveness (`expiresAt`) without staling live orchestrator leases on hostname or PID mismatch.
- **Public `leaseId` separated from secret `token`:** `buildLeasePayload` mints a distinct public `leaseId` alongside the release/renewal capability `token` so `read`-tier `healthcheck()` and MCP refusal payloads never leak release authority, and `withHeavyMaintenanceLease` refuses `NEO_HEAVY_MAINTENANCE_LEASE_INHERITED_TOKEN` inheritance if a child requests `kbWriteExclusive: true` under a non-exclusive parent lease.
- **Complete `manage_knowledge_base` write coverage:** in addition to the 6 incremental `IngestionService`/`VectorService` upsert/delete sites, `VectorService.deleteCollection` (`action: 'delete'`) and `VectorService.embedViaShadowSwap` (`createCollection` + promote `modify`) also route through `kbWriteGate`, while `DatabaseService.importDatabase`/`truncateDatabase` stay un-gated for `#1432`'s inside-lease bundle restore fallback.

### 🪜 Strategic-Fit Decision

Per §9 Strategic-Fit Step-Back:
- **Decision**: Approve
- **Rationale**: No premise row fires. The fence is the one #1432's convergence chose. A writer-side gate refuses while a KB-exclusive lease is held, and the coordinator gets a drain acknowledgement on its own lease id. The only drift was the ticket's Contract Ledger, which named 6 sites; I synced it to this head (below), so nothing is left for a round.

**Peer-Review Opening:** Thank you, Maryam. The design choice that carries this PR is `inFlightWrites++` before `inspectGate()`: once a coordinator reads `{gate: 'closed', leaseId: <own>, inFlightWrites: 0}`, no write can slip in uncounted. The intake also caught two traps the ticket missed. A cross-container reader would have staled every live lease on `bootId`/`pid`, and the 5-minute health cache would have served a stale gate. Separating the public `leaseId` from the release `token` keeps the read tier from ever holding release authority.

### 🔬 Depth Floor

- **Challenge (non-blocking, for #1432's author):** The gate has no holder identity: while a KB-exclusive lease stands, it refuses every gated write in every process, the holder's own included. That is safe today. #1432 rewrites through the Chroma client, and its restore fallback uses `DatabaseService.importDatabase` / `truncateDatabase`, which this PR deliberately leaves ungated (verified: direct `collection.upsert` and `ChromaManager.deleteCollection`). A future holder op that reaches `VectorService.embedViaShadowSwap` or `deleteCollection` would refuse itself and run out its lease. Second watch item: a lease file still malformed after the 10 ms retry reads as `open`. The drain protocol covers that, because the coordinator proceeds only on `closed` for its own id, and renewals write atomically. A file corrupted mid-window is the one case it does not cover.
