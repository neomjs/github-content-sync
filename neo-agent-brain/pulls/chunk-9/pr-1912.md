Resolves #1795
Related: #66, #133, #1432, #1434

Folds Chroma's unpersisted `embeddings_queue` tail (`seq_id` strictly above the vector segment's `max_seq_id` on `persistent://default/default/<collectionId>`) into `auditChromaVectorCoverage` using Chroma 1.5.9's vector-index membership semantics (`local_hnsw.rs`): only a vector-bearing `ADD` (`0`) or `UPSERT` (`2`) can establish membership, `DELETE` (`3`) removes it, and `UPDATE` (`1`) preserves existing membership at that point in sequence without creating or resurrecting an absent ID. Healthy rows waiting for Chroma's 1,000-row HNSW flush are reported in `pendingInQueueCount` / `pendingInQueueSample` instead of falsely triggering `missingFromVectorCount` (`wal-stall` → `re-embed-missing`) or masking `store-bloat` (`defrag`).

Evidence: L2 (Playwright unit suite `CheckChromaIntegrity.spec.mjs` + `CorruptionRecoveryGate.spec.mjs` across `execFn` and SQLite snapshot fixtures) + L3 (live `chromadb/chroma:1.5.9` container snapshot with 1,005 rows + tail delete verified at `missing=0 extra=0 pending=5`) → L2 required (AC-1..AC-4).
