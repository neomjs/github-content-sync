Resolves #1770

A sunset written behind a locked screen now rotates at the unlock instead of expiring unseen. The receiver reads the console session's lock flag (`readScreenLocked()`: `ioreg -n Root -d 1`, `CGSSessionScreenIsLocked`, no privacy grant). A rotation that finds the screen locked defers `screen-locked` without calling the adapter, so nothing activates or types, and its 60 s counts only unlocked time (`rotationLockPatch`, `rotationDeadline`). The holder fence still records the seat's holder on the first pass and runs again after the unlock. The plane's envelope carries `holdUntil` (the receipt's `sentAt` plus `windowMs`), so the receiver never types after the plane stops holding the seat's wakes. The plane posts one `defect-note:` through `publishDefectNote` when it records a rotation `incomplete`.

Evidence: L2 (unit arms for the contract, the receiver and the lane, plus the mutation probes below) → L3 required for AC-1 (the lock flag on the operator host) and AC-6 (a live sunset behind a locked screen). AC-1's receipt lands here before review. Residual: AC-6, Residual-Owner: #1373.

## Deltas from ticket
- A rotation that is still locked is skipped at the top of the drain, before it is claimed: one `ioreg` read per pass and no record write, so an overnight lock causes no file churn. The first locked pass (which records the holder) and the first pass after the unlock run the whole path. Arm: "#1770: while the lock holds, a waiting rotation is neither claimed nor rewritten".
- `isRotationExpired` and `rotationDeadline` take the receiver record instead of `acceptedAt`; their three callers moved with them.
- `check-block-alignment --fix` realigned one neighbouring `const` block in `buildOsascriptArgs`.
- The `incomplete` note's hand-start prompt says the session was started by hand. The plane's own prompt says the plane opened it, which would misstate a person's start. The operator caught it on today's manual restart.
