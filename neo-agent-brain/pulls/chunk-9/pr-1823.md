Resolves #1822

The `GEMINI.md` that Fleet writes for an Antigravity seat now carries a guard card under the seat's identity line: a subagent is a helper and never the seat, one writer per checkout, mechanical work goes to `Model: "flash"` with an `ESCALATE_TO_CARBON` stop, and no `schedule` polling for what Fleet and Antigravity already wake on. The renderer moves to `seatMemoryLayerTemplate.mjs`, the memory-layer template SSOT, beside a pure `isAntigravityMemoryLoader`. That recognizer accepts the first loader's exact shape, or exactly what Fleet renders for the identity and memory folder the file names. Existing seats therefore upgrade on their next Start, and an edited file stays the resident's.

## Deltas from ticket
- The ticket's v2 recognizer became "equals the current rendering for the identity and folder it names" rather than a second hand-written regex. The card text then lives in one place, and the renderer's JSDoc says that changing it means keeping the previous rendering recognizable first, as the first loader is.
- `refreshAntigravityMemoryLoader` is exported so its upgrade path has a direct spec; before this it had none.

## Slot rationale
`GEMINI.md` is read into every Antigravity turn, so the card is always-loaded substrate for those seats (`/turn-memory-pre-flight` step 4: harness-local).
- Guard card, `keep`: each rule fires on a per-turn act (spawning a subagent, writing to the checkout, delegating, waiting). A miss costs a seat-identity copy, `.git/index.lock` races, frontier quota, or a full-context timer wake (49 `schedule` fires in 34 h, measured on #1822). Discipline-only: Antigravity exposes no hook that could enforce subagent prompts or tool choice. Cost: about 1.1 KB per Antigravity turn.
- Retirement: a rule leaves the card once Antigravity or Fleet enforces it mechanically, for example a subagent tool allowlist, or a `schedule` that knows the wake plane.
- Retired: nothing; the first loader's shape stays only as a recognizer.

Decision Record impact: none.
