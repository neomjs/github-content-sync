Resolves #1890

Adds HMAC-signed `POST /wake/settle` to the graphless host wake receiver (`ai/daemons/wake/receiver.mjs`) and wires off-path Memory Core mailbox/task settlement (`ai/services/memory-core/wakeCoalescePolicy.mjs`, `WebhookDeliveryService#deliverSettle`, `WakeSubscriptionService#{settleHandledSources,reconcileHistoricalPendingWakes}`, `MailboxService#{markRead,transitionTask,listMessages}`) so `pending` `wake/digest` records whose `MESSAGE:*` / `TASK:*` `sourceEventIds` are all durably handled transition to `skipped` (`outcomeReason: 'source-events-already-handled'`) without adding latency to MCP calls, degrading un-upgraded endpoints, or tripping `STALE_SKIP_RUN` reachability decay.

Decision Record: aligned-with neomjs/neo-agent-brain#adr:0002-phase3-wake-substrate-standards-alignment

Evidence: L2 (loopback HMAC-signed HTTP createWakeReceiver + Memory Core SQLite loopback in unit specs, plus static dependency-closure guard) → L2 required (all close-target ACs covered by unit and closure specs). No residuals.

## Deltas from ticket
- **Shared settle contract & breakdown guard (`ai/services/memory-core/wakeCoalescePolicy.mjs`):** On wire, `wake/heartbeat_pulse`, `wake/permission_granted`, and `wake/task_state_changed` emit bare UUIDs / `01H*` event IDs in `sourceEventIds`; `wakeCoalescePolicy.mjs` exports `WAKE_SETTLE_EVENT_TYPE`, `SOURCE_EVENTS_HANDLED_REASON`, `isSettleableSourceEventId`, and `isSettleableWakeRecord` (enforcing both the `MESSAGE:`/`TASK:` prefix whitelist and zero counts on `envelope.payload.breakdown.{heartbeat_pulse,permission_granted,task_state_changed}`) as the single pure source of truth for both the graphless host receiver and Memory Core.
- **Native spool pointer release & drain mutex (`ai/daemons/wake/primaryWakeSpool.mjs`, `ai/daemons/wake/receiver.mjs`):** `isSpoolPointerActive` treats `TERMINAL_STATES` (`delivered`, `skipped`, `failed`, `unknown`) as inactive when `attempt?.recordKey !== entry.recordKey` so settled staged pointers never wedge later wakes, and `settleSubscriptionRecords` serializes behind `withStateMutex` so concurrent `drain()` passes never hide a `pending` candidate in transient `dispatching`.
