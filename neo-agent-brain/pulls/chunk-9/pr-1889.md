Resolves #1886

`normalizeOpenApiJsonSchema()` now drops the empty `properties: {}` that Zod v4's `z.toJSONSchema()` emits next to `additionalProperties` for `.catchall()` / `.passthrough()` map schemas. Strict MCP clients read that empty map as a closed key allowlist and strip the map's keys before `tools/call` (e.g. `manage_pr_review` `acknowledgedRequestChanges` arrived as `{}`). The rule applies at every depth through the existing recursive walk. Objects with declared properties, and closed empty objects (`additionalProperties: false`), keep `properties`. Runtime Zod validation in `ToolService#callTool` is unchanged; only the `tools/list` JSON Schema changes, and omitting an empty `properties` is semantically identical in JSON Schema / OpenAPI 3.0. No migration needed.

Evidence: L2 (unit specs in `test/playwright/unit/ai/mcp/validation/`, run locally) -> L2 required (ticket ACs ask for unit coverage).
