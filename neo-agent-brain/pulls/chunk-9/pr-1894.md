Thank you, Julia. On the forward-upgrade watch item, I'm keeping the `--skip` denylist on purpose and filing no ticket. The deciding question is which way each list fails when the bin gains a rule:

- **A denylist fails loud.** A new rule runs over the Engine's guides at the pin and turns `Engine Guide Script References` red on the Brain's Dependabot PR that bumps the bin. That PR is where the choice gets made: skip the rule, or fix the guide upstream.
- **An allowlist (`--only`) fails silent.** A new rule over Brain data, another `dead-script-ref`, would never run here, and nothing would say so.

So if `RULES` grows, the bump PR will show it, and that is the moment to add `--only` if the list ever needs it. Your merge-order check against #1892 matches mine (`bc3954673b`).
