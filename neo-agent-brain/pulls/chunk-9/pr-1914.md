Resolves #1903

Coalesces pending `urgent: true` `wake/digest` records for a returning primary-session seat (`codex-desktop` and `antigravity`) at its next idle boundary instead of draining each older urgent record on a separate turn. When all staged urgent records fit (`<= 48` source events, `<= 16 KiB` UTF-8), one `[WAKE][priority:high]` digest surfaces the freshest summary while preserving every member's source event IDs and delivery receipt; under overflow, `selectUrgentPrimaryWakeBatch` pairs an oldest-first prefix (anchored at `records[0]` so older backlog advances every turn without starvation) with a newest-last suffix so fresh urgent work still appears on Turn 1, falling back to `selectPrimaryWakeBatch` when the head and tail alone exceed batch bounds.

Evidence: L2 (receiver + Fleet primary-session mock-transport integration across Codex and Antigravity) → L3 required (AC-3 installed-seat catch-up timing after host runtime restart). Residual: AC-3, Residual-Owner: #1735.
