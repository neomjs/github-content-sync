Resolves #1869

One merge into `dev` now wakes one rebase. Before, every approved PR it made conflicting woke at once. `mergeLineOf` orders the approved open PRs into each base branch of a repository by their oldest standing approval. A conflicting PR behind one that still holds its place reads `await-merge-turn`, names that PR in `ahead`, and gets no wake. Once that PR merges, the next one is woken to rebase. The projection and the wake round pass the same line to `holderOf`, so they still agree on whose turn a PR is.

Evidence: L2 (unit specs drive the real holder, reducer, projection, wake planner and wake round over snapshots) → L2 required (AC-1 to AC-3 are holders and planned wakes over a snapshot). Residual: none.

## Deltas from ticket
- **Standing approval holds a place, not on-head approval.** After the first PR merges `dev` in, its approval judged an earlier head. A line of on-head approvals would release the next PR onto a `dev` without the first. Decided in the intake comment (issuecomment-7028700541); the Contract Ledger is in the ticket body.
- **A row holds a place only while both readers would act on it.** The wake round must decide it, by its own rule `decidableRow`, shared from `openWorkHolder.mjs`: freshly observed, and read completely or a red outside head. Its author must not be absent and no close target blocked. Its own holder must not be `unknown`, `address-changes` or `await-prerequisite`. The wake round reads absent seats whenever a PR waits in the line, so an author going absent ahead releases the follower with no other wake planned. For the projection to read the same signal, `absentOf` moved beside `familiesOf` in `wireFleetOpenWorkSource.mjs`.
- **One line per base branch.** The snapshot now reads `baseRefName`, so an approved release PR into `main` holds no place for PRs into `dev`.
- **Not taken:** the optional approval carry across base merges, which is its own fork (see the intake comment). The FM's words for the new kind are also not taken; Institution's `OpenWorkSeat.mjs` renders it `unknown` until then.
- **Accepted cost:** two PRs that conflict with `dev` on disjoint files now rebase one after the other. Falsifier: a waiting PR whose files share none with the PR ahead.
- No consumer lines removed: this adds an order between PRs that the per-row holder could not express.
