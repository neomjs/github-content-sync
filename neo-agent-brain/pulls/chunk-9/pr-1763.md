Resolves #1762

On the local ingress, a Caddy-generated 502 for `POST /mc/mcp` now produces one error record. Its category is one of `connection_refused`, `connection_reset`, `upstream_eof` or `upstream_error`. An HTTP error returned by the upstream application passes through without this diagnostic. The log excludes request data and raw upstream error text.

Evidence: L3 (isolated production Caddy image, exact Caddyfile and controlled faults) → L3 required for the source contract.

## AC Evidence

| Criterion | Verification |
| --- | --- |
| AC-1 | Outside-CI: the unmodified dev and candidate Caddyfiles each served the same isolated 15-case matrix. Refusal, forced reset, early EOF and a malformed upstream status returned empty 502s. The base emitted zero access records. The candidate emitted one record per fault with its matching category. |
| AC-2 | Outside-CI: the eleven remaining cases emitted zero diagnostic records. They included MC GET, a different MC path, KB, all three Fleet fallbacks, an unrelated path and upstream 200/500/502/503 replies. Both configurations preserved the client status, response body and fixture header. |
| AC-3 | Outside-CI: exact emitted fields were `level`, `ts`, `logger`, `msg`, `duration`, `status`, `service` and `category`. Synthetic authorization, cookie, query, custom header, session/request and response data and malformed-wire markers were excluded from the diagnostic. The focused deployment spec also checks the binary against the cached Compose Caddy image. |

## Deltas from ticket

None substantive. The default site access log is discarded; only the original MC POST inside the 502 error handler selects the named stderr logger. The four-second upstream pool setting and Fleet’s existing 404 responses are preserved.

## Test Evidence

The isolated baseline/candidate run used the deployed Caddy 2.11.3 image, loopback dummy services and no host ports or live configuration mounts. All 15 paired responses matched. The [installed-parent observation](https://github.com/neomjs/neo-agent-brain/issues/904#issuecomment-6675574898) records why this diagnostic is needed: an empty-body 502 at 13:34 UTC after the prior keep-alive fix was active and both maintenance jobs had ended.
