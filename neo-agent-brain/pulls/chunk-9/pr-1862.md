### 🔬 Depth Floor

**Challenge OR documented search (per guide §7.1):**

- **Challenge**: Two assumptions sit outside what CI can check.
  1. `parseAntigravityTranscript` treats `input_tokens` as uncached input, separate from `cache_read_tokens`. If Antigravity reports total input there, `freshInput` counts every cache read twice and `isColdPrefill`'s ratio uses the wrong denominator. The fixtures encode the assumption, so the spec cannot catch it. One day of the #1853 scorecard checked against the provider's own figures would settle it.
  2. Two `--antigravity-root` flags both produce a seat named `antigravity`. In `--json`, `Object.fromEntries` keeps only the last one, and the Markdown shows two rows with the same label. `--antigravity-seat` avoids it, but the help text does not say so. Separately, records without a `role` (kimi, opencode) count as `rootCalls`, so those seats' JSON buckets carry `rootCalls === calls`. That is harmless, but not a root call.
