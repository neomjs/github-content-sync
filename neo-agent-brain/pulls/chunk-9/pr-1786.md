### 🔬 Depth Floor

**Challenge OR documented search (per guide §7.1):**

- **Challenge, RA-1: the cursor is acknowledged before COMMIT.**
    - **What changed.** Before this PR, `executeLink` auto-committed its `UPDATE Edges` and then synced the cache. Now `UPDATE Edges` (`GraphService.mjs:1105–1106`), `syncCachedEdgeProperties` (`:1110`) and `acknowledgeLocalMutations()` (`:1116–1118`) all run inside `this.db.storage.db.transaction(…).immediate()`, which commits only when the callback returns (`:1120`).
    - **Why it matters.** `acknowledgeLocalMutations()` sets `lastSyncId` to `MAX(log_id)` (`Database.mjs:184–188`), and that includes this transaction's own uncommitted `edge_update` row. If COMMIT fails (for example SQLITE_FULL or an I/O error), the row and its id roll back while the cached weight and the cursor stay. A peer's next commit can then reuse an id at or below the cursor, and `getDeltaLog(log_id > lastSyncId)` never delivers it, so the stale cache is never invalidated.
    - **Why it's an RA.** This is the cache-before-commit shape the #1510 intake rules out, and the rest of this PR avoids it: `#runIdentityPublicationMutation` syncs after the helper returns, and `Database#syncCache` advances `lastSyncId` only after both invalidations succeed.
