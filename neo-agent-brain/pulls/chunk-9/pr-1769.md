Resolves #1768

An approved, green pull request whose close target still has an open blocker no longer reaches the operator's merge list. The open-work snapshot reads each close target's open-blocker count, GitHub's `issueDependenciesSummary.blockedBy`. While one is blocked, `holderOf` names `{role: 'author', kind: 'await-prerequisite', targets}` instead of `operator/merge`. The author gets one wake, which never escalates to another seat, and once the blocker closes the next pulse hands the head to the merge. No merge is certified without a complete close-target read, so a row saved before this change certifies none either. The Fleet Manager's awaiting-merge list reads the holder, so the list itself needs no change.

Evidence: L2 (unit arms on the holder, the reducer and the wake round, plus a live read of the new snapshot document) → L3 required for AC-5 (the installed Fleet Manager). Residual: AC-5, Residual-Owner: #759.

Prescription checked: `ai/services/fleet/openWorkHolder.mjs` owns the concern. The awaiting-merge list and the wake round both read `holderOf`, so a hold placed there reaches every reader.

## Deltas from ticket
- **No second read.** The ticket planned one bounded read per approved head. `issueDependenciesSummary.blockedBy` counts only open blockers without a nested list, so the snapshot carries it at no formula cost: round((1 + 50 × 10) / 100) = 5. That keeps one read path instead of adding a query, its budget and its failure handling.
- **The hold names targets, not blockers.** A count says *that* a close target is blocked, not by what, so the holder names the blocked close targets.
- The previous-snapshot price entry moves to the document this PR replaces (hash `0654027a…`, cost 5), as its comment prescribes.
- **A merge needs positive evidence (review RA-1).** A node without the list is unread and certifies no merge, and so is a row the producer saved before this read and restores ahead of its first refresh. Fixtures that model a fully read row now say so.
- **A prerequisite wait only informs (review RA-2).** `await-prerequisite` is a notice kind in `openWorkWakes.mjs`. A reachable author gets one wake, and the wait raises no `holder-silent`, `holder-unreachable` or `unowned` escalation, since no seat could act on it. Actionable work escalates as before.
- **Follow-ups, both blocked by #1768:**
  - neomjs/neo-agent-skills#402 gives authors the slot: declare a merge order as a native `blocked_by` edge.
  - neomjs/neo-agent-institution#991 gives the author's seat card words for `await-prerequisite`. Until then the card reads "next action unknown".
