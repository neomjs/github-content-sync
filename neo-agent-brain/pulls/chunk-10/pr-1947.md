## Deltas from ticket
- Adapted `consentedInputs` to `RECIPE_VERSION = 2` (`desktop-wake` `<stateDir>/records` carrier binding and `composeContextOf` profiles) so untouched v2 effects (`write-secrets` when secret set matches, `register-forge`, `start-wake-receiver`) stay `ok` across preset changes while `desktop-wake` flips also key `write-env` and `compose-up` cleanly.
- Implemented the two `PR #1604` / `#810#issuecomment-6797485764` clarifications: `applyEffect` and `recordVerification` archive replaced receipts into `record.history` (`RETIRE_REASONS.inputChanged` / `reapplied`), `evaluateEffect` keeps a `failed` re-application `failed` over still-present earlier host state so the next run retries it, and `verifyExits` offers `['run']` (`duplicatePossible: false`) rather than `[]` or `['new-attempt']` after re-composition.
- Added `--preset <id>` and `--provider-key <file>` (admitted via `admitCredentialReference`) to `ai/scripts/setup/firstRun.mjs` so an operator can change the consented preset on an existing `--run-id` directly from the CLI.
