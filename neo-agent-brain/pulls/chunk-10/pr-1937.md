Resolves #1933

A stalled `mc-server` now leaves two records of what it was doing:

- **Each call's start row keeps its argument shape**, written before dispatch: the closed values of the tool's allow-listed arguments and only the keys of everything else. A call that wedges the process is named by tool and query shape, and no argument value is stored.
- **An event-loop probe writes one `mc_event_loop_block` row per block of a second or more**, once the loop frees. The row holds the block's length, the GC time inside it, and the calls in flight across it. That includes the call that caused it, which usually returns just before the late sample runs.

`get_memory_core_tool_metrics` serves both: `argsShape` on `unfinishedCalls` and `recentSlowCalls`, and the new `eventLoopBlocks`.

Evidence: L2 (unit arms on real timers, one mutation-checked) → L2 required (AC-1–AC-3 are unit). Residual: the first live block after deploy, Residual-Owner: #1843.

## Deltas from ticket

- **The window names a call that already returned.** The blocking call usually completes before the late sample runs, so a call that ended inside the window counts. The window opens at the last on-time sample, so it can also name a call that ended up to one interval (500 ms) before the block.
- **GC time is read one sample later**, after the `gc` observer has delivered the entries from inside the window. `noteGc` is the probe's seam for tests.
- **The probe starts with the recorder** (`initAsync` → `startBlockProbe`) and needs no `AiConfig` leaf. Its threshold and interval are module constants, per the ticket.

Intake: self-authored in an earlier session. Since #1933 was filed, `dev` has moved only `ContainerHealthDiagnosisService`, so this ticket's paths were untouched.
