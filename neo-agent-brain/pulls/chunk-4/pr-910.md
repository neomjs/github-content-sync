Resolves #909

A Fleet-launched Claude Desktop now carries its Neo MCP rows in its own profile, so every Code session of that Desktop has them, whatever folder it opened. Desktop starts each row with a stripped environment, so the row runs Fleet's launcher. The launcher redeems that server's grant from the Fleet's issuer over loopback, then starts the unchanged server.

At each redemption, the issuer resolves the seat's PAT from the registry and its plane credential from the tenant or plane binding Start selected. It proves the value the way Start does and hands over exactly the bytes that proved. The profile holds no PAT, plane bearer or signing key, and the issuer keeps neither credential.

This implements D19437's graduated design. Its authority is ADR 0038 §2.5.1 class 8, merged in neomjs/neo#19439.

Evidence: L2 (unit tests, plus a process-level run of the real launcher, issuer, stdio bridge and an authenticated MCP endpoint) → L4 required (the installed receipts under #571). Residual: installed receipts, Residual-Owner: #571

## Deltas from ticket
- **Sticky revocation.** It hangs on a registry `definitionChange` event (Neo Observable) fired after every committed write, not on the configure wire verb, so no write path can bypass it.
- **Profile in use.** Start refuses a Desktop seat whose profile another process holds (`FLEET_SEAT_PROFILE_IN_USE`). That check keeps stopped-only convergence true when Desktop was opened outside Fleet.
- **Credential refusals end nothing.** A child whose credential's owner holds no value, or holds one that does not prove, is refused: `credential-missing` or `credential-unproven`, naming `seat-pat` or `plane-bearer`. The next child is admitted once the owner holds a value that proves. Concurrent proofs of one value share one probe. A proof is bounded at 10 s, which keeps it inside the launcher's own bound.
- **Older rows.** Rows a pre-receipt Fleet wrote into the profile are recognized and replaced. That adds the GitHub row those older rows could not carry.
- **A Stop during a Start ends its admission, not its launch.** A Stop asked for while a Start is still provisioning has no generation to revoke yet. The issuer counts it, and the reservation of that Start comes back already revoked. The launch itself still completes, as it does for every harness when a Stop arrives mid-Start. The seat card then reads `revoked: stop-requested` until the operator restarts the seat.
