Resolves #848

A run that names no plane now binds the plane its profile declares, so a first run gets past `write-env`, and `compose-up` now asks for the whole plane. `hostLayout()` states the local profile's target once (the canonical local plane id, its container-side data root, the loopback endpoint), and one function, `setupRunRecord.runTarget`, decides a run's target for every renderer: what the invocation names, else what the record is bound to, else the profile's. The CLI uses it; its three flags stay as overrides. Before, a run started without `--plane-id` and `--data-root` had a null target and `write-env` failed on it.

Evidence: L2 (unit tier: the CLI as a child process on its fake host, and the pure target function) → L2 required for this leaf's criteria. Residual: a cold run through the setup card reaches `done ok`, Residual-Owner: neomjs/neo-agent-institution#550.

Decision Record impact: `aligned-with ADR 0041` §2.4 and `aligned-with ADR 0019` §10.7. Decision Record: Not needed in this PR; the record's author adds one sentence to ADR 0041 §2.4 in a PR of her own. ADR 0019 was read before the change (§3, §5, §6, §10.1, §10.3, §10.7): the target is the profile's declaration, built from the leaf's default constant and the anchor function over the image's root; no env read and no second resolver is added.

agent-preflight: ran on the staged files and this body; all requested gates passed.

## Deltas from ticket

- **The leaf was widened by the planner while it was being built** (neomjs/neo-agent-institution#351 comment 5982055393, corrected at 16:31Z; AC-5 was added to the ticket). `compose-up` passed no compose profile, so a first run started the Memory Core, the Knowledge Base and Chroma and never the orchestrator, the Fleet service or the ingress: nothing listened at the endpoint the run is bound to. The layout now declares `cloud`, `fleet` and `ingress` and the effect passes them. `local-model` stays out: the local presets use the host's own model server.
- **The rule lives in a function both renderers call**, `runTarget`, beside `resumeTarget`. The ticket asked for CLI defaults; a default in `parseArgs` would have made every resume without flags name the profile's plane and retire a run bound to another one. With `runTarget` a resume keeps its record's binding and only a run that names no plane takes the profile's.
- **A named plane takes nothing of the profile's root.** A custom id on the canonical root is refused at boot, so the profile's root is defaulted only together with its id.
- A record created before this change with no target takes the profile's on its next run and its earlier proof retires through the existing target-changed path.
