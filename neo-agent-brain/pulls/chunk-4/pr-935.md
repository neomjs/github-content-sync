Resolves #931

`healthcheck` no longer hands one caller another caller's session. The cached payload carries no session. Every return path (full check, in-flight join, and both cache hits) gives the caller a shallow copy with its own session, read in its own request context. The openapi field now names it as the calling client's session.

Evidence: L2 (unit: concurrent request contexts through `RequestContextService.run`, including the in-flight join) → L4 required (AC-4: two seats on the shared plane after deployment). Residual: AC-4, Residual-Owner: #121.

## Deltas from ticket
- A fourth return path was in scope: a caller that joins another caller's in-flight check received that caller's payload. It is the likely path of the original observation, whose timestamp matched the observer's own call, and it is the red-first case here.
- The existing freshness test asserted that the fast path returns the cached object by identity. Every caller now receives a per-caller copy, so the test asserts equality with the snapshot. The cache itself is still never mutated.
- The new test stands in for `SessionService`'s getter at its namespace (request-bound id first, then a process session), because importing the real singleton starts its storage initialization.
