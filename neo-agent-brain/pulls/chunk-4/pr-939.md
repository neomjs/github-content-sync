Resolves #768

🌿 *A Fleet Start can no longer hand a Claude seat a window route its own session is about to withdraw, and a poll on some other route can no longer pass for a seat's pull route.*

A Fleet Start no longer arms a Claude Desktop seat on `osascript`. `claude-desktop` leaves `GUI_WAKE_DISPATCH`, so `armFleetSeatWake` answers `null` for it, as it does for OpenCode, and nothing is subscribed or published. The seat arms its own pull route at SessionStart (`armSeatWakePull`).

The decomposed wake-routes read (`fleetWakeRoutesSource`) now reads that route. Each `fleet-identities` observation carries `pullRoute`: `{lastPollAt}` when the identity holds an active `SENT_TO_ME` route on `none`, stamped over those routes only, else `null` (`readActiveWakeSubscriptionObservations`, forwarded by the plane reader). A seat holding one reads `armed` with `route: {adapter: 'pull', lastPollAt}`. A manifest-armed row keeps its own detail, so a Codex seat polling its push route keeps its manifest route. Without pull evidence the row stays what the manifest read answered; on a plane image predating `pullRoute`, a Claude seat reads `none` until the plane updates. The wake pane reads only `armed.state` and `armed.reason`, which keep their meaning.

Evidence: L2 (unit, plus a producer test from the production `poll-digest` stamp through SQLite, `fleet-identities` and the plane reader into the routes source) → L4 required (an installed Fleet Start of a Claude seat) for AC-2's plane receipt and AC-3 on the installed FM. Residual: AC-2, AC-3, Residual-Owner: #571.

Prescription checked: `armFleetSeatWake.mjs` owns AC-1 and AC-2. AC-3's owner is `fleetWakeRoutesSource.mjs`, whose arming axis is what the routes pane shows; its pull evidence comes from the observation producer, per #768's Contract Ledger.
