Resolves #953

🌿 *An app that connected before a seat started can no longer be invisible to that seat.*

The Neural Link bridge relayed each app's `register` and `window_connected` messages only to the agents connected at that moment. An agent that joined later got nothing but `app_connected`. So every seat session started after an app registered saw it connected but without windows: `get_window_topology` omitted it, and nothing could be routed to it. That includes the installed Fleet Manager, which has been on the bridge all along ([#649's intake](https://github.com/neomjs/neo-agent-institution/issues/649#issuecomment-6084862144)).

The bridge now keeps each app's last registration and its open windows, from the messages it already relays. It replays them as `app_message` envelopes right after `app_connected`. There is no new wire type, and the agent side and the engine client are unchanged.

Evidence: L2 (unit: the Bridge with stand-in sockets, and the agent's own `ConnectionService.handleBridgeMessage` folding the replayed frames) → L3 required for the shared bridge (post-merge: a fresh seat lists the installed Fleet Manager's windows). Residual: the live bridge read, Residual-Owner: neomjs/neo-agent-institution#649.

| AC-2 | CI-covered by `Bridge.spec.mjs`: a window closed before the join is absent. A reconnect under the same id replays only the new registration and window, and the replaced socket's close evicts nothing (no `app_disconnected`; the successor stays). |

## Deltas from ticket

- **Reconnect guard.** `registerApp`'s close handler now acts only for the socket that is still registered. Before this, a socket replaced by a same-id reconnect closed after its successor had registered. It then deleted the successor from `apps` and broadcast `app_disconnected` for a live app. The replay state depends on the guard, so it ships here.
