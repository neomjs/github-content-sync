Resolves #52

S4b: the operator↔seat relation, keyed on the owner principal. One store on the Fleet's data root records which principal operates each seat. A seat's create claims its operator before anything else is written, and a plane-host CLI covers the legacy seats and transfers. One lookup, `operatesSeat(principal, seatId)`, reads it for #700 and #762. On the plane, the admitted claim stays dormant until #856 admits `defineAgent`. The product path is plane-side (#52's body, settled on the authority map).

Evidence: L2 (unit, on a real temp data root and the real registry; the CLI spawned as its own entrypoint) → L3/L4 required for the plane-side journey, owned by #856, #857 and #700. Residual: provision → Add → `operatesSeat` → Detail confirmation on an attached plane, Residual-Owner: #857.

## Deltas from ticket
- **A create claims its operator first** (Sophie's RA-1). `defineAgent` writes three stores in order: the operator claim (the admitted principal, or no one, which clears whatever an earlier seat of the id left), then the credential, then the registry row. A refused claim (busy, an untrusted store, a malformed admission) refuses the create before anything is written. A later write failure leaves a claim for a seat that does not exist, which no lookup reads as operated, and the next create replaces it. `removeAgent` releases the record as tidiness; the claim is the guarantee. `claim` and `release` replace `stamp`.
- **Integrity fails closed** (RA-2). The store's `version` must count its events, each `seq` at its position. A registry without an `agents` table reads `unavailable`, not empty. Neither is ever repaired by a relation operation.
- The store sits beside the forge-connection registry and follows its discipline: a lock file, a re-read under the lock, atomic replace, an append-only event log.
- `dispatchFleetRequest` forwards an admission only to `SEAT_CREATING_METHODS` (`defineAgent`). `fleetServerPolicy` passes `requestContext.ownerPrincipal` as that admission.
- `operatesSeat` answers `no-principal` for anything that is not an owner principal. The AC-6 arm found that a login reached the store and answered `other-operator`.
- **Unit isolation:** every create now reads `fleet.dataDir` through its claim, so `playwright.config.unit.mjs` binds that leaf to a root per worker process, removed at exit. Without it, specs that root their registry elsewhere would lock or write the host's Fleet root.
- **ADR-0019 checked** (critical gate 10). The store reads `aiConfig.fleet.dataDir` at the use site through `getDataDir()`, like `ForgeConnectionRegistryService`: no `?.`, no export, no pass-along (B5: the registry never threads its root into the store), no runtime write. Tests isolate through the env layer (`NEO_FLEET_DATA_DIR`) or the instance override, never by mutating AiConfig.
- Contract Ledger (RA-3): proposed on #52 to its author (5983621008).
