Resolves #932

A Claude seat now refuses a publishing or writing call whose input carries its own harness session id. `harnessIdGuardHook` runs on `PreToolUse` for `Bash`, `Write`, `Edit`, the GitHub workflow tools and Memory Core `add_message`/`add_memory`, and matches the payload's exact `session_id`. It uses node builtins only and fails open. Fleet projects it like the other seat hooks, beside the Engine's tracked `rgReplaceGuardHook`.

Evidence: L2 (unit tests: decision function, entrypoint subprocess, manifest matcher, reconciliation into hydrated settings) → L4 required (AC-5: refusal in a Fleet-launched seat). Residual: AC-5, Residual-Owner: #571.
