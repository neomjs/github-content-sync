Resolves #783

Fleet admission now resolves an admission's owner through a plane-governed forge-connection registry (ADR 0038 §2.2, amended by neo#19371): `owner:<connectionId>:<providerUserId>`, where the connection is the plane's own record of a trusted forge and the endpoints its operator approved. The plane-local CLI is the registry's only writer. A forge admission that does not resolve carries `ownerResolution` with its reason; a refused lifecycle write names it, and the Fleet service logs the refusal.

Evidence: L2 (unit specs over the real registry, real CLI processes over temp Fleet roots, and the real wire dispatcher). Residual: none on #783's ACs; the rollout step below is operational.

## Deltas from ticket

- **A class with an instance seam, not plain functions.** The intake's shape had `readConnectionStore(dataDir)`. ADR-0019 B5 forbids threading `AiConfig.fleet.dataDir` into a consumer, so the registry is a singleton that reads the leaf at its use site, with FleetRegistryService's `dataDir` instance override for isolation and tests.
- **`initialize()`, not `init()`**: `init()` is core.Base's construction hook.
- **Possession-only admissions are not resolved.** A context without `authProvider` (the local bearer) gets neither field, so its refusal keeps today's words instead of a misleading "no provider user id".
- **The refusal reason rides `error`.** The wire contract (`src/fleet/contract/wire.mjs`) whitelists its fields and is shared with the cockpit, so it is unchanged.
- **An endpoint with credentials, a query or a fragment is no endpoint**, stricter than the witness harness, which would have bound it by host.
- **`deriveOwnerPrincipal` is deleted**: its one caller now resolves.

## Rollout

Once a composed plane runs this, every forge-authenticated lifecycle write is refused (`uninitialized`) until its host initializes the registry and registers its forge, in the `fleet-server` container: `node ai/scripts/fleet/forgeConnections.mjs init --apply`, then `register --provider github --endpoint https://api.github.com --apply`. That is the ledger's intent: no owner-scoped write precedes registration. `ai/scripts/lifecycle/local-agent-os/README.md` shows the command. The installed Fleet Manager's local `devFleetServer` imports only the bearer-class assertions from `fleetServer.mjs` and never resolves an owner, so the packaged app is unaffected.
