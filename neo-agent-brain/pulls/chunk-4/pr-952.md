Resolves #921

Adds explicit A2A observation to the existing list/detail paths: `all`, `involves-me`, and recipient-only `own`. The server clamps the requested content policy and reads admission, retained history, count, page and detail from one SQLite snapshot. Observation leaves receipts and Tasks unchanged. Ordinary inbox calls keep their current behavior. Fleet's existing mirror/detail routes consume the request; the merged #946 question list and Home count now bind to its own-inbox scope.

Evidence: L2 (isolated SQLite, actual MC parser/adapter, Fleet bridge and real MCP SDK over scripted HTTP) → L2 required for the producer contract. The installed observer journey remains with Residual-Owner: neomjs/neo-agent-institution#490; installed own-question adoption remains with Residual-Owner: neomjs/neo-agent-institution#490.

## Deltas from ticket

- The plane client checks the connected session's advertised observer scope and optional policy before dispatch. Without this check an older schema would silently strip the new argument and perform an ordinary stamping list.
- Permission projection is reused through an internal synchronous stored read, so grants and content share the same snapshot. The separate pre-existing ordinary delegated-list cache window is recorded in the [author checkpoint](https://github.com/neomjs/neo-agent-brain/issues/921#issuecomment-6076897003) and a source note; this change does not claim to repair every ordinary permission reader.
