Resolves #857

Related: #877 (superseded: its branch carried a merge commit without a ticket id, and pushed history is not rewritten; this branch holds the identical change, same patch-id, as one commit)

In plane mode, the relay now defines a seat on the plane first, and this host applies only what the plane accepted. `defineAgent` goes to `<planeBase>/fleet` through a new `planeFleetClient`, which reuses `createFleetRegistryBridge`'s versioned wire. It presents the fleet-surface credential (`fleet.planeAdmissionBearer`), never the plane-MCP bearer.
- When the plane accepts, this host writes the plane's accepted definition as its actuation copy and claims no operator, because the relation is the plane's. The copy takes the plane's declaration fields, defaults included, plus only the host-owned PAT and launch owner.
- These each answer as themselves and write nothing here:
  - a plane refusal;
  - an unreachable plane;
  - an undeclared fleet-surface credential;
  - an id already defined on this host;
  - an answer without the accepted definition.
- A local failure after the plane accepted says the seat now exists on the plane.

In-process mode is unchanged.

Evidence: L2 (the relay's client against the plane's own S1 policy as a fixture, plus the bridge's plane path on a real registry in a temp root) → L2 required (AC-1 to AC-5 name a fixture plane or unit). Residual: none.
