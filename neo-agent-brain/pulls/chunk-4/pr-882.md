Resolves #874

🌿 Another operator's Start fleet no longer asks our seed file who is benched.

The Fleet roster's `participationStatus` now comes from the seat's identity node, as `who_is_online` reports it, with the operator's `statusReason` and `since` beside it. `resolveIdentityDisplay` no longer reads it from the roots. A read that did not answer leaves the status `null` with `participationRead: {state: 'unread', reason}`; a seat without a node is `null` with `state: 'read'`. Host mode gains a presence reader over its in-process Memory Core, so both modes read the node, and the roster and the wake-routes verb share that one reader.

Evidence: L2 (unit specs over the projection, the adapter, the bridge, and a host chain on a seeded test graph) → L3 required for AC-5 (the deployed Fleet's Start fleet summary). Residual: AC-5
