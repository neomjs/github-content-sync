Resolves #965

A Claude seat's wakes now follow the session prompted last, not the newest session process. The listener takes the seat on `UserPromptSubmit` (bounded, no polling) instead of `SessionStart`, so a resumed old session that nobody prompts can no longer hold the seat without ever polling. A `Stop` polls only while its own session owns the seat, and a dead or absent owner frees it. #907's guarantee is kept: a prompt still makes an older poll stand down before the new turn's digest.

Evidence: L2 (unit: the listener and the projected manifest) → L4 required for AC-5 (a live Claude seat after its hooks are re-projected). Residual: AC-5, Residual-Owner: #571.

## Deltas from ticket

- If a `SessionStart` entry is still registered from an older projection, its run exits at once with `a session start claims nothing`.
- A prompt in the session that already owns the seat keeps that session's running listener (`already-owner`), so a turn does not restart the poll loop.
