Resolves #950

`prepareRepos({id})` prepares a running seat's additional repositories through the same ordered ensure loop as Start. It clones missing checkouts, uses the captured launch's Git identity, and publishes timestamped `via: 'prepare'` outcomes only while that launch remains live. Reused checkouts are verified without configuration writes. The operation never restarts the harness or rewrites its workspace; unknown, stopped, identity-unavailable and superseded launches retain the ticket's explicit outcomes.

Evidence: L2 (real temporary checkout inspection and Git identity probes, with isolated clone/process boundaries) → L4 required (AC-5 installed same-session commit/push). Residual: AC-5, Residual-Owner: neomjs/neo-agent-institution#642. That witness requires the paired Accounts consumer and installed artifact; source tests do not prove native harness reach.

## Deltas from ticket

A two-attempt control found a retry gap: after a clone's identity setup failed, reuse alone could falsely report it prepared. `convergeSeatGitIdentity({readOnly: true})` now verifies reused checkouts without changing config or ownership records; mismatches remain failed until resolved. Real-Git controls prove missing, edited and Fleet-owned configurations remain byte-identical under verification. No pending-clone store or second clone path was added.

### 🔬 Depth Floor

- **Challenge** (three non-blocking notes):
  1. **The definition is read before the hold.** `registry.getDefinition(id)` runs at `FleetManager.mjs:910`, outside `withSeatHome` (`:925`). A preparation queued behind a long Start or another preparation therefore works from the repository list as of its request. A repository unlisted meanwhile is still cloned with the seat's PAT, and one listed meanwhile waits for the next request. Reading the definition inside the hold makes "what the seat declares" and "what the hold serializes" one moment. Otherwise, name the request-time snapshot in the JSDoc.
  2. **A missing credential fails present checkouts too.** A missing or unreadable credential swaps `ensureRepo` for a thrower (`:948`), so a checkout that needs no clone also reports `failed: the seat has no stored credential`. Failing only at the clone seam would keep those rows precise.
  3. **Bench and release are not consulted** (question; a hypothesis that needs V-B-A, not a finding). The verb does not consult `launchRefusalOf`, which `assertStartPermitted` uses. A seat whose identity is benched after its spawn keeps running and can still gain checkouts. A clone is not a start, so this may be intended; one JSDoc sentence would settle it.
- **Documented search:** I also looked for four failure modes and found none:
  - A refused Start overwriting the identity the verb trusts. It cannot: `startAgentProvisioned.mjs:280` returns for a running seat before any `setGitIdentity`, and the verb's launch snapshot is re-fenced inside the hold.
  - The verb and Start converging against different environments. Both call `convergeSeatGitIdentity` with its default `env`.
  - The new liveness clause dropping Start rows. No await separates `spawnPermitted`'s return from `setRepoOutcomes` (`:716`), so only a launch that died during its own spawn handshake loses its Start rows, which is consistent with the fence.
  - The PAT reaching a different origin. `credentialOrigin` is `agent.forgeHost`, the same as Start (`:555`).
