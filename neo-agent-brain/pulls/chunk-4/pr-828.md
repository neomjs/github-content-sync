Resolves #826

A running Claude Desktop seat's status now says where its session opened, against the checkout the seat was launched in: `sessionFolder: {state, expected, observed?, reason?}`, with `state ∈ {pending, ok, wrong, unknown}`.

The source is the seat's own Desktop profile (`claude-code-sessions/**/local_*.json`), never the host's shared `~/.claude/projects` transcripts. Every session on the machine writes those, so they cannot say whose a session is. That was the stage-2 finding at intake, and the ticket body is amended with it.

This is the Brain half of #571 gap 3. neomjs/neo-agent-institution#522 renders it.

Evidence: L1 unit on real temp profiles, plus a read-only run on a real Fleet seat's profile → L1 required (all three ACs are unit).

## AC Evidence

| AC | Evidence |
|---|---|
| AC-1 | `seatSessionFolder.spec`: `pending`, `ok`, `wrong` (with `observed`) and `unknown` (with `reason`), each with `expected`. `FleetLifecycleService.spec`: a running `claude-desktop` record carries it, while another family, a stopped seat, or a launch without checkout, profile or start carries `null`. The `FleetManager.spec` and `fleetCockpitStatus.spec` arms pass it through to the runtime row and the cockpit roster row. |
| AC-2 | `ok` comes only from a record in the seat's own profile: active since the launch, not archived, and opened (`originCwd`, else `cwd`) in the checkout. A record untouched since the launch reads `pending`. A session reopened at relaunch counts only once it is active again, and the most recently active session decides. |
| AC-3 | A malformed record and a shapeless one read `unknown` with "2 of the seat's session records since the launch could not be read", never `ok`. A readable record beside them still answers. |

## Deltas from ticket

- The source moved at intake, from shared transcripts to the seat's profile; the body is amended.
- `unknown` was added as a fourth state; the ticket now carries AC-3 for it.
- The folder is `originCwd`, else `cwd`, because a worktree session moves `cwd`.
- "Since the launch" means active since `startedAt`, because Desktop reopens a profile's earlier sessions on relaunch.
