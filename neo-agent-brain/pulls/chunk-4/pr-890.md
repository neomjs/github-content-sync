Resolves #879

🌿 A seat the operator benched is no longer woken because our team's file still calls it active, not even by a wake already waiting to flush.

The wake daemon reads the `AgentIdentity` rows once per poll cycle, through the graph store's `idx_nodes_label`; these are the rows `who_is_online` reads. `wakeTargetPermission` answers `eligible`, `benched` or `unread`, and every delivery boundary uses it:
- queue admission;
- the coalesced flush, before it consumes its queue;
- retry enqueue;
- retry attempt.

A bench drops the work. An unread read defers it: a throwing read aborts the cycle before the cursor moves, and queued and retried work waits for the next read. A seat without a node stays eligible. `wakeTargetEligibility.mjs` no longer imports the roots.

Evidence: L2 (spawned daemons over temp graphs, plus the query and permission specs) → L2 required (the ACs name specs and a grep). Residual: none
