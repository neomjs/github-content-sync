Resolves #829

A Fleet seat now commits as itself.
- **Resolving the identity:** Start resolves the seat's Git identity before anything is cloned. A declaration on the definition wins. Otherwise the seat's own forge account is read with its existing PAT, and it must be the seat's own: a PAT that answers for another login is a mismatch. The email is a GitHub primary only when public, a GitLab commit address, then the public email. No address is ever made up.
- **Carrying it:** each managed checkout gets the identity in its own config scope. A value the Fleet did not write, or one edited or unset since its write, is never overwritten. The launch env carries the four `GIT_*` values.
- **Checking it:** `git var` must read the identity back with and without that env. A missing, unreadable or conflicting identity refuses the start with a typed `FLEET_SEAT_GIT_IDENTITY_*` reason that names the next step.
- **Showing it:** the seat status and roster row carry `gitIdentity`, and `fleetSeatGitIdentity({id})` gives Add the same derivation after a define.

Evidence: L2 (unit arms: a fixture forge, real temporary repositories and a linked worktree, the launch env as a control) → L2 required (AC-1 to AC-5, each marked unit on #829). Residual: the installed seat's own commit, Residual-Owner: #571.

## Deltas from ticket
- The Fleet replaces **its own** write, unchanged since, when the seat's resolved identity changes. Otherwise a renamed account would read `mismatch` against the Fleet's stale value. An edited value stays foreign, as the ledger says.
- A caller's launch env may not name any of the four `GIT_*` slots (rejected fail-fast), so only the resolved identity reaches the child.
- An address-list failure other than 403/404 fails the read as `unknown` instead of falling back, so a provider outage never switches a seat's address.
