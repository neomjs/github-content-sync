Resolves #797

An adopted seat now brings its agent's markdown memory with it. `defineAgent` records the consent, `memoryImport`: an agent's memory folder, or `'none'`. Start then copies that folder into the folder the seat's family loads memory from. Start refuses until a consented first import has arrived verified, and it refuses again if the seat later reads empty. This follows the steward's call B on the ticket: the consent is born in `defineAgent`, converged in the seat, and refused at Start when unconverged; it is not a first-run recipe step.

Evidence: L2 (unit specs over real temp folders for the import, the real Codex preparer followed by the import, and the existing injected-composer specs for Start). Residual: none on #797's ACs; the installed witness is the #571 pilot below.

## Deltas from ticket

- **The consent names only an agent's memory folder:** `~/.claude/projects/<project>/memory`, `~/.codex/memories` or `~/.codex-instances/<name>/memories`. `defineAgent` is a wire verb, and the copy reads whatever the consent names. An open path would let a wire caller have the Fleet copy any host directory into a seat it starts. Every segment from the home down to the folder must be a real folder, so a link anywhere on the path cannot carry the allowed words into another tree. Start re-checks this, and detection applies the same rule.
- **A first import completes or refuses.** If the seat already holds a source file with other bytes, Start refuses before copying anything and names the file to reconcile. The seat's own content is never overwritten. A source that holds nothing also refuses. Once the import is receipted, only a fresh read of the destination counts, so the seat's later edits never fail a Start.
- **The import runs in `startAgentProvisioned`, after workspace preparation and before the spawn,** not inside `prepareManagedAgentWorkspace`. The workspace plan's agent is a closed `{id, harnessType, forge}` record, so the registry row's consent never reaches it. `importMemory` is an injectable seam like `prepareWorkspace`. Because preparation runs first, the import sets its destination to 0700 itself: the Codex preparer leaves `memories` at 0755.
- **One `deriveCodexHome`.** A Codex seat's `CODEX_HOME` was computed inline in the launch spec. It is now one exported function that the launch spec and the import destination both use, so the two cannot drift.
- **A seat without a managed repository is refused** when it consents to an import: Claude pins its memory folder in the managed checkout, so there is nothing to converge into.
- **The cockpit's add-agent offer is its own leaf** (Institution), over this field and `detectMemoryCandidates`.
