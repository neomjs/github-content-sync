Resolves #840

The first-run recipe is now the one effect order, and an evaluated effect row says what it needs as data. `EFFECT_ORDER` is read from the recipe's steps instead of stated a second time. Every effect row that is not `ok` carries `waitsFor`, the step in its way, and a selected effect that cannot run reports the same step where it used to return silently. The `verify` row carries `exits` and `duplicatePossible`, so a renderer never matches a reason sentence to choose an action; the CLI's text output reads those fields. In the other direction, the effect no longer writes a second witness once the first is accepted, whatever the caller consents to.

The record came first (ADR 0005 §6.5): neomjs/neo-agent-brain#843 (ADR 0041 §2.10) merged on 2026-10-04.

## Deltas from ticket

- **The recipe's list moved, the host's write order did not.** Every real run has written the secret files before the carrier that points at them, so the recipe now lists them that way and a renderer's two file rows swap. No recipe version bump: the steps and their meaning are unchanged, and a bump would retire every existing run's consents.
- **A new attempt is named only after a search.** Right after a lost acknowledgement the row names `resume`; once a reconciliation read answered without the marker it names `resume` and `new-attempt` with a possible duplicate. That takes one new stamp on the attempt, `attempt.searchedAt`.
- **An accepted witness refuses a new attempt** (AC-5, added on the record author's read of #843). Before, `--new-attempt` on an accepted run wrote a second row that proved nothing; a new run is the way to witness a plane again. A new attempt outside the row's exits in any other state is still made, since ADR 0034 puts that admission at the shell and the CLI's flag is the operator's consent at the host. Every attempt records the exits it was offered (`attempt.offered`), so the record shows which writes were made outside them.
- **A failed host effect says so** (AC-6, folded in by the planner on 2026-10-04 from the gap line neomjs/neo-agent-institution#351 comment 5981291794). A `write-env` whose handler threw read `pending` with "… does not exist", so nobody learned why. The absent result still decides the row; the failed receipt beside it says why it is absent, as an accepted receipt already says a result is gone (ADR 0041 §2.3: nothing turns green from a receipt). A run retries it. The CLI's exit code for such a run is 1 where it was 2.
- **The provider-key question waits as data too.** The Institution's card chose that row's action by the first word of its reason (`apps/agentos/view/setup/StepList.mjs:27`), so AC-4 was not satisfiable for it: the row now carries `waitsFor: 'preset'` until a preset is consented.
- **The same silent return existed behind an unanswered question**, and behind a consented preset the table no longer holds. Both now report.
- **`verify`'s gate report takes the same sentence shape** as the other waits: `'verify' waits for 'validation': it is …`.
- `EFFECT_ORDER` and `VERIFY_GATES` stay exported, derived from the recipe: the Institution's broker reads the first.
- Not in it: exits for host-effect rows. A failed host-effect row whose receipt is accepted is #810.
