Resolves #930

An existing managed Codex seat can discover and explicitly select its own native notes for import into its shared memory folder. Scoped discovery binds the registry definition to both host placement owners and requires the producer's matching scope echo; old, mismatched or unreadable answers remain unavailable. Consent admits only that seat's derived source. Start refuses before birth files when native notes exist without a choice, while explicit empty memory and completed-import receipts retain their behavior.

Evidence: L2 (real temporary files with isolated registry, wire and Start-composer controls; no live seat changed) → L4 required (AC-6 installed native retention). Residual: AC-6, Residual-Owner: #571. The installed witness requires the paired Institution chooser and a coordinated cold-start window; it is not claimed by these tests.

### 🔬 Depth Floor

**Challenge 1: the placement check treats two roots as one.** `managedMemorySource` checks `agent.seatHome === path.resolve(instanceRoot, agent.id)`. `seatHome` is recorded under the registry's agents root (`FleetRegistryService` → `getAgentsRoot()`). The native home, however, is derived under the lifecycle root (`getInstanceRoot()`, documented as "the test/tenant override seam"). When those differ, the birth gate throws the helper's uncoded `TypeError` out of Start, where `dev` started the seat fresh.

Named falsifier: `importSeatMemory` for a `codex` seat with no consent, seat home under `<tmp>/agents`, `instanceRoot` `<tmp>/instance homes`:

| Tree | single-root | split-root |
|---|---|---|
| `dev` `98e52e9e06` | `{"state":"none"}` | `{"state":"none"}` |
| head `9ee32e1eee` | `{"state":"none"}` | `THROWS TypeError - Seat 'neo-x' has no matching managed memory placement on this host.` |

`9ee32e1e` moved the `onboardPeer` owner fixture from split roots (`repos` / `instance homes`) to one root, so the suite no longer covers that layout.

Why this is non-blocking: no production code writes `FleetLifecycleService.instanceRoot` on Brain or Institution `dev`; the only other hit is one Institution e2e spec. `devFleetServer` sets `FleetManager.managedRoot = AiConfig.fleet.agentsRoot`, and `getInstanceRoot()` falls back to the same leaf.

Either fix is small; your call:
- turn the mismatch into a coded `unconverged` refusal and keep a split-root control; or
- state on `getInstanceRoot` that native-memory admission requires one root, and add the fixture narrowing to Deltas.

**Challenge 2: the chooser has to arrive no later than the gate.** The birth gate goes live in the FM with whichever Institution Brain-pin move carries this PR. Until Institution #603 forwards the seat id, that FM's chooser offers only the host-global candidates. So an affected seat, such as the one your preflight found, gets refused with "an explicit memory source or empty-memory choice", and the only product answers are:
- `none`: once the seat writes shared memory, `seatHoldsMemory` locks the consent, and the native notes can no longer be imported this way;
- a classic host folder such as `~/.codex/memories`: someone else's notes.

Suggested guard: put the order "the Institution Brain-pin move that carries #983 also carries #603, or comes after it" on #603's ACs or the pin-move checklist.
