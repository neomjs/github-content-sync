Resolves #883

🌿 A bench no longer needs a pull request, and a sign-in can no longer undo one.

The plane host records an identity's participation with `ai/scripts/fleet/participation.mjs` (`bench --reason`, `activate`, `show`). It is a dry run unless `--apply`, and its actor is `os-user:`. The write, `recordParticipation`, puts `participationStatus`, `statusReason`, `since` and `participationDecidedBy` on the identity node. A recorded decision outranks the other two writers: the seeder leaves a decided node's participation fields alone, and the sign-in refresh writes `participationStatus` only when it creates a node. `IdentitySchema.md` states both rules and gives the command. This is #28's first write slice; the cockpit's own write still waits for an identity-wide principal.

Evidence: L2 (specs over the write, the command, the seeder and the sign-in refresh) → L3 required for AC-5 (the command on the plane, read back through `who_is_online`). Residual: AC-5

- Re-recording the decision a node already carries writes nothing, so `since` stays the date the decision began.
- The command loads `dotenv` inside its entry function, unlike `seatOperators.mjs`, so its spec can import it in-process.
