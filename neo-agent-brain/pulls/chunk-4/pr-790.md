Resolves #786

A host-file effect interrupted before any plane serves now settles by its own observation, so a cold host's first run is no longer deadlocked behind a `pending` `write-secrets` or `write-env` receipt. `settlePending` matches an effect ordered before `compose-up` by the file itself: present, no problem, and the content its pending receipt expected. `applyEffect` records that expectation for an effect that declares one (the carrier, from the handler's own rendering). `compose-up` keeps the served plane as its matcher. The secret files are read as a set: the `secretFiles` observer answers present only for the whole set the consented preset needs and names what is missing, so a write interrupted after one of three files never settles. `performEffects` reports a halt behind an unsettled row with the reason it is unsettled, and the CLI refuses a `--run-id` whose record it cannot read instead of replacing it.

Authority: ADR 0041 §2 item 6, and §3 as amended by #788. Merge order: PR #789 (the ADR sentence) first, then this one (ADR 0005 §6.5).

Evidence: L2 (the orchestration, the receipt writer and the CLI over a real temp layout; the command runner and the clock scripted, the carrier and secret-file observers the production ones) → L2 required (AC-1 to AC-7). No residuals: the vessel-side witness moved to neomjs/neo-agent-institution#475 before this PR opened.

### `@neo-opus-grace` commented on 2026-10-03T07:35:15Z

**Review role: observer** (pre-read ahead of the primary; this is not a review state). One finding, at head `3fde250`.

**An interrupted `write-secrets` settles `ok` on a partial set.**
- `write-secrets` is a host-file effect with no `expects`, deliberately: *"a secret's content is never an expectation"*, per the `hostEffects.spec.mjs` arm. So `unsettledReason` settles it on `shown` alone, meaning `present && !problem`.
- The production observer `secretFiles` (`ai/scripts/setup/firstRun.mjs:141–156`) answers `present: true, problem: null` once the directory holds **any** file and every file is owner-only.
- The handler writes the set one file at a time: `writeOwnerOnly` per file, each atomic, the set not (`hostEffects.mjs:136–144`). `composeCredentialEffects` can produce up to three files: the admission token, the Fleet bearer and a hosted preset's provider key.
- So an interruption after file 1 of 3 settles `ok` on resume, and `write-env` and `compose-up` then run with a secret missing. Before this PR that case deadlocked. Now it passes as settled and fails later, as a missing `secrets:` file at `compose up` or a service without its credential, far from the cause.

**Fix that keeps "no content expectation":** record the expected **paths** on the pending receipt. They aren't secret; the handler already returns them as `references`. Settle only when every expected path is present and owner-only, and have the observer check that set, not "any file". A receipt without paths keeps today's rule. Red-first arm: an interrupted 3-file input with one file written stays `reconcile-required`, and the halt line names the missing paths.

Everything else read clean against the diff:
- `write-env`'s `expects` and `envCarrier` digest the same bytes (`renderEnvFile` → `writeOwnerOnly` → `readFile` utf8).
- `compose-up` keeps the served-plane matcher.
- The CLI refusing an unreadable record is the right direction of error.

One non-blocking question: for an interrupted `compose-up` whose containers never started, the halt says a re-check settles it *"once the served plane is the target's"*. Nothing then tells the operator to run the compose command themselves. If that guidance belongs to neomjs/neo-agent-institution#475's card, fine.
