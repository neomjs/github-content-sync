Resolves #907

The Claude wake listener now polls only on `Stop`. Under Claude Desktop, the long-running listener registered on `SessionStart` was not backgrounded while the SDK initialized, so an FM-launched seat's first prompt waited until a wake arrived or the 86400 s timeout passed.

`SessionStart` keeps one bounded entry, with no `asyncRewake` and a 10 s timeout. That run only takes the seat for the newest session and exits, so an older session's listener stands down instead of consuming a digest during the new session's first turn. The listener's `SessionStart` head-start `sleep` is gone, and `Stop` keeps the `asyncRewake` poll.

Watermark carryover applies on the same plane when the seat already has a stored watermark. A seat's first listener, or a listener on a changed plane, records a baseline at its first `Stop` poll rather than replaying earlier events.

Evidence: L2 (unit: manifest projection, listener ownership/overlap control, red-first on both) → L4 required (AC-3: a re-projected FM Claude Desktop seat runs its first prompt unaided). Residual: AC-3, Residual-Owner: #571

The older poll then returns a digest at 11 and exits `superseded` with the watermark still at 10, and the newer session's first `Stop` gets that digest.
  - Removing only the claim-only return makes this control fail (`the listener never stopped`).
  - With `origin/dev`'s manifest, the projection test fails at the registration assertions.

- **Live witness behind the fix:** in Ada's pilot on 2026-10-06, killing only the session's `SessionStart` listener moved Desktop from `initializationResult read failed` to a mapped CLI session within 1 s, with `init=71908ms`.
