Resolves #922

🌿 *An operator's open question can no longer pass as one mailbox row among all mail: the cockpit can list what waits for their word, and count it.*

The Fleet wire now reads the viewer's own open questions. `fleetOwnQuestions({limit, offset})` asks the own-inbox seam for #860's Task view: `InputRequired`/`Submitted`/`Working`, `status: 'all'`, `includeArchived: true`, `taskOrder: 'priority-age'`. It answers the mailbox mirror's body-free rows with the complete count, under the transport-stamped viewer; no identity crosses the seam. `fleetOpenWork` carries `questions: {state, count, reason}` from a one-row page of the same read, so the Home axis counts what the list lists. The read runs only through the seam's `observeMessages`, a list that never records `seenAt`: in process it is `MailboxService.listMessages`, non-stamping by omission; a plane wires none, because its one list is the model-visible `list_messages`, so there the questions and their count answer `unavailable` until #921's observer path serves them. An unwired, failed or countless read answers `unavailable` with its reason, never an empty list or a zero. A Task can also carry its sender's optional `fallback` plan (Emmy's decision on #922): validated and declared, it survives transitions and expiry, the recipient reads it through `getMessage`, and nothing runs it.

Evidence: L2 (unit; a real-graph MailboxService test runs the bridge's exact query) → L2 required (every #922 AC is unit-scoped). Residual: on a plane the questions read unavailable until an observational list exists there, Residual-Owner: #921; the cockpit consumer and its installed witness are Institution #599.

## Deltas from ticket

The read is a new verb, `fleetOwnQuestions`, rather than a `fleetMailboxMirror` mode: the mirror stays one agent's active inbox, and the questions view needs archived rows and a Task filter it never forwards. The mirror's row projection is exported (`createFleetMailboxMirrorRow`) so both share one body-free row; it now carries `archivedAt`, which only the questions read can set (the mirror lists active mail), and each questions answer carries `capturedAt`. Clio's design read on #599 needs both: archived-but-open rows say `archived`, and the pane's freshness chip ages the list by its own read. `fleetOpenWork` became async; it has no in-process caller.
