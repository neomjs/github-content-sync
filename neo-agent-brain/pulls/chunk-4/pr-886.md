Resolves #885

🌿 Start no longer launches a seat its operator benched, when the bench can be read, not even one benched mid-start.

`launchRefusalOf(definition, participation)` gives the release refusal first, then the operator's bench in words: "benched by the operator on <date>: <reason>". Four places read it:
- `startAgent`, inside the seat's home, so a start keeps its place in the seat's queue;
- `restartAgent`, before its stop;
- `spawnPermitted`, which re-reads after preparation;
- the roster row's `launchRefusal`.

An unread participation is no refusal. The cockpit's Start fleet exclusion of `unread` stays #28's Institution leaf.

Evidence: L2 (specs over the contract, admission, restart, the spawn re-read with a bench during preparation, and the roster row) → L3 required for AC-5 (a per-card Start of a benched seat on the plane). Residual: AC-5

## Deltas from ticket

- `startAgent` reads participation inside `withSeatHome`, not before it. An await before the home let a model-catalog read queued after the start overtake it, which is what the existing queue-order spec caught.
- `seatParticipation` snapshots the one seat, and only when a presence reader is wired.

## Test Evidence

- Negative control: against the pre-change source, the five #885 specs fail. The two positive controls (release first, and nothing refused for active or absent participation) pass on both.
- Contract, fleet, provisioned-start and manager suites: 1423 passed, 2 skipped, 4 failed. The 4 are `provisioningTemplates.spec`, which reads `.codex/config.template.toml`; this checkout lacks that file.
