Resolves #787

The wake delivery reader now holds each terminal record by file name and reads only new, `pending` or `dispatching` ones; overlapping calls join one read. `who_is_online` used to re-read the receiver's whole history on every call (9,572 files on the plane today). A repeat read of the same directory now costs one `readdir`. `receiverState` exports `TERMINAL_STATES` and refuses a transition out of a terminal state, which is what makes holding a record by name safe.

Evidence: L3 (unit arms, red-first plus one mutation per guard; the shipped module run in a throwaway container from the plane's MC image over the real bind-mounted records) → L2 required for AC-1–AC-5. Residual: none.

| AC-3 | › a record the directory no longer lists is let go: it leaves the verdict, and a return is read fresh |

## Deltas from ticket

- `receiverState.transition()` refuses a terminal expected state. The ticket's Architectural Reality showed that terminal records were final only by caller convention. The reader's hold now depends on that, so the writer enforces it (one arm in `receiverState.spec.mjs`).
- AC-3's arm also covers a name that returns with new content. Its first version passed with the deletion loop removed: it was checking the wrong axis.
- AC-6 moved to #787's Post-Merge Validation as PMV-1 and was discharged before merge in the plane's own image.

## Test Evidence

- **Red-first:** against the old reader, exactly the AC-1 and AC-4 arms fail (2 failed, 11 passed).
- **Mutations**, each killed by its own arm only: hold every record (AC-2) · drop the deletion loop (AC-3) · drop `held.clear()` (AC-5) · drop the finality guard (the `receiverState` arm).
- **Neighbouring suites** (`unit/ai/services/memory-core` and `unit/ai/daemons/wake`): the same 10 local failures on base and head (graph backup, NL relocation, embedding caps, none on the wake path); head adds 6 passes.
- **The shipped module on the plane's records:** a throwaway container from the plane's MC image mounted this branch's two source files plus the real records directory, read-only, with no network. The first read took 2,711 ms; repeats took 195–197 ms; three overlapping calls took 204 ms and resolved to one shared result. All observed the same 11 subscriptions as the live `healthcheck`. For comparison, the old reader's full read in the live container took 3.9–4.4 s every time.
- **What the hold costs:** 23.3 MB of heap for 9,577 records (measured with `--expose-gc` in the same image). The MC's limit is 2.35 GB, and the directory grows by about 330 records a day.

None owed. The plane check ran before merge (above). After the next canonical container refresh, `get_memory_core_tool_metrics`' recent slow calls should stop listing `who_is_online`, an observation rather than an obligation.
