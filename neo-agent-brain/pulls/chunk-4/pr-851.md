Resolves #841

🌿 A wake receiver that stops accepting can no longer pass for one with nothing to accept: its own account says when it last did.

The receiver keeps `records/receiver.liveness`. It records:
- its starts;
- the last completed accept;
- the last completed pass of its 30 s manifest sweep;
- #838's stuck exits.

Each list is bounded at 20, and the file is replaced atomically on each event. The name isn't `.json`, so neither record reader takes it. A plane already mounts `records/`, so no deployment changes. A stuck exit is written synchronously before the process exits, and the next start carries it forward. The sweep stamp runs inside the watchdog-tracked pass, so a write that hangs is a stuck pass, not a silent one.

The account is an observation, never a precondition. Startup doesn't wait for it: the start is stamped at creation, the previous account is read within 2 s, and later writes queue behind that read. `normalizeReceiverLiveness` owns the shape, so a wrong-shaped account reads `unknown` and a start over it begins fresh. The contract is the ledger on #841.

`readWakeDelivery` projects the account as `receiver`: both ages, plus the last hour's starts and stuck exits. Healthcheck's wake delivery block therefore carries it, and an absent account reads `unknown`, never fresh. `stopWatchingManifest` now returns the reload chain, so a caller can wait for the last stamp.

Evidence: L2 (unit arms: the account's semantics, a real `startWakeReceiver` over a temporary state directory, the accept hook, the reader over a real records directory) → L3 required (the host receiver writes the account and the plane reads a fresh sweep age). Residual: both deployments, Residual-Owner: #503

## Deltas from ticket

- The sweep pass is the heartbeat, not a manifest reload. Reloads happen only on change, so their age is normally hours. The ticket's ACs now say so.
- The account lives in `records/`, not beside it, because the plane mounts only `records/`.
- "Restart count" is `startsLastHour` (every start, whatever caused it), beside `stuckExitsLastHour` (the watchdog's).
