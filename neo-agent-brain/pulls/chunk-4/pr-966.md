Resolves #964

When a plane is slow or restarting, native MCP launch admission now reports an unanswered proof instead of telling the operator their credential is invalid. The launcher retries transient failures with fresh signed requests under one 60-second elapsed-time budget. Expired proofs abort their network requests; identity, plane binding and generation revocation checks remain in place. MC and KB expose `healthcheck({scope: 'plane'})` to read authenticated process identity without full health probes.

Evidence: L2 (focused unit and native-launch controls) → L4 required for served-plane timing and the installed multi-seat startup witness. Residual: AC-5 live timing and AC-6, Residual-Owner: neomjs/neo-agent-institution#12.

## Deltas from ticket

Terminal credential refusals retain the existing credential-type `reason` label for compatible FM rendering. `proof-unavailable` carries the allowlisted producer diagnostic in `reason`, falling back to a fixed credential-type label for unknown text; the machine verdict alone controls retry. Legacy `{ok}` proof callbacks remain compatible, while an explicit unknown verdict fails closed. No new MCP tool or positive proof cache was added. The default healthcheck remains unchanged; the optional scope does not inject a new default argument into existing calls.

The probe uses seven protocol requests plus two best-effort session DELETEs when proving caller identity and both plane roots; this corrects the ticket's eight-round-trip estimate. The optimization removes dependency probes from the two healthcheck calls, not the authentication exchanges.
