Resolves #67

The presence hook writer's deadline now comes from config leaves and matches how each harness registers the hook. Each entrypoint names its registration. A synchronous deadline must leave the hook process 500 ms of it; a configured value that does not is refused by name before the plane is dialled. Only an asynchronous registration (Claude's `progress`) spends the remote-sized deadline. A skip, a refusal or a spent deadline ends in a named warning on stderr in all three harnesses, and the hook still exits 0.

**How config reaches the writer.** `TurnPresenceConfig`, the retired twin shape (ADR-0019 §10.1), is deleted: its literals now sit inline in the leaves, and its parallel env resolver is gone. Both deadline leaves are `positiveInt`, so a malformed env value warns by name and the default stands. The writer stays Neo-free and resolves nothing. Each hook entrypoint (Claude, Codex, Kimi), already "the only place config is resolved", reads its deadline through `seatConfig` for its own registration and injects it beside the plane. Loading the Memory Core config there costs about 2 ms on top of the Tier-1 load the plane read already pays.

**Rollout.** Seats are never re-projected unattended. A copy projected before this lands still loads but injects no deadline, so each write is a named skip that says to re-project. A pre-#817 Codex copy swallows that skip, and its context still loads. #67's Contract Ledger holds the full rows.

Evidence: L2 (unit arms, plus the projected hooks spawned against a silent and an answering local plane). No harness observation. Residual: where the Claude harness captures an async hook's stderr (below).
