Resolves #862

🌿 A seat declared at a model and effort starts on them, and its row shows the config beside the declaration, so "the harness quietly started on its own default" stops being something nobody sees.

A seat declares its model and reasoning effort through `configureAgent`. Each field is set, or handed back with `null` so Fleet stops setting it. A harness change withdraws both, because a model id names one family's model.

Start carries the declaration into what each family reads:
- `claude-code` gets `--model` and `--effort`.
- `codex` and `codex-desktop` get `model` / `model_reasoning_effort` at the root of the seat's `config.toml`, replacing whatever value it held. The file is read and written as TOML (`codexConfigToml.mjs`): only the root value changes, quoted keys and multiline strings included, and the result must parse equal to the source except for the declared values. Otherwise nothing is written, and Start refuses with the reason. A withdrawal leaves the file alone.
- `claude-desktop` takes no declaration: its app starts every session with its own flags, which outrank any settings file (AC-3's probe).

A value that merely differs never refuses a Start (Clio's disposition, 20:03Z); a real error still does, and #864's validation will. The runtime status row and the cockpit projection carry `harnessSettings`, what a Codex seat's config is set to now, a stopped seat's included. That is configured state, never proof of what a chat runs on.

Evidence: L2 (unit arms over the declaration, the launch arguments, the workspace converge on real seat homes and the live read-back) → L4 required for AC-5 (the effective model and effort a started and a resumed Codex thread report, on the next #12 candidate). Residual: AC-5, Residual-Owner: #571.
