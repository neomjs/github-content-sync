Resolves #558

🌿 The PR bird view answers for the repository a caller names, so a plane that carries six tenant corpora stops pretending it only ever had one.

`explore_pull_request_history` ran against the one repository the server's AiConfig named at start (`owner` / `repo` injected through the dependency bag, `PullRequestHistoryService.mjs:1372–1373`), read one pre-split corpus root, and handed back repo-implicit drill-downs; the tool schema exposed only the window. It now takes an optional `origin` (`owner/repo`). `resolvePullRequestOrigin` decides what the call addresses before any read: absent, the configured repository and roots, unchanged and without a catalog read; present, the owner must be the plane's configured owner and the repository a slug the plane's corpus catalog names — `resolveContentOrigins(fleet.contentRoot)`, the `_index.json` reader #413 gave the fleet activity feed, now moved to `ai/services/graph/contentOrigins.mjs` and imported by both consumers so "known origin" is one set — or the configured repository itself. The request never builds a path: `.` / `..` are refused before the catalog is read, and a catalog row is selected by exact slug equality, so an existing but unindexed directory is not an origin. A catalogued origin reads its row's `pulls` and sibling `archive` roots even when the tree is missing (the scan degrades by name, as the activity feed does); the configured repository outside the catalog keeps the pre-split roots. Anything else is refused with an `Error` carrying `code: 'unknown-origin'` and the origin, never answered from the default. Every returned drill-down now names its repository — `get_conversation {pr_number, repo: 'owner/repo'}`, the configured origin included — so a handle from one origin never opens another. The live search, the review-comment passes, the release-window resolution and the temporal cache partition (`repository:${owner}/${repo}:${resolution}`) already took `owner` / `repo`. The op passes the caller's options through unchanged; the openapi `origin` description, which is the tool's handbook entry, names the form, the catalog, the refusal and the drill-down rule.

Evidence: L2 (fixture + unit arms on the service's injected seams; the spec unloadable at dev because the export does not exist there) → L4 required (a call with `origin: 'neomjs/neo-agent-brain'` on the local plane, AC-1). Residual: AC-1's plane receipt, Residual-Owner: #64 (AC-8).
