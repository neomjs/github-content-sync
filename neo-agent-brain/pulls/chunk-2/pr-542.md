Resolves #534

ISSUE and PULL_REQUEST graph nodes now carry the logins the corpus holds, which is the node fact the observatory's team lens colours and filters by (neomjs/neo#10034, H3-g).
- **ISSUE nodes** get `author`, and `assignees` as an array: `[]` when nobody holds the issue, so the next sync after an unassignment replaces the old holders.
- **PULL_REQUEST nodes** get `author`, and `assignees` only where the synced frontmatter has the key. `PullRequestSyncer` writes none today, and an absent key must not read as an asserted empty list.
- **No backfill:** `GraphService#upsertNode` merges `properties` on every call, and both ingest passes upsert every node on every sync, so existing rows gain the fields on the first sync after the plane runs this head.
- **CI coverage:** `IssueIngestor.spec.mjs` joins `brain-unit.yml`'s run list; it was never on it.

Evidence: L2 (the ingestor spec over real frontmatter files in a temp content root; CI's run list run locally) → L3 required (AC-2: the plane's ISSUE rows gain `author` after a sync on this head). Residual: AC-2, Residual-Owner: neomjs/neo-agent-brain#64 (the plane recreate onto a merged head is Vega's lane there).

Order vs #459 (AC-3): this PR lands first. #459 (unassigned, no PR) rebases its content-root fallback onto it, as named on #459 ([comment](https://github.com/neomjs/neo-agent-brain/issues/459#issuecomment-5844753843)).
