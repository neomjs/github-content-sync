Resolves #509

🌿 A read receipt the GC deleted can be given back from the bundle that still holds it, without touching a mark made since — the incident has stopped being permanent.

`ai/scripts/maintenance/restoreReceipts.mjs`, beside `restore.mjs`: for every `DELIVERED_TO` edge and `MESSAGE` node in a bundle's graph JSONL that carries `readAt` or `archivedAt`, the live row with the same identity (`(source, target, type)` for deliveries, the node id for direct messages) receives the field where it is null; a non-null live value is never touched. Every non-mailbox edge type is counted against the live graph, and the types named with `--edge-types` are inserted where no live row shares their identity and both endpoints exist, the identity checked inside the insert statement (`INSERT … WHERE NOT EXISTS`), so neither a second bundle row for the same identity nor a concurrent live writer can produce a second edge; the three mailbox carriers are never inserted. A bundle's duplicate rows for one identity or one receipt field count as `duplicateInBundle`, the first row wins. The whole source is parsed before the first write, so a malformed record refuses the run instead of ending it after committed batches; a failure past that point returns the committed counts on the error, and a rerun is safe because every write is conditional on the live state. Counts are the rows the statements changed. Dry-run by default with the database opened read-only, so nothing can be written without `--apply`; `--db-path` is explicit and mandatory (`mailboxReadStateProbe.mjs`'s handle shape). Bundles chain: run oldest first, each fills only what the later ones lack.

Evidence: L2 (eight arms on a real SQLite file) + L3 (the read-only dry run on the live plane, below) → L4 required (the operator-gated `--apply` on the shared graph, AC-3). Residual: AC-3, Residual-Owner: #64.
