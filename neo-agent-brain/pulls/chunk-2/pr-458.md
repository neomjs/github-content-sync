Resolves #432
🌿 *A tenant slice can no longer spend its rebuild starting one git process per file of a corpus it read a minute ago.*

The envelope used to read every file through `readRevisionBlob`, which pays a credential resolution, an isolated HOME and a `git show` spawn per file, awaited one after another. Now `GitMirror.openRevisionBlobSession` answers the whole revision from a single `git cat-file --batch` process. It is anonymous and runs with `GIT_NO_LAZY_FETCH=1`, so it serves local objects only. Anything it cannot answer comes back `null` and falls through to the per-file read, which still owns the credentialed promisor fetch. The revision reader shares one session with every scope it hands out, and `buildIngestEnvelope` closes it in a `finally`. `getEntry` now uses a path index instead of a linear scan on every read.

Evidence: L1 (unit arms and two mutation controls) + L2 (a local 2,000-file fixture benchmark, no plane) → L4 required for AC-3 (the deployed slice's rebuild time). Residual: AC-3, Residual-Owner: #64.

## Deltas from ticket
- `getEntry`'s path index. The linear `find` measured 3,784 ms against 6.3 ms over 47,140 entries. It was added to #432's Fix before this PR opened.
- `openRevisionBlobSession` takes `maxOutputBytes`, the same per-read limit `runGit` applies. A body over the limit is discarded as it streams and never buffered whole, so the discard arm runs without a 50 MB fixture.

## Test Evidence
- **Mutation A** (per-file fallback removed): 4 arms red. They are the #432 reader arm, two older reader arms and the builder failure arm.
- **Mutation B** (builder `close()` removed): 3 arms red. They are the #16045 isolated-HOME arm (the session's HOME outlives the build), the FULL `close` assertion and the failure arm.
- **Local benchmark** (macOS, 2,000-file fixture, the same builder with and without the session): per-file 19,233 ms, batched 512 ms (37.6×), with byte-identical envelope `files`.
