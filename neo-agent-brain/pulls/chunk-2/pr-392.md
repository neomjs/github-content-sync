Resolves #105

Adds the Discussion family to the existing durable community reconciliation pipeline. Every pass enumerates active and closed roots, then independently exhausts comments, replies and provider edit revisions. Child revisions and counts are checked again before emission; a reply edit is detected even when its closed root's `updatedAt` is unchanged. The service submits metadata-only batches through the existing admission transaction and owns no checkpoint writes, scheduling, wake or Task policy.

Evidence: L2 (provider/admission seam fixtures and mutation control) plus L3 (bounded live GraphQL schema probes) → L2 required for this adapter leaf. No live corpus admission or coordinator activation is claimed. No residual ACs.

## Deltas from ticket

Intake sharpened this older self-authored ticket against current source: the Markdown syncer already exhausts child pages, but remains a prose mirror with a root delta cutoff. The implementation follows `IssueReconciliationService` / `PullRequestReconciliationService`, `community/` helpers and existing neutral admission instead of coupling durable events to Markdown emission.

GitHub lacks exhaustive Discussion lifecycle/deletion histories. Those provider limitations remain adapter-owned coverage gaps on every run; no caller can erase them by passing a cap. Visible creations/revisions and explicit deletion evidence are supported. Missing or changing entity evidence invalidates that root's candidate observations.

The three new specs are included in the actual Brain CI execution list. New service/query/helper files use existing sibling homes; no new subsystem, configuration, registry or operational threshold. Existing issue/PR producers are unchanged.

Decision Record impact: aligned with accepted ADR 0036. Its authority and the closed issue-reconciliation dependency were verified during intake. The parent remains open.
