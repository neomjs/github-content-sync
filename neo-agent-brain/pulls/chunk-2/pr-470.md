Resolves #469
🌿 *The heap-ceiling guard can no longer pass a memory cap that leaves no room for native memory or the probe.*

A cap must hold V8's heap limit, native memory and the healthcheck's own `node` at once. The probe counts because it runs in the same cgroup. If the cap is lower, a full heap ends in the kernel's silent SIGKILL instead of V8's `Reached heap limit`. This PR sizes three caps by that rule and makes the guard assert it:
- **Caps.** mc-server goes from `1g` to `2g`, kb-server from `1g` to `1536m` and fleet-server from `512m` to `768m`. Measured totals at the new caps are ≈ 1.21 GiB, ≈ 1.06 GiB and ≤ 600 MiB. The tables are in #469.
- **Guard.** `DeclaredHeapCeilings.spec.mjs` asserted only "strictly below", which admitted mc-server's 768 under the 1g it was killed at. It now adds each API server's measured non-heap memory, `NON_HEAP_MB`.
- **CI.** Brain Unit only listed the spec; now it runs it.
- **Compose notes.** The kb-server note states the rule, and the mc-server and fleet-server notes point to it.

Evidence: L1 (the spec, with a control run at `origin/dev`'s caps) + L2 (`docker compose config` renders; V8 heap limits measured under each new cap) → L2 required. Residual: none.
