Resolves #576

Every agent holds its GitHub PAT, per the operator's ruling that Fleet Manager needs at least one per agent:
- `defineAgent` requires the credential.
- The provisioned start resolves the PAT once, before any checkout, and hands that value to the spawn.
- `start()` refuses a null PAT on every path, restarts included.
- `onboardPeer` reads the PAT from the variable `--credential-env` names.

An untokened seat's `gh` would otherwise fall back to the machine's keyring account.

Evidence: L2 (unit arms against real registry writes and recording start seams; each new refusal arm red on dev first) → L2 required (AC-1 to AC-4). No AC residuals.

## Deltas from ticket
- `defineAgent` checks the PAT last, after the shape and state checks, so an invalid definition still reports its own error. The orphan guard goes: every define now carries a PAT, which overwrites an orphan.
- `startAgentProvisioned` runs its structural refusals first, so none of them reads a secret: a tenant seat without a repo, a raw launch override, a missing managed root, a relative runtime root. The tenant branch's second credential read is gone.
- `onboardPeer` exports `defineRequestOf(intent, env)`, so the pass-through is testable without a child process.
- The two specs carrying the AC-1 and AC-3 arms join brain-unit's list. `onboardPeer.spec` stays off, because its two-CLI arm is red on dev (defect-note `c3d213b5`).
