Resolves #500

🌿 A REM cycle that ran and one that never ran read alike from the Memory Core, and now they cannot.

The compose file gives the REM run-state directory its own shared channel, `shared-rem-runs-data`, writable on the orchestrator and read-only on mc-server, the way the `handoff` channel already pairs the two. `configBase.mjs` declares `remRunStateDir` as a plane member that the dream child writes and both processes read. #425's per-service roots left it in the orchestrator's private root, so the Memory Core server read an empty directory of its own and `get_rem_pipeline_state` reported `recentCycles: []` on every compose plane while REM ran. On the local plane today: the 16:10Z cycle's receipt on disk beside 199 older ones, the tool empty.

The #425 guard gains a fourth arm pinning the channel: the orchestrator mounts it writable, mc-server read-only, no other service mounts it.

Evidence: L1 (a static guard over the committed compose file, red-first) → L1 required (AC-1, AC-2). Residual: the plane receipt after the recreate, under Post-Merge Validation.
