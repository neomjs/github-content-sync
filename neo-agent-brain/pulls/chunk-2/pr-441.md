Resolves #440
🌿 *A spec that writes "inside the guard" can no longer be sharing it with a renewal tick.*

The two lease-loss specs in `TenantRepoSyncService.spec.mjs` now enter the lifecycle guard through `enterLifecycleGuard` (asserting a non-null hold) and leave it through `exitLifecycleGuard` in a `finally`, the same helpers the spec already uses at its other guard sites. Before, they created the guard with `fs.ensureDir`, which succeeds on a directory that one of the run's 25 ms renewal ticks already holds, so the tick's exit raced the test's `rmdir`. The unused `LIFECYCLE_GUARD_SUFFIX` import goes with it. Test-only.

Evidence: L2 (unit spec, local repeat runs) → L2 required. No residual.

Micro-review eligible: test-only — two spec sites switch to the existing guard helpers; no production change.
