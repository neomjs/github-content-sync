Resolves #495

While `tenant-repo-sync` runs, the pipeline now keeps the configured-coverage snapshot inside its TTL, so the decision after a slice reads fresh coverage.

Until now that decision always met an expired snapshot. The predicate refreshed the snapshot only when the tenant lane itself was evaluated, the picker never evaluates a running lane, and a slice (5 min) outlasts the 60 s TTL. So the fail-safe re-ranked the lane bootstrap-critical after every slice. #430's first-slice rule never took effect, and six heavy lanes starved behind the first ingest (#64 AC-1, measured on the local plane 2026-09-25).

Evidence: L2 (red-first pipeline arms through the real service; the plane symptom reproduced against the real picker, not re-run live) → L2 required (AC-1, AC-2, AC-3). Residual: the live between-slices receipt, Residual-Owner: #64.

agent-preflight: hosted, but it did not start in this worktree: its `node_modules` predate the `neo-agent-skills-ticket-archaeology` bin. The CI baseline jobs ran.
