This adds the missing coordinator rather than replacing the existing source producers. No acquisition, admission, or policy owner is duplicated.

### 🔬 Depth Floor

**Challenge:** `decoratedAdmission.admitBatch` is **single-use per family pass, and nothing says so.** `attempts` is declared once alongside `capturedBatch` and shared across every call to the decorator within that pass:

```js
let capturedBatch = null, attempts = 0, …
admitBatch: async batch => {
    capturedBatch = batch;
    …
    while (attempts < maxAdmissionAttempts) { attempts++; try { return await admissionService.admitBatch(batch) }
        catch (error) { if (attempts >= maxAdmissionAttempts) throw error } }
}
```

On a **second** `admitBatch` call in one `reconcile()`, `attempts` already equals `maxAdmissionAttempts`, so the `while` body never runs and the function **returns `undefined` — no throw, no retry, no signal.** Downstream, `outcome?.receipt` is undefined and the fallback reads `capturedBatch`, which the second call has already overwritten, so the row would report the *later* batch's receipt lookup for an admission that never happened.

**Not reachable today, and I checked rather than assumed** — both live reconcilers tail-return a single `admissionService.admitBatch(batch)` (`IssueReconciliationService.mjs:118`, `PullRequestReconciliationService.mjs:127`), and all fifteen `admitBatch` sites in the new spec admit at most once per `reconcile`. So this is latent, not live, and I am not blocking on it.

Worth noting because the failure is silent and the constraint is invisible at the reconciler's side of the contract — a future family that admits per-page would hit it. The cheap fix is one line: reset `attempts = 0` at the top of the decorator, which also makes the budget mean "attempts per batch" rather than "per family pass" — arguably what the leaf's name already promises. Your call whether that belongs here or on a follow-up; it is not a Required Action either way.

**Rhetorical-Drift Audit:** N/A — the body's architectural prose is bounded and each claim resolves to a diff line I checked (`uuid()` per pass, `let capturedBatch` scope, null leaves + throw). No overshoot found.
