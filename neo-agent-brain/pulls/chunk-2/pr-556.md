Resolves #555

🌿 The roster's last two full scans become two index seeks, so the glance the cockpit takes every fifteen seconds stops costing the plane a second and a half.

After #553 the plane measured `who_is_online` at 877 / 1,484 ms (min / avg) under the cockpit's tick, against the 300 ms the lane asked for. Two reads remained. The per-agent activity recency (`_projectAgentLiveness`, one `MAX(timestamp)` per identity over that agent's `AGENT_MEMORY` rows) ran on the label index and therefore walked all 35,806 memory rows for each of the 16 identities: 107 ms × 16 on the live graph. And the trail read's `label = 'MESSAGE'` predicate, redundant because only `MailboxService` writes `MESSAGE:` ids, made the planner choose the label index (every message) over the partial sent-time index (the horizon's range): 612 ms against 325 ms on the busy server. `SQLite.mjs` now declares a third idempotent expression index, partial over `AGENT_MEMORY` rows on (`agentIdentity`, `timestamp`), which turns each `MAX` into a seek without touching the query; the trail read keeps exactly the two predicates its partial index is shaped for.

Evidence: L2 (a new arm on the in-memory storage, red at dev; the planner asserted for both read shapes) + L2 (the live graph's read-only timings above) → L4 required (the deployed plane's tool metrics, AC-1). Residual: AC-1, Residual-Owner: #64.
