Resolves #530

🌿 The served Memory Core can finally see what the host's wake receiver measured, so a seat that reads "armed" while every dispatch fails stops being invisible from inside the plane.

The local overlay gives `mc-server` one read-only bind of the active receiver's `--state-dir/records` at `/app/wake-receiver-records` and sets `NEO_WAKE_RECEIVER_RECORDS_DIR` to that path, so `readWakeDelivery()` (PR #510) reads the receiver's records instead of a home-directory convention the container lacks. The source is the env file's `NEO_WAKE_RECEIVER_RECORDS_HOST_DIR` as a required variable: a missing variable fails the render with its own sentence, a missing directory fails `up` (`create_host_path: false`), and the container cannot write through it. Local profile only; the contract is documented beside the mount in the overlay. `WakeReceiverRecordsMount.spec.mjs` pins the bind, its read-only flag, the required-variable source, the no-create rule, and that no other profile acquires the env or the mount.

Evidence: L2 (four placement arms) + L3 (the rendered plane config with and without the variable, and the served healthcheck's delivery leg on the live plane running this exact overlay, below) → L3 required (AC-3). Residual: none; AC-3 is met on this head, receipt on #530.

## Deltas from ticket
- The container target sits outside the plane data root (`/app/wake-receiver-records`): the records are host-owned and read-only, not a plane member, so they do not join the `#425` volume discipline.
- The local runbook's `## Start the container plane` names `NEO_WAKE_RECEIVER_RECORDS_HOST_DIR` as a `.env` prerequisite beside the token, derives it from `NEO_WAKE_RECEIVER_STATE_DIR` (one declaration for the receiver's `--state-dir` and the bind; Compose 5.1.4 interpolates one `.env` value from another, verified by a render), creates the directory with `mkdir -p -m 0700` before `up`, and tells receiver-less deployments (the containerized half; Windows) that their delivery leg reads `no-records` (Ada's RA-1). A spec arm reads the runbook for those four facts.

The env file names the variable once, and its value equals the plist's `--state-dir` + `/records`, an existing directory. If the receiver's state dir moves, the old directory remains, `up` passes, and the delivery leg reads the old records as `observed` — the "coincidences break silently" case of ADR 0019 §10.9. The runbook already passes the plist its `--state-dir` from `NEO_WAKE_RECEIVER_STATE_DIR`. Deriving the env value from that same variable makes the pair one declaration; RA-1's wording can do it at no extra cost.

Its only caller is `HealthService.mjs:565`, inside Memory Core, so a leaf read is available there. The sibling `fleet.wakeReceiverManifestPath` is already a leaf, where empty means "no wake lane declared". This is #510's code, not this PR's, but this PR makes that env load-bearing in production.
