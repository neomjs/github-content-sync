Resolves #506

Every REM cycle ends in `GraphMaintenanceService.runGarbageCollection` (`src/evolution/RemDigestion.mjs:945`).

**What went wrong.** The GC counted an edge as unanchored whenever an endpoint was missing from the **in-memory node cache**. The dream process's cache is lazy and LRU-bounded, so most endpoints were simply not loaded.
- Each severed edge auto-saved a `DELETE` to SQLite.
- The orphan pass then purged the Chroma vectors of every id its storage query returned. Of the nodes themselves, only those the cache held left storage, because `Database.removeNode` reaches storage through the cache's mutate event (@neo-opus-vega's review).
- One cycle on the local plane (receipt: the orchestrator container's `mc-server-2026-09-25.log`):

```
19:51:17Z [GraphMaintenanceService] Garbage Collection complete. Severed 38316 unanchored edges.
19:51:19Z [GraphMaintenanceService] Apoptosis detected 129283 orphaned nodes. Commencing eradication...
```

**The loss is edges.** The GraphLog shows about 2.3k nodes leaving storage in that cycle, 2,264 of them `MESSAGE`; the rest of the 129,283 survived as nodes, and 231,812 were live after the day's cycles. Their vector purges took about 1,400 session-summary vectors per cycle, which the summary sweep replays from stored receipts (#511). The mailbox symptom is the visible part: committed `DELIVERED_TO` receipts vanished, and the lazy WAL repair re-derived them unread.

**The fix.** An endpoint now anchors its edge when either the cache or storage holds it. With no storage attached, the cache is the whole graph and decides alone, as before. The orphan pass is unchanged, because its query already reads storage.

Evidence: L2 (unit arm on a real SQLite graph with a cache-evicted endpoint, red on `dev`) → L3 required for AC-3. Residual: AC-3.
Residual-Owner: #64 (the plane's next recreate carries this head; the dream stays stopped until then).

### 🔬 Depth Floor

**Challenge OR documented search (per guide §7.1):**

- **Challenge (body receipt, not the fix):** the cycles did not eradicate nodes. `GraphService.removeNodes` runs `db.removeNode(id)` in a transaction, and `Database.removeNode` removes from the cache collections; the storage `DELETE` rides `onNodesMutate(mutation.removedItems)`, so a node the cache never held produces no storage delete. The log agrees: today's four cycles report `Severed 58997 / Apoptosis 138607` (16:09Z), `29298 / 129261` (18:00Z), `13370 / 128166` (18:09Z), `38316 / 129283` (19:51Z), and the live plane DB still holds 231,812 nodes at 20:14Z (read-only count from a throwaway container). What the cycles did destroy: the severed **edges** (cached, so their rows were deleted, ~140k deletions across the four runs, the mailbox receipts among them) and the **vectors** of every "orphan" (`graphColl.delete({ids})` goes by id regardless of the cache): chroma's `neo-native-graph` collection holds 501 vectors at 20:24Z. The ~129k "orphans" are the same edge-less rows every cycle. So the body's "the orphan pass then removed every node the severing had stranded" and AC-1's "129,283 nodes eradicated" should read: edges deleted, vectors purged, nodes intact. The fix is unaffected (with anchoring by storage, nothing is stranded), but the restore lane's scope is edges + vectors, and the 13:12Z bundle (`backup-2026-09-25T13-12-54.234Z`, restorable) predates all four cycles.
- **Challenge (non-blocking):** the anchor test costs two primary-key lookups per cached edge; at the plane's ~156k edges that is bounded by the `Nodes` PK index and runs once per cycle. If the edge cache ever holds the whole graph, a single `SELECT id FROM Nodes WHERE id IN (...)` batch is the shape; not needed today.
- **Documented search:** I looked for a second deleter of live rows (none: `decayGlobalTopology` honours `PROTECTED_EDGE_TYPES`; `removeNodes` is storage-derived; `restore.mjs` has `--preserve-read-state` and did not run); for a lazy load hidden behind `nodes.get` (none: it is the cache collection); for the moment the defect went live (the check and the lazy cache both date from the import, so the trigger for today's scale is the dream child's cold cache on each cycle; not resolved by this PR and not needed for it).
