Resolves #307

Unified integration CI builds its exact-checkout Docker images before Playwright starts the readiness timer. The named build step has 15 minutes for cold dependency downloads and native compilation, leaving half of the existing 30-minute job budget for setup, startup and tests. The fixture then selects `--no-build` through `NEO_INTEGRATION_PREBUILT=true`; unset or false retains direct local `--build` behavior. Parity integration is unchanged.

Evidence: L2 (cold-run GitHub Actions image build followed by unified integration, plus isolated fixture controls) → L2 required. No residual.

Change class: capability → feat, for the explicit prebuilt test-stack path. No production runtime or AiConfig change.

### 🔬 Depth Floor

**Challenge — the new build step is now the only place that must agree with the fixture's project name, and it is the one place that hardcodes it.**

The step runs `docker compose -p neo-integration-test -f … build`. The fixture resolves the same project as `process.env.NEO_INTEGRATION_COMPOSE_PROJECT || 'neo-integration-test'`, and so do six other files (`BackupRestoreWipe`, `CloudProviderReadiness`, `KBBackupRestoreWipe`, `TeamPrivateRetrieval`, `multi-tenant`, `kbTenantRecords`). Seven readers honour the override; the new writer does not.

This matters because four services in `docker-compose.test.yml` (`kb-server`, `kb-server-oidc`, `mc-server`, `mc-server-oidc`) declare `build:` with **no explicit `image:`**, so compose derives their image names from the project — which the job's own log confirms, every container coming up as `neo-integration-test-<service>-1`. Set `NEO_INTEGRATION_COMPOSE_PROJECT` in CI and the build lands under `neo-integration-test-*` while `up --no-build` looks for `<override>-*` and, by construction, will not build one.

**Not a blocker, and I want to be exact about why:** nothing sets that variable in CI today, the defaults agree on both sides, and the failure mode is loud and immediate ("no such image" at `up`) rather than a silent wrong-image run. So this is a trap for a future reader, not a defect in what merges. The one-line version is `-p ${{ env.NEO_INTEGRATION_COMPOSE_PROJECT || 'neo-integration-test' }}`, or set the variable once at job level so both sides read one source. Worth folding into the next touch of this workflow.
