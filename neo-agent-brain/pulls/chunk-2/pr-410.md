Resolves #246

The fleet server's activity feed reads its issue and pull trees under one declared leaf, `fleet.contentRoot` (`NEO_FLEET_CONTENT_ROOT`), at both wiring sites in `ai/services/fleet/devFleetServer.mjs`. The default keeps the pre-split checkout-relative `resources/content`, so a self-contained checkout changes nothing; a Brain checkout, which carries no such tree, names the corpus instead. Against the `neo/` tree of a `neomjs/github-content-sync` checkout the unchanged readers return today's rows where the live cockpit still reads `quiet since Aug 26`. Reading every origin (`<root>/<repoSlug>/…`, origin-qualified rows) is the next leaf, not this one.

Evidence: L2 (leaf resolved through the real Provider, production readers run against a corpus checkout, host-local) → L2 required (AC-1 path resolution, AC-2 env re-point + honest degrade, AC-3 recipe). Residual: none of the close target's ACs; the plane's compose value for the new env is deployment work, Residual-Owner: #213.
