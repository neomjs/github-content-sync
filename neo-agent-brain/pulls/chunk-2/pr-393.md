Related to #306 — **CLOSED UNMERGED. This implementation is withdrawn and does not resolve the ticket.**

The head `58cf5f7006ff35c16a4e5b0a7f28dd0d6040267b` removes the physical defrag CLI orchestration and its post-recycle caller. That is the wrong scope. @tobiu reports that the Chroma store grew dramatically without the custom daily defrag. No version-specific evidence establishes that newer Chroma makes collection rewriting, orphan-segment cleanup or SQLite VACUUM unnecessary.

My mistake was treating an endpoint-only client's inability to prove access to the physical store as justification for retiring maintenance. The storage-binding defect is real; unconditional retirement is not its repair.

## Corrected scope

Preserve the custom compaction algorithm, snapshot/recovery safeguards and daily execution requirement. Refuse only when the executing process cannot establish access to the actual store. The supported container deployment needs a functioning route from the daily trigger to that store. Backup topology must report observed storage or null with an explicit reason.

The [corrected #306 intake contract](https://github.com/neomjs/neo-agent-brain/issues/306) replaces my earlier deletion-based ledger. Grace's [changes-requested review](https://github.com/neomjs/neo-agent-brain/pull/393#pullrequestreview-5258184417) remains unresolved. No replacement implementation is yet claimed.

## Current evidence and limits

- The deployed code retains the daily chain: `maxRuntimeMs = DAY_MS` → supervised Chroma recycle → readiness probe → `chromaDefrag` child. The current cloud configuration disables that supervised child, and persisted task states show no invocation in the current instance.
- Chroma's actual store is the named volume mounted at `/data`; the orchestrator does not mount it. Its configured client-process path is not that store.
- The current host-edge profile also explicitly disables the Chroma child. A localhost probe is not evidence that this profile still owns a working maintenance path.
- These are current-runtime observations. They do not reconstruct or negate the earlier deployment in which daily defrag controlled growth.
- The old head's 711 passing CI-selected tests and nine green checks verify its refusal implementation. They do **not** prove preservation of the required capability. The five separately reproduced base-suite failures remain recorded on [#201](https://github.com/neomjs/neo-agent-brain/issues/201#issuecomment-5745751965).

## Successor work

The repair continues under #306 and [D#19014](https://github.com/orgs/neomjs/discussions/19014). Verify successful maintenance on an isolated owned store, refusal on an unrelated/unreachable store, daily dispatch, accepted-write preservation and recovery safeguards before opening a replacement proposal. The truthful backup-topology representation and owning CI coverage are salvageable; their tests must be revalidated with the corrected scope. See the [author withdrawal](https://github.com/neomjs/neo-agent-brain/pull/393#issuecomment-5746181248) and [controlled late-write reproduction](https://github.com/neomjs/neo-agent-brain/issues/306#issuecomment-5746178477).

No live defrag, container restart or production-data mutation was performed for this investigation.

**Challenge — the removed orchestration ran in the plane where the premise does not apply, and it was doing work nothing else does.**

`localhost` is the tell.
