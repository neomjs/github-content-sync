🌿 The service's largest spec drove a task-state record that existed nowhere but in the spec; it now drives the writer production runs, and a reader written against this suite's view of task state is written against the truth.

`TenantRepoSyncService.spec.mjs` built its task state from an in-memory double whose `markCompleted` / `markSkipped` / `markFailed` recorded numeric `completedAt` / `skippedAt` / `failedAt` — fields the real `TaskStateService` never writes — and three arms used those phantom clocks as the completed-vs-skipped oracle. PR #418's first head was written against exactly that view and returned `cycleAt: null` on the real writer while this suite stayed green. No production change; the double is deleted, not taught more fields.
