Resolves #438
🌿 *A session the model cannot summarize no longer fails under the lease on every sweep.*

A failed summary job now carries a not-before: `failSummarizationJob` sets `expires_at` to 30 minutes, doubling with each claim since the job's last success and capped at 24 hours, in one SQL statement with no schema change. The drift sweep drops sessions inside that window **before** `capSessionsForSweep`, so the five slots go to sessions that can run. `queueSummarizationJob` no longer re-opens such a row as `pending` when a transport disconnects. Acknowledging a summary resets `retry_count`, which until now was written and never read. The `drift complete` line, the one that reaches the orchestrator log, now reports `failed=` and `backoff=`. An explicit single-session run still ignores the window.

Evidence: L2 (unit arms against the run-scoped Memory Core substrate; the spec is CI-skipped) → L4 required (AC-4: the deployed plane's next sweeps). Residual: AC-4, Residual-Owner: #64.

## Deltas from ticket
The disconnect path (Fix item 3, and AC-1's second half) was added to #438 in place during implementation. `Server.mjs:685` fires `queueSummarizationJob` on every Streamable-HTTP disconnect, and that rewrote a backed-off `failed` row to `pending` with `expires_at = NULL`, a second way past the backoff that the drift filter alone would not close.
