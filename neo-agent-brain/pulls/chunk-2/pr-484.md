Resolves #482
🌿 *Installing the Brain can no longer write another repository's skills façade into your root.*

The lifecycle runs from `prepare`, never from `postinstall`: `ai/scripts/setup/prepare.mjs` runs the per-clone config bootstrap (`initServerConfigs.mjs`, unguarded — a nested Brain needs its `ai/config.mjs`) and then the skills materializer, skipped inside a dependency build (`INIT_CWD` is a foreign root, compared by realpath) — the engine's own guard shape (`neomjs/neo buildScripts/util/prepare.mjs`, neomjs/neo#19053 + #19205). The engine tarball moves from `17b59aad` (its `package.json` still declared `postinstall: neo-agent-skills-materialize`) to dev head `7f16355a`, past the prepare guard, so a nested engine cannot write into a consumer's root either.

Consumer-install witness, matched arms: a Brain pack at `dev@77bfa56` installed into a scratch consumer writes `.agents/skills -> ../node_modules/neo-agent-skills/.agents/skills` and `.claude/` into the consumer's root; the same install of this head's pack writes nothing. A tarball install runs no `prepare`, so the nested Brain has no `ai/config.mjs` until `npm run prepare` / `--migrate-config` in its own dir, as the harness README documents; that is the pre-existing contract, not this diff's.

Evidence: L3 (the two scratch-consumer installs above, on this machine) → L2 required (AC-1 also has its static arm; AC-2, AC-3 are L2). Residual: none.

## Deltas from ticket
- **`prepare.mjs` beside `initServerConfigs.mjs`** (structural pre-flight: sibling lift of the existing prepare script's directory) rather than folding the guard into `initServerConfigs.mjs`, so the config bootstrap stays a pure per-clone script and the guard has its own seams and spec.
- **Pin shape, not this PR's:** the tarball is a hand-bumped org-internal dependency, and the operator's standing rule (2026-09-21) is latest `dev` resolved at run time; the plane image installs with `npm ci --ignore-scripts` from the lockfile, so any shape is lock-pinned there. The ticket asked for the bump and gets it; the shape decision is recorded on the ticket's Contract Ledger for its own leaf.
- **The preflight's archaeology detector, found by the pin bump:** `ai/scripts/agent-preflight.mjs` imported `neo.mjs/buildScripts/util/check-ticket-archaeology.mjs`, which the engine deleted when the guard moved to `neo-agent-skills` (neomjs/neo#18905), so the preflight broke at import on any pin past 2026-08-28. The skills package exports no module path (`exports` names only the manifest; defect-note sent), so the detector is resolved through the manifest's `bin` declaration and imported by file URL. Its parser makes an unparsable module a named gate failure instead of an exception (`check-ticket-archaeology: N supplied module(s) could not be parsed`), the skills CLI's own verdict; one spec arm added, one fixture made a real module.
- **The CI callers of the removed script, found by the first CI run:** both Brain workflows materialized the checkout's projections with `npm run postinstall` before `npm run prepare`; they now run `npm run prepare` alone, which does both for the checkout (`INIT_CWD` is the workspace). `lint-script-plane` refuses a computed import it cannot follow unless its identity is on `UNRESOLVED_EDGE_LEDGER` with its reason; `ai/scripts/agent-preflight.mjs::dynamic-import::<module-scope>` is recorded there (the detector's path is computed from the skills manifest by construction), and the lint reports 9 unresolved edges, all known.
- **`prepare.spec.mjs` is not on Brain Unit's run list in this PR:** #483 appends to the same hunk of `brain-unit.yml`; it joins the list after #483 lands. Residual-Owner: #201 (the run-list ticket).
