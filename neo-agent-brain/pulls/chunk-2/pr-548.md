Resolves #532

A provisioned seat published its wake envelope once per hand-copied file and never again. Nothing in
provisioning placed the OpenCode plugin that publishes the envelope on each new session, so the "two
producers, one contract" statement at `ai/daemons/wake/daemon.mjs` had a runbook step behind it rather
than an installer. This makes the generated `write-wake-envelope` hook install the plant itself, which
is the same tmp+rename discipline it already uses for the envelope.

**The plant is inlined as base64, read once at module load.** Base64 rather than a template literal
because the plant is ~19 KB of JavaScript and embedding source in a generated string literal invites
escaping that would break the byte-equality contract *silently*. Inlined rather than copied at launch
because a hook that read the plant from the Brain checkout would make a seat's wake lane depend on a
repository the seat may not have.

## What the delivery path actually was

The ticket frames the problem as "provisioning installs nothing". Measuring it found the sharper shape:
the previous PR installed the plant **from inside the boot hook**, behind an `XDG_CONFIG_HOME` guard.
Two independent facts make that branch dead on a real seat:

1. `bootstrapOpenCodeWakeRoute` runs the hook with `hookEnv` = `AMBIENT_ENV_ALLOWLIST` + the server
   credential pair. It does **not** pass `XDG_CONFIG_HOME`.
2. The hook runs **after** the OpenCode server is listening. Even with the variable present, the plant
   it installed could only be loaded by a *later* process — never the session that boot created.

So the installer could not have worked on a Fleet-managed seat, and the fix is structural rather than a
guard change: the plant is a sibling artifact, converged before spawn, at a caller-resolved path.

The other measured finding is unchanged and still unowned: a **live seat carries two plants side by
side** (`neo-wake-envelope.js` 16129 B, Aug 1; `neo-wake-envelope.mjs` 19028 B, Sep 26), neither marked
`GENERATED`, ~3 KB apart, and nothing in the system records which one OpenCode loaded.

## Deltas from ticket

- **Sibling, not payload.** The plant is its own emitted file rather than a base64 blob inside the hook.
  This is the accretion answer as much as the delivery one: the emitted hook goes from **31,695 to
  3,362 bytes** — 27.7 KB less substrate in every seat's home — and editing the plant can no longer make
  every seat's boot hook divergent.
- **Freshness is the existing posture, aimed at the right artifact — and the posture is
  create-or-refuse, not converge.** `convergeTextArtifact` creates an absent file, returns MATCH on
  equal bytes, and throws `FLEET_WORKSPACE_DIVERGENT` on any difference; it never writes over an
  existing artifact. An earlier version of this section claimed the posture was "create absent,
  converge owned, refuse drift" — **that was false, and the middle clause does not exist.** The plant's
  own policy row is right about the artifact and silent about the consequence, so stating it plainly:
  **the first plant edit after this merges is refused on every provisioned seat** whose
  `<instanceHome>/opencode/plugins/neo-wake-envelope.mjs` holds an earlier generation. Correcting my
  own claim is a separate matter from closing that gap, and this section previously conflated them.
- **`XDG_DATA_HOME` is now required in the plant** (RA-5). The `~/.local/share` fallback resolved to the
  one path that is *not* per-seat, and one process can instantiate the plant for several project
  directories at once, so the fallback made the route fail by **collision** (last writer wins, nothing
  records which) rather than by absence. It now refuses at load, which is loud and leaves any prior
  envelope untouched.
