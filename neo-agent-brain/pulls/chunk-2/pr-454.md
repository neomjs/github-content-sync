Resolves #443
🌿 *The temporal summary can no longer count merged work from a tree nobody has updated since August.*

`TemporalSummaryAggregationService#readContentRecords` now reads the core corpus projection's materialized root, the `neo` origin of the published corpus that the Graph consumers already read. It refuses when the projection is disabled and never falls back to a checkout's frozen `resources/content`. The lane is container-plane and cloud-only, so the projection root is always where it runs, and the layout (`<type>/chunk-*/*.md`) matches unchanged. The github-workflow reader runs in each seat's harness on the host, where no projection exists. Its lookup is already origin-qualified, so the fix there is honest text: the not-found and stale-index messages name the root they read instead of claiming "the scheduled Data Sync pipeline regenerates resources/content/_index.json", a tree nothing regenerates now.

Evidence: L2 (unit arms; the projection root is driven through its env in a child process, with no plane). No deployed AC: the lane is opt-in and off on the local plane. Residual: none.
