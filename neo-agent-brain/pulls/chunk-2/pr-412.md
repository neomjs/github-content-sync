Resolves #402

🌿 A conversation the Knowledge Base cites now names the repository it came from, and a ticket number alone can no longer say which conversation it means.

One built-in extractor, `ConversationCorpusSource`, replaces the three per-facet Sources that walked the Engine's frozen `resources/content` tree. It reads the org corpus that `neomjs/github-content-sync` publishes hourly — the root `_index.json` plus the `<origin>/{issues,pulls,discussions,archive}` trees — through the route-bound revision reader, so repository, revision and territory come from the tenant invocation and nothing is recovered from `AiConfig` or cwd. Every identity comes from the index: a file the index does not name yields nothing (the filename fallback is gone), an index row without an origin refuses the run, and two artifacts for one `(origin, facet, id)` refuse. The conversation's origin rides `customMeta` and the chunk name (`neo/issue-86#body` vs `neo-agent-brain/issue-86#body`); ownership stays the server's stamp for the corpus tenant, so the extractor never writes `repoSlug` or `tenantId`. The tenant is declared in `deploy/cloud/kb-config.yaml` with `disabled: true`; the flip and the plane-side receipts are #411, gated on #237. The default registry drops from ten Sources to seven; three specs and three `sourcePaths` keys leave with them.

Evidence: L2 (unit — the real profile runner over a real revision reader bound to a fixture Git mirror; no deployed plane in the sandbox) → L2 required (AC-1 to AC-4 are code and spec criteria). Residual: the deployed-plane activation and freshness receipts (the ticket's former AC-5 to AC-7), Residual-Owner: #411.
