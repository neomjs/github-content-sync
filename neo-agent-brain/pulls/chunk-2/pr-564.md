Resolves #563

🌿 A page hydrates what it holds now, and what the whole mailbox holds is nothing a read can say any more.

`listMessages` served fifty rows by evaluating every message an identity could see: it hydrated every broadcast's vicinity, projected each of thousands of candidates, sorted them all and sliced last, and `repairMessageGraphIntegrity` scanned the message WAL ahead of each call. The page and its count now read ONE set named in SQL — `buildMailboxMatchQuery`: the four routing branches (direct `SENT_TO`, per-recipient `DELIVERED_TO`, legacy `SENT_TO AGENT:*` without a cohort, outbox `SENT_BY`) unioned by id, receipt state read where the row stores it as `resolveReceiptState` reads it, identity spellings through `json_each`. `totalCount` is a `COUNT` over that set, the page is its newest `limit` rows after `offset`, and only those rows are hydrated (`_projectMailboxRow`; the continuation advances by rows served). What that bounds is the per-message reads and the hydration; the match set is still counted and ordered inside SQLite (one statement each, a temporary B-tree for the order), so that work grows with the matches — 18 ms → 122 ms for a warm page of 50 between 1k and 10k visible messages, at the same 77 statements and 0 vicinity loads. `countMessages` reads the same set under its own contract. The post-marker repair pass rides the message drain host at a named cadence: `createMessageGraphIntegrityRepairCadence` (`MESSAGE_GRAPH_REPAIR_CADENCE_MS`, 60 s) as `afterCycle` on `startMessageDrainLoop`, wired in the in-process host and the daemon; its first pass, every changed or failed pass and an hourly digest of every pass since the last digest land on the host's log, and `getLastSummary()` / `getDigest()` read the same state in process.

Because the read no longer awaits the repair, a broadcast's `SENT_TO AGENT:*` routing edge now carries its send-time cohort (`broadcastCohort: 'known'` + `intendedRecipientCount`, or `'legacy-unknown'`), written by the projection and merged onto an intact edge on replay; the legacy branch admits only an edge stamped `legacy-unknown` or known zero-audience, so a modern broadcast whose delivery edges are missing is visible to nobody until the pass restores them — never to an outsider — and an UNSTAMPED edge is unknown provenance, served to nobody. Existing projections are classified before the first page or count a process serves: `ensureBroadcastCohortStamps` (awaited by `listMessages` and `countMessages`, once per process) stamps every unstamped routing edge from the marker index, the cache, then one WAL read, in chunks with the loop yielded between them; an unreadable record leaves its edge unknown. The repair pass keeps a bounded stamping (`cohortStamped`, ≤ 200 per pass) as the steady-state fallback. A fresh mc-server on the current plane pays the gate once (about 10.5k broadcast edges); afterwards it is a settled promise, no statement per read.

Evidence: L2 (unit: the counting-seam arms at limit 50 for both read paths, the three membership arms, the contract arms, the cadence and digest arms) → L2 required for AC-1, AC-2, AC-4, AC-5.
