Resolves #446

Every REM extraction on a non-Gemma chat model behind LM Studio deferred forever as `context-overflow`, for two endings the provider could not tell apart: the Tri-Vector schema's `type: ['string', 'null']` unions, which LM Studio's MLX structured-output engine refuses with an error frame inside a 200 stream, and Qwen3.6's chat template, which streams the whole answer as `reasoning_content`. The schema now spells both nullable fields as `anyOf`; the OpenAI-compatible transport routes every frame through one gate and throws a typed failure for each ending (`PROVIDER_STREAM_ERROR` carrying the provider's message, `REASONING_ONLY_RESPONSE` carrying the byte count — a sibling of the timeout contract); the friction helper files the latter as the deterministic symptom `reasoning-only-response` and keeps a typed failure's message beside the caller's note; the extractor's defer reason names it instead of `under-band-choke`. gpt-oss-20b now extracts through the shipped path.

Evidence: L3 (live LM Studio run of the shipped extraction path on gpt-oss-20b, 3/3 payloads without a harness-side rewrite) → L3 required (AC-2). No residuals.

agent-preflight: crashed (`ERR_MODULE_NOT_FOUND` on `neo.mjs/buildScripts/util/check-ticket-archaeology.mjs`, the stale engine import); the archaeology checker ran directly against `origin/dev` and the five `ai/scripts/lint` scripts pass locally. Change class: `feat` (the typed stream-failure contract is a new, separately testable path; the schema restoration rides with it).
