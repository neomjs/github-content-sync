Resolves #403

🌿 *A reconcile pass over the Engine corpus now costs one plan per archive bucket it cuts, not one per closed issue — "the emitter needs 36 minutes to find nothing" is no longer true of this step.*

`IssueSyncer.reconcileClosedIssueLocations` computed the ordinal-100 bucket plan inside its loop over closed active issues; the inventory one line above was already hoisted with a comment saying "ONCE for the reconcile pass". The plan is now computed lazily once per pass and **refreshed when a move changes the one planner input the pass itself mutates**: whether the target archive bucket exists on disk. `#deriveMilestoneVersion` routes a milestone issue only into an already-cut bucket (`existsSync`), so a bucket cut by an earlier move must be visible to the issues planned after it (@neo-gpt's round-1 differential) — and the refresh keys on the **directory state**, not on the rename succeeding, because `mkdir` can cut the bucket and the rename still fail inside the caught branch (@neo-gpt's repair probe). Refreshes are bounded by the number of buckets cut in a pass, not by the closed backlog. A move's other effect — the issue's path — resolves to the same release either way.

Measured cause (github-content-sync run 35592845470, `NEO_LOG_LEVEL=info`): the `neo` origin's emission took 35 m 39 s, of which 35.4 minutes were silent between `🔄 Reconciling closed issue locations...` and `✓ No closed issues need archiving`; the delta sync after it took about a minute, and the four small origins took 2 s – 1 m 39 s. `PullRequestSyncer.reconcileClosedPullRequestLocations` already plans once before its loop (`PullRequestSyncer.mjs:415`) and is unchanged.

Evidence: L2 (unit spec with three mutation controls) → L2 for the close target's AC-1 and AC-2. AC-3 is a hosted duration observation on a *different* repository's run after that repository bumps its pin; it is recorded on github-content-sync#3 (*Deferred validations owned here*), a cross-repository owner this line's grammar cannot name, so this body carries no open obligation.

Change class: restoration (`fix`) — no capability added; the pass produces the same moves without the repeated planning (the planner itself still sorts, and still runs once per newly cut bucket).
