Resolves #538

🌿 A message's replies, thread, tickets and tags come back from the message itself, so the dream's years of quiet pruning stop being the mailbox's permanent shape.

`ai/scripts/maintenance/rebuildMessageEdges.mjs`, beside `restoreReceipts.mjs`: walks every `MESSAGE` node and links, for each of the four node-borne fields (`inReplyTo`, `partOfThread`, `relatedTickets`, `taggedConcepts`), the edge the projection would have written — weight 1, the message's `sentAt` as `timestamp`, its `userId`, `sharedEntity` — where the live graph lacks it. A tag's concept node is created when absent (the projection's `ensureTaggedConceptNode` shape); any other target must exist, else the field is reported as `missingTarget`. A present edge keeps its weight. Identity is decided inside the insert (`INSERT … WHERE NOT EXISTS`), counts are the rows changed, `--types` narrows the run to named types, the dry run opens the database read-only. The message ids are read up front and each node is fetched by id, so no cursor is open on the connection when a batch flushes. The two session fields are WAL-borne, not on the node, and stay with #509's bundle path (the ticket's corrected Reality names it).

Evidence: L2 (eight arms on a real SQLite file) + L3 (the read-only dry run on the live plane, below) → L4 required (the operator-gated `--apply` on the shared graph, AC-3). Residual: AC-3, Residual-Owner: #64.
