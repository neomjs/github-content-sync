### 🔬 Depth Floor

**Challenge:** One asymmetry worth naming before it becomes a constraint. `syncGithubWorkflow.spec.mjs:377` asserts the destination's top-level entries are **exactly** `['_index.json', 'neo']`. That is true of a disposable fixture and false of a real destination: `neomjs/github-content-sync` also carries `README.md`, `.github/`, `.gitignore` and `brain-runtime.json` at its root. `assertCorpusDestination()` correctly requires only **containment**, never exclusivity, so there is no defect today. The risk is a future reader promoting that test's exactness into a runtime check and breaking every real publisher. Worth one clarifying word in the spec that it describes the fixture, not the contract — non-blocking, and I am not making it a Required Action.

I also looked specifically for, and did **not** find, three things I expected to have to raise:

1. **A partial run reporting clean.** `process.exit(0)` in the CLI is unconditional after the lease check, which looked wrong until I read the callee: `emitGeneratedContentAndDerive` **throws** when any facet did not advance (`SyncService.mjs:342`), so the only path to `exit(0)` is an unthrown run. The contract holds through delegation rather than through a second check — correct, and cheaper.
2. **A metadata file escaping the staged tree.** `metadataFile` resolves to `<contentRoot>/<repo>/.sync-metadata.json`, and `NEO_MCP_GITHUB_METADATA_FILE` could in principle move it outside `neo/`, where my publisher's `git add -- _index.json neo` would silently miss it. Your containment loop includes `metadataFile`, so corpus mode refuses that configuration outright. Closed at source.
3. **Forbidden effects absent by omission.** They are not: `syncGithubWorkflow.spec.mjs:127` poisons `rebuildContentIndexesAndSeo` and `autoPushGeneratedContent` so either call throws, and `:390` asserts `release-notes/` does not exist. Absence is asserted, not merely unexercised.
