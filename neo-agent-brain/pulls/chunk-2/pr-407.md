Resolves #406

🌿 *A deploy that follows its own guide can no longer ask the Brain remote for an Engine commit.*

Six surfaces still named `neomjs/neo.git` as the Agent OS source after the 2026-08-27 split: the Dockerfile's `ARG NEO_REPO_URL` default and its header comment, the reference pipeline's `NEO_REPO_URL` default, and the documented pin command in `PipelineWiring.md` (twice), `Day0Tutorial.md` and the local Agent OS README. Compose already fetched from the Brain (#256 / PR #258), so a pin resolved against the Engine died at `git fetch` with `upload-pack: not our ref`, and a bare Dockerfile build fetched a tree with no `ai/` to run. All six now name `https://github.com/neomjs/neo-agent-brain.git`. One spec, `test/playwright/unit/deploy/DeploySourceRepository.spec.mjs`, reads exactly those surfaces plus the four compose defaults and refuses the Engine — positive half first (each surface must name the Brain), so a gutted file cannot pass — and it joins the `brain-unit.yml` executed list, because a collected-but-unexecuted spec is not a guard (#201).

This reverses a scoping I made myself in #256 ("generic default, intentionally untouched, kept for standalone reuse"): the builder stage hard-codes `ai/` paths, so there is no tree but the Brain's it can build, and a default that can never succeed is not generality.
