Resolves #464
🌿 *A mailbox drain can no longer copy the whole cached graph for each message it checks.*

@neo-opus-ada's profile (AC-1) put the drain's cost in phase 1's per-candidate checks. Three copies made each candidate cost the size of the cached graph, and this PR removes all three:
- **Edge checks.** `hasMailboxGraphEdge` and `getMailboxGraphEdgeTargets` scanned `edges.items`, a copy of every cached edge, once per edge checked. The plane's graph holds about 157k edges. Both helpers now read `getMessageSourceEdges`, the source-indexed read that already reconciles stale index entries.
- **Endpoint cache warm-up.** `getMailboxProjectionEndpointRestorePlan` reloaded each endpoint's vicinity only to warm `nodes.get`. For `AGENT:*` and identity hubs, that copied the hub's whole edge list for every candidate. It now syncs the cache and loads only on a miss.
- **Graph `Store`.** It inherited the data store's `load` event, whose payload copies every item on each mutation. No graph store has a `load` listener, so the graph store now fires none. Storage still follows `mutate`.

The repair also turns the loop between candidates. Intact candidates do no I/O, so without a turn a drain's backlog held the loop until it ended.

Evidence: L1 (a unit witness with four mutation controls, plus the affected suites) + L3 (two before/after drains on copies of the plane's graph, in one-off containers of the plane image at the plane's heap flag) → L4 required for AC-4 (a deployed drain under the 1 GiB cap). Residual: AC-4, Residual-Owner: #466.

## Deltas from ticket
- **A third copy site.** The ticket named two per-candidate copies. The unit witness found a third, the graph Store's inherited `load` payload: every edge-store mutation copied the collection.
- **One candidate per loop turn.** That is how "bounded chunks" landed. It needs no batch-size constant, and each candidate is now cheap.
- **Why the helpers use `getMessageSourceEdges`.** A first version read `edges.getByIndex('source', …)` directly. The cohort-repair test caught that the index keeps a removed edge's raw object once the store has swapped in a Record for it. `getMessageSourceEdges` reconciles exactly that.
