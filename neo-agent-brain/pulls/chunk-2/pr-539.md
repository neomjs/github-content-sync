Resolves #537

🌿 The dream can no longer lose sight of its own clock and run the decay again and again, and a message's reply, thread, ticket, tag and session links can no longer be worn away as scent — the mailbox has stopped being something the dream forgets.

The 24-hour lock reads `lastDecayedAt` from storage instead of the node cache, so a clock another writer removed or advanced is seen (the pre-#515 orphan pass deleted the cached clock every cycle: five runs in 37 minutes on 09-24, two in 9 minutes on 09-25), and the blank re-create on a cache miss is gone. The decay and prune statements exclude every edge a `MESSAGE` node sources, beside `PROTECTED_EDGE_TYPES`, and `getInboundStructuralSupport` applies the same rule to its decaying buckets (`isMessageRecordEdge`, one predicate for both), so a permanent record never reads as current motion.

Evidence: L2 (two red-first arms and two controls on a real SQLite graph; `GraphService.spec.mjs` 59/59) → L3 required (AC-4: one `Running` then `Skipping` on the recreated plane, message-edge weights unchanged across it). Residual: AC-4, Residual-Owner: #64.

## Deltas from ticket
The read-side projection joins the change (Euclid's RA-1): `getInboundStructuralSupport` counted a message-sourced inbound edge as decaying support, and `GoldenPathSynthesizer` reads that bucket for Discussion liveness; it now shares the source predicate. The predicate is `substr(source, 1, 8) <> 'MESSAGE:'` in both statements; an edge that only targets a message (`RESOLVES`, `DISCUSSED_IN` from other layers) keeps its own layer's rule.
