Resolves #382

This fleet no longer starts a seat that was released to its own harness, even when it ran that seat before. `launchRefusalOf` reads the registry's own write: `external` with a `launchOwnerSince` is a release, and the refusal holds until an adoption. It has three readers:
- `FleetManager#startAgent` refuses before anything runs.
- `#restartAgent` refuses before the stop, so a restart never ends half done.
- `fleetRoster` stamps the same words on the cockpit row beside `launchable`.

The process record stays observation: `fleetRuntimeStatus` is untouched.

A seat with no ownership act answers `null`, so its process record stays its only start gate, exactly as today. That covers `onboardPeer`'s Phase A rows, every legacy row and the host seats. This is the ticket's option 1: no existing row changes behaviour.

Evidence: L2 (unit arms over the registry helper, the manager's verbs with recorded stubs, the roster assembler and the Body map) → L2 required (the ACs are the verb's refusal and the row's stamped fact; the cockpit's use of the fact is the Institution's own leaf).
