Resolves #413

The fleet server's activity feed now reads every origin of a `neomjs/github-content-sync` checkout. The wiring takes the `fleet.contentRoot` leaf's value itself and resolves the origins from the tree and the corpus's own index: a root with `issues/` directly under it stays the single-origin tree every deployment reads today; a corpus root reads `<root>/<repoSlug>/{issues,pulls}` for every slug the index declares. The shared readers own the identity: with an `origin` an issue record answers an origin-qualified `issueId` and a pull record a `prId`, each with `repoSlug`, while callers without an origin keep the bare ids the Graph keys; foreign-origin event ids are qualified the same way (`<repoSlug>#<number>`) and the Graph origin's ids stay byte-identical. The pull reader's pre-parse bound ranks by each file's `updatedAt` (peeked from the head, never parsed), so an older PR updated today outranks a newer one updated in January. One unreadable origin degrades the slot by name while the other origins' rows are kept, and stall inference stays with the Graph's origin because its joins are by bare issue id and the Graph carries one origin by contract.
