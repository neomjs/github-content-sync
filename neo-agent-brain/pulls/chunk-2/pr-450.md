Resolves #449
🌿 *A new plane's first projection cycle no longer depends on sixteen thousand separate network fetches all succeeding.*

`materializeCoreCorpusRevision` now works out the paths it will read before any blob read (tree and diff reads fetch nothing). It asks `prefetchRevisionBlobs` for the root index and those paths in one call, then reads. This is the ingest path's two-tier contract (#247) applied to the projection. An incremental cycle asks only for its changed paths. The outcome rides the materialization result as `prefetch: {status, requested, missing, chunks, reason}`, and `unavailable` leaves the per-file reads as the fallback.

The failed cycle also left a `core-corpus-materialized.next-*` directory behind. `mapWithConcurrency` rejected on the first failure while its siblings kept writing, so a sibling's `outputFile` recreated the directory the `finally` had just removed. The pool now stops taking values after a failure and rejects once its in-flight calls settle.

Evidence: L2 (unit arms through `runCoreCorpusProjectionCycle` with a fake mirror; no plane), and every #449 AC is unit-level. The deployed confirmation is the next cold mirror, recorded on #442. Residual: none on #449's ACs; the Post-Merge item's Residual-Owner is #442.
