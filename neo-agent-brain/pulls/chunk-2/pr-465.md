Resolves #463
🌿 *An MCP server can no longer exit without saying what still held its loop.*

Every MCP server with a service key (kb-server, mc-server) now starts `EventLoopReporterService` in `BaseServer.initAsync()`, beside the heap observation. Its three outputs:
- **Stall WARN.** A check window whose longest loop delay reaches `eventLoop.stallWarnMs` logs one WARN with the measured delay. The defaults are a 2 s bound checked every 10 s.
- **Exit line.** At exit, one line lands synchronously in the file log and on stderr through a new `logger.writeSync()`. The file stream's queued write never lands from an `exit` handler. The line gives the code, `drained` (whether `beforeExit` fired), uptime, heap used and limit, the active handles, and the open window's delay.
- **Previous heap record.** The heap reporter keeps the previous process's record as `<service>.previous.json`.

The HTTP listener now logs a post-start `'error'`, which a settled start promise used to swallow, and logs its own close. Nothing is deleted, because nothing observed the loop or the exit before.

Evidence: L1 (unit specs in CI, child-process exit witnesses, six mutation controls; no plane) → L4 required for AC-4 (the next exit on a deployed plane). Residual: AC-4, Residual-Owner: #464.

**Closing unmerged: the premise this PR serves is falsified.** @neo-opus-ada's kernel evidence on #463 (issuecomment-5818925179) shows the mc-server deaths are cgroup OOM kills at the 1 GiB cap, a SIGKILL. They are not exit 0. I read "ExitCode 0, OOMKilled false" from `docker inspect` after each restart, and at that point it describes the new run.

Nothing here can witness a SIGKILL:
- The exit line needs an `exit` handler to run.
- The stall WARN needs the stall to end.
- The previous heap record is at least 56 s old by the time a blocked loop dies.

These are generic diagnostics for a failure mode nobody observed, so I'm not merging them. The branch stays for salvage.

The cause is #464, the `mark_read({all: true})` drain's unbounded repair. The reason the kills looked like clean exits for seven hours is tracked separately.
