Resolves #435

On a plane without a GitHub credential or a plane base, the `ci-failure-ingest` and `defect-ledger-digest` lanes now end their tick as deferred instead of failing. Each prints the supervisor's existing deferred envelope (`{deferred: true, reason}`) and exits 0, and `ProcessSupervisorService#classifySuccessfulChildOutcome` records a `skipped` outcome whose reason names the missing input: `github-token-unset` or `plane-base-unset`. The two resolution points that already threw (`resolveGithubToken()`, the plane-base check in each script) now throw typed codes, and only those codes are mapped. A present-but-failing input, such as a plane that cannot be reached, still exits 1. No scheduler, registry or config change, and no new AiConfig read (ADR-0019 read before the change; its SSOT lint and both AiConfig guards pass).

Evidence: L3 (both lane scripts run as real child processes, their stdout read by the supervisor's own parser and classifier) → L3 required (the lane ACs). No residuals.
