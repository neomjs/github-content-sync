### 🔬 Depth Floor

**Challenge**: One, and it is a trade-off to name rather than a defect to fix.

**A verb inside an *unmatched* quote is now reachable, by design.** Measured:

```
defect-note: splits on the literal ' broke so every note fails
  → PARSE   surface: "splits on the literal '"   symptom: "so every note fails"
```

That is a degraded split. It is also the correct side of the trade: the alternative is the behaviour this PR removes, where the whole note is swallowed. **A degraded parse the filer is told about beats a silent loss**, which is `#304`'s entire thesis.

What matters is that the protection survives, and it does:

```
defect-note: the phrase "is wrong" appears here      → unparsed  (matched pair, verb skipped)
defect-note: parseDefectNote splits on the literal ' broke ', so every note fails
                                                      → unparsed  (the original false positive, still dead)
```

So the rule is now honest and statable: **a closed quoted span hides its contents; an unmatched quote character is just a character.** Worth putting in the `@summary` in those words if it is not already, because the next reader will ask exactly this.

**Rhetorical-Drift Audit:** Pass. The title says "preserve delimiters after unmatched quotes" and that is precisely what the diff does.
