Resolves #425

This PR makes every path a service writes under `/app/.neo-ai-data` land in a named volume. Two kinds don't today:

- kb-server and mc-server lost their heap-observation writer mounts on 2026-08-25, and the channel has read `unavailable stale` since then.
- The orchestrator's concepts, lazy-edge queue, REM runs and wake cursor live in the container layer, and so does mc-server's wake cursor. Every recreate drops them; #253 had to copy them by hand.

The changes:

- kb-server and mc-server mount `shared-heap-observation-data` again, under the WRITE-half comments that were left orphaned.
- kb-server, mc-server, orchestrator and fleet-server each get a private `<service>-plane-root` volume at the data root. The channel volumes stay nested on top of it.
- `PlaneDataRootMount.spec.mjs` guards both. It reads the heap target from the production config descriptor instead of spelling it.

Evidence: L1 (compose + unit guard, red-first) + L2 (mechanism proof in a disposable Compose project) → L4 post-merge (deploy with seeding).

The deploy is an announced transaction, using the copy step from the #64 runbook:

1. Stop each moving service and copy its layer state out.
2. `up --no-start --force-recreate`, copy the state into the new root, then start.
3. Check:
   - the snapshot shows kb/mc heap observations `available`;
   - after an hour, `docker diff` lists no plane path outside a mount;
