Resolves #481
🌿 *A seat's Neural Link no longer depends on which test run last left a bridge behind.*

The host edge elects `neuralLinkBridge`, the orchestrator's supervised bridge lane (`ai/daemons/orchestrator/taskDefinitions.mjs:346`): `src/composition/orchestrator/hostEdgeProfile.mjs` turns `NEO_ORCHESTRATOR_NL_BRIDGE_ENABLED` on beside LM Studio, the two closure specs assert the election, and the local-agent-os README plus ADR 0019 §10.7's canonical-local row name the bridge as a host-edge lane on loopback 8081. The lane's port stays the Neural Link provider's (`NEO_NL_PORT`, default 8081); its authority class is already `host-edge` (`getTaskAuthorityClass('neuralLinkBridge')` → `host-edge`, `isTaskOwnedByProfile` → `true`), and `duplicateListenerPolicy: 'defer'` means it never fights a foreign listener.

Why: every seat's Neural Link MCP server on the team machine runs from an engine checkout (`cwdFinding: BRIDGE_CWD_MISSING_SCRIPT`), so no seat can spawn a bridge; today's bridges are test-run leftovers and the team's is an orphan (neomjs/neo#18965, comments 18597857 and 18598174). Both closure specs join Brain Unit's run list, which collects the whole suite and executes a named list (#201).

Evidence: L2 (the closure specs and the authority-class read) → L2 required (AC-1, AC-2). Residual: AC-3, AC-4 (post-merge by the ticket's own flag: the team machine's orphan stop and host-edge restart at the merged SHA), Residual-Owner: #84 (the machine's canonical-topology ticket, where the host-edge receipts live).
