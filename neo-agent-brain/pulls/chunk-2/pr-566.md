Resolves #565

🌿 A seat that already runs elsewhere can now be written down in one act, and the window in which the fleet could have started it twice is gone.

`FleetRegistryService#defineAgent` records `launchOwnerSince` in the same write whenever the caller passes `launchOwner` explicitly, either value; an omitted owner keeps the timestamp-less default that #382 chose on purpose (the predicate's "never had an ownership act" case). `launchRefusalOf`, `FleetManager.assertStartPermitted` and `spawnPermitted` are untouched: a row born `external` now answers their refusal from birth, an adoption still lifts it, and `ai/scripts/fleet/onboardPeer.mjs` (which passes no owner) behaves as before. The doctrine paragraph and the option's JSDoc say the shipped rule. The three fleet specs that cover this contract (registry, manager, bridge) join `brain-unit`'s explicit list, which never ran them.

Evidence: L2 (unit: the registry arm, the manager's refusal arms, the bridge) → L2 required for AC-1 to AC-4. Residual: none.

Micro-review eligible: contained — one spread in a definition literal plus its doc, in the idiom `setLaunchOwner` already uses; no new concept, no consumed shape changes.
