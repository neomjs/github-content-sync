Resolves #1173

A seat's Fleet id can now be renamed on the plane host, with the FM quit and the seat stopped:

```
node ai/scripts/fleet/renameSeat.mjs --id neo-gpt --to neo-gpt-euclid [--apply]
```

`renameSeat` copies the seat's folder under the new id, proves and publishes the copy with the seat-root move's own parts (now exported from `moveSeatHomes.mjs`), and only then re-keys the registry row (`renameAgent`: `previousId`, `previousSeatHome`). The PAT, the operator, the plane credentials and the window record follow the row. `carrySeatSessions` points each harness's own session index at the new folder, so the seat resumes the very same sessions (the operator's requirement, 13:1xZ). The first Start re-derives the Fleet-owned files rendered under the previous id. Until the row is re-keyed, the old seat stays startable; a re-run completes an interrupted rename.

Evidence: L2 (unit arms on the operation, the session carry, the registry, operator and plane stores, and the Start's re-derivation) → L2 required (AC1–AC3); AC2's installed half and AC4 are the run with the operator. Residual: the run, Residual-Owner: neomjs/neo-agent-institution#732.
