*   **Expected Solution Shape:**
    - The child reconnects on an unexpected close, with backoff and without spawning.
    - A fresh token comes from the process that holds the admission (the launcher), never by giving the child the grant.

    - It must not lengthen token TTLs, read the grant in the child, or let a Fleet-managed seat spawn a Bridge.
*   **Patch Verdict:** It matches.
    - **Reconnect:** `scheduleReconnect` backs off from 0.5 s to a 5 s cap on an unref'd timer, fires only after an established socket closes, and stops on `manage_connection stop`.
    - **Refresh:** `refreshBridgeCredentials` asks the parent over IPC with an id-matched reply and a 15 s timeout.
    - **Parent side:** the launcher coalesces refreshes and keeps the grant in its own memory; `composeTargetEnv` still strips the grant and issuer.
    - **1008:** refresh, then retry once. With a Fleet token present, no spawn ever happens.
    - **Re-redemption:** `redeem` has no single-use or replay refusal, so it works while the generation is active. A revoked generation refuses, which is exactly the authority boundary we want.
*   **Premise Coherence:** It coheres with friction to gold. The defect-note's two causes, no reconnect and an expired token, each have a mechanism now, under the owner that already holds the credential.

### 🔬 Depth Floor

**Challenge OR documented search (per guide §7.1):**

- **Challenge** (each non-blocking):
  1. **A 1008 that no refresh can cure retries forever.** A child without the parent IPC (Codex rows, #571) or with a revoked generation keeps presenting a dead token. Every 5 s it is rejected, and each rejection is a warn line in the Bridge log. Stopping (or backing off to minutes) after a 1008 that the refresh left unchanged would keep the log quiet until a restart.
  2. **Every later attempt re-redeems.** `ensureBridgeAndConnect` refreshes before each subsequent attempt, even while the token is still valid, for example after a Bridge restart inside the hour. Each refresh is a full admission with credential proofs. The coalescing bounds it to one per launcher, and refreshing only after a 1008, or once `expiresAt` has passed, would spare the issuer.
  3. **The token is written twice.** `refreshBridgeCredentials` sets both `bridgeToken` and `process.env.NEO_FLEET_BRIDGE_TOKEN`. `createBridgeUrl` already prefers the field, so the env write only lets a credential flow through ambient state.
  4. **Every launcher row gets IPC.** `runTarget` opens fd 3 and sets `NEO_FLEET_MCP_PARENT_IPC` for all rows, though only Neural Link uses it. Nothing else in `ai/` or `src/` touches `process.send` or `process.channel`, so it is inert today. Scoping it to rows with a renewable credential would keep it that way.
