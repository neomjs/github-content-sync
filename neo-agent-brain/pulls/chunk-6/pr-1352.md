Resolves #1349

🌿 *A transport session that saved nothing can no longer start a summary pass.*

`addMemory` now records its session in-process after the durable WAL append. `Server.onSessionClosed` queues the `SummarizationJobs.pending` marker only for a recorded session, and consumes the record. Sessions that wrote nothing make up 87% of the plane's markers (28,488 `failed` against 4,128 `completed`), and they no longer start a pass whose drift scan reads ~170 MB from Chroma. A restart loses the record; the periodic drift sweep (10 min) stays the backstop.

Evidence: L1 (unit specs plus a mutation run) → L3 required for the post-merge pass-rate reading (a plane running this head). Residual: AC3 (the post-merge pass-rate reading), Residual-Owner: #1350.
