Resolves #1246

Realigns `_index.json` when closed issues are archived or synced in `IssueSyncer` and `SyncService`, and repairs the live `neomjs/github-content-sync` corpus index and `neo-knowledge-base` Chroma collection (`1,910 / 1,910` `neo/archive/issues/v13.2.0/` files).

Evidence: L4 (`neo-shared` / `github-content-sync` live Chroma collection `neo-knowledge-base` verified at corpus revision `2620ccf9eba6cfeee868be5ca82261e198647569`, all 1,910 `neo/archive/issues/v13.2.0/` files present, and exact-title `query_documents(type: 'ticket')` queries verified for `#5577` and `#16123`).

## Cause of the `neo/archive/issues/v13.2.0/` Drop

1. **`ConversationCorpusSource#extractFromRepository` (`ai/services/knowledge-base/source/ConversationCorpusSource.mjs:134-139`) is strictly `_index.json`-authoritative:**
   - Every `.md` file in `neomjs/github-content-sync` is looked up by `sourcePath` in the root `_index.json`; unindexed files are skipped as `reason: 'unindexed'`.
   - Because `ConversationCorpusSource` declares `deltaSafe: false`, every `tenant-repo-sync` run on `github-content-sync` deletes KB rows whose old paths (`neo/issues/chunk-X/issue-NNNN.md`) left `manifestSnapshot.pathsAfterPush` and writes only `yieldedSourcePaths`.
2. **`IssueSyncer#reconcileClosedIssueLocations` moved closed issues into `archive/issues/<version>/` without updating `_index.json`:**
   - When `v13.2.0` was cut (`19b7b8dd` / `10da7652` in `github-content-sync`), `IssueSyncer#reconcileClosedIssueLocations` renamed closed issues from `neo/issues/chunk-X/issue-NNNN.md` to `neo/archive/issues/v13.2.0/chunk-Y/issue-NNNN.md` and updated `.sync-metadata.json`, **but never called `updateContentIndex`**.
   - Out of `1,910` files in `neo/archive/issues/v13.2.0/`, only the `9` touched by later `pullFromGitHub` runs were updated in `_index.json`; the remaining `1,901` (`v13.2.0`) plus `5` (`v13.3.0`) kept their deleted pre-archive paths (`version: null`) in `_index.json` and were skipped as `unindexed`.
   - By contrast, `PullRequestSyncer#reconcileClosedPullRequestLocations` updates `_index.json` on archive moves and runs `PullRequestSyncer#reconcilePullRequestIndex` on every sync, which is why `neo/archive/pulls/v13.2.0/` arrived intact.

## Deltas

- **`ai/services/github-workflow/sync/IssueSyncer.mjs`:**
  - Updated `reconcileClosedIssueLocations(metadata)` to batch `createContentIndexEntryFromPath` upserts for every archived issue and write them via `updateContentIndex` (throwing if the index write fails after files move, matching `PullRequestSyncer`).
  - Resolved shifted active-tier source copies via `inventory.get(id).filter(copy => !copy.version && !copy.bucket)` when `reconcileActiveChunks` moved an issue between active `chunk-N` directories without updating `.sync-metadata.json`, and guarded against destination overwrite collisions (`stats.collisions`).
  - Unified `pullFromGitHub`, `refetchIssuesByNumber`, and `migrateArchiveBuckets` to build `_index.json` upserts from the written `targetPath` via `createContentIndexEntryFromPath`.
  - Added `reconcileIssueIndex(inventory = null)` to realign single-copy `issues` rows in `_index.json` from on-disk inventory, preserve valid existing rows for out-of-scope multi-copy issues (`skippedAmbiguous`), and remove dangling rows.
- **`ai/services/github-workflow/SyncService.mjs`:**
  - Wired `IssueSyncer.reconcileIssueIndex()` into `emitGeneratedContent`'s `issues` facet after `pullFromGitHub` and included `issueIndexStats` in the returned stats.

## Test Evidence

- Diagonal / mutation verification: running `IssueSyncer.spec.mjs`'s `'an archive move of an issue facet updates _index.json and drops no element from the KB (#1246)'` without the `reconcileClosedIssueLocations` `updateContentIndex` upsert fails with `yieldedSourcePaths: []` and `skippedFiles: [{sourcePath: 'neo/archive/issues/v13.2.0/chunk-1/issue-5577.md', reason: 'unindexed'}]`.

### 🔬 Depth Floor

**Challenge (non-blocking):** `reconcileIssueIndex` leaves an issue with two or more on-disk copies unindexed whenever no copy matches its previous row. The row is removed, or for an issue that never had one, never written. `ConversationCorpusSource` then skips every copy as `unindexed`, which is the #1246 symptom for that id. The new collision guard in `reconcileClosedIssueLocations` creates exactly this two-copy state.

The ids do land in `skippedAmbiguous`, but only in the returned stats. The 🧭 log line reports written, removed and unchanged, and omits them, so a future gap of this class stays as silent as #1246 was until a backup diff found it. Cheap mitigation: log `skippedAmbiguous` and `collisions` at warn, with the ids. In the live repair the one ambiguous id was #174; its row matched a copy, so `removed: 0`.
