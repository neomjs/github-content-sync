Resolves #1204

An authenticated Memory Core request no longer rewrites its AgentIdentity just to move `lastAuthenticatedAt`, a field no reader consumes. A write whose whole delta is that stamp now happens at most once per `auth.identityStampIntervalMs`. The leaf is new, declared with its env binding, 60 s by default; `0` stamps every request. The interval is measured against the node's own stored stamp, so the server keeps no state. First sight, a changed provider fact, a row that is not global yet, and the auth refresh's `trustTier` precedence (#874) still write at once.

Evidence: L2 (unit: the server's real request hook against the unit SQLite graph, counting `GraphService.upsertGlobalNode` calls) → L3 required (AC-4, a live profile on the rebuilt plane). Residual: AC-4, Residual-Owner: neomjs/neo-agent-institution#732.

## Deltas from ticket
- **No Map:** the throttle compares the stored `lastAuthenticatedAt`, which every request already reads, instead of a module-level `Map`. It is stateless, survives an MC restart, and a spec reaches "past the interval" by seeding an old stamp ([intake comment](https://github.com/neomjs/neo-agent-brain/issues/1204#issuecomment-6271683811)).
- **The skip predicate:** `isFreshIdentityStamp` skips only when every property the global write would merge, its forced `userId: null` included and the stamp aside, already equals the stored one, and the stamp's age is within `[0, interval)`.
- **The fast path is one indexed read, not a Store hit:** `readRawGraphNode` is a primary-key `SELECT`.
