Resolves #1325

Authored by Julia (Gemini 4 Argon, Antigravity).

Lowers `pullRequest.maxCommentsPerPullRequest` from `100` to `25` in `github-workflow` config while decoupling corpus sync onto `pullRequest.syncMaxComments: leaf(100)`, extends the existing pre-mutation ID lookups (`GET_ISSUE_ID`, `GET_PULL_REQUEST_ID`, `GET_DISCUSSION_ID`) to select `comments { totalCount }` with zero extra round-trips, refuses `action: 'create'` in `IssueService.createComment` and `DiscussionService.createComment` with `code: 'COMMENT_CAP_EXCEEDED'` when `comments.totalCount >= 25` (while keeping `action: 'update'` and `#createReassignAuditComment` working on threads of any length), switches `GET_CONVERSATION`, `GET_ISSUE_CONVERSATION`, and `GET_DISCUSSION_CONVERSATION` to `comments(last: $maxComments)` (and `replies(last: $maxReplies)`), and updates `openapi.yaml` and unit tests.

Evidence: L2 (Playwright unit suite covers config leaves, GraphQL query shapes, service refusal/boundary paths, corpus sync decoupling, and OpenAPI/handbook tiers) → L2 required (all 6 ACs are service/query/schema/unit-test contracts verifiable in CI).

## Deltas from ticket
- **Corpus sync decoupled (`RA-1`):** `PullRequestSyncer.mjs` previously read `pullRequestConfig.maxCommentsPerPullRequest || 50` into `FETCH_PULL_REQUESTS_FOR_SYNC` and `FETCH_SINGLE_PULL_FOR_SYNC` (`comments(first: $maxComments)`). Added `pullRequest.syncMaxComments: leaf(100)` in `configBase.mjs` (and `config-leaf-parity.json`) and wired `PullRequestSyncer.mjs` to `pullRequestConfig.syncMaxComments` without a hidden `|| 50` fallback (per ADR-0019 §5).
- **Missing-target GraphQL error (`IssueService.mjs`):** When neither `issue` nor `pullRequest` resolves on `GET_ISSUE_ID`, `GraphqlService.query` already throws GitHub's `GraphQL error: Could not resolve to an Issue or PullRequest with the number of N` before the service return is reached; removed the unreachable post-query `if (!target)` branch.
