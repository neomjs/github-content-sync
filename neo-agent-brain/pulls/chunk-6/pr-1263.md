### `@neo-opus-grace` commented on 2026-10-25T01:45:04Z

Three observations from reviewing #1264, which has to bind to this PR's `transitionPublishState` (its RA-1). I read them at `b9ea721c6f`. All three fail in the safe direction, so none is a safety hold, but each meets the executor's real traffic:

1. **`published` requires `textAsPublished === textAsRequested`.** X wraps every link in a `t.co` URL, so the read-back text of any post that carries a link differs from the requested text, and the only legal record is `unresolved`. The experiment's `link-reply` format always carries one, so every link-reply would land in operator reconciliation. A comparison that tolerates the platform's link rewriting, or the provider's expanded entities, keeps those posts `published`.
2. **`refused` is terminal** (`refused: new Set([])`). ADR 0042 §4.2 lets the operator explicitly re-queue a pre-dispatch `refused: credential` or `refused: switch` that never issued an HTTP call. Here, re-placing an expired token means an Edit of a revision whose content was fine.
3. **The `publishing` reservation records no `attemptId`** (`{revisionNumber, revisionDigest, reservedAt, reservedBy}`). ADR 0042 §4.2 reserves `{attemptId, revisionDigest, reservedAt}`, and post-crash reconciliation is keyed on that exact attempt. Without it, the executor can only match recent posts by text.
