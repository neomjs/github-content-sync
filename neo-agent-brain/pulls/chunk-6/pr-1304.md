Resolves #1303

Related: neomjs/neo#20114

Sends MCP `initialize` `instructions` from `BaseServer.createMcpServer()` via `getServerInstructions()` (`null` disables) directing clients to call `get_mcp_tool_handbook({toolId})` for full tool usage guides and parameter documentation. All six `BaseServer` subclasses compact `tools/list` today, so providing the default on `BaseServer` covers all six servers deliberately (~220 characters per server in each client's `initialize` response) while keeping `tools/list` bytes unchanged. Also exempts `get_mcp_tool_handbook` at the `BaseServer` dispatch check so static OpenAPI handbook lookups succeed even while Neural Link's own Bridge link is down during startup or a Bridge outage (`HealthService.mjs:123-127`).

Evidence: L2 (in-memory MCP client/server handshake + tool-call verification via `ServerInstructions.spec.mjs`) → L2 required (AC-1, AC-2).

## AC Evidence
| AC-1 | `test/playwright/unit/ai/mcp/server/ServerInstructions.spec.mjs` (`client.getInstructions()` on `IsolatedNeuralLinkServer` returns the `get_mcp_tool_handbook({toolId})` instruction string, and `client.callTool({name: 'get_mcp_tool_handbook', arguments: {toolId: 'get_dom_rect'}})` returns the full parameter schema) |
| AC-2 | `test/playwright/unit/ai/mcp/server/ServerInstructions.spec.mjs` (`client.listTools()` on `IsolatedNeuralLinkServer` preserves `compactToolSchemas` with `get_dom_rect.inputSchema.properties.componentIds.description === undefined`) |

## Deltas from ticket
- Recorded the deliberate choice to emit `initialize.instructions` from `BaseServer#getServerInstructions()` across all six compacted MCP servers (~220 characters per server in `initialize`, `0` added bytes in `tools/list`), and exempted `get_mcp_tool_handbook` at the `BaseServer` dispatch gate (`name !== 'get_mcp_tool_handbook'`) because the handbook reads static in-memory OpenAPI metadata and needs no healthy backend while the server's Bridge connection is down (`HealthService.mjs:123-127`).
