Resolves #1323

The corpus emitter can now heal named pull requests and discussions, the way it already heals named issues. `--refetch-pulls=<n,…>` and `--refetch-discussions=<n,…>` follow the `--refetch-issues` rules:

- the flags are parsed before the emitter loads;
- each facet refetches its named items inside its own index update;
- a named item that does not come back fails its facet, so the run exits nonzero and publishes nothing.

This also closes two gaps in the discussion refetch:

- **Denylist:** a denylisted discussion is never written.
- **Duplicates:** a refetched discussion is left with one copy. The corpus holds 58 closed discussions that are still in the active tier. A refetch would otherwise have copied them into the archive and kept the active file, and the archive-only collision check cannot see a duplicate split that way.

Evidence: L2 (unit specs, plus the real CLI in a child process against a fixture corpus, acquisition stubbed) → L2 required (every AC is emitter behaviour). Residual: none.

## Deltas from ticket

- AC-5 and Fix item 5 came out of implementation and are now in #1323's body. The issue path removes stale active copies (`IssueSyncer#removeOtherCopies`), but the discussion path did not.
- `DiscussionSyncer#removeOtherCopies` mirrors the issue method as a sibling rather than a shared helper. A shared helper would need a logger in the Neo-free inventory module and would touch both of the issue method's call sites, with no change in behaviour.
- `parseRefetchIssues` became `parseRefetchNumbers(argv, flag)`, one parser for all three flags. Its error now reads "positive numbers".
- Touched-file hygiene: `DiscussionSyncer#isDenylisted` and the `syncDiscussions` denylist read lose their `|| {}` / `?.` fallbacks (ADR 0019 §3 B3), like their issue sibling. The issue docblock no longer describes a divergence.
