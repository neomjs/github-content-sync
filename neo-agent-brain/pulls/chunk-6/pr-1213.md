Resolves #1180

Records the digest of a seat's Fleet-owned project MCP projection in `.neo-fleet-mcp-project.json` inside `instanceHome` beside `.neo-fleet-mcp-transport.json`, so subsequent Starts recognise and update a Fleet-written project file across arbitrary or consecutive plan changes without enumerating new `previous*Plan` candidate permutations.

Evidence: L1 (unit-test sandbox with real filesystem and atomic publication) → L1 required (AC-1, AC-2, AC-3, AC-4).

## AC Evidence
| AC-1 | CI-covered: `test/playwright/unit/ai/services/fleet/prepareManagedAgentWorkspace.spec.mjs` (`records the owned projection beside the transport receipt and converges across consecutive plan changes without candidate helpers` + `an interrupted project-file write converges on the next Start via the receipt previous digest`) |
| AC-2 | CI-covered: `test/playwright/unit/ai/services/fleet/prepareManagedAgentWorkspace.spec.mjs` (`a project file edited outside Fleet is refused and preserves non-Fleet entries`) |
| AC-3 | CI-covered: `test/playwright/unit/ai/services/fleet/prepareManagedAgentWorkspace.spec.mjs` (`an existing pre-receipt seat migrates cleanly on its first Start via the fallback candidate list and writes the receipt` + `a stale receipt left behind by a rollback to a pre-receipt build still converges via the fallback candidate list and refreshes the receipt`) |
| AC-4 | CI-covered: `ai/services/fleet/prepareManagedAgentWorkspace.mjs` (`convergeTransportArtifact` and legacy candidate list JSDoc retirement trigger) |

## Deltas from ticket
`convergeCodexProjectSwitches` also advances `.neo-fleet-mcp-project.json` when a receipted Codex project file has its `enabled` lines converged before `convergeTransportArtifact`.
