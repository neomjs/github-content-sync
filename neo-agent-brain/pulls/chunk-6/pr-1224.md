Related: #1142, neomjs/neo-agent-institution#732

### 🔬 Depth Floor

**Challenge OR documented search (per guide §7.1):**

- **Challenge**: `devFleetServer.mjs` starts `recoveryStartedAt` before `await runtime.verify()` and logs `formatFleetBootPhaseLine('recovery', …)` after `recoverRuntimeCustody`. On a packaged boot that line carries the full inventory #1142 measured at 2.9–6.7 s (23,747 files, 965 MB), so AC-5's "`recovery` ≤ 50 ms" fails on every real update, however fast recovery itself becomes. The inventory moved from the `runtime bind` label to the `recovery` label, rather than out of the reading. (RA-1)
- Also checked and cleared:
  - The reset to `'ready'` before `admission.recover()`. Everything between it and the call is synchronous (`adoptLeasedSeats`, the seat loop, `probeSeat`), and `recover()` sets `'recovering'` before its first await, so no Start can interleave.
  - The seed key (`JSON.stringify(runtimeGenerationPin(current))` against `JSON.stringify(start.runtime)`). Even if key order differed, `verifyPin`'s `isDeepStrictEqual(start.runtime, currentPin)` branch reuses the memoized `verify()`, so the running generation is still read once.
  - AC-2, through #1185's existing changed-bytes arm, still green at head.
- Non-blocking: `verify`, `verified` and `failureReason` are attached to a plain object with `Object.defineProperty`. A small explicit shape (or a class) would show at the call sites that the binding carries a verification state.
