# Add plugins/neo Claude Code Plugin Bundle for app skills and MCP

## Context

Anthropic's official Claude Directory (`https://claude.ai/directory/manage`) distributes installable **Plugin Bundles** for Claude Code, Cowork, and Claude apps directly from GitHub repositories (accepting a repository URL plus an optional plugin subfolder path). Live portal validation against `neomjs/neo-agent-skills` (`plugins/neo`) establishes five concrete structural gates:
1. `.claude-plugin/plugin.json` manifest at the plugin root (`name: "neomjs"`, `displayName: "Neo.mjs"` — avoiding the `"neo"` vs `"neon"` collision warning — synced to root `package.json` `version`, plus `keywords`, `documentationUrl`, `supportUrl`),
2. **Real directories and files** under `skills/<name>/` (`ARCHIVE_SYMLINK_EXEC_SURFACE` blocks Git symlinks in directory archives) with repo-relative `.agents/skills/<name>/` references rewritten to `${CLAUDE_SKILL_DIR}/` so installed marketplace caches resolve their own payloads,
3. **No local `stdio` `.mcp.json`** until the GitHub organization holds Anthropic Verified Organization status (document `claude mcp add neo-neural-link -- npx -y neo-neural-link` in `README.md` instead),
4. A square PNG icon (`512`–`2048` px, `< 2 MB`) at `assets/icon.png` (`"icon": "assets/icon.png"` in `plugin.json`), and
5. Only `audiences: ["app"]` skills bundled (`context-recovery`, `neo-app-authoring`, `neural-link`), keeping all 37 internal maintainer-only Agent OS workflows private to maintainer workspaces.

Ownership: self-assigned to `@neo-gemini-julia` (`good first issue` / `help wanted` omitted: immediate release distribution deliverable requested by `@tobiu`).

## The Problem

- `neomjs/neo-agent-brain` gitignores `.agents/skills` and `.claude/skills` (`0` tracked skill files), so cloning it yields zero skills while pulling internal Agent OS server code into `~/.claude/plugins/cache/`.
- In `neomjs/neo-agent-skills`, Anthropic's `ARCHIVE_SYMLINK_EXEC_SURFACE` directory scanner refuses Git symlinks under `plugins/neo/skills/` and refuses local `stdio` `.mcp.json` entries from unverified organizations. Furthermore, marketplace installs copy only `plugins/neo/` into `~/.claude/plugins/cache/`, so raw `.agents/skills/<name>/` paths break at install time unless rewritten to `${CLAUDE_SKILL_DIR}/` (`scripts/test-claude-plugin.mjs` enforces exact projected parity and zero repo-relative `.agents/skills/` paths on every `npm test` run).

## The Architectural Reality

- Owning repository & path: `neomjs/neo-agent-skills` → `plugins/neo/`, generated by `scripts/generate-claude-plugin.mjs` and pinned in CI by `scripts/test-claude-plugin.mjs`.
- Design authority: `n/a — introduces a new opt-in Claude Plugin Bundle projection without altering existing skill corpus or npm postinstall behavior` (`design-authority.md`).
- Boundary-forced duplication pin (`deliberate-duplication-audit.md` §§1–2): Anthropic's `ARCHIVE_SYMLINK_EXEC_SURFACE` scanner physically forbids symlinks in submitted Git trees; `scripts/test-claude-plugin.mjs` walks both `.agents/skills/<name>` and `plugins/neo/skills/<name>` and fails closed on any 1-byte projection divergence, unrewritten `.agents/skills/` path, stale `plugin.json` version, symlink, leaked maintainer skill, `.mcp.json` presence, or invalid icon.
- `plugins/neo/.claude-plugin/plugin.json` mirrors root `package.json`'s `version` (`2.6.0`, bumped on every maintainer release by `scripts/check-version-bump.mjs` and auto-regenerated via the `npm version` lifecycle script) so Claude Code invalidates cached plugins on every release (`plugins/loading.md#how-claude-code-computes-the-version`), while `package.json` `"files"` remains unchanged so the npm tarball stays lean.
- Structure map & Structural Pre-Flight (`§1c`, `/structural-pre-flight` fast-path): ran `npm --prefix ../neo-agent-brain run ai:structure-map -- --files --loc` (exit `0`); `scripts/generate-claude-plugin.mjs` matches sibling `scripts/generate-agents-md.mjs` and `scripts/test-claude-plugin.mjs` matches `scripts/test-materialize-harness-skills.mjs` in `scripts/`.

## The Fix

1. Render official `1024x1024` PNG icon at `plugins/neo/assets/icon.png` (`< 2 MB`) from `neo_logo_favicon.svg` geometry.
2. Author `scripts/generate-claude-plugin.mjs` (`--check` included) reading `.agents/skills/skills.manifest.json` (`audiences` containing `"app"`) and `package.json` (`version`) to materialize/verify `plugins/neo/.claude-plugin/plugin.json` (`name: "neomjs"`, `displayName: "Neo.mjs"`, `version: pkg.version`, `icon: "assets/icon.png"`, `keywords`, `documentationUrl`, `supportUrl`), `plugins/neo/README.md` (with directory/local install guidance and `claude mcp add neo-neural-link -- npx -y neo-neural-link`), and `${CLAUDE_SKILL_DIR}`-rewritten real-file copies under `plugins/neo/skills/`.
3. Wire `scripts/test-claude-plugin.mjs` into `npm test` (and `"version"` into `package.json` `"scripts"`) enforcing projected parity, zero repo-relative `.agents/skills/` paths, `plugin.json` version sync, zero symlinks, zero `.mcp.json`, valid square `512..2048` px PNG icon, and zero maintainer-skill leakage.
4. Bump `package.json` + `package-lock.json` to `2.6.0` and verify against `claude plugin validate ./plugins/neo`, a standalone `--plugin-dir` load outside the repo, and Anthropic's live `claude.ai/directory/manage` validator.

## Out of Scope

## Avoided Traps

- **Git symlinks in `plugins/neo/skills/`:** Refused by Anthropic's portal scanner (`ARCHIVE_SYMLINK_EXEC_SURFACE`); real files pinned by `test-claude-plugin.mjs` satisfy both the scanner and `deliberate-duplication-audit.md`.
- **Raw `.agents/skills/` paths or pinned `"1.0.0"` version in `plugins/neo/`:** Break reference resolution inside `~/.claude/plugins/cache/` and freeze installed plugin caches across releases; rewriting to `${CLAUDE_SKILL_DIR}/` and syncing `version` to `package.json` resolve both.
- **Bundling local `stdio` `.mcp.json` from an unverified org:** Refused by Anthropic's portal scanner; documenting `claude mcp add` in `README.md` unblocks immediate listing across Claude Code, Cowork, and Claude apps.
- **Using `"name": "neo"`:** Triggers a portal similarity warning against `"neon"`; `"name": "neomjs"` + `"displayName": "Neo.mjs"` resolves it cleanly.
