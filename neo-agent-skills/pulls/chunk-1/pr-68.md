Resolves #69
Refs neomjs/neo#16553

The published archaeology guard flags every all-numeric `#hash` in a comment. A CSS color such as `backgroundColor_='#000000'` therefore needs the typed `[not-ticket-ref: css-color]` marker to pass. The guard already recognizes color syntax (`CSS_COLOR_CONTEXT_RE`), but it used that pattern only to validate the marker.

With this PR, color syntax is enough on its own. The PR also adds a rule that cannot hide a real ref: a number with a leading zero is never a ticket.

This PR is the published half of neomjs/neo#16553, which requires the published guard to change first. **It carries its own version bump, 0.1.4 → 0.1.5, so merging it makes it publishable in one step** — a guard change without a version is not a complete PR, and this package has paid for that before: #44 existed only because `npm latest` and `origin/dev` both read `0.1.3` while twelve merged commits sat between them. The engine guard and the removal of the engine's two markers follow in neo, after the publish.

Evidence: L2 (red-first contract arms on the guard, the existing negative controls still reporting, and the other test runners green on this branch) → L2 required (every AC here is a property of what the guard reports on a comment line). Residual: the release, and the engine adoption after it.

## Deltas

- **Color context, not a width rule.** Treating every 6- or 8-digit number as a color would silence a future six-digit ticket in prose. With this change, a bare `#123456` outside color syntax still reports. The context comes from the guard's existing `CSS_COLOR_CONTEXT_RE`, unchanged.
- **The marker stays valid.** The guard still accepts it on a color and still reports it anywhere else (`see #242 [marker]`, `issue='#9473' [marker]`, an unused marker). Consumers that carry the marker keep passing until they remove it.
- **The README** now states the rule instead of requiring the marker.
- **A second false positive from the same family joins this PR: a numeric HTML entity.** @neo-opus-vega hit it live — a doc comment describing rendered markup carried `&#39;`, and `NUMERIC_REF_RE`'s `(?![A-Za-z0-9_])` boundary is satisfied by `;`, so the guard reported `#39` and reded CI on a comment containing no ticket. Unlike the colour case this needs no context inference and no typed marker: `&#\d+;` is an entity and the `&` immediately before the `#` is the whole rule. It lands here rather than in its own change because it is one exclusion in the same function, on a PR no seat has reviewed yet.
- **The version bump ships here, not after.** `0.1.4 → 0.1.5` in `package.json`. The workflow's own `SKILLS_VERSION` pins are consumer references, not the package's identity, so they move with every other consumer after the publish; bumping them here would point CI at an unpublished version.
- The design choice went to @neo-gpt, the guard's author.
