Resolves #71

0.1.5 rejected the legacy `ticket-ref-ok` marker and kept the typed `[not-ticket-ref: …]` form bound to colours only. A marker on anything else was itself `invalid-escape`, so **a deliberate ticket reference in a durable comment had no accepted state anywhere**.

That was invisible until consumers moved. It is now live in `neomjs/neo`, owned by [neomjs/neo#18740](https://github.com/neomjs/neo/issues/18740).

## Deltas

Measured at the consumer — one comment, four candidate repairs, both implementations run directly:

| repair | engine `buildScripts/util/check-ticket-archaeology.mjs` | this package at 0.1.5 |
|---|---|---|
| keep `ticket-ref-ok` | green | **RED** |
| migrate to `[not-ticket-ref: implementing ticket]` | **RED** | **RED** |

| delete the reference itself | green | green |

**What this PR does and does not reach — corrected after review.** My first draft of this body implied the merge ends the deadlock. It does not. The engine keeps its own implementation, which has no concept of a reference escape, so after this publishes a typed marker on a reference is **green in CI and still RED in the pre-commit hook**. Verified directly against `neo:origin/dev` post-#18734:

```
/** @see #11133 [not-ticket-ref: implementing ticket] */
  engine (pre-commit) : RED
  skills (this PR)    : green
```

That moves the worst case from *both red* to *one red*, and every one of the remaining disagreements is in the direction where the **engine stays stricter** — nothing slips past both guards. Real progress, not the outcome. *"A deliberate reference has a state both guards accept"* needs [neomjs/neo#18740](https://github.com/neomjs/neo/issues/18740) as well. Caught by @neo-opus-ada, whose 13-case differential put agreement at 7/13 with only three of the six disagreements belonging to this change.

**The deprecation notice pointed authors at the worst option.** Migrating off the legacy marker — the documented move — reds both guards where the current state reds one. The only both-green state deletes lines like `@see #11133 — the ticket this script implements`, in the file whose purpose is implementing `#11133`.

**`scripts/check-ticket-archaeology.mjs`** — `escapedRefOffsets` mirrors `escapedColorOffsets` and is wired the same way:

- offset-scoped, so a marker excuses **its own token and never the row**. A row-level escape would silence genuine archaeology sharing a line with one justified reference.
- `css-color` excluded from it, so a colour marker still cannot relabel a short ticket.
- the count equality widened to `escaped.size + refs.size` rather than dropped, so a marker binding to nothing still fails closed.
- the reason text is free-form and ungraded, but it must **declare something** — at least one non-blank character. An empty `[not-ticket-ref: ]` costs exactly what `ticket-ref-ok` cost, which is the marker this replaces. The guard owns no vocabulary; it does require a justification.
- the binding tolerates a short run of closing punctuation, because a real citation ends `(#11590)"` before the marker. Prose between token and marker does **not** bind — adjacency is what makes this a declaration.

`LEGACY_ESCAPE_RE` is untouched: `ticket-ref-ok` stays rejected. This adds one accepted form and removes no rejection.

**`scripts/test-ticket-archaeology.mjs`** — thirteen arms.

**`package.json` → 0.1.6, and `reusable-pr-baseline.yml`'s three `SKILLS_VERSION` values with it.** A guard change with no version is unreachable — consumers install `neo-agent-skills@${SKILLS_VERSION}` and resolve a range from `package.json`, so an unpublished fix reaches nobody. Leaving the workflow on 0.1.5 would publish the fix and still gate every consumer with the guard it replaces, which is precisely the split that red-lit #18734 this morning. Same shape as #68's release: the version commit, then the three pins moving in step.

**`README.md`** — it stated the token-scoped marker was accepted on a colour *"and nowhere else"*. This PR makes that false, so the sentence moves with the code rather than after it.

## Test Evidence

`node scripts/test-ticket-archaeology.mjs` → exit 0. Full suite `npm test` → **24/25**, and the 25th is not mine: a dangling `.claude/skills/whitebox-e2e` projection link fails `test-lint-skill-corpus.mjs` identically on a clean `origin/dev` worktree (control run, same 24/25). It is a local materialization artifact, not a change in this diff.

**The pre-existing colour arm caught a real defect in my first draft, and it is the lesson worth keeping.** I wrote the exclusion as `\[not-ticket-ref:\s*(?!css-color\s*\])`. The `\s*` sits *before* the lookahead, so the engine backtracks it to zero width, evaluates the negation at `" css-color]"` where `css-color` does not match, passes trivially, and the binding swallows the colour marker. `// CSS color #000000 [not-ticket-ref: css-color]` went from green to `invalid-escape`. My ten new arms all passed while that regression shipped silently — only the older arm saw it. The lookahead is now anchored to the colon: `\[not-ticket-ref:(?!\s*css-color\s*\])`.

Consumer shapes, run against the patched guard using the real comment text from the ten affected files: **6 of 7 clear**. The one that does not is `DockSplitterIframePane.spec.mjs:4`, where the reference sits *inside* the marker's reason text and so binds to nothing — deliberately not widened, and recorded below.

## Post-Merge Validation

- A release, then the pin move in each consumer — and **there are three pins, not two**. `package.json` reaches the pre-commit hook; `SKILLS_VERSION` ships inside the reusable workflow; but `uses: …@<sha>` in the consumer's own `pr-baseline.yml` moves only by a commit in that repository. With the first two moved and the third left behind, the baseline job silently installs the previous release and flags the exact lines the release existed to pass — measured on #18734 today. `skills-materialized` reads the caller's lockfile while the archaeology, substrate-size and PR-body jobs read the `uses:` SHA, so **both** coordinates move or the jobs disagree — measured today on [neomjs/neo-agent-institution#139](https://github.com/neomjs/neo-agent-institution/pull/139).
- The engine's second implementation takes the same binding, or the two disagree again in the other direction. That is [neomjs/neo#18740](https://github.com/neomjs/neo/issues/18740)'s step.
- Two shapes remain unreachable by offset binding and need their own read on that ticket: a reference **inside** the marker's reason text, and `NAMED_TRACKING_PATTERNS` prose carrying no `#` at all (`pull request 11982`, `ADR 0004 §2.2`).
