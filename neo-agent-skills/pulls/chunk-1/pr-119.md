Resolves #114

Consumers can call the shared PR baseline at `@v0`, a major tag that follows every published release. A skills fix then reaches every consumer's next PR without a pin PR in any repository:
- `tag-release` also moves `v0` (the major tag for 0.x) to each published release, forward only. A prerelease never moves it, and neither does a version older than the one it marks, so a backport can't downgrade every caller.
- `release-ref` still refuses a SHA or a branch by its form. It then checks commit identity instead of one tag name: the workflow's own commit (`job.workflow_sha`) must be the one `v${SKILLS_VERSION}` marks on `job.workflow_repository`. So `@v0` and an exact `@vX.Y.Z` both run, and a tag on an unpublished commit is refused.
- 0.1.20 is the release that makes `@v0` callable.

Evidence: L2 (the `tag-release` fixture against a real bare origin, the contract test's 75 mutation arms, and the `release-ref` script run against the live tags) → L3 required for AC-4 (a published 0.1.20 plus the three consumer switches). Residual: AC-4, Residual-Owner: #14 (unified PR governance).
