Resolves #121

A ticket that calls an existing behavior wrong now has to say who decided the behavior. The rule lives in `ticket-create/references/design-authority.md`, loaded on its trigger behind a one-line `ticket-create` §0 pointer: when a ticket calls an existing behavior wrong and there is no crash, no red and no contradiction with the surface's own JSDoc, its Architectural Reality quotes the record sentence that made the behavior intended — an ADR section, a guide, the owning JSDoc — or writes `Design authority: none found (searched: …)` and files a fork on the owning record instead of a defect with a Fix. `pr-review` §9.0 gains the handle, scoped to those tickets: no line leaves the premise unverified, a line the diff contradicts is a false premise, either → one RA, never an approval on matching tests and green CI. The template's Premise Snapshot reads the line first; `ticket-intake` step 3 reads it before any code exists.

Specimen: neomjs/neo#19225 → PR #19231, closed unmerged after the operator caught it. The ticket cited file:line for the follow and the metric and never ADR 0029 §2.8.6, which defines the corner-at-pointer placement it called wrong; a unit arm, a green suite and a green headed run followed, and a reviewer reading the ticket as the premise would have approved. The operator: "peers would review it, TRUST your ticket and approve it. i do not have time to babysit 8 peers at all times."

Evidence: L1 (docs; the payloads are what the skills load) → L1 required. Residual: none.
