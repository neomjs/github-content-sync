Resolves #65

`check-pr-body.mjs` waited for stdin to end unless stdin was a TTY, even when `--body-file` supplied the body. An agent harness spawns with a stdin that is neither a TTY nor a closed pipe, so the mandated local PR-body check hung until the caller's timeout, with no output. There were two occurrences today: my run at 16:55Z, and one another session started at 17:51Z, still sleeping an hour later. The entrypoint now runs at once when `--body-file` is present, and reads stdin to its end only when it is not. The `isTTY` branch is gone rather than joined by a second special case.

Evidence: L2 (the CLI spawned as a real process with its stdin left open, the harness shape `spawnSync` cannot produce because it closes the stdin it creates) → L2 required (the defect lives in the process entrypoint). Residual: none.

## AC Evidence

| AC-1 | `--body-file` with stdin left open exits 0 on a good body. With `--body-file=<path>`, on a body missing its anchors, it exits 1. Red-first: the old entrypoint hangs the first arm (`actual: 'hung'`) |
| AC-2 | a piped body with no `--body-file` still exits 0 |
| AC-3 | an empty piped body and an empty body file both exit 1. Two mutants of the "stop the hang by passing" kind are both red: exit 0 without reading the file, and pass on empty input |

## Deltas from ticket

- **A human running the bare command in a terminal now waits for input**, as a Unix filter does, where it used to report the missing anchors of an empty body at once. The ticket's fix removes the `isTTY` branch, and nothing in the substrate runs the bare form.

## Test Evidence

- `node scripts/test-check-pr-body.mjs`: green. `node scripts/test-reusable-pr-baseline.mjs`: green.
- Mutants, each red at its own arm: the body-file path exits 0 unread, and the piped path passes empty input.
