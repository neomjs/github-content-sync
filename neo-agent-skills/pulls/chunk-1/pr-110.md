Resolves #109

A push of a rebased branch is no longer refused for the upstream commits the branch moved onto. For a branch the remote already has, `pendingRanges()` now scans `remoteSha..localSha --not --remotes`, the exclusion a new branch already used. So a commit that some remote-tracking ref has seen is someone else's, and every commit the push adds is still read. The "no remote-tracking ref" refusal now fires only for ranges measured against the remotes alone (no `..`). An existing branch keeps its own remote sha as its basis.

Evidence: L3 (real git: a disposable origin, clone and rebase drive the guard through its hook payload) → L3 required (the push ACs). No residuals.

## Deltas from ticket
- The no-basis refusal needed narrowing to ranges without `..`. Otherwise every existing-branch push from a checkout with no remote-tracking refs would have been refused, as the existing no-remote arms show. Both changes are load-bearing: reverting either one reds an arm (Test Evidence).
- No version bump. #107 and #108 both bump to 0.1.16, so this publishes with whichever merges after it rather than adding a third racer.
