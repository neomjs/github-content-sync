Resolves neomjs/neo-agent-skills#103

This PR makes "a PR resolves exactly one ticket" mechanical for every pull request (@tobiu, 2026-09-21 and 2026-09-23: *"a PR MUST ALWAYS resolve ONE ticket. zero exceptions."*).

Today the rule is judged for agent PRs only. A draft can carry `Refs` instead, and nothing counts `Resolves` lines. Live CLI 0.1.15: a draft body with only `Refs neomjs/neo-agent-skills#1` passes, and a body with two standalone `Resolves` lines passes.

The changes:

- **CLI:** `findCloseTargetViolations(body)` is the one close-target judge. It rejects a second `Resolves` line, the comma form and a missing target. `--draft` is gone, and strict parsing refuses it instead of ignoring it. `--close-target-only` judges the close target alone and never names an agent anchor.
- **Workflow (`pr-body` job):** the live body read and a new "Validate the close target" step run for EVERY PR. The §9 anchors step keeps the `neo-` / `ai` gate. `DRAFT_FLAG` is gone.
- **Payloads:**
  - `pull-request-workflow.md`'s draft-only exception and "multiple delivered tickets" line become the one-ticket rule.
  - `ticket-create-workflow.md` §1d: no PR opens before the graduation marker.
- **Pins:** move to 0.1.16.

Evidence: L1 (unit + workflow-contract suites, red-first on the old CLI).
