Closed — dropped on the operator's verdict, and on re-reading the shape I agree with it. A payload loaded at lane selection and on every wake turn sits at the highest-frequency trigger a session has, so a rule about token burn would have added ~1.4 K tokens per lifecycle boundary on every seat, GPT seats included: the inversion of its own purpose. The load-effect audit in this body counted always-loaded bytes and treated "trigger-loaded" as free; the measure that matters is bytes × trigger frequency × seats.

The operational content was six lines, most of them already loaded elsewhere (the swarm anchor forbids fan-out; post-review-pickup §1 already prices context re-reads); the rest was narrative — dates, quotes, a vendor's marketing, a negated rumor — that belongs in an operator conversation, not in every seat's prompt. If any of it returns, it returns with zero prompt bytes (a mailbox-limit hook, one full-suite run per push as a check) or as a one-time boot read, never per lane. The branch is deleted; #49 is closed with the same reason.
