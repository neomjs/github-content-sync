Resolves neomjs/neo-agent-skills#88

A consumer's npm `overrides` are now judged on every PR. Each rule reads **needed**, **REDUNDANT** or **FIGHTING** against the ranges its dependents declare in `package-lock.json`, with no network. Dependabot neither bumps nor removes `overrides` (dependabot/dependabot-core#5590, dependabot/dependabot-core#14736), so without this a rule outlives its reason. A stale one also silently forces a dependent's new major back onto the old one (e.g. `gray-matter` moving to js-yaml 4 under our `^3.15.2`). The guard ships as `neo-agent-skills-npm-overrides`, with a stable `npm overrides` job in the reusable baseline. The PR includes the 0.1.10 release bump, as neomjs/neo-agent-skills#84 did for 0.1.9.

Evidence: **L3** — the guard run against the real `neomjs/neo` and `neomjs/neo-agent-brain` locks at `dev`, plus eleven mutation runs on the guard. The baseline job's live run needs 0.1.10 on npm, so it is listed under Post-Merge Validation.

## Deltas from ticket

- **The job runs on every PR, with no path gate.** The verdict reads only `package.json` and `package-lock.json`, so it can only change in a PR that changes one of them. The ticket body is corrected to match.
- **`semver` is a runtime dependency** rather than vendored. The package already depends on `acorn`, and npm's own implementation gives exact parity with npm's ranges.
- **Nested scope is the resolved subtree, not the parent's direct edges.** npm applies a nested override anywhere beneath the parent, and a hoisted transitive dependent keeps a rule alive (a dedicated arm covers it).
- The committed lock was stale (root at 0.1.3, two bins missing). Adding `semver` refreshed it; the formatting stays at 4-space, so the diff is the real delta.
