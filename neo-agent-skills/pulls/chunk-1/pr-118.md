Resolves #117

A dependabot pull request stops failing `PR body`. Since #103, the close target has been judged for every author, and a bot's body never carries `Resolves #N`. As a result, every version bump in every consumer reds, including #114 AC-4's tag move.

**The scope:**
- `Validate the close target` runs for every author whose `user.type` is not `Bot`, draft included. A missing type is not `Bot`, so it is judged: the check fails closed.
- For a `Bot` author, a new step logs that the close target was not judged and why, naming the login. The green says what happened, so it is not the vacuous pass #103 removed.
- Human and agent PRs are judged exactly as before. The operator merges bot PRs without a ticket (neomjs/neo#19048, #19025, #18815 and #18756; neomjs/neo-agent-institution#188). The check now matches that practice.

**Release 0.1.19:** 0.1.18 is published, so this PR moves `package.json`, the lockfile and all seven `SKILLS_VERSION` pins.

**Load effect:** none. The reusable workflow is not loaded into any agent's context.

Evidence: L2 (the workflow contract suite requires the scope and the report step; three new mutations) → L2 required (AC-1…AC-3). Residual: a live dependabot PR going green at 0.1.19, Residual-Owner: #114 (AC-4, open).
