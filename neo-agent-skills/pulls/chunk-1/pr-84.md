Resolves #83

🌿 Naming the reference you cite stops costing you the only way to declare it deliberate: the typed escape now binds to the ref it names — `Epic #1234`, `Discussion #1234`, `ADR 0004` — and not just to a bare hash.

The failure message prescribes one remedy and it worked for exactly one shape. Each of these carrying the *same* valid marker, measured through `findArchaeology()` before the fix:

| comment | escape honoured? | kinds |
|---|---|---|
| `#1234 [not-ticket-ref: …]` | ✅ | — |
| `Epic #1234 [not-ticket-ref: …]` | ❌ | `tracking-reference` |
| `Discussion #1234 [not-ticket-ref: …]` | ❌ | `tracking-reference` |
| `ADR 0004 [not-ticket-ref: …]` | ❌ | `tracking-reference`, **`invalid-escape`** |

Following the instruction on an ADR produced **two** findings where there was one.

## Why the obvious one-line fix is the wrong one

Widening `REF_ESCAPE_RE` to accept an `ADR NNNN` token is the change this looks like it needs, and it would have fixed the ADR row while leaving `Epic #1234` **exactly as inescapable** — because the named branch never consulted the escape at all.

The escapes are offset-based: `escapedRefOffsets()` collected the position of each escaped token, and the bare-numeric loop skipped those positions. That loop was the only consumer. `NAMED_TRACKING_PATTERNS.some(pattern => pattern.test(comment))` was a **whole-comment boolean** evaluated before it, and a boolean carries no position, so there was nothing an offset could excuse. Two mechanisms on different models that never met.

So the named patterns are now matched **per token** with `matchAll`, and a match inside an escape is skipped the way the numeric loop already skips one.

## Deltas from ticket

- **RA-1 (@neo-opus-grace): the excused range spanned the marker, so the reason became a place to hide refs.** `#1234 [not-ticket-ref: supersedes #5678]` excused `#5678` too — the line-wide bypass this escape is scoped to prevent, arriving through the one door an escape has to leave open. The token is captured now and the range ends at `match.index + match[1].length`. Both consumers still land inside it: the named branch indexes `Epic #1234` at the `E`, the numeric loop at the `#`. Four arms, all red against the previous head — a bare ref hidden in a reason, a named ref hidden in a reason, both-named, and the case-insensitive marker the body called a deliberate delta while nothing pinned it.
- **The two summaries drifted from the code and now match it.** `withinEscape`'s said "inside an escape"; it is inside an escaped **token**, and the difference is the whole of RA-1.

- **Ranges, not start offsets.** One escape now covers tokens its two consumers index differently — the named branch reports `Epic #1234` at the `E`, the numeric loop reports the same ref at the `#`. A point comparison would have excused whichever consumer happened to agree with the escape's own start, so `escapedRefOffsets()` became `escapedRefRanges()` with a `withinEscape()` predicate.
- **One source string for both shapes.** The detection patterns and the escape that excuses them are now built from `NAMED_WORD_REF_SOURCE` and `NAMED_ADR_REF_SOURCE` rather than two hand-kept spellings, so they cannot drift apart about what a named ref is. That was not in the ticket; it is what stopped me writing the escape's copy of the pattern slightly differently from the detector's.
- **The escape pattern is now case-insensitive**, which it was not. `ANY_TYPED_ESCAPE_RE` already matched `[NOT-TICKET-REF: …]` case-insensitively while `REF_ESCAPE_RE` did not, so an uppercase marker counted as a marker and not as an escape — `invalid-escape`, on a correctly-written escape. A second small trap, closed by the same edit.

## AC-5 is post-merge on purpose

`neomjs/neo` keeps a mirrored copy whose comment states why: *"Both patterns mirror the published guard rather than paraphrasing it, because the ONLY thing this change buys is the two agreeing."* But CI there runs **this package's published binary**. Updating the engine mirror before `0.1.9` is published would make its hook accept an escape that CI still rejects — hook green, build red, which is the worse direction of the divergence recorded on `neomjs/neo#18794`.

- [ ] After `0.1.9` publishes and the engine bumps its dependency: mirror these patterns into `neomjs/neo:buildScripts/util/check-ticket-archaeology.mjs` so the two agree line for line. **Owner: `neomjs/neo#18794` AC-4**, which already carries exactly this work — so it survives this ticket closing.

## Why it matters with zero corpus findings

No comment in `neomjs/neo` carries a named ref with an attempted escape, so the corpus shows nothing. The cost was paid at the keyboard, twice today: the guard refuses the ref, the author follows the instruction, and it refuses again with an extra finding. Both times the author rephrased instead of escaping — which is exactly why the corpus stays clean and the defect stayed invisible.
