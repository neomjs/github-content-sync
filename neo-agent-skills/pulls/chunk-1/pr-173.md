**Triage: the red `corpus` job is the contract check pinning `@v2`, not a defect in fetch-metadata v3.**

`scripts/test-reusable-dependabot-automerge.mjs:284` looks for the literal `continue-on-error: true\n        uses: dependabot/fetch-metadata@v2`. This PR changes only the version token (`reusable-dependabot-automerge.yml:77`, `@v2` → `@v3`); `continue-on-error: true` on the `metadata` step is untouched. The property the check exists for still holds: a failed metadata read does not fail the job. Its message, "a failed metadata read fails the job", is reporting a version mismatch.

**Fix that survives the next major:** match the property, not the version. For example `/ {8}continue-on-error: true\n {8}uses: dependabot\/fetch-metadata@v\d+\n/`, or parse the step and assert `continue-on-error: true` on the step whose `uses` starts with `dependabot/fetch-metadata@`. The mutation control at `:364`, which deletes the `continue-on-error` line, keeps failing under either form, so the guard stays live.

Checked against v3: its `action.yml` still exports `dependency-names` and `update-type`, the only two outputs the reusable workflow reads (`:103-104`), and it runs on `node24`. The rest of the release notes cover build tooling (ncc → esbuild, ES2024 target).
