Resolves #56

Every merge to `dev` now publishes, and `package.json` is the only place a version is written. This follows the operator's review of #119.
- **Every PR bumps.** `scripts/check-version-bump.mjs`, run from `skill-corpus.yml`, fails a PR in any of these cases:
  - the version is not greater than its base's;
  - it disagrees with the lockfile;
  - npm already has it;
  - the registry cannot answer.
- **Every merge publishes.** `.github/workflows/publish.yml` tests, then runs `npm publish` through npm trusted publishing. That is `id-token: write`, the engine's `npm-publish.yml` shape. `postpublish` then pushes `v<version>`. If npm already has the version, it runs `tag-release.mjs` instead, which finishes a rerun or refuses a merge that skipped its bump.
- **The version is read, never written.**
  - The baseline's new `Skills version` job reads `package.json` at `job.workflow_sha`.
  - `Release ref` and all six installs take the version from it (`needs: version`).
  - The seven `SKILLS_VERSION` literals are gone, and the contract test fails on any `x.y.z` in the workflow.
- This PR bumps to 0.1.20.

Evidence: L2 (contract tests over the workflow text and the scripts; the bump check run live against the real registry) → L3 required for AC-4 (the first CI publish). Residual: AC-4, Residual-Owner: #80 (its AC-2 is the first release reaching a consumer).
