Resolves #211

Related: neomjs/neo#20114

A workspace that `neo-app` creates for an outside developer can now get the skills that fit it, and only those. `neo-agent-skills-materialize --audience app` links the skills whose manifest row lists `app`: `neural-link` and the new `neo-app-authoring` (a router plus payload, ADR 0008). In that mode both harness surfaces are per-skill links, because a directory link at `.agents/skills` would expose the whole maintainer corpus. The generator emits the matching instruction file for a declared `neo-app-workspace` kind, with its own preamble, two sections and no maintainer gate. A row without `audiences` serves maintainers, so every existing consumer's projection is unchanged.

Evidence: L2 (unit contract tests against real temporary consumer roots, plus a red-first run on base) → L2 required. No runtime or host effect beyond the file projection.

agent-preflight: not hosted here; baseline `skill-corpus` jobs ran locally (corpus lint, every contract test, `check-version-bump`).

- **Added: `neo-app-authoring`** (`app` audience only). Disposition: keep, for app workspaces. - **Accretion:** the materializer gains a mode, not a consumer, and its two link checks now share one helper (`checkLinks`). There is no consumer code to delete.
