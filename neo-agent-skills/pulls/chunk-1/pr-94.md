Resolves #93

The commit-authorship guard gets a published home. It refuses agent commits that carry the operator's identity, or that credit an address outside the team, and nothing ran it until now (neomjs/neo#18757). Its logic ships as `neo-agent-skills-commit-authorship`. The team roster is the caller's input and never data of this package. As @tobiu put it, the roster marks **our team**, whose agents have their own accounts and addresses, apart from **everyone else** running the Agent OS with their own PAT logins, forks, and contributors who are not maintainers.

Evidence: L2 (a contract test over real commits in a disposable repository with a linked worktree, plus the workflow contract suite) → L2 required (the guard reads git topology and history; a pure-function tier cannot see either). Residual: the CI job runs only once a consumer names a baseline revision carrying 0.1.12, and 0.1.12 must be published first.

## AC Evidence

On a new branch of a pinned clone whose trunk is `main`, with no `dev`, the same leak is refused, and with the roster its off-team trailer is refused too |

## Deltas from ticket

- **The roster contract is two functions the Brain already exports.** `ai/graph/agentCoAuthorEmails.mjs` satisfies `registryAgentLogins()` and `rosterEmailForLogin(login)` today, so the Brain needs no change to be a caller. The team's domains are derived from its seats' addresses instead of a hardcoded `@neomjs.com`.
- **A roster the caller named but the guard cannot read fails loud** (exit 1). The Brain guard failed open on unreadable input, which is right for a missing map in someone's push hook. It is wrong for a CI caller whose misconfigured path would otherwise green every PR.
- **A new branch is measured against what the remote has seen, not against one trunk name.** A new remote branch and a manual run scan `<sha> --not --remotes`, so a `main`-trunk repository is covered like a `dev` one. The first head hardcoded `origin/dev` and swallowed the failed read, so a `main`-trunk push greened both checks (@neo-gpt's review, RA-1). Two refusals replace the silent pass: no remote-tracking ref to measure against, and a range git cannot read. The repair hint no longer names `origin/dev`.
- **The checkout-override contract got one exception.** `test-reusable-pr-baseline.mjs` refused any `repository:` checkout. The roster step is now the only exception, and it must land in `.team-roster`, beside the caller's tree. The existing caller-override arm still fails.
