Resolves #78

🌿 The contract could say "a checkout exists" only in the dialect of one release — so upgrading the action read as deleting the step; now it asserts the structure, and an arm proves it can still notice the structure's absence.

`:64` expressed *"the `skills-materialized` job checks out the caller"* as *"matches `checkout@**v4**`"*. Dependabot moved `v4 → v7`, the regex missed, and a job that still had its checkout was reported as having lost it.

Evidence: **L2** (the contract test executed against both workflow revisions, plus a sabotage control on the loosened assertion) → L2 required — the claim is about what a test accepts and rejects, fully observable by running it. Residual: none.

## AC Evidence
| AC-1 | `:64` is now `/uses: actions\/checkout@v\d+/`. Deliberately not a bare `checkout`, which would also match a commented-out line or another action containing the word. |
| AC-2 | Reproduced then fixed against **#77's actual bumped workflow**: before, `actual: [ 'missing caller checkout' ]`; after, exit 0. |
| AC-3 | Three `.replace()` targets no longer embed a major — see **Deltas**, the count in the ticket was wrong. |
| AC-4 | `assert.notEqual(mutated, source, …)` at `:237` is **unchanged** — `git diff` touches only the assertion regex, three anchors, and the new arm. |
| AC-5 | New arm `caller checkout removed` deletes the step and expects `'missing caller checkout'`. **Sabotage control:** replacing the assertion with `/uses: actions/` makes that arm fail — `caller checkout removed: expected "missing caller checkout"` — so the loosening is constrained rather than permissive. |
| AC-6 | `test-reusable-pr-baseline.mjs` exit 0 with **43** mutations at `checkout@v4` *and* at `checkout@v7`; `lint-skill-corpus.mjs --base origin/dev` green. |

## Deltas from ticket
**The ticket said five `.replace()` targets embed a version. Three do.** I conflated the *anchor* with the *inserted value*:

| site | verdict |
|---|---|
| `:268` checkout, `:318` setup-node, `:396` github-script | anchors carried a major → **fixed** |
| `:414` | anchor is `'- name: Install immutable PR-body guard'`, already version-free. Its *inserted* `@v4` is harmless: the assertion accepts any major, so the insertion still matches. **Unchanged** — churning it would be noise. |

**And the ticket's central risk assessment was inherited from a diagnosis that was wrong, which I corrected before implementing.** @neo-opus-ada reported `:265`/`:407` as *"the nastier half — a `.replace()` on a vanished literal silently does nothing, so the arm passes for the wrong reason,"* the *"control that cannot fail"* shape. It cannot happen: `:237` already asserts the mutation changed the source. **Demonstrated rather than argued** — with `:64` fixed against the bumped workflow, the stale literal produced:

```
AssertionError: caller checkout: fixture mutation changed nothing
```

Named, loud, pointing at the arm. So those sites were **upgrade friction**, not a false-green risk, and the fix is worth making for noise rather than for correctness.

**What the ticket missed entirely, and it is the more serious half:** the `caller checkout` assertion had **no negative arm**. Nothing proved it could fail. Loosening a regex with no such arm is precisely how an assertion starts matching anything — so the new arm is not decoration, it is what makes AC-1 safe. That gap predates this change.
