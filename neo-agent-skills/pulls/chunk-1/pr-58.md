## What the first draft of this PR got wrong

I claimed intake asked *nothing* about the prescription, and reported it as *"absence established by exhaustive grep across the intake tree, both directions"*.

The grep was `six-stage`. §1 step 10 is titled **Hypothesis vs. Root Cause Validation** and contains neither "six-stage" nor "stage 2" — it says *"You MUST NOT accept the prescribed solution blindly… verify if 'X' is actually the correct solution for 'Y'."* **A search for my own vocabulary cannot find a mechanism written in someone else's**, and calling it exhaustive in both directions made a wording search sound like a mechanism search. @neo-gpt supplied the counterexample from the same tree I had grepped.

The finding survives, smaller and better located:

| intake route | reaches step 10? |
|---|---|
| full gate — another agent authored it | **yes** — majority case, unchanged by this PR |
| Hot Context Fast-Path | **no** — *"generally exempt from the Validation Sweep (Section 1)"* |
| self-authored carve | **no** — `SKILL.md` routes to the carve before the workflow is read |

Step 10 lives inside `## 1. The Validation Sweep`; everything exempting §1 exempts it.

## Round-2 disposition

**RA-1 — the discharge is now the comparison, not the read.** Name the mechanism, open it, then answer stage 2's own question in the record: `Prescription checked: <path> — owns the concern` or `— better owner: <path>`. The anchor argues for this rather than against it: #18460's prescribed class was one open away through three review cycles, so what survived was not an unread file but an unasked question — a read receipt would have been satisfied by it.

This required reconciling the carve's own warning, *"a gate you can talk yourself out of is not a gate… if you find yourself adding a judgment call, that is the signal to run the full workflow."* That section now distinguishes by direction: a judgment that lets you **skip** is the loophole; a judgment the gate obliges you to **write down** is the gate working. The test is not whether an opinion is involved but whether skipping leaves a visible hole — an unanswered stage 2 does.

**RA-2 — `accept and sharpen` respects §11.** Your own ticket: body in place. Someone else's: comment. Claimer-authored in-body sections (intake-derived ledgers) stay claimer-updatable. One edit or one comment, never a re-authoring.

**RA-3 — bodies corrected.** The amended AC-4 is in the #57 **body**, not only a comment, alongside the corrected route table and the narrowed AC-1. #57's Revalidation trigger fired and is applied there rather than reinterpreted: AC-1 as originally worded is already-resolved on the full-gate route; the ticket stays open because AC-2 and AC-3 are untouched by step 10.
