Resolves #154

A consumer's Dependabot `neo-agent-skills` bump now merges itself once its required checks pass.
`reusable-dependabot-automerge.yml` decides from the event, then hands the pull request to GitHub's auto-merge when:
- the author is `dependabot[bot]` and a `Bot`, and Dependabot sent the event;
- every dependency is on the allow-list (the package and the reusable-baseline tag);
- the update is a patch or minor;
- the repository variable `NEO_AUTOMERGE_SKILLS` is not `off`.

Before arming, `handoff` reads the consumer live: *Allow auto-merge* on, at least one required status check in the base branch's rulesets, and the head still the admitted commit. A missing, empty, unreadable or malformed read turns it red and arms nothing. The arming carries `--match-head-commit`. Every event decides again, and an ineligible Dependabot pull request loses the arming this workflow made.

Nothing in the workflow merges by itself. Both jobs run one script each from the workflow's own commit (`job.workflow_sha`), never from the pull request's head. Critical gate 1 gains a `machine_merge` line naming this one machine path; agents still never run `gh pr merge`. The version is 0.1.33.

Evidence: L2 (the real decision and handoff on fixture events and a recorded `gh`, the command line through a stub `gh`, and a mutation-sensitive contract over the workflow source; GitHub's auto-merge and the consumer rulesets cannot be exercised before a caller exists) → L4 required for AC-5 (a consumer's first self-merged Dependabot PR). Residual: AC-5, Residual-Owner: #14.

## Deltas from ticket

- Eligibility is a script run from the workflow's own commit, not YAML expressions. AC-1's fixtures therefore exercise the decision that runs, and the code that decides a merge is never code the merge brings in. Recorded at intake ([6098596650](https://github.com/neomjs/neo-agent-skills/issues/154#issuecomment-6098596650)).
- The admission reads GraphQL `autoMergeAllowed`: REST omits `allow_auto_merge` below write access. Required checks come from the base branch's rulesets, which every consumer uses; classic branch protection is not read, so a repository relying on it alone is refused.
- Every event decides again. Without that, a fix a peer pushes onto an armed Dependabot pull request would merge with no human merge.
- The workflow header states the `GITHUB_TOKEN` rule: a merge GitHub performs for this token is expected to start no `push` runs on the base branch. Measured on the consumers, none of those runs matters for a pin bump: `substrate-sync` only asserts materialization, CI repeats the pull request's own checks, and devindex `pages` would deploy unchanged output.
- The gate line names no ticket, so the substrate carries no archaeology.
