Resolves #116

This is the package side of #114. Operator, 2026-09-24: *"we want npm versions. published skill releases. NEVER EVER SHA values."* After this PR, the shared baseline refuses a caller that is not at the tag of the release it installs, and a real publish sets that tag.

**Tag every publish.** `postpublish` runs `scripts/tag-release.mjs`, which puts an annotated `v<version>` on origin at the published commit. It runs after the registry already holds the version, and a failure cannot be undone by publishing again, so every path is loud and safe to rerun:
- `npm publish --dry-run` still runs postpublish, with `npm_config_dry_run=true` (measured on npm 11.12.1), so it exits 0 and tags nothing;
- a tag already on origin at HEAD is a no-op;
- a tag marking another commit, locally or on origin, is refused;
- a dirty tree is refused before tagging;
- a failed push exits 1, naming the rerun that finishes the release.

**Only this release's own tag.** The reusable baseline's new first job, `Release ref`, fails unless `job.workflow_ref` ends in `@refs/tags/v${SKILLS_VERSION}`. That is the job's own pin, the npm version every job installs, and the drift test holds it to `package.json`. A SHA, a branch, another version, or a non-canonical tag such as `v01.2.3` all fail.

**Docs:** the workflow header and the README say "a published release tag".

**Release 0.1.18:** `package.json`, the lockfile and all **seven** `SKILLS_VERSION` pins, including `Release ref`'s. 0.1.17, carrying #111 and #113, was published before this PR, with `gitHead` `f7b29e7`. It is tagged `v0.1.17` by hand, the manual step the script now automates.

Evidence: L2 (the tag script against a real bare origin, covering a dry run, a failed push and its recovery; the contract test's mutations; the exact bash check across refs) → L2 required (AC-1, AC-2). Residual: the consumer switch and the dependabot read, Residual-Owner: #114 (the open parent).
