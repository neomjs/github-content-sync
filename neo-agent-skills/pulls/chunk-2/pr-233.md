Resolves #22

🌿 *A review template can no longer change without the check that enforces it changing in the same release.*

The agent review lint now ships as a package, beside the templates it enforces. `scripts/check-pr-review-body.mjs` is a pure policy, published as `neo-agent-skills/pr-review-policy` and the `neo-agent-skills-pr-review-body` bin; it judges a review envelope and never reads GitHub. `.github/workflows/reusable-pr-review.yml` is the `pull_request_review` entry a consumer calls at a release tag. Its read-only `Review body` job judges the live review. A separate `Review correction` job, the only one that writes, keeps one marker-owned comment per failing review. Until callers adopt it, a review posted with `gh pr review` or in the UI is linted only in neo; Brain, Institution, Skills and Stage run nothing, which is how #232's star-rated review went unflagged.

Evidence: L2 (unit arms, the packed tarball, and the workflow's own scripts executed against mocks, plus a differential against Engine's inline workflow on real reviews) → L3 required for AC-4/AC-5 (a live run on a caller's review). Residual: AC-4, AC-5, Residual-Owner: #14 (its caller leaves follow this release). `agent-preflight`: not hosted here; the corpus, PR-body and ticket-body jobs run instead.

Related: #14

## Deltas from ticket
The three sharpenings from [the intake](https://github.com/neomjs/neo-agent-skills/issues/22#issuecomment-6473478603), as Emmy folded them into the body ([6473708487](https://github.com/neomjs/neo-agent-skills/issues/22#issuecomment-6473708487)):
- The two Engine divergences resolve to the managed contract. These are enumerated porting deltas, not a precedence rule, and from here the package owns the policy.
  - Skeleton headings come from the shipped templates, for the full and follow-up forms and for Round 2, whose H1 now needs its `(disposition only)` suffix.
  - A COMMENT never opens a demand packet, whatever its budget markers.

  These are the only verdict changes a neo caller inherits.
- The comment carries at most one finding, always one of the module's own strings.
- The activation issue is an input (`budget_activation_issue`); 0 means every Request Changes owes provenance.

The ticket's "derive the shapes from the assets" is met by binding, not by runtime reads. The anchors are declared constants, and the suite asserts each one appears in the template it names, in the repository and in the packed tarball. A runtime read would need Brain's fallback copy for a missing file. Rules that need pull-request history stay managed-only: the Round-2 relation, acknowledgement of an outstanding RC, and A+FU ownership against close targets. Measured and not added: a 0–100 metric-value check, which caught nothing the anchors miss in 207 real reviews.
