Resolves #215

The two app-audience skills now work in any harness and say how to get connected. Both routers told the agent to "use the `view_file` tool", which an outside harness does not have; they now say "read". `neural-link`'s handbook covered tool order only once connected. It gains a §0 Getting Connected:
- the Bridge on `127.0.0.1:8081` (`NEO_NL_PORT` overrides it), which the server starts when none runs;
- that zero `sessions` in `healthcheck` means no page is connected;
- the reload rule for "No active App Worker sessions found";
- `get_mcp_tool_handbook({toolId})` for a tool's parameter documentation;
- the `windowId` fallback for engines up to 13.3.2.

The corpus lint now refuses an app-audience router that names `view_file` or `read_file`. 0.1.64.

The deletion: the two router clauses that named a tool. The new lint rule is the one added check, and it keeps AC-1 true without a reviewer.

Evidence: L2 (the corpus lint and its fixture test, run on the real corpus) → L2 required (AC-1, AC-2, AC-3). Residual: none.
