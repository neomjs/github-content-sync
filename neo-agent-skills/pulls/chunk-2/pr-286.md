Resolves #285

A closing expression in a commit message closes its issue once the commit reaches the default branch, and neo builds squash bodies from commit messages. The PR-body check guards only the body. The commit-authorship guard is the one guard that reads the commit range, at pre-push and in CI, so it now refuses any closing expression in a commit message.

- **Matcher:** `GITHUB_CLOSING_EXPRESSION` from `check-pr-body.mjs`, the one the PR body answers to. No second regex.
- **Scope:** every commit in the pushed or PR range, at the hook and in CI. The rule reads only the published text: who authored the commit or opened the PR never exempts it.
- **Reads:** commits are now read for every push. The no-basis refusal stays with the identity checks. Without a basis, the closing check reads the whole unseen history, which is everything this push publishes.
- **Whole messages:** `readCommits` reads with `git log -z` and newline-separated fields. A message carrying the old in-band `\x1f`/`\x1e` delimiters is now read whole, for the trailer check too.
- **Deletion:** the manual `git log origin/dev..HEAD` scans in `pull-request-workflow.md` and `pr-review-guide.md` §5.2 shrink to a pointer at the guard (−282 skill bytes).
- **Release:** 0.1.90 → 0.1.91.

Evidence: L2 (guard contract arms against real commits in a disposable repository, on the hook and CI paths) → L2 required (#285's ACs are guard behavior).
