Resolves #358

A pull request from a fork keeps the base version, and its merge publishes nothing; the next maintainer release carries it, as it already carries Dependabot's. One exported classifier, `originOf` in `scripts/release-origin.mjs`, answers `dependabot`, `fork` or `maintainer` from a PR receipt, and both callers use it: `check-version-bump.mjs` and `releaseOrigin()`. A fork that never touched the version passes however far `dev` moved since it branched. A fork that changes the version fails with a sentence written for its author. Version 1.4.5, a patch: the release rule is this repository's own, and no bin or consumer rule changes. #348 merged as 1.4.4; this branch is rebased onto it.

Evidence: L2 (the contract runners exercise the three origins, the deleted fork, the missing base, a fork over a base two releases ahead, a bumped fork, and the publish workflow's own origin step under stubs) → L2 required (AC-1 to AC-6). AC-7 is the post-merge re-run, mine, on the day of the merge.
