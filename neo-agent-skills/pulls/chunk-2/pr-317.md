Resolves #316

**Release 1.0.0.** A hand-posted reply's review now scales with its claims. A reply that only restates what a reviewed, published piece says goes to the operator after the author's self-check. A reply with a new claim about how our system works keeps the cross-family check, and its author reads the code behind the claim, not its name. Boundaries apply to every reply, and the executor path keeps its attestation. The evidence: seven replies of the first kind passed six review rounds unchanged, and the one reply of the second kind carried a factual error that the cross-family read caught.

Evidence: L1 (payload-only skill text; `npm run lint -- --base origin/dev` and `npm test` green locally) → L1 required (AC-1, AC-2).

## AC Evidence
| AC | Evidence |
|---|---|
| AC-1 | `outbound-post.md` §1.7 (the review scales with the claims) and §4's opening line (posts, plus replies with a new claim) |
| AC-2 | lint "within budget", with the growth justified in the commit; `npm test` exits 0; version 0.1.98 → **1.0.0** |

## Load effect
The `SKILL.md` router is unchanged, so the always-loaded delta is 0 B. `outbound-post.md` grows by +374 B and loads only for an outbound post or reply.

## Deltas from ticket
- **This PR is the 1.0.0 release (the operator's ruling).** The team has used the package as a stable contract for a long time, but its 95 releases were all 0.1.x patches, rule additions included. The README gains `## Versioning`:
  - the public contract: skill names and paths, the bins and their flags, the reusable workflows and their inputs;
  - which part a change bumps: major breaks a consumer, minor adds or changes behavior, patch corrects without changing what a rule or check decides.
- An intermediate 0.2.0 commit is superseded by 1.0.0 in the same PR, so only 1.0.0 publishes.
