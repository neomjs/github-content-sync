Resolves #336

The gate header said "These ten rules", but four of the five variants emit nine gates. Only the variants that include `neo-agent-brain`, which declares the tenth gate, emit ten.

An agent told "ten rules" with nine in front of it either looks for a tenth that its variant never had, or learns that a count in a gate header is loose. The header is in the turn-loaded file of every maintainer session.

The numeral was prose in the section, so the fix is one word: the header now says "These rules". The generator is unchanged and still numbers each gate from its declared number, so a variant that drops a rule keeps the numbers it declares.

Evidence: L2 (the generator and the skill corpus lint run in CI) → L2 required (AC-1, AC-2, AC-3).

## Slot Rationale & Substrate-Load Audit

- **Router impact:** none. The change is one line in `agents-md/sections/0400-critical-gates.md`, the source of the emitted `§critical_gates` block. No skill file, no manifest, no routing table is touched.
- **Modified section (`agents-md/sections/0400-critical-gates.md` §`critical_gates`):**
  - **Disposition:** `keep` in the on-demand payload (one word: `ten` removed).
  - **Rationale:** The count was prose, so the generator never knew about it. Dropping it is the only change that can be right for every variant: the number of gates differs per variant, the wording does not.
- **Net `agents-md/**/*.md` byte delta:** `-4` B (`"These ten rules"` → `"These rules"`).
