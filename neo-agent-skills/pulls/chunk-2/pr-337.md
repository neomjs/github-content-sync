Resolves #334

🌿 Running one spec for a receipt can no longer cost the seven files a new harness pattern needs.

§2 of `unit-test.md` now keys its reads on the work: nothing for a run, the spec itself for arms or a fix, a sibling and `setup.mjs` for a new spec file, and the former full set only for a pattern no sibling shows. Step 1, a session boot inside a running session, is gone. The file is 6,899 B before and after; the package goes to 1.3.5.

Evidence: L1 (the text, the lint and the test runners) → L1 required (no runtime-verify ACs). No residuals.

## Deltas from ticket

## Slot rationale

- **Load path.** `SKILL.md` is the always-loaded router and is untouched. `references/unit-test.md` is the payload a seat reads on activation: 6,899 B before and after. What changes is what the payload makes the seat read next.
- **§2, the reads: `rewrite`.** Trigger-frequency: every activation. Failure-severity: minor, a wrong-shaped spec fails in CI and §4's rules stay. Enforceability: discipline-only.
- **§2 step 1: `retire`.** It repeated the turn-start mailbox check and the turn-end save, and its extra `add_memory` contradicted `§memory_core_protocol`.
- Prescription checked: `.agents/skills/unit-test/references/unit-test.md` §2 — owns the concern. The router's trigger is right as it is; the reads were mandated here.
