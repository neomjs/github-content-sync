Resolves #318

The shared PR baseline gains a `guards` input, a JSON list of `{name, run}`, and a `guards` job that runs the list on the pull-request-code side. A caller binds one context however many guards it declares: `baseline / guards` in Engine. This is step 1 of `neomjs/neo#17171`'s Decision. Engine's half (its guard list, retiring its standalone `*-lint.yml` workflows, the pin bump and the ruleset entry) builds against this interface.

- **The job sits beside `Skills materialized`, not in `PR baseline`.** A caller's guards are its own scripts, so they are pull-request code, and `PR baseline` runs none (steps of one job share `GITHUB_ENV`, `GITHUB_PATH` and the filesystem). It does checkout, `setup-node`, `npm ci`, then one step for the whole list.
- **Every guard runs, even after a red,** in order, each in its own log group. The step summary has a pass/fail row per guard, and the job fails if any guard failed.
- **A malformed list fails before any guard runs.** That covers not JSON, not a non-empty array, an entry other than `{name, run}`, an unsafe or duplicate name, and an empty command. The list reaches the runner through `env:`, never a shell.
- **A caller that declares no guards skips the job,** so it holds no runner slot for it.

**Version: 1.1.0, a minor bump.** The input is opt-in, so a caller that declares nothing sees no change, and no guard newly fails a consumer that passed (README "## Versioning").

Evidence: L2 (`test-reusable-pr-baseline.mjs`: the canonical contract + 97 negative mutations, 7 of them new; the runner runs for real in the contract, node plus a bash guard per entry; all 24 `skill-corpus.yml` steps green locally at e9191c7) → L3 when Engine's caller runs its first `guards` job. Residual: the first hosted `guards` run, Residual-Owner: `neomjs/neo#17171`.

## Deltas
- **The contract test's job lookup anchors to a line start.** The `guards` input's line, `      guards:`, contains the job marker `  guards:`, so the old substring lookup returned the input block. This is the first time an input and a job share a name.
- **An empty list skips the job instead of running it green.** A green job with no guards would hold a runner slot on every consumer's pull requests for nothing. A caller that requires `guards` declares guards, so for it the job always runs.
