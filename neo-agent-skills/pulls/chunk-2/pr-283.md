Resolves #281

The shared PR baseline drops from ten jobs to two, saving 8 runner slots per PR push in every consumer under the organization's 20-slot cap:
- **`PR baseline`** runs the nine checks that execute no pull-request code as steps of one job: one checkout of the exact head with full history, and one guard install into `runner.temp` at the release `package.json` names.
- **`Skills materialized`** keeps its own job, unchanged. It runs the caller's `npm ci` and a binary from the caller's lockfile, and steps of one job share `GITHUB_ENV`, `GITHUB_PATH` and the filesystem.
- **Every step after the first runs under `!cancelled()`.** A red check doesn't stop the later ones, and the job fails if any step failed. `continue-on-error` stays forbidden.
- **Every event runs every check**, `edited` included. One context carries all nine verdicts, so an edit running only the body checks would overwrite another check's red on the same head (Emmy's condition).
- **Nothing the workflow owns lands in the caller's tree.** The release version is read over the API and the team roster is cloned into `runner.temp`, so the caller head is the job's only checkout and no tracked path is replaced or deleted before a guard reads it.

Evidence: L2 (the workflow contract suite, the full `npm test` chain and `lint --base origin/dev`) → L3 required for the live job count and the neo ruleset swap. Residual: AC-6, AC-7, Residual-Owner: neomjs/neo#20328.

## Deltas from ticket

- **No aggregate step.** The ticket first planned `continue-on-error` plus a final failing step. The suite already forbids `continue-on-error`, so `!cancelled()` gives the same coverage with nothing that could miss a check. #281's body was updated to match.
- **One guard install, not seven.** The guards ship in one package, so the per-guard `runner.temp` roots collapse into `neo-agent-skills-guards`.
- **No checkout but the caller's.** The release version is read over the API, and the team roster is cloned into `runner.temp`. Earlier heads checked both out inside the caller's tree and removed the version copy afterwards. That removal hid a caller-tracked file under the same path from the secrets scan (Emmy's RA-1).
- **Comments describe behaviour.** `check-ticket-archaeology` scans a touched file in full, so the contract suite's ticket and review references became plain statements.
- `README.md`, the `pull-request` reference and a `skill-corpus.yml` comment name steps where they named jobs.
