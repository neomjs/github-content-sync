### 🔬 Depth Floor

- **Challenge**: Two concrete edges in `scripts/check-pr-body.mjs` (Required Action 1) plus one non-blocking observation on `ci-job-count.mjs`:
  1. **Merge-base vs live `BASE_SHA` (`ciJobsAgainst`, `scripts/check-pr-body.mjs:492-504`):** On `pull_request` `edited`/`synchronize`, `github.event.pull_request.base.sha` points to the current tip of `dev`, not `git merge-base <base> HEAD`. `#426` explicitly notes that `#427` and an upcoming Engine PR will cut existing CI jobs on `dev`. As soon as `dev` drops e.g. `38 → 30` jobs, every already-open PR forked at `38` jobs (and un-rebased per today's rebase-only-on-conflict rule) has `head = 38 > base = 30`, causing `PR baseline` to fail every un-rebased non-workflow PR until it rebases (burning ~35 runner jobs per rebase) or writes a false `CI jobs:` claim. Resolving `mergeBase = git merge-base <base> HEAD` (matching `check-ticket-archaeology.mjs:298`'s `base...HEAD`) compares the branch strictly against the commit it forked from (`git merge-base HEAD HEAD === HEAD`, so working-tree CLI tests still pass).
  2. **Fail-open `catch` on `readWorkflows` (`scripts/check-pr-body.mjs:494-501`):** `read({ref})` runs `git ls-tree` (repo-root-relative from any subdirectory), whereas `read({})` runs `readdirSync(join(process.cwd(), '.github/workflows'))` (cwd-relative). Wrapping both in `try { return readWorkflows(options) } catch { return {} }` means invoking `neo-agent-skills-pr-body --base origin/dev` from a subdirectory (or hitting a non-`ENOENT` read error on head) reads `base = 38` and catches head `ENOENT` as `{}` (`head = 0`), exiting `0` even when the diff added CI jobs. Resolving `git rev-parse --show-toplevel` once and catching only an absent `.github/workflows` path closes the fail-open path.
  3. **Non-blocking note (`ci-job-count.mjs:132-145`):** A reusable-workflow caller job (`uses: org/repo/.github/workflows/foo.yml@v1`) counts as `1` rather than expanding the callee's internal jobs (`reusable-pr-baseline.yml` runs up to 3). Because base and head use the same rule and adding a new caller job still increments `0 → 1`, the relative gate remains sound without cross-repo YAML fetches.
