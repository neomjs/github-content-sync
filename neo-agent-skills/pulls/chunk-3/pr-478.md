Resolves #477

Before drafting Neo Engine, example and Learn tickets, authors must try the native way to accomplish the user's task. The existing prescription and consumer checks now use the result to choose public Engine work, application composition, teaching work, or no ticket.

Evidence: L2 (skill-corpus and generated-plugin contracts, plus inspection of the shipped workflow) → L2 required.

| Criterion | Verified change |
|---|---|
| AC-1 | Both the maintainer and standalone paths load §2. Stage 2 links the Engine Structural Inventory to locate packages. Maintainers query the Knowledge Base for usage. Standalone readers can search the Engine’s `src/`, `examples/` and `learn/`. Both trace the public entry through the owner and a shipped consumer. |
| AC-2 | Stage 2 requires the distinguishing behavior and a working case to preserve. Missing evidence leaves the prescription open. The Architectural Reality section requires authors to state the observed gap and how it determined scope. |
| AC-3 | Stage 4 requires an independent app's import or declarative config and app-owned data or actions. If the capability exists, the author identifies the remaining teaching gap or drops the issue. The generated verify-before-code workflow carries the same instructions. |

The minor bump from 2.9.4 to 2.10.0 changes an authoring rule. The new inventory link is registered in the document-reference census. The form/picker case is a worked example with four required grading criteria.

## Slot rationale

Rewrite the existing prescription, consumer and Architectural Reality instructions. The trigger remains before a Neo ticket is drafted. The canonical router and workflow together are 117 bytes smaller than on the base. The worked example and grader are loaded only for the exercise.

These are qualitative worked-example results. They do not establish that the revised workflow improves real ticket decisions. The AC table above cites the actual rule and distribution paths.
