Resolves #436

The shared baseline's `guards` job now hands every guard a caller declares the pull request's base commit (`BASE_SHA`, in history) and its live body (`BODY_FILE`). The job reads the body itself, before `npm ci` and on every run attempt, with the step `PR baseline` runs, so "Re-run failed jobs" judges a corrected body. It gains `pull-requests: read` and stays read-only on its own repository. Its checkout takes full history and persists no credential, and a `Base commit in history` step fails the job before any guard runs if the base is missing. neomjs/neo#21504 needs exactly this to fold File Size Guard into `guards` and drop its two Engine runner jobs per guarded event.

Evidence: L2 (contract test: a fixture guard through the real runner, the body step pinned to `PR baseline`'s, and a mutation arm per property; a reusable workflow runs only from a published release tag, so no job of this PR can run it) → L3 required (AC-1's real-job half).
