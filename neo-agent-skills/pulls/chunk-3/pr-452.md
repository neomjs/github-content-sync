Resolves #447

`scripts/generate-claude-plugin.mjs` now builds every plugin from one harness-neutral `PLUGIN_BUNDLES` registry. Each entry holds a slug, a name, the description a model reads when it decides to install, and its skills or audience. The script writes each bundle into `plugins/<slug>/` and writes the root `.claude-plugin/marketplace.json`.

Two things now work:
- `claude plugin marketplace add neomjs/neo-agent-skills` installs from this repo (its default branch is `dev`).
- `--check` fails on drift in the registry, the bundles, the marketplace, or any unregistered bundle.

`plugins/neo` keeps `name`/`displayName` for the pending directory submission. Its description now leads with the UI work no directory plugin covers today: data grids, Gantt, schedulers, kanban, multi-window desktops, and live inspection of a running app.

Evidence: L1 (contract tests and `claude plugin validate`, run locally) → L1 required (AC-1 to AC-4). Directory listing and search rank are L3/L4 rows on #446's closeout matrix, not this leaf's.

agent-preflight: not hosted here (no `ai/`). Baseline `npm run lint -- --base origin/dev` and `npm test` ran, exit 0.

## Deltas from ticket

- `description` is capped at 500 characters (`MAX_DESCRIPTION`), because the directory's search results cut longer descriptions mid-word (measured 2026-11-24 in the epic review on #446). `--check` reports any bundle over the cap.
- A bundle sets exactly one of `skills` (explicit) or `audience` (derived; `plugins/neo` keeps `app`). An unknown skill throws. Generic `intro`/`setup` README lines replace the ticket's `mcpSetup` field.
- Unregistered `plugins/<dir>` directories and duplicate slugs or names fail closed.
- The `npm version` lifecycle now stages `plugins` and `.claude-plugin`.
- `appSkillsFrom` became `audienceSkillsFrom(manifest, audience)`. The `PLUGIN_REL` export is gone; only the tests used it.
