Updates `cssnano` from 9.0.5 to 9.2.0
<details>
<summary>Release notes</summary>
<p><em>Sourced from <a href="[QUARANTINED_URL: github.com]">cssnano's releases</a>.</em></p>
<blockquote>
<h2>v9.2.0</h2>
<h3>Features</h3>
<ul>
<li>Merge box alignment properties into the <code>place-content</code>, <code>place-items</code> and <code>place-self</code> shorthands, such as <code>align-items:center;justify-items:start</code> into <code>place-items:center start</code>. This only happens when every browser in your Browserslist targets supports the shorthands, because a browser that does not would ignore both alignments. The <code>defaults</code> query includes browsers with unknown support, such as Opera Mini and UC Browser, so it keeps the longhands. Values that use <code>safe</code>, <code>unsafe</code> or <code>last baseline</code> merge only when both values use the same keywords. <code>postcss-merge-longhand</code> now accepts the Browserslist options <code>overrideBrowserslist</code>, <code>stats</code>, <code>path</code> and <code>env</code>.</li>
</ul>
<h3>Fixes</h3>
<ul>
<li>
<p>Write numbers in scientific notation when it is shorter, such as <code>1e-6px</code> for <code>0.000001px</code> and <code>1e6px</code> for <code>1000000px</code>. This also applies when <code>length</code> unit conversion is disabled. Numbers written without a decimal point, such as <code>z-index:1000000</code>, keep their form, because an <code>&lt;integer&gt;</code> cannot use scientific notation.</p>
</li>
<li>
<p>Stop merging longhands across a nested rule or at-rule. The shorthand ended up after the nested rule and overrode it, so in <code>a{margin-top:1px;&amp;{margin-top:2px}…}</code> the nested <code>margin-top</code> was lost. This applies to <code>margin</code>, <code>padding</code>, <code>border</code>, <code>border-radius</code> and <code>columns</code>. Declarations on each side of a nested rule are now merged separately. An at-rule without a block, such as <code>@apply x;</code>, also separates them, since it may add declarations. An empty rule such as <code>&amp;{}</code> does not. A <code>border-image</code> or <code>all</code> declaration before a nested rule no longer prevents merging the <code>border</code> longhands after it.</p>
</li>
<li>
<p>Stop merging rules that have an invalid selector, such as <code>b: hover</code>, <code>[a b]</code>, <code>:lang(en fr)</code> or <code>a||b</code>. An invalid selector makes the whole selector list invalid, so the browser also dropped the valid rule it was merged with.</p>
</li>
<li>
<p>Only treat a dimension as the font size in the <code>font</code> shorthand when it has a length unit. An invalid value such as <code>font:bold 1s &quot;Arial Black&quot;</code> is now left unchanged.</p>
</li>
<li>
<p>Leave the <code>font</code> shorthand unchanged when it contains <code>attr()</code>, <code>if()</code>, <code>inherit()</code> or a custom function such as <code>--name()</code>, as already done for <code>var()</code> and <code>env()</code>. Their result is only known when the browser computes the value.</p>
</li>
<li>
<p>Remove a zero color stop position only when it has the right type for the gradient. <code>conic-gradient()</code> now drops <code>0deg</code> and keeps an invalid <code>0px</code>, while linear and radial gradients still drop <code>0px</code>. <code>-webkit-linear-gradient()</code> keeps <code>to bottom</code> and other <code>to</code> directions as written, since the prefixed syntax measures angles differently.</p>
</li>
<li>
<p>Stop turning a comment inside a selector into a descendant combinator. A comment is not whitespace, so <code>.a/**/.b</code> selects elements with both classes, including inside <code>:is()</code>, and is no longer rewritten as <code>.a .b</code>. Invalid selectors such as <code>div/**/span</code> are left as written instead of becoming valid.</p>
</li>
<li>
<p>Leave rules with an invalid selector unchanged, including an ID selector that starts with a digit, such as <code>#1a</code>, and a combinator after a pseudo-element, such as <code>a::before b</code>.</p>
</li>
<li>
<p>Shorten <code>top center</code> and <code>bottom center</code> to <code>top</code> and <code>bottom</code>, instead of <code>0</code> and <code>100%</code>, which the browser reads as horizontal positions. <code>center top</code> and <code>center bottom</code> are now shortened the same way.</p>
<p>Leave a position unchanged when it cannot be safely rewritten:</p>
<ul>
<li>in a <code>background</code> layer where another value splits the position, as in <code>left no-repeat center</code>, which is invalid;</li>
<li>when it contains a function such as <code>attr()</code>, <code>if()</code> or a custom <code>--function()</code>, which may return a keyword, as <code>var()</code> already did;</li>
<li>when an invalid three-value position contains a math function, such as <code>left abs(1px) top</code>, as <code>calc()</code> already did.</li>
</ul>
</li>
<li>
<p>Keep strings unchanged when removing a line continuation (a backslash before a newline) right after an escape. In <code>&quot;\31</code> followed by a line continuation and <code>2&quot;</code>, joining the lines would turn <code>\31</code> into <code>\312</code>, so the result is now <code>&quot;\31 2&quot;</code>.</p>
<p>Leave <code>@charset</code> unchanged. Browsers only recognize it with double quotes, so rewriting single quotes would make an ignored <code>@charset</code> take effect.</p>
</li>
<li>
<p>Update <code>postcss-calc</code> to 11.2.2. postcss-calc() now attempts to preserve fractions if the replacement would lose too much precision</p>
</li>
</ul>
