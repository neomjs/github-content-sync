<p><strong>Full Changelog</strong>: <a href="[QUARANTINED_URL: github.com]">[QUARANTINED_URL: github.com]</a></p>
<h2>v9.1.0</h2>
<h2>What's Changed</h2>
<h3>New Features</h3>
<ul>
<li>Merge corner <code>border-*-radius</code> longhands into <code>border-radius</code> shorthands. Four complete corner declarations in the same importance lane now collapse into one shorthand, with horizontal and vertical axes minified independently and separated by a slash when distinct.</li>
</ul>
<h3>Bug fixes and Improvements</h3>
<ul>
<li>
<p>Merge margin, padding, border, border-radius, columns, and border-spacing declarations inside at-rule containers such as <code>@page</code>, <code>@position-try</code>, and nested at-rules. Fold identical horizontal and vertical <code>border-spacing</code> components to a single value. Recognize <code>columns</code> shorthands combining a count and a math function in either order, and preserve invalid declarations as written: border shorthands with multiple styles and <code>columns</code> values combining CSS-wide keywords with widths or counts no longer discard preceding valid longhands.</p>
</li>
<li>
<p>Preserve percentage units in registered custom-property initial values with composite syntax, ranges, groups, and multipliers, and avoid clamping numeric operands nested inside alpha-value functions.</p>
</li>
<li>
<p>Restrict color minification to CSS properties that accept <code>&lt;color&gt;</code> and custom properties, preserving custom identifiers in properties like <code>animation-name</code>, <code>grid-area</code>, and <code>counter-reset</code>. Add support for <code>hwb()</code> color values and minification inside <code>color-mix()</code>, <code>light-dark()</code>, and <code>var()</code> fallbacks, while preserving relative color syntax, math functions, and token boundary separators.</p>
</li>
<li>
<p>Preserve zero percentage units in rgb(), rgba(), and modern CSS Color 4 functions to avoid invalid syntax, respect disabled time conversions for 0ms, clamps percentage opacity values adhering to CSS Color 4 alpha semantics, and improve compatibility with uppercase at-rules and vendor-prefixed keyframes.</p>
</li>
<li>
<p>Preserves zero length in <code>columns</code> shorthands and zero units inside <code>@property</code> with <code>&lt;angle-percentage&gt;</code> syntax, retaining keyframe percentage units under nested rules. Symmetrically rounds negative numbers when precision is configured, converts between metric units (<code>mm</code>, <code>cm</code>, <code>q</code>), preserves zero percentages on SVG stroke properties to retain transition interpolation, and caches Browserslist lookups across runs. Also preserves units inside CSS Fonts 5 override descriptors, <code>anchor()</code> functions, <code>flex-basis</code>, and IE-targeted sizing properties.</p>
</li>
<li>
<p>Remove comments more reliably and preserve the ones you keep exactly. Comments are now removed from   <code>!important</code> declaration values and comment detection respect CSS token boundaries: text inside unquoted <code>url()</code> values and behind escape sequences in strings and identifiers is no longer mistaken for a comment. Kept comments are emitted byte-for-byte, including an unclosed comment at the end of a value, and whitespace inside kept comments is left untouched. Removal state is scoped to each document, so a shared processor no longer carries <code>removeAllButFirst</code> first-comment state between runs, and the <code>remove</code> callback runs once per comment occurrence. A non-function <code>remove</code> option now fails with a <code>TypeError</code>.</p>
</li>
<li>
<p>Improve conformance for modern CSS math functions, grid-line values, and case-sensitive attribute selector modifiers while preserving ambiguous or invalid declarations. The affected transforms now use bounded, linear scans for these forms.</p>
</li>
<li>
<p>Value transforms now read the CSS Values 4 math function names from one <code>mathFunctions</code> table in <code>cssnano-utils</code>, so unit retention, box and shorthand merging, parameter and whitespace handling, and time classification agree on which functions count as math functions. Serialized output is unchanged.</p>
</li>
<li>
<p>Standardize output normalization for margin, padding, and physical border properties. Property names and case-insensitive keywords in generated shorthands and normalized standalone shorthand declarations are canonicalized to lowercase, while preserving author casing for unmerged longhands, custom properties, hack prefixes, and unresolved values.</p>
</li>
<li>
<p>perf: median 15% speed increase on test fixtures</p>
</li>
<li>
<p><code>postcss-normalize-url</code> now decodes quoted <code>url(...)</code> values, preserving literal backslashes and escape sequences whether quotes are stripped or kept.
Relative URLs now normalize using POSIX path semantics across all platforms, and converted <code>@namespace</code> URLs escape double quotes.</p>
</li>
<li>
<p>Join every escaped line continuation in a multiline <code>url()</code> value into one line, including <code>\r\n</code> continuations that previously left an invalid string behind. Rewriting a <code>@namespace</code> URL no longer overwrites the tokens that follow it, so trailing text is preserved and multiple URLs in one namespace declaration are each normalized.</p>
</li>
<li>
<p>Remove insignificant whitespace around custom-property names and, in standard declarations, around <code>env()</code> custom-ident arguments and around comma delimiters in <code>var()</code>, <code>env()</code>, and <code>constant()</code>. Between a custom-property name and its value, only the parser-consumed leading whitespace run is dropped; authored whitespace elsewhere in the value, such as after a preserved comment, is preserved per CSS Variables 2. Required whitespace between distinct tokens and the single whitespace token in an empty fallback remain preserved, and a preserved comment kept between a declaration name and value now survives minification, for custom properties and standard declarations alike. Comment removal in selectors and values no longer fuses the tokens the comment in-between: an attribute case-insensitivity flag or any other name-like token keeps its boundary, and math-operator spacing is restored for every function whose value productions accept <code>&lt;calc-sum&gt;</code> arguments (including <code>calc-size()</code>, <code>calc-mix()</code>, and <code>random()</code>). Values without comments are now left byte-for-byte untouched rather than re-spaced.</p>
</li>
<li>
<p>Preserve whitespace around division operators across all modern CSS math functions such as <code>min()</code>, <code>max()</code>, and <code>clamp()</code>, and trim extraneous whitespace from commas in nested calculations.</p>
</li>
</ul>
