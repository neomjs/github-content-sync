Updates `inquirer` from 14.3.0 to 14.3.1
<details>
<summary>Release notes</summary>
<p><em>Sourced from <a href="[QUARANTINED_URL: github.com]">inquirer's releases</a>.</em></p>
<blockquote>
<h2>inquirer@14.3.1</h2>
<h3>What's new</h3>
<ul>
<li><strong>Node.js 20 support is restored</strong> — the engines range accidentally dropped it in 14.3.0 (<a href="[QUARANTINED_URL: redirect.github.com]">#2449</a>, see <a href="[QUARANTINED_URL: redirect.github.com]">#2431</a>); it will be dropped properly in the next major release</li>
</ul>
<h3>Fixes in the bundled prompts</h3>
<ul>
<li><strong>input</strong>: keys typed while a validation is pending no longer leak into the answer; <code>pattern</code> validation is repeatable (a <code>g</code>-flagged regex no longer fails the second submission); keys typed during a pending validation are discarded</li>
<li><strong>number</strong>: input left empty on an optional prompt now calls <code>validate</code> with <code>undefined</code>; pending keystrokes no longer leak into the retry; only plain decimal input is accepted (<code>0x10</code>/<code>0b11</code>/<code>0o7</code> are rejected)</li>
<li><strong>password</strong>: pending keystrokes during validation no longer leak into the retry</li>
<li><strong>confirm</strong>: keyword hints show complete characters/emoji instead of broken halves; built-in y/n answers always work, even when custom keywords start with n/y</li>
<li><strong>checkbox</strong>: a number key on a disabled choice shows the disabled error instead of nothing; toggling with all/invert/number shortcuts clears a stale validation error</li>
<li><strong>rawlist</strong>: rejected input stays editable instead of being wiped; the input is only matched by exact key or a plain digit index (<code>2x</code> no longer selects choice 2); arrow-key picks keep the line editable; an explicit <code>null</code> default preselects the null choice</li>
<li><strong>expand</strong>: rejected input stays editable; expanding the help list no longer leaves a stale <code>h</code> on the line</li>
<li><strong>search</strong>: the query survives arrow navigation; the prompt stops its loading spinner when the source fails; the query is preserved while a selection is being validated</li>
<li><strong>editor</strong>: user edits are kept when a validator throws (per <code>validationFailureMode</code>); Ctrl+D during validation no longer crashes with an unhandled error</li>
<li><strong>select</strong>: only plain digit lines jump to a numbered choice (<code>2e1</code> no longer jumps to item 21)</li>
<li>The editor's validation error message is now localizable via <code>@inquirer/i18n@1.5.0</code></li>
</ul>
</blockquote>
