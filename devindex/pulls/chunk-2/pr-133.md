<summary>Release notes</summary>

<blockquote>
<h2>v8.1.1</h2>
<p>This release fixes nineteen security-relevant issues in the tokenizer, serializer, SAX parser, rewriting stream, tree adapters and tree construction, reported by outside researchers and by Anthropic, and further issues of the same kinds found while reviewing them. The issues include crashes from a few bytes of input, parse time and memory far out of proportion to the input, and serializer output that re-parses into markup the parsed tree did not contain. Everyone who runs parse5 on untrusted input should update.</p>
<p>There are no CVEs or GitHub security advisories for these issues: private vulnerability reporting on this repository is only accessible to <a href="[QUARANTINED_URL: github.com]"><code>@​inikulin</code></a>. The current maintainers cannot access it, so the reports could not be filed or published as advisories here.</p>
<h2>Security fixes</h2>
<ul>
<li><a href="[QUARANTINED_URL: github.com]"><code>9b57bf87</code></a> High: a crash from two code units. A lone low surrogate followed by another low surrogate was decoded as a pair, and <code>String.fromCodePoint</code> then threw out of every parser entry point. Only a high surrogate now starts a pair. Reported by Joshua Rogers and by Anthropic.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>98a4bb34</code></a> High: a crash, also through cheerio's <code>$.html()</code>. Serialization recursed once per DOM level, so a few KB of nesting exhausted the call stack. It now uses an explicit stack, and the output is unchanged byte for byte. Reported by SnailSploit.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>ea240155</code></a> High: quadratic parse time. The SAX parser's namespace stack was shifted from the front for every element, quadratic in the nesting. It is kept at its tail. Reported by iaohkut, José Antonio Zamudio Amaya and Ravindu Lakmina.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>fa1eb9b0</code></a> High: a crash, and quadratic time before it. Nested templates were closed recursively at EOF, and the template insertion-mode stack was shifted per template. Both are iterative now. Reported by SnailSploit and by the three reporters above.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>20591465</code></a> High: quadratic parse time. Foster parenting scanned all preceding siblings of the table for every insertion. The reference is found without scanning. Reported by iaohkut, José Antonio Zamudio Amaya and Ravindu Lakmina.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>6c705d57</code></a> High: 8,002,000 attribute records from 39 KB of input. Integration-point checks read the attribute list of every element, which the htmlparser2 adapter allocates on each call. Only <code>annotation-xml</code> needs it, and its list is now read once per element, as the HTML Standard decides by the start tag (rereading it on every pop took 7 s for 8,000 attributes and children; a script that edits <code>encoding</code> mid-parse no longer changes the verdict, stated in the commit). Reported by Anthropic; the rereads on every pop were found while reviewing this series.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>0a61bd54</code></a> High: 210 ms from 35 KB, growing quadratically. <code>adoptAttributes</code> rebuilt the recipient's name Set for an empty merge, so repeated <code>&lt;html&gt;</code> and <code>&lt;body&gt;</code> tags without attributes were quadratic. It returns early. Tags that each add an attribute rebuilt it too (816 ms for 8,000 <code>&lt;html&gt;</code> tags), so the adapter now keeps the names between merges and re-indexes when the list changed under it; a script that renames an attribute between two merges to a name the cache has never seen is the one documented difference (stated in the commit). Reported by iaohkut, José Antonio Zamudio Amaya and Ravindu Lakmina; the merges that add attributes were found while reviewing this series.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>89dceda8</code></a> High: a crash and mutation XSS. Resetting the insertion mode matched foreign elements by tag id, so an SVG <code>select</code> or <code>template</code> selected an HTML mode; a <code>TypeError</code> followed from 50 bytes, and a longer shape serialized into an <code>&lt;img onerror&gt;</code> absent from the tree. Foreign elements are skipped. Reported by Anthropic.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>f5d58d8f</code></a> High: quadratic parse time from formatting tags. Formatting tags with distinct attributes (<code>&lt;b a=1&gt;&lt;b a=2&gt;…</code>) made every insertion into the list of active formatting elements scan the list for Noah's Ark, and formatting end tags scanned and spliced it. The list is now linked and indexed by tag and by attributes, so insertion costs the tag's attributes and removal and lookup are constant. An attribute group leaves the index with its last entry, so the index does not grow with the distinct attribute sets of the input. Reported by Liyi Zhou, Ziyue Wang, Strick Sheng, Maurice Ng and Chenchen Yu (University of Sydney), and by Anthropic.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>e2901d06</code></a> High: 13–18 s from 300 KB, also through cheerio's <code>.append()</code>, <code>.html()</code> and <code>$()</code>. Moving a node's children (every <code>parseFragment</code> result out of its root, the adoption agency's furthest block) detached them one at a time from the front of the child list, quadratic in their number. The children are copied once, detached from the end and appended in order, and both bundled adapters check the last child before searching the list, as <code>insertBefore</code> already did; the adapter interface is unchanged. <code>parseFragment</code> of 100,000 <code>&lt;b&gt;&lt;/b&gt;</code>: 4.1 s → 45 ms. Reported by Anthropic.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>fcce48d0</code></a> High: the reported deep-nesting quadratic. Every search of the stack of open elements cost up to its depth per token: scope checks, list items, generic end tags, insertion-mode resets, end tags in foreign content, foster parenting and the adoption agency's up to eight passes per end tag. 391 KB of nested <code>&lt;div&gt;</code>s took 23.7 s, and 256 repetitions of <code>&lt;b&gt;</code>, 255 <code>&lt;span&gt;&lt;div&gt;</code> pairs and 33 <code>&lt;/b&gt;</code> took 17.2 s from 735 KB. Once 64 elements are open, the stack indexes them by tag and counts the special elements and scope boundaries at or below each, so every search is constant per token, and the adoption agency leaves a removed element's slot free instead of shifting the stack; the two documents take 39 ms and 104 ms. Stacks that never reach 64 elements are scanned as before; a stack that does keeps the index for the rest of the parse and pays for it on every push and pop (300 nested tables parse about 20% slower). Reported by iaohkut, José Antonio Zamudio Amaya and Ravindu Lakmina; the adoption-agency and foreign-content cases were found while reviewing this series.</li>
<li><a href="[QUARANTINED_URL: redirect.github.com]">#1922</a> High: quadratic tokenizer time from a tag with many attributes. The duplicate-attribute check compared every new name with every earlier one; tags with more than 64 attributes now use a set. Reported by SameerJS6 in <a href="[QUARANTINED_URL: redirect.github.com]">#1901</a>.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>53d1261c</code></a> Medium: a script-stripping rewriter misses a script. When the parsed chunk was dropped between the two code points of a character reference, input after the reference was skipped: no tag events for it, while <code>RewritingStream</code> forwarded its raw bytes. The position is recomputed from the current buffer. Reported by Anthropic.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>4bffbe64</code></a> Medium: a filter bypass once the output is embedded in a page. At EOF inside a tag, the pending text's source range covered the dropped tag, so <code>RewritingStream</code> forwarded an unfinished tag that no listener saw. The text now ends where the tag starts. Reported by Anthropic.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>e02abba4</code></a> Medium: XSS through the rewriter. <code>RewritingStream#emitText</code> chose raw output from <code>lastStartTagName</code>, so text after <code>&lt;/script&gt;</code>, before <code>&lt;script&gt;</code> or in an SVG <code>&lt;style&gt;</code> was written unescaped and entity-encoded input became live markup. It now tracks <code>inRawText</code> from the tokenizer state. Reported by Joshua Rogers and by Anthropic.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>ac2f60d5</code></a> Medium: memory proportional to an uncapped stream. The streaming parsers kept a whole run of text as one pending token until a tag; memory grew with the stream. Completed text is flushed when a parsed chunk is dropped, with exact source ranges, in every state without an unfinished token, so a stream whose every chunk ends inside a CDATA <code>]]</code>, a named reference or an escaped-script <code>&lt;</code> is flushed too and only the pending construct stays buffered. Reported by Liyi Zhou, Ziyue Wang, Strick Sheng, Maurice Ng and Chenchen Yu (University of Sydney); the chunks ending in a delimiter or reference were found while reviewing this series.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>fd22254c</code></a> Medium: mutation XSS. The adoption agency acted on an older formatting element behind a scope boundary and moved the boundary element; the serialized tree re-parsed into an <code>&lt;img&gt;</code> absent from the input. It runs on the identified element. Reported by Anthropic.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>61676e2b</code></a> Medium, for consumers that inspect parse5's tree and forward the original bytes. Implied end tags popped foreign elements, so a <code>&lt;/form&gt;</code> closed an SVG <code>rp</code> and parse5 read raw text where browsers see an <code>&lt;img onerror&gt;</code>. HTML elements only. Reported by Anthropic.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>b9093da5</code></a> Medium, same consumer pattern. Foreign end tags were matched with <code>toLowerCase</code>, which folds U+212A KELVIN SIGN to <code>k</code>; the wrong ancestors stayed open and parse5 hid an <code>&lt;img&gt;</code> browsers render. Matching is ASCII case-insensitive. Reported by Anthropic.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>69f69313</code></a> Medium, same consumer pattern. In a fragment, an unmatched foreign end tag was dropped at the root instead of being processed with the HTML rules, so a <code>&lt;/form&gt;</code> did not reset the form pointer and a later <code>&lt;form action=javascript:…&gt;</code> was missing from the fragment. Reported by Anthropic.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>d5f4f129</code></a> Medium, same consumer pattern. A fragment context's SVG <code>form</code> ancestor was taken as the form element pointer, suppressing the fragment's HTML form. Only an HTML <code>form</code> qualifies. Found while reviewing this series.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>48aba8cb</code></a> Low: a self-closing <code>&lt;svg/&gt;</code> or <code>&lt;math/&gt;</code> left its namespace frame in the SAX simulator, so a stream of such roots grew the frame stack without bound and following content was tokenized as foreign; integration-point end tags now close only the frame their element opened. Frames also follow tree construction for <code>svg</code> and <code>math</code> inside the other foreign namespace, <code>mglyph</code> and <code>malignmark</code> in a MathML text integration point, and <code>&lt;/p&gt;</code> and <code>&lt;/br&gt;</code>. Found while reviewing this series.</li>
<li><a href="[QUARANTINED_URL: github.com]"><code>f52fa37f</code></a> Documentation. <code>SECURITY.md</code> now says that the current maintainers cannot see reports filed through GitHub's private vulnerability reporting, and that Tidelift is the only channel for reports.</li>
</ul>
