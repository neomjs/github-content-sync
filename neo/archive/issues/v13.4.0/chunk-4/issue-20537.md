# Show a stateful UI debugging case through the Neural Link

## Context

The existing [runtime-possession overview](https://neomjs.com/news/blog/ai-agents-runtime-possession) already covers the Neural Link's broad interface. This follow-up serves a narrower reader: an application developer who needs to diagnose a reactive state transition and check the rendered result. It is a worked case, not another tool catalogue.

## The Problem

The Clock repair in PR `#20440` gives a concrete lesson: construction with a nonnumeric size did not expose the stale dimensions that a numeric-to-nonnumeric transition did. The original component-tier probe used direct worker evaluation, not Neural Link. A new article must not rewrite that discovery history or call empty inline dimensions proof of a responsive 50% clock.

## The Architectural Reality

`src/component/Clock.mjs#afterSetSize` clears dimensions with null overrides. `src/component/Base.mjs#beforeGetWrapperStyle` and `updateStyle` explain how deleting keys can expose retained wrapper values. Flex layout can retain the initial dimensions; the public Clock example's base layout can retain the latest ones.

A November 7 author reproduction used the existing `examples/component/clock/`, an explicitly connected App Worker, native semantic discovery/property reads/source reads/setters, and independent DOM reads. With the old Clock blob `372f3406aa5a1c2eba8f4cd4e896206bb44ede81`, its sequence retained 300px after a 500 → 300 → nonnumeric transition; changing only the two deletes to null assignments cleared both inline dimensions. The original fixture's 500px fallback remains a separately attributed observation. This new walkthrough is a reproduction of an existing source repair, not live hot-patching or original NL diagnosis.

## The Fix

Write `learn/blog/debugging-ui-state-with-neural-link.md` and its entry in `apps/portal/resources/data/blog.json`. Lead with the stateful failure and explain the inherited style owner, then show the actual inspect → change → rendered-result comparison. Include a diagram, the exact source/control boundaries, and a public-readable action/result summary. Link the existing overview and source repair rather than copying their broad claims. No runtime code or API changes.
