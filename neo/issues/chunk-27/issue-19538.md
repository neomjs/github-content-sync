# Retire the dormant pointer-path vessel conversion and park machinery

## Context

#19533 (operator decision, 2026-10-10) gives a pointer drag one rule for every window of the group. Inside a window it is that window's tab-header proxy; outside every window it is a vessel; leaving a window opens a fresh vessel (docking design record §2.8.6, amended there). `TabSortZone#resolveRemoteDragTransition` now hands a claimed frame straight to the claiming window, so the pointer-path conversion sensor, its park and its re-show are no longer reached. #19533 changed behaviour and kept that code dormant so the release PR stayed reviewable; this ticket deletes it.

## The Problem

Dormant code that still reads as live costs every reader. The conversion events, host handlers and park effects look wired, unit specs keep exercising them, and the size-calibrated park matrix in `WorkstationHumanPopupOverlapNL` is skipped rather than gone.

## The Architectural Reality

Unreached since #19533. Each item is verified with a caller census before deleting. The native title-bar drop keeps its own park through `nativeVesselParkHandlers` and must survive.

- `src/dashboard/dock/interaction/TabSortZone.mjs`:
  - `getVesselConversionSensor` with `onConvertIn` / `onConvertOut`;
  - the replay scheduling;
  - the `conversionActive` branches in `processDragEnd` / `onDragCancel` (`dockVesselConversionTerminal`, `dockVesselConversionRetired`).
- `src/dashboard/dock/window/VesselConversion.mjs` and its unit spec.
- `src/dashboard/dock/projection/LayoutAdapter.mjs`: the `dockVesselConversion*` listeners and options.
- `src/manager/DragCoordinator.mjs`: the transition protocol's `retain`, `preview`, `commitEligible` and `replayAfterTransition` branches. The claim resolver never returns them.
- Hosts:
  - `apps/workstation/view/VesselWorkspace.mjs`: `onDockVesselConversion*`, the pointer `vesselParkHandlers`, `resolveVesselConversionSourceRect`, and the pointer branch of `parkTearOutVessel`;
  - `examples/dashboard/crossWindow/DemoBWorkspace.mjs`: the same family.
- `src/dashboard/dock/window/NativeVesselTransaction.mjs`:
  - the pointer park effect, including the corner placement `resolveClearPark`;
  - the pointer dispose and the extent restore;
  - the re-show's `DragDrop` addon calls, which only a parked pointer drag could answer.
- `src/dashboard/dock/window/VesselPark.mjs`: the pointer convert-out (`onConversionOut`, `pendingOut`). The native drop never re-shows mid-gesture.
- `test/playwright/e2e/workstation/WorkstationHumanPopupOverlapNL.spec.mjs`: the skipped size matrix (`runOverlap`, `MATRIX_CELLS`, `positionTargetForPartialOverlap`) and the helpers only it uses.
- The pointer-conversion arms of `DockTabSortZone.spec`, `DockVesselPark.spec`, `DockNativeVesselTransaction.spec`, `DockLayoutAdapter.spec`, `DragCoordinator.spec`, `Workspace.spec` and `DemoBWorkspace.spec`.

## The Fix

Delete the pointer-path conversion and park, and keep every native title-bar seam: `VesselPark` serves that path alone. The docs that describe the pointer park as live move with it: the docking guides and ADR 0029's resolver contract row. Net negative lines; no behaviour change.

The main-thread `DragDrop` addon's park surface (`parkWindowDrag`, park recovery, orphan recovery) loses its last caller here and is deleted by #19541.

## Acceptance Criteria

- [ ] No `dockVesselConversion*` event, handler or option remains; `VesselConversion` is gone.
- [ ] The native title-bar drop keeps parking behind its target after release; its unit and e2e arms are green.
- [ ] The HumanPopupOverlap size matrix and its exclusive helpers are deleted; the foreign-popup arms stay green.
- [ ] The unit suite and the Workstation and dashboard e2e folders are green at their `dev` baseline.

## Out of Scope

Any behaviour change; the native title-bar path; the film; the main-thread addon (#19541).
