# Retire the dormant pointer-path vessel conversion and park machinery

## Context

#19533 (operator decision, 2026-10-10) gives a pointer drag one rule for every window of the group: inside a window it is that window's tab-header proxy; outside every window it is a vessel; leaving a window opens a fresh vessel (docking design record §2.8.6, amended there). `TabSortZone#resolveRemoteDragTransition` now hands a claimed frame straight to the claiming window, so the pointer-path conversion sensor, its park and its re-show are no longer reached. #19533 changed behaviour and kept that code dormant to keep the release PR reviewable; this ticket deletes it.

## The Problem

Dormant code that still reads as live costs every reader: the conversion events, host handlers and park effects look wired, unit specs keep exercising them, and the size-calibrated park matrix in `WorkstationHumanPopupOverlapNL` is skipped rather than gone.

## The Architectural Reality

Unreached since #19533 (verify each with a caller census before deleting; the native title-bar drop keeps its own park through `nativeVesselParkHandlers` and must survive):
- `src/dashboard/dock/interaction/TabSortZone.mjs`: `getVesselConversionSensor` with `onConvertIn` / `onConvertOut`, the replay scheduling, and the `conversionActive` branches in `processDragEnd` / `onDragCancel` (`dockVesselConversionTerminal`, `dockVesselConversionRetired`).
- `src/dashboard/dock/window/VesselConversion.mjs` and its unit spec.
- `src/dashboard/dock/projection/LayoutAdapter.mjs`: the `dockVesselConversion*` listeners and options.
- Hosts: `apps/workstation/view/VesselWorkspace.mjs` (`onDockVesselConversion*`, the pointer `vesselParkHandlers`, `resolveVesselConversionSourceRect`) and `examples/dashboard/crossWindow/DemoBWorkspace.mjs` (the same family).
- `src/dashboard/dock/window/NativeVesselTransaction.mjs`: the pointer park effect, including the corner placement `resolveClearPark`.
- `test/playwright/e2e/workstation/WorkstationHumanPopupOverlapNL.spec.mjs`: the skipped size matrix (`runOverlap`, `MATRIX_CELLS`, `positionTargetForPartialOverlap`) and the helpers only it uses.
- The pointer-conversion arms of `DockTabSortZone.spec`, `DockVesselPark.spec`, `DockNativeVesselTransaction.spec` and `DockLayoutAdapter.spec`.

## The Fix

Delete the pointer-path conversion and park, keep every native title-bar seam, and leave `VesselPark` serving that path alone (its header was already rescoped by #19533). Net negative lines; no behaviour change.

## Acceptance Criteria

- [ ] No `dockVesselConversion*` event, handler or option remains; `VesselConversion` is gone.
- [ ] The native title-bar drop keeps parking behind its target after release (its unit and e2e arms unchanged and green).
- [ ] The HumanPopupOverlap size matrix and its exclusive helpers are deleted; the foreign-popup arms stay green.
- [ ] Unit suite and the Workstation and dashboard e2e folders green at their `dev` baseline.

## Out of Scope

Any behaviour change; the native title-bar path; the film.
