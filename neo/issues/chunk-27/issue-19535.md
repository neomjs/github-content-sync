# A popped-out pane's closing window reads as a failed repaint render

## Context

Since #19534 merged (`b4065ca961`), `WorkstationHeaderStatePopOutNL` fails on `dev` (`6acb770a79`, re-run 2026-10-10 00:3xZ). The arm is "the popped-out pane resolves the workspace provider and rea…". Its console-error assertion reads one extra line:

```
App Worker: PopupWorkspace: the landed pane's repaint render failed Worker port disconnected before reply: neo-port-2
```

A full Workstation and dashboard run on that base also failed two more arms with the same line. Both depend on timing:
- `WorkstationPopOutPaneIdentityNL` "component, provider, store and descendant identities survive pop-out AND …";
- `WorkstationReclaimEmbodimentNL` "control: a vessel that connected and then closed takes the release route …". This one passed alone on `dev`.

## The Problem

`PopupWorkspace#repaintLandedPane` awaits `pane.promiseUpdate()`. #19534's RA-1 fix made the catch report every rejection on a surviving pane as a failed render. A popup window that closes while that render is in flight also rejects the promise. In that case the message is `NEO_DEAD_PORT` with "Worker port disconnected before reply". The pane survives, because a window disconnect is a render-target signal, not a destruction. So the catch logs an expected teardown as a defect.

## The Architectural Reality

- `apps/workstation/view/PopupWorkspace.mjs` `repaintLandedPane`: `catch (error) { if (pane.isDestroyed) return; console.error(...) }`.
- `src/worker/Base.mjs` `isDeparture(reason, windowId)` is the engine's predicate for exactly this. It is true when `code === 'NEO_DEAD_PORT'` and the window departed recently. `src/component/Sparkline.mjs` uses it the same way: `Neo.currentWorker.isDeparture(error, windowId) || console.error(...)`.

## The Fix

Report only a rejection that is not the window's departure:

```js
Neo.currentWorker.isDeparture(error) || console.error('PopupWorkspace: the landed pane\'s repaint render failed', error)
```

The layer still comes off afterwards, as it does for any surviving pane.

## Acceptance Criteria

- [ ] A unit arm: a repaint whose render rejects as a departure reports nothing and still removes the layer. The existing failed-render arm (a live failure is reported) and the destroyed-pane arm stay green.
- [ ] `WorkstationHeaderStatePopOutNL` "the popped-out pane resolves the workspace provider…" is green on the fix, alone and in the full Workstation folder run.
- [ ] `WorkstationPopOutPaneIdentityNL` "component, provider, store and descendant identities…" and `WorkstationReclaimEmbodimentNL` "control: a vessel that connected and then closed…" show no repaint line in their console reads.
