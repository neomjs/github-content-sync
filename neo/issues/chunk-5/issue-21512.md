# An un-sized ComboBox or Country field collapses its input in align-start containers

Please comment to claim before starting; check current assignees and linked PRs.

## Context

Surfaced during `#21178` (`examples/grid/nestedRecordFields/EditUserDialog.mjs`, which instructs: *"If the narrow Country field is an engine defect, file it and work around it here"*). Inside a default `Neo.container.Base` or `Neo.dialog.Base` `bodyContainer` (`layout: {ntype: 'vbox', align: 'start'}`) where fields carry no explicit `width`, `Neo.form.field.Text` and `Neo.form.field.Date` render a normal-width input (~`150 px`), while `Neo.form.field.ComboBox` and subclasses such as `Neo.form.field.Country` collapse their input box to ~`30–42 px` so the value text (`"Germany"`) overlaps the clear and picker triggers.

## The Problem

`Neo.container.Base` defaults `layout` to `{ntype: 'vbox', align: 'start'}` (and `Neo.container.Panel#createItems` creates `bodyContainer` as a plain `container` inheriting `align: 'start'`). Under `align: 'start'`, flex items size to their intrinsic `max-content` width unless `width` or `align: 'stretch'` is supplied:
- Plain `Text` / `Picker` / `Date` fields keep `<input class="neo-textfield-input">` in normal flow (`min-width: 50px; width: 100%` over `<input>`'s default `size="20"` intrinsic width), so `.neo-input-wrapper` (`flex: 1 1 1px`) resolves to ~`150 px` plus triggers.
- `ComboBox` wraps the input and typeahead overlay in `.neo-input-field-wrapper` and takes both `<input>` elements out of flow (`position: absolute; inset: 0`), leaving `.neo-input-field-wrapper` with zero intrinsic content width and only `flex: 1 1 30px` (`resources/css/src/form/field/ComboBox.css:2-9`). Without container stretch or an explicit `width`, the entire input region shrinks to its `30 px` flex-basis.

## The Architectural Reality

- `resources/css/src/form/field/ComboBox.css:2-9`:
  ```css
  .neo-combobox {
      .neo-input-field-wrapper {
          flex    : 1 1 30px;
          position: relative;

          .neo-textfield-input, .neo-typeahead-input {
              position : absolute;
              inset    : 0;
          }
  ```
- `resources/css/src/form/field/Text.css:403-410`: `.neo-input-wrapper { display: flex; flex: 1 1 1px; }`
- `src/container/Panel.mjs:161-169`: `bodyContainer` is created as `{ntype: 'container', flex: 1, items, itemDefaults: me.itemDefaults, reference: 'bodyContainer', ...containerConfig}` (inheriting `align: 'start'`).
- Design authority: `src/form/field/ComboBox.mjs:38` (`@extends Neo.form.field.Picker`) — a `ComboBox` without an explicit `width` in the same `vbox` container as `TextField` / `DateField` is expected to have a comparable readable default input width rather than collapsing onto its triggers.

## The Fix

1. Give `.neo-combobox .neo-input-field-wrapper` in `resources/css/src/form/field/ComboBox.css` a sensible intrinsic/default basis or `min-width` (matching an un-sized `Neo.form.field.Text` input in `align: 'start'` containers while still allowing explicit `width` / narrow `flex` containers to shrink cleanly when constrained, e.g. via `flex-basis` on `.neo-input-field-wrapper` + `flex: 1 1 auto` on `.neo-combobox > .neo-input-wrapper` or CSS variable `--combobox-input-min-width`), and rebuild themes (`npm run build-themes -- -n -e dev -t all`).
2. Add a browser unit/component spec under `test/playwright/` mounting a `TextField` and a `ComboBox` / `Country` field inside a default `Neo.container.Base` (`align: 'start'`, no explicit `width`) and asserting that the `ComboBox` input wrapper renders at a readable width (`>= 120 px`) without trigger overlap, while an explicit narrow `width` (e.g. `120px`) still shrinks cleanly without overflow.

## Acceptance Criteria

- [ ] AC-1: Inside a default `Neo.container.Base` (`layout: {ntype: 'vbox', align: 'start'}`, no explicit `width` on the container or field), `Neo.form.field.ComboBox` and `Neo.form.field.Country` render an input area at least `120 px` wide with zero overlap between text and triggers.
- [ ] AC-2: When an explicit `width` or `align: 'stretch'` constrains a `ComboBox` (including grid cell editors and narrow toolbars), the field respects that width without horizontal overflow.
- [ ] AC-3: `npm run build-themes -- -n -e dev -t all` succeeds cleanly across all themes.
- [ ] AC-4: A Playwright spec reproduces the collapsed width on `dev` and passes at head.

## Out of Scope

- Changing `Neo.container.Panel`'s default `bodyContainer` alignment across all panels/dialogs.
- Renewing `examples/grid/nestedRecordFields` (handled in #21178).

## Avoided Traps

- Setting a rigid `min-width: 180px` on `.neo-combobox` itself, which would break compact toolbar/header-filter comboboxes explicitly configured with `width: 100` or `width: 120` — prefer `flex-basis` (with `flex-shrink: 1`) over an unshrinkable outer `min-width`.
