# The Web Desktop cover shows a placeholder Mail window the demo no longer has

## Context

The featured Web Desktop card in the examples section uses `devmode/webdesktop-14-0.jpg`, captured on 2026-11-16 (#21095, served by `neomjs/pages#88`). It shows the demo as it was then:
- a Mail window with the placeholder card ("Read and send email. Granted by view-mail to Alex Morgan");
- the old row launcher;
- a Videos icon;
- the old window glyphs.

Since then, #21414 (`1c768535a1`, merged today) gave every app a working view. #21364 laid the launcher out in captioned group columns, #21387 added the desktop's identity, #21378 replaced the window glyphs, and Videos left the catalog. The examples section is read as a whole on Friday 2026-11-20. Its done signal asks that each published example be "current, captioned and shown at its best".

#21414's Post-Merge Validation named #21331 for the re-take, but #21331 had already closed, so the item is unowned. This ticket owns it.

## The Problem

A visitor's first view of the demo is a stub app the demo no longer has. The card promises a desktop of working apps, and the cover contradicts it.

## The Architectural Reality

- The cover exists twice, with the same bytes:
  - the source original, `apps/portal/resources/images/examples/devmode/webdesktop-14-0.jpg`, in this repository;
  - the copy `neomjs/pages` serves, `resources_pub/website/examples/devmode/webdesktop-14-0.jpg`.
- A re-take keeps the file name, as `neomjs/pages#114` did for the Dashboard covers, so `examples.json` keeps its `image`.
- The recipe `apps/portal/resources/data/example-captures.json` (`id: webdesktop`) signs in and stops at the launcher. It cannot drag a window, so it describes the cover rather than reproducing it, as before (#21095).

Design authority: the epic #21140's done signal, "each published example current, captioned and shown at its best".

## The Fix

1. **Re-take the cover:** 1280 × 720 JPEG in the demo's neo-dark theme, signed in as Alex Morgan, with Mail open on its inbox and a message in the reading pane. Drag the window clear of the launcher's first group columns, and park the pointer off every control.
2. **Replace both copies with the same bytes:** a PR here and one in `neomjs/pages`.
3. **Update the recipe** to open Mail after sign-in, and its `state` to say so.

## Acceptance Criteria

- [ ] AC-1: the new cover shows a working Mail view and the current launcher, with no placeholder card and no Videos icon.
- [ ] AC-2: both copies have the same sha256, and the pull request names it.
- [ ] AC-3: the recipe opens Mail and its `state` describes the cover.

## Post-Merge Validation

- [ ] The deployed examples page shows the new cover (#21139 owns the deployed check).

## Out of Scope

- **The card's text:** its `feature`, `lookFor` and `scope` already describe the working desktop.
- **The cover's capture automation**, such as drag steps in `captureExamples.mjs`.
