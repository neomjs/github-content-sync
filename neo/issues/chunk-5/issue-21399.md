# A button takes a size: small, medium or large

Owned and in progress: the operator's direction of 2026-11-18, so no contributor labels.

## Context

The operator wrote this on 2026-11-18, after #21393: "buttons should have different sizes available. could be a config. apps/workstation and other demo apps already use compact styling, but the implementation feels messy. toolbar buttons definitely by default compact." #21395 makes the neo themes' default button compact and resets every toolbar to it. A button still cannot ask for a size, so consumers hand-roll one.

## The Problem

These hand-rolled sizes are on `dev`, at `ecea698bff`. The list comes from a probe over `resources/css/src/**` for rules and `--button-*` variables that size `.neo-button`. It was run again with POSIX classes, since `git grep -E` does not read `\s`.

**One-off compact sizes, migrated by this ticket:**
- **`apps/workstation`:**
  - `Workspace.css`: the workspace toolbar's `--button-height: 32px` and the tour bar's `34px`.
  - `Viewport.css`: the row action's `height: 30px`.
- **Five grid examples** (`countries`, `export`, `filtering`, `headerGroups`, `pinnedColumns`): `.neo-button {padding: 8px 12px}`, and `export` adds `height: auto`.

**Sizes that stay, each for a reason:**
- Workstation's arrangement switch, 28 px: with its border and padding the switch makes one 34 px pill.
- The Portal's doors (42 px and 36 px) and its examples build control (14 px text): the Portal keeps its design.
- `apps/route`'s header (14 px serif): a typographic skin on a classic-theme app.
- `examples/ConfigurationViewport.css`'s theme switch (44 px, `!important`): a touch target on phones.
- The desktop taskbar (40 px): its own size, which #21395 already lets win.

Each one-off picks its own number. None of them reads from the button's config, and a theme change does not reach them.

## The Architectural Reality

- `src/button/Base.css` sizes every button from `--button-height`, `--button-min-width`, `--button-padding` and `--button-text-font-size`.
- With #21395, both neo themes set the compact values on `:where(.neo-theme-neo-*)` and `:where(.neo-theme-neo-* .neo-toolbar)`. The Portal's viewport and header opt back into `--cmp-button-height` (48 px). The classic themes size a button by its content (`--button-height: initial`).
- `Neo.component.Base#ui` maps to a `neo-${ntype}-${ui}` class (`src/component/Base.mjs:1039`). A `neo-button-small` class would share that namespace.
- Prior art: Clio's cockpit-bar scaling (2026-09-25) found that re-valuing scoped variables is the consistent way to scale buttons. A size config re-values the same variables, on the button itself.
- Design authority: the operator, 2026-11-18, in session: "buttons should have different sizes available. could be a config." and "toolbar buttons definitely by default compact."

## The Fix

1. **`Neo.button.Base#size_`:** the values are `null` (the default, where the context decides: compact in a toolbar), `'small'`, `'medium'` and `'large'`. `beforeSetEnumValue` validates the value, and it maps to a `neo-button-size-<size>` class.
2. **`src/button/Base.css`:** each size class re-values the four variables from size tokens, so an explicit size wins over its context.
3. **Size tokens in every theme:**
   - The neo themes step 24, 32 and 48 px, with matching padding and text.
   - The classic themes get their own steps.
   - #21395's compact block and the Portal's opt-in read the medium and large tokens instead of repeating the values.
4. **Migration:** each hand-rolled size above moves to a `size` config, or goes where the compact default already covers it (the grid examples' padding). Each one is checked against frames.

## Acceptance Criteria

- [ ] AC-1: `size: 'small' | 'medium' | 'large'` sets the button's height, padding and text in all five themes, including inside a toolbar or the Portal. `null` keeps the context's size. A component spec measures each size in each theme.
- [ ] AC-2: `size` changes at runtime, and the class follows (unit).
- [ ] AC-3: The one-off sizes in workstation and the five grid examples are gone: each takes the default or a `size`, with frames before and after. The sizes that stay keep their reasons in The Problem.
- [ ] AC-4: The Portal and #21395's compact default do not change: the button inventory over the neo-themed examples and apps reads the same before and after.

## Out of Scope

- The button's colour and `ui`.
- A size for icon-only buttons beyond `min-width`.
- The Portal's buttons: they keep the viewport opt-in.

## Avoided Traps

- **`size` through `ui`'s `neo-button-<value>` namespace:** `ui: 'small'` would collide.
- **A default of `'medium'`:** an explicit default would override every context, so a toolbar or the Portal could no longer set the size.
- **A pixel number per consumer:** the next consumer picks another one.
