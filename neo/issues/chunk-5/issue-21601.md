# A cold-boot Reset commits the Feed to main but never renders it

## Context

#21209 (closed by PR #21264) split the cold-boot Reset test in `test/playwright/component/workstation/WorkstationBoot.spec.mjs` into two observations. Lines 262-271 poll the persisted topology until `main` lists the Feed and its window workspace is empty. Line 273 then waits 60 s for the Feed pane in the DOM. The first failure (run 44000812835, read on #21209) could not tell a slow projection from a stalled one. #21209 recorded that a stall makes AC-3, a reproducing test plus the fix, the next step.

On 2026-11-20, PR #21600's Engine Tests answered it (run 44778016222, job 136434477604, `components (3/3)`, reported by @neo-gemini-maryam):

```
Error: Reset returns the retained pane to the default arrangement
expect(locator).toBeVisible() failed
Locator: locator('.workstation-pane-feed:not(.workstation-placeholder)').first()
Timeout: 60000ms
Error: element(s) not found
  > 273 |                 .toBeVisible({timeout: 60000})
```

- **Observed:** line 271 passed. The persisted topology reads `{main: true, vessel: []}`, so Reset committed the Feed into `workstation-main` and emptied `workstation-vessel:feed`.
- **Observed:** the Feed pane never appeared within 60 s, and the test's 150 s budget did not cut the wait (`223 passed, 1 failed`).
- **Observed:** #21600's head (`d3fd00aae9`) contains #21582 (merged 2026-11-20 15:21Z), which parks commits on a headless DockWorkspace until it mounts. The stall happens with that change in place. Whether #21582 changed its shape is not known, because the Nov 17 run predates it.
- **Not known:** where the projection stops. It is seen on hosted CI only and is not yet reproduced locally.

## The Problem

A cold boot that retains a saved window workspace builds that workspace headless (no window, not mounted). Reset then moves the Feed back into the main workspace. The document commit lands, but the main workspace never shows the pane. Inferred from the test, not yet seen by hand: a user who resets after reopening the Workstation loses the Feed until a reload. The component test fails intermittently on hosted CI and reds unrelated PRs.

## The Architectural Reality

- `apps/workstation/view/Workspace.mjs:240` `resetTopology(name)` commits the default topology: main holds the Feed, and the window workspace list is empty.
- At cold boot the Feed's pane lives in the retained `PopupWorkspace` `workstation-vessel:feed`. It is created headless by `apps/workstation/view/VesselWorkspace.mjs:253` (`createPopupWorkspace(..., {committed: true, windowId: null})`) and extends `Neo.dashboard.dock.Workspace` without a `dockHostReference`.
- `src/dashboard/dock/Workspace.mjs#refreshDockWorkspace` parks a headless host's projection in `departedProjection` until `afterSetMounted` replays it (#21582). Before #21582 the same call waited in `promiseUpdate()`. The vessel workspace never mounts after Reset empties it.
- **Hypothesis, needs V-B-A before any fix:** the main workspace's projection waits on the vessel workspace to release the Feed pane, and that release sits in a parked (or, before #21582, hanging) projection of a workspace that will never mount.

Design authority: n/a, a defect excuse applies (the fenced error and failing spec above). Reset's intended outcome is the spec's own assertion, "Reset returns the retained pane to the default arrangement".

## The Fix

1. Reproduce it deterministically: a cold boot with a retained window workspace, then Reset, with the vessel workspace's projection held open or parked. Use CPU throttling locally if the hold alone does not trigger it. This is #21209's AC-3 test.
2. Trace where the Feed pane stops between `workstation-vessel:feed` and `workstation-main`, and fix it at the owner. That is likely the transfer out of a headless workspace, not the test's waits.

## Acceptance Criteria

- [ ] A test reproduces the stall on `dev`: after a cold boot that retains a window workspace, Reset commits the Feed into main, and the Feed pane is absent from the DOM.
- [ ] With the fix, that test renders the Feed, and `WorkstationBoot.spec.mjs` "a cold boot retains the saved workspace and Reset brings its pane back" passes on three consecutive hosted `components` reruns.

## Out of Scope

- #21209's budget and fresh-context changes (merged in PR #21264).
- Changing the test's waits. They already separate the commit from the render.

So this picture is exactly what the page shows when no later refresh lands. Replays also share the refresh chain and stand down on a newer `scheduledProjection` (`:2918`).

What remains is that Reset's projection never landed, by one of two routes:
- **Starved:** it waits behind an await in the cold-hydrate cycle that never settles (`host.promiseUpdate()` at `src/dashboard/dock/Workspace.mjs:2695`, `await played` at `apps/workstation/view/VesselWorkspace.mjs:1046`). Every later projection chains on the same tail, so such a hang would also freeze every later layout change on that page.
- **Failed silently:** `Commit.complete` turns a projection rejection into a receipt (`src/manager/transaction/Commit.mjs:210`), and `resetTopology` swallows `refreshPromise` rejections (`apps/workstation/view/Workspace.mjs:306-309`).

Local runs don't reproduce it (105/105 in CI order, 10/10 at 4× CPU, 3/3 with the hydrate refresh held across the click). Next: make the next CI failure name its cause, from the timing of main's projection cycle and any "Dock projection failed" or "vdom update parked" output.
