# build: add shared non-TTY inquirer guard across buildScripts before file writes

## Context & Problem

On `2026-11-19`, running `npm run build-themes -- -f` (`node ./buildScripts/build/themes.mjs -f` without `-t all -e dev`) in a background non-TTY shell blocked indefinitely on an interactive `inquirer` prompt (`task-1459`, `03:00:53Z → 09:53:09Z`), pinning Seat 1 out of `CASCADE_RUN_STATUS_IDLE` for `6h 52m` and holding normal fleet wake delivery.

`buildScripts/create/theme.mjs` (lines `152–185`) already establishes the repo precedent: checking `!process.stdin.isTTY` when required answers are missing and throwing `Pass --name and --base with --noquestions for unattended use.` before mutating files. Eight other scripts under `buildScripts/` still prompt `inquirer` directly on non-TTY stdin and hang indefinitely when required CLI flags are omitted.

## The Architectural Reality

- `buildScripts/build/all.mjs`, `buildScripts/build/themes.mjs`, `buildScripts/create/addConfig.mjs`, `buildScripts/create/app.mjs`, `buildScripts/create/appMinimal.mjs`, `buildScripts/create/class.mjs`, `buildScripts/create/component.mjs`, and `buildScripts/webpack/buildThreads.mjs` call interactive `inquirer` prompts when flags are omitted without checking `process.stdin.isTTY`.
- Because `watch-themes` and similar long-running watchers are inherently interactive/persistent, documentation must restrict them to supervised dev shells rather than un-daemonized agent tasks.
- Extracting a single shared helper in `buildScripts/util/` eliminates duplicating `!process.stdin.isTTY` guards across 8 files (`Accretion Defense`).

## Proposed Implementation Prescription

1. Create one shared helper module under `buildScripts/util/` (extending/lifting the `buildScripts/create/theme.mjs` pattern) that takes unresolved prompt specifications plus the exact unattended invocation hint and, when `!process.stdin.isTTY` (or non-interactive stdin) and required questions remain unanswered, throws/fails **before any file write or directory creation**.
2. Wire the shared helper into all 8 scripts in `buildscripts-noninteractive-inquirer` (and adopt it in `buildScripts/create/theme.mjs` if strictly cleaner without altering existing CLI behavior/error compatibility).
3. Include clear error output showing the exact unattended command (for example, `npm run build-themes -- -n -e dev -t all` for `themes.mjs`).
4. Audit sibling downstream packages (`neomjs/create-app` `tasks/createPackageJson.mjs` and `neo-cc` `buildScripts/create/class.mjs`) in a consumer census section on the PR and file follow-up issues if they still expose unguarded non-TTY `inquirer` prompts.
5. Add **one release-note bullet** documenting the published non-TTY fail-fast behavior across `buildScripts`.

## Acceptance Criteria

- [ ] One shared non-TTY pre-prompt guard exists under `buildScripts/util/` (lifting `buildScripts/create/theme.mjs`'s `!process.stdin.isTTY` pattern).
- [ ] All 8 scripts in `buildscripts-noninteractive-inquirer` fail before any filesystem write when required flags are omitted on non-TTY stdin, printing the exact unattended invocation flags.
- [ ] Interactive TTY invocations and non-TTY invocations supplying all required CLI flags (`-n` / explicit args) continue working unchanged.
- [ ] `watch-themes` / infinite watcher scripts remain clearly scoped to supervised interactive dev shells in script help/docs.
- [ ] Consumer census completed for `neomjs/create-app` (`tasks/createPackageJson.mjs`) and `neo-cc` (`buildScripts/create/class.mjs`), with follow-up tickets filed if uncovered.
- [ ] PR includes one release-note line covering the published non-TTY fail-fast safeguard.
- [ ] Unit tests verify fail-before-write behavior on non-TTY stdin vs. success when required flags are supplied.

## Avoided Traps

- Do not hang waiting on stdin EOF when `process.stdin.isTTY` is `undefined`/`false` — reject synchronously or throw before invoking `inquirer.prompt`.
- Do not copy-paste 8 separate `if (!process.stdin.isTTY)` blocks across buildScripts; share one helper in `buildScripts/util/`.
- Do not perform partial directory creation (`mkdir`) or `writeFile` before running the shared non-TTY check.
