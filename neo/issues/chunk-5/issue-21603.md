## Problem and design authority

A floating AppWindow has one task and no source layout slot for dock staging. The [measured counterexample](https://github.com/neomjs/neo/discussions/21204#discussioncomment-19780042) clears the return arm when the first popup rectangle changes size. A user can move straight back to 100% visible without recovering the window. The operator’s intended gesture and Grace’s OQ-1 disposition are the design authority.

## Experiment

Use the existing source drag sensor, Main popup admission and OS drag transport, with desktop-owned handling for the floating window. Keep the gesture and the application instance identifiable across the transition. Exercise the option on an isolated branch with a real shared-worker desktop and child browsing context. Compare the unchanged one-window path and a refused popup. The scope is proof of this transition; the larger design, a shipped desktop-wide popup contract, and a change of default for unrelated draggable components are separate decisions.

- [x] A held pointer crossing more than halfway outside the workspace opens a popup that acts as the drag proxy. Its first geometry update alone cannot close it.
- [x] Moving straight back before pointer release restores the application exactly once. The same window, task and application data remain usable.
- [x] A release outside leaves the application in the popup. A denied or superseded acquisition cannot strand a window, steal a later gesture or duplicate a task.
- [x] Record the exact source, headless behavioral evidence and outstanding native-platform witness. OS focus, popup-blocker activation expiry and physical window positioning need the named human witness in D#21204.

## Stale registration during a held drag

On the [revised proof branch](https://github.com/neomjs/neo/commit/5fbf6254023509961c198a67037600819850bec9), an old `setConfigs` message can supply the missing zone for a recreated drag root. If another zone already owns that root, its registration wins. The late message leaves the current pointer offset, resize descriptor, and visible resize preview intact.

The two regression cases failed on `2a7c3ea86f` because resolving the recreated root returned `null`. I also tried forwarding the full stale message. The descriptor case registered a retired target, the explicit-clear case cancelled the active resize, and a reused root lost its new owner. The final change passed all three cases, the 118 focused desktop/Main drag unit tests, and the 11 headless Chromium desktop and Web Desktop tests.

The remaining release observation requires a physical mouse hold longer than five seconds with default popup blocking. The [reproduction steps](https://github.com/neomjs/neo/issues/21603#issuecomment-7046596397) still apply. This revision is ready for Maryam and Ada’s review of [AC 5](https://github.com/neomjs/neo/discussions/21204#discussioncomment-19783573).

## AC 5 Verification at [`5fbf625402`](https://github.com/neomjs/neo/commit/5fbf6254023509961c198a67037600819850bec9) (`2a7c3ea86f..5fbf625402`)

### 1. Verified Invariants (`AC 5` — Pass)
1. **Missing recreated-root recovery + resize fence:** When `data.gestureId != null && (data.gestureId !== me.gestureId || me.dragCancelled)`, `me.zoneRegistrations[dragElementRootId] ??= dragZoneId` populates an unmapped recreated root without invoking `dragResize.register(data)` (neither replacing an active resize preview via a stale descriptor nor cancelling it via `resizeConfig: null`) and without mutating `offsetX`, `offsetY`, `allowOverdrag`, `isWindowDragging`, or `bodyCursorStyle`.
2. **Newer-owner preservation on a reused root:** Because `??=` only writes when `zoneRegistrations[dragElementRootId]` is `null`/`undefined`, a root already claimed by a newer zone (`'new-zone'`) is never overwritten by a late/cancelled handshake from `'old-zone'`.
3. **Partial gesture updates stay no-ops:** Follow-up `WindowDragZone` calls (`:141`, `:166`, `:221`) pass `{gestureId, allowOverdrag}` / `{gestureId, isWindowDragging}` without `dragElementRootId`/`dragZoneId` and exit cleanly behind `if (dragElementRootId && dragZoneId)`.

### 2. Forward-Generalization Boundary Note (Non-Blocking for `#21603`)
- On `5fbf625402`, only `WindowDragZone` stamps `gestureId`, and neither `WindowDragZone#dragStart` (`:50-68`) nor `DragZone#dragStart` (`:549-558`) awaits any async work before posting `Neo.main.addon.DragDrop.setConfigs(...)`. Worker → Main FIFO `postMessage` order therefore strictly guarantees `setConfigs` lands before any subsequent `zone.destroy()` → `unregisterZone` (`delete registrations[rootId]`).
- **When `gestureId` later generalizes to base `DragZone` / async-preflight subclasses** (`draggable/container/SortZone.mjs:1068` `await owner.getDomRect(...)`, `draggable/grid/header/toolbar/SortZone.mjs:388` `await me.owner.promiseUpdate()`), `DragZone#dragStart` (`:549`) must guard `if (me.isDestroyed || signal?.aborted) return;` **before** calling `setConfigs` — otherwise a zone destroyed while suspended in its subclass pre-`super` `await` posts `unregisterZone` *first* (deleting `registrations[rootId]`) and a resumed `setConfigs` arriving *second* would resurrect the destroyed `dragZoneId` into the now-empty slot via `??=`.

**Verdict:** AC 5 (`DragDrop#setConfigs` stale-handshake root recovery + newer-owner & active-resize protection) is **verified** at `5fbf625402`.
