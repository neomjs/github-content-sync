# An application toolbar example whose items arrive as JSON

Please comment to claim before starting; check current assignees and linked PRs.

## Context

Buttons, Menus & Toolbars in the Portal's examples has no example of the toolbar an application opens on. #21142 ([comment](https://github.com/neomjs/neo/issues/21142#issuecomment-6980244557), correction 1) adds one as a new card, its items arriving as JSON, and retires `examples/serverside/toolbarItems` as a card: that page loads eight items from `resources/data/toolbar-items.json` with one click (`Viewport.mjs:33`, `loadItems()`), and shows nothing else. This leaf is open to an outside contributor (#21367).

## The Problem

A reader who wants a menu bar, an action toolbar or a toolbar a server configures finds no page that shows one. The proof that a toolbar's items can arrive as data exists only as a test-like page.

## The Architectural Reality

- `Neo.toolbar.Base` is a container: `add()` takes item configs, so JSON that describes buttons becomes buttons.
- `Neo.button.Base` takes a `menu` config; the split button (`src/button/Split.mjs`, #21430) opens its menu from its trigger.
- `Neo.container.Base#loadItems({url})` (`src/container/Base.mjs:791`) fetches a JSON file of item configs, as `examples/serverside/toolbarItems/Viewport.mjs` does; a toolbar turns `'->'` into a spacer (`src/toolbar/Base.mjs:1037`).
- An example folder holds `app.mjs`, `index.html`, `neo-config.json` and a `MainContainer.mjs`; styles go to `resources/css/src/examples/<path>/`. Read two sibling examples first, for instance `examples/button/split` and `examples/grid/serverSide`.

## The Fix

A new example, `examples/toolbar/application/`:

- A toolbar across the top of a small app (a text editor or a drawing pad), whose items come from a JSON file in the example's `resources`: buttons with icons and tooltips, a split button with a menu, a separator, a toggle, and a `->` spacer before the right-hand items.
- Each item does something visible in the app below it; a status line names the last action.
- At 390 px the toolbar wraps or moves its overflow into a menu, so no item is cut.
- A record in `apps/portal/resources/data/examples.json` (family `buttons`) and a capture recipe in `apps/portal/resources/data/example-captures.json`. The cover image ships in a `neomjs/pages` pull request; a maintainer can take it with `node buildScripts/docs/captureExamples.mjs --record <id>`.

## Acceptance Criteria

- [ ] AC-1: The toolbar's items are created from the JSON file; editing the file changes the toolbar after a reload.
- [ ] AC-2: Every item changes the app or the status line, and the split button's menu opens from its trigger.
- [ ] AC-3: At 390 × 844 no toolbar item is cut or off the screen.
- [ ] AC-4: The record and its recipe exist; the catalog count specs (`MainContainerController.spec.mjs`, `e2e/portal/ExamplesCatalogNL.spec.mjs`) follow.
