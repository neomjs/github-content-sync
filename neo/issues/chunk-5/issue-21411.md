# A workbench example keeps its changed configs in the URL

## Context

Split out from `#21144` (re-cut 2026-11-18) so the Engine 14 lock (`Sun 22 Nov 18:00 CET`) closes cleanly on `#21144` (Part 1: the workbench Code View) while URL-state persistence ships immediately after the cut per parent epic `#21140` (*After the cut*, item 4). Design authority: operator direction of 16 Nov 2026, `#21140`, and `#21144`.

## The Problem

In a workbench example (`Neo.examples.ConfigurationViewport`), a visitor changes inspector configs and discovers a component configuration worth bookmarking or sharing, yet reloading the page resets every config to initial defaults and no URL carries that state to a colleague.

## The Architectural Reality

- [`examples/ConfigurationViewport.mjs`](https://github.com/neomjs/neo/blob/dev/examples/ConfigurationViewport.mjs) owns `snapshotInitialState()`, `onConfigChange()`, `onConfigRecordChange()`, `onRadioChange()`, `onReset()`, and (delivered by `#21144`) the diffed config map relative to `initialConfigValues`.
- [`src/Main.mjs`](https://github.com/neomjs/neo/blob/dev/src/Main.mjs) (`editRoute` / `setRoute`), [`src/main/DomEvents.mjs`](https://github.com/neomjs/neo/blob/dev/src/main/DomEvents.mjs) (`parseHash` / `sendRoute` / `setRoute`), and [`src/util/HashHistory.mjs`](https://github.com/neomjs/neo/blob/dev/src/util/HashHistory.mjs) already route hash parameters per window without requiring a server round-trip.

## The Fix

Serialize the workbench's changed configs (relative to `initialConfigValues`) into the example's URL hash whenever inspector controls change them, parse/restore matching typed configs onto `exampleComponent` and its inspector controls when opening a URL carrying those parameters, and clear the URL parameters cleanly on `onReset()`.

## Acceptance Criteria

- [ ] Changing a config in the workbench updates the example's URL to reflect the changed configs; opening that URL in a fresh load restores the changed state across `exampleComponent` and its inspector controls; clicking `Reset` clears the URL state back to initial.
- [ ] e2e: change a config, reload the page at the resulting URL, verify the same component state and inspector control values are restored; reset clears the URL parameters and restores defaults.

## Out of Scope

- The workbench Code View panel and clipboard copy (owned by `#21144` in Engine 14 scope).
- Per-example custom multi-target mutations outside inspector-bound `exampleComponent` configs unless explicitly documented in `#21144`'s exception census.
- Persisting state in `localStorage`, generated standalone example files, or an in-Portal example page of its own (`#21140`, *After the cut* item 2).

## Avoided Traps

- **State in `localStorage`.** Browser-local storage cannot be copied as a link or opened by a colleague on another machine.
- **Unbounded object serialization in URL.** Encode only primitive/JSON-safe config diffs that differ from `initialConfigValues` and skip unknown or non-serializable keys safely on restore.
