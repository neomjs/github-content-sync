# A list or tree item can be renamed in place

## Context

#21140's target gives the Trees group a file explorer whose items are "renamed in place" (row Trees). Checked on 19 Nov (#21140 `issuecomment-7006670970`): no list or tree in the engine edits an item's text in place, so the card waits on this ticket and on its sibling for drag-move.

unowned-rationale: an engine feature the Trees card needs; a maintainer takes it when the band's examples are in review, and if it misses the lock (Sun 22 Nov 18:00 CET) the card rides the next cut.

## The Problem

`Neo.list.Base` renders each record's `displayField` as the item's content (`createItemContent`), and `Neo.tree.List` inherits that. Neither offers a way to edit that text where it is shown, so an app has to open a dialog or a form to rename a file, a folder or a list entry.

## The Architectural Reality

- `Neo.list.Base` owns item rendering, selection and keyboard navigation; `Neo.tree.List` extends it, so a feature on the list reaches both.
- The engine already edits in place elsewhere: grid cell editing (`Neo.grid.plugin.CellEditing`) places a field over a cell, commits to the record and restores focus. That is the pattern to follow, not to share code with.
- An item's text is a record field, so the edit commits by setting that field and the list renders from the store.

## The Fix

An opt-in way to edit a list item's text in place, available on `Neo.list.Base` and so on `Neo.tree.List`: F2 or a double-click opens a text field over the item's text; Enter or leaving the field commits to the record's `displayField`; Escape cancels; focus returns to the item. A listener can veto a name before it is committed.

## Acceptance Criteria

- [ ] AC-1: With the feature on, F2 on a focused item and a double-click on an item open an editor over its text, holding the current value.
- [ ] AC-2: Enter and blur write the new text to the record's `displayField`, and the item shows it; Escape leaves the record unchanged.
- [ ] AC-3: A veto keeps the old text and the editor open; focus is on the item after a commit or a cancel.
- [ ] AC-4: A component spec covers a list and a tree; lists without the feature behave as today.

## Out of Scope

- Editing more than the display text.
- Drag-move in trees: its own ticket.
