# A header menu option with one match reads "1 matches" to screen readers

## Context

Welcome! This is a small, self-contained accessibility fix in the grid header menus that Neo.mjs 13.3 introduces (#19643). You need a fork, Node and the dev server; no Agent OS, Docker or AI tooling.

A header menu lists a column's values, each with the number of rows that match it. A screen reader announces each option by its `aria-label`, which `src/list/ValuePicker.mjs` builds in `createPooledItem()`:

```js
node['aria-label'] = this.getOptionLabel(item.record) + ', ' + (item.record.count ?? 0) + ' matches';
```

So a value with exactly one match is announced as "sloemo01, 1 matches".

## The Problem

To see it:

1. `npm install`, then `npm run server-start`.
2. Open `http://localhost:8080/examples/grid/issues/index.html`, hover the **Author** header and click its ▾.
3. Inspect the `sloemo01` option in DevTools: `aria-label="sloemo01, 1 matches"`.

The tests currently expect the wrong text: `test/playwright/e2e/grid/HeaderMenuStateNL.spec.mjs` contains `1 matches` twelve times, so they would also fail once the label is fixed. Those expectations change together with the label.

## The Architectural Reality

- The label belongs to the option row the value picker renders (`createPooledItem()` in `src/list/ValuePicker.mjs`). The visible row shows only the number; only the `aria-label` has the word.
- `test/playwright/unit/list/ValuePicker.spec.mjs` already reads the label (`'Value 0, 20000 matches'`), so a unit case can cover the singular form; unit tests run locally without anything else installed.
- `HeaderMenuStateNL.spec.mjs` belongs to the browser tier that the maintainers' CI runs on every pull request. You do not need to run it locally; updating its expected strings is enough.

## The Fix

1. In `createPooledItem()`, use `match` when the count is 1 and `matches` otherwise: "0 matches", "1 match", "2 matches".
2. Add a unit case to `test/playwright/unit/list/ValuePicker.spec.mjs` for a value with one match.
3. In `test/playwright/e2e/grid/HeaderMenuStateNL.spec.mjs`, change every expected `…, 1 matches` to `…, 1 match`.

## Acceptance Criteria

- [ ] AC-1 An option whose count is 1 has the `aria-label` `<label>, 1 match`; every other count keeps `matches`.
- [ ] AC-2 `npm run test-unit -- test/playwright/unit/list/ValuePicker.spec.mjs` passes and covers a count of 1 and a plural count.
- [ ] AC-3 No spec under `test/` still expects `1 matches`.

## Out of Scope

- Translating the label; the engine has no string catalog for it.
- The visible count in the option row.
