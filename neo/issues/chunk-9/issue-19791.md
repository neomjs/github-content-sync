# Grid record search: an optional toolbar with visible filter state

Terminal predicate: a grid can opt into a search toolbar whose scoped term search, visible filter state and single reset work on fully loaded local data, and the issues showcase searches its Title and Summary through it.

## Problem scope

The per-column value picker shipped in `#19643`, but a grid still has no record search.
- **No text path.** The issues showcase's main content, Title and Summary, carries `columnMenu: false`. Its text has no filter path, and resetting means clearing each menu in turn.
- **Invisible filter state.** On `examples/grid/bigData`, a picker selection stays active after the header field is cleared, while the header looks unfiltered. The cause is the menu's closed-surface early return.

The operator moved the optional toolbar into v13.3 on 2026-10-16. This needs an epic, not a single ticket, because three surfaces must compose, and each lands as its own PR: the data contract the search writes, the header's active state, and the toolbar with its summary.

## Intended solution shape

The converged contract is the body of #19786 (SHA-256 `72b90388…`). In short:
- **One Store-owned search contribution** `{ownerRole: 'grid-search', property: null, filterBy}` carrying declared `fields`. An explicit `null` marks the columnless slot. The owned-key validator resolves the property the Filter actually exposes, so absence keeps the `id` default.
- **Matching** splits the query into whitespace terms, and every term must match at least one searched field. The match is case-insensitive unless toggled. Raw items are read directly, without hydration or renderers. An empty query disables the contribution and keeps its scope.
- **Counting:** `getFilterValues` honours declared `fields`, so picker counts follow the search.
- **Visible state:** a generic `Filter.effective` read lets headers mark filtered columns, and the toolbar's summary lists what has no header. Clear removes only the grid's own roles.
- **The toolbar** is a `searchToolbar_` descriptor config on `grid.Container`, mirroring `footerToolbar_`, and is null by default.

## Avoided traps

Rejected in #19786:
- per-view search, which needs a projection layer nothing else pays for;
- header text filters as the only path;
- matching rendered cell text, which would mean stateful renderers;
- a clear-all that also drops application predicates;
- the `id` slot, a filter named `id` that never filters by id;
- sampled regex admission.
