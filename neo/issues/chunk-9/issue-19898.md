# A vessel closed mid-boot leaves its tear-out slot bound to a dead window

## Context

The Workstation film tour (`WorkstationFilmTourNL`, both arms) has been quarantined since 2026-10-12 as "hosted only: the tour stops at journey hop 3 because no fresh vessel is born" (accountable: me). A read-only diagnosis of the hop-level `[film-probe]` logs (runs `38258413156`, `38260376912`, `38271163182`, `38276837825`, `38291757581`; 12 arm attempts) found **two** failure modes. This ticket is mode A (5 arms, 4 of them autoGates):

`journey hop 3 (desktop): no fresh vessel was born — isWindowDragging=false reattachArmed=true lastRatio=0 vesselOpen={…"stage":"granted"} connects=false … activeVessel=false`. No popup is created for the hop at all.

Every leg between main and the desktop point crosses Metrics' window. That window claims the drag, the vessel retires, and leaving reopens it, so a journey births 6 popups, 3 of them short-lived. In all 5 mode-A arms, hop 1's reopened vessel closed 0.41–0.47 s after creation. Every arm that closed it within 0.38 s went on to birth hop 3's vessel.

## The Problem (inferred, ~60–70 %)

`acquire` returns null at `reserve` (`src/manager/transaction/NativeLifecycle.mjs` ~197–198), which refuses a slot with a live binder (`src/manager/Transaction.mjs` ~852). Every generation uses the same per-item key (`apps/workstation/view/VesselWorkspace.mjs` ~58–68). The binder can stay live past the window's death:
- `App#registerApp` binds the slot before it sends `registerAppName` (`src/worker/App.mjs` ~897–898);
- `DomEvents#onBeforeUnload` sends `disconnect` only for `Manager.appNames` (`src/main/DomEvents.mjs` ~485–486).

A popup closed between those two steps never disconnects, and nothing retries: the exit fires only while the pointer is moving out (`src/draggable/container/SortZone.mjs` ~388–400). For a user, a vessel closed quickly can leave that item unable to tear out again in the session.

## The Fix

1. First, confirm. Add the key's binding `windowId` and its port liveness to the gesture driver's `diag()` (`apps/workstation/tour/NativeGestureDriver.mjs` ~1414), and run hosted once with reporter output kept, or locally under 6× CPU throttling. A null binding at failure falsifies this cause.
2. `DomEvents#onBeforeUnload`: when `appNames` is empty, send a window-scoped `disconnect` that `worker/Base#onDisconnect` (~559) accepts.
3. `App#registerApp`: skip `Transaction.admit` when the window's port is already gone (`importApp` is async, so registration can follow the disconnect).

## Acceptance Criteria

- [ ] AC-1: The diag names the slot's binder and its liveness at a hop failure.
- [ ] AC-2: A vessel closed between `registerApp` and `registerAppName` leaves its slot free: a unit or e2e arm, red before and green after.
- [ ] AC-3: The autoGates film arm passes on every attempt across ≥ 5 hosted runs, and its quarantine entry is gone.
