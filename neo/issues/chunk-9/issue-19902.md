# The Portal's theme switch does nothing on its first click

**Claim it first:** comment on this issue before you start, and check the open pull requests for one that already points here. We merge the first approve-worthy PR (see `CONTRIBUTING.md`, point 3).

## Context

Welcome! This is a small fix in the Portal, the app behind neomjs.com (`apps/portal`). You need a fork, Node and the dev server; no Agent OS, Docker or AI tooling.

Found in release testing, 2026-10-20, with headless Chrome on a fresh profile. The Portal loads in its dark theme, and the header's theme button shows a moon. The first click changes the icon but keeps the dark background. Only the second click switches to light. Reproduced 2/2.

## The Problem

The first click asks for the theme that is already showing.

## The Architectural Reality

- `apps/portal/neo-config.json`: `"themes": ["neo-theme-neo-dark", …]`, so the Portal boots dark.
- `apps/portal/view/ViewportController.mjs#onSwitchTheme`: `oldTheme = viewport.theme || 'neo-theme-neo-light'`. Before any switch, `viewport.theme` is unset, so the method assumes light and "switches" to dark.
- `apps/portal/view/HeaderToolbar.mjs` starts the button with `iconCls: 'fa-solid fa-moon'`.

## The Fix

When `viewport.theme` is unset, fall back to the theme the app actually booted with (the first entry of `themes`) instead of a hardcoded light. Make sure the button's starting icon matches that theme.

## Acceptance Criteria

- [ ] AC-1: on a fresh load, one click on the theme button switches dark → light, and a second click switches back.
- [ ] AC-2: the button's icon matches the theme on screen before and after each click.

## Out of Scope

- Following the OS's light or dark preference. The dark default is deliberate.
