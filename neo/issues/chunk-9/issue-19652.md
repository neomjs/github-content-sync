# Cut Engine v13.3.0 through the release PR

## Context

#19637 changes how the Engine is released. The old flow pushed straight to `dev` and needed a ruleset bypass. Now `publish.mjs prepare` opens a release PR, the operator merges it once its required checks pass, and `publish.mjs finish` squashes the merge onto `main` and creates the GitHub release. 13.3.0 (milestone v13.3) is the first cut on that path.

This ticket is the cut's record. It is not the release PR's close target. The release PR resolves a preparation leaf filed at cut time, so this record stays open until `finish`, npm and the Portal are verified. It owns the real-cut validation that #19637 cannot show before a release exists.

## The Cut

1. Bump `package.json` to 13.3.0, and author `.github/RELEASE_NOTES/v13.3.0.md` through the release-notes epic.
2. File the preparation leaf, the release PR for v13.3.0, whose ACs the PR itself delivers. Write the release PR body against it. Then `node buildScripts/release/publish.mjs prepare --rehearse --ticket <leaf> --body-file <body>` prints every gate as ✅.
3. `node buildScripts/release/publish.mjs prepare --ticket <leaf> --body-file <body>` opens the release PR.
4. The operator merges it after its required checks and CodeQL pass. This is the cut's one human step.
5. `node buildScripts/release/publish.mjs finish`.
6. Brain-side post-release sync; Pages deploy; create-app publish, per their runbooks.

If a phase stops, re-running the same command continues it.

## Acceptance Criteria

- [ ] AC-1: The release PR ran `dev`'s required checks and CodeQL, and nothing reached `dev` except through it. No ruleset bypass was added.
- [ ] AC-2: `finish`'s squash push to `main` succeeded for the account that ran it, and the GitHub release body ends with the atomic-commit line.
- [ ] AC-3: `npm-publish.yml` published 13.3.0 through Trusted Publishing (OIDC), with no token.
- [ ] AC-4 (post-merge): once the content sync archives the release, the Portal's 13.3.0 notes route shows the atomic-commit line.
- [ ] AC-5 (post-cut): the Pages refresh from the published 13.3.0 package keeps the corrected featured-Workstation catalogs and covers (#19640, neomjs/pages#37) without re-applying them by hand. This retires the package-refresh caveat that #14800 carried ([Sophie's closeout](https://github.com/neomjs/neo/issues/14800#issuecomment-6122873793)); until then, a Pages refresh must keep the reviewed overlay.
