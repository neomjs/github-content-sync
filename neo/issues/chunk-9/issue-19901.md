# Blog posts' relative links leave the Portal and 404

**Claim it first:** comment on this issue before you start, and check the open pull requests for one that already points here. We merge the first approve-worthy PR (see `CONTRIBUTING.md`, point 3).

## Context

Found in team:engine release testing of the Portal (the neomjs.com app, `apps/portal`), 2026-10-20, in headless Chrome against the dev server on `origin/dev` 4844087a77.

To reproduce, open `#/news/blog/blog/the-organism-already-existed` and click the "DynamicGrids.md" link. The tab leaves the app for `http://localhost:8080/apps/guides/datahandling/DynamicGrids.md` and gets a 404 ("Cannot GET …"). The v10 series' links between its posts fail the same way: `./v10-post1-love-story.md` resolves to `/apps/portal/v10-post1-love-story.md`. Reproduced 2/2.

## The Problem

`learn/blog/` holds relative `.md` links on 23 lines across 7 posts. They work on GitHub, where they are files next to each other, but in the Portal none of them reaches a page.

## The Architectural Reality

- `src/app/content/Component.mjs#rewriteLinks` rewrites a relative `.md` href onto `contentRoute`. It returns the HTML unchanged when `contentRoute` is not set (`if (!contentRoute || !me.record?.id) return html`).
- `apps/portal/view/learn/Component.mjs` sets `contentRoute: '#/learn/'`. `apps/portal/view/news/blog/Component.mjs` extends the same `ContentComponent` and sets none, so a blog post's links are never rewritten.
- A post's targets resolve under `learn/`. Some are sibling posts (`learn/blog/…`, routed `#/news/blog/blog/<slug>`), and some are guides (`learn/guides/…`, routed `#/learn/<id>`). A single `contentRoute` therefore covers only one of the two.
- Design authority: `rewriteLinks`' own summary, "Rewrites relative Markdown links onto `contentRoute`". The blog component inherits it and opts out by omission.

## The Fix

In the blog component, route a resolved target under `learn/blog/` to the blog view and any other `learn/` target to the learn view. Reuse `rewriteLinks` and `resolveContentId` rather than adding a second link rewriter.

## Acceptance Criteria

- [ ] AC-1: in the Portal, "DynamicGrids.md" in `the-organism-already-existed` opens `#/learn/guides/datahandling/DynamicGrids`, and a v10 post's link to `./v10-post1-love-story.md` opens that post in the blog view.
- [ ] AC-2: a unit test covers both kinds of target, plus an absolute URL that stays as written.

- Links that point at moved or deleted files, filed separately.
