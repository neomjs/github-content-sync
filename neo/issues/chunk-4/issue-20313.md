# A blog post's Mermaid diagram is an empty div on its static page

## Context

Found during a quality read of `learn/blog/persistent-memory-for-ai-coding-agents.md` before Medium (2026-11-05). The live static page, https://neomjs.com/news/blog/persistent-memory-for-ai-coding-agents, returns 200 with its canonical pointing to itself. Its sequence diagram is `<div class="neo-mermaid" id="neo-mermaid-1"></div>`, an **empty** placeholder: the page has 0 `<svg>` and 0 `<pre>`.

The lead-in *"The rules also end every turn with a write, so the next recovery has something to read:"* therefore ends on its colon for every reader without JavaScript. That includes crawlers, link previews and Medium's "Import a story".

## The Problem

The Markdown component emits the placeholder, and the Mermaid wrapper fills it client-side, asynchronously. The static snapshot captures the empty div. Since `neo-agent-skills` 0.1.85, the blog guide requires every post to carry a diagram or an image, so Mermaid blocks will become common.

## The Architectural Reality

- `src/component/Markdown.mjs` emits the `neo-mermaid` placeholder.
- `src/component/wrapper/Mermaid.mjs` renders it in the browser.
- Design authority: the blog authoring guide, §1 (`neo-agent-skills` ≥ 0.1.85): *"every post carries at least one Mermaid diagram or image … Each is render-verified before merge."* The render check passed in the app, but the static page is the canonical, indexed surface.
- Decision Record impact: none.

## The Fix

The static output carries the diagram. Either the snapshot waits for the Mermaid render and inlines the SVG, or the placeholder ships a fallback (a pre-rendered image, or the source in a `<pre>`). Pick the cheaper one that leaves the app's rendering unchanged.

## Acceptance Criteria

- [ ] The persistent-memory post's static page carries the diagram, as inline SVG or an image, verified without JavaScript (`curl` shows it).
- [ ] A test pins that a Mermaid block in Markdown yields non-empty static output.
