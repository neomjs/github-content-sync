# Resizable desktop windows should expose standard minimize and maximize controls by default

## Requested behavior

Resizable desktop/app windows should expose Minimize, Maximize/Restore, and Close controls by default, with working framework-owned behavior. Application developers should not have to wire the standard window controls individually.

## Current public defaults

`src/dialog/header/Toolbar.mjs` already defines:

```js
actions: ['maximize', 'close']
```

Its actionMap contains maximize and close, but no minimize action. Therefore this is not a claim that the stock dialog lacks Maximize.

A custom headerConfig.actions list replaces the defaults. A consumer that supplies only a customized Close action also loses Maximize. The default-controls contract and the supported way to customize icons while retaining standard controls should be clear.

## Desired default contract

- A resizable desktop window offers Minimize, Maximize/Restore, and Close without application-specific header-action wiring.
- Maximizing uses the usable desktop/workspace area, and Restore returns to the previous normal size and position.
- Minimizing integrates with the desktop window manager/taskbar so the window has a clear restore path.
- Standard action icons can be customized without inadvertently removing the other default controls; document the existing supported mechanism or provide an appropriate one.
- Keep explicit opt-outs and intentional custom action lists available.
- Define behavior for non-resizable windows and modal dialogs explicitly. Minimize needs a restore owner and should not leave an unmanaged dialog inaccessible.

## Acceptance criteria

1. A minimal resizable desktop window exposes all standard actions without consumer handlers for them.
2. Maximize and Restore form a working state toggle, with matching icons and accessible labels.
3. Minimize and taskbar/manager restore preserve the normal window geometry.
4. Changing the Close icon through the documented customization mechanism retains the default Minimize and Maximize controls.
5. A documented opt-out can suppress individual controls when inappropriate.

## Related

- #21201 already proposes desktop AppWindow with minimize, maximize, and close. This request makes the default action/capability and customization contract explicit.
- #21199 provides window-manager minimize/restore ownership.
- #21271 requests preservation of user geometry when desktop bounds change.

Thank you, @armando-ota. Separating "the stock dialog lacks Maximize" (which you didn't claim) from the default-controls contract made this easy to place. What `dev` does today (`a2d97b19b8`):

- Maximize and Restore are already one toggle: `dialog.Base#maximize` flips `maximized` and swaps the button's icon between `maximizeCls` and `minimizeCls` (`src/dialog/Base.mjs:648-654`).
- That toggle has two real defects. The restore state shows a minimize glyph (`minimizeCls: 'far fa-window-minimize'`, `:122-124`). Our own web desktop adds a real Minimize with that same glyph (`apps/webdesktop/view/AppWindow.mjs:62`), so a maximized window there shows two identical buttons. The button's accessible name also stays "maximize", because it comes from the action name once, at creation (`src/toolbar/Base.mjs:717-723`).
- Minimize needs a restore owner, as you say. A plain `dialog.Base` has none, so its defaults stay `['maximize', 'close']`. The owner is the desktop window manager (#21199: `minimize(appId)`, `restore(appId)`), and the window with all three controls is the desktop's app window (#21201).
- To change one icon today, you restate the list with an object entry, for example `headerConfig: {actions: ['maximize', {action: 'close', iconCls: '…'}]}`. `headerConfig` is spread over the header (`src/dialog/Base.mjs:548-558`), and its `actions` replaces the default list (`src/dialog/header/Toolbar.mjs:17-35`).

**Decision: this is #21201's scope, as you anticipated, so I folded your contract into #21201** rather than keep two tickets for one class. Its new AC-5 to AC-7 cover all three controls without consumer handlers, a restore glyph with an accessible name that follows the state, normal geometry kept through minimize and maximize, changing one icon without losing the others, leaving out a single control, and Minimize only where a manager can restore the window. If #21201 now covers what you need, I'll close this one as its duplicate. If not, tell me what it still misses.
