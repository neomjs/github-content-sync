# DockMotion's resizeSplit witness can stop on another motion's signal

## Context

`test/playwright/e2e/dashboard/DockMotionNL.spec.mjs` › *a committed resizeSplit GLIDES* has failed its samples floor on three hosted Brain-tier runs. Each time it read `Expected: > 5, Received: 5`, while the signal bracket's appear and clear both passed:
- run `38333432524`, which #19893 and #20090 both deferred in their Out of Scope;
- run `38319888826`, job `115046963106`, Engine `c37f76c6da`, 2026-10-12: line 220. The in-run retry passed.
- job `127374333148`, `e2e-brain (5/10)` on PR #20343's head `c2580b7800`, 2026-11-05: line 222. The job failed. Reported by @neo-gpt-sophie.

**Observed:**
- The count was 5 on all three runs.
- The floor's message prints neither `gaps` nor which element carried the signal.
- Not reproduced locally yet.

## The Problem

The arm arms its witness without waiting for in-flight motion to settle. It then calls `expectSignalBracket(page)` with the default selector, which counts any `.neo-dashboard-dock-animating` element.

**Inference, not yet reproduced:**
- `executeDockOperation` resolves when the document commits. The workspace FLIP plays after that, fire-and-forget (`src/dashboard/dock/Workspace.mjs` ~2808–2828).
- If another producer's signal opens and closes the bracket before the glide begins, `Promise.all` settles with the RPC, and `readMotionSamples` stops the sampler before the glide plays.
- That window is roughly one RPC round-trip. A near-constant count of 5 fits it better than frame starvation, which would vary.

The sibling *rail-click reveal SLIDES* arm failed the same way (`Received: 0`). #19893 fixed it by settling the setup's motion first and narrowing the bracket to the overlay's own signal.

## The Architectural Reality

Design authority: the `expectSignalBracket` comment, `DockMotionNL.spec.mjs:71-72`: "`selector` narrows the bracket to one producer's signal: any other motion still settling would otherwise open and close it before the motion under test begins."

- **The glide's producer.** The resizeSplit glide is the workspace FLIP. `Workspace.mjs:2819` calls `MotionSignal.enter(me)` on the `neo-dock-workspace` root and leaves when `flip.play()` settles.
- **Other producers of the class:**
  - `RevealOverlay`;
  - `TabEnterButton`;
  - the `Maximize` plugin;
  - the `LayoutAdapter` overflow projection, which a width change can start (`LayoutAdapter.mjs:1404-1405`).
- **The other arms in this spec:**
  - The moveItem FLIP arm already brackets `.neo-dock-workspace${SIGNAL}` (`:263`).
  - The SLIDES arm brackets the overlay (`:396`).
  - The addTab arm settles its setup before the witness (`:324`).

## The Fix (test-only)

In the GLIDES arm (`:189`–`:227`):
1. Before `startMotionSampler`, poll `page.locator(SIGNAL).count()` down to 0, as the addTab and SLIDES arms do.
2. Bracket the workspace FLIP's own signal: ``expectSignalBracket(page, {selector: `.neo-dock-workspace${SIGNAL}`})``.
3. The samples floor's message names `gaps`, as the SLIDES arm's does at `:403`.

On a seat whose `NEO_NL_PORT` points at the fleet Bridge, run the e2e tier with a free port (#20339).

## Out of Scope

- **The addTab arm's default bracket (`:334`):** it settles its setup first and has no sighting.
- **The `> 5` floors:** they stay, because they stop an oracle that observed nothing from passing (see the comment above `startMotionSampler`).
- **Quarantine:** three sightings in four weeks don't justify taking the arm off the gate.

## Avoided Traps

- **Lowering the floor:** it would hide a bracket that closed early, because the read would still come before the motion it is meant to witness.
- **A fixed wait before the read:** it trades the race for runtime, and still doesn't tie the read to the glide.
