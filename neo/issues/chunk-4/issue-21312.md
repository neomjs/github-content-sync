# The video examples stream a music video the project has no licence for

Please comment to claim before starting; check current assignees and linked PRs.

## Context

While capturing the Components covers (#21120), the `video` example's playing state showed its clip: a music video preview with an identifiable performer, streamed from Apple's iTunes media CDN. A cover of that state would republish a frame of it on neomjs.com, so the cover shows the player before play instead ([comment on #21120](https://github.com/neomjs/neo/issues/21120#issuecomment-6970812940)).

## The Problem

One URL, `https://video-ssl.itunes.apple.com/itunes-assets/Video125/v4/a0/57/54/a0575426-dd8e-2d25-bdf3-139702870b50/mzvf_786190431362224858.640x464.h264lc.U.p.m4v`, appears three times:

- `examples/component/video/MainContainer.mjs:35`, the Components group's video example
- `examples/videoMove/MainContainer.mjs:32`, the video-move demo
- `src/component/Video.mjs:10`, the usage example in the class JSDoc

The repository carries no licence for this clip, and its host is a third-party CDN the project does not control, so both examples break the day the asset moves. On 2026-11-18 it answered `200`, `video/x-m4v`, 6,169,688 bytes.

## The Architectural Reality

- `Neo.component.Video` (`src/component/Video.mjs`) plays whatever `url` it is given: a ghost overlay with a play control until clicked, then a muted, autoplaying `<video>` element.
- Example media lives in `neomjs/pages` under `resources_pub/`: country flags and data files, referenced for example from `examples/component/coronaGallery/CountryGallery.mjs:173` and `examples/grid/issues/MainStore.mjs:41`. Those references use `raw.githubusercontent.com`, which answers `content-type: text/plain` with `x-content-type-options: nosniff`, so a `<video>` element cannot play a file from there. `https://neomjs.com/resources_pub/<path>` serves the same files with their real content type (`neomjs.github.io/pages/<path>` redirects there).
- Design authority: n/a — the ticket calls no behaviour wrong; it replaces a media asset the project holds no licence for.

## The Fix

1. Choose a short clip (10 to 60 s, at most 10 MB, H.264 MP4, around 640×360) published under CC0 or CC BY, for example from the Blender Foundation's open movies or from Wikimedia Commons. Note its title, author, licence and source URL.
2. Open a `neomjs/pages` pull request that adds it under `resources_pub/video/`, with a short text file beside it giving the credit its licence requires.
3. Once that has merged, check that `curl -sI https://neomjs.com/resources_pub/video/<file>.mp4` answers `200` with `content-type: video/mp4` and `accept-ranges: bytes`.
4. Here, point all three URLs at that address, with one comment line beside each naming the clip, its author and its licence.

## Acceptance Criteria

- [ ] `git grep -n itunes.apple.com` returns nothing.
- [ ] `examples/component/video` and `examples/videoMove` play the new clip in Chrome, Firefox and Safari from the local dev server.
- [ ] The clip's licence permits redistribution, and the credit it requires stands beside the file in `neomjs/pages` and beside each URL here.
- [ ] The pull request links the merged `neomjs/pages` pull request.

## Out of Scope

- The video example's cover: #21120's recipe shows the player before play and is re-shot once this lands.
- Any change to `Neo.component.Video` itself.

## Avoided Traps

- Serving the file through `raw.githubusercontent.com`: `text/plain` with `nosniff` blocks playback.
- A YouTube or Vimeo embed: these examples show `Neo.component.Video` on a plain media URL.
- A clip without an explicit open licence, including "royalty-free" stock that restricts redistribution.
