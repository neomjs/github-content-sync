# Engine PRs run only the e2e specs their change can reach

## Context

Parent epic #20328 measured the baseline: 279 of the 346 PRs merged into `dev` from 2026-10-13 to 2026-11-05 ran all 14 e2e shards, about 53 runner-minutes each. Many of them reached far less than that:
- 97 touched only leaf `src/` families;
- 19 touched only e2e specs or fixtures;
- 29 touched only apps or examples.

Every one of them still ran every spec. The Brain-gated tier alone is 66 % of PR runner time.

## The Problem

Selection inside the E2E boundary is all or nothing. A grid-only change runs the Workstation dock specs, the portal specs and every other spec, on both tiers, before merge. The `dev` push then runs them all again.

## The Architectural Reality

- `buildScripts/util/e2eCiSelection.mjs` owns both populations (`--paths`, `--brain-paths`). It shards them by measured time and declares `BRAIN_SMOKE` and the quarantines.
- A spec reaches source through the app or example it navigates. In `test/playwright/e2e`, `apps/workstation` has 98 references, `apps/grid-cell-editing` 23 and `apps/portal` 11, and about 20 more apps are referenced.
- **What a `dev` push runs.** The Brain-gated tier always runs in full. The engine tier runs its full population when the push's own diff (`before...after`) reaches the boundary.
  - The engine tier's `dev` runs cancel when a newer push lands; the Brain tier's newer push replaces only a queued run.
  - So a merge burst can leave a merged commit's own diff unclassified: comment `6664576222`.
- **Reach is per spec.** An app-level closure is too coarse: Workstation's reaches 41 % of `src/`, including `grid` and `dashboard` (comment `6661250878`). Reach has to be measured per spec.

Design authority: #19655, intended solution (amended 2026-11-05 for #20332): "The full tier runs when the existing E2E impact boundary in `classify-test-scope.yml` matches, or when grid, AI-client or NL fixture/spec/config files change." This leaf amends that for pull requests only. Its steward is @neo-opus-ada.

## The Fix

1. **Map.** At classify time, read the committed tree. Each spec maps to what it exercises: the app or example it navigates, narrowed by the classes and views the spec itself names. Each of those maps to its static import closure (`import` and literal `import()`). The dry run measures this per-spec map against the app-level fallback.
2. **Select.** A changed file under a foundation path, or one the map cannot place, runs both tiers in full. The foundation paths are `src/core/`, `src/worker/`, `src/main/`, `src/vdom/`, `src/manager/`, `src/util/` and top-level `src/*.mjs`. Otherwise each tier runs the specs whose closure contains a changed file, any changed specs, and `BRAIN_SMOKE`.
3. **Dry-run before wiring.** Replay the 346-PR corpus and report, per PR, the selected spec count and runner-minutes against the full ones. Replay every red Brain or engine run in the window, and report whether the selection would have included its failing spec.
4. **Wire.** The selection reaches `e2eCiSelection.mjs` as a path list, and shards stay balanced by measured time. A `dev` push gets no per-spec selection: every tier it admits runs its full population.

## Acceptance Criteria

- [ ] A dry-run receipt is posted on this ticket before any workflow change. It shows the runner-minutes saved, and it lists every historical red whose failing spec the selection would have skipped, with the cause of each. No miss may remain unexplained.
- [ ] Four things an app's import closure cannot see must count as foundation, unless the replay shows they are covered:
  - main-thread addons, which load by name (`mainThreadAddons`, `Neo.main.addon.*`);
  - the other entry points: `src/main/**`, `src/vdom/**`, `src/worker/**`, and the canvas and offscreen workers;
  - styles under `resources/scss/**`;
  - runtime loading: `importPath`, `loadModule({path})`, and lazy `module: () => import(...)`.

  These are @neo-opus-ada's four blind spots.
- [ ] The ticket names who owns a `dev` red that follows a selective green. By default, that is the merged PR's author.
- [ ] @neo-opus-ada (steward of #19655) and one non-Claude family give their signal on the dry run before the workflow change merges.
- [ ] A change under a foundation path, or to an unmapped file, runs both tiers in full. A classifier arm pins each case.
- [ ] A leaf change runs the mapped specs plus `BRAIN_SMOKE`. The job summary lists the selected population and the reason for each spec.
- [ ] A `dev` push runs the full population of every tier it admits.
- [ ] The dry run counts how often a merge burst left a tier unrun for a merged commit (comment `6664576222`). The wiring PR either closes that hole or records why the Brain tier's forced `full` is enough.
- [ ] `WhiteboxE2E.md` states what a PR runs and what the `dev` push runs.

## Out of Scope

- Misclassified paths: the sibling leaf under #20328.
- Flake reduction: #17844, #19919.
- The unit and component tiers.

## Avoided Traps

- **Hand-kept tables mapping specs to areas:** they rot the way the e2e file list did before the classifier switched to rules.
- **Running the full tier on the `dev` push only:** a red then lands on `dev` for every agent to trip over. #19655 exists because a regression sat on `dev` for 14 hours.
- **Selection by coverage instrumentation:** it needs instrumented runs to stay current. A static map carries no runtime state.

**Finding for the dry run: a cancelled `dev` push leaves its own diff unclassified.**

On 2026-11-05, three merges landed within 70 s: `20d763470b` (#20332, 17:17:47Z), `b09106c476` (17:18:25Z) and `414b95234a` (#20335, 17:18:57Z). On `20d763470b`, *Engine Tests*, *E2E (engine tier)* and *E2E (Brain-gated tier)* all ended `cancelled`.

The mechanics on `origin/dev`:
- `test.yml` and `test-e2e.yml` share the ref stream, so a newer `dev` push cancels the older run.
- `test-e2e-brain.yml` lets a started `dev` run finish and replaces only a queued one.
- `classify-test-scope.yml:77-87` classifies a push by `payload.before...after`, meaning only the push's own commits.

So a cancelled push's diff is never classified. A later push re-tests the cumulative tree in a tier only when its own diff admits that tier:
- The Brain tier is forced to `full` on every push, so it is covered.
- Unit, components and the engine e2e tier are not covered whenever the later diff misses them, for example a docs-only merge right after.

This burst was covered, because both later merges touch `src/`. The dry run should count how often a burst left a tier unrun for a merged commit, because PR-side per-spec selection leans on the push as its safety net.

Two shapes to weigh there, not decided here:
- classify a `dev` push against the last commit whose run of that tier completed;
- stop cancelling `dev` pushes in the tiers the net depends on.

**Dry-run receipt v1** (dev `485650cd4f`; corpus: the 346 PRs merged into `dev` from 2026-10-13 to 2026-11-05). Partial: the open items are at the end.

**Model**

A spec's reach is its own e2e imports plus the static import closure (`import` and literal `import()`) of every app, example or fixture app it names.

A PR runs the full tier on any of these:
- foundation: `src/{core,worker,main,vdom,manager,util}/`, top-level `src/*.mjs`, `resources/scss/` and `src/canvas/`;
- runtime loading: `importPath`, `loadModule({…})`, `mainThreadAddons`;
- e2e support that no spec reaches;
- any other file the model can't place.

Otherwise it runs the specs whose reach holds a changed file, plus any changed specs, `BRAIN_SMOKE` (8 specs), and the 5 specs that name no app.

**Cost**

| | all or nothing | selected |
|---|---|---|
| e2e-touching PRs | 258 | 118 selective, 140 full |
| spec-runs | 50,310 | 40,846 (−18.8 %) |
| Brain runner-minutes (`e2eBrainDurations.json` + 45 s boot per job) | 8,105 | 6,782 (−16.3 %) |
| Brain shard jobs | 2,580 | 2,191 (−15.1 %) |
| engine shard jobs (costed by spec count) | 1,032 | 862 (−16.5 %) |

The job rows hold only if the matrix is sized to the selection. A fixed 10-shard matrix keeps every job.

The saving is modest for two reasons:
- Workstation's closure holds 41 % of `src/`, including `grid` and `dashboard`, so a grid or dashboard PR still runs nearly every Workstation spec.
- 73 of the 140 full PRs are full only because of files this model can't place: `package-lock.json` in 33, `buildScripts/util` in 28, `package.json` in 16. The classifier's dependency-kind and launch-chain rules could narrow some of these; that is the next increment.

**Recall**

The window holds 114 red e2e runs (engine 24, Brain 90):
- 98 name a failing spec; 10 failed before any test ran, and 6 logs were unavailable.
- 44 of the 98 had a full selection.

The selection would have skipped 26 failing specs in 25 runs. In none of them could the diff have caused the failure:
- **16: the diff can't reach runtime.** Docs, ADRs, blog posts, release notes, unit specs, non-e2e workflows, portal data.
- **6: changed code lies outside the failing spec's reach.**
  - `Carousel` → `IssuesShowcase`: `examples/grid/issues` can't reach it (its only portal user, `References.mjs`, is imported nowhere), and the Brain tier passed on that SHA.
  - `functional/useMemo` (2) and the docs app (2) → `DockCrossWindowWitnessNL` / `DockMotionNL`: 6 and 9 red runs in the window (defect-note on #20337, and #20351).
  - Calendar week view → `HeaderMenuInteractionNL`.
- **4: the diff changed only another spec.** Each is a single occurrence: either a flake, or a cross-spec leak through the shared app heap. A real leak would still turn the `dev` push red.

The skipped specs are the window's chronic flakers: `WorkstationFiveBeatNL` (18 red runs), `IssuesShowcase` (11), `DockMotionNL` (9), `PremeasureRowsNL` (7), `DockCrossWindowWitnessNL` (6). Five of the 25 runs were pull requests, which a selection would have spared a red unrelated to their change.

- Excluding the unreferenced `buildScripts/util/check-*.mjs` lint scripts as well changes nothing: none of the remaining full PRs is full because of them alone.

**2. Recall.** Unchanged from v1. The selection would have skipped 26 failing specs in 25 red runs, and none of those failures was caused by its diff.

**3. The merge-burst hole (AC).**
- Of 325 engine-tier `dev`-push runs in the window, 122 (38 %) were cancelled by a newer push.
- For 101 of those, the cancelled commit's own diff admitted the tier.
- For 16 of those 101, the next completed push did not admit it. Each change got no engine-tier run until a later admitting push, so a red it caused would land on the wrong commit.
- The Brain tier has no such hole: it is forced to `full` on every push, and its queued runs are replaced, never skipped.

**Recommendation.** Wire this only with both of these:
- a Brain and engine matrix sized to the selection, which is the only way the job count (the org cap) moves;
- `dev` pushes classified against the last commit whose run of that tier completed, not against `before`, which closes the 16-commit hole.

Without the sized matrix, the gain is runner-minutes only, which is not worth the classify-time map and its upkeep.

Even with both, rank it behind #20338. At about 2.2 fewer shard jobs per e2e-touching PR, it is a smaller lever than #20338's 2.6 skip-only jobs per PR, or than #20349's 12 lint jobs. The structural limiter is Workstation's closure (41 % of `src/`): grid and dashboard PRs reach nearly every Workstation spec.
