# A grid example exports what it shows as CSV

Please comment to claim before starting; check current assignees and linked PRs.

## Context

New example 4 of the Grid & Table slate ([#21142](https://github.com/neomjs/neo/issues/21142#issuecomment-6924949418)), a leaf of #21175 (the Grid & Table group, under #21140). The visitor's question: can the data leave the grid?

## The Problem

The grid exports its rows as CSV since #20380: `toCsv()` returns the text and `exportCsv()` downloads it (`src/grid/Container.mjs:1915` and `:1954` on `dev` `c40689ef53`). No example and no app of this repository calls either. Export is one of the first things a buyer of a grid asks for, and the examples section cannot show it.

## The Architectural Reality

- `toCsv({delimiter, escapeFormulas, header})`: `escapeFormulas` defaults to true and guards a cell that starts with `=`, `+`, `-` or `@` against being run by a spreadsheet (`:1927`).
- `exportCsv({fileName, ...options})` hands the text to the main thread, since a worker cannot start a download (`:1948`).
- #20380 decided what is exported: the store's records, never the rendered rows, with a column's `exportRenderer` for a formatted value. It left out Excel files, unloaded remote pages and a selection-only export.
- The Grids guide covers both methods since #20676 (`learn/guides/datahandling/Grids.md`).
- `examples/grid/headerGroups` is the model for the page: its own viewport, a headline, one instruction line, a theme button, both themes.
- Placement: a sibling folder `examples/grid/<feature>/`.
- Design authority: n/a, a new example.

## The Fix

1. **A new folder `examples/grid/export`**, after the `headerGroups` model.
2. **A sheet worth exporting**, 200 to 500 rows, for example invoices: a number, a customer, a date, an amount shown as currency, a status.
3. **A filter field and sortable headers**, so "what it shows" can change.
4. **Two buttons:** "Export CSV" calls `exportCsv()`. "Show CSV" puts the first 20 lines of `toCsv()` into a read-only pane beside the grid, so the proof needs no file and works on a phone.
5. **A delimiter choice** (comma or semicolon) and one row whose text starts with `=`, so the escaping shows in the pane.
6. A new catalog record with the group `grid-table`, `feature` and `lookFor`.

## Acceptance Criteria

- [ ] After a filter and a sort, the pane's lines are the grid's rows in the grid's order, and a spec under `test/playwright/e2e/grid/` asserts it.
- [ ] "Export CSV" starts a download; the spec waits for the download event and reads its first line.
- [ ] The formatted amount arrives as the PR says it should (raw or formatted), by `exportRenderer` where needed.
- [ ] The formula-like cell arrives escaped, and the pane shows it.
- [ ] The PR states what the export contains when a column is hidden or pinned, as observed. A result that contradicts #20380 is filed, not worked around.
- [ ] 1440 × 900 and 390 × 844; both themes; both buttons reachable by keyboard.
- [ ] **Look:** the first frame and one with the pane open, at both sizes, are on the PR, and the design seat reads them before code review.
- [ ] A catalog cover is shot with the producer of #20679 and is on `neomjs/pages` `main` before this PR merges: `publishes()` (`apps/portal/model/Example.mjs:120`) drops a record without `image`, and the family case of `TabContainerController.spec.mjs` turns red on one. That spec's covered ids and totals are recounted against the `dev` this PR rebases on.
- [ ] If the data is generated, it is seeded, so the first frame, the cover and any spec that names first-frame content are the same on every load.

## Out of Scope

Excel files, a selection-only export and remote pages (all left out by #20380); changes to `toCsv()` or `exportCsv()`.

## Avoided Traps

- **A button and nothing to see.** A download a visitor has to open proves little; the pane is the proof.
- **Exporting the rendered rows.** #20380 ruled it out: a buffered grid renders a window.
