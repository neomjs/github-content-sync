# Run the single-app Neural Link specs in CI without a Bridge

Terminal predicate: hosted CI drives the single-app Neural Link e2e specs through each page's own App Worker, with no Brain checkout and no WebSocket, and a production boot behaves exactly as before.

Graduated from D#18775 (`[GRADUATION_APPROVED]` by Euclid at DC_kwDODSospM4BKGYJ). The leaves carry the acceptance criteria and are linked natively.

## Problem

- **One class is both a service registry and a transport.** `ai.Client`'s `construct()` builds the six services and then calls `connect()` unconditionally (`src/ai/Client.mjs:155`). Every CI page of a `useAiClient: true` app opens a socket that cannot connect.
- **The suite pays for a Bridge it mostly doesn't use.** Hosted CI excludes Brain-gated specs from selection: 128 of 195 e2e spec files at Engine `1bb05f5426` (Euclid's STEP_BACK). The Discussion's census found the suite's NL calls >99% single-app, with 5 multi-window calls in the whole suite.
- **Why an epic:** the seam (engine), the harness adapter (test fixture), the contract specs, the CI selection and a production-artifact check land as separate, ordered PRs. The Bridge and headed tier stays #19655's.

## Intended solution (option F as the mechanism, option G as the sequencing)

- **One registered Client, explicit transport start.** `construct()` stops calling `connect()`; the App boot starts transport when `useAiClient` resolves true. No new registry class and no new transport class.
- **`useAiClient` keeps its meaning and its three forms** (`true`, an environment array, an environment string; `src/worker/App.mjs:782`). No consumer config moves. A new test-only flag (name open; precedent `allowVdomUpdatesInTests`, `src/DefaultConfig.mjs:244`) defaults to `false`, loads the registry without transport, and is the only thing that exposes a dispatch entry to the test harness.
- **Write envelope.** Every test call carries a fixture-minted `{agentId, sessionId}` pair in `parseAgentEnvelope`'s shape (`src/ai/Client.mjs:304`). An incomplete pair is refused before dispatch, so the legacy null context, which admits a write without a lock, is unreachable from the test entry.
- **Transport isolation, not a name denylist.** The test entry calls the six registered services' handlers unchanged, with no WebSocket and no Brain service. What the Brain owns stays Bridge-bound: connection auth and session stamping, routing and topology, disconnect delivery, transport recovery, `RecorderService` and the archive clients. Physical popup and placement journeys stay in the headed/Bridge tier (#19655).
- **Writer lifetime.** The fixture ends each test's pair through `Client#handleAgentDisconnected` (`src/ai/Client.mjs:272`), the same release and sweep an `agent_disconnected` frame runs, keyed on the full pair.
- **Addressing.** The adapter dispatches to the page's captured dedicated App Worker (precedent: `test/playwright/e2e/core/AiClientLateBridge.spec.mjs`), never by app name. `ConnectionService.waitForSession` stays a Bridge consumer (#19713 is why).
- **Placement.** The main-thread half lives in the test harness, never in `src/main/addon/`: every addon ships as a lazy chunk in every dist build.
- **Sequencing.** Dedicated-worker apps come first (the `DefaultConfig` default). The SharedWorker adapter is a named residual, not a silent mode change.
- **Coordination.** #20330 (under #20328) owns which e2e specs a PR runs; #19655 owns the Bridge/headed tier. The selection change moves specs out of the Brain-gated set and leaves both of those boundaries as they are.

## Decision Record

`Decision Record:` Not needed (D#18775 fold): `useAiClient` keeps its meaning and no consumer config moves. Reopening condition: an ADR is required if the seam grows past the six-service dispatcher or the test entry reaches a production build.

Decision Record impact: aligned-with `neomjs/neo#adr:extended-nl-multi-writer-write-enforcement` (the full writer pair, one heap authority, held until release).

## Out of Scope

- Multi-window journeys, `RecorderService`, perspectives and the archive clients: the Bridge tier, #19655.
- Moving the Bridge into the engine repo (option D) and direct service remotes (option C), both rejected in D#18775.
- Changing `useAiClient`'s meaning, or any production main-thread API.

## Avoided Traps

- **A main-thread addon in `src/main/addon/`** (option B as first written): it would ship in every dist build.
- **A window-name denylist as the safety boundary:** `InstanceService.callMethod` and `simulateEvent` reach the same effects, so the boundary is transport isolation.
- **Promising byte-identical production builds:** a new `DefaultConfig` key changes emitted bytes even while dormant. Parity is claimed only against a named before/after artifact pair.
- **Binding a test to its app by name:** `waitForSession(appName)` returned the oldest same-name session (#19713).

All six leaves target the authoritative ownership layers.
