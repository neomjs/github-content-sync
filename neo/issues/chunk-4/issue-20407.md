# IssuesShowcase AX test can read before the lazy menu triggers land

## Context

`grid/IssuesShowcase.spec.mjs`'s accessibility test has failed in three engine-tier runs since its trigger assertion landed in #20188 (PR #20190, 2026-10-31):
- [42037221880](https://github.com/neomjs/neo/actions/runs/42037221880), `dev` push `0091a91213`
- [41666963270](https://github.com/neomjs/neo/actions/runs/41666963270), `dev` push `d187157b83`
- [41647213436](https://github.com/neomjs/neo/actions/runs/41647213436), PR head `1063af45b6`

All three fail at the same assertion: `columnMenus` is `[]` where four `Filter …` triggers are expected. The row, cell and toolbar assertions before it pass in all three.

## The Problem

The test reads Chromium's accessibility tree once (`Accessibility.getFullAXTree`), as soon as `beforeEach` sees the first body row. The header menu triggers aren't part of that first render. `grid.header.Button#afterSetColumnMenu` imports `grid/header/plugin/Menu.mjs` lazily, and the plugin installs each trigger when it constructs. A read that lands between the rows and the plugin finds no trigger anywhere: `strayControls` passes and `columnMenus` is empty.

**Reproducer:** hold `src/grid/header/plugin/Menu.mjs` for 2.5 s with `page.context().route`. The test then fails 3/3 with the CI signature; without the hold it passes 3/3.

## The Architectural Reality

- `src/grid/header/Button.mjs` `afterSetColumnMenu`: the lazy `import('./plugin/Menu.mjs')`, then appends the plugin.
- `src/grid/header/plugin/Menu.mjs` `onOwnerConstructed`: creates the trigger (`neo-grid-menu-trigger`, `aria-label` `Filter <text>`) and pushes it into the header's vdom.
- `test/playwright/e2e/grid/IssuesShowcase.spec.mjs`: the one-shot read at the top of the AX test; `beforeEach` waits only for the first body row.

## The Fix

Before the AX read, wait until the grid holds its four `.neo-grid-menu-trigger` buttons. The read stays one-shot: the test asserts the settled tree, and the wait names the one part that settles late.

## Acceptance Criteria

- [ ] The AX test waits for the lazily installed menu triggers before it reads the tree.
- [ ] With `Menu.mjs` held 2.5 s, the test fails on `dev` and passes with the fix (receipt in the PR).
- [ ] The full `IssuesShowcase.spec.mjs` passes locally, repeated, and in CI.

## Out of Scope

- Loading the menu plugin eagerly. The lazy import keeps grids without column menus free of it.
- The older IssuesShowcase reds in #20330's receipt: they failed other tests in the file, before 2026-10-24.

## Avoided Traps

- **Polling the whole AX read until it matches.** It would also absorb a readiness gap nobody has seen, and hide which part settles late.
