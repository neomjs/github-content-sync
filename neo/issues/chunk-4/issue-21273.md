# Grid columns choose their header label's alignment

Please comment to claim before starting; check current assignees and linked PRs.

## Context

@neo-opus-vega saw it on #21240's 1440 px frame: the Amount values align right, and the Amount header label stays at the column's left edge.

Measured on `dev` `b1394d834c`: `examples/grid/export`, viewport 1440 × 900, headless Chromium through the e2e config. The Amount header spans x 863.8 → 1151.4. Its label spans 880.8 → 926.1, so its right edge sits **225 px** from the column's right edge. The first Amount cell's digits (`$6,143.50`) span 1082.5 → 1140.4, **11 px** from the cell's right edge. The header button computes `justify-content: flex-end` and `flex-direction: row-reverse`.

## The Problem

A reader matches a header to its numbers by position. Once columns flex, a right-aligned numeric column puts its label about 200 px from its digits. No setting moves the label today, so an app that wants its numeric headers over their digits has no way to get it. Engine examples with right-aligned columns include `grid/export`, `grid/bigData`, `grid/countries`, `grid/cellEditing`, `grid/filtering`, `grid/pinnedColumns` and `grid/treeBigData`.

## The Architectural Reality

- `src/grid/header/Button.mjs` declares `cellAlign_` ("Alignment of the matching grid cells"), validated by `beforeSetCellAlign` through `beforeSetEnumValue` against `static cellAlignValues`. Nothing in the header reads it, and nothing named `headerAlign` exists in `src/`.
- The cells' side: `src/grid/Row.mjs` adds `neo-<cellAlign>` to a cell's classes for any value other than `left`.
- `resources/css/src/grid/header/Button.css` lays the button out as a flex row with `justify-content: var(--grid-header-button-justify-content)`. The themes set it to `flex-end`, or `start` in `neo-dark`. The header's default `iconPosition: 'right'` adds `.icon-right`, which is `row-reverse` with the glyph margin `0 0 0 6px`. Every theme therefore puts the label at the left edge, with the sort glyph after it. The glyph keeps its space while hidden (`opacity: 0`).
- `src/grid/Container.mjs` has `columnDefaults`, so a column-level config also works grid-wide.
- **Design authority:** the operator's calls on this ticket (2026-11-17). Left-aligned headers are his own preference, so alignment becomes configurable and the default stays left. An `auto` value lets a header take the alignment of its body cells, so it is never configured twice. A grid with 100 columns of mixed alignment sets `columnDefaults: {headerAlign: 'auto'}` once, instead of repeating each column's alignment for its header. That rules out the other two options from the first version of this ticket: making the header follow `cellAlign` by default, and keeping it left with no setting.

## The Fix

1. `src/grid/header/Button.mjs`:
   - A reactive `headerAlign_: 'left'` with the values `auto`, `left`, `center` or `right`, validated like `cellAlign` (a `beforeSetHeaderAlign` through `beforeSetEnumValue`).
   - The effective alignment is `cellAlign` when `headerAlign` is `auto`, else `headerAlign`.
   - One method sets `neo-header-align-center` or `neo-header-align-right` on the header button from the effective alignment; `left` sets no class. Both `afterSetHeaderAlign` and `afterSetCellAlign` call it, so an `auto` header follows a `cellAlign` change at runtime.
   - `toJSON()` includes `headerAlign`.
   - The JSDoc says it aligns this header's label, and that `auto` takes `cellAlign`.
2. `resources/css/src/grid/header/Button.css`:
   - `neo-header-align-right` switches to `flex-direction: row` and `justify-content: end`, so the glyph comes first and the label sits at the right edge. The glyph's margin moves to its right side (`0 6px 0 0`), overriding `.icon-right`'s.
   - `neo-header-align-center` sets `justify-content: center`.
3. Without `headerAlign`, nothing changes: no theme variable changes, and every existing grid renders as on `dev`.

- [ ] AC-2: `headerAlign: 'center'` centers the label, within the hidden glyph's width.

## Out of Scope

- Making `auto` (or any other value) the default.
- The table's header (`src/table`).
- The examples' own column configs.

## Avoided Traps

- **Following `cellAlign` by default.** That would move every right-aligned header in every existing app. `auto` offers it as an opt-in instead.
- **A theme variable for alignment.** Alignment is a per-column property. A theme-wide variable cannot set one column right and its neighbour left.
- **Resolving `auto` once at construction.** `cellAlign` is reactive, so an `auto` header has to re-read it in `afterSetCellAlign`.
