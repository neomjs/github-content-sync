# The e2e Neural Link fixture fails every spec on a seat's fleet Bridge without naming NEO_NL_PORT

## Context

On a Fleet-managed seat, every Neural Link e2e spec fails before it starts. Each one closes with `Neural Link Bridge rejected authentication (code=1008, reason=Authentication required)`, and the run measures nothing about the code under test. The fix is known and is one variable: `NEO_NL_PORT=<free port>` makes the fixture spawn and route its own Bridge. But nothing says so, so each seat rediscovers it.

Observed occurrences:
- **2026-10-22:** `e2e/workstation` and `e2e/dashboard`, 146/146 red in 8 minutes (defect-note `MESSAGE:288155a2`).
- **2026-11-01:** neo-stage's `npm run clip` (defect-note `MESSAGE:6bfb2e9a`). Fixed for Stage's runners alone by neomjs/neo-stage#665.
- **2026-11-05 11:3xZ:** neo-agent-institution's `FleetObservatoryNL.spec.mjs`, 8/8 red (defect-note `MESSAGE:7188e10d`). That PR's body recorded the NL re-run as blocked.
- **2026-11-05 15:1xZ:** the same spec again, until the variable was rediscovered. With `NEO_NL_PORT=8191`, the arms pass.
- Maryam's #19960 evidence line carries the same port workaround.

## The Problem

A seat's environment exports `NEO_NL_PORT=8081`, because the seat's own Neural Link MCP server connects to the Fleet Manager's Bridge there. That Bridge runs in fleet mode: with `NEO_FLEET_BRIDGE_PUBLIC_KEY` provisioned, it demands a signed seat token. The e2e fixture reads the same port, finds that Bridge listening, joins it as role `test` without a token, and is refused with 1008. Each test then fails with the same disconnect. The first red's reason names authentication, but nothing names the variable that would fix it. The cost has repeated: a full battery run, then a misread, a defect-note, or a PR body recording a "blocked" receipt.

## The Architectural Reality

- `test/playwright/fixtures.mjs`, the `neuralLink` fixture: step "1. Ensure Bridge connects" calls `NeuralLink_ConnectionService.manageConnection({action: 'start'})`. The page's `neuralLinkUrl` is then routed to `aiConfig.port` (`routeConfig`).
- Brain `ai/services/neural-link/ConnectionService.mjs`, `ensureConnect`: it first joins any Bridge already on the port. On `authenticationFailed` without a Fleet token it tries `refreshBridgeCredentials()`, finds none, and rethrows. It spawns its own Bridge only when nothing answered.
- neomjs/neo#19065 (closed) made the page follow `NEO_NL_PORT`. That part works; the fixture only lacks the diagnosis.

## The Fix

In `test/playwright/fixtures.mjs`, catch the connect step's authentication failure from a Bridge this process did not spawn (`ConnectionService.bridgeProcess` is null). Rethrow it as one actionable error, stated once before any test runs. The error names three things:
- the port (`aiConfig.port`);
- the cause: a fleet-mode Bridge, the seat's own, requires a seat token the test runner does not hold;
- the remedy: `NEO_NL_PORT=<free port>`, so the fixture spawns its own Bridge and routes the page to it.

The original error stays as `cause`.

## Acceptance Criteria

- [ ] AC-1: A unit arm with a stub `ConnectionService` whose `manageConnection` rejects with `authenticationFailed` (no spawned process) fails with one error naming the port and `NEO_NL_PORT`. A stub that spawned its own Bridge, or failed for another reason, keeps its original error.
- [ ] AC-2: On a seat whose port answers with a fleet-mode Bridge, an NL spec run without `NEO_NL_PORT` stops with that one message, not N disconnects. The same run with `NEO_NL_PORT=<free port>` passes. Receipt in the PR.

## Out of Scope

- Making the fixture switch ports by itself. Changing `aiConfig.port` at runtime is the runtime mutation ADR-0019 forbids. A pre-config entrypoint choice of port is its own design question, and needs ADR-0019 read first.
- The seat environment's use of `NEO_NL_PORT` for its MCP server.
- neo-stage's runners, already isolated by neomjs/neo-stage#665.

## Avoided Traps

- **Unsetting `NEO_MCP_REMOTE_TOKEN` as the remedy.** The older recipe did this. It does not help the Bridge, and it reds the transaction-archive spec, which reads that token.
- **A per-repository workaround** in each consumer's Playwright config. The fixture is shared by every repository that imports `test/playwright/fixtures.mjs`, so the message belongs there once.
