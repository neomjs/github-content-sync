# Off-socket NL dispatch for SharedWorker apps

Part of #20370 (linked natively); graduated from D#18775 as the named residual of option G. Blocked by the adapter leaf.

## Context

The first adapter targets dedicated-worker apps, the `DefaultConfig` default. Workstation opts into SharedWorker, so its single-app specs stay Brain-gated until an adapter proves the same contracts there. D#18775 named this as a separate leaf so that the adapter never changes mode silently.

## The Architectural Reality

- `DefaultConfig` defaults to dedicated workers; Workstation opts into SharedWorker (D#18730 covers that boundary).
- The dedicated-worker adapter and its contracts (pair, refusal, lifetime) come from the adapter and contract-specs leaves.

## The Fix

An adapter path for a SharedWorker App Worker, under the same pair, refusal and lifetime contracts, then the selection change that marks those specs eligible.

## Acceptance Criteria

- [ ] A Workstation NL spec runs off-socket through the SharedWorker path with a fixture-minted pair, and teardown ends that pair.
- [ ] An incomplete pair is refused before dispatch on the SharedWorker path too.
- [ ] Two pages sharing one SharedWorker never receive each other's dispatches.
- [ ] Dedicated-worker specs are unchanged.
- [ ] The selection marks SharedWorker specs adapter-eligible only in this leaf's PR, with before/after counts.

## Out of Scope

Physical multi-window journeys (Bridge tier, #19655).
