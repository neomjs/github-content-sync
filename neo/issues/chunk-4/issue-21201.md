# The desktop container, taskbar and app window move into src

## Context

Leaf of #21198 that completes the shell. After #21199 (the window manager) and #21200 (the launcher and its apps tree), the demo still owns the pieces that put them together: `view/Desktop.mjs` (the workspace), `view/Taskbar.mjs` with the start button, `view/TaskList.mjs`, and `view/AppWindow.mjs`.

## The Problem

Without these pieces in `src/`, a consumer still assembles the shell by copying the demo, and the window manager has no owner but a consumer's controller.

## The Architectural Reality

- Design authority: n/a — moves and generalizes existing behavior; calls none of it wrong.
- `AppWindow` is a `dialog.Base` that grows out of its launcher icon (`animateTargetId`), stays inside the workspace (`boundaryContainerId`, `resizablePluginConfig`), and fires `headerAction` for minimize. Today its opener hands it a state provider with `data.app`, parented to the desktop's (`ViewportController.mjs:80`), and it binds `title: data => data.app.text`.
- The taskbar is a `toolbar.Base`. Its start button's `menu.List` reads the same apps store as the launcher, so every submenu honors the filter (#21062).
- Below 600px the taskbar shows icons only and windows fill the workspace; the demo's SCSS holds that.
- Styles: `resources/scss/src/apps/webdesktop/{AppWindow,Desktop,TaskList,Taskbar}.scss`, with neo-dark and neo-light variables.

## The Fix

- `src/desktop/AppWindow.mjs`: the dialog, with minimize, maximize and close. Its public input is a `record` config (title and icon come from it); any state provider stays internal. Its `@summary` carries the naming rule of #21198 and points at `Neo.manager.Window`.
- `src/desktop/TaskList.mjs`: a list over the tasks store; a click restores the window or brings it to the front through the manager.
- `src/desktop/Taskbar.mjs`: the start button with a `menu.List` over the apps store, the task list, and room for a consumer's own items (the demo's account chip, theme and permissions buttons).
- `src/desktop/Container.mjs`: the workspace, launcher and taskbar. It creates and owns the `Neo.desktop.WindowManager`, whose `windowClass` defaults to `Neo.desktop.AppWindow`, loaded lazily.
- `examples/desktop/basic`: three apps, no sign-in, built from `Neo.desktop.Container` and an apps store with no controller code of its own. It is the family's second consumer, the guide's source (#21202) and the theme leaf's surface (#21205).
- The demo's viewport becomes its sign-in plus a `Neo.desktop.Container`. Its controller keeps sign-in, permissions and theme, and hands the container the manager's `reset()` on sign-out.
- Styles move to `resources/scss/src/desktop/` with the neo-dark and neo-light variables, the phone layout included. The other three themes are #21205.

## Acceptance Criteria

- [ ] AC-1: The four classes exist under `src/desktop/` with `@summary` JSDoc, and the container owns the window manager.
- [ ] AC-2: `examples/desktop/basic` ships: three apps, no sign-in, no controller code of its own. An e2e spec on it opens an app, minimizes it, restores it from the taskbar, brings one of two windows to the front, and closes it.
- [ ] AC-3: The styles live under `resources/scss/src/desktop/` with the neo-dark and neo-light variables, the phone layout included; the demo keeps none of the shell's styles.
- [ ] AC-4: The demo is unchanged for its user: `test/playwright/e2e/webdesktop/PhoneAndTouch.spec.mjs` and the demo's unit specs pass, and its viewport holds only sign-in, the container and its own taskbar items.
