# Grid column types that read record[dataField] miss a nested dataField

## Context

A grid column's `dataField` may be a dotted path into an object field, such as `metrics.load` over a model that declares `metrics`. `Neo.grid.Row` reads a cell through `record.get(dataField)` (`src/grid/Row.mjs` l.169), and `Record#get` resolves the path (`src/data/RecordFactory.mjs` l.244–245), so a plain column shows the value. Sorting and filtering resolve dotted paths since #20275 and #20284, and cell editing on nested fields has its witness in #18981.

Nine column types read the value themselves, or match changes by a top-level name, and so miss the path. This was found while building a grid whose cells read an object field's members.

**Observed** in a unit run on `dev` `dd14f3fc51`, over a record `{load: 40, metrics: {load: 40}}`:

| | `dataField: 'load'` | `dataField: 'metrics.load'` |
|---|---|---|
| `record.get(dataField)` | 40 | 40 |
| `progress`: `applyRecordConfigs(column.component, record).value` | 40 | `undefined` |
| `tree`: `applyRecordConfigs({}, record).value` | 40 | `undefined` |
| `animatedChange`: `onRecordChange` for a change to `load` / `metrics` | matches | no match |

## The Problem

- **Eight types read `record[...]` directly**, and that misses a nested path:
  - `Progress#applyRecordConfigs` (`src/grid/column/Progress.mjs` l.36). `Component#cellRenderer` passes it the static `component` config, which carries no `value`, so the bar gets none.
  - The same read in `Sparkline` (l.44), `Tree` (l.82), `Icon` (l.40), `IconLink` (l.52), `LinkedIn` (l.40), `CountryFlag` (l.40), and `AnimatedCurrency` (l.83, `compareField || dataField`).
- **`AnimatedChange#onRecordChange`** matches a change by `field.name === me.dataField` (l.61). A change to `metrics` arrives as `{name: 'metrics'}`, so a column on `metrics.load` never animates.

## The Architectural Reality

- Rendered rows hold records, and `Record#get` resolves dotted paths.
- In Turbo Mode (`autoInitRecords: false`) an item can be a plain object without `get`. `Neo.ns(path, false, item)` resolves the same path on it. `Neo.grid.Body` already branches on `typeof record.get === 'function'` (l.736).
- The tree column's `value` feeds every tree-based column type, so its read is the widest of the eight.

## The Fix

- **`Neo.grid.column.Base`:** add one reader, for example `getRecordValue(record, field=this.dataField)`. It uses `record.get(field)` when `get` exists, and `Neo.ns(field, false, record)` otherwise.
- **The eight types** read through it instead of `record[...]`. `AnimatedCurrency` keeps its `compareField || dataField` choice and passes that field to the reader.
- **`AnimatedChange#onRecordChange`:** a change matches when its `name` is the `dataField` or the path's first segment. The column animates only when the value at the path differs between `oldValue` and `value`.

## Acceptance Criteria

- [ ] For each of the nine types there is a unit arm with a nested `dataField` over a record that holds the value, and the column shows (or animates on) it. A flat `dataField` behaves exactly as before.
- [ ] `AnimatedChange` animates when the nested value changes and stays still when only a sibling member of the same object changes.
- [ ] The existing grid unit and e2e tiers stay green. Their columns use flat fields.

## Out of Scope

- Cell editing on nested fields, done in #18981.
- How models declare nested fields.
- The table column types (`src/table/column/`), which are a separate surface.
