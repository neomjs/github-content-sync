# The first run of `npx neo-app` ends on the app, without webpack

Terminal predicate: a fresh `npx neo-app` on Engine 14 installs one dependency set once, builds only the development themes, starts a file server of the engine's own and shows the generated app, styled, without a click; and the time from Enter to that frame, measured from an empty npm cache on an ordinary machine, is stated in the release notes.

## Problem scope

The first run is the first impression the engine makes, on a person and on a coding agent alike. Measured on 2026-11-17 (`neo-app@13.4.1`, `neo.mjs@13.4.0`, Apple M5 Max, one run per condition): 64.4 s from an empty npm cache, 41.0 s with a warm one.

| Phase | Cold |
|---|---:|
| highlight.js step of `build-all`: an unpinned `git clone`, `npm install` of 447 packages, upstream's build script | 23.9 s |
| webpack, `dist/development` and `dist/production` | 11.3 s |
| workspace `npm i`, 520 packages | 9.8 s |
| `npx` fetching the generator, which lists the engine as a dependency it never imports | 6.6 s |
| a second `npm i` inside `node_modules/neo.mjs`, 525 packages | 6.2 s |
| `dist/esm` and the path check | 3.5 s |
| themes | 1.7 s |

What the run needs is far less. Dev mode reads one thing a build produces, the development themes (1.0 s). A full `build-all` passes without the nested install, which adds 491 MB. The engine as the only dependency installs in 1.7 s from an empty cache, and the generated app renders 0.2 s after navigation. And the run does not end on the app at all: `server-start` is `webpack serve --open`, which opens a directory listing of the workspace root, two clicks away from the app.

The dev server is also the heaviest tree in the lockfile. Of the engine's 560 lockfile entries, `webpack-dev-server` alone keeps 155 installed and webpack's four packages 211. Its config has no entry: it starts webpack to serve files.

**Why an Epic.** The outcome spans two repositories (the engine and the generator), its leaves break two live consumers at the merge and so land paired, and it is one measurable result: the run from Enter to the visible app.

## Intended solution shape

Selected in https://github.com/orgs/neomjs/discussions/21210 (Axes 1 and 2). @tobiu's input governs the cut: 14.0 is the window for breaking changes, and a clean cut with an upgrade note is preferred to a migration path. Compatibility binds within a major only.

1. **The generator builds what dev mode reads.** After the install it runs the development theme build and names `npm run build-all` for the three dist environments. Filed as neomjs/create-app#69.
2. **One install.** The generated `postinstall` loses its nested `npm i`; the scaffold declares the packages a postinstall or scaffold step imports, and the parity check asserts that (neomjs/create-app#68). The generator loses its own engine dependency (neomjs/create-app#61).
3. **The highlight.js bundle is built from the installed package** with esbuild (#21211). Under point 1 it leaves the first run; it stays in `build-all` and CI.
4. **A file server of the engine's own replaces `webpack serve`.** One engine leaf and one generator leaf.
   - The command line is chosen once and its callers move together: `npm run server-start -- --port <n> --no-open` keeps working for the six Playwright configs that start it, and `PORT` keeps selecting the port for the agent seats' launcher.
   - It serves the working directory with `.mjs` and `.wasm` MIME types and range requests, serves the engine's release-notes directory while every other dot-directory stays closed, and carries today's development-theme freshness warning.
   - With `--open` in a workspace it opens the app the generator wrote, not the root listing. That closes the directory-listing finding; the generator leaf owns it (`neomjs/create-app` `#72`).
   - The generator copies the docs app only on request. Row 1d selected `copyDocsApp` as opt-in, so the default first run copies nothing (`neomjs/create-app` `#72`).
   - `buildScripts/webpack/webpack.server.config.mjs` is deleted, not kept as a deprecated entry, and `webpack-dev-server` leaves the engine's and the generated dependency lists.
   - Named by the old path inside the engine: `.claude/launch.json`, `.github/workflows/classify-test-scope.yml`, two unit specs and a fixture, `buildScripts/create/component.mjs`, `buildScripts/README.md`, `learn/agentos/RunningTheFleetCockpit.md`, `learn/benefits/body/FourEnvironments.md`.
   - Two consumers break at the merge, not at the release, and land paired on the same day: the Institution, which follows the engine's `dev`, and one private package repository, whose `server-start` runs webpack with that path. devindex, Stage and pages move when they bump the engine. Thirteen other public repositories that name the path are pinned to engine 4 to 9 and are not reached.
5. **The package ships less, first step.** The engine's own `*.spec.mjs` files (13.9 MB in 1,066 files) and `apps/portal` (9.1 MB) leave the npm package, after a fresh workspace has shown that `test-unit`, `build-all` and `server-start` work with the Playwright configs and fixtures alone. `resources/examples` (13.9 MB) stays until `copy-examples`, which reads it, is decided.
6. **The bar and how it is measured.** From Enter on `npx neo-app` with the defaults accepted to the styled app visible on its own, the server start and the icon requests included, from an empty npm cache. Measured on two machines, one of them ordinary, and once under a slow network, with the conditions of every run reported (`neomjs/create-app` `#71`). Five seconds is the operator's target; today's single-machine numbers do not certify it.

**Gate for 14.0** (the steward of the cut, comment 19669790): the engine leaf, the generator leaf and the paired consumer changes are merged with the e2e suites green by Fri Nov 20, so the release reading runs them. If that fails, the row moves, and the next window is the operator's to name.

## Avoided traps

- **Keeping the old config path as a deprecated entry.** Rejected with the clean cut: the consumers that matter are few and named.
- **A dev-only dependency list** (row 2b). npm has no lazy dependency group, and a second list is a second thing to keep in step; removing trees reaches the same goal.
- **Loading the engine from a CDN** (row 2d). Every worker needs a same-origin shim, and the CDN copy carries no CSS.
- **Shipping built CSS in the package** (row 3b). It changes the rule that the package carries no generated output, for the engine's sheets only.
- **Building nothing and letting the server build on demand** (row 1c). The theme hook only warns today.
