# Emptying a locked grid region destroys the moved header button DOM and shifts GroupRow by 180px, and runtime column.locked splits a headerGroup across regions

## Context

During the Engine 13.4 release-gate verification matrix on `#20379` (*Grid columns can sit under a shared group header*, evaluated on `dev` at `ccb30d8d6e`), real-pointer Playwright + Neural Link testing on `examples/grid/headerGroups` surfaced critical layout/VDOM corruption when emptying a locked region (`Row 4`), group splitting when mutating `column.locked` at runtime (`Row 8`), and missing multi-leaf `locked: 'start'` group coverage in `examples/grid/headerGroups` (`Row 4` / `Row 7`).

## The Problem

Measured in Chromium + Neural Link on `examples/grid/headerGroups` (`dev` at `ccb30d8d6e`):

1. **Row 4A — Emptying `headerStart` / `headerEnd` (e.g. dragging `Region` from `locked: 'start'` into `center`) destroys the moved header button's DOM node and shifts all `center` group header cells by `180px`:**
   - When `Region` (`locked: 'start'`, `width: 180`) is dragged rightward and released over `May` (`center`), `Region.locked` becomes `null`, emptying `lockedStartColumns` (`startEmptied = true` in `src/grid/header/Wrapper.mjs:297-325`).
   - Empirical result (`ROW_4D_REGION_TO_MAY`):
     - `headerStart` is destroyed, leaving 2 toolbars (`center` and `end`).
     - In the DOM, `toolbar0` (`center`) renders only `["Mar","Jan","Feb","Apr","May","Jun","Jul","Aug","Sep","Oct","Nov","Dec","Id"]` — **`Region`'s `<button>` DOM node is completely missing from the live DOM!**
     - Meanwhile, in the App Worker, `headerToolbar.items` and `body.columnPositions` *do* contain `region` (`x: 0, width: 180`).
     - Because `GroupRow#project()` places `Q1..Q4` from `body.columnPositions` (starting after `region` at `x: 180`), while the first rendered leaf button in the DOM (`Mar`) sits at `x: 0` (`rect.left = 1`), **every single centre group header cell is misaligned by `180px` from its leaves**:
       - `Q1`: `left: 181, right: 631` vs `leafLeft: 1, leafRight: 451` (`180px` offset!)
       - `Q2`: `left: 631, right: 1081` vs `leafLeft: 451, leafRight: 901` (`180px` offset!)
       - `Q3`: `left: 1081, right: 1531` vs `leafLeft: 901, leafRight: 1351` (`180px` offset!)
       - `Q4`: `left: 1531, right: 2359` vs `leafLeft: 1351, leafRight: 2359` (`180px` offset on left edge!)
2. **Row 8 — Runtime `column.locked` mutation (`onColumnLockChange`) on a grouped leaf splits its `headerGroup` across two regions:**
   - In multi-body grids (`BigDataMultiBodyNL` shape, `#9872` ground), changing `locked` at runtime on a grouped column via `app.setProperties(janColId, {locked: 'start'})` (or `column.locked = 'start'` / `responsiveLockPolicy`) invokes `grid.Container#onColumnLockChange(column)` (`src/grid/Container.mjs:1275-1313`).
   - Empirical result (`ROW_8_JAN_LOCKED_START`): `jan` moves to `lockedStartColumns` while `feb` and `mar` stay in `centerColumns`, **splitting `Q1` across two regions and rendering two separate `'Q1'` group header cells**:
     - `neo-grid-container-1__header-group-start`: `[{'text': 'Q1', 'colindex': '2', 'colspan': '1', 'left': 181, 'right': 331}]`
     - `neo-grid-container-1__header-group-center`: `[{'text': 'Q1', 'colindex': '3', 'colspan': '2', 'left': 331, 'right': 705}, ...]`
   - This violates `#20379`'s core invariant (*"so the group stays in one region"*).
3. **Row 4 & Row 7 Example Surface (`examples/grid/headerGroups/MainContainer.mjs` & `neo-config.json`):**
   - `examples/grid/headerGroups/MainContainer.mjs:42-50` has an ungrouped `Region` under `locked: 'start'` and a single-leaf `Year` group (`Total`) under `locked: 'end'`, so no multi-leaf group under `locked: 'start'` is exercised in the example surface, and `examples/grid/headerGroups/neo-config.json` lacks `"useAiClient": true`.

## The Architectural Reality

- **Why `Region`'s DOM node disappears when `startEmptied` / `endEmptied` is `true` (`src/grid/header/Wrapper.mjs:297-325`):**
  1. `grid.Container#onColumnsMutate` (`src/grid/Container.mjs:1403`) calls `me.createOrUpdateSubGrids()`, which calls `headerWrapper.updateHeaders()`.
  2. In `Wrapper#updateHeaders` (`lines 300-303`), when `startEmptied` is `true`, `me.applyColumnButtonOrder(lockedStartColumns, centerColumns, lockedEndColumns)` runs *before* `headerStart` is destroyed.
  3. Inside `applyColumnButtonOrder`, `headerToolbar.insert(index, button)` calls `Container#insert(index, item, silent=false)`:
     - `headerStart.remove(button, true)` removes `button`'s `{componentId: button.id}` reference from `headerStart.vdom.cn` **silently** — so `headerStart.vnode` is **not** updated and still contains `button`'s full expanded `vnode`!
     - `headerToolbar.insert` adds `{componentId: button.id}` to `headerToolbar.vdom.cn` and triggers `headerToolbar.promiseUpdate()`, which coalesces into `headerWrapper.promiseUpdate()` (scheduled for the next microtask).
  4. Immediately on `lines 307-320` of `Wrapper#updateHeaders` (synchronously in the same tick, before `promiseUpdate` runs!):
     ```javascript
     if (startEmptied) {
         retired[me.headerStart.id] = me.headerStart.vnode;
         me.headerStart.destroy();
         me.headerStart = null
     }
     ...
     me.vnode && VNodeUtil.unlinkRetiredReferences(me.vnode, retired)
     ```
     Because `headerStart.vnode` still holds `button`'s vnode child, `VNodeUtil.unlinkRetiredReferences(me.vnode, retired)` inlines `headerStart.vnode` (including `button`'s vnode!) into `me.vnode`. When the VDOM worker diffs `me.vdom` against `me.vnode`, or when the main thread removes the retired `headerStart` DOM element after `moveNode`, `button`'s physical DOM node is destroyed along with `headerStart`!
  5. Furthermore, `onColumnsMutate` (`src/grid/Container.mjs:1414`) calls `me.headerWrapper.applyColumnButtonOrder(...)` a second time right after `createOrUpdateSubGrids()`.
- **Why runtime `column.locked` splits a group (`src/grid/Container.mjs:1275-1313`):**
  - `flattenColumns` (`src/grid/Container.mjs:1106-1116`) copies `entry.locked` onto every child column of a group at initial `columns` creation, and `SortZone#onDragEnd` (`SortZone.mjs:419-420`) keeps `column.locked` when a grouped leaf is dragged. However, `grid.Container#onColumnLockChange(column)` (`src/grid/Container.mjs:1275`) only re-sorts `me.columns` after a single `column.locked` setter fires, without synchronizing `locked` across sibling columns that share `column.headerGroup.id`.

Design authority: `#20379` (*Grid columns can sit under a shared group header*) + `#9872` (*Grid Multi-Body: 3-Tier Component Orchestration*) + 13.4 release-gate verification matrix (Rows 4 & 8).

## The Fix

1. **Preserve moved header button DOM nodes when `headerStart` or `headerEnd` empties (`src/grid/header/Wrapper.mjs:297-325`):**
   - Before capturing `retired[me.headerStart.id] = me.headerStart.vnode` (and `headerEnd.vnode`), strip any re-homed child button vnodes from the retiring toolbar's `vnode` (or sync the retiring toolbar's `vnode` after `applyColumnButtonOrder` removes its buttons) so `VNodeUtil.unlinkRetiredReferences` only retires the emptied toolbar shell (`headerStart` / `headerEnd`), never the button vnodes that just moved into `headerToolbar`!
2. **Keep `headerGroup` columns in one region on runtime `column.locked` changes (`src/grid/Container.mjs:1275-1313`):**
   - In `grid.Container#onColumnLockChange(column)` (or `column.Base#afterSetLocked`), when `column.headerGroup` is present, propagate `column.locked` (silently, `_locked = column.locked` + `vdom` sync) to every sibling column in `me.columns` sharing `column.headerGroup.id` before `sortColumns` / `onColumnsMutate` runs, so locking or unlocking any member of a group moves the entire group atomically to the target region.
3. **Update `examples/grid/headerGroups` (`MainContainer.mjs` & `neo-config.json`) (Rows 4 & 7):**
   - Enable `"useAiClient": true` in `examples/grid/headerGroups/neo-config.json` and include a `locked: 'start'` group (or group `Region` + an adjacent start column, preserving clear test geometry) so both `locked: 'start'` and `locked: 'end'` header groups are represented on the example surface.

## Acceptance Criteria

- [ ] **AC-1 (Row 4A — Emptying a locked region preserves button DOM & group alignment):** When the last ungrouped column in `headerStart` or `headerEnd` is unlocked / dragged into `center`, its `.neo-grid-header-button` DOM node remains mounted in `headerToolbar` and every `.neo-grid-header-group-cell` aligns within `< 2px` of its first and last leaf button (e2e).
- [ ] **AC-2 (Row 8 — Runtime `column.locked` is group-atomic):** Mutating `column.locked` at runtime on a grouped leaf (e.g. via `setProperties` / `column.locked = 'start'`) moves all leaves sharing `column.headerGroup.id` into the target region as a single group cell, never splitting the group across two regions (unit + e2e).
- [ ] **AC-3 (Row 4 & Row 7 — Example surface):** `examples/grid/headerGroups` includes a `locked: 'start'` group as well as `center` and `locked: 'end'` groups, and `examples/grid/headerGroups/neo-config.json` sets `"useAiClient": true`.

## Out of Scope

- Within-toolbar `SortZone` swap guards and group-cell drag reorder (tracked in the sibling `SortZone` / `GroupRow` bug ticket under `#20379`).
- Column resize on `flex` columns and live mid-drag `GroupRow#project()` (tracked in the sibling `Resizable` / `Body` bug ticket under `#20379`).

## Avoided Traps

- **Passing `retired[me.headerStart.id] = me.headerStart.vnode` after silent child removal:** `Container#remove(item, true)` mutates `vdom.cn` without pruning `vnode.childNodes`, so `VNodeUtil.unlinkRetiredReferences` inlines the moved button's old `vnode` inside the retiring toolbar's `vnode`, causing the VDOM diff to delete the moved button from the DOM when the retiring toolbar is removed.
