# `server-start` runs a file server of the engine's own

No curated labels: it is a cut item for Engine 14 and has to be merged by Fri Nov 20, paired with two consumer changes.

## Context

`npm run server-start` is `webpack serve -c ./buildScripts/webpack/webpack.server.config.mjs --open`. The config has no entry: webpack is started to serve the working directory. `webpack-dev-server` alone keeps 155 of the engine's 560 lockfile entries installed (28 %). In a generated workspace the same script ends the first run on a directory listing of the workspace root.

Sub of #21213 (its intended solution, point 4). Source: https://github.com/orgs/neomjs/discussions/21210, row 1d. @tobiu's input governs the cut: 14.0 is the window for breaking changes, a clean cut with an upgrade note and no deprecated entry.

## The Problem

A dev server that bundles nothing costs the engine and every workspace its largest dependency tree, and with it the upkeep that tree brings: of 58 Dependabot pull requests since 2026-08-17 that name one package, 5 sit in this tree. Dev mode needs files served, a few headers, and one warning.

## The Architectural Reality

- `package.json:54` defines `server-start`; `package.json:52` runs `buildScripts/util/check-installed-dependencies.mjs` before it (`preserver-start`); `package.json:144` lists `webpack-dev-server`.
- `buildScripts/webpack/webpack.server.config.mjs` does four things besides starting webpack: it serves `process.cwd()` statically with `watch: false` (`:156` to `:169`); it reads the port from `process.env.PORT` (`:141`), which is how an agent seat's launcher tells the server its port; it serves the engine's release-notes directory at its own path while the static server keeps every other dot-directory closed (`:144` to `:154`); and it exports `createDevelopmentThemeFreshnessHooks` (`:43`), which warns about stale development themes at startup and at most once per interval while theme CSS is requested. The hook warns; it builds nothing.
- Callers of the script, all with the same flags, `npm run server-start -- --port ${PORT} --no-open`: `test/playwright/playwright.config.mjs:52`, `playwright.config.clipboard.mjs:39`, `playwright.config.component.mjs:38`, `playwright.config.e2e.mjs:106`, `playwright.config.matrix.mjs:66`, `playwright.config.visual.mjs:65`.
- Named by the config path: `.claude/launch.json:7` (it runs `npx webpack serve -c …` directly), `.github/workflows/classify-test-scope.yml` (`:216`, `:270`, `:275`, `:406`), `test/playwright/unit/buildScripts/util/WorkflowScopeClassifier.spec.mjs:952`, `test/playwright/unit/buildScripts/util/developmentThemeAssets.spec.mjs` (it imports the hook from the config file, `:12` to `:14`), `test/playwright/unit/buildScripts/fixtures/neoAppPackage.json:37`, `buildScripts/create/component.mjs:198`, `buildScripts/README.md`, `learn/agentos/RunningTheFleetCockpit.md`, `learn/benefits/body/FourEnvironments.md`.
- `src/index.js` exists only as webpack's default entry for this server.
- Every arm of the first-run measurement rendered the generated app on a 40-line Node file server.
- `Design authority: "**Script:** `webpack serve -c ./buildScripts/webpack/webpack.server.config.mjs --open`"` (`buildScripts/README.md`, the section on `npm run server-start`). The record makes today's behavior intended; this ticket changes the record with the behavior, as selected in #21213.

## The Fix

A Node script under `buildScripts/` (its placement is the implementer's, per `structural-pre-flight`) serves the working directory and replaces `webpack serve` in `server-start`. `webpack-dev-server` leaves `package.json` and the lockfile. `buildScripts/webpack/webpack.server.config.mjs` and `src/index.js` are deleted. The freshness hook moves to a module of its own, so its spec keeps importing it without the server.

## Out of Scope

- The generator's side (its `server-start`, its `webpack-dev-server` entry, opening the generated app): the generator leaf under #21213.
- webpack as the builder of `dist/development` and `dist/production`: deferred in the source Discussion until a measurement exists.
- Building stale themes on request: the hook keeps warning only.

## Avoided Traps

- **Keeping the old config as a deprecated entry.** Rejected with the clean cut; the live consumers are few and named.
- **A server dependency from npm.** The point is fewer packages; `node:http` covers the contract.
- **Hot reload.** The engine does not use it; `watch` is already `false`.
