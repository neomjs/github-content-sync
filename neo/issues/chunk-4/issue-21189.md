# A grid example pages, sorts and filters against a simulated server

Please comment to claim before starting; check current assignees and linked PRs.

## Context

New example 5 of the Grid & Table slate ([#21142](https://github.com/neomjs/neo/issues/21142#issuecomment-6924949418)), a leaf of #21175 (the Grid & Table group, under #21140). The visitor's question: how does the grid page, sort and filter against an API?

No `good first issue` label: where the simulated server lives is settled at intake (The Fix, step 1).

## The Problem

Every example of the group holds all its rows in the browser. A buyer with a million rows behind an API cannot see the grid ask a server for one page. The store can: `pageSize`, `remoteSort` and `remoteFilter`. The one example that tries, `examples/toolbar/paging`, calls a backend no static host has and opens with headers and zero rows. And `examples/serverside/gridContainer` loads a view's config from JSON, which is not a server-side row model (#20500 named that trap).

## The Architectural Reality

- `src/data/Store.mjs` on `dev` `c40689ef53`: `currentPage_` (`:174`), `pageSize_` (`:222`), `remoteFilter` (`:244`), `remoteSort` (`:250`), `totalCount` (`:260`). `load()` (`:1204`) builds `{page, pageSize}` (`:1230`), adds the filters and the sorters when they are remote (`:1237`, `:1241`), reads through the store's pipeline (`:1305`) and takes `items` and `totalCount` from the response (`:1310`).
- A pipeline is a connection, a parser and a normalizer (`learn/guides/datahandling/DataPipelines.md`); the connections are under `src/data/connection/`.
- The paging toolbar is `src/toolbar/Paging.mjs`. `examples/toolbar/paging` shows its config, with `api: 'MyApp.backend.UserService'` on the store (`store/Users.mjs:18`).
- The gate of 7 Nov on #20498 counts a server-side example only with a backend a static host can serve.
- `examples/grid/headerGroups` is the model for the page. Placement: a sibling folder `examples/grid/<feature>/`.
- Design authority: n/a, a new example.

## The Fix

1. **The server is simulated inside the example.** Intended shape: a connection class in the example's folder that answers a read with one page of a generated dataset of 100,000 rows, sorted and filtered as asked, with the total count, after a short delay. Confirm at intake that a store's pipeline takes a connection of the example's own. If it does not, file the gap as its own ticket and say so here; a service worker that fakes HTTP is not the fallback, since the engine has a service worker of its own.
2. **A new folder `examples/grid/serverSide`** with a grid, the paging toolbar, sortable headers and one filter.
3. **A request line in the frame**, for example "page 3 · sort: amount, descending · filter: country = DE · 50 of 12,431 rows · 40 ms", updated on every request, so a visitor sees that each gesture asks the server.
4. A new catalog record with the group `grid-table`, and a `scope` that says the server is simulated.

## Acceptance Criteria

- [ ] The store never holds more than one page: after any gesture its count equals the page size, while the frame shows the total.
- [ ] A page change, a header sort and a filter each produce one request with the expected parameters; a spec under `test/playwright/e2e/grid/` asserts all three.
- [ ] The delay shows the grid's loading state, and the request line updates.
- [ ] The example runs from a static host, with no server process.
- [ ] The caption and the frame say that the server is simulated.
- [ ] 1440 × 900 and 390 × 844; both themes; paging by keyboard.
- [ ] **Look:** the first frame and one taken mid-request, at both sizes, are on the PR, and the design seat reads them before code review.
- [ ] A catalog cover is shot with the producer of #20679 and is on `neomjs/pages` `main` before this PR merges: `publishes()` (`apps/portal/model/Example.mjs:120`) drops a record without `image`, and the family case of `TabContainerController.spec.mjs` turns red on one. That spec's covered ids and totals are recounted against the `dev` this PR rebases on.
- [ ] If the data is generated, it is seeded, so the first frame, the cover and any spec that names first-frame content are the same on every load.

## Out of Scope

Engine changes to the store, the pipeline or the paging toolbar; a real backend; infinite scrolling over remote data; repairing `examples/toolbar/paging`.

## Avoided Traps

- **Loading everything and sorting locally.** It looks the same and proves nothing; the first criterion catches it.
- **A JSON file per page.** It cannot sort or filter.
- **Hiding that the server is simulated.** A developer opens the network tab.
