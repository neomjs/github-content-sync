# The desktop family looks right in the cyberpunk, dark and light themes

## Context

Leaf of #21198. The refactoring leaves (#21199, #21200, #21201) move the shell's styles into `resources/scss/src/desktop/` with the neo-dark and neo-light variables the demo has. Engine families carry variables for every theme they ship: `timeline` covers all five, and `dialog`, `menu` and `toolbar` cover at least dark, light, neo-dark and neo-light.

## The Problem

The desktop family has no look in cyberpunk, dark or light. Those are new designs, not moves, so they do not belong inside refactoring pull requests (Mnemosyne's review of #21198).

## The Architectural Reality

- Design authority: n/a — adds theme variables to a new family; calls nothing wrong.
- Theme variables live under `resources/scss/theme-<name>/<family>/`; `resources/scss/theme-*/timeline/` is the nearest complete sibling.
- `examples/desktop/basic` (#21201) is the surface to judge the look on.

## The Fix

Variables for every class of `src/desktop/` in `theme-cyberpunk`, `theme-dark` and `theme-light`, read against the neo themes the family already has and against each theme's own families (taskbar against `toolbar`, start menu against `menu`, windows against `dialog`).

## Acceptance Criteria

- [ ] AC-1: Every class of `src/desktop/` has variables in `theme-cyberpunk`, `theme-dark` and `theme-light`.
- [ ] AC-2: The pull request shows `examples/desktop/basic` in all five themes, with a window open and the start menu open, on a desktop width and a phone width.
- [ ] AC-3: The demo's look in neo-dark and neo-light is unchanged.

## Out of Scope

New desktop features; changes to the neo-dark and neo-light looks.
