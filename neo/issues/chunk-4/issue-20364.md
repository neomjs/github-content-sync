# Align grid.Row and table.Body cell component renderer lifecycle

## Context

Following the merge of PR #20352 (resolving #4574 — `Neo.table.Body#applyRendererOutput` support for `Neo.component.Abstract` instances and `{module}` / `{className}` / `{ntype}` config descriptors), an architectural comparison between `src/table/Body.mjs` and `src/grid/Row.mjs` surfaced three concrete parity and lifecycle gaps across the two `applyRendererOutput()` implementations:

1. **`Neo.grid.Row#applyRendererOutput` (`src/grid/Row.mjs:224`) rejects `Neo.functional.component.Base` instances:**
   `src/grid/Row.mjs:224` checks `if (rendererOutput instanceof Neo.component.Base)`. Because `Neo.functional.component.Base` (`src/functional/component/Base.mjs:19`) extends `Neo.component.Abstract` (`src/component/Abstract.mjs`) rather than `Neo.component.Base`, a functional component returned by `Neo.grid.column.Component#cellRenderer` (`src/grid/column/Component.mjs:104-185`) or a custom `grid.Row` renderer fails the `instanceof` guard, skips `me.components[column.dataField]` registration, and is not converted via `rendererOutput.createVdomReference()`.
2. **`Neo.table.Body` (`src/table/Body.mjs:160-173`) forwards `theme` and `windowId` to `createdCellComponents`, but omits `mounted`:**
   Like `Neo.grid.Row` (`src/grid/Row.mjs:97-141`), `Neo.table.Body` extends `Neo.component.Base` rather than `Neo.container.Base`. While `table.Body` forwards `theme` (`afterSetTheme`, lines 160-163) and `windowId` (`afterSetWindowId`, lines 170-173) to `this.createdCellComponents`, it lacks `afterSetMounted(value, oldValue)` forwarding (`component.mounted = value`).
3. **`Neo.table.Body#applyRendererOutput` (`src/table/Body.mjs:226-234`) omits `component` from the `column.renderer` payload:**
   `Neo.grid.Row#applyRendererOutput` (`src/grid/Row.mjs:193`) passes `component: me.components?.[column.dataField]` into `column.renderer.call(...)` so renderers can inspect or update an existing cell component directly. `Neo.table.Body#applyRendererOutput` already resolves `cellId` before calling `column.renderer` (`lines 215-222`), so passing `component: me.createdCellComponents?.get(cellId)` gives `table` renderers the same reuse hook.

## The Problem

- In `Neo.grid.Row`, using a `Neo.functional.component.Base` subclass inside `Neo.grid.column.Component` or returning one from a `column.renderer` produces a raw `NeoInstance` in `cellConfig.cn` instead of `[rendererOutput.createVdomReference()]`, breaking VDOM reference expansion and pooled row lifecycle forwarding (`forwardToCells`).
- In `Neo.table.Body`, config-created cell components inside `createdCellComponents` do not receive `mounted = true` / `false` when the owning `table.Body` mounts or unmounts, and `column.renderer` cannot inspect the existing `component` instance for `cellId` on re-render.

## The Architectural Reality

- `Neo.grid.*` remains the virtualized, Fixed-DOM-Order row/cell-pooled surface (`src/grid/Row.mjs`, `src/grid/column/Component.mjs`), while `Neo.table.*` (`src/table/Body.mjs`) remains the lightweight unpooled HTML `<table>` surface.
- Both `Neo.component.Base` and `Neo.functional.component.Base` inherit from `Neo.component.Abstract` (`src/component/Abstract.mjs`), which defines `createVdomReference()`, `mounted`, `theme`, and `windowId`.
- Both `Neo.grid.Row` and `Neo.table.Body` extend `Neo.component.Base` (not `Neo.container.Base`), so both must explicitly relay `mounted`, `theme`, and `windowId` to the cell components they own.

## The Fix

1. **`src/grid/Row.mjs`:**
   - Import `AbstractComponent from '../component/Abstract.mjs'`.
   - In `applyRendererOutput` (`src/grid/Row.mjs:224`), widen `if (rendererOutput instanceof Component)` (`Neo.component.Base`) to `if (rendererOutput instanceof AbstractComponent)`.
2. **`src/table/Body.mjs`:**
   - Add `afterSetMounted(value, oldValue)` to forward `mounted` to `this.createdCellComponents` (`this.createdCellComponents?.forEach(component => component.mounted = value)`), matching `afterSetTheme` and `afterSetWindowId`.
   - In `applyRendererOutput` (`src/table/Body.mjs:226-234`), include `component: me.createdCellComponents?.get(cellId)` in the `column.renderer.call(...)` config object, matching `src/grid/Row.mjs:193`.
3. **Unit Tests:**
   - Extend `test/playwright/unit/table/BodyRendererOutput.spec.mjs` to verify `afterSetMounted` forwarding to `createdCellComponents` and `component` payload delivery into `column.renderer`.
   - Add unit coverage in `test/playwright/unit/grid/` verifying `Neo.grid.Row#applyRendererOutput` with a `Neo.functional.component.Base` instance (both `me.components[column.dataField]` registration and `{componentId}` VDOM reference emission).

## Acceptance Criteria

- [ ] `Neo.grid.Row#applyRendererOutput` checks `rendererOutput instanceof AbstractComponent` (`Neo.component.Abstract`) so `Neo.functional.component.Base` instances register in `me.components[column.dataField]` and emit `{componentId}` VDOM references.
- [ ] `Neo.table.Body#afterSetMounted` forwards `mounted` state changes to `this.createdCellComponents`.
- [ ] `Neo.table.Body#applyRendererOutput` passes `component: me.createdCellComponents?.get(cellId)` in the `column.renderer` payload.
- [ ] Playwright unit tests cover `Neo.functional.component.Base` in `grid.Row#applyRendererOutput` and `afterSetMounted` + `component` renderer argument in `table.Body`.

## Out of Scope

- Duplicating `Neo.grid.column.*` classes inside `src/table/`.
- Introducing row/cell pooling to `Neo.table.Body`.
