# Demo B rejects the header-only proxy's valid pane transfer

## Context

The focused external-Brain evidence work on #17844 now reaches Demo B's cross-window proof. `DemoBPerspectivesNL` retains the original pane but reads mount count 3 where its endpoint expects 2. An oracle-preserving cold-gesture diagnostic at Engine `bfd1d262b2` captured the actual executor receipt:

| Stage | Pane mount delta |
| --- | ---: |
| Source → live vessel | 1 |
| Vessel → target header proxy | 0 |
| Final target document | 1 |
| Total | 2 |

The target embodiment is header=true, ownsPane=false, settled=true and visible=true. Same-instance, non-reset frames, source removal, target placement, one transfer and source-drop suppression all pass. The receipt rejects only “target proxy added exactly one mount” and “vessel, proxy and final target each mounted once”.

## The Problem

The example's post-transfer oracle still requires the old pane-owning proxy (proxy +1, total +3). The accepted header-only proxy carries no pane mount. This rejects a valid committed transfer and prevents the perspective tour from continuing. The cold cross-window witness mirrors those stale numbers; the perspective endpoint still assumes only one transfer mount.

## The Architectural Reality

- `DemoBWorkspace#commitCrossWindowTransfer` already captures pre-gesture, settled vessel, settled proxy and final target counters; its existing deltas isolate every stage.
- `VesselEmbodiment`'s header branch renders a header and never stages the pane. Its snapshot exposes header, ownership, settlement, visibility and window identity.
- `DemoBCrossWindowDragNL.spec.mjs`'s cold arm reads the complete receipt; its round-trip arm already expects header-only ownership.
- `DemoBPerspectivesNL.spec.mjs` owns the paced tour and deterministic no-pause replay.

Design authority: ADR 0029 §2.8.6 says “the live pane stays in the parked vessel until the drop”; merged PR `#19254` implemented that contract. The current stage receipt matches it.

## The Fix

Align the example-owned proof and its two dependent E2E witnesses with the header-only path. Explicitly prove a settled visible header proxy for the correct item and target that does not own the pane, then require stage deltas 1/0/1 and total 2. Retain single-commit/drop suppression, document ownership, identity and frame checks. The perspective endpoint must count the vessel and final-target mounts; the tour and replay must then finish.

Prescription checked: restore the existing host oracle; changing the engine or removing proof would treat the symptom.
