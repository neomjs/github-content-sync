# Stream and Fetch miss a workspace's relative data URLs in dev mode

## Context

Found on 2026-10-06 while deploying DevIndex's environments (neomjs/devindex#60). @neo-opus-grace first diagnosed it on 2026-08-19 but never filed it. DevIndex is a workspace: `neo.mjs` is a dependency under `node_modules/neo.mjs`, as in every `npx neo-app` workspace.

## The Problem

In a workspace's dev mode the page sits at `apps/<app>/` and the workers run from `node_modules/neo.mjs/src/worker/`. A worker resolves a relative URL against its own script. So DevIndex's store URL, `Neo.config.basePath + 'apps/devindex/resources/data/users.jsonl'` with `basePath: '../../'` written for the page, lands at `node_modules/neo.mjs/apps/devindex/resources/data/users.jsonl`.

Measured in headless Chromium on 2026-10-06, against the devindex workspace on `neo.mjs` 13.1.0:
- **At an origin root,** dev mode fetches `/node_modules/neo.mjs/apps/devindex/resources/data/users.jsonl` and gets a 200. That is only because `neo.mjs@13.1.0` still ships DevIndex's own data, the copy #17240 later removed. The grid shows that stale copy instead of the workspace's index, and nothing turns red.
- **Under a mount** (`/devindex/`), the same fetch is a 404 and the grid stays empty.
- **From 13.2.0,** which no longer ships `apps/devindex`, it is a 404 at an origin root too.

The engine already compensates for this offset in two places, each its own way:
- `src/data/connection/Xhr.mjs:186` prefixes `../../` to a relative URL when the worker runs inside `node_modules/neo.mjs`. It applies to Xhr only, and it keys on the hostname (`!location.href.startsWith('https://neomjs.com/')`).
- `src/worker/App.mjs:746` does the same for the theme map, keyed on `Neo.config.workerBasePath` containing `node_modules`.

`src/data/connection/Fetch.mjs:115` and `src/data/connection/Stream.mjs:71` pass the URL to `fetch()` unchanged.

## The Architectural Reality

- `Neo.data.connection.Base` is the shared base of `Fetch`, `Stream` and `Xhr`.
- `basePath` stays page-relative. The Stylesheet addon depends on its relative form (`basePath.substring(6)`), and an absolute `basePath` broke DevIndex's boot when measured on 2026-08-19.
- A fixed `../../` fits only a page two levels below the workspace root. A nested child app (four levels, as in neomjs/multiwindowcolors) already reaches the root from the worker without a prefix, so a fixed prefix overshoots there.

## The Fix

The connections resolve a relative URL the way the page that wrote it would. One rule lives in `Neo.data.connection.Base`, and `Fetch`, `Stream` and `Xhr` all use it. It covers every page depth, and it replaces Xhr's hostname branch.

The design choice is how a worker learns the page's location. Main knows the document URL, and the worker manager already sends each window's config at registration, so main can hand the page's base URL to the workers there. The connection then resolves a relative URL against it with `new URL(url, base)`. Whoever implements this confirms the delivery path, the multi-window case included, before building.

## Acceptance Criteria

- [ ] `Fetch`, `Stream` and `Xhr` resolve a relative URL from a workspace's dev-mode worker to the same URL the page would, for a page two and four levels below the workspace root. Specs pin both depths.
- [ ] Xhr's hostname branch is gone.
- [ ] The engine repo's own apps fetch exactly as before; existing specs stay green.
- [ ] After a release, DevIndex's dev mode paints its grid from the workspace's own index (neomjs/devindex follow-up).

## Out of Scope

- `basePath` itself, and the Stylesheet addon's relative paths.
- Direct `fetch()` calls in app code outside the connections.
