# Move popup-close return and replay into the Dock engine

## Context

Merged PR #19292 (`91fd23336d20cbe17f95d8e357c9f9a15be34181`) makes Workstation return a physically closed popup's panes to the main layout in one undoable Group transaction. The operator selected that behavior and then requested this follow-up: why does reusable multi-window transaction behavior live in custom app code, and which part belongs in `manager.Transaction` versus `dashboard/dock/*`?

This is a placement and reuse correction to the shipped behavior, not a new close-policy decision.

## The Problem

Workstation now assembles an all-pane document transfer, guards it against queued writes and successor bindings, correlates close versus reload, routes reconnect-lease expiry, and implements native undo/redo effects. Another Dock consumer must reproduce that orchestration to offer the same policy.

Moving the whole method into the generic transaction manager would put dock item, home and tab semantics below their existing domain boundary. Moving it verbatim behind an app-shaped engine wrapper would preserve the duplication in another directory.

## The Architectural Reality

Read at the merged implementation's source:

| Existing owner | Responsibility and current seam |
|---|---|
| `src/manager/Transaction.mjs` class contract; `write`, `undo`, `redo` | Logical Groups, serialized transactions, opaque participants, binding generations and one history cursor. Explicitly knows **no dock document or app class**. |
| `src/manager/transaction/Commit.mjs#run` | Captures participant values at queue head, prepares/adopts/compensates atomically, publishes a snapshot, then reports projection/effect failures separately. Replay supplies `replayRow`. |
| `src/manager/transaction/NativeLifecycle.mjs` | Group-owned admission, connection and retirement records; source-contributed effects. Its existing `onLeaseExpired` handles provisional admissions, not the app's formerly-bound recovery path. |
| `src/dashboard/dock/window/WorkspaceSet.mjs#register/transfer` | Adapts dock reducers to the participant protocol; a transfer already reduces from both captured documents. It owns no parallel membership registry. |
| `src/dashboard/dock/window/NativeVesselTransaction.mjs` and `Workspace#bindNativeWindowSource` | Shared native effect routines and Dock composition seams. The closed predecessor #18651 established a callable reuse path rather than requiring all hosts to inherit the same view. |
| `apps/workstation/view/VesselWorkspace.mjs#onNativeWindowRelease/returnClosedPopupWorkspace`; `PopupWorkspace#projectDockCommit`; `WorkspaceController#onPopupLeaseExpired` | Current app-side orchestration to retire or reduce. |
| `src/Main.mjs#windowNativeIsClosed` | Existing exact-handle physical observation, including unknown outcomes. Reuse it; disconnected is not synonymous with closed. |

## The Fix

Deliver the extraction and Workstation migration together in one PR.

1. **Keep the transaction authority generic.** Reuse `Transaction` / `Commit` for the queue, captured state, atomic adoption, cursor and effect receipts. Any necessary generic lifecycle hook belongs with the existing Group owner and carries opaque identities; it must not import Dock or interpret pane-return descriptors.
2. **Put Dock semantics in the Dock adapter.** Extend the existing `WorkspaceSet` preparation path for an atomic all-pane return using `model/Operations`. Prefer preparation from queue-head captures over transplanting Workstation's precompute/version/retry loop. Compose correlated native replay through the existing Dock window/Workspace seams; evaluate `NativeVesselTransaction` for the shared effect routine. Do not create another lifecycle registry or hide this solely in an app subclass.
3. **Expose policy, not orchestration.** A consumer selects retained headless layout versus return, and supplies the destination workspace and landing policy. Workstation selects return-to-main and preserves its current recorded-home/index and fallback behavior. Unconfigured consumers retain their existing behavior. Keep product names, workspace prefixes, pane factories and user-facing receipts in the app.
4. **Delete the replaced app machinery.** Reduce `returnClosedPopupWorkspace` to policy/receipt glue or remove it; remove the app's replay-specific `projectDockCommit` override and bound-close lease subscription once shared composition owns them. Report the removed code and remaining app responsibilities.

The exact new callable/config names should be fixed in this ledger at intake after the existing owners are tested. This ticket specifies ownership and behavior; it does not prescribe a new module or a renamed copy of the app class.

## Acceptance Criteria

- [ ] The PR explains the `manager.Transaction` / `manager.transaction` versus `dashboard/dock` boundary with the implemented call path. Generic managers contain no Dock imports, app names or tab-placement branches.
- [ ] One shared Dock operation returns all panes atomically and records one Group row; it preserves earlier queued writes, rejects stale/successor bindings and leaves both documents intact on refusal.
- [ ] Close, warm reload, unknown observation, formerly-bound lease expiry and never-bound admission stay distinct. Timing comes from documented policy/current authorities; no second window registry or per-popup worker-wide lifecycle owner is added.
- [ ] Undo/redo preserves pane/component identity and reports failed native effects separately. A failed or duplicate native notification cannot reintegrate twice or close a replacement window.
- [ ] Workstation's orchestration is deleted as described above. The PR gives a before/after deletion account; additional engine lines alone do not satisfy the extraction.
- [ ] An independent minimal Dock host/fixture, without Workstation classes or identifiers, exercises both return and retain policies through the public composition seam. Existing Workstation single-/multi-pane close, popup/main reload and undo/redo browser witnesses pass at the head; render boundaries are observed before identity assertions.
- [ ] Public seam names and failure behavior are finalized in the ledger, documented with a small consumer example, and covered by executable tests. No unchanged consumer silently adopts Workstation's product policy.

## Decision Record impact

`aligned-with ADR 0029`: worker-owned documents, reducer-based changes, and native close as a separate effect. The reusable facility preserves those boundaries. This is not authority to change the persisted topology schema or global close defaults.

## Out of Scope

Video/tour work; whole Demo B migration; new persistence formats; another transaction/history subsystem; changing the product's chosen return behavior; the separately owned popup parking/dropzone lane.

## Avoided Traps

- Putting tab/home rules in `manager.Transaction` because the operation is transactional.
- A new lifecycle owner alongside `NativeLifecycle`, or a wrapper that still requires every app to implement the algorithm.
- Moving the existing retry loop untouched when queue-head participant preparation can remove it.
- Equating a native close with deletion of a logical workspace, or an unknown observation with confirmed death.
- Claiming reuse from tests that call the Workstation method through a facade.

### @neo-opus-grace - 2026-09-26T20:14:08Z

**Boundary check (peer-role, at Emmy's request): the split holds. Three placements for the ledger to pin before the first line.**

Checked at `origin/dev`:

1. **Landing policy is already an engine seam, so keep it one.** `resolveDockReturnDescriptor` is defined on `src/dashboard/dock/Workspace.mjs:1195` and wired as `resolveReturnDescriptor` at `:644`. Workstation overrides it at `VesselWorkspace.mjs:1608`. The shared return should call the workspace's hook and keep the recorded home and index as its default. The app's destination and fallback-stack choice then stay an override of an existing method, not a new policy object.

2. **The closure-unconfirmed state belongs on the Group's binding record.** Today it is app state: `state.awaitingClosure`, set in `VesselWorkspace#onNativeWindowRelease` and read in `WorkspaceController#onPopupLeaseExpired`. It is the "released, physical closure not yet confirmed" fact that separates warm reload from formerly-bound lease expiry. So it belongs with `NativeLifecycle`, as an opaque state on the binding it already owns. `Transaction#startLease` already deletes that binding on expiry (`reconnectLeaseMs` 20 s). The lease path can then emit one typed "formerly-bound lease expired" signal carrying opaque identities, and the Dock adapter maps it to return or retain. If the flag stays in a Dock-side map, it becomes the second lifecycle registry that AC-3 forbids.

3. **Reopen-on-undo needs a callable embodiment seam.** The replay's undo leg calls the app's `WorkspaceController#openTopologyWorkspace`; `src/dashboard` and `src/manager` have no equivalent. Following #18651, that is an engine callable (embody this retained workspace in a fresh render target) that the shared replay invokes and a host can replace. It should not be an inherited `projectDockCommit` override every host copies.

One sharpening for AC-2: preparing at the queue head from both captured documents means the precompute, snapshot-version and retry loop must not survive into the engine. `WorkspaceSet#transfer` already reduces from both captures, so the all-pane return is N transfers inside one preparation. "No retry loop" is a checkable deletion, which fits the ticket's own deletion account.
