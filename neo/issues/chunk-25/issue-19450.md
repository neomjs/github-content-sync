# A torn-out tab opens its window at the tab header's size, not the widget's

## Context

2026-10-07, operator decision, open to challenge: a tab torn out of a dock opens its window at the **originating widget's size**, not at the tab-header proxy's. @neo-gpt-sophie's Fleet Manager finding is the symptom: a torn-out Mailbox opened at 320×208 content and clipped its preview and Task badge.

## The Problem

`TearOut` hands a host's vessel handler `{itemId, proxyRect, …}`. During a tab tear-out, `proxyRect` is the tab-header proxy. Both hosts size the window from it with the same line:

- `apps/workstation/view/VesselWorkspace.mjs` `openTearOutVessel`: `width = max(proxyRect.width || 480, 320)`, `height = max(proxyRect.height || 360, 240)`;
- Fleet Manager's `VesselContainer` (neomjs/neo-agent-institution), copied.

So every torn-out tab opens at the 320×240 floor, whatever it showed in the app.

## The Fix

1. `TearOut` adds the dragged pane's rendered rect (`sourceRect`) to the handler payload, measured before the pane leaves the window.
2. The engine owns one sizing helper that both hosts call: the source size by default, clamped to the screen's available area, with a host option to pin a fixed size. The Workstation film's choreography may need the fixed size; check before adopting the default there.
3. Workstation adopts the helper. Fleet Manager adopts it in its own repo.

## Acceptance Criteria

- [ ] The handler payload carries `sourceRect` (unit).
- [ ] The helper returns the source size, clamped to the screen and to the current 320×240 floor, and a host-pinned size when given (unit).
- [ ] A Workstation tab torn out opens its window at the pane's size, within the clamp (e2e on the dock-popout or Workstation fixture).
- [ ] The film tours still pass, or pin their size explicitly.

## Out of Scope

- Fleet Manager's adoption (Institution).
- The target-side proxy while dragging back into an app, which is the tab header (#19248, settled).

### Challenge answered (the film's author): no mechanical dependency, one staged one; the default stands

- **No cue pins a size.** `apps/workstation/tour/fiveBeatFilm.mjs` names no window dimension (the 2560×1440 at :104 is the workspace document); `NativeGestureDriver.mjs` measures live rects for every move (`getDomRect`, the windows' `innerRect`); `WorkstationFilmTourNL.spec.mjs` asserts births and transfers, never dimensions. Replace the floor and the choreography still resolves.
- **The footprint is staged.** Scenes 3 and 4 drag across the main window's targets beside the born vessel, and the Metrics pane renders larger than 320×240 in that document. Born at source size, the vessel would cover the targets the pointer must cross. So the film pins its size through the host option, AC 4's second arm, which is the right place for a staged composition.
- **The default is right**: a torn-out tab should show what it showed. One input for the helper: the clamp should subtract the title-bar delta the host already measures (`winData.outerHeight - winData.innerHeight`, `VesselWorkspace.mjs:1123`), so a source-sized window born at the pointer does not land half off-screen.
