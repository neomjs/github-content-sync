# Hacktoberfest 2026: a contributor door that works without the Agent OS

## Context

@tobiu raised it on 2026-09-19: October is Hacktoberfest, and curated good first issues across the org's repositories are a cheap way to win outside contributors — with one constraint he named himself: **they cannot easily use the Knowledge Base or the Memory Core.** The event starts on October 1, so the door has to exist before then.

Measured on 2026-09-19:

- No repository in the org carries the `hacktoberfest` topic (`neo`, `neo-agent-brain`, `neo-agent-institution`, `neo-agent-skills`, `devindex`, `create-app`).
- Open `good first issue` issues: **0** in all six. `help wanted`: 5, all in `neo`. #14230 measured the same empty label in June.
- Outside contributors exist without an invitation: 14 externally authored PRs in `neomjs/neo` over the last 90 days.
- The org ran this in 2025: #7296 (the campaign), #7465 and #7475 (missions), #7304 (reverting the temporary protocol afterwards). **October 2025 brought 60 externally authored PRs from 20 people, 53 merged** (`repo:neomjs/neo is:pr created:2025-10-01..2025-10-31`, the maintainer and bots excluded). Nothing exists for 2026.
- **Agent-assisted contributors are in scope** (@tobiu, 2026-09-19): `neo-agent-skills` is a published package, so a contributor with their own coding agent can use the skills without the Knowledge Base or the Memory Core. A good first issue may name the skill that fits it (`unit-test`, `pull-request`).

## The Problem

Everything this team writes assumes a reader with the Agent OS: a ticket points at memories, a guide assumes MCP servers, the Brain needs Docker and an inference provider. An outside contributor in October has a fork, Node and an evening. An issue that needs anything private is a bounce, and #14230 already measured what bounces look like here: 214 forks, zero externally authored issues.

Two further constraints are structural. The merge gate is one human, and October is a month in which he has less time, not more. And an open door during Hacktoberfest attracts low-effort and spam PRs; the org has a playbook for that (`hostile-content-quarantine`) which nobody has pointed at this event.

## The Architectural Reality

- The contributor surface that needs **no** Agent OS is the Body: `src/**`, `examples/**`, `learn/**`, `resources/scss/**`, `test/playwright/unit/**` and `component/**`. Its loop is `npm install`, the dev server and the custom Playwright configs.
- The Brain, the Institution's live cockpit and anything under `ai/` need containers, models or a plane. They are not first-issue territory.
- The fat-ticket discipline is already the right shape: "assume the reader has access to nothing private". A good first issue is that rule applied without exceptions.

## The Fix

One readiness pass, bundled here rather than scattered:

1. **Read the 2025 run first** (#7296, #7465, #7475, #7304) and carry what worked; say in the PR what did not.
2. **Opt in** the chosen repositories with the `hacktoberfest` topic; decide which ones and say why.
3. **Curate 20–30 good first issues**, each self-contained: exact files, a repro or a failing test, the commands of the loop, the definition of done. Areas: unit-test gaps on the engine, examples, guides, theme SCSS. Nothing that needs the KB, the Memory Core, Docker or a model.
4. **`CONTRIBUTING` leads with this door**, and the dev setup it names is verified on a clean clone with no MCP server configured.
5. **Review and label discipline**: who reviews external PRs, the `hacktoberfest-accepted` label, the quality bar, and the spam path through `hostile-content-quarantine`.
6. **A merge-window plan for the operator**: batched windows, so thirty small PRs are not thirty interruptions.
7. **Measure it**: external PRs opened and merged, first-time contributors, and who comes back in November.

## Out of Scope

- The **adopter's** path — running an institution on one's own repository — which is D#18965. Hacktoberfest contributors are engine contributors; it is the other door.
- Solo mode and the fork-configuration bugs (#14230's facets 4 and 5).

## The door is not the point — the CONVERSION is (claimer-authored, @neo-opus-ada, operator input 2026-09-19)

**The economics.** GitHub promotes `good first issue` for us; a curated one is claimed in well under an hour

**The mechanism, and it is not a paragraph of prose.** Drag a tab out of the browser window in
`apps/workstation` and it becomes its own OS window, still running, same component instances, same worker.
That survives no one's mental model of a web app, and it takes fifteen minutes from a clean clone — the
recipe is the README's (`build-themes` plus `server-start`), not `build-all`, which is heavier than needed.

Knowledge Base nor the Memory Core**, because `neo-agent-skills` is published on npm. A contributor with
Claude or GPT can therefore take work far past a first issue — which is the actual size of the opportunity.

**Where it goes, because placement decides whether it is read.** Not at the top of a ticket — a claimer skims
for the task and a manifesto above it is noise. Two placements, both now in use:

1. **A short orientation section near the end of the issue**, under a *"while you wait for review"* heading — read

2. **A full one on merge**, which is the real window: the contributor is done, pleased, and has nothing queued.

every merged external PR gets the invitation. An issue that produces a merge and no second visit has failed
at the thing this ticket exists for, and AC-7's November question is exactly *who came back*.

## The curation bar gains a tier rule (claimer-authored, @neo-opus-ada, operator input 2026-09-19)

@tobiu: *"e2e and component-based testing beats unit testing by a long shot when it comes to visual items."*

This corrects a ticket I had already filed. `#19010` asked for a **unit** spec over `Neo.layout.Cube`, a layout
that positions faces with CSS 3D transforms — and in the same body I listed *"asserting a transform string copied
out of the source"* as a trap to avoid, then prescribed the one tier where that is the only thing available. A unit
assertion there can only read back the value the layout just wrote; it cannot tell a correct cube from one rendering
inside out. `#19010` is now a **component-tier** ticket.

**The rule, added to the bar every curated issue must clear:**

| the thing under test | tier |
|---|---|
| geometry, layout, transforms, theming — anything a human would *look* at | **component** (real browser, computed styles) or **e2e** |
| a full journey across windows, drag, focus | **e2e** |
| pure functions, comparators, parsers, validators | **unit** |

The tell that a ticket picked wrong: **if the only thing the contributor can assert is the value they just set, the
tier is too low.** By that test `#19006` (calendar month view) was already right, `#19007` (sorter precedence) is
correctly unit, and `#19010` was wrong and is fixed.

**A related correction of my own framing.** I described `test/playwright/unit/vdom/layout/Cube.spec.mjs` and
`unit/vdom/Calendar.spec.mjs` as *decoys* whose *"path names lie"*. They are neither. Each states in its own docblock
that it tests `VdomHelper` over hand-built vdom trees, which is what specs looked like here in late 2025 before the
component and e2e tiers matured. The cube one was authored by **@kart-u on 2025-10-04 — during Hacktoberfest 2025**,
one of fourteen commits converting the old Siesta suite to Playwright, and it is still load-bearing a year later.
**Age is not wrongness, and a spec that says what it does has misled nobody** — I misread it, and that is worth
recording on a ticket about welcoming contributors, because the thing I nearly disparaged is the last campaign's work.

### The third one is the finding

**A drive-by contributor's agent reads `AGENTS.md` automatically.** It is the one file in this repository that a stranger's Claude or GPT loads without being asked — and what it currently finds is the maintainer substrate: the identity firewall, `§critical_gates` demanding A2A notifications and `add_memory` at end of turn, lane-claims broadcast to `AGENT:*`, ticket-ID commit discipline. None of which that agent can do, none of which applies to it.

So the agent-side door is not merely missing. **It is misaddressed** — the first thing an outside agent reads tells it to behave like a seat inside an institution it cannot join. Two failure modes, both bad: it tries and fails, or it concludes the file is not for it and reads nothing else.

That is fixable with a short addressed-to-outsiders block at the *top* of `AGENTS.md` — a fork in the road rather than new substrate, and explicitly not a per-event protocol of the kind #7304 had to revert. Something a stranger's agent can act on:

> **Contributing from outside the institution?** You cannot use the Memory Core, the Knowledge Base or A2A, and nothing below applies to you. Read `learn/benefits/Introduction.md` first — it is written to be read by a model and it will change what you think this repository is. Then: `npm install`, `npm run build-all`, `npm run server-start`, and open `apps/portal` or `apps/workstation` to see the thing you are changing actually run. Tests: `npm run test-unit` / `test-components` / `test-e2e` — never bare `npx playwright test`.

### Why this is the retention lever rather than politeness

Everything else we do to a drive-by contributor happens **at review time**, which is after the work is done and they are already leaving. The ticket body and `AGENTS.md` are the only two surfaces they see *before* deciding whether this place is worth a second visit — and we currently spend neither on orientation.

And the specific thing that would make someone stay is cheap: **show them what they are building.** `build-all` + `server-start` + `apps/portal` is three commands. Nobody develops loyalty to a repository they never saw run.

So you had already shipped it, two hours before I said it was missing.

**The mechanism, because it is reusable and nasty.** I ran:

```sh
ls CONTRIBUTING* .github/CONTRIBUTING* 2>/dev/null || echo "NO CONTRIBUTING.md anywhere"
```

zsh fails the **entire command** when *any* glob matches nothing — `.github/CONTRIBUTING*` had no match, so `ls` never ran at all, never listed the first glob, and my `|| echo` fired. Reproduced in a scratch dir with the file plainly present:

```
$ ls CONTRIBUTING* .github/CONTRIBUTING* 2>/dev/null || echo "→ reported ABSENT"
(eval):1: no matches found: .github/CONTRIBUTING*
→ reported ABSENT
$ ls CONTRIBUTING*
CONTRIBUTING.md
```

An absence claim built from a multi-glob `ls` is worthless: one unmatched pattern silently converts *every* other pattern's hit into a miss. `git cat-file -e <rev>:<path>` asks the revision directly and cannot fail this way, which is what I should have used against a named commit in the first place.

**What survives from my comment:** the other two measurements hold — `.github/ISSUE_TEMPLATE/` has `bug_report.md` and `feature_request.md` with no good-first-issue template, and `AGENTS.md` is 185 lines that never address an outside agent.
