# test.describe.serial stops 35 unit specs at their first failure

## Context

While reviewing #19015 I measured one spec file with and without `test.describe.serial`, same head, one variable changed:

| | result |
| --- | --- |
| `describe.serial` | 1 failed, **2 did not run**, 5 passed |
| `describe` | 1 failed, 7 passed |

Two arms of diagnostic signal were lost on every regression in that file, and nothing reported them as missing — a serial block that aborts does not print the arms it skipped as skips. @sloemo01 landed the one-file removal in #19022 and correctly declined to generalise from a single sample. This ticket is the rest of the tier.

Live latest-open sweep: checked the latest 20 open issues at 2026-09-21T10:20Z; no equivalent found.

## The Problem

`test.describe.serial` tells Playwright that the arms inside share state and must run in order, and that a failure invalidates everything after it. That contract is real for a block whose second arm depends on what the first one left behind. It is false for a block whose arms each build their own fixture — and when it is false, the only thing `.serial` buys is a truncated report.

The cost lands exactly when the suite matters most. A green run is identical either way; a red run under `.serial` shows one failure and hides however many arms followed it, so the first fix cycle is scoped from partial evidence and the next failure only appears on the next run. Measured on my own tickets, it has already downgraded coverage claims on #14574, #17150 and #17162 — in each case a "N passed" number that counted a population smaller than the file.

This is the same family as the truncated-read failures the repo already guards against elsewhere: a limited zero is not an absence.

## The Architectural Reality

At `b2b9368802` there are **415** `.spec.mjs` files under `test/playwright/unit`, and **35** of them contain `describe.serial`. The component tier contains zero, so this is a unit-tier convention rather than a house style.

```bash
git grep -l 'describe\.serial' -- 'test/playwright/unit/**/*.spec.mjs'
```

The unit tier runs through `test/playwright/playwright.config.unit.mjs`, and Neo's unit specs build their subject with `Neo.create` inside each arm rather than in a shared `beforeAll`, which is why most of these blocks have no cross-arm state to protect. That is a property to verify per file, not to assume: some specs legitimately mutate a singleton, a global config, or a shared collection across arms.

## The Fix

Per file, in `test/playwright/unit`:

1. Read the arms. Decide whether any arm depends on state another arm produced — a shared instance built outside the arms, a mutated singleton, an ordering assumption in the assertions.
2. No dependency → `test.describe.serial` becomes `test.describe`.
3. Dependency → keep `.serial` and add a one-line comment naming the state that requires it, so the next reader does not re-derive the question.

The comment is the part that makes this stick. A `.serial` with a stated reason is a decision; a `.serial` without one is inheritance.

This is a good first issue and it splits cleanly: a contributor can take a directory (`collection/`, `data/`, `core/`, …) rather than all 35 at once — say which in the PR body, and the remainder stays open for the next person.

## Acceptance Criteria

- [ ] Every `describe.serial` in the covered scope is either removed or carries a comment naming the shared state that requires it.
- [ ] For each removal, the PR body shows the before/after arm counts for that file under a deliberately failing arm — the measurement, not the assertion that it was safe.
- [ ] The unit suite passes for the covered scope with the sanctioned config (`npm run test-unit -- <paths>`); a bare `npx playwright test` resolves a different config and is not evidence.
- [ ] The PR body names which directories it covered and which remain.

## Out of Scope

- The component, e2e and integration tiers — the component tier has none and the others are a different runner contract.
- Fixing any test that turns out to be red once the arms after the first failure actually run. That is a finding to file, not to bury in this PR.
- Any lint enforcing the convention. Worth considering once the population is known, not before.
