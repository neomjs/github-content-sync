# The Workstation tour can play the film: gated cross-window steps

## Context

Operator, 2026-09-23 ~00:30 CEST: the tour inside `apps/workstation` "looks boring" now that multi-window, tear-out and rails were polished, and a generated video for the README is wanted. Measured on `dev@a186e92cfa`:

- The in-app tour (`TourToolbar` "Start dense tour" → `TourController#startTour` → `TourRunner` with `workstationTourScript` from `apps/workstation/tour/denseWorkstation.mjs`) plays four scenes — dense overview, dropzone choreography, promote, theme handoff. None births a window.
- The film screenplay `apps/workstation/tour/fiveBeatFilm.mjs` (#16311 / #16376; witness authority `test/playwright/e2e/workstation/WorkstationFiveBeatNL.spec.mjs`) has eight scenes: cold open, showcase, tear-out, re-entry, second-window docking, stack return, perspectives + undo/redo, signature. Its scenes carry `narration` and `beats` (strings) and no runnable `steps`; nothing consumes it at runtime.
- The choreography the operator misses exists as app-owned real-pointer executors in `apps/workstation/tour/NativeGestureDriver.mjs` (`executeTearOutStep` with `cancel` / `reenter`, the convert-while-dragging executor, `executeStackReturnStep`, the vessel birth / commit / retirement gates) — driven today only from Playwright.

## The Problem

Two authorities for one journey: the viewer sees the dense script; the film and its witness use another. The film's window scenes cannot run from a button as they stand, for one mechanical reason: a scripted vessel birth (`Neo.Main.windowOpen` at `apps/workstation/view/VesselWorkspace.mjs:1035`) needs transient user activation — browsers block `window.open` outside a user gesture, and the app already reports that outcome fail-closed as `lastVesselOpen.stage = 'windowOpen-false'`. The runner's v1 vocabulary is `op | pause | topology-assert | cross-window` (`src/ai/client/tourScript.mjs:66`); it has no step that waits for the viewer.

## The Architectural Reality

- `Neo.ai.client.TourRunner`: modes `demo` (paced), `record` (script-authored pacing), `spec` (waits skipped); `crossWindowExecutor.executeCrossWindowStep(step)` returns a settlement receipt validated by `validateCrossWindowResult`; `pause` is viewer pacing only.
- `TourController#runTourSpec(script, options)` already accepts any script; `startTour` hardcodes the dense one (`TourController.mjs:67`).
- Perspectives live on `DockService` (`capturePerspective` / `listPerspectives` / `restorePerspective`), not in the `Operations` vocabulary; `'perspective'` is a `RESERVED_STEP_TYPES` entry. Dock undo/redo run on one Group cursor through the Neural Link (#19063 is the proof).
- Film-take mode (`NEO_FILM_TAKE=1`) records the same journey drive per page. One runnable script therefore serves both the viewer's tour and the README film.

## The Fix

1. **`src/ai/client/tourScript.mjs` + `TourRunner.mjs`:** a `gate` step — `{type: 'gate', caption, prompt}`. In `demo` mode the runner pauses until the host resolves it (`runner.continue()`); `record` and `spec` auto-continue. The log records the gate; `validateTourScript` admits it; the mode table in the class summary gains the row.
2. **`apps/workstation/tour/fiveBeatFilm.mjs`:** every scene gains `steps`: the cold open and showcase reuse the dense script's `op` / `pause` + cue shapes; tear-out, re-entry (`cancel`), second-window convert and stack return become `gate` + `cross-window` steps over the existing executors; perspectives and undo/redo run through the reserved `perspective` type or an executor-backed step; the signature is a `topology-assert`. `narration` stays the caption source; `beats` become the steps' captions.
3. **`TourController`:** a `crossWindowExecutor` mapping semantic steps onto `NativeGestureDriver` (as the witness does) and a `startFilmTour` entry. **`TourToolbar`:** a "Start film tour" button and a Continue affordance bound to the gate (a click or Space is the activation the birth needs; the gate caption says where to look).
4. **Witnesses:** unit — `validateTourScript(fiveBeatFilmScript)` is valid and `gate` semantics per mode land in `test/playwright/unit/ai/client/TourRunner.spec.mjs`; e2e — the film script runs through `runTourSpec` in `spec` mode under Playwright (popups allowed) and reproduces the five-beat witness's receipts for scenes 3–7 (pane identity equality, `claimCount: 1`, the `documents-adopted → … → topology-exited` phase order); the dense tour and its specs stay untouched.
5. **Docs:** the Workstation README documents both tours; the dense tour remains the no-window fallback.

## Avoided Traps

- Scripted vessel births without activation: blocked silently in production browsers, and `windowOpen-false` is the receipt that proves the trap. The gate is the honest carriage, not a workaround.
- A second screenplay: the film script is the screenplay; the tour and the take consume it. No parallel step list in the controller.
- Reusing the dense tour's timings: the film's `targetSeconds` budget the cut, and `record` mode pins the authored pacing.
