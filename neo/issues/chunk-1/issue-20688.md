# Route-specific seo.json, canonical URL, and ld+json for deep Portal routes

## Context

Parent epic: #20671 (*Search engines and agents find and classify neomjs.com*, Engine 13.5 cornerstone 4 in `ROADMAP.md`).

When a crawler (`Googlebot` via `neomjs/middleware-v2`), coding agent, or user navigates to any deep route in the Portal (`/learn/*`, `/news/blog/*`, `/news/releases/*`), `Portal.view.ViewportController#onHashChange` (`apps/portal/view/ViewportController.mjs:230-236`) delegates `<head>` updates to `Portal.service.Seo#onRouteChanged` (`apps/portal/service/Seo.mjs:127-130`).

## The Problem

Measured on `dev` at `62f75736ba`:

1. **`apps/portal/resources/data/seo.json` contains only 10 top-level routes** (`/about-us`, `/docs`, `/examples`, `/home`, `/learn`, `/news`, `/news/blog`, `/news/releases`, `/news/videos`, `/services`).
2. **Every deep route falls back to generic parent metadata (`#8439` stopgap):**
   - `Portal.service.Seo#getMetadata(route)` (`apps/portal/service/Seo.mjs:72-95`) pops path segments until it matches a top-level prefix.
   - As a result, all 145+ `/learn/*` guides render with the identical `<title>Learn Neo.mjs</title>` and `<meta name="description" content="Learn the fundamentals of the Neo.mjs platform.">`; all `/news/blog/*` articles render with `<title>Neo.mjs Blog</title>`; and all `/news/releases/*` notes render with `<title>Neo.mjs Releases</title>`.
3. **`Portal.service.Seo` never sets `<link rel="canonical">`, OpenGraph route metadata, or route-specific `ld+json`:**
   - `Portal.service.Seo#updateDocumentHead` (`apps/portal/service/Seo.mjs:142-145`) only passes `{description, title, windowId}` to `DocumentHead.update`.
   - `apps/portal/index.html:9-13` hardcodes `<meta property="og:title" content="Neo.mjs - An Agent Institution">`, `<meta property="og:description" ...>`, and `<meta property="og:url" content="https://neomjs.com/">`, which stay frozen on `/home` across all route transitions, and no `<link rel="canonical">` tag is emitted.
   - In `src/main/addon/DocumentHead.mjs:246-254`, `update({ldJson})` calls `me.setLdJson({value: ldJson})` without forwarding `name`, which selects the first `script[type="application/ld+json"]` in `<head>` and overwrites the root `data-schema-name="neo-organism"` graph (`apps/portal/index.html:15`).

## The Architectural Reality

- `buildScripts/docs/seo/generate.mjs` already walks `learn/tree.json`, `apps/portal/resources/data/blog.json`, and `apps/portal/resources/data/releases.json` for `sitemap-core.xml` and `llms*.txt`, but does not generate or synchronize `apps/portal/resources/data/seo.json`.
- `Neo.main.addon.DocumentHead` (`src/main/addon/DocumentHead.mjs`) already exposes `setCanonical({url})`, `setDescription({value})`, `setTitle({value})`, `setTag({value})`, and named `setLdJson({name, value})` (`script[type="application/ld+json"][data-schema-name="..."]`).
- `test/playwright/e2e/portal/ConnectNL.spec.mjs` asserts the `/services` entry in `apps/portal/resources/data/seo.json`, so the 10 curated top-level entries must be preserved intact when deep-route entries are generated.

Design authority: #20671 (`ROADMAP.md` Engine 13.5 cornerstone 4: *"every canonical Portal route serves route-specific SSR metadata, structured schema and clean semantic HTML"*).

## The Fix

1. **Extract route-specific titles and descriptions in `buildScripts/docs/seo/generate.mjs` (`getSeoJson` / `--format seo-json`):**
   - Preserve the 10 curated top-level entries in `apps/portal/resources/data/seo.json`.
   - Generate deterministic route-specific `{title, description, schemaType}` entries for every leaf in `learn/tree.json` (`/learn/<id>`), every blog post in `apps/portal/resources/data/blog.json` (`/news/blog/<slug>`), and every release note in `apps/portal/resources/data/releases.json` (`/news/releases/<version>`), extracting the H1/node title and the first non-heading summary paragraph from each Markdown file (capped cleanly to meta-description length ~155–160 chars).
2. **Preserve named `ld+json` schemas in `Neo.main.addon.DocumentHead#update` (`src/main/addon/DocumentHead.mjs:246-254`):**
   - Allow `update({ldJson})` to accept `{name, value}` (or `ldJsonName`) so route-level structured data writes to `<script type="application/ld+json" data-schema-name="neo-route">` without clobbering `<script type="application/ld+json" data-schema-name="neo-organism">`.
3. **Update `Portal.service.Seo` (`apps/portal/service/Seo.mjs`) to synchronize canonical URL, OpenGraph tags, and route `ld+json`:**
   - Normalize incoming `hashString` (`/learn/...`, `/news/blog/...`, `/news/releases/...`), resolve route metadata via `getMetadata(route)`, and update `<title>`, `<meta name="description">`, `<link rel="canonical" href="https://neomjs.com<route>">`, `og:title`, `og:description`, `og:url`, and `<script type="application/ld+json" data-schema-name="neo-route">` (`TechArticle` / `BlogPosting` / `WebPage`).

## Acceptance Criteria

- [ ] `buildScripts/docs/seo/generate.mjs` exports `getSeoJson()` (and supports `--format seo-json`), populating `apps/portal/resources/data/seo.json` with route-specific `title` and `description` entries for all `learn/tree.json` leaves (`/learn/*`), `blog.json` leaves (`/news/blog/*`), and `releases.json` leaves (`/news/releases/*`) while keeping all 10 top-level routes unchanged.
- [ ] `Neo.main.addon.DocumentHead#update` supports named `ldJson` (`{name: 'neo-route', value: ...}`) without overwriting `<script type="application/ld+json" data-schema-name="neo-organism">`.
- [ ] `Portal.service.Seo` updates `title`, `description`, `canonicalUrl` (`https://neomjs.com<route>`), `og:title`, `og:description`, `og:url`, and `data-schema-name="neo-route"` `ld+json` on route change.
- [ ] Unit tests verify `getSeoJson()`, `Portal.service.Seo#getMetadata` on deep `/learn/*`, `/news/blog/*`, and `/news/releases/*` routes, and `DocumentHead#update` preserving `data-schema-name="neo-organism"`.

## Out of Scope

- Example overview routes (`/examples/*` family pages under `#20498`), which will be added once their route structure lands.
- Middleware SSR cache invalidation on the build host (`neomjs/middleware-v2#55`).

## Avoided Traps

- **Adding `19,400+` archive routes (`/news/tickets/*`, `/news/pulls/*`, `/news/discussions/*`) to `seo.json`:** That would bloat `seo.json` into a multi-megabyte runtime fetch on Portal boot. `seo.json` stays scoped to the curated core routes (`sitemap-core.xml` scope).
- **Calling `DocumentHead#setLdJson` without `name`:** Overwrites the root `data-schema-name="neo-organism"` graph in `apps/portal/index.html`.
