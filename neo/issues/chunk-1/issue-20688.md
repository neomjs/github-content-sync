# Route-specific seo.json, canonical URL, and ld+json for deep Portal routes

## Context

Parent epic: #20671 (*Search engines and agents find and classify neomjs.com*, Engine 13.5 cornerstone 4 in `ROADMAP.md`).

When a user or coding agent navigates to any deep route in the Portal browser shell (`/learn/*`, `/news/blog/*`, `/news/releases/*`), `Portal.view.ViewportController#onHashChange` (`apps/portal/view/ViewportController.mjs:230-236`) delegates `<head>` updates to `Portal.service.Seo#onRouteChanged` (`apps/portal/service/Seo.mjs:127-130`). Crawler snapshots (`Googlebot` / LLM bots) are built separately by `neomjs/middleware-v2` (`SsrService#buildHeadInjection`) from the rendered body and `apps/portal/index.html`; wiring `SsrService#buildHeadInjection` to consume `apps/portal/resources/data/seo.json` is tracked in #20700 under #20671.

## The Problem

Measured on `dev` at `62f75736ba`:

1. **`apps/portal/resources/data/seo.json` contains only 10 top-level routes** (`/about-us`, `/docs`, `/examples`, `/home`, `/learn`, `/news`, `/news/blog`, `/news/releases`, `/news/videos`, `/services`).
2. **Every deep route falls back to generic parent metadata (`#8439` stopgap):**
   - `Portal.service.Seo#getMetadata(route)` (`apps/portal/service/Seo.mjs:72-95`) pops path segments until it matches a top-level prefix.
   - As a result, all `/learn/*` guides render in the browser shell with the identical `<title>Learn Neo.mjs</title>` and `<meta name="description" content="Learn the fundamentals of the Neo.mjs platform.">`; all `/news/blog/*` articles render with `<title>Neo.mjs Blog</title>`; and all `/news/releases/*` notes render with `<title>Neo.mjs Releases</title>`.
3. **`Portal.service.Seo` never sets `<link rel="canonical">`, OpenGraph route metadata, or route-specific `ld+json`:**
   - `Portal.service.Seo#updateDocumentHead` (`apps/portal/service/Seo.mjs:142-145`) only passes `{description, title, windowId}` to `DocumentHead.update`.
   - `apps/portal/index.html:9-13` hardcodes `<meta property="og:title" content="Neo.mjs - An Agent Institution">`, `<meta property="og:description" ...>`, and `<meta property="og:url" content="https://neomjs.com/">`, which stay frozen on `/home` across all route transitions, and no `<link rel="canonical">` tag is emitted.
   - In `src/main/addon/DocumentHead.mjs:246-254`, `update({ldJson})` calls `me.setLdJson({value: ldJson})` without forwarding `name`, which selects the first `script[type="application/ld+json"]` in `<head>` and overwrites the root `data-schema-name="neo-organism"` graph (`apps/portal/index.html:15`).

## The Architectural Reality

- `buildScripts/docs/seo/generate.mjs` and `buildScripts/docs/rebuildContentIndexesAndSeo.mjs` already walk `learn/tree.json`, `apps/portal/resources/data/blog.json`, and `apps/portal/resources/data/releases.json` for `sitemap-core.xml` and `llms*.txt`, but do not generate or synchronize `apps/portal/resources/data/seo.json`.
- `Neo.main.addon.DocumentHead` (`src/main/addon/DocumentHead.mjs`) already exposes `setCanonical({url})`, `setDescription({value})`, `setTitle({value})`, `setTag({value})`, and named `setLdJson({name, value})` (`script[type="application/ld+json"][data-schema-name="..."]`).
- `test/playwright/e2e/portal/ConnectNL.spec.mjs` asserts the `/services` entry in `apps/portal/resources/data/seo.json`, so the 10 curated top-level entries must be preserved directly from `apps/portal/resources/data/seo.json` as their single source of truth when deep-route entries are generated.

Design authority: #20671 (`ROADMAP.md` Engine 13.5 cornerstone 4: *"every canonical Portal route serves route-specific SSR metadata, structured schema and clean semantic HTML"*).

## The Fix

1. **Extract route-specific titles and descriptions in `buildScripts/docs/seo/seoJson.mjs` (`getSeoJson` / `--format seo-json`) and wire into `buildScripts/docs/rebuildContentIndexesAndSeo.mjs`:**
   - Preserve the 10 curated top-level entries directly from `apps/portal/resources/data/seo.json` (no duplicate hardcoded map in build scripts).
   - Generate deterministic route-specific `{title, description, schemaType}` entries for every leaf in `learn/tree.json` (`/learn/<id>`), every blog post in `apps/portal/resources/data/blog.json` (`/news/blog/<slug>`), and every release note in `apps/portal/resources/data/releases.json` (`/news/releases/<version>`), extracting the H1/node title and the first non-heading summary paragraph from each Markdown file (capped cleanly to meta-description length ~155–160 chars), and regenerate `seo.json` inside `rebuildContentIndexesAndSeo.mjs`.
2. **Preserve named `ld+json` schemas and support `tags` arrays in `Neo.main.addon.DocumentHead#update` (`src/main/addon/DocumentHead.mjs`):**
   - Allow `update({ldJson, tags})` to accept `tags: Object[]` (forwarded to `setTag({value})`) and unambiguous `{name, value}` wrappers (`!('@context' in ldJson) && !('@type' in ldJson)`) so route-level structured data writes to or clears (`value: null`) `<script type="application/ld+json" data-schema-name="neo-route">` without clobbering `<script type="application/ld+json" data-schema-name="neo-organism">` or misclassifying plain Schema.org objects that happen to carry `name` and `value`.
3. **Update `Portal.service.Seo` (`apps/portal/service/Seo.mjs`) to synchronize canonical URL, OpenGraph tags, and route `ld+json`:**
   - Normalize incoming `hashString` (`/learn/...`, `/news/blog/...`, `/news/releases/...`), normalize `/home` (and `/`) `canonicalUrl` and `og:url` to `'https://neomjs.com/'`, resolve route metadata via `getMetadata(route)`, update `<title>`, `<meta name="description">`, `<link rel="canonical">`, `og:title`, `og:description`, `og:url`, and emit `<script type="application/ld+json" data-schema-name="neo-route">` (`TechArticle` / `BlogPosting` / `WebPage`) only for exact routes in `seo.json` while clearing `neo-route` (`value: null`) on parent-segment fallback hits.

## Acceptance Criteria

- [ ] `buildScripts/docs/seo/generate.mjs` exports `getSeoJson()` (and supports `--format seo-json`, wired into `rebuildContentIndexesAndSeo.mjs`), populating `apps/portal/resources/data/seo.json` with route-specific `title` and `description` entries for all `learn/tree.json` leaves (`/learn/*`), `blog.json` leaves (`/news/blog/*`), and `releases.json` leaves (`/news/releases/*`) while preserving all 10 curated top-level routes directly from `apps/portal/resources/data/seo.json`.
- [ ] `Neo.main.addon.DocumentHead#update` supports `tags: Object[]` and unambiguous named `ldJson` wrappers (`{name: 'neo-route', value: ...}` or `value: null`) without overwriting `<script type="application/ld+json" data-schema-name="neo-organism">` or misclassifying plain Schema.org objects.
- [ ] `Portal.service.Seo` updates `title`, `description`, `canonicalUrl` (`https://neomjs.com/` for `/home`, `https://neomjs.com<route>` otherwise), `og:title`, `og:description`, `og:url`, and `data-schema-name="neo-route"` `ld+json` on exact route matches (clearing `neo-route` on fallback routes).
- [ ] Unit tests in `test/playwright/unit/buildScripts/docs/seo/Generate.spec.mjs`, `test/playwright/unit/buildScripts/docs/rebuildContentIndexesAndSeo.spec.mjs`, `test/playwright/unit/main/addon/DocumentHead.spec.mjs`, and `test/playwright/unit/apps/portal/service/Seo.spec.mjs` verify all contracts.

## Out of Scope

- Wiring `neomjs/middleware-v2` (`SsrService#buildHeadInjection`) to read `apps/portal/resources/data/seo.json` for crawler snapshots (#20700 under #20671).
- Example overview routes (`/examples/*` family pages under `#20498`), which will be added once their route structure lands.
- Middleware SSR cache invalidation on the build host (`neomjs/middleware-v2#55`).

## Avoided Traps

- **Adding `19,400+` archive routes (`/news/tickets/*`, `/news/pulls/*`, `/news/discussions/*`) to `seo.json`:** That would bloat `seo.json` into a multi-megabyte runtime fetch on Portal boot. `seo.json` stays scoped to the curated core routes (`sitemap-core.xml` scope).
- **Duplicating curated top-level metadata in build scripts:** `apps/portal/resources/data/seo.json` is the single source of truth for curated top-level routes; `getSeoJson()` reads and preserves them directly from `seo.json`.
- **Calling `DocumentHead#setLdJson` without `name`:** Overwrites the root `data-schema-name="neo-organism"` graph in `apps/portal/index.html`.
