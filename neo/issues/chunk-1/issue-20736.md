# Document binary BlobPart content in Neo.main.addon.FileDownload#saveText

## Context

`Neo.main.addon.FileDownload` (`src/main/addon/FileDownload.mjs`, introduced in `#20380` / PR `#20389`) saves files generated in the App worker by constructing a `Blob` on the main thread and clicking a temporary `<a download>` element.

- **Design authority:** `src/main/addon/FileDownload.mjs:45-61` (`new Blob([content], {type: mimeType})`) and `src/worker/Base.mjs:813` (structured-clone worker messaging, which transfers `Uint8Array` / `ArrayBuffer` across the worker boundary intact).

## The Problem

`src/main/addon/FileDownload.mjs:46` passes `[content]` directly into `new Blob([content], {type: mimeType})`, which natively accepts any `BlobPart` (`String`, `Uint8Array`, `ArrayBuffer`, `Blob`) transferred from the App worker via structured clone. However:

1. The class summary (`src/main/addon/FileDownload.mjs:4`) and method JSDoc (`src/main/addon/FileDownload.mjs:38-44`) document `content` exclusively as `{String}` (*"Saves text that the app worker generated as a file the browser downloads"* / `@param {String} data.content`).
2. Callers generating binary files in the App worker (such as zip archives, images, or binary exports) either have to call `saveText()` with a `Uint8Array` against its `{String}` JSDoc contract or lack a documented byte-capable entry point (`saveFile` / widened `saveText` JSDoc).

## The Architectural Reality

- `src/main/addon/FileDownload.mjs:18-62`:
  - `remote: {app: ['saveText']}` (`:30-34`)
  - `saveText({content, fileName, mimeType='text/plain'})` (`:45-61`) wraps `new Blob([content], {type: mimeType})` and clicks an `<a download>` anchor.
- `src/grid/Container.mjs:1420` (`exportCsv`) is the current Engine caller of `FileDownload#saveText`.
- Worker boundary (`src/worker/Base.mjs:813`): `postMessage` structured-clones `Uint8Array` and `ArrayBuffer` payloads without string encoding loss.

## The Fix

1. Widen `Neo.main.addon.FileDownload#saveText`'s JSDoc (`src/main/addon/FileDownload.mjs:4, 38-44`) to `@param {ArrayBuffer|ArrayBufferView|Blob|String} data.content` (and update the class `@summary` / `@description` to reflect both text and binary `BlobPart` payloads), or add a remote `saveFile` alias delegating to the same `Blob` download path while keeping `saveText` supported.
2. Add a unit/component test verifying that `Neo.main.addon.FileDownload` accepts both `String` and `Uint8Array` payloads and constructs a `Blob` with identical byte length and MIME type.
