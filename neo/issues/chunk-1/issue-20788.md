# The Engine takes its AGENTS.md pointer from neo-agent-skills 1.4.0

## Context

This is step 1 of neomjs/neo-agent-skills#335 (comment 6801123360). `neo-agent-skills` 1.4.0 ships the `AGENTS.md` pointer and its git filter beside the generator, as `neo-agent-skills-agents-md --pointer`; neomjs/neo-agent-skills#347 merged on 2026-11-11. The Engine still carries its own copy, from #20749 and #20777. neomjs/devindex#135 adopts the package's version too. Two copies of one required filter drift: #20777's smudge fix had to land in the Engine alone.

## The Problem

Read at `dev` `5012129e70` and `neo-agent-skills` `b3a73a9`:

- `buildScripts/util/agentsMdPointer.mjs` holds the pointer text, the filter name and the clean command (`node buildScripts/util/agentsMdPointer.mjs`). `test/playwright/unit/buildScripts/util/agentsMdPointer.spec.mjs` covers it.
- `buildScripts/util/prepare.mjs` registers that filter (`ensureAgentsMdFilter`, `:121`) before it runs the `generate-agents-md` script. Afterwards it lets the index re-read the file (`refreshAgentsMd`, `:160`). `test/playwright/unit/buildScripts/prepare.spec.mjs` covers both (`:170`, `:195`, `:272`, `:282`).
- The package's `scripts/agents-md-pointer.mjs` does the same with `ensureFilter`, `refresh`, `pointerFor` and `cleanCommand`. `--pointer` runs them around the write.
- The committed pointer stays byte-identical: the Engine's `AGENTS_MD_POINTER` equals 1.4.0's `pointerFor('neo')`.

## The Architectural Reality

- In `package.json`, `generate-agents-md` is `neo-agent-skills-agents-md --repo neo,neo-agent-brain --out AGENTS.md`, and `neo-agent-skills` is pinned at `1.3.7`.
- `.gitattributes:1-2` routes `/AGENTS.md` through `filter=neo-agents-md`, the same filter name 1.4.0 registers. Its comment cites `agentsMdPointer.mjs`.
- 1.4.0's `ensureFilter` rewrites any `filter.neo-agents-md.*` value that differs from its own. A checkout that still names the Engine's clean command therefore moves to `node node_modules/neo-agent-skills/scripts/agents-md-pointer.mjs --repo neo` on its next `npm install`.
- Git keeps filter settings per clone, and every worktree of the clone reads them. *(Added 18:45Z, from the probe in the pull request.)* An `npm install` in a worktree of a commit before this change registers the old command again, for every worktree. The filter is `required`, so a checkout of this change then fails `git status` with `fatal: AGENTS.md: clean filter 'neo-agents-md' failed` once `AGENTS.md` changes on disk, unless the old command still runs there.

## The Fix

1. Pin `neo-agent-skills` to `1.4.0` and add `--pointer` to `generate-agents-md`.
2. `prepare.mjs` drops `ensureAgentsMdFilter` and `refreshAgentsMd`; its `AGENTS.md` stage runs the script, which now does both. `buildScripts/util/agentsMdPointer.mjs` becomes a delegate to the package's pointer, so a checkout of this change still answers the old command. #20790 retires it.
3. The `.gitattributes` comment names the package instead of the module.

## Acceptance Criteria

- [ ] A checkout whose `filter.neo-agents-md.clean` still names `node buildScripts/util/agentsMdPointer.mjs` runs `npm install` and ends with the 1.4.0 filter registered, the rules in the working copy and `git status` clean. The PR shows this in a real git checkout: the checkout direction is what #20776 missed.
- [ ] A fresh `git worktree add` followed by `npm install` ends the same way.
- [ ] The committed `AGENTS.md` is unchanged.
- [ ] Nothing imports `agentsMdPointer.mjs`; it runs only as git's clean command. `prepare.spec.mjs` keeps arms only for what `prepare.mjs` still does.
- [ ] After a worktree of a commit before this change runs `npm install`, `git status` in a checkout of this change still works once `AGENTS.md` changes on disk.

## Out of Scope

- neomjs/devindex#135.
- The Brain's import of `POINTER_MARKER` (neomjs/neo-agent-skills#335, step 4).
- The `.claude/CLAUDE.md` symlink (#335, step 3).
- The reverse direction. A worktree of an older commit, after a checkout of this change registers the package's command, fails the same way, because its `node_modules` lacks the package's script. No new commit can change an old one; `npm install` in that worktree re-registers its own command and recovers it.

## Avoided Traps

- **Keeping the Engine copy beside the package's.** Two copies of a required filter drift, and a fix like #20777's would have to land twice.
- **Deleting the old clean path outright.** *(Corrected 18:45Z: this item first rejected a shim at the old path, on the reasoning that the next `npm install` closes the window. The probe showed that the window reopens whenever a worktree of an older commit installs, so the path stays as a delegate until #20790.)*
