# A field unmounted with its picker open keeps swallowing Escape

## Context

`test/playwright/e2e/grid/CellEditingPickerProjection.spec.mjs:80` (combo, vertical) failed on hosted CI for #20719 @ `56affca80b` (run 42822687875, `e2e-engine (2/14)`):

```
Error: Escape ended the edit
Expected: true
Received: false
- Timeout 5000ms exceeded while waiting on the predicate
```

**Observed** (the shard's `trace.zip`, frame snapshots decoded): after the editor is reprojected, the combo input carries `aria-expanded="true"`, no `.neo-picker-container` exists, and that holds across every Escape press of the 5 s poll.
**Inferred**, from a local reproduction (below): the field's unmount reached the App worker before the main thread's align hide of its picker.

## The Problem

`Neo.form.field.Picker#afterSetMounted` closes an open picker when its field unmounts with the picker's `hide()` method:

```js
if (value === false && oldValue && this.pickerIsMounted) {
    this.picker.hide()
}
```

`Component#hide()` writes `_hidden` without passing the `hidden` config, so `afterSetHidden` does not run and no `hiddenChange` fires. The field's `pickerIsMounted`, and `ComboBox`'s `aria-expanded`, stay `true`. Every later close is then a no-op. `hidePicker()` sets `hidden: true`, which equals `_hidden`, so the setter skips. Main's align hide, `setConfigs({hidden: true})`, skips the same way. `onKeyDownEscape` still sees `pickerIsMounted` and cancels the event. A grid cell editor whose cell left the row pool with its picker open can then never be cancelled by Escape. 25 s of presses never end the edit, so the state is stuck, not slow.

**When it happens.** The path runs only when the unmount lands first. In the spec, main's align-on-scroll hide of the picker usually lands about 36 ms ahead of the field's unmount. That margin is the same on `dev` and on #20719's head, measured locally. On hosted CI the order flipped once.

**Reproduction (local, deterministic).** In the `grid-cell-editing-pickers` fixture, a worker-side probe defers the picker's `set({hidden: true})` by 150 ms:

| | stuck |
|---|---|
| `dev` @ `7bd7312458` | 2/2 |
| #20719 head | 2/2 |
| `dev` + the fix below | 0/6 |

## The Architectural Reality

- `src/form/field/Picker.mjs`:
  - `afterSetMounted` (`:133`);
  - `hidePicker`, which sets `picker.hidden = true` (`:255`);
  - `onKeyDownEscape` (`:330`);
  - `onPickerHiddenChange`, the only writer of `pickerIsMounted` (`:349`).
- `src/component/Base.mjs`: `afterSetHidden` fires `hiddenChange` (`:594`); `hide()` writes `_hidden` directly (`:1675`).
- `src/form/field/ComboBox.mjs:798`: `onPickerHiddenChange` writes `aria-expanded`.
- `src/main/DomAccess.mjs:282` and `:1521` hide a floating picker whose target is clipped or gone, through `Neo.worker.App.setConfigs({hidden: true})`.
- `fc1086b463` (`#4995`, 2023) based the picker's show and hide on the `hidden` config, and kept this one `hide()` call.

## The Fix

`Picker#afterSetMounted`: `this.picker.hide()` → `this.hidePicker()`. The close then passes the `hidden` config, and `pickerIsMounted` and `aria-expanded` follow it.

## Acceptance Criteria

- [ ] A Picker field unmounted with its picker open ends with `pickerIsMounted === false`, and `onKeyDownEscape` no longer cancels Escape. Unit test in `test/playwright/unit/form/field/Picker.spec.mjs`, red on `dev` before the fix.
- [ ] `CellEditingPickerProjection.spec.mjs` and `CellEditingPooling.spec.mjs` stay green.

## Out of Scope

- `ComboBox#doFilter` and `#filterOnInput` also call `picker?.hide()`. Probed: typing to no match, or clearing the input, leaves `aria-expanded` false and Escape working. Every keystroke first closes the picker through `hidePicker()` (`deselectAll` → `onListItemSelectionNoChange`), so those calls meet an already-hidden picker.
- The spec's wait, `the picker is open over the draft`, can pass on the first keystroke's picker. The fix removes the stuck state in either order.

## Avoided Traps

- Retrying, or lengthening the spec's Escape poll: the state is permanent.
- Re-syncing `pickerIsMounted` on remount: it treats the symptom, and the desync starts at the silent close.
