# Example covers come from recorded captures; Grid and Table first

## Context

A leaf of #20498, cornerstone 1 of Engine 14 (`ROADMAP.md`). Its first leaf, #20500 (PR #20675), put 21 captioned Grid and Table demonstrations on the Portal. Seventeen of them have no screenshot.

**Rewritten on 16 Nov 2026.** The operator read the examples overview that day and graded the covers in its previews 1 of 10 (#21119 carries his words and the measurements). Two things change here:

- The card will show a cover whole (#21119). The rule "the telling detail sits in the top-left third" is withdrawn.
- 46 of 76 records have no cover on `dev` `2404340dfa`, 71 of 101 once #21105 merges. Covers now come from recorded captures, not from hand screenshots. This ticket delivers the script and the Grid and Table covers as its first output.

The frame table below is unchanged.

## The Problem

A stranger evaluating the grid sees seventeen near-identical cards. The caption says what an example proves and nothing shows it.

Count receipt: `examples.json` at `c8034978b8`, filtered on `family === 'grid-table'`: 21 records, 4 with an `image` (`grid-big-data`, `grid-issues`, `grid-tree-big-data`, `table-filtering`), 17 with `"image": null`, listed in the frame table. Re-counted on `dev` `2404340dfa`: unchanged.

The 30 covers in use were made one by one for the 13.4 list: whole browser windows, some with the tab strip and address bar (`helix.png`, `offscreenCanvas.png`), in mixed themes and scales. Seventy more by hand would repeat that, and none could be re-shot when a theme changes.

## The Architectural Reality

- `Portal.view.examples.List#imageBasePath` (`apps/portal/view/examples/List.mjs:73-87`) serves a record's `image` from `neomjs/pages` `main`, `resources_pub/website/examples/`: by relative path on the deployed site, from `raw.githubusercontent.com` everywhere else. A new cover is invisible in a local Portal until Pages holds it.
- Pages holds every cover. The engine tree holds five originals (`apps/portal/resources/images/examples/devmode/`); the other covers in use exist on Pages only. A hundred covers at 150 KB would add 15 MB to the engine tree.
- `buildScripts/` has no capture script. The Portal's other producers live in `buildScripts/docs/seo/`; the script's home is the implementer's placement call through `structural-pre-flight`.
- Design authority: the operator's read of 16 Nov 2026, quoted on #21119, for the withdrawn composition rule; the covers themselves call no existing behavior wrong.

## The Fix

One recipe per record, one script that runs them, 17 covers as the first output.

- **The recipe**, committed beside the catalog: the record's id, the example's URL, viewport, theme, the interactions that reach the state, and the region to capture.
- **The script** opens each recipe in headless Chromium against the local dev server and writes the cover, for one record or for all. No hand screenshot and no crop in an image editor.
- **The frame:** 1280×720 JPEG, at most 150 KB: a 16:9 region of the example's own surface of about 640×360 CSS px at device scale 2, so that its controls stay legible when a card shows the cover 445 px wide. No browser or OS chrome. The card shows the frame whole, so the telling detail may sit anywhere in it.
- **State:** the feature in action, never the untouched default view.
- **Theme:** the dark theme where the example offers a switch, otherwise the example's default.
- **Bytes:** the covers go to `neomjs/pages` as `resources_pub/website/examples/devmode/<record id>-14.jpg`. The engine pull request carries the script, the recipes and the 17 `image` values. A local Portal can show a freshly written cover before Pages merges.

## Contract Ledger

| Target surface | Source of authority | Proposed behavior | Fallback / edge case | Docs | Evidence |
|---|---|---|---|---|---|
| A cover recipe | this ticket | one per record that has a cover; running it again reproduces the cover | an example that needs a key or an unreachable service gets no recipe and no cover | the script's header | the 17 recipes |
| The cover files | `#19640`, `#19947`; #21119 | 1280×720 JPEG, at most 150 KB, the example's own surface, legible at 445 px | a feature a still cannot show (animated sorting) shows the control that drives it | a per-cover table printed from the recipes | one sheet of the covers at card width |
| 17 `image` values in `examples.json` | #20498's kitchen-sink standard | each names a published cover | a record without a cover renders no card (#21119) | this ticket | a unit arm: every `image` has a recipe |

Decision Record impact: none.

## Acceptance Criteria

- [ ] The script writes all 17 covers from their recipes in one run on a clean checkout. The command is in the pull request and in the script's header.
- [ ] Each cover is 1280×720, JPEG, at most 150 KB, shows the state its row of the frame table names, and contains no browser or OS chrome.
- [ ] **Look:** the pull request shows the 17 covers on one sheet at card width (445 px). On each, the component and the named state are recognised without zooming. The design seat reads the sheet before review.
- [ ] The four existing Grid and Table covers are held to the same rule; the pull request says which were re-shot.
- [ ] A unit arm fails when a record's `image` has no recipe.
- [ ] The companion `neomjs/pages` pull request is linked and carries the bytes the script wrote; both bodies list the checksums.
- [ ] No caption changes, no new example.

## Post-Merge Validation

After the Pages deployment and the Engine publication the public overview shows 21 Grid and Table covers. Whoever merges the Pages pull request records the served result under #20498.

## Out of Scope

Covers for the other families (#21120, #21121; they reuse this script); the card (#21119); caption copy; where deployed covers are served from.

## Avoided Traps

- A frame of the example's untouched default view: most of these examples open on a plain grid that looks like the next one.
- A whole-window screenshot: at card width it is texture.
- A mock-up or a composited image: a cover is a capture of the running example.
- A script that needs a service or a private checkout: it runs against the local dev server, so a contributor can add a recipe.
