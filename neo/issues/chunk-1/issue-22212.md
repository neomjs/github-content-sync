# The two-thread line logs a departed window's dead port as a failed update

## Context

ADR 0043's Phase-1 gate (b) ran the #22114 Workstation tear-out specs at matched repeats in both arms (#22208). The worker arm stayed clean. The two-thread arm (`useVdomWorker: false`) failed `WorkstationFiveBeatNL` scene 2 (morph): L2644 *"out past the edge and BACK IN: the vessel retires mid-drag"* and L2688 *"after a whole-stack return … the born vessel mounts its pane"*. Each run below used `repeatEach: 8`.

| Head | Arm | Run | L2644 failed | L2688 failed |
|---|---|---|---|---|
| `d8e3bf0` (#22210, with I3) | worker | [45665562433](https://github.com/neomjs/neo/actions/runs/45665562433) | 0/8 | 0/8 |
| `d8e3bf0` (#22210, with I3) | two-thread | [45665578649](https://github.com/neomjs/neo/actions/runs/45665578649) | 7/8 | 5/8 |
| `dev` `a33e762` + the arm switch only, no I3 | two-thread | [45668777889](https://github.com/neomjs/neo/actions/runs/45668777889) | 8/8 | 6/8 |

Every failure is the same `workerErrors` fixture catch:

```text
App Worker: vdom update failed neo-container-19 worker.Base#promiseMessage: no live port for destination "<vessel windowId>" (updateVdom) — a window closed?
    at App.applyDeltas (src/worker/App.mjs:139:21)
    at BodyContainer.executeVdomUpdate (src/mixin/VdomLifecycle.mjs:588:27)
```

Two conclusions follow:
- **The defect predates I3.** The third row has no I3 and fails the same way.
- **Only the two-thread line hits it.** In the worker arm the App worker never sends deltas to a window itself.

## The Problem

Observed: a `BodyContainer` flight targets the retired vessel's window id, and its send fails because that window's port is gone.

Inferred from the source cited below: the vessel's disconnect removes its port, and the App worker reaps the departed tree one task later. A flight collected in that gap for a component still bound to the vessel sends with `Neo.applyDeltas(windowId, …)`. `promiseMessage` finds no port and rejects with `code: 'NEO_DEAD_PORT'`. `executeVdomUpdate`'s catch logs `console.error('vdom update failed', …)`.

The departure is expected teardown, not a failed update. The catch already releases the flight: it unregisters the in-flight state and rejects the parked callbacks. Only the error log is wrong, and under the `workerErrors` fixture that log turns this tear-out red in every two-thread run. That blocks the default flip (#22209).

## The Architectural Reality

- **`promiseMessage`** (`src/worker/Base.mjs` L724–742): a missing port rejects with `{code: 'NEO_DEAD_PORT', destination, windowId}`.
- **`removePort`'s in-flight rejection** (L524–532): carries `code: 'NEO_DEAD_PORT'` and `name: 'PortDisconnectedError'` (#19727).
- **`isDeparture(reason, windowId = reason?.windowId ?? reason?.destination)`** (L414–416): the two-part test #19071 made the one departure predicate, `code === 'NEO_DEAD_PORT' && isWindowDeparted(windowId)`.
- **`App#onDisconnect`** (`src/worker/App.mjs` L701): removes the port, then reaps with `timeout(0)`, *"after every listener and its microtask chain"*.
- **`initVnode`'s catch** already decides with it: `worker?.isDeparture?.(err, me.windowId) || console.error('initVnode error', err, id)`.
- **`executeVdomUpdate`'s catch** (`src/mixin/VdomLifecycle.mjs` L664 at `d8e3bf0`) stays silent only for:
  - a destroyed-only flight;
  - `err?.name === 'PortDisconnectedError'`;
  - parked promise callbacks.

  A dead port at send time, which is not a `PortDisconnectedError`, reaches the log. The line's `applyDeltas` send postdates #19071's four sites.

Design authority: `worker.Base#isWindowDeparted`, *"the discriminator for `code: 'NEO_DEAD_PORT'` when the caller must tell an expected teardown from a real failure and has only a `windowId`"* (`src/worker/Base.mjs`, JSDoc above `isWindowDeparted`).

## The Fix

In `executeVdomUpdate`'s catch, replace the name test `err?.name === 'PortDisconnectedError'` with `Neo.currentWorker?.isDeparture?.(err)`:
- **One predicate covers both departures.** Since #19727, an in-flight retired-port rejection carries `NEO_DEAD_PORT` and its `windowId`, so the predicate silences that case and the dead port at send time.
- **No `windowId` argument is needed.** The rejection carries `destination`, which is the flight's window.
- **A real dead port still logs.** A port for a window that never departed fails `isWindowDeparted`, which #19071 requires to stay visible.
- The cleanup path is unchanged.

## Contract Ledger

None: no consumed surface changes. The flight still rejects its parked callbacks with the same error; only the console line goes.

## Decision Record impact

`aligned-with` `adr:0043-vdom-diff-placement`: Phase 1 makes the line the default, and this removes a false failure that only the line produces, which the gate measured.

## Acceptance Criteria

- [ ] A flight whose send rejects with `NEO_DEAD_PORT` for a departed window, at send time or in flight, logs no `vdom update failed`. It still releases its in-flight state and rejects its callbacks. The unit spec for the send-time case is red on `dev`.
- [ ] Negative control: a `NEO_DEAD_PORT` for a window that has not departed, and any other send error, still logs.
- [ ] `WorkstationFiveBeatNL` at `repeatEach: 8` in the two-thread arm (dispatch `neoConfig: {"useVdomWorker":false}`) shows no `no live port … (updateVdom)` failure, against the receipts above.

## Out of Scope

- The default flip itself (#22209).
- Why a flight is collected for a departed window at all: the reap runs a task after the disconnect by design.
- The name tests in `src/Neo.mjs` and `src/worker/App.mjs`.

## Avoided Traps

- **Waiving the line in the spec** (`workerErrors.expect(/no live port/)`): it would hide the defect from every other tear-out.
- **Treating every `NEO_DEAD_PORT` as departure:** a dead port for a window that never departed is a real misroute, which is why `isDeparture` checks the departure record (#19071, #20041).
- **Adding the predicate beside the name test:** that keeps the suppression by error name that #19727 ruled out.
- **Blaming I3:** the probe row without I3 fails the same way.
