# A grid selection model can select cells only as a list of ids

## Context

Part of #20667: what an application or a package outside this repository can contribute to the grid. A selection model is such a contribution, and today it can state a cell selection only as one id per cell. Measured on `dev` `62f75736ba`.

## The Problem

A model that selects by a rule (the rectangle between two cells, every cell of a store, a band of rows) cannot tell the grid which cells are selected. It has to write one logical cell id per cell into `items`, and the row then scans that array once for every cell it renders.

**Measurement.** `Neo.selection.grid.CellModel` with `singleSelect: false`, a store of 20,000 records and 20 columns, a row pool of 36 rows (720 cells), in the unit tier. Render is the median of seven forced `grid.Body#createViewData(true, true)` runs.

| ids in `items` | Render, window outside the selection | Render, window at its start | One `updateCells(items)` pass |
|---|---|---|---|
| 0 | 2.5 ms | 2.3 ms | 0.05 ms |
| 1,000 | 2.7 ms | 2.7 ms | 3.5 ms |
| 10,000 | 6.4 ms | 2.6 ms | 24.8 ms |
| 100,000 | 49.9 ms | 2.6 ms | 269 ms |
| 200,000 | 107.6 ms | 2.6 ms | 603 ms |

A rectangle of 10,000 rows and 20 columns is 200,000 ids: 43 times the render time and 0.6 s for each selection change, where the answer per cell is two comparisons. A handful of selected cells costs nothing measurable, so this is a missing seam, not a slow path a user of the shipped models meets.

## The Architectural Reality

- `Neo.grid.Row#applyRendererOutput` paints a cell's selection from two fixed rules: `selectionModel.selectedColumns.includes(dataField)` (`src/grid/Row.mjs:273`) and `selectedCells.includes(gridBody.getLogicalCellId(record, dataField))` (`:303`).
- `selectedCells` is `Neo.grid.View#selectedCells`, the model's `items` (`src/grid/View.mjs:282`). The View owns the one model and a row paints the View's projection without holding it (`#18626`).
- The row class is fixed: `Neo.grid.Body#createRowPool` creates `module: Row` (`src/grid/Body.mjs:771`).
- Columns already repaint without ids: `Neo.selection.grid.BaseModel#updateColumns` walks the rendered rows and their cell nodes (`src/selection/grid/BaseModel.mjs:581`). Cells have `updateCells(logicalIds)`, one lookup per id and body.
- `aria-selected` on a cell is written at the same places (`Row.mjs:305`, `BaseModel#updateBodyCells`).
- `#20115` guarded the scan for an empty selection; the scan for a non-empty one is unchanged.
- Design authority: n/a — a missing seam; no existing behavior is called wrong.

## The Fix

The row asks, through the View, whether a cell is selected.

1. `Neo.selection.grid.BaseModel` gains `isSelectedCell(record, dataField)`. The default answers from `items` in constant time, so the six shipped models paint what they paint today. A model that selects by rule overrides it.
2. `Row#applyRendererOutput` uses that answer in place of the scan at `:303`, reached through the View as `selectedCells` is today.
3. `BaseModel` gains the cell counterpart of `updateColumns`: one method that re-evaluates the answer over the rendered rows and updates only the rows that changed. A rule change repaints through it, with no id list.
4. `BaseModel` gains `getCellCls(record, dataField)`, the classes a model adds to a selected cell, empty by default. A model that draws an outline around its selection needs them.

`items` is written in place (`cloneOnGet: 'none'`), so the constant-time lookup has to stay true to it. Where that lookup lives is the implementer's call.

## Acceptance Criteria

- [ ] The six shipped grid selection models paint the same cells, rows and columns as before. The existing selection specs pass unchanged: `ColumnSelection`, `ViewOwnedSelectionModel`, `SelectionModelStateIsolation`, `RowModelKeypressClick`. `RowCellIdMigration` keeps every arm but one: the arm that pinned the row's own scan of an id array pins the row asking the View's cell model once per living cell.
- [ ] A unit spec defines a model that selects a rectangle by rule and keeps `items` empty. The cells inside carry the selected class and `aria-selected` on first render, after the rule changes, and on rows that enter the pool by scrolling.
- [ ] `Row#applyRendererOutput` scans no array per cell for cell selection. The pull request body repeats the table above; the render with 200,000 selected ids lies within the run-to-run spread of the render with none.
- [ ] Classes from `getCellCls` reach the cell node and leave it when the model stops returning them.
- [ ] Each new method's JSDoc says when a model overrides it.

## Out of Scope

- Any shipped model that selects by rule. This ticket delivers the seam and a test model.
- Keyboard, pointer and accessibility behavior of any model.
- The column rule at `Row.mjs:273`. It moves behind the same answer only if that makes the diff smaller.

## Avoided Traps

- **Materializing the rule into ids.** The table above.
- **A configurable row class.** Every package would subclass `Row` to change one predicate.
- **A model read from the body.** `#18626` moved the model to the View; the row keeps reading the View's projection.
