# After Back, the examples side nav keeps focus on the walked link

## Context

#22098 (Resolves #22061) failed its Post-Merge Validation on neomjs.com 14.0.0. The run used a 1440 × 900 viewport and real key presses, and the failure reproduced 2/2 ([receipt](https://github.com/neomjs/neo/pull/22098#issuecomment-7117364914)). Observed: after a history Back, the side nav's focus no longer matches the page the user sees.

## The Problem

Steps on `/examples/scheduler`:
1. Focus the Scheduler link in the side nav.
2. ArrowDown: Gantt opens (`/examples/gantt`) and focus moves to the Gantt link.
3. Browser Back: the URL returns to `/examples/scheduler`. `aria-current="page"` and the Tab stop (`tabIndex 0`) move back to the Scheduler link, and Gantt goes to `tabIndex -1`.
4. ArrowRight.

- **Expected:** Scheduler's first card ("Studio Bookings") takes focus.
- **Observed:** DOM focus is still on the Gantt link from step 3. ArrowRight opens `/examples/gantt` again and focuses Gantt's first card ("Community Garden Plan").

A keyboard user who walks the nav and then goes Back (Alt+Left, Cmd+[, or the back button) sees Scheduler, but their next ArrowRight lands in Gantt.

From a freshly focused Scheduler link, ArrowRight focuses the first card and ArrowLeft returns to the link, so #22061's AC-5 and AC-6 hold. Only the route change from history leaves focus behind.

## The Architectural Reality

- `apps/portal/view/examples/GroupIndex.mjs:355-368` (`onKeyDown`): ArrowRight fires `enterCards` with `getLinkRoute(data.target?.id)`, which is the route of the **focused** link.
- `apps/portal/view/examples/MainContainer.mjs:361` wires `enterCards` and `walk` to the controller (`onIndexEnterCards`, `onIndexWalk`), which writes the route.
- A history Back changes the route without a walk. The index moves `aria-current` and the Tab stop to the new link, but DOM focus stays on the link the walk rested on.

Design authority: the `GroupIndex` class JSDoc (`GroupIndex.mjs:18-21`):
> "the open destination's link (or `"All examples"` when on `/examples`) carries `aria-current="page"`. `list` is one Tab stop, that link (`"All examples"` under a filter), and the arrow keys, Home and End walk the links through `Neo.main.addon.Navigator`. The link a walk rests on asks to open (`walk`), ArrowRight asks for the cards (`enterCards`), and the controller does both."

Here focus rests on a link that is neither the Tab stop nor `aria-current`.

## The Fix

When the route changes by history while focus rests on an index link, move focus to the open destination's link, the new Tab stop. The next key then acts from the page the user sees. A Back with focus outside the side nav moves no focus. The rest of #22061's model stays as it is.

## Acceptance Criteria

- [ ] `ExamplesCatalogNL.spec.mjs`, side nav keys: Scheduler link → ArrowDown → `page.goBack()` → ArrowRight focuses Scheduler's first card, and ArrowLeft returns to the Scheduler link. The spec is red on `dev` at `3f3acb8aea` before the fix.
- [ ] A Back while focus is outside the side nav leaves focus where it was.
- [ ] Post-merge: #22098's Post-Merge Validation item passes on neomjs.com.

## Out of Scope

- Scrolling the Learn tree's selected leaf into view after a deep link. That is a separate observation (the `guides/datahandling/Tables` leaf sits 2772 px down in a 900 px viewport).
- Any change to the walk, Home/End or the phone presentations.

## Avoided Traps

- **Resolving `enterCards` from the shown route instead of the focused link.** ArrowRight on a visibly focused "Gantt" link would then enter Scheduler's cards, which is a second desync.
