# Each dist build copies 5,839 Font Awesome files; the runtime loads 5

## Context

The development and production webpack builds of the main thread end by copying the whole `@fortawesome/fontawesome-free` npm package into the dist folder:

- `buildScripts/webpack/development/webpack.config.main.mjs:19-20,61`
- `buildScripts/webpack/production/webpack.config.main.mjs:18-19,68`

Both run `copyFolder -s node_modules/@fortawesome/fontawesome-free -t <dist>/resources/fontawesome-free`. `#3082` introduced the copy in 2022.

Measured on `dev` at `5343d947d2`, with `@fortawesome/fontawesome-free` 7.3.1:

| What | Files | Bytes |
|---|---|---|
| The package, as copied | 5,839 | 25,338,026 |
| `css/all.min.css` | 1 | 90,336 |
| `webfonts/` (four `.woff2`) | 4 | 258,588 |
| `LICENSE.txt` | 1 | 7,427 |

On disk the copy takes 42,328 KB in `dist/development/resources/fontawesome-free` and the same again in `dist/production/resources/fontawesome-free` (`du -sk`). Most of it is `svgs-full/` (11.7 MB), `svgs/` (11.6 MB), `metadata/` (7.4 MB), `js/` (6.7 MB), the two sprite folders (3.7 MB) and `scss/` (0.3 MB).

## The Problem

The runtime loads one file from the copy: `resources/fontawesome-free/css/all.min.css` (`src/main/addon/Stylesheet.mjs:55`). That stylesheet references four files, all in `../webfonts/`. No other line in `src/`, `apps/`, `examples/`, `docs/app`, `learn/`, `resources/`, `buildScripts/` or `test/` names the copied folder, apart from the two config lines that write it.

So five files are used and 5,834 are not: SVG sources, sprites, icon metadata, a JavaScript build and SCSS sources. Every dist folder carries them, in this repository and in every workspace that builds with the engine's configs. A workspace that deploys its dist folder uploads them. A workspace whose deploy check forbids source files in the output cannot use the engine's copy step at all and has to replace it.

## The Architectural Reality

- `buildScripts/util/copyFolder.mjs` is `fs.copySync(source, target)` behind two flags, `-s` and `-t`. It has no include or exclude option.
- Both configs pass the command to `WebpackHookPlugin`'s `onBuildEnd` list, and each holds its own copy of the `faFrom` / `faTo` paths.
- `src/main/addon/Stylesheet.mjs:53-55`: dev mode and `dist/esm` read the stylesheet from `node_modules/`; only the two webpack dist environments read it from `resources/fontawesome-free/`.

## The Fix

Copy what the runtime loads, and nothing else: `css/all.min.css`, the `webfonts/` folder and `LICENSE.txt`.

The shape is the implementer's choice: narrower copy commands, or an include option on `copyFolder.mjs`. Either way both configs take the list from one place, so the development and production builds cannot drift apart.

## Acceptance Criteria

- [ ] After `npm run build-all`, `dist/development/resources/fontawesome-free` and `dist/production/resources/fontawesome-free` each hold exactly `css/all.min.css`, `webfonts/` and `LICENSE.txt`.
- [ ] Every `url(...)` in the copied `all.min.css` resolves to a file inside the copied tree.
- [ ] A unit spec reads the installed package's `css/all.min.css`, extracts its `url(...)` references and fails when one of them is not covered by the copy list. A Font Awesome upgrade that adds a font file then fails a spec instead of shipping broken icons.
- [ ] The development and production configs take the copy list from one shared place.
- [ ] The PR body shows an icon rendering from `dist/production` (for example `dist/production/apps/portal/index.html` behind `npm run server-start`): a screenshot, or the computed `font-family` of one `.fa-solid` element.

## Out of Scope

- Subsetting the icon fonts, or replacing Font Awesome.
- Dev mode and `dist/esm`, which read the package from `node_modules/` and copy nothing.
- The workspace template in `neomjs/create-app`.

## Avoided Traps

- **Deleting after the copy.** A cleanup step still writes 5,839 files in every build. Copy less instead.
- **Dropping the licence file.** It is 7 KB, and the package's licence terms ask for it to travel with the fonts.
- **A size budget alone.** "Under 1 MB" passes today and says nothing when a font file goes missing. The reference check in the third criterion is the one that fails for the right reason.
