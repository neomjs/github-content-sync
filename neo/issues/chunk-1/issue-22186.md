# Release in-flight OffscreenCanvas transfers orphaned before onCanvasRegistered

`handoff: @neo-gemini-julia` (author of `#22174`, `73e6207999`; her `neomjs/neo` checkout is clean on `dev` while mine holds `#22179`).

## Context

Immediately after `#22174` (`73e6207999`, `Resolves #22125`) merged to `dev` at `2026-11-25T08:31:19Z`, `e2e-engine (9/18)` (`test/playwright/e2e/workstation/WorkstationPopOutSparklinesNL.spec.mjs:485` and `:490`) failed on both:
1. `dev` post-merge run [`45577018733` (`job 139077529480`)](https://github.com/neomjs/neo/actions/runs/45577018733/job/139077529480):
   - `native-close`: `Expected {mapDelta: 0, sparklineDelta: 0, staleBindings: 0, staleSparklines: 0}`, received `{mapDelta: 13, sparklineDelta: 0, staleBindings: 0, staleSparklines: 0}`.
2. PR `#22179` run [`45579463606` (`job 139085619813`)](https://github.com/neomjs/neo/actions/runs/45579463606/job/139085619813) (`Merge 147ac3201d into 73e6207999`):
   - `native-close`: `{mapDelta: 13, sparklineDelta: 0, staleBindings: 0, staleSparklines: 0}`
   - `group-undo`: `{mapDelta: 6, sparklineDelta: 0, staleBindings: 0, staleSparklines: 0}`

## The Problem

1. When `FeedPane` pops out of the opener window's dock layout in `WorkstationPopOutSparklinesNL.spec.mjs`, `ScalePane` in the opener expands to fill the vacated space, growing the live `Sparkline` instance count in the opener from `18` (`find_instances` `7,560 B`) to `31` (`11,125 B` — exactly **`+13`** pooled `ScalePane` sparklines).
2. When `FeedPane` returns to the opener (`native-close` or `group-undo`), `ScalePane` shrinks back and destroys/unmounts those `13` extra sparkline cells (`31 -> 18`).
3. On slower Linux CI runners (`16.7s` vs `9.8s` on M5 Max), `DomAccess#transferCanvasToWorker` (`src/main/DomAccess.mjs:1710-1717`) has **already** transferred the `<canvas>` to `Neo.worker.Canvas#registerCanvasDirect` (`cw.map[nodeId] = offscreen`, `cw.canvasWindowMap[nodeId][openerId] = offscreen`), **while `canvasRegistered` (`Canvas -> App`) is still in flight** (`me.offscreenRegistered === false`).
4. When `ScalePane` unmounts/destroys (or moves) those cells before `canvasRegistered` arrives in the App Worker:
   - `Canvas#afterSetMounted(false)`, `Canvas#afterSetWindowId`, and `Canvas#destroy` (`src/component/Canvas.mjs:219-284`) cancel `registerCanvasCallbacks[id]` (`promise` resolves `false`), see `me.offscreenRegistered === false`, and **skip** `Neo.worker.Canvas.unregisterCanvas`.
   - Moments later, `App#onCanvasRegistered({componentId, nodeId, windowId})` (`src/worker/App.mjs:590-599`) arrives in the App Worker (strictly after `Canvas` Worker executed `registerCanvas`), sees `!instance` (or no matching callback / mismatched `windowId` / `!instance.mounted`), and **does nothing**.
   - Result: `Sparkline.register` never ran (`sparklineDelta: 0`), `windowId` was `openerId` rather than `departedPopupIds` (`staleBindings: 0`, `staleSparklines: 0`), and all `13` (or `6`) `OffscreenCanvas` entries remain orphaned in `Neo.worker.Canvas.map` (`mapDelta: 13` / `6`).

## The Architectural Reality

- `Design authority:` `#22125` AC-1/AC-3 (`WorkstationPopOutSparklinesNL.spec.mjs:482`: `expect(...).toEqual({mapDelta: 0, sparklineDelta: 0, staleBindings: 0, staleSparklines: 0})`) and `src/worker/Canvas.mjs:215-224` (`registerCanvasDirect` registers into `map` + `canvasWindowMap` before posting `canvasRegistered` to the App Worker).
- Because `Main -> Canvas` (`registerCanvasDirect` on the SharedWorker port) and `App -> Canvas` (`unregisterCanvas` on `channelPorts.app`) travel over separate `MessagePort`s without cross-port FIFO ordering, sending `unregisterCanvas` eagerly at cancel-time in `Canvas.mjs` could arrive at `Canvas` *before* `registerCanvasDirect`. By contrast, `App#onCanvasRegistered` fires **strictly after** `Canvas#registerCanvas` completed!

## The Fix

1. **`src/worker/App.mjs` (`onCanvasRegistered`, lines `590-599`):**
   - When `onCanvasRegistered({componentId, nodeId, windowId})` arrives:
     - If `instance && !instance.isDestroyed && instance.mounted && instance.registerCanvasCallbacks?.[nodeId] && (!windowId || !instance.windowId || instance.windowId === windowId)`: delete and invoke `registerCanvasCallbacks[nodeId]()` as today (so `instance.offscreenRegistered` flips `true` and normal lifecycle teardown owns cleanup from that point on).
     - **Otherwise** (component already destroyed, unmounted, moved to another `windowId`, or superseded by a newer `#mountGeneration` before `canvasRegistered` arrived, AND `!instance?.offscreenRegistered` for that `(nodeId, windowId)`): call `Neo.worker.Canvas.unregisterCanvas({nodeId, windowId: windowId || instance?.windowId})` (routing via `windowId`'s canvas group when `windowId` is present) so the already-registered `OffscreenCanvas` is deterministically evicted from `cw.map` and `cw.canvasWindowMap`!
   - Guard against evicting a live re-registration on the same `(nodeId, windowId)` when `instance?.offscreenRegistered && instance.getCanvasId?.() === nodeId && (!windowId || instance.windowId === windowId)`.
2. **Also verify baseline settle in `WorkstationPopOutSparklinesNL.spec.mjs` (`lines 389-394`):**
   - Ensure `ScalePane`'s initial opener sparklines have **all** finished `offscreenRegistered` + `Sparkline.items` registration (`every` mounted opener sparkline registered, not just `.toBeGreaterThan(0)` on the first cell) before sampling `baselineRegistry` so an un-settled initial `ScalePane` cell never skews `baselineRegistry.mapCount`.
3. **Unit test (`test/playwright/unit/worker/CanvasGroupLifetimes.spec.mjs` or `CanvasWindowCleanup.spec.mjs`):**
   - Add a deterministic unit test reproducing `transferCanvasToWorker` -> component unmount/destroy/window-move while `offscreenRegistered === false` -> late `App#onCanvasRegistered` arrival -> asserts `Neo.worker.Canvas.unregisterCanvas({nodeId, windowId})` is called and `cw.map` / `cw.canvasWindowMap` return to `0`.

## Acceptance Criteria

- [ ] AC-1: `App#onCanvasRegistered` in `src/worker/App.mjs` calls `Neo.worker.Canvas.unregisterCanvas({nodeId, windowId})` whenever `canvasRegistered` arrives after the owning `Canvas` component was destroyed, unmounted, moved to another `windowId`, or superseded before `offscreenRegistered` became `true` (without evicting an already-live registration on the same `(nodeId, windowId)`).
- [ ] AC-2: `WorkstationPopOutSparklinesNL.spec.mjs` waits for all mounted opener `ScalePane` sparklines (not just `> 0`) to finish `offscreenRegistered` + renderer registration before capturing `baselineRegistry`, and passes both `native-close` and `group-undo` arms cleanly (`mapDelta: 0`).
- [ ] AC-3: Unit test in `test/playwright/unit/worker/` reproduces the in-flight unmount/destroy `onCanvasRegistered` race (red on `73e6207999`, green with fix).

## Out of Scope

- VDOM engine or `Grid.Body` row-pooling changes (forbidden without ADR and unnecessary here).

## Avoided Traps

- **Calling `unregisterCanvas` inside `Canvas#cancelPendingRegistration` before `canvasRegistered` arrives:** `Main -> Canvas` (`registerCanvasDirect`) and `App -> Canvas` (`unregisterCanvas`) use distinct `MessagePort`s; `unregisterCanvas` can arrive before `registerCanvasDirect` and leave `cw.map[nodeId]` stranded anyway. Releasing inside `App#onCanvasRegistered` guarantees causal ordering *after* `Canvas#registerCanvas`.
