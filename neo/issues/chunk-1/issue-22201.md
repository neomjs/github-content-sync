# Mark Web Desktop as Multi-Window in the Portal examples catalog

## Context

Native multi-window tear-out for `Neo.desktop` and `apps/webdesktop` landed right before the Engine 14.0.0 cut (`#21603` / PR `#22067` at `dd8dbec672`, followed by `#22084`, `#22107`, `#22108`, and `#22110`): `apps/webdesktop/neo-config.json` runs with `"useSharedWorkers": true`, `apps/webdesktop/app.mjs` boots `Neo.desktop.PopupViewport` on `?desktopPopup`, and `apps/webdesktop/view/Viewport.mjs` configures `tearOutUrl: './index.html'` so open app windows pop out or tear out into native browser windows and return cleanly.

Because `#22067` landed at the release lock after `apps/portal/resources/data/examples/apps.json` was authored in `#21331`, the `"webdesktop"` catalog record (`apps/portal/resources/data/examples/apps.json:26-56`) still omits both `"sharedWorkers": true` and `"alsoIn": ["multi-window"]`.

## The Problem

1. **Missing `Multi-window` badge and broken same-environment SharedWorker launch target:** `Portal.view.examples.List#createItemContent` (`apps/portal/view/examples/List.mjs:294-297`) hides `.neo-multi-window` when `!record.sharedWorkers`, and `List#createLink` (`:344-348`) sets `target: '_blank'` whenever `!record.sharedWorkers || this.environment !== Neo.config.environment || externalLink`. Because `apps/webdesktop/neo-config.json` sets `"useSharedWorkers": true`, omitting `"sharedWorkers": true` both suppresses the `Multi-window` cover badge on `Start here` / `Apps` and opens Web Desktop in a new tab sharing the Portal's App Worker when both run in the same environment (`devmode` or `dist_prod`).
2. **Missing from `/examples/multi-window` and `multi-window` search/SEO:** Without `"alsoIn": ["multi-window"]`, `Portal.model.Example.belongsTo(record, 'multi-window')` (`apps/portal/model/Example.mjs:122-124`) excludes `webdesktop` from `/examples/multi-window`, `Example.matchesQuery` (`:178`) omits `"Multi-Window"` from its group-title search tokens, and `apps/portal/resources/data/seo.json` (`:1174-1179`, `:1264-1268`) neither counts Web Desktop in `/examples/multi-window` (`12` → `13`) nor labels `/apps/webdesktop/index.html` as a `Multi-Window JavaScript Demo`.

## The Architectural Reality

Design authority: `"family names the record's home group, one id of Portal.view.examples.MainContainer#familyDefinitions; alsoIn lists the other groups that show it (empty by default)."` (`Portal.model.Example#fields`, `apps/portal/model/Example.mjs:21-22`) and `"// Do not open multi-window examples inside a new browser window, in case the environment is the same."` (`Portal.view.examples.List#createLink`, `apps/portal/view/examples/List.mjs:344-348`, paired with `.neo-multi-window`'s `removeDom: !record.sharedWorkers` at `:294`).

- Sibling `apps.json` records that run on `useSharedWorkers: true` and detach views into native popups (`email` at `apps.json:132-164` and `on-air-at-eight` at `apps.json:166-188`) keep `"family": "apps"` as their home group while setting `"sharedWorkers": true` and including `"multi-window"` in `"alsoIn"`.
- Keeping `"family": "apps"` preserves `MainContainerController.spec.mjs:1052` (`moved.apps`), keeps `Apps`'s home count unchanged (`10` cards in `devmode` for `ExamplesCatalogNL.spec.mjs:661,700`), keeps Web Desktop's `Start here` home-group badge as `Apps`, and increments `/examples/multi-window`'s `crossCount` by `1` (`order: 110`, placing Web Desktop right after `workstation` and `shared-covid`).
- `buildScripts/docs/seo/seoJson.mjs` derives both `/examples/multi-window`'s example count and per-app `Multi-Window JavaScript Demo` titles from the catalog records (verified locally via `node buildScripts/docs/seo/verify.mjs`, with unit contracts in `test/playwright/unit/buildScripts/docs/seo/` running in CI and `buildScripts/release/prepare.mjs` regenerating `seo.json` at release).

Decision Record impact: none.

## The Fix

1. **`apps/portal/resources/data/examples/apps.json` (`id: "webdesktop"`):**
   - Add `"alsoIn": ["multi-window"]` and `"sharedWorkers": true` (preserving `"family": "apps"` and `"order": 110`).
   - Update `lookFor`, `scope`, and `keywords` to mention popping out / dragging an app window into its own browser window and `Allow popups` on desktop while preserving the authorization caveat (`"hiding UI is not authorization"`), and keeping `feature` concise so `Start here`, `Apps`, and `Multi-Window` card footers stay whole at rest (`ExamplesCatalogNL.spec.mjs:1010`).
2. **`apps/portal/resources/data/seo.json`:**
   - Regenerate via `node buildScripts/docs/seo/generate.mjs -f seo-json` and verify with `node buildScripts/docs/seo/verify.mjs` so `/examples/multi-window` (`13` live multi-window examples) and `/apps/webdesktop/index.html` (`Web Desktop — Multi-Window JavaScript Demo | Neo.mjs`) stay synchronized.
3. **`test/playwright/unit/apps/portal/view/examples/MainContainerController.spec.mjs` (`:1232-1244`, `:1517`):**
   - Include `'webdesktop'` in the cross-listed `Example.belongsTo(record, 'multi-window') && record.family !== 'multi-window'` assertion and pin `sharedWorkers: true` on `store.get('webdesktop')`.

## Acceptance Criteria

- [ ] `webdesktop` in `apps/portal/resources/data/examples/apps.json` carries `"sharedWorkers": true` and `"alsoIn": ["multi-window"]` while keeping `"family": "apps"`, renders the `.neo-multi-window` (`Multi-window`) badge on `/examples`, `/examples/apps`, and `/examples/multi-window`, omits `target="_blank"` when `Portal.view.examples.List#environment === Neo.config.environment`, and keeps its `feature` whole at rest on desktop cards.
- [ ] `webdesktop`'s progressive details (`lookFor`, `scope`, `keywords`) note popping out / tearing out an open app window and popup permission on desktop while retaining `"hiding UI is not authorization"`, without overflowing `.portal-example-more`'s `<= 40%` cover band on `1 × 1` cards or the docked lead-card details band (`ExamplesCatalogNL.spec.mjs`).
- [ ] `apps/portal/resources/data/seo.json` is regenerated and passes `node buildScripts/docs/seo/verify.mjs`.
- [ ] `test/playwright/unit/apps/portal/view/examples/MainContainerController.spec.mjs` and `test/playwright/e2e/portal/ExamplesCatalogNL.spec.mjs` pass.

## Out of Scope

- Changing `apps/webdesktop` or `src/desktop` runtime tear-out behavior (`#22185`, `#22114`).
- Publishing a standalone catalog card for `examples/desktop/basic`.
- Re-capturing `devmode/webdesktop-14-0.jpg` / `webdesktop-14-0-light.jpg`.

## Avoided Traps

- Moving `webdesktop`'s `"family"` from `"apps"` to `"multi-window"`, which breaks `MainContainerController.spec.mjs:1052`, changes its `Start here` group pill from `Apps` to `Multi-Window`, and drops `Apps` below the `10`-card `3n + 4` layout check in `ExamplesCatalogNL.spec.mjs:661,700`.
- Editing `apps.json` without regenerating `apps/portal/resources/data/seo.json`, which fails `node buildScripts/docs/seo/verify.mjs` on `/examples/multi-window` count and `/apps/webdesktop/index.html` title metadata.
- Lengthening `webdesktop.feature` past a single resting footer line on desktop cards (`ExamplesCatalogNL.spec.mjs:1010` `featureWhole`).
