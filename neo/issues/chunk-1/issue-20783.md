## The Problem

The failing test is neomjs/neo-agent-institution `test/playwright/e2e/agentos/FleetActivityObserver.spec.mjs`, › "by keyboard: the rows are one Tab stop, arrows move the row focus, Enter opens the focused message, Escape closes it". All of its steps pass. What fails is the fixture's no-worker-error check, which receives the same error repeatedly (stack at `5f407d69`):


The file's two mouse-driven tests stay green, so the error belongs to the keyboard sequence:
1. Tab into the rows, then ArrowDown ×2.
2. Enter opens the detail; Escape closes it.
3. Tab out.
4. Switch to the "mailbox" mode, then click a row and press Enter.

**Unknown:** which step emits the first error. The run's Playwright trace (`trace: 'on'`) answers that.

## The Architectural Reality

- `ActivityStream` (`apps/agentos/view/fleet/activity/Container.mjs` in the Institution) renders its rows with a `Neo.list.Buffered`. Buffered pools row components with ids `<list-id>__<index>__component` and destroys them as the range or the store changes (`src/list/Buffered.mjs`, the `destroy()` call sites).
- #20743 changed `VdomLifecycle#updateVdom` in two ways:
  - While a parent or child update is in flight, a component now records `needsVdomUpdate = true` and runs later. Before, it waited only on the no-vnode branch.
  - `afterExecuteVdomUpdate` now runs once per live emitted root.
- The throw comes from `syncVnodeTree` → `VNode.createMap`. That walk resolves every component reference in the returned vnode tree through `getVnode`, and an id with no live component throws.
- **Inference, not verified:** the deferred update now runs after Buffered has destroyed or re-pooled row component `__6__`, and the tree it syncs still references that id. The guard in #20764 (incoming reparent unmounts) does not cover this path; the error persists at `5012129e`.

## The Fix

1. Reproduce it in the engine: a `Neo.list.Buffered` with component rows, whose rows are replaced while an ancestor update is in flight and a row update is deferred. The new spec must be red at `5f407d69` and green at `c7e19744`. The Institution spec stays the consumer witness.
2. Fix it at the seam the reproduction names: the deferred path in `VdomLifecycle`, or how `syncVnodeTree` treats references to components destroyed since the update was scheduled. Keep the gains #20743 measured (S1/S2 in `#20747`).

**Outcome (#20793):** the seam was `Neo.list.Buffered`, which destroyed pooled rows without unlinking them from its stored vnode. `VdomLifecycle` is unchanged. Step 1's red-at-`5f407d69` target did not hold: `src/list/Buffered.mjs` is unchanged since `c7e19744`, so the spec pins `Buffered`'s invariant instead, red on `dev` and green at the fix.
