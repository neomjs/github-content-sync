# Example cards clip bottom border and shadow on Overview and Search

## Context

Operator (`@tobiu`, `2026-11-25`) spotted on `/examples` (`Portal.view.examples.Overview`) in both `neo-light` and `neo-dark` that the bottom row of `"Start here"` example cards (`Web Desktop` and `Dock Choreography Demo`) has its `1px` bottom border and drop shadow cut off flush at the card's bottom edge. Curated `good first issue` / `help wanted` labels are omitted because this maintainer-owned quick-win fix is being delivered immediately.

## The Problem

Each `.neo-list-item` in `Portal.view.examples.List` (`resources/css/src/apps/portal/examples/List.css:91`) paints both its `1px` perimeter ring and its elevation shadow via an **outset `box-shadow`**:

```css
box-shadow: 0 0 0 1px var(--portal-examples-list-edge), var(--portal-examples-list-shadow), var(--portal-examples-list-glow);
```

Because an outset `box-shadow` paints outside the element's border box (`1px` ring + `0 8px 22px` / `0 10px 28px` resting shadow, expanding to `0 14px 34px` on `:hover`), any ancestor scroll container with `overflow: auto` and `padding-bottom: 0` slices off the entire bottom border and shadow of the final row.

## The Architectural Reality

In `apps/portal/view/examples/List.mjs:104-107, 416-418`, `_vdom` is `{cn: [{tag: 'ul', cn: []}]}` and `getVdomRoot()` returns `this.vdom.cn[0]`. Consequently, even when `useWrapperNode: false` (`Overview.mjs:192-193`, `SearchResults.mjs:136-140`):
- The outer `<div>` (`this.vdom`) receives `wrapperCls` (`portal-examples-overview-cards`, `portal-examples-search-cards`, `portal-examples-search-tiles`) plus `.neo-flex-item`.
- The inner `<ul>` (`this.vdom.cn[0]`) receives `cls` (`portal-examples-list neo-list ...`).

In both `resources/css/src/apps/portal/examples/Overview.css:70-74`:

```css
.portal-examples-overview-cards.portal-examples-list.neo-list {
    margin-top: 14px;
    overflow  : visible;
    padding   : 0;
}
```

and `resources/css/src/apps/portal/examples/SearchResults.css:110-114, 123-126`:

```css
.portal-examples-search-cards.portal-examples-list.neo-list,
.portal-examples-search-tiles.portal-examples-list.neo-list {
    overflow: visible;
    padding : 4px 0 0;
}
```

the compound selectors assume both classes sit on the same DOM node, so they match **zero elements**. As a result, the inner `<ul>` falls back to `overflow: auto` (`resources/css/src/list/Base.css:17`) and `padding: 16px 16px 0` (`resources/css/src/apps/portal/examples/List.css:54`, `8px 8px 0` at `<= 600px` at line `614`), clipping the last row's `1px` bottom ring and shadow on `/examples` and every grouped `SearchResults` list (while also indenting `Overview` cards `16px` horizontally inside `Overview`'s gutter).

Design authority: `"useWrapperNode: false, // the overview scrolls, not the list"` (`apps/portal/view/examples/Overview.mjs:192`) and `overflow: visible` in `Overview.css:72` / `SearchResults.css:112` (confirmed by `@tobiu` visual inspection on `2026-11-25`).

## The Fix

1. **`resources/css/src/apps/portal/examples/Overview.css`:** Split `.portal-examples-overview-cards` (`margin-top: 14px; overflow: visible;`) from its child `> .portal-examples-list.neo-list` (`overflow: visible; padding: 0;`) so `Overview` remains the sole scroll container (`padding-bottom: 40px`).
2. **`resources/css/src/apps/portal/examples/SearchResults.css`:** Split `.portal-examples-search-cards, .portal-examples-search-tiles` (`overflow: visible;`) from `> .portal-examples-list.neo-list` (`overflow: visible; padding: 4px 0 0;`) and drop the redundant mobile duplicate rule.
3. **`resources/css/src/apps/portal/examples/List.css`:** Restore symmetric bottom padding on standalone `.portal-examples-list.neo-list` (`padding: 16px` desktop, `padding: 8px` at `<= 600px`) so any standalone `useWrapperNode: true` list also clears its last-row ring and shadow (`GroupPage.css` and `Overview.css` / `SearchResults.css` set explicit `padding` on their non-scrolling `<ul>` children).
4. **Playwright E2E regression guard:** Assert in headless Chromium that `Overview` and `SearchResults` card/tile `<ul>` nodes resolve `overflow: visible` and `paddingBottom` / unclipped card ring geometry.

## Acceptance Criteria

- [ ] **AC-1:** On `/examples` (`Overview`), `.portal-examples-overview-cards` and its child `ul.portal-examples-list.neo-list` both compute `overflow-x: visible`, `overflow-y: visible`, and `padding: 0px`, leaving the final row's `1px` perimeter ring and drop shadow unclipped in both `neo-light` and `neo-dark`.
- [ ] **AC-2:** On `/examples` with an active search query (`SearchResults`), `.portal-examples-search-cards` / `.portal-examples-search-tiles` and their child `ul.portal-examples-list.neo-list` compute `overflow-x: visible` and `overflow-y: visible` without clipping the last row's bottom border or shadow.
- [ ] **AC-3:** Before (`dev`) and after (PR head) whole-tab screenshots in `neo-light` and `neo-dark` plus a Playwright E2E regression assertion verify unclipped bottom card borders and clean theme guards.

## Out of Scope

- Updating the left-rail `"All examples · 170"` label and find placeholder (tracked in a separate sibling ticket with `@neo-opus-ada`).
- Changing card shadow tokens or `GroupPage.css` (`GroupPage.css:11-14` already uses descendant `.portal-examples-list.neo-list { overflow: visible; padding: 14px 0 32px; }`).

## Avoided Traps

- **Adding `border: 1px solid` to `.neo-list-item` instead of fixing the `<ul>` scroll clip:** Would still clip the resting/hover drop shadow (`0 10px 28px` / `0 14px 34px`) and selection glow (`--portal-examples-list-selected-glow`), and shift card cover dimensions by `2px`.
- **Setting `overflow: visible` only on `ul.portal-examples-list` while leaving `.neo-flex-item` wrapper clipping unchecked:** Setting `overflow: visible` explicitly on both wrapper and `> ul` guarantees neither layer establishes an accidental scrollport.
