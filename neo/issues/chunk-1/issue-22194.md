# Responsive plugin's body orientation classes never reach the DOM

Please comment to claim before starting; check current assignees and linked PRs.

## Context

Found while writing the VDOM engine guides (#22189). `plugin.Responsive#onResizeBody` sends its `document.body` orientation classes to `Neo.applyDeltas(me.appName, …)`. `applyDeltas` takes a **window id**. Since #20042 (2026-10-23), Main applies only DOM updates addressed to its own window and answers anything else with a `NEO_DEAD_PORT` rejection. An app name is never a window id, so `neo-landscape` / `neo-portrait` never reach `document.body`.

Observation vs inference: the code path below is read, not run. No app or example in this repo sets `responsive`, and no CSS here consumes the two classes, so nothing visible breaks in-repo today. Any app that sets the public `responsive` config and styles `.neo-landscape` / `.neo-portrait` gets nothing, plus an unhandled rejection per resize (inferred: `onResizeBody` neither awaits nor catches the promise). AC-1 turns that into a measured red.

## The Problem

`src/plugin/Responsive.mjs:226-241` builds the delta and calls `Neo.applyDeltas(me.appName, {id: 'document.body', cls: {add, remove}})`. `#20334` (2026-11-05) reworked this plugin after the guard landed; its unit spec (`test/playwright/unit/component/ResponsiveAdmission.spec.mjs`) covers `onResize` and component `cls`, never `onResizeBody`, so nothing went red. Of 51 `applyDeltas` call sites in `src/`, `apps/` and `examples/`, this is the only one addressed by app name (`git grep -nE "applyDeltas\([^,]*appName" -- src apps examples`).

## The Architectural Reality

- `src/worker/App.mjs:120-139` `applyDeltas(windowId, deltas, meta)` → `promiseMessage(windowId, {action: 'updateVdom', deltas})`.
- `src/worker/Base.mjs` `sendMessage` sets `destination` to the given id. `'Portal'` (an app name) matches no port by window id or port id, so the message leaves on the default port with `destination: 'Portal'`.
- `src/worker/Manager.mjs:537-541`: an `updateVdom` whose destination `isForeignWindowId` (not `'main'`, not this window) goes to `refuseForeignDomUpdate` and gets a `PortDisconnectedError` reply.
- The plugin already knows the right target: `src/plugin/Responsive.mjs:139-156` registers one body listener per **window id** (`apps[windowId]`, from `me.owner`).
- The resize payload is fine: Main's ResizeObserver addon sends both `rect` and `contentRect` (`src/main/addon/ResizeObserver.mjs:238-247`).

Design authority: `"Add either neo-landscape or neo-portrait to the parent viewport component"` (`Responsive#onResizeBody` JSDoc), with `App#applyDeltas`: `"Sends DOM deltas and optional component update metadata to a target window's Main thread."` and Main's per-window ownership from #20042.

## The Fix

In `onResizeBody`, address the window whose Viewport fired the resize, the same window id the listener was registered for in `apps[windowId]`, instead of `me.appName`. Mind window moves: the plugin rebinds on move (`:160-185`), so read the id from the registration or the Viewport, not a cached value that a move can strand.

This is a call-site destination fix. It does not touch the VDOM engine's update path.
