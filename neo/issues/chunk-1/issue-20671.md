# Search engines and agents find and classify neomjs.com

Terminal predicate: every canonical Portal route on neomjs.com (home, learn guides, blog, releases, example overviews, and apps) serves route-specific SSR metadata, structured schema, and clean semantic HTML without archive-sidebar or frontmatter noise, the 3-repo sitemap index and 3-tier llms.txt surfaces stay fresh on every release and sync deploy, and Search Console's core-sitemap coverage and engineering query impressions are measured against the 2026-10-24 baseline with zero archive-token dilution.

Steward: Julia.

## Problem scope

On 2026-10-24, Google Search Console (`Last 3 months`) showed `https://neomjs.com` ranking almost exclusively for Air India flight numbers (`ai12742` — `4,137` impressions / `0` clicks; `ai10794` — `699` impressions / `0` clicks) and CI error strings (`"git_no_lazy_fetch" "2.43"` — `578` impressions / `0` clicks), with **zero** rankings for engineering terms (`multi-threaded web engine`, `offscreencanvas worker`, `json vdom`, `agent os`, `mcp memory core`).

The first diagnostic wave (#20088, #20089, #20101 in `neomjs/neo`; `neomjs/middleware-v2#35`, `#36`, `#40`–`#44`; `neomjs/pages#54`–`#56`) stopped the immediate dilution: it fixed doubled `/news/blog/blog/<slug>` routes, stripped duplicate `id` + `labels: ai` frontmatter table tokens and `2,253`-item sidebar boilerplate from ticket SSR pages, segmented `sitemap.xml` into a `<sitemapindex>` over `sitemap-core.xml` (`469` core routes) and `sitemap-archive.xml` (`19,436` archive routes), and shipped the 3-tier `llms.txt` (`41.3 KB` Map), `llms-full.txt` (`1.7 MB` Core Documentation Atlas), and `llms-all.txt` (`1.3 MB` Archive Index).

Engine 13.5 (`The Front Door`, cut Monday 2026-11-23) reshapes the surfaces that search engines and coding agents actually land on: the home section, the component-family example overviews (#20498), and the three-reader learning section. Without coordinated search and agent-discovery plumbing across those surfaces, new overview and guide routes can ship with generic shell metadata, stale `sitemap-core.xml` / `llms*.txt` indexes, or unverified crawler classification.

**Why an epic:** the work spans `buildScripts/docs/seo/*` and `apps/portal/**` in `neomjs/neo`, SSR metadata and `/raw/` markdown routing in `neomjs/middleware-v2`, and live post-deploy verification on `neomjs.com` + Google Search Console across the 13.5 window. Each deliverable is a separate single-PR leaf that shares one outcome and one release clock (2026-11-23).

## Intended solution shape

Three capability families, delivered as linked one-PR leaves:

- **1. Route-specific semantic metadata and structured schema across front-door routes (`neomjs/neo` + `neomjs/middleware-v2`).** Every canonical route in `sitemap-core.xml` — home, `/learn/*` guides, `/examples/*` component-family overviews (#20498), `/news/blog/*`, `/news/releases/*`, and `/apps/*` — resolves a distinct, non-generic `<title>`, `<meta name="description">`, `<link rel="canonical">`, OpenGraph/Twitter card metadata, and JSON-LD structured schema (`SoftwareSourceCode`, `TechArticle`, `WebApplication`) naming the engineering capability the page proves.
- **2. Sitemap Index and 3-tier `llms*.txt` synchronisation for 13.5 front-door surfaces (`buildScripts/docs/seo/*`).** As new example overviews (#20498), learning routes, and home-section updates land, `generate.mjs` and `rebuildContentIndexesAndSeo.mjs` keep `sitemap-core.xml`, `llms.txt`, and `llms-full.txt` synchronized with accurate route titles, descriptions, `<lastmod>` dates, and automated integrity checks that reject broken canonical or `/raw/` links before deploy.
- **3. Crawler and agent-fetch verification against the 2026-10-24 Search Console baseline.** A repeatable verification probe checks live `Googlebot` and agent HTTP responses (`status`, `canonical`, `<title>`, meta description, structured data, payload size, and zero sidebar/frontmatter noise) across representative `sitemap-core.xml`, `sitemap-archive.xml`, and `llms*.txt` endpoints, paired with Search Console per-child sitemap coverage (`sitemap-core.xml` vs `sitemap-archive.xml`) and engineering query classification readouts.

Sequencing follows the 13.5 release train in `ROADMAP.md` (cut Monday 2026-11-23).

## Out of scope

- Off-site backlink / citation campaigns and external social distribution (outbound work outside this repository).
- The visual layout and copy of the Portal home section itself (stewarded by Clio) and the authoring of the component-family example overviews (#20498).
- Full middleware SSR architecture replacement (`neomjs/middleware-v2#54`).

## Avoided traps

- **Re-mixing raw archive churn into `sitemap-core.xml` or `llms.txt`.** The `19,400+` ticket, PR, and discussion routes remain isolated in `sitemap-archive.xml` and `llms-all.txt` so crawl budget and LLM context windows stay concentrated on canonical documentation, examples, and architecture.
- **Serving generic SPA shell `<title>` / `<meta name="description">` on deep routes.** Deep `/learn/*` and `/examples/*` routes that share root shell metadata get folded or de-ranked by crawlers as soft duplicates.
- **A hardcoded sub-registry in this body.** Leaves are linked natively via `update_issue_relationship` and queried on demand.

**A finding from the home-section read (#20682): `neomjs.com/examples` is a 404 for a person, and a 200 for a crawler**

Probed Tue Nov 10 at 01:35Z, with `curl` and in a headed Chromium (desktop and phone):

| Request | Browser user agent | curl's default user agent |
|---|---|---|
| `/home`, `/services`, `/learn`, `/news` | 302 to `/#/home`, `/#/services`, … | 200 |
| `/examples` | 301 to `/examples/`, then **404** ("File not found", the static host's page) | 200 |
| `/examples/` | **404** | 200 |

So the one section route that shares its name with a deployed folder never reaches the app for a person: whoever types the address, or follows a search result or a shared link to it, lands on the host's 404 page. `/#/examples` and the header's button work. `/apps` answers 301 to `/apps/` the same way; I did not follow it.

This sits beside `neomjs/middleware-v2#21` (organic landings are redirected off the URL that ranked): for this route the landing is not redirected, it is lost. It matters for 13.5 because the gate sends a newcomer to the example overviews.
