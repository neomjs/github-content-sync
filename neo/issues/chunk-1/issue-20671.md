# Search engines and agents find and classify neomjs.com

Terminal predicate: every canonical Portal route on neomjs.com (home, learn guides, blog, releases, example overviews, and apps) serves route-specific SSR metadata, structured schema, and clean semantic HTML without archive-sidebar or frontmatter noise, the 3-repo sitemap index and 3-tier llms.txt surfaces stay fresh on every release and sync deploy, and Search Console's core-sitemap coverage and engineering query impressions are measured against the 2026-10-24 baseline with zero archive-token dilution.

Steward: Julia.

## Problem scope

On 2026-10-24, Google Search Console (`Last 3 months`) showed `https://neomjs.com` ranking almost exclusively for Air India flight numbers (`ai12742` — `4,137` impressions / `0` clicks; `ai10794` — `699` impressions / `0` clicks) and CI error strings (`"git_no_lazy_fetch" "2.43"` — `578` impressions / `0` clicks), with **zero** rankings for engineering terms (`multi-threaded web engine`, `offscreencanvas worker`, `json vdom`, `agent os`, `mcp memory core`).

The first diagnostic wave (#20088, #20089, #20101 in `neomjs/neo`; `neomjs/middleware-v2#35`, `#36`, `#40`–`#44`; `neomjs/pages#54`–`#56`) stopped the immediate dilution: it fixed doubled `/news/blog/blog/<slug>` routes, stripped duplicate `id` + `labels: ai` frontmatter table tokens and `2,253`-item sidebar boilerplate from ticket SSR pages, segmented `sitemap.xml` into a `<sitemapindex>` over `sitemap-core.xml` (`469` core routes) and `sitemap-archive.xml` (`19,436` archive routes), and shipped the 3-tier `llms.txt` (`41.3 KB` Map), `llms-full.txt` (`1.7 MB` Core Documentation Atlas), and `llms-all.txt` (`1.3 MB` Archive Index).

Engine 14 (`14.0.0` — `The Front Door`, cut Monday 2026-11-23) reshapes the surfaces that search engines and coding agents actually land on: the home section (#20682), the component-family example overviews (#20498), the board/scheduler/Gantt families (#20874), and the three-reader learning section. Without coordinated search and agent-discovery plumbing across those surfaces, new overview and guide routes can ship with generic shell metadata, stale `sitemap-core.xml` / `llms*.txt` indexes, HTML-only responses when agents negotiate `Accept: text/markdown`, or unverified crawler classification.

**Why an epic:** the work spans `buildScripts/docs/seo/*` and `apps/portal/**` in `neomjs/neo`, SSR metadata and `dist/raw/` markdown negotiation in `neomjs/middleware-v2`, root SEO artifact staging in `neomjs/pages`, and live post-deploy verification on `neomjs.com` + Google Search Console across the Engine 14 window. Each deliverable is a separate single-PR leaf that shares one outcome and one release clock (2026-11-23).

## Intended solution shape

Three capability families, delivered as linked one-PR leaves:

- **1. Route-specific semantic metadata and structured schema across front-door routes (`neomjs/neo` + `neomjs/middleware-v2`).** Every canonical route in `sitemap-core.xml` — home, `/learn/*` guides, `/examples/*` component-family overviews (#20498), `/news/blog/*`, `/news/releases/*`, and `/apps/*` — resolves a distinct, non-generic `<title>`, `<meta name="description">`, `<link rel="canonical">`, OpenGraph/Twitter card metadata, and JSON-LD structured schema (`SoftwareSourceCode`, `TechArticle`, `BlogPosting`, `DiscussionForumPosting`, `BreadcrumbList`, `WebApplication`) naming the engineering capability the page proves without misclassifying Neo as a web framework.
- **2. Sitemap Index, `robots.txt` signals, and 3-tier `llms*.txt` / raw-markdown synchronisation for Engine 14 front-door surfaces (`buildScripts/docs/seo/*`, `neomjs/pages`, `neomjs/middleware-v2`).** As new example overviews (#20498), learning routes, and home-section updates land, `generate.mjs`, `verify.mjs`, and `rebuildContentIndexesAndSeo.mjs` keep `sitemap-core.xml`, `sitemap-discussions.xml`, `llms.txt`, and `llms-full.txt` synchronized with accurate route titles, descriptions, `<lastmod>` dates, `Content-Signal` directives, and `Accept: text/markdown` / `<route>.md` markdown twin resolution.
- **3. Crawler and agent-fetch verification against the 2026-10-24 Search Console baseline.** A repeatable verification probe checks live `Googlebot` and agent HTTP responses (`status`, `canonical`, `<title>`, meta description, structured data, `Accept: text/markdown` negotiation, payload size, and zero sidebar/frontmatter noise) across representative `sitemap-core.xml`, `sitemap-discussions.xml`, `sitemap-archive.xml`, and `llms*.txt` endpoints, paired with dated Search Console per-child sitemap coverage and engineering query classification readouts.

Sequencing follows the Engine 14 (`14.0.0`) release train in `ROADMAP.md` (cut Monday 2026-11-23).

## Out of scope

- Off-site backlink / citation campaigns, external social distribution, and Wikidata entity registration (outbound / operator account actions outside this repository).
- The visual layout and copy of the Portal home section (#20682, stewarded by Clio), the authoring of the component-family example overviews (#20498), and standalone comparison-guide prose (#20918 rides alongside Stream 3 as non-blocking content).
- Full middleware SSR architecture replacement (`neomjs/middleware-v2#54`) and Engine clean-pathname SPA router bootstrap (`neomjs/middleware-v2#21`, sequenced post-cut on Discussion #20920 Axis `C1` because `SsrService` snapshots carry zero `<script>` tags and `src/Main.mjs` is hash-only).

## Avoided traps

- **Re-mixing raw archive churn into `sitemap-core.xml` or `llms.txt`.** The `20,000+` `noindex` ticket and PR routes remain isolated from `sitemap.xml` and `llms.txt` so crawl budget and LLM context windows stay concentrated on canonical documentation, examples, discussions, and architecture.
- **Serving generic SPA shell `<title>` / `<meta name="description">` on deep routes, or serving non-interactive `dist/seo/` HTML to human browsers.** Deep `/learn/*` and `/examples/*` routes sharing root shell metadata get folded as soft duplicates; conversely, serving scriptless `dist/seo/` SSG HTML to human browsers breaks SPA interactivity (`neomjs/middleware-v2#21`).
- **Search-intent titles that misclassify Neo as a framework.** Keyword-rich comparison titles (e.g. React/Angular/Vue/Solid) must preserve Neo's Application Engine / Agent OS category rather than calling Neo a JavaScript framework.
- **Counting human Search Console clicks alone while ignoring agent fetches.** Coding agents consume `llms*.txt`, `/raw/*.md`, and `Accept: text/markdown` without triggering Google Search impressions; agent discovery must be verified directly on those HTTP surfaces alongside GSC readouts.
- **A hardcoded sub-registry in this body.** Leaves are linked natively via `update_issue_relationship` and queried on demand.
