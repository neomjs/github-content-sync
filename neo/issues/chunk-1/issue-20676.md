# The grid guide does not cover CSV export or reading cell values

## Context

A grid can hand its data out in two ways:

- Since 13.4.0 it exports its rows as CSV: `toCsv()`, `exportCsv()` and a column's `exportRenderer` (`#20380`).
- On `dev` it also reads its cells as values: `getCellValues()` and `dataFields` (`#20672`). That part ships with 13.5.

The grid guide, `learn/guides/datahandling/Grids.md`, mentions none of the five. A search of `learn/`, `examples/` and `apps/` for `toCsv`, `exportCsv`, `getCellValues` and `exportRenderer` finds nothing (measured on `dev` at 6ba8c6ca86).

## The Problem

A developer who wants to export a grid, or to read what it shows, finds the API only by reading `src/grid/Container.mjs`. The JSDoc there is complete. The guide is where grid features are introduced: it has sections for sorting, filtering, selection and cell editing, and none for getting data out.

## The Architectural Reality

- `Neo.grid.Container#toCsv({delimiter, escapeFormulas, header})` returns the CSV text. Rows follow the store's current filter and sort, including rows a buffered grid has not rendered. Columns run in display order: locked start, center, locked end.
- `Neo.grid.Container#exportCsv({fileName, ...})` downloads that text. A worker cannot start a download, so the main thread's `Neo.main.addon.FileDownload` does it (`src/main/addon/FileDownload.mjs`).
- `Neo.grid.column.Base#exportRenderer({record, value})` replaces a cell's exported value. A column's `renderer` returns markup for display and is never exported.
- `Neo.grid.Container#getCellValues({dataFields, mode, records})` returns `values[row][column]`. `mode` is `'export'` (the default) or `'raw'`. `Neo.grid.Container#dataFields` lists the columns it reads by default.
- The guide's last two top-level sections are `## Cell Editing` and `## Performance and Big Data`.

Design authority: n/a — calls no existing behavior wrong; this documents shipped behavior.

## The Fix

Add one section to `learn/guides/datahandling/Grids.md`, between `## Cell Editing` and `## Performance and Big Data`, for example `## Exporting and Reading Cell Values`. It covers four topics, each with a short code sample that agrees with the JSDoc:

1. `grid.toCsv()` and its three options, and what a row and a column are in the output.
2. `grid.exportCsv({fileName})`, and why the download runs on the main thread.
3. `exportRenderer` on a column, and why a `renderer` is not exported.
4. `grid.getCellValues()` and `grid.dataFields`: reading a part of the grid through `dataFields` and `records`, and the difference between the `export` and `raw` modes.

- [ ] The section states the defaults: `delimiter: ','`, `escapeFormulas: true`, `header: true`, `fileName: 'export.csv'` and `mode: 'export'`.
- [ ] `npm run check-relative-links` passes.
- [ ] No other section of the guide changes.

## Out of Scope

- New API, and changes to the JSDoc.
- A runnable example under `examples/`.
- Other guides, and the structure of the learning section (`#20498`).
