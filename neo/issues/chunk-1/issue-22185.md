# Web Desktop Settings pop-out can time out after Mail is detached

## Context

On Board PR #22147 at `50ce2ee3e2` against `dev` `73e6207999`, Engine E2E shard 13 logged one 90-second test failure and then reached its six-minute step limit. The same test passed in 5.0 seconds in the matching shard on the exact `dev` base.

[Failed shard](https://github.com/neomjs/neo/actions/runs/45580400806/job/139088788535) · [Retained trace](https://github.com/neomjs/neo/actions/runs/45580400806/artifacts/15006572522) · [Exact-base pass](https://github.com/neomjs/neo/actions/runs/45577018733/job/139077529377)

## The Problem

The test opens detached Mail and then detaches Settings from the same desktop. In the retained failing trace, the Settings launcher double-click completes (`abzo@13592`). The popup waiter is armed (`abzo@13594`), and Playwright resolves the Settings **Pop out window** button, dispatches the click, and records `click action done` (`abzo@13597`). The browser context records a child page and `desktopPopup` navigation for Mail only. The Settings dialog and its active pop-out button are still in the final accessibility snapshot. The action and after snapshots for `abzo@13597` show Settings still marked `animated-hiding-showing`. The successful Mail click at `abzo@13587` is on a settled dialog. The first gap is between the completed click and registration of a native popup page. The trace leaves App Worker handler entry, Main's native-open result, and adoption unresolved.

## The Architectural Reality

[Apps.spec.mjs](https://github.com/neomjs/neo/blob/73e620799910041c267820ae3122cdd0746759e3/test/playwright/e2e/webdesktop/Apps.spec.mjs#L203-L225) uses the actual Web Desktop dialog and the originating Playwright page's native popup event. The application detach and adoption flow owns the new window. #22104 introduced this theme coverage, and #21853 previously fixed an opening-flight timing issue in a different case in the same file.

## The Fix

Capture the second pop-out at App Worker handler entry and admission, then at Main's native window open with its activation state and result. Keep the opener and new window IDs at context page registration and App Worker adoption. Compare the immediate click with a click after the existing dialog-open check on the same source. Use the recorded transitions to identify what needs to change. Preserve the cross-window theme assertions.

Focused hosted reproducer: **Engine Tests** with `suite=e2e`, `specs=test/playwright/e2e/webdesktop/Apps.spec.mjs`, and `repeatEach=3`. [Current dev probe](https://github.com/neomjs/neo/actions/runs/45582470155)
