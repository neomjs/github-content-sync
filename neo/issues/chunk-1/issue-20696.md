# The State & Data examples get their overview

## Context

The 13.5 gate asks that a stranger finds each component family's examples as an overview in which every example names what it proves (`ROADMAP.md`). `/examples/grid` is the pattern: 21 captioned Grid and Table demonstrations (#20500). The steward's map on #20498 ([comment](https://github.com/neomjs/neo/issues/20498#issuecomment-6757406109)) lists the families; this leaf delivers State & Data at `/examples/state`: state providers, the data pipeline, the config system, workers and functional components.

## The Problem

How an application holds state and moves data is the first architecture question a developer asks. `examples/` holds 23 demonstrations that answer it; one has a catalog record (`state-provider`), none has a caption, and 22 can be reached only by typing their URL.

## The Architectural Reality

- One record per example in `apps/portal/resources/data/examples.json`; the record's shape is documented on `apps/portal/model/Example.mjs:16-27`. The 21 records with `"family": "grid-table"` are the reference for the length and tone of a caption.
- A family's tab appears with its first record (#20690), and a unit spec fails on a family record without `feature` or `lookFor`.
- Inventory at `62f75736ba`, each path under `examples/` with its own `neo-config.json`: `stateProvider/advanced` (record `state-provider`), `stateProvider/dialog`, `extendedClass`, `inline`, `inlineNoStateProvider`, `nestedData`, `table`, `twoWay` · `data/pipeline` · `core/config` · `remotesApi/basic` · `worker/task` · `functional/button/base`, `functional/defineComponent`, `hostComponent`, `nestedComponents`, `nestedTemplateComponent`, `templateComponent` · `serverside/toolbarItems` · `preloadingAssets` · `sitemap` · `todoList/version1`, `todoList/version2`.
- The two multi-window state provider demos (`stateProvider/multiWindow`, `multiWindow2`) belong to the Multi-Window leaf.
- Design authority: n/a — adds catalog records, calls no existing behavior wrong.

## The Fix

For every demonstration of the inventory: run it (`npm run server-start`, then its `index.html`), read its view and controller, and decide. It publishes when one sentence can say what it proves; otherwise it stays out and the pull request says why. A published demonstration gets one record: a stable string `id`, `name`, `"family": "state"`, `component`, `feature` (what it proves), `lookFor` (one action and what to observe), `scope` where it has a limit, the four `urls`, `sourceUrl`, and `image: null` unless a cover exists. The existing record gets the family and its caption in place. Insert the new records as one block directly after the record `state-provider`, so that parallel family pull requests touch different lines.

The tab's label is one string. If the published set reads better under another name, propose it in the pull request with the list in hand.

## Acceptance Criteria

- [ ] Every path of the inventory is a record of family `state` or is named in the pull request with its reason for staying out.
- [ ] Each `feature` and `lookFor` was checked in the running example; the pull request names the build and the browser. A caption states no number the example does not show and names no commercial feature.
- [ ] Every URL of a record answers 200 on neomjs.com, where the examples are deployed in all four builds, or that build is omitted on the record.
- [ ] `npm run test-unit -- test/playwright/unit/apps/portal/view/examples` passes with the new counts.
- [ ] The pull request shows `/examples/state` at 1440×900 from a real browser.

## Out of Scope

New examples; covers (the typographic fallback is allowed, #20679 is the pattern for real ones); an engine fix for an example that turns out broken: file it and leave the example out.

## Avoided Traps

- A caption taken from a directory name: the grid map on #20498 checked configured views, controllers and stores, and several names promised more than the example shows.
- An example whose effect is invisible published without telling the visitor where to look: a worker task or a config demo names the control to press and the output to watch, or it stays out.
- Moving the existing record: the showcase order is delivered intent (#19640).
