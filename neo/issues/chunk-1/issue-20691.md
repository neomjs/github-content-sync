# The Forms examples get their overview

## Context

The 13.5 gate asks that a stranger finds each component family's examples as an overview in which every example names what it proves (`ROADMAP.md`). `/examples/grid` is the pattern: 21 captioned Grid and Table demonstrations (#20500). The steward's map on #20498 ([comment](https://github.com/neomjs/neo/issues/20498#issuecomment-6757406109)) lists the families; this leaf delivers Forms at `/examples/forms`.

## The Problem

The engine ships 26 form field types (`src/form/field/`). `examples/` holds 23 form demonstrations; three have a catalog record (`date-selector`, `date-field`, `combobox-field`), none has a caption, and the other twenty can be reached only by typing their URL. A team evaluating the engine for a form-driven application cannot see on the Portal what a field does.

## The Architectural Reality

- One record per example in `apps/portal/resources/data/examples.json`; the record's shape is documented on `apps/portal/model/Example.mjs:16-27`. The 21 records with `"family": "grid-table"` are the reference for the length and tone of a caption.
- A family's tab appears with its first record (#20690), and a unit spec fails on a family record without `feature` or `lookFor`.
- Inventory at `62f75736ba`, each path under `examples/` with its own `neo-config.json`: `form/field/checkbox`, `chip`, `color`, `combobox`, `date`, `email`, `fileupload`, `number`, `picker`, `radio`, `select`, `switch`, `text`, `textarea`, `time`, `trigger/copyToClipboard`, `url` · `form/fieldset` · `fieldWithPrefix` · `fields` · `layout/form` · `date/selectorContainer` · `component/dateSelector`.
- `apps/form` is an application with its own entrypoint and no record: a candidate for this family.
- Design authority: n/a — adds catalog records, calls no existing behavior wrong.

## The Fix

For every demonstration of the inventory: run it (`npm run server-start`, then its `index.html`), read its view and controller, and decide. It publishes when one sentence can say what it proves; otherwise it stays out and the pull request says why. A published demonstration gets one record: a stable string `id`, `name`, `"family": "forms"`, `component`, `feature` (what it proves), `lookFor` (one action and what to observe), `scope` where it depends on an external service or has a limit, the four `urls`, `sourceUrl`, and `image: null` unless a cover exists. The three existing records get the family and their captions in place. Insert the new records as one block directly after the record `combobox-field`, so that parallel family pull requests touch different lines.

## Acceptance Criteria

- [ ] Every path of the inventory is a record of family `forms` or is named in the pull request with its reason for staying out; `apps/form` is decided the same way.
- [ ] Each `feature` and `lookFor` was checked in the running example; the pull request names the build and the browser. A caption states no number the example does not show and names no commercial feature.
- [ ] Every URL of a record answers 200 on neomjs.com, where the examples are deployed in all four builds, or that build is omitted on the record.
- [ ] `npm run test-unit -- test/playwright/unit/apps/portal/view/examples` passes with the new counts.
- [ ] The pull request shows `/examples/forms` at 1440×900 from a real browser.

## Out of Scope

New examples: ten field types have no dedicated field example (Country, Currency, Display, Hidden, IBAN, Password, Phone, Range, Search, ZipCode). Nine are configured in composed examples or apps, IBAN in none; which of them need a demonstration of their own is decided in Discussion 20742 (corrected Nov 10 23:23Z: the first version said they had none). Covers: the typographic fallback is allowed, and #20679 is the pattern for real ones. An engine fix for an example that turns out broken: file it and leave the example out.

## Avoided Traps

- A caption taken from a directory name: the grid map on #20498 checked configured views, controllers and stores, and several names promised more than the example shows.
- One card per field type that only says "a text field": the caption names what this field does that a plain input does not (validation, a picker, a trigger, a mask).
