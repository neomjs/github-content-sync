# Concept Graph Visualization App

## Objective
Build a Neo.mjs application that visualizes the concept ontology graph interactively. Provides value as both a validation tool and an LLM context primer.

## Context
Phase 2 of the Concept Ontology epic (#10030). Depends on the ConceptService from #10032.

## Deliverables

### Neo.mjs Visualization App
Location: `examples/conceptGraph/` or `apps/conceptGraph/`

### Features
1. **Hierarchical tree view** of all concepts (using Neo.mjs tree component or LearningSection-like layout)
2. **Color-coded by tier**: Tier 1 (red/high priority), Tier 2 (orange), Tier 3 (blue)
3. **Coverage status indicators**: ✅ has guide, ⚠️ partial coverage, 🔴 gap
4. **Click concept** → detail panel showing:
   - Description
   - IMPLEMENTED_BY classes (with file paths)
   - EXPLAINED_BY guides (with links)
   - EXEMPLIFIED_BY examples
   - REQUIRES prerequisites
5. **Gap report view**: Filter to show only concepts missing guides, sorted by weight
6. **Export**: Serialize current concept tree as compact text (the LLM context format)

### Optional: Force-Directed Graph View
If feasible, add a d3-force or pure-Neo.mjs force-directed layout showing concept nodes and relationships visually. This gives a spatial overview of the knowledge architecture.

### Data Source
Loads directly from `.neo-ai-data/concepts/nodes.jsonl` and `edges.jsonl` via fetch or the ConceptService.

## Value Proposition
1. **Validation tool**: Visually inspect the concept graph for errors, missing relationships, tier assignments
2. **Curation UI**: Identify gaps and malformed entries before they enter the real graph
3. **Dogfooding**: Neo.mjs visualizing its own architecture — showcase material
4. **LLM primer**: The serialized tree view can be copy-pasted into agent prompts

## Acceptance Criteria
- [ ] App loads and renders the full concept hierarchy
- [ ] Tree view supports expand/collapse
- [ ] Coverage status is visible per concept
- [ ] Gap report filters correctly by weight threshold
- [ ] Runs in development mode (`npx neo-app`)

## Product-proof re-entry — current runtime shape

The May deferral rationale ("not a cloud-deployment unblocker") is now stale. The valuable product boundary is the **local** Agent OS / Fleet Manager control plane, and a live graph explorer is one of the clearest ways to make that invisible moat visible. This ticket should remain the owner; do **not** create a duplicate visualization ticket.

### Authority correction

ADR 0024 and the current runtime make the original JSONL-only shape incomplete:

- the live Native Edge Graph is the SQLite node/edge substrate operated through `GraphService` and the Memory Core read/query tools;
- the git-versioned concept ontology remains a distinct curated JSONL representation and is ingested into the runtime graph;
- therefore concepts are one important **projection**, not the explorer's sole data source.

The implementation must consume the current bounded read surfaces (`get_node`, `get_neighbors`, `search_nodes`, `query_hybrid_graph`, or a purpose-built read service over the same authority). It must not build a second graph model by fetching JSONL directly into UI state.

### Reframed product shape: bird view → bounded exploration → evidence

1. **Bird view:** aggregate the graph by node type, edge type, concept hierarchy, provenance/trust, and time window. A 100k-node hairball is a failure, not a showcase.
2. **Bounded exploration:** search or select a node, then expand a capped neighborhood; filter edge types and traverse a chosen relation/path without losing orientation.
3. **Evidence drill-down:** inspect the selected node/edge, source/provenance, timestamps, visibility scope, and the artifacts behind it.
4. **Concept projection:** retain the hierarchical concept tree, coverage/gap cues, IMPLEMENTED_BY / EXPLAINED_BY / EXEMPLIFIED_BY / REQUIRES relations, and compact export—but as one lens over the larger graph.
5. **Product proof:** provide a synthetic/sanitized showcase dataset and a local-live mode. No maintainer, repository-private, tenant, or client graph may become a public demo payload.

### Acceptance direction

A credible first release proves all three zoom levels on realistic graph volume, remains responsive through bounded queries, makes edge semantics legible, and shows provenance rather than decorative dots. It should serve two users at once:

- a maintainer debugging graph quality and missing/malformed relationships;
- a newcomer understanding in minutes that Neo's Agent OS has a live, active hybrid graph—not just documentation claiming one.

This is now adjacent to the product-first front-door direction in D#14683. That Discussion owns public page composition; #10034 owns the graph-explorer product surface. Milestone/board placement should follow the v13.2 convergence pass rather than being silently inferred here.
