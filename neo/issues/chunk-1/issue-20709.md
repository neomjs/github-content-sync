# Clarify contributor skill materialization & PR body template in CONTRIBUTING.md and GETTING_STARTED.md

## Context

Three first-time contributor pull requests opened against `good first issue` tickets on 2026-11-10 (`#20702` by `@chaitanya-y20`, `#20704` by `@bfs2021`, and `#20708` by `@DevEtaiGabbai`) failed `baseline / PR baseline` (`Validate the close target`) for the exact same reason: their PR descriptions used `Fixes #<id>` (or `Fixes: #<id>`) instead of a standalone `Resolves #<id>` line, and none of the agent-assisted submissions loaded `.agents/skills/pull-request/SKILL.md` (`pull-request-workflow.md §9`).

## The Problem

Auditing our contributor entry documents (`CONTRIBUTING.md` and `.github/GETTING_STARTED.md`) reveals why first-time contributors and their AI coding agents repeatedly miss the materialized skills and the PR body contract:

1. **`CONTRIBUTING.md:82-83` tells contributors not to use the materialized skills and names only `.claude/skills`:**
   - Line 82–83 reads: `It prints neo-agent-skills: materialized N link(s). That is our agent-skill package linking itself into .claude/skills. It needs nothing from you, and you do not need it to contribute.`
   - In reality, `buildScripts/util/prepare.mjs` invokes `neo-agent-skills-materialize`, which links the published `neo-agent-skills` workflows into both `.agents/skills/` and `.claude/skills/` (`pull-request`, `unit-test`, `identity-firewall`). Telling contributors *"you do not need it to contribute"* causes both humans and agents reading the top of `CONTRIBUTING.md` to skip `.agents/skills/pull-request/SKILL.md`.
   - Furthermore, when an external agent sandbox installs dependencies with `npm install --ignore-scripts`, `prepare` is skipped and `CONTRIBUTING.md` never mentions running `npm run prepare` (or `npx neo-agent-skills-materialize`) to materialize `.agents/skills/`.
2. **`CONTRIBUTING.md §3.4` and `§5` never mention the `Resolves #<id>` close-target gate or the CLI/agent PR body template:**
   - When a human opens a PR in the browser UI, GitHub pre-fills `.github/PULL_REQUEST_TEMPLATE.md` (`Resolves #`).
   - When a contributor or AI agent opens a PR via `gh pr create` or the GitHub API, GitHub does not inject `.github/PULL_REQUEST_TEMPLATE.md`. Because `CONTRIBUTING.md §3.4` says only *"Please make sure that pull requests are always related to an issue inside our Issues Tracker"*, agents default to `Fixes #N`, which fails `baseline / PR baseline` (`neo-agent-skills-pr-body --close-target-only`).
3. **`.github/GETTING_STARTED.md` is a stale pre-Brain-split duplicate that contradicts `CONTRIBUTING.md`:**
   - Lines 47–52 still instruct contributors to run `npm run install-brain` (`package.brain.json` / `package-lock.brain.json`), which was removed when the Brain moved to `neomjs/neo-agent-brain` (`#17791`).
   - Line 55 instructs contributors to run `npm run build-all` instead of the fast 10-second setup loop in `CONTRIBUTING.md`.
   - Maintaining a second copy of the engine setup loop in `.github/GETTING_STARTED.md` (which no tracked file links to) is why it drifted into stale `install-brain` instructions.

## The Architectural Reality

- `buildScripts/util/prepare.mjs:43-46` runs `husky` and `neo-agent-skills-materialize` during `npm install` (`npm run prepare`), projecting `.agents/skills/` and `.claude/skills/` into the checkout root.
- `.github/workflows/pr-baseline.yml` calls `neomjs/neo-agent-skills/.github/workflows/reusable-pr-baseline.yml`, which runs `neo-agent-skills-pr-body --close-target-only` on every non-bot PR (`Resolves #N` on its own line; `Fixes #N` and `Closes #N` forbidden) and full `neo-agent-skills-pr-body` (`§9` anchors) on `neo-*` or `ai`-labeled PRs.
- `buildScripts/util/check-relative-links.mjs` audits every relative link in `CONTRIBUTING.md` and `.github/GETTING_STARTED.md` against `git ls-files` (`npm run check-relative-links`). Because `.agents/skills/` is materialized by `prepare` rather than git-tracked, references to `.agents/skills/...` in tracked markdown must stay inline code spans rather than relative markdown links.

Design authority: "Every PR — any author, draft or ready — resolves exactly ONE ticket: one standalone `Resolves #N`, no second line, no `Resolves #X, #Y`. `Closes` and `Fixes` are forbidden." (`.agents/skills/pull-request/references/pull-request-workflow.md §9.1`, `#18985`, `#18999`, `#20556`).

## The Fix

1. **Update `CONTRIBUTING.md`:**
   - In the `npm install` note (lines 82–84), state accurately that `neo-agent-skills` links its workflows into `.agents/skills/` and `.claude/skills/` (`unit-test`, `pull-request`), and note that if dependencies were installed with `--ignore-scripts`, `npm run prepare` (or `npx neo-agent-skills-materialize`) materializes them on demand.
   - In `§3` item 4 (line 133), state that every PR resolves one issue and must include `Resolves #<issue-id>` on its own line in the PR description (`Fixes #N` and `Closes #N` are rejected by `baseline / PR baseline`; `.github/PULL_REQUEST_TEMPLATE.md` pre-fills this in the web UI, while CLI/agent PRs can verify locally with `npx neo-agent-skills-pr-body --body-file <file> --close-target-only`).
   - In `§5` (`Contributions from AI Agents & Autonomous Entities`), state both the `--ignore-scripts` recovery command (`npm run prepare` / `npx neo-agent-skills-materialize`) and the requirement for agents to read `.agents/skills/unit-test/SKILL.md` and `.agents/skills/pull-request/SKILL.md` (`.agents/skills/pull-request/references/pull-request-workflow.md §9` — standalone `Resolves #<issue-id>` plus the §9 sections, testable locally via `npx neo-agent-skills-pr-body --body-file <file>`).
2. **Replace `.github/GETTING_STARTED.md` with a concise pointer:**
   - Remove all obsolete `install-brain` / `package.brain.json` / `npm run build-all` instructions and legacy `/neo/docs/` URLs, and replace the duplicate setup copy with a short pointer directing app builders to `../learn/gettingstarted/Setup.md` and engine contributors to `../CONTRIBUTING.md` as the single canonical home for setup, test suites, `.agents/skills/` materialization, and PR requirements.

## Out of Scope

- Changing `baseline / PR baseline` (`neo-agent-skills-pr-body`) enforcement rules.
- Modifying turn-loaded `AGENTS.md` or `.agents/skills/**` in `neomjs/neo`.

## Avoided Traps

- **Using markdown links `[...](.agents/skills/...)` in `CONTRIBUTING.md` or `.github/GETTING_STARTED.md`:** `buildScripts/util/check-relative-links.mjs` validates relative links against `git ls-files`. Since `.agents/skills` is materialized by `npm install` (`prepare`) and git-ignored, linking to `.agents/skills/...` as a markdown href would fail `npm run check-relative-links`; keep `.agents/skills/...` paths in inline code spans and use tracked relative links (`../CONTRIBUTING.md`, `.github/PULL_REQUEST_TEMPLATE.md`) for repo files.
- **Maintaining a second copy of the setup loop in `.github/GETTING_STARTED.md`:** `CONTRIBUTING.md` is the canonical home; keeping `.github/GETTING_STARTED.md` as a short pointer prevents future drift.
