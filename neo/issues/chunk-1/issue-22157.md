# The engine guide's title and opening lead with agents

## Context

On 2026-11-24 the operator noted that neomjs.com labels the engine "The Application Engine for the AI Era". He reads that as the pre-AI-era trap: it persuades humans to dive into code instead of hitting hard on the fact that agents understand the engine, excel with it and build on it. #22155 handles the README side; this ticket covers the guide that carries the label.

## The Problem

`learn/benefits/body/ApplicationEngine.md`:
- Its H1 is "The Application Engine for the AI Era". The page title derives from it, and the nav entry reads "Application Engine".
- It opens with a lesson on libraries, frameworks and engines. The agent argument starts only in the second numbered section ("The JSON-First AI Synergy"), and the Neural Link appears in the last section.
- It has no diagram.

## The Architectural Reality

- `apps/portal/resources/data/seo.json` takes each learn page's title from its H1 and its description from the bold lead (`buildScripts/docs/seo/seoJson.mjs`), and the pipeline regenerates it. It is not edited by hand.
- `learn/tree.json` is the nav source of truth. The route id `benefits/body/ApplicationEngine` stays, so the URL and inbound links keep working.
- #20518 restored the paradigm-shift conviction on this page at the operator's direction on 2026-11-07. This change adds and reorders; it cuts nothing.
- Guide-authoring bar §2 asks positioning pages to frame JSON-first blueprints as native LLM fluency plus Neural Link verification, not as a burden on humans.

## The Fix

1. H1 becomes "The Engine Agents Build On", with a bold lead about what agents do with the engine.
2. A new opening section, before the libraries/frameworks/engines lesson, covers what an agent gets. The app is described in JSON. Components are live objects that an agent inspects and changes through the Neural Link. Development has no build step. Several agents can work in one running app. A top-down Mermaid diagram shows that loop.
3. Every existing section follows, unchanged in substance.
4. `learn/tree.json` names the entry "The Engine Agents Build On".
5. `test/playwright/e2e/portal/LearnMermaidRender.spec.mjs` covers the route, so the diagram is checked on every run.

## Acceptance Criteria

- [ ] AC-1: The H1 and the `tree.json` name read "The Engine Agents Build On". The file path and route are unchanged.
- [ ] AC-2: The page opens with the agent section and its diagram. No existing section is removed; apart from the title and lead, the diff only adds and moves.
- [ ] AC-3: The diagram renders in the Portal. `LearnMermaidRender.spec.mjs` covers the route and passes.
- [ ] AC-4: `npm run check-relative-links` passes.

## Out of Scope

- `seo.json`, which is derived and regenerates.
- The README (#22155).
- The parent nav node "The Body - Application Engine".
- The portal FAQ entry "Why is Neo.mjs called an Application Engine instead of a framework?" in `apps/portal/index.html`.
- The identity skill's cluster table, which still names "Application Engine for the AI Era". It lives in the skills repository and gets its own follow-up.

## Avoided Traps

- **Cutting the paradigm-shift sections or the uniqueness sentence.** #20518 restored them at the operator's direction, and a framing critique is no license for cuts.
- **Renaming the file.** That would break the route, the SEO URL and inbound links.
