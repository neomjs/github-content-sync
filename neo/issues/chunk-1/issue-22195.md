# A dialog's animated hide can leave it visible (board CardEditor e2e)

## Context

The same test failed twice on unrelated docs-only heads:

1. 2026-11-24, neo#22158: run 45505582256, job 138839901800, e2e-engine 7/18.
2. 2026-11-25, neo#22192: run 45604582094, job 139172147604, e2e-engine 8/18.

Both re-runs passed, so the failure is intermittent. Sighting 2:

```
test/playwright/e2e/board/CardEditor.spec.mjs:86 › the editor moves a candidate to Interview and saves name, role and recruiter; Cancel and Escape change nothing
Error: expect(locator).toBeHidden() failed
Locator:  locator('.neo-board-card-editor')
Expected: hidden
Received: visible
Timeout:  5000ms
  4 × locator resolved to <div id="neo-board-1__editor" class="neo-board-card-editor neo-dialog … animated-hiding-showing">
  10 × locator resolved to <div id="neo-board-1__editor" class="neo-board-card-editor neo-dialog … neo-flex-wrap-nowrap">
> 94 |         await expect(editor).toBeHidden();
```

**Observed:** after `Cancel`, the editor carries `animated-hiding-showing`, then loses it and stays visible until the timeout. Sighting 1 showed the same sequence.

**Unknown:** whether the product leaves a cancelled dialog on screen, or only the test's timing exposes it. Neither failure has a trace read yet.

## The Problem

The failure turns unrelated PRs red and costs re-runs. If the product path is racing and not just the test, a user who cancels the card editor can be left looking at it.

## The Architectural Reality

- **Test sequence:** `CardEditor.spec.mjs:89-94` opens the editor from the card menu, waits for `toBeVisible()`, fills one field, and clicks `Cancel`. `Cancel` can therefore land inside the show animation's window.
- **`src/board/CardEditor.mjs`:** `onCancelButtonClick` / `onKeyDownEscape` → `cancel()` → `hide()`. The editor uses `closeAction: 'hide'` with `animateTargetId` set to the card.
- **`src/dialog/Base.mjs` `hide()`:** it animates only when `mounted && !mountFlight`. `animateHide()` measures, waits 30 ms, adds `animated-hiding-showing` with the target rect, and waits 250 ms. It then calls `closeOrHide(false)`, and for `closeAction === 'hide'` sends a direct `removeNode` delta.
- **Where the class is removed:**
  - `animateShow()` removes it in a direct delta after its 200 ms. Its comment says a `hide()` during the animation wins.
  - The cls sync after `#afterAnimation(timeout(250))` removes it too.

Hypotheses, unverified (the trace decides):
- (a) The show's 200 ms cleanup lands after the hide added the class, so the show and hide sequences interleave.
- (b) A VDom update of the dialog lands after the direct `removeNode` delta and re-renders the node without the class.

## The Fix

1. Reproduce `CardEditor.spec.mjs:86` with `--repeat-each=50` under CPU throttling (the e2e config, never the default `npx playwright test`). Keep the trace of a failing run.
2. From the trace, name the call that leaves the node visible.
3. Fix it at its owner. If that is the Dialog's own show/hide sequencing, the fix lands in `src/dialog/Base.mjs`.
4. If the root cause is the VDom update path (`VDomUpdate`, `VdomLifecycle`, `DeltaUpdates`), it does not get a pre-cut patch. It routes guides → ADR → code under the operator's 2026-11-25 rule; the guides are `learn/guides/vdomengine`.
5. Leave the assertion as it is, with no retry and no longer timeout: it encodes the intended behavior.

### Finding: `animateHide()` never ran — `Dialog#animateShow()` accepted a pointer hit-check during its `timeout(50)` card-rect pause, then launched before mouse dispatch

Both pre-trace hypotheses (`(a)` show/hide `animated-hiding-showing` cleanup interleaving and `(b)` post-`removeNode` VDOM update) are falsified by the traces. In both failures, **`CardEditor#cancel()` / `CardEditor#save()` and `Dialog#animateHide()` never executed**. The `4 × animated-hiding-showing` polls followed by `10 ×` un-classed `visible` polls seen by `expect(editor).toBeHidden()` were **`Dialog#animateShow()` (`src/dialog/Base.mjs:521-595`) completing its own opening animation** after the button click missed:

1. `animateShow()` mounts `#neo-board-1__editor` offscreen at `(-10000px, -10000px)` (`src/dialog/Base.mjs:548`, `initVnode(true)`), which satisfies `expect(editor).toBeVisible()` (`CardEditor.spec.mjs:91, 105`) while `pointer-events` are already enabled on the dialog.
2. `animateShow()` reads `[me.id, 'document.body']` (`line 550`), moves `#neo-board-1__editor` onto `animateTargetId` (`card('c-02')`: `left: 24px, top: 265px, width: 260px, height: 90px`, `lines 553-561`), and **parks it motionless for `await me.timeout(50)` (`line 564`)**.
3. Because `50 ms` spans ~3 animation frames at 60 Hz, Playwright's `locator.click()` stability check (2 consecutive `rAF` frames ≈ `33.4 ms`) passes on the squished footer button over `card('c-02')`, and `timeout(50)` expires inside the `4–5 ms` CDP dispatch gap before `performing click action`:
   - **Sighting 2 (`Cancel`, `CardEditor.spec.mjs:93-94`, `ivba@200..204`):** `getByLabel('Role').fill('Staff data analyst')` (`ivba@200`) executes offscreen at `6486.0 ms` (`box: {x: -9983, y: -9796, width: 406, height: 25}`). `Cancel.click()` (`ivba@202`) passes `visible, enabled and stable` at `6572.9 ms` on `box: {x: 118.97, y: 314.13, width: 71.92, height: 32}`, `point: {x: 154.92, y: 330.12}` (over `card('c-02')`). Between `6572.9 ms` and `performing click action` (`6577.4..6582.2 ms`), `timeout(50)` expires and `animateShow()` (`lines 567-578`) applies `cls: {add: ['animated-hiding-showing']}` + centered geometry (`left: 480px, top: 264px`). Under `200 ms ease-out`, the `71.9 px` button moves off `(154.92, 330.12)` before click completion (`error-context.md` confirms `Role` still holds `"Staff data analyst"`). `ivba@204` (`toBeHidden()`) then polls `animateShow()`'s own `animated-hiding-showing` at `6591.1..6770.7 ms` (`4` polls), followed by `animateShow()`'s `timeout(200)` cleanup (`line 584`) leaving the open dialog centered at `6874.8..11390.9 ms` (`10` polls).
   - **Sighting 1 (`Save`, `CardEditor.spec.mjs:110-111`, `lwzo@231..233`):** Identical race on the third open: `Save.click()` (`lwzo@231`) passes stability at `17555.4 ms` on `box: {x: 198.89, y: 314.13, width: 58.70, height: 32}`, `point: {x: 228.24, y: 330.12}`, `timeout(50)` expires before `17559.5..17564.8 ms` click dispatch, and `lwzo@233` polls `4 × animated-hiding-showing` (`17572.5..17749.9 ms`) then `10 ×` settled visible (`17852.8..22382.9 ms`). *(On Sighting 1's first open, `lwzo@202` beat `timeout(50)` by a few ms at `(154.92, 330.12)`, invoking `hide()` during `mountFlight`, while `animateShow()` still ran its `250 ms` expansion in `lwzo@204` before `startMountFlight` unmounted it at `16527.0 ms`.)*

### Ownership & VDOM Update-Path Gate (`AC-3`)

- **Owner:** `Neo.dialog.Base` (`src/dialog/Base.mjs` + `resources/css/src/dialog/Base.css`). **Zero VDOM update-path modules** (`src/vdom/**`, `VDomUpdate`, `VdomLifecycle`, `DeltaUpdates`) are involved, so this defect does not wait on the VDOM ADR.
- **Why page-only CDP throttling misses locally:** Chromium's `Emulation.setCPUThrottlingRate` returns `-32000: Operation is only supported for pages, not workers` on `DedicatedWorker` targets, throttling only the renderer Main thread while leaving `App` and `VDom` workers at unthrottled host speed (`waitForDomRect` finishes in `~1 ms`, shifting the `50 ms` window ahead of Playwright's `33.4 ms` two-`rAF` stability check).
- **Fix:** Hold `.neo-animating { pointer-events: none; }` on `Neo.dialog.Base` across `animateShow()` (from before `initVnode(true)` until its landing `applyDeltas`, with `finally` cleanup and immediate exit after `initVnode` if `me._hidden` flips mid-flight) and `animateHide()` (with single-flight guard), keeping programmatic `.focus()` / `.fill()` and keyboard `Escape` / `Enter` (`CloseFocus.spec.mjs`, `webdesktop/Apps.spec.mjs`) intact while preventing mid-transition pointer hits.
