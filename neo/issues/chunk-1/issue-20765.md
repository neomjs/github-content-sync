# An app served over plain http outside localhost does not boot

## Context

Seen while reviewing #20763 (not caused by it). Measured at `82458b0453` in Chromium (Playwright 1.65), with the component tier's test app under the dev server that `npm run server-start` starts:

| Load | Result |
|---|---|
| `http://localhost:<port>/test/playwright/component/apps/empty-viewport/index.html` | boots |
| the same path on `http://<LAN address>:<port>` | `isSecureContext` is `false`; `pageerror: crypto.randomUUID is not a function`; nothing mounts |
| the same, with `window.__NEO_SSR__ = {windowId}` set before boot | the VDom, Data and App workers start, then the App worker throws at `src/worker/App.mjs:39` (static initializer); nothing mounts |

## The Problem

`crypto.randomUUID` exists only in a secure context. A page served over plain http from any host other than localhost is not one. `npm run server-start` prints an "On Your Network" address that is such an origin, so an app opened from a phone or a second machine during development shows a blank page, and so does an app deployed on an http intranet. The error names a missing function, not the origin, so the cause is not obvious to the person who hits it.

The two boot-path calls date from `b583820910` (20 Nov 2025, window id) and `9053f909e5` (28 Dec 2025, App worker id).

## The Architectural Reality

- `src/worker/Manager.mjs:112`: `windowId: window.__NEO_SSR__?.windowId || crypto.randomUUID()`, main thread, at boot.
- `src/worker/App.mjs:39`: `id: crypto.randomUUID()` in the static config, App worker, at class definition.
- On demand, after boot: `src/Main.mjs:1351,1377,1383`, `src/manager/Transaction.mjs:243,245,313,371,858`, `src/manager/transaction/Commit.mjs:81`, `src/manager/transaction/History.mjs:190`, `src/data/Pipeline.mjs:996`, `src/dashboard/dock/window/Placement.mjs:394`. Twelve calls; each throws on the same origin when its path runs.
- `src/worker/CanvasGroups.mjs:76–85`, `CanvasGroups.mint()`: mints its id from `crypto.getRandomValues`, which has no secure-context gate and exists in workers.

Design authority: the summary of `Neo.worker.CanvasGroups.mint`, "Mints a fresh group id without needing a secure context … an app served over plain http whose window id comes from SSR — which boots without it today — would throw here." The engine's own record wants such an app to boot; row three of the table shows it does not.

## The Fix

One way to mint an id that needs no secure context, used at every browser-side call listed above. It returns the same text form as today (a version-4 UUID), built from `crypto.getRandomValues`, so no consumer of these ids sees a different shape. `CanvasGroups.mint` is the working precedent and can use the same helper.

Decision Record impact: none.

| Target Surface | Source of Authority | Proposed Behavior | Fallback | Docs | Evidence |
|---|---|---|---|---|---|
| ids minted in the browser (`windowId`, the App worker's `id`, transaction, pipeline and window-open tokens) | the summary of `CanvasGroups.mint` | a version-4 UUID string from `crypto.getRandomValues`, in secure and insecure contexts alike | none; one path | JSDoc of the helper | a browser control on a plain-http origin other than localhost |

## Acceptance Criteria

- [ ] The component test app loaded from a plain-http origin other than localhost boots: the viewport mounts and the page reports no error. A browser control holds that, and it fails on `82458b0453`.
- [ ] `git grep -n 'crypto\.randomUUID()' -- src` finds no call (18 lines today, comments included).
- [ ] The ids keep their text form: a consumer that stores or compares a `windowId` sees a version-4 UUID as before.
- [ ] `CanvasGroups.mint`'s summary is true again or is reworded to what the code does.

## Out of Scope

Features that browsers restrict to secure contexts themselves, such as the async Clipboard API and `getScreenDetails` (`src/main/addon/DragDrop.mjs:671` already checks `isSecureContext`): they stay unavailable on such an origin. Node-side code under `ai/` and `buildScripts/`.

## Avoided Traps

- **Guarding `Manager.mjs:112` only.** With a window id supplied, the App worker still throws (row three).
- **Feature-detecting `crypto.randomUUID` with a fallback.** Two paths, and the fallback runs only where nobody tests.
- **`Math.random` ids.** `crypto.getRandomValues` is available in insecure contexts and in workers.
