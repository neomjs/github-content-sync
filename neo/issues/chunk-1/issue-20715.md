# Move /learn search-intent title qualifiers into seoJson.mjs

Parent: #20671 · Companion: `neomjs/middleware-v2#57` / `PR #58` · Surfaced by: `neomjs/middleware-v2#58#pullrequestreview-5841488241` Required Action 5 (`@neo-fable-clio`) · Target window: before the `v13.5` cut (`2026-11-23`)

## Context

In `neomjs/middleware-v2#49` (`PR #50`), `SsrService#formatRouteTitle` (`src/service/SsrService.mjs:250–299`) enriched generic `/learn/*` headings with developer search-intent qualifiers across 7 rules (now unified onto ADR 0018 OD-1's `Application Engine` category noun):
1. `/learn/comparisons/Overview` → `'JavaScript Framework Comparisons (React, Angular, Vue, Solid vs Neo.mjs) | Neo.mjs'`
2. `/learn/comparisons/*` (`< 45` chars, no dash/colon qualifier) → `'${cleanH1} — Multi-Threaded JavaScript UI Comparison | Neo.mjs'`
3. `/learn/benefits/body/*` → `'${cleanH1} — Multi-Threaded JavaScript Application Engine | Neo.mjs'` (skipped when `${cleanH1}` already contains `Application Engine`, e.g. `/learn/benefits/body/ApplicationEngine` → `'The Application Engine for the AI Era - Neo.mjs'`)
4. `/learn/(benefits|agentos)/*` → `'${cleanH1} — AI Agent OS & Multi-Threaded Application Engine | Neo.mjs'`
5. `/learn/guides/*` → `'${cleanH1} — Neo.mjs Developer Guide'`
6. `/learn/tutorials/*` → `'${cleanH1} — Neo.mjs Tutorial | Neo.mjs'`
7. Any other `/learn/*` route (`< 45` chars, no dash/colon qualifier, no `Neo.mjs`, and not already containing `Application Engine`) → `'${cleanH1} — Multi-Threaded JavaScript Application Engine | Neo.mjs'`

In #20688 (PR #20689, merged at `3b4ccd00e1`), `buildScripts/docs/seo/seoJson.mjs` began populating `apps/portal/resources/data/seo.json` for ~125 `/learn/*` leaves using raw `<h1>` + `' - Neo.mjs'` (e.g. `'Overview - Neo.mjs'`, `'Extreme Speed - Neo.mjs'`). When `neomjs/middleware-v2#57` (`PR #58`) reads `apps/portal/resources/data/seo.json` as primary authority, `seo.json` wins whenever a route entry is present — which on the day the `13.5` package reaches the build host would replace `#49`'s search-intent qualifiers across those ~125 `/learn/*` routes unless the qualifiers live in `buildScripts/docs/seo/seoJson.mjs` itself.

## The Problem

Right now, two separate places format `/learn/*` route titles:
1. `buildScripts/docs/seo/seoJson.mjs#extractMarkdownSeoMetadata` (`buildScripts/docs/seo/seoJson.mjs:81–145`) appends a plain `' - Neo.mjs'` suffix when the `<h1>` does not already mention `Neo.mjs`, producing generic titles like `'Overview - Neo.mjs'` for `/learn/comparisons/Overview` and `'Extreme Speed - Neo.mjs'` for `/learn/benefits/body/Speed`.
2. `Neo.middleware.service.SsrService#formatRouteTitle` (`neomjs/middleware-v2` `src/service/SsrService.mjs:250–299`) enriches `/learn/comparisons/*`, `/learn/benefits/*`, `/learn/agentos/*`, `/learn/guides/*`, `/learn/tutorials/*`, and fallback `/learn/*` headings with developer search-intent qualifiers (`#49`), but only runs when a route is absent from `seo.json`.

Once `13.5` publishes the expanded `apps/portal/resources/data/seo.json` to `neomjs/pages` and `neomjs/middleware-v2`, `seo.json` overrides `formatRouteTitle` for every `/learn/*` route in the table, dropping `#49`'s search-intent qualifiers in crawler snapshots while the browser's `Portal.service.Seo` also misses them.

## The Architectural Reality

- `buildScripts/docs/seo/seoJson.mjs#getSeoJson` iterates `learn/tree.json` leaves and computes `route = '${cleanBase}/${cleanId}'` (`e.g. '/learn/comparisons/Overview'`) before calling `extractMarkdownSeoMetadata`.
- Passing `route` and `basePath` into `formatLearnSeoTitle(baseTitle, route, suffix, basePath)` in `buildScripts/docs/seo/seoJson.mjs` lets `apps/portal/resources/data/seo.json` serve as the single source of truth for `/learn/*` search-intent titles across both readers (`Portal.service.Seo` in the browser and `SsrService#extractRouteMetadata` in `neomjs/middleware-v2`).
- Unifying the category noun onto ADR 0018 OD-1's `Application Engine` and guarding `hasCategoryNoun = /application\s+engine/i.test(cleanTitle)` avoids unanchored `Web Engine` / `UI Engine` drift and prevents doubling the noun on headings like `'The Application Engine for the AI Era'`.
- Once the `13.5` package with enriched `/learn/*` titles in `seo.json` is published, `SsrService#formatRouteTitle`'s `/learn/*` branches in `neomjs/middleware-v2` become redundant and can be retired.

## The Fix

1. **Enrich `/learn/*` titles in `buildScripts/docs/seo/seoJson.mjs` before the `13.5` cut (`2026-11-23`):**
   - Port the 7 `/learn/*` search-intent qualifier rules into `buildScripts/docs/seo/seoJson.mjs` (`formatLearnSeoTitle(baseTitle, route, suffix, basePath)` / `extractMarkdownSeoMetadata` with `route` and `basePath`), covering `comparisons/Overview`, `comparisons/*`, `benefits/body/*`, `(benefits|agentos)/*`, `guides/*`, `tutorials/*`, and the 7th fallback `/learn/*` rule, unified onto the `Application Engine` category noun (ADR 0018 OD-1) with a `hasCategoryNoun` duplicate-noun guard.
   - Regenerate `apps/portal/resources/data/seo.json` so both `Portal.service.Seo` and `neomjs/middleware-v2` consume identical search-intent-qualified titles from one file.
2. **Add unit test coverage in `test/playwright/unit/buildScripts/docs/seo/Generate.spec.mjs`:**
   - Pin all 7 `/learn/*` qualifier rules and the `hasCategoryNoun` duplicate-noun guard against a self-contained `tempDir` fixture tree, and verify that committed `apps/portal/resources/data/seo.json` equals fresh `getSeoJson()` output.
