# The Multi-Window examples get their overview

## Context

The 13.5 gate asks that a stranger finds each component family's examples as an overview in which every example names what it proves (`ROADMAP.md`). `/examples/grid` is the pattern: 21 captioned Grid and Table demonstrations (#20500). The steward's map on #20498 ([comment](https://github.com/neomjs/neo/issues/20498#issuecomment-6757406109)) lists the families; this leaf delivers Multi-Window at `/examples/multi-window`: dock layouts, tear-out, and applications that span browser windows.

## The Problem

A live view that moves between browser windows is the capability no single-threaded UI library shows, and the Portal gives it no place. `examples/` holds ten demonstrations; two have a catalog record, none has a caption. Five application records belong to the same family (the Workstation among them) and sit uncaptioned in a list of 44 cards.

## The Architectural Reality

- One record per example in `apps/portal/resources/data/examples.json`; the record's shape is documented on `apps/portal/model/Example.mjs:16-27`. The 21 records with `"family": "grid-table"` are the reference for the length and tone of a caption.
- A family's tab appears with its first record (#20690), and a unit spec fails on a family record without `feature` or `lookFor`.
- Inventory at `62f75736ba`, each path under `examples/` with its own `neo-config.json`: `dashboard/base`, `dashboard/choreography` (record `dock-choreography`), `dashboard/crossWindow`, `dashboard/crossWindowWitness`, `dashboard/dock`, `dashboard/tearOut` · `component/multiWindowCoronaGallery` (record `multi-window-covid-gallery`) · `component/multiWindowHelix` · `stateProvider/multiWindow`, `stateProvider/multiWindow2`. The `childapp` folders of the two component demos are their popup windows, not entries.
- Application records that move into the family: `workstation`, `shared-covid`, `shared-offscreen-canvas`, `multi-window-drag-drop`, `colors-dashboard`.
- A record's `sharedWorkers` flag draws the multi-window badge and decides how its link opens (`apps/portal/view/examples/List.mjs:121,169`); it follows `useSharedWorkers` in the example's `neo-config.json`.
- Design authority: n/a — adds catalog records, calls no existing behavior wrong.

## The Fix

For every demonstration of the inventory: run it (`npm run server-start`, then its `index.html`), read its view and controller, and decide. It publishes when one sentence can say what it proves; otherwise it stays out and the pull request says why. A published demonstration gets one record: a stable string `id`, `name`, `"family": "multi-window"`, `component`, `feature` (what it proves), `lookFor` (one action and what to observe, for example which gesture moves a view into a second window), `scope` where it needs popups to be allowed or has a limit, the four `urls`, `sourceUrl`, `sharedWorkers`, and `image: null` unless a cover exists. The seven existing records get the family and their captions in place. Insert the new records as one block directly after the record `dock-choreography`, so that parallel family pull requests touch different lines.

## Acceptance Criteria

- [ ] Every path of the inventory is a record of family `multi-window` or is named in the pull request with its reason for staying out.
- [ ] The five application records carry the family, `feature` and `lookFor`.
- [ ] Each `feature` and `lookFor` was checked in the running example with a second window open; the pull request names the build and the browser. A caption states no number the example does not show and names no commercial feature.
- [ ] Every URL of a record answers 200 on neomjs.com, where the examples are deployed in all four builds, or that build is omitted on the record.
- [ ] `npm run test-unit -- test/playwright/unit/apps/portal/view/examples` passes with the new counts.
- [ ] The pull request shows `/examples/multi-window` at 1440×900 from a real browser.

## Out of Scope

New examples; Workstation behavior; covers (the typographic fallback is allowed, #20679 is the pattern for real ones); an engine fix for an example that turns out broken: file it and leave the example out.

## Avoided Traps

- Publishing a witness or test fixture as a demonstration: `dashboard/crossWindowWitness` enters only if a visitor can see what it proves.
- A caption that says "multi-window" without the gesture: the visitor must know what to drag, and where.
- Changing the position of the existing records: the showcase order is delivered intent (#19640).
