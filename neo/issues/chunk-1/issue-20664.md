# publish.mjs prepare sets the version in its release commit

## Context

On 2026-11-09 the operator directed a new ticket for this ("a new ticket mentioning the closed one is cleaner"), after Vega's evidence from the 13.4.0 cut. #19827 ("`publish.mjs prepare` sets the release version itself") was closed not planned on 2026-10-16 at his direction ("bumping `package.json` before `prepare` works as is"). Its PR #19828 was closed unmerged at a reviewed head.

What the 13.4.0 cut showed:
- **The bump cannot be a one-file edit.** A manual bump must drop the last released note in the same commit, or `test/playwright/unit/buildScripts/release/PublishReleaseNoteOrphan.spec.mjs` fails.
- **The committed Portal index still points at the dropped note.** `apps/portal/resources/data/releases.json` keeps the reference until something regenerates it, so `dev`'s news route fetches a 404 page.
  - **13.4.0:** CI caught it on #20658's first head through `test/playwright/e2e/portal/NewsTabOverflow.spec.mjs` (#20599). A second commit (`508dcb93f5`) regenerated the index.
  - **13.3.1:** #20024 made the same drop without touching the index, before any spec covered news routes.
- **Each cut whose notes merge before the bump pays twice:** an extra ticket, PR, full CI run, review and operator merge (13.4.0: #20656 → #20658).

## The Problem

The version is a manual precondition of the cut, but three things must change with it: `package.json` and `package-lock.json`, the drop of the released note, and the Portal release index. `prepare` already does the last two in its release commit. The manual bump splits them across two PRs and two merges, and `dev` breaks in the gap between those merges. Since #20599, CI refuses a bump that skips the index, so the broken news route can no longer reach `dev`. What remains is a second PR per cut and three coupled hand edits that each cut must remember.

## The Architectural Reality

- `buildScripts/release/publish.mjs:60` reads the version from `package.json` when it loads. The comment at `:61` says it "was bumped to before the cut", and the summary at `:9` lists "version bumped" as a preflight condition.
- `prepare` already does the rest, then commits to `release/v<version>`:
  - It drops every note older than the version being released (`publish.mjs:71`).
  - It stamps the note.
  - It runs `prepare.mjs`, which regenerates the Portal release index (`prepare.mjs:14` imports `createReleaseIndex` from `buildScripts/docs/index/release.mjs`).
  - It runs `build-all`.
- `releaseState.mjs:91` blocks an existing tag with "bump package.json first", and `:182` ends with "(bump package.json)".
- `buildScripts/README.md:80` says `prepare.mjs` "Handles version bumping, changelog generation, and git tagging". It does none of the three.
- `package.json` defines no `preversion`, `version` or `postversion` scripts (checked at `origin/dev`), so `npm version <v> --no-git-tag-version` touches only `package.json` and `package-lock.json`.
- Design authority: the operator on 2026-11-09, "a new ticket mentioning the closed one is cleaner". On the 13.4.0 evidence, it supersedes his 2026-10-16 "bumping `package.json` before `prepare` works as is" (#19827).

## The Fix

- **`publish.mjs prepare --version <semver>`.**
  - The preflight requires a valid semver newer than `package.json`'s version, its note present and no existing tag.
  - The release commit sets the version first, with `npm version <v> --no-git-tag-version`.
  - It then runs the existing steps: the note drop, the stamp, `prepare.mjs` (which propagates the version and regenerates the Portal index) and `build-all`. The bump, the drop and the index land in one commit.
- **`finish`** derives the version from `origin/dev`'s `package.json`, which the merged release PR set.
- **Stale messages and docs** that ask for a manual bump are corrected: `releaseState.mjs:91` and `:182`, `publish.mjs:9` and `:61`, and `buildScripts/README.md:80`.
- **Starting point:** #19828's reviewed head, where it still applies. Its RA-1, to canonicalize the target version before deriving the release identity, was addressed there.
