# Crawler snapshots read apps/portal/resources/data/seo.json for route metadata and neo-route JSON-LD

Parent: #20671 · surfaced by: #20689 Round-1 review (`5836208814` by `@neo-fable-clio`)

## Context

In Engine 13.5 Cornerstone 4 (#20671 — *Search engines and agents find and classify neomjs.com*), #20688 (`PR #20689`) generates route-specific `title`, `description`, and `schemaType` entries into `apps/portal/resources/data/seo.json` and wires `Portal.service.Seo` + `Neo.main.addon.DocumentHead#update` so the browser shell updates `<title>`, `<meta name="description">`, `<link rel="canonical">`, Open Graph tags, and `data-schema-name="neo-route"` `application/ld+json` on route change.

As `@neo-fable-clio` verified in `#20689` review `5836208814`, crawler snapshots served by `neomjs/middleware-v2` (`SsrService#buildHeadInjection`) do **not** run `Portal.service.Seo` or `Neo.main.addon.DocumentHead`: the middleware builds the `<head>` of a crawler snapshot from the rendered markdown/route and `index.html`. Consequently, after `#20689` merges, a deep route has two different `<title>` values (`"Setup — Multi-Threaded JavaScript UI Engine | Neo.mjs"` in the crawler snapshot vs `"Setup - Neo.mjs"` in the browser shell from `seo.json`), and `data-schema-name="neo-route"` (`TechArticle` / `BlogPosting` + `BreadcrumbList` JSON-LD) exists in the browser shell only — not in the crawler snapshot that Googlebot and coding agents receive.

## The Problem

1. **Divergent titles & descriptions between crawler snapshots and the browser shell:** `SsrService#buildHeadInjection` in `neomjs/middleware-v2` constructs `<title>` and `<meta name="description">` with its own rules rather than reading `apps/portal/resources/data/seo.json`, so the browser shell (`Portal.service.Seo`) and the crawler snapshot disagree on route titles and descriptions.
2. **Missing `data-schema-name="neo-route"` JSON-LD in crawler snapshots:** `Portal.service.Seo` injects `TechArticle` / `BlogPosting` and `BreadcrumbList` JSON-LD via `DocumentHead#update` in the browser, but `SsrService#buildHeadInjection` never runs `Portal.service.Seo`, leaving crawler snapshots without route-specific `application/ld+json` (Search Console's 3-month baseline recorded on `#20671` shows `0` rich results).

## The Architectural Reality

- **`apps/portal/resources/data/seo.json` is the published route metadata table (`#20688` / `#20689`):** Deployed to `neomjs/pages` at `/apps/portal/resources/data/seo.json` (and `/dist/production/apps/portal/resources/data/seo.json`) and refreshed by `buildScripts/docs/rebuildContentIndexesAndSeo.mjs`.
- **`SsrService#buildHeadInjection` (`neomjs/middleware-v2`):** Assembles the `<head>` tags injected into `index.html` for crawler and agent requests (`Googlebot`, `claudebot`, `gptbot`, `curl`, etc.).

## The Fix

1. Update the crawler snapshot `<head>` builder (`SsrService#buildHeadInjection` in `neomjs/middleware-v2`) to read `apps/portal/resources/data/seo.json` for matching routes so both the crawler snapshot and `Portal.service.Seo` serve the same `<title>`, `<meta name="description">`, `<link rel="canonical">`, and Open Graph tags.
2. Emit `<script type="application/ld+json" data-schema-name="neo-route">` (`TechArticle` / `BlogPosting` + `BreadcrumbList` matching `Portal.service.Seo#buildRouteLdJson`) in the crawler snapshot alongside the existing `data-schema-name="neo-organism"` script when `seo.json` holds an exact entry for the requested route.

## Acceptance Criteria

- [ ] Crawler snapshots for `/learn/*`, `/news/blog/*`, `/news/releases/*`, and curated top-level routes in `apps/portal/resources/data/seo.json` serve the same `<title>`, `<meta name="description">`, and `<link rel="canonical">` as `Portal.service.Seo` in the browser.
- [ ] Crawler snapshots for routes with an entry in `seo.json` include `<script type="application/ld+json" data-schema-name="neo-route">` carrying the route's schema (`TechArticle` / `BlogPosting` / `WebPage` + `BreadcrumbList`) while preserving `data-schema-name="neo-organism"`.
- [ ] Unit tests pin `buildHeadInjection` against `seo.json` entries and fallback routes.
