# Board columns slide into place during a column drag

## Context

Engine 14 shipped the Board’s full-column drag proxy in #21657. The Board moved out of Neo Pro, and neomjs/neo-pro#228 closed as superseded. The remaining interaction from neomjs/neo-pro#215 is the sideways slide of neighboring whole columns during a drag.

## The Problem

Open `examples/board/basic` at 1920 × 1080, pick up Ready by the header, and move it past In Progress. In headless Chrome in both Neo Light and Neo Dark, the proxy carried Ready’s ten cards. The neighboring In Progress column jumped from x=564 to x=288 with a computed transition duration of 0s. The frame series sampled 58 frames for light with drop and 57 for dark with Escape. The original Ready column returned visible at x=564 on drop and x=288 on Escape. Both existing Engine column-drag cases passed.

The probe used local Engine `fc30265ef9`. The Board ColumnSortZone, shared SortZone and Board Column CSS blobs match the 14.0.0 tag.

A controlled replay on the public Board example reproduced the same motion. With a normal Chrome user agent, Neo Light drop and Neo Dark Escape captured 74 and 57 frames respectively. Both runs carried ten cards in the proxy, reported a 0s transition and recorded only x=564 and x=288 for In Progress. Ready settled at x=564 on drop and x=288 on Escape. The default HeadlessChrome user agent received the crawler snapshot, so the deployment replay uses the browser user-agent path. [Public Board example](https://neomjs.com/examples/board/basic/index.html) · [Middleware routing](https://github.com/neomjs/middleware-v2/blob/35e1dd21d9a04d8011c3be17c8772a8a27b7b8db/src/server.mjs#L872-L906)

## The Architectural Reality

[Board ColumnSortZone](https://github.com/neomjs/neo/blob/14.0.0/src/board/ColumnSortZone.mjs) inherits the shared [SortZone](https://github.com/neomjs/neo/blob/14.0.0/src/draggable/container/SortZone.mjs) geometry and clones the dragged column’s rendered tree. The shared sort moves pinned items through their wrapper position. [Board Column CSS](https://github.com/neomjs/neo/blob/14.0.0/resources/css/src/board/Column.css) styles the carried column’s shadow. The evidence here concerns the original neighboring column while the pointer is held.

Design authority: the operator’s correction in neomjs/neo-pro#215 says “other whole columns must slide sideways behind it, as the free Grid does.”

## The Fix

Use the existing Board column drag state and motion tokens to animate neighboring whole columns between their preview slots. Extend the existing [Board E2E](https://github.com/neomjs/neo/blob/14.0.0/test/playwright/e2e/board/BasicNL.spec.mjs#L151) to sample the neighbor before, during and after the slot switch. Keep the shared sort responsible for reordering.

## Acceptance Criteria

- [ ] During a pointer drag, the original neighboring column passes through intermediate horizontal positions. Its header and a retained card travel with it. Show both Neo Light and Neo Dark.
- [ ] A locked column stays pinned, and reduced motion settles directly into the preview slot.
- [ ] Drop settles the preview with one reorder. Escape restores the starting order. Record frames through both ends and confirm the existing full-column proxy and subsequent card drag still pass.
