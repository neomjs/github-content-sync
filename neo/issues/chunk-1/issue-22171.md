# Document pathname routing, windowId SharedWorker links, and spaRoot

Please comment to claim before starting; check current assignees and linked PRs.

`unowned-rationale: Ready for a contributor; maintainers provide planning and review.`

## Context

Part of #22169 (graduated from [Discussion #22145](https://github.com/orgs/neomjs/discussions/22145) `OQ-1`, `OQ-2`, `OQ-5`, and Step-Back Rows `2(c)`, `5`, `7`). Owns the `4`-file documentation slice across `learn/tutorials/Routing.md` and `learn/gettingstarted/{Setup,CreatingYourFirstApp,Workspaces}.md`.

## The Problem

1. **`learn/tutorials/Routing.md` documents hash routing only:** Developers and agents have zero guide coverage for opting into `routerMode: 'pathname'`, `routerBasePath`, `routerIgnorePaths`, `<base href>`, `?query` / `Main#editRoute`, explicit `windowId` link formatting in `SharedWorker` apps, `fileServer.mjs` `spaRoot` / `--no-spa-root`, or the boundary between Engine human-core routing and external crawler/archive middleware.
2. **Getting-started guides assume `npm run server-start` serves a directory listing at `/`:** Enabling `"neo": {"spaRoot": "apps/portal"}` in `neomjs/neo` changes `/` on `npm run server-start` to serve the Portal unless `--no-spa-root` is passed, while `npx neo-app` workspaces (`neomjs/create-app`) continue using `run({open})` without a `spaRoot` unless configured.

## The Architectural Reality

- `Design authority:` `src/DefaultConfig.mjs:246-268`, [Discussion #22145](https://github.com/orgs/neomjs/discussions/22145), and `.agents/skills/guide-authoring/` (`learn/tutorials/` + `learn/gettingstarted/`).
- All `4` target files already exist in `learn/` (zero file moves or `tree.json` renames required).

## The Fix

1. **`learn/tutorials/Routing.md`:** Add a clear, example-backed section on opt-in `'pathname'` routing covering:
   - Keeping `'hash'` as the zero-config default vs. when to opt into `'pathname'`.
   - Configuring `routerMode: 'pathname'`, `routerBasePath`, `routerIgnorePaths` (raw-pathname evaluation order before trailing-slash canonicalization), and `<base href>` across dev and `dist/*` builds.
   - Reading and mutating `?search` query parameters (`value.hash` / `value.query` / `value.search`, `Neo.Main.editRoute({key: 'val'})` and `editRoute({key: null})`).
   - Passing explicit `windowId` to `Neo.util.String.toRouteHref(route, this.windowId)` and reading `Neo.windowConfigs[windowId]` inside `SharedWorker` apps.
   - Local SPA serving with `fileServer.mjs` (`package.json` `"neo": {"spaRoot": "..."}`, `--spa-root`, `--no-spa-root`, sub-path `pathname` mounts) and the explicit scope boundary (Engine covers interactive human routing; crawler SSR, `410`s, and archive redirects belong to deployment middleware).
2. **`learn/gettingstarted/Setup.md`, `CreatingYourFirstApp.md`, and `Workspaces.md`:** Document that `npm run server-start` in `neomjs/neo` mounts `apps/portal` at `/` via `"neo": {"spaRoot": "apps/portal"}`, how to pass `npm run server-start -- --no-spa-root` for the root directory listing, and how `npx neo-app` workspaces use `fileServer.mjs` `run({open})` with optional `neo.spaRoot` support.
