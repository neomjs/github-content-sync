# Add pressed background, text, and glyph tokens to Neo.button.Base

## Context

Surfaced during review of `neomjs/neo-pro#146` (`neomjs/neo-pro#145`, `PRR_kwDOVg8fac8AAAABXGZm0g`), where grouping preset and summary toolbar buttons set `pressed: true` (`Neo.button.Base#afterSetPressed` toggling `.pressed` on the button root).

- **Design authority:** `src/button/Base.mjs:59-64` and `src/button/Base.mjs:379-388` (`pressed_` config: *"pressed state for buttons; toggles the `'pressed'` class on the button element via `NeoArray.toggle(cls, 'pressed', value === true)`"*) together with `#18141` / `#18171` (every `&.pressed` button variant in `resources/scss/src/` must read flat theme tokens declared across all 5 theme sheets, and `theme-neo-dark` / `theme-neo-light` must give pressed buttons a visually distinct state).

## The Problem

`Neo.button.Base` provides first-class `pressed_` state (`src/button/Base.mjs:59-64`, `:379-388`), and `resources/scss/src/button/Base.scss` styles `&.pressed` across all four button UIs (`primary`/default, `--secondary`, `--ghost`, `--tertiary`). However:

1. **Structural stylesheet only consumes border tokens on `&.pressed`:**
   - `resources/scss/src/button/Base.scss:332-334` (`&.pressed { border: var(--button-border-pressed); }`)
   - `resources/scss/src/button/Base.scss:96-98` (`.neo-button-secondary.pressed { border: var(--button-secondary-border-pressed); }`)
   - `resources/scss/src/button/Base.scss:176-178` (`.neo-button-ghost.pressed { border: var(--button-ghost-border-pressed); }`)
   - `resources/scss/src/button/Base.scss:253-255` (`.neo-button-tertiary.pressed { border: var(--button-tertiary-border-pressed); }`)
   None of the four `&.pressed` blocks consume pressed background, text, or glyph color tokens (`--button-*-background-color-pressed`, `--button-*-text-color-pressed`, `--button-*-glyph-color-pressed`).
2. **Stock `theme-neo-dark` and `theme-neo-light` set `--button-*-border-pressed` identical to unpressed:**
   - In both `resources/scss/theme-neo-dark/button/Base.scss` and `resources/scss/theme-neo-light/button/Base.scss`:
     - `--button-border-pressed: none` (identical to `--button-border: none` at line 23)
     - `--button-secondary-border-pressed: var(--cmp-button-borderwidth) solid var(--cmp-button-secondary-border-default)` (identical to `--button-secondary-border` at line 55)
     - `--button-ghost-border-pressed: none` (identical to `--button-ghost-border: none` at line 85)
     - `--button-tertiary-border-pressed: none` (identical to `--button-tertiary-border: none` at line 117)
   As a result, setting `pressed: true` on a stock `Neo.button.Base` in `neo-theme-neo-dark` or `neo-theme-neo-light` produces zero computed-style difference from `pressed: false`, forcing consumers (such as `neomjs/neo-pro`'s `progridgrouping` toolbar in `neomjs/neo-pro#146`) to write an app-local `.neo-button.pressed` override block.

## The Architectural Reality

- `src/button/Base.mjs:379-388` — `afterSetPressed(value, oldValue)` toggles `'pressed'` on `this.cls`.
- `resources/scss/src/button/Base.scss`:
  - Primary/default `&.pressed` (`:332-334`)
  - `.neo-button-secondary` `&.pressed` (`:96-98`)
  - `.neo-button-ghost` `&.pressed` (`:176-178`)
  - `.neo-button-tertiary` `&.pressed` (`:253-255`)
- All 5 theme sheets carrying `button/Base.scss` (`#18141` nested-theme reset rule):
  - `resources/scss/theme-neo-dark/button/Base.scss`
  - `resources/scss/theme-neo-light/button/Base.scss`
  - `resources/scss/theme-dark/button/Base.scss`
  - `resources/scss/theme-light/button/Base.scss`
  - `resources/scss/theme-cyberpunk/button/Base.scss`
- Sibling precedent: `#18171` (`resources/scss/src/tab/header/Button.scss:67`, which reads `--tab-button-glyph-color-pressed` and `--tab-button-text-color-pressed` on `&.pressed` and declares them in every theme sheet carrying `tab/header/Button.scss`).

## The Fix

1. **Extend `resources/scss/src/button/Base.scss` `&.pressed` rules** across the four button variants (`default`, `secondary`, `ghost`, `tertiary`) to apply:
   - `background-color: var(--button-<variant>-background-color-pressed)` (and `--button-background-color-pressed` on base)
   - `border: var(--button-<variant>-border-pressed)`
   - `.neo-button-text { color: var(--button-<variant>-text-color-pressed); }`
   - `.neo-button-glyph { color: var(--button-<variant>-glyph-color-pressed); }`
2. **Declare the pressed token set in all 5 `resources/scss/theme-*/button/Base.scss` files** (`theme-neo-dark`, `theme-neo-light`, `theme-dark`, `theme-light`, `theme-cyberpunk`):
   - In `theme-neo-dark` and `theme-neo-light`, bind pressed background, border, text, and glyph tokens to visually distinct active/contrast semantic tokens (e.g. `--cmp-button-*-surface-active`, `--sem-color-border-focused` / `--cmp-button-secondary-border-hover`, `--sem-color-fg-neutral-contrast`) so a `pressed: true` button is visually distinguishable from `pressed: false` in both themes out of the box.
   - In `theme-dark`, `theme-light`, and `theme-cyberpunk`, declare each new `--button-*-background-color-pressed`, `--button-*-text-color-pressed`, and `--button-*-glyph-color-pressed` token so nested theme boundaries reset cleanly per `#18141`.
3. **Compile CSS outputs** via `npm run build-themes` (or targeted theme build) and verify with a Playwright component/unit spec asserting computed `backgroundColor`, `borderColor`, and text/glyph `color` differ between `pressed: false` and `pressed: true` in both `neo-theme-neo-dark` and `neo-theme-neo-light`.

## Avoided Traps

- **Adding descendant `.pressed` selectors inside theme files:** per `#18145` and `#18171`, `pressed` is a class on `.neo-button` itself (`&.pressed`), and selector blocks belong in `resources/scss/src/button/Base.scss` while `resources/scss/theme-*/button/Base.scss` declare CSS custom properties only.
- **Declaring new tokens in `theme-neo-*` only:** per `#18141`, omitting new tokens from `theme-dark`, `theme-light`, or `theme-cyberpunk` leaks outer theme values across nested theme boundaries.
