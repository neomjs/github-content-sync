# Flip useVdomWorker's default to false (ADR 0043 Phase 1)

## Context

ADR 0043 §2.4 (`learn/agentos/decisions/0043-vdom-diff-placement.md`) ends Phase 1 with `useVdomWorker` defaulting to `false`, once three observables hold. (b) and (c) are the gate leaf #22208's. (a), the full hosted matrix green in the two-thread arm, is read on this leaf's own required CI (moved from #22208 on 2026-11-25). This leaf is the flip and nothing else.

## The Problem

The default still starts the VDom worker in every app, so the line ADR 0043 chose runs only where a config opts out. No app or example sets the flag explicitly: `git grep useVdomWorker` over `apps/`, `examples/` and the build scripts at `origin/dev` `e6418ff` finds only an archived Portal ticket JSON. The default therefore decides for all of them.

## The Architectural Reality

- `src/DefaultConfig.mjs:416-419` declares `useVdomWorker: true`. The flag is read by `src/Main.mjs`, `src/mixin/VdomLifecycle.mjs`, `src/worker/App.mjs`, `src/worker/Base.mjs` and `src/worker/Manager.mjs`.
- No tracked `neo-config.json` sets the flag (0 of 286 at `e6418ff`). So with the default flipped, the required `e2e-engine` shards run the full hosted matrix in the two-thread arm. That run is ADR 0043 §2.4 (a).
- `test/playwright/e2e/rendering/YieldedMoveCoalescingNL.spec.mjs` drives the worker directly and sets no `useVdomWorker` today. On the new default it would fail for the wrong reason, and ADR 0043 §2.4 (a) keeps it on the worker arm through Phase 2.
- `learn/guides/vdomengine/Overview.md` names each stage's realm in its "Runs in today" column. ADR 0043 says it changes one cell of it, stage 3's.

## The Fix

1. `src/DefaultConfig.mjs`: `useVdomWorker: false`. Its JSDoc names ADR 0043 and says `true` stays supported until Phase 3.
2. `learn/guides/vdomengine/Overview.md`: stage 3's "Runs in today" cell names the App worker.
3. `YieldedMoveCoalescingNL` pins `useVdomWorker: true` for its pages, the way `TwoThreadPipelineNL` pins the other value.
