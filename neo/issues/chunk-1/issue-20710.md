# Examples stops observing when its cards are not ready yet

## Context

Engine 13.5's examples overview (#20498) relies on intersection notifications to load card covers beyond the first four. An existing defect note and Vega's independent intake both identified an undeclared retry budget in `Portal.view.examples.List`.

## The Problem

On `54ee6a6b02` and PR #20703's `5ef827829c`, `registerIntersectionObserver()` reads `intersectionObserverReconnects`, which neither the Examples class nor its ancestors declare. If the first registration finds no targets while DOM nodes are moving into place, the retry loop executes zero times.

Exact-source probe with a real `Neo.create(List)`, a register result of `{countTargets: 0}`, and an observe result of `{countTargets: 5}`:

```text
current default: timeout(150), register(0); no observe call
budget = 10: timeout(150), register(0), timeout(100), observe(5)
```

This is a controlled App-worker method receipt, not a claimed natural browser reproduction.

## The Architectural Reality

- `apps/portal/view/examples/List.mjs#registerIntersectionObserver` owns the existing bounded retry loop.
- `apps/portal/view/news/medium/List.mjs` declares `intersectionObserverReconnects: 10` for its equivalent loop. Its JSDoc explicitly describes targets temporarily missing while moving a component in the DOM.
- Design authority: that existing retry loop and the Medium sibling's documented delayed-target recovery.
- Closed #5881 covered the converse Examples-to-blog navigation in 2024; it does not declare this missing Examples config.
- Prescription checked: Examples List owns its retry budget; no engine or observer-addon change is needed.

## The Fix

Declare and document the Examples list's retry budget using the existing sibling default. Keep its initial delay, retry delay and stop-on-success behavior. Exercise the real List method with controlled observer responses in the existing Portal examples unit spec.

## Contract Ledger

| Target Surface | Source of Authority | Behavior | Fallback | Docs | Evidence |
|---|---|---|---|---|---|
| `List#intersectionObserverReconnects` | existing retry loop; Medium List sibling | ten bounded retries by default; instance override supported | zero disables retries | config JSDoc | delayed-target, immediate-success and exhaustion controls |

## Acceptance Criteria

- [ ] A default List retries an initially empty registration and stops as soon as targets appear.
- [ ] An initial registration with targets makes no observe call.
- [ ] Permanently missing targets exhaust a finite budget; an explicit instance budget, including zero, is respected.
- [ ] The focused Portal examples unit spec passes.

## Out of Scope

Family navigation, catalog records, artwork, the Medium list, observer-addon changes, retry-timing changes and claims of deployed acceptance.

## Avoided Traps

Do not introduce another retry owner or use an unbounded poll. A constant-only assertion is insufficient: invoke the production method and count observer calls.
