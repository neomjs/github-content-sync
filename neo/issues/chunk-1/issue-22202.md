# Torn-out desktop popup windows lose AppWindow glass surface styling

## Context

Reported by `@tobiu` against `https://neomjs.com/dist/production/apps/webdesktop/index.html` (`14.0.0`): popping out or tearing out a Web Desktop app window (`Reports`, `Mail`, `Documents`, `Messages`, `Music`, `Photos`, `Settings`, `Help`, `Recycle Bin`) into its native popup window (`?desktopPopup=...`) drops the desktop app window's glass surface and wallpaper backdrop, rendering the widget over flat neutral `#0d0f12` (`rgb(13, 15, 18)`) black in `neo-theme-neo-dark` with an unstyled `#0d0f12` return toolbar.

Live Chromium reproduction on `dev` (`d80c89b8ca`) opening `Reports` and clicking `Pop out window`:
- **Inside `Neo.desktop.AppWindow` (`windowId: 1`):** `dialogBg = "rgba(15, 23, 42, 0.74)"` (`backdrop-filter: blur(30px) saturate(160%)` over `var(--desktop-wallpaper)`), `dialogColor = "rgb(241, 245, 249)"`, `--container-background-color: transparent`, `oddCellBg = "rgba(0, 0, 0, 0)"`, `evenCellBg = "rgba(255, 255, 255, 0.1)"`.
- **Inside `Neo.desktop.PopupViewport` (`windowId: 2`):** `vpBg = "rgb(13, 15, 18)"`, `tbBg = "rgb(13, 15, 18)"`, `bodyWrapBg = "rgb(13, 15, 18)"`, and `--desktop-wallpaper = ""` (empty).

## The Problem

1. **`Neo.desktop.PopupViewport` (`src/desktop/PopupViewport.mjs`) has no class hook and no stylesheet (`resources/css/src/desktop/PopupViewport.css` does not exist):**
   - Inside the desktop, every app body renders inside `.neo-dialog.neo-desktop-app-window` (`resources/css/src/desktop/AppWindow.css:2-21`), which sets `--container-background-color: transparent`, `background-color: var(--desktop-app-window-background-color)`, `color: var(--desktop-app-window-color)`, and a transparent bottom-bordered header toolbar (`--toolbar-background-color: transparent`, `border-bottom: 1px solid var(--desktop-app-window-border-color)`).
   - When `WindowTearOut` moves the live app body into `PopupViewport`'s `desktopPopupBody` (`Neo.container.Base`), `PopupViewport` inherits `.neo-viewport`'s raw `--viewport-background-color` (`rgb(13, 15, 18)` in `neo-theme-neo-dark`), `desktopPopupBody` and nested containers paint opaque `--container-background-color` (`rgb(13, 15, 18)`), `desktopPopupToolbar` (`← Back to desktop`) paints opaque `rgb(13, 15, 18)` with no glass border or header ink tokens, and plain text loses `color: var(--desktop-app-window-color)`.
2. **`Neo.desktop.Container`'s theme stylesheet (`--desktop-wallpaper`, `--desktop-color`) is never loaded in the popup document:**
   - `WindowTearOut#attach` (`src/desktop/WindowTearOut.mjs:188-190`) calls `insertThemeFiles` on `root` (`WebDesktop.view.Viewport`) and `owner` (`Neo.desktop.AppWindow`), neither of which subclasses `Neo.desktop.Container`. Consequently `resources/css/theme-*/desktop/Container.css` is never added to the popup's `<head>`, leaving `--desktop-wallpaper` empty (`""`).
3. **Shared engine impact:** Because `PopupViewport` is the engine shell in `src/desktop/PopupViewport.mjs`, both `apps/webdesktop` and `examples/desktop/basic` (`Calculator`, `Music`, `Notes`) suffer the same surface loss when torn out.

## The Architectural Reality

Design authority: `"The engine's grid on an app window's glass: its stylesheet sets the grid's own CSS variables from the window's tokens, so the apps' grids share one look and no rule competes with the grid's rules."` (`WebDesktop.view.apps.GlassGrid`, `apps/webdesktop/view/apps/GlassGrid.mjs:4-5`) and `"/* An app window drawn as desktop glass. .neo-dialog in the selector outranks the dialog's own chrome rules. */"` (`resources/css/src/desktop/AppWindow.css:1-21`).

- `#22104` (PR `#22108`) synchronized the popup's `theme` class (`neo-theme-neo-dark` / `neo-theme-neo-light`) and verified `--desktop-app-window-color` + `--webdesktop-ink-dim` token availability in `Apps.spec.mjs:390-413`, which passed even while `PopupViewport` itself never consumed `--desktop-app-window-background-color`, `--desktop-wallpaper`, `--desktop-app-window-color`, or `--container-background-color: transparent`.
- `Neo.worker.App#insertThemeFiles` (`src/worker/App.mjs:479-481`) natively resolves `additionalThemeFiles` on component prototypes (used by `Neo.dashboard.dock.Workspace` at `src/dashboard/dock/Workspace.mjs:194` with `additionalThemeFiles: ['Neo.dashboard.Container']`).
- Inside the desktop, an `AppWindow` visually composites `var(--desktop-app-window-background-color)` (`rgba(15, 23, 42, .74)` in `neo-dark`, `rgba(255, 255, 255, .78)` in `neo-light`) over `Neo.desktop.Container`'s `var(--desktop-wallpaper)`. Layering `linear-gradient(var(--desktop-app-window-background-color), var(--desktop-app-window-background-color)), var(--desktop-wallpaper)` on `.neo-viewport.neo-desktop-popup-viewport` reproduces that exact glass-over-wallpaper surface in a standalone OS window across all 5 themes (`neo-dark`, `neo-light`, `dark`, `light`, `cyberpunk`) without needing an underlying desktop DOM node.

Decision Record impact: none (`aligned-with` ADR 0029 by keeping desktop popup styling inside `src/desktop/`).

## The Fix

1. **`src/desktop/PopupViewport.mjs`:**
   - Add `cls: ['neo-desktop-popup-viewport']` and `additionalThemeFiles: ['Neo.desktop.Container', 'Neo.desktop.AppWindow']` so every popup viewport automatically loads both desktop token sheets (`--desktop-wallpaper`, `--desktop-color`, `--desktop-app-window-*`) and its own structural stylesheet.
2. **`resources/css/src/desktop/PopupViewport.css` (+ theme build / `cssMap` regeneration via `npm run build-themes -- -n -e dev -t all`):**
   - Style `.neo-viewport.neo-desktop-popup-viewport` with `--container-background-color: transparent`, `background: linear-gradient(var(--desktop-app-window-background-color), var(--desktop-app-window-background-color)), var(--desktop-wallpaper)`, and `color: var(--desktop-app-window-color)`.
   - Style `.neo-desktop-popup-viewport > .neo-toolbar` to match `.neo-desktop-app-window .neo-header-toolbar` (`--toolbar-background-color: transparent`, `border-bottom: 1px solid var(--desktop-app-window-border-color)`, color/button tokens harmonized with `--desktop-app-window-color` / `--desktop-app-window-icon-color`).
   - Check `WebDesktop` font inheritance (`Viewport.css` sets `font-family: system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif` on `.webdesktop-viewport`; verify computed typography and contrast across torn-out `Reports`, `Mail`, `Messages`, `Documents`, `Settings`, `Help`, and `examples/desktop/basic`).
3. **Tests (`test/playwright/unit/desktop/` and `test/playwright/e2e/webdesktop/Apps.spec.mjs` / `test/playwright/e2e/desktop/WindowTearOut.spec.mjs`):**
   - Assert in real Chromium that a torn-out `WebDesktop` window (`Reports` / `Mail`) in `PopupViewport` resolves non-empty `--desktop-wallpaper`, transparent `desktopPopupBody` / `desktopPopupToolbar` container backgrounds, and a `PopupViewport` `backgroundImage` / `color` matching the desktop glass surface across dark and light themes (rather than raw `rgb(13, 15, 18)` / `rgb(255, 255, 255)`).
   - Include before/after whole-window screenshots (`pr-review` Rendered-Surface Audit) in both dark and light themes.

## Acceptance Criteria

- [ ] `Neo.desktop.PopupViewport` declares `cls: ['neo-desktop-popup-viewport']` and loads `Neo.desktop.Container` + `Neo.desktop.AppWindow` theme files (`--desktop-wallpaper` and `--desktop-app-window-*` resolve non-empty in the popup document across configured themes).
- [ ] `resources/css/src/desktop/PopupViewport.css` (and generated CSS map / theme outputs) gives `.neo-viewport.neo-desktop-popup-viewport` the composited desktop window glass-over-wallpaper background, `--container-background-color: transparent`, `color: var(--desktop-app-window-color)`, and a glass-styled `Back to desktop` header bar with `1px solid var(--desktop-app-window-border-color)` bottom divider.
- [ ] Popping out or tearing out `WebDesktop` widgets (`Reports`, `Mail`, `Settings`, etc.) and `examples/desktop/basic` widgets preserves their glass surface, alternating row contrast, border tokens, and theme switching (`neo-dark` ↔ `neo-light`) without falling back to neutral `.neo-viewport` black/white.
- [ ] Unit and E2E specs assert the computed popup surface styles (failing on `dev` where `vpBg` / `bodyWrapBg` / `tbBg` are `rgb(13, 15, 18)` and `--desktop-wallpaper` is empty), and the PR body embeds before/after frames.

## Out of Scope

- Changing `WindowTearOut` drag/dwell geometry or popup lifecycle (`#22114`, `#22185`).
- Portal examples catalog metadata for `webdesktop` (tracked in `#22201`).

## Avoided Traps

- Fixing this only in `resources/css/src/apps/webdesktop/` instead of `src/desktop/PopupViewport.{mjs,css}`, which would leave `examples/desktop/basic` and external `Neo.desktop` consumers unstyled in popups.
- Referencing `var(--desktop-wallpaper)` in `PopupViewport.css` without declaring `'Neo.desktop.Container'` in `PopupViewport`'s `additionalThemeFiles`, which leaves `--desktop-wallpaper` undefined (`""`) in the popup document.
- Forgetting `npm run build-themes -- -n -e dev -t all` so `dist/development/css-map.json` / `resources/data/css-map-*.json` register `Neo.desktop.PopupViewport` (`src` folder) for `Stylesheet#addThemeFiles`.
