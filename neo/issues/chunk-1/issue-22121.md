# Arrow keys stop between demonstration cards and component tiles

Please comment to claim before starting; check current assignees and linked PRs. The reproduction is public and the change is local to the Portal examples gallery.

## Context

On [Forms & Fields](https://neomjs.com/examples/forms), the Demonstrations and Field types sections share one scrolling page. A keyboard user can enter the gallery from the side navigation and move between rows of demonstrations, but cannot arrow into the field types below.

## Reproduction

Verified on the deployed v14 Portal in Chrome at 1440 × 960:

1. Select the body of **Address and payment**, the last demonstration. Press **ArrowDown**. Focus and selection stay there. **ArrowUp** to **Multi-Step Account Form** and **ArrowDown** back work within that section.
2. Click the body of **Checkbox**, the first Field types tile. Both **Checkbox** and **Address and payment** now show a selected ring (`.neo-selected`). Only **Checkbox** has DOM focus.
3. Press **ArrowUp**. Focus stays on **Checkbox**. **ArrowRight** moves to **Chip field**, but the demonstration above still appears selected.

The same sequence reproduces through the sidebar on **Buttons, Menus & Toolbars**. **ArrowDown** on **Grid Server-side Paging** and **ArrowUp** on the first component tile, **Button**, each stay put. Selecting **Button** leaves both rings visible.

## Why it happens

[`GroupPage#createItems()`](https://github.com/neomjs/neo/blob/3f3acb8aea/apps/portal/view/examples/GroupPage.mjs) creates a separate `List` and filtered store per section. Each has its own `ListModel`. [`stepRow()`](https://github.com/neomjs/neo/blob/3f3acb8aea/apps/portal/view/examples/ListModel.mjs) measures only the current list and reselects its current item when it finds no further row. The page already exposes the two lists in reading order through `getLists()`.

Design authority: `ListModel` documents that row navigation keeps “DOM focus and `.neo-selected` on the same card.” The two headings and compact tile layout are deliberate; each section retaining a separate selection makes that relationship ambiguous on the page.

## Expected behavior and acceptance criteria

- [ ] **ArrowDown** from the bottom row of demonstrations enters the first visible tile row. **ArrowUp** from the first tile row returns to the bottom demonstration row. Use the existing visual-row convention to choose a horizontally aligned destination when row widths differ. At the outer edges of the whole gallery, stay put.
- [ ] A keyboard move transfers both focus and selection. Selecting an item body with the pointer in either section clears the previous section’s selection. At most one gallery item shows the selected ring. Native title and launch links retain their existing behavior.
- [ ] The working side-nav Left/Right handoff still returns to the active gallery item. Pages with only demonstrations or only tiles still navigate within their visible section.
- [ ] Add a browser regression to `test/playwright/e2e/portal/ExamplesCatalogNL.spec.mjs`. Exercise both crossings and assert the focused item and selected count across both lists. Cover Forms and a second mixed gallery; include a narrow layout to catch column assumptions.

## Scope

Fix the shared group-page navigation and selection. Keep the two visual sections. Hover styling and the sidebar’s browser-Back behavior are separate concerns.
