# Align examples rail Start here badge and find total with page items

## Context

Operator (`@tobiu`, `2026-11-25`) flagged UX inconsistency on `/examples`: the top navigation row below the search input reads **`All examples · 170`**, whereas `/examples` (`Portal.view.examples.Overview`) renders only **12 curated (`featured: true`) `"Start here"` items**, while every other side-nav row's badge equals the exact count of items rendered on its destination page (`count + crossCount`). Changing `"All examples"` to `12` alone would also mislead. `@neo-opus-ada` and `@neo-gemini-maryam` converged via `/peer-role` (`MESSAGE:5d9a6c87` → `MESSAGE:a481841a` → `MESSAGE:bf39c3d3`) on naming `/examples` by its own `<h2> Start here` heading (**`Start here · 12`**) and moving the live global catalog total into the find placeholder (**`Search 170 examples…  /`**), while keeping **`All 21 groups`** on the phone crumb picker toggle. Curated `good first issue` / `help wanted` labels are omitted because this maintainer-owned convergence item is being delivered immediately.

## The Problem

1. **Destination count mismatch (`GroupIndex.mjs:228-240`):** `All examples` displays `published` (`170` in `dist_prod`, `169` in `devmode`) while navigating to `Overview.mjs`, which shows the `12` featured `"Start here"` cards (`Overview.mjs:176, 199`).
2. **Frozen badge while filtering (`GroupIndex.mjs:239, 269-275`):** When `matchCounts` is active, all 21 group badges switch to their match count (`counts.total`) and dim at `0`, while the top row stays frozen at `170`.
3. **Hidden search reach (`MainContainer.mjs:262`):** `Find examples…  /` does not communicate that typing reaches all `170` published examples beyond the `12` curated `"Start here"` cards.

## The Architectural Reality

- `apps/portal/view/examples/MainContainerController.mjs:288-324` (`publishGroups`) already computes `published` across the selected `catalogMode`, and `applyFindQuery` (`lines 55-106`) computes `matched` and `matchCounts`.
- `apps/portal/view/examples/GroupIndex.mjs` binds `store: 'stores.groups'` and `matchCounts: data => data.matchCounts`; adding `featuredCount` (published `featured: true` count in `catalogMode`) and `featuredMatches` (or `'__featured'` / state-provider `featuredCount` + `featuredMatches`) lets `GroupIndex` render both resting and filtered badges with one single-unit rule (`badge = examples on that destination page`).
- `apps/portal/view/examples/MainContainer.mjs:252-266` creates `sidebar-find` and `mobile-find`, and `syncNavigation` (`line 689`) sets the phone crumb dropdown toggle to `All ${total} groups` at rest on `/examples` (which opens `group-sheet`, where `Start here · 12` sits as the first destination link).
- **Same-turn reconciliation (`#22096`):** Supersedes `#22096`'s prescription (`All examples · 170` on the rail row) while preserving `#22096`'s intent — immediate top-of-sidebar and mobile-crumb visibility of the live build's distinct catalog total — inside `Search ${published.length} examples…  /` (alongside `Overview.mjs:270`'s `170 live examples in 21 groups` and `GroupIndex.mjs:252`'s `170 examples in all. Some appear in more than one group.`).

Design authority: Operator `@tobiu` (`2026-11-25` consistency directive) + cross-family `/peer-role` convergence between `@neo-opus-ada` and `@neo-gemini-maryam` (`MESSAGE:bf39c3d3`).

## The Fix

1. **`apps/portal/view/examples/MainContainerController.mjs` & `MainContainer.mjs`:**
   - Track `featuredCount` (`published.filter(r => r.featured).length`) and `publishedCount` (`published.length`) in the state provider during `publishGroups()`, updating `sidebar-find` and `mobile-find` `placeholderText` to ``published.length ? `Search ${published.length} examples…  /` : 'Search examples…  /'`` (preserving `aria-label: 'Find examples'`).
   - During `applyFindQuery()`, include `featuredMatches` (`matched.filter(r => r.featured).length`, cleared to `null` in `clearFind()` / empty query).
   - Update fallback text in `MainContainer.mjs:338, 689` (`Start here` before group load; `All ${total} groups` once loaded).
2. **`apps/portal/view/examples/GroupIndex.mjs`:**
   - Bind `featuredCount` and `featuredMatches` from the state provider.
   - Render the top `/examples` link (`#__all`) as **`Start here`** with badge `String(me.matchCounts ? me.featuredMatches : me.featuredCount)`, `aria-label` following `ExampleGroup.countLabel` grammar (`"Start here, 12 live examples"` at rest; `"Start here, 1 matching example"` / `"Start here, N matching examples"` while filtering), and `.portal-examples-group-index-zero` dimming when filtering yields `0` featured matches.
   - Retain `${published} examples in all. Some appear in more than one group.` in `.portal-examples-group-index-note`.
3. **Unit & E2E Tests (`MainContainerController.spec.mjs` + `ExamplesCatalogNL.spec.mjs`):**
   - Assert `Start here` resting/filtered counts and `Search ${published} examples…  /` build-mode switching (`170` → `169` in `devmode`).
   - Rename `allLink` → `startLink` (`/^Start here\b/`) and update `#22096` / `#22061` E2E expectations.

## Acceptance Criteria

- [ ] **AC-1:** On desktop (`list`) and phone (`sheet`), `GroupIndex`'s `/examples` row displays **`Start here`** with the live published featured count (`12`) and accessible name **`Start here, 12 live examples`**, while `.portal-examples-group-index-note` continues to state `${published} examples in all. Some appear in more than one group.`
- [ ] **AC-2:** While a find query is active, `Start here`'s badge switches to the count of matching published featured examples (`featuredMatches`), updates its `aria-label` to `Start here, N matching example(s)`, and applies `.portal-examples-group-index-zero` when `0`.
- [ ] **AC-3:** Both `sidebar-find` and `mobile-find` display `Search ${published} examples…  /` (`170` in `dist_prod`, `169` in `devmode`, preserving `aria-label="Find examples"`), and the phone crumb button on `/examples` continues to read `All 21 groups`.
- [ ] **AC-4:** `MainContainerController.spec.mjs` and `ExamplesCatalogNL.spec.mjs` pass, accompanied by before/after desktop rail (rest and filtering) and `390 × 844` phone crumb/sheet frames.

## Out of Scope

- Adding a flat 170-card browse page (an empty/broad search already groups matches across the catalog).
- Changing featured item membership (`12` curated items).

## Avoided Traps

- **`"All groups · 21"` on the desktop rail:** `Overview.css:89-96` hides `.portal-examples-overview-mobile-index` above `640px`, so desktop `/examples` renders `0` group entries (`12` `"Start here"` cards), and mixing `21` (groups) with `23` (examples) breaks column unit consistency (`MESSAGE:a481841a` / `MESSAGE:bf39c3d3`).
- **`"All examples · 12"`:** Misstates total catalog scale.
