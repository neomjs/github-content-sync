# The Calendar examples get their overview

## Context

The 13.5 gate asks that a stranger finds each component family's examples as an overview in which every example names what it proves (`ROADMAP.md`). `/examples/grid` is the pattern: 21 captioned Grid and Table demonstrations (#20500). The steward's map on #20498 ([comment](https://github.com/neomjs/neo/issues/20498#issuecomment-6757406109)) lists the families; this leaf delivers Calendar at `/examples/calendar`. It is the smallest family and a good first one.

## The Problem

The calendar is 28 classes under `src/calendar/` with day, week, month and year views, live settings, drag and drop with snapping, and an event editor. The Portal shows one card named "Calendar" without a word about any of it, and `examples/calendar/weekview` has no card at all.

## The Architectural Reality

- One record per example in `apps/portal/resources/data/examples.json`; the record's shape is documented on `apps/portal/model/Example.mjs:16-27`. The 21 records with `"family": "grid-table"` are the reference for the length and tone of a caption.
- A family's tab appears with its first record (#20690), and a unit spec fails on a family record without `feature` or `lookFor`.
- Inventory at `62f75736ba`: `examples/calendar/basic` (the existing record `calendar`) and `examples/calendar/weekview`.
- What the views can do is in the source, with the configs to quote: `src/calendar/view/week/TimeAxisComponent.mjs` (row height, interval, start and end time), `src/calendar/view/week/EventDragZone.mjs` (snapping), `src/calendar/view/settings/`, `src/calendar/view/EditEventContainer.mjs`.
- Design authority: n/a — adds catalog records, calls no existing behavior wrong.

## The Fix

Run both demonstrations (`npm run server-start`, then each `index.html`) and write their captions from what they do. The record `calendar` gets `"family": "calendar"`, `component`, `feature` and `lookFor` in place; `calendar/weekview` gets a new record directly after it (a stable string `id`, `name`, the family, `component`, `feature`, `lookFor`, the four `urls`, `sourceUrl`, `image: null` unless a cover exists). If one caption cannot carry what the full calendar proves, the `lookFor` names the one gesture a visitor should try first.

## Acceptance Criteria

- [ ] `calendar` and a record for `calendar/weekview` carry the family, `feature` and `lookFor`; a demonstration that cannot say what it proves stays out, with the reason in the pull request.
- [ ] Each `feature` and `lookFor` was checked in the running example; the pull request names the build and the browser. A caption states no number the example does not show and names no commercial feature.
- [ ] Every URL of a record answers 200 on neomjs.com, where the examples are deployed in all four builds, or that build is omitted on the record.
- [ ] `npm run test-unit -- test/playwright/unit/apps/portal/view/examples` passes with the new counts.
- [ ] The pull request shows `/examples/calendar` at 1440×900 from a real browser.

## Out of Scope

New calendar examples or features; covers (the typographic fallback is allowed, #20679 is the pattern for real ones); an engine fix for an example that turns out broken: file it and leave the example out.

## Avoided Traps

- A caption taken from the folder name ("basic"): the first calendar example is the full calendar, and its caption says so.
- Moving the record `calendar`: the showcase order is delivered intent (#19640).
