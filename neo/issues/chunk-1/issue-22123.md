# Remove the header wave’s per-sample geometry allocation

Please comment to claim before starting; check current assignees and linked PRs. The hot path is isolated and can be verified without a production deployment.

## Context

In the v14 Portal, `Header.calculateStrandGeometry()` samples the foreground wave every two CSS pixels. Its single call site immediately destructures the object returned by `getStreamOffset()`. At a width of 1,992 pixels that is 996 short-lived geometry results per animated frame. [Released source](https://github.com/neomjs/neo/blob/14.0.0/src/canvas/Header.mjs#L326-L358)

## Measurement

Profiled the real `canvasworker.js` SharedWorker in an isolated Chrome 157 on the locally served production build, 1,992 × 58 header, eight navigation bounds, pointer at rest. In two 15-second header-only windows, V8 allocation sampling including collected objects estimated 45.8 and 42.9 MiB. `getStreamOffset` accounted for 89% of the combined estimated bytes. The wave buffers were reused and no header resource resize occurred during those windows. The allocation predates the new active-link helix.

A second run recorded GC trace events without the heap sampler. Against the released method, five 15-second windows produced 315 minor GCs in 4,404 draws. A disposable same-browser control reused one result object and produced 11 in 2,640 draws across three windows. That is 71.5 versus 4.2 minor GCs per 1,000 draws. Reverting the control brought the churn back. All three returned numbers matched across 2,988 sample positions/pointer configurations. The measured GC durations were short; these observations do not establish the cause of a browser freeze.

## The fix

Make the geometry loop reuse storage for the three per-sample values. Preserve the existing method contract for callers that retain a result, or show that the chosen internal path preserves that behavior. Keep the existing visual geometry and navigation interaction. The owning source already states the intent to avoid render-loop garbage.

## Acceptance criteria

- [ ] The animated strand loop creates no new result object per x sample. A fixed-input control covers empty space, text links, icon zones and pointer proximity, including all three returned values.
- [ ] On comparable width and frame counts, report before/after worker allocations and normalized minor-GC counts. A paused or reduced-motion control distinguishes the renderer from background work.
- [ ] The released shape and interaction of the idle, active and hovered waves remain intact.
