# createVnodeTree mounts children before applyDeltas in two-thread mode

Curated contributor labels (`good first issue`, `help wanted`) omitted: active blocker of in-flight #22209 / PR #22215 under Epic #22196, self-assigned for immediate fix.

## Context

Found by #22209's ADR 0043 §2.4 `(a)` full-matrix CI run on PR #22215 ([run `45685928075`](https://github.com/neomjs/neo/actions/runs/45685928075)): flipping `DefaultConfig.useVdomWorker` to `false` turned `unit` green (`8,828` passed) while failing `53` browser assertions across `components (1..3/3)` and `10/18` `e2e-engine` shards (including the previously unread `AnchorCorrection` / `ContentSizedRowsExample` failure noted in `#20780` Out of Scope).

## The Problem

1. **`VdomLifecycle#createVnodeTree` adopts vnodes and mounts every descendant component *before* `Neo.applyDeltas` inserts the root into the DOM:**
   - In `src/mixin/VdomLifecycle.mjs:185-202`, `afterCreate?.(data)` (`onInitVnode(vnode, false)`) runs *before* `await Neo.applyDeltas(windowId, deltas)`.
   - Inside `onInitVnode` (`line 1154`), `me.vnode = vnode` triggers `afterSetVnode` → `syncVnodeTree()` (`deltas = null`). Because `syncVnodeTree` (`line 1345`, from `#19970`) computes `mountsChildren = me.mounted || !deltas`, `!deltas === true` sets `component.mounted = true` on **every descendant component** before `Neo.applyDeltas` has sent `insertNode` to Main.
   - Every descendant `afterSetMounted(true, false)` hook (`List` → `Navigator.subscribe`, `Grid`/`List.plugin.Animate` → `ResizeObserver.register`, `MonacoEditor.createInstance`, `FormContainer` `'mounted'` → `DomAccess.getChildNodeIds`) executes while `document.getElementById(id)` on Main is still `null`, silently dropping subscriptions and geometry measurements (`ComboBox`, `Chip`, `FloatingMountFlight`, `AnimateSort`, `LayoutTiles`, `HeaderMenuShape`, `AnchorCorrection`, `PremeasureRowsNL`, `CascadeNL`, `IssuesShowcase`, `ExamplesCatalogKeysNL`).
   - Passing `false` to `onInitVnode(vnode, useVdomWorker ? autoMount : false)` (`line 963`) also skips `app.mounted = true; app.fire('mounted')` (`lines 1174-1177`) in two-thread mode, and leaves adopted `_vnode` trees behind if `Neo.applyDeltas` rejects mid-flight — violating ADR 0043 §2.3 Invariant I2.
2. **`App#onRegisterNeoConfig` fires an unawaited `import('../vdom/Helper.mjs')` (`src/worker/App.mjs:867`):** Can race fast `onLoadApplication` or `createNeoInstance` calls when `useVdomWorker: false`.
3. **`VesselClosesMidFirstRenderNL.spec.mjs:45` only intercepts VDom-worker `reply` frames:** Holds `event.data?.action === 'reply' && event.data.data?.autoMount`, missing two-thread `action === 'updateVdom'` `insertNode` frames.

## The Architectural Reality

- `Design authority:` `"I2. The vnode never runs ahead of the DOM. Adoption waits for Main's acknowledgement, and a failed write leaves the old vnode in place."` — `learn/agentos/decisions/0043-vdom-diff-placement.md` §2.3 (graduated after `#20780` / `#22159`, superseding `#20780`'s pre-ADR `afterCreate`-before-insert Contract Ledger clause on `createVnodeTree`).
- With `useVdomWorker: true`, the VDom worker's `autoMount` reply passes through Main (`Manager#onWorkerMessage` → `DeltaUpdates#insertNode`) *before* reaching the App worker, so `onInitVnode(vnode, true)` always runs after all DOM nodes exist on Main. Running `afterCreate` after `await Neo.applyDeltas(windowId, deltas)` in `createVnodeTree` gives both arms identical lifecycle ordering and restores `app.fire('mounted')`.

## The Fix

1. **`src/mixin/VdomLifecycle.mjs` (`createVnodeTree` & `initVnode`):**
   - In `createVnodeTree(config, afterCreate)` (`lines 185-204`), execute `if (createOpts.autoMount && !Neo.config.useVdomWorker) { ... await Neo.applyDeltas(windowId, deltas) }` *before* `afterCreate?.(data)`.
   - In `initVnode(mount)` (`lines 962-968`), pass `autoMount` directly (`me.onInitVnode(vnode, autoMount)`) and delete the redundant `if (autoMount && !useVdomWorker) { me.mounted = true }` block.
2. **`src/worker/App.mjs` (`onRegisterNeoConfig`, `onLoadApplication`, `createNeoInstance`):** Store `me.vdomHelperPromise = !config.useVdomWorker ? import('../vdom/Helper.mjs') : null` and await it before booting an app or creating a dynamic test instance when `!Neo.config.useVdomWorker`.
3. **`test/playwright/e2e/workstation/VesselClosesMidFirstRenderNL.spec.mjs`:** Hold the vessel's initial mount message in both arms (`action === 'reply' && data?.autoMount` or `action === 'updateVdom' && deltas?.[0]?.action === 'insertNode'`).
4. **Unit coverage (`test/playwright/unit/vdom/TwoThreadPipeline.spec.mjs` & `test/playwright/unit/component/MountFlight.spec.mjs`):** Add a unit test (failing on `dev`) proving that during `initVnode(true)` under `useVdomWorker: false`, `me.vnode`, `me.mounted`, `child.mounted`, and `app.mounted` all remain unset while `Neo.applyDeltas` is pending, settle together after `Neo.applyDeltas` resolves, and remain unset if `Neo.applyDeltas` rejects; update `MountFlight.spec.mjs:144` to reflect I2 (`isVnodeInitializing === true` during the pending `insertNode` flight).

## Decision Record impact

`aligned-with` `adr:0043-vdom-diff-placement` — enforces §2.3 Invariant I2 on the `createVnodeTree` / `initVnode` initial-mount path so Phase 1 observable `(a)` (#22209) can pass.

## Acceptance Criteria

- [ ] Under `useVdomWorker: false`, `initVnode(true)` awaits `Neo.applyDeltas` before adopting `me.vnode`, mounting descendant components, setting `me.mounted = true`, or firing `app.fire('mounted')`; if `Neo.applyDeltas` rejects, `me.vnode` and `child.mounted` remain unset (`test/playwright/unit/vdom/TwoThreadPipeline.spec.mjs`).
- [ ] `App#onRegisterNeoConfig` stores the `import('../vdom/Helper.mjs')` promise when `!config.useVdomWorker` and awaits it before `onLoadApplication` and `createNeoInstance` execute.
- [ ] `VesselClosesMidFirstRenderNL.spec.mjs` holds the vessel's initial render in both `useVdomWorker: true` and `useVdomWorker: false` arms.
- [ ] `FloatingMountFlight.spec.mjs`, `ComboBox.spec.mjs`, `AnimateSort.spec.mjs`, and `LayoutTiles.spec.mjs` pass locally when `useVdomWorker` is `false`, and the full unit + CI suites pass on `dev` (`useVdomWorker: true`).

## Avoided Traps

- **Folding engine edits into #22209 / PR #22215:** `#22209` is scoped strictly to `"the flip and nothing else"`; keeping this ADR 0043 I2 defect in its own narrow `bug` leaf preserves clean bisectability and review scope, matching `#22212`.
- **Changing `syncVnodeTree` `mountsChildren = me.mounted || !deltas` (`line 1345`):** `onInitVnode` sets `me.vnode = vnode` (`line 1154`) before `me.mounted = true` (`line 1172`), and unit tests rely on `await instance.initVnode()` syncing child vnodes; ordering `afterCreate` after `Neo.applyDeltas` fixes root and descendant mount timing without breaking `onInitVnode` or unit-mode initialization.
