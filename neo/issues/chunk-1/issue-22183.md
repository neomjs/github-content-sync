# Workstation tab-drag CI can read an extra tab after settle

## Context

Hosted `WorkstationTabDragHeadersStayNL.spec.mjs` failed after an in-window drag on the exact `b3b79b0` synthetic merge of Workstation PR #22178. Focus and the settle poll had passed. The final DOM comparison at line 489 expected tab IDs `[4, 6]` and read `[4, 5, 6]`. An earlier run of the same merge passed this exact test.

- [Failed assertion](https://github.com/neomjs/neo/actions/runs/45573226010/job/139064900149)
- [Earlier pass on the same merge](https://github.com/neomjs/neo/actions/runs/45534935329/job/138939215182)
- [Current dev `844ed560f0` control, 16/16](https://github.com/neomjs/neo/actions/runs/45576659960/job/139076245549)
- [Same base plus candidate `c208b67079`, 16/16](https://github.com/neomjs/neo/actions/runs/45576659967/job/139076245224)

## The Problem

The final assertion can fail after the poll observes two stable DOM frames and the overflow drain. A historical trace recorded the same visible IDs after the same gesture, but the focus/settle predicate itself failed in that run. The newer failure reached a later assertion. #20020 previously repaired an assertion that read the strip during the drain. The current samples neither reproduced the discrepancy nor establish its cause. [Historical trace](https://github.com/neomjs/neo/issues/20022#issuecomment-6365360273)

## The Architectural Reality

[The spec](https://github.com/neomjs/neo/blob/c208b670790a18df93066f6e6dffa5c31a281d71/test/playwright/e2e/workstation/WorkstationTabDragHeadersStayNL.spec.mjs#L239-L491) polls Main DOM geometry plus App Worker overflow state, then reads both surfaces again to compare against `Overflow.computeOverflow`. The final DOM sample and some App Worker reads can occur at different times. A sampling mismatch and a real change after settlement both fit the available log.

## The Fix

Capture the successful settle sample and the values used at the final comparison. Record frame times, focused tab, measured extent, rendered IDs, `appliedHiddenIds`, and in-flight or queued projection state from both observations. Compare a hosted failing trace to a green run of the same tree. Fix the layer the trace identifies and preserve the focused-partition, geometry, and consistency checks.

## Acceptance Criteria

- [ ] Retain a failing hosted or controlled trace that distinguishes a mixed sample from a real post-settle projection.
- [ ] Verify the corresponding correction with the normal and loaded-Main cases on the same base. Preserve the checks for focus ownership, the visible partition, and VDOM/DOM/items consistency.
