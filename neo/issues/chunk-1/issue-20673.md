# grid.columns.get() misses a column whose dataField changed at runtime

## Context

A grid column's `dataField` can change at runtime. `Neo.grid.column.Base` documents it (`src/grid/column/Base.mjs:50-54`):

> **Runtime Updates:** You can change this config at runtime to point the column to a different model field. The Grid will automatically: 1. Update the internal `columnPositions` map (preserving sort order). 2. Refresh the visible rows to display the new data.

`#9151` built this. It re-keys `body.columnPositions`, because that collection is keyed by `dataField`. The grid's own `columns` collection is keyed by `dataField` too (`src/grid/Container.mjs:1077`), and nothing re-keys it.

## The Problem

After a column is pointed at another field, the grid no longer finds it by its `dataField`:

```js
// a grid with one column {dataField: 'first'}, on a store whose model has both fields
grid.centerColumns[0].dataField = 'second';

grid.columns.get('second'); // nothing. Expected: the column
grid.columns.get('first');  // the column. Expected: nothing
```

Measured on `dev` at c24fd4c228, in a unit spec built like `test/playwright/unit/grid/DynamicColumn.spec.mjs`.

`columns.get(<dataField>)` is how the grid looks a column up. Eleven call sites in `src/grid` do it:

- `View.mjs:830`, the columns measured for content-sized rows;
- `Body.mjs:1079` and `:1170`;
- `Row.mjs:523` and `:607`, as the fallback after an index match;
- `header/GroupRow.mjs:146`;
- `plugin/CellEditing.mjs:219`, `:365`, `:402`, `:651` and `:720`.

Each of them gets no column for a column that was pointed at another field. The failed lookup is the measured part. Which call sites turn it into a visible defect has not been measured.

## The Architectural Reality

- `afterSetDataField()` (`src/grid/column/Base.mjs:150-176`) handles the change. For `body.columnPositions` it deletes the old key from the collection's map, updates the item and sets the new key (`:159-167`). It then updates the header button's `dataField` (`:169-171`). It does not touch `gridContainer.columns`.
- `Neo.collection.Base` indexes its items by `keyProperty` in a `Map`. A search of `src/collection/Base.mjs` for `updateKey`, `rekey` and `changeKey` finds no method that re-keys an item in place.

Design authority: the JSDoc quoted in Context makes a runtime `dataField` change supported behavior.

## The Fix

In `afterSetDataField()`, re-key the column in `gridContainer.columns` the way `columnPositions` is re-keyed a few lines below: drop the old key from the collection's map and set the new key for the same column instance. The order of `columns.items` must not change.

## Acceptance Criteria

- [ ] After a runtime `dataField` change, `grid.columns.get(newDataField)` returns the column and `grid.columns.get(oldDataField)` no longer does (unit, in `test/playwright/unit/grid/DynamicColumn.spec.mjs`).
- [ ] `grid.columns.items` keeps its order and its count across the change (unit).
- [ ] The new test fails on `dev` without the fix.
- [ ] The existing tests in `DynamicColumn.spec.mjs` pass.

Run them with `npm run test-unit -- test/playwright/unit/grid/DynamicColumn.spec.mjs`.

## Out of Scope

- Changing any of the eleven call sites.
- `Neo.grid.Container#getCellValues()` (`#20672`), which looks columns up in the region arrays and does not depend on this fix.
- A general re-key method on `Neo.collection.Base`.
