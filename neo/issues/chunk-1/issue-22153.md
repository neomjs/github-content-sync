# Board column drag drops fast/repeated gestures and moves vertically

## Context

While inspecting the Portal home view's third snap page (`apps/portal/view/home/parts/Planning.mjs`, "Gantt & Task Board") on 24 Nov 2026, the operator reported three board column-drag defects:
1. Roughly 30% of attempts to drag the first column (`To do`) fail to drag or reorder.
2. When a column drag engages, the dragged column proxy is not locked horizontally — it moves up and down inside `.neo-board`'s top and bottom padding gaps (`±8px`, `16px` vertical travel).
3. Neighboring columns jump instantly instead of sliding horizontally like grid columns (already tracked in `#22144` / open PR `#22147` and kept out of scope here to avoid collision).

## The Problem

Live Playwright instrumentation on `/apps/portal/index.html#/home` (`Planning` section, `1512×945` and `1440×900`) reproduced four concrete runtime defects across `ColumnSortZone`, `SortZone`, `DragDrop`, and `Pointer`:

1. **Vertical travel inside board padding (`ColumnSortZone`):** `.neo-board` applies `padding: var(--neo-board-padding)` (`8px` in `Planning.css`). Because `ColumnSortZone` omits `moveVertical: false`, `DragDrop#onDragMove` clamps `top` to `boundaryContainerRect` (`499..924`) rather than locking the column to its row (`507`), letting diagonal pointer motion shift the column proxy vertically (`proxyY: 499..515`).
2. **Pre-delay pointer travel lost when `Pointer#pointerDownTimeout` arms the drag (`Pointer.mjs`):** `Pointer` uses `delay: 100` ms and `minDistance: 5` px. When a user presses a column header (`x = 623`), sweeps into the adjacent column (`x = 880`) within the first `100ms`, and pauses before releasing, `pointerDownTimeout` calls `onDistanceChange(..., true)` → `startDrag()`, which emits `drag:start` at `startEvent`'s stale coordinates (`x = 623`) and never emits `drag:move` for `this.point` (`x = 880`). Releasing without further movement produces zero column reorder (`moved: false`).
3. **Stale proxy placement across async worker drag setup (`DragDrop.mjs`):** `ColumnSortZone#onDragStart` spans three async worker round-trips (`owner.getDomRect` → `DragDrop.setConfigs` → `createDragProxy` → `DragProxyComponent#afterSetMounted` → `DragDrop.setDragProxyElement`). `DragDrop#onDragMove` only updates `this.clientX`/`this.clientY` when `scrollContainerElement` is set, and `setDragProxyElement` attaches `.neo-dragproxy` without syncing `left`/`top` to the latest pointer coordinates — leaving `.neo-dragproxy` visually frozen at the starting slot (`left: 562px`) even when `pointermove` already carried the cursor to `x = 931px`.
4. **Post-drop `dragQueue` clobber and `dragStartPending` drop (`ColumnSortZone` + `SortZone`):** `SortZone#processDragEnd` holds `dragQueue` across `timeout(10)` + `timeout(30)` without clearing `dragComponent`, so `ColumnSortZone#onDragEnd` sets `this.dragComponent = null` *after* `await super.onDragEnd(data)` (outside `dragQueue`). Starting another column drag within that window queues `onDragStart`, which sets `this.dragComponent = draggedItem` when `processDragEnd` yields `dragQueue`, and the resuming `ColumnSortZone#onDragEnd` microtask immediately overwrites `this.dragComponent = null`, killing the new drag (`moved: false`). While `dragStartPending` is `true`, `ColumnSortZone#onDragMove` also rejects incoming moves before `SortZone#onDragMove` can record `pendingDragMove`. In addition, `Pointer#startDrag` dispatches `drag:start` on `.neo-board-column-header` (`currentElement`), so `SortZone#onDragStart` checking only `data.path[0]` misses `data.targetPath[0]` (`button.neo-board-column-collapse`), allowing drags initiated on the collapse button to drag the column.

## The Architectural Reality

- `src/board/ColumnSortZone.mjs:17-64` configures `sortDirection: 'horizontal'`, `dragHandleSelector: '.neo-board-column-header'`, and `ignoreDragSelector: '.neo-board-column-collapse'`, whereas `src/draggable/grid/header/toolbar/SortZone.mjs:66` sets `moveVertical: false`.
- `src/board/ColumnSortZone.mjs:222-241` overrides `onDragEnd` and `onDragMove` while `test/playwright/unit/board/ColumnSortZone.spec.mjs:391-394` enforces that `ColumnSortZone.prototype` delegates `onDragStart` and `processDragEnd` directly to `Neo.draggable.container.SortZone`.
- `src/draggable/container/SortZone.mjs:774-790` resets gesture state inside `processDragEnd` (serialized on `dragQueue`) and `src/draggable/container/SortZone.mjs:985-990` checks `ignoreDragSelector` against `data.path[0]`.
- `src/main/draggable/sensor/Pointer.mjs:280-303,372-374,461-485` owns delayed threshold arming; `test/playwright/unit/main/draggable/sensor/Pointer.spec.mjs:465-491,568-604` pins immediate (`delayElapsed === false`) `pointermove` arming to emit `drag:start` alone.
- `src/main/addon/DragDrop.mjs:467-603,965-967` owns main-thread proxy movement while `this.clientX`/`this.clientY` serve as `scrollContainer`'s delta baseline (`:718-726`).
- Design authority: the operator, 24 Nov 2026: "30% of the time, trying to drag the first column does not work. second defect: if dragging works, it is not limited to horizontal only. there are gaps at the top and bottom, and the current implementation allows to move upwards or downwards inside the parent container. this makes no sense." — aligned with `src/draggable/grid/header/toolbar/SortZone.mjs:66` (`moveVertical: false`) and `src/board/ColumnSortZone.mjs:6` ("Reorders unlocked board columns horizontally by dragging their header").

Decision Record impact: none.

## The Fix

1. **`src/board/ColumnSortZone.mjs`:**
   - Add `moveVertical: false` to `static config`.
   - In `onDragEnd`, guard `if ((!this.dragComponent && !this.dragStarting) || this.dragEndActive) return` and delegate to `await super.onDragEnd(data)` without mutating `this.dragComponent` outside `dragQueue`.
   - In `onDragMove`, allow moves while `this.dragStartPending` is `true` (`if ((!this.dragComponent && !this.dragStartPending) || !this.isResortable()) return`) so `SortZone#onDragMove` buffers `pendingDragMove`.
2. **`src/draggable/container/SortZone.mjs`:**
   - Reset `dragComponent: null` inside `processDragEnd`'s `dragQueue`-serialized cleanup (`:774`, verified safe across all `SortZone` subclasses).
   - Check `(data.targetPath?.[0] || data.path[0])?.cls?.includes(ignoreClassName)` (and `data.path[0]`) for `ignoreDragSelector` so `Pointer` gestures starting on `.neo-board-column-collapse` inside `.neo-board-column-header` are rejected.
3. **`src/main/draggable/sensor/Pointer.mjs`:**
   - Track the latest pre-threshold `PointerEvent` (`lastMoveEvent`, cleared in `endGesture`) and, when `delayElapsed === true` arms `startDrag()` after the pointer already moved away from `start` (`point.clientX !== start.clientX || point.clientY !== start.clientY`), immediately emit `triggerStream('drag:move', lastMoveEvent || startEvent, point)` so pre-delay pointer travel is applied without disturbing `delayElapsed === false` stream contracts.
4. **`src/main/addon/DragDrop.mjs`:**
   - Track the latest gesture pointer coordinates (`lastClientX` / `lastClientY`, separate from `scrollContainer`'s `clientX` / `clientY` delta state) across `onDragStart`, `onDragMove`, and `resetDragState`, and apply clamped horizontal/vertical proxy placement inside `setDragProxyElement` when a proxy mounts mid-gesture.

## Acceptance Criteria

- [ ] Dragging a board column diagonally keeps `.neo-dragproxy`'s `top` locked to the column's slot `y` (`moveVertical: false`), with zero vertical movement into `.neo-board` top/bottom padding.
- [ ] Sweeping a board column header into a neighboring column within `Pointer`'s `100ms` arming delay and holding still before release reorders the column and places `.neo-dragproxy` at the live pointer `x` rather than stranding it at the start slot.
- [ ] Back-to-back column drags initiated within `SortZone#processDragEnd`'s post-drop window (`~40ms`) do not clobber `dragComponent` or drop `pendingDragMove`, and dragging `.neo-board-column-collapse` in a live browser never starts a column drag.
- [ ] Unit tests (`ColumnSortZone.spec.mjs`, `Pointer.spec.mjs`, `DragDrop.spec.mjs`) and Playwright E2E coverage (`BoardColumns.spec.mjs` / `BasicNL.spec.mjs`) verify all behaviors with zero regressions.

## Out of Scope

- Neighboring column CSS slide transition during column drag (already owned by `#22144` / open PR `#22147`).
- Live-proxy single-frame end restoration (`#20871`).
- Changing `Pointer`'s global `delay: 100` double-click jitter guard across all draggable surfaces.

## Avoided Traps

- **Overriding `processDragEnd` on `ColumnSortZone`:** breaks the delegation invariant pinned by `ColumnSortZone.spec.mjs:391-394`; `SortZone#processDragEnd` itself owns resetting `dragComponent` inside `dragQueue`.
- **Mutating `DragDrop#clientX` / `clientY` unconditionally in `onDragMove`:** `DragDrop#scrollContainer` computes `deltaX = data.clientX - me.clientX` from those fields; use dedicated latest-pointer fields for initial proxy placement.
- **Emitting `drag:move` inside `Pointer#startDrag` on `delayElapsed === false`:** breaks the immediate-arm `drag:start`-only contract pinned by `Pointer.spec.mjs:465-491,568-604`.
