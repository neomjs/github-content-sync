# NativeLifecycle#retire strands retired vessels under readmit hold

## Context

Surfaced on 2026-11-11 while running the full golden capture battery (`npm run test-goldens`) for `neomjs/neo-agent-institution#911`: `test/playwright/e2e/agentos/FleetCockpitDrillRoundTripNL.spec.mjs:285` (`join 3: reattach`, clicking `.fm-detail-window-toggle` → `VesselContainer#returnPane('detail')` → `nativeWindows.retire(...)`) deterministically times out after `30,000 ms` waiting for `.fm-agent-detail` to return to the main window, even though the popup window physically closes.

- Live latest-open sweep: checked latest 20 open issues (`#20768`..`#20693`, `sort: 'created'`) at `2026-11-11T10:21:20Z`; no equivalent found.
- A2A in-flight claim sweep: checked latest 30 messages across all read states (`status: 'all'`) up to `2026-11-11T10:18:01Z`; no overlapping `[lane-claim]` or `[lane-intent]`.
- Semantic & local sweep: `ask_knowledge_base` (`NativeLifecycle retire readmit holdReleasedVessel tear-out returnPane`) and `git grep` on `resources/content/issues/` + `resources/content/discussions/` returned no open or archived equivalent.

## The Problem

Commit `d47905526b` (`#20144` / PR `#20145`, Oct 26) introduced the `readmit: true` hold path in `Neo.manager.transaction.NativeLifecycle#releaseSource` (`src/manager/transaction/NativeLifecycle.mjs:456-463`) and `Neo.dashboard.dock.window.NativeVesselTransaction.holdReleasedVessel` (`src/dashboard/dock/window/NativeVesselTransaction.mjs:136-154`) so a reloading tear-out window keeps its pane while detaching the live component from the departed window's tree before App-worker disconnect cleanup (`59037f202a`).

When a host **explicitly retires** a bound tear-out vessel via `nativeWindows.retire(sourceId, vessel)` (such as `Workspace#retireTearOutVessel` / `VesselContainer#returnPane`), three arrival orders between `retire()`'s `await retirement.close(vessel)` and the window's `disconnect` (`onRelease` → `releaseSource`) fail to hand the committed item back to `effects.released`:

1. **`disconnect` arrives while `await retirement.close(vessel)` is in flight (dominant browser order):**
   `releaseSource` (`NativeLifecycle.mjs:430-465`) runs `source.effects.unbind(data)` (`holdReleasedVessel`, which detaches `pane` synchronously and returns `{retained: true, awaitingClosure: true, readmit: true, closed}`), matches and deletes `retirement` from `source.retirements` (`retirement.released = true` at lines `445-452`), yet line `456` **still** enters `if (owned && retained && result?.readmit === true)` and stores a `held` record (`readmit: true`, matching `generationToken`) in `source.admissions`. When `await retirement.close(vessel)` resolves `true` on the next turn in `retire()`, line `323` (`matches(source.admissions.get(workspaceKey)) && source.admissions.delete(workspaceKey)`) deletes `held` directly from `source.admissions` without calling `releaseHeld` / `effects.released`, permanently stranding `source.owners.get(workspaceKey)` (`{...entry, windowId: null}`) even past `reconnectLeaseMs`.
2. **`retirement.close(vessel)` resolves `true` before `disconnect` arrives:**
   Both `Neo.Main#windowClose` (`src/Main.mjs:1070`) and `Neo.Main#windowNativeClose` (`src/Main.mjs:1168`) delete `this.openWindows[windowName]` once the popup closes, so `Neo.Main#windowNativeIsClosed` resolves `null` rather than `true`. Because `retire()` already deleted `source.retirements` at line `320`, `releaseSource` sees no active retirement record, enters `readmit: true` hold with `closed` resolving `null`, and stalls pane reintegration for the full `20,000 ms` `reconnectLeaseMs`.
3. **`retire()` resolves `true` after `disconnect` already placed a `readmit: true` hold in `source.admissions`:**
   Line `323` deletes `source.admissions` directly instead of calling `releaseHeld`, stranding the held item without firing `effects.released`.

The regression stayed masked on Linux CI because `playwright.config.e2e.mjs` skips `toHaveScreenshot` specs under `CI`, and `WorkstationHeaderStatePopOutNL.spec.mjs` asserted `popup.isClosed() === true` without asserting host pane reintegration.

## The Architectural Reality

- `Neo.manager.transaction.NativeLifecycle` (`src/manager/transaction/NativeLifecycle.mjs`) owns generation-scoped retirement (`retire`, lines `309-326`), disconnect release (`releaseSource`, lines `429-465`), and held-lineage release (`releaseHeld`, lines `477-485`).
- `source.effects.unbind(data)` (`NativeVesselTransaction.holdReleasedVessel`) **must still run synchronously** on disconnect even during retirement so `pane.parent?.remove(pane, false, true)` detaches the held pane before the App worker destroys the departed window's component tree.
- What must NOT happen for an explicitly retired generation is entering (or silently dropping) the `readmit: true` hold: once platform retirement and window disconnect have both occurred for that `generationToken`, the committed item must pass directly to `source.effects.released` (`awaitingClosure = false`), while preserving non-`readmit` retention semantics (`unbind: () => false` or `{retained: true}` without `readmit: true`) and unowned `readmit` disconnect behavior (`#20773`).

## The Fix

In `src/manager/transaction/NativeLifecycle.mjs`:

1. **`retire(sourceId, vessel, close)`:**
   - If `!retirement.released` when `close` resolves `true` and `source.owners.get(workspaceKey)` matches `vessel`'s generation/window, stamp `retired = true` on that owner record so the subsequent `releaseSource` knows this generation was explicitly retired even after `source.retirements` is cleaned up.
   - If `source.admissions.get(workspaceKey)` matches `vessel`, call `await this.releaseHeld(sourceId, workspaceKey, admission.releaseData, admission)` when `admission.readmit` is `true` instead of silently deleting the admission; keep `source.admissions.delete(workspaceKey)` for provisional non-`readmit` admissions.
2. **`releaseSource(sourceId, source, data)` & `releaseHeld(sourceId, workspaceKey, data, admission)`:**
   - Track `retired = Boolean(entry.retired)` and set `retired = true` whenever a matching entry in `source.retirements` is consumed.
   - Gate the `readmit` hold on `holdForReadmit = Boolean(owned && retained && result?.readmit === true && !retired)`, and compute `stayRetained = retained && !(owned && result?.readmit === true && retired)` so only retired bound `readmit` vessels override `retained`, clear `data.releasedBinding.awaitingClosure = false`, and invoke `source.effects.released` immediately after synchronous `unbind` detach, leaving unowned `readmit` disconnects and non-`readmit` `retained` callers unchanged.
   - Capture `releaseData: data` on `held` in `releaseSource`, and in `releaseHeld` fall back to `admission.releaseData ?? {}` when `data` is omitted/empty and clear `envelope.releasedBinding.awaitingClosure = false` whenever `this.isCurrentRelease(envelope)` holds.
3. **Unit coverage (`test/playwright/unit/manager/transaction/NativeLifecycle.spec.mjs`):**
   - Cover all three retirement/disconnect arrival orders (`disconnect` during in-flight `retire` close, `retire` close resolving before `disconnect`, and `retire` resolving after `disconnect` already placed a `readmit: true` hold), plus pinning that an unowned `readmit` disconnect releases nothing.

## Acceptance Criteria

- [ ] `NativeLifecycle#releaseSource` skips the `readmit: true` hold and invokes `effects.released` immediately (while still running `effects.unbind` first) when a bound generation disconnects during an in-flight `retire()`.
- [ ] `NativeLifecycle#retire` records retirement on a matching `source.owners` entry when `close` resolves `true` before `disconnect` arrives, so the subsequent `releaseSource` hands the item directly to `effects.released` without waiting on `result.closed` or `reconnectLeaseMs`.
- [ ] `NativeLifecycle#retire` delegates a matching `readmit: true` admission to `releaseHeld` when `retire()` settles after `disconnect` already held the key.
- [ ] All existing and new unit specs in `test/playwright/unit/manager/transaction/NativeLifecycle.spec.mjs` pass without regressing `#20144` / `#20147` reload-readmit behavior.

## Out of Scope

- Changing `Neo.Main#windowClose` / `Neo.Main#windowNativeClose` handle cleanup in `src/Main.mjs`.
- Downstream golden baseline refresh in `neomjs/neo-agent-institution#911` (consumes this fix once merged to `dev`).

## Avoided Traps

- **Skipping `effects.unbind` for retired vessels:** `NativeVesselTransaction.holdReleasedVessel` detaches the live pane from the popup's `mainView` synchronously on `disconnect`; skipping `unbind` would leave the pane mounted in the departed window tree where App-worker disconnect cleanup destroys it (`59037f202a`).
- **Working around the stall in `VesselContainer#returnPane`:** Every `Workspace` / `NativeVesselTransaction` consumer (`TearOut`, `VesselContainer`, `Workstation`) shares `NativeLifecycle#retire`; fixing `NativeLifecycle` closes the race at the single owning primitive.
