# Retire .gemini/concepts/worktree-bootstrap.md and .gitignore negation

## Context

While reviewing repository setup substrate in `neomjs/neo`, `.gemini/concepts/worktree-bootstrap.md` (`15` lines) surfaced as a leftover pointer from the pre-Brain-split era (`#11156` → `#15049` → `#19735`). It is the sole tracked file remaining under `.gemini/`, kept alive by a dedicated negation pair in `.gitignore:141-142` (`.gemini/*` + `!.gemini/concepts/`).

## The Problem

`.gemini/concepts/worktree-bootstrap.md` adds zero runtime or onboarding value for either maintainer seats or external fork contributors, and carries misleading framing:

1. **No AI harness auto-loads `.gemini/concepts/*.md`:** Antigravity 2.x loads `AGENTS.md`, `GEMINI.md`, and `.agents/skills/**`; `.gemini/settings.template.json` was removed in `#15049`, and Claude Code / Codex ignore `.gemini/concepts/`.
2. **Fleet Manager maintainer seats do not use Engine git worktrees:** each provisioned seat runs in an isolated harness profile with dedicated repository clones.
3. **External fork contributors working in `neomjs/neo` have nothing to hydrate with `bootstrapWorktree.mjs`:** an Engine checkout has no `ai/` directory and no `.neo-ai-data/` SQLite/Chroma state (`npm install` runs `buildScripts/util/prepare.mjs:43-46` → `husky` + `neo-agent-skills-materialize`, and `.gitattributes` `smudge=cat` from `#20776` materializes `AGENTS.md` in any clone or worktree).
4. **Misleading Engine-checkout command framing:** line 11 (`node ai/scripts/migrations/bootstrapWorktree.mjs`) fails in an Engine checkout (`MODULE_NOT_FOUND`), while multi-harness Brain setup is already documented under `.github/AI_QUICK_START.md` (`§8.5 Multi-Harness Worktree Hydration`, `:315-336`).

## The Architectural Reality

- `.gemini/concepts/worktree-bootstrap.md` is the only git-tracked file under `.gemini/`.
- `.gitignore:141-142` uses `.gemini/*` + `!.gemini/concepts/` solely to allow tracking `.gemini/concepts/worktree-bootstrap.md`; `buildScripts/util/npmIgnoreComposition.mjs` derives `.npmignore` from `.gitignore`.
- Cross-repo reference sweep (`worktree-bootstrap` and `.gemini/concepts` across `neo`, `neo-agent-skills`, `neo-agent-brain`, `neo-agent-institution`, and `devindex`) surfaces only two non-self references:
  1. `test/playwright/unit/buildScripts/gitignoreNegationReachability.spec.mjs:12` — a JSDoc prose comment contrasting unreachable `.neo-ai-data` rules against `.gemini/*` followed by `!.gemini/concepts/`. Updating that JSDoc example to cite an active negation pair in `.gitignore` (such as `/docs/output/*` followed by `!/docs/output/class-hierarchy.json` at `.gitignore:71-77`) keeps the spec commentary accurate.
  2. `neomjs/neo-agent-brain` `ai/scripts/diagnostics/check-retired-primitives.mjs:47` — lists `'.gemini/concepts/'` in `ACTIVE_ANTIGRAVITY_ROOTS`, which `runScan` (`:222`) filters via `fs.existsSync(path.resolve(root))`; deleting `.gemini/concepts/` in `neomjs/neo` does not break Brain diagnostics.

Design authority: "Where an edit touches existing substrate, prefer `retire` / `rewrite` / `compress-to-trigger` over pure `keep` + append" (`learn/agentos/decisions/0007-agents-md-compaction-taxonomy.md` §5.4; `AGENTS.md §self_evolving_systems` Accretion Defense).

## The Fix

1. Delete `.gemini/concepts/worktree-bootstrap.md`.
2. Simplify `.gitignore:141-142` from `.gemini/*` + `!.gemini/concepts/` to `.gemini/`.
3. Update the JSDoc example in `test/playwright/unit/buildScripts/gitignoreNegationReachability.spec.mjs:11-13` so it cites an existing reachable negation pair in `.gitignore` (e.g. `/docs/output/*` + `!/docs/output/class-hierarchy.json`) instead of the retired `.gemini/concepts/` rule.

Decision Record impact: aligned-with ADR 0007
