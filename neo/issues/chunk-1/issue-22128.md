# Qualify Portal example cards as Desktop · Mobile via 390×844 audit

Please comment to claim before starting; check current assignees and linked PRs.

## Context

On the live v14.0.0 Portal (`/examples`), selecting a mobile-qualified example card displays a solitary uppercase `MOBILE` pill inside `.portal-example-more` (`apps/portal/view/examples/List.mjs:327-330`), while neighboring cards display no platform badge. Operator review on 2026-11-24 surfaced two gaps: (1) dropping `"Desktop"` (`#21676` / PR `#21829`) makes dual-surface examples (`Data Grid: 100k Rows`, `Todo List`, `Multi-Step Account Form`) read as mobile-only; and (2) no catalog-wide phone viewport audit was run across the v14 example slate.

## The Problem

1. **Ambiguous solo `MOBILE` pill & missing `nowrap`:** From `#5866` (`b2080ba727`) until `#21676` (`78b90d9e2f`), `List.mjs` rendered `record.environments.join(', ')` (`"Desktop"` or `"Desktop, Mobile"`). Unlike `"Multi-window"` (an additive capability), `"Mobile"` is one pole of a binary platform pair (`Desktop` vs `Mobile`), so a standalone `[MOBILE]` pill implies mobile-only. In addition, `.portal-example-mobile` (`resources/css/src/apps/portal/examples/List.css:541-552`) omits `white-space: nowrap`, so a multi-word pill beside a `scope` sentence (`35 / 109` cards carry `scope`, avg `71` chars inside a `312 px` column) can wrap across two lines.
2. **Unmeasured `environments` metadata across `109` demonstration cards:** JSON census across `apps/portal/resources/data/examples/*.json` at `dev` `35072c32aa` (producer: Node JSON scan over `apps/portal/resources/data/examples/*.json`; filter: `record.id && record.kind !== 'component'` vs `record.kind === 'component'`; sampled hits: `grid-big-data` `["Desktop","Mobile"]`, `on-air-at-eight` `["Desktop"]`, `table-filtering` `undefined`) shows `170` records (`109` demonstration cards, `61` component tiles): only `15 / 109` cards (`13.8%`) carry `["Desktop", "Mobile"]` (`9` pre-v14 carryovers + `6` ad-hoc v14 PRs), `3 / 109` explicitly declare `["Desktop"]`, and `91 / 109` (`83.5%`) omit `environments` altogether (falling back to `Portal.model.Example`'s `['Desktop']` default; `74 / 109` omit `scope`). Responsive siblings (`Toast Notifications`, `Popover`, `Sign-up validation`, `Input masks`, `Address and payment`, `Table Filtering`, `Animated Row Sorting`, `Animated List`, `Sparklines`, etc.) were never evaluated at phone width (`390×844`).
3. **Search blind spot:** `Portal.model.Example.matchesQuery` (`apps/portal/model/Example.mjs:167-183`) tokenizes `name`, `feature`, `lookFor`, `component`, `groupTitles`, and `keywords`, omitting `environments` — so typing `mobile` in the Examples find field misses mobile-qualified examples unless `"mobile"` happens to appear in prose.

## The Architectural Reality

- `apps/portal/view/examples/List.mjs:280,327-330`: `hasMobile = Boolean(record.environments?.includes('Mobile'))` conditionally renders `{tag: 'span', cls: ['portal-example-mobile'], text: 'Mobile'}` inside `.portal-example-meta` in `.portal-example-more-inner`.
- `resources/css/src/apps/portal/examples/List.css:336-395,541-552`: `.portal-example-more-inner` uses `grid-template-columns: minmax(0, 1fr) auto` (`column-gap: 6px`) capped at `22.5cqi`; keeping desktop-only cards badge-free preserves `~22 px` of unoccluded `16:9` cover height on the `74` cards with no `scope` line and leaves desktop-only `scope` cards (`Workstation`, `On Air at Eight`) the full `312 px` width.
- `apps/portal/model/Example.mjs:51-54,167-183`: defines `environments` (`defaultValue: ['Desktop']`) and `matchesQuery`.
- `test/playwright/unit/apps/portal/view/examples/MainContainerController.spec.mjs:1273`: asserts `mobile.removeDom === !record.environments?.includes('Mobile')`.

Design authority: "Progressive details (`lookFor`, `scope`, and positive `Mobile` qualification) sit in `.portal-example-more` with zero focusable descendants — opening in-frame (`<= 40%` height) in multi-column lists" (`apps/portal/view/examples/List.mjs:268-271`; refined per operator & maintainer convergence on 2026-11-24 to label the conditional pill `Desktop · Mobile` and populate `environments` from a measured `390×844` catalog sweep).

## The Fix

1. **Explicit dual-surface pill + `nowrap` + search indexing:**
   - Update `.portal-example-mobile` text in `apps/portal/view/examples/List.mjs:328` from `'Mobile'` to `'Desktop · Mobile'` (retaining `removeDom: !hasMobile` so desktop-only cards carry zero redundant `[DESKTOP]` wallpaper).
   - Add `white-space: nowrap;` to `.portal-example-mobile` in `resources/css/src/apps/portal/examples/List.css:541-552` (and rebuild compiled Portal CSS themes if applicable) so `scope + pill` rows never wrap the pill.
   - Include `...(record.environments?.includes('Mobile') ? ['mobile'] : [])` in `Portal.model.Example.matchesQuery` (`apps/portal/model/Example.mjs:172-180`) so searching `mobile` in `/examples` surfaces every mobile-qualified card, covered by unit assertions.
2. **Measured `390×844` phone qualification sweep across all `109` demonstration cards:**
   - Run an automated Playwright `390×844` touch-viewport audit over all `109` published demonstration URLs verifying: (a) clean app mount with zero uncaught page/console errors, (b) zero unintended document/viewport horizontal overflow (`documentElement.scrollWidth <= 390` unless an intentional inner scroll container such as a grid/table/timeline body owns horizontal scroll), and (c) primary controls/content visible and usable on a single phone window without requiring desktop multi-window popups (`sharedWorkers` popup-only flows stay `['Desktop']` unless a usable single-window phone layout exists).
   - Update `"environments": ["Desktop", "Mobile"]` (or explicit `["Desktop"]` where audited desktop-only) across `apps/portal/resources/data/examples/*.json` strictly from the measured results, and log any unexpected phone layout breakages as `defect-note`s rather than fixing unrelated app layouts inside this PR.

Decision Record impact: none.

## Acceptance Criteria

- [ ] Selected cards with `Mobile` in `environments` render `Desktop · Mobile` on a single unwrapped pill line inside `.portal-example-more` (including alongside long `scope` text at `1440×900` and `390×844`), while desktop-only cards render no `.portal-example-meta` node.
- [ ] Typing `mobile` into the Portal Examples find field returns every published record whose `environments` includes `'Mobile'`.
- [ ] All `109` demonstration cards in `apps/portal/resources/data/examples/*.json` are audited at `390×844` in Playwright, with `environments` updated from measured pass/fail criteria and the full group-by-group qualification summary recorded in the PR's `## Test Evidence`.
- [ ] Portal unit and whitebox E2E tests (`MainContainerController.spec.mjs`, `ExamplesCatalogNL.spec.mjs` or companion E2E assertion red on `dev` base) pass, with before/after frames embedded in the PR body.

## Out of Scope

- Refactoring individual example apps whose layouts legitimately require desktop viewports or multi-window popups (any genuine phone-layout bug uncovered during the sweep is captured via `defect-note` / separate scoped issue).
- Adding environment pills to compact `kind: 'component'` workbench tiles.

## Avoided Traps

- **Stamping a separate `[Desktop]` pill on all `109` cards:** Repeats a `100%` baseline truth `109` times (the same zero-entropy pattern retired for browser names in `#21676`), adds an extra row (`~22 px` cover occlusion) on the `74` cards with no `scope` text, and steals width from `scope` sentences on desktop-only cards.
- **Tagging `"Mobile"` by guessing from JSON descriptions without loading each example at `390×844`:** Risks advertising broken/clipped demos as mobile-ready.
