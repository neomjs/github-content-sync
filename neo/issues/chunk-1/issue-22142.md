# HomeAudienceDoorsNL Tab focus jumps across scroll-snap stages

Curated contributor labels (`good first issue`, `help wanted`) omitted: maintainer-owned immediate CI flake repair after two independent `e2e-engine (18/18)` failures on the same day (`PR #22140` and `PR #22141`).

## Context

`Engine Tests / e2e-engine (18/18)` failed intermittently twice on 2026-11-24 — first on PR `#22140` (run `45421489783`) and independently again on PR `#22141` (run `45435436874`, job `138591967891`) — inside `test/playwright/e2e/portal/HomeAudienceDoorsNL.spec.mjs`:

```text
1) [chromium] › test/playwright/e2e/portal/HomeAudienceDoorsNL.spec.mjs:459:9 › Portal Home AudienceDoors (Neural Link) › neo-theme-neo-dark: Features and AI Toolchain cards carry the glass card and light in place without moving (#22063)

  > 530 | expect(focused.position).toEqual(rest.position);
```

## The Problem

In `HomeAudienceDoorsNL.spec.mjs:483-538` (added in `#22063`), the test iterates over `[featureCards, toolchainCards]` inside `Portal.view.home.MainContainer` (`scroll-behavior: smooth; scroll-snap-type: y mandatory;` in `MainContainer.css:3-4`, with `.portal-home-content-view { min-height: 100%; scroll-snap-align: center; }` in `BaseContainer.css:3`):

1. At the end of the `featureCards` iteration (`line 537`), `await card.evaluate(node => node.blur())` blurs `featureCards.first()`, which leaves Chromium's sequential-focus navigation starting point anchored on `featureCards.first()` in the `Features` stage.
2. On the `toolchainCards` iteration (`Portal.view.home.parts.AiToolchain`, which also contains `FooterContainer` and is `192px` taller than the `900px` scrollport, so `scroll-snap-align: center` snaps `96px` into the stage at `card` viewport `top: 310.671875`), line 525 executes bare `await page.keyboard.press('Tab')` before `await card.evaluate(node => node.focus())`.
3. Pressing `Tab` jumps focus back up to `featureCards.nth(1)` in the `Features` stage above `AiToolchain`, initiating an upward `scroll-behavior: smooth` scroll on `.portal-home-maincontainer`. Calling `node.focus()` immediately afterward interrupts or re-snaps the scroll container by `96px` (`top: 406.671875` vs `310.671875`), failing `expect(focused.position).toEqual(rest.position)` even though the card itself never moved within `AiToolchain`.
4. Additionally, the test scrolls before awaiting `waitForHomeStylesAndFonts(page)` (`lines 70-91`), unlike `scrollHomeToReference` (`line 102`).

## The Architectural Reality

- `Design authority: "/* A hover lights the card and never moves it: a lift clipped the top border and moved every target inside the card. */"` (`resources/css/src/apps/portal/Viewport.css:174` and `#22063`).
- In the neighboring Stage-1 door test (`HomeAudienceDoorsNL.spec.mjs:439-441`), keyboard `:focus-visible` is exercised by focusing an adjacent link inside the **same** stage before pressing `Tab`, avoiding any cross-stage scroll-snap jump.
- Both `featureCards` (`Portal.view.home.parts.Features`) and `toolchainCards` (`Portal.view.home.parts.AiToolchain`) render 6 `<a class="portal-content-box portal-glass-card">` cards in a 3-column grid at `1440×900`, so `cards.nth(1)` sits on the exact same horizontal row as `cards.first()` (`card`).

## The Fix

In `test/playwright/e2e/portal/HomeAudienceDoorsNL.spec.mjs` (`lines 482-535`):
1. Await `waitForHomeStylesAndFonts(page)` before scrolling and measuring card positions in the `#22063` theme loop.
2. Replace the cross-stage bare `Tab` + unguarded `node.focus()` sequence (`lines 525-526`) with `await cards.nth(1).evaluate(node => node.focus({preventScroll: true}))` followed by `await page.keyboard.press('Shift+Tab')`, keeping keyboard sequential-focus navigation strictly within the already-visible top row of the active stage (`zero` scroll-container displacement while triggering genuine `:focus-visible` glint and border sweep on `cards.first()`).

## Avoided Traps

- **Calling `node.focus({preventScroll: true})` without a real keyboard navigation event:** After `page.mouse.move(5, 895)`, Chromium is in pointer modality, so programmatic `.focus()` alone does not match `:focus-visible`; `Shift+Tab` from `cards.nth(1)` enters genuine keyboard modality on `cards.first()` without leaving the active row.
