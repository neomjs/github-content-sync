# AGENTS.md is generated at install and every Start, not tracked

## Context

neomjs/neo-agent-skills#335 decided (shape C, its first two comments) that a consumer's maintainer `AGENTS.md` is a projection of its installed skills package, generated rather than hand-kept. This leaf is the Engine half: #335's AC-1 to AC-5, plus the Engine's part of AC-6. The Brain's link and `devindex` (AC-7) land as their own leaves.

**Amended 2026-11-11 (operator input):** directories and studies look for a root `AGENTS.md`, and an agent in a fork that never installed should learn that its rules are missing. So git keeps a pointer in `AGENTS.md`, and the working copy holds the generated rules: the pattern Git LFS uses for its pointer files.

## The Problem

The tracked `AGENTS.md` changes only when someone commits it. Dependabot moved the skills pin on 11-06, 11-08 and 11-10 without it, and #20739 caught it up by hand. The next section release drifts it again: the rule ships, gets pinned and installed, and no session loads it.

## The Architectural Reality

Design authority: "Generated copies (`AGENTS.md` sections, `.claude/CLAUDE.md`) are never hand-edited; they regenerate from the package." (neomjs/neo-agent-skills#140, the authority #335 cites)

- **The set:** `package.json:45` declares `"generate-agents-md": "neo-agent-skills-agents-md --repo neo,neo-agent-brain --out AGENTS.md"` (since #20739).
- **`buildScripts/util/prepare.mjs`** runs the stages `husky` and `materialize`, each a bin resolved from its package's manifest and run through `node`, never through a PATH shim, so the lifecycle stays portable to `cmd.exe`. Both run behind the lock-only guard and `isDependencyBuild`.
- **`buildScripts/helpers/seatStart.mjs`** runs on every Fleet Start, including one whose lockfile digest matches: `READY` includes `present` (neomjs/neo-agent-brain `ai/services/fleet/installAgentRepoDependencies.mjs:33`). A non-zero exit lands on the start row as `seatStart: {state: 'failed'}` (`:385`).
- **Harness entries:** `.claude/CLAUDE.md` is a tracked symlink to `../AGENTS.md`, `.agents/ANTIGRAVITY_RULES.md:3` links it, and Codex reads the root file. Claude Code reads `AGENTS.md` itself from v2.1.277 when no `CLAUDE.md` exists. No script, workflow or hook reads `AGENTS.md`.
- **Git filters:** a `clean` filter named in `.gitattributes` decides what git stores for a path. Git trusts a changed file size without reading the file, so a filter-backed path needs `git update-index --refresh` after the working copy is rewritten.

## The Fix

1. **`prepare.mjs`:** a third stage, `agents-md`, runs the `neo-agent-skills-agents-md` bin with the arguments of the checkout's own `generate-agents-md` script, read from `package.json` (AC-2). Before it writes, the stage registers the `neo-agents-md` clean filter, and afterwards it refreshes git's stat cache. A checkout that declares no script skips the stage, and a script that is not a plain call of the bin fails it.
2. **`seatStart.mjs`:** runs the same stage on every Start, ahead of the theme check. A failed generation exits non-zero (AC-5), and the theme check still runs.
3. **The pointer:** `AGENTS.md` stays tracked, holding a short pointer whose single source is `buildScripts/util/agentsMdPointer.mjs`. `.gitattributes` routes the file through the `neo-agents-md` clean filter, which that module answers.
4. **Links (AC-6):** both blog links point to `agents-md` in neomjs/neo-agent-skills. `CONTRIBUTING.md:165` says `npm install` generates the root file from there.
5. **Specs:** the stage order and its script arguments; a missing script skips and a non-plain one is refused; a fixture bump moves the file (AC-3); `seatStart` restores a deleted file (AC-4) and exits 1 on a failed generation (AC-5); a real-git round trip keeps `git status` clean; and the committed file equals the pointer.

## Avoided Traps

- **Untracking the file.** Scanners and an uninstalled fork find nothing, and CI's substrate guard reads the dangling `.claude/CLAUDE.md` as a seat without rules.
- **Spawning `npm run generate-agents-md`.** That brings back the PATH shim `prepare.mjs` exists to avoid, and a nested npm inside the lifecycle.
- **A second copy of the repository set** (a constant in `prepare.mjs`). Two declarations drift; the script is the one #20739 placed.
- **Generating only at install.** A Start with a matching lockfile digest installs nothing.

Euclid's review found two ways the generated rules could reach the index.

- `git update-index --refresh -- AGENTS.md` registers the file's content.
  With no filter in place, it staged the raw rules. The refresh now
  re-sets the entry to its own blob, clearing the cached stat, and runs
  `git update-index -q --refresh` without a pathspec. The index then
  re-reads the file through the filter, and nothing is ever written to it.
- The filter was optional, and a failed registration only warned. The
  stage now makes sure `clean` and `required = true` are registered before
  it writes, and stops when they cannot be. A filter that cannot run
  makes git refuse to store the file, never store it raw.

The stage's git steps run through an injectable gitFn, so the unit specs
never touch the real repository's config. Real-git arms cover each
failure path; both reverted mutations fail them."
