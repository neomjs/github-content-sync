# Calendar week view setting columnsBuffer sets totalColumns to NaN

## Context

Clio (`@neo-fable-clio`) found by reading `src/calendar/view/week/Component.mjs` that `afterSetColumnsBuffer` reads a non-existent `this.visibleColumns` property instead of `this.columnsVisible`. Browser verification in Chromium `157.0.8103.39` against `dev` (`82458b0453b8a89f3a09974abf7f5c7ba9ae7f8a`) confirms that setting `columnsBuffer` at runtime turns `totalColumns` into `NaN` and breaks subsequent week header and event updates.

## The Problem

Initial construction of `Neo.calendar.view.week.Component` hides the typo only because `columnsBuffer_` (`line 66`) precedes `columnsVisible_` (`line 72`) alphabetically in `static config`: during `initConfig`, `afterSetColumnsBuffer(7, undefined)` sets `this.totalColumns = NaN`, and `afterSetColumnsVisible(7, undefined)` (`line 340`) immediately overwrites `NaN` with `21`.

When `columnsBuffer` is mutated after construction (e.g. `cmp.columnsBuffer = 5`):
1. `this.totalColumns` becomes `NaN` (`undefined + 2 * 5`).
2. Subsequent in-place updates (`afterSetCurrentDate`, `afterSetShowWeekends`, `afterSetWeekStartDay`) advance `firstColumnDate`, while `updateHeader` (`for (; i < me.totalColumns; i++)`) and `updateEvents` (`endIndex = this.totalColumns`) execute `0` loop iterations, leaving DOM columns and headers frozen on the previous date range (`2024-07-21..2024-08-10` after `firstColumnDate` moved to `2024-07-30`).
3. A clean header rebuild (`headerCreated = false`, empty `cn`, `updateHeader(true)`) renders `0` columns, `0` header items, and `0` events.
4. Neither `afterSetColumnsBuffer` nor `afterSetColumnsVisible` rebuilds the column and header VDOM containers when mutated on an already-constructed week view (`vdomColumnCount` remains `21` instead of `2 * columnsBuffer + columnsVisible`).

## The Architectural Reality

- `src/calendar/view/week/Component.mjs:62-72` defines reactive configs `columnsBuffer_: 7` and `columnsVisible_: 7`; no `visibleColumns` member exists anywhere on `Component`.
- `src/calendar/view/week/Component.mjs:329-331`: `afterSetColumnsBuffer` computes `this.totalColumns = this.visibleColumns + 2 * value`.
- `src/calendar/view/week/Component.mjs:339-341`: `afterSetColumnsVisible` computes `this.totalColumns = 2 * this.columnsBuffer + value`.
- `src/calendar/view/week/Component.mjs:831` (`onWheel`), `891` (`updateEvents`), and `1025` (`updateHeader`) all bound their loops by `this.totalColumns`. When `columnsBuffer` or `columnsVisible` changes after `headerCreated` is `true`, `updateHeader(false)` (`:1052`) assumes `content.cn` and `header.cn` already have length `this.totalColumns`, so changing `totalColumns` at runtime also requires resetting `content.cn = []` and `header.cn = []` and rebuilding via `updateHeader(true, true)` + `updateEvents()`.

Design authority: `src/calendar/view/week/Component.mjs:62-71` (`"Amount of hidden columns on both sides each inside this view. @member {Number} columnsBuffer_=7 @reactive"` and `"Amount of visible columns inside this view. @member {Number} columnsVisible_=7 @reactive"`) together with `afterSetColumnsVisible` at `:340` (`this.totalColumns = 2 * this.columnsBuffer + value`).

## The Fix

In `src/calendar/view/week/Component.mjs`:
1. Fix `afterSetColumnsBuffer` (`:329-331`) to use `this.columnsVisible + 2 * value` (guarding when `this.columnsVisible` is not yet initialized if config order ever changes, or computing `2 * value + (this.columnsVisible ?? 0)`).
2. When `this.isConstructed && oldValue !== undefined` in `afterSetColumnsBuffer` and `afterSetColumnsVisible`, clear `getColumnContainer().cn = []` and `getHeaderContainer().cn = []`, reset `headerCreated = false`, and rebuild columns/headers and events (`updateHeader(true, true); updateEvents()`) so runtime changes to either `@reactive` config keep VDOM and DOM column counts synchronized with `totalColumns`.

## Acceptance Criteria

- [ ] AC-1: Mutating `columnsBuffer` at runtime on a constructed `Neo.calendar.view.week.Component` sets `totalColumns` to `2 * columnsBuffer + columnsVisible` (never `NaN`) and updates the rendered column/header count and subsequent `currentDate` transitions accordingly.
- [ ] AC-2: Mutating `columnsVisible` at runtime on a constructed `Neo.calendar.view.week.Component` likewise rebuilds the column and header containers to match the new `totalColumns` without throwing in `updateHeader`.
- [ ] AC-3: Add regression coverage under `test/playwright/unit/calendar/` (or `test/playwright/component/calendar/`) that fails on `dev` before the fix and passes with `npm run test-unit -- test/playwright/unit/calendar`.

## Out of Scope

- Infinite-scroll column paging thresholds in `onWheel` beyond reading the updated `columnsBuffer`, `columnsVisible`, and `totalColumns`.
- Calendar event drag-and-drop date calculation or store notification behavior (tracked in separate issues).

## Avoided Traps

- **Fixing only the `this.columnsVisible` typo without rebuilding `content.cn` / `header.cn`:** If `columnsBuffer` increases from `7` to `9` (`totalColumns` `21` -> `25`) while `headerCreated` stays `true`, the next `updateHeader(false)` (`:1052`) calls `Object.assign(content.cn[21], ...)` on `undefined` and throws; if `columnsBuffer` decreases from `7` to `5` (`21` -> `17`), 4 stale trailing columns remain in `content.cn` and `header.cn`.
