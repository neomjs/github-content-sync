# Medium list: the JSON-LD story moved into ITNEXT, update entry 78

## Context

`apps/portal/resources/data/medium_blog.json` feeds the Medium tab of the Portal's News section. Entry 78 was added on 2026-11-10 (#20733) for the story "JSON.stringify is not safe inside a script tag: the JSON-LD XSS and its one-line fix". At that moment the story stood on the author's profile and belonged to no publication, so the entry has an empty `publisher` and a URL on `tobiasuhlig.medium.com`.

## The Problem

About two hours later the ITNEXT editor took the story into the publication. Read on 2026-11-10 at 18:19Z: the profile URL redirects to `https://itnext.io/json-stringify-is-not-safe-inside-a-script-tag-the-json-ld-xss-and-its-one-line-fix-3a4f6e3302b2`, and the page says "Published in ITNEXT". The card in the Medium tab therefore shows no publication, while its four neighbours show "in ITNEXT", and its link takes a redirect.

## The Architectural Reality

- `apps/portal/resources/data/medium_blog.json`, the first entry (`"id": 78`). The four entries below it (77 to 74) show the target shape: `"publisher": "ITNEXT"` and a `url` on `itnext.io` with the query `?source=friends_link&sk=…`.
- `apps/portal/view/news/medium/List.mjs` renders the publication after the author's name when `publisher` is not empty. No code changes.
- Design authority: n/a — calls no existing behavior wrong; a data entry that the story outran.

## The Fix

In entry 78 only:

1. `"publisher": ""` becomes `"publisher": "ITNEXT"`.
2. In `url`, the host `tobiasuhlig.medium.com` becomes `itnext.io`. The path and the query string stay exactly as they are.

## Acceptance Criteria

- [ ] AC-1: entry 78 has `"publisher": "ITNEXT"` and a `url` that starts with `https://itnext.io/json-stringify-is-not-safe-inside-a-script-tag-` and keeps its query string.
- [ ] AC-2: the new `url` opens the story, and the page names ITNEXT as its publication.
- [ ] AC-3: the file parses and still holds 78 entries; `git diff --numstat` shows two changed lines in this one file.

How to check AC-3: `node -e "console.log(JSON.parse(require('fs').readFileSync('apps/portal/resources/data/medium_blog.json','utf8')).length)"` prints `78`.
