# ADR 0043 Phase 1 gate: two-thread e2e arm, tear-out pair, I3

## Context

ADR 0043 (accepted 2026-11-25 in #22197, `learn/agentos/decisions/0043-vdom-diff-placement.md`) moves stage 3, the diff, into the App worker and retires the VDom worker. Its §2.4 gates the first step: `useVdomWorker` flips to `false` only once three observables hold. Before the two-thread line carries every update, its invariant I3 (§2.3) needs one code change. This leaf delivers I3 and observables (b) and (c). Observable (a) is read on the flip leaf #22209's own required CI (decided 2026-11-25, see The Fix).

Today only a four-page boot smoke runs the two-thread arm (D#20751 finding 10). `test/playwright/e2e/rendering/TwoThreadPipelineNL.spec.mjs` sets the flag per page.

## The Problem

1. **I3 does not hold on the line yet.** `VdomLifecycle` sends the deltas with `Neo.applyDeltas(me.windowId, …)` after `await Promise.resolve(Neo.vdom.Helper.updateBatch(batchData))` ([`src/mixin/VdomLifecycle.mjs` L570–L585 at `15ef0e9`](https://github.com/neomjs/neo/blob/15ef0e9f8272bd91b141d858d387ddf722c08b1d/src/mixin/VdomLifecycle.mjs#L570-L585)). So the window id is read one microtask after collection. A component that moves windows in that turn sends its deltas to the new window: the destination error [Euclid measured](https://github.com/neomjs/neo/discussions/20751#discussioncomment-19687273) for a deferred reply.
2. **The gate has no observables yet.** No CI run covers the hosted e2e matrix in the two-thread arm. No tear-out comparison exists across the two arms. No spec exercises a SharedWorker multi-window pop-out and re-dock without the VDom worker.

## The Architectural Reality

- `Neo.config.useVdomWorker` (`src/DefaultConfig.mjs:416-419`, default `true`) is read by `src/Main.mjs`, `src/mixin/VdomLifecycle.mjs`, `src/worker/App.mjs`, `src/worker/Base.mjs` and `src/worker/Manager.mjs`. No tracked `neo-config.json` sets it (0 of 286 at `e6418ff`).
- On the line, `Helper.update` and `updateBatch` run synchronously in the App worker. The `await Promise.resolve(…)` is the only turn between collection and send (ADR 0043 I3).
- The e2e matrix runs as the `e2e-engine` shards of `.github/workflows/test.yml`. The organisation has 20 runner slots.
- The stages and the line are described in `learn/guides/vdomengine/`.

## The Fix

1. **I3.** `executeVdomUpdate`, the one update path, already captures the window at collection (`batchData.windowId = me.windowId`, L558), but it sends with `me.windowId` read again after the `await` (L585). Send with the captured id. `createVnodeTree` already captures before its `await` (L179) and sends with that id (L201). A unit spec moves `windowId` between collection and the reply and asserts the deltas reach the captured window. It is red on `dev`.
2. **(a) is read on #22209's CI.** Decided 2026-11-25 on [Grace's proposal](https://github.com/neomjs/neo/issues/22208#issuecomment-7168670785). With the default flipped, #22209's required `e2e-engine` check runs the full hosted matrix in the two-thread arm, and the flip cannot merge red. A fixture-wide switch with its own 18-shard job here would cost runner slots and become dead code at the flip. The `YieldedMoveCoalescingNL` worker pin moves to #22209 with it.
3. **(b) The tear-out comparison.** Run the hosted tear-out specs (the #22114 family) at the same repeat count in both arms, on one build, and post both failure counts here. Running both arms on one build takes a dispatch input that sets an environment variable, which the e2e fixture's config route applies.
4. **(c) A SharedWorker multi-window spec.** Under `useSharedWorkers: true` and `useVdomWorker: false`, pop a window out and re-dock it. Assert I3's routing (deltas land in the window captured at collection), and that no in-flight state survives a departing window.

## Avoided Traps

- **A separate two-thread CI job.** It doubles the e2e shards against a 20-slot runner budget and becomes dead code at the flip, whose own required checks run the matrix in that arm.
- **Reading the window id after the `await`.** That is the deferred-reply destination error I3 exists to close.
