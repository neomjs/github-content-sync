# The settings template's autoMode block is never read

## Context

`.claude/settings.template.json` carries an `autoMode` block (lines 62 to 82 at `781af05fa4`): one `environment` sentence, two `allow` sentences and four `hard_deny` sentences. #13453 added it as a prose mirror of `AGENTS.md`'s gates. Claude Code does not read it from this file.

Four artifacts built on it between 2026-11-02 and 2026-11-11: a premise read on neomjs/neo-agent-brain#132 marked a fix as resolved by it, a comment there named it as a cause, #20794 proposed one more `allow` entry (closed once measured), and the first step of #20795 edits one of its `hard_deny` sentences.

## The Problem

- Claude Code's documentation, [Where the classifier reads configuration](https://code.claude.com/docs/en/auto-mode-config#where-the-classifier-reads-configuration): `autoMode` is read from the user's `~/.claude/settings.json`, from managed settings and from `--settings`. "The classifier doesn't read `autoMode` from project settings."
- Measured, with controls, in comment 6807353591 on #20794: in a checkout whose `.claude/settings.json` carries the block, `claude auto-mode config` prints exactly what `claude auto-mode defaults` prints.

So the block allows nothing and denies nothing. It reads like a guard and like an allowance, and each reader builds on it.

## The Architectural Reality

- What holds a seat is elsewhere: `permissions.deny` and `permissions.ask` in the same file, and `AGENTS.md`, which the classifier reads as `CLAUDE.md`. Each `hard_deny` sentence restates a rule `AGENTS.md` carries (critical gates 1, 3, 8 and 9, and the fan-out ban of §swarm_topology_anchor).
- The two `allow` sentences describe writes that go through the MCP servers. `permissions.allow` admits those before the classifier runs.
- Tracked text that mentions `autoMode` (`git grep` at neo `781af05fa4`, neo-agent-brain `c27e8b9b`, neo-agent-skills `c6f0d73`, neo-agent-institution `6f00d3da`; the grep finds the template's own line): this template, and one JSDoc line in `neomjs/neo-agent-brain` that neomjs/neo-agent-brain#1615 covers. No spec asserts the block.
- Design authority: #13453, "a prose `autoMode` whose `hard_deny` names: no `gh pr merge`, no push/commit to `main`|`dev`, no client-names in public artifacts". That intent stands and lives in `AGENTS.md` and `permissions.deny`. Only its unread copy goes.

## The Fix

Delete the `autoMode` key from `.claude/settings.template.json`. Nothing else changes.

## Acceptance Criteria

- [ ] The template has no `autoMode` key and stays valid JSON.
- [ ] `permissions` and `hooks` are unchanged: `jq -S 'del(.autoMode)'` of the file on `dev` equals `jq -S .` of the file on the branch.
- [ ] The pull request body names, for each deleted `hard_deny` sentence, where its rule still lives: the `AGENTS.md` gate or the `permissions.deny` rule.

## Out of Scope

- A user-scope `autoMode` block. Only a person installs one, in their own `~/.claude/settings.json`; no repository file can.
- The generated files of existing seats: neomjs/neo-agent-brain#1615.
- `permissions.ask` for `Agent` and `Task`: #20795.
- Allowances for maintainer acts. They are actions on the github-workflow server: neomjs/neo-agent-brain#1614 and neomjs/neo-agent-brain#1616.

## Avoided Traps

- **Moving the block into `.claude/settings.local.json`.** That is a project file too, and it is not read either.
- **Keeping it as documentation.** It documented a guard that does not exist, and four artifacts relied on it within ten days.

## Note for the author

A Claude Code agent in auto mode may refuse to edit this file as a change to its own permissions (observed on 2026-11-11, #20794). The change deletes 21 lines and can be made by hand.
