# A helper call still asks the operator on every use

## Context

On 2026-11-11 the operator decided that a Claude Code seat may use one read-only helper at a time for reads that fit. neomjs/neo-agent-skills#354 changes the sentence every seat loads.

**Corrected on 2026-11-11, 21:4xZ, 25 minutes after filing.** The first version of this ticket also named the single-subagent sentence in `autoMode.hard_deny` (`.claude/settings.template.json:80`) and asked to rewrite it. That sentence is inert: Claude Code does not read `autoMode` from a project's settings. Vega measured it with controls (#20794, comment 6807353591), Grace confirmed it on her seat, and on mine `claude auto-mode config` equals `claude auto-mode defaults` and does not contain the sentence. #20796 deletes the dead block. What stays here is the one rule that is read.

## The Problem

`.claude/settings.template.json:57-60`: `permissions.ask` holds `Agent` and `Task`. Permissions are honoured from project settings, so a helper call asks the operator. After neomjs/neo-agent-skills#354 the loaded sentence allows one read-only helper at a time, and the harness still turns each use into a confirmation. Nobody has decided whether that is wanted: #13707 added the ask-gate for the earlier decision, "only on the operator's explicit in-session permission".

## The Architectural Reality

- A permission rule is resolved before the classifier runs (#19649 is the precedent for `permissions.allow`).
- A permission rule cannot bind the agent type, the model or the count. That bound lives in the loaded sentence, which the classifier reads as part of the instruction file.
- A template change does not reach an existing seat: neomjs/neo-agent-brain#1615.
- A Claude seat cannot edit this file; its classifier refuses the change as self-modification (#20794).
- Design authority: the operator's decision of 2026-11-11, quoted in neomjs/neo-agent-skills#354: "we can allow claude peers to use one subagent at a time for use cases that fit."

## The Fix

1. Record what one helper call does on a Claude seat in auto mode: does the prompt for `Agent` appear? The transcript is the receipt. The call itself needs the operator's word while the old sentence is loaded.
2. The operator decides between two shapes:
   - **The prompt stays.** One helper per confirmation. The file does not change, and the sentence of neomjs/neo-agent-skills#354 says so.
   - **`Agent` and `Task` leave `ask`.** The loaded sentence is the gate. A non-Claude author removes the two entries, and the change reaches the seats by the path of neomjs/neo-agent-brain#1615.

## Acceptance Criteria

- [ ] The helper call's behaviour in auto mode is recorded on this ticket with its transcript.
- [ ] The operator's decision is recorded on this ticket in his words. Human step: the decision. Owner: the operator; @neo-fable-mnemosyne brings him the recorded call.
- [ ] If the prompt stays: this ticket closes without a file change, and neomjs/neo-agent-skills#354's sentence names the confirmation.
- [ ] If the entries leave: `permissions.ask` no longer holds `Agent` and `Task`, the file stays valid JSON, a `jq` diff against `dev` shows only that edit, and on a seat that carries it the fresh-session check of neomjs/neo-agent-skills#354 passes while a request for two helpers at once is refused.

## Out of Scope

## Avoided Traps

- **A `permissions.allow` rule for `Agent`.** A permission rule cannot bind the agent type, the model or the count.
