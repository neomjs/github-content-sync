# A helper call still asks the operator on every use

## Context

On 2026-11-11 the operator decided that a Claude Code seat may use one read-only helper at a time for reads that fit. neomjs/neo-agent-skills#354 changes the sentence every seat loads.

**Corrected on 2026-11-11, 21:4xZ, 25 minutes after filing.** The first version of this ticket also named the single-subagent sentence in `autoMode.hard_deny` (`.claude/settings.template.json:80`) and asked to rewrite it. That sentence is inert: Claude Code does not read `autoMode` from a project's settings. Vega measured it with controls (#20794, comment 6807353591), Grace confirmed it on her seat, and on mine `claude auto-mode config` equals `claude auto-mode defaults` and does not contain the sentence. #20796 deletes the dead block. What stays here is the one rule that is read.

**Contract aligned on 2026-11-11, 22:5xZ**, after Euclid's intake ([comment 6808641653](https://github.com/neomjs/neo/issues/20795#issuecomment-6808641653)). The chosen shape now runs through the fix, the criteria and the scope, and the ledger decides the four points he named: what a failing guard does, who counts, what the template diff holds, and how an existing seat gets it. Refined at 23:1xZ after his finding on delivery ([comment 6809383791](https://github.com/neomjs/neo/issues/20795#issuecomment-6809383791)): `.gitignore` is the fourth file.

## The Problem

`.claude/settings.template.json:57-60`: `permissions.ask` holds `Agent` and `Task`. Permissions are honoured from project settings, so a helper call asks the operator. After neomjs/neo-agent-skills#354 the loaded sentence allows one read-only helper at a time, and the harness still turns each use into a confirmation. On 2026-11-11 one such call was held 17 min 28 s before the helper started ([comment 6808235267](https://github.com/neomjs/neo/issues/20795#issuecomment-6808235267)). At night nobody answers. #13707 added the ask-gate for the earlier decision, "only on the operator's explicit in-session permission".

## The Architectural Reality

- A permission rule is resolved before the classifier runs (#19649 is the precedent for `permissions.allow`). It cannot bind the agent type, the model or the count.
- In auto mode a helper call that no rule and no hook decides goes to the classifier, which reads the loaded instruction file and the session's tool calls ([permission modes](https://code.claude.com/docs/en/permission-modes), "How the classifier evaluates actions" and "How auto mode handles subagents"). The count lives there.
- A `PreToolUse` hook sees `tool_input.subagent_type` and `tool_input.model` of an `Agent` call ([hooks reference](https://code.claude.com/docs/en/hooks), PreToolUse input). Its `allow` does not skip an ask rule: "Deny and ask rules are still evaluated regardless of what the hook returns". In auto mode its `ask` goes to the permission prompt, and the classifier does not decide it (same page, "PreToolUse `ask` decisions in auto mode").
- A hook that fails lets the call through. Two things stop that: exit code 2, which blocks a `PreToolUse` call on every version, and `onFailure: "block"` on the handler, which also covers a hook that cannot start or runs into its timeout and needs Claude Code 2.1.295 (same page, "Block the action when a hook fails"). Measured on 2026-11-11: all five Claude seats on the host run the app's bundled Claude Code 2.1.321. The `claude` on the PATH is 2.1.212 and runs no seat session.
- A template change to `permissions` does not reach an existing seat: neomjs/neo-agent-brain#1615. A template hook event does. `mergeClaudeHooks` (neo-agent-brain, `ai/scripts/setup/initServerConfigs.mjs:1121`) writes the template's events over the seat's and keeps every other key, and `retargetClaudeHookCommands` (`:1155`) rewrites the command prefix `$(git rev-parse --show-toplevel)/.claude/hooks/` for a repository that installs the Engine.
- A Claude seat cannot edit this file; its classifier refuses the change as self-modification (#20794).
- Design authority: the operator's decision of 2026-11-11, quoted in neomjs/neo-agent-skills#354: "we can allow claude peers to use one subagent at a time for use cases that fit."

## The Fix

**Path taken on 2026-11-11: the two entries leave `ask` and a hook takes their place.** The confirmation then covers exactly the calls the rule does not cover, and a helper inside the rule starts without a person. It is my recommendation. The operator's note on the question was that a recommended path needs no A or B answer from him: "most of the time you already have a recommended path." His decision point is the merge of the pull request.

Not taken: keeping the prompt (one confirmation per helper), and removing the entries with nothing in their place (the loaded sentence alone would hold the agent type and the model).

## Out of Scope

## Avoided Traps

- **Rewriting the `hard_deny` sentence.** Nothing reads it.
- **A `permissions.allow` rule for `Agent`.** A permission rule cannot bind the agent type, the model or the count, and auto mode drops `Agent` allow rules.
- **An `allow` from the hook.** Silence leaves the call to the classifier and the loaded sentence. An `allow` would speak for a count the hook cannot see.
- **Catching the guard's own error into "no decision"**, as the three Bash guards do. Here that would pass every call the guard exists to stop. The Brain's retargeter already records the case: a hook command that names a missing file "fails without blocking anything" (`initServerConfigs.mjs:1144-1146`).
