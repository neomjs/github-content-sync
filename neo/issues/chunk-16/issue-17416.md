# Extract GitHub content sync into a dedicated corpus repository

Terminal predicate: Selected repositories' GitHub conversations are published in a dedicated corpus and reach their intended consumers at identifiable revisions, without committing generated mirror bodies into Engine, Brain or other source repositories.

> **Scope status — 2026-09-19:** the **producer-only boundary** in [D#17846 §6.1 / §8.4a / §8.9](https://github.com/neomjs/neo/discussions/17846) has a [scoped non-author graduation approval](https://github.com/neomjs/neo/discussions/17846#discussioncomment-18519041). This replaces the old D#17247 reservation as authority for that boundary. The wider consumer rollout remains separately gated. This epic is not complete, and no producer or consumer deployment is claimed by this update.

## Problem scope

Generated GitHub conversations need a durable home independent of the repositories whose source code they describe. The original August 2026 reservation measured mirror commits as Engine activity; September's [producer-outage record](https://github.com/neomjs/neo/issues/17416#issuecomment-5743185216) and D#17846's index collision probes establish why restoring a producer and qualifying its data must be delivered together.

This is more than a directory move. It crosses generated-corpus custody, artifact identity, Graph and vector ingestion, local lookup, Portal/Pages derivation and Fleet Manager activity. A correct publisher alone does not make those readers current. These independently observable boundaries require an epic; a single implementation PR must not close it.

The corpus repository and the repositories whose conversations it mirrors are different identities. Origin identity must survive publication without being substituted for the Knowledge Base's ownership tuple.

## Intended solution shape

### Approved first boundary: producer in its destination

Brain retains the generator code. A job owned by the dedicated corpus repository runs a pinned Brain runtime and publishes only into that repository. The first live origin is `neo`; the implementation must also prove that two origins with the same artifact number remain independent.

Logical identity is `(repoSlug, type, id)`, carried through factories, index writes and reads, integrity checks and syncer-local maps. Paths express location. Unqualified lookup queries are refused before matching. Legacy unqualified input may be read during bootstrap, but every emitted row must be qualified; a read-modify-write round trip is an emission.

The producer reuses the syncers, release-history retrieval, reconciliation and integrity machinery. Portal derivation and release-note files are excluded from this publication path. Per-origin sync state advances only for successful work, and the published revision identifies files and index together. Installation, declared configuration, credentials and failed-run behavior are demonstrated from a fresh checkout before activation.

ADR 0004's ordinal-100 rule and complete-membership principle remain in force, scoped to the correct origin and bucket. The design introduces no second chunking primitive.

### Remaining boundary: consumer adoption

KB, Portal/Pages, Fleet Manager, `LocalFileService` and `IssueIngestor` each need an explicit root/index/revision contract before switching. A reader must use qualified identity or a deliberate single-origin projection. Local materialization and Knowledge Base admission are distinct decisions.

The first producer delivery makes no consumer-currentness claim. Distribution/refresh policy, KB admission and legacy-row retirement, typed Graph identity, deployment revision and consumer activation retain their own evidence gates. Prior [D#16794](https://github.com/orgs/neomjs/discussions/16794) findings on one writer, revisioned acquisition and projection receipts remain inputs to those decisions; a new repository's history cannot inherit a source repository's baked revision as an ancestry witness.

Native parent-child relationships are the delivery registry. Acceptance criteria and executable contracts belong to the leaf tickets.
