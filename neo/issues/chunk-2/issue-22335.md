# Set color-scheme once on the neo-theme- base selector

## Context

Order-of-work row 5 and Seam 5 of Design System Epic #22295 (`learn/agentos/decisions/0044-design-system.md` §2.7 & §4 step 2, graduated from [Discussion #22228](https://github.com/orgs/neomjs/discussions/22228) at R3): set `color-scheme: var(--neo-color-scheme)` once in structural CSS on the `[class*="neo-theme-"]` base selector and on the document `:root` whose `<body>` carries a theme class, retire the three per-component declarations that read `--neo-color-scheme` today, repair Neo Dark `Timer` button contrast under dark `ButtonText`, and price the rule with `#22300`'s computed-style equality audit and before/after dark-theme frame pairs.

Ownership: self-assigned (`@neo-gemini-julia`). Curated contributor labels (`good first issue`, `help wanted`) intentionally omitted: active `v14.1` critical-path foundation leaf under #22295 requiring multi-theme Playwright visual capture for the design seat (`@neo-fable-clio`) ahead of the `29–30 Nov` release cut, and sequenced directly behind #22326.

## The Problem

All five shipped engine themes already declare `--neo-color-scheme` (`dark` in `theme-neo-dark`, `theme-dark`, and `theme-cyberpunk`; `light` in `theme-neo-light` and `theme-light`) in their `Global.css` (`#18432`). However, on `dev` (`a676e9fb99`), structural CSS never binds `color-scheme: var(--neo-color-scheme)` on themed scope roots or on a themed body's document `:root` (`getComputedStyle(document.documentElement).colorScheme === 'normal'`, `getComputedStyle(document.body).colorScheme === 'normal'`). Only three widget rules opt in manually:

1. `resources/css/src/component/Progress.css:6` (`progress { color-scheme: var(--neo-color-scheme); }`, landed in `#21941`)
2. `resources/css/src/form/field/Select.css:36` (`.neo-selectfield-input { color-scheme: var(--neo-color-scheme); }`)
3. `resources/css/src/form/field/Select.css:132` (`&::picker(select) { color-scheme: var(--neo-color-scheme); }`)

As a consequence:
- Future `ADR 0044` `light-dark()` role declarations (`theme-neo/Global.css`) would resolve every dark theme as `light` unless `color-scheme` is set on the `[class*="neo-theme-"]` scope boundary.
- Generic scrollable containers, un-wrapped native form controls, and embedded `<iframe>` elements inside dark themes inherit `color-scheme: normal` instead of the active theme's declared scheme, while nested theme islands (`neo-theme-light` inside `neo-theme-neo-dark`, or `neo-theme-dark` inside `neo-theme-neo-light`) do not automatically re-establish UA `color-scheme` at their scope root.
- Because CSS Color Adjustment Level 1 §6.2 compares an outer `<iframe>`'s `color-scheme` against the embedded document's `:root` (`<html>`) scheme, and Neo stamps `neo-theme-*` on `<body>`, an embedded dark Neo document whose `:root` remains `normal` flashes an opaque white `#ffffff` canvas inside a dark Neo parent.
- `Neo.component.Timer` (`resources/css/src/component/Timer.css:91-97`) styles its native `<button>` with `background-color: var(--timer-button-color)` (`#cde8e7` in `theme-neo-dark`) and no `color`, so flipping `ButtonText` to `rgb(255, 255, 255)` drops play-glyph contrast to `1.30:1` unless Neo Dark's `--timer-button-color` uses a dark teal wedge.

## The Architectural Reality

- Design authority (`ADR 0044` §2.7 Decision 7, amended here with `@neo-fable-clio`'s design-seat wording): *"A theme declares `--neo-color-scheme` per class, structure sets `color-scheme: var(--neo-color-scheme)` once, on the base selector and on the root of a document whose body carries a theme class, so the canvas and what an embedding page sees agree with the theme, and roles pick with `light-dark()`."*
- Declaring `--neo-color-scheme` once per theme on `:where(:root:has(> .neo-theme-<name>), .neo-theme-<name>)` (Neo pair) / `:root:has(> .neo-theme-<name>), :root .neo-theme-<name>` (classic pair & Cyberpunk) and setting `:root:has(> [class*="neo-theme-"]), [class*="neo-theme-"] { color-scheme: var(--neo-color-scheme); }` in `resources/css/src/Global.css`:
  1. Gives `<html>` the body theme's `color-scheme` without matching `<html>` when `<body>` carries no `neo-theme-*` class (preserving host-page `html { color-scheme }` rules when Neo is mounted only as an inner island),
  2. Keeps `<html>` locked to `<body>`'s theme via the direct-child `>` combinator even when nested `.neo-theme-*` islands exist deeper in the DOM,
  3. Keeps `0` redeclared properties in `npm run theme-census`, passes `check-theme-value-files`, `check-theme-var-references`, `check-theme-coverage`, and `check-theme-surfaces`, and retargets cleanly through `buildScripts/create/theme.mjs` and `extractThemeClasses`.

## The Fix

1. **`resources/css/src/Global.css` & `resources/css/theme-*/Global.css`**: Declare `--neo-color-scheme` on `:root:has(> .neo-theme-<name>)` alongside the theme class in all five `Global.css` files, and set `:root:has(> [class*="neo-theme-"]), [class*="neo-theme-"] { color-scheme: var(--neo-color-scheme); }` once in `resources/css/src/Global.css`.
2. **`resources/css/src/component/Progress.css` & `resources/css/src/form/field/Select.css`**: Delete the three redundant `color-scheme: var(--neo-color-scheme);` declarations (`Progress.css:6`, `Select.css:36`, `Select.css:132`).
3. **`resources/css/theme-neo-dark/component/Timer.css`**: Update `--timer-button-color` from `#cde8e7` to dark teal `#1f5754` (`8.24:1` contrast against white `ButtonText`, `2.32:1` wedge separation against `#0D0F12`).
4. **`learn/agentos/decisions/0044-design-system.md`**: Amend §2.7 Decision 7's third bullet to include the document root of a themed `<body>`.
5. **Component-tier Playwright witnesses (`test/playwright/component/`)**: Verify computed `colorScheme` across all five themes on `:root`, `<body>`, `<progress>`, `<select>`, `::picker(select)`, `<iframe>`, `.neo-theme-scope`, bidirectional nested theme islands, embedded themed vs unthemed `srcdoc` `<iframe>` documents, and `Neo.component.Timer` Neo Dark button contrast (`>= 4.5:1`).
6. **Visual & computed-style gate**: Run `#22300`'s computed-style equality audit across the three dark themes (and two light themes as a `0`-diff control), declare/fix every difference, and attach `11` before/after dark-theme frame pairs (`grid`, `select`, un-schemed and themed-Neo `iframe`, and Neo Dark `Timer`) routed to `@neo-fable-clio`.

## Avoided Traps

- **Using bare `:root` without `:has(> [class*="neo-theme-"])` or omitting `[class*="neo-theme-"]`:** Bare `:root { color-scheme: var(--neo-color-scheme) }` at `(0,1,0)` would match unthemed host documents and clobber `html { color-scheme }` rules via IACVT, while omitting `:root:has(> [class*="neo-theme-"])` leaves embedded dark Neo `<iframe>` documents with a `normal` root scheme and an opaque white `#ffffff` canvas. Pairing `:root:has(> [class*="neo-theme-"])` with `[class*="neo-theme-"]` aligns the root canvas with `<body>` while preserving nested theme island resets (`#18141`).
- **Declaring `--neo-color-scheme` twice in a theme's `Global.css`:** Grouping `:root:has(> .neo-theme-<name>)` and `.neo-theme-<name>` into one `--neo-color-scheme` block keeps `0` extra redeclarations in `npm run theme-census`.
- **Keeping redundant `color-scheme: var(--neo-color-scheme)` rules in `Progress.css` and `Select.css`:** Fails Accretion Defense and hides inheritance regressions on `::picker(select)` or nested scopes.
