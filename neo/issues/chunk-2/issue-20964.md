# dist/esm: a package's Canvas module loads from outside the emitted tree

## Context

My boundary review on #20863 (comment 6880574910) named this from reading the code, and promised an artifact probe. This is the probe: `dev` `3c9ef1039f`'s own transforms and identity guard, run over the real `src/worker/Canvas.mjs` in a workspace whose `dist/esm` exists:

```
emitted package branch:     `../../../${path.slice(13)}.mjs`   (unchanged by the transform)
loadModule({path: 'node_modules/widget/canvas/Renderer'}) requests: dist/widget/canvas/Renderer.mjs   (exists: false)
emitted package copy:       dist/esm/node_modules/widget/canvas/Renderer.mjs                         (exists: false)
findUnresolvableImports on that branch: no verdict
```

Positive control: in the same run, the guard reports the stub tree's absent siblings and `computed-root ../canvas/${path.slice(11)}.mjs`. The package branch's root resolves to `dist/`, which every `dist/esm` build has, so it passes.

## The Problem

`Canvas#loadModule`'s `node_modules/` branch climbs three levels from the worker file. From an installed engine's `node_modules/neo.mjs/src/worker/`, that lands in `node_modules/`. From `dist/esm/src/worker/`, it lands in `dist/`, outside both trees. Main has a layout switch for the same request; the Canvas worker has none.

The build never emits `neo.canvasModules` roots either. So even a corrected path would find no emitted copy, and loading the source copy would bring the source Engine into the Canvas worker. Neither the build nor its identity guard reports any of this.

## The Architectural Reality

- `src/worker/Canvas.mjs` `loadModule()`: `src/canvas/` → `../canvas/…`; `node_modules/` → `../../../${path.slice(13)}.mjs`; anything else → `../../${path}.mjs`.
- `src/Main.mjs` (about line 500): the Main thread's `dist/esm` switch for package addons, `../node_modules/${modulePath}.mjs`.
- `buildScripts/build/esmodules.mjs` admits declared `neo.mainAddons` roots only. `buildScripts/util/declaredPackageRoots.mjs` reads `neo.canvasModules` too, but nothing in the ESM build consumes it.
- `findUnresolvableImports()` passes a computed specifier whose root directory exists. `dist/` always exists.
- After #20956: `createEsmBuildPlan()` and `esmDestination()` own every admission's destination.
- Design authority: n/a: the probe above shows a request for a file no build emits.

## The Fix

1. Give the Canvas worker's `node_modules/` branch the layout switch Main uses: in `dist/esm` it resolves under the emitted tree's `node_modules/`.
2. Emit declared `neo.canvasModules` roots through #20956's plan (`esmDestination()`), with their Engine edges rebased the way Main roots are.
3. Fail the build for a computed specifier whose root leaves `dist/esm`, instead of passing it because the directory exists. An absent root inside the tree keeps its current warning.

Decision Record impact: none.

## Acceptance Criteria

- [ ] A workspace declaring `neo.canvasModules` builds to `dist/esm`. The emitted Canvas worker loads the package module from `dist/esm/node_modules/<package>/…`, and that module reaches the emitted CoreBase: an identity read, not a mount.
- [ ] Source and webpack builds keep loading it from `node_modules/<package>/…`.
- [ ] A computed specifier whose root leaves `dist/esm` fails the build, naming the importer. An absent root inside `dist/esm` stays a warning.
- [ ] An undeclared package stays unadmitted.
