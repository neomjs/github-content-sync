# Neo.clone reads `deep` as ignoreNeoInstances and overflows on cycles

Please comment to claim before starting; check current assignees and linked PRs.

## Context

`Neo.clone(obj, deep=false, ignoreNeoInstances=false)` (`src/Neo.mjs:254`) calls `cloneMap[type](obj, deep, ignoreNeoInstances)`, but the instance branch is declared `NeoInstance(obj, ignoreNeoInstances)` (`src/Neo.mjs:32-34`), so it reads `deep` as `ignoreNeoInstances`. Measured on `dev` (`4d5236b292`) in Node with a `Neo.core.Base` instance `inst`:

| Call | JSDoc says | Today |
|---|---|---|
| `Neo.clone(inst, false, true)` | returns `inst` | creates a new instance (`neo-base-2`) |
| `Neo.clone({a: inst}, true, false)` | clones `inst` | keeps `inst` |
| `Neo.clone(cyclic, true)` | a deep copy | `RangeError: Maximum call stack size exceeded` |

## The Problem

- The instance branch decides on `deep`: an instance is cloned exactly when `deep` is false, whatever `ignoreNeoInstances` says.
- The reactive setter calls `Neo.clone(value, false, true)` for every config whose descriptor says `clone: 'shallow'` (`src/Neo.mjs:449-455`), such as `items_` in `collection/Base.mjs` and `container/Base.mjs` and four configs in `grid/Body.mjs`. Their values are arrays in the engine's own use, so nothing breaks yet; a `clone: 'shallow'` config holding an instance would get a new copy on every set.
- The deep walk (the `Array` and `Object` branches) keeps no record of what it already copied, so a cyclic input overflows the stack.

## The Architectural Reality

- 58 lines in `src/` call `Neo.clone(`, at least 29 of them with `deep: true` and the default `ignoreNeoInstances: false`. Those rely on today's behavior: a deep walk keeps the instances it meets, so a deep copy of a config never creates components or stores.
- `Neo.cloneNeoInstance` (`src/Neo.mjs:267`) builds the copy from `originalConfig`.
- No unit spec covers `Neo.clone` directly. `test/playwright/unit/collection/SorterPrecedence.spec.mjs:246` relies on the `clone: 'shallow'` path for arrays.

## The Fix

1. Declare the branch as `NeoInstance(obj, deep, ignoreNeoInstances)` and make the rule explicit: an instance is cloned only by a shallow clone with `ignoreNeoInstances` false. That keeps every current call's result except `(deep: false, ignoreNeoInstances: true)`, which then returns the instance, as documented.
2. Rewrite the JSDoc of `clone` to state the rule, including that a deep clone never clones the Neo instances it meets.
3. Give the deep walk a `WeakMap` from source to copy, so a cyclic input produces a copy with the same cycles.
4. Add a unit spec for `Neo.clone`: the four `(deep, ignoreNeoInstances)` combinations on an instance, nested instances under both values of `deep`, a cyclic object and a cyclic array, `Date`, `Map`, `Set`, and symbol keys.

## Acceptance Criteria

- [ ] `Neo.clone(inst, false, true) === inst`, and all four combinations match the rule in the new JSDoc.
- [ ] A deep clone of `a.self = a` returns `c` with `c !== a` and `c.self === c`; the same holds for a cyclic array.
- [ ] The PR lists the `Neo.clone(` call sites in `src/` whose result changes (expected: none, unless a `clone: 'shallow'` config holds an instance).
- [ ] The first two items are red on `dev` and green on the head (receipt in the PR); the unit tier passes: `npx playwright test -c test/playwright/playwright.config.unit.mjs`.

## Out of Scope

- `Map` and `Set` stay shallow under `deep: true` (`cloneMap.Map` says so); deep-copying their contents is a separate decision.
- Equality: #22385.
- What `cloneNeoInstance` copies.

## Avoided Traps

- Honoring `ignoreNeoInstances: false` inside deep walks: the call sites that deep-copy configs holding stores or components would start creating instances.
- `structuredClone`: it rejects functions and class instances, which configs carry.
