# Add buildScripts guard for CODING_GUIDELINES JSDoc and config rules

Design authority: `.github/CODING_GUIDELINES.md` (`§3` Rule 15, `§4` Rules 18 & 21, `§5` Rule 24, `§6` Rule 28, `§8` Class methods — extended in this PR for `#private` methods & `mergeConfig`, `§12` Compact JSDoc blocks `L563-671`), graduated `neomjs/neo#22305` (`DC_kwDODSospM4BMEUe`), `src/core/Base.mjs`, `src/core/Config.mjs:237`, `src/Neo.mjs:449`, and `buildScripts/util/check-class-module-scope.mjs`.

unowned-rationale: Maintainer self-select alongside the Engine best-practices enforcement collaboration (`@neo-gpt-emmy`, `@neo-fable-clio`, `@neo-gemini-maryam`) graduated from Discussion #22305.

## Context

Both `neomjs/neo#22257` (`CommandPalette`, closed `D+S`) and shipped v14 `src/gantt/*` (`11` files, #22306) passed every `.github/workflows/pr-baseline.yml` check (`check-class-module-scope`, `check-jsdoc-types`, `check-parse`, etc.) while violating deterministic, machine-checkable rules of `.github/CODING_GUIDELINES.md` and `Neo.core.Base` class/config hygiene. Worse, several of those violations **silently corrupt `docs/output/all.json` or seal extension seams** while keeping `npm run generate-docs-json` and unit tests green.

## The Problem

1. **Silent JSDoc metadata loss (`.github/CODING_GUIDELINES.md §12`, `L563-671`):**
   - `check-jsdoc-types.mjs` validates `{type}` Catharsis syntax only (`L9-24`) — it misses compact one-line `@member` blocks with array/object defaults (`→` empty default), compact blocks with a second tag (`@protected` / `@reactive` eaten into description), inline defaults with whitespace truncation, and separate `@default` lines on array/object `@member`s (publishes `/**` as default).
2. **`buildScripts/helpers/checkReactiveTags.mjs` is unwired and has a false-negative bug:**
   - Unwired from CI/`lint-staged`, requires `docs/output/all.json`, and checks `member.comment.includes('@reactive')` (`L124`) on the raw comment string — passing one-line `@reactive` docblocks where JSDoc ate `@reactive` into the description.
3. **Unchecked `static config`, `_vdom`, `#private` method, and leaf `mergeConfig()` invariants — plus missing `.github/CODING_GUIDELINES.md §8` lines (`D#22305#discussioncomment-19939646`):**
   - Nothing in `lint-staged` or `pr-baseline.yml` checks `static config` key ordering (Rule 21), missing `static config` JSDoc (Rule 18), redundant `tag: 'div'` in `_vdom` literals (Rule 24), `#private` methods on `Neo.setupClass` classes, or leaf-class `mergeConfig()` overrides (`only 4 base classes` in `src/` define `mergeConfig()`).
   - **Standalone contributor contract (`@neo-fable-clio` R2 tightening):** Today `.github/CODING_GUIDELINES.md §8` states the module-scope function rule (`check-class-module-scope.mjs`) but has **no written rule** for `#private` methods (including `src/core/Base.mjs:929` `#preDestroyHook`, which is intentionally `#private` to protect single-destroy invariants and must NOT be filed as burndown debt!) or 4-base `mergeConfig()` ownership. Adding both rules explicitly to `.github/CODING_GUIDELINES.md §8` in this same PR ensures every guard diagnostic points standalone contributors and maintainers to a real, readable line in the public guidelines.

## The Architectural Reality

- `buildScripts/util/check-class-module-scope.mjs` (`L51-64`) establishes the canonical Neo guard architecture: fast `acorn.parse(..., {locations: true, onComment})` scan over `SCAN_SURFACE = ['src/**/*.mjs', 'apps/**/*.mjs', 'examples/**/*.mjs', 'docs/app/**/*.mjs']`, exported pure analyzer function, symmetric ratcheted baseline JSON (`check-coding-guidelines-baseline.json`), and dual wiring in `package.json` `lint-staged` + `.github/workflows/pr-baseline.yml` (`check-guard-ci-parity.mjs` clean).
- **Five Mandatory Engine Passing Controls (`D#22305`):**
  1. **`#private` fields allowed (`core/Base.mjs:196-232`, `CODING_GUIDELINES.md:150` `#rippleTimeoutId`):** Only `MethodDefinition` `PrivateIdentifier`s (`#foo() {}`) are checked by `no-private-methods`.
  2. **Intentional non-replaceable base invariants allowed (`src/core/Base.mjs:929` `#preDestroyHook`):** A `#private` method whose JSDoc explicitly declares an un-overridable lifecycle invariant (e.g. `@invariant` / `core.Base#preDestroyHook` allowlist/marker documented in `CODING_GUIDELINES.md §8`) is **exempt by design**, never filed in the burndown baseline as tech debt.
  3. **One-way `local foo_ → @reactive` check (`src/app/content/Container.mjs:79-82`):** A subclass overriding an ancestor reactive config (`layout` overriding `container/Base.mjs:109` `layout_`, Rule 18) has no trailing `_` while carrying `@reactive` in JSDoc; the single-file AST check is strictly one-way (`locally declared trailing _ requires a standalone @reactive tag line`), and the diagnostic states explicitly that it checks the local direction only (`DC_kwDODSospM4BMEYL`).
  4. **Reactive array defaults allowed (`src/core/Config.mjs:237`, `src/Neo.mjs:449`):** Deep-cloned automatically on reactive `config_` properties.
  5. **Subclass plain-object overrides of ancestor `[isDescriptor]` configs allowed (`ConfigMerging.spec.mjs:89`).**

## The Fix

- `.github/CODING_GUIDELINES.md` — §8 `#private` method + `core.Base#preDestroyHook` invariant & 4-base `mergeConfig()` rules
- `buildScripts/util/check-coding-guidelines.mjs` — AST + JSDoc deterministic guard
- `buildScripts/util/check-coding-guidelines-baseline.json` — symmetric burn-down baseline
- `package.json` — npm script + `lint-staged` hook
- `.github/workflows/pr-baseline.yml` — CI baseline step
- `test/playwright/unit/buildScripts/checkCodingGuidelines.spec.mjs` — unit spec + passing controls
<!-- /binding-inventory -->

1. **Document `#private` method & `mergeConfig()` rules in `.github/CODING_GUIDELINES.md §8`:**
   - Add concise numbered rules to `§8 Class methods`: (a) class behavior lives in `@protected` / public methods replaceable by subclasses, mixins, and `Neo.overwrites` — a `#private` method is permitted only for an invariant no subclass may replace (such as `core.Base#preDestroyHook`), documented explicitly in its JSDoc; (b) `mergeConfig()` is owned exclusively by the four base classes (`core.Base`, `component.Base`, `container.Base`, `form.field.Text`) — subclasses declare `[isDescriptor]` entries in `static config` rather than overriding `mergeConfig()` or calling `this.mergeConfig()` in `construct()`.
2. **Create `buildScripts/util/check-coding-guidelines.mjs` (+ `check-coding-guidelines-baseline.json`):**
   - Check `{src,apps,examples,docs/app}/**/*.mjs` via `acorn` (`locations: true`, `onComment`), citing the exact `.github/CODING_GUIDELINES.md` section/rule in every diagnostic message:
     - **`compact-jsdoc-loss` (`§12`):** single-line `/** ... */` blocks with second `@` tags, inline array/object `=` defaults, or inline whitespace truncation; multiline array/object `@member` blocks using separate `@default` or inline whitespace.
     - **`local-reactive-tag` (`§5` Rule 18, strictly one-way):** locally declared `foo_` `static config` keys missing a standalone `@reactive` tag line (message notes local-direction scope per `DC_kwDODSospM4BMEYL`), plus missing JSDoc on `static config` entries.
     - **`static-config-order` (`§5` Rule 21):** `className`, `ntype`, alphabetical keys, `vdom`/`_vdom`.
     - **`redundant-vdom-div` (`§6` Rule 24):** literal `tag: 'div'` in `_vdom` / `vdom` / `itemTpl`.
     - **`no-private-methods` (`§8`):** `#private` `MethodDefinition`s on `Neo.setupClass` classes lacking the documented invariant exemption (`core.Base#preDestroyHook` exempt by design; existing ordinary debt in symmetric baseline; `#private` fields pass).
     - **`leaf-merge-config` (`§8`):** `mergeConfig` `MethodDefinition` outside `{src/core/Base.mjs, src/component/Base.mjs, src/container/Base.mjs, src/form/field/Text.mjs}` or `this.mergeConfig(...)` / `me.mergeConfig(...)` inside `construct()` outside `src/core/Base.mjs`.
3. **Wire into `package.json` (`scripts`, `lint-staged`) and `.github/workflows/pr-baseline.yml`** (`check-guard-ci-parity.mjs` clean) + add `test/playwright/unit/buildScripts/checkCodingGuidelines.spec.mjs`.

## Out of Scope

- Cross-file inheritance resolution (e.g. parent-default deduplication or ancestor-only `@reactive` configs in `src/gantt/*`), owned by semantic review (`neomjs/neo-agent-skills#479`).

## Avoided Traps

- **Enforcing `#private` method / `mergeConfig` rules in CI without writing them in `.github/CODING_GUIDELINES.md §8` (`D#22305#discussioncomment-19939646`):** Leaves standalone contributors facing a CI failure pointing to a section that says nothing about it, and wrongly classifies `core.Base#preDestroyHook` as burndown debt.
- **Reciprocal `@reactive → trailing _` enforcement in a single-file guard (`D#22305#discussioncomment-19939331`, `DC_kwDODSospM4BMEYL`):** Keep strictly one-way (`local foo_ → @reactive`) so `src/app/content/Container.mjs:79` and `src/gantt/*` ancestor overrides pass, and avoid enforcing Rule 30 `@param` prose without exempting standard `afterSet*(value, oldValue)` / `beforeSet*(value, oldValue)` config hooks.

**Three measured notes from the pass over `src/gantt` (PR #22317), all in the scope of this guard.**

1. **A `@reactive` rule that reads the local key sees half of what was missing.** Before the pass the docs output recorded no reactive tag on eleven configs of `Neo.gantt.*`. Five were one-line blocks with the tag on the same line, the case section 12 names. Five have no underscore in the local key and are reactive in an ancestor: `barMarginPct`, `minBarWidthPx` and `showNonWorkingTime` (`Neo.scheduler.Container`), and `fields` in both models (`Neo.data.Model`). One, `TaskStore.rollupParents_`, carried the tag at the end of a description line inside a multi-line block, which loses it the same way. Two consequences: the rule should catch a tag anywhere but at the start of its line, in every block; and its message should say that it checks the local direction, with `npm run check-reactive-tags` as the cross-class check.
