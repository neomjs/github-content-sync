# Re-anchor Portal, learn, blog, and example titles and H1s to search intent

## Context

Across the last 28 days (`2026-10-14` – `2026-11-10`), `sc-domain:neomjs.com` recorded **`0` named non-brand clicks** (`19` total non-brand impressions across `/learn/`, `/news/blog/`, and `/examples/` combined). Auditing all `316` core non-release routes in `neomjs/neo` shows **`0` `<title>` or `<h1>` tags** containing the plain-English problem terms developers actually search.

`unowned-rationale: Open for maintainer self-selection in coordination with #20682 (Home section steward @neo-fable-clio); good first issue omitted because front-door positioning requires cross-epic alignment.`

## The Problem

1. **Zero developer keyword-intent coverage in `<title>` and `<h1>`:**
   - Across all `316` core non-release routes (`origin/dev` @ `a07f581f13`, `apps/portal/resources/data/seo.json` + `learn/tree.json` + `blog.json` + `{apps,examples}/**/index.html`; positive control: `"Multi-Threaded"` matches `68` `seo.json` titles):
     - Exact `"JavaScript data grid"` in `<title>` or `<h1>`: **`0`** (`1` body hit)
     - `"100k rows"` / `"100,000 rows"` in `<title>` or `<h1>`: **`0`** (`6` body hits)
     - `"virtual scrolling"` in `<title>` or `<h1>`: **`0`** (`2` body hits)
     - `"Web Worker"` (any casing) in `<title>` or `<h1>`: **`0`** (`24` body hits)
     - `"OffscreenCanvas"` in SSR `<title>` or `<h1>`: **`0`** (`examples/component/canvas/index.html` `<title>Neo OffscreenCanvas</title>` is overwritten to `"Component Canvas"` by SSR fallback)
     - `"GitHub Workflow MCP"` / `"Live Browser DOM MCP"` in `<title>` or `<h1>`: **`0`**
2. **Homepage `/` `seo.json` gap, `5` `<h1>` tags, and off-domain link leaks:**
   - `apps/portal/resources/data/seo.json` lacks a canonical `'/'` entry (only `'/home'` with `"Neo.mjs — Home"`), causing SSR to fall back to generic `"Neo.mjs — Home"` instead of deriving from `apps/portal/index.html` (whose `<title>` and `<meta name="description">` belong to the ADR 0018 §2.3 `"an agent institution"` lead cluster governed by `/neo-identity-update` and `#20682`). Meanwhile portal section routes (`/examples`, `/docs`, `/learn`, `/news/blog`) serve generic labels (`"Neo.mjs — Examples"`, `"Neo.mjs — Learn"`).
   - Live `/` renders **`5` separate `<h1>` tags** (`Neo.mjs` + section headings), navbar links Home to `/home` instead of `/`, and `apps/portal/view/home/parts/Colors.mjs:28` links `"Learn More"` off-domain to `itnext.io`.
3. **Vague `<h1>` stems in `/learn/*` bypass or dilute section suffixes (#20715):**
   - Pages such as `/learn/benefits/body/WhyEnhance` (`<h1>Why Enhance? A Look Beyond Incremental Improvements</h1>` > 45 chars -> skips qualifier suffix completely!), `/learn/benefits/body/Speed` (`Extreme Speed`), `/learn/guides/datahandling/GridContainer` (`The Grid Container`), and `/learn/agentos/NeuralLink` (`Neural Link: The Possession Interface`) lead with internal metaphors instead of searchable engineering problems.

## The Architectural Reality

`Design authority: "Every canonical route in sitemap-core.xml — home, /learn/* guides, /examples/* component-family overviews (#20498), /news/blog/*, /news/releases/*, and /apps/* — resolves a distinct, non-generic <title>, <meta name=\"description\">... naming the engineering capability the page proves."` (#20671 Intended solution shape §1). Putting unsearched coined metaphors in `<title>` / `<h1>` while keeping searchable terms in body prose inverts search packaging: `<title>` and `<h1>` must name the developer's problem in plain terms, while body prose teaches Neo's coined architecture (`Application Engine`, `Object Permanence`, `Neural Link`, `Model Experience`), and root `/` `<title>` / `<meta name="description">` derive at build time from `apps/portal/index.html` per ADR 0018 §2.3–§2.4.

## The Fix

1. **Homepage `/` build-time derivation, portal section metadata, single-`<h1>` hierarchy, & internal link hygiene (`seoJson.mjs`, `apps/portal/resources/data/seo.json`, `apps/portal/view/home/**`, `apps/portal/view/HeaderToolbar.mjs`):**
   - Derive `seo.json['/']` and `seo.json['/home']` at build time directly from `apps/portal/index.html` (`ADR 0018 §2.4` Preference #1, eliminating `"Neo.mjs — Home"` while keeping ADR 0018 §2.3 root copy governed by `#20682` / `/neo-identity-update`), and upgrade non-identity portal section routes (`/examples`, `/docs`, `/learn`, `/news/blog`) to developer search-intent `<title>`s and `<meta name="description">`s naming Web Workers, `SharedWorker` multi-window apps, `100k+`-row Data Grids, OffscreenCanvas, and AI Agent OS / MCP tools.
   - Demote secondary homepage section `<h1>`s to `<h2>` so `/` carries exactly `1` `<h1>`.
   - Point header Home navigation to `/` (not `/home`) and route homepage `Colors.mjs` `"Learn More"` CTA to canonical `/learn/benefits/body/MultiWindow` instead of `itnext.io` (leaving `AiToolchain.mjs`'s 5 Brain repo links intact until `#20920` mirrors Brain docs onto `neomjs.com`).
2. **Search-intent `<title>` & `<h1>` upgrades across high-value `/learn/*`, `/news/blog/*`, and `/examples/*` routes (`learn/**/*.md`, `seoJson.mjs`):**
   - Support explicit frontmatter `seoTitle` / `seoDescription` overrides in `extractMarkdownSeoMetadata` (`seoJson.mjs`) so blog posts and guides keep expressive editorial `<h1>`s when desired while serving search-intent `<title>`s (e.g. `a-data-grid-in-a-web-worker` `<title>`: `JavaScript Data Grid in a Web Worker: 100k+ Rows Off the Main Thread | Neo.mjs`).
   - Update vague `<h1>`s / `seoTitle`s on core engine & Agent OS guides (`GridContainer`, `Grids`, `PooledGridAnimation`, `OffTheMainThread`, `MultiWindow`, `CanvasArchitecture`, `WhyEnhance`, `NeuralLink`) and key standalone examples (`examples/grid/bigData/index.html`, `examples/component/canvas/index.html`) so `"JavaScript Data Grid"`, `"100k Rows"`, `"Virtual Scrolling"`, `"Web Worker"`, `"SharedWorker"`, `"Multi-Window JavaScript Apps"`, `"OffscreenCanvas"`, and `"Live Browser DOM MCP"` appear in `<title>` / `<h1>`.

## Acceptance Criteria

- [ ] `seoJson.mjs` derives `seo.json['/']` and `seo.json['/home']` at build time from `apps/portal/index.html` (eliminating `"Neo.mjs — Home"` while preserving ADR 0018 §2.3 root `<title>` and `<meta name="description">` for `#20682`), upgrades `/examples`, `/docs`, `/learn`, and `/news/blog` section metadata, and rendered `/` contains exactly `1` `<h1>`.
- [ ] `seoJson.mjs` supports frontmatter `seoTitle` / `seoDescription` overrides and emits explicit developer search-intent `<title>`s across flagship Grid, Web Worker, SharedWorker, Multi-Window, OffscreenCanvas, and Neural Link / MCP routes (`>= 12` target routes verified by unit spec).
- [ ] Portal header Home navigation links to `/` rather than `/home`, and `Colors.mjs` no longer leaks its primary `"Learn More"` CTA to `itnext.io`.
- [ ] `node buildScripts/docs/seo/verify.mjs` and SEO / portal / markdown unit specs pass cleanly.

## Out of Scope

- Redesigning the visual layout, narrative prose, or ADR 0018 §2.3 `"an agent institution"` root lead cluster of the Home view (`#20682` / `/neo-identity-update`).
- New component-family overview pages and comparison guides (tracked in `#20498` and `#20918`).

## Avoided Traps

- **Erasing Neo's identity in body copy or reversing ADR 0018 §2.3:** Keep `Agent Institution`, `Application Engine`, `Object Permanence`, `Neural Link`, and `MX Loop` strong in hero/body prose and leave `apps/portal/index.html`'s ADR 0018 §2.3 lead cluster untouched for `#20682` — derive `seo.json['/']` from `apps/portal/index.html` at build time so SSR and static head cannot drift.
