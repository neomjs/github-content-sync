# A timeline family: one time axis for time-based views

## Context

Leaf of #20874. It adds the shared base of the scheduler and the Gantt, and later of the calendar's week view.

## The Problem

The engine has no shared way to map time to pixels. The calendar carries its own scale inside its views, and any new time-based view would write a third. Overlap packing and time-aware dragging exist nowhere as reusable parts.

## The Architectural Reality

- The time axis is a plain `Neo.core.Base` scale with no DOM reads: start, end, tick unit and step, snapping, pixels per minute, and a working calendar (non-working weekdays and dates) with working-time arithmetic.
- The timeline column plugs into the multi-body grid (`src/grid`); the header renders the axis' ticks.
- The drag zone extends `Neo.draggable.DragZone` and commits a move or a resize as one `record.set`.
- The event model and store are `data.Model` and `data.Store` (`id`, `startDate`, `endDate`, `title`, `description`, `allDay`, `resourceId`), sorted by start.
- Placement inside `src/timeline` (for example `model`, `store`, `draggable`, `util` subfolders as in `src/calendar`) is decided by the structural pre-flight in the pull request.
- Styles under `resources/scss/src/timeline` plus theme folders; this leaf brings the two neo themes.
- Guards: file size (1,000 code lines), ticket archaeology, class-module-scope lint, JSDoc with `@summary`.

## The Fix

Add the family under `Neo.timeline`: the time axis, its header, the timeline column, an interval packer (lanes for overlapping intervals), an event drag zone (move and resize, horizontal or vertical), an event editor, and the event model and store. The implementation exists and lands in one pull request with its unit specs and its styles.

## Acceptance Criteria

- [ ] The classes exist under `Neo.timeline` and appear in the output of `npm run generate-docs-json`.
- [ ] The family's unit specs pass in the engine's unit configuration, including the working-calendar arithmetic across a weekend and a daylight-saving change.
- [ ] No module of the family reads the DOM to compute a date or an offset.
- [ ] A bar can be marked through the column config `highlightedRecordIds`. The class and the data attribute it renders are named for that state (`highlighted`) and for no particular analysis; which bars are marked is the business of the caller.
- [ ] Styles exist for `theme-neo-dark` and `theme-neo-light`.
- [ ] The file-size, ticket-archaeology and lint guards pass.

## Out of Scope
