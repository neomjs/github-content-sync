# Render Neo.app.content.Container main article before sidenav in DOM order

## Context

Live `Googlebot/2.1` inspection of `neomjs.com` content routes on 2026-11-14 shows that `Neo.app.content.Container` renders the full sidenav tree (`<aside>`) before the primary page content in DOM order, pushing the article `<h1>` to byte `59,912`–`76,924` (`36%–47%` of the HTML document) with zero `<main>` landmark tags.

`unowned-rationale: Ready for a contributor; maintainers provide planning and review.`

## The Problem

Because `src/app/content/Container.mjs` (`origin/dev` @ `a07f581f13`) declares `'sidenav-container'` (`weight: 10`, `tag: 'aside'`), `splitter` (`weight: 20`), and `pageContainer` (`weight: 30`, default `div` tag in `src/app/content/PageContainer.mjs`), every `/learn/*` and `/news/*` route renders hundreds of sidebar navigation items before the page's own `<h1>` and prose:

- `https://neomjs.com/learn/benefits/ArchitectureOverview` (`127,601` B, `Googlebot/2.1` fetch 2026-11-14): `0` `<main>` tags; `<h1>` at byte `59,912` after `130` `<a href>` links, `142` `<li>` nodes, and `445` identical sidebar words.
- `https://neomjs.com/news/releases/13.4.0` (`214,511` B, `Googlebot/2.1` fetch 2026-11-14): `0` `<main>` tags; `<h1>` at byte `76,924` after `186` `<a href>` links and `178` `<li>` nodes.

While Googlebot's 15 MB parser still reaches `<article>`, placing `130–186` boilerplate links and `445` identical words ahead of `<article>` with no `<main>` landmark dilutes contextual link equity, degrades passage/snippet salience (`43` core routes sit in GSC `Crawled - currently not indexed`), and forces screen-reader / keyboard traversal through the entire tree before reaching the page heading unless visual order is decoupled from DOM order.

## The Architectural Reality

`Design authority: none found (searched: src/app/content/Container.mjs, src/app/content/PageContainer.mjs, resources/scss/src/app/content/Container.scss, and ask_knowledge_base on "Neo.app.content.Container sidenav weight DOM order").` `src/app/content/Container.mjs:31-75` uses `layout: {ntype: 'hbox', align: 'stretch'}` and relied on item `weight` (`10, 20, 30, 40`) solely to achieve left-to-right visual order `[sidenav | splitter | pageContainer | page-sections]` and `splitter.resizeTarget: 'previous'`.

## The Fix

1. **Add semantic `<main>` landmark (`src/app/content/PageContainer.mjs`):**
   - Configure `tag: 'main'` on `Neo.app.content.PageContainer` so every `Neo.app.content.Container` consumer (`Portal.view.learn.MainContainer`, `Portal.view.news.MainContainer`, etc.) emits `<main class="neo-app-content-page-container ..."><article ...>...</article><nav ...>...</nav></main>`.
2. **Render `pageContainer` first in DOM order while keeping visual left-to-right layout (`src/app/content/Container.mjs` + `resources/scss/src/app/content/Container.scss`):**
   - Update item `weight` in `Neo.app.content.Container` so `pageContainer` (`<main>`) mounts **first** in VDOM/DOM (`weight: 10`), followed by `page-sections-container` (`weight: 20`), `splitter` (`weight: 30`), and `'sidenav-container'` (`<aside>`, `weight: 40`).
   - Set explicit CSS Flexbox `order` rules in `resources/scss/src/app/content/Container.scss` (`sidenav-container { order: 1; }`, `main-content-splitter { order: 2; }`, `neo-app-content-page-container { order: 3; }`, `page-sections-container { order: 4; }`) so visual desktop and `x-small` mobile drawer presentation remain pixel-identical.
   - Verify `Neo.component.Splitter` resize direction (`resizeTarget` / drag delta sign when `'sidenav-container'` follows `splitter` in DOM order vs visual order, or target `'sidenav-container'` explicitly) so dragging the splitter widens/narrows `'sidenav-container'` identically to `origin/dev`.

## Acceptance Criteria

- [ ] `Neo.app.content.PageContainer` renders with `<main>` (`tag: 'main'`), giving `/learn/*` and `/news/*` routes `1` `<main>` landmark wrapping `<article>`.
- [ ] In `Neo.app.content.Container`'s rendered VDOM/DOM, `pageContainer` (`<main>`) precedes `'sidenav-container'` (`<aside>`), placing the article `<h1>` ahead of the sidenav tree in HTML byte order.
- [ ] Visual left-to-right order (`[sidenav-container | splitter | pageContainer | page-sections-container]`), `x-small` responsive sidenav toggle overlay behavior, and `main-content-splitter` drag-resizing width behavior match `origin/dev` (`getBoundingClientRect` verified in Playwright).
- [ ] Targeted Playwright specs pass (`npx playwright test --config buildScripts/playwright/playwright.config.unit.mjs` on new/updated `test/playwright/unit/app/content/Container.spec.mjs`).

## Out of Scope

- Trimming the number of expanded `<a href>` links injected by `neomjs/middleware-v2` `SsrService` (tracked in `neomjs/middleware-v2`).
- Changing Portal visual styling, widths, or typography.

## Avoided Traps

- **Breaking `Neo.component.Splitter` drag math:** `Splitter` (`src/component/Splitter.mjs`) resolves `previousSibling` / `nextSibling` in the `items` array; reordering `items` without updating `resizeTarget` (`'next'` vs `'previous'` or explicit sibling resolution) will invert or break splitter resizing unless tested with real bounding rects.
- **Running bare `npx playwright test`:** Always pass Neo's explicit unit/component config (`buildScripts/playwright/...`).
