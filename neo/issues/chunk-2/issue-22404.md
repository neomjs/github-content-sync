# Recognize tap, repeated tap and press without double activation

## Context

Neo already delivers click, double-click and context-menu events through [DomEvent](https://github.com/neomjs/neo/blob/5ff17dedc8/src/manager/DomEvent.mjs). Its [drag sensor](https://github.com/neomjs/neo/blob/5ff17dedc8/src/main/draggable/sensor/Pointer.mjs#L110) holds a touch before starting a drag. Adding independent recognizers can otherwise fire both default activation and an app action, or commit a pending press after cancel.

## The Fix

Implement the ADR's opt-in tap and press recognitions on the shared Main contact owner, including declared tap count or simultaneous-contact policy. Coordinate motion thresholds, hold timing, release and cancellation with the existing delayed drag and browser context menu. Native links and buttons retain one activation.

## Acceptance Criteria

- [ ] AC-1 Demonstrate single/repeated/chorded tap with the configured contact count and a real button/link. One ordinary tap produces exactly one native activation.
- [ ] AC-2 A press starts after the configured hold and reports its release. Moving past threshold, losing ownership or canceling before timeout prevents a late commit. Cover press competing with hold-to-drag and context menu.
- [ ] AC-3 Keyboard and visible mechanisms retain access to the same application action. Tests exercise the actual per-node listener API.
