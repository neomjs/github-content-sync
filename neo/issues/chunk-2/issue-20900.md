# A floating tab overflow button can mount twice on the mobile Portal

## The problem

At a 390 × 300 viewport, opening Examples, expanding to desktop, and returning to News on mobile can leave two “More tabs” buttons with the same DOM ID. The strict locator in `NewsTabOverflow.spec.mjs:75` caught this on [the Scheduler run](https://github.com/neomjs/neo/actions/runs/43482878071/job/132083737687) and on [two](https://github.com/neomjs/neo/actions/runs/43496333649/job/132130373074) [Gantt runs](https://github.com/neomjs/neo/actions/runs/43496333649/job/132134517793) on the same commit.

## The architectural reality

`src/tab/plugin/Overflow.mjs#syncControl` starts the floating button with automatic mounting, then can call `initVnode(true)` when the button is still unmounted. The re-arm flag tracks only the latter call. `isVnodeInitializing` excludes theme deferral and the wait for the main-thread insertion. The existing remount tests start with an already-created control. These paths explain a possible duplicate insert. Prove the overlapping first and second attempts before changing the owner.

## Acceptance criteria

- [ ] Delay the first floating button’s mount, request another projection, and verify exactly one mount/insert for the same control ID. Retain recovery after a failed attempt and a later genuine unmount.
- [ ] Retiring the control while its mount is pending leaves no orphan and no stale latch on its replacement.
- [ ] Run the mobile Examples/News/desktop Portal test with its strict selector, and run the existing Overflow unit tests.

Scope is the shared tab overflow plugin and its control lifecycle. Preserve ordinary toolbar action contributions. Related: #16434 established remount recovery; #17980 covered tab-bar children during reconciliation. The latest 20 open issues and a closed More-tabs/floating search showed no equivalent among 40 open issues. I will take this repair because it blocks the public Gantt review.
