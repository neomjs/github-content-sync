# Adopt the verified merge base in Engine PR guards

## Context

Engine still calls the shared PR baseline at `v2.10.0`. [Skills #486](https://github.com/neomjs/neo-agent-skills/pull/486) shipped the checkout-parent fix in `v2.11.1`. The GitHub tag and npm metadata both point to `c3b2a52b5a`.

## The Problem

On [Engine #22111](https://github.com/neomjs/neo/pull/22111), the old caller judged a docs-only PR against an event base older than the actual merge checkout. Its [guard job](https://github.com/neomjs/neo/actions/runs/45939026740/job/140308794757) charged inherited `src/main/DomAccess.mjs` growth to the PR.

## The Architectural Reality

Design authority: "Callers own only their event trigger and a published release tag". [Reusable baseline](https://github.com/neomjs/neo-agent-skills/blob/v2.11.1/.github/workflows/reusable-pr-baseline.yml#L3-L6)

The baseline reads its own guard package version from its published workflow commit. The Engine npm installation and materializer run separately. The Engine owns the caller pin and the file-size guard commands.

## The Fix

Move only the Engine PR baseline caller to Skills `v2.11.1`. Keep the declared guard commands and existing event set.

## Acceptance Criteria

- [ ] The Engine caller resolves to `v2.11.1` and its three hosted baseline contexts pass at the adoption PR head.
- [ ] The hosted guards job logs a two-parent merge matching the event head and passes the verified first parent to the declared guards.
- [ ] Replay the historical candidate with both bases. The released approach accepts inherited growth, and a PR-growth control still fails without its declaration.

## Post-Merge Validation

- [ ] On the next suitable same-head body edit with a genuinely stale event base, record the emitted checkout parent and the hosted guard result.

## Out of Scope

The article’s editorial review, Engine’s installed Skills package, the other reusable workflow pins, and file-size policy.
