# GridHorizontalScrollSync: sync --grid-scroll-left onto follower rows outside grid.body

## Context

`Neo.main.addon.GridHorizontalScrollSync` keeps a grid's centre body, centre header toolbar, and centre header-group row aligned with the horizontal scrollbar in the same animation frame on the main thread (`src/main/addon/GridHorizontalScrollSync.mjs:68-84`). A grid plugin or subclass that mounts a fixed summary or footer row outside `grid.body` (for example inside `grid.ariaWrapper` below `grid.view`) currently has no slot in `GridHorizontalScrollSync` to receive that main-thread `--grid-scroll-left` update.

## The Problem

Because `GridHorizontalScrollSync#onScroll` writes `--grid-scroll-left` only onto `registration.bodyId` (`grid.body.id`), an auxiliary centre row mounted outside `grid.body` can only observe `scrollManager.scrollLeft` in the App worker and push a VDOM style update back to the main thread. In still frames the row aligns with the centre columns, while during active horizontal scrolling it trails `grid.body` and `headerToolbar` by one worker round trip.

## The Architectural Reality

- `Neo.grid.ScrollManager#updateGridHorizontalScrollSyncAddon` (`src/grid/ScrollManager.mjs:385-412`) registers `{id, scrollerId, bodyId, viewId, headerId, groupHeaderId, windowId}` once when `ScrollManager` mounts (and re-registers across `windowId` moves in `afterSetWindowId`, `:151-164`).
- `Neo.main.addon.GridHorizontalScrollSync#onScroll` (`src/main/addon/GridHorizontalScrollSync.mjs:68-84`) synchronously updates `bodyNode.style.setProperty('--grid-scroll-left', scrollLeft + 'px')`, `headerNode.scrollLeft = scrollLeft`, and `groupHeaderNode.scrollLeft = scrollLeft` in the same main-thread `scroll` frame.
- `Body.scss` (`resources/scss/src/grid/Body.scss:111-113`) translates `.neo-grid-cell:not(.neo-locked-start):not(.neo-locked-end)` by `calc(var(--grid-scroll-left, 0px) * -1)`. In a multi-body grid (`bodyStart`, `body`, `bodyEnd`), setting `--grid-scroll-left` on `grid.ariaWrapper` or `grid.id` would leak into `bodyStart` and `bodyEnd` cells that lack `.neo-locked-start` / `.neo-locked-end`, so explicit centre-part node targeting (matching `bodyId` and `groupHeaderId`) preserves multi-body isolation.
- Auxiliary summary or footer rows can mount and unmount dynamically during a grid's lifetime (for example when a plugin toggles summary mode), just as `groupHeaderId` comes and goes with header groups (`#20379`).

## The Fix

1. Add a follower-id seam on `Neo.grid.ScrollManager` (for example `registerHorizontalScrollFollower(nodeId)` / `unregisterHorizontalScrollFollower(nodeId)`, or an observable `horizontalScrollFollowerIds` set passed to `GridHorizontalScrollSync#register` / updated via a lightweight addon method) for centre-region DOM nodes outside `grid.body` that consume `--grid-scroll-left`.
2. In `Neo.main.addon.GridHorizontalScrollSync#onScroll`, iterate any registered `followerIds` alongside `bodyId` and call `node.style.setProperty('--grid-scroll-left', scrollLeft + 'px')` in the same animation frame, skipping ids whose DOM node is not currently mounted (`DomAccess.getElement(id)`) and seeding the current `scrollerNode.scrollLeft` on registration so followers joining mid-scroll align immediately.
3. Preserve symmetric cleanup in `ScrollManager#afterSetMounted`, `ScrollManager#afterSetWindowId`, and `GridHorizontalScrollSync#unregister`.

## Acceptance Criteria

- [ ] A centre-region element registered outside `grid.body` receives `--grid-scroll-left` in the same main-thread `onScroll` turn as `grid.body`, including when registered while `scrollerNode.scrollLeft > 0`.
- [ ] Unregistering a follower or unmounting the grid leaves no stale listener or registration entry, and `afterSetWindowId` carries active followers to the new window's addon registration.
- [ ] Locked `bodyStart` and `bodyEnd` cells remain unaffected (`--grid-scroll-left` is not inherited by locked bodies).
- [ ] Unit coverage in `test/playwright/unit/grid/` and a browser E2E scroll check verify zero-lag `--grid-scroll-left` parity between `grid.body` and the registered follower node.

## Out of Scope

- Built-in summary or aggregation calculation inside `Neo.grid.Container`.
- Vertical scroll synchronization (auxiliary summary/footer rows sit outside `grid.view`'s vertical scrollport by design).

## Avoided Traps

- **Writing `--grid-scroll-left` onto `grid.ariaWrapper` or `grid.id`:** CSS custom properties inherit into `bodyStart` and `bodyEnd`, whose cells match `.neo-grid-cell:not(.neo-locked-start):not(.neo-locked-end)` in multi-body mode and would shift horizontally out of their locked regions.
- **Syncing via `scrollManager.scrollLeft` in the App worker:** requires a main → App → VDom → main round trip, causing visible 1-frame lag during horizontal flicks while preserving `saveScrollPosition` / VDOM rebuild hazards if not coordinated with VDOM style persistence (`#20501`).
