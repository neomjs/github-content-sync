# Serve minified HighlightJs, unify line numbers & fix source escaping

Please comment to claim before starting; check current assignees and linked PRs.

## Context

Implements converged **Option `2c` (`Minify All 10 Languages & Consolidate Gutter`)** from the `14.1` read-only code preview investigation in #22240 ([measured report `#22240#issuecomment-7198610079`](https://github.com/neomjs/neo/issues/22240#issuecomment-7198610079)), scheduled for post-`14.1` delivery per `ROADMAP.md`. Editable previews continue to use Monaco and `LivePreview`.

## The Problem

Measured against `dev` (`45513a78ef`, `highlight.js@11.12.0`, `highlightjs-line-numbers.js@2.9.1`, Chromium `1440×900` cold cache):

1. **Unminified bundle served on every cold load:** `src/util/HighlightJs.mjs:20` sets `debug: true` with zero production overrides. Every cold Learn and Docs load fetches `dist/highlight/highlight.custom.js` (`140,380 B` raw / `36,619 B` gzip) instead of `dist/highlight/highlight.custom.min.js` (`71,092 B` raw / `21,286 B` gzip / `18,899 B` brotli), even though `npm run build-highlightjs` already produces both files (`#21211`).
2. **Broken newline regex, multiline `<span>` splitting, and duplicate line-number plugin:**
   - `src/util/HighlightJsLineNumbers.mjs:5` defines `lineRegex = /\\r\\n|\\r|\\n/g` (double-escaped backslashes), so `'a\nb\nc'.split(lineRegex)` returns `1` line instead of `3`.
   - Splitting highlighted HTML on newlines without balancing open `<span class="hljs-...">` tags breaks multi-line `/* ... */` JSDoc comments and template literals across `<tr><td>` boundaries.
   - `src/main/addon/HighlightJS.mjs:28,95` loads classic `node_modules/highlightjs-line-numbers.js/dist/highlightjs-line-numbers.min.js` (`3,288 B` raw / `1,549 B` gzip) via `<script>` instead of sharing `Neo.util.HighlightJsLineNumbers`.
3. **Raw HTML injection strips `<Generic>` types and markup in source views:** `docs/app/view/classdetails/SourceViewComponent.mjs:138` (`node.cn[0].html = data`) and `examples/component/toast/MainContainerController.mjs:59` (`oVdom.html = output.itemTpl(values)`) assign raw source to `innerHTML` before `HighlightJS#syntaxHighlight` reads `node.textContent`. Browser HTML parsing strips `<Boolean>` in `@returns {Promise<Boolean>}` and `<tag>` literals in templates, and decodes `&amp;` to `&`.
4. **WCAG 2.1 AA (`4.5:1`) contrast gaps in light and classic-dark highlight palettes:**
   - `resources/css/theme-light/util/HighlightJs.css`, `resources/css/theme-neo-light/util/HighlightJs.css`, and `resources/lib/highlightjs-custom-github-theme.css` (`#fff` background): `comment` (`#998`, `2.89:1`), `meta` (`#999`, `2.85:1`), and `.hljs-ln-numbers` (`rgba(27,31,35,.3)`, `1.97:1`) fail `4.5:1`.
   - `resources/css/theme-dark/util/HighlightJs.css` and `resources/lib/highlightjs-custom-dark-theme.css` (`#2b2b2b` background): `comment` (`#808080`, `3.59:1`), `string` (`#6a8759`, `3.52:1`), `keyword` (`#cc7832`, `4.25:1`), and `.hljs-ln-numbers` (`#606366` on `#303335`, `2.10:1`) fail `4.5:1` (`theme-neo-dark` passes all tokens at `>= 6.15:1`).

## The Architectural Reality

- `src/util/HighlightJs.mjs` owns dynamic ESM loading of `dist/highlight/highlight.custom(.min).js` (`getBundlePath()`, `load()`) for both worker (`Neo.component.Markdown`) and main-thread (`Neo.main.addon.HighlightJS`) consumers. All 10 grammars in `buildScripts/build/highlightJs.mjs` (`bash`, `css`, `javascript`, `json`, `markdown`, `plaintext`, `ruby`, `scss`, `xml`, `yaml`) stay registered because `highlight.js/lib/languages/yaml.js` delegates `<% ... %>` ERB blocks via `subLanguage: 'ruby'` (`+1,202 B` gzip over 9 grammars).
- `src/util/HighlightJsLineNumbers.mjs` owns `<table class="hljs-ln">` generation with `[data-line-number="N"]` cells consumed by `HighlightJS#syntaxHighlightLine` (`src/main/addon/HighlightJS.mjs:189-220`).
- `src/main/addon/HighlightJS.mjs` sets `preloadFilesDelay: false` (`src/main/addon/Base.mjs:93-98`), so listing `"HighlightJS"` in `apps/portal/neo-config.json` registers the App-worker remote proxy for `#/docs` without triggering `loadFiles()` on cold Home or Learn boots.
- `Design authority: "The Neo.config.basePath-relative bundle {@link #load} imports, chosen by debug."` (`src/util/HighlightJs.mjs:50`), `"Node.js-capable version of: https://github.com/yauhenipakala/highlightjs-line-numbers.js"` (`src/util/HighlightJsLineNumbers.mjs:8`), and `"Waits for mount and source publication before highlighting the rendered code leaf."` (`docs/app/view/classdetails/SourceViewComponent.mjs:129`).

## The Fix

1. **`src/util/HighlightJs.mjs`:** Change `debug: true` to `debug: false` so consumers load `dist/highlight/highlight.custom.min.js` unless `HighlightJs.debug = true` is explicitly configured; keep both bundle variants load-bearing in `test/playwright/unit/util/HighlightJs.spec.mjs`.
2. **`src/util/HighlightJsLineNumbers.mjs`:** Fix `lineRegex` to `/\r\n|\r|\n/g` and balance open `<span ...>` tags across line splits (closing open spans at each line end and reopening active spans on the next line) while preserving exact `.hljs-ln`, `.hljs-ln-numbers`, `.hljs-ln-code`, and `data-line-number` markup.
3. **`src/main/addon/HighlightJS.mjs` & `package.json`:** Replace the classic `highlightJsLineNumbersPath` `<script>` load and `hljs.lineNumbersBlockSync` / `hljs.lineNumbersBlock` calls with `HighlightJsLineNumbers.addLineNumbers(node.innerHTML, data.windowId)` (retaining `globalThis.hljs = HighlightJs.hljs` and explicit `highlightJsPath` override support). Remove `highlightjs-line-numbers.js` from `package.json` / `package-lock.json` and update `test/playwright/unit/buildScripts/fixtures/neoAppPackage.json` if guarded, `test/playwright/unit/main/addon/HighlightJS.spec.mjs`, and `test/playwright/e2e/portal/HighlightJsResources.spec.mjs:45`.
4. **`docs/app/view/classdetails/SourceViewComponent.mjs:138` & `examples/component/toast/MainContainerController.mjs:59`:** Publish raw code via `.text = ...` instead of `.html = ...` before calling `syntaxHighlight()`.
5. **Contrast tokens (`resources/css/theme-{light,neo-light,dark}/util/HighlightJs.css`, `resources/css/theme-{light,neo-light,dark}/util/HighlightJsLineNumbers.css`, `resources/lib/highlightjs-custom-{github,dark}-theme.css`):** Raise `comment`, `meta`, `string`, `keyword`, and `.hljs-ln-numbers` foreground contrast to WCAG 2.1 AA (`>= 4.5:1`) against their declared code backgrounds, then run `npm run build-themes`.

## Acceptance Criteria

- [ ] `Neo.util.HighlightJs.debug` defaults to `false`; cold Learn and Docs views load `dist/highlight/highlight.custom.min.js`, while `HighlightJs.debug = true` still loads `dist/highlight/highlight.custom.js` (`HighlightJs.spec.mjs` green).
- [ ] `Neo.util.HighlightJsLineNumbers` splits `\n` and `\r\n` lines accurately and preserves open `<span class="hljs-...">` classes across multi-line comments and template literals (`HighlightJsLineNumbers.spec.mjs`).
- [ ] `Neo.main.addon.HighlightJS` formats line numbers through `HighlightJsLineNumbers` with zero requests to `highlightjs-line-numbers.min.js`, and `highlightjs-line-numbers.js` is removed from `package.json` / `package-lock.json`.
- [ ] `SourceViewComponent` and the Toast example render `@returns {Promise<Boolean>}`, `<div class="probe">&amp;</div>`, and template literals verbatim without stripping `<Boolean>` or HTML tags, and copying code omits line numbers while matching raw source text.
- [ ] Highlight token colors (`comment`, `meta`, `string`, `keyword`, `.hljs-ln-numbers`) achieve `>= 4.5:1` contrast against their code block background in `neo-light`, `light`, `dark`, and `neo-dark`.
- [ ] `DocsMixinsNL.spec.mjs`, `HighlightJsResources.spec.mjs`, `GlobalTypographyNesting.spec.mjs`, and relevant unit tests pass via Neo's explicit Playwright configs (`npx playwright test --config=test/playwright/playwright.config.unit.mjs ...` — never bare `npx playwright test`).

## Out of Scope

- Replacing Highlight.js with a custom tokenizer or Shiki, or using Monaco for read-only fences (evaluated and rejected in `#22240#issuecomment-7198610079`).
- Trimming the 10-language list in `buildScripts/build/highlightJs.mjs` (`yaml` delegates embedded ERB to `ruby`).
- Removing `"HighlightJS"` from `apps/portal/neo-config.json` `mainThreadAddons` without migrating Docs views to async `getAddon('HighlightJS')` (`preloadFilesDelay: false` already prevents eager bundle/CSS network fetches on non-Docs routes).

## Avoided Traps

- **Using `.html` on VDOM `<code>` nodes before `hljs.highlightBlock`:** Browser `innerHTML` strips `<Type>` JSDoc generics before Highlight.js reads `textContent`.
- **Naive `html.split(/\r\n|\r|\n/)` across `<tr><td>` rows:** Browsers auto-close unclosed `<span class="hljs-comment">` tags at `</td>`, leaving lines `2..N` of multi-line comments unstyled.
- **Dropping `ruby` from `buildScripts/build/highlightJs.mjs`:** Breaks `highlight.js/lib/languages/yaml.js`'s `subLanguage: 'ruby'` ERB highlighting for only `1,202 B` gzip.
