# The Gantt's dependency layer reacts to its own inputs, each written once

Decision record: the pre-code decision on `#22306`, [comment 7216849463](https://github.com/neomjs/neo/issues/22306#issuecomment-7216849463). This ticket builds that decision and nothing else. It is the first of three pull requests that bring `src/gantt` to the Engine bar.

## Context

The operator's audit of 27 Nov rates `src/gantt` 3 of 10 as Engine classes (`#22306`). The mechanical pass is merged (`#22309`, PR `#22317`), so every line below is read at `eed5718b0f`. This ticket takes criterion 2 of `#22306`, the dependency overlay, out as a prerequisite, the way `#22309` took the mechanical pass out.

## The Problem

`Neo.gantt.DependencyLayer` draws the dependency arrows over the timeline. Its owner, `Neo.gantt.Container`, wires it by hand:

- **Inputs are written twice.** Ten `afterSet*` hooks copy a chart value into the layer; eight of them then call `syncDependencyLayer()`, which sends ten keys again in one `set()` before it projects (`Container.mjs:1434-1454`). The layer cannot do without the second write: of its eleven reactive inputs only three re-project on change (`DependencyLayer.mjs:193-234`); five have no hook, and three only release an owned store or axis.
- **Two writers disagree.** `afterSetViewportWidth` sends the configured width (`Container.mjs:477-480`), the ten-key set sends `timelineColumn.effectiveViewportWidth` (`:1448`). It works because the hook calls the second one next.
- **Creation and mount are mixed.** `ensureDependencyLayer()` creates the layer and also pushes its vdom reference into the body's root (`:704-734`), which `Body#createRowPool` does again (`Body.mjs:33-37`). `dependencyLayerConfig` is spread in without a merge descriptor (`:75-76`, `:722`).
- **A field is written from outside.** The chart assigns `layer.drawnSpans` after creation (`:724`).

So a subclass cannot override one key of an inherited `dependencyLayerConfig` without replacing all of it, and the layer does not show which of its configs are live.

## The Architectural Reality

Design authority: "Declarative relay descriptors for container-level timeline configs forwarded to {@link #timelineColumn}, its {@link Neo.timeline.TimeAxisHeader}, and/or {@link #eventDragZone}. […] Subclasses can override those descriptors and supply their own `afterSet<Config>` hook for additional keys." (`src/scheduler/Container.mjs:72-79`, the Gantt's parent class), and `.github/CODING_GUIDELINES.md` §8 (29b): "Leaf classes declare their defaults in `static config`. An inherited descriptor supplies its merge strategy."

The Engine has every part this needs:

- **A relay.** `static timelineRelays` and `relayTimelineConfig()` forward a container config to the column, its header and the drag zone from generated hooks (`scheduler/Container.mjs:80-104`, `:465-492`, `:1435-1442`). Four of the Gantt's ten hooks override a generated relay hook only to add the layer, and `afterSetTimeAxis` overrides the scheduler's.
- **A child that reacts.** Every input hook of `Neo.timeline.Column` re-renders its rows (`timeline/Column.mjs:377-525`).
- **An owned child's config with a descriptor.** The Engine's common shape for an owned child component is a `<name>Config` spread into a `Neo.create` in `construct` or a lazy `ensure…` method (60 spread lines in 33 files under `src`; the parent class has `eventDragZoneConfig`, `editorConfig` and `timelineColumnConfig`, `scheduler/Container.mjs:726-756`). The newer composites declare that config as `{[isDescriptor]: true, merge: 'deep'}` (`desktop/Container.mjs:92`, `app/content/Container.mjs:89`).

The gap is that the layer's inputs do not use the first two, and its config lacks the descriptor.

## The Fix

1. **The layer reacts.** Every input config of `DependencyLayer` gets an `afterSet` hook that re-projects once the layer is constructed. `drawnSpans` arrives with the creation config.
2. **One writer per input:**

| Input | Whose value | The one writer |
|---|---|---|
| `bufferPx`, `startDateField`, `endDateField`, `timeAxis`, `rowHeight`, `taskStore`, `dependencyStore`, and the plumbing pair `appName`, `windowId` | a chart config | the relay table, which gains a `layer` hop beside `column`; a config the scheduler does not relay calls the relay from its own hook |
| `axisLeft`, `scrollLeft`, `viewportWidth` | the timeline column's geometry | one chart method, fed by the scroll and column-position subscriptions, sending the column's effective width |
| `highlightedDependencyIds` | the registered analysis | one chart method, which `syncDependencyLayer()` and the relay hop call |

`syncDependencyLayer()` shrinks to geometry, highlights and `project()`.

3. **The config merges.** `dependencyLayerConfig` gets a deep-merge descriptor and becomes reactive, because a plain config's descriptor merges between classes only, not with an instance config. `ensureDependencyLayer()` stays the lazy creator, as `ensureEventDragZone()` is in the parent, and only creates. The chart destroys the layer in `destroy()`, as today.
4. **One mount path.** `Neo.gantt.Body#createRowPool` mounts the overlay; the chart no longer writes into the body's vdom.

The chart stays the one that decides when the data inside the stores has settled (`_movingTask`, `isUpdatingRows`, `schedule.isPublishing`: `Container.mjs:306-322`, `:396-431`).

The relay hop lives in a Gantt override of `relayTimelineConfig()` that calls `super`, with the Gantt's own `static timelineRelays`; `src/scheduler` stays untouched.

## Acceptance Criteria

- [ ] Each layer input has exactly one writer in `src/gantt`: a spec counts the writes per input during one cascading edit and during one scroll, and finds at most one each.
- [ ] Writing a chart config alone (`rowHeight`, `bufferPx`, `startDateField`, `endDateField`, `timeAxis`, `store`, `dependencyStore`) re-projects the arrows: one spec arm per input, with no `syncDependencyLayer()` call in the test.
- [ ] `syncDependencyLayer()` sends no mirrored input, `ensureDependencyLayer()` pushes no vdom reference, and the reference has one push site.
- [ ] `dependencyLayerConfig` merges deep: an instance config `{bufferPx: 800}` keeps the other key of a subclass default, and `{module: <subclass>}` swaps the layer class.
- [ ] A resize of the center body alone updates the layer's window: a spec changes the body's `containerWidth` and asserts the arrows in the newly visible span. Today's behaviour is recorded first; if it already passes, the spec stays as a guard.
- [ ] The layer stays a direct child of the center body's root node (the clip rule of `#21692` selects on it), and a store batch still re-projects once (`#21407`).
- [ ] The existing Gantt unit and e2e specs pass unchanged; a spec that has to change says why in the pull request body.
- [ ] The ten examples under `examples/gantt` render the same arrows as on `dev` (headless comparison of the layer's markup, as in PR `#22317`).
- [ ] The pull request body reports the lines removed and added in `src/gantt`, and the coding-guidelines baseline gains no row.

## Avoided Traps

- **The layer reading its chart** through one `chart` config, as `CascadeMotion` does: the ten hooks would stay as notify calls, and the projection would stop being a function of the layer's own configs, which six constructions in two spec files rely on.
- **Turning the layer itself into a reactive config** built in `beforeSet…`, as the grid does for `body_`: my first reading, corrected on 27 Nov. The config plus a lazy `ensure…` is the Engine's common shape and the parent class's own; the ticket asks for the descriptor on that config.
- **A state provider between chart and layer:** a second copy of each value. An app binds the chart's reactive configs; one relay hop carries them on.
- **Moving the store listeners into the layer:** the chart is the single writer and knows where a batch ends; a layer that listened by itself would project once per changed successor, the defect `#21407` closed.
- **Re-syncing the overlay from the body's row render:** a second clock, rejected in `#21655`.
