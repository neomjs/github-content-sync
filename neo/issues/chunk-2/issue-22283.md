# Desktop and nine other packages paint 22 bare colour literals

Live latest-open + closed sweep: the parent epic's sweep of 2026-11-26 23:06Z covers this leaf (colour literal, structural rule); no equivalent found. Not offered as a contributor issue: it is wanted for the weekend cut.

## Context

A theme can only style what a structural rule reads through a variable. The census (`npm run theme-census`, at `8855a8b023` over `dev` `11f48ebb15`) counts 72 colour literals that sit bare in structural rules. This leaf takes the 22 outside the component, grid, table and calendar packages.

## The Problem

| File | Bare literals |
|---|---:|
| `desktop/Launcher.css` | 4 |
| `desktop/TaskList.css` | 1 |
| `desktop/AppWindow.css` | 1 |
| `form/field/Range.css` | 4 |
| `dashboard/Container.css` | 2 |
| `gantt/Container.css` | 2 |
| `code/LivePreview.css` | 2 |
| `draggable/tree/SortZone.css` | 1 |
| `scheduler/Container.css` | 1 |
| `plugin/Resizable.css` | 1 |
| `plugin/Popover.css` | 1 |
| `list/Circle.css` | 1 |
| `dialog/Base.css` | 1 |

No theme, palette or app can change these colours without writing its own selector.

## The Architectural Reality

- Structure lives in `resources/css/src`, values in `resources/css/theme-*/<same path>`; a theme file declares variables only (`check-theme-value-files`).
- Component variables follow `--<component>[-<variant>][-<part>]-<css-property>[-<state>]`: the CSS property name unabbreviated (`background-color`, never `bg`), the state word last.
- `plugin` is a baselined zero-coverage package in `check-theme-coverage`; a variable for its two literals belongs to the component the plugin decorates, or the baseline row changes in the same pull request.

## The Fix

For each literal: the rule reads a new component variable, and each of the four full themes (`theme-neo-dark`, `theme-neo-light`, `theme-dark`, `theme-light`) declares it in its variable file for that component, created where the theme has none, **with the value the literal has today**. The paint does not change.

A literal that is not paint a theme should own stays and is named in the pull request with its reason.

## Acceptance Criteria

- [ ] `npm run theme-census` reports no bare colour literal for the thirteen files, or the pull request names each remaining one with its reason.
- [ ] Every new variable follows the grammar above and is declared in all four full themes with today's value.
- [ ] The four theme guards pass, and `check-theme-var-references` finds every new variable resolved.
- [ ] The pull request states that computed colours are unchanged in Neo Dark and Neo Light for one example per package.

## Out of Scope

- Giving a theme a different value: a follow-up with a look.
- Cyberpunk, renames, the `--cmp-*` layer.
