# Prevent keyboard edits to a disabled TextField while preserving programmatic updates

## Contract

`disabled: true` prevents **user-driven UI changes**. Application code can still set the field’s value and the displayed input must follow. The existing [global `.neo-disabled` rule](https://github.com/neomjs/neo/blob/0c1cc8eb58/resources/css/src/Global.css#L178-L181) owns opacity and pointer-event suppression. **No CSS changes in this fix.** The earlier brief failed to record that working baseline and the programmatic-write control.

## What was reproduced

Opened `http://localhost:8080/examples/form/field/text/#disabled=true` in a fresh Chrome context, identified the actual `exampleComponent` (Project name), and verified the served component Base, TextField and Global.css matched Engine `dev@0c1cc8eb58` byte for byte.

| Operation | Baseline result |
|---|---|
| Initial field | Worker disabled, displayed value and worker value both “Neo Workspace”; computed `pointer-events: none`, opacity `0.5`. |
| Physical pointer click on the input | Focus stayed on the body. The existing global policy worked. |
| Tab from the body, then type | One Tab focused the native input. It had `disabled=false`, `readOnly=false`, `tabIndex=0`. Typing “Keyboard audit” changed only the displayed value. The worker retained “Neo Workspace”. |
| Set `field.value` in the App worker while disabled | Display and model both became “Programmatic audit”. This behavior must survive. |
| Re-enable and type | Both display and worker accepted “Enabled audit”. |

The same native keyboard problem was observed on the disconnected companion in the shipped advanced StateProvider example. Its record stayed detached. This does not justify changing primary form pedagogy or redefining disabled as immutable.

## Acceptance and scope

- [ ] On the existing hash route and after runtime/bound disable, user pointer and keyboard input must not edit the displayed value. Keep the existing disabled class and cascade. Check the real active element and the native value, as well as worker state.
- [ ] While disabled, programmatic `field.value` and form/binding-driven writes still update the displayed input and the model. Re-enable restores ordinary input; keep read-only semantics separate.
- [ ] Show the smallest owner-level behavioral change that closes the proven gap. Keep both existing stylesheets unchanged. Additional trigger-class changes need a separately demonstrated user-input failure on their normal public path. Preserve callable application APIs.
- [ ] Rerun the pointer/Tab/programmatic/re-enable controls and the real companion fallback. The defect is fixed when visible behavior matches the contract.
