# A Markdown diagram throws on mount when its placeholder is missing

## Context

`dev`'s `Engine Tests` failed on `test/playwright/e2e/portal/PathnameRoutingNL.spec.mjs:92` three times between 2026-11-26 20:09Z and 2026-11-27 02:36Z (runs `45888954816`, `45918181727`, `45929346103`) and once on a PR branch (run `45959250231`): 4 of the 18 failed runs I read. Each time, the `workerErrors` auto-fixture failed the test, not an assertion of its own, and each time with the same two diagrams:

```
App Worker: initVnode error Initial mount insertNode skipped for "neo-mermaid-5" (parentId: "neo-mermaid-3")
Error: Initial mount insertNode skipped for "neo-mermaid-5" (parentId: "neo-mermaid-3")
    at Mermaid.createVnodeTree (src/mixin/VdomLifecycle.mjs:243:23)
    at async Mermaid.initVnode (src/mixin/VdomLifecycle.mjs:1003:30)
```

The same error appeared for `neo-mermaid-6` under `neo-mermaid-4`. The throw arrived with #22217 (merged 2026-11-26 01:12Z): in two-thread mode an initial mount waits for Main's acknowledgement, and a skipped insert throws (ADR 0043 I2, "the vnode never runs ahead of the DOM"). Then #22215 (12:14Z the same day) made two-thread mode the default. That puts this throw on every app's default mount path in 14.1, the Portal's Learn pages included.

## The Problem

Markdown renders its HTML with one placeholder div per diagram. After `await import('./wrapper/Mermaid.mjs')` it creates one `Neo.component.wrapper.Mermaid` per placeholder, with `parentId` set to that placeholder. Main skips an insert whose parent is not in the document, and the acknowledgement turns that skip into a throw.

**Observed:** the placeholder `neo-mermaid-3` was not in the document when the insert for `neo-mermaid-5` arrived.

**Unknown:** which of two orders produced that.

1. **Replaced content.** The route changed after `#createRenderComponent` admitted the diagram, and the new HTML replaced its placeholder. The diagram was still alive when its acknowledgement returned, because `isLiveAttempt()` checks only the diagram's own destruction. In this case the mount should end quietly.
2. **Early insert.** The diagram's insert reached Main before the Markdown HTML that holds its placeholder. In this case the diagram was missing before #22217 as well, and only the error is new.

The spec moves through `/learn`, `?query`, `#section` and back in quick succession, which favours (1); nothing yet rules out (2). Depending on the order, a reader sees a console error per diagram or a diagram that never appears.

## The Architectural Reality

- `src/mixin/VdomLifecycle.mjs`: L182 `isLiveAttempt`; L223–244 the two-thread `autoMount` branch, which applies one `insertNode` delta, awaits `Neo.applyDeltas`, and throws at L243 when the ack reports a skip.
- `src/component/Markdown.mjs`: L230–240 `#createRenderComponent`, which checks render currency before and after `Neo.create`; L248 `#isCurrentRender`; L748–762 diagram creation; L771 `updateComponentState`. `src/code/LivePreview.mjs` L382 imports the same wrapper.
- `test/playwright/fixtures.mjs` L236–267: `workerErrors` fails a test on any worker error.
- #21905 (closed) added the render-identity guard. Its AC, "An obsolete or destroyed render registers no child after the mount delay", covers registration, not a mount already in flight.

Decision Record impact: aligned-with `adr:0043-vdom-diff-placement` (I2 stays: a write that is genuinely lost still fails loudly).

## The Fix

1. **Name the order.** Run the spec under `--repeat-each` with a Main-side probe on skipped inserts that records whether the parent was removed or never present.
2. **Fix it at its owner.**
   - For (1): Markdown ends a replaced render's mounts before the new HTML lands, by destroying them when the render identity changes so that `isLiveAttempt()` is false when the ack returns. Alternatively, the attempt also ends when its parent was removed after it started.
   - For (2): Markdown creates its diagrams only once the HTML holding their placeholders has been applied.

   An insert whose parent never existed keeps throwing.
3. **Prove it** with a spec that is red on `dev` and green on the fix.

## Acceptance Criteria

- [ ] A receipt from the probe names the order: replaced content, early insert, or both.
- [ ] A spec drives that order directly and fails on `dev` with `Initial mount insertNode skipped`.
- [ ] On the fix's head that spec passes, and `PathnameRoutingNL.spec.mjs` passes 30 of 30 with `--repeat-each=30`.
- [ ] An insert whose parent never existed still throws.

## Out of Scope

- The other failures on `dev` in the same window. `HomeAudienceDoorsNL`, `ContentSecurityPolicy`, `HighlightJsResources` and three Workstation specs each failed once in the runs read.
- Reverting #22217's error or #22215's default.

## Avoided Traps

- **Listing the message among the spec's expected worker errors, or retrying it.** The engine is reporting a write that did not happen.
- **Catching the throw in `createVnodeTree`.** That hides case (2), a diagram that never appears.
