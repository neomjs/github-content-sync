# Track gesture subscriptions and contact ownership per window

## Context

App already mounts per-node listeners in [DomEvent](https://github.com/neomjs/neo/blob/5ff17dedc8/src/manager/DomEvent.mjs#L481), and Main installs them in [DomEvents](https://github.com/neomjs/neo/blob/5ff17dedc8/src/main/DomEvents.mjs#L220). A stateless DOM forward can disappear with its element. A recognizer can retain a claim, an active contact or a timer. Duplicate listeners, portal ancestry and node removal therefore matter before implementing any gesture family.

## The Fix

Extend the existing declarative listener lifecycle for the six opt-in families. Keep each registration scoped to its component or node and owning window. Reuse logical component propagation, and provide explicit release to the Main owner. Supply gesture recognizers with the current active/changed contacts, stable identity, target-relative CSS pixels and monotonic elapsed time. Retain browser ownership after native cancellation; a late second finger cannot reclaim a scroll. Implement the minimal registration/contact seam that the ADR specifies.

## Acceptance Criteria

- [ ] AC-1 Creating a chart with no gesture listeners adds zero recognizer messages. Adding two observers of one family and removing only one preserves the remaining subscription. Removing the last observer releases it.
- [ ] AC-2 Unmounting/replacing a subscribed target, hiding its document, cancellation and window loss release in-flight contacts or timers with no application commit. A sibling window and a remounted component work independently.
- [ ] AC-3 Exercise a nested target and a registered raw touch listener. Measure added messages for neither, raw-only, semantic-only and both. Keep the public raw listener contract intact.
- [ ] AC-4 With passive observers on a `touch-action: pan-y` surface, compare horizontal and vertical browser-driven strokes. The horizontal stroke stays eligible for app recognition when the pointer continues through `pointerup` and the container stays still. The vertical stroke can produce `pointercancel` and native scrolling. A second finger joining that scroll cannot acquire the gesture. Both strokes can deliver `touchmove` with `cancelable === false`. Assert ownership and actual scroll independently. [Chromium control](https://github.com/neomjs/neo/discussions/22259#discussioncomment-19962224) · [Circle late-join control](https://github.com/neomjs/neo/discussions/22259#discussioncomment-19962152)

AC-1 also counts recognizer-owned native listeners on Main before the first subscription, during two subscriptions and after the last release. The idle counts are zero; existing raw input and DragDrop listeners are the measured baseline. A blocking listener requires a surface whose input policy needs it. Verify registrations and removals in the owning window as well as Main→App messages.
