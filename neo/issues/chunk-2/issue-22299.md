# The --cmp-* layer goes: component variables read what it aliased

## Context

The first migration step of the design system (epic and ADR 0044, graduated from [Discussion #22228](https://github.com/orgs/neomjs/discussions/22228)). The operator retired the `--cmp-*` layer on 26 Nov: core and semantic tokens stay, the component aliases between them and the component variables do not. Its gate is the equality run of #22300, which is built first.

unowned-rationale: critical path of the 14.1 cut, so it is for a maintainer seat. Claim by assignee and a `[lane-claim]`.

## The Problem

`--cmp-*` is an alias layer from a 2023 Figma export that sits between the semantic tokens and the component variables in the Neo pair only. Measured with `npm run theme-census` on `dev` at `a22c1a96e9`:

- 71 names, declared in `resources/css/theme-neo-dark/Global.css` and `resources/css/theme-neo-light/Global.css`. The classic pair and Cyberpunk have none.
- 34 of the 71 are read by nothing. For a model that is a plausible name that changes nothing and reports nothing.
- 69 component values in Neo Dark and 62 in Neo Light route through one; 69 of the 71 have the same value in both themes.
- Neither Workstation nor Fleet overrides one.

## The Architectural Reality

- Readers: nine theme files in each Neo folder, and four files under `resources/css/src`, where a structural rule reads an alias directly instead of a component variable.
- Outside CSS, the names appear in `src/component/EmptyState.mjs`, `test/playwright/component/dashboard/DockRailTabPaint.spec.mjs`, `test/playwright/component/apps/dock-rail/app.mjs` and the census's own spec `test/playwright/unit/buildScripts/themeCensus.spec.mjs`. One file in `neomjs/neo-agent-institution` names a `--cmp-*` or `--sem-*` token.
- `check-theme-var-references` fails a fallback-free read of an undeclared variable inside a theme file.

Design authority: "`--cmp-*` goes." (ADR 0044, context; the operator's input of 26 Nov recorded in Discussion #22228; the roadmap's "the `--cmp-*` layer goes".)

## The Fix

1. In both Neo themes, each component variable that reads a `--cmp-*` name reads what that name held instead: its `--sem-*` token or its value.
2. The four structural files read a component variable. Where none exists, add it in both Neo themes with today's value, and in the classic pair if the rule paints there.
3. Delete the 71 declarations from both `Global.css` files.
4. Update the JavaScript and the tests that name an alias; the census spec keeps a fixture of its own.

## Acceptance Criteria

- [ ] AC-1 `npm run theme-census` reports no `--cmp-*` name in any theme, and a grep for `--cmp-` over `resources/css`, `src`, `apps`, `examples` and `test` returns only the census spec's fixture.
- [ ] AC-2 Paint is unchanged, shown by machine: the computed-style equality run of #22300 reports no undeclared difference between the base and this head, in all five themes. A comparison of resolved values over the built CSS is a quick pre-check and not the gate: it cannot see what a selector matches where a structural rule changes the variable it reads.
- [ ] AC-3 No structural rule reads a `--sem-*` or `--cmp-*` name directly after the change that did not before; the four files read component variables.
- [ ] AC-4 `check-theme-coverage`, `check-theme-value-files`, `check-theme-var-references` and `check-theme-surfaces` pass.
- [ ] AC-5 The one file in `neomjs/neo-agent-institution` is named in the pull request with its owner, so that repository follows.

## Out of Scope

- The `--sem-*` tokens: they stay until theme Neo has moved onto the roles.
- Any rename of a component variable: one scripted pull request, later.
- Unread `--sem-*` names.

## Avoided Traps

- **Keeping the 37 read aliases under a new name.** The layer goes; a component variable is the public hook.
- **Proving "no visual change" with screenshots only.** Computed values are exact; frames are not.
