# No guide names the install step the engine's build scripts need

## Context

The engine is published without generated output and without runtime dependencies: `.npmignore` drops `/dist` ("The npm package contains their sources and build scripts, never generated output."), and `package.json` declares no `dependencies`, only 38 `devDependencies`, among them `webpack`, `sass` and `@playwright/test`.

A workspace made by `npx neo-app` works anyway, because `create-app` writes this `postinstall` into its `package.json` (neomjs/create-app `tasks/createPackageJson.mjs:41`):

```
cd node_modules/neo.mjs && npm i && npm run bundle-parse5 && npm run bundle-marked
```

and lists the engine's toolchain as the workspace's own `devDependencies`. No engine guide says any of this. Anyone who depends on the engine without starting from `create-app`, such as a package that lives in its own repository (#20667), has to find the line in the generator's source.

Measured 2026-11-14 on such a package, installed from a tarball packed at `dev` `a07f581f13` (receipt on #20667):

- without the step, `npm run build-themes` stops at `Cannot find package 'autoprefixer' imported from …/node_modules/neo.mjs/buildScripts/build/themes.mjs`, and scripts that call `node_modules/neo.mjs/node_modules/.bin/webpack` or `…/playwright` find no file;
- with it, the themes build in all five themes, and the package's e2e suite and production build pass.

## The Problem

`learn/gettingstarted/Workspaces.md` says that "a Neo.mjs workspace is a conventional npm package", but not that installing the engine takes two installs: the workspace's own, then the engine's inside `node_modules/neo.mjs`, followed by the two bundles the engine imports at module scope. Because every `npm install` replaces `node_modules/neo.mjs`, the bundles go with it, which is why the step is a `postinstall` and not a one-time setup.

## The Architectural Reality

- `create-app` `tasks/createPackageJson.mjs:39-41` states the reason in its comment: the engine package ships no generated bundles and an install replaces `node_modules/neo.mjs`, so every install rebuilds the two the engine imports at module scope; the others load lazily through `bundle-browser-deps`.
- The package side is documented: `learn/guides/uibuildingblocks/StylingAndTheming.md:402` explains how an installed package ships its own SCSS (`neo.scss`). The clone path for engine contributors is documented in `CONTRIBUTING.md` (#18999). The step between them is not.
- Design authority: n/a — this ticket calls no existing behavior wrong; it documents it.

## The Fix

One short section in `learn/gettingstarted/Workspaces.md`, after the "conventional npm package" sentence (a sibling page linked from there is fine if `learn/tree.json` reads better). It says what the published engine leaves out (`/dist`, runtime dependencies), quotes the `postinstall` line as `create-app` writes it and explains each part, names the lazily loaded bundles and `npm run bundle-browser-deps`, and tells a package that depends on the engine without `create-app` to add the same line and the toolchain `devDependencies`. When `node_modules/neo.mjs` links an engine checkout instead, that checkout's own install already did this. Quote `create-app`; do not write a second recipe. Follow the `guide-authoring` skill (`.agents/skills/guide-authoring/SKILL.md`).
