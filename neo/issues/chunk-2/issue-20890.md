# The timeline shows dates a person reads: editor, header, long bars

## Context

Leaf of #20874. Seen in the design read of the first example that uses the timeline family (`examples/scheduler/basic`, #20888), in `neo-theme-neo-light` and `neo-theme-neo-dark`. All three points sit in the timeline family on `dev` (`c19cd4934a`), not in that pull request.

## The Problem

1. **The editor asks for ISO strings.** Double-click a bar: "Start date" and "End date" are text fields holding `2026-11-09T02:00`. A person has to type a timestamp.
2. **The header's date row prints an ISO day key.** With no `majorFormatter`, a day reads `2026-11-09`.
3. **A long bar loses its name when its start scrolls out.** At the hour zoom, a booking that began before the visible range is a coloured block without a label, and the header's date row is empty until the next midnight scrolls in.

## The Architectural Reality

- `src/timeline/EventEditor.mjs:227–238`: both date items are `Neo.form.field.Text`.
- `src/timeline/TimeAxisHeader.mjs:483–516`: `formatMajorTick()` falls back to `d.toISOString().slice(0, 10)`.
- `resources/scss/src/timeline/Column.scss:80`: `.neo-timeline-bar-label` is a plain flex child; nothing keeps it inside the visible part of its bar.
- The axis already formats with `Intl.DateTimeFormat` and knows its `timeZone` (`src/timeline/TimeAxis.mjs:32`).
- Design authority: n/a — a look and wording choice; no record makes the ISO forms intended, and the family's JSDoc names `majorFormatter` only as an override.

## The Fix

1. The editor edits start and end with the engine's date and time fields (`Neo.form.field.Date`, `Neo.form.field.Time`) in the axis' time zone, and still commits through the owner's `commitTimelineEdit()` once.
2. The default major label is built with `Intl.DateTimeFormat` in the axis' time zone and locale (a day reads like "Mon 9 Nov"; week and month units get their own default). `majorFormatter` keeps overriding it.
3. A bar's label stays inside the visible part of the bar while the bar is partly scrolled out, and the header's date row always names the day of the leftmost visible tick.

## Acceptance Criteria

- [ ] The editor shows a date and a time control for start and for end; an edit is one record change (the existing editor spec stays green, extended for the new fields).
- [ ] With no `majorFormatter`, no ISO day key appears in the header; a unit spec pins the default label per unit and time zone.
- [ ] At the hour zoom of `examples/scheduler/basic`, scrolled to 18:00, every visible bar shows its title and the header shows the day.
- [ ] **Look:** frames of the editor, the header and a partly scrolled-out bar in both neo themes in the pull request; the epic's design read (#20874) passes on them.
- [ ] Unit specs pass in the engine's unit configuration (`npm run test-unit`), and `npm run build-themes` compiles.

## Out of Scope

Recurrence, all-day events and a date-range picker. The scheduler's and the Gantt's own containers.
