# getCellValues() misreads computed fields of a raw Turbo Mode row

## Context

`Neo.grid.Container#getCellValues()` is the grid's one value walk: `toCsv()` serializes it, and a reader outside the grid calls it. In Turbo Mode (`autoInitRecords: false`) a store holds a row as a raw object until something asks for its record, which the grid does for the rows it renders. The walk reads every row of the store, so most of the rows it reads are raw. For those it answers a different value than for the same row once it is a record, for every field the model computes.

Measured on `dev` at `be8d0b0340` with a unit spec.

## The Problem

The reproducer: a flat `Neo.data.Store` with `autoInitRecords: false` and 60 rows, in a grid that renders 8 rows. After the first render 14 of the 60 items were records and the rest raw.

```js
model: {fields: [
    {name: 'id',     type: 'Integer'},
    {name: 'value',  type: 'Integer'},
    {name: 'double', calculate: data => data.value * 2},
    {name: 'city',   mapping: 'address.city'},
    {name: 'upper',  convert: value => String(value).toUpperCase()}
]}
// each row: {id: n, value: n, address: {city: `City ${n}`}, upper: 'ab'}
// columns: value, double, city, upper
```

`grid.toCsv()`:

```
value,double,city,upper
1,2,City 1,AB
…
52,,,ab
```

Row 1 was rendered and is a record. Row 52 was never rendered and is raw: its calculated and mapped cells are empty, and its converted cell holds the unconverted value.

The same row read three ways (row 51, raw):

| Read | `value` | `double` | `city` | `upper` |
|---|---|---|---|---|
| `getCellValues({mode: 'raw', records: [raw]})` | `51` | `undefined` | `undefined` | `'ab'` |
| `getCellValues({mode: 'export', records: [raw]})` | `51` | `null` | `null` | `'ab'` |
| `store.resolveField(raw, field)` | `51` | `102` | `'City 51'` | `'AB'` |
| `getCellValues({mode: 'raw', records: [store.get(51)]})` | `51` | `102` | `'City 51'` | `'AB'` |

So a CSV export of a Turbo Mode grid is wrong in every row the user has not scrolled to, and a spreadsheet writer or an agent that reads the walk gets the same values.

## The Architectural Reality

- `getCellValues()` (`src/grid/Container.mjs:1435`) reads each cell through `column.getRecordValue(record)`. `toCsv()` (`:1855`) serializes its answer.
- `Neo.grid.column.Base#getRecordValue()` (`src/grid/column/Base.mjs:345`) reads a record through `record.get(field)` and a raw row through `Neo.ns(field, false, record)`, by property. A raw row has no property for a calculated or a mapped field, and it holds the unconverted value of a converted one. The raw branch came with `#20359` for dotted paths.
- `Neo.data.Store#resolveField(item, fieldName)` (`src/data/Store.mjs:1775`) is the engine's resolver for one field of a raw row. It handles `mapping`, `calculate`, `convert` and `defaultValue`, keeps the result on the raw row and creates no record. The class JSDoc calls this Soft Hydration (`:64`). `doSort()` (`:643`), `filter()` (`:798`) and `Neo.data.TreeStore` (`:411`, `:625`) call it for Turbo Mode when the model has complex fields; the sort came with `#9066`. The method is `@protected`.
- **Added on 2026-11-12:** those callers ask it only for a property the row does not hold. Asked for one the row holds, it replaces the datum with its converted form, and the next call and the row's later record convert that again: `convert: v => v * 1000` over `ms: 52` answers `52000`, then `52000000`, and the record then holds `52000000000`. The reproducer's `toUpperCase()` is idempotent and hid it. Measured in #20802, rows 1 and 2.
- `Neo.data.Model#hasComplexFields` (`src/data/Model.mjs:94`) says whether a model has such fields.
- Design authority: "`toCsv()` serializes it, and a reader outside the grid (a clipboard, a spreadsheet writer, an agent) calls it for the records and columns it needs, so every reader gets the same value for the same cell." (the JSDoc of `getCellValues()`). A cell's value must not depend on whether its row was rendered.

## The Fix

The store answers a raw row for the walk, and the walk asks it. `Neo.data.Store` gets one public read that takes a raw row and field names, and returns a copy on which `resolveField()` has resolved each name that is a model field. For a record, and for a model without complex fields, it returns the row itself. `getCellValues()` passes every row through it and hands the result to `column.getRecordValue()`, which reads it by property as it does today. The walk hydrates no row and leaves every row as it found it.

`resolveField()` stays `@protected`, and `getRecordValue()` is not touched. A column knows nothing of Soft Hydration, and `Neo.grid.column.AnimatedChange` passes it a field's old and new value, which are no rows (`src/grid/column/AnimatedChange.mjs:67`).

Measured on `dev` at `be8d0b0340` with this shape in a unit spec: eight field shapes (calculated, calculated with `depends`, mapped, converted, two converters that are not idempotent, mapped and converted) answer in two walks what the row's record answers, the row keeps its keys, and 50,000 raw rows by 8 columns take 177 ms against 79 ms for today's property reads.

**Amended on 2026-11-12, after the review of PR #20801.** The first version of this section sent the read through `resolveField()` from the column and made `resolveField()` public, and PR #20801 built exactly that. The gap was in this ticket: its reproducer never read the same row twice.

## Acceptance Criteria

- [ ] Over a raw Turbo Mode row, `getCellValues()` answers for a calculated, a mapped and a converted field what it answers for that row's record, in `raw` and in `export` mode.
- [ ] `toCsv()` of the reproducer's grid has `52,104,City 52,AB` for row 52.
- [ ] The walk creates no record: after `getCellValues()` over every row, the number of records among `store.items` is what it was before.
- [ ] A `dataField` that is no model field, and a dotted `dataField`, read as they do today. The arms of `#20359` stay green.
- [ ] A store whose model has no complex fields takes the property read and does not call `resolveField()`.
- [ ] The walk leaves a row as it found it. Two walks over one raw row answer the same values, the row has the keys it had, and its record then holds what an unread row's record holds, for a `convert` that is not idempotent (`v => v * 1000`), alone and with a `mapping`.
- [ ] `getRecordValue()` reads an object that is no row as it does on `dev`: `{load: 1}` with the field `load` answers `1` in a store whose model maps a field named `load`.

## Out of Scope

- **Type conversion.** A raw row holds what the data holds: `'7'` in an `Integer` field reads as the string `'7'` from a raw row and as the number `7` from its record (measured in the same spec). `resolveField()` does not parse types either. That difference needs its own decision.
- **The other cells the walk answers differently for a raw row.** A dotted `dataField` under a mapped or calculated root, a `defaultValue` in a model without complex fields, a `convert` over a key the row lacks. They are measured in #20802, which owns them with the type conversion above.
- `getRecordValue()` on a record.

## Avoided Traps

- **Hydrating the rows the walk reads.** A store runs in Turbo Mode so that a row nobody looks at costs no record.
- **Resolving in `toCsv()` alone.** The walk has other readers, and they would keep the wrong values.
- **Resolving on the store's own row.** Soft Hydration keeps what it resolves, and a kept value is converted again by the next read and by the row's record (#20802).
