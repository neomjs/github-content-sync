# A grid that allows several selections never sets aria-multiselectable

## Context

A grid whose selection model has `singleSelect: false` lets a person select several rows or cells, but its ARIA root never says so: assistive technology announces a grid in which one item can be selected. Measured on `dev` `32fb6cb32e` with a throwaway unit spec that reads `grid.getAriaRoot()` for each model:

```
default                       | Neo.selection.grid.RowModel  single=true  | role=grid aria-multiselectable=undefined
RowModel  singleSelect:true   | Neo.selection.grid.RowModel  single=true  | role=grid aria-multiselectable=undefined
RowModel  singleSelect:false  | Neo.selection.grid.RowModel  single=false | role=grid aria-multiselectable=undefined
CellModel singleSelect:false  | Neo.selection.grid.CellModel single=false | role=grid aria-multiselectable=undefined
```

## The Problem

Nothing under `src/grid` or `src/selection/grid` writes `aria-multiselectable`. The engine sets it elsewhere: `src/list/ValuePicker.mjs:91` and `src/form/field/Chip.mjs:355`, on lists that allow several selections.

## The Architectural Reality

- `Neo.grid.Container#getAriaRoot()` (`src/grid/Container.mjs`) returns the VDOM root of the inner container that carries `role="grid"` (or `treegrid`). The container writes ARIA attributes there and then updates that wrapper, as `updateRowCount()` does: `me.getAriaRoot()['aria-rowcount'] = …; me.ariaWrapper.update()`.
- The selection model belongs to the grid's View (`Neo.grid.View#selectionModel`). Every grid model registers with the View through `Neo.selection.grid.BaseModel#register(component)` and leaves through `#unregister()` (`src/selection/grid/BaseModel.mjs`). That covers a model from `viewConfig.selectionModel` and one swapped in at runtime (`grid.view.selectionModel = {…}`). The View reaches its container as `view.gridContainer`.
- `singleSelect` (`Neo.selection.Model`) is a plain config, not reactive, so the value read at `register()` is the model's for its lifetime.
- Design authority: the WAI-ARIA Authoring Practices grid pattern, under which a grid that allows several rows or cells to be selected sets `aria-multiselectable="true"` on the grid element; in the engine, the two list precedents above.

## The Fix

In `Neo.selection.grid.BaseModel`:
- `register(component)`: after `super.register(component)`, set `aria-multiselectable` on `component.gridContainer.getAriaRoot()`: `true` when `singleSelect` is false, otherwise remove it (`null`). Then call `ariaWrapper.update()`, as `updateRowCount()` does.
- `unregister()`: remove the attribute and update, unless the view is being destroyed (the method already skips its repaint in that case).

Add JSDoc that says why the model writes the attribute.

## Acceptance Criteria

- [ ] A new unit spec beside `test/playwright/unit/grid/AriaRegions.spec.mjs`: a grid with `viewConfig: {selectionModel: {module: RowModel, singleSelect: false}}` has `aria-multiselectable` `true` on its ARIA root; the same with `CellModel`; a default grid has no `aria-multiselectable`.
- [ ] Swapping the model at runtime (`grid.view.selectionModel = {module: RowModel, singleSelect: false}`, then back to a single-select model) sets the attribute, then removes it.
- [ ] A tree grid (`role="treegrid"`) with a multi-select model gets the attribute too.
- [ ] `test/playwright/unit/grid` passes in full.

## Out of Scope

- `aria-selected` on rows and cells, which the grid already writes.
- A runtime change of `singleSelect` on a live model: it is not reactive.
