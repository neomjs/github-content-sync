# No SECURITY.md: the private reporting path is unnamed

## Context

Found on 2026-11-15 while writing the evaluator's page (#20530). GitHub's community profile for this repository lists no security policy (`gh api repos/neomjs/neo/community/profile --jq .files.security_policy` → `null`), while private vulnerability reporting is switched on (`gh api repos/neomjs/neo/private-vulnerability-reporting` → `enabled: true`).

## The Problem

A person who finds a vulnerability has no page that says where to send it. The Security tab reads "No security policy detected", and the natural fallback is a public issue. A reviewer doing due diligence on the engine opens the same tab.

## The Architectural Reality

- GitHub reads a policy from `SECURITY.md` in the root, in `docs/` or in `.github/`. This repository keeps its community files in `.github/` (`CODE_OF_CONDUCT.md`, `PULL_REQUEST_TEMPLATE.md`).
- What is true today, and all the file may say: reports go through private vulnerability reporting; a fix ships in the next release of the current release line; no long-term-support branch exists (`git branch -r` shows none).
- `Design authority: n/a — calls no existing behavior wrong.`

## The Fix

One file, `.github/SECURITY.md`, with these four parts and nothing else:

1. **Reporting a vulnerability.** "Report it privately through [Report a vulnerability](https://github.com/neomjs/neo/security/advisories/new). Please do not open a public issue, discussion or pull request for it."
2. **What to include.** The version or commit, the browser and environment, and the smallest steps that show the problem.
3. **Supported versions.** "Fixes ship in the next release of the current release line. There is no long-term-support branch."
4. **Scope.** This repository, the engine. A finding in another repository of the organisation is reported in that repository.

## Acceptance Criteria

- [ ] AC-1: `.github/SECURITY.md` exists with the four parts above.
- [ ] AC-2: it names no response time, no bounty and no e-mail address.
- [ ] AC-3: `node buildScripts/util/check-relative-links.mjs` and `node buildScripts/util/check-whitespace.mjs` pass.
- [ ] AC-4, after the merge: `gh api repos/neomjs/neo/community/profile --jq .files.security_policy` is no longer `null`.

## Out of Scope

- The same file in the organisation's other repositories. None has one; each is a ticket in its own repository.
- A response-time commitment. None exists, and making one is the operator's decision.
- Any change to the engine.

## Avoided Traps

- **A template policy** with a supported-versions table and a contact address. Both would state things that are not true here.
