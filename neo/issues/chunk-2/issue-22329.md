# Resolve themes from theme-map and Global.css across buildScripts

## Context

Follow-up leaf to `#22298` (`PR #22304`, merged at `0c1585bcc5`) under Epic #22295 and [ADR 0044](https://github.com/neomjs/neo/blob/dev/learn/agentos/decisions/0044-design-system.md) (graduated from [Discussion #22228](https://github.com/orgs/neomjs/discussions/22228) at `R3`). `#22298` added the `themes` (`class → folders`) table to `resources/theme-map.json` and wired the runtime `Stylesheet` loader and `setCssVariable`, explicitly scoping out the `buildScripts` theme readers until the map shape landed on `dev`.

Ownership: self-assigned maintainer leaf on the `v14.1` design-system critical path (carries no contributor labels because downstream `theme-base` and `theme-neo` migration PRs depend on it).

## The Problem

Across `buildScripts/`, theme discovery still relies on `theme-*` directory-name prefixes, `folderName.includes('theme')`, hardcoded `theme-neo-dark` / `theme-neo-light` paths, and `'neo-' + folder` string concatenation:

1. `buildScripts/util/themeCss.mjs:134` (`isCssTargetFolder`) admits any directory with `folderName.includes('theme')` even when its `Global.css` declares no `.neo-theme-*` class.
2. `buildScripts/create/theme.mjs:12,34,49` filters base themes via `/^theme-[a-z0-9]+(?:-[a-z0-9]+)*$/` and derives selector classes via `` `neo-${path.basename(baseRoot)}` `` — which lists `theme-base` as a selectable base theme once `resources/css/theme-base` lands and fails to retarget a shared folder like `theme-neo` whose `Global.css` declares `.neo-theme-neo-light` and `.neo-theme-neo-dark`.
3. `buildScripts/util/theme-census.mjs:189`, `buildScripts/util/check-theme-value-files.mjs:69,170`, and `buildScripts/util/check-theme-var-references.mjs:30,60` enumerate `name.startsWith('theme-')` and export `theme-*` `SCAN_SURFACE` globs — which will misclassify `theme-base` as a standalone theme (failing `check-theme-var-references` and polluting `theme-census` counts) and miss any mapped theme folder without a `theme-` prefix.
4. `buildScripts/util/check-theme-coverage.mjs:48-49` and `buildScripts/util/check-theme-surfaces.mjs:29-30` hardcode `resources/css/theme-neo-dark` and `resources/css/theme-neo-light` instead of resolving the folders serving `neo-theme-neo-dark` and `neo-theme-neo-light` from the theme map (and `theme-base` once packages move).

## The Architectural Reality

- `buildScripts/util/themeCss.mjs` (`0c1585bcc5`) already exports `extractThemeClasses(css)` and `collectThemeClassMap(cssRoots, seedThemes)`, which `buildScripts/build/themes.mjs` and `buildScripts/helpers/watchThemes.mjs` use to write `themeMap.themes` into `resources/theme-map.json` and `dist/<env>/resources/theme-map.json`.
- `/resources/theme-map.json` is gitignored (`.gitignore:87`), so in `.github/workflows/pr-baseline.yml` (`lines 75-79`) the theme guards run right after `npm ci` before `build-themes` writes `resources/theme-map.json`, and `ScanSurfaceAlignment.spec.mjs:148-156` enforces that every `SCAN_SURFACE` glob matches tracked files in `git ls-files`.
- Therefore, the shared reader in `buildScripts/util/themeCss.mjs` must read `themeMap.themes` from `resources/theme-map.json` when present on disk (with `includeWorkspaceMap: false` for build/watch source discovery so stale workspace maps never re-admit deleted local themes) and derive the identical `class → folders` map via `collectThemeClassMap` over `Global.css` when `theme-map.json` is absent (fresh CI checkouts, unbuilt workspaces, and isolated `--root` test trees), while `SCAN_SURFACE` derives tracked folder globs plus `resources/css/*/Global.css` without referencing gitignored `resources/theme-map.json` or `theme-*` directory wildcards.

Design authority: "The theme build writes, for each theme class, the folders whose `Global.css` declares it into `resources/theme-map.json`. The loader, `setCssVariable`, the census, the guards and `create-theme` read it; none globs `theme-*` or strips a prefix (step 2)." (ADR 0044, invariant I7; Epic #22295 Seam 4 and Order-of-work row 3; `#22298` Out of Scope.)

## The Fix

1. Add `readThemeMapFile(themeMapPath)`, `resolveThemeClassMap({cssRoots, includeWorkspaceMap, root, seedThemes, themeMapPath})`, and `resolveThemeFolders({cssRoots, existingOnly, includeWorkspaceMap, root, seedThemes, themeMapPath})` to `buildScripts/util/themeCss.mjs`, and tighten `isCssTargetFolder(cssRootsOrRoot, folderName)` to `'src'`, `'theme-base'`, or a theme folder resolved across `cssRoots` with `includeWorkspaceMap: false` (dropping `folderName.includes('theme')` and retiring deleted workspace themes in one watch reconciliation).
2. Update `buildScripts/build/themes.mjs` (`themeFolders`, `themeMap.themes`) and `buildScripts/helpers/watchThemes.mjs` (`getThemeSourceCensus`, `createDevelopmentThemeMap`, `inspectThemeWatcherAssets`) to pass full `cssRoots` with `includeWorkspaceMap: false`.
3. Update `buildScripts/create/theme.mjs` (`listThemes`, `generateTheme`, `retargetCss`, `main`) to share one selectable-folder policy (`collectSelectableThemes`, accepting `_` and `-` folder names with a valid `Global.css` while excluding `theme-base` and component-only split folders), retarget the base folder's mapped `.neo-theme-*` selector class(es), and print the exact `.neo-theme-*` class(es) declared in the generated `Global.css`.
4. Update `buildScripts/util/theme-census.mjs`, `check-theme-value-files.mjs`, `check-theme-var-references.mjs`, `check-theme-coverage.mjs`, and `check-theme-surfaces.mjs` (`resolveWorkstationSurface`) to preserve full `class → folders` membership across per-theme definitions, Workstation skin parity, and census scheme pairing (pairing dark/light schemes via mapped `.neo-theme-*` class names rather than folder suffixes, and treating `theme-base` as shared variables-only coverage/definitions), and replace `theme-*` in `SCAN_SURFACE` with mapped folder globs plus `resources/css/*/Global.css`.
5. Add unit test coverage in `test/playwright/unit/buildScripts/util/check-theme-value-files.spec.mjs` (sibling to `check-theme-surfaces.spec.mjs`) and extend `themeCensus.spec.mjs`, `checkThemeVarReferences.spec.mjs`, `checkThemeCoverage.spec.mjs`, `check-theme-surfaces.spec.mjs`, `createTheme.spec.mjs`, `helpers/watchThemes.spec.mjs`, `build/themes.spec.mjs`, and `util/developmentThemeAssets.spec.mjs`.

## Out of Scope

- Adding the new "roles without a reader" section to `theme-census.mjs` or role/palette parity guards (lands with `theme-neo/Global.css` in Order-of-work row 9 once roles exist on `dev`).
- Removing `check-theme-surfaces.mjs`'s dark/light parity check (lands when the two Neo folders merge in Order-of-work row 12).
- Creating `resources/css/theme-base` or `resources/css/theme-neo` content.

## Avoided Traps

- **Listing gitignored `resources/theme-map.json` in `SCAN_SURFACE` or requiring it on fresh checkouts.** `.gitignore:87` ignores `/resources/theme-map.json`, so `pr-baseline.yml` runs the theme guards after `npm ci` before `build-themes`, and `ScanSurfaceAlignment.spec.mjs` rejects untracked `SCAN_SURFACE` members. Falling back to `collectThemeClassMap` over `Global.css` keeps `theme-map.json` and unbuilt checkouts mathematically identical without `theme-*` globs.
- **Treating `theme-base` as a theme folder.** `theme-base` holds shared component variable bindings without a `Global.css` theme class; guards check its variables-only rule and shared definitions/coverage without counting it as a theme.
