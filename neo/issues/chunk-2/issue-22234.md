# A reusable single-choice segmented control for the Board

## Context and problem
Board card designs manually synchronize three pressed buttons in `examples/board/cardDesigns/Viewport.mjs:112-126,175-193`. A reusable single-choice control can own that coordination.

## Architectural reality and approach
Use Neo component and reactive state conventions and existing button primitives. Adopt it in the Board card-design example, replacing the manual state synchronization. Avoid prescribing a new underlying control until current primitives are inspected.

## Contract ledger
| Surface | Authority and behavior | Fallback / evidence |
| --- | --- | --- |
| Single-choice control | Consumer supplies choices and selection; one selected value is exposed and changes propagate | Define invalid, disabled and empty-choice behavior; tests and docs |
| Board example | Selection controls the existing card designs | Existing designs and user interaction remain usable |

## Acceptance criteria
- [ ] A reusable themed single-choice segmented control exposes its choices, selection and change behavior, with accessible names, selected state and keyboard operation.
- [ ] The Board card-design example adopts it and removes duplicated pressed-state coordination; pointer and keyboard changes select the correct design.
- [ ] Tests cover initialization, programmatic changes, user selection, disabled choices and relevant focus behavior; demonstrate light and dark themes.
- [ ] Document the public contract and its invalid/empty selection behavior.

## Out of scope
Multi-select and a wholesale Board redesign.
