# The Grid edit dialog stays inside the viewport when the window narrows

Live latest-open + closed sweep: latest 20 open plus open and closed search ("keepInBoundary", "dialog outside viewport", "EditUserDialog", "edit in dialog resize") and PRs ("keepInBoundary") at 2026-11-27T04:45Z (Out of Scope / Avoided Traps read on #21271 and #21178); the A2A claim window (since 04:28Z, all read states), Memory Core ("an open dialog leaves the viewport when the window narrows") and my open assignments swept; no equivalent or prior exclusion found. Backlog band: 50 open (orange); no ticket owns this defect, and the adaptive-components track that surfaced it lives in Discussion #22259.

## Context

Emmy measured the 14.1 adaptive-form baseline on [Discussion #22259](https://github.com/neomjs/neo/discussions/22259#discussioncomment-19935919). The Grid contact editor was opened at 1200 × 850, its first name edited, and the window resized to 390 × 844. The draft and the focused input survived, but the dialog did not stay visible:

| State | Left | Width | Width inside the viewport |
|---|---:|---:|---:|
| Open at desktop width | 390 px | 420 px | 420 px |
| Same open dialog after narrowing | 390 px | 366 px | 0 px |
| Reopen at the same phone width | 12 px | 366 px | 366 px |

## The Problem

A user who narrows the window, or rotates a tablet, while editing loses the whole dialog: its Save and Cancel and the focused field all sit outside the viewport. Escape still works, so the draft can be discarded only by a key the user cannot see. The 14.1 roadmap's adaptive track uses this editor as its baseline, and its suggested integration check narrows the viewport with an unsaved edit open.

## The Architectural Reality

- `examples/grid/nestedRecordFields/EditUserDialog.mjs` is a modal `Neo.dialog.Base` whose width follows the viewport (`min(420px, calc(100vw - 24px))`). Its position is set when it opens, so a narrowed window shrinks it in place.
- `Neo.dialog.Base#keepInBoundary` (default `false`, #21271 via PR #21839) moves a dialog back inside its `boundaryContainerId` (`document.body` here) by the smallest distance when that container changes size. A user-moved dialog is left where the user put it until it would leave the container. `examples/dialog/DemoDialog.mjs` and every `Neo.desktop.Container` app window opt in; this example does not.
- `test/playwright/e2e/grid/EditInDialogExample.spec.mjs` covers opening at 390 × 844, keyboard close, Escape and Save, but no resize while open.

Design authority: "Keeps the dialog inside its {@link #boundaryContainerId} when that container changes size" (`Neo.dialog.Base#keepInBoundary` JSDoc) and "opens a full-width form dialog (>= 180px fields at 1440×900, usable at 390×844)" (the example's spec header).

## The Fix

1. `EditUserDialog` opts in: `keepInBoundary: true`.
2. `EditInDialogExample.spec.mjs` gains the resize case: open at 1200 × 850, type a draft, narrow to 390 × 844, and assert the dialog's box lies inside the viewport with the draft and focus intact. Then Escape returns focus to Edit, and a reopen and Save commit the row.

Contract Ledger: n/a. The example opts into an existing config; no consumed surface changes.

## Acceptance Criteria

- [ ] AC-1 With the dialog open at 1200 × 850 and a draft typed, narrowing to 390 × 844 leaves the dialog's box entirely inside the viewport; the draft and the focused input survive.
- [ ] AC-2 Escape still discards and returns focus to the row's Edit button, and Save still commits; the existing cases stay green.
- [ ] AC-3 The new case is red on `dev` (dialog outside the viewport) and green on the head.

## Out of Scope

- Flipping `keepInBoundary`'s default for modal dialogs: Discussion #22259 still chooses between an adaptive Dialog and a separate Sheet, and the default belongs to that decision.
- The adaptive sheet and the floating Edit action.
- Re-centering after a resize: the smallest move is the existing contract.

## Avoided Traps

- Re-running the open-time positioning on every resize: it would also move a dialog the user dragged, which `keepInBoundary` deliberately leaves alone while it fits.
