# Structural rules hold 64 corner radii no theme can reach

Leaf of #22295. The design seat asked for it in [its decision on the Material gap list](https://github.com/neomjs/neo/issues/22295#issuecomment-7218629885), item 3. It carries no starter labels: it is sequenced inside the epic's order, after the rename (#22349), and it touches every theme folder.

## Context

ADR 0044 binds names in one direction: a rule reads a component variable, a component variable reads a role, a role reads the palette. The groundwork (#22280) made that true for colour: no structural rule paints a colour a theme cannot reach. Shape was not swept. The [Material gap list](https://github.com/neomjs/neo/issues/22295#issuecomment-7218019616) measured it, and the role list gains two radius steps in #22350 (`--neo-radius-large`, `--neo-radius-extra-large`). A theme will then have five steps to say its shape with, and more than half of the engine's sized corners will not listen.

## The Problem

Measured on `dev` at `a9bf2171f8`, over the 176 tracked CSS files under `resources/css/src` outside `apps/` and `examples/`, comments stripped, every `border-radius` declaration and its corner longhands:

| Class | Declarations |
|---|---:|
| reads a variable | 53 |
| `0` or `inherit` | 13 |
| percentages only: circles and blobs, shape by construction | 35 |
| **a literal length** | **64** |
| total | 165 |

- **14 distinct values:** 13× `4px`, 8× `999px`, 8× `2px`, 7× `3px`, 6× `6px`, 6× `5px`, 4× `8px`, 4× `16px`, 2× `14px`, 2× `12px`, and one each of `10px`, `0.5rem`, `7px`, `9px`.
- **34 files:** desktop 13, board 11, component 9, dashboard 5, form 5, table 4, button 3, grid 3, calendar 2, scheduler 2, timeline 2, and one each in app, draggable, gantt, plugin, tab.
- **Samples:** `app/content/TreeList.css:75` (`8px`), `board/Card.css:109` (`4px`), `board/Card.css:148` (`999px`).

What it costs: a theme whose language is its shape cannot say it. Material reads six radius steps (pill buttons, 12 px cards, 28 px dialogs). With the roles in place, 64 corners keep theme Neo's numbers in every theme. For a model the failure is silent: it sets a radius role or a component's radius variable, and a card inside that component keeps its `6px`.

## The Architectural Reality

- **Owner:** each component's structural file, `resources/css/src/<pkg>/<Cmp>.css`. The pattern exists 53 times, for example `border-bottom-left-radius: var(--textfield-border-radius)` in `form/field/Text.css:356`.
- **A component variable** is declared by every theme (`check-theme-coverage`), read without a fallback (`check-theme-var-references`, census section 6) and named by ADR 0044's grammar: `--<component>[-<variant>][-<part>]-border-radius[-<state>]`.
- **The census** (`npm run theme-census`) has section 7 for colour literals in structural rules and none for shape.
- **The proof** that a literal became a variable without a paint change is `npm run theme-equality` (#22300): computed styles per component, theme and state. A declaration diff is no proof (`#18232`, "Avoided Traps").
- **Precedent for one such literal:** `#18232` turned `code { border-radius: 4px }` into `--global-code-border-radius`.

## The Fix

One pull request, after the rename (#22349) has merged, so the new names are born in its grammar and no theme file is renamed under it:

1. Each of the 64 literal lengths becomes a read of a component variable, new or existing. Corners that are one decision share one variable. The `999px` pills get one too: they are a theme's `full`.
2. Every theme folder present at the pull request's base declares each new variable with the literal's value, so no pixel moves.
3. The census gains a section, "Corner radius literals in structural rules (engine files)", with the count and the files.
4. A guard fails a literal length in a corner-radius declaration under `resources/css/src` outside `apps/` and `examples/`. `0`, `inherit` and percentage-only values pass.

- [ ] The guard fails a new literal length and passes `0`, `inherit` and percentage-only values; its spec shows both.

## Out of Scope

- Binding the new variables to `--neo-radius-*`: that is each package's `theme-base` move (#22351 and its siblings).
- `apps/` and `examples/`.
- Border widths and shadows: not measured here.
- The values themselves. No radius changes in this leaf.

## Avoided Traps

- **Folding the sweep into each `theme-base` move.** It would spare the per-theme declarations this leaf adds and the moves delete again. It also turns each mechanical move into a structural edit, and a package that moves late keeps its literals until then. One sweep behind the equality run keeps every move a binding change. If the epic's steward folds it the other way, this leaf keeps items 3 and 4.
- **Proving it with a declaration diff.** The cascade can change without a declaration changing (`#18232`). The gate is the computed-style run.
- **Sweeping percentages.** `50%` is a circle, not a theme's choice.
