# A String key field fed numeric ids breaks get() in Store and TreeStore

## Context

Measured on `dev` `32fb6cb32e` with a throwaway unit probe: model field `{name: 'id', type: 'String'}`, rows `{id: 1}`, `{id: 2}` (TreeStore: `{id: 1, parentId: null}`, `{id: 2, parentId: 1}`, `{id: 3, parentId: null}`), once in Turbo Mode (`autoInitRecords: false`) and once eager:

```
Store     autoInit=false | get(1)#1=record(id="1") get(1)#2=null same=false get('1')=record(id="1") same-as-#1=true getAt(0)===#1:true
TreeStore autoInit=false | get(1)#1=record(id="1") get(1)#2=record(id="1") same=false | getChildren(1)[0] same=false get(2)===child:false get('2')===child:false
Store     autoInit=true | get(1)#1=null get(1)#2=null same=true get('1')=record(id="1") same-as-#1=false getAt(0)===#1:false
TreeStore autoInit=true | get(1)#1=record(id="1") get(1)#2=record(id="1") same=false | getChildren(1)[0] same=false get(2)===child:false get('2')===child:false
```

A flat Store answers `get(1)` once, then `null` (Turbo), or never (eager). A TreeStore returns a new record on every `get(1)` and every `getChildren(1)`, in both modes, so an edit on one of them is lost. With string ids every identity holds.

## The Problem

A record's key is the converted value (`'1'`). Since #17716 the Store has a primitive for exactly that, `Store#getCanonicalKey(value)`, but the stores' own boundaries never call it: a raw item registers under its raw key, `get(key)` looks the argument up as given, and `TreeStore` keeps raw items under raw keys in `#allRecordsMap` while records sit under converted keys.

## The Architectural Reality

- `Store#getCanonicalKey` (`src/data/Store.mjs:1592`) returns the key insertion stores, by delegating to `RecordFactory`'s parser, or `undefined` outside its supported domain (`calculate`, `convert`, object results, `NaN`, absent). Its callers today: `onPipelinePush`, `list/Base`, `list/Buffered`, `list/ValuePicker`, `component/Gallery`, `component/Helix`, `form/field/Chip`.
- `Store#getKey(item)` (`:683`) returns the raw value for a raw item and the converted value for a record.
- Base `Store#hydrateRecord` (`:1054`) moves a map entry from the raw key to the record's key, which is why a second `get(1)` misses in Turbo Mode.
- `TreeStore#get` (`src/data/TreeStore.mjs:721`) falls back to `#allRecordsMap` by the raw argument; `TreeStore#hydrateRecord` (`:877`) stores the record under its key and leaves the raw-key entry in place.
- Design authority: `getCanonicalKey`'s JSDoc: "a key whose wire type differs from the stored one is therefore not a near-miss but a miss".

## The Fix

Use the canonical key at the stores' own boundaries:

1. `Store#get(key)`, `TreeStore#get(key)` and `TreeStore#getChildren(key)` look up `getCanonicalKey(key) ?? key`.
2. A raw item registers in the map, and in `TreeStore`'s `#allRecordsMap`, under its canonical key, so hydration has nothing to re-key.

The canonical key is one more call per row on the Turbo Mode ingestion path: measure 100,000 rows before and after.

## Acceptance Criteria

- [ ] With a `String` key field and numeric raw ids, in both modes: `get(1)`, a second `get(1)` and `get('1')` return the one record `getAt(0)` returns.
- [ ] `TreeStore`, both modes: `getChildren(1)[0]` is the same record on every call and is `get(2)`; an edit on it survives a later `get(2)`.
- [ ] String ids, a store without a declared key field, and a key the primitive refuses (`calculate`, `convert`) behave as before: the `test/playwright/unit/data` specs pass unchanged.
- [ ] The ingestion of 100,000 Turbo Mode rows, before and after, is in the PR body.
