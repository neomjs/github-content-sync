# An outside contributor gets a standing, a badge and a next issue

Terminal predicate: every merged pull request from outside the team gets one comment that names its author's standing and two open issues, the badge of that standing is served under neomjs.com in three forms for every outside contributor, each contributor who merged before the badges were live has been told once, the claim reply honours standing, the guide explains all of it, and the read at 40 outside merges is recorded.

> **Restated on 2026-11-13.** The badge was first planned as one static file per rung, which any account could have shown. It is now per contributor and keyed by the account id; see "The badge" and "Unresolved Dissent".
>
> **Restated on 2026-11-14.** Every outside account with a merged pull request holds a badge from the first run, and an account that merged before the badges were live is told once, on its latest merged pull request (#20949). The rule that a badge needs a merge after the launch is gone: of the 120 accounts concerned, 75 have merged exactly once.

## Problem scope

Contribution is how most people first meet this repository, and the path ends at the merge. Measured on `neomjs/neo` on 2026-11-12 (pull requests whose author is not a bot and not a member, owner or collaborator; aggregates only, no account is named):

| Read | Value |
|---|---|
| Accounts with a merged pull request since July 1, and their merged pull requests | 47 accounts, 69 pull requests |
| Of those accounts: exactly one merge / two / more | 39 / 6 / 2 |
| First merge at least 30 days old: accounts, and those with a second merge within 30 days | 20, 3 |
| Starred the repository | 2 of 47 |
| Open to merge, outside pull requests of the last 30 days | median 2.2 hours |

A contributor reads a ticket, writes a fix and a test, gets a merge two hours later and hears nothing more. Nothing at the merge says what they could take next, nothing they could show for it exists, and nothing on the path shows the engine running. The merge is the one moment at which the person certainly hears from us, because GitHub notifies the author.

Why an epic: five changes in two repositories share one definition of standing and land in an order (the badge files, the module and the comment, the launch with its note to earlier contributors, the claim reply, the guide).

## Intended solution

**Standing is one count, derived when asked and never stored.** The author's merged pull requests across the public repositories of the `neomjs` organisation: `org:neomjs is:pr is:merged author:<login>`. At a merge the count is the merges before the event plus the event itself (`merged:<` the event's `merged_at`, plus one), so it never waits for search to index the merge. "Outside" is `isOutsideHuman` of `buildScripts/util/claimResponse.mjs`: not a bot, and an association other than `COLLABORATOR`, `MEMBER` or `OWNER`. No second definition is written.

**The rungs.** A published slug is never renamed, removed or repurposed. A renamed rung changes the words on the art; a new rung adds a file.

- `bronze` — 10, Bronze Contributor
- `silver` — 25, Silver Contributor

- `diamond` — 100, Diamond Contributor

**The badge is per contributor and generated from the public merge record**, so it can only show what the record says for the account it names. Each contributor has one folder in `neomjs/pages`, served under `https://neomjs.com/`. The folder's name is `<login>-<id>`: GitHub's numeric account id decides, because a changed login is free for anyone to claim, and the login is the readable part. The folder is a small page, the account's record: it names the account, its rung and its count and links to the account's merged pull requests on GitHub and to the home page. It holds the badge in three forms (a card, a plate, a medal), each with the account's handle printed on it. One scheduled workflow of `neomjs/pages` writes the folders. Every account with an outside merge gets one, from the first run on (#20949). An account that merged before the badges were live is told once, on its latest merged pull request, and any account can ask to be left out.

- `badges/<login>-<id>/card.svg`
- `badges/<login>-<id>/plate.svg`
- `badges/<login>-<id>/medal.svg`
<!-- /binding-inventory -->

A published folder is never repurposed and is removed only at its holder's request. After a rename the workflow writes a folder for the new login and keeps rewriting the old one, so a pasted line keeps working and shows the current handle.

**The line a contributor pastes** never changes while the rung does: `<a href="https://neomjs.com/badges/<login>-<id>/"><img src="https://neomjs.com/badges/<login>-<id>/card.svg" alt="Neo.mjs contributor"></a>`. The link is the account's record, which is where a reader checks the badge. It carries no marker, so the first version attributes no arrivals.

**What this guarantees, and what it does not.** A badge under neomjs.com is true about the account it names. Copying a line cannot be prevented: a copied badge shows someone else's true standing under their handle. On a GitHub profile the profile's own name stands beside it; anywhere else one click lands on the named account's record. The read counts how often a line is shown by another account.

**The comment.** One comment per merged outside pull request, posted once. It names the standing and what the next rung needs, hands over the badge line once (the line never changes; at a new rung the comment says that the badge now shows it), names two open, unassigned curated issues with the reason each follows the merged work and links the full list, and at a rung carries one invitation chosen by what the pull request touched. Every sentence informs a person; none tells an agent to act on someone's behalf. A star is one plain sentence and never a condition of anything.

**Standing in the claim reply.** From five merged pull requests a contributor holds two open curated claims at once in this repository. The claim window stays three days for everyone: a claim that delivers does so within hours, so a longer window only lengthens a silent hold.

**The workflow** runs on a merged `pull_request_target`, checks out only the modules from the default branch, never the pull request's head, and reads the payload in script. A soft error warns and ends green, because a `pull_request_target` run anchors its check runs on the pull request's head and a red one would stay on a contributor's merged pull request (#20061).

**The engine goes first.** It holds 49 of the 57 outside merges of the last 30 days across the organisation (2026-11-13). Another repository later copies the caller and imports the same module, as the claim responders do.

**The read.** Forty outside merges after the first comment, three observations are read apart: breadth (first-time outside authors, and the stock of unassigned curated issues), return (a second merge within 30 days of the first; before: 3 of 20) and reach (profiles that show a badge line, and how many of those lines name another account). The first comment's URL is the start of the "after". The accounts told once by #20949 are read as a group of their own: how many of them merge again within 30 days of the note. The read's record lives in the maintainers' planning repository (`neomjs/business#75`); everything needed to build is in this epic and its leaves.

The generator, its workflow and the folders are neomjs/pages#73; the other leaves are linked as sub-issues.

## Out of scope

- The record as a route of the portal. The static page comes first, because a portal view reaches neomjs.com only with an engine release. The portal later takes over the same address, so no pasted line changes.
- A list of all contributors.
- The comment in the other public repositories.
- A mechanical check that an outside pull request's changed spec fails on `dev`. It came out of the review of this plan and gets its own ticket.
- Attribution of arrivals from a badge.

## Avoided traps

- **A ladder that starts at ten.** One account since July reached ten merges, so a first rung at ten pulls on nobody who stands at one.
- **A longer claim window as a reward.** See "Standing in the claim reply".
- **A static file per rung.** Any account could show any rung, and a published address cannot be taken back. This was the first plan of this epic.
- **An address keyed by the login.** GitHub frees a changed username for anyone to claim, so a freed login would inherit a genuine badge.
- **A GitHub login for getting a badge.** The facts are public and the pasted line is public, so a login proves who generated a line and never who shows it; it would also put a client secret and personal-data duties on the site.
- **A tooltip that names the account.** An SVG shown as an image reacts to nothing, and a tooltip in the pasted line belongs to whoever pastes it. The handle is printed on the image.
- **A list of contributors as the badge's landing.** A grid of logins verifies nothing and tells a stranger nothing. The landing is the one account's record, which says in one sentence what Neo.mjs is and links to the home page.
- **A marker in the badge's link.** Nothing reads it, it cannot be removed from a pasted line, and it gives the record a second address.
- **Renaming the curated labels.** They are the search key (#20889).
