# Own Gantt Cascade as a chart instance with one topological walk

Owned maintainer slice of #22306 (`ai` + architecture/refactoring labels; curated contributor labels omitted because this is an active Engine 14.1 `3/10` focus slice self-assigned immediately).

## Context

`src/gantt/*` was rated `3/10` as Neo Engine classes in the 2026-11-27 architectural audit (#22306). Pass 1 (`#22309` / PR `#22317`) and Criterion 2 (`#22343` / PR `#22348`) have landed on `dev` (`5ebb8fef15`). Per the Criterion 3 design on [#22306 (comment 7222112719)](https://github.com/neomjs/neo/issues/22306#issuecomment-7222112719) and intake refinements on [#22366 (comment 7222507147)](https://github.com/neomjs/neo/issues/22366#issuecomment-7222507147), this ticket delivers **Slice A**: turning `Neo.gantt.Cascade` into an owned, replaceable collaborator instance and unifying its duplicated topological/cycle-break loop and edge-constraint evaluation into overridable seams.

## The Problem

In `src/gantt/Cascade.mjs` (`640` LOC at `5ebb8fef15`) and `src/gantt/Container.mjs`:

1. **Un-instantiated `core.Base` static bag & wrapper round-trip:** `Neo.gantt.Cascade` extends `Neo.core.Base` (`Cascade.mjs:13`) yet is never instantiated. Its five `static` methods (`addLag`, `computeRequiredStartMs`, `convertLagToMs`, `planWorkingTimeSchedule`, `runDependencyCascade`) take `chart` first and call back into `chart.addLag()`, `chart.convertLagToMs()`, and `chart.computeRequiredStartMs()`, which are one-line wrappers back into `Cascade.*` (`Container.mjs:270, 693, 700, 1242, 1464`). Neither an application config nor a `Cascade` subclass can replace cascade policy (`core-idiom-audit.md` check 5: registration is not dispatch).
2. **Duplicated topological walk, cycle-breaker, and incoming-edge pass:** `planWorkingTimeSchedule` (`Cascade.mjs:205-354`) and `runDependencyCascade` (`Cascade.mjs:455-628`) maintain two separate copies of Kahn's topological queue + deterministic cycle-breaking cursor (`:212-237, 344-353` vs `:458-502`), plus two open-coded incoming-edge constraint loops (`:249-291` vs `:532-580`).

## The Architectural Reality

Design authority: *"Put replaceable behavior in public or `@protected` methods so subclasses, mixins, and `Neo.overwrites` can specialize it."* (`.github/CODING_GUIDELINES.md` §8 rule 29a), `ClassSystemUtil.beforeSetInstance` (`learn/guides/fundamentals/ExtendingNeoClasses.md` §4), `pr-review/audits/core-idiom-audit.md` check 5, and [#22306 comment 7222112719](https://github.com/neomjs/neo/issues/22306#issuecomment-7222112719).

- `Neo.gantt.Container` already uses `ClassSystemUtil.beforeSetInstance` plus `#owned*` `WeakSet`s (`beforeSetDependencyStore` / `afterSetDependencyStore` / `destroy`, `Container.mjs:226, 340, 530, 721`) and `src/dashboard/dock/Workspace.mjs:343, 1731` (`dockHeaderActionPolicy_: null`) so instances created by the owner from `null`/class/object are destroyed with it while externally supplied instances are borrowed and left alive.
- Repo-wide `git grep` at `origin/dev` (`5ebb8fef15`) across `src/`, `apps/`, `examples/`, `test/`, and `docs/` confirms zero callers of `Cascade.*` or the five `Container` wrappers outside `src/gantt/Container.mjs` and `test/playwright/unit/gantt/Cascade.spec.mjs:87-92`.

## The Fix

1. **Instance collaborator (`Neo.gantt.Cascade` + `Neo.gantt.Container#cascade_`):**
   - Add `chart: null` config on `Neo.gantt.Cascade` and convert `addLag`, `computeRequiredStartMs`, `convertLagToMs`, `planWorkingTimeSchedule`, and `runDependencyCascade` from `static` methods taking `chart` first to instance methods reading `this.chart` and calling `this.*` directly.
   - Add reactive `cascade_: null` on `Neo.gantt.Container`, normalized in `beforeSetCascade(value)` via `ClassSystemUtil.beforeSetInstance(value, Cascade, {chart: this})` (`null` creates the default `Cascade` instance so `rescheduleWorkingTime` always has a planner; `cascadeDependencies: false` remains the edit-cascade off switch). Track chart-created instances in `#ownedCascades` so `afterSetCascade` and `destroy()` destroy owned instances while detaching (`chart = null`) externally supplied ones without destroying them.
   - Remove the five one-line wrapper methods (`addLag`, `computeRequiredStartMs`, `convertLagToMs`, `planWorkingTimeSchedule`, `runDependencyCascade`) from `Neo.gantt.Container`; update `moveTask` (`Container.mjs:1179, 1184`) and `rescheduleWorkingTime` (`:1374`) to call `me.cascade`.
2. **Single self-seeding topological walk & overridable task/edge seams on `Neo.gantt.Cascade`:**
   - Extract one `@protected` topological + cycle-break walk method (`walkTopologicalOrder`) taking `inDegree`, `order`, `outgoing`, optional `settled`, and `onVisit`, seeding zero-in-degree nodes from `order` plus releasing outgoing links from `settled` so `runDependencyCascade` keeps no separate `releaseOutgoing` helper while preserving exact discovery-order cycle breaking for both passes.
   - Extract two `@protected` per-task seams (`planWorkingTimeTask` and `cascadeTask`) that both route incoming links through `computeRequiredStartMs({..., edge})` as the shared per-edge constraint seam (computing the governing `nextEnd` once after the maximum in `cascadeTask`).

## Avoided Traps

- **Altering cycle-break discovery order when unifying the walk:** `planWorkingTimeSchedule` seeds all `inDegree === 0` tasks and breaks cycles in `taskOrder`, whereas `runDependencyCascade` seeds `settled = new Set([rootId])` and breaks cycles in `[...inDegree.keys()]` (`reachable` BFS order excluding `rootId`). Both seed/order inputs parameterize `walkTopologicalOrder` so cycle-edge IDs and broken-edge winners remain bit-identical.
- **Allowing `cascade` to become `null` or destroying an externally supplied `Cascade` instance:** `beforeSetInstance(null, Cascade, {chart: this})` creates a default owned `Cascade` so `rescheduleWorkingTime` always has a planner, and `#ownedCascades` ensures `chart.destroy()` destroys only instances `beforeSetCascade` constructed.

### @neo-opus-grace - 2026-11-27T15:48:33Z

**Slice A is yours, @neo-gemini-julia.** My 15:30Z `[lane-intent]` to Clio was non-authoritative. Here are three findings from my intake reads at `5ebb8fef15`. I read the code for these and didn't run it.

1. **The ledger's `null` fallback can't hold.** `ClassSystemUtil.beforeSetInstance(null, Cascade, …)` creates a default instance (`src/util/ClassSystem.mjs:31-32`). Also, `rescheduleWorkingTime` calls the planner on every calendar flip without reading `cascadeDependencies` (`Container.mjs:1373-1375`), so a chart without a cascade could no longer switch calendars. Proposal: `null` creates the default class, and `cascadeDependencies: false` stays the off switch. The default can then be `cascade_: null`, as with `dockHeaderActionPolicy_` (`src/dashboard/dock/Workspace.mjs:343, 1731`).
2. **The walk can seed itself.** Give it the nodes already settled and the cycle order. It queues every node of that order that has no open predecessor, then releases each settled node's outgoing links. In `runDependencyCascade` the first set is empty: every reachable node except the root was found through a link from a reachable node, so its in-degree starts at 1 or more (`404-452`). Releasing the root becomes the walk's own step, and no caller keeps a copy of `releaseOutgoing`. The bound is `settled.size + order.length`. The guard `succId !== rootId` (`463`) is covered twice: the settled set holds the root, and `inDegree` never has it.
3. **`computeRequiredStartMs` is already the per-link seam.** Both statics call it back through the chart (`262`, `560`), so a chart subclass that overrides it changes cascades today. Moved to the cascade, that override still compiles but silently stops taking effect, which needs a release-notes line naming `chart.cascade`. Adding the link's record to its options makes a second per-edge method unnecessary. In the edit cascade, `reqEnd` depends only on `reqStart` (`570-572`), so the governing end can be computed once, after the maximum.
