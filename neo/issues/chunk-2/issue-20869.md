# HighlightJS line requests can outlive their code node

## Context

The first case of `test/playwright/e2e/portal/DocsMixinsNL.spec.mjs` failed twice in the hosted E2E shard for #20865 with the same error:

```text
Cannot read properties of null (reading 'querySelector')
at HighlightJS.syntaxHighlightLine (src/main/addon/HighlightJS.mjs:198)
```

This is a separate source-view lifetime defect, not evidence against #20864's metadata delivery repair.

## The Problem

A line-highlight request can reach Main after ordinary Docs tab navigation has removed its code leaf. Main dereferences that absent element and the error reaches the page.

A controlled native witness uses the actual Docs source route and class-tab navigation:
1. Open `Docs.app.view.MainContainer` source at line1; the normal line highlight succeeds.
2. Request line20 and hold the genuine Main line request while its code node exists.
3. Navigate to the class tab; the existing card layout removes the inactive source DOM.
4. Deliver the held original method. The code node is absent and the call throws.

The exact Manager modules were response-hash verified:

| Manager | Held request captured | Target at execution | Result | Metadata-only batches |
| --- | --- | --- | --- | --- |
| admitted `1b12232214a5b36bec6ca0255c2b93b5ef51e3ed` | present, ready | absent | same null-target error | 0 |
| candidate `c7eee289cd6c8e49ee5ae037595d8e1e7dce5ba2` | present, ready | absent | same null-target error | 0 |

An unmodified natural baseline replay passed once. The held cases establish the inherited lifetime boundary, not its natural frequency. The two hosted occurrences independently establish that ordinary navigation reaches it.

## The Architectural Reality

- `docs/app/view/classdetails/SourceViewComponent.mjs:95–105` schedules line highlighting after 50ms; the request can outlive the source leaf.
- `src/layout/Card.mjs` defaults `removeInactiveCards:true`, and Docs activates inserted content tabs. Removing an inactive source leaf is expected behavior.
- `src/main/addon/HighlightJS.mjs#syntaxHighlightLine` obtains `document.getElementById(data.vnodeId)` and unconditionally queries it in both add-line and remove-line paths.
- The adjacent `syntaxHighlight` method already ignores an absent code element.
- `Manager#onWorkerMessage` dispatches this through its unchanged `remoteMethod` branch. Docs, HighlightJS and the failing spec are byte-identical between the two source pins.

Design authority: the existing source-view navigation contract and inactive-card removal behavior (#1010), plus the adjacent highlighter's absent-target no-op. A visual callback arriving after its target leaves the document must not turn valid navigation into an uncaught error.

## The Fix

Make `HighlightJS#syntaxHighlightLine` settle without DOM work when its code leaf is absent. Keep the readiness/cache check first, and retain add/remove class and scroll behavior for a present leaf.

Prescription checked: `src/main/addon/HighlightJS.mjs` owns the final DOM lookup. A worker-side mounted check cannot guarantee that a node still exists when an already-sent RPC reaches Main. No timer redesign, lifecycle generation or new consumer obligation is needed.

Extend the existing HighlightJS unit spec and Docs native spec. Preserve the normal route case and the automatic worker/page-error assertion.

| Surface | Authority | Behavior | Boundary | Evidence |
| --- | --- | --- | --- | --- |
| Late line request | Main DOM lookup | absent target settles as a no-op | applies to add and remove | missing-target red controls |
| Present code leaf | existing method | add/remove line classes and scroll to added line | no behavior change | mounted positive control |
| Library readiness | existing addon cache | not-ready requests keep their current queued path | no early DOM lookup | readiness control |
| Docs navigation | source/class routes and card layout | late delivery after actual tab removal produces no page/worker error | no artificial DOM removal or error waiver | controlled native route plus existing cases |

Decision Record impact: none; existing Main-thread DOM boundary repair. Structure-map: N/A, existing runtime method and existing test families.

## Acceptance Criteria

- [ ] Missing code nodes are harmless for both add-line and remove-line requests; the controls fail on pre-fix source.
- [ ] Mounted add/remove highlighting and scroll behavior are preserved; the readiness cache still receives not-ready calls before DOM lookup.
- [ ] A genuine held line request delivered after actual Docs class-tab navigation removes the leaf completes without page/worker errors. Initial mounted highlighting remains a positive control.
- [ ] Existing DocsMixins and HighlightJsResources native cases and relevant units pass without skips, weakened error assertions or added timing sleeps.
- [ ] No Manager transport, Docs route semantics, inactive-card retention policy or new public API is changed.

## Out of Scope

#20864's metadata delivery gate; highlighter resource packaging; unrelated `scrollIntoView` hardening; generic callback cancellation; a new Docs application.

## Avoided Traps

Checking only worker `mounted` before sending; retaining inactive source DOM to evade cleanup; retrying or suppressing the error; changing the 50ms timer; swallowing unrelated exceptions.
