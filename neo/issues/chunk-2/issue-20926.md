# Give the Workstation one visitor-facing tour

## Context

On first launch the Workstation asks a visitor to choose between **Start dense tour** and **Start film tour**. Both are real playback paths. A visitor has to know how we produced the demo to choose their first click. [Tour toolbar at the reported revision](https://github.com/neomjs/neo/blob/a07f581f131e58de9870a30f2a7dd23dffb6784d/apps/workstation/view/TourToolbar.mjs#L26)

## The Problem

Film production and test playback acquired their own product entry points. Moving the two choices into a menu would still leave the visitor with two tours.

## The Architectural Reality

Design authority: Tobi’s Workstation review, November 14, 2026: “i insist that there is one tour”. The earlier [topology toolbar decision](https://github.com/neomjs/neo/issues/18680) reserves the second row’s actions for Reset to default, Undo and Redo. The shared Workstation owns both headers. Its tour controller already has a programmatic path for exercising a specific script.

## The Fix

Offer one **Start tour** action and one visitor-facing sequence. Choose or combine the existing scenes into that sequence. Keep capture and test playback accessible to their callers through the tour driver. Update the Workstation README and any tests that teach the two-launcher UI.

## Acceptance Criteria

- [ ] On a fresh launch, one keyboard-accessible **Start tour** begins the product tour directly. There is no second visitor tour, mode picker or alternate launcher elsewhere in the UI. Conditional **Continue** advances the running tour.
- [ ] In the normal Workstation browser suite, inspect the rendered actions across both global header rows on first paint and during playback. Scope the assertion by header ownership and semantic action so a new or renamed test button, including an icon-only one, fails the check. Theme and tour progress remain usable. The topology row offers Reset to default, Undo and Redo.
- [ ] Demonstrate that the check catches an extra action, then run it against the final UI. The product tour completes, and the existing scripted film/test journeys can still run through their drivers. Include a first-launch header frame in the PR.
- [ ] Record the placement rule beside the existing Workstation UI guidance: a new demo or test scenario uses the runner or fixture; a new function belongs where a person uses it. A deliberate change to the global actions changes the documented design and its test together.

**Verification starting points:** `WorkstationTourActivationNL.spec.mjs` already boots the real app and exercises playback. `WorkstationTopologyGroupsNL.spec.mjs` already checks the three layout actions.

## Out of Scope

The film edit, caption wording, and a redesign of Workstation layout or history.

Related: #18680, #18458, #19070. The earlier film work supplies reusable scenes and playback. This decision supersedes the two public start buttons.
