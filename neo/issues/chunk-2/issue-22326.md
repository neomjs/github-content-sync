# Reserve neo-theme- class prefix and rename ThemeSwitcher classes

## Context

Implements Seam 5 / Order-of-work step 4 (*"The reserved class prefix"*) of Design System Epic #22295 (`ms:v14.1`, graduated from [Discussion #22228](https://github.com/orgs/neomjs/discussions/22228) and recorded in [`learn/agentos/decisions/0044-design-system.md`](https://github.com/neomjs/neo/blob/dev/learn/agentos/decisions/0044-design-system.md) §2.7 and §2.10 Invariant **I4**).

## The Problem

Under ADR 0044, `theme-base` declares every component variable once on the single attribute selector `[class*="neo-theme-"]` so variables resolve against roles at every theme root (`neo-theme-<name>`) and inline role scope (`neo-theme-scope`). Runtime theme resolvers (`src/Main.mjs`, `src/component/Base.mjs`, `src/draggable/DragZone.mjs`, `src/draggable/container/SortZone.mjs`, `src/draggable/tab/header/SortZone.mjs`, `src/tooltip/Base.mjs`, and `buildScripts/docs/captureExamples.mjs:456`) likewise inspect `startsWith('neo-theme-')` or `[class*="neo-theme-"]`.

Today `Neo.button.ThemeSwitcher` (`src/button/ThemeSwitcher.mjs:24,29,304,313`) declares `ntype: 'theme-switcher'` (whose `component.Base#afterSetUi` emits `neo-theme-switcher-ghost`) and stamps `neo-theme-switcher`, `neo-theme-switcher-menu`, and `neo-theme-switcher-icon-{sun,moon,palette}`. Because all six tokens begin with `neo-theme-`:
1. `[class*="neo-theme-"]` matches the switcher button, its floating menu, and its glyph node, re-binding `theme-base` `--button-*` / `--menu-*` component variables on the widget itself and clobbering ancestor toolbar overrides.
2. `captureExamples.mjs:456` had to document a manual workaround warning that `neo-theme-switcher` is not a theme class.
3. Without a mechanical guard, any future widget or example introducing a `neo-theme-*` CSS class or `theme`/`theme-*` `ntype` silently creates an unintended theme scope.

## The Architectural Reality

- Design authority: `"The class prefix neo-theme- is reserved. neo-theme-<name> is a theme; neo-theme-scope is a scope that keeps its theme."` (`learn/agentos/decisions/0044-design-system.md` §2.7; §2.10 **I4**: *"A class with `neo-theme-` is a theme class or `neo-theme-scope` (a guard in step 2)."*)
- Repo-wide `git grep -hoE "neo-theme-[a-zA-Z0-9_-]+"` across `resources/css/**`, `src/**`, `apps/**`, and `examples/**` (`neomjs/neo`, plus `0` hits across `neomjs/neo-agent-institution` and `neomjs/devindex`) shows that **only** `ThemeSwitcher` violates the reserved prefix outside JSDoc `@example` prose (`src/button/ThemeSwitcher.mjs:47`).
- Neo's compound-noun widget `baseCls` and `ntype` convention (`dateselector`, `monthyearselector`, `textfield`, `switchfield`, `selectfield`) gives `ntype: 'themeswitcher'` and the non-colliding class stem `neo-themeswitcher` (`neo-themeswitcher`, `neo-themeswitcher-ghost`, `neo-themeswitcher-menu`, `neo-themeswitcher-icon-{sun,moon,palette}`), avoiding both `[class*="neo-theme-"]` and `Neo.button.Base#ui`'s `neo-button-<ui>` namespace while preserving `super.afterSetUi` and consumer `{ntype: 'themeswitcher'}` configs.
- `buildScripts/util/themeCss.mjs#collectThemeClassMap` (landed in `#22298` / `#22304`) derives the canonical set of declared theme classes from `resources/css/*/Global.css`, so the new guard reads declared theme classes dynamically rather than hardcoding a theme list (satisfying **I7** alongside **I4**).
- Structural pre-flight (Stage 1 fast-path): `buildScripts/util/check-theme-class-prefix.mjs` sits beside `buildScripts/util/check-theme-value-files.mjs` and `buildScripts/util/check-theme-var-references.mjs` (exporting tracked `SCAN_SURFACE` globs for `ScanSurfaceAlignment.spec.mjs`), with unit coverage at `test/playwright/unit/buildScripts/util/check-theme-class-prefix.spec.mjs`.

   - `src/button/ThemeSwitcher.mjs`: `ntype: 'themeswitcher'`, `baseCls: ['neo-button', 'neo-themeswitcher']`, menu `cls: ['neo-themeswitcher-menu']`, `iconCls: 'neo-themeswitcher-icon-' + icon`.

   - `buildScripts/docs/captureExamples.json` (7 dark-theme switcher selectors) and `buildScripts/docs/captureExamples.mjs` (JSDoc note at line 456).
   - `13` Playwright specs (`test/playwright/component/button/ThemeSwitcher.spec.mjs` and `12` e2e specs, including `{ntype: 'themeswitcher'}` queries in `StandaloneThemeSwitcher.spec.mjs` and `ExamplesCatalogTheme.spec.mjs`).
2. **Add reserved-prefix guard (`buildScripts/util/check-theme-class-prefix.mjs`) + hook/CI parity:**
   - Allow only theme classes discovered via `collectThemeClassMap([path.join(repoRoot, 'resources/css')])` plus `'neo-theme-scope'`.
   - Scan `resources/css/**/*.css` selector headers and `{src,apps,examples}/**/*.{mjs,html}` non-comment `neo-theme-*` class tokens / concatenation prefixes AND reserved `'theme'` / `'theme-*'` `ntype` values (whose `component.Base#afterSetUi` derives `neo-theme-*` classes at runtime), failing closed with `file:line` diagnostics while preserving dynamic prefix utilities (`startsWith('neo-theme-')`, `/^neo-theme-/`) and JSDoc examples.
   - Export `SCAN_SURFACE` and wire `node ./buildScripts/util/check-theme-class-prefix.mjs` into `package.json` (`scripts` + `lint-staged`) and `.github/workflows/pr-baseline.yml` (`guards`).
3. **Add unit spec (`test/playwright/unit/buildScripts/util/check-theme-class-prefix.spec.mjs`):**
   - Verify live-tree pass, fail-closed detection on rogue `.neo-theme-switcher` / `.neo-theme-unregistered` in CSS, `.mjs`, and `.html`, fail-closed detection on `ntype: 'theme-switcher'` alongside clean pass on `ntype: 'themeswitcher'` in both class definitions and consumer configs, comment stripping, and missing-root fail-closed `[surface]` error.

## Out of Scope

- Adding runtime `.neo-theme-scope` injection on `component.Base` when inline `--neo-*` styles are set (owned by the downstream `"The scope class"` step in Epic #22295 after the `--neo-*` property-prefix guard lands).
- Setting `color-scheme: var(--neo-color-scheme)` once on `[class*="neo-theme-"]` (owned by #22335 / PR #22337).

## Avoided Traps

- **Hardcoding the 5 built-in theme names in the guard:** violates ADR 0044 **I7** and would reject a newly added theme folder (e.g. `theme-neo` or Material) whose `Global.css` declares its class. Derive valid theme classes via `collectThemeClassMap`.
- **Keeping `ntype: 'theme-switcher'` with a file-level `afterSetUi` exemption:** `component.Base#afterSetUi` derives `neo-${ntype}-${ui}` (`neo-theme-switcher-ghost`), and a file-level `afterSetUi` exemption rejects consumer blueprints (`{ntype: 'theme-switcher'}`). Renaming `ntype` to `'themeswitcher'` removes the root cause cleanly.
- **Renaming `ThemeSwitcher` to `neo-button-theme-switcher`:** collides with `Neo.button.Base#ui` (`'neo-button-' + ui`, where `ThemeSwitcher` already uses `ui: 'ghost'` → `neo-button-ghost`). Compound `neo-themeswitcher` matches `neo-dateselector` / `neo-switchfield`.
- **Matching bare `'neo-theme-'` prefix strings in JS:** runtime theme resolvers legitimately call `.startsWith('neo-theme-')` and `.replace(/^neo-theme-/, '')`; only tokens with one or more characters after `neo-theme-` (`neo-theme-[a-zA-Z0-9_-]+`) represent class names or class sub-prefixes like `'neo-theme-switcher-icon-' + icon`.
