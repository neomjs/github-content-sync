# A disabled CheckBox, Radio or Switch still toggles from the keyboard

Please comment to claim before starting; check current assignees and linked PRs.

Live latest-open + closed sweep: latest open plus open and closed search ("checkbox disabled keyboard", "CheckBox disabled native", "disabled checkbox toggles") at 2026-11-27T04:54Z (Out of Scope read on #22286 and #18818); no equivalent or prior exclusion found. Backlog band: 52 open (red); the native-disabled fix for text fields (#22262, PR #22266) did not cover check boxes.

## Context

A disabled check box can still be changed from the keyboard. Probed in Chromium on `examples/form/field/checkbox` (its `disabled` state), with the disabled text field of `examples/form/field/text` as the control:

```text
checkbox  native disabled: false · Tab reaches it: yes · Space: checked true → false
text      native disabled: true  · Tab reaches it: no
```

`Neo.form.field.Radio` and `Neo.form.field.Switch` extend `CheckBox`, so they inherit the gap.

## The Problem

`.neo-disabled` sets `pointer-events: none`, which stops the mouse but not the keyboard. The native `<input type="checkbox">` keeps no `disabled` attribute, so Tab focuses it and Space toggles it. `onInputValueChange` then sets `checked` and fires the user change event, which means a form can submit a value the user was not allowed to change. Assistive technology also announces the control as enabled.

## The Architectural Reality

- `Neo.component.Base#afterSetDisabled` only toggles the `neo-disabled` class.
- `Neo.form.field.Text#afterSetDisabled` (since #22266) also projects the state onto its native input with `me.changeInputElKey('disabled', isDisabled ? true : null, true)`. `changeInputElKey` lives in `Neo.form.field.Base`, so `CheckBox` already has it.
- `CheckBox.mjs` has no `afterSetDisabled`. The component spec `test/playwright/component/form/field/CheckBox.spec.mjs` covers checking, but not the disabled state.

Design authority: "Disabled components will get the neo-disabled cls applied and won't receive DOM events" (`Neo.component.Abstract#disabled` JSDoc).

## The Fix

1. In `src/form/field/CheckBox.mjs`, add `afterSetDisabled(value, oldValue)`: call `super.afterSetDisabled(value, oldValue)`, then `this.changeInputElKey('disabled', value ? true : null)`. Read `Text#afterSetDisabled` first; a check box has no inline label or clear trigger, so the rest of that method does not apply.
2. In `CheckBox.spec.mjs`, add a case. A disabled check box's input is `disabled`; Tab skips it; Space and a click leave `checked` unchanged; setting `disabled: false` makes it reachable and togglable again.

## Acceptance Criteria

- [ ] AC-1 A disabled `CheckBox` renders its native input with the `disabled` attribute, and removes it when re-enabled.
- [ ] AC-2 With the component disabled, keyboard focus skips the input, and Space or a click does not change `checked`. The component spec proves it in a real browser.
- [ ] AC-3 `Radio` and `Switch` inherit the fix with no change of their own. One assertion on a disabled `Radio` shows it.

## Out of Scope

- `readOnly` for check boxes: the example notes "A check box has no read-only state".
- Other field types.
