# A pressed Button never tells assistive technology it is pressed

## Context

`Neo.button.Base` has a reactive `pressed_` config ([src/button/Base.mjs:124-128](https://github.com/neomjs/neo/blob/5ecce11aaa4ce4ea39e0006380796d59ed6abff9/src/button/Base.mjs#L124-L128)), and `afterSetPressed` ([:384-389](https://github.com/neomjs/neo/blob/5ecce11aaa4ce4ea39e0006380796d59ed6abff9/src/button/Base.mjs#L384-L389)) toggles only the `pressed` CSS class. The engine's own grid search toolbar writes the attribute by hand next to `set({pressed})` ([src/grid/SearchToolbar.mjs:67](https://github.com/neomjs/neo/blob/5ecce11aaa4ce4ea39e0006380796d59ed6abff9/src/grid/SearchToolbar.mjs#L67), [:262](https://github.com/neomjs/neo/blob/5ecce11aaa4ce4ea39e0006380796d59ed6abff9/src/grid/SearchToolbar.mjs#L262)), and app code that wants an accessible toggle has to copy that.

- **Design authority:** the WAI-ARIA Authoring Practices [button pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/): a toggle button exposes its state through `aria-pressed`. `pressed_` is documented as "The pressed state of the Button" with no semantics beyond the class.

## The Problem

A screen reader announces a toggle button's state from `aria-pressed`. A Neo button with `pressed: true` reads as a plain button, and its state change is silent. Every consumer that wants the right semantics writes the attribute itself, in a second write next to the config, and can drift from `pressed`.

## The Architectural Reality

- `pressed_` defaults to `false`, so `afterSetPressed(false)` runs for every button at construction. Today a plain button and a toggle that is off are the same state. Writing `aria-pressed="false"` on every button would announce plain buttons as toggles, so the attribute must stay off buttons that are not toggles.
- `toJSON()` serializes `pressed` ([:654](https://github.com/neomjs/neo/blob/5ecce11aaa4ce4ea39e0006380796d59ed6abff9/src/button/Base.mjs#L654)).
- Engine code that sets `pressed`: `src/toolbar/Base.mjs`, `src/dashboard/dock/interaction/RevealOverlay.mjs`, `src/grid/SearchToolbar.mjs`.
- Tab headers are buttons too. `Neo.tab.header.Button` (`role="tab"`) extends `Neo.button.Base` and calls `super.afterSetPressed()`, and `Neo.tab.Container` sets a Boolean `pressed` on every header (`src/tab/Container.mjs:543`, `:904-906`). A tab states its selection through `aria-selected` (`test/playwright/unit/tab/Aria.spec.mjs`); ARIA does not allow `aria-pressed` on `role="tab"`.

## The Fix

The button renders `aria-pressed` from `pressed` for toggle buttons only, in the same update that toggles the class. One shape: default `pressed_` to `null` (not a toggle), and let `afterSetPressed` write `aria-pressed` for a Boolean and remove it for `null`. Check the existing `pressed` readers first (for example strict `=== false` comparisons); if the default cannot move, an explicit toggle config is the alternative. Then `SearchToolbar` drops its manual writes. Tab headers keep `aria-selected` and render no `aria-pressed`.

## Acceptance Criteria

- [ ] A button whose owner sets `pressed: true` or `pressed: false` renders `aria-pressed="true"` / `"false"` and keeps it in sync on every change, in the update that toggles the `pressed` class.
- [ ] A button that never sets `pressed` renders no `aria-pressed`.
- [ ] A tab header (`role="tab"`) renders `aria-selected` and no `aria-pressed`.
- [ ] `src/grid/SearchToolbar.mjs` writes no `aria-pressed` itself, and its case button still follows the filter.
- [ ] A unit spec under `test/playwright/unit/button/` covers the plain, pressed and unpressed states through the vdom.

## Out of Scope

`aria-expanded` on menu buttons, the selection semantics of tab headers, toggle groups.

## Avoided Traps

- `aria-pressed` on every button: it announces plain buttons as toggles.
- `aria-pressed` on tab headers: a tab's state is its selection.
