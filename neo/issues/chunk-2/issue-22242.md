# ExamplesCatalogKeysNL queries overview-list before FEATURED mounts on CI

## Context

Promoted from `defect-note` (`MESSAGE:112dafc9`, fingerprint `2a96670e89e1acf8`) after **2 consecutive independent `e2e-engine (5/8)` failures on `dev` head `b85df18c30`** (`#22224` / `#22223`):

1. Run `45845958793` attempt 1, job `139999686717` (`67 passed, 1 failed`):
   `TypeError: Cannot read properties of undefined (reading 'id')` at `test/playwright/e2e/portal/ExamplesCatalogKeysNL.spec.mjs:659:46`
2. Run `45845958793` attempt 2, job `140006593929` (`67 passed, 1 failed`):
   Identical `TypeError: Cannot read properties of undefined (reading 'id')` at `test/playwright/e2e/portal/ExamplesCatalogKeysNL.spec.mjs:659:46`

Every Engine PR running `e2e-engine` on `dev` (including `#22227`) currently fails shard `5/8` on this un-awaited lazy mount.

## The Problem

In `ExamplesCatalogKeysNL.spec.mjs:655-659`:

```js
await page.goto(`${PORTAL}#/examples/devmode`);
app = await neuralLink.connectToApp('Portal');
const overviewList = (await app.queryComponent({className: 'Portal.view.examples.List'}, ['id', 'reference']))
    .find(item => item.properties.reference === 'overview-list');
await app.setProperties(overviewList.id, {baseUrl: `${baseURL}/`});
```

1. Earlier in the test (`:577`), `page.goto('/apps/portal/index.html#/examples/forms')` redirects (`301`) via `fileServer`'s `spaRoot: 'apps/portal'` to `/#/examples/forms` (pathname `/`).
2. When `:655` calls `page.goto('/apps/portal/index.html#/examples/devmode')`, the pathname differs from `/`, triggering a `301` redirect to `/#/examples/devmode` and a **full document reload** with a fresh App Worker.
3. `neuralLink.connectToApp('Portal')` resolves as soon as the fresh App Worker reports its `workerId` — **before** the route handler finishes lazy-importing `OverviewPage` and constructing `overview-list`.
4. On fast local Apple Silicon hosts `OverviewPage` usually finishes during `connectToApp`; on 2-vCPU Ubuntu CI runners `queryComponent` runs first, `.find(...)` returns `undefined`, and `overviewList.id` throws.

## The Architectural Reality

- Sibling specs in `test/playwright/e2e/portal/ExamplesCatalogLaunchNL.spec.mjs:31` & `:69` and `openOverview` (`test/playwright/e2e/utils/portalExamplesCatalog.mjs:103`) explicitly gate on `await expect(page.locator(FEATURED)).toBeVisible()` before querying `Portal.view.examples.List` / `overview-list`.
- `readOverviewList(app)` (`test/playwright/e2e/utils/portalExamplesCatalog.mjs:78-82`) is the shared helper for reading `overview-list`.

## The Fix

In `test/playwright/e2e/portal/ExamplesCatalogKeysNL.spec.mjs:655-660`:
1. Await `await expect(page.locator(FEATURED)).toBeVisible();` after `page.goto('${PORTAL}#/examples/devmode')` and `connectToApp('Portal')`.
2. Poll `app.queryComponent({className: 'Portal.view.examples.List'}, ['id', 'reference'])` via `expect.poll` until `overview-list` resolves before calling `app.setProperties(overviewList.id, ...)`.
