# Single-card board drag proxy offsets card by its column row position

## Context

Reported by `@tobiu` on the Portal landing page's 3rd scroll section (`Portal.view.home.parts.Planning` — "Gantt & Task Board"):

- Dragging the 1st card in a column (`row 0`) renders the drag proxy nearly aligned with the card.
- Dragging the 2nd card (`row 1`) renders the card inside the drag proxy shifted down by **one full row** (a 1-row gap above the card).
- Dragging the 3rd card (`row 2`) shifts the card inside the drag proxy down by **two full rows** (a 2-row gap above the card).

## The Problem

Every single-card drag on any `Neo.board.Container` double-applies the card's column-body offset inside `.neo-dragproxy`:

1. The outer `.neo-dragproxy` element is already placed at the card's viewport coordinates `(rect.x, rect.y)`.
2. Its cloned child `.neo-board-card` ALSO carries inline `position: absolute; left: 10px; top: <4 + k * rowStride + scrollTop>px`, shifting the rendered card right by `10px` (column body `padding-left`) and down by `4px + k * rowStride + scrollTop` (column body `padding-top` + $k$ rows + scroll offset).
3. On row `0`, `top: 4px` and `left: 10px` are subtle enough to look roughly aligned at a glance; on row `1` and row `2` the gap grows by one full row per index; in a scrolled column (such as `examples/board/bigData` scrolled down thousands of pixels), the card inside the proxy renders completely off-screen below the viewport.
4. Existing tests missed this because:
   - `test/playwright/unit/board/SortZone.spec.mjs:300` stubs `zone.dragStart = async () => {...}`, bypassing `DragZone#createDragProxy` / `getDragProxyVdom`.
   - `test/playwright/e2e/board/BasicNL.spec.mjs:385` and `MultiSelect.spec.mjs:231` assert `expect(page.locator('.neo-dragproxy')).toHaveCount(1)` (outer proxy presence) without comparing `.neo-dragproxy > .neo-board-card`'s bounding box to `.neo-dragproxy`'s bounding box.

## The Architectural Reality

- In `Neo.draggable.container.SortZone#onDragStart` (`src/draggable/container/SortZone.mjs:1135-1163`), `await me.dragStart(data)` creates the drag proxy **before** `pinnedItems.forEach(...)` writes `position: 'absolute'`, `left`, and `top` onto `item.wrapperStyle`.
- In `Neo.board.SortZone#onDragStart` (`src/board/SortZone.mjs:599-630`):
  1. Line `602` assigns `me.dragElement = VDomUtil.find(column.body.vdom, card.id)?.vdom || card.vdom` — a **live reference** to `card.vdom`.
  2. Line `610` calls `me.getDragProxyConfig()` (`:372-430`). For multi-card drags (`records.length > 1`), `getDragProxyConfig` calls `me.cloneCardVdom(leadRecord)` (`:330-361`) *before* pinning and explicitly deletes `height`, `left`, `margin`, `position`, `top`, `visibility`, and `width` from `clone.style`. For single-card drags (`records.length <= 1`), `getDragProxyConfig` returns `base` with `vdom` deleted (`:378-383`).
  3. Line `616` awaits `me.beginColumnSort(column, card, ...)` (`:141-195`), which writes `card.wrapperStyle = {height, left: '${rect.x}px', margin: '0px', position: 'absolute', top: '${rect.y}px', width}` directly onto `card.vdom.style` (`me.dragElement.style`), where `rect.y = cardViewportY + scrollTop - bodyRect.y`.
  4. Line `629` awaits `me.dragStart(data)` (`src/draggable/DragZone.mjs:367-368`), which snapshots and clones `me.dragElement` *after* `card.vdom.style` already holds those body-relative absolute coordinates.
  5. In `resources/css/src/draggable/DragProxyComponent.css:28-36`, `.neo-dragproxy > *` sets `position: relative; left: 0; top: 0; width: 100%; height: 100%` without `!important`, so the cloned card's inline `position: absolute; left: 10px; top: <rect.y>px` wins.
- **Design authority:**
  - `test/playwright/unit/draggable/container/SortZone.spec.mjs:473-478` (from `#20626` / `759bca4133`): *"the item the proxy clones carries no position"* (`expect(sortZone.dragElementSnapshot.style?.left ?? null).toBeNull()`).
  - `Neo.board.SortZone#cloneCardVdom` (`src/board/SortZone.mjs:330-361`, `#21700` / `5fa8c5561b`): canonical sanitizer for board card proxy VDOM clones (strips `neo-board-card-ghost`, `neo-board-card-slot`, and pinned `height`/`left`/`margin`/`position`/`top`/`visibility`/`width` while preserving `--neo-board-card-accent`).
  - `test/playwright/unit/board/SortZone.spec.mjs:1009`: single-card drags keep `zone.dragProxyConfig.vdom === undefined` and source their proxy from `me.dragElement`.

## The Fix

1. **`src/board/SortZone.mjs` (`onDragStart`):** Snapshot `me.dragElement` before `setGhostCards` and `beginColumnSort` mutate `card.vdom` by building it through `{...me.cloneCardVdom(card.record), id: card.id}`:
   - Preserves root `id: card.id` on `me.dragElement` so `DragZone#getDragElementRoot()`, `getDragElementRect()`, `createDragProxy()` theme lookup, and `getMainThreadConfigs()` (`dragElementRootId`) continue to resolve `card.id` (`DragZone#createDragProxy` strips `id`s via `VDomUtil.clone` when building `dragElementSnapshot` and `getDragProxyVdom()`).
   - Unifies single-card and multi-card proxy VDOM sanitization on `cloneCardVdom`, ensuring `me.dragElement` never inherits `beginColumnSort`'s `position: 'absolute'`, `left`, `top`, `margin`, `width`, `height`, or `visibility` mutations.
   - Keeps `beginColumnSort` ahead of `me.columnRects` and `me.dragStart(data)` so the pin-before-hit-test gate (`SortZone.spec.mjs:481-502`) and `zone.dragProxyConfig.vdom === undefined` (`SortZone.spec.mjs:1009`) hold unchanged.
2. **Unit regression test (`test/playwright/unit/board/SortZone.spec.mjs`):** Assert that after `onDragStart` on row `0`, row `1`, row `2`, and a scrolled column (`scrollTop > 0`), `zone.getDragProxyVdom()` / `zone.dragElement` carries no `position`, `top`, `left`, `margin`, `width`, `height`, or `visibility` inline styles while retaining `zone.getDragElementRoot().id === card.id` and `--neo-board-card-accent`, whereas the live `card.wrapperStyle` in the column body retains its pinned `position: 'absolute'` and `top`.
3. **Whitebox E2E regression tests (`test/playwright/e2e/portal/HomeComponentPreviews.spec.mjs` & `test/playwright/e2e/board/BasicNL.spec.mjs`):**
   - In `HomeComponentPreviews.spec.mjs` (3rd scroll page `.portal-home-parts-planning`): start real pointer drags on row `0` (`Scheduling`), row `1` (`Load test`), and row `2` (`Go live`) in the `To do` column and assert `.neo-dragproxy > .neo-board-card`'s `boundingBox()` aligns with `.neo-dragproxy`'s `boundingBox()` (`|deltaX| <= 1`, `|deltaY| <= 1`) on all three rows.
   - In `BasicNL.spec.mjs`: assert the same proxy-card alignment across rows `0..2` and inside the scrolled windowed column (`readyAtEnd`) test where `scrollTop > 0`.

## Out of Scope

- Changes to `Neo.draggable.DragZone`, `Neo.draggable.container.SortZone`, or `DragProxyComponent.css` (`Neo.board.SortZone` owns the pre-`dragStart` `beginColumnSort` mutation).
- Any VDOM engine diff (`#22189`).

## Avoided Traps

- **Assigning `me.dragElement = me.cloneCardVdom(card.record)` without `id: card.id`:** `VDomUtil.clone` strips `id` by default, which breaks `DragZone#getDragElementRoot().id` inside `getDragElementRect(data)` (`rect` resolves `null`), `createDragProxy()` theme lookup, and `dragElementRootId` registration.
- **Moving `beginColumnSort` after `dragStart(data)`:** `dragStart` awaits main-thread `DragDrop.setConfigs` and `createDragProxy`; keeping `beginColumnSort` before `columnRects` preserves the board zone's pin-before-hit-test invariant (`SortZone.mjs:626`, `SortZone.spec.mjs:481-502`).
- **Adding `!important` overrides to `.neo-dragproxy > *` in `DragProxyComponent.css`:** masks a corrupted `dragElementSnapshot` in `BoardSortZone` instead of fixing the snapshot at the source, and risks breaking custom proxy children across calendar/timeline/dashboard zones.
