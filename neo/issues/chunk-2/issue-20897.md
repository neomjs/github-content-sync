# A grid built before it joins a window never loads its columns' styles

## Context

Found while reading why a dock pane's timeline bars rendered without their styles. The engine Workstation's `Workspace#createPane` builds every pane before the dock places it in a window (`apps/workstation/view/Workspace.mjs:595-598`). Measured at `dev` `e152c053af` in headless Chromium:

- **`apps/workstation`:** the scale pane carries `animatedChange`, `progress` and `sparkline` columns (`apps/workstation/view/ScalePane.mjs:58-67`), the feed pane `animatedChange` and `sparkline` (`FeedPane.mjs:46-52`). The page requests no `grid/column/*` stylesheet at all.
- **Control, `examples/grid/animatedRowSorting`:** its grid is built inside its window, and the page requests `grid/column/Progress.css` for `src` and each theme.
- **Unit probe** `test/playwright/unit/grid/ColumnWindowIdForwarding.spec.mjs`: both arms fail at `e152c053af` at the forwarding assertion, while their controls pass. A grid built detached keeps `[null, null]` as its columns' window after `grid.windowId = 'w1'`. A grid moved from `w1` to `w2` keeps `['w1', 'w1']`.

## The Problem

A column asks for its own theme files when its `windowId` arrives. A grid hands each column its `windowId` once, when it creates the column, and never again.

A grid built while detached leaves every column without a window for good. That is how a dock, a lazy card or a pop-out builds its panes. A column class that ships styles then never loads them: tree, progress, icon, sparkline, animated change, the timeline column, or any app column. A grid that moves into another window leaves its columns' styles behind in the same way.

## The Architectural Reality

- `Neo.grid.column.Base#afterSetWindowId` inserts the column's theme files for a truthy id (`src/grid/column/Base.mjs:263-265`).
- `Neo.grid.Container#createColumns` creates each column with `windowId: me.windowId` (`src/grid/Container.mjs:1057-1061`).
- `Neo.grid.Container#afterSetWindowId` forwards a new id only to its `scrollManager` (`src/grid/Container.mjs:847-855`). Columns are not components, so the `container.Base` cascade over `items` never reaches them.
- The same gap was closed for a row's cell components (#18291) and for selection models (#20722).
- Design authority: the "Non-Component Theme Injection" JSDoc on `Neo.grid.column.Base#afterSetWindowId` says columns "hook into the theme engine exactly like components do" (#6535). A component's theme files follow its window; a column's do not.

## The Fix

`Neo.grid.Container#afterSetWindowId` forwards the new id to every column in `_columns`, beside the `scrollManager`, and its summary names the columns. Before `construct()` turns `columns` into a collection, `_columns` still holds the config array, so the forward runs only on a collection. `createColumns` already hands a window present at creation to each column.

## Acceptance Criteria

- [ ] A grid built without a `windowId` hands its first id to every column. A column class with theme files asks for them in that window: `insertThemeFiles(windowId, proto)` is recorded with its prototype.
- [ ] A grid moved from one window to another moves its columns, which ask for their theme files in the new window.
- [ ] `npm run test-unit` passes.
- [ ] The pull request shows the engine Workstation requesting its columns' stylesheets (`grid/column/Progress.css` and its siblings), which it does not at `e152c053af`.

## Out of Scope

- Table columns. `Neo.table.Container` keeps plain column configs, not instances (`src/table/Container.mjs:376`).
- Other helpers that have no window.

## Avoided Traps

- **Each column following its grid with `observeConfig`, the #20722 shape.** That fit selection models, which nine view classes own. Columns have one owner, `grid.Container`. It already creates them with its window and already forwards to its scroll manager. One forward there covers every column and every subclass, with no subscription per column.
- **Creating columns at mount.** Columns exist before mount, so the header and the body can size against them.
