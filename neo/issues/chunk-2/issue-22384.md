# A prepared child added outside its container's landed tree is mounted without DOM

handoff: @neo-gemini-maryam (the same file as #22381; she accepts it, folds it into #22381, or hands it back). No curated labels: it is an engine change behind the operator's VDOM gate.

## Context

ADR 0043 I5, as corrected by #22382, says a container passes `mounted: true` only to items its landed tree contains. #22381 implements the Workstation repair (#22184) with a narrower guard, `Boolean(items[i].vnode)`. Euclid's Chromium control on #22381's head (`ec3088451e`) found two supported paths that the narrower guard lets through.

## The Problem

A child prepared by a vnode-only render (`initVnode(false)`) has a vnode that Main never wrote. It is mounted with no DOM in Main, and its `mountedPromise` resolves, when it is:
1. added silently, as a floating leaf, while the container's first render is held (the removal sweep exempts floating items);
2. added from `parent.on('vnodeInitialized', () => parent.add(child, true))`, synchronously after the vnode sync.

Controls: an ordinary late child stays unmounted and pending until a later render draws it, and a child included before capture mounts normally.

## The Architectural Reality

- `Container#afterSetMounted` (`src/container/Base.mjs`) passes `mounted` to its items; #22381 adds the vnode guard there.
- The container's landed tree is what `onInitVnode` and `syncVnodeTree` already read: the child ids `ComponentManager.getChildIds(vnode)` returns from the synced vnode.
- **Witness gate.** The operator's VDOM gate asks for a real app flow that fails on `dev`. Euclid's paths are fixture-reached, not app flows. On `dev`, `src` and `apps` call `initVnode(false)` nowhere, and the `autoInitVnode: false` users (`CardEditor`, `EventEditor`, `ComposeDialog`, `tab/plugin/Overflow`, the dock's drag proxy) have not been shown to reach either path.

## The Fix

Once a real flow reproduces either path, the cascade checks membership in the container's landed tree (the ids of its synced vnode, read once per mount transition) instead of the item's vnode alone.

## Acceptance Criteria

- [ ] A real app flow on `dev` that mounts a prepared child with no DOM is named, with its receipt. Without one, this issue stays the record of the gap and no code changes.
- [ ] The cascade passes `mounted: true` only to items the container's landed tree contains; Euclid's two paths and both controls are unit witnesses.
- [ ] Hot-path cost stated: one landed-tree read per mount transition, nothing per update.

2. **Two source-verified traps to avoid when AC-1 is eventually met (`src/util/VNode.mjs:219-229`, `src/mixin/VdomLifecycle.mjs:1200, 1424-1429, 1482`):**
   - **Trap A — `ComponentManager.getChildIds(this.vnode)` returns `[]` after `syncVnodeTree`:**
     In `onInitVnode` (`VdomLifecycle.mjs:1200`), `me.vnode = vnode` runs `syncVnodeTree()`, whose line `1482` (`ComponentManager.addVnodeComponentReferences(vnode, me.id)`) replaces every child component in `me._vnode` with `{componentId, id}` *before* `me.mounted = true` runs at line `1218`. `ComponentManager.getChildIds` delegates to `VNodeUtil.getChildIds` (`src/util/VNode.mjs:221`), which filters `if (childNode.id && !childNode.componentId)` — skipping every `{componentId}` reference and returning `[]` for child components. Instead, collect `childNode.componentId` and `childNode.id` across `this.vnode`'s own inline `childNodes` (recursing only when `!childNode.componentId` so wrapper DOM elements like `.neo-panel-body` are traversed in `O(own VDOM nodes)` without descending into child component vnodes).
   - **Trap B — Landed-tree membership must stay conjunctive with `Boolean(item.vnode)`:**
     In `outer.syncVnodeTree()` (`VdomLifecycle.mjs:1424-1429`), `parent._vnode` already holds `{componentId: child.id}` at `i = 0` *before* `i = 1` assigns `child._vnode`. Checking `landedIds` *instead of* `Boolean(item.vnode)` would regress the `i = 0` nested-container breach (`dock-host` mounting with `vnode: null`). Require `Boolean(item.vnode) && (landedIds.has(item.id) || landedIds.has(item.vdom.id))`.
