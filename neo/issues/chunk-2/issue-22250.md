# Reorder the release checklist with the keyboard

Please comment to claim before starting. Check current assignees and linked PRs.

## Context

The public Reorder by Drag example teaches how a pointer drag changes a List’s Store order. Add a keyboard path for its release checklist so visitors can complete the same exercise and contributors can see two input paths share one Store update. This is optional standalone work outside the 14.1 milestone and release gate. [Example](https://github.com/neomjs/neo/blob/3e43effbf34adf83d8436c7b93bff2e0236fa3e4/examples/list/reorder/MainContainer.mjs#L36-L66)

## The Problem

The checklist renders positions and labels and turns on a drag zone. Its instructions describe pointer dragging. Start the dev server and open `/examples/list/reorder/index.html` to inspect the existing exercise. [Checklist source](https://github.com/neomjs/neo/blob/3e43effbf34adf83d8436c7b93bff2e0236fa3e4/examples/list/reorder/StepList.mjs#L24-L52)

## The Architectural Reality

`SortZone.moveRecord(record, target, before)` renumbers the Store in one batch. The desktop launcher already calls that method from a keyboard handler, waits for the render, then restores focus using the record’s stable item ID. The checklist should own its keyboard behavior through the same commit path. [Store mutation](https://github.com/neomjs/neo/blob/3e43effbf34adf83d8436c7b93bff2e0236fa3e4/src/draggable/list/SortZone.mjs#L118-L146) · [Keyboard precedent](https://github.com/neomjs/neo/blob/3e43effbf34adf83d8436c7b93bff2e0236fa3e4/src/desktop/Launcher.mjs#L213-L233)

## The Fix

Add keyboard-operable actions to move a checklist step one position earlier or later. Explain the controls in the example, preserve focus on the moved step, and announce its new position.

## Contract Ledger

| Target surface | Source of authority | Behavior | Boundary | Docs | Evidence |
|---|---|---|---|---|---|
| Standalone checklist and its existing SortZone | Checklist source and `moveRecord` above | Keyboard and pointer share the Store update and rendered order | At either edge keep the order and focus. | Example instructions | Existing reorder E2E plus a keyboard case |

Decision Record impact: none.

## Acceptance Criteria

- [ ] A keyboard-only visitor can find the controls and move a checklist step exactly one position in either direction.
- [ ] Focus remains on the moved step after render. The announced position, visible numbering, and Store order agree. At both ends the order stays intact.
- [ ] Extend [`ReorderExampleNL.spec.mjs`](https://github.com/neomjs/neo/blob/3e43effbf34adf83d8436c7b93bff2e0236fa3e4/test/playwright/e2e/list/ReorderExampleNL.spec.mjs#L36-L67) to verify the keyboard action and Store order, then verify a pointer drag after a keyboard move.
