# A press in a grid nested in another grid drag-scrolls the outer one

## Context

`Neo.main.addon.GridDragScroll` scrolls a grid by mouse or touch drag. It is on by default (`ScrollManager#dragScroll_`, `src/grid/ScrollManager.mjs:24–28`). Each grid registers its view element, the addon adds one capture `mousedown` (or `touchstart`) listener per registration (`src/main/addon/GridDragScroll.mjs:386–402`), and one window keeps all registrations in one map.

## The Problem

Read from the code; no spec covers a grid inside another grid's view yet, so the red-first spec below is the first observation.

- `onDragStart` takes the first registration whose view element is in the event path (`GridDragScroll.mjs:239–246`). A press inside a grid that sits in another grid's view, for example in a component cell or in content a package hosts in the view, has both view elements in its path. The map's insertion order decides, not the nesting. The outer grid usually registered first, so the drag scrolls the outer grid.
- Its capture listener sits on both elements, so one press runs `onDragStart` twice. The second run overwrites `mouseDownTimeout` without clearing the first timer (`:275–297`). When the button comes up within the delay, `onMonitorEnd` clears only the second timer and sets `monitorDrag` to `null` (`:323–324`). The first timer then calls `onMonitorMove`, which reads `monitor.startX` of `null` (`:304–315`).
- A press-drag on non-row content inside a view, such as text in an input that a component in the view renders, starts a drag-scroll too. The handler only skips `neo-draggable`, `neo-grid-editor` and the scrollbars (`:254–264`).

## The Architectural Reality

- Design authority: the addon's class JSDoc, "It listens for `mousedown` or `touchstart` on the grid body". The grid pressed is the grid scrolled.
- Prior fixes in the same addon: #18065, #18099, #18104, #19820.

## The Fix

- Resolve the registration from the innermost registered view in the path.
- Start a drag only for a press on that grid's own rows: the path holds a `.neo-grid-row` whose nearest `.neo-grid-view` is the registration's element.
- Handle one press once, so no second timer is armed.

## Acceptance Criteria

- [ ] Red first, then green: in a grid whose view hosts a second grid, a press-drag on the inner grid's rows scrolls the inner grid only (component or e2e spec).
- [ ] A press-drag on the outer grid's rows still scrolls the outer grid.
- [ ] A click inside the inner grid, with the button up within the addon's delay, logs no error.
- [ ] A press-drag inside a text input that a grid's view hosts outside its rows selects text and scrolls nothing.
- [ ] The existing drag-scroll specs stay green.

## Out of Scope

- Kinetic tuning; touch gestures beyond the press that starts a drag.
