# Four variables that structural rules read are undefined in the Neo themes

Live latest-open + closed sweep: the parent epic's sweep of 2026-11-26 23:06Z covers this leaf (unresolved variable, structural rule); no equivalent found. Not offered as a contributor issue: it is wanted for the weekend cut.

## Context

A `var(--x)` without a fallback whose `--x` no file defines is invalid at computed-value time: the property takes its inherited or initial value and nothing reports it. `check-theme-var-references` catches such reads inside theme files. It does not look at structural rules.

## The Problem

On `dev` at `11f48ebb15`, structural rules read four variables that neither `theme-neo-dark`, `theme-neo-light` nor any file under `resources/css/src` defines:

| Variable | Read in |
|---|---|
| `--calendar-settings-header-color` | `calendar/view/SettingsContainer.css` |
| `--list-border-color` | `app/content/SectionsList.css` |
| `--list-item-border-color-active` | `list/Chip.css` |
| `--menu-list-item-color-disabled` | `menu/List.css` |

Six other reads look the same and are not gaps: `--desktop-app-color`, `--neo-duration`, `--neo-easing`, `--neo-tree-level` and `--upload-progress` are set from JavaScript, `--fa-style-family-classic` by Font Awesome.

## The Architectural Reality

- A theme file declares variables only; the value for a component lives in `resources/css/theme-*/<same path as the rule>`.
- Whether each of the four is a missing value or a stale read is not known yet: a rule may read a variable that was renamed or retired.

## The Fix

Per variable, one of two outcomes, stated in the pull request: the Neo pair defines it, with a value shown in a frame pair of the affected widget; or the read is stale and the rule is corrected to the variable that exists.

## Acceptance Criteria

- [ ] `npm run theme-census` reports no unresolved structural read for the Neo pair beyond the runtime list.
- [ ] Each of the four is either defined in both Neo themes or its read is corrected, with the reason named.
- [ ] Look: for each value that changes paint, the pull request shows the widget in Neo Dark and Neo Light before and after; the design seat reads the pairs.
- [ ] The four theme guards pass.

## Out of Scope

- The classic pair's unresolved reads: its own leaf under the parent.
- Extending `check-theme-var-references` to structural rules: after the design-system decision names the rules.
