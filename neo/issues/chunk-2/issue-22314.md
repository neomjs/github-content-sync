# Legit opens with an empty file tree after seeding its workspace

## Context

A visitor opens the [Legit IDE](https://neomjs.com/apps/legit/) to select one of its seeded files, edit it and run its preview. On `dev@59b558101f` in Chromium the app initializes, the file service lists all four seeds on the branch, and its normal preview handler renders both starter modules. The file tree stays empty.

## The Problem

Open `/apps/legit/index.html` in a fresh browser session. With the SDK served as `@legit-sdk/core@0.6.1`, the first poll reads a valid 40-character branch head. Listing that commit's directory succeeds, but inspecting the files in the commit fails with `NotFoundError` on the same head. The poll never populates the existing file Store. This reproduces before and after the Learn export change in #22313.

## The Fix

Restore the service's commit-snapshot reads using the SDK's supported storage and filesystem APIs. Preserve file membership and the distinction between changed content and a different filename when comparing two commits. Drive the existing provider-owned Stores through the ordinary poll. Do not seed example rows in the UI. [File service](https://github.com/neomjs/neo/blob/59b558101f/apps/legit/service/Legit.mjs#L103) · [Poll and selection](https://github.com/neomjs/neo/blob/59b558101f/apps/legit/view/ViewportController.mjs#L158)

Design authority: #8108 puts file I/O and git operations in the service; #8110 puts history presentation in the grid bound to the existing commit Store. Decision Record impact: none.

## Acceptance Criteria

- [ ] A fresh visit lists the four actual seeded files. Clicking `Helix.mjs` and `Gallery.mjs` in the tree and opening Preview renders the corresponding controls.
- [ ] A committed addition, edit and deletion are reflected against their respective immutable heads, including a nested path. Internal filesystem entries stay out of the file tree.
- [ ] Saving through the IDE updates the history grid and preserves the selected editor’s contents. Record a Chromium run through the normal host with the SDK version observed.

**Intake.** The current SDK and stock app were exercised before prescribing a UI change. The latest-open queue plus open/closed Legit, SDK and `loadTreeDelta` searches found the historical service/history work and no live owner for this failure. This is separate from changing the example source strings. I am taking the repair during the nightshift.
