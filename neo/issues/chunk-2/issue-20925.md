# Every Claude seat gets the ruled gh rights from the settings template

## Context

On 2026-11-12 the operator ruled that every Claude seat has the permission set Ada's seat runs with: "equal peers paradigm. of course all peers should have the same rights." Grace recorded the set in her verdict on neomjs/neo-agent-brain#1614: allow `Bash(gh *)`, `Bash(git config *)` and the four Neo MCP servers; deny `gh pr merge`. It was to be applied by hand to each seat's gitignored `.claude/settings.local.json`, with neomjs/neo-agent-brain#1615 named as the durable path.

#1615 shipped the same day: a seat's hydration (`npm prepare`, or a seat Start) replaces an untracked `.claude/settings.json`'s `permissions` with the template's once the installed engine carries them (`initClaudeSettings`, neo-agent-brain `ai/scripts/setup/initServerConfigs.mjs`). The template itself never got the ruled set.

## The Problem

Measured 2026-11-14 (`dev` `a07f581f13`): `.claude/settings.template.json` allows seven specific `gh pr` / `gh issue` commands and no `gh api`. My seat's local file has `Bash(gh api *)` (applied by hand on 10-29); per #1614's table Ada's has `Bash(gh *)`. Each seat's rights follow its hand-edit history, so a maintainer act the operator ruled every seat's (starting a first-time contributor's held runs, `gh api -X POST …/actions/runs/<id>/approve`, rulings of 11-11 and 11-13) works on some seats and is refused by the classifier on others.

## The Architectural Reality

- `permissions.allow` is resolved before the auto-mode classifier runs; a call an allow rule matches is not classified (#1614, Architectural Reality). A compound shell command, such as a `for` loop, matches no prefix rule and still goes to the classifier.
- `autoMode` is never read from a project file (#20794, #20796), so `permissions` is the only lever the template has.
- Deny rules win over allow rules: the template's `Bash(gh pr merge *)` deny keeps merging human-only under a `Bash(gh *)` allow.
- Design authority: the operator's ruling of 2026-11-12 quoted above, as recorded on neomjs/neo-agent-brain#1614.

## The Fix

`.claude/settings.template.json`, `permissions.allow`: add `Bash(gh *)`, which replaces the seven `gh` rules it subsumes, plus `Bash(git config *)` and `mcp__neo-mjs-neural-link__*`. `permissions.deny` is unchanged.

## Acceptance Criteria

- [ ] The template allows `Bash(gh *)`, `Bash(git config *)` and the four `mcp__neo-mjs-*` servers; the seven subsumed `gh` rules are gone; `Bash(gh pr merge *)` is still denied.
- [ ] The specs that read the template stay green (`test/playwright/unit/hooks`).
- [ ] `[post-merge]` After a Claude seat's next hydration on an engine that carries this commit, its `.claude/settings.json` holds the ruled set, and a plain `gh api -X POST …/actions/runs/<id>/approve` reaches GitHub without a classifier refusal.

## Out of Scope

- The lines hand-applied to each seat's `.claude/settings.local.json`: those files are the operator's.
- An approve tool in github-workflow (#1614, not planned) and routing approve-runs wakes by family.

## Avoided Traps

- `Bash(gh api -X POST repos/neomjs/*/actions/runs/*/approve)`: a `*` in the middle matches spaces, so the rule admits unrelated `gh api` writes that end in `/approve` (#1614).
