# Add cyberpunk, dark and light themes for timeline, scheduler and Gantt

## Context

Split out as the immediately unblocked Part 1 leaf of #20879 under parent epic #20874 (`Engine 13.5`, Milestone #14, cut `2026-11-23`), offered in `@neo-fable-clio`'s handover (#20879#issuecomment-6866604418). On `origin/dev` (`a07f581f13`), `timeline` (#20876), `scheduler` (#20877), and `gantt` (#20878) are merged, while #20879 retains `blockedBy: [#20875]` (open `board` family move) and prescribes two separate pull requests; per `pull-request-workflow.md §9.1` (`1 PR = 1 standalone Resolves #N`), this 1:1 leaf owns the `timeline`, `scheduler`, and `gantt` theme slice now while #20879 retains the `board` slice behind #20875.

## The Problem

The engine ships five themes (`theme-neo-dark`, `theme-neo-light`, `theme-dark`, `theme-light`, and `theme-cyberpunk`), and `npm run build-themes` builds all five without failing when a component file is missing in one theme — leaving its CSS variables undefined. Today on `dev`:
- `timeline/Column.scss`, `timeline/EventEditor.scss`, `timeline/TimeAxisHeader.scss`, `scheduler/Container.scss`, and `gantt/Container.scss` exist only in `theme-neo-dark` and `theme-neo-light` (`0` files in `theme-cyberpunk`, `theme-dark`, and `theme-light`).
- `examples/scheduler/basic/Viewport.scss` (`--studio-*` header chrome tokens) and `examples/gantt/basic/Viewport.scss` (`--project-*` header chrome tokens) likewise exist only in `theme-neo-dark` and `theme-neo-light`, and both examples' `neo-config.json` list only `["neo-theme-neo-light", "neo-theme-neo-dark"]` in `themes`.
- In `resources/scss/src/examples/gantt/basic/Viewport.scss` (`.project-control`, which uses `ui: 'secondary'`) and `resources/scss/src/timeline/EventEditor.scss` (`.neo-timeline-event-editor-save` / `-cancel`, which render `.neo-button-text`), only `--button-text-color` / `color` were bound, leaving `--button-secondary-text-color` and button text variables unbound (`1.0:1` invisible button labels in `theme-light` and `theme-dark`).

## The Architectural Reality

- Structural rules live in `resources/scss/src/{timeline,scheduler,gantt}/*.scss` and `resources/scss/src/examples/{scheduler,gantt}/basic/Viewport.scss`, consuming CSS variables scoped per theme.
- Sibling theme token vocabularies live in `resources/scss/theme-{dark,light,cyberpunk}/Global.scss` (notably `--cyber-cyan`, `--cyber-gold`, `--cyber-red`, `--cyber-bg`, `--cyber-bg-alt`, `--cyber-text`, `--cyber-border`, `--cyber-glow` in `theme-cyberpunk/Global.scss`) and `resources/scss/theme-{dark,light,cyberpunk}/{grid,button,dialog}/*.scss`.
- Per #20902, review evidence screenshots must NOT remain tracked at the PR head (where `npm pack` ships them): commit the 6 frames to obtain a commit SHA, link `https://github.com/neomjs/neo/blob/<sha>/<path>?raw=true` in the PR body, and remove the PNGs in a subsequent commit on the PR branch.
- Decision Record impact: none.

## The Fix

1. Add the 15 component theme files across `theme-cyberpunk`, `theme-dark`, and `theme-light` (`timeline/Column.scss`, `timeline/EventEditor.scss`, `timeline/TimeAxisHeader.scss`, `scheduler/Container.scss`, `gantt/Container.scss`), plus the 6 example header chrome files (`examples/scheduler/basic/Viewport.scss` and `examples/gantt/basic/Viewport.scss` across the same three themes), deriving colours from each theme's existing token vocabulary (`Global.scss`, `grid/*.scss`, `button/Base.scss`, `dialog/Base.scss`).
2. Wire `--button-secondary-*` to `var(--project-*)` in `resources/scss/src/examples/gantt/basic/Viewport.scss` and `--button-text-color*` to `var(--neo-timeline-editor-*)` in `resources/scss/src/timeline/EventEditor.scss` so button labels maintain AA/AAA contrast across all five themes while keeping theme value files 100% selector-free (`check-theme-value-files.mjs`).
3. Add `"neo-theme-light"`, `"neo-theme-dark"`, and `"neo-theme-cyberpunk"` to the `themes` list in `examples/scheduler/basic/neo-config.json` and `examples/gantt/basic/neo-config.json` so `Neo.main.addon.Stylesheet` can load any of the five shipped themes (without adding a UI theme switcher).
4. Run `npm run build-themes` and verify both `examples/scheduler/basic` and `examples/gantt/basic` in `theme-cyberpunk`, `theme-dark`, and `theme-light` with 6 screenshots pinned by commit SHA and removed from the branch head per #20902.

## Out of Scope

- `src/board` theme files (retained on #20879 behind open blocker #20875).

- Adding a UI theme switcher to the examples.

## Avoided Traps

- Leaving `examples/{scheduler,gantt}/basic/Viewport.scss` out of the three secondary themes, which leaves `--studio-*` and `--project-*` header chrome variables undefined in the rendered frames.
- Leaving `--button-secondary-text-color` unbound on `.project-control` (`ui: 'secondary'`) or `--button-text-color` unbound on `.neo-timeline-event-editor-save` / `-cancel`, which produces `1.0:1` invisible button text in `theme-light` and `theme-dark` (or adding selector overrides inside theme value files, which violates `check-theme-value-files.mjs`).
- Leaving the 6 review screenshots tracked at the PR head where `npm pack` ships them (#20902).
- Using `:root` vs `:where()` selector specificity inconsistently in a way that overrides component state modifiers.
