# An order review desk demonstrates a working Grid workflow

## Problem and intended outcome
Give a first-time visitor a runnable, coherent order review desk demonstrating enterprise Grid interactions on realistic local or generated data. Existing grid samples isolate features; the desk should show a task end to end, with a visible question and outcome. It complements the build-along tutorial #20529, which teaches readers to construct features, rather than replacing it or treating tutorial prose as a shipped example.

## Acceptance criteria
- [ ] Define the reader task, data and exact existing Grid capabilities before building; prove why current grid examples alone do not cover the integrated journey. No unsupported backend or commercial capability claims.
- [ ] Start with 100,000 deterministic local orders and visible exceptions. Filter to the exceptions, keep the identifying column visible while scrolling, correct an invalid quantity, and observe the recalculated total and exception count. Resolve the last exception to reach the empty state. A distant order remains reachable with a viewport-bounded set of mounted rows.
- [ ] Agree model, field names, data generator and runnable entry point with #20529 so the final tutorial lab runs this same desk. A reader can follow the stages independently of the example’s implementation schedule.
- [ ] Run real interactions at desktop and mobile widths, including keyboard/accessibility and reload semantics; document data ownership and whether edits persist. Show results on the page, not only in console.
- [ ] Register a truthful Portal catalog entry and its required cover through the existing publication process; validate in released consumer separately from source. Reuse existing data/patterns where appropriate.

Parent #21140; distinguish #20529 tutorial and #21189 simulated-server paging. No new server or enterprise feature is implied.

### 1. Why Existing `examples/grid/*` Samples Do Not Cover This Journey (`AC-1`)
- `examples/grid/bigData/` isolates `100,000`-row buffered rendering and synthetic column/row rebuilds without cell editing or an end-to-end user task.
- `examples/grid/cellEditing/` exercises typed `NumberField` / `DateField` / `CountryField` editors on a `40`-row eager store (`autoInitRecords: true`), without `100,000`-row Turbo Mode (`autoInitRecords: false`), locked columns, grouped headers, or exception filtering.
- `examples/grid/lockedColumns/` and `examples/grid/headerGroups/` isolate region/header geometry on static rows.
- `examples/grid/orderReviewDesk/` unifies these existing Engine capabilities into one coherent local task: triage and repair invalid quantities across a `100,000`-row deterministic order sheet (`autoInitRecords: false`), scroll to distant orders with viewport-bounded DOM row pooling while keeping `orderId` (`locked: 'start'`) and `lineTotal` / `status` (`locked: 'end'`) visible, edit invalid quantities inline via `grid.plugin.CellEditing`, watch `lineTotal` and the live exception badge recalculate, and resolve the final exception into a clear zero-exceptions state (in-memory local session state; reload resets to the deterministic seed, disclosed on screen).
