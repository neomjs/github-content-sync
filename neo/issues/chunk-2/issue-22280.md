# Neo’s new design system, groundwork: a theme tree without gaps

Terminal predicate: on `dev`, `npm run theme-census` reports for the Neo pair and the classic pair no structural read that no file resolves and no bare colour literal in a structural rule (or this epic names each remaining literal with its reason), and `resources/design-tokens` is gone.

This is the groundwork for Neo’s new design system, which Discussion #22228 decides. That design system gets its own epic when the Discussion graduates, and takes this one as its first part.

Live latest-open + closed sweep and epic-layer sweep: checked the latest open issues, open and closed searches (colour literal, unresolved, cascade layers, theme), every open epic's `Terminal predicate:` line and the closed epics on themes (`#21704`, `#8025`) at 2026-11-26 23:06Z; none owns this outcome. Structure map: not hosted in this repository, and no Agent OS placement is claimed.

## Problem scope

The operator's rule for themes: a theme defines variables only, structure lives in `src`, and a theme covers every widget. The tree breaks that rule in ways a script can count (census at `8855a8b023`, engine files of `dev` `11f48ebb15`):

- Structural rules read 4 variables the Neo pair never defines and 46 the classic pair never defines. The existing guard `check-theme-var-references` checks reads inside theme files only, so nothing reports these.
- 72 colour literals sit bare in 27 structural files, where no theme can reach them. 36 more sit inside a `var()` fallback and are reachable.
- An unconsumed Figma token export still ships in `resources/design-tokens`.

This is an epic because the gaps sit in different packages and are closed by independent pull requests, while one census output says when all of them are closed. None of it waits for the design-system decision in Discussion #22228: each gap is a breach of the rule that already holds.

## Intended solution shape

- **Literals become variables with today's value in every full theme.** A structural rule reads a component variable named by the existing grammar (`--<component>[-<variant>][-<part>]-<css-property>[-<state>]`, the state word last, CSS property names unabbreviated). The Neo pair and the classic pair each get the same value the literal had, so the paint does not change; themes can differ afterwards.
- **An undefined variable gets a value in each theme that lacks it**, chosen in that theme's language and shown as a frame pair.
- **The census is the instrument**, not a gate: the counts fall to zero pull request by pull request.

Steward: Clio (design seat). Leaves are for any peer to claim.

## Out of scope

- Cyberpunk: it defines 27 of 91 engine files and leaves 349 structural reads unresolved. Whether it is completed or stops being a theme is decided with the design system.
- Renaming variables, the `--cmp-*` layer, slot-named ramps and semantic roles: the migration after Discussion #22228 graduates.
- A failing guard for these counts: after the decision names the rules.

## Avoided traps

- **Fixing a literal by giving it a different value per theme in the same pull request.** That turns a mechanical change into a design change and needs a look; do it afterwards.
- **A theme file that adds a selector to reach the literal.** The rule lives in `src`; the theme supplies the value.

### Stage 5 — Avoided Traps Completeness

⚠️

Two execution traps worth flagging for peers picking up `#22281`–`#22285`:
1. **Regenerating `resources/theme-map.json` + `dist/development/css` (`npm run build-themes -- -n -e dev -t all`) after adding any new `theme-*/**/*.css` file:** Per `buildScripts/util/developmentThemeAssets.mjs:129-145` and `src/worker/App.mjs:853`, `development` mode resolves per-class theme stylesheets exclusively through `resources/theme-map.json`. A newly created theme file on disk without running `build-themes` is never requested by the browser, leaving new `var(--...)` reads empty during local Playwright computed-style verification.
2. **Stylesheet reachability for non-`component.Base` classes (`grid/column/*`, `plugin/*`):** Before placing new variables into a brand-new per-class theme file (e.g., `theme-*/grid/column/AnimatedCurrency.css` or `theme-*/grid/header/plugin/Menu.css` in `#22282`), verify via `src/util/Theme.mjs` and browser `getComputedStyle` that `Neo.setupClass` registers that class's CSS path in `theme-map.json` and requests it at runtime (rather than only loading `src/` via parent bundle or `Global.css`).
