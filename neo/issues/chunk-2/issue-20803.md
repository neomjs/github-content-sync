# CONTRIBUTING sends returning contributors to an empty label

## Context

`CONTRIBUTING.md` (lines 117–121) says: for a first pull request take a `good first issue`; "After your first merged PR, move on to help wanted or an unassigned issue in the roadmap's milestone, the same way. Good first issues stay reserved for first-time contributors."

#19105 added those lines on 2026-09-23, when returning contributors were consuming a scarce entry supply. Its Out of Scope said the `help wanted` supply had to be refreshed too: "pointing returning contributors at a stale label only moves the gap." The refresh did not happen.

Measured on this repository on 2026-11-12:

| Read | Value |
|---|---|
| Open: `good first issue` / `help wanted` | 22 / 1 |
| `help wanted`, open and unassigned | 0 |
| Outside accounts with a merged pull request since Jul 1, and those with exactly one | 47, of which 39 |
| Curated issues closed in the last 30 days: by an outside pull request / by a maintainer seat | 27 / 17 |
| Open and unassigned `good first issue`, and their age | 14, median two days, none older than three |

## The Problem

- After a first merge the guide's path ends. `help wanted` holds one issue and none is free.
- An agent applies the guide literally. Its search is `is:open label:"help wanted" no:assignee`, the result is empty, and it moves to another repository.
- The reservation's reason has lapsed. Maintainer seats close 17 of 45 curated issues themselves and 14 sit unassigned, so a returning contributor takes idle work before a newcomer's.

## The Architectural Reality

- `CONTRIBUTING.md:117–121` holds the path; `:128–134` holds the claim rules, which already cover both labels ("one open curated claim at a time").
- `buildScripts/util/claimResponse.mjs`: `CURATED_LABELS` lists both labels, `curatedLabel()` prefers `good first issue` on an issue that carries both, and the reply's alternatives come from that label's list. It needs no change.
- neomjs/neo-agent-skills#370 makes both labels the default for new tickets. This ticket covers the guide and the issues that are open today.
- The Brain's and the Fleet Manager's guides carry the same lines.
- What the labels mean. GitHub's default-label table: `good first issue` "Indicates a good issue for first-time contributors", `help wanted` "Indicates that a maintainer wants help on an issue or pull request" ([Managing labels](https://docs.github.com/en/issues/using-labels-and-milestones-to-track-work/managing-labels)). That is suitability and no reservation. The ticket-create workflow defines the first label as "first-contribution readiness, not difficulty" (neomjs/neo-agent-skills#199). The reservation exists only in this guide.

Design authority: "someone who lands their first PR is steered to the second label, not into another entry slot" (#18985, restated in #19105). The measurement above is the reason to change it; the operator proposed the change on 2026-11-12 as a peer's input, and the pull request's review decides.

## The Fix

1. Lines 117–121 of `CONTRIBUTING.md` become, with the existing links kept:

   > **Looking for somewhere to start?** Take an issue labelled good first issue or help wanted: comment on one to claim it (see 3). No approval round needed; they are already approved. Most carry both labels, and both are open to you whether this is your first pull request or your tenth. Good first issue means the ticket holds everything you need to finish it; it is no promise that the work is small. An unassigned issue in the roadmap's milestone works the same way.

2. Every open `good first issue` gets `help wanted`. This is a maintainer step, because an outside author cannot label; the reviewing maintainer runs it at merge:

   ```bash
   gh issue list --repo neomjs/neo --state open --label "good first issue" --limit 100 --json number --jq '.[].number' | xargs -I{} gh issue edit {} --repo neomjs/neo --add-label "help wanted"
   ```

## Acceptance Criteria

- [ ] The guide names both labels as open to every contributor and holds no sentence that reserves one.
- [ ] The guide says in one sentence what `good first issue` means here: readiness, not size.
- [ ] Paragraph 3 of the guide still matches `claimResponse.mjs`: one open curated claim at a time, on either label.
- [ ] Post-merge, maintainer step: `is:issue is:open label:"good first issue" -label:"help wanted"` returns nothing.
- [ ] Post-merge: the same wording reaches the Brain's and the Fleet Manager's guide, one ticket each, filed by this ticket's author once the wording is reviewed.

## Out of Scope

- The label default for new tickets: neomjs/neo-agent-skills#370.
- A separate stream for returning contributors: neomjs/neo-agent-skills#370 holds the reason.
- Recognition for contributors (badges, standing).

## Avoided Traps

- **Stocking `help wanted` by hand.** #19105 asked for it in September. The label holds one issue.
- **Dropping the reservation and keeping one label.** A returning contributor's agent searches `help wanted`; the label has to be on the issue.
- **Assuming the slack lasts.** Returning contributors draw on the same list as newcomers. The triager's tripwire: fewer than five unassigned curated issues for a day, or fewer first-time authors in a month than in the month before, means label more work or split the labels again.
