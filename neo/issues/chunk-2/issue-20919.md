# Add News tab SEO routes and salvage v14 SharedWorker WebSocket post

## Context

Live `Googlebot/2.1` crawl inspection of `https://neomjs.com` (`2026-11-14`) surfaced two search-discovery gaps on the Portal's News and Blog surfaces (`apps/portal/view/news/TabContainer.mjs:31-80` and `apps/portal/resources/data/medium_blog.json`):
1. Every `/news/*` SSR snapshot renders seven tab links in `TabContainer.mjs:31-80` (`/news/releases`, `/news/tickets`, `/news/discussions`, `/news/blog`, `/news/medium`, `/news/pulls`, and `/news/videos`), yet none of the five indexable section hubs (`/news/blog`, `/news/releases`, `/news/discussions`, `/news/medium`, `/news/videos`) are listed in `TOP_LEVEL_ROUTES` (`buildScripts/docs/seo/generate.mjs:48-55`), so `neomjs/middleware-v2` never prerenders `dist/seo/news/{blog,releases,discussions,medium,videos}/index.html` from `sitemap-core.xml` and crawlers hit `404` on `/news/discussions`, `/news/medium`, and `/news/videos`.
2. `apps/portal/resources/data/medium_blog.json` holds `78` external Medium/ITNEXT URLs versus `25` self-hosted Markdown posts in `apps/portal/resources/data/blog.json`. While `a-data-grid-in-a-web-worker` and `building-a-multi-window-dashboard-with-dock-layouts` cover the Data Grid and Dock Layout wedges on `neomjs.com`, our high-intent **real-time WebSocket streaming across multiple browser windows via `SharedWorker`** topic still lives exclusively on a 2020 Medium URL using pre-v10 APIs.

## The Problem

1. **Broken crawler hub links across `/news/*` SSR snapshots (`generate.mjs:48-65`, `seoJson.mjs:23-35`):**
   - `apps/portal/view/news/TabContainer.mjs:31-80` (`origin/dev` @ `32fb6cb32e`) defines seven child routes: five indexable hubs (`/news/releases`, `/news/discussions`, `/news/blog`, `/news/medium`, `/news/videos`) and two `noindex` archive hubs (`/news/tickets`, `/news/pulls`, marked `X-Robots-Tag: noindex, follow` by `neomjs/middleware-v2` `isArchiveBotRoute()`).
   - `apps/portal/resources/data/seo.json` lacks entries for `/news/discussions`, `/news/medium`, `/news/tickets`, and `/news/pulls`, and `generate.mjs:48-55` (`TOP_LEVEL_ROUTES`) includes only `/news` — omitting all five indexable child hubs from `sitemap-core.xml`. Meanwhile `collectTopLevelRoutes()` in `generate.mjs:302-310` binds every top-level route's `lastmod` only to `ViewportController.mjs` instead of sharing `TOP_LEVEL_SOURCE_PATHS` with `seoJson.mjs`.
2. **Missing current-engine (`v14`) canonical hero post for multi-window `SharedWorker` WebSocket streaming:**
   - Per the closed ruling on #9852 (`IC_kwDODSospM8AAAABjw8G5Q`, `2026-11-06`), `62` of the `73` pre-2025 entries in `medium_blog.json` use superseded pre-v10 APIs and MUST NOT be bulk-copied verbatim; instead, `#9852`'s explicit **Salvage** clause states: *"an old post that is still worth reading becomes a new post through the `blog-post` skill, rewritten against the current engine."*
   - Across all `304` core routes on `origin/dev`, sharing a single live `Neo.data.connection.WebSocket` stream across multiple browser windows via `SharedWorker` (`"useSharedWorkers": true`, `Neo.data.Store#bulkUpdateRecords`, `Neo.state.Provider`) has `0` dedicated `learn/blog/*.md` posts written against current engine primitives.

## The Architectural Reality

- `Design authority:` #20671 Intended solution shape §1–§2 (*"automated integrity checks that reject broken canonical or `/raw/` links before deploy"* and route-specific SSR metadata across `/news/*` front-door surfaces), #9852 Salvage ruling (`IC_kwDODSospM8AAAABjw8G5Q`), and `.agents/skills/blog-post/references/blog-authoring-guide.md` (§1–§5: regular-weight TL;DR with `<= 1` bold phrase per `#250`, outbound preview drafts per `outbound-post.md §0`, render-verified Mermaid diagram, and pipeline-owned `sitemap*.xml` / `llms*.txt` never committed by hand).
- `Prescription checked: buildScripts/docs/seo/generate.mjs — owns TOP_LEVEL_ROUTES, PRIORITIES, collectTopLevelRoutes, and getLlmsTxt Main Pages labels`
- `Prescription checked: buildScripts/docs/seo/seoJson.mjs — owns TOP_LEVEL_SOURCE_PATHS and curated top-level seo.json preservation + git lastmod resolution`
- `Prescription checked: apps/portal/resources/data/blog.json + learn/blog/ — owns self-hosted blog navigation and BlogPosting frontmatter/body`

## The Fix

1. **Register News tab routes across `seoJson.mjs`, `generate.mjs`, and `seo.json`:**
   - Export `TOP_LEVEL_SOURCE_PATHS` from `buildScripts/docs/seo/seoJson.mjs` covering all seven `/news/*` tabs (`/news/blog`, `/news/releases`, `/news/discussions`, `/news/medium`, `/news/videos`, `/news/tickets`, `/news/pulls`) and wire `collectTopLevelRoutes(root)` in `buildScripts/docs/seo/generate.mjs` to use `TOP_LEVEL_SOURCE_PATHS` so `sitemap-core.xml` and `seo.json` agree on source-backed `<lastmod>` dates, with readable `## Main Pages` labels in `getLlmsTxt`.
   - Add the five indexable News hubs (`/news/blog` `0.9`, `/news/releases` `0.8`, `/news/discussions` `0.6`, `/news/medium` `0.5`, `/news/videos` `0.5`) to `TOP_LEVEL_ROUTES` and `PRIORITIES` in `generate.mjs`, curate search-intent `title` + `<= 160`-char `description` entries for `/news` and all five hubs in `apps/portal/resources/data/seo.json`, and add `robots: "noindex, follow"` entries in `seo.json` for `/news/tickets` and `/news/pulls` while keeping them out of `sitemap-core.xml`.
2. **Author one fresh v14 blog post via `.agents/skills/blog-post/SKILL.md` (`learn/blog/*.md` + `apps/portal/resources/data/blog.json` + regenerated `seo.json`):**
   - Write a current-engine (`v14`) hero post demonstrating **sharing one live `Neo.data.connection.WebSocket` stream across multiple browser windows via `SharedWorker`, `Neo.data.Store`, and `Neo.state.Provider`** (citing real `dev` classes including `src/data/connection/WebSocket.mjs`, `src/ai/Client.mjs`, `Neo.dashboard.dock.Workspace`, and `examples/stateProvider/multiWindow`, with a render-verified `flowchart TD` Mermaid diagram and outbound venue previews per `blog-authoring-guide.md §1`), register it under `"2026"` in `apps/portal/resources/data/blog.json`, and regenerate `apps/portal/resources/data/seo.json` via `generate.mjs -f seo-json` (without committing pipeline-owned `apps/portal/sitemap*.xml` or `apps/portal/llms*.txt`).

## Avoided Traps

- **Copying 2019–2024 Medium posts verbatim into `learn/blog/`:** Rejected in #9852 (`IC_kwDODSospM8AAAABjw8G5Q`) because 62 pre-2025 posts teach replaced APIs; rewrite against current v14 primitives via `/blog-post`.
- **Adding `/news/tickets` or `/news/pulls` to `TOP_LEVEL_ROUTES` (`sitemap-core.xml`):** `neomjs/middleware-v2` `isArchiveBotRoute()` serves `X-Robots-Tag: noindex, follow` on both paths, which would trigger GSC `Submitted URL marked 'noindex'` errors (`verify.mjs:446` also rejects `noindex` routes in `sitemap-core.xml`).
- **Hand-editing or committing `apps/portal/sitemap*.xml` or `apps/portal/llms*.txt`:** Owned by the data-sync pipeline (`blog-authoring-guide.md §5`); regenerate `seo.json` only and verify sitemaps/`llms.txt` in memory via `verify.mjs` and unit specs.
