# Add News tab SEO routes and salvage v14 SharedWorker WebSocket post

## Context

Live `Googlebot/2.1` crawl inspection of `https://neomjs.com` (`2026-11-14`) surfaced two search-discovery gaps on the Portal's News and Blog surfaces (`apps/portal/view/news/TabContainer.mjs:37-80` and `apps/portal/resources/data/medium_blog.json`):
1. Every `/news/blog/*` and `/news/releases/*` SSR snapshot renders tab links `<a href="/news/releases">`, `<a href="/news/blog">`, `<a href="/news/medium">`, and `<a href="/news/videos">`, yet none of those four section index routes are listed in `TOP_LEVEL_ROUTES` (`buildScripts/docs/seo/generate.mjs:45-53`), so `neomjs/middleware-v2` never prerenders them and crawlers hit `404` / Fastly `503` on the News tab bar itself.
2. `apps/portal/resources/data/medium_blog.json` holds `78` external Medium/ITNEXT URLs versus `25` self-hosted Markdown posts in `apps/portal/resources/data/blog.json`. While `a-data-grid-in-a-web-worker` and `building-a-multi-window-dashboard-with-dock-layouts` cover the Data Grid and Dock Layout wedges on `neomjs.com`, our high-intent **real-time WebSocket across multiple browser windows via `SharedWorker`** topic still lives exclusively on a 2020 Medium URL using pre-v10 APIs.

`unowned-rationale: Ready for a contributor or peer maintainer; maintainers provide planning and review.`

## The Problem

1. **Broken crawler hub links across all `/news/*` SSR snapshots (`generate.mjs:45-53`, `seoJson.mjs:474-486`):**
   - `apps/portal/view/news/TabContainer.mjs:37-80` (`origin/dev` @ `a07f581f13`) defines crawlable routes `/news/releases`, `/news/blog`, `/news/medium`, and `/news/videos` (#20589).
   - `apps/portal/resources/data/seo.json` carries static entries for `/news/blog` and `/news/releases` (`0` entries for `/news/medium` or `/news/videos`), and `generate.mjs:45-53` (`TOP_LEVEL_ROUTES`) includes only `/news` — omitting all four child index routes from `sitemap-core.xml`. Consequently, `middleware-v2` never generates `dist/seo/news/{blog,releases,medium,videos}/index.html`, turning `<a href="/news/medium">` (and sibling tab links) on all `25` `/news/blog/*` snapshots into broken crawler links (`HTTP 404`), and depriving `/news/blog` of a crawlable HTML index linking to all `25` self-hosted posts.
2. **Missing current-engine (`v14`) canonical tutorial for multi-window `SharedWorker` WebSocket streaming:**
   - Per the closed ruling on #9852 (`IC_kwDODSospM8AAAABjw8G5Q`, `2026-11-06`), `62` of the `73` pre-2025 entries in `medium_blog.json` use superseded pre-v10 APIs and MUST NOT be bulk-copied verbatim; instead, `#9852`'s explicit **Salvage** clause states: *"an old post that is still worth reading becomes a new post through the `blog-post` skill, rewritten against the current engine."*
   - Across all `316` core non-release routes on `origin/dev`, `SharedWorker` + `WebSocket` multi-window state sharing has `0` dedicated `learn/blog/*.md` tutorials written against current `Neo.worker.Manager` + `Neo.state.Provider` + `Neo.data.Store` APIs.

## The Architectural Reality

- `Design authority:` #20671 Intended solution shape §1–§2 (*"automated integrity checks that reject broken canonical or `/raw/` links before deploy"* and route-specific SSR metadata across `/news/*` front-door surfaces) + #9852 Salvage ruling (`IC_kwDODSospM8AAAABjw8G5Q`: rewrite high-value topics against the current engine via `.agents/skills/blog-post/SKILL.md` rather than migrating pre-v10 Medium exports verbatim).
- `apps/portal/view/news/TabContainer.mjs` mounts `blog/MainContainer.mjs`, `releases/MainContainer.mjs`, `medium/Container.mjs`, and `videos/Container.mjs` under `/news/{blog,releases,medium,videos}`.
- `buildScripts/docs/seo/generate.mjs` (`TOP_LEVEL_ROUTES` / `PRIORITIES`) governs which static Portal routes enter `sitemap-core.xml` (and therefore `middleware-v2`'s SSG build queue), while `apps/portal/resources/data/seo.json` + `buildScripts/docs/seo/seoJson.mjs` supply their `<title>` and `<meta name="description">`.

## The Fix

1. **Register `/news/blog`, `/news/releases`, `/news/medium`, and `/news/videos` in SEO metadata & `sitemap-core.xml` (`apps/portal/resources/data/seo.json`, `buildScripts/docs/seo/generate.mjs`, `buildScripts/docs/seo/verify.mjs`):**
   - Add curated `title` and `description` entries for `/news/medium` and `/news/videos` (and upgrade `/news/blog` and `/news/releases` descriptions) in `apps/portal/resources/data/seo.json`.
   - Include `/news/blog` (`0.9`) and `/news/releases` (`0.8`) in `sitemap-core.xml` (`TOP_LEVEL_ROUTES` / `PRIORITIES`), and ensure `/news/medium` and `/news/videos` are prerendered cleanly (`robots: 'noindex, follow'` or `0.5` hub index per `seo.json`) so `<a href="/news/medium">` and `<a href="/news/videos">` on `/news/*` pages resolve `200 OK` instead of `404`.
2. **Author one fresh v14 blog tutorial via `.agents/skills/blog-post/SKILL.md` (`learn/blog/*.md` + `apps/portal/resources/data/blog.json` + regenerated `seo.json`):**
   - Write a current-engine (`v14`) technical tutorial demonstrating **sharing real-time WebSocket streams across multiple browser windows with `SharedWorker`, `Neo.data.Store`, and `Neo.state.Provider`** (with runnable v14 code, verified API names, and search-intent `<title>` / `<h1>`), register it in `apps/portal/resources/data/blog.json`, and run `node buildScripts/docs/rebuildContentIndexesAndSeo.mjs`.

## Acceptance Criteria

- [ ] `/news/blog`, `/news/releases`, `/news/medium`, and `/news/videos` all carry explicit entries in `apps/portal/resources/data/seo.json` and are emitted for SSG prerendering so News tab links no longer `404` for crawlers.
- [ ] A new v14-native tutorial on multi-window real-time WebSocket streaming with `SharedWorker` is authored per `.agents/skills/blog-post/SKILL.md` in `learn/blog/`, registered in `apps/portal/resources/data/blog.json`, and indexed in `seo.json` / `sitemap-core.xml` / `llms.txt`.
- [ ] Zero verbatim pre-v10 code or prose is copied from 2019–2024 Medium posts (#9852 ruling honored); every Neo class/config referenced in the post exists on `dev`.
- [ ] `node buildScripts/docs/rebuildContentIndexesAndSeo.mjs`, `node buildScripts/docs/seo/verify.mjs`, and SEO unit specs pass.

## Out of Scope

- Bulk-migrating pre-2025 `medium_blog.json` archive entries (#9852 closed `not_planned`).
- Setting external Medium/ITNEXT canonical links in Medium's UI (tracked in `neomjs/business`).

## Avoided Traps

- **Copying 2019–2024 Medium posts verbatim into `learn/blog/`:** Rejected in #9852 (`IC_kwDODSospM8AAAABjw8G5Q`) because 62 pre-2025 posts teach replaced APIs; rewrite against current v14 primitives via `/blog-post`.
- **Adding `learn/blog/*.md` without registering in `apps/portal/resources/data/blog.json`:** `generate.mjs:616` walks `blog.json` (not `learn/tree.json`), so an unregistered `.md` file is invisible to both the Portal UI and `sitemap-core.xml`.
