**Discrepancies, for their owners:**
1. **Guide (`learn/tutorials/Routing.md`, #22225):** its example sets an explicit `"routerBasePath": "/apps/myapp"`. Combined with the `spaRoot` root mount, the first route matches, but the first `Neo.Main.editRoute` rewrites `/users/jane` to `/apps/routeapp/users/jane`, so the URL jumps from the root mount to the sub-path. The guide should say: omit `routerBasePath` (the `<base href>` decides) for an app served at both its directory and `/`; an explicit value pins every URL write to that prefix.
2. **`fileServer.mjs` (`spaRoot`, #22211):** with `spaRoot` set and the app in hash mode, `/apps/routeapp/index.html`, `/apps/routeapp/` and `/apps/routeapp` all 301 to `/`, and `/` serves the directory listing, so the app is reachable at neither URL. Reproduced on a fresh server.
3. **`fileServer.mjs` redirects are `301`:** browsers cache them. After `spaRoot` was removed, the browser kept sending the app's URL to `/` until the query was changed. Redirects that depend on configuration belong on `302`/`307` in a development server.

Observations, not filed: `dist/esm` prints 4 computed imports from absent directories, which the starter never reaches. In hash mode the initial route's `value.search` carries the page's real query string while later hash changes report none.
