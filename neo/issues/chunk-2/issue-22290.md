# Stale Text#updateCenterBorderElWidth getDomRect overwrites centerBorderElWidth

## Context

Following the merge of `#22266` (`cb3f854618`), `test/playwright/unit/form/field/TextDisabled.spec.mjs` intermittently fails on the first attempt (`1 flaky`, which fails the `unit` CI job) in GitHub Actions shard runs across unrelated PRs (`#22287` reported by `@neo-opus-grace`, `#22257` job `140228106741` at line 108 `Expected: 84, Received: 708`, and `#22267` job `140231259739` at line 117 `Expected: undefined, Received: 708`):

```text
1) [unit-engine] › test/playwright/unit/form/field/TextDisabled.spec.mjs:45:5 › Neo.form.field.Text#afterSetDisabled › projects disabled onto the native input, clears transient focus/hover in one VDOM update, and preserves programmatic APIs
Error: expect(received).toBe(expected) // Object.is equality
Expected: 84
Received: 708
  at test/playwright/unit/form/field/TextDisabled.spec.mjs:108:49
```

Curated labels (`good first issue`, `help wanted`) are omitted because this is an active `dev` CI shard flake blocking Engine `14.1` PRs; owned and fixed immediately by `@neo-gemini-maryam`.

## The Problem

Two unguarded async boundaries in `Neo.form.field.Text` (`src/form/field/Text.mjs`) combine to produce the race:

1. **`afterSetLabelPosition('inline', 'top')` (`src/form/field/Text.mjs:675-677`):** During construction of a non-empty inline `TextField` (`!isEmpty`), `afterSetLabelPosition` schedules `!isEmpty && me.timeout(20).then(() => { me.updateCenterBorderElWidth(false) })` even while `!me.mounted` (`afterSetMounted(true)` already calls `updateCenterBorderElWidth()` on mount). Locally the unit test finishes in `<10ms` (before the `20ms` timer fires, after which `destroy()` sets `mounted = false`), whereas under 4-worker CI shard contention the `20ms` timer fires mid-test right around lines 101–117, invoking `updateCenterBorderElWidth(false)` after `field.centerBorderElWidth = 84` or `field.disabled = true`.
2. **`updateCenterBorderElWidth(silent = false)` (`src/form/field/Text.mjs:1741-1752`):** Fires an unguarded async `me.getDomRect(me.getCenterBorderEl().id).then(data => { me.centerBorderElWidth = Math.round(data.width * .7) + 8; ... })` (which in `test/playwright/setup.mjs:178` resolves `{width: 1000} -> 708`). Neither scheduled callbacks (`afterSetLabelPosition` `timeout(20)`, `afterSetLabelText` `promiseUpdate()`) nor in-flight `getDomRect` promises track a request generation, so an older measurement resolving after an explicit `centerBorderElWidth` write, a newer measurement, `afterSetDisabled(true)`, `onFocusLeave`, unmount, or `destroy()` overwrites `centerBorderElWidth` and `getCenterBorderEl().width` with stale `708`.

## The Architectural Reality

- `src/form/field/Text.mjs`:
  - `centerBorderElWidth: null` (`:63`) is currently a non-reactive config, so explicit writes (`field.centerBorderElWidth = 84`) leave no generation marker that scheduled or in-flight `updateCenterBorderElWidth()` calls can observe.
  - `afterSetLabelPosition` (`:675`), `afterSetLabelText` (`:723`), `afterSetMounted` (`:798`), and `onFocusEnter` (`:1528`) initiate inline border-width measurements, while `afterSetDisabled` (`:446`), `afterSetMounted(false)` (`:800`), `afterSetLabelPosition` away from `'inline'` (`:645`), and `onFocusLeave` (`:1555`) clear the inline border cut-out.
- Design authority: n/a — reproducible defect (stale 20ms timer and async DOM measurement clobbering newer state and flaking `dev` CI).

## The Fix

1. Make `centerBorderElWidth_: null` reactive on `Neo.form.field.Text` and track a private `#centerBorderRequestId = 0` incremented in `beforeSetCenterBorderElWidth` as well as when clearing the inline cut-out (`afterSetDisabled` when inline+empty, `afterSetMounted(false)`, `afterSetLabelPosition` leaving `'inline'`, and `onFocusLeave` when empty).
2. In `afterSetLabelPosition`, schedule `me.timeout(20)` only when `!isEmpty && me.mounted`, capturing `const requestId = ++me.#centerBorderRequestId` at schedule time (and likewise in `afterSetLabelText` before `me.promiseUpdate()`) and passing `requestId` into `updateCenterBorderElWidth(silent, requestId)`.
3. In `Text#updateCenterBorderElWidth(silent = false, requestId = ++this.#centerBorderRequestId)`, bail out both before and after `me.getDomRect(...)` when `requestId !== me.#centerBorderRequestId || me.isDestroyed || !me.mounted || me.labelPosition !== 'inline'` or `!borderEl`, and skip writing `borderEl.width` when `me.disabled && me.isEmpty()`.
4. Add deterministic regression coverage in `test/playwright/unit/form/field/TextDisabled.spec.mjs` (using controlled `timeout` and `getDomRect` promises with zero fixed sleeps) proving neither a delayed `labelPosition` timer nor a stale `getDomRect` resolution can overwrite `centerBorderElWidth = 84`, re-populate `getCenterBorderEl().width` after `disabled = true` / blur, or throw after unmount/destroy.

## Acceptance Criteria

- [ ] `afterSetLabelPosition('inline', ...)` does not arm an unmounted `timeout(20)` measurement before mount, and a runtime `labelPosition = 'inline'` timer superseded by a later `centerBorderElWidth` write or `disabled = true` transition is ignored.
- [ ] An in-flight `Text#updateCenterBorderElWidth` `getDomRect` measurement superseded by a later `centerBorderElWidth` write, a newer `updateCenterBorderElWidth` call, `disabled = true` on an empty inline field, `onFocusLeave` on an empty inline field, unmount, or `destroy()` does not overwrite `centerBorderElWidth`, mutate VDOM, or throw.
- [ ] `test/playwright/unit/form/field/TextDisabled.spec.mjs` deterministically reproduces and guards both races on `dev` without relying on CI shard timing or fixed sleeps.

## Out of Scope

- Changing inline label cut-out math (`Math.round(data.width * .7) + 8`) or CSS layout.
- Widening `component.Base#removeCls` JSDoc signatures (tracked separately in `#22288`).
