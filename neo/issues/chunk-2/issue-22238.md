# Share a filtered Examples catalog with a link

## User outcome
A visitor finds examples by a phrase such as “drag”, copies one link and sends it to a colleague. Opening the link in a fresh tab restores the Find field and the same grouped results. Typing remains local: #21326 deliberately keeps per-keystroke filter changes out of history.

## Share, restore and clear

- **Copy search link** is an explicit keyboard-accessible action in the results header. Construct an absolute URL for the originating window and the current Examples route using `String.toRouteHref(route, windowId)`. Put the Portal-owned `find` key in the **page query** in both routing modes. For example, a root pathname installation can emit `/examples/forms?find=drag`; a hash installation keeps its document path and emits `?find=drag#/examples/forms`. Preserve the deployment mount and unrelated query keys, including repeated values. Where the route alone does not reproduce the selected build, encode the catalog’s build-mode ID in `catalogMode` and validate it against the existing build modes on restore. Existing build-route links continue to work.
- **Open, reload and Back.** Read the decoded raw string for the destination window. Seed the existing provider on entry to the shared Examples route. Once its catalog is ready, use the same search and grouping as typing. The route-load completion must preserve any newer user edit, Clear or intervening navigation. A normal group link opens its normal page; retained outer query parameters in hash mode must not unexpectedly reapply a previous group's search.
- **Typing, Copy and Clear/Escape** leave the current address and history length unchanged. Clear shows the underlying group or overview with its ordinary focus behavior. A hard reload of a saved share URL or Back to that history entry restores its saved query and build. A navigation to an ordinary Examples URL uses the normal route behavior.
- **Clipboard feedback.** Report “Copied” after the originating window’s clipboard operation confirms success. On denial, unsupported operation or an unconfirmed result, present the selectable URL for manual copying. A resolved worker RPC alone does not confirm a browser write.

## Acceptance checks

- [ ] Copy `café+drag?x=#` in a nondefault build with repeated unrelated query keys. Open the copied URL in a fresh tab, then reload. Check the original group, build, decoded field text, counts and grouped results (including zero matches) on root and mounted paths and in hash mode.
- [ ] Check typing, Copy, Clear/Escape, navigation away and Back, plus a slow catalog load followed by a newer edit or Clear. Each restores the state described above and creates history only for an actual navigation.
- [ ] Verify keyboard use and the desktop and phone layouts. Demonstrate confirmed copy and selectable-link fallback. Catalog search and its URL keys stay Portal-owned. Existing crawler routes and search infrastructure are outside this leaf.
