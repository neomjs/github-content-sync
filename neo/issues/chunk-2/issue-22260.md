# Teach the native default export in Learn previews and editable starter modules

## Context

A reader should be able to take the entry component from a live preview and use the same declaration in a source file. `MainView = Neo.setupClass(MainView);` can render inside LivePreview via its namespace fallback, but gives an ES-module importer no default export. The source-file form is:

```javascript
export default Neo.setupClass(MainView);
```

**Design authority:** Tobi’s 26 November review of the [Grid tutorial](https://github.com/neomjs/neo/pull/22253). Both tutorial labs were corrected there. The [LivePreview executor](https://github.com/neomjs/neo/blob/ed76831065/src/code/executor/Neo.mjs#L139-L146) already accepts the expression; the app, example and class generators already use it. Earlier [DataPipelines guidance](https://github.com/neomjs/neo/issues/9568) reflects the previous authoring convention.

## Scope and implementation

On `dev@ed76831065`, before the Grid tutorial, 36 Learn Markdown files contained 135 same-binding assignments. **86 `javascript live-preview` fences** ended in one, including 80 ending in `MainView`. There were another 36 assignments inside those live fences, nine in read-only fences and four in ordinary JavaScript fences. Two editable starter modules embedded in [the Legit example](https://github.com/neomjs/neo/blob/ed76831065/apps/legit/service/Legit.mjs#L274) also use the old ending. Repeat the inventory on the implementation head.

```sh
git grep -nP '\b([A-Za-z_$][\w$]*)\s*=\s*Neo\.setupClass\s*\(\s*\1\s*\)' -- learn apps examples
```

Convert the entry component of each source-like example. Keep helper registration and named exports when another class or subsequent statement needs them. Inspect [Extending Classes](https://github.com/neomjs/neo/blob/ed76831065/learn/gettingstarted/Extending.md), which sets up several classes in one fence, and [Using Stores](https://github.com/neomjs/neo/blob/ed76831065/learn/guides/datahandling/UsingStores.md#L56-L59), which already exports its store. Preserve one default export per module and one setup per class. Runtime rebindings such as the cached return value in `src/functional/defineComponent.mjs`, and intentional legacy-parser test fixtures, have different purposes.

For representative single-class and multi-class cases, verify both the real native ES-module export and the rendered Portal preview; edit and rerun a preview to cover the executor’s hot-update path. Verify the changed starter modules still launch in their normal host.
- [ ] Keep existing supported preview input forms working. Run the executor’s existing regression suite, Learn link and whitespace checks, and record the coverage in the PR.
