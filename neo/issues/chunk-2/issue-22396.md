# Verify staggered touch cancellation and restart through Neural Link and browser input

## Context

The existing Helix E2E suite checks a staggered partial lift through Chromium and through the Playwright Neural Link fixture. Its fixture case ends with an ordinary lift. A release-design probe on `5ff17dedc8` exercised cancellation followed by a new contact through the public Neural Link tool, the fixture, and browser input. All three observed the same eight transitions. [Runnable sequence and measured results](https://github.com/neomjs/neo/discussions/22259#discussioncomment-19961766)

## The Problem

The suite cannot catch a provider losing the cancellation, retaining the old contact when a fresh one starts, or reporting only a successful dispatch. A short fresh movement can also be suppressed by Chromium. [Existing test](https://github.com/neomjs/neo/blob/5ff17dedc8/test/playwright/e2e/component/HelixTouchNL.spec.mjs#L180)

## The Architectural Reality

Engine `EventSimulator` materializes the JSON contacts in their target window. The test fixture already exposes `app.simulateEvent` and Chromium exposes `Input.dispatchTouchEvent`. Listen at the real example’s target and query its existing App state. One test sequence can feed both entry points. The contact lists, trust and fresh gesture are independent observations. This is coverage of shipped input, without prescribing the proposed public recognizer API.

## The Fix

Extend the existing fixture control to replay the same staggered-contact, cancellation and restart sequence through the fixture and browser. Retain the existing partial-lift geometry assertions. Assert the observed active/changed IDs, terminal state and whether input was trusted, and check the fresh gesture actually moves the target.

## Acceptance Criteria

- [ ] AC-1 A single trace covers A down, B joins, B lifts, A moves, A cancels, C starts, moves and lifts on the real Helix example. Both providers observe the expected transitions and a usable fresh interaction.
- [ ] AC-2 Each route proves input trust and a separate application outcome. Preserve the existing opposite-lift-order and one-finger regression coverage. The browser fixture runs through the normal Engine E2E configuration.
