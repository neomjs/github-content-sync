# Neo.isEqual drops key-only changes, never equals NaN, loops on cycles

Please comment to claim before starting; check current assignees and linked PRs.

## Context

`Neo.isEqual` (`src/core/Compare.mjs`) decides whether a reactive config changed: `Config#set` writes and notifies only when `isEqual(newValue, oldValue)` is false (`src/core/Config.mjs:154-167`; the default is set at `:240`). Measured on `dev` (`4d5236b292`) in Node:

| Input | Today | Expected |
|---|---|---|
| `{a: undefined}` vs `{b: undefined}` | `true` | `false` |
| `{a: 1, b: undefined}` vs `{a: 1, c: undefined}` | `true` | `false` |
| `NaN` vs `NaN` | `false` | `true` |
| two invalid `Date`s | `false` | `true` |
| `a.self = a` vs `b.self = b` | `RangeError: Maximum call stack size exceeded` | `true` |

Through a config (a class with `foo_` and a counting `afterSetFoo`): after `p.foo = {a: undefined}; p.foo = {b: undefined}`, `afterSetFoo` did not run for the second set and `p.foo` still holds `{a: undefined}`. The new value was dropped. Setting `p.foo = NaN` three times ran `afterSetFoo` three times.

## The Problem

- `compareObjects` (`Compare.mjs:98-110`) checks that the key counts match, then walks `item1`'s keys with `isEqual(item1[key], item2[key])`. A key missing from `item2` reads `undefined`, so it matches a key whose value is `undefined`. `for...in` also walks inherited enumerable keys, while the count uses own keys.
- Numbers fall through to `item1 === item2` (`:162`), and `compareDates` compares `valueOf()` with `===` (`:44-46`). `NaN` is never `===` itself.
- `compareArrays` and `compareObjects` recurse without remembering which pairs are already being compared, so two cyclic structures recurse until the stack overflows.

## The Architectural Reality

- Configs that need other semantics override `isEqual` in their descriptor: `button/Base.mjs` (`handler_`) and `component/EmptyState.mjs` for functions, `mixin/VdomLifecycle.mjs:97` (`vnode_`) for identity.
- Function equality by source text is a decided contract: `#18236` (closed, not planned) found that `applyPendingDomListeners` depends on it. This ticket leaves `compareFunctions` alone.
- No spec imports `src/core/Compare.mjs`; `test/playwright/unit/config/Basic.spec.mjs` reaches it only through configs.

## The Fix

In `src/core/Compare.mjs`:
1. `compareObjects`: equal only when both sides have the same own enumerable keys (the `Object.keys` count plus `Object.hasOwn(item2, key)` for each key of `item1`), then compare the values.
2. `NaN` equals `NaN` in `isEqual` and in `compareDates`. Keep `===` otherwise, so `0` and `-0` stay equal.
3. Cycles: carry the pairs under comparison through the recursion (for example a `WeakMap` from left object to a `Set` of right objects) and treat a pair already in progress as equal, so the walk ends.
4. Add `test/playwright/unit/core/Compare.spec.mjs`: one case per `Compare.map` type, the five rows above, and the config case through a `Neo.setupClass` probe.

## Out of Scope

- Function equality (`#18236`).
- `Map` values and `Set` members compare by identity while object and array values compare deeply; changing that needs its own consumer sweep.
- Config descriptors that override `isEqual`.

## Avoided Traps

- `Object.is` for every primitive: it also makes `0` and `-0` unequal, so a config moving between them would start firing `afterSet`.
- `JSON.stringify` comparison: it drops `undefined` values and throws on cycles.
