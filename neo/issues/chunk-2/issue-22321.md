# The Overrides guide's Human snippet is not valid JavaScript

Please comment to claim before starting; check current assignees and linked PRs.

Live latest-open + closed sweep: latest open plus open and closed search ("Overrides.md", "Overrides snippet", "learn javascript overrides syntax") and open PRs ("Overrides.md") at 2026-11-27T04:51Z; the file's last change was 2023 (#7061). No equivalent or prior exclusion found. Backlog band: 51 open (red); no ticket owns this page.

## Context

The JavaScript Classes chapter of Learn teaches overriding with two snippets on [`learn/javascript/Overrides.md`](https://github.com/neomjs/neo/blob/dev/learn/javascript/Overrides.md). The second one, the `Human` class at line 59, is not valid JavaScript. A reader who copies it gets a syntax error, and a model trained on it learns a class syntax that does not exist. It surfaced while every Learn snippet that calls `Neo.setupClass` was parsed as an ES module for #22313; this is the only one that fails.

## The Problem

Parsing the fence as a module (Acorn, `ecmaVersion: 'latest'`, `sourceType: 'module'`):

```text
SyntaxError: Unexpected token (9:5)
```

Line 9 of the fence is `},` after `speak()`: class bodies separate methods with nothing, unlike object literals. Two smaller things in the same fence:

- `}}` closes `yodel()` and the class on one line.
- `Neo.create(Human, …)` runs before `Neo.setupClass(Human)`, which sits at the end. Neo builds a class's configs in `Neo.setupClass` (see the [SetupClass guide](https://github.com/neomjs/neo/blob/dev/learn/guides/coreengine/SetupClass.md)), so the snippet creates an instance of a class that is not set up yet.

## The Architectural Reality

- The fence is `javascript readonly`: the Portal shows it as code and does not run it, so nothing on the page flags the error.
- The first snippet on the same page (the `Mammal` class) is valid and ends with `export default Neo.setupClass(Mammal);`, the form the rest of Learn uses (#22260).

## The Fix

In `learn/javascript/Overrides.md`, in the `Human` fence only:

1. Remove the comma after `speak()`'s closing brace.
2. Put the class's closing brace on its own line.
3. Set the class up before creating an instance: move `export default Neo.setupClass(Human);` directly under the class, above `const myPerson = …`.

## Acceptance Criteria

- [ ] AC-1 The `Human` fence parses as an ES module. A quick check: paste it into a `.mjs` file and run `node --check file.mjs`, which reports syntax errors without running the code.
- [ ] AC-2 `Neo.setupClass(Human)` comes before `Neo.create(Human, …)`, and the fence keeps exactly one `export default`.
- [ ] AC-3 The explanation around the fence still matches it, and `npm run check-relative-links` passes.
