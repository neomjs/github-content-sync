# A pending target can duplicate moved children behind a leaf flight

## Context

PR #20764 resolved #20762. Review of the later candidate #20832 requires this post-merge remainder to have its own close target, following the recorded #20562 → #20573 / #20574 precedent. The original repair stays complete; this issue carries the newly demonstrated dispatched-leaf case and its implementation candidate.

## The Problem

A mounted leaf's VDOM update has already been dispatched and its genuine response is pending. In one turn, a sibling target changes style and receives the leaf through `Container.insert()`. That API requests a full-depth lowest common ancestor.

The target's normal pre-collection timer can still collect a target-only diff. It emits `insertNode` for the existing mounted ID. When the ancestor later runs, it emits no structural cleanup, leaving two physical nodes despite correct logical ownership. Generic unit and native witnesses reproduce this without board-specific code or manually assigned lifecycle flags.

A shallow intermediate component carrying merged full-depth target work has the same gap: raw depth alone does not describe the work it carries.

## The Architectural Reality

- `Container.insert()` computes the common ancestor and explicitly sets that ancestor's `updateDepth = -1`.
- `VdomLifecycle#mergeIntoParentUpdate` excludes a waking pre-collection scope from a pending ancestor when other descendants have already dispatched.
- `VDomUpdate#getAdjustedUpdateDepth` already describes the waking scope's own and merged requirements; querying it does not widen the actual parent payload.
- Design authority: `Container.insert()` states that the move flushes at the lowest common ancestor. Both old and new parents must therefore be visible to the structural diff.
- Prescription checked: eligibility in `VdomLifecycle` owns this gap. A consumer wait or a new registry would treat the symptom.

## The Fix

Retain declared or merged full-depth work under an ancestor that explicitly requests full depth, while keeping independent narrow payloads on the existing path. Reuse the existing depth query and yield/settlement machinery. Preserve the original incoming-child ownership repair and callback handling.

The parent-side declared-depth boundary is deliberate: a merged descendant's full-depth requirement does not itself declare that the parent payload covers the whole move. Standard `Container.insert()` explicitly declares the LCA's full depth.

## Contract Ledger

| Surface | Authority | Required behavior | Fallback | Evidence |
| --- | --- | --- | --- | --- |
| Pre-collection eligibility | Existing common-ancestor move contract | Direct and intermediate full-depth work stays with the declared full-depth ancestor | Existing narrow dispatch path | Generic unit + native identity controls |
| Callback and removal lifetime | Existing VDOM lifecycle | All real update callbacks settle; prior incoming-child vnode/mounted guards remain | Existing rejection/destruction paths | Existing and extended VDOM suite |
| Scope independence | Existing exclusion for dispatched descendants | Narrow work is not absorbed solely because an ancestor requests full depth | Unchanged shallow/noncolliding behavior | Shallow and chained-yield controls |

Decision Record impact: none; no public API, scheduler state, worker-wire or isolation/watchdog redesign.

## Acceptance Criteria

- [ ] Direct target and partial-carrier cases reproduce the split on unchanged source and preserve one original DOM node after repair: one move, no insertion/removal of the moved ID, correct items/VDOM/DOM after settlement.
- [ ] Moving-leaf, target, carrier and ancestor update callbacks settle; existing intermediate-owner callback coverage remains passing.
- [ ] Independent narrow/shallow work and the unchanged chained-yield control remain passing; prior stale-target incoming-child ownership and genuine-removal behavior are preserved.
- [ ] The VDOM unit suite, required `SyncVnodeTreeProfile` bounds and full `YieldedMoveCoalescingNL` native witness pass, including coherence/error gates.

## Out of Scope

Reworking #20747 / #20751 isolation or watchdog behavior; changing Main removal semantics; consumer sleeps or extra synchronization obligations; treating an ancestor's effective child depth as a declaration of whole-tree coverage.

## Avoided Traps

Absorbing every waking descendant (swallows an independent leaf flight); checking only raw descendant depth (misses the merged carrier); modifying the older correctness tests to accept either error; treating final logical state as proof of native node identity.
