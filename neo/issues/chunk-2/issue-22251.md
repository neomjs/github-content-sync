# Let create-component finish without opening a preview

Please comment to claim before starting. Check current assignees and linked PRs.

## Context

An interactive contributor may want to answer the component generator’s prompts and return to the shell once the files and themes are ready. Add an explicit option for that workflow. This is optional standalone work outside the 14.1 milestone and release gate.

## The Problem

After scaffolding a `Neo.*` component in a TTY, `create-component` synchronously starts the example server with `--open`. Its option list lacks a preview switch. A no-write replay of the launch branch confirmed the interactive Neo path requests the server, while an app namespace or non-TTY run completes without a preview. [CLI options](https://github.com/neomjs/neo/blob/3e43effbf34adf83d8436c7b93bff2e0236fa3e4/buildScripts/create/component.mjs#L36-L51) · [Launch branch](https://github.com/neomjs/neo/blob/3e43effbf34adf83d8436c7b93bff2e0236fa3e4/buildScripts/create/component.mjs#L203-L228)

## The Architectural Reality

The component CLI orchestrates class, CSS, example scaffolding and theme building before launch. It owns the choice to start a server. The file server’s existing `--no-open` controls browser opening while the server runs. [Scaffold sequence](https://github.com/neomjs/neo/blob/3e43effbf34adf83d8436c7b93bff2e0236fa3e4/buildScripts/create/component.mjs#L175-L228) · [File server options](https://github.com/neomjs/neo/blob/3e43effbf34adf83d8436c7b93bff2e0236fa3e4/buildScripts/README.md#L355-L359)

## The Fix

Add `npm run create-component -- --no-preview`. Gate the final preview-server spawn on that option, after the existing scaffold and theme steps. Document the flag in CLI help and the build-scripts guide.
