# A mounted TextField stays editable after readOnly is enabled

Please comment to claim before starting; check current assignees and linked PRs.

## Context

An app can switch a mounted `Neo.form.field.Text` between editable and read-only. The shipped TextField example exposes that public config through its **readOnly** checkbox.

## The Problem

1. Open `examples/form/field/text/` and check **readOnly**. Focus **Project name**, press End and type X. Both the displayed text and the App-worker value become `Neo WorkspaceX`, although the worker reports `readOnly === true`.
2. Reload the resulting `#readOnly=true` URL. The native input is now read-only and still focusable. Uncheck the box. The worker reports editable, while the native input stays read-only.

Chromium reproduced both directions with the pre-#22266 TextField and with the revised one. The relevant source and example are unchanged between the tested base and `dev@c51aa6828c`.

## The Architectural Reality

`Text#updateReadOnlyState()` writes the HTML name `readonly`. Initial rendering reflects it correctly. During a live toggle the Main delta writer indexes the element by that lowercase name. After enabling read-only I observed `input.readonly === true`, `input.readOnly === false` and no HTML `readonly` attribute. After reloading and switching it off, the first two values reversed and the attribute remained. [Field writer](https://github.com/neomjs/neo/blob/c51aa6828c/src/form/field/Text.mjs#L1782-L1786) · [Delta writer](https://github.com/neomjs/neo/blob/c51aa6828c/src/main/DeltaUpdates.mjs#L934-L943)

Design authority: [TextField’s public config](https://github.com/neomjs/neo/blob/c51aa6828c/src/form/field/Text.mjs#L234-L242) says “the field may not be changed by user interaction.”

## The Fix

Make in-place `readonly` updates reflect the native control in both directions. Keep initial rendering, focus, selection and programmatic updates working. Verify the smallest shared owner before changing any other boolean attribute. No stylesheet or example workaround is needed.

## Acceptance Criteria

- [ ] Use the real example checkbox or equivalent public setter on a mounted field. While read-only, the input stays focusable/selectable, rejects typing, and displays a programmatic value write.
- [ ] Turning read-only off allows typing again, including after a fresh load with `#readOnly=true`. Compare the displayed value, native `readOnly`, HTML attribute and App-worker state.
- [ ] Preserve the existing native disabled path and live-property behavior of other controls touched by the fix.
