# Release GridDragScroll’s touch listeners on cancellation and partial lift

## Reproduction on a shipped grid

A canceled touch drag on the Order Review Desk can consume the next touch outside the grid. Julia identified the missing cancel terminal in the [gesture discussion](https://github.com/neomjs/neo/discussions/22259#discussioncomment-19934123). We reproduced the failure with browser-generated touch input in Chromium on `dev@0c1cc8eb58`.

- Start contact 13 on a grid row, cancel during the monitoring interval, then start a contact outside the grid. The stale monitor can start a grid drag from that outside input.
- Engage a grid drag, deliver `touchcancel`, then move a new contact outside the grid. The abandoned grid’s `scrollTop` moved from 63 to 232 px; both outside moves were default-prevented.
- While 13 is dragging, add contact 27, wait through the arming delay and move both. Lift only 13. Chrome reported active contacts `[27]` and changed contacts `[13]`. A quick release started inertia with 27 still down. Continuing and releasing 27 produced uncaught reads of `containerElement` and `move` from undefined; an outside move could still be consumed. A 160 ms quiet interval before the lift suppressed the tail in the control. A coordinate teleport was not established.

## Ownership and acceptance

**Design authority:** [Grid drag scrolling](https://github.com/neomjs/neo/issues/8914) replaces native panning for the grid gesture it owns. [The existing interruption repair](https://github.com/neomjs/neo/issues/18099) and [kinetic-tail cleanup](https://github.com/neomjs/neo/issues/18104) are adjacent precedents. The single-contact stream, document listeners and inertia live in [the Main addon](https://github.com/neomjs/neo/blob/0c1cc8eb58/src/main/addon/GridDragScroll.mjs). Both monitor and active phases register `touchmove` and `touchend`; another start can rearm while an earlier gesture still owns listeners.

- [ ] Treat cancellation in either monitoring or active drag as a terminal. Release the gesture’s timer, document listeners and tracking state without starting momentum. A subsequent outside contact remains available to its original target.
- [ ] Give the grid a defined multi-contact interruption policy. A second contact and partial lift cannot replace a live gesture’s bookkeeping, launch a spurious fling, or leave stale listeners handling the next contact.
- [ ] Cover both cancellation phases and staggered contact lifetimes using a real grid and browser-generated input. Check grid position, outside input/default prevention, and absence of uncaught errors. A subsequent fresh one-finger drag and ordinary release must still work.

This is a current interaction bug; it can be fixed independently of the gesture-driver ADR, changes to global passive listeners, or the choice of grid zoom policy. Physical iOS/Android behavior remains to be verified.

Live latest-open and open/closed issue and PR searches, addon history, current source, Memory Core and recent claims were checked. No open owner for these grid-specific cases surfaced. Decision Record impact: none.
