# Colors: a detached widget opens empty on the production build

## Context

Found on 2026-11-14 while fact-checking a blog post that walks a reader through this demo (the pull request of `#20919`). The demo is the Home's "Shared Socket Data" example. The post leaves the detach step out because it fails on the live site.

## The Problem

On `https://neomjs.com/dist/production/apps/colors/index.html`, in Chromium 158, run twice:

1. **Start** fills the grid (99 cells, updating).
2. A click on **Grid** in the header toolbar opens `https://neomjs.com/apps/colors/childapps/widget/index.html?name=grid&dashboardId=neo-dashboard-1`.
3. After 20 s that window has no grid cell and no text. The main window still holds all 99 cells.

Expected: the grid moves into the new window and keeps updating there, as it does in dev mode.

## The Architectural Reality

- `apps/colors/view/Viewport.mjs:45` sets the dashboard's `popupUrl: 'apps/colors/childapps/widget/index.html'`. That is the dev-mode path, in every environment.
- `openWidgetInPopup` in `src/dashboard/Container.mjs` prepends `basePath` to a relative `popupUrl` and opens it. So the production parent opens the dev-mode child, which loads `src/MicroLoader.mjs` and attaches to a different shared worker than the parent's. The widget never arrives.
- The production child exists: `https://neomjs.com/dist/production/apps/colors/childapps/widget/index.html` answers 200.
- `popupUrl` takes a function. The one other app that sets it builds it per environment: `apps/email/view/WorkspaceContainer.mjs:28`.
- `apps/colors/view/ViewportController.mjs:43-52` already builds this child's URL with the environment, for its second branch (the one that opens a window without the dashboard). The app has two builders for one URL, and only one of them is right.

## The Fix

One function in the Colors app returns the child app's URL for the current environment (`Neo.config.environment`: nothing added in `development`, the environment as a path segment otherwise). The dashboard's `popupUrl` uses it, and so does the controller's second branch, so the URL is built in one place.

## Acceptance Criteria

- [ ] AC-1: the dashboard's `popupUrl` in `apps/colors` is no longer a fixed dev-mode path, and the child app's URL is built in one place for both ways of opening a widget window.
- [ ] AC-2: a unit spec covers that function for `development` and for one built environment (`dist/production`).
- [ ] AC-3: the pull request shows the detach working on a production build served locally (`npm run build-all`, then `npm run server-start` and the built `apps/colors`): after **Start** and **Grid** the new window's URL carries the environment path, the new window shows grid cells that update, and the main window no longer holds the grid. A screenshot of both windows or the numbers of a probe will do.
- [ ] AC-4 (after the next deploy of neomjs.com, owner: a maintainer): the three steps under "The Problem" end with a filled window on the live site.

## Out of Scope

- `dashboard.Container` resolving environments by itself. One app is wrong and its sibling shows the supported form.
- The blog post. It no longer names the detach step.

## Avoided Traps

- **An absolute URL to neomjs.com.** It would break local runs and other hosts.
- **Fixing only the dashboard's `popupUrl`.** Two builders would stay, one edit away from drifting again.
