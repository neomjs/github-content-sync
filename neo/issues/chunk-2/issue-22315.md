# Release notes and blog post edits wait until their skill is read

Live latest-open + closed sweep: latest 20 open in neo plus open and closed search ("hook skill release notes", "PreToolUse read witness") in neo, neo-agent-brain and neo-agent-skills at 2026-11-27T04:18Z, re-checked right before filing (Out of Scope / Avoided Traps read on the release-notes hits #19712, #20497, #21033); the A2A claim window (last 30, all read states), Memory Core ("seats edited release notes without loading the skill; hook on file path") and my open assignments (#22265, #22239, #21642) swept; no equivalent or prior exclusion found. Backlog band: 49 open (orange); the content routes are owned by neomjs/neo-agent-skills#438, whose Avoided Traps names this ticket as the Engine's half.

## Context

The Engine 14 release notes (#22091, ticket #22076) were approved and then rated 1/10 on the cut day; the seats that reworked them never loaded the `release-notes` skill. neomjs/neo-agent-skills#438 (PR neomjs/neo-agent-skills#481) routes content work to its skill at ticket creation, at intake and at review. [Julia's note on it](https://github.com/neomjs/neo-agent-skills/issues/438#issuecomment-7116217455) shows the gap those routes leave: on #22091, three seats edited `.github/RELEASE_NOTES/v14.0.0.md` directly on the PR branch through A2A and operator collaboration without reading the ticket, and a resumed session does not re-read it either.

## The Problem

A skill loads when the session classifies its own task. A seat that arrives framed as "refresh the counts" or "reorder the chapters" on an existing file does not classify the task as release notes, and no route written into a ticket or a review reaches it. The file path is the one signal that needs no classification: every edit names it.

## The Architectural Reality

- `.claude/hooks/` holds the Engine's tracked guard hooks (`bodyFileGuardHook.mjs`, `rgReplaceGuardHook.mjs`, `redirectionGuardHook.mjs`, `gitCommitPushGuardHook.mjs`, `helperCallGuardHook.mjs`). `bodyFileGuardHook.mjs`, for one, reads the Claude Code hook payload on stdin, writes `{decision: 'block', reason}` to stdout and fails open on a malformed payload. Their specs live in `test/playwright/unit/hooks/`, and three of them also assert the template registration.
- `.claude/settings.template.json` registers them under PreToolUse matchers `Bash` and `^(Agent|Task)$`; nothing matches `Write` or `Edit`. The Brain's `mergeClaudeSettings` (`ai/scripts/setup/initServerConfigs.mjs`) merges the template's hook events into every existing seat's `.claude/settings.json`, and `projectSeatHooks.mjs` reconciles the Agent OS events after it.
- The payload carries `transcript_path`. The transcript JSONL records each `Read` tool call with its `file_path` and each compaction as a `"subtype":"compact_boundary"` system entry; the seat's `seatModelGuardHook.mjs` and `laneStateStopHook.mjs` already read it.
- `.codex/hooks.json` wires `SessionStart`, `UserPromptSubmit` and `Stop`; no pre-edit event.
- Owning folder (§1c): `.claude/hooks/`, sibling precedent `bodyFileGuardHook.mjs` and its spec; the Brain's structure map does not cover the Engine's `.claude/`.

Design authority: "use when a release window opens, release notes are requested/authored/iterated/reviewed" (the `release-notes` trigger) and "Fires when you author, revise, or review a public blog post" (the `blog-post` guide). Both fire on the task; this hook makes the trigger fire on the edit.

## The Fix

1. `.claude/hooks/contentSkillGuardHook.mjs`: a PreToolUse guard for `Write` and `Edit`. When `tool_input.file_path` lies under `.github/RELEASE_NOTES/` or `learn/blog/`, it reads the transcript and blocks unless the session has read the governing payload since its last compaction boundary: `.agents/skills/release-notes/references/release-notes-workflow.md` for notes, `.agents/skills/blog-post/references/blog-authoring-guide.md` for posts. The reason names the file to read. It fails open on a malformed payload or an unreadable transcript, like its siblings.
2. Register it in `.claude/settings.template.json` under a `^(Write|Edit)$` PreToolUse matcher.
3. A spec beside its siblings: block without the read, allow with it, block when the only read precedes the last compaction boundary, allow outside the two folders, fail open on a malformed payload, and the template registration.

## Acceptance Criteria

- [ ] AC-1 An `Edit` or `Write` of a file under `.github/RELEASE_NOTES/` or `learn/blog/` is blocked when the session has not read the governing payload; the reason names the payload path.
- [ ] AC-2 The same edit passes once the transcript holds a `Read` of that payload after the last compaction boundary; a read before it does not count.
- [ ] AC-3 Edits outside the two folders and malformed payloads pass untouched (fail open).
- [ ] AC-4 `.claude/settings.template.json` registers the guard for `Write` and `Edit`, and a spec asserts the registration.
- [ ] AC-5 Post-merge: a seat's `.claude/settings.json` carries the matcher after its next settings merge, and one real blocked edit is linked here.

## Out of Scope

- Codex, Gemini, Kimi and OpenCode: none wires a pre-edit event here today; a harness that can gets its own ticket.
- A gate on the review verdict in `check-pr-review-body`: neomjs/neo-agent-skills#438 records its activation condition.
- Shell writes to those paths: AGENTS.md §file_editing_tool_selection routes every edit through `Write` or `Edit`, and the redirection guard refuses shell redirects.

## Avoided Traps

- Injecting a reminder instead of blocking: an injected line competes with the task framing that caused the miss; a block is answered only by the read.
- A state file recording reads: the transcript already holds them, and a second store can drift from it.
- Accepting the `Skill` call as the witness: the router only points at the payload, so the payload's `Read` is the witness.
