# The theme build writes each sheet's cascade layer from its folder

## Context

Seam 1 of the design system (epic and ADR 0044, graduated from [Discussion #22228](https://github.com/orgs/neomjs/discussions/22228)). It is the first step that changes how the cascade decides, so it carries an inventory as its gate, and it merges behind the equality run (#22300), which measures the changes of winner that an inventory of `!important` lines cannot show. Two peers tried to break the seam before graduation and added the guardrails below ([Grace](https://github.com/neomjs/neo/discussions/22228#discussioncomment-19937166), [Julia](https://github.com/neomjs/neo/discussions/22228#discussioncomment-19937175), [Emmy](https://github.com/neomjs/neo/discussions/22228#discussioncomment-19937235)).

unowned-rationale: critical path of the 14.1 cut and bound to a decision record, so it is for a maintainer seat. Claim by assignee and a `[lane-claim]`.

## The Problem

`resources/css` and `src` hold no `@layer` today. Who wins between an engine theme sheet and an app's projection depends on a mix of `:where(.neo-theme-*)` (0,0,0) and `:root .neo-theme-*` (0,2,0) and, at a tie, on which sheet loaded last (`#18102`). Theme sheets arrive in network order (`Promise.all`, `src/main/addon/Stylesheet.mjs:130`).

## The Architectural Reality

- `buildScripts/build/themes.mjs:236` passes every sheet through PostCSS per target folder (`buildFiles(files, mode, target)`), with cssnano for esm and production.
- `buildScripts/helpers/watchThemes.mjs:320` runs its own PostCSS pass for a single saved file. A wrapper that lives only in the build would let watch mode serve an unlayered sheet, which outranks every layer.
- Nothing under `resources/css` uses `@import`, `@charset` or `@namespace`; `@property`, `@font-face` and `@keyframes` are valid in a layer block. `buildScripts/create/theme.mjs:38-44` preserves relative CSS imports for a generated theme, and an `@import` inside a layer block is not fetched.
- `src/main/addon/HighlightJS.mjs:96` loads `resources/lib/highlightjs-custom-{github,dark}-theme.css` by `<link>`, from outside `resources/css`.
- `resources/css/src` holds 321 `!important` lines in 98 files. `!important` inverts across layers: an earlier layer's wins, and a layered one beats an unlayered one.
- 99 sheets live under `resources/css/src/apps` and 125 under `resources/css/src/examples`.

Design authority: "A sheet's layer follows from its folder … and the theme build writes it … No source file writes `@layer`." (ADR 0044, decision 6; Discussion #22228 at R3, seam 1.)

## The Fix

One PostCSS plugin, in a module that `build/themes.mjs` and `helpers/watchThemes.mjs` both call. It wraps a sheet's syntax tree (never a string) in the layer its folder determines and starts every built sheet with the order statement.

| Sheet | Layer |
|---|---|
| `theme-<name>/Global.css` | `neo.roles` |
| `theme-base/**` | `neo.base` |
| `theme-<name>/<pkg>/**` | `neo.theme` |
| `src/**` | `neo.rules` |
| `apps/**` and `examples/**` under `src` or a theme folder | `neo.apps`, this leaf's name for the sibling layer after `neo.rules` |

<!-- binding-inventory: cascade-layers -->
- `neo.roles`
- `neo.base`
- `neo.theme`
- `neo.rules`
<!-- /binding-inventory -->

Proposed, and decided by this leaf's inventory: an app's and an example's rules in a sibling layer after `neo.rules` (never a sub-layer of it), so an app's rule wins without `!important`; the two Highlight.js theme files carry their own layer, declared before `neo.roles`; rules inserted at runtime (`util/Css.insertRules`) stay unlayered. The four names above are fixed; a further layer for sheets the engine does not author is this leaf's to name, in the order statement.

## Out of Scope

- `theme-base` content and the loader (the map leaf).
- Any rename of a variable.

## Avoided Traps

- **Prepending the wrapper as a string.** It shifts source-map lines.
- **A sub-layer `neo.rules.apps`.** Un-nested rules of `neo.rules` outrank it.
- **A wrapper written in source files.** 600 copies of one decision, and an order that depends on load.
