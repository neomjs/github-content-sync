# An activation-only dock commit rebuilds the whole shell

## Context

@neo-opus-grace measured this while building #20952, in `apps/workstation` at `b52fd886e6`, with `Reconciler.reconcileProjection` wrapped over CDP in the App worker. Two tab presses in two tabs nodes commit two refreshes. Both reconcile with `retainTopology: false` and `geometryOnly: false`, and both return `landedInPlace: false`. So every press rebuilds the shell. The destroyed containers' `revertFocus()` is #20952's symptom, which PR #20955 guards. The fork's answer is on #20952: https://github.com/neomjs/neo/issues/20952#issuecomment-6881679244

## The Problem

`setActiveItem` writes one node field, but its change class is `topology`. So `Workspace#getRefreshOptions` returns `{}`, and every activation takes the full staged transaction. Every press pays a rebuild the reconciler does not need.

## The Architectural Reality

- `model/Operations.mjs` `operationChangeClass` has `setActiveItem: 'topology'`. It comes from #18154's map, whose rule is "an operation with no entry here is treated as topology". No rationale stands beside it, while `setItemPinned`, `setItemAutoHidden` and `restoreTab` each carry one. #18255 also found it classed `topology` with no argument.
- `Operations.setActiveItem` clones the document and writes exactly `nodes[tabsNodeId].activeItemId`.
- Design authority: the class definitions in `operationChangeClass`'s JSDoc.
  - `topology`: "may restructure nodes, zones or splits".
  - `itemFlags`: "writes only `document.items[id].<flag>`; the node tree is byte-identical".
  - An activation fits neither: it is node-preserving and placement-neutral.
- `Workspace#getRefreshOptions` maps `geometry` → `{geometryOnly: true}` and `itemFlags` → `{retainTopology: true}`. Everything else maps to `{}`.
- `Reconciler.reconcileStableTopology` under `reconcileItems`, which `retainTopology` sets, admits "tab item/active deltas while retaining the proven-identical structural shell". Its plans carry `activeIndex`. `reconcileTabChrome` writes that index silently and starts a parked active pane's load. Structure is still validated, and `landedInPlace` reports the path taken.
- Consumers:
  - every user tab press;
  - activation-only batches of a perspective restore (#18255);
  - every other projection of the same document converging on the commit (#17838).

## The Fix

- `Operations.operationChangeClass` gets a fourth class, `activation`: "writes only `nodes[id].activeItemId`; every node keeps its identity, items and order". `setActiveItem` moves to it. `changeClassFor` documents the new class.
- `Workspace#getRefreshOptions` maps `activation` → `{retainTopology: true}`.

## Acceptance Criteria

- [ ] AC-1: The pairing spec (`DockOperationChangeClass.spec.mjs`) classes `setActiveItem` as `activation`. `getRefreshOptions` returns `{retainTopology: true}` for a scalar and for a homogeneous Group activation, and `{}` for a mixed Group.
- [ ] AC-2: A browser witness in `apps/workstation` (whitebox e2e): a tab press in a second tabs node commits with `retainTopology: true` and lands with `landedInPlace: true`. It is red on base (`landedInPlace: false`) and green at head.
- [ ] AC-3: #17838's convergence holds. A non-first selected tab stays selected, in document truth and rendered content, after a press and after an unrelated re-projection. The existing dock and Workstation witnesses stay green.
- [ ] AC-4: A programmatic `setActiveItem` to a lazy, never-rendered pane lands in place and loads the pane.

## Out of Scope

- The focus guard: #20952 / PR #20955. It lands either way.
- Restore-plan ordering (#18255).
- Every other `topology` entry.

## Avoided Traps

- **Reclassifying `setActiveItem` as `itemFlags`.** That class promises a byte-identical node tree, and activation changes one node field.
- **Skipping the refresh for a view-originated press.** Every other projection of the document must still converge (#17838).
