# Resolve Portal home Screen 1 unprompted continuation discovery

Split from #20971 (PR #20982, `RA-2` in `pullrequestreview-5908211161`) under #20682 and [Discussion #20950](https://github.com/orgs/neomjs/discussions/20950) so Screen 2 `AudienceDoors`, shared `.portal-glass-card` tokens, and crawlable Home SSR anchors could land on `dev` under Option A fallback while retaining explicit open ownership of Screen 1 unprompted continuation discovery and `@tobiu` visual selection.

## Context

In [Discussion #20950](https://github.com/orgs/neomjs/discussions/20950), three model families converged on shipping Screen 2 `AudienceDoors` unconditionally while holding Screen 1 at **Option A** (no Screen 1 audience row) unless **Option B** (3-cell frosted visitor-verb dock) or **Option C** (compact pill cue row) both beat Option A on the two-phase cold-reader Look gate and received `@tobiu`'s visual selection.

Running the original `2026-11-15` two-phase cold-reader protocol on pre-`RoundTable` frames (`agent/20971-evidence` @ `ddd382b298`) with three zero-context readers surfaced a sharp split:

| Candidate (`2026-11-15` pre-`#21581`) | `1440×900` dark (Phase 1: 10s Screen 1 unprompted) | `390×844` dark (Phase 1) | `1440×800` / `900×700` / `neo-light` (Phase 1) | Phase 2 (after 1 scroll to Screen 2) |
|---|---|---|---|---|
| **Option A** (clean hero, no Screen 1 cue) | **Fail continuation & Body discovery** — reader saw `"An Agent Institution"`, detected no cue that content exists below the fold ("self-contained splash"), missed web-app engine role, and would click `View on GitHub` | **Fail continuation & Body discovery** — same self-contained splash read | Uncovered in Phase 1 cold-read | **Pass** (`1440×900` & `390×844` dark) — named both hemispheres, all 3 audiences, proofs, and next steps |
| **Option B** (3-cell frosted dock `>= 841px`) | **Pass** — reader named Agent Institution + JS app runtime, all 3 audiences (`THE BODY` / `THE BRAIN` / `THE ORGANISM` + `↓`), and would click GitHub or a dock cell to jump down (noted dock text is slightly small/subtle) | Identical to Option A (`<= 840px` hides dock) — **Fail** | Uncovered in Phase 1 cold-read (`900×700` dark verified in Phase 2) | **Pass** (`1440×900` & `900×700` dark) — all 3 cards unclipped |
| **Option C** (single pill cue `>= 841px`) | **Pass** — reader named Agent Institution + surfaced all 3 audiences via `Build an application · Run an agent team · Study the model ↓` (noted shared pill border is slightly ambiguous between 1 scroll cue vs 3 buttons) | Identical to Option A (`<= 840px` hides pill) — **Fail** | Uncovered in Phase 1 cold-read (`1440×900` light verified in Phase 2) | **Pass** (`1440×900` dark & light) |

### Post-`2026-11-20` `dev` Drift Reconciliation

Four merged changes on `dev` reshaped Screen 1 after `#20987` was filed:
1. **`RoundTable` Hero Canvas (`#21568` / PR `#21581` at `02adfb3bc8` + `#21602` / PR `#21608`):** Replaced `Portal.canvas.HomeCanvas` with `Portal.view.home.parts.hero.Canvas` (`apps/portal/view/home/parts/hero/Canvas.mjs`, extending `Neo.app.roundtable.Canvas` / `Neo.canvas.RoundTable`), which draws the 7-day PR replay strip and legend along the bottom band of Screen 1 above `718px` viewport height ([`#20682` steward note](https://github.com/neomjs/neo/issues/20682#issuecomment-7044174484)). Pre-`#21581` bottom-band candidates (`Option B` / `Option C` on `ddd382b298`) can no longer sit across the bottom of Screen 1 without colliding with the `RoundTable` replay strip and legend.
2. **Hero Copy & Three-Project Line (`#21595` / PR `#21604` at `e6ec564bad`, amending `ADR 0018` §2.3):** Updated `apps/portal/view/home/parts/hero/Content.mjs` to **8** `MagicMoveText` phrases (`Content.mjs:55-64`, holding `'An Agent Institution'` for `5300ms`) and a two-span `.neo-h3` (`span.hero-lead` + `span.hero-projects`, `Content.mjs:69-83`) that explicitly names the multi-threaded JavaScript application engine and all three open-source projects (*"Three open-source projects: the engine with grids, Gantt charts and task boards, the Agent OS, and the team's cockpit."*) on Screen 1. That resolves the pre-`#21604` Body/3-project silence on Screen 1 while leaving **unprompted below-the-fold continuation discovery** (discovering Screen 2 `AudienceDoors`) open.
3. **Native CSS Migration (`resources/scss/` → `resources/css/`):** `resources/scss/` and `_breakpoints.scss` were removed; Screen 1 styles now live in `resources/css/src/apps/portal/home/parts/hero/{Content,Container,Canvas}.css`, and the `840px` scroll-snap boundary lives in `resources/css/src/apps/portal/home/MainContainer.css:6` (`@media (max-width: 840px)`).

## The Problem

1. **Unprompted below-the-fold continuation on Screen 1 remains unverified/unaddressed post-`#21581`:** While `#21604` now names the multi-threaded JavaScript application engine and all three projects on Screen 1, Screen 1 (`100dvh` snap on `> 840px`, `786px` height at `390×844` per `#21604`) still carries no explicit continuation affordance pointing visitors to Screen 2 (`AudienceDoors`).
2. **Pre-`#21581` `Option B` / `Option C` bottom-dock geometry is invalidated by the `RoundTable` strip:** `Neo.canvas.RoundTable` occupies the bottom band of Screen 1 (`>= 718px` height) with the 7-day PR replay strip and legend, and `Container#onConstructed` (`apps/portal/view/home/parts/hero/Container.mjs:68-71`) reserves `bandIds` (`magic-move`) and `blockIds` (`logo-container`, `neo-h3`, `button-group`). Any Screen 1 continuation affordance must avoid colliding with the `RoundTable` strip and register any protected foreground bounds with `Container#onConstructed`.
3. **Screen 1 visual selection belongs to `@tobiu` (`Tier 4` aesthetic choice):** Per `D#20950` `OQ1`, `PR #20982` `RA-2`, and the [`#20682` cut posture](https://github.com/neomjs/neo/issues/20682#issuecomment-7044174484) (which locked the `RoundTable` + `#21604` hero shape for the `v14.0` cut), adding a Screen 1 scroll/doors cue requires fresh post-`#21581`/`#21604` candidate frames and `@tobiu` `Tier 4` visual selection across desktop and `<= 840px` mobile.

## The Architectural Reality

- `apps/portal/view/home/parts/hero/Content.mjs:34-103` and `resources/css/src/apps/portal/home/parts/hero/Content.css:6-157` own Screen 1's foreground stack (`.logo-container`, `MagicMoveText` `reference: 'magic-move'`, two-span `.neo-h3`, and `.button-group` with `Get started` + `View on GitHub`).
- `apps/portal/view/home/parts/hero/Container.mjs:61-72` (`onConstructed`) passes `bandIds: [content.getItem('magic-move').id]` and `blockIds: [idOf('logo-container'), idOf('neo-h3'), idOf('button-group')].filter(Boolean)` to `Portal.view.home.parts.hero.Canvas` (`apps/portal/view/home/parts/hero/Canvas.mjs`, extending `Neo.app.roundtable.Canvas`) so no seat or chord draws under the statement or buttons while the 7-day replay strip occupies the bottom edge.
- `apps/portal/view/home/MainContainer.mjs:54-63,114-125` exposes `reference: 'home-audience-doors'`, `'home-body-entry'`, and `'home-agent-os'` plus `scrollToPart(reference)`, and `resources/css/src/apps/portal/home/MainContainer.css:4-9` disables mandatory scroll-snap at `@media (max-width: 840px)`.
- Design authority: `ROADMAP.md:41` (#20682 done signal: *"someone who has never seen Neo reads the home section and can say in their own words what Neo is, who it is for and what to do next"*), [Discussion #20950](https://github.com/orgs/neomjs/discussions/20950) (`OQ1` / `OQ4`), and `learn/agentos/decisions/0018-neo-identity-source-of-truth-model.md` (`§2.3` / `§2.3.1`).

## The Fix

1. Capture fresh post-`#21581`/`#21604` Screen 1 candidate frames (`dev` baseline vs compact `.button-group`-adjacent or `RoundTable`-cleared scroll/doors affordance across desktop and `390×844` mobile) and present them to `@tobiu` for `Tier 4` visual selection (`ROADMAP.md:49` — non-blocking on the `2026-11-23` cut unless `@tobiu` selects pre-cut).
2. Implement the `@tobiu`-selected continuation cue in `apps/portal/view/home/parts/hero/Content.mjs`, `apps/portal/view/home/parts/hero/Container.mjs` (updating `blockIds` if a new foreground box is added), and `resources/css/src/apps/portal/home/parts/hero/Content.css` (plus theme overrides if token-needed), wired to `MainContainer#scrollToPart('home-audience-doors')` without mutating `#21604`'s two-span `.neo-h3` or 8 `MagicMoveText` phrases (`ADR 0018` §2.3) and without overlapping the `RoundTable` bottom replay strip.
3. Cover `<= 840px` (`390×844`) as well as desktop (`1440×900`, `1440×800`, `900×700`) so mobile first-screen visitors also perceive continuation to `AudienceDoors` without vertical overflow.
4. Run the two-phase zero-context cold-reader Look gate across `1440×900`, `1440×800`, `900×700`, and `390×844` in `neo-dark` and `neo-light`, verifying combined Phase 1 + Phase 2 pass plus unit/E2E parity.
