# Resolve Portal home Screen 1 unprompted continuation discovery

Split from #20971 (PR #20982, `RA-2` in `pullrequestreview-5908211161`) under #20682 and [Discussion #20950](https://github.com/orgs/neomjs/discussions/20950) so Screen 2 `AudienceDoors`, shared `.portal-glass-card` tokens, and crawlable Home SSR anchors can land on `dev` under Option A fallback while retaining explicit open ownership of Screen 1 unprompted continuation discovery and `@tobiu` visual selection.

## Context

In [Discussion #20950](https://github.com/orgs/neomjs/discussions/20950), three model families converged on shipping Screen 2 `AudienceDoors` unconditionally while holding Screen 1 at **Option A** (no Screen 1 audience row) unless **Option B** (3-cell frosted visitor-verb dock) or **Option C** (compact pill cue row) both beat Option A on the two-phase cold-reader Look gate and received `@tobiu`'s visual selection.

Running the two-phase cold-reader protocol on rendered frames (`agent/20971-evidence` @ `ddd382b298`) with three zero-context readers surfaced a sharp split:

| Candidate | `1440×900` dark (Phase 1: 10s Screen 1 unprompted) | `390×844` dark (Phase 1) | `1440×800` / `900×700` / `neo-light` (Phase 1) | Phase 2 (after 1 scroll to Screen 2) |
|---|---|---|---|---|
| **Option A** (clean hero, no Screen 1 cue) | **Fail continuation & Body discovery** — reader saw `"An Agent Institution"`, detected no cue that content exists below the fold ("self-contained splash"), missed web-app engine role, and would click `View on GitHub` | **Fail continuation & Body discovery** — same self-contained splash read | Uncovered in Phase 1 cold-read | **Pass** (`1440×900` & `390×844` dark) — named both hemispheres, all 3 audiences, proofs, and next steps |
| **Option B** (3-cell frosted dock `>= 841px`) | **Pass** — reader named Agent Institution + JS app runtime, all 3 audiences (`THE BODY` / `THE BRAIN` / `THE ORGANISM` + `↓`), and would click GitHub or a dock cell to jump down (noted dock text is slightly small/subtle) | Identical to Option A (`<= 840px` hides dock) — **Fail** | Uncovered in Phase 1 cold-read (`900×700` dark verified in Phase 2) | **Pass** (`1440×900` & `900×700` dark) — all 3 cards unclipped |
| **Option C** (single pill cue `>= 841px`) | **Pass** — reader named Agent Institution + surfaced all 3 audiences via `Build an application · Run an agent team · Study the model ↓` (noted shared pill border is slightly ambiguous between 1 scroll cue vs 3 buttons) | Identical to Option A (`<= 840px` hides pill) — **Fail** | Uncovered in Phase 1 cold-read (`1440×900` light verified in Phase 2) | **Pass** (`1440×900` dark & light) |

## The Problem

1. **Option A fallback leaves Phase 1 unprompted continuation unresolved:** Without a Screen 1 scroll/continuation cue, a cold visitor on Screen 1 sees a self-contained splash and never discovers Screen 2 (`AudienceDoors`) or the multi-threaded UI Engine (`src/`) unprompted.
2. **Screen 1 visual selection belongs to `@tobiu` (`Tier 4` aesthetic choice):** Per `D#20950` `OQ1` and `PR #20982` `RA-2`, a Screen 1 cue (Option B, Option C, or a subtler scroll affordance) requires `@tobiu`'s visual selection over the captured frames (`agent/20971-evidence` @ `ddd382b298`).
3. **Mobile (`<= 840px`) and remaining Phase 1 cells (`1440×800`, `900×700`, `neo-light`) remain uncovered:** Because Options B and C in `D#20950` were scoped to `>= 841px`, `390×844` renders identically to Option A and still lacks a continuation cue.

## The Architectural Reality

- `apps/portal/view/home/parts/hero/Content.mjs` and `resources/scss/{src,theme-neo-dark,theme-neo-light}/apps/portal/home/parts/hero/Content.scss` own Screen 1's foreground controls above the canvas (`z-index: 3`).
- `apps/portal/view/home/MainContainer.mjs` (via #20971 / PR #20982) already exposes `reference: 'home-audience-doors'`, `'home-body-entry'`, and `'home-agent-os'` plus `scrollToPart(reference)` and `$portal-home-snap-max-width: 840px` in `resources/scss/src/apps/portal/home/_breakpoints.scss`.
- Design authority: `ROADMAP.md:39` (#20682 done signal: *"someone who has never seen Neo reads the home section and can say in their own words what Neo is, who it is for and what to do next"*), [Discussion #20950](https://github.com/orgs/neomjs/discussions/20950) (`OQ1` / `OQ4`), and `learn/agentos/decisions/0018-neo-identity-source-of-truth-model.md`.

## The Fix

1. Present the captured Screen 1 candidate frames (`agent/20971-evidence` @ `ddd382b298`: Option A vs Option B vs Option C, plus a compact mobile-safe scroll cue if selected) to `@tobiu` for visual selection (`Tier 4`).
2. Implement the selected Screen 1 continuation cue in `apps/portal/view/home/parts/hero/Content.mjs` + `Content.scss` (`src`, `theme-neo-dark`, `theme-neo-light`), wired to `MainContainer#scrollToPart('home-audience-doors')` (or per-door targets if Option B is chosen) without touching `.neo-h3` or the 28 `MagicMoveText` phrases (`ADR 0018`).
3. Address the `<= 840px` (`390×844`) continuation gap so mobile first-screen visitors also perceive below-the-fold continuation without re-introducing `Fork S2` vertical bloat.
4. Run the two-phase zero-context cold-reader Look gate across all four viewports (`1440×900`, `1440×800`, `900×700`, `390×844`) and both themes (`neo-dark`, `neo-light`), verifying combined Phase 1 + Phase 2 pass before closing this leaf.
