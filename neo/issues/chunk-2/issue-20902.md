# Review frames ship in the npm package again; a guard keeps them out

## Context

One defect class came back three times in three days: frames captured as review evidence are committed to the tracked tree, and the package ships them. #20712 removed four on Nov 10. The review of #20703, the same day, asked eight more out and named the alternative. On Nov 13, #20888 merged six, and #20891 and #20898 carried five between them until their authors were asked.

## The Problem

- On `dev` at e152c053af, `examples/scheduler/basic/preview/` holds six PNG files, 312,523 bytes. `git grep -n "scheduler/basic/preview" -- . ':!*.png'` prints nothing, and `npm pack --dry-run --json` lists all six (measured at 9705965fcf, which contains that `dev`; 6,347 entries).
- Their only reader is the description of #20888. Its links are pinned to its head 0094fde137, which `git ls-remote` shows held by `refs/pull/20888/head` alone, and `https://github.com/neomjs/neo/blob/0094fde13768adc228b671b9501be6a747d73502/examples/scheduler/basic/preview/light.png?raw=true` answers 200 after the squash merge. So the files can leave `dev` and the description keeps its pictures.
- The remedy is known and lives in one review (#20703, Required Action 3): commit the frames, link them pinned to that commit, remove them in a later commit of the same pull request. Two authors and one reviewer (the filer, on #20888) did not carry it over. A rule that lives in a review does not hold; a check does.

What such a check meets today, measured at 9705965fcf by searching every packed text file (`mjs`, `js`, `json`, `scss`, `css`, `md`, `html`, `yaml`, `txt`, `svg`) for each packed image's bare file name: 1,021 images, 18,545,331 bytes; 415 of them, 7,531,544 bytes, are named nowhere.

## The Architectural Reality

- `package.json` has no `files` list, so `.npmignore` decides what ships, and `buildScripts/util/check-package-contents.mjs` is the one script that asserts what the tarball holds. It runs `npm pack --dry-run --json`, applies the pure predicate `findForbiddenEntries` (covered by `test/playwright/unit/buildScripts/checkPackageContents.spec.mjs`) and runs on every pull request (`.github/workflows/pr-baseline.yml`, the "package contents" step).
- Design authority: `.npmignore`, line 1: "Additional rules, which are solely npm related, to not bloat the package size."
- #20712's Avoided Trap stands: an `.npmignore` rule keeps a frame out of npm and leaves it in every clone, so the files leave the tree.

## The Fix

1. Delete `examples/scheduler/basic/preview/`.
2. In `check-package-contents.mjs`, add a second pure predicate beside `findForbiddenEntries`: given the packed paths and a reader for packed text files, it returns every packed image (`png`, `jpg`, `jpeg`, `gif`, `webp`) that no packed text file names by parent folder and file name. Call it in the entry block; a finding fails the check.
3. A committed baseline beside the script, in the manner of `check-class-module-scope-baseline.json`, lists what is unnamed today, by folder prefix where a folder is read by pattern, each entry with its reason. An image outside the baseline fails.
4. The failure text carries the rule, so that nobody has to find it in a review:

```text
A pull request's frames do not belong in the tree. Commit them, link them pinned to that commit
(https://github.com/neomjs/neo/blob/<sha>/<path>?raw=true), and remove them in a later commit of the
same pull request; its ref keeps the commit served.
```

## Acceptance Criteria

- [ ] `git ls-files examples/scheduler/basic/preview` prints nothing, and the six images in the description of #20888 still load with the change on your branch. Say so in the pull request.
- [ ] `npm run check-package-contents` passes on the branch, and fails when an image that no packed text file names by folder and file name is added outside the baseline. Show the red run with one planted file.
- [ ] The unit spec covers the predicate: a named image passes, an unnamed one is found, a baselined prefix passes, and `preview/dark.png` is found although `dark.png` occurs elsewhere.
- [ ] Every baseline entry states its reason. The pull request states the count under the folder-and-name match (the table above used the bare name, so the count will differ) and what happened to each single file: referenced, removed or listed.
- [ ] The failure text contains the pinned-link rule.

## Out of Scope

- The 10.9 MB of images that are named, and whether the 399 `ai_images` should ship at all.
- Private repositories, whose frames live in a media repository, and the before-and-after rule of the Stage repository.
- #20891 and #20898: their frames leave in review.
- Example cover images (#20679).

## Avoided Traps

- **An `.npmignore` rule** (#20712).
- **A written rule alone.** It has existed since the review of #20703 and did not hold three days.
- **Matching the bare file name.** Two of the six frames pass that way.
- **A list of allowed image folders.** The frames went into three different folders in three days.
