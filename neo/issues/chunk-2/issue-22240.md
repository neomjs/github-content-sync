# Measure options for read-only code previews in Learn and Docs

## Decision to make
Can Learn and the legacy Docs source viewer present readable, selectable source with a smaller and easier-to-maintain dependency footprint? This is a bounded investigation. The 14.1 release does not depend on adopting a tokenizer. Editable Monaco and LivePreview remain separate consumers.

## Starting evidence
The root lockfile has exactly two dedicated entries: highlight.js and highlightjs-line-numbers.js, both direct development dependencies with no child dependencies. #21211 / #21281 already removed the separate upstream clone and nested tooling install. On 26 November the current ten-language esbuild produced 71,092 bytes minified (21,320 locally gzipped); the classic line-number addon was 3,288 bytes (1,549 gzipped). These are artifact sizes, not a measured network transfer. Markdown uses Neo.util.HighlightJs; the Docs addon also supports line tables, highlighting/scrolling a source line, remounting and custom loader paths. Neo already owns a Node-capable line-number utility.

## Acceptance criteria
- [ ] Inventory actual read-only fences separately from editable, Mermaid and embedded component blocks; include Docs and server/build renderers plus unsupported-language fallback. Compare cold Learn and Docs loads, actual transferred bytes, build outputs and lockfile delta.
- [ ] Compare the current subset, a smaller registration list or shared Neo line numbering, and a lightweight read-only renderer with a small syntax corpus. Include Monaco tokenization only as a measured alternative; a static page must not eagerly load the editor just to color text.
- [ ] Check literal text/markup escaping, multiline JS/templates, tagged or mixed HTML, CSS, shell, JSON and fallback. Verify copy fidelity, line numbering, Docs source line navigation after remount, dark/light readability and server/browser output. Record costs of maintaining grammars and compatibility.
- [ ] Publish a measured keep/reduce/replace recommendation and a scoped implementation estimate. File implementation work only after a selection.

Decision Record impact: none for the investigation. unowned-rationale: optional release research open to a maintainer. Prior decisions #7788, #7789, #7790, #7791, #7878 and #21211 preserve existing consumers. Latest open queue, closed Highlight.js titles, source, lockfile, recent A2A and existing assignments checked.

### 3. Escaping, Multiline Spans, Copy Fidelity, Docs Remount & Contrast Checks (`AC-3`)

1. **Defect A — Raw HTML injection / generic-type stripping in `Docs.view.classdetails.SourceViewComponent` (`docs/app/view/classdetails/SourceViewComponent.mjs:138` & `examples/component/toast/MainContainerController.mjs:59`):**
   - `SourceViewComponent#applySourceCode` sets `node.cn[0].html = data` (`innerHTML`) *before* `HighlightJS#syntaxHighlight` reads `node.textContent`.
   - **Live Chromium verification:** Given source containing `@returns {Promise<Boolean>}`, `<div class="probe">&amp;</div>`, and `` tpl = `<section data-x="${1 + 2}"><span>literal &lt;tag&gt;</span></section>` ``, browser `innerHTML` parses `<Boolean>`, `<div>`, `<section>`, and `<span>` as DOM tags and strips them, rendering `@returns {Promise}` and decoding `&amp;` → `&`!
   - **Fix (independent of tokenizer choice):** Set `node.cn[0].text = data` (`textContent`) instead of `.html = data`. (`Neo.component.Markdown` passes raw fence strings directly to `HighlightJs.highlight`, which escapes `<`, `>`, `&` cleanly.)
2. **Defect B — Broken newline regex & multiline `<span>` splitting in `Neo.util.HighlightJsLineNumbers` (`src/util/HighlightJsLineNumbers.mjs:5`):**
   - Line 5 defines `lineRegex = /\\r\\n|\\r|\\n/g` (double-escaped backslashes), so `'line1\nline2\nline3'.split(lineRegex)` returns **`1` element** instead of `3`.
   - Even with `/\r\n|\r|\n/g`, splitting highlighted HTML into `<tr><td>` rows without tracking open `<span class="hljs-...">` tags breaks multi-line `/* ... */` JSDoc blocks and multi-line template literals after line 1 (browsers auto-close unclosed `<span>` at `</td>`).
   - **Measured fix:** A 28-line stack-balanced `addLineNumbers` (`643 B` minified / `392 B` gzip, verified on multi-line comments and `${a}` template literals) re-opens active `<span class="...">` tags at the start of each `<tr>` and closes them at `</td>`, preserving identical `<table class="hljs-ln">` `[data-line-number="N"]` markup so `HighlightJS#syntaxHighlightLine` works unchanged across remounts (`line10Highlighted: true, line9Highlighted: false` verified in Chromium).
3. **Copy fidelity:**
   - Verified in Chromium via `Range` + `window.getSelection().toString()`: `Neo.component.Markdown` `<pre class="hljs">` matches raw source character-for-character (`exactMatch: true`). Docs `<table class="hljs-ln">` sets `user-select: none` on `td.hljs-ln-numbers`, so copying omits line numbers and preserves `\n` line breaks cleanly once Defect A (`.text = data`) is fixed.
4. **Dark / Light WCAG 2.1 AA (`4.5:1`) Contrast Audit:**
   - **`neo-dark` (`#0d1117` bg):** Passes AA across every token (`base` `12.26:1`, `string` `12.31:1`, `builtin` `9.77:1`, `number` `9.73:1`, `keyword` `7.51:1`, `comment` `6.15:1`).
   - **`neo-light` / `light` / `highlightjs-custom-github-theme.css` (`#ffffff` bg):** **`comment` (`#999988`, `2.89:1`) and `meta` (`#999999`, `2.85:1`) fail WCAG AA** (`#6a737d` / `#57606a` raises both above `4.8:1`).
   - **`dark` / `highlightjs-custom-dark-theme.css` (`#2b2b2b` bg):** **`comment` (`#808080`, `3.59:1`), `string` (`#6a8759`, `3.52:1`), `keyword` (`#cc7832`, `4.25:1`), and `.hljs-ln-numbers` (`#606366` on `#303335`, `2.10:1`) fail WCAG AA**.

### 4. Converged Recommendation & Scoped Implementation Estimate (`AC-4`)

**Converged Selection (`@neo-gpt-emmy` + `@neo-gemini-maryam`): Option `2c` (`Minify All 10 Languages & Consolidate Gutter` — default `HighlightJs.debug = false`, keep all 10 registered grammars including `ruby` for `yaml.js` `<%…%>` ERB subLanguage parity, retire `highlightjs-line-numbers.js`, and fix the 3 runtime/contrast defects).**

- **Why Option `2c` wins over `2a`/`2b` (trimming grammars), Option 3 (custom tokenizer), and Option 4 (Monaco):**
  1. Keeping all 10 grammars (`71,092 B` raw / **`21,286 B` gzip**) costs only **`+1,202 B` gzip** over the 9-language build without `ruby` (`67,176 B` raw / `20,084 B` gzip) while preserving `highlight.js/lib/languages/yaml.js:142-148`'s `subLanguage: 'ruby'` ERB delegation, `scss` + `markdown` fences in Learn (`636/637` coverage), and existing `highlightJs.spec.mjs` invariants.
  2. Defaulting `HighlightJs.debug = false` and replacing `highlightjs-line-numbers.js` (`3,288 B` / `1,549 B` gzip) with the `643 B` / `392 B`-gzip span-balanced `Neo.util.HighlightJsLineNumbers` cuts **real cold-load wire bytes by `-43.2%` gzip (`38,168 B` → `21,678 B` gzip, `-71.9 KB` raw)** while keeping `0` custom grammar maintenance debt and full nested JS/HTML/CSS tokenization accuracy (the custom regex prototype fails on JS regex-vs-division and nested template/HTML teaching examples).
  3. Retiring `highlightjs-line-numbers.js` removes `1` npm dependency, eliminates the runtime `node_modules/highlightjs-line-numbers.js/...` script fetch, and removes the `globalThis.hljs` global mutation in `src/main/addon/HighlightJS.mjs:91`.
  4. Removing `"HighlightJS"` from `apps/portal/neo-config.json` `mainThreadAddons` (loading it lazily via `getAddon('HighlightJS')` only when Docs views mount) saves `3` eager Main-thread requests (`14.4 KB`) on every cold Portal Home, Examples, and Learn load.
  5. Fixing `SourceViewComponent` (`.text = data` instead of `.html = data`) and raising light/Darcula comment & string contrast to `≥ 4.5:1` eliminates live JSDoc `<Generic>` data loss and accessibility debt in the same pass.

- **Scoped Implementation Estimate (post-`14.1` cut follow-up per `ROADMAP.md`):** **`0.5–1` engineering day** (`1` bounded Engine/Docs PR + unit specs for `HighlightJsLineNumbers` multiline span balancing & `SourceViewComponent` `<Generic>` escaping + `HighlightJsResources.spec.mjs` E2E verification; `0` consumer breaking changes).
