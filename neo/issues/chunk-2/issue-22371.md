# Dragging a Circle item throws before the proxy appears

## Context

Circle is a shipped Engine component and an example in the Portal. In Chromium 159, an ordinary mouse drag in the stock `/examples/component/circle/index.html` fails on `dev` at `8d0276127c`. The Circle source blob is identical at tag `14.0.0` (`9b459410583506ab8856e151cdea701936f47f56`).

## The Problem

Open the Circle example, click **Expand**, grab a visible item on the ring, and drag far enough to start the gesture. No proxy appears. `Circle#onDragStart` sets its drag flag, then throws before a zone exists. The flag stays set after mouseup.

```text
TypeError: me.getProxyVdom is not a function
    at Circle.onDragStart (src/component/Circle.mjs:710:44)
```

## The Architectural Reality

Design authority: Circle's class JSDoc says, “Items within the circle are draggable.”

- [`Circle#onDragStart`](https://github.com/neomjs/neo/blob/8d0276127c30650f0844f4d32b93eec602863262/src/component/Circle.mjs#L697-L722) supplies its own VDOM as `dragElement`, then calls a missing `getProxyVdom` method. Its delegated `onDragEnd` only logs.
- [`DragZone#getDragProxyVdom`](https://github.com/neomjs/neo/blob/8d0276127c30650f0844f4d32b93eec602863262/src/draggable/DragZone.mjs#L314-L330) already clones the configured `dragElement` if no custom proxy is supplied. `DragZone#dragEnd` clears the proxy and resets the zone. `dragZoneConfig` remains the Circle caller’s override point.

## The Fix

Use the existing DragZone clone path in Circle and finish the zone on the delegated release. Keep setup and termination local to Circle. The hosted engine and gesture recognizer require no policy change.

An in-memory source variant proved both pieces on the same stock example. Removing the missing method call alone created one proxy that remained after release. Adding the zone’s release cleanup produced one proxy during the drag and zero after mouseup, cleared Circle’s drag flag, and raised no uncaught exception.

## Acceptance Criteria

- [ ] On the stock Circle example, dragging an expanded item creates exactly one proxy and records no uncaught exception.
- [ ] Releasing the item removes the proxy and clears the active gesture. A second drag can start and complete.
- [ ] The browser regression fails on the current stock implementation and passes with the repair.

## Out of Scope

Two-finger rotation, `touch-action` defaults, and shared drag or VDOM scheduling behavior.

## Avoided Traps

Copying Dialog’s content-stripping `getProxyVdom` would attach a Dialog-only policy to Circle. Removing the undefined call alone leaves a proxy behind on release.
