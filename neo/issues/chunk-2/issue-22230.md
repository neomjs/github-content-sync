### 2. Live Feed Provenance, CORS & Upstream Magnitude Observation

- **Endpoint & CORS:** `https://nameless-tundra-27404.herokuapp.com/go/?fn=earthquakes` (a live Heroku proxy originally wrapping Icelandic seismic observations; direct `https://apis.is/earthquake/is` currently fails TLS issuer verification) returned HTTP `200` (`application/json; charset=utf-8`) and echoed matching `Access-Control-Allow-Origin` headers on both `Origin: http://localhost:8080` and `Origin: http://localhost:8081`. The tutorial keeps `http://localhost:8080` as the default `server-start` recipe and instructs readers on fallback ports to verify in DevTools → Network that `Access-Control-Allow-Origin` permits their actual browser origin.
- **Schema & Field Semantics:** `{data: [{timestamp, lat, lng, location, magnitude, depth}, ...]}` (`61`–`62` observations on `2026-11-26`, all serialized as strings). Declaring `type: 'Date'` on `timestamp` and `type: 'Float'` on `magnitude`, `lat`, and `lng` produces finite `Number` coordinates (`allFiniteCoords: true`) and numeric magnitudes.
- **Observed Upstream Anomaly:** Live `magnitude` strings currently span `~1.02` to `~46.90` (`1.68`–`45.60` during final browser run). Reported faithfully in the tutorial (`value.toFixed(2)`) as an observed upstream test-feed reading without inventing a root cause or clamping values.

### 3. Transferable Teaching Assessment & Worked Lab Extract (for `#20529`, `#22231`, `#22232`)

Analyzing Max Rahder's original `6676963fb0` arc surfaces four techniques that transfer cleanly across our `14.1` tutorials without forcing a uniform voice or collapsible `<details>` layout:

1. **Make the reader *feel* the architectural problem in DevTools before naming the primitive.**
   Max never opens `Shared Bindable Data` with an abstract definition of `Neo.state.Provider`. Instead, he has the reader duplicate `EarthquakesGrid` (`items: [gridA, gridB]`), open **DevTools → Network (`Fetch/XHR`)**, and observe **two** identical requests (`grids[0].store !== grids[1].store`). Even better, his intermediate step adds `stores.earthquakes` to the provider *before* removing the inline stores so the reader predicts and sees **three** requests, then replaces both inline configs with `bind: {store: 'stores.earthquakes'}` and sees **one** request.
2. **Pair every UI change with one falsifiable Worker-Console probe.**
   One-line console checks inside `neomjs-app-worker` (`(a === b) && (a === c)`, `temp1.magnitude = 2.5`, `await store.load()`) prove object permanence directly in the runtime rather than asking the reader to trust prose.
3. **Separate "config reuse" (subclassing) from "instance sharing" (state provider).**
   Refactoring `Grid.mjs` first proves that class inheritance shares *blueprints* (`columns`), which makes the remaining gap — sharing one live `Store` *instance* — unmistakable.
4. **Disclose external / environment boundaries at the exact step where failure would look like an engine bug.**
   Naming browser-origin CORS verification, CDN/tile requests, or worker realm boundaries right beside the `Save and refresh` prompt turns potential reader dead-ends into diagnostic skill.

#### Worked Lab Pattern ("Predict → Observe → Bind/Switch → Verify Identity")

Authors of `#20529` (Enterprise Grid), `#22231` (Shared State across Form/Dialog/Window), and `#22232` (Data Pipeline across `App`/`Data` Workers) can adapt this 4-beat lab skeleton in their own format:

```markdown
1. **Setup the naive / baseline state**
   Run the working view first (e.g., two views with inline Store configs; a 5,000-row Grid before scrolling; or a Pipeline on `workerExecution: 'app'`).

2. **Predict & measure one concrete observable**
   Ask the reader what DevTools or the App Worker console should show *before* changing the config:
   - Network count (`?fn=earthquakes`: 2 requests vs 1)
   - Mounted DOM row pool (`document.querySelectorAll('.neo-grid-row').length` vs `store.count` before and after scrolling to row 2,500)
   - Worker attribution & preserved state (`sample.worker`, `store.count` when an attempt rejects or arrives incomplete)

3. **Change one config**
   Move the Store into `StateProvider` + `bind`, scroll to a distant record, or flip `workerExecution: 'data'`.

4. **Verify object identity in `neomjs-app-worker`**
   Run a 2–3 line check proving *why* the behavior changed (`map.markerStore === store && grid.store === store`, or row record IDs changing while `.neo-grid-row` count stays bounded).
```
