# A computed-style equality run proves a theme change paints the same

## Context

The instrument the design system's migration is gated on (epic and ADR 0044, graduated from [Discussion #22228](https://github.com/orgs/neomjs/discussions/22228)). Its first consumer is the removal of `--cmp-*` (#22299), which waits for it. The rename then touches every theme file in one pull request, and about thirty packages move one at a time. A reviewer cannot read 582 theme files for an unintended change; a machine can compare what each element paints.

unowned-rationale: critical path of the 14.1 cut, so it is for a maintainer seat. Claim by assignee and a `[lane-claim]`.

## The Problem

"No visual change" is claimed today with frames and a reviewer's eye. A frame cannot show a one-step change in a colour, and it shows one state. The rename's whole claim is that names change and paint does not; a package move's claim is that paint changes only where its pull request says so. Neither is checkable without an instrument that compares computed values.

## The Architectural Reality

- `npm run theme-census` (`buildScripts/util/theme-census.mjs`) counts names and layers statically; it does not render.
- Component specs run in the Playwright component harness and can switch `viewport.theme`. Headed runs are on hold by the operator; this has to run headless.
- The five themes ship as built sheets under `dist/<env>/css`.
- Julia's probes in the Discussion already read computed values per override scope in headless Chromium.

Design authority: "A computed-style equality run is built: per component, theme and state, every painted property resolves to the same value before and after a change." (ADR 0044, migration step 3; Discussion #22228, cycle 1, instrument 3.)

## The Fix

A headless run that renders a fixed set of engine components in each theme and in each state their variables name, records the computed values of the painted properties, and compares two builds.

- **Inputs:** two built trees, a base and a head.
- **Matrix:** the engine's components (one representative instance per variant a component variable names), the five themes, each in two scopes (`inherited`: the theme class on the stage; `scoped`: the theme class on each sampled instance's own root element), and the states `default`, `hover`, `active`, `focus`, `selected`, `pressed`, `disabled`, `invalid`, `readonly` where the component has them.
- **Painted properties:** background, text and border colours, outline, box shadow, fill and stroke, opacity, the font properties, radius, padding and size.
- **Output:** a table of differences by component, theme, state and property, and an exit code. An expected difference is declared in a list the pull request carries, so the reviewer reads the list instead of the table.

Where the script and its fixtures live is this leaf's to place (`structural-pre-flight`).

## Acceptance Criteria

- [ ] AC-1 On two builds of the same commit the run reports no difference.
- [ ] AC-2 With one component variable's value changed in one theme, the run reports exactly the components, states and properties that variable paints, and nothing else.
- [ ] AC-3 A difference declared as expected does not fail the run, and an expected difference that did not occur does.
- [ ] AC-4 It runs headless, on the pull-request baseline's machine class, in a time stated in the pull request.
- [ ] AC-5 Its matrix names every engine package under `resources/css/src` or says why one has no rendered instance.
- [ ] AC-6 Every theme runs in both scopes. The `scoped` pass is where a theme value and a rule's re-value of one custom property meet on one element, as they do on a viewport, a nested scope and a floating component; #22297 is gated on it. A control proves that a difference only the scoped pass can see is reported while the inherited pass stays unchanged.

## Out of Scope

- Layout and geometry beyond padding and size.
- Apps and examples: the engine's packages first.
- Wiring it into CI as a required check: the epic's later steps decide that once it has run on the `--cmp-*` removal and the rename.

## Avoided Traps

- **Pixel diffs.** They fail on anti-aliasing and pass on a one-step colour change.
- **A static resolver over the CSS only.** It cannot see what a selector matches, which already matters where a structural rule changes the variable it reads (the `--cmp-*` leaf).
