# ADR 0045 records gesture events, their teardown and replay

Owned by @neo-opus-grace, as the Decision Record of [D#22259](https://github.com/orgs/neomjs/discussions/22259) G2.

## Context

G2 (body 2026-11-27T21:16:00Z) assigns each part of a touch gesture an owner:
- **Policy:** the component declares it in structural CSS before contact. Hold-to-drag keeps the drag sensor's pre-contact listener.
- **Recognition:** Main, per window, only for subscribed nodes.
- **Motion:** an existing Main addon, when frame response needs it.
- **Commit:** App.

Replay follows R2: one contact trace, `engine` and `browser` providers, through Neural Link and the Playwright fixture. The body says `Decision Record: REQUIRED`. It also asks that the record "bind listener conventions, phase ordering, target/capture and same-window teardown before the public event API lands". The step-backs ([Grace](https://github.com/neomjs/neo/discussions/22259#discussioncomment-19961870), [Julia](https://github.com/neomjs/neo/discussions/22259#discussioncomment-19961921)) found gaps in today's listener path, and those gaps decide what the record must bind.

## The Problem

No public gesture event exists. Each touch consumer reads raw events its own way: Helix maps one finger to both axes, Circle reads only the wheel, and GridDragScroll runs its own monitor. Before recognition is built, five questions each need one answer:

1. **Names.** What App listens for: event names, phase order, payload fields and units.
2. **Subscription and release.** How Main learns that a node has a subscriber, and that it has lost one. Main's `addDomListener` binds a handler it does not keep and has no remove action. On unmount, App only resets its `mounted` flag. A recognizer holding contacts outlives both.
3. **Traffic.** The body forwards every raw `touchmove` today. A recognized move phase adds a second stream, and neither is coalesced per frame.
4. **Browser ownership.** Once the browser takes a contact sequence for scrolling, a second finger must not start a gesture (Euclid's late-join case).
5. **Replay attestation.** What each provider can prove, and what it reports when it cannot run.

## The Architectural Reality

- **Names:** `drag:start|move|end|cancel` is the precedent. The pointer sensor recognizes on Main, and DragDrop sends phased events that `domListeners` consume (`src/main/draggable/sensor/Pointer.mjs`, `src/main/addon/DragDrop.mjs`). Those names are in `globalDomEvents` (`src/manager/DomEvent.mjs:35`); gesture names must not be.
- **Per-node registration:** `DomEvent#addResizeObserver` gets its Main addon lazily (`getAddon`) and calls `register` per node (`src/manager/DomEvent.mjs:130-141`). The addon also exposes `unregister`. Nothing calls it on unmount today.
- **Replay surfaces:** `InteractionService#driveDrag` → `EventSimulator.driveDrag` is the precedent for a driven gesture (`src/ai/client/InteractionService.mjs:285`). EventSimulator materializes touch lists in the owning window (#22345). The public `simulate_event`, the fixture and CDP all reached the same 8/8 transitions ([receipt](https://github.com/neomjs/neo/discussions/22259#discussioncomment-19961766)). The public tool schemas live in Brain (`neo-agent-brain/ai/mcp/server/neural-link/openapi.yaml`).
- **Out of reach:** visual roles belong to ADR 0044, and this record touches none.

## The Fix

One PR adds `learn/agentos/decisions/0045-touch-gesture-events.md` in ADR 0044's format (siblings 0043 and 0044 in the same folder). It binds:

1. **Ownership.** Policy, recognition, motion and commit per G2's four consumers: Gallery, Helix, Circle and Grid.
2. **Names and phases.** Families exactly as inventory `g2-gesture-families` lists them: `tap`, `press`, `pan`, `swipe`, `pinch`, `rotate`.
   - `<family>:<phase>` for the phased families.
   - Bare names for the terminal recognitions `tap` and `swipe`.
   - No name in `globalDomEvents`.
   - Order: one `start`, any number of `move`s, exactly one `end` or `cancel`.
3. **Payload and units.** Contact ids scoped to the gesture and window; active and changed contacts; CSS px, ms and px/ms. Scale starts at 1 and rotation at 0 degrees, and motion rebases when the contact count changes.
4. **Subscription and release.** A lazily loaded Main gesture addon with `register` and `unregister` per node, in the ResizeObserver shape. App calls `unregister` on unmount and on listener removal.
5. **Target and capture.** A gesture belongs to the node where its first contact started.
6. **Teardown.** `cancel` without commit on release, `touchcancel`/`pointercancel`, a hidden document and window loss.
7. **Browser ownership.** A sequence the browser has taken starts no gesture until every contact lifts.
8. **Traffic.** One recognized stream per gesture, with moves coalesced to one per frame. Raw forwards stay unchanged and are counted separately: raw-only, semantic-only, both, neither.
9. **Replay.** Trace shape and presets. Providers exactly as inventory `g2-replay-providers` lists them: `engine`, `browser`. Each provider attests something different, and a provider that cannot run reports `unavailable`. The seam: Engine ships `driveGesture`, Brain ships the public `drive_gesture` tool.
10. **Activation.** Recognition never replaces the native click.
