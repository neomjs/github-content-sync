## Context

Flagged by @tobiu after PR #22266 (`cb3f854618`) merged `Neo.form.field.Text#afterSetDisabled`:

```javascript
cls = me.cls;
NeoArray.remove(cls, ['neo-focus', 'neo-hovered']);
me.cls = cls;
```

`Neo.component.Base#removeCls(value)` (`src/component/Base.mjs:1942-1947`) already delegates directly to `NeoArray.remove(cls, value)` and assigns `this.cls = cls`, and `Neo.util.Array.remove` (`src/util/Array.mjs:126-140`) accepts either a single item or an array of items (`!Array.isArray(items) && (items = [items])`). The same applies to `addCls(value)` (`:432-437`) and `addWrapperCls(value)` (`:459-464`), which delegate to `Neo.util.Array.add` (`src/util/Array.mjs:23-35`). However, their JSDoc `@param` annotations still declare `{String} value`, unlike sibling `removeAddCls(removeItems, addItems)` (`src/component/Base.mjs:1928-1936`), which already documents `{String|String[]}`.

## The Problem

1. **Stale JSDoc signatures on `Neo.component.Base`:** `removeCls`, `addCls`, and `addWrapperCls` document `@param {String} value` even though their underlying `NeoArray` primitives natively accept `String|String[]`. That narrow signature misleads both human developers and AI agents into hand-rolling `let cls = me.cls; NeoArray.remove(cls, [...]); me.cls = cls;` when removing or adding multiple root classes at once.
2. **Redundant `get-mutate-set` boilerplate on single-operation `component.cls` sites:** Several engine files perform a standalone `cls = me.cls; NeoArray.remove(cls, ...); me.cls = cls` on a component's own `cls` config where `me.removeCls(...)` expresses the exact same single reactive assignment in one line.

## The Architectural Reality

- `Neo.component.Base#beforeGetCls` (`src/component/Base.mjs:1177-1179`) returns a shallow clone (`value ? [...value] : []`), and `removeCls(value)` executes:
  ```javascript
  removeCls(value) {
      let cls = this.cls;

      NeoArray.remove(cls, value);
      this.cls = cls
  }
  ```
- Calling `me.removeCls(['neo-focus', 'neo-hovered'])` (including inside a `me.silentVdomUpdate = true` bracket such as `src/form/field/Text.mjs:436-456`) performs the exact same single `this.cls` assignment and triggers zero extra VDOM updates.
- Per the findings established in `#18736` and `#15201`, **only standalone removals (or standalone additions) on a `Neo.component.Base` instance's own `.cls` config** belong on `removeCls` / `addCls`. Swaps (`remove` + `add` together), child VDOM node `.cls` arrays, and multi-config `set({cls, ...})` / `setSilent({cls})` batches must NOT be converted to `removeCls`.

## The Fix

1. **Update JSDoc in `src/component/Base.mjs`:**
   - `addCls(value)` (`:428-437`): `@param {String|String[]} value`
   - `addWrapperCls(value)` (`:455-464`): `@param {String|String[]} value`
   - `removeCls(value)` (`:1938-1947`): `@param {String|String[]} value`
2. **Migrate standalone `component.cls` removal sites in `src/` to `removeCls(...)`** (verifying each site mutates the component instance's `.cls` config rather than a child VDOM node or a `setSilent` batch):
   - `src/form/field/Text.mjs:440-443` (`afterSetDisabled`): replace `cls = me.cls; NeoArray.remove(cls, ['neo-focus', 'neo-hovered']); me.cls = cls;` with `me.removeCls(['neo-focus', 'neo-hovered']);` and drop the unused `cls` declaration.
   - `src/form/field/Text.mjs:1550-1552` (`onFocusLeave`) and `:1636-1638` (`onMouseLeave`): replace standalone `cls = me.cls; NeoArray.remove(cls, ...); me.cls = cls` with `me.removeCls('neo-focus')` / `me.removeCls('neo-hovered')` (verify whether `cls` is used elsewhere in each method first).
   - `src/form/field/FileUpload.mjs:439-441` and `:695-697`: replace standalone `NeoArray.remove(cls, 'neo-field-empty'); me.cls = cls` when `cls` is not mutated further in the same branch.
   - `src/dashboard/dock/interaction/DockSplitter.mjs:206-208`: `me.removeCls(\`neo-dashboard-dock-splitter-${oldValue}\`)`.
   - `src/draggable/DragZone.mjs:490-492`: `owner.removeCls('neo-is-dragging')`.
   - `src/draggable/tab/header/toolbar/SortZone.mjs:121-123`: `owner.removeCls('neo-no-animation')` (confirm `owner` is always a `Neo.component.Base` instance).
3. **Add focused unit test coverage** verifying `component.addCls(['a', 'b'])`, `component.addWrapperCls(['w1', 'w2'])`, and `component.removeCls(['a', 'b'])` mutate `cls` / `wrapperCls` in a single config assignment.

## Out of Scope

- Sequential `remove` + `add` class swaps (governed by `removeAddCls` from `#18736`).
- Child VDOM node `.cls` mutations (`iconNode.cls`, `node.cls`, `vdom.cls`).
- Multi-config `set({cls, ...})` / `setSilent({cls})` batches or VDOM update-pipeline files (`src/vdom/**`, `src/mixin/VdomLifecycle.mjs`, `src/main/DeltaUpdates.mjs`).

## Avoided Traps

- **The child-node look-alike trap (`#18736`):** Expressions like `NeoArray.remove(iconNode.cls, oldValue)` or `NeoArray.remove(vdom.cls, ...)` mutate an inner VDOM element, NOT `component.cls`. Calling `this.removeCls(...)` there would mutate `vdomRoot` instead of the child node.
- **The two-round-trip swap trap (`#15201`, `#18736`):** Never replace `NeoArray.remove(cls, oldCls); NeoArray.add(cls, newCls); me.cls = cls` with `me.removeCls(oldCls); me.addCls(newCls)` — two separate assignments fire two VDOM updates instead of one (`removeAddCls` owns swaps).
