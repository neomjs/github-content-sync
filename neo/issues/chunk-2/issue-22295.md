# A new design system for Neo that every theme is written against

Terminal predicate: on `dev`, all five engine themes are written against ADR 0044: `theme-base` declares every component variable once and binds it to roles, each theme's `Global.css` defines the same palette and role names with light and dark in one file, `npm run theme-census` reports no `--sem-*`, `--cmp-*` or hue-named name and no role without a reader, and fresh readers of two model families find the short reference unaided and change the paint of a widget they have not seen.

Graduated from [Discussion #22228](https://github.com/orgs/neomjs/discussions/22228) at body revision R3, 27 Nov 2026.

Decision Record: REQUIRED. ADR 0044, `learn/agentos/decisions/0044-design-system.md`, delivered by this epic's record leaf. Merge gate: no other pull request of this epic merges before the record's.

## Why an epic

The work is seven engine seams, one scripted rename over every theme file, 42 moves that go one at a time (26 engine packages and 16 app and example groups), and three more themes. The order between them is strict, each step has a gate of its own, and several peers build in parallel. The groundwork that needs no decision is its first part: #22280.

## Problem scope

Measured with `npm run theme-census` on `dev` at `a22c1a96e9` and by the censuses in the Discussion:

1. **Five themes, three structures.** The Neo pair carries 90 `--sem-*` and 71 `--cmp-*` names from a 2023 Figma export; the classic pair and Cyberpunk have neither, apart from one reset each (`--sem-color-fg-neutral-contrast: initial`). 42 of the 90 and 34 of the 71 are read by nothing.
2. **A light and dark pair costs 481 decisions where 33 would do.** 843 component variables carry the same name in all four full themes. Between Neo Dark and Neo Light, 33 of 90 semantic values differ and 481 of 894 component values.
3. **One thing has several words.** A background is `background-color` in 158 names, `background` in 40 and `bg` in 24; the state word is last in 184 names and elsewhere in 44.
4. **Products bypass the token layers.** Workstation and Fleet override 171 and 150 component variables and no `--sem-*` or `--cmp-*` name.
5. **Colour ramps are named by hue,** so an override cannot be written once for different base themes.

For a model this is the worst case: it predicts a name, and a plausible name that changes nothing reports nothing. A blind trial hit 4 of 21 names cold with today's names and with the new ones, and 20 and 21 of 21 after one short reference. The names stand on structure, and the reference is a deliverable.

## Intended solution

**The decision.** Three kinds of names told apart by shape and bound in one direction: a rule reads a component variable, a component variable reads a role, a role reads the palette. Every engine custom property carries the prefix `--neo-`: a custom property is global to the cascade, so the prefix is the library's only isolation in a page it shares with other code. The second segment tells the kind: `palette`, a role category, or a component. This reverses the record's first naming of a component variable, on the operator's objection of 27 Nov ([the direction](https://github.com/neomjs/neo/issues/22295#issuecomment-7222605243)); the rename's pull request amends decision 1, I4 and step 4. Every theme defines the same palette and role names. Component variables are declared once, in `theme-base`. Light and dark are one theme through `--neo-color-scheme`, `color-scheme` and `light-dark()`. A sheet's cascade layer follows from its folder, and the theme build writes it. A theme covers every widget; a product look is a palette of a theme. Names change in one cut, with a rename map and no alias layer.

**Seven engine seams.** Lines re-read on `dev` at `a22c1a96e9`.

1. **Layers.** One PostCSS plugin, called by `buildScripts/build/themes.mjs` and by `buildScripts/helpers/watchThemes.mjs` (which runs its own pass at line 320), wraps each sheet's syntax tree in the layer its folder determines and starts every built sheet with the order statement. No source file writes `@layer`. A sheet with a relative `@import` keeps it at the top level with `layer(…)` or has it flattened, so imported rules enter the layer once. An app's and an example's sheets sit in `neo.apps`, after `neo.rules`; a sheet the engine loads from outside the theme build enters `neo.vendor` through `DomAccess.loadStylesheet`; rules inserted at runtime stay unlayered (decision 6, amended by #22297). `!important` inverts across layers.
2. **One map says what a theme is.** The theme build writes, for each theme class, the folders whose `Global.css` declares it into `resources/theme-map.json`: a list, so theme Neo's old and new folders can both serve its two classes while its packages move. The loader (`Stylesheet.mjs:123`) admits `theme-base` like `src` and reads the map; `App.mjs:1307` stops stripping a prefix. A theme is a folder whose `Global.css` declares a theme class.
3. **`Stylesheet#setCssVariable`** resolves its sheet through the map, walks into layer blocks and skips a sheet without `href` (lines 294 and 296; a `<style>` sheet throws there today).
4. **Guards and census.** `check-theme-coverage` becomes `src/<pkg>` against `theme-base/<pkg>`. `check-theme-var-references` resolves `src` reads against `theme-base` and role reads against each theme's `Global.css`. `check-theme-surfaces` loses its parity half with the second Neo folder. `theme-census`, the guards, `create-theme` and the build's theme list read the map instead of globbing `theme-*`. The census gains a row: roles without a reader.
5. **Scope class, reserved class prefix, scheme.** `neo-theme-` is reserved for scopes, so the base selector is the one attribute selector `[class*="neo-theme-"]`. `ThemeSwitcher`'s classes match it today and are renamed. `component.Base` adds `neo-theme-scope` when a style key names a role: it reads the kind, not the prefix, which a component variable carries too. Structure sets `color-scheme: var(--neo-color-scheme)` once on the base selector, and the three declarations that read the variable today go.
6. **Names read outside CSS.** JavaScript reads component variables by name, as static strings and as template literals (`DockFlip.mjs:700`, `DomAccess.mjs:1854`), and so do tests and guides.
7. **The property prefix `--neo-` is the library's.** Every engine custom property carries it. On `dev` at `5ebb8fef15`, 1,210 names are declared in an engine folder and 112 carry the prefix; the rename gives it to the rest, in CSS, in JavaScript strings, in tests and in guides. 915 names are declared only by apps and examples and are theirs to prefix at their own move. Four groups have their place ([the read](https://github.com/neomjs/neo/issues/22295#issuecomment-7222855183)): the old skeleton (`--sem-*`, `--core-*`, the hue ramps, `spacing`, `height`, `borderradius`, `cyber`) gains the prefix and is a fourth kind, a closed list the guard allows until those names go; the seven motion names of `src/Global.css` take the names of the duration and ease roles; a name that is role-shaped today without being a role (`--neo-color`, `--neo-font-family`, `--neo-duration`) takes its component's word; another library's property (`--fa-width`) keeps its name on a closed list. One module owns the name shapes, and the guards import it.

**Rules every package move follows.** Decided by the design seat, so no move decides them again.

1. **Binding by ending.** `…-background-color` binds to a background role, `…-color` to a text role, `…-border-color` to a border role (decision 3). Six engine names end with `-color` and are read by two or more properties: the board's accent, card accent, column accent and WIP colours, the timeline editor's accent and the gantt highlight. They are bound by hand or split by reader.
2. **A theme's value never reads a variable that the rules re-value.** A multi-variant package resolves such classic and Cyberpunk values in its own move; the equality run's scoped pass is the gate.
3. **Shape.** Dialogs and windows read `radius-extra-large`, cards and panels `radius-large`, menus, tooltips and fields `radius-small`.
4. **A control's only boundary owes 3:1.** A field's edge reads `border-strong`. An outlined button's border reads it too, gated by a dense second frame pair in the pilot.
5. **Literals.** Optical offsets and coupled geometry stay literals in `theme-base`, listed. No raw colour stays there (I1): where no role fits, a role enters with the move that reads it. The `form` move brings `background-track`, `background-track-hover` and `background-handle`.
6. **A disabled state** is painted by the disabled roles or by `opacity-disabled`, never both.
7. **Type** is one variable per property; a `font` shorthand is split (decision 3).
8. **A role paints what its family owes.** Text never reads a border variable.
9. **A ripple is a press layer;** a variable without a reader is dropped.
10. **A palette's lightness numbers are its own,** and every palette declares the same names.
11. **An input keeps its noun.** A number or a coordinate that a rule computes with, set by JavaScript or by a parent, is not named after a CSS property.
12. **An app's and an example's own variables** take the grammar when their group moves, with the rename's script and a second map.
13. **A binding table is the body of its row's leaf.** The holder files the leaf when the table is ready, one row in flight per seat, and the design read is a comment there.
14. **A role and a palette name are declared in a `Global.css`;** a component sheet declares component variables only. The palette guard of #22350 refuses a palette or colour-role name outside a theme class. Neither guard refuses a new role-shaped name in a component sheet yet (three arms on #22358 at `d77d6cc908`): a leaf once #22350 is on `dev`.

**Open, each with its trigger.** Whether a field's hover needs a step: the `form` frame pair. The mono family, which names a face nothing loads: the first mono reader's move decides between shipping the face and a system stack. The light scrim: the `dialog` move. The field height in the `control` family: the first density scope. The ripple's layer: the pilot's pair. Which sheet owns the values of the seven motion roles: measured on the merge tree of #22350 at `695c046e1d` and #22349 at `d77d6cc908`, each sheet through the build's layer plugin. Under `prefers-reduced-motion: reduce` a themed element computes `--neo-duration-fast: 0ms` in both arrival orders, because `src/Global.css` sits in `neo.rules` above `neo.roles`; without layers the theme's rule would win and the collapse would be lost. Decision 3 holds, and neither pull request waits for the other on it. The same order makes a theme's own value for a motion role inert while `src/Global.css` declares the seven: a theme that says `90ms` computes `120ms`. Theme Neo's values are equal today. The end state is `src/Global.css` with the collapse alone and each theme's `Global.css` with the seven values; the trigger is the first theme whose motion differs, the Material pair (#22359).

## Avoided traps
