# A new design system for Neo that every theme is written against

Terminal predicate: on `dev`, all five engine themes are written against ADR 0044: `theme-base` declares every component variable once and binds it to roles, each theme's `Global.css` defines the same palette and role names with light and dark in one file, `npm run theme-census` reports no `--sem-*`, `--cmp-*` or hue-named name and no role without a reader, and fresh readers of two model families find the short reference unaided and change the paint of a widget they have not seen.

Graduated from [Discussion #22228](https://github.com/orgs/neomjs/discussions/22228) at body revision R3, 27 Nov 2026.

Decision Record: REQUIRED. ADR 0044, `learn/agentos/decisions/0044-design-system.md`, delivered by this epic's record leaf. Merge gate: no other pull request of this epic merges before the record's.

## Why an epic

The work is seven engine seams, one scripted rename over every theme file, about thirty packages that move one at a time, and three more themes. The order between them is strict, each step has a gate of its own, and several peers build in parallel. The groundwork that needs no decision is its first part: #22280.

## Problem scope

Measured with `npm run theme-census` on `dev` at `a22c1a96e9` and by the censuses in the Discussion:

1. **Five themes, three structures.** The Neo pair carries 90 `--sem-*` and 71 `--cmp-*` names from a 2023 Figma export; the classic pair and Cyberpunk have neither. 42 of the 90 and 34 of the 71 are read by nothing.
2. **A light and dark pair costs 481 decisions where 33 would do.** 843 component variables carry the same name in all four full themes. Between Neo Dark and Neo Light, 33 of 90 semantic values differ and 481 of 894 component values.
3. **One thing has several words.** A background is `background-color` in 158 names, `background` in 40 and `bg` in 24; the state word is last in 184 names and elsewhere in 44.
4. **Products bypass the token layers.** Workstation and Fleet override 171 and 150 component variables and no `--sem-*` or `--cmp-*` name.
5. **Colour ramps are named by hue,** so an override cannot be written once for different base themes.

For a model this is the worst case: it predicts a name, and a plausible name that changes nothing reports nothing. A blind trial hit 4 of 21 names cold with today's names and with the new ones, and 20 and 21 of 21 after one short reference. The names stand on structure, and the reference is a deliverable.

## Intended solution

**The decision.** Three kinds of names told apart by shape and bound in one direction: a rule reads a component variable, a component variable reads a role, a role reads the palette. Every theme defines the same palette and role names. Component variables are declared once, in `theme-base`. Light and dark are one theme through `--neo-color-scheme`, `color-scheme` and `light-dark()`. A sheet's cascade layer follows from its folder, and the theme build writes it. A theme covers every widget; a product look is a palette of a theme. Names change in one cut, with a rename map and no alias layer.

**Seven engine seams.** Lines re-read on `dev` at `a22c1a96e9`.

1. **Layers.** One PostCSS plugin, called by `buildScripts/build/themes.mjs` and by `buildScripts/helpers/watchThemes.mjs` (which runs its own pass at line 320), wraps each sheet's syntax tree in the layer its folder determines and starts every built sheet with the order statement. No source file writes `@layer`. A sheet with a relative `@import` keeps it at the top level with `layer(…)` or has it flattened, so imported rules enter the layer once. An app's and an example's rules get a sibling layer after `neo.rules`, never a sub-layer; the two Highlight.js theme files under `resources/lib` carry their own layer; rules inserted at runtime stay unlayered. `!important` inverts across layers.
2. **One map says what a theme is.** The theme build writes, for each theme class, the folders whose `Global.css` declares it into `resources/theme-map.json`: a list, so theme Neo's old and new folders can both serve its two classes while its packages move. The loader (`Stylesheet.mjs:123`) admits `theme-base` like `src` and reads the map; `App.mjs:1307` stops stripping a prefix. A theme is a folder whose `Global.css` declares a theme class.
3. **`Stylesheet#setCssVariable`** resolves its sheet through the map, walks into layer blocks and skips a sheet without `href` (lines 294 and 296; a `<style>` sheet throws there today).
4. **Guards and census.** `check-theme-coverage` becomes `src/<pkg>` against `theme-base/<pkg>`. `check-theme-var-references` resolves `src` reads against `theme-base` and role reads against each theme's `Global.css`. `check-theme-surfaces` loses its parity half with the second Neo folder. `theme-census`, the guards, `create-theme` and the build's theme list read the map instead of globbing `theme-*`. The census gains a row: roles without a reader.
5. **Scope class, reserved class prefix, scheme.** `neo-theme-` is reserved for scopes, so the base selector is the one attribute selector `[class*="neo-theme-"]`. `ThemeSwitcher`'s classes match it today and are renamed. `component.Base` adds `neo-theme-scope` when a style key starts with `--neo-`. Structure sets `color-scheme: var(--neo-color-scheme)` once on the base selector, and the three declarations that read the variable today go.
6. **Names read outside CSS.** JavaScript reads component variables by name, as static strings and as template literals (`DockFlip.mjs:700`, `DomAccess.mjs:1854`), and so do tests and guides.
7. **The property prefix `--neo-` is the theme's.** 129 names carry it today without being palette names or roles (board 47, timeline 36, content 14, scheduler 8, gantt 7, singles), 21 of them named in JavaScript and several set inline once per row. They get component names in the rename map.

## Out of scope

- **Product palettes for Workstation and Fleet.** Their own track, after theme Neo has moved. Recorded constraint: a floating component stamps its own theme class and not an app's viewport class.
- **A Material pair and mobile components.** The 14.1 capstone, on green foundations only (`ROADMAP.md`).
- **A categorical colour scale.** Until a component needs a category that reuse cannot give.
- **Touch gestures and their events.** [Discussion #22259](https://github.com/orgs/neomjs/discussions/22259); components there read the elevation, shape and motion roles.

## Avoided traps

- **An alias layer for old names.** Nobody outside the organization builds on the theme variables yet.
- **A generated token source,** DTCG included. CSS is the source; the one export Neo had was consumed by nothing.
- **Source files that write their own `@layer`.** The same decision in 600 files, and an order that depends on which sheet loads first.
- **`[style*="--neo-"]` as a scope selector.** It clobbers an ancestor's component variable and costs 3.5 to 6.1 times the style recalculation.
- **Binding the base on each component's root.** It breaks an ancestor's override of a component variable.
- **A product look called a theme.** A theme covers every widget in per-widget files and is never one file.
