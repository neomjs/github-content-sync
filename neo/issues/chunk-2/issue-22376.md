# The documented create-theme command fails in a fresh workspace

## Context

The [Styling and Theming guide](https://github.com/neomjs/neo/blob/8d0276127c30650f0844f4d32b93eec602863262/learn/guides/uibuildingblocks/StylingAndTheming.md#7-creating-a-new-theme) and [build-script reference](https://github.com/neomjs/neo/blob/8d0276127c30650f0844f4d32b93eec602863262/buildScripts/README.md#npm-run-create-theme) give a development workspace a direct command for creating an editable theme.

## The Problem

Generate a fresh workspace with `npx neo-app@14.0.0 -w ws -n ThemeProbe -t neo-theme-neo-light -u no -s false --no-agent`. From that workspace, run `node node_modules/neo.mjs/buildScripts/create/theme.mjs --name theme-custom --base theme-neo-dark --noquestions`. The command exits with `ERR_MODULE_NOT_FOUND` for `postcss-selector-parser` before generating the theme. Verified both the published `neo.mjs@14.0.0` and a locally packed `dev@8d0276127c` installed in the workspace.

## The Architectural Reality

The [generator](https://github.com/neomjs/neo/blob/8d0276127c30650f0844f4d32b93eec602863262/buildScripts/create/theme.mjs#L3) imports `postcss-selector-parser` to preserve selector behavior. The Engine declares it as a development dependency under #5105. The starter installs the tools its initial development flow needs, as recorded in #21213. A workspace that adds the parser as a development dependency can run the installed generator and the normal theme build.

## The Fix

Update the two installed-workspace recipes to show the parser install step before generating a theme. Explain that its need first arises when the developer chooses to generate an editable theme. Keep the step in the existing theme-creation section and the existing build-script command reference.

## Acceptance Criteria

- [ ] From a fresh generated workspace on the packed Engine, the installed-workspace recipe produces an editable theme and names the custom class it generated.
- [ ] The following theme build emits CSS for that class and its entry in `resources/theme-map.json`.
- [ ] The guide and build-script reference carry the same prerequisite. The Engine-checkout recipe still uses its installed development dependencies.
