# Merge comment runs when Brain or the Institution calls it

## Context

The operator said to Grace in chat on 2026-11-27: "well, on the long run engine, brain, FM repos should have the same policies and features. especially since our badges program should honor the 3." It is recorded here because #20892 has reached its 25-comment cap.

The epic owner cut that direction into leaves ([comment 7223179188](https://github.com/neomjs/neo/issues/22363#issuecomment-7223179188)) from [two reads](https://github.com/neomjs/neo/issues/22363#issuecomment-7223046899). Standing already counts all three repositories, so it gets no leaf. **This ticket is leaf A, the Engine's one pull request.** Leaves B (Brain) and C (Institution) are thin callers, each filed in its own repository once A's pull request is open.

## The Problem

`merge-comment.yml` posts the merge comment (standing, next issues, badge) on outside pull requests, and only in neo. A sibling cannot call it for two reasons:
- It has no `workflow_call` trigger (`:17-28`).
- Its sparse `actions/checkout` (`:51-60`) names no `repository:`, so a called run would check out the caller's tree, where neither module exists. The import at `:74` would then throw, and `:178` turns that into a warning: the run ends green and posts no comment.

## The Architectural Reality

Design authority: the operator's direction above, as cut by the epic owner.

The precedent is `claim-responder.yml`, which Brain and the Institution already call (`neo-agent-institution/.github/workflows/claim-responder.yml:30`). It accepts `workflow_call` with zero inputs and has no checkout. It checks that `job.workflow_sha` is a full commit SHA and fetches its pure modules from `neomjs/neo` at that SHA through the contents API (`claim-responder.yml:63-82`).

In a called run, `context.repo` names the caller, as the claim responder's posts on neomjs/neo-agent-institution#1023 show. So the comment, the pull-request reads and the team check land on the caller's pull request, and the next issues come from the caller's queue. The org-wide count (`:108`) and the `pages` reads (`:121`, `:132`) name their repository explicitly, so they don't change.

## The Fix

In `.github/workflows/merge-comment.yml`:
- `on:` gains `workflow_call:` with no inputs.
- The checkout step becomes a fetch step. It checks that `job.workflow_sha` is a full 40-character SHA, then fetches `claimResponse.mjs` and `contributorStanding.mjs` (which imports the former) from `neomjs/neo` at that SHA through the contents API. Unlike the claim responder, a failed fetch warns and ends green, as the checkout did: the job's checks anchor on the merged head, where a red one would stay.
- The header states the callable contract. Callers own the trigger and the token's permissions (`contents: read`, `issues: read`, `pull-requests: write`; a called workflow cannot widen them), and they omit `concurrency:`.

In `test/playwright/unit/buildScripts/util/contributorStanding.spec.mjs`, the arms that pin the checkout pin the fetch instead, and one new arm runs the script as a sibling's call.

## Acceptance Criteria

- [ ] `merge-comment.yml` accepts `workflow_call` and has no `actions/checkout`. It fetches exactly the two modules from `neomjs/neo` at `job.workflow_sha` through the contents API, and no `run:` step interpolates event data.
- [ ] A failed fetch, or a `job.workflow_sha` that is not a full SHA, warns and ends green without a comment.
- [ ] Run with a sibling's `context.repo`, the script comments on that repository's pull request and takes its next issues from that repository, while keeping the org-wide count and the `pages` reads.
- [ ] `npm run test-unit -- test/playwright/unit/buildScripts/util/contributorStanding.spec.mjs` passes.
- [ ] Post-merge: a `workflow_dispatch` dry run on `dev` renders the comment for a merged outside pull request, which proves the fetch at the default branch's SHA.

## Out of Scope

- The callers in Brain and the Institution (leaves B and C), and each caller's path in its repository's Actions policy. That path is the operator's step before each caller merges, since enforcement begins 2 December.
- Standing, which already counts across repositories.
- `review-admission-mergeability.yml`, which is not ported. The read that rides with this leaf, and its reason, are on this ticket.
