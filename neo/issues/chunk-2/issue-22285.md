# 46 variables that structural rules read are undefined in the classic themes

Live latest-open + closed sweep: the parent epic's sweep of 2026-11-26 23:06Z covers this leaf (unresolved variable, structural rule); no equivalent found. Not offered as a contributor issue: it is wanted for the weekend cut.

## Context

The operator's rule: a theme covers every widget. A `var(--x)` without a fallback whose `--x` no file defines is invalid at computed-value time: the property takes its inherited or initial value and nothing reports it. `check-theme-var-references` catches such reads inside theme files, not in structural rules.

## The Problem

On `dev` at `11f48ebb15`, structural rules read 46 variables that neither `theme-dark`, `theme-light` nor any file under `resources/css/src` defines:

| Read in | Variables |
|---|---|
| `component/Markdown.css` (17) | `--markdown-bg`, `-blockquote-bg`, `-blockquote-border`, `-code-bg`, `-code-border`, `-details-icon-color`, `-details-summary-color`, `-h1-color`, `-hr-border`, `-lab-shadow`, `-lab-shadow-hover`, `-link-color`, `-list-marker-color`, `-pre-border`, `-table-border`, `-table-header-bg`, `-text-color` |
| `app/content/*.css` (10) | `--neo-app-content-sections-bg`, `-sections-btn-bg`, `-sections-btn-disabled-bg`, `-sections-glyph-color`, `-sections-shadow`, `-sidenav-bg`, `-sidenav-btn-bg`, `-sidenav-shadow`, `-toolbar-btn-bg`, `-toolbar-text-color` |
| `grid/column/component/IconLink.css` (4) | `--icon-link-color`, `--icon-link-font-size`, `--icon-link-hover-color`, `--icon-link-text-decoration` |
| `grid/column/Icon.css`, `grid/column/IconLink.css` (3) | `--grid-column-icon-font-size`, `--grid-column-icon-link-font-size`, `--grid-column-icon-link-label-font-size` |
| `component/Icon.css` (2) | `--icon-color`, `--icon-font-size` |

| `app/content/PageContainer.css`, `app/content/SectionsList.css` (3) | `--cmp-button-spacinghorizontal`, `--sem-color-text-neutral-subdued`, `--list-border-color` |

| `component/wrapper/MonacoEditor.css`, `component/Timer.css` (2) | `--monaco-editor-background-color`, `--timer-button-color` |

So Markdown, the content views, icon columns, the live preview and the timer render in Dark and Light with inherited or initial values.

## The Architectural Reality

- A theme file declares variables only; the value for a component lives in `resources/css/theme-*/<same path as the rule>`, created where the classic pair has no file yet.
- Three reads are `--cmp-*` and one is `--sem-*`: tokens only the Neo pair defines, read directly by a structural rule. That layer is leaving, so these four rules read a component variable instead, and all four full themes define it.
- `--list-border-color`, `--list-item-border-color-active` and `--menu-list-item-color-disabled` are also undefined in the Neo pair; their sibling leaf decides whether the read is stale. Take its answer rather than defining them twice.

## The Fix

The classic pair defines each variable in the classic design language (its greys, its Helvetica stack), in the variable file of the component. Where a widget has never been styled for the classic pair, that is a small design job: propose the values and show them.

## Acceptance Criteria

- [ ] Look: the pull request shows each affected widget in Dark and Light before and after; the design seat reads the pairs.
