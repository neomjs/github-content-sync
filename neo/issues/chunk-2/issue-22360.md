# theme-equality counts built sheets whose sources are gone

## Context

On a long-lived checkout, `npm run theme-equality -- --base <clean dev worktree> --head <checkout>` reported 956 undeclared differences, while two clean trees compare at 0 of 192,000 (Clio's defect-note, 2026-11-27 12:40Z). The head's `dist/development/css` still held built sheets whose sources were deleted, for example `theme-neo-light/design-tokens`, `dashboard/dock/interaction` and `component/IconLink.css`.

## The Problem

`collectThemeStylesheetUrls` (`buildScripts/util/theme-equality.mjs`) picks each folder from `theme-map.json` (`themeMap.themes[themeClass]`). It then lists the folder with `listEngineCssFiles`, a `readdirSync` walk that mounts every `.css` file on disk. So a sheet the build left behind changes the computed styles the runner compares, although no application ever loads it.

## The Architectural Reality

Design authority: the runner compares "the computed styles a page renders", and the runtime defines which sheets a page gets. `Neo.main.addon.Stylesheet.addThemeFiles` loads, per class, `src`, `theme-base` and each mapped theme folder, but only those folders the class's entry in `resources/theme-map.json` lists. `themes.mjs` derives that map from sources (`resolveThemeClassMap`), so a stale built file is never requested.

The map's `Neo` section is that class tree, and its leaves list folders, for example `Neo.button.Base: ['src', 'theme-neo-light', …]`. App namespaces live in a separate top-level `apps` key.

Julia (owner of the runner, #22308) agreed with this shape and handed the fix back.

## The Fix

In `collectThemeStylesheetUrls`, when `tree.themeMap.Neo` is present, list each folder's sheets from the map: every leaf that names the folder becomes `<namespace path>.css`, with `Neo.examples` skipped (as the walk skips `examples/`), `Global.css` first and the rest sorted. A mapped sheet missing on disk fails closed, because the build is incomplete. Without a `Neo` tree (the synthetic fixtures), keep the directory walk.

`themes.mjs` stays as it is: pruning there can over-delete (#21253).

## Acceptance Criteria

- [ ] With a map that has the `Neo` class tree, a built sheet absent from the map is not mounted, and the URLs keep the runtime's folder order (`src`, `theme-base`, theme folders).
- [ ] A sheet the map lists but the build lacks fails the run with a message naming it.
- [ ] A map without the `Neo` class tree keeps today's walk, so the existing unit and component specs pass unchanged.

## Out of Scope

- Pruning stale files in `themes.mjs` or `watch-themes`.
- The runner's component matrix.
