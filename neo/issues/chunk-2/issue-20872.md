# Delta listeners change the batch after its length is captured

## Context

While comparing the existing Main hook path for #20871, an isolated execution of the actual `DeltaUpdates.update` method reproduced a batch-consumption defect on `dev` `e0fa9f0a2857c27b6eafca247b9ea35a6c819e31`. It is independent of the drag terminal's eventual transport.

## The Problem

With both diagnostic flags at their default `false`, an `update` listener can edit the delta array but dispatch still uses its earlier length:

| Input before listener | Listener edit | Expected dispatch | Observed |
| --- | --- | --- | --- |
| `[ordinary]` | none | `[ordinary]` | `[ordinary]` |
| `[]` | prepend `prefix` | `[prefix]` | `[]` |
| `[ordinary]` | prepend `prefix` | `[prefix, ordinary]` | `[prefix]` |

The ordinary control passes. This is a method-level witness, not a claim of a new browser incident.

## The Architectural Reality

`src/main/DeltaUpdates.mjs#update` normalizes the input and captures `len`, then fires `update`. It refreshes the length only inside the optional grammar/coherence instrument branches. The dispatch loop and counters consume that length.

Design authority: the existing method's documented mutation window says listeners may mutate the delta array and those modifications are consumed by the update loop. Closed #12994 likewise places validation after listener mutation, on the final batch.

Prescription checked: `DeltaUpdates.update` owns traversal of that final batch. Fixing App/VDom producers or enabling diagnostic flags would leave the generic default path wrong.

## The Fix

Capture the length once after the synchronous `update` event. Use it for both optional instruments, counters and dispatch; remove the duplicated instrument-specific length refreshes. Preserve existing normalization, ordering and cleanup.

Extend `test/playwright/unit/vdom/DeltaUpdatesGrammarGuard.spec.mjs`, whose real Main singleton and instrument controls already own this boundary. No new module or directory.

## Contract Ledger

| Surface | Authority | Required behavior | Boundary | Evidence |
| --- | --- | --- | --- | --- |
| `DeltaUpdates.update` array mutation window | Existing method contract; #12994 | Consume the array after listeners finish, including inserted and removed entries | No new event, config or array-replacement contract; ordinary and single-object input remain supported | Default-off red controls plus instrument-enabled and existing normalization tests |

Decision Record impact: none; repair the existing consumption contract.

## Acceptance Criteria

- [ ] With diagnostics disabled, a listener can prepend/append to an empty or nonempty array and every final entry dispatches once in order; regression tests fail before the fix.
- [ ] A listener can remove every entry without dispatching an undefined delta.
- [ ] The same mutation cases pass with grammar validation enabled; existing grammar/coherence and ordinary-input tests remain green.
- [ ] Update the method's JSDoc to name the post-listener batch boundary; add no new API or configuration.

## Out of Scope

#20871's channel choice and drag lifecycle; metadata transport (#20864/#20780); native repeated-move scroll preservation; diagnostic predicate changes; replacing `data.deltas` with a different array.

## Avoided Traps

Enabling diagnostics to hide a default-path defect; adding another per-instrument length update; applying a new Helper metadata contract as a workaround.
