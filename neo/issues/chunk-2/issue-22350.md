# Theme Neo's Global.css: palette and roles, light and dark in one file

## Context

Step 5 of ADR 0044's migration (`learn/agentos/decisions/0044-design-system.md` §4). The roles exist in the Discussion's cycle 3 and in the epic's binding list, and in no file of the repository. Until one declares them, no package can bind to a role (step 6, [42 moves](https://github.com/neomjs/neo/issues/22295#issuecomment-7217835670)) and no second theme can be written against them.

Self-assigned: the values and their checks are the design seat's working files, so nobody else can start this leaf. It carries no contributor labels for that reason.

## The Problem

- 85 palette names and 109 roles have no file. Theme Neo's two `Global.css` files still declare 90 `--sem-*` and 71 `--cmp-*` names each (`dev` at `9380db92d8`).
- I8 has no guard: a palette's text, border and focus-ring pairs must meet their floors in each scheme, and the check that measured theme Neo's 35 pairs lives outside the repository.
- The scrim's value is open (ADR 0044 §5, "Open, with an owner").

## The Architectural Reality

- A theme is a folder whose `Global.css` declares a theme class, and one class may be served by several folders: `buildScripts/util/themeCss.mjs` (`extractThemeClasses`, `collectThemeClassMap`) builds that list, and `resources/theme-map.json` carries what the loader reads. That is the seam `#22298` built for this step, so theme Neo's old and new folders can both serve its two classes while packages move.
- `--neo-color-scheme` and `--neo-font-smoothing` are declared today in each theme's `Global.css` and read in `resources/css/src/Global.css` (lines 73 and 177). They are the only two of the 194 names the tree already declares, with the same meaning.
- Nothing reads another role yet, so this leaf changes no paint.
- Not verified before filing, settled at intake: whether `check-theme-coverage` and `check-theme-surfaces` accept a theme folder that holds only `Global.css`.

Design authority: "Theme Neo gets its `Global.css` in `theme-neo`. The old tokens stay beside it while packages move." (ADR 0044 §4, step 5.) And §3, rejected: "Generate the CSS from a token source […] CSS is the source". So the file is the source, and the script that drafted it does not ship.

## The Fix

1. `resources/css/theme-neo/Global.css` declares the palette and the roles for `.neo-theme-neo-light` and `.neo-theme-neo-dark`: the scheme per class, every colour role through `light-dark()`, no raw colour outside the palette.
2. A palette check as a guard (I8), run by an npm script and with the other theme guards: it resolves each listed pair in both schemes against 4.5:1 for text on its region and 3:1 for borders and the focus ring, and it asserts that a grade has one OKLCH lightness in every slot of a palette and that a slot's grades descend. It holds no table: the numbers are each theme's own (ADR 0044 decision 2, amended here as ruled in [the epic's comment](https://github.com/neomjs/neo/issues/22295#issuecomment-7218629885)). The pair list ships with it.
3. The scrim's value, set on a frame pair.

## Acceptance Criteria

- [ ] AC-1 `resources/css/theme-neo/Global.css` declares exactly the names of the binding lists below (85 palette names, 109 roles with `--neo-color-scheme`) for both theme classes, and variables only (`check-theme-value-files`).
- [ ] AC-2 Within a palette a grade has one lightness in every slot, and a slot's grades descend in lightness; the check asserts both and holds no table.
- [ ] AC-3 The I8 check passes for theme Neo in both schemes and fails on a planted weak pair.
- [ ] AC-4 A theme Neo app loads the sheet under both classes: a component spec reads one role's computed value in light, in dark, and inside a nested dark island.
- [ ] AC-5 Paint is unchanged: `npm run theme-equality` reports no difference between base and head.
- [ ] AC-6 The scrim's value is shown by a frame pair of a modal dialog over a filled page in both schemes, against today's mask.
- [ ] AC-7 The census row "roles without a reader" is shown in the pull request.
- [ ] AC-8 The theme guards pass. Where one has to learn that a class is served by more than one folder, the change is in this pull request and named.

## Out of Scope

- A reader of a role: `theme-base`, step 6.
- Deleting an old token or a Neo folder: step 8.
- Another theme's `Global.css`: the classic pair and Cyberpunk (step 10), a Material pair (the capstone).
- A generator in the repository.

## Avoided Traps

- **Shipping the generator as the source.** The record rejects a generated token source; a hand-readable CSS file with a guard is the contract.
- **Reading contrast off the grade distance.** OKLCH lightness is not luminance (ADR 0044, decision 2); the check measures each pair.
- **Moving a first package in the same pull request.** Each move is revertable by itself.
