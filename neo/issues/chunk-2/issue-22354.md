# Upgrade Monaco to 0.58.0 and retire the DOMPurify override

## Context

Dependabot’s Monaco 0.58.0 upgrade in #22333 passes the build and browser tests. Its [required PR baseline](https://github.com/neomjs/neo/actions/runs/45960142063/job/140376313751) fails after the npm overrides guard classifies `dompurify: ^3.4.17` as redundant.

## The Problem

Monaco 0.57.0 pins DOMPurify 3.4.15, so the override is still needed on current `dev`. Monaco 0.58.0 pins 3.4.17 and Mermaid requires `^3.4.17`. In a replay on the upgrade manifests, removing the override cleared the guard and npm still resolved a single 3.4.17 entry.

## The Architectural Reality

Design authority: "Fails an npm `overrides` rule that no longer does anything, or that now forces a downgrade." [Shared guard source](https://github.com/neomjs/neo-agent-skills/blob/v2.10.0/scripts/check-npm-overrides.mjs#L3-L13)

`package.json` and `package-lock.json` own this policy and its resolved tree. Neo builds Monaco from its ESM entry points and resolves the sanitizer from npm. [Monaco bundle](https://github.com/neomjs/neo/blob/992fa75479c33f939419e4d206aa33053dd0f78a/buildScripts/build/monaco.mjs#L12-L39)

## The Fix

Adopt the Monaco 0.58.0 dependency bump and remove the root DOMPurify override in the same PR. Regenerate the lockfile against current `dev`.

## Acceptance Criteria

- [ ] The manifests use Monaco 0.58.0 with no DOMPurify override. The other current overrides stay in place and the shared guard passes.
- [ ] A locked install resolves a single DOMPurify 3.4.17. Neo’s Monaco build reports that sanitizer version.
- [ ] The existing headless LivePreview suite passes, including real edits and the Mermaid model embedded in Markdown.

## Out of Scope

Monaco API changes, workflow changes, and other dependency upgrades.
