# Board, timeline, scheduler and Gantt in the cyberpunk, dark and light themes

## Context

Leaf of #20874. The four family leaves bring styles for `theme-neo-dark` and `theme-neo-light`. The engine ships five themes.

## The Problem

An app that uses `theme-cyberpunk`, `theme-dark` or `theme-light` would show a board, a scheduler or a Gantt without its theme variables: wrong surfaces, borders and text colours, or none.

## The Architectural Reality

- A component's structure lives in `resources/scss/src/<family>/<Component>.scss` and reads CSS variables. Each theme sets those variables in `resources/scss/theme-<name>/<family>/<Component>.scss`.
- The five theme folders are `theme-cyberpunk`, `theme-dark`, `theme-light`, `theme-neo-dark` and `theme-neo-light`.
- `npm run build-themes` builds them; a missing theme file for a component is not an error, the variables are simply undefined.
- The grid's theme files are the sibling to follow for surfaces, borders, hover and selection.
- On `dev` at `a07f581f13` the timeline, the scheduler and the Gantt have five files in each neo theme (`timeline/Column`, `timeline/EventEditor`, `timeline/TimeAxisHeader`, `scheduler/Container`, `gantt/Container`) and none in the three other themes. The board is not on `dev` yet.

## The Fix

For every component of `src/board`, `src/timeline`, `src/scheduler` and `src/gantt` that has a file in the two neo themes, add its file in the three other themes, with values taken from that theme's existing tokens. No new colour is invented where a token of the theme exists.

Two pull requests: the timeline, the scheduler and the Gantt now (fifteen files), the board's files once #20875 is merged.

## Acceptance Criteria

- [ ] Every component with a file under `theme-neo-dark` has one under `theme-cyberpunk`, `theme-dark` and `theme-light`; the pull request lists the files.
- [ ] `npm run build-themes` passes.
- [ ] The examples of the families a pull request covers (`examples/scheduler/basic` and `examples/gantt/basic` first, `examples/board/basic` with the board) are checked in each of the three themes; the pull request carries one screenshot per example and theme.
- [ ] **Look:** the epic's design read (#20874) passes on those frames: in each theme the bars, the time header, the selection, the drop targets and the drag state read as that theme's own, and no surface is left without its variables.
- [ ] No hard-coded colour is added where the theme has a token for it.

## Out of Scope

Changes to the components' structure or to the two neo themes. A theme switcher in the examples.
