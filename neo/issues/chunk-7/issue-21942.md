# Complete the catalog’s light and dark cover backfill

## Context

The Portal consumer in #21936 and the camera in #21933 establish how a published pair is selected and produced. This leaf owns the remaining asset work. Register pairs in batches once the two images are available, so the first six examples can ship independently of the rest.

## The Problem

Across the four build modes, the initial census found 143 distinct published record/image paths: 92 full-example frames and 51 component crops. The union is larger than a single mode. Every base file existed in the pinned Pages tree; that tree had no convention-matched light siblings. New example records, including the Sales Pipeline and Gantt task tree, are separate additions to this baseline.

## The Architectural Reality

The existing `image` path remains the base asset. A genuine partner inserts `-light` before the extension. The application stores only the presentation fact `hasLightCover: true`. Production of full opening frames uses the shared 960 × 540 CSS viewport at 4/3 device scale. The Workbench tile producer uses the same mounted control and a shared crop across the two supported native palettes. Capture manifests and measurements belong with tooling and review evidence.

## The Fix

Start from the [Portal consumer](https://github.com/neomjs/neo/pull/21940) and [the producer's record](https://github.com/neomjs/neo/issues/21933). Count distinct image paths, including cross-listed records only once. Evaluate the visitor's actual opening frame in both themes. When an earlier cover showed a later interaction, read the opening on its own merits. Where a theme is unavailable or the opening misrepresents the demo, repair the example at its own source or record a steward decision.

## Acceptance Criteria

- [ ] For every still-published record in the initial set, identify the two available first-frame files or the named source issue preventing them. Keep new records and retired records explicit in the count.
- [ ] Publish each accepted pair on Pages before enabling the catalog record. Verify both public URLs and the live Portal selection in a full-example group and a tile group.
- [ ] The backfill finishes when every still-in-scope record has passed the paired check. A source defect, missing external asset, or unreviewed local capture keeps that entry open. The epic steward owns any change to the set.
