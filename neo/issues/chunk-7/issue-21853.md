# Desktop app test can click Close while its window is opening

Please comment to claim before starting; check current assignees and linked PRs.

## Context

The [hosted Engine E2E shard](https://github.com/neomjs/neo/actions/runs/44969409842/job/137046573993) failed at `test/playwright/e2e/webdesktop/Apps.spec.mjs:110`. Documents was still visible after the test clicked its Close button. The trace has `animated-hiding-showing` on the window at input time, with the click at the launcher end of the opening animation.

## The Problem

The test uses the expected width and workspace bounds as its readiness check. Documents can satisfy those checks before the opening animation moves its Close button out of the click's target.

In a headless Chromium replay on the same checked-out tree, `48e3b5857930b40ee4e8fc10534aefad57020c70`, pause the running opening transition over Documents, press Close, then let the animation move the button before releasing at the original point. The trusted pointer-down reached Close, pointer-up landed elsewhere, and Close received no click. After the worker's mount flight settled, a trusted click on the same button closed the same window.

## The Architectural Reality

The existing test describes its geometry assertion as measuring the settled window. `Dialog#animateShow` can display the window during opening, and `Component#startMountFlight` holds the App Worker latch until the mount and animation complete. The neighboring `PhoneAndTouch.spec.mjs` already uses the latch before closing Mail. [Existing guard](https://github.com/neomjs/neo/blob/c916b512ee17af5e78c0a27ea547348040c45c47/test/playwright/e2e/webdesktop/PhoneAndTouch.spec.mjs#L110-L121)

## The Fix

Use the adjacent test's worker-side check in the existing Apps loop. Resolve the real dialog ID and wait for its mounted, visible worker state with `mountFlight === null` before measuring or clicking Close.

## Acceptance Criteria

- [ ] Every app's existing view, width and workspace assertions run after its opening flight settles. The existing Close and stylesheet assertions still pass.
- [ ] Run `npm run test-e2e -- test/playwright/e2e/webdesktop/Apps.spec.mjs --grep 'every app opens' --workers=1` and report the result. Show that the guard waits through the opening phase.

## Out of Scope

Dialog motion and native device acceptance remain with their existing desktop work.
