# Four form-field configs are documented under another config's name

Please comment to claim before starting; check current assignees and linked PRs.

## Context

Every config of a Neo class carries a JSDoc block, and its `@member` line names the config, its type and its default. The API docs are generated from those lines, so a block that names the wrong config documents the wrong thing. Four configs in `src/form/field/` carry a copy of a neighbouring config's `@member` line. One was spotted while reviewing #21859, the new `Range` spec; a scan of the folder found the other three.

## The Problem

At `dev` `877f789836`:

| File and line | Config below the block | `@member` line today | Should read |
|---|---|---|---|
| `src/form/field/Base.mjs:51` | `isTouchedEvent_` | `@member {String} isTouched_=false` | `@member {String} isTouchedEvent_='focusLeave'` |
| `src/form/field/Color.mjs:33` | `colorFormatter` | `@member {Function} colorField=(scope,data)=>data[scope.colorField]` | `@member {Function} colorFormatter=(scope,data)=>data[scope.colorField]` |
| `src/form/field/Number.mjs:56` | `excludedValues` | `@member {Number[]\|null} excluded=null` | `@member {Number[]\|null} excludedValues=null` |
| `src/form/field/Range.mjs:59` | `useSpinButtons` | `@member {Boolean} useInputEvent=false` | `@member {Boolean} useSpinButtons=false` |

## The Architectural Reality

Design authority: n/a — documentation only; no behavior changes.

- The convention is in [`.github/CODING_GUIDELINES.md`](https://github.com/neomjs/neo/blob/dev/.github/CODING_GUIDELINES.md) and in `src/core/Base.mjs`, whose own configs (`className`, `ntype`) are the model: the `@member` name is the config key, with a trailing `_` for a reactive config.
- Only the four JSDoc lines change. The configs, their values and every caller stay as they are.

## The Fix

Edit the four `@member` lines to read as the table's last column. Nothing else in the four files changes.

## Acceptance Criteria

- [ ] Each of the four `@member` lines names the config directly below it, with that config's type and default.
- [ ] The diff touches only those four lines.
- [ ] CI is green on the PR.

## Out of Scope

- Other JSDoc defects, such as `errorTextStepSize` in `Number.mjs`, whose `@member` type and default don't match its function value.
- Folders other than `src/form/field/`.
