# An example without a capture recipe is captured from the frame a visitor lands on

Owned and urgent: every new example PR before the Engine 14 cut depends on it, so no `good first issue` label.

## Context

The operator, 11-22 ~11:35Z, on a recipe in `apps/portal/resources/data/example-captures.json`: "BLOAT for all example definitions with fixed sizes and CSS selectors in json configs? this is NOT neo best practices … PRIO 0." Measured on `dev` `78013b10fc`: 79 KB, 82 recipes carrying eight fields each, 575 CSS selectors, 137 scripted steps in 53 recipes, 23 viewport sizes, 51 tile sizes. Clio, who owns the overviews' look, set the rule on #21140/#21346 the same hour: **a cover is the frame a visitor lands on**. New recipes are frozen (A2A 775ef373); her 18 example leaves (#21876 to #21895) build to that rule.

## The Problem

`validateCaptureRecipes` (`buildScripts/docs/captureExamples.mjs`) refuses a catalog record that has a cover (`image`) in a declared family but no recipe ("covered record has no recipe in this family"), and the committed-manifest specs in `test/playwright/unit/buildScripts/docs/CaptureExamples.spec.mjs` run it against the real catalog. So under the freeze, every new example PR either adds a recipe or goes red.

## The Architectural Reality

- `captureExamples.mjs` is Brain-free by design (no Neural Link): Playwright opens the record's `urls.devmode`, waits for each recipe's `ready` selectors, runs its `steps`, asserts its `after` selectors and crops its `region`.
- The recipe's `ready` list is the script's only readiness signal ("no network-idle or fixed-time sleeps").
- Covers are published through `neomjs/pages`; the catalog record names the file in `image`.

## The Fix

1. A record without a recipe is valid; `--record <id>` captures it from its landing frame: one viewport for every such capture, the theme the catalog launches it with, the whole frame, and a generic readiness wait (the example's viewport is visible and the DOM stops changing for a quiet period), never a per-example selector.
2. `buildScripts/README.md` says it: no new recipe; an example that needs a state shows it on landing, set in its own code.

## Acceptance Criteria

- [ ] AC-1: `validateCaptureRecipes` accepts a covered record with no recipe; the specs pin it (one covered record without a recipe validates; an existing recipe still validates as before).
- [ ] AC-2: `npm run capture-examples -- --record <id>` for a record without a recipe writes a cover from its landing frame, with no per-example input; receipt: one real example captured on this branch.
- [ ] AC-3: The README states the freeze and the landing-frame rule.
- [ ] AC-4: A catalog component record that the frozen tile list does not name is captured as a tile at its component's own size (added 12:1xZ: without it, every new tile is a manifest edit, e.g. #21883); the 51 listed tiles keep their entries.

## Out of Scope

Converting the 53 stepped recipes into examples that land on their state (one PR per example, later leaves); deleting the manifest (when it is empty); tile sizes.
