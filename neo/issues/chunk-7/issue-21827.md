# The dock's empty center well accepts a dropped tab

## Context

#21375 keeps a window's center as a place after its pane tears out: Demo B projects an empty center well (`LayoutAdapter`'s `enableDockCenterWell`), and the pane comes home into it. Clio's design read (#21375, comment 7069215433) also makes the well a drop target: "Dropping a tab on the well uses the dock's ordinary drop preview." #21375's pull request delivers the well and the return. This ticket owns the drop.

## The Problem

A tab dragged over the well finds no drop target today. The well is not a dock node: it carries no `dockNodeId`, because the committed document has no center. The preview path only knows dock nodes. So the one place the window offers for a pane accepts none, and a user who closed the away pane has no way to put any tab back in the center.

## The Architectural Reality

- The host measures dock zones and hands their rects to `Neo.dashboard.dock.interaction.PreviewProducer#produce` (`src/dashboard/dock/Workspace.mjs`, the `producerZones` read). It resolves a placement kind per hovered zone.
- `Neo.dashboard.dock.model.PreviewContract` owns the kinds (`VALID_PLACEMENT_KINDS`) and the one path from preview to operation, `previewToOperation`. A free edge-zone center needs a kind of its own, because neither `addTab` nor `splitNode` targets an empty slot.
- `Operations.restoreTab` with `home: {parentId: <edge-zone>, slot: 'center'}` already places a new tabs node into a free center (the return in #21375 uses exactly that), so no new reducer operation is needed.
- `Neo.dashboard.dock.interaction.Preview` renders the region; `DropIndicators` builds the five-position menu, which a well, holding no node to split, does not fit.

## The Fix

1. The well config names its edge-zone (a runtime-only field), and the host's zone measurement includes it.
2. A `zone-center` placement kind: the producer emits it over the well, the contract validates it, and `previewToOperation` maps it to `restoreTab` into the free center.
3. The preview renders the whole well as the drop region; the indicator menu stays off over a well.

## Acceptance Criteria

- [ ] AC-1: Over Demo B's well, the ordinary drop preview shows the whole well, and a drop puts the tab into a rebuilt center (`root.zones.center` holds it).
- [ ] AC-2: `PreviewContract` validates `zone-center` and maps it to `restoreTab`; unit arms cover the producer, the contract and the mapping, and a malformed `zone-center` preview fails closed.
- [ ] AC-3: Hosts without `enableDockCenterWell` see no change: no well, no new kind emitted.

## Out of Scope

- The keyboard path to the well; it follows if the pointer path holds.
- Wells in hosts other than Demo B.
