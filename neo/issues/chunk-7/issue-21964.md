# Keep review admission current when more than 32 PRs target dev

## Context

[Ideas #21955](https://github.com/neomjs/neo/discussions/21955#peer-fold-22-november) selected one Engine change for the review-admission controller. The current 33-target overflow attempts to report `error` on every listed head. The existing write fence also reads PR base metadata that stayed unchanged after `dev` moved. In a fresh 26-target board query, the call cost one GraphQL point and none of the PR base fields matched the live `dev` tip.

## The fix

In `.github/workflows/review-admission-mergeability.yml`, read the board with cursor-paginated GraphQL and the current repository `refs/heads/dev` tip. Use bounded REST GET wakeups for persistent `UNKNOWN`. Only a fresh boolean conflict should publish `failure`. Treat quota exhaustion, partial pages and unavailable observations as controller conditions with visible diagnostics and a bounded retry path. Keep state-only status deduplication. Recheck the live PR head and repository tip before and after each write and converge when the pair moves.

Preserve the existing GitHub status context and live reviewer-assignment check. The already-requested-reviewer path in Brain is a separate residual because a head-only status cannot carry the base it certifies. Engine coverage here is controller publication and recovery.

Decision Record: NOT_NEEDED

## Acceptance criteria

- [ ] Replay 32 → 33 → 32 targets, preserving a genuine conflict as failure and avoiding author-side failure on overflow, rate limits, API failures or incomplete GraphQL pages. Verify how the oldest eligible PR recovers through bounded retry, next base push, or a dispatch.
- [ ] Read more than 100 targets, using a consistent live base and complete pagination. Prove a moving live tip with frozen PR base metadata and an older single-PR run racing a newer board result. Closed or retargeted PRs receive no status writes.
- [ ] Keep unchanged verdicts write-free and count GraphQL cost, REST reads, writes and retries. A hosted read-only or quiet-board trial before human merge must verify the workflow token’s actual permissions and account for any publication.
- [ ] Keep required test failure visible in a negative control. Preserve the existing public check and branch rules.
