# A Gantt example adds custom columns beside the task tree

## Context

A leaf of #21346, the planning examples under #21140. The visitor's question: can the table beside the bars carry our columns: an outline number, an owner, dates, days, progress?

No contributor labels: the capability is read from the source ([the check on `#21346`](https://github.com/neomjs/neo/issues/21346#issuecomment-6982869553)) and has not been driven in a browser. A maintainer builds it, and the drive is the first step.

## The Problem

Both Gantt examples show one column, the task tree. A project manager reads the table as much as the bars, and the engine's task side takes column descriptors.

## The Architectural Reality

- `taskColumns_` (`src/gantt/Container.mjs:71`): descriptors for the locked task columns. The default is one tree column, `{type: 'tree', dataField: 'title', locked: 'start'}`.
- Tree filtering exists and is untested in the Gantt, and a cell edit does not cascade (the source check linked above). The columns of this example are read-only.
- Template: `examples/gantt/basic` (not edited). Specs for the family: `test/playwright/e2e/gantt/`.
- Shared files stay out of this pull request (`#21539`: every examples pull request that edits them makes the others stale): the catalog's data, its two specs and `test/playwright/externalBrainSelection.mjs` belong to #21613, which takes the record below as written.
- Design authority: n/a — a new example; it calls no existing behaviour wrong.

## The Fix

1. **Drive it first** on a scratch copy of the base example: seven columns, two of them with a renderer, a collapsed phase, and a horizontal scroll of the chart. A defect becomes an engine ticket, linked here as a blocker.
2. **A new folder `examples/gantt/taskColumns`:** a festival's production plan. About 30 tasks in five phases. The columns: outline number, task (the tree), owner with initials in a badge, start, end, days, and percent done as a small bar. The data ships with the example, in stores of models.
3. **The record, for #21613:** id `gantt-task-columns`, name "Your columns beside the plan", `feature` "Seven task columns: outline number, tree, owner, dates, days and a progress bar", `lookFor` "Collapse a phase: its rows fold in the table and in the chart together. Scroll the chart: the columns stay." Cover: the table with its owner badges and progress bars, the chart beside it.

## Acceptance Criteria

- [ ] At 1440 × 900 the seven columns stand beside a chart that keeps at least half of the width.
- [ ] Collapsing a phase folds its rows in the table and in the chart, and the two stay aligned.
- [ ] At 390 × 844 the tree column alone stays locked, and the pull request shows that frame.
- [ ] A spec under `test/playwright/e2e/gantt/` asserts the column count and that table rows and chart rows match after a collapse.
- [ ] No console error. Every theme the base example's `neo-config.json` lists.
- [ ] **Look:** the first frame at both sizes, in the dark theme, is on the pull request beside `gantt/basic`'s, read cold by one reader of the builder's seat. Numbers are right-aligned, dates share one format, and the badge and the progress bar are designed for the dark and the light theme.
- [ ] The pull request edits no shared file.

## Out of Scope

Engine changes. Editable cells. Tree filtering. Reordering or resizing the columns.

## Avoided Traps

- **Seven columns of plain text.** Two of them show what a renderer can do.
- **Columns so wide that the chart disappears.**

What the intake established (on `dev` `5527f7de2e`):
- **Columns exist; no engine change.** `taskColumns_` takes plain grid column descriptors. The `progress` type (`Neo.grid.column.Progress`) draws percent done as a component. A base column's `renderer` may return a vdom object, e.g. `({value}) => ({cls: [...], text})` as `examples/grid/issues` does, which carries the owner badge. `cellAlign: 'right'` handles the numbers.
- **The task model needs a subclass** for `owner` and the outline number: `Neo.gantt.TaskModel` declares its own fields, and `TaskStore` uses it. Subclass it in the example's folder and give the `TaskStore` `model:` that subclass.
- **390 × 844: the tree column alone stays locked.** The grid's `responsiveLockPolicy_` toggles `column.locked` by breakpoint, and no example uses it yet, so drive it first. A runtime `taskColumns` reassignment throws at `src/grid/header/Toolbar.mjs:419` (defect-notes `2ba8b461`, `17178e75`). If toggling `locked` takes the same path, that's an engine blocker to file and link here, per step 1.
- The sibling `#21625` (PR #21680) is the template: house build data, five theme files, `ZoomNL.spec.mjs` with a link-on-bars measure, two cold readers in swapped order (`rendered-surface-audit`), and frames on an `ada/<ticket>-evidence` branch, embedded as `github.com/neomjs/neo/blob/<sha>/…` (raw URLs fail the PR baseline).
