# A scheduler example zooms from hours to weeks

## Context

A leaf of #21346, the planning examples under #21140. The visitor's question: can a planner go from one morning's detail to the week's overview without losing their place?

No contributor labels: the capability is read from the source ([the check on `#21346`](https://github.com/neomjs/neo/issues/21346#issuecomment-6982869553)) and has not been driven in a browser. A maintainer builds it, and the drive is the first step.

## The Problem

Both scheduler examples open at one fixed scale. The engine ships three zoom presets, and no example offers them.

## The Architectural Reality

- `static zoomPresets` (`src/scheduler/Container.mjs:45`): `hour`, `day` and `week`, each with its own tick units, pixels per minute and snap. `zoomTo(presetOrConfig)` (`:1325`) takes a preset's name or a config.
- A month level exists only as a custom config, and what stays in view on a zoom is an engine gap named on #21346.
- Template: `examples/scheduler/basic` (not edited). Specs for the family: `test/playwright/e2e/scheduler/`.
- Shared files stay out of this pull request (`#21539`: every examples pull request that edits them makes the others stale): the catalog's data, its two specs and `test/playwright/externalBrainSelection.mjs` belong to #21613, which takes the record below as written.
- Design authority: n/a — a new example; it calls no existing behaviour wrong.

## The Fix

1. **Drive it first** on a scratch copy of the base example. Note what stays in view on each zoom: the centre date, the left edge, or neither. A jump becomes an engine ticket, linked here as a blocker.
2. **A new folder `examples/scheduler/zoom`:** a conference venue. Twelve rooms and a week of sessions, about 120. A segmented control in the toolbar offers Hours, Days and Week and shows which one is active. The example opens at Days. The data ships with the example, in stores of models.
3. **The record, for #21613:** id `scheduler-zoom`, name "Zoom from hours to a week", `feature` "Three zoom levels over the same bookings, each with its own time axis and snap", `lookFor` "Switch from Hours to Week and back: the axis changes its units and the sessions keep their place." Cover: the week level, dense with small bars.

## Acceptance Criteria

- [ ] Each of the three levels draws its own header units, and the control shows the active level.
- [ ] The pull request states what stays in view on a zoom, with a frame before and after.
- [ ] A spec under `test/playwright/e2e/scheduler/` asserts the tick unit of each level.
- [ ] No console error. 1440 × 900 and 390 × 844. Every theme the base example's `neo-config.json` lists.
- [ ] **Look:** all three levels at 1440 × 900 and the first frame at 390 × 844, in the dark theme, are on the pull request beside `scheduler/basic`'s, read cold by one reader of the builder's seat. No control in the example's toolbar keeps its default style.
- [ ] The pull request edits no shared file.

## Out of Scope

Engine changes. A month level. Zoom by wheel or pinch.

## Avoided Traps

- **So few sessions that the week level looks empty.** The widest level is the cover.
- **A zoom that loses the visitor's place without saying so.** The pull request states it; the engine ticket fixes it.
