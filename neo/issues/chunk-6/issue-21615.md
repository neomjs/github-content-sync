# A scheduler example edits a booking in its editor

## Context

A leaf of #21346, the planning examples under #21140. The visitor's question: can a planner open a booking and change its fields in a form, with a rule such as a minimum length?

No contributor labels: the capability is read from the source ([the check on `#21346`](https://github.com/neomjs/neo/issues/21346#issuecomment-6982869553)) and has not been driven in a browser. A maintainer builds it, and the drive is the first step.

## The Problem

A buyer of a scheduler asks early whether a booking can be edited in a form. The Scheduler group has two examples and neither opens the editor on purpose or shows what it refuses.

## The Architectural Reality

- `editable_` (`src/scheduler/Container.mjs:158`) opens the shared `Neo.timeline.EventEditor` (`src/timeline/EventEditor.mjs`) on a booking's double-click, on Enter when it has focus, or through `openEventEditor()` (`:1266`). `editorConfig` (`:163`) overrides the dialog. `minimumDuration_` (`:216`) is in minutes.
- Template: `examples/scheduler/basic` (not edited). Specs for the family: `test/playwright/e2e/scheduler/`.
- Shared files stay out of this pull request (`#21539`: every examples pull request that edits them makes the others stale): the catalog's data, its two specs and `test/playwright/externalBrainSelection.mjs` belong to #21613, which takes the record below as written.
- Design authority: n/a — a new example; it calls no existing behaviour wrong.

## The Fix

1. **Drive it first** on a scratch copy of the base example. A defect becomes an engine ticket, linked here as a blocker.
2. **A new folder `examples/scheduler/eventEditor`:** a dental practice's day. Five treatment rooms, about 25 appointments named by treatment, a minimum of 30 minutes, and at least two appointments that already sit at the minimum. The data ships with the example, in stores of models.
3. **The record, for #21613:** id `scheduler-event-editor`, name "Edit a booking in a form", `feature` "A booking's editor: title, room, start and end, with a minimum length", `lookFor` "Double-click an appointment, or focus it and press Enter. Shorten it below 30 minutes: the editor refuses." Cover: the editor open over the day.

## Acceptance Criteria

- [ ] A double-click and Enter both open the editor on that appointment. Save writes the record and the bar follows. Cancel and Escape change nothing and return focus to the bar.
- [ ] An end before the minimum is refused, with a message the pull request shows.
- [ ] A spec under `test/playwright/e2e/scheduler/` asserts a save and the refusal.
- [ ] No console error. 1440 × 900 and 390 × 844. Every theme the base example's `neo-config.json` lists.
- [ ] **Look:** the first frame and the open editor at both sizes, in the dark theme, are on the pull request beside `scheduler/basic`'s, read cold by one reader of the builder's seat. The editor's rest, focused, invalid and saved states are shown. No button in the dialog keeps its default style.
- [ ] The pull request edits no shared file.

## Out of Scope

Engine changes. Fields beyond the event model's. Creating and deleting bookings. Recurrence.

## Avoided Traps

- **Data in which every edit is valid.** The refusal is half of the example.
- **An editor nobody finds.** The record's sentence names both ways in.
