# Release Engine v14.0.0: the release PR (preparation leaf of #21033)

## Context

The cut record #21033 holds the readiness and gate readings and the cut mechanics for 14.0.0. `publish.mjs prepare` opens the release PR against a preparation leaf, and that PR resolves the leaf, so the record stays open until `finish`, npm and the Portal read back. This ticket is that leaf. It was filed on Sat 21 Nov, once the reading of #20874's generated-app check fixed the version (`issuecomment-7061569523`), so the rehearsal can check the release PR body before Monday. The cut's steward owns it, so it carries no contributor labels.

## The Problem

Nothing to fix. The leaf exists so the release PR has exactly one standalone `Resolves` line, and so the record can keep its post-merge ticks.

## The Architectural Reality

`buildScripts/release/publish.mjs`:
- **`prepare` preflight** (`releaseState.mjs`): on `dev` at `origin/dev`, a clean tree, 14.0.0 newer than `package.json`'s 13.4.0, `.github/RELEASE_NOTES/v14.0.0.md` present, no `v14.0.0` tag.
- **`prepare` then:**
  - checks the body against this leaf: exactly one `Resolves` line for this ticket, one AC Evidence row per AC below, then `check-pr-body.mjs`;
  - sets the version (#20664, so no bump leaf is needed, unlike 13.4.0's #20656);
  - drops the older notes and stamps the note;
  - runs `prepare.mjs` and `build-all`;
  - commits once to `release/v14.0.0` and opens the PR to `dev`.
- **`finish`:** squashes the merge onto `main` with the atomic-commit line, tags it and creates the release, which publishes through `npm-publish.yml` (Trusted Publishing).

## The Fix

Run `prepare --version 14.0.0 --rehearse`, then `prepare --version 14.0.0`, with this leaf as `--ticket` and the release PR body as `--body-file`. Both run on the cut candidate that #21033's steps 2 and 3 leave on `dev`.

## Acceptance Criteria

- [ ] AC-1: The release PR's head is `prepare`'s one release commit, on top of `dev` at the cut candidate recorded on #21033 (AC-3).
- [ ] AC-2: `package.json` and the lock's root read 14.0.0, and `v14.0.0.md` is the only note under `.github/RELEASE_NOTES/`.
- [ ] AC-3: The release PR passed `dev`'s required checks and CodeQL, with no ruleset bypass.
- [ ] AC-4 (post-merge, recorded on #21033): `finish` succeeded; the GitHub release ends with the atomic-commit line; `npm view neo.mjs@latest version` reads 14.0.0.
