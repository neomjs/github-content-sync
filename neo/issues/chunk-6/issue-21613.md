# The planning groups publish the examples merged by the lock

## Context

A leaf of #21346, the planning examples under #21140. On 20 Nov 2026 the epic got nineteen example leaves for Scheduler, Gantt and Task Board. Each of those pull requests adds only its own files. This ticket publishes what has merged, in one pull request that edits the shared catalog files once.

No contributor labels: it runs against the lock of Sun 22 Nov 18:00 CET and needs the capture recipe and `neomjs/pages`.

## The Problem

An examples pull request that adds its own record edits files every other examples pull request edits too. `#21539` counted it on 19 Nov: five open pull requests on the same catalog files, 45 commits to `examples.json` in three days, and every merge made the others stale. Nineteen more pull requests in three groups would repeat that at the merge gate in the week of the cut.

## The Architectural Reality

- The shared files one published example touches, read off pull request `#21410` (the swimlanes example): `apps/portal/resources/data/examples.json` (the record), `apps/portal/resources/data/example-captures.json` (the capture recipe, read by `buildScripts/docs/captureExamples.mjs`), `apps/portal/resources/data/seo.json` (written by `buildScripts/docs/seo/generate.mjs`), `test/playwright/e2e/portal/ExamplesCatalogNL.spec.mjs`, `test/playwright/unit/apps/portal/view/examples/MainContainerController.spec.mjs` (the counts per group), and `test/playwright/externalBrainSelection.mjs` (the e2e specs that run hosted).
- `publishes()` in `apps/portal/model/Example.mjs:170` drops a record without a cover. Covers live in `neomjs/pages` and come from the capture recipe, never from a hand screenshot.
- Each example leaf carries its record as text (id, name, `feature`, `lookFor`) and names the state its cover shows.
- Design authority: n/a — it publishes new records and calls no existing behaviour wrong.

## The Fix

1. List the leaves of #21346 whose pull request has merged and whose example has no record.
2. Per example: the record as its leaf writes it, in its family; a capture recipe in the dark theme for the state the leaf names; the cover in `neomjs/pages`.
3. Once for all of them: regenerate `seo.json`, update the counts in the two catalog specs, and add each example's e2e spec to the selection list after a green hosted run.

## Acceptance Criteria

- [ ] Every example leaf of #21346 that merged by Sun 22 Nov 12:00 CET has a card with a cover on its group page.
- [ ] The pull request names each example it publishes and each merged one it leaves out, with the reason.
- [ ] `buildScripts/docs/seo/verify.mjs` passes, and both catalog specs are green with the new counts.
- [ ] **Look:** the Scheduler, Gantt and Task Board pages at 1440 × 900 and 390 × 844, in the dark theme, are on the pull request. At card size no two covers of one group can be mistaken for each other. The design seat reads the three pages whole.
- [ ] It is the only open pull request that edits these files for the planning groups, and it merges `dev` once, right before its review.

## Out of Scope

- Any example's code, and a record for an example that has not merged.
- The split of the catalog data per group (`#21539`). If that lands first, this ticket follows its layout.
- Examples that merge after the cut-off: each later wave gets a ticket of its own.

## Avoided Traps

- **A record in every example's pull request.** That is the collision this ticket removes.
- **A cover taken by hand.** The recipe is what the next retake runs.
- **Publishing an example whose look has not been read.** Its leaf's Look criterion comes first.
