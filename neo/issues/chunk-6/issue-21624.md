# A Gantt example edits a task in its editor

## Context

A leaf of #21346, the planning examples under #21140. The visitor's question: can a planner open a task, set its dates and its progress in a form, and does the plan follow?

No contributor labels: the capability is read from the source ([the check on `#21346`](https://github.com/neomjs/neo/issues/21346#issuecomment-6982869553)) and has not been driven in a browser. A maintainer builds it, and the drive is the first step.

## The Problem

A task's dates and progress are what a planner changes every day. No Gantt example opens the task editor on purpose or shows that a saved change moves the tasks behind it.

## The Architectural Reality

- `openTaskEditor()` (`src/gantt/Container.mjs:623`) opens the editor. `moveTask()` (`:654`) updates a task and cascades the dates of its dependents.
- A cell edit in a task column writes the record directly and does not cascade (the source check linked above). This example edits through the editor only.
- Template: `examples/gantt/basic` (not edited). Specs for the family: `test/playwright/e2e/gantt/`.
- Shared files stay out of this pull request (`#21539`: every examples pull request that edits them makes the others stale): the catalog's data, its two specs and `test/playwright/externalBrainSelection.mjs` belong to #21613, which takes the record below as written.
- Design authority: n/a — a new example; it calls no existing behaviour wrong.

## The Fix

1. **Drive it first** on a scratch copy of the base example: the editor opened by pointer and by keyboard, a later end saved, progress set to 100 %, and an end before the start. A defect becomes an engine ticket, linked here as a blocker.
2. **A new folder `examples/gantt/taskEditor`:** a website relaunch. Sixteen linked tasks in four phases, each with its percent done drawn in the bar. The data ships with the example, in stores of models.
3. **The record, for #21613:** id `gantt-task-editor`, name "Edit a task in a form", `feature` "A task's editor: title, start, end and percent done, and a plan that follows the change", `lookFor` "Double-click a task and move its end a week out: its successors shift. Then set it to 100 %." Cover: the editor open over the chart.

## Acceptance Criteria

- [ ] The editor opens on a task by pointer and by keyboard; the pull request names both ways.
- [ ] A saved end moves the bar and its successors; a saved percent changes the fill. Cancel and Escape change nothing and return focus to the task.
- [ ] An end before the start is refused, with a message the pull request shows.
- [ ] A spec under `test/playwright/e2e/gantt/` asserts a successor's start after a save.
- [ ] No console error. 1440 × 900 and 390 × 844. Every theme the base example's `neo-config.json` lists.
- [ ] **Look:** the first frame and the open editor at both sizes, in the dark theme, are on the pull request beside `gantt/basic`'s, read cold by one reader of the builder's seat. The editor's rest, focused, invalid and saved states are shown. No button in the dialog keeps its default style.
- [ ] The pull request edits no shared file.

## Out of Scope

Engine changes. Cell edits that cascade, and a phase that takes its progress from its tasks: engine gaps named on #21346.

## Avoided Traps

- **Editable cells in the task columns.** They would bypass the cascade, and the example would show a plan that does not follow.
- **Tasks without successors.** The change has to move something.
