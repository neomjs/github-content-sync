# Wait for keyboard focus in the Theme Switcher component test

## Context

The same Theme Switcher assertion failed while validating [Pan and Swipe](https://github.com/neomjs/neo/actions/runs/46082317064/job/140783924522), [TapPress](https://github.com/neomjs/neo/actions/runs/46085052401/job/140792610243) and an [earlier dev-based candidate](https://github.com/neomjs/neo/actions/runs/46011856825/job/140549224051). The assertion expects the Neo Light row to take focus after `Home`.

## The Problem

`test/playwright/component/button/ThemeSwitcher.spec.mjs` sends `Home` after checking the menu rows and their ARIA state. At dev `3a767aa484`, a Chromium probe held the two Main Navigator focus requests for the reopened menu while leaving its DOM and key listener ready. A trusted `Home` reached the opener. In the paired arm, releasing the same requests first made `Home` reach the focused Cyberpunk row and move focus to Neo Light. The controlled delay isolates a possible cause of the recorded failures. The CI logs do not record the original key target.

## The Architectural Reality

[ThemeSwitcher.afterSetMounted](https://github.com/neomjs/neo/blob/3a767aa4846951d9b63010a8cd6e3637be869c04/src/menu/ThemeSwitcher.mjs#L32) asks the Main Navigator to focus the active radio row. The Navigator handles `Home` from within the menu. The test owns the readiness predicate for the action it is driving.

Design authority: [the original Theme Switcher contract](https://github.com/neomjs/neo/issues/21705) requires a keyboard-accessible theme menu and a component test for keyboard operation.

## The Fix

In the existing component spec, require the active row to have browser focus on each keyboard reopen before sending the next key with `page.keyboard`. Keep the existing key, focus and theme assertions.

## Acceptance Criteria

- [ ] The first keyboard reopen verifies Cyberpunk focus before `Home`, followed by Neo Light, Neo Dark and the actual applied theme.
- [ ] The second keyboard reopen verifies Neo Dark focus before `Escape`, followed by the closed menu and restored opener focus.
- [ ] The whole Theme Switcher Chromium component spec passes repeatedly on the repair head. The paired focus-hold control documents why row visibility is insufficient.

## Out of Scope

Changes to production keyboard routing, menu mounting or release disposition of an early keypress. This ticket repairs a recurring CI check.
