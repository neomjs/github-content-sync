# Enforce the existing writer lock for public gesture replay

## Context

The Engine and Playwright replay paths from #22407 and #22408 are in place. The remaining public Neural Link action, neomjs/neo-agent-brain#1966, is specified under the existing writer lock. This Engine prerequisite completes that contract for the public caller.

## The Problem

At Engine dev `f8ad427057`, the registered App Worker dispatcher passes the Bridge-stamped writer context to interaction handlers. `InteractionService.driveGesture` currently resolves the window and delegates to Main without consulting the existing target write authority. Main serializes input in one window with the drag mutex. That serves browser input ownership and leaves App subtree admission to the Engine client. The public tool tier governs discovery.

## The Architectural Reality

[The registered dispatcher](https://github.com/neomjs/neo/blob/f8ad427057c79e167da0367a2926fb2637efaa5f/src/ai/client/resolveServiceMethod.mjs#L43) already supplies the authenticated context. [The fenced lock lifecycle](https://github.com/neomjs/neo/blob/f8ad427057c79e167da0367a2926fb2637efaa5f/src/ai/WriteGuard.mjs#L180) owns App-side writer admission and release. The existing Main simulator remains the owner of contacts, native target/window resolution and cleanup.

Design authority: [ADR 0045, decision 10](https://github.com/neomjs/neo/blob/f8ad427057c79e167da0367a2926fb2637efaa5f/learn/agentos/decisions/0045-touch-gesture-events.md#2-decision) places the public action “under the existing write lock.” Brain #1966 AC-2 requires the existing competing-writer and disconnected-session guarantees.

## The Fix

Use the Engine's existing writer admission in `InteractionService.driveGesture` before starting replay for a Bridge-attributed writer. Resolve the live target component or the managed owner of a node in the selected window. Return a typed refusal when ownership cannot be established or the existing lock denies admission. Keep the acquisition and Main contact lifetime coordinated through completion, cancellation and writer departure.

## Contract Ledger

| Surface | Authority | Behavior and fallback | Evidence |
| --- | --- | --- | --- |
| Engine `drive_gesture` (registered App Worker RPC) | ADR 0045 decision 10, Bridge-stamped writer identity, existing Engine WriteGuard | Attribute the existing target forms to a live owner in the named window. Apply the existing scoped admission to an attributed writer. Keep the provider and trace/receipt shape. Ownership denial has a typed result with no observed dispatch. | Registered RPC on a local test app, distinct real writer envelopes, App and Main receipts |
| Existing writer teardown | Engine Client writer lifecycle and EventSimulator contact cleanup | End or cancel the replay at the old writer boundary before an admitted replacement can race its contacts. Preserve ordinary native-input and fixture provider behavior. | Writer departure during an open sequence, cleanup receipt and succeeding writer |

Decision Record impact: aligned with ADR 0045 and the existing Engine multi-writer contract. No new writer or provider subsystem.

## Acceptance Criteria

- [ ] An attributed writer can replay the accepted trace on an eligible target. Both component and managed-node targets retain their owning-window behavior.
- [ ] A competing writer with an overlapping lock, or a target with unresolvable ownership, receives a typed refusal and dispatches zero events. A disjoint eligible target supplies a positive control.
- [ ] In-flight writer departure cancels and cleans up owned contacts before a replacement can act. Existing timeout, window-departure, target-replacement and explicit browser-provider refusal controls still pass.
