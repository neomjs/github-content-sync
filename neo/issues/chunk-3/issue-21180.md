# The tree grid example shows values that roll up per level

Please comment to claim before starting; check current assignees and linked PRs.

## Context

Row 8 of the Grid & Table slate ([#21142](https://github.com/neomjs/neo/issues/21142#issuecomment-6924949418)), a leaf of #21175 (the Grid & Table group, under #21140).

## The Problem

`examples/grid/tree` is the card "Tree Grid". It shows seven rows of a file tree in a corner 250 px wide: a name, a type and a size. A tree list could show the same. What a tree grid adds, columns of values per level, is not there, and most of the stage is empty.

## The Architectural Reality

- `examples/grid/tree/`: `GridContainer.mjs` (39 lines; three columns at `:23` to `:34`, the first with `type: 'tree'`), `MainContainer.mjs` (a fit layout), `MainStore.mjs` (inline nodes from `:22`), `MainModel.mjs`.
- Both themes are in `neo-config.json`.
- Three spec files name the folder: `test/playwright/e2e/grid/Tree.spec.mjs`, `test/playwright/component/container/CardGridContainment.spec.mjs` and `test/playwright/unit/buildScripts/moveRuntimeReferences.spec.mjs`.
- The tree store is documented in `learn/guides/datahandling/TreeStore.md`.
- Catalog record `grid-tree`. Its sibling `grid-tree-big-data` is the scale proof (#21165); this card is the small, readable one.
- Design authority: "Every renew and every new row is then filed as its own leaf under #21140" (#21142), row 8 of its Grid & Table table; the bar is the one #21140 names: "an example resets, works at phone width, in both themes, by keyboard".

## The Fix

1. **A hierarchy with a value on every level**, three levels and at least 40 nodes, for example a budget by department, team and item, or a parts list with quantities and cost. A parent row shows the sum of its children.
2. **Four to six columns** beside the tree column, at least one numeric with a total and one that is not a number (an owner, a status).
3. **The grid fills the stage** and opens with the first level expanded.
4. One line says what to try, for example "Expand a team. Its numbers add up to the department's."

## Acceptance Criteria

- [ ] Every parent row's value equals the sum of its children; a unit or e2e assertion checks one of them.
- [ ] Expanding and collapsing works by click and by keyboard; the PR says with which keys.
- [ ] At 1440 × 900 the grid uses the stage's width and height, and at least 15 rows show.
- [ ] The three spec files pass, adapted where they pin the old nodes (`npm run test-e2e -- test/playwright/e2e/grid/Tree.spec.mjs`, `npm run test-components -- test/playwright/component/container/CardGridContainment.spec.mjs`, `npm run test-unit -- test/playwright/unit/buildScripts/moveRuntimeReferences.spec.mjs`).
- [ ] 390 × 844; both themes.
- [ ] **Look:** the first frame at both sizes is on the PR beside today's frame, and the design seat reads it before code review.
- [ ] The catalog cover is re-shot from the new default state with the producer of #20679, or the PR names the change that brings it.

## Out of Scope

`examples/grid/treeBigData` (#21165); changes to the tree column or the tree store; drag and drop between nodes.

## Avoided Traps

- **A file tree again.** It needs no columns, which is why today's frame reads as a list.
- **Totals typed into the data.** They are computed from the children, so an edit could never leave them wrong.
