# theme-base: bind tab's 58 variables to roles

Owner: Vega (`@neo-opus-vega`), the row's holder. Step 6 row `tab` of #22295, on the template of the Button pilot (#22351, PR #22420, on `dev` as `e94e60872d`). The acting design seat has [read the table](https://github.com/neomjs/neo/issues/22295#issuecomment-7223146905): it stands, with three points folded in below.

## Context

#22295 Step 6 declares each engine package's variables once in `theme-base`, bound to theme Neo's roles (`resources/css/theme-neo/Global.css`). The draft table for `tab` was posted on the epic before its leaf existed ([table](https://github.com/neomjs/neo/issues/22295#issuecomment-7222398527)); by the design seat's rule a table moves into its row's leaf, and this is that leaf. The row also carries the cut's gate in #22295: a theme generated with `--base theme-neo` paints a hovered tab only once `tab` has moved ([Sophie](https://github.com/neomjs/neo/issues/22295#issuecomment-7226072052), [Euclid](https://github.com/neomjs/neo/issues/22295#issuecomment-7226097386)).

## The Problem

`resources/css/theme-neo-{light,dark}/tab/` writes tab's variables twice, once per scheme: `Container.css` 23, `Strip.css` 3, `header/Button.css` 32 (58 on `dev` at `c91d3f482a`). They read old tokens and one another component's variable (`--neo-button-text-font-weight`), so a theme written against the roles cannot reach the tabs, and a theme generated from theme Neo paints a hovered tab transparent.

## The Architectural Reality

- Design authority: #22295's decided rules: a component variable reads roles only (rule 2), a separator on a raised region reads `border-default` (rule 18), and the design seat's [read of this table](https://github.com/neomjs/neo/issues/22295#issuecomment-7223146905).
- Readers: `resources/css/src/tab/Container.css`, `src/tab/Strip.css` and `src/tab/header/Button.css` read them; the tab header button is a Button subclass that paints from its own variables, so #22420's Button move leaves it as it is.
- `theme-light`, `theme-dark` and `theme-cyberpunk` declare their own `tab` sheets, so their values win over `theme-base` and the classic themes do not move.
- One variable is newer than the draft: `--neo-tab-button-close-border-radius: 2px`, from #22390's radius sweep.

## The Fix

Write `resources/css/theme-base/tab/Container.css`, `tab/Strip.css` and `tab/header/Button.css` under `[class*="neo-theme-"]`, delete the six theme-neo sheets, and run #22420's equality and frame procedure.

### Binding table (draft at `a5ef0298e8`, roles at `24d1ecce37`; the build re-resolves both on its base, and the equality run declares the final list)

Of the 58: 21 bind to a role with the same value, 23 are keywords (`none`, `transparent`, `0`, `inherit`, `uppercase`), 5 stay listed literals, and 9 bind with a changed value. Two of the nine change notation only (`16px` becomes `1rem`; the button weight reads the role instead of Button's variable). Seven are value moves (light · dark), each a declared difference:

| Variable | Binds to | Before | After |
| :--- | :--- | :--- | :--- |
| `--neo-tab-container-content-border` | `border-default` (with `border-width-thin`) | `#ddd` · `#43495c` | `#d3d6de` · `#3e4458` |
| `--neo-tab-header-inline-box-shadow` | `border-default` in `inset 0 calc(-1 * var(--neo-border-width-thin)) 0 …` | `#d3d7d2` · `#43495c` | `#d3d6de` · `#3e4458` |
| `--neo-tab-header-action-glyph-color` | `text-muted` | `#454b42` · `#989fb4` | `#3e4458` · `#979eb2` |
| `--neo-tab-button-glyph-color` | `text-muted` | as above | as above |
| `--neo-tab-button-color` | `text-muted` | as above | as above |
| `--neo-tab-header-inline-background-color` | `background-surface-raised` | `#ffffff` · `#282c37` | `#ffffff` · `#252834` |
| `--neo-tab-indicator-background-color-active` | `background-inverse` | `#000` · `#fff` | `#0e0f13` · `#f9fafb` |

The rest bind exactly: the action and button hover and active fills to the neutral layers, pressed glyph and label to `text-strong`, heights to the `control` family (24, 32, 48), radii to `radius-small`, `radius-none` and `control-radius`, the inline font to `control-font-size-small` and `font-weight-regular`.

### Decided by the acting design seat ([read](https://github.com/neomjs/neo/issues/22295#issuecomment-7223146905))

1. `--neo-tab-button-text-font-weight` binds to `font-weight-semibold`, the value Button's variable resolves to. A theme that wants tabs and buttons to move together sets both.
2. The indicator stays on `background-inverse`. An accent indicator is a theme's per-widget file; the Material pair (#22359) writes one.
3. `--neo-tab-strip-height: 3px` and the block parts of the three paddings (`4px 8px 3px`, `7px 16px 6px`) stay listed literals; their inline parts bind (`control-padding-inline-small`, `-large`).

### Open for the design seat (one line)

`--neo-tab-button-close-border-radius: 2px` has no step on the radius scale (0, 4, 8, full). Proposed: a listed literal, like the strip height, so nothing moves; binding it to `radius-small` would double the close button's corner.

- [ ] AC-3: `npm run theme-equality` reports 0 undeclared differences in `theme-light`, `theme-dark` and `theme-cyberpunk`, and the `theme-neo-light` / `theme-neo-dark` differences are the declared ones of the table, as re-measured on the build's base.
- [ ] AC-4: A theme generated with `create-theme --base theme-neo` in a fresh workspace paints a hovered tab header button with a non-transparent fill (the cut gate of #22295).
- [ ] AC-5: Light and dark frame pairs (before · after) of the tab example and one dense page with tabs are posted for the acting design seat, with rule 18 checked on the header bar.
- [ ] AC-6: Reverting the pull request cleanly restores the pre-move state.

## Out of Scope

- An accent indicator (a theme's per-widget file, #22359).
- App and example tab overrides, such as Workstation's two-panel tab header (a counted deviation of #22426).
- The paddings' move to the space scale (trigger: the first density scope).

## Avoided Traps

- Binding the button weight to `--neo-button-text-font-weight`: one component reading another's variable, which rule 2 forbids.
- Rounding the close radius to `radius-small` silently: a visible move that needs the design seat, not a rounding.
