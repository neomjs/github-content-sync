# Preserve gesture replay hold timing and report dispatch time

## Context

Handoff: @neo-gpt-euclid, the Engine replay owner. The fixture and release diagnostics are with Sophie. This is a follow-up to #22407 and #22408 under #22400.

The HighlightJs PR #22532 exercised the landed Helix replay case on merge `49252ae39c`, based on `dev@76d743e589`. The [hosted shard](https://github.com/neomjs/neo/actions/runs/46108565285/job/140866786119) measured a 210.7 ms receipt interval for the nominal 240 ms engine hold. The unchanged exact tree passed eight local repetitions.

## The Problem

Two headless controls on that merge held a document capture callback for 65 ms. Both preserved the expected events, contact IDs and final Helix geometry.

| Delayed callback | Event timestamp gap, hold down to up | Replay receipt gap |
| --- | --- | --- |
| Hold down | 239.9 ms | 174.9 ms |
| Previous sequence’s last up | 197.8 ms | 197.9 ms |

The first difference is in reporting. The second shortens the actual delivered contact.

## The Architectural Reality

[Engine replay](https://github.com/neomjs/neo/blob/76d743e589440a8381d1875a92b1a346a0a821cc/src/main/addon/EventSimulator.mjs#L617-L665) schedules absolute deadlines from the first frame and reads `performance.now()` after synchronous event dispatch. The [browser provider](https://github.com/neomjs/neo/blob/76d743e589440a8381d1875a92b1a346a0a821cc/test/playwright/playwrightGestureReplay.mjs#L168-L191) preserves inter-frame spacing when the preceding dispatch has run late. [ADR 0045](https://github.com/neomjs/neo/blob/76d743e589440a8381d1875a92b1a346a0a821cc/learn/agentos/decisions/0045-touch-gesture-events.md) defines offsets from the first frame. #22407 requires a timed hold and truthful receipt.

## The Fix

Record dispatch timing for the correlated event in the owning clock. Name the contract for late frames with the replay owner and align the timed-hold behavior and its acceptance test between the providers. Preserve the existing timeout, cancellation, target and realm checks.

Prescription checked: `src/main/addon/EventSimulator.mjs` owns Engine dispatch timing. The fixture owns the independent clock comparison.

## Contract Ledger

| Surface | Authority | Behavior | Evidence |
| --- | --- | --- | --- |
| Observed event elapsed time | #22407, ADR 0045 | Use the correlated dispatch time in the owning realm. User-handler duration cannot shorten the reported hold. | Delayed hold-down callback and separate DOM timestamps |
| Late frame during a hold | #22407 and browser replay fixture | Document and enforce parity for the required hold duration and the overall deadline. | Delay the previous sequence’s terminal; compare actual contact timing and the declared result |

## Acceptance Criteria

- [ ] The receipt matches correlated DOM event intervals under a blocking handler and never reports a completed hold solely from the planned offsets.
- [ ] A late previous frame has a deterministic hold result consistent with the agreed Engine/browser contract. If the deadline cannot be met, the transaction cleans up under its existing timeout behavior.
- [ ] The full Helix trace keeps its event ordering, terminal sequence and geometry checks, and the timed-hold cases pass on the exact hosted head.

## Out of Scope

Gesture recognition, Helix motion tuning, HighlightJs styling, and native physical phone policy changes.

A synchronous handler counts as elapsed hold time if the contact has already gone down, so a 65 ms listener does not add 65 ms to a 240 ms hold. The existing one-trace execution deadline stays in force. If the next frame cannot fit, the Engine returns `GESTURE_TIMEOUT` and cancels active contacts before releasing the lock.
