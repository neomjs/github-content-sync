# Tab Container opens in Classic Dark from a Light catalog

## Context

The Tab Container card has Light and Dark covers. The 14.1 visual audit exposed that its live link requests Neo Light and the example still opens in Classic Dark. The example supports Neo Light. [Audit evidence](https://github.com/neomjs/neo/issues/22490#issuecomment-7235516324) · [Catalog record](https://github.com/neomjs/neo/blob/76d743e589440a8381d1875a92b1a346a0a821cc/apps/portal/resources/data/examples/tabs.json)

## The Problem

Open `examples/tab/container/index.html?theme=neo-theme-neo-light` on `dev@76d743e589`. The body and viewport both paint Classic Dark. An explicit Classic Light request also opens Classic Dark. The same startup module is present in 14.0.0.

## The Architectural Reality

Portal already passes the selected theme into the example URL. This workbench's entry passes a bare view class and never resolves that URL. Its config declares Classic Dark, Classic Light and Neo Light. The established resolver preserves the requested scheme when the exact Neo variant is unavailable.

Design authority comes from [the operator’s catalog direction](https://github.com/neomjs/neo/issues/21835#issuebody). The catalog theme should also reach the opened example.

## The Fix

Use the same `resolveStartTheme(Neo.config)` view configuration as [Browser-Style Tabs](https://github.com/neomjs/neo/blob/76d743e589440a8381d1875a92b1a346a0a821cc/examples/tab/browser/app.mjs#L1-L7). Keep the existing workbench switch and theme inventory. The scratch browser check verified both explicit Light requests, the first actual switch from each, and the current default and unsupported Neo Dark fallback.

## Acceptance Criteria

- [ ] A Neo Light link opens the example in Neo Light. Explicit Classic Light still selects Classic Light. A bare launch and a Neo Dark request select Classic Dark.
- [ ] The workbench’s first deliberate switch moves body and viewport together to the next configured theme after each Light launch.
