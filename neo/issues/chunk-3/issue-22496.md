# Check the app palette’s name count against its stock theme

## The problem

At `f8ad427057`, the stock product-palette unit fails with “Expected: 195, Received: 199”. Reproduce with `npm run test-unit -- buildScripts/util/check-theme-palette.spec.mjs --grep 'a product palette in an app'`. The preceding assertions for the two schemes and the two app overlays pass.

## The architectural reality

Design authority: the [product-palette contract](https://github.com/neomjs/neo/issues/22427) permits an app to re-value existing names on its theme. The stock control in [the same spec](https://github.com/neomjs/neo/blob/f8ad427057/test/playwright/unit/buildScripts/util/check-theme-palette.spec.mjs#L617) already checks the published count of 199 after the four form roles landed. The app fixture repeats an older count, so it fails even with the correct set.

## The fix

Compare the app fixture’s reported count to the same stock theme measured alone. The dedicated control owns the exact public count.
