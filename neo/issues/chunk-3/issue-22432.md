# Workstation's look, light and dark, is one palette file of theme Neo

On the Engine `14.1` path: the operator named the Workstation light and dark theme for this release (#22391). This is its first product leaf under #22426, so it is seat work and carries no contributor labels.

unowned-rationale: defined and ready for a maintainer seat, offered by message on 27 Nov. The acting design seat holds no build of #22426.

## Context

Epic #22426 decides how a product wears its look: one palette file in the app's folder of the theme, `resources/css/theme-<name>/apps/<app>/Global.css`, on the theme's own classes. This leaf is that file for Workstation, the route that loads it in every window the product opens, and the demonstration the epic sets as its entry gate. Read on `dev` at `c7730115b9`.

## The Problem

Workstation's look is a bridge. `resources/css/theme-neo-light/apps/workstation/Viewport.css` and its dark twin each declare 15 names (`--workstation-*`: eleven colours, two font stacks, two cursor values), and `resources/css/src/apps/workstation/Viewport.css` maps component variables onto them under the viewport. Measured in the running app ([Sophie's witness](https://github.com/neomjs/neo/issues/22365#issuecomment-7228773019)):

1. A floating component the bridge does not list paints theme Neo. The Close action's tooltip in a populated Metrics pop-out paints `#3e63dd` in both schemes: the rule that would re-colour it sits in `Workspace.css`, which that window does not load.
2. The main window's tooltip stays light on a fresh hover after a switch to dark. Its cause is #22428.

The bridge also cannot simply go as packages move to `theme-base` (#22295, step 6): each block needs a palette underneath that paints the same colours through roles.

## The Architectural Reality

Design authority: ADR 0044, decision 8, with the sentence #22427 adds; epic #22426, "Intended solution", points 1, 2, 4, 6 and 7.

- **The carrier is measured.** Values on theme Neo's classes in a sheet of the `neo.apps` layer reach the viewport, a nested theme class, a light island, a floating `body` child and a second window. Values on the viewport class reach neither of the last two (the table in #22426).
- **The loader exists.** A class names extra theme files in `additionalThemeFiles`, and `insertThemeFiles` (`src/worker/App.mjs`) loads each once per window. `Workstation.view.Workspace` names three today (`apps/workstation/view/Workspace.mjs`).
- **The theme map is not touched.** `collectThemeClassMap` (`buildScripts/util/themeCss.mjs`) reads the `Global.css` directly inside a theme folder, so an app's `Global.css` two levels down declares no theme.
- **The guard refuses the file today.** A second value for a palette or role name of theme Neo fails `check-theme-palette` as `[cascade]`. #22427 teaches the check to read the file as a product palette, in one folder per theme class.
- **A role on the element is half the proof.** Theme Neo's light tooltip sheet declares `--neo-tooltip-background-color: #3E63DD` as a literal, so the tooltip stays blue while the product's role resolves correctly on it ([the epic review](https://github.com/neomjs/neo/issues/22426#issuecomment-7229357029), Stage 5). The painted value follows when `tooltip` moves to `theme-base`: one sheet with 8 variables, a row of #22295's step 6 without a leaf or a holder at filing.
- **What the palette paints at its merge:** `src/Global.css` and every package already in `theme-base`. Where a bridge block still re-values a package's component variables, the bridge wins until that block goes.

## The Fix

1. **`resources/css/theme-neo/apps/workstation/Global.css`**, light and dark in one file, on `.neo-theme-neo-light` and `.neo-theme-neo-dark`. It re-values palette and role names of theme Neo and adds none. The palette comes first; a role is re-bound only where the look needs another grade (#22426, point 2).
2. **A table in this body before the first commit:** for each of the eleven colours (`ground`, `panel`, `panel-2`, `rail`, `line`, `line-soft`, `ink`, `ink-dim`, `ink-faint`, `signal`, `state-ok`), the palette or role name that carries it in each scheme, or the reason none does. A colour that fits no role is asked of the design seat on this leaf. The two font stacks and the two cursor values are not colours: they stay Workstation's own variables.
3. **Every window the product opens loads the file.** The class each Workstation window creates names it in `additionalThemeFiles`, the pop-out's host included.
4. **The demonstration**, a whitebox spec beside `WorkstationGridDragProxySkinNL.spec.mjs` in `test/playwright/e2e/workstation/`. It compares the painted background and text colour of a tooltip with the product's values, in the populated pop-out and in the main window after a switch, in dark and in light. It also reads the role on the element, which tells a missing file from a missing binding.
5. No bridge line is removed here. Each removal is its own leaf and owns its visual comparison.

## Avoided Traps

- **Values on the viewport class.** Measured in #22426: no floating component, no second window.
- **The eleven colours as new `--neo-*` names.** That is the bridge under another prefix.
- **Component variables in the palette file.** A product does not re-value a component variable that a role carries; a counted deviation stays in the product's own sheets with its reason (#22426, point 6).
- **A second file in `theme-neo-dark` or `theme-neo-light`.** Both folders map to a class that `theme-neo` already serves, and the loader fetches from each: two overlays that pass alone can fail together (the epic review, Stage 4).
- **A spec that reads only the role.** It passes while the tooltip is still blue.

**Acting design seat: yes for a whole grade, no for a single value. Dark moves three grades; light keeps the ladder.**

Each step against what it sits on, measured with the palette check's functions on your 22 values:

| Step | Workstation today | Theme Neo's ladder |
| :--- | ---: | :--- |
| Dark: panel on ground | 1.11 | 1.31 (`900` on `950`) |
| Dark: line on panel | 1.30 | 1.52 (`800` on `900`) |
| Dark: line-soft on panel | 1.12 | 1.00 (`border-subtle` and the raised surface both read `900`) |
| Dark: panel-2 on panel | 1.08 | no grade between |
| Dark: rail on ground | 1.04 | no grade between `950` and `900` |
| Light: panel on ground | 1.09 | 1.12 (white on `100`) |
| Light: line on panel | 1.41 | 1.46 (`200`) |
| Light: line-soft on panel | 1.22 | 1.12 (`100`) |
| Light: rail on ground | 1.07 | no grade between `100` and `200` |

**1. A product palette may give a grade its own lightness, as a whole grade.** The numbers are the palette's own (#22295, rule 10), and all seven slots move at that grade (ADR 0044, decision 2; #22426, point 2). #22427's check then holds the merged palette to its floors in both schemes.

**2. Dark moves three:** `950` to .163, `900` to .216, `800` to .303. That keeps the relations the night look stands on: a panel 1.11 off the ground and a line 1.30 off a panel. On the stock ladder they would be 1.31 and 1.52, which is another product.

**3. Light keeps theme Neo's numbers** and re-values hue and chroma alone. Its shifts are small (1.09 to 1.12, 1.41 to 1.46, 1.22 to 1.12), and each is named under AC-6.

**4. A value between the product's grades is not a palette entry and not a role.**
- `panel-2` in dark is the tab header's second panel, the counted deviation #22426 lists in point 6. It stays a component variable in Workstation's own sheet.
- `rail` is Workstation's own region: its own variable, reading two roles through `color-mix`, counted with its reason. At 1.04 and 1.07 it is under the 1.1:1 the system asks of a step (#22295, rule 15). If your frame shows no loss with the rail on `background-canvas`, drop it.
- `line-soft` reads `border-subtle` as bound. On a panel at night that is no line, with or without the move. If the frame needs one, the product re-binds `border-subtle` in dark to `800` and has one line weight at night.

**5. Text maps by rank, and a role's floor wins over reproduction.** `ink` is `text-default`, `ink-dim` is `text-muted`, `ink-faint` is `text-subtle`, each in both schemes: one Workstation name, one role. Where the ladder makes secondary text stronger than today, that is a shift to name and no reason to leave the role.

**One knock-on of point 2.** Moving `800` also moves light's `text-muted`, which reads `neutral-800`: at .303 it would sit almost on `text-default`. Re-bind it in light (`700` keeps the rank above `text-subtle` at `600`). The dark subtle fills and `background-disabled` read `900` and stay level with a panel, as they do in stock Neo.

The neutral hue, `signal` and `state-ok` are slot re-values of hue and chroma: yours as tabled.

The rule is in #22426's body, point 2. A pull request that lands these decisions is reviewed by another seat.
