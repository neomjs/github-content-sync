# Check Browser replay deadlines at the dispatch boundary

## Context

This is the Playwright Browser fixture follow-up to #22408 and #22535. Euclid owns the Engine repair in #22539. Sophie owns the fixture path.

## The Problem

In a deterministic transport control, an already open Browser contact passed the frame deadline check. The target-liveness await then returned after the deadline. The old path sent `touchEnd` and returned success. With a 100 ms deadline and a 180 ms liveness stall, release was sent around 193 ms.

The fixture records trusted event receipt time with `performance.now()` in its capture listener. A listener registered earlier can block that measurement and make a real hold appear shorter.

## The Architectural Reality

[`playwrightGestureReplay.mjs`](https://github.com/neomjs/neo/blob/76d743e589440a8381d1875a92b1a346a0a821cc/test/playwright/playwrightGestureReplay.mjs) owns native CDP dispatch, observing the target’s document and the one-replay-per-page lock. The current frame check controls scheduled waiting. Checking again immediately before a CDP send covers the intervening liveness await. The paired Gallery run supplies a planned recognizer clock to CDP. That clock can make `TouchEvent.timeStamp` equal the requested offset even when actual delivery takes longer. [Paired evidence](https://github.com/neomjs/neo/issues/22541#issuecomment-7234709420)

## The Fix

Record trusted event delivery from an early window capture installed before navigation in fixture-owned contexts. Keep Gallery’s planned CDP clock for recognizers. Recheck the same deadline immediately before dispatch after the asynchronous liveness check. Retain the settled scheduling cadence and existing cancellation, target and lock boundaries.

Prescription checked: the Playwright Browser fixture owns both operations. Its deterministic timer control belongs beside `test/playwright/unit/test/dedicatedWorkerNeuralLink.spec.mjs`.

## Acceptance Criteria

- [ ] A deadline crossed during liveness returns `GESTURE_TIMEOUT`. Given an open contact, transport sends one cancel and a fresh replay on the same page can complete.
- [ ] The trusted Browser hold receipt matches independent DOM event timings when another listener stalls; minimum contact spacing remains intact.
- [ ] The existing two-window Browser fixture and Helix Browser results continue to verify routing, contact order and cleanup.

## Out of Scope

Engine scheduling, native gesture recognition and physical-device policy.
