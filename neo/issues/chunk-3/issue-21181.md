# The value banding example explains its bands on data that reads real

Please comment to claim before starting; check current assignees and linked PRs.

## Context

Row 9 of the Grid & Table slate ([#21142](https://github.com/neomjs/neo/issues/21142#issuecomment-6924949418)), a leaf of #21175 (the Grid & Table group, under #21140).

## The Problem

`examples/grid/valueBanding` tints runs of rows that share a value in a column, so a sorted sheet reads in blocks. A visitor sees names such as "First_32" in a box that cuts the grid at eleven rows, and a tint nobody explains. The feature is useful and the frame hides it.

## The Architectural Reality

- `examples/grid/valueBanding/`: `MainContainer.mjs` (93 lines: a `height` field at `:25`, the checkboxes `stripedRows` at `:35` and `useValueBanding (Dept)` at `:41`, five columns at `:61` to `:65` of which Country and Department carry `useValueBanding: true`, a wrapper fixed at 400 px at `:68`), `MainStore.mjs` (100 generated rows, the loop at `:32`, names built as `First_${i}` at `:35`, sorted by country at `:16`), `MainModel.mjs`.
- The example is hosted on `examples/ConfigurationViewport.mjs`, which #21143 turns into the workbench. The host stays.
- No spec file loads the folder.
- Catalog record `grid-value-banding`.
- Design authority: "Every renew and every new row is then filed as its own leaf under #21140" (#21142), row 9 of its Grid & Table table; the bar is the one #21140 names: "an example resets, works at phone width, in both themes, by keyboard".

## The Fix

1. **Rows that read as real**, 80 to 150 of them, sorted so that the banded columns form runs, for example staff by country and department, or shipments by region and carrier.
2. **The grid takes the stage's height.** The 400 px wrapper goes.
3. **One sentence in the frame says what a band is**, for example "Rows that share a country get one band, so each country reads as a block. Switch Department on for a second level."
4. The two checkboxes stay, with labels a visitor understands.
5. The record's `feature` and `lookFor` use the word banding.

## Acceptance Criteria

- [ ] No generated placeholder value shows in any cell.
- [ ] At 1440 × 900 the grid uses the stage's height, and the first frame shows at least three bands of different length.
- [ ] Switching the Department band on changes the frame, and the sentence in the frame matches what the switches do.
- [ ] Neither the frame nor the catalog record calls banding grouping.
- [ ] 390 × 844; both themes.
- [ ] **Look:** the first frame at both sizes, once with one band level and once with two, is on the PR beside today's frame, and the design seat reads it before code review.
- [ ] The catalog cover is re-shot from the new default state with the producer of #20679, or the PR names the change that brings it.

## Out of Scope

Row grouping, group headers or aggregation, which `dev` does not have; changes to the banding logic; the workbench (#21143).

## Avoided Traps

- **Calling it grouping.** #20500 named this trap: banding tints rows, it does not group them.
- **Unsorted data.** Without runs there are no bands, and the frame reads as a striped grid.
