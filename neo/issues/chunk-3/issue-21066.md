# Grid search menu opens behind its owning dialog

Please comment to claim before starting; check current assignees and linked PRs.

## Context

A grid with `searchToolbar: {}` inside a normal `Neo.dialog.Base` (`modal: false`) opens its **Grid columns** menu behind the dialog. The application can expose it by raising the created menu's `zIndex`, but ordinary nested use should not require an application-specific layer number.

Reproduced in headless Chrome at `94a7dd27e38224f08f4112880e0691f7693a9508`, viewport1400×900, through the page's own Neural Link App Worker. No engine source patch was used.

## The Problem

```javascript
const {default: Dialog} = await import('/src/dialog/Base.mjs');
```

## The Architectural Reality

Design authority: `Button#toggleMenu` documents “Toggles the visibility of the button's menu, if one is configured.” An opened menu must remain visible and pointer-reachable over its owning dialog.

- [Button.afterSetMenu](https://github.com/neomjs/neo/blob/94a7dd27e38224f08f4112880e0691f7693a9508/src/button/Base.mjs#L344) supplies logical `parentComponent: button` and merges the public `menu` object, without resolving an owner layer.
- [Menu.List](https://github.com/neomjs/neo/blob/94a7dd27e38224f08f4112880e0691f7693a9508/src/menu/List.mjs#L161) defaults `zIndex` to100 and writes it inline. Submenus use their parent menu's z-index plus1.
- `parentId` defaults to `document.body`; logical component ownership does not create a DOM stacking context. [The floating contract](https://github.com/neomjs/neo/blob/94a7dd27e38224f08f4112880e0691f7693a9508/src/component/Base.mjs#L126) deliberately keeps those concerns separate.
- Dialog defaults to floating; [the floating CSS](https://github.com/neomjs/neo/blob/94a7dd27e38224f08f4112880e0691f7693a9508/resources/scss/src/component/Base.scss#L23) uses1000.
- SearchToolbar creates and retains its scope menu; it updates alignment/items/selection, with no dedicated scope-menu z-index pass-through.

## The Fix

Nige's existing Picker/Dialog model is the precedent to reuse, not a new ancestor-z calculator.

- [16c9246, 2023-09-10](https://github.com/neomjs/neo/commit/16c92464186e143150f90bf2bbe0dc9be36877f3) introduced the shared floating layer and the dialog SelectField example (now ComboBox).
- [f43c92e, 2023-09-15](https://github.com/neomjs/neo/commit/f43c92efca252573d8d46419dd0eef0e27aabf50) added nested modal dialogs and main-thread mask synchronization. Current [DomAccess.syncModalMask](https://github.com/neomjs/neo/blob/94a7dd27e38224f08f4112880e0691f7693a9508/src/main/DomAccess.mjs#L1649) moves one shared mask immediately before the active modal; fallback selects the last remaining `.neo-modal` in DOM order or removes the mask.
- [f992e52](https://github.com/neomjs/neo/commit/f992e52c3894c677051a69166301f6ae3d187ede) adds main-thread mask-pointer prevention and per-dialog focus sentinels/TreeWalker wrapping. Picker Escape stops propagation. These are distinct from paint ordering and must be preserved.
- Picker containers and dialogs share `.neo-floating`1000. A picker mounts on BODY after its dialog; the shared mask is before the active dialog. The menu's inline100 overrides this common layer.

A second browser control changed only the menu to1000: it followed the dialog in BODY before and after the change, retained the identical rectangle, and changed from failing to passing hit testing. A larger1500 value is unnecessary for this default case. The unchanged `examples/dialog` opening/picker/focus/Escape checks also passed at three nested modal levels, with one correctly positioned mask and all pickers at1000. This is not a whole-example pass: automatic mask cleanup after header-close failed on the base; the existing main-thread fallback repaired it when called manually, and that caller/lifecycle issue is recorded separately.

Reconcile the root menu's conflicting inline default with the established floating layer and DOM-order mechanism. Preserve explicit `menu.zIndex` and a coherent cascade without letting background menus defeat the foreground modal mask. Keep the existing body portal, main-thread mask authority, focus and alignment responsibilities. No new popup manager, folder or mandatory application config is prescribed.
