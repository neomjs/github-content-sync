## The Problem

The one screenshot that explains it exists and is live: Neo's own 497 most recent issues in a grid whose rows fit their text, with headers that filter by checked values and a search toolbar — https://neomjs.com/examples/grid/issues/index.html.

## The Architectural Reality — what the post may claim, each with its receipt (source read at `dev` 4f286abbbe, Oct 30; area notes of Oct 24)

- **Where it runs:** the grid's logic lives in the App Worker, off the main thread; the DOM is a projection; in SharedWorker mode a grid moved into a second browser window keeps its state (the Workstation, 13.2).
- **Scale:** pooled rows and cells and buffered rows *and* columns (`src/grid/Body.mjs`, rebuilt June 2025); lazy record instantiation (the 10.5 release notes: 50k rows × 100 columns and 100k × 200 — the author re-verifies the millisecond figures at the source before quoting them); raw-object stores for streamed data (DevIndex).
- **Columns:** 15 column classes in `src/grid/column/` (tree, sparkline, progress, currency, animated change and currency, country flag, icon, icon link, index, component, GitHub user and orgs, LinkedIn, the base); locked start and end regions as separate bodies, moved between regions by width breakpoints (#9497); resizable and drag-reorderable headers; the header menu plugin.
- **Behaviour:** cell editing (`plugin/CellEditing.mjs`), animated row changes (`plugin/AnimateRows.mjs`), six selection models (`src/selection/grid/`: cell, row, column, cell-column, cell-row, cell-column-row), remote sort, filter and paging, ARIA grid roles, keyboard navigation.
- **13.3, the newest chapter:** content-sized rows (#19658 — heights measured by the browser in one hidden pre-render pass requested from a worker that has no DOM; the row you read holds still while measured heights replace estimates, #19674; proven at 10k rows, cells sized by text), header value menus with live counts (#19643; local data), the search toolbar (#19794); the issues showcase (`examples/grid/issues/`); 13.3.1's follow-ups (#20056, #20058, #20082).
- **Speed:** `neomjs/benchmarks` `COMBINED_BIG_DATA_REPORT.md` on `main` (4300c48, 2026-10-26 — Julia's re-run of the latest grid against the latest AG Grid, PR #5): neo 13.3.1 + `patches/neo.mjs-13.3.1-bigdata-hotpath.patch` (#20116, merged Oct 26, in the next release) vs React 19.1.1 + AG Grid Community 36.2.0 (`animateRows=false`), production bundles, **Chromium only**. Wins: 7.2× on 50→200 columns at 100k rows (150.26 vs 1,082.58 ms UI time), 3.0× on 1,000→100,000 rows (109.30 vs 327.04 ms), 1.8× on the first filter; **0.00 ms long-task blocking and 14.7–16.8 ms max RAF in all ten scenarios** vs 328.80 ms blocking / 378.44 ms stall and 59.60 ms / 90.02 ms on the two big updates. Losses, said in the post: the three scrolling trajectories 1.7–2.8× slower (the `isScrolling` latency, #20124 → #20125 merged after the run) and the second filter and clear by 6–11 ms. The author quotes the report, names the version pair and the browser, and links it.
- **Not in the MIT grid today, said plainly and without a roadmap:** row grouping, aggregation, pivot, export, clipboard, range selection, master/detail.
- **Images:** the 13.3.0 release images (`neomjs/pages` `resources_pub/website/release-notes/v13.3.0/grid-issues-{dark,light}.png`) and fresh captures of the showcase and of a grid in a popup window.
- **Authority:** `.agents/skills/blog-post/` (the hero-piece arc, every external claim sourced, the three over-claim flavors killed, the cross-family review bar); `learn/blog/<slug>.md` registered by hand in `apps/portal/resources/data/blog.json`; the SEO surfaces regenerate.

## The Fix

0. **The headline names the reader's problem and carries the search term — never the product name.** "Neo.mjs" lives in the byline and the body; a stranger knows neither the name nor why to care (the operator, 23:5x CET: a product-name headline creates zero traction — the first title of this ticket had one). **The hook is the benchmark's hard data, and the defensible claim is responsiveness, not "fastest"** (the operator, 00:1x CET: a title that sparks curiosity, backed by `neomjs/benchmarks` `COMBINED_BIG_DATA_REPORT.md`): the report on `main` (4300c48, Oct 26; neo 13.3.1 + the hot-path patch of #20116 vs React 19.1.1 + AG Grid Community 36.2.0, production bundles, Chromium) shows **0.00 ms long-task blocking and ~16.7 ms max RAF in every scenario** for neo against **328.80 ms blocking and a 378.44 ms frame stall** for React + AG Grid on the 50→200-column update at 100k rows, **7.2× faster** on that update and **3.0×** on 1,000→100,000 rows — and it also shows AG Grid **faster on the three scrolling trajectories (1.7–2.8×, a neo latency fixed in #20125 after the run) and on repeated filters by a few ms**. A "fastest data grid" headline is falsified by our own scrolling table; "the main thread never blocks" is not. Candidates for the author, with area G's term: *We put a data grid in a web worker. The main thread never blocked — React + AG Grid stalled 378 ms.* · *100,000 rows × 200 columns, and the page never freezes: a data grid that runs in a web worker* · *7× faster than AG Grid on the heaviest update, 0 ms main-thread blocking everywhere* · *Why our data grid never blocks the main thread (0 ms vs 378 ms at 100k rows, benchmark inside)*. The post says in paragraph one what was measured (Chromium, Community, production, the patch) and where AG Grid wins; that candor is the credibility the title spends. **The benchmark is one chapter, not the post** (the operator): the story is the grid — the worker, the scale, the columns and behaviours, the multi-window state, the showcase, 13.3's measuring — and the numbers are what the title spends to get the stranger to paragraph one. The cover shows the grid doing it, not a logo. **The worst-parse test on the chosen title (the operator, on the last Medium post):** *Multi-window web apps without syncing state* meant "the engine syncs for you, nested cross-window providers included" and strangers read "isolated windows, AI slop, no state" — nobody clicked. Read the title as a skeptical developer with zero context and take its worst honest parse; "without X" only before a cost (jank, blocking), never before a capability (syncing, state); state the benefit positively, with the number.
