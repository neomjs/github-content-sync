# Report every checked contrast pair for each theme scheme

Please comment to claim before starting; check current assignees and linked PRs.

## Context and problem

An author preparing a design brief needs the actual ratios, including the pairs that pass. Clio wrote a second script to obtain them. [Authoring report](https://github.com/neomjs/neo/discussions/22418#discussioncomment-19964719)

## The architectural reality

#22425 added a useful single-pair command. On the inspected dev revision, `--contrast text-default background-selected` returns 13.11:1 and 8.83:1 for Neo Light/Dark. The normal run gives a pass summary; `--theme all` selects palettes for one requested pair. [Existing CLI and pair evaluator](https://github.com/neomjs/neo/blob/2c6e9a4642c61765a49606bd102082e6eda38f83/buildScripts/util/check-theme-palette.mjs)

## The fix

Add an opt-in complete report to the existing palette check. Enumerate its registered CONTRAST_PAIRS and evaluate both schemes of the selected theme(s) using the guard’s parser, cascade resolution, alpha compositing and ratio calculation. Document a command an author can run on their pair.

## Acceptance criteria

- [ ] Each checked pair in each matching scheme gets a row with theme class, scheme, foreground, background, measured ratio, required floor and verdict. Report all rows on both passing and failing palettes; use unrounded values for threshold decisions.
- [ ] Match the single-pair result for opaque and translucent pairs. A deliberately weak pair is visibly identified and fails validation; an unresolvable pair or unknown theme has an explicit diagnostic.
- [ ] Keep ordinary guard and existing single-pair CLI behavior intact. A report for a custom pair and a multiple-theme run are covered. Use the registered list dynamically as the palette contract grows, and avoid reparsing the entire CSS tree once per output row.
