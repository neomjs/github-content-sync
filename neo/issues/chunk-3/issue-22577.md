# theme-base: bind apps/docs sheets and classdetails colours to roles

## Context

Step 6 of #22295 (#22484) includes the `apps/docs` stylesheet projection (`6` file pairs, `30` custom properties in `resources/css/theme-neo-{light,dark}/apps/docs/`, carrying `10` `--neo-sem-*` reads in `theme-neo-dark` that block Step 8 removal of `theme-neo-{light,dark}`). `Docs.view.MainContainer` renders standalone via `docs/index.html` and inside the Portal's `/docs` route (`apps/portal/view/Viewport.mjs:58`) under `neo-theme-neo-light` and `neo-theme-neo-dark`.

In addition to the 30 theme-sheet variables, `resources/css/src/apps/docs/classdetails/{HeaderComponent,HierarchyTreeList,MembersList,TutorialComponent}.css` still hardcodes 2019 Classic-Dark colours and letterpress shadows (`color: rgba(0,0,0,0.6)` on `.neo-docs-header-text`, `.neo-list-item-header`, and `.neo-header-text`, painting dark-on-dark class and member headings in `neo-theme-neo-dark`; `#282b2b` and `#3c3f41` borders; `a { color: #bbb }` at `1.92:1` on light surfaces; and `0 5px 10px rgba(0,0,0,.4)` box shadows), while `--docs-classdetails-headerpanel-border-right` is unread across the entire repository (`resources/css/src/apps/docs/classdetails/MainContainer.css:3` sets `border: 0`, accounting for the sole `1 of 186` and `1 of 50` unread `apps` variable in `npm run theme-census`).

## The Problem

1. `theme-neo-light` and `theme-neo-dark` duplicate 30 `--docs-*` variables across 12 files, reading 10 legacy `--neo-sem-*` tokens in dark mode and failing WCAG AA on source links (`#bbb` on `#fff` = `1.92:1`) and search highlights (raw `red` text without a subtle fill).
2. A theme generated via `create-theme --base theme-neo` inherits zero `--neo-docs-*` values until `apps/docs` moves to `theme-base`.
3. Bare colours in `resources/css/src/apps/docs/classdetails/*.css` bypass the theme layer completely, leaving class titles and member headers (`rgba(0,0,0,0.6)`) near-invisible in `neo-theme-neo-dark` and tutorial links (`#bbb`) unreadable in `neo-theme-neo-light`.

## The Architectural Reality

[ADR 0044](learn/agentos/decisions/0044-design-system.md) (§2.1, §2.4, §2.6) assigns `apps/*` structural and theme projections to `neo.apps`, requires `--neo-` prefixed custom properties with CSS-property suffixes and state words last, and binds `theme-base` component variables exclusively to roles (plus single-role `transparent` mixes, keywords, and listed geometry literals; #22571). Under #22295 Rules 9, 12, 16, 17, 18, and 23:
- Unread variables (`--docs-classdetails-headerpanel-border-right`) are dropped (Rule 9) and recorded with `"dropped": true` in `buildScripts/util/theme-variable-renames-apps-and-examples.json` (#22483 / Rule 12).
- App and header bars read `--neo-color-background-surface-raised` with neutral chrome text `--neo-color-text-default` (Rules 17, 18).
- List search matches (`.neo-highlight-search`) read `--neo-color-background-brand-subtle` + `--neo-color-text-strong` (Rule 23).
- Classic `theme-light` and `theme-dark` keep their `:root .neo-theme-{light,dark}` rules (`(0,2,0)` outranking `[class*="neo-theme-"]` `(0,1,0)` inside `neo.apps`), preserving 100% Classic computed-style parity including the extracted `classdetails` legacy values.

Design authority: [ADR 0044 §2.1, §2.4, §2.6](learn/agentos/decisions/0044-design-system.md#2-decision) and #22295 Step 6 Rules 5, 9, 12, 16, 17, 18, and 23.

## The Fix

1. Add the 30 `--docs-*` entries (`29` `--neo-docs-*` renames + `1` `"dropped": true` entry for unread `--docs-classdetails-headerpanel-border-right`) to `buildScripts/util/theme-variable-renames-apps-and-examples.json` and run `rename-theme-variables.mjs --map buildScripts/util/theme-variable-renames-apps-and-examples.json`.
2. Replace the remaining bare colours and Classic-Dark letterpress properties in `resources/css/src/apps/docs/classdetails/{HeaderComponent,HierarchyTreeList,MembersList,TutorialComponent}.css` with `--neo-docs-*` component variables, add Rule 23's `--neo-docs-param-table-list-item-highlight-search-background-color` on `.neo-highlight-search`, and preserve Classic Light/Dark's exact values in `resources/css/theme-{light,dark}/apps/docs/**/*.css` (removing the unread `--docs-classdetails-headerpanel-border-right` line there too).
3. Create the 7 `resources/css/theme-base/apps/docs/{ContentTabContainer,HeaderContainer,MainContainer,classdetails/{HeaderComponent,HierarchyTreeList,MembersList,TutorialComponent}}.css` sheets on `[class*="neo-theme-"]` and delete the 12 `resources/css/theme-neo-{light,dark}/apps/docs/**/*.css` sheets.

- [ ] `buildScripts/util/theme-variable-renames-apps-and-examples.json` records all 30 `--docs-*` entries (`29` renames + `1` `"dropped": true`) and passes `node ./buildScripts/util/rename-theme-variables.mjs --check --map buildScripts/util/theme-variable-renames-apps-and-examples.json` alongside all 8 `check-theme-*` guards, `theme-equality`, and `WorkstationPaletteBridgeNL`.
- [ ] Classic `theme-light` and `theme-dark` preserve their exact legacy `apps/docs` values (`:root .neo-theme-{light,dark}` in `neo.apps`), while released-vs-head light and dark frames of the Docs view (`neo-theme-neo-light` and `neo-theme-neo-dark`) show legible class/member headings, `>= 4.5:1` source links, and Rule 23 member search highlights.

## Out of Scope

- Shared HighlightJS syntax styling (`util/HighlightJs.css`, owned by #22530) and shared `app/content` learn reader (`src/app/content/*`, owned by #22534).
- Structural layout or routing changes to `docs/app/` (the second docs app remains deferred per `ROADMAP.md`).

## Avoided Traps

- **Binding `.neo-docs-memberlist-group-header` to `background-accent`:** Under Rules 17 and 24, tooltip is the sole non-acting accent fill; section group headers (`Configs`, `Methods`) are passive chrome and read `background-surface-raised` + `text-default`.
- **Leaving bare `rgba(0,0,0,0.6)` and `#282b2b` in `src/apps/docs/classdetails/*.css`:** Moving only the 30 existing `--docs-*` variables would leave class titles and member names painted black-on-dark in `neo-theme-neo-dark`.
