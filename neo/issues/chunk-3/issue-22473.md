# Style dirty field values and clear their cue on baseline reset

Please comment to claim before starting; check current assignees and linked PRs.

## Context and problem

A changed form value should be able to read as “pencil” until the app accepts it. The hint and placeholder still need a distinct appearance. [Clio’s field treatment](https://github.com/neomjs/neo/discussions/22418#discussioncomment-19964363)

## The architectural reality

[form.field.Base](https://github.com/neomjs/neo/blob/2c6e9a4642c61765a49606bd102082e6eda38f83/src/form/field/Base.mjs#L124) already compares the submit value to the original value for `isDirty`. [Text](https://github.com/neomjs/neo/blob/2c6e9a4642c61765a49606bd102082e6eda38f83/src/form/field/Text.mjs#L1019) toggles `neo-is-dirty` on a value change. In a real field, editing A → B and calling `field.reset('B')` makes `isDirty` false but can leave that class on the field when its value setter sees the same value. Form submission alone does not acknowledge persistence. #22368/#22445 own the shared typography and color bindings.

## The fix

Make the dirty-state projection follow the existing reset/dirty contract, and supply themeable text color and font style on the real input value. Stock defaults should preserve ordinary value styling. Keep validation, hints and placeholders legible as distinct states.

## Acceptance criteria

- [ ] Edit and blur a field; an opt-in theme can distinguish its changed value by color and font style without recoloring the label, placeholder, or error message. Exercise direct and trigger-wrapped Text fields in light and dark.
- [ ] Calling reset with the current edited value clears isDirty, the class and the visible cue. Reverting to the original value and resetting to a different accepted value also clear the cue.
- [ ] Confirm the chosen focus, invalid, readonly and disabled behavior on the real control and verify an alternate nested theme restores its defaults. No application save callback is required just to display native dirty state.

## Contract ledger

| Surface | Authority | Behavior | Compatibility | Evidence |
|---|---|---|---|---|
| Form field dirty baseline and Text value styling | Base.isDirty/reset and Text state class | Project and style an outstanding edit | Ordinary stock value style | Edit/blur/reset, placeholder and state controls |
