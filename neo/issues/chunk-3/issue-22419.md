# A persistent bottom sheet that snaps between heights

Owned by @neo-opus-grace. A leaf of #22414 (mobile components).

## Context

On a phone, secondary content sits in a sheet that the user drags up from the bottom edge: a map's details, filters, a player. D#22259 G2 names "the swipeable sheet" as the component stream's first build, starting on existing Engine primitives.

## The Problem

Neo has no non-modal sheet. `dialog.Base` is draggable and resizable (`src/dialog/Base.mjs:74-86`, a lazily imported `Neo.draggable.DragZone`), but it is a floating window that drags a proxy. It has no snap positions, no handle that maps a vertical drag to a height, and no bottom anchoring inside the safe area.

## The Architectural Reality

- **The drag-to-height primitive exists.** `Neo.component.Splitter` with `liveResize` resizes a sibling on Main. A `DragZone` with `useProxy: false` registers a `resizeConfig`; `Neo.main.draggable.Resize` writes the target's `height` on every pointer frame, clamped to its computed `min-height`/`max-height`; App receives one terminal size on `drag:end`. With `awaitWorkerSettlement`, App then accepts that size or has Main restore the start (`DragZone#settleResize`, as `DockSplitter` does).
- **Ownership per ADR 0045 decision 1 (PR #22412):** motion follows the finger on Main, and App decides the snap point on release. That is the split above. The sheet moves to `pan` events once #22405 lands.
- **The sensor** (`src/main/draggable/sensor/Pointer.mjs`) arms a mouse drag after 100 ms and 5 px, a touch drag after a 200 ms hold. While Main resizes, `drag:move` reaches App only with `alwaysFireDragMove`. Each event carries `clientY` and `timeStamp`, which is enough for a release velocity.
- **First paint:** a `floating` component sits at -10000px until it is aligned (`resources/css/src/component/Base.css`). The sheet is not floating. It is `position: fixed` at the bottom, and its inline height is its snap point from the first render.
- **Motion roles** exist in all five themes since #22413, and `src/Global.css` zeroes their durations for reduced motion.
- **Namespace:** the interaction domain a reader searches for, independent of the base class. Precedent: `Neo.button.Segmented` lives in `button` and extends `Neo.toolbar.Base`.

Design authority: n/a — a new component; it calls no existing behavior wrong.

## The Fix

`Neo.sheet.Base` (`src/sheet/Base.mjs`, ntype `sheet`) extends `container.Base`. `Neo.sheet.Handle` (`src/sheet/Handle.mjs`, ntype `sheet-handle`) extends `component.Base`.

- **`snapPoints_`:** ascending heights, each a Number in px or a CSS length String (`'50dvh'`, `'20rem'`). A percentage is refused, because App cannot compute a px value for a fixed sheet's percentage.
- **`snapIndex_`:** the current point, the reactive state App owns. The sheet's inline `height` is `snapPoints[snapIndex]`. Its `min-height` and `max-height` are the first and last points, so a drag stays inside the range.
- **The handle** is `Neo.sheet.Handle`, the shared seam #22421 reuses: a full-width bar with a grip.
  - A vertical drag resizes its `target` on Main.
  - On release, the handle reports the terminal height and the release velocity that Main measured: App sees no frame in between, and `drag:start` carries the press, too old for a velocity. The owner resolves the snap point with the static `Neo.sheet.Handle.resolveSnapIndex()` and settles: App accepts the size when the point changed, and Main restores it when the point did not.
  - A cancel restores the start on Main.
  - Keyboard follows the APG window splitter: `role="separator"`, focusable, `aria-valuenow` = `snapIndex`. Arrow Up and Arrow Down step, and Home and End go to the first and last point.
- **Settle rule:** a release slower than `flingVelocity` (px/ms, default 0.5) settles on the nearest point. A faster one settles on the next point past the release height in its direction: exactly one point, however fast.
- **The visible control:** a button at the end of the header. It expands one point at a time, and at the top point it collapses to the first.
- **Content:** it scrolls natively inside the sheet's body. Only the handle carries `neo-draggable` and `touch-action: none`.
- **Styling:** structural CSS in `resources/css/src/sheet/Base.css` and `Handle.css`.
  - Component variables bind ADR 0044 roles in the neo pair.
  - Light, dark and cyberpunk carry literals like their siblings.
  - All five themes bind the motion roles.
  - The safe-area inset pads the bottom.
  - No transition runs while `neo-drag-active` brackets a gesture, so Main's frames are never animated.
- **Example:** a phone example, `examples/sheet/base/`.

## Acceptance Criteria

- [ ] `Neo.sheet.Base` with `snapPoints` and `snapIndex` as reactive configs, with JSDoc and `@summary`.
- [ ] Releasing a drag settles on the nearest point; a fast release moves exactly one step in its direction; a cancel restores the start point (unit spec on the settle rule, real-browser receipt on the drag).
- [ ] Arrow keys on the handle and the visible control reach every snap point without a pointer.
- [ ] Content inside the sheet scrolls without moving the sheet.
- [ ] The first paint shows the sheet at its initial snap point: no frame off-screen, no jump.
- [ ] No literal colour, radius, shadow or duration in the structural CSS; the theme guards pass.
- [ ] Phone example frames at 390 px in light and dark, at two snap points.

## Out of Scope

- The modal form's sheet presentation (#22421), which reuses `Neo.sheet.Handle`.
- Gesture events (#22400). Until `pan` (#22405) replaces the sensor here, a touch drag on the handle arms after the sensor's 200 ms hold, so a quick flick does not drag.

## Avoided Traps

- **A proxy drag, as `dialog.Base` does:** it would clone the sheet and its content on every gesture. The sheet resizes itself.
- **App-side motion from `drag:move`:** every frame would cross to App before it paints. App reads the moves only for the release velocity.
- **A per-target touch delay in the sensor:** a new surface that the `pan` gesture retires.
