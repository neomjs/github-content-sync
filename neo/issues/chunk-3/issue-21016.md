# A pressed Effect button never tells assistive technology it is pressed

## Context

#20829 asked that a pressed button tell assistive technology it is pressed. PR #20833 (merged 2026-11-12) did that for `Neo.button.Base`, and kept the tab headers on `aria-selected`. The effect-based button, `Neo.button.Effect`, was not in #20829's scope and still has the gap. This was found while triaging PR #21015, which carries a fix for it.

## The Problem

Assistive technology announces a toggle built on `Neo.button.Effect` as a plain button: its pressed state never reaches it. `pressed_` defaults to `false`, so a plain Effect button and an unpressed toggle cannot be told apart. That is why `Neo.button.Base` moved its default to `null`.

## The Architectural Reality

- **`src/button/Effect.mjs`:**
  - `pressed_: false` (`:107`).
  - `getVdomCls()` toggles the `pressed` class (`:215`).
  - `getVdomConfig()` (`:227`) builds the root VDOM from the configs and writes no `aria-*`.
- **`src/tab/header/EffectButton.mjs`** (`Neo.tab.header.EffectButton`, `role="tab"`) extends it. It takes `super.getVdomConfig()` and sets `aria-selected` from `pressed`. ARIA does not allow `aria-pressed` on `role="tab"`, so whatever the base adds, this subclass must not carry it (#20829's ledger row for the tab headers).
- **`Design authority:`** #20829's premise, and the Contract Ledger that #20833 shipped for `Neo.button.Base`. `null` marks a plain button. A Boolean marks a toggle and renders `aria-pressed`.

## The Fix

- **`Neo.button.Effect`:**
  - `pressed_` defaults to `null`.
  - `getVdomCls()` toggles `pressed` for `pressed === true`.
  - `getVdomConfig()` renders `aria-pressed` as `String(pressed)` for a Boolean and leaves it out for `null`.
  - The VDOM derives from the configs in one effect, so the class and the attribute change in the same update.
- **`Neo.tab.header.EffectButton#getVdomConfig()`:** removes `aria-pressed` beside setting `aria-selected`.

## Acceptance Criteria

- [ ] A `Neo.button.Effect` without `pressed` renders no `aria-pressed`. `pressed: false` renders `aria-pressed="false"` and `pressed: true` renders `"true"`, and a change of `pressed` updates the class and the attribute together (unit).
- [ ] A `Neo.tab.header.EffectButton` renders `aria-selected` and no `aria-pressed`, pressed or not (unit).
- [ ] The existing button and tab unit specs pass unchanged (receipt).

## Out of Scope

- `Neo.button.Base`, `Neo.tab.header.Button` and the grid search toolbar: done in #20833.
- `aria-expanded` on menu buttons, and toggle groups (as in #20829).

## Avoided Traps

- `aria-pressed` on every Effect button: it announces plain buttons as toggles.
- Letting `Neo.tab.header.EffectButton` inherit the attribute: a tab's state is its selection.
