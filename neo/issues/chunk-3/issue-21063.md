# Web desktop: sign-in, launcher and start menu follow permissions

## Context

First app leaf of #21061. It answers the community question the epic describes: navigation that follows the signed-in account's permissions, with one store, one filter and no component per permission. Windows and drag and drop are sibling leaves built on this one.

## The Problem

No app in `apps/` shows navigation that depends on who signed in. The pattern needs a home a stranger can run, read in a few files, and copy.

## The Architectural Reality

Design authority: n/a — a new app; it calls no existing behavior wrong.

- App gate (`AGENTS.md` authoring gate): data UI binds a `data.Store` of `data.Model` records, providers stay at view roots, styles stay in SCSS. Siblings: `apps/email` (`ViewportStateProvider`), `apps/workstation` (app-owned theme files under `resources/scss/theme-neo-*/apps/workstation/`).
- `state.Provider#onDataPropertyChange(key, value, oldValue)` (`src/state/Provider.mjs:812-814`) is the subclass hook where the provider writes the granted keys into the permission filter.
- `collection.Filter`: `operator: 'included'` keeps a record whose `permission` is in `value` (`src/collection/Filter.mjs:374-376`); with the default `includeEmptyValues: true` an empty `value` makes the filter ineffective (`src/collection/Filter.mjs:114-120`, `243-245`), so the app sets it to `false`.
- `data.TreeStore#filter()` keeps the ancestors of kept nodes (`src/data/TreeStore.mjs:588-713`): a group without a permission shows exactly when one of its apps does.
- `list.Base` re-renders on its store's `filter` event (`src/list/Base.mjs:402-414`); `menu.List` cascades over a TreeStore, and its levels honor the filter once #21062 lands.

## The Fix

New app `apps/webdesktop/` (namespace `WebDesktop`):

- `app.mjs`, `index.html`, `neo-config.json` (themes `neo-theme-neo-dark`, `neo-theme-neo-light`), `README.md`.
- `model/App.mjs` (a TreeModel: `id`, `text`, `iconCls`, `permission`, `description`), `model/Account.mjs`.
- `store/Apps.mjs` (the TreeStore: catalog plus the permission filter), `store/Accounts.mjs` (`url` → `resources/data/accounts.json`).
- `view/Viewport.mjs`, `view/ViewportStateProvider.mjs` (account, permissions, stores), `view/ViewportController.mjs` (sign in and out).
- `view/SignIn.mjs` (account cards from the accounts store), `view/Desktop.mjs`, `view/Launcher.mjs` (`list.Base` subclass: group rows as section headers, apps as icons), `view/Taskbar.mjs` (start button → `menu.List` over the apps store; account button → Sign out), `view/PermissionsPanel.mjs` (live permission toggles).
- SCSS: `resources/scss/src/apps/webdesktop/` plus `resources/scss/theme-neo-dark/apps/webdesktop/` and `theme-neo-light/apps/webdesktop/`.
- Portal: an entry in `apps/portal/resources/data/examples.json` naming what the demo proves.

## Acceptance Criteria

- [ ] `apps/webdesktop/index.html` boots on `dev` in both neo themes (dark by default) without console errors.
- [ ] The sign-in screen lists the demo accounts read from `resources/data/accounts.json` through a store `url`; choosing one signs in.
- [ ] Each account sees exactly its permitted apps in the launcher, in the start menu and in every submenu; a group without a permitted app is absent from both (real-browser screenshot per account).
- [ ] An account with no permissions sees an empty desktop, proven by a unit test that also shows the default `includeEmptyValues: true` would have shown every app.
- [ ] Toggling a permission in the permissions panel updates launcher and menus in place; the view instances survive (unit test on the provider → filter path, browser witness for the views).
- [ ] Signing out returns to the sign-in screen and leaves no permission granted.
- [ ] Visibility is decided in one place, the apps store's filter; no view decides whether an app shows.
- [ ] README: what the demo proves, how to run it, and that hiding UI is not authorization.
- [ ] Portal examples entry whose `feature` and `lookFor` name the proof.
- [ ] Unit specs green under `npm run test-unit`.

## Out of Scope

- Windows and the taskbar window list (sibling leaf), drag and drop (sibling leaf).
- Authentication with credentials.
