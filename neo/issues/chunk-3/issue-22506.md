# Fix TextField inline label top-border notch across mount and resize

Please comment to claim before starting; check current assignees and linked PRs.
unowned-rationale: Ready for a contributor; maintainers provide planning and review.

## Context

Post-merge visual inspection of `#22445` (`#22368`, [`form-states-dark-head.png`](https://github.com/neomjs/neo/blob/f4d05e84a294f6504487944b9c4a2d3e49997e29/review-evidence/22368/form-states-dark-head.png?raw=true), row 3 column 3 `TextField [inline] — floating label`) exposed a broken top border on `Neo.form.field.Text` with `labelPosition: 'inline'`: `.neo-center-border` carries an inline `style="width: 190px"` on a `260px` field while the floated `"Inline"` label is only `~31.4px` wide, leaving `~158px` of missing top border across the center of the input.

## The Problem

`Neo.form.field.Text` currently sizes `.neo-center-border`'s top-border cut-out in JavaScript (`src/form/field/Text.mjs:1748-1769`, `updateCenterBorderElWidth`) because `.neo-textfield-label` shrinks visually via `transform: translateX(4px) translateY(...) scale(.7)` (`resources/css/src/form/field/Text.css:322,333`), which leaves `<label>`'s DOM layout box unscaled. Four distinct defects in that JS measurement path break the top border across mount, state transitions, and resize:

1. **Measures `<div class="neo-center-border">` instead of `<label>` (`src/form/field/Text.mjs:1750-1765`):**
   - `updateCenterBorderElWidth()` calls `me.getDomRect(centerBorderEl.id)`. Whenever `afterSetMounted` runs before `Text.css` is applied (e.g. `themes: []` in `test/playwright/component/apps/theme-equality/neo-config.json:7`, dynamic stylesheet swaps, or async `<link>` loading on boot via `Neo.main.addon.Stylesheet`), `<div class="neo-center-border">` is UA `display: block` at `100%` of the `260px` field width (even though `<label>` is `display: inline` at `37.3px`), permanently stamping `Math.round(260 * 0.7) + 8 = 190` (`style="width: 190px"`) onto `.neo-center-border`.
   - Even after CSS loads, once `borderEl.width` is written onto `centerBorderEl`, any subsequent `updateCenterBorderElWidth()` call without first clearing `borderEl.width` measures `centerBorderEl`'s own stamped `style.width` instead of the label text's intrinsic width.
2. **Stamps floated cut-out width onto empty unfloated fields at mount (`src/form/field/Text.mjs:794-797`):**
   - `afterSetMounted(true)` calls `me.updateCenterBorderElWidth()` with `silent = false` even when `me.isEmpty()` is `true` and `.neo-textfield-label` is unfloated at `1.0x` width.
3. **Programmatic `value` and `placeholderText` writes miss `.neo-center-border` restoration (`src/form/field/Text.mjs:811-823,1004-1028,1561-1564`):**
   - `onFocusLeave` on an empty inline field deletes `centerBorderEl.width` (`:1563`). Subsequent programmatic `field.value = 'Neo'` (`afterSetInputValue` adding `.neo-has-content`) or `field.placeholderText = '...'` (`afterSetPlaceholderText` adding `.neo-has-content`) floats the label and sets `border-top-color: transparent !important` on `.neo-center-border` without restoring a cut-out width.
4. **No reactivity on field/container resize, font load, or theme typography changes:**
   - The one-shot pixel `style.width` never updates when a fluid inline field resizes narrower than the label, when webfonts finish loading, or when a theme changes `--neo-textfield-input-font-size`.

## The Architectural Reality

- `resources/css/src/form/field/Text.css:289-395` renders `.label-inline > .neo-label-wrapper` as a three-segment flex overlay (`.neo-left-border` `flex: 0 0 auto`, `.neo-center-border` wrapping `<label class="neo-textfield-label">`, and `.neo-right-border` `flex: 1 0 auto`). When unfocused and empty, all three segments paint the same top border; when `.neo-focus` or `.neo-has-content` is active, `.neo-center-border` sets `border-top-color: transparent !important` so the floated label sits inside the top-border notch.
- Shrinking the floated `<label>`'s actual layout box in CSS (`font-size: .7em; padding-inline: 4px; transform: translateY(calc(-62% - 0.5 * var(--neo-textfield-border-top-width)));` with `.neo-center-border { display: flex; flex: 0 1 auto; min-width: 0; }` and `.neo-textfield-label { overflow: hidden; text-overflow: ellipsis; }`) sizes `.neo-center-border` to the exact floated label width (`31.44px` on `"Inline"`, leaving `216.56px` `.neo-right-border` at `260px` and `76.56px` at `120px`) natively in the browser layout engine across stylesheet load order, programmatic `value`/`placeholderText`, font load, and container resizing — eliminating the need for Main-thread `getDomRect` roundtrips and `timeout(20)` timers (`#22290`'s `Out of Scope` explicitly left inline cut-out math and CSS layout to a dedicated fix).
- `test/playwright/unit/form/field/TextDisabled.spec.mjs:103,241-370` and `test/playwright/unit/calendar/WeekView.spec.mjs:810` currently stub or assert `centerBorderElWidth` / `updateCenterBorderElWidth`.
- Design authority: `resources/css/src/form/field/Text.css:304-339,347-379` (`.label-inline` `.neo-center-border` opens a `border-top-color: transparent` notch matching the floated `.neo-textfield-label` width while `.neo-left-border` and `.neo-right-border` close the remaining top border).

## The Fix

1. In `resources/css/src/form/field/Text.css` (`.neo-textfield.label-inline`):
   - Make `.neo-label-wrapper .neo-center-border` size to its child label with truncation safety on narrow widths (`display: flex; flex: 0 1 auto; min-width: 0;`) and set `overflow: hidden; text-overflow: ellipsis;` on `.neo-textfield-label`.
   - In `&.neo-focus .neo-textfield-label` and `&.neo-has-content .neo-textfield-label`, replace `transform: translateX(4px) translateY(...) scale(.7)` with layout-sizing `font-size: .7em; padding-inline: 4px; transform: translateY(calc(-62% - 0.5 * var(--neo-textfield-border-top-width)));` (updating `transition` on `.neo-textfield-label` so focus/blur remains smooth without leaving an unscaled layout gap).
2. In `src/form/field/Text.mjs` (`Accretion Defense`):
   - Retire the obsolete JS cut-out width measurement plumbing (`centerBorderElWidth_`, `#centerBorderRequestId`, `beforeSetCenterBorderElWidth`, `updateCenterBorderElWidth`, the `timeout(20)` call in `afterSetLabelPosition`, and manual `centerBorderEl.width` writes/deletes in `afterSetDisabled`, `afterSetLabelText`, `afterSetMounted`, `onFocusEnter`, and `onFocusLeave`), keeping `getCenterBorderEl()` for `afterSetHideLabel`.
   - Update `test/playwright/unit/form/field/TextDisabled.spec.mjs` and `test/playwright/unit/calendar/WeekView.spec.mjs:810` to match the CSS-owned inline cut-out contract.
3. Rebuild themes (`node buildScripts/build/themes.mjs -n -e dev -t all`), run `npm run theme-equality`, and add a headless-Chromium component spec asserting `.neo-center-border` width matches the floated `.neo-textfield-label` width (within `<= 2px`) across:
   - initial mount with `value: 'Neo'` both when CSS loads before mount and when CSS attaches after mount (`themes: []` -> stylesheet injection),
   - empty mount -> focus -> blur -> programmatic `value = 'Neo'` and `placeholderText = 'Hint'`,
   - dynamic width resize (`260px -> 120px -> 72px` with label ellipsis and unbroken `.neo-left-border` / `.neo-right-border`).

## Acceptance Criteria

- [ ] AC-1: On `Neo.form.field.Text` with `labelPosition: 'inline'`, `.neo-center-border`'s rendered width matches the floated `.neo-textfield-label` width (no oversized missing top-border gap) whether stylesheets load before or after component mount (including `#eq-cell-textfield-inline` in `theme-equality`).
- [ ] AC-2: Transitioning an empty mounted inline `TextField` via focus, blur, programmatic `value = '...'`, `clear()`, and `placeholderText = '...'` opens and closes the top-border notch cleanly without border strikethrough or trailing top-border gaps.
- [ ] AC-3: Resizing an inline `TextField` (e.g. `260px -> 120px` and narrower than the label) keeps `.neo-left-border`, `.neo-center-border`, and `.neo-right-border` within `100%` of `.neo-label-wrapper` without horizontal overflow, truncating long floated labels cleanly.
- [ ] AC-4: Obsolete Main-thread `getDomRect` inline border measurement code in `src/form/field/Text.mjs` is retired (or any retained compatibility shim documented in `Deltas from ticket`), `node buildScripts/build/themes.mjs -n -e dev -t all`, unit tests, `npm run theme-equality`, and the new headless-Chromium component spec pass.

## Out of Scope

- Vertical stretching of `.neo-field-trigger` on taller `TextField` heights (tracked in the companion follow-up issue).
- `SelectField` or `ComboBox` non-inline label layouts.

## Avoided Traps

- Fixing only `getDomRect(centerBorderEl.id)` -> `getDomRect(me.getLabelId())` while keeping one-shot JS pixel stamping: although measuring `<label>` avoids the `260px -> 190px` block-div measurement when `themes: []` is active, a static `style.width` still goes stale on container resize, webfont load, theme font-size changes, and programmatic `afterSetPlaceholderText` / `afterSetInputValue` transitions after blur.
- Keeping `transform: scale(.7)` alongside `font-size: .7em`, which would double-shrink the floated label to `0.49x`.
