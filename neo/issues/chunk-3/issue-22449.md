# Wait for the primary app in the multi-window gesture spec

## Context

The v14.1 multi-window gesture acceptance spec can fail before any gesture runs. The Engine shard on the persistent sheet PR failed at the first primary-window probe. The App Worker logged `Cannot read properties of undefined (reading 'mainView')`. [Hosted failure](https://github.com/neomjs/neo/actions/runs/46082822652/job/140785691742)

## The Problem

The spec waits for the SharedWorker to answer, then injects a probe into the primary app. With delayed app startup, the worker answers while the primary app is absent. On exact dev `49e7e53866`, injecting `loadApplicationDelay: 1500` into the primary example's config in a disposable Chromium run made the old ordering fail with the same error. Waiting for the opener under the same delay reached both windows' expected gesture terminals.

## The Architectural Reality

Worker connection and application startup are separate. The source window exposes its own readiness through the rendered **Open second window** button. The companion already waits for its **Edit user** button before mounting its probe. The sibling state-sharing spec uses the source opener as well. [Gesture spec](https://github.com/neomjs/neo/blob/49e7e5386679a2542fdd9b70bc2bf2450ce1d8a2/test/playwright/e2e/core/GestureOwnershipMultiWindow.spec.mjs#L65) · [Sibling spec](https://github.com/neomjs/neo/blob/49e7e5386679a2542fdd9b70bc2bf2450ce1d8a2/test/playwright/e2e/core/SharedStateMultiWindow.spec.mjs#L59)

## The Fix

Wait for the source opener before calling `addGestureProbe` in `GestureOwnershipMultiWindow.spec.mjs`. Reuse the locator to open the popup.

## Acceptance Criteria

- [ ] AC-1: A controlled late primary-app start reproduces the probe failure on the previous spec and passes with the opener readiness check.
- [ ] AC-2: The standard spec still observes the same SharedWorker and both windows' expected gesture phases, including cancellation after popup loss.

## Out of Scope

The production worker and gesture lifecycles stay under their existing owners. The delayed config is a disposable test control.
