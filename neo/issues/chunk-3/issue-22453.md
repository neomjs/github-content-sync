# Keep an explicitly themed subtree when its parent switches through the same theme

## The problem

An app can give one container its own theme and let its siblings inherit. On `dev` at `ab98a1fb22`, start with a Neo Dark parent and a Neo Light child. Switch the parent to Neo Light, then back to Neo Dark. The child and grandchild end up dark. The unconfigured sibling correctly follows both changes.

## The architectural reality

Design authority: `Neo.component.Base#theme` lets an application “style specific component trees differently from your main view.” The container’s creation path already gives the item config, item defaults and class default precedence over the parent. The live cascade and instance adoption infer ownership by comparing the two effective values. Equality loses the original choice. [Theme config](https://github.com/neomjs/neo/blob/ab98a1fb22/src/component/Base.mjs#L285) · [Live propagation](https://github.com/neomjs/neo/blob/ab98a1fb22/src/container/Base.mjs#L299) · [Decision 7](https://github.com/neomjs/neo/blob/ab98a1fb22/learn/agentos/decisions/0044-design-system.md#L76)

Earlier adoption work explicitly deferred equal-valued theme ownership. The Material exercise reproduced the limitation using the two shipping Neo themes. [Adoption precedent](https://github.com/neomjs/neo/issues/18672) · [Retained tabs](https://github.com/neomjs/neo/issues/22428)

## The fix

Preserve whether a managed item declared or inherited its theme in the existing component and container paths. Honor a new assignment to a managed item, including one equal to the current inherited value. Clearing the choice resumes inheritance. Existing component owners continue to supply themes to floating widgets and pooled rows.

## Acceptance criteria

- [ ] An explicitly themed child and its descendants retain Neo Light while the parent goes dark → light → dark. A sibling with no local choice follows both switches.
- [ ] An explicit item, item default or class default initially equal to the parent's theme keeps its choice on the next switch. A managed item can pin its current value, move containers and clear that choice.
- [ ] Existing first-adoption behavior for an unmanaged instance whose theme already matches its destination is preserved. A grid switch adds no theme classes to pooled rows relative to the release base.

## Contract ledger

| Surface | Observable contract |
|---|---|
| `Neo.component.Base#theme`, `getTheme()` | Assigning a theme to a container item gives its subtree its own theme, even when the value matches the container's current theme. Assigning `null` to the item resumes inheritance from its container. When the container switches themes, only inheriting items follow the switch. |
| `Neo.container.Base#createItem`, `afterSetTheme` | Existing precedence and adoption behavior hold. Parent updates reach inheriting items. |
