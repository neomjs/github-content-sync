# Stretch field triggers and input boxes to taller TextField heights

Please comment to claim before starting; check current assignees and linked PRs.
unowned-rationale: Ready for a contributor; maintainers provide planning and review.

## Context

Post-merge visual review of `#22445` (`#22368`, [`form-states-dark-head.png`](https://github.com/neomjs/neo/blob/f4d05e84a294f6504487944b9c4a2d3e49997e29/review-evidence/22368/form-states-dark-head.png?raw=true), row 2 column 1 `TextField — focus`) surfaced a broken trigger border whenever a `Neo.form.field.Text` (or trigger-bearing subclass) renders taller than the default `25px` `--neo-textfield-input-height`: `.neo-input-wrapper` expands vertically while `.neo-field-trigger` stays pinned at `25px` in the top corner, severing `border-left` / `border-right` mid-way down the input box and leaving the trigger glyph and hover fill uncentered at the top edge.

## The Problem

1. **Fixed trigger height defeats flex stretch (`resources/css/src/form/field/trigger/Base.css:9,11`):**
   - `.neo-input-wrapper` (`resources/css/src/form/field/Text.css:409-419`) sets `display: flex; align-items: stretch; min-height: var(--neo-textfield-input-height); overflow: hidden;`, and its child `<input class="neo-textfield-input">` (`Text.css:420-427`) uses `min-height: var(--neo-textfield-input-height)` with no fixed `height`, so `<input>` stretches cleanly when `.neo-input-wrapper` is taller.
   - However, `.neo-field-trigger` (`trigger/Base.css:9,11`) hardcodes `height: var(--neo-textfield-input-height);` and `line-height: 26px;`. In Flexbox, an explicit `height` on a flex item overrides the container's `align-items: stretch`, freezing every trigger (`Clear`, `Picker`, `ComboBox`, `Date`, `Time`, and `NumberField`'s `50%` `.neo-spin-button` pair) at `25px` whenever `.neo-input-wrapper` grows via a custom `height` config or flex stretch.
   - `resources/css/src/form/field/TextArea.css:15-17` previously added a local `.neo-textarea .neo-field-trigger { height: inherit; }` workaround for this exact defect instead of fixing `.neo-field-trigger` at its owner.
2. **Inconsistent input-box stretching across `labelPosition` modes on explicit `height` configs (`resources/css/src/form/field/Text.css:2,347-349`):**
   - In `labelPosition: 'left'` and `'right'`, `.neo-textfield` (`Text.css:2`) uses `align-items: center`, so configuring `{module: TextField, height: 48}` grows `.neo-textfield` to `48px` while leaving `.neo-input-wrapper` / direct `.neo-textfield-input` at `27px` instead of stretching the input box while keeping `.neo-textfield-label` centered.
   - In `labelPosition: 'inline'`, `.neo-label-wrapper` (`Text.css:347-349`) hardcodes `height: calc(var(--neo-textfield-input-height) + var(--neo-textfield-border-top-width) + var(--neo-textfield-border-bottom-width))` and `.neo-input-wrapper` / `.neo-textfield-input` lack `height: 100%` inside `display: block` `.label-inline` when no in-flow counter/error grid is active.
3. **Theme-equality stage cell flex leakage (`test/playwright/component/apps/theme-equality/app.mjs:73-78`):**
   - `cell()` wraps each stage widget in a `Neo.container.Base` whose default `vbox` layout stamps `flex: 1` onto items lacking an explicit `flex`, causing single-line fields in taller CSS Grid rows (`Row 2` alongside invalid/error cells) to stretch unintentionally instead of rendering at their natural height unless `height` is explicitly configured.

## The Architectural Reality

- `resources/css/src/form/field/trigger/Base.css:1-24` owns base `.neo-field-trigger` layout and borders across `TextField`, `TextArea`, `NumberField`, `ComboBox`, `PickerField`, `DateField`, and `TimeField`.
- `resources/css/src/form/field/Text.css:1-56,289-429` owns `.neo-textfield`, `.neo-label-wrapper`, and `.neo-input-wrapper` height/flex alignment across all five `labelPosition` values (`top`, `bottom`, `left`, `right`, `inline`) and in-flow error/counter grids.
- `resources/css/src/form/field/TextArea.css:15-17` holds the redundant `.neo-field-trigger { height: inherit; }` patch that retires once `trigger/Base.css` stretches natively.
- Design authority: `resources/css/src/form/field/Text.css:409-415` (`".neo-input-wrapper { align-items: stretch; ... display: flex; flex: 1 1 1px; min-height: var(--neo-textfield-input-height); }"`) and `resources/css/src/form/field/TextArea.css:15-17` (`".neo-field-trigger { height: inherit; }"`).

## The Fix

1. In `resources/css/src/form/field/trigger/Base.css`:
   - Replace `height: var(--neo-textfield-input-height);` and `line-height: 26px;` on `.neo-field-trigger` with `min-height: var(--neo-textfield-input-height);` so `.neo-input-wrapper`'s `align-items: stretch` stretches `.neo-field-trigger` (and its `border-left` / `.neo-align-start` `border-right`, `:hover` background, centered glyph, and `NumberField` `50%` `.neo-spin-button` halves) to the full inner height of `.neo-input-wrapper` without overlapping `.neo-input-wrapper`'s top/bottom border (`overflow: hidden`).
   - Delete the redundant `.neo-textarea .neo-field-trigger { height: inherit; }` workaround in `resources/css/src/form/field/TextArea.css:15-17`.
2. In `resources/css/src/form/field/Text.css`:
   - When no in-flow `.neo-textfield-character-count` or non-absolute `.neo-textfield-error` grid row is active, let direct `.neo-input-wrapper` and `.neo-textfield-input` stretch to an explicit taller `.neo-textfield` height across `label-left`, `label-right`, and `label-inline` (keeping `.neo-textfield-label` vertically centered in `left`/`right`, and sizing `.label-inline > .neo-label-wrapper` to `height: 100%` when no in-flow error/counter row is present).
3. In `test/playwright/component/apps/theme-equality/app.mjs:73-78`:
   - Add `itemDefaults: {flex: 'none'}` to `cell()` so default-height stage widgets do not inherit `vbox` `flex: 1` vertical stretching from taller grid-row neighbors.
4. Rebuild theme CSS via `node buildScripts/build/themes.mjs -n -e dev -t all` and add a headless-Chromium component spec verifying trigger border continuity and glyph centering across default height, explicit `height: 48` (`left`, `top`, `inline`, `NumberField` spin buttons, `ComboBox`, `.neo-align-start` trigger), flex-stretched `.neo-input-wrapper`, and `TextArea`.

## Acceptance Criteria

- [ ] AC-1: On any `TextField`, `NumberField`, `ComboBox`, `PickerField`, or `TextArea` whose `.neo-input-wrapper` is taller than `--neo-textfield-input-height` (via explicit `height: 48` / `height: 80` or flex stretch), `.neo-field-trigger` (`align: 'end'` and `align: 'start'`) spans `100%` of `.neo-input-wrapper`'s inner height with continuous `border-left` / `border-right`, full-height `:hover` fill, centered trigger icon, and `50%`/`50%` `NumberField` spin buttons.
- [ ] AC-2: Configuring an explicit `height` (e.g. `height: 48`) on `Neo.form.field.Text` stretches the input box cleanly across `labelPosition: 'left'`, `'right'`, `'top'`, `'bottom'`, and `'inline'` while keeping default unconfigured field heights (`27px` input box) and in-flow error/character-count rows unchanged.
- [ ] AC-3: `resources/css/src/form/field/TextArea.css` removes its local `.neo-field-trigger { height: inherit; }` override without regressing `TextArea` clear-trigger height, and `test/playwright/component/apps/theme-equality/app.mjs` sets `itemDefaults: {flex: 'none'}` on stage cells while `npm run theme-equality` passes.
- [ ] AC-4: `node buildScripts/build/themes.mjs -n -e dev -t all` and a headless-Chromium component spec (recorded red on `dev` and green at head) pass.

## Out of Scope

- Changing `--neo-textfield-input-height` (`25px`) default density in `theme-base` or `theme-neo`.
- Inline floating-label `.neo-center-border` top-border notch sizing (tracked in the companion follow-up issue).

## Avoided Traps

- Keeping `height: var(--neo-textfield-input-height)` on `.neo-field-trigger` and adding per-subclass `height: inherit` overrides like `TextArea.css:15-17`, which leaves `TextField`, `NumberField`, `ComboBox`, and `PickerField` triggers broken whenever `height` or flex layout stretches `.neo-input-wrapper`.
- Using `align-items: stretch` directly on `.neo-textfield` for `labelPosition: 'left'` / `'right'`, which would push `.neo-textfield-label` text to the top edge instead of keeping the label vertically centered beside the taller input box.
