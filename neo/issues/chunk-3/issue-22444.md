# theme-base: bind the global sheet's variables to roles

**Row `global` of step 6 of #22295 (rule 20).** Release work for v14.1 and the first blocker of the Material pair (#22359), so it carries no `good first issue` label.

unowned-rationale: open to any maintainer seat. Claim with a comment here and a `[lane-claim]`. I answer design questions on this leaf and build nothing.

## Context

Step 6 of #22295 declares every component variable once in `theme-base`, bound to roles (pilot: Button, #22351). The row map counted the 26 engine packages. `resources/css/src/Global.css` is none of them, so the global sheet had no row until rule 20.

## The Problem

Measured on `dev` at `c91d3f482a`:

- `src/Global.css` reads 18 `--neo-global-*` names. Only the five legacy sheets declare them (`theme-light`, `theme-dark`, `theme-cyberpunk`, `theme-neo-light`, `theme-neo-dark`, 18 each). `theme-neo/Global.css` declares none.
- It reads ten old-token names at 14 places (heading, paragraph, inline code): nine `--neo-core-*` and `--neo-sem-color-fg-neutral-contrast`. The same five sheets declare them.
- A theme class without a legacy sheet therefore has no page background and paints its text in the browser's serif. In Chromium, with the sheets built through the build's layer plugin, a `.neo-body` under theme Neo's roles alone computes `background-color: rgba(0, 0, 0, 0)` and `font-family: Times`. The Material build shows it on a running page ([frame critique in the draft pull request](https://github.com/neomjs/neo/pull/22438)).

## The Architectural Reality

Design authority: ADR 0044, decision 4: "Every component variable is declared once, in `theme-base`, bound to roles." Decision 5: "`src/Global.css` reads `--neo-global-*` component variables like any structural file, so a classic theme nested in a Neo document can decline element typography without wiping a role for Neo descendants." ([ADR 0044](https://github.com/neomjs/neo/blob/c91d3f482a510f97d5fa48a1bc120941b9326efc/learn/agentos/decisions/0044-design-system.md))

Three things the row has to keep. Each is measured.

1. **The classic decline (#18232).** `theme-light`, `theme-dark` and `theme-cyberpunk` each declare 14 of the 18 variables and all ten old tokens as `initial`, and the rules read those names with a `revert` fallback. A classic scope nested in a Neo document keeps the browser's heading metrics that way. A role read directly in `src/Global.css` could be declined only by wiping the role for Neo descendants, so the 14 old-token reads become `--neo-global-*` component variables, never role reads.
2. **The layer order.** The build puts every `theme-base` sheet in `neo.base` and a theme's `Global.css` in `neo.roles`, which is weaker (`cascadeLayer` in `buildScripts/util/themeCssLayers.mjs`). A binding in `neo.base` outranks every theme's own value for the same variable.
3. **The palette check's file classes.** `isThemeGlobal` in `buildScripts/util/check-theme-palette.mjs` matches `theme-base/Global.css`, so the check reads a base sheet of that name as a theme's own.

**Measured placements.** Chromium; the `src`, `theme-light`, `theme-neo` and `theme-neo-light` `Global.css` sheets of #22425's head `a750e0c1ff`, each through `cascadeLayerPlugin`; one planted base sheet that binds the page background, the font family and the heading letter spacing to roles. The last column uses a synthetic theme class that re-values the font family.

| Base sheet | Classic theme alone | Classic nested in theme Neo | A new theme's own value |
| :--- | :--- | :--- | :--- |
| none (today) | `rgb(250, 250, 250)`, Helvetica Neue | declines: Helvetica Neue, spacing `normal` | not applicable |
| `neo.base`, `[class*="neo-theme-"]` | **transparent, Times** | **takes Neo's: Source Sans 3, `-0.64px`** | **inert:** the binding wins |
| `neo.roles`, `[class*="neo-theme-"]` | unchanged | declines | wins or loses by arrival order |
| `neo.roles`, `:where([class*="neo-theme-"])` | unchanged | declines | wins in both arrival orders |

**Decided by the acting design seat: the fourth row.** The global sheet is the one structural file whose per-theme sheet is the theme's `Global.css`, so its base bindings sit in that layer, at zero weight. This amends ADR 0044 decision 6 by one sentence. It also corrects rule 20 of #22295, which first named role reads and left the layer open.

## The Fix

1. `resources/css/theme-base/Global.css`: every `--neo-global-*` variable, declared once under `:where([class*="neo-theme-"])`, bound to roles. Component variables only.
2. `buildScripts/util/themeCssLayers.mjs`: `cascadeLayer` returns `neo.roles` for `theme-base/Global.css`. ADR 0044 decision 6 says so in one sentence.
3. `resources/css/src/Global.css`: the 14 old-token reads become `--neo-global-<element>-<property>` variables, named as the 18 are (`--neo-global-heading-font-family`, `--neo-global-heading-1-font-size`, `--neo-global-paragraph-line-height`, `--neo-global-code-color`). Each keeps its `revert` fallback.
4. The three classic sheets decline the new names with `initial`, where they declare the old tokens `initial` today.
5. `theme-neo-light/Global.css` and `theme-neo-dark/Global.css` drop their `--neo-global-*` declarations. They sit at `:where()` weight, a tie with the base that arrival order decides (measured: the legacy value wins when its sheet arrives last, the binding when the base does). Theme Neo takes the bindings; a value the equality run shows as changed is asked here.
6. `buildScripts/util/check-theme-palette.mjs`: `theme-base/Global.css` is a base sheet, not a theme's. A palette or role name declared there fails.

The binding table is the holder's first act, posted here (rule 13): the 18 names and the new ones, each with its role and the legacy values it replaces.

**The guard arms behind point 6.** A copy of #22425's head `a750e0c1ff`, one planted `theme-base/Global.css` per arm, all eight `check-theme-*` guards unless noted:

## Avoided Traps

- **Reading roles directly in `src/Global.css`.** Rule 20 said so at first. A classic theme could then decline only by wiping a role (ADR 0044 decision 5, #18232).
- **The base sheet in `neo.base`,** like every other `theme-base` sheet. Measured above: it strips the classic themes of their own values.
- **Copying the variables into each new theme's `Global.css`.** Every new theme would carry the same lines, and none of them says anything about its design.
- **Appending a generic family to a `revert` fallback:** #21291 records why that is invalid at computed-value time under a classic theme.
