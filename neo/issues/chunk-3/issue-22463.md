# The dialog example's actions sit in the body, not in a docked footer

## Context

The operator flagged this on 2026-11-28 with a `dev` frame of `examples/dialog` in dark mode. The Edit another contact / Cancel / Save row sits inset, inside the body's padding, while the title bar runs edge to edge. He reads it as broken since v14 and asks that the footer integrate the way the header does.

The frames from #22452's evidence (same example, dark) show both states:
- **Released 14.0 (neomjs.com):** the row is a transparent strip inside the body, with no rule above it.
- **`dev` after #22435 (toolbar roles):** the same strip now paints the raised toolbar background. The inset shows as a floating bar, narrower than the header.

## The Problem

`examples/dialog/DemoDialog.mjs` builds its action `Toolbar` as the fourth item of `this.items`. That puts it inside the body container `neo-dialog-contact-fields`, which has `padding: 1rem` (`resources/css/src/examples/dialog/DemoDialog.css`). The example CSS zeroes the toolbar's own padding (`.neo-dialog-contact-actions {padding: 0}`) to make it fit there. The dialog's footer styling never applies, because the toolbar is not a footer. The code is the same at tag `14.0.0`.

## The Architectural Reality

- `Neo.dialog.Base` extends `Neo.container.Panel`. `createHeader()` unshifts the title bar (`dock: 'top'`) into `headers` and keeps every header the config brings.
- The dialog's structural sheet already styles a footer: `.neo-dialog.neo-panel .neo-footer-toolbar` in `resources/css/src/dialog/Base.css`. It draws a top rule in `--neo-dialog-border-color` and takes the footer buttons' radius, height and margin from `--neo-dialog-footer-button-*`.
- Two consumers already dock one:
  - `examples/toolbar/paging/view/AddUserDialog.mjs`: `headers: [{cls: ['neo-footer-toolbar', 'neo-toolbar'], dock: 'bottom', ...}]`.
  - `src/board/CardEditor.mjs`: a `footerToolbar` with `dock: 'bottom'`, appended to `headers`.
- The gap is the example's composition. No engine change is needed.

Design authority: "An extended Container supporting multiple docked header toolbars" (the `Neo.container.Panel` JSDoc, which `Neo.dialog.Base` inherits). The dialog's own `.neo-footer-toolbar` rule in `resources/css/src/dialog/Base.css` defines the footer it docks.

## The Fix

- `examples/dialog/DemoDialog.mjs`: move the action `Toolbar` from `this.items` into `headers`, with `dock: 'bottom'` and `cls: ['neo-footer-toolbar', 'neo-toolbar']`. Keep its three buttons, their handlers and the `->` spacer.
- `resources/css/src/examples/dialog/DemoDialog.css`: drop the `.neo-dialog-contact-actions` override, which is no longer needed.
- Read the spacing on the frames: the toolbar's own `gap` and the dialog's footer button margin both apply.

## Acceptance Criteria

- [ ] The action row renders as the dialog's footer: below the body, edge to edge like the title bar, under the dialog's top rule, in theme Neo light and dark. The PR shows frames of the released site (neomjs.com), `dev` and its head.
- [ ] Nested editors (Edit another contact), Cancel, Save, Escape and focus return behave as before: `test/playwright/e2e/dialog/CloseFocus.spec.mjs` and `test/playwright/e2e/dialog/MenuLayerNL.spec.mjs` pass without an edit.
- [ ] Tab still reaches the three fields before the footer buttons.

## Out of Scope

- The colour of the raised bars (rule 18 of #22295, #22435) and of the title (rule 17, answered on #22448).
- `apps/legit/view/AddFileDialog.mjs`, which also places its Save toolbar in the body. It is an app surface, with its own frames.
