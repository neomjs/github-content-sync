# The grid's edit-in-a-dialog example gets real records and a usable form

Please comment to claim before starting; check current assignees and linked PRs.

## Context

Row 6 of the Grid & Table slate ([#21142](https://github.com/neomjs/neo/issues/21142#issuecomment-6924949418)), a leaf of #21175 (the Grid & Table group, under #21140).

## The Problem

`examples/grid/nestedRecordFields` is the card "Nested Grid Records". What a visitor gets is a second way to edit: an Edit button in each row opens a dialog with a form on that row, and saved cells are marked as modified. The card's name describes the model instead (fields such as `user.firstname`). The grid has four rows, and on 16 Nov the dialog's Country field rendered a few pixels wide at 1440 × 900.

## The Architectural Reality

- `examples/grid/nestedRecordFields/`: `Viewport.mjs` (the columns at `:65` to `:73`, the Edit button as a component column), `EditUserDialog.mjs` (the form: Firstname `:57`, Lastname `:62`, Date `:67`, Country `:71`, Selected `:79`), `ViewportController.mjs`, `ViewportStateProvider.mjs` (the countries store, a relative URL at `:25`), `MainStore.mjs` (four inline rows from `:14`), `MainModel.mjs`.
- The example has its own viewport, a theme button (`Viewport.mjs:47`) and both themes in `neo-config.json`.
- The countries URL resolves only when the server root is the repository root. Run and capture from there.
- No spec file loads the folder.
- Catalog record `grid-nested-record-fields`.
- Design authority: "Every renew and every new row is then filed as its own leaf under #21140" (#21142), row 6 of its Grid & Table table; the bar is the one #21140 names: "an example resets, works at phone width, in both themes, by keyboard".

## The Fix

1. **The card says what a visitor gets:** a row edited in a dialog. Name, `feature` and `lookFor` follow; nested fields are one clause, not the title.
2. **20 to 40 rows of a record with a real nested part**, for example a contact with `address.city` and `address.country`, or an order with `customer.name`.
3. **The dialog is usable at both sizes:** every field has a width a person can type into, the Country field included.
4. One line in the frame says what to do, for example "Press Edit in a row."
5. The toolbar's two buttons stay.

## Acceptance Criteria

- [ ] At least 20 rows; at least two columns read a nested field.
- [ ] The dialog opens from a row, every field is at least 180 px wide at 1440 × 900 and usable at 390 × 844, and saving updates the row and marks the changed cells.
- [ ] The dialog opens and closes by keyboard; the PR says with which keys.
- [ ] A spec under `test/playwright/e2e/grid/` opens the dialog, changes a nested field, saves, and asserts the cell.
- [ ] Both themes.
- [ ] **Look:** the first frame and one frame with the dialog open, at both sizes, are on the PR beside today's frames, and the design seat reads them before code review.
- [ ] The catalog cover is re-shot from the new default state with the producer of #20679, or the PR names the change that brings it.

## Out of Scope

`examples/table/nestedRecordFields`, which leaves the catalog; inline cell editing (`examples/grid/cellEditing`, #21164); changes to the form fields' classes. If the narrow Country field is an engine defect, file it and work around it here.

## Avoided Traps

- **Renaming the folder.** The record id and the folder stay; the card's name changes.
- **A second inline editor.** This card is the dialog path; #21164 is the inline one.
