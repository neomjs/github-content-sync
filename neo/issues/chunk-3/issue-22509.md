# A container inside a raised bar paints the page's fill: dark blocks in the Portal header

Owner: Ada (`@neo-opus-ada`), author of the `toolbar` move (PR #22435) and holder of the 14.1 bug gate (#22364). Found by #22490's triage of the released-vs-`dev` run.

A census of fills inside toolbars, across all 96 theme-Neo surfaces in dark, finds only the first two new against 14.0. It flags an opaque element inside a bar whose fill differs from the bar's on `dev` but not on 14.0. The breadcrumb case is the reverse shape, a bar inside a container, and the frame comparison found it.

## The Problem

In 14.0 a container and a bar painted the same fill in each scheme. `--container-background-color` and the toolbar fill were both `#ffffff` in light and `#0d0f12` in dark. A container inside a bar, or a bar inside a container's padding, was invisible.

Two step-6 moves gave them different roles:
- the `container` row (#22443, PR #22446) binds `--neo-container-background-color` to `background-surface` (`#f9fafb` · `#0e0f13`);
- the `toolbar` row (#22397, PR #22435) binds bars to `background-surface-raised` (`#ffffff` · `#252834`), per rule 18.

Each move's equality run declared its own row. Neither run had a surface that nests one in the other.

## The Architectural Reality

Design authority: "A bar is raised. Toolbars and the grid's header and footer read `background-surface-raised`." (#22295, rule 18.) No rule says what a container inside a bar paints. That is the question for the design seat on this leaf.

- `Neo.toolbar.Base` extends `Neo.container.Base`. A plain container placed in a toolbar's items reads `--neo-container-background-color`, so it paints the page's surface on the raised bar.
- Portal: `apps/portal/view/HeaderToolbar.mjs` groups its three action buttons in a container (`ntype: 'container'`, cls `portal-header-actions`).
- sideBySide: `examples/layout/sideBySide/MainContainer.mjs` groups each label and its buttons in a `Container` (`examples-layouts-group`).
- breadcrumb: `examples/toolbar/breadcrumb/view/MainContainer.mjs` puts a `BreadcrumbToolbar` and a `ThemeSwitcher` side by side in a `Container` (`neo-breadcrumb-folders-header`).

## The Fix

Proposed rule for the design seat: a container inside a bar is layout, not a region, and paints no fill of its own. The bar re-values `--neo-container-background-color` to `transparent` for its descendants. This fixes the Portal and sideBySide without touching either.

The breadcrumb header is a region that holds a bar. The example either moves the theme switcher into the breadcrumb bar or lets the header read the bar's fill.

If the seat rules otherwise, each surface paints its container in its own sheet.

## Out of Scope

- The fill of a container that is a region of its own (a card, a panel body, a page).
- The scheduler's timeline header against the raised header bar: that header is the `timeline` row's, not a container.
