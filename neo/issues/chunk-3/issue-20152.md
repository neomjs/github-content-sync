# A Workstation popup closed after the main window reloads may wait out the lease

## Context

Julia flagged this in her review of #20149 (the Depth Floor section of `pullrequestreview-5660612405`) as a sibling of #20148 on the nested-workspace route. A source read confirms that the condition she named holds in the Workstation today. It is **not measured yet**.

## The Problem

#20148 found that a reloaded main window is a new document, which never held the windows its predecessor opened. A handle bound to the departed opener can therefore never answer whether a popup closed. On the default tear-out route this made every close after an opener reload wait out the reconnect lease. #20149 fixed that route.

The nested route probably waits the same way. A Workstation popup closed after the main window reloaded would return its workspace only when the lease ends.

## The Architectural Reality

- **The probe.** `NativeVesselTransaction.releaseWorkspace` (`src/dashboard/dock/window/NativeVesselTransaction.mjs`) reads `native.route()` and, when a route is present, awaits `Neo.Main.windowNativeIsClosed({nativeHandleKey: route.nativeHandleKey, windowId: route.ownerWindowId}).catch(() => null)`. An answer that is neither `true` nor an expired lease keeps the workspace retained and awaiting closure.
- **The cached route.** The Workstation caches the route across reconnects. `PopupWorkspace#getNativeWindowRoute` returns `runtimeState.nativeRoute` (`apps/workstation/view/PopupWorkspace.mjs:244`), and `VesselWorkspace` keeps the old route on a route-less reconnect (`state.nativeRoute = WindowManager.get(windowId)?.nativeRoute ?? state.nativeRoute`, `apps/workstation/view/VesselWorkspace.mjs:542`).
- **After an opener reload**, `route.ownerWindowId` names a window that `Neo.manager.Window` no longer holds.

## The Fix (after the measurement)

1. Measure first. In the Workstation: pop out a pane, reload the main window, close the popup, and time the workspace's return.
2. If it waits for the lease, apply #20149's rule in `releaseWorkspace`: a route whose `ownerWindowId` is no longer a registered window cannot answer, so the workspace returns at once.

## Acceptance Criteria

- [ ] The measurement is recorded here, with the return time after a main-window reload.
- [ ] If confirmed: a unit arm in `test/playwright/unit/dashboard/DockNativeVesselTransaction.spec.mjs`. A departed opener returns the workspace without waiting for the lease, and the live-opener arms stay green.
- [ ] If not confirmed: the reason is recorded here, and the issue closes.

## Out of Scope

The default tear-out route, which #20149 covers.
