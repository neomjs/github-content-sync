# Apply timeline drag moves received before startup and proxy mount

## Context

Isolated from repeatable `e2e-engine (2/20)` failures on `PR #22464` ([run 46094494509 attempt 1](https://github.com/neomjs/neo/actions/runs/46094494509/job/140822741338) and [attempt 2](https://github.com/neomjs/neo/actions/runs/46094494509/job/140834186824), trace triaged with `@neo-gpt-emmy` in `#22464#issuecomment-7232479612`) at `test/playwright/e2e/scheduler/BasicNL.spec.mjs:26`:

```text
Error: expect(received).toBeGreaterThan(expected)
Expected: > 346
Received:   326
```

A real pointer press at `(371, 229)` on `ev-3` (`Score mix`, `original.x = 326, width = 90`) followed by a `+60px` horizontal sweep to `(431, 229)` mounts `.neo-dragproxy` at `left: 326px` and leaves it stuck at `x = 326` for the entire 5s poll whenever the pointer sweep finishes inside `Neo.main.draggable.sensor.Pointer`'s `100ms` arming delay (`delay: 100`).

## The Problem

Two async startup races in `Neo.timeline.draggable.EventDragZone` (`src/timeline/draggable/EventDragZone.mjs`, shared by both `Neo.scheduler.EventDragZone` and `Neo.gantt.EventDragZone`) combine whenever pointer movement occurs before `dragStart` and `DragProxyComponent` mounting settle:

1. **Move frames dropped while `super.dragStart` awaits `DragDrop.setConfigs`:**
   When a user or Playwright sweep completes within `Pointer#delay` (`100ms`), `Pointer#onDistanceChange(..., true)` (`src/main/draggable/sensor/Pointer.mjs:308-312`, added in `#22153`) calls `startDrag()` (`drag:start` at `startEvent` `x = 371`) and synchronously emits one catch-up `drag:move` at the live pointer (`x = 431`), with no further `pointermove` events while the pointer rests.
   In the App Worker, `EventDragZone#dragStart` (`src/timeline/draggable/EventDragZone.mjs:358`) `await`s `super.dragStart(..., signal)` (`DragDrop.setConfigs` IPC) **before** initializing `this.initialSnapshot` (`:374`). While `setConfigs` is in flight, `EventDragZone#onDragMove` (`:489-493`) checks `if (this.initialSnapshot)` and **discards** the catch-up `drag:move` (`x = 431`). When `super.dragStart` resolves, `:389` calls `me.dragMove(data)` with the stale `drag:start` payload (`x = 371`, `0px` displacement), leaving both `pendingDrop` and proxy `left` at `326px`.
2. **Pre-mount `Neo.applyDeltas` lost against async `DragProxyComponent` `insertNode`:**
   `DragZone#createDragProxy` (`src/draggable/DragZone.mjs:406`) instantiates `DragProxyComponent` (`autoInitVnode: true, autoMount: true`, `moveInMainThread: false`) with initial `config.style.left = '326px'` without awaiting `proxy.mountedPromise` (`isContainer === false`, keeping unit tests non-blocking). `EventDragZone#dragMove` (`src/timeline/draggable/EventDragZone.mjs:312-317`) dispatches raw `Neo.applyDeltas(me.windowId, [{id: me.dragProxy.id, style}])` directly from the App Worker before the VDom Worker's `insertNode` mounts `#neo-dragproxy-N` in the Main DOM (measured with `Neo.config.logDeltaUpdates = true`: `updateStyle` arrives with `inDomBefore: false` ahead of `insertNode`), so `DeltaUpdates` drops the style delta and `insertNode` paints the initial `left: 326px`.

Local headless Chromium reproduction on `dev` with zero artificial RPC delay: a sub-`100ms` pointer sweep (`await page.mouse.move(x + 60, y, {steps: 3})`) reproduces `original.x = 326, proxyBox.x = 326` `100%` deterministically.

## The Architectural Reality

- `Neo.timeline.draggable.EventDragZone` (`src/timeline/draggable/EventDragZone.mjs:289-390,489-493,526-531`) owns `dragStart`, `onDragMove`, `dragMove`, and `resetDragState` for both `Neo.scheduler.EventDragZone` (`src/scheduler/EventDragZone.mjs`) and `Neo.gantt.EventDragZone` (`src/gantt/EventDragZone.mjs`), which both run with `useProxy: true, moveInMainThread: false`.
- Sibling precedent in `Neo.draggable.container.SortZone` (`#22153`) buffers incoming `onDragMove` payloads while `dragStart` is pending and reconciles proxy position once the proxy element mounts in the DOM (`DragDrop#setDragProxyElement` only runs when `moveInMainThread: true`, `src/draggable/DragProxyComponent.mjs:46`).
- Unit specs (`test/playwright/unit/scheduler/Container.spec.mjs`, `test/playwright/unit/gantt/TaskPreview.spec.mjs`) run with `unitTestMode: true, useDomApiRenderer: false`, where `DragProxyComponent#mountedPromise` never resolves unless driven; therefore `dragStart` must not block on `mountedPromise`, and instead syncs the mounted DOM style via a guarded `mountedPromise.then(...)` continuation when `!proxy.mounted`.
- Design authority: `#20907` (*"A scheduler created without `eventDragZoneConfig` shows a preview that follows the pointer during a move and during a resize. A test reads it mid-gesture, before release."*) and `#22153` (*"Sweeping ... within `Pointer`'s `100ms` arming delay and holding still before release ... places `.neo-dragproxy` at the live pointer `x` rather than stranding it at the start slot."*).

Decision Record impact: none.

## The Fix

In `src/timeline/draggable/EventDragZone.mjs`:
1. Track an invocation-scoped `#activeStart` token and `#pendingMoveData` buffer across `dragStart` and `resetDragState`. While `this.#activeStart` is active and `this.initialSnapshot` is still `null`, `onDragMove(data)` stores the latest `data` in `this.#pendingMoveData`.
2. When `super.dragStart` finishes without aborting (`!signal?.aborted && me.#activeStart === startToken`), compute `me.grabOffset` from the initial `drag:start` coordinate (`data`) as before, clear `#activeStart` / `#pendingMoveData`, and invoke `me.dragMove(pendingMove || data)` so both `me.pendingDrop` and proxy geometry reflect the latest pointer frame.
3. In `dragMove`, store `me.#latestProxyStyle = style` (cleared in `resetDragState`), dispatch `Neo.applyDeltas(me.windowId, [{id: proxy.id, style}])`, and when `!proxy.mounted && proxy.mountedPromise`, attach one per-proxy `mountedPromise.then(...)` callback guarded by `me.dragProxy === proxy && !proxy.isDestroyed && me.#latestProxyStyle` that applies `me.#latestProxyStyle` immediately after `insertNode` mounts `#neo-dragproxy-N` (and keep `proxy.vdom.style` / `proxy.style` aligned or apply via `Neo.applyDeltas` post-mount).

## Acceptance Criteria

- [ ] AC-1 `EventDragZone#onDragMove` buffers pointer moves arriving while `dragStart` awaits `super.dragStart`, keeps `grabOffset` anchored to the `drag:start` press coordinate, and applies the latest buffered move (updating both `pendingDrop` and proxy style) once `initialSnapshot` is initialized; `Escape` / `onDragEnd` / overlapping `dragStart` cancellations discard stale buffered moves cleanly.
- [ ] AC-2 When `me.dragProxy` has not finished mounting (`!proxy.mounted`) at the time `EventDragZone#dragMove` computes a snapped style, the latest proxy style is applied once `proxy.mountedPromise` settles (unless cancelled or destroyed beforehand), without blocking `dragStart` in `unitTestMode`.
- [ ] AC-3 Unit tests in `test/playwright/unit/timeline/EventDragZone.spec.mjs` and `test/playwright/unit/scheduler/Container.spec.mjs` cover buffered `onDragMove` frames during delayed `DragDrop.setConfigs`, post-mount proxy style flush on `mountedPromise`, and cancellation/overlap cleanup.
- [ ] AC-4 `test/playwright/e2e/scheduler/BasicNL.spec.mjs` verifies sub-`100ms` (`Pointer#delay`) move and resize sweeps (`steps: 3`, red on base before the fix) displace `.neo-dragproxy` immediately upon visibility without follow-up pointer motion.

## Out of Scope

- Modifying `src/vdom/**`, `src/mixin/VdomLifecycle.mjs`, `src/main/DeltaUpdates.mjs`, or `DragZone#createDragProxy` container placeholder flows.
- Live-proxy single-frame drop restoration (`#20871`).
- Changing `Pointer`'s `delay: 100` double-click guard.

## Avoided Traps

- **Awaiting `proxy.mountedPromise` inside `DragZone#createDragProxy` or `EventDragZone#dragStart`:** In `unitTestMode: true` (`useDomApiRenderer: false`), `DragProxyComponent` does not mount into a browser DOM, so awaiting `mountedPromise` deadlocks unit specs (`test/playwright/unit/scheduler/Container.spec.mjs`).
- **Computing `grabOffset` from `pendingMove` instead of `drag:start`'s `data`:** `Pointer#startDrag` reports the press coordinate where the user grabbed the bar; computing `grabOffset` from the moved coordinate would zero out the pre-delay travel and snap the bar back to `original.x`.
- **Splitting the sweep in `BasicNL.spec.mjs` instead of fixing `EventDragZone`:** Waiting for `proxy` visibility mid-sweep masks a real UX bug hit by every `< 100ms` mouse flick on Scheduler and Gantt bars.
