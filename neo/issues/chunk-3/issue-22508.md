# board/cardDesigns' density toggle paints its labels 2px smaller than 14.0

Owner: Ada (`@neo-opus-ada`), holder of the 14.1 bug gate (#22364). Found by #22490's triage of the released-vs-`dev` run.

## Context

`examples/board/cardDesigns` switches its cards between Compact, Standard and Detailed with a three-way toggle in its header. On `dev` the toggle's labels paint smaller than on the released site. Measured on the painted label (`.neo-button-text`), theme Neo light and dark alike:

| Viewport | 14.0 (neomjs.com) | `dev` `3a767aa484` |
|---|---|---|
| 1280 × 800 | `14px` / `600` | `12px` / `600` |
| 390 × 844 | `13px` / `600` | `11.5px` / `600` |

| Light, 1280 px wide | 14.0 (neomjs.com) | `dev` |
|---|---|---|
| The toggle | ![released](https://github.com/neomjs/neo/blob/980f1400c78e9c34e6d4049a98c9532f1c7bc6ba/review-evidence/22490/carddesigns-toggle-light-released.png?raw=true) | ![dev](https://github.com/neomjs/neo/blob/980f1400c78e9c34e6d4049a98c9532f1c7bc6ba/review-evidence/22490/carddesigns-toggle-light-dev.png?raw=true) |

neomjs.com was read with a desktop Chrome user agent; `dev` is a git-archive export with its themes built, served on loopback. #22490's runner reported the button element itself (`12px` → `13.3333px`, `600` → `400`). That element paints no text, so its numbers are the pointer, and the table above is the symptom.

## The Problem

In 14.0 the example set `font-size: 12px` on `.editorial-seg-btn.neo-button`, and `11.5px` at phone width. Those declarations land on the button element. The label reads `--button-text-font-size`, so 14.0 painted the button's own sizes: `14px`, and `13px` below 600px wide.

#22234 (PR #22247, `ed6c6cc72c`) rebuilt the toggle on `Neo.button.Segmented`. It carried both numbers into `--neo-button-text-font-size`, the variable the label reads (`src/button/Base.css`, rule `.neo-button-text`). So the labels now paint the numbers that never painted before: 2px smaller on a desktop, 1.5px smaller on a phone. PR #22247's frame critique names no size change.

## The Architectural Reality

Design authority: "The control inherits the button skin." (#22234, AC-1 as delivered by PR #22247.) The label's size belongs to that skin:
- `theme-base/button/Base.css` binds `--neo-button-text-font-size` to `--neo-control-font-size-medium` (`14px`);
- `src/button/Base.css` re-values it to `13px` on the button itself below 600px.

The example overrides both:
- `.editorial-segmented.neo-segmented-button` declares `--neo-button-text-font-size: 12px` (and `--neo-button-text-font-weight: 600`, which equals the skin's semibold);
- the phone rule's `.editorial-segmented.neo-segmented-button > .neo-button` declares `--neo-button-text-font-size: 11.5px`.

Both are in `resources/css/src/examples/board/cardDesigns/Viewport.css`.

## The Fix

Delete the example's two `--neo-button-text-font-size` declarations and the redundant weight. The labels then read the skin's size, as 14.0 painted them. Measure both widths. If one does not come back to 14.0's value, find what set it in 14.0 instead of writing a literal.

## Acceptance Criteria

- [ ] AC-1: In theme Neo light and dark, the toggle's painted labels compute `14px` / `600` at 1280 × 800 and `13px` / `600` at 390 × 844. These are 14.0's values on neomjs.com.
- [ ] AC-2: The pull request shows released / `dev` / head frames of the header at both widths, in both schemes.
- [ ] AC-3: `test/playwright/e2e/board/CardDesigns.spec.mjs` passes.

## Out of Scope

- The `Segmented` package's own variables (#22488).
- Button sizes in other examples. #22490's verdict table lists every difference the run found.
