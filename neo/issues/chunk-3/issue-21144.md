# A workbench example can be shared and copied: URL state, config as code

## Context

The second slice of the examples workbench, after Engine 14. The operator's direction of 16 Nov 2026 (relayed) asks for something like a storybook for Neo; Discussion #20744 described what the config panel could become and has had no comment since 10 Nov. This leaf exists so that the part after the cut has an owner-shaped place. A leaf of #21140.

## The Problem

In an example of the configuration viewport a visitor changes configs and finds a state worth showing. Nothing lets them keep it: a reload starts over, a link cannot carry it, and the config object that produced it is not shown. An evaluator cannot send a colleague "this is the button we want", and a coding agent cannot read the configs it would have to write.

## The Architectural Reality

- `examples/ConfigurationViewport.mjs`, after its first slice (the stage, the inspector, the reset): the configs an example exposes are known to the panel.
- The engine's config system reports a component's changed configs; a route hash is available to every example.
- Design authority: the operator's direction of 16 Nov; Discussion #20744 (ungraduated, an input).

## The Fix

1. **The look first:** one example with its state in the URL and a code view, at 1440×900 and 390×844, read by the operator before the build.
2. **State in the URL:** a changed config is reflected in the example's URL and restored on load.
3. **The config as code:** a view shows the component's config object as changed, ready to copy.

Both work for every example of the viewport, without code of its own.

## Acceptance Criteria

- [ ] The look is on this ticket with the operator's read.
- [ ] Changing a config updates the URL; opening that URL restores the state; the reset clears it.
- [ ] The code view shows only configs that differ from the example's initial state, as valid Neo config.
- [ ] Works in every example of the viewport; exceptions are listed with the reason.
- [ ] e2e: change, reload, same state; copy, the text matches the component's configs.
- [ ] **Look:** released and changed, two readers without session context.

## Out of Scope

Named here so they are not lost; each becomes a leaf of #21140 when this one lands: the events an interaction fires, a size switch, a config's description and type in the inspector. The same holds for the options of Discussion #20744 that no slice has decided: controls generated from the class (B), curated by the catalog record (C), and one read and write path for a human and an agent (E), with its open questions on where a config's type and description come from at runtime and whether the playground becomes an engine class. Also out: the first slice (its own leaf), Storybook (#5010).

## Avoided Traps

- **State in local storage.** It cannot be sent to a colleague.
- **A generated example file.** The config object is the unit a reader copies.
