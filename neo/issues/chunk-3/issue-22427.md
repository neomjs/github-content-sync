# The palette check reads an app's Global.css as a product palette

Curated labels are left off: the leaf amends an accepted ADR and edits the module that #22395 has in flight, so it is seat work.

## Context

Epic #22426 decides how Workstation and Fleet Manager get their looks: a product palette is `resources/css/theme-<name>/apps/<app>/Global.css`, which re-values palette and role names of a theme on that theme's own classes (its points 1 to 3, with the Chromium measurement). The operator named both looks for 14.1 on 27 Nov (#22391). This leaf is the first build of that epic and needs no package move of #22295.

## The Problem

`check-theme-palette` refuses every such file today. Planted into a copy of the tree at `dev` `28c9e53cf8`, with all eight `check-theme-*` guards run from that copy:

| Planted | `check-theme-palette` |
|---|---|
| nothing (control) | pass, as do the seven other guards |
| three palette names on theme Neo's classes in `theme-neo/apps/workstation/Global.css` | `[cascade]`: a theme class has one palette, and each name has 2 values |
| the same in `theme-neo/apps/workstation/Viewport.css` | `[cascade]` |
| the same in `src/apps/workstation/Palette.css` | `[cascade]` |
| one colour role re-bound to another grade, in the app `Global.css` | `[cascade]`: 2 values |
| the palette names under `.workstation-viewport`, in the app `Global.css` | `[scope]` |
| `neutral-900` at lightness 0.33, in the app `Global.css` | `[cascade]` |

So a product can ship its look only as component-variable overrides, which is the bridge the epic removes.

## The Architectural Reality

Design authority: n/a — the leaf calls no existing behaviour wrong. The check does what its summary says: "one value per theme class, declared on the class itself … under no condition", and "this check models no cascade". The record it implements leaves the product case to the palette track (ADR 0044 decision 8), and #22426 is that track's decision.

- Owner: `buildScripts/util/check-theme-palette.mjs`, with `themeNameShapes.mjs` for the name shapes and `themeCss.mjs` for the class map. Its spec is `test/playwright/unit/buildScripts/util/check-theme-palette.spec.mjs`.
- The build already places the file: `cascadeLayer` gives any sheet under an `apps` folder `neo.apps` (`themeCssLayers.mjs:37`), and `collectThemeClassMap` reads only a top folder's `Global.css` for the theme map (`themeCss.mjs:292`), so an app's `Global.css` is never taken for a theme.
- #22395 (Maryam, in flight) edits the same guard family: roles only in a `Global.css`. This leaf lands after it and counts an app's `Global.css` in a theme folder as a `Global.css`.

## The Fix

1. `check-theme-palette` treats `theme-<name>/apps/<app>/Global.css` as a product palette of the theme classes its rules declare on, when those classes belong to that theme folder. It measures one more palette per file and class: the theme's values with the file's on top. The file is admitted only in the folder whose own `Global.css` declares that class's palette. A class can map to two folders (`.neo-theme-neo-dark` is declared by `theme-neo/Global.css` and by `theme-neo-dark/Global.css`), and the loader fetches a named file from each, so an app's `Global.css` in the second folder fails: one app has one overlay per theme class.
2. The merged palette is held to the rules a theme's is: no name the theme does not declare, one lightness per grade across the slots, descending grades, the contrast pairs of each scheme. A product palette may leave any name out.
3. Everything else that declares a palette or colour-role name a second time keeps failing as in the table above.
4. The passing line names each product palette beside the theme's.
5. Run by its normal command from a workspace, the check resolves the base palette through the build's roots in their order (`buildScripts/util/themeCssRoots.mjs`) and reads the workspace's app file as the product palette. Fleet's file lives in such a root.
6. ADR 0044 is amended in the same pull request: decision 8 says where a product palette lives, that it travels on the theme's classes in `neo.apps`, and its limit (one product look per document, reopened by the first host that needs two); I5 and I8 say that a product palette is measured merged; §5's open line "where a product palette lives and how it travels" goes.

## Out of Scope

- Workstation's and Fleet's palette files, their loading and the demonstration: later leaves of #22426.
- A palette class beside the theme class, or a `body` class: the epic's Out of scope and Avoided traps.

## Avoided Traps

- **Modelling the cascade in the check.** The carrier is a class so that a palette stays readable as syntax; a selector with a condition is what the epic rejects.
- **Passing an app `Global.css` unmeasured.** A product palette that only a browser can judge is a pair no script holds.
