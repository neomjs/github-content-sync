# Bind Desktop’s five theme sheets to shared roles

## Context

The [Material coverage ledger](https://github.com/neomjs/neo/issues/22484#issuecomment-7233945527) identifies Desktop as a 48-property package move. On `dev@76d743e589`, AppWindow (8), Container (4), Launcher (12), TaskList (8), and Taskbar (16) define the same names in the two legacy Neo folders.

## The Problem

The generated theme has palette and role values but misses the Desktop hooks that paint the desktop, windows, launcher, running-task strip, and start menu. The current equality fixture samples Taskbar. Product acceptance also needs an independently painted floating window and detached popup.

## The Architectural Reality

The Desktop CSS consumes per-component custom properties. `PopupViewport` loads the AppWindow and Container sheets and shares their glass and wallpaper hooks. [ADR 0044 decision 4](https://github.com/neomjs/neo/blob/76d743e589440a8381d1875a92b1a346a0a821cc/learn/agentos/decisions/0044-design-system.md#L49-L66) permits translucent role mixes for a component. AppWindow and Taskbar currently use identical glass recipes in each Neo scheme. Container’s wallpaper is a separate art-directed composition.

## The Fix

Move the package’s 48 declarations to `resources/css/theme-base/desktop/` and retire the corresponding legacy Neo pairs. Apply the step-6 bindings from #22295. Ask the design seat to settle the shared glass treatment and wallpaper before declaring the visual delta. Keep the taskbar, launcher, and windows in a single package move.

Prescription checked: `resources/css/theme-base/desktop` owns shared paint values. The existing structural sheets and popup loading path own their consumers. Decision Record impact: aligned with ADR 0044.

## Acceptance Criteria

- [ ] All 48 Desktop hooks are declared in the five theme-base sheets. The two legacy Neo copies retire.
- [ ] Neo Light and Dark show the wallpaper, launcher, Taskbar, start menu and a floating window. The detached window uses its own scope and resolves the same named shell paint roles.
- [ ] A newly generated theme paints the same surfaces in both schemes. Run exact equality and verify the classic and Cyberpunk samples.
- [ ] Theme guards, Desktop and popup checks pass. Record visible differences, icon and text contrast, and before/after whole frames.

### Desktop corner control

I reran the actual Notes and Apps menu at draft `1f64b5f123` in Neo Light and Dark, at 1440 × 900 and 390 × 844. In each page I changed only the existing AppWindow and Start menu radius hooks. On desktop, the computed radii go from 8/4 px to the released 16/14 px. On phones the full-width Notes window stays square in both arms, and the Start menu goes from 4 to 14 px. All four comparisons held each element’s bounds, background, border color, and shadow constant.

I recommend preserving 16/14 px in the Desktop hooks, alongside its existing 16 px launcher tile and 14 px compact tile geometry. The control retains the draft’s stronger Dark surface separation. This leaves the shared glass and wallpaper calls in the design thread.
