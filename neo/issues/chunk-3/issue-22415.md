# A floating action button that collapses or hides on scroll

Owned by @neo-opus-grace. A leaf of #22414 (mobile components).

## Context

A phone screen's primary action sits in a floating action button. Neo has none; `src/button/` holds Base, Effect, Menu, Segmented, Split and ThemeSwitcher. The mobile Grid example is adding a floating Edit action (#22398), and its ticket asks for exactly this component.

## The Problem

Today an app author has to float a plain Button with their own CSS. That means hand-written fixed placement, safe-area insets, a size, an elevation, and the scroll behaviors phone users expect. The extended variant (icon plus label) should collapse to its icon while the content scrolls down. A plain one can hide. Both come back when the user scrolls up. Every app would write this again, each time differently.

## The Architectural Reality

- `Neo.button.Base` already renders icon and text and adds `no-text` when the text is empty. It handles `size` (`null`, `small`, `medium`, `large`), `ui`, `badgeText`, `handler`, `route` and the ripple (`src/button/Base.mjs:47`, `:532-584`). A floating action button is a Button with a placement and two scroll behaviors, so it extends Base and adds no rendering of its own.
- Scroll events reach App with `scrollTop`, `scrollLeft`, `clientHeight` and `clientWidth` (`src/main/DomEvents.mjs:1073-1087`). Any component can add and remove listeners on another through `addDomListeners` / `removeDomListeners` (`src/mixin/DomEvents.mjs:46`, `:117`).
- `component.Toast` is the viewport-anchored precedent: position classes and a literal `1rem` (`resources/css/src/component/Toast.css:94-130`). This component reads ADR 0044 roles instead of literals.

## The Fix

New `src/button/FloatingAction.mjs` (`Neo.button.FloatingAction`, ntype `floating-action-button`), extending `Neo.button.Base`:

- `extended_` (Boolean, default `true`): shows `text` beside the icon. When false, or when collapsed, the text stays the accessible name through `ariaLabel`.
- `position_` (`'start'|'center'|'end'`, default `'end'`): bottom placement with logical insets and `env(safe-area-inset-*)`.
- `scrollBehavior_` (`null|'collapse'|'hide'`, default `null`) and `scrollTarget_` (a component or its id). On a downward scroll past a small threshold the button collapses or hides; on an upward scroll, or back at `scrollTop` 0, it returns. The listener moves when the target changes and goes away on destroy.
- Structural CSS in `resources/css/src/button/FloatingAction.css`: fixed placement, size, shape, elevation and the transition. Every value is a component variable bound to ADR 0044 roles in the theme files. Motion stops under `prefers-reduced-motion`.
- A phone example, `examples/button/floatingAction/`: a long list with an extended button set to collapse, plus an icon-only button set to hide.

## Acceptance Criteria

- [ ] `Neo.button.FloatingAction` extends `Neo.button.Base`. `extended`, `position`, `scrollBehavior` and `scrollTarget` are reactive configs with JSDoc and `@summary`.
- [ ] With `extended: false`, or while collapsed, the button shows only its icon, and the screen reader name is still `text`.
- [ ] Scrolling the target down past the threshold collapses (`'collapse'`) or hides (`'hide'`) the button. Scrolling up, or reaching `scrollTop` 0, restores it.
- [ ] Changing or nulling `scrollTarget`, or destroying the button, removes its scroll listener from the old target.
- [ ] A hidden button cannot take focus or receive a tap. A collapsed one stays operable.
- [ ] No literal colour, length or duration in the structural CSS: every value is a `--neo-floating-action-button-*` variable bound to roles in the theme files.
- [ ] Unit spec for the configs, the classes they set and the scroll-direction rule.
- [ ] Phone example frames at 390 px in light and dark: at rest, collapsed, hidden.
