# The Engine 14 example slate: keep, renew, retire or new, per group

## Context

The operator, Mon 16 Nov 2026 (relayed): what matters a lot is which examples Engine 14 shows. It needs many new ones, some existing ones are old, and the grids need more. A leaf of #21140, for the cut on Mon 23 Nov.

## The Problem

Nobody has decided, example by example, what the section shows. [The inventory](https://github.com/neomjs/neo/issues/20498#issuecomment-6918253093) counts 139 runnable examples and 15 apps; the catalog publishes 72. The leaves so far add records and covers for whatever exists. Two readers without session context named what that produces ([the first look](https://github.com/neomjs/neo/issues/21130#issuecomment-6918809237)): tiles that read as toys (a lorem-ipsum tree, a cube, a clock, an empty calendar) and thin groups (Scheduler 1, Gantt 1, Calendar 2, Tree 2).

Discussion #20742 asked the same on 10 Nov (its OQ4 and OQ5) and proposed a bar: an example can be reset and inspected at desktop and phone width, in the supported themes, by keyboard; a new demonstration names the visitor's question and shows why no existing example answers it. Neither was filed.

## The Architectural Reality

- `examples/**` and `apps/**` on dev; `apps/portal/resources/data/examples.json` (77 records; `feature`, `lookFor`, `scope`).
- The six inventory sheets under `review-evidence/20498/inventory-2026-11-16/` at commit `53e279b1d0` (branch `clio/20498-first-screen-look`).
- Design authority: the operator's direction of 16 Nov on #20498; the publication bar of Discussion #20742.

## The Fix

One table on this ticket, grids first, a row per runnable entry:

- **keep**, **renew** (what changes: the data, the default state, the theme, the size) or **retire** from the catalog, with one reason;
- per group, the **new** examples Engine 14 needs: the question each answers, and why no existing example can.

Every renew and every new row is then filed as its own leaf under #21140, with an owner or a curated label. The operator gets the per-group summary as one page.

## Acceptance Criteria

- [ ] Every runnable entry of the inventory has a verdict and a reason.
- [ ] Every group names its new examples, or says that it needs none and why.
- [ ] Each example that stays published meets the bar, or its row says which part it fails and which leaf repairs it.
- [ ] Grid & Table, Tree, Calendar, Scheduler and Gantt each say how a visitor sees depth, not one demonstration.
- [ ] No row names a commercial feature (the rule of #20498, until 1 Dec).
- [ ] Every renew and new row links its filed leaf.
- [ ] The summary is with the operator; his objections changed rows or are answered on this ticket.

This ticket closes by comment with the table and the list of filed leaves. No pull request resolves it.

## Out of Scope

Building any example; covers; the group list itself (map v2); the workbench (its own leaf).

## Avoided Traps

- **A field-type checklist as a ticket batch.** Discussion #20742 ruled it out: a missing folder is not a missing proof.
- **A verdict from one still frame.** A row that retires or renews an example opens it first.
- **New examples to fill a count.** The count follows the questions.
