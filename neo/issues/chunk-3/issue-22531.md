# Bind Calendar’s nine stylesheet pairs to theme-base roles

## Context

The [Material package census](https://github.com/neomjs/neo/issues/22484#issuecomment-7233945527) attributes 66 unresolved names per scheme to Calendar. At Engine `76d743e589440a8381d1875a92b1a346a0a821cc`, the nine legacy Calendar stylesheet pairs declare the same 67 names. The Calendar package has no `theme-base` tree.

## The Problem

Stock Neo Light and Dark supply these variables through the two legacy folders. Material and a generated theme can load Calendar’s structural CSS while missing its component values. The event colors also carry user-selected calendar identities across event text, edges, resize glyphs, the sidebar and picker swatches. Several of the current focused text pairs fail 4.5:1 in the legacy palette.

## The Architectural Reality

[ADR 0044](https://github.com/neomjs/neo/blob/76d743e589440a8381d1875a92b1a346a0a821cc/learn/agentos/decisions/0044-design-system.md) and the package rules in #22295 govern this move. Component variables belong in `resources/css/theme-base/calendar`. `resources/css/src/calendar` owns structural reads. `src/calendar/view/EditEventContainer.mjs` and `src/calendar/view/calendars/ColorsList.mjs` resolve category colors by name. The package’s classic and Cyberpunk sheets supply their own overrides.

## The Fix

Move Calendar’s nine stylesheet pairs to the shared component layer, bind the named values below, and retire the matching legacy Neo Light and Dark pairs. Preserve the existing component property names where they still have consumers. Reconcile any split or drop through the existing rename map. Exercise the real Calendar views in both schemes and in the Material/generated-theme coverage check.

### Design-seat questions

1. **Calendar event identity and focus.** How should the six user-selected event hues carry into theme-base while remaining distinct? Blue, green, orange, pink, red and yellow are calendar identities. Five existing `--neo-event-*-color` values serve both ink and boundaries, and the picker builds those names dynamically. Orange and yellow need distinct treatment. Pink has no existing house role. Old fills use 10%/30% alpha at rest and 60%/70% while focused. Measured after compositing on the old surface, all six Light focused pairs and Dark focused yellow fall below 4.5:1. Decide the palette authority and the focused fill/ink pairs together. Preserve sidebar, picker, drag-proxy and event consumers in the witness.
2. **Today and keyboard focus.** The current week/year today badges use red. Year focus is a different state with a blue fill, white text and no outline. White on the red badge is 4.00:1. Proposed direction is accent/on-accent for today and a separate visible focus treatment. The existing accent/on-accent pair measures 5.20:1 in both schemes; selected-strong/default ink measures 9.84:1 Light and 6.33:1 Dark. Confirm the distinction on a focused cell that is also today.
3. **Year density.** Counts are an ordered magnitude. Light currently steps yellow → orange → red, while Dark intensifies one accent at .25/.5/.8. Choose the scale for low, medium and high with legible default ink and a visible difference from today and focus.
4. **Weekend and month chrome.** Confirm the permanent weekend tint, which currently uses a 35% translucent neutral, and the month’s shared grid/header background. If the header should rise separately under rule 18, split its reader. The optional month scroll shadow uses one surface and one blue pigment across two layers. Confirm its pigment while keeping geometry.
