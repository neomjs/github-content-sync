# The rename map records step-6 splits and drops, and every target exists

## Context

`buildScripts/util/theme-variable-renames.json` is the step-4 map of #22349 (PR #22358). Two readers depend on it: the codemod `buildScripts/util/rename-theme-variables.mjs`, which app authors run to move to 14.1, and the rename section of the 14.1 notes (#22265). Step-6 moves now split and drop names after the map was written. Grace raised the notes side; the codemod's owner, Julia, agreed the fix and its schema and handed the build here.

## The Problem

The map only knows 1:1 renames. #22445 (the `form` row, in review) splits `--neo-textfield-input-font` and `--neo-selectfield-input-font` four ways each. On its head the map still sends `--textfield-input-font` and `--selectfield-input-font` to names that no longer exist, so the codemod would rewrite an app's CSS to a dead name. `rename-theme-variables.spec.mjs` validates the map's shape (duplicate, chained and colliding targets) and proves no old name remains, but it never checks that a target still exists, so nothing fails.

Measured at 01:05 UTC (every `to` declared or read under `resources/css` or `src`): `dev` `2c6e9a4642`, 1,191 targets, 0 missing; #22445's head, 2 missing. `src` must be scanned: `--neo-grid-row-pin-offset` lives only in `src/main/addon/GridRowScrollPinning.mjs:145` and `src/grid/Row.mjs:753`.

## The Architectural Reality

- `loadRenameMap()` in `rename-theme-variables.mjs` reads `{entries: {"--old": {to, rule}}}` and rejects duplicate, chained and pre-existing targets.
- `runThemeVariableRename()` rewrites `.css`, `.html`, `.mjs` (including dashless `setCssVariable` keys), `.github/CODING_GUIDELINES.md` and `learn/apps/docs/examples` Markdown.
- ADR 0044 §3: no alias layer for old names, so a split or a drop needs a record, never an alias.

## The Fix

The schema is Julia's (MESSAGE:4275291b):

1. **Split (1 → N):** `"--textfield-input-font": {"split": ["--neo-textfield-input-font-family", "--neo-textfield-input-font-size", …], "rule": "…", "reason": "… (#22445)"}`. No `to`; `split` holds at least two distinct `--neo-*` names.
2. **Drop (1 → 0):** `"--obsolete-var": {"dropped": true, "reason": "retired in #N: …"}`. No `to`; `reason` is required.
3. **Codemod:** an entry with `to` rewrites 1:1 as today. A `split` or `dropped` entry is never rewritten. If a scanned repository still holds the old name (dashed, or as a dashless `setCssVariable` key), the run reports it with its `split` list or its `reason` and exits non-zero, under `--check` and in a normal run.
4. **Live-target check:** the spec's CONTROL test asserts that every `to` and every `split` name is declared or read under `resources/css` or `src` in the live repository, dashless `setCssVariable` keys included. A `dropped` entry is exempt.

## Acceptance Criteria

- [ ] AC-1: `loadRenameMap()` accepts the three entry shapes and refuses a `split` with fewer than two names or a non-`--neo-` name, a `dropped` entry without a `reason`, and an entry carrying `to` beside `split` or `dropped`.
- [ ] AC-2: `runThemeVariableRename()` writes no `split` or `dropped` target. A fixture file that still holds such an old name, dashed or as a dashless `setCssVariable` key, is reported with its `split` list or `reason`, and the run exits 1 with and without `--check`.
- [ ] AC-3: The spec's CONTROL test fails when a `to` or a `split` name is neither declared nor read under `resources/css` or `src`, and passes on the live tree.
- [ ] AC-4: At merge, `dev` passes the live-target check: every split or drop already on `dev` is recorded in the map. If #22445 lands first, this pull request writes its two `split` entries; if this lands first, #22445 writes them under the new check.

## Out of Scope

- An alias for an old name (ADR 0044 §3).
- Rewriting a shorthand into its longhands automatically: a split needs the author's eyes.
- The 14.1 notes' rename section (#22265 reads this record at the cut).
