# Web desktop: a double-click opens an app window out of its icon

## Context

Leaf of #21061. The operator's definition of a real web desktop includes "dblclick on an item => opening a dialog with animateTarget to the item". Builds on the permission shell (#21063).

## The Problem

The shell offers apps but cannot run them. A desktop opens each app in a window that grows out of its icon, lists open windows in a taskbar, and never keeps a window open for an app the account may no longer use.

## The Architectural Reality

Design authority: n/a — new app behavior; it calls no existing behavior wrong.

- `dialog.Base` animates out of and back into `animateTargetId_` and offers `draggable_`, `resizable_`, `maximized_`, `closeAction` and `boundaryContainerId` (`src/dialog/Base.mjs:35-150`); `apps/email/view/ComposeDialog.mjs` is the sibling usage.
- The operator's reference pattern for a dialog that spawns out of its trigger: create it on first use through a lazy `import()` with `animateTargetId` set to the trigger's id, the trigger's `appName` and `windowId`, `closeAction: 'hide'`, and `stateProvider: {parent: <controller>.getStateProvider()}`. A floating dialog sits outside the component tree, so its provider names its parent explicitly. Later opens call `show()` on the kept instance.
- The launcher is a `list.Base` (#21063); its item nodes are the animation targets.

## The Fix

- `view/AppWindow.mjs` (`dialog.Base` subclass, loaded lazily): title and icon from the app record, `animateTargetId` = the launcher icon's node, `appName` and `windowId` from the launcher, a provider parented to the desktop's, bounded to the desktop, with minimize, maximize and close.
- `store/Windows.mjs`: one record per open window; the taskbar renders it through a store-bound list.
- Controller: a double-click or Enter on an icon opens its window (or shows and focuses the kept one), a single click selects; choosing an app in the start menu opens it the same way.
- Revoking a permission closes that app's window; signing out closes every window.

## Acceptance Criteria

- [ ] A double-click (and Enter) on a launcher icon opens its app's window, animating out of the icon; closing animates back into it (real-browser frame captures).
- [ ] A single click selects the icon without opening it.
- [ ] Opening an app whose window is open focuses that window; no duplicates.
- [ ] The taskbar lists open windows from the window store; clicking an entry focuses or restores its window; minimizing collapses the window into its entry.
- [ ] The focused window is on top, and windows stay inside the desktop area.
- [ ] Revoking an open app's permission closes its window; signing out closes every window.
- [ ] Choosing an app in the start menu opens it the same way.
- [ ] Unit specs for the window store and controller rules green under `npm run test-unit`.

## Out of Scope

- Moving a window into its own browser window (#21061 Out of Scope).
- Drag and drop of icons (sibling leaf).
