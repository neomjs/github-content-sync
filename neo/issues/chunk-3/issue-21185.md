# The table's own example says when a table beats a grid

Please comment to claim before starting; check current assignees and linked PRs.

## Context

Row 12 of the Grid & Table slate ([#21142](https://github.com/neomjs/neo/issues/21142#issuecomment-6924949418)), a leaf of #21175 (the Grid & Table group, under #21140).

## The Problem

The engine ships a table beside the grid, and it is maintained: 17 commits this year, three features on 5 Nov. No example says what a table is for. `examples/table/container`, the card "Table Configuration", shows the six team names again with a selection picker, which the grid's selection card shows as well. A visitor concludes that the table is an older grid.

## The Architectural Reality

- `examples/table/container/`: `MainContainer.mjs` (199 lines; a `height` field at `:42`, the selection radios from `:50`, further switches below), `MainStore.mjs` (six inline rows from `:14`), `MainModel.mjs`.
- The example is hosted on `examples/ConfigurationViewport.mjs`, which #21143 turns into the workbench. The host stays.
- **Four spec files load the folder:** `test/playwright/e2e/grid/HeaderInlineProjectionNL.spec.mjs`, `test/playwright/e2e/grid/RowModelModifierClick.spec.mjs`, `test/playwright/e2e/table/HeaderResize.spec.mjs` and `test/playwright/e2e/table/SortedHeaders.spec.mjs`. Read them before changing the data: a spec that depends on the six rows' geometry decides how far the rows can change.
- The table is documented in `learn/guides/datahandling/Tables.md`, the grid in `learn/guides/datahandling/Grids.md`.
- Catalog record `table-container`.
- Design authority: "Every renew and every new row is then filed as its own leaf under #21140" (#21142), row 12 of its Grid & Table table; the bar is the one #21140 names: "an example resets, works at phone width, in both themes, by keyboard".

## The Fix

1. **The card answers one question: when do I take the table?** Small data where every row is in the page and the columns size themselves to their content, for example a plan comparison, a specification sheet or a list of settings, 8 to 20 rows.
2. **One sentence in the frame says it**, in the words of the Tables guide, with a pointer to the grid for thousands of rows.
3. **The frame shows what the table does by itself:** column widths that follow the content, a header that stays, a cell that wraps.
4. The switches that are the table's own stay. The selection radios stay only if the four specs need them; the grid's selection card owns that subject.
5. The record's name, `feature` and `lookFor` follow.

## Acceptance Criteria

- [ ] The frame says in one sentence when to use a table, and the PR quotes the lines of `learn/guides/datahandling/Tables.md` it rests on.
- [ ] No row shows the six team names; the data reads as real, and the columns visibly take their content's width.
- [ ] The four spec files pass. Where a spec needs the old rows, the PR says whether the rows were kept in shape or the spec got a fixture of its own, and why.
- [ ] 1440 × 900 and 390 × 844; both themes.
- [ ] **Look:** the first frame at both sizes is on the PR beside today's frame, and the design seat reads it before code review.
- [ ] The catalog cover is re-shot from the new default state with the producer of #20679, or the PR names the change that brings it.

## Out of Scope

Changes to the table's classes; the table twins that leave the catalog; a comparison page of grid against table (a guide's job); the workbench (#21143).

## Avoided Traps

- **Proving the table with big data.** That is the grid's ground, and the table renders every row.
- **Breaking four specs for a nicer dataset.** The specs are read first.
