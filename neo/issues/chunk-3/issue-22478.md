# Reject unregistered runtime classes in coding-guidelines checks

## Context

Translation's first extraction in #22439 used a bare JavaScript class. The coding-guidelines check accepted it, and the re-review missed the class-system requirement. The operator restated the standing Neo rule before merge. [Prior Engine class repair](https://github.com/neomjs/neo/issues/19160)

## The Problem

The existing scanner starts class-specific checks with the set of constructors found through `Neo.setupClass`. A new bare declaration is absent from that set. On current Engine source, `findViolations('export default class Translation { track() {} }', 'src/main/gesture/Translation.mjs')` returns an empty list. The one-class-per-module check measures declaration count and method placement.

## The Architectural Reality

Neo runtime classes derive from `Neo.core.Base` and register in the Neo class system. That provides config construction, overwrites, and teardown through the normal instance lifecycle. The coding-guidelines scanner already visits Acorn nodes under its tracked runtime roots and compares findings to the exact base revision when a baseline changes. [Current analyzer](https://github.com/neomjs/neo/blob/4ffe11d57263a37c0b80923a0b764d1db35e87ae/buildScripts/util/check-coding-guidelines.mjs)

## The Fix

Inspect runtime class declarations and expressions before inspecting registered class members. Require a recognized `Neo.setupClass` registration and an explicit superclass, with the registered engine root as the root of that hierarchy. Catch direct native bases when the syntax proves them. Record pre-existing findings in the existing base-verified ledger. Document the standing rule where maintainers already look for class anatomy.

## Acceptance Criteria

- [ ] AC-1 The original bare helper shape, a bare class expression and a registration without a superclass each fail the guard. A registered Neo subclass and the registered core root pass.
- [ ] AC-2 The same existing guard entry points run on staged and PR source. Adding a new class finding to the baseline fails against the base revision.
- [ ] AC-3 The coding guidelines state the inheritance, registration and construction requirements. The repository scan records only findings already present on the base.

## Out of Scope

Existing bootstrap, platform, factory and legacy class findings retain their existing source owners. The PR handles static cases in the existing scanner's runtime roots.

Decision Record impact: none. This enforces the operator's standing rule through an existing build check.
