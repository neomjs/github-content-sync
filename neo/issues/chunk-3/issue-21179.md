# The animated row sorting example re-sorts a ranking on its own

Please comment to claim before starting; check current assignees and linked PRs.

## Context

Row 7 of the Grid & Table slate ([#21142](https://github.com/neomjs/neo/issues/21142#issuecomment-6924949418)), a leaf of #21175 (the Grid & Table group, under #21140).

## The Problem

`examples/grid/animatedRowSorting` shows rows that glide to their new place when the sort changes. A visitor who opens it sees seven rows in the top left third of the stage, and nothing moves until a header is clicked. Nothing says so. The one thing this card exists for is invisible in its first frame.

## The Architectural Reality

- `examples/grid/animatedRowSorting/`: `Viewport.mjs` (91 lines: a Firstname filter field at `:31`, a Transition Duration field at `:37` with the value 500, the grid capped by `wrapperStyle: {maxWidth: '902px'}` at `:53`, `animatedRowSorting: true` at `:56`, five columns at `:64` to `:68`, one of them `type: 'progress'`), `MainStore.mjs` (inline rows from `:13`), `MainModel.mjs`.
- Both themes are in `neo-config.json`.
- `test/playwright/e2e/grid/AnimatedRowSorting.spec.mjs` drives the example, and `test/playwright/unit/buildScripts/fixtures/e2eSelectionReplay.json` names its folder.
- Catalog record `grid-animated-row-sorting`.
- Design authority: "Every renew and every new row is then filed as its own leaf under #21140" (#21142), row 7 of its Grid & Table table; the bar is the one #21140 names: "an example resets, works at phone width, in both themes, by keyboard".

## The Fix

1. **A ranking that changes by itself**, 20 to 30 rows, for example a leaderboard or a build queue: a score or a progress value changes on a timer, the grid is sorted by it, and rows overtake each other without a click.
2. **The stage is filled:** the width cap goes, or the grid is centred in a composed frame.
3. **One line says what to click**, for example "Rows re-sort as scores change. Click a header to sort by another column."
4. A Pause button stops the updates. The Transition Duration field and the filter stay.

## Acceptance Criteria

- [ ] Without any input, at least one row changes its position within five seconds of the first frame, and keeps doing so.
- [ ] At least 20 rows; the data reads as real.
- [ ] Pause stops the updates and a second press resumes them. A header click still sorts with the animation.
- [ ] The PR says what the example does when the system asks for reduced motion.
- [ ] `npm run test-e2e -- test/playwright/e2e/grid/AnimatedRowSorting.spec.mjs` passes, adapted where it pins the old rows; the replay fixture still names an existing path.
- [ ] 1440 × 900 and 390 × 844; both themes.
- [ ] **Look:** the first frame and a frame taken mid-move, at both sizes, are on the PR beside today's frame, and the design seat reads them before code review.
- [ ] The catalog cover is re-shot with the producer of #20679 from a frame in which rows are moving, or the PR names the change that brings it.

## Out of Scope

Changes to the row animation plugin or a grid-level duration API (#19889 ruled the example its only consumer).

## Avoided Traps

- **Updates so fast that the grid flickers.** One overtake every second or two reads; ten a second does not.
- **Random values without a subject.** The ranking is of something.
