# Web desktop: the desktop works on phones and touch screens

## Context

Leaf of #21061, from the operator's review of the first drafts: responsiveness, as a follow-up. The shell (#21063) and the windows (#21064) were built and witnessed at desktop sizes only.

## The Problem

A web desktop shared as a Portal example gets opened on phones. At narrow widths today:

- The taskbar's labelled buttons (Apps, Permissions, account, Sign out) and the task list compete for one row.
- The 320 px permission panel squeezes the launcher.
- Windows open at 520×380, wider than a phone.
- Touch has no double-click, so the windows leaf's open gesture needs a touch equivalent.

## The Architectural Reality

Design authority: n/a: new behavior for a new app; it calls no existing behavior wrong.

- Layout lives in the app's SCSS (`resources/scss/src/apps/webdesktop/`), and the views stay layout-agnostic per the app gate (styles stay in SCSS).
- The launcher grid is `grid-template-columns: repeat(auto-fill, 100px)` (`Launcher.scss`), which already reflows; the tile and label sizes do not.
- Windows are `dialog.Base` instances with `maximized_` (`src/dialog/Base.mjs`). On a narrow workspace an app window can open maximized.
- The launcher opens on `dblclick` and Enter (#21064). A touch device needs a tap that opens, while the mouse keeps select-then-double-click.

## The Fix

- SCSS breakpoints:
  - Taskbar labels collapse to icons, and the task list scrolls instead of wrapping.
  - The permission panel becomes an overlay sheet.
  - Tiles shrink a step.
  - The sign-in card fits a 375 px width.
- Narrow workspaces open windows maximized.
- Touch input opens an app on tap. The detection follows the engine's existing touch/pointer signal; this leaf decides which during intake.

## Acceptance Criteria

- [ ] At 375×812 (the browser pane's mobile preset) the sign-in card, the launcher, the taskbar and the permission panel fit without horizontal scrolling, in both neo themes (screenshots).
- [ ] The taskbar keeps the start menu, the open tasks, the permission toggle, theme and sign-out reachable at that width.
- [ ] A window opened at that width fills the workspace and still minimizes, restores and closes.
- [ ] On a touch device (mobile emulation), a single tap opens an app; with a mouse, a click still selects and a double-click opens.
- [ ] Desktop sizes look and behave as before (screenshot at 1280×800).

## Out of Scope

- A separate phone UI (a different layout or navigation model): the desktop adapts, it is not replaced.
- Drag and drop on touch (#21065 owns drag and drop).
