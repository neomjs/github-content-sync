# Load country data in compiled Grid and Table examples

## Context

While verifying compiled examples for v14.1, the Grid Cell Editing country request returned HTTP 404 on both the released ESM page and the packaged development build. The Production entry reached the data. The same worker-relative lookup fails in the ESM builds of Table Filtering, Table Cell Editing, and Table Nested Record Fields.

## The Problem

Grid Cell Editing and both Table record examples request `/dist/resources/examples/data/countries.json` in ESM. Table Filtering requests `/dist/esm/resources/examples/data/countries.json`. The package ships the shared dataset under `resources/examples/data`. The released ESM grid renders its order rows with blank country labels. Table Filtering still shows its 80 inline rows, but the Country filter offers no Afghanistan option. The two other Table pages mount their HTML tables while their country lookup fails.

## The Architectural Reality

Each example's Store config owns its URL. The App Worker receives the registered page base in `Neo.config.url.base`. Compiled build roots put the Worker at different depths. The existing Contact Editor repair applies the page-base rule to its own Store.

Design authority: use the registered page base for the shipped app asset as in [the Contact Editor repair](https://github.com/neomjs/neo/issues/22551). This extends the same example-level rule to four other consumers.

## The Fix

Resolve the shared asset via `new URL(Neo.config.basePath + 'resources/examples/data/countries.json', Neo.config.url.base).href` at each of these Store declarations:

- `examples/grid/cellEditing/MainContainerStateProvider.mjs`
- `examples/table/cellEditing/MainContainerStateProvider.mjs`
- `examples/table/nestedRecordFields/ViewportStateProvider.mjs`
- `examples/tableFiltering/MainContainer.mjs`

A disposable all-mode build of the four changes returned HTTP 200 in all eight tested ESM/Production arms. Grid Cell Editing rendered Germany and populated rows at a nested host prefix. Table Filtering offered Afghanistan after typing `Afghan` in both modes. Table Nested Record Fields rendered Germany in both.

## Acceptance Criteria

- [ ] All four compiled ESM and Production examples fetch the shipped country dataset with HTTP 200 and zero page errors.
- [ ] Grid Cell Editing mounts populated rows and resolves country labels in compiled ESM and Production from a nested host path.
- [ ] Table Filtering uses the data to offer a real country option. Table Nested Record Fields resolves its country cell text in each compiled mode.

## Out of Scope

The Contact Editor Store in #22551 and the general Store URL API. Table Cell Editing's blank country labels on the existing Production build are a separate renderer symptom, observed with HTTP 200 before this URL repair.

**One question before the fifth wrapper.** With #22552, this ticket brings the count of Store declarations spelling `new URL(Neo.config.basePath + '…', Neo.config.url.base).href` to five.

**Where the layer beneath stands.** `src/data/connection/Base.mjs#resolveUrl` already re-bases relative data URLs against `Neo.config.url.base`, but only when the worker runs from `/node_modules/neo.mjs/`. Its JSDoc says Engine and `dist` workers keep worker-relative URLs on purpose. That rule is why every compiled Engine example now needs the wrapper.

**My recommendation.** If the package-only rule isn't load-bearing for `dist` layouts, one change in `resolveUrl` would make the plain `Neo.config.basePath + 'resources/…'` form correct everywhere. That change is resolving a `basePath`-relative store URL against the registered page base. It would retire these wrappers, and the next example wouldn't have to know the rule. If the rule is load-bearing, a note saying why in `resolveUrl`'s JSDoc would stop the next reader from asking.

**Unverified, so not ticketed.** The bare-`basePath` siblings (`examples/component/{helix,gallery}/ImageStore.mjs`, `apps/webdesktop/view/apps/Photos.mjs`) may work only at host root, where URL resolution clamps at the origin, and fail on a nested mount like these.
