# Swipe actions on buffered list rows, keyed by record, with Undo

Unowned: open to any peer for 14.1. Check the assignee and linked PRs before claiming. A leaf of #22414 (mobile components).

## Context

On a phone, the fastest way to act on a list row is to swipe it: archive, delete, mark done. D#22259's audit names "swipe actions, undo" on buffered list rows as a candidate. It requires that the action and its Undo stay bound to the record while DOM rows recycle.

## The Problem

`list.Buffered` mounts a window of pooled row slots and rebinds them while the user scrolls (`src/list/Buffered.mjs:12-15`, `bufferRowRange_`). An action tied to a DOM row would act on whichever record that slot shows later. Neo has no row-swipe behavior today.

## The Architectural Reality

- `list.Buffered` already maps each record to its slot (`getRecordId`, `recordSlotMap`, `:276-278`). The record key at gesture start is therefore knowable.
- `component.Toast` can carry an action button for Undo.
- The pointer sensor delivers a horizontal drag today. ADR 0045's `pan` and `swipe` (#22405) replace it once they land.

## The Fix

A row-swipe feature for `list.Buffered`, either a plugin or a config; the leaf decides and records why.
- **Reveal:** a horizontal drag reveals the row's action at its edge.
- **Commit:** releasing past a threshold, or tapping the revealed action, commits it against the record key captured at gesture start. A slot that rebinds before the commit cancels it.
- **Undo:** after a commit, an actionable Toast offers Undo for the same record.
- **Visible alternative:** a row menu exposes the same actions without a gesture.

## Implementation Contract Ledger

Triaged per `ticket-triage`. Applied `core`. The Pan dependency has closed and a list plugin owns the action rather than the Main recognizer.

## Acceptance Criteria

- [ ] A swipe past the threshold commits the action for the record under the finger at gesture start, exactly once.
- [ ] If the slot rebinds to another record before the commit (scroll away and back), the action is cancelled and no record changes.
- [ ] Undo restores the record and the action can run again.
- [ ] Every swipe action is also reachable through a visible control and by keyboard.
- [ ] Vertical scrolling of the list is unaffected by the feature (real-browser receipt).
- [ ] A phone example on a large Store, with frames.

## Out of Scope

- Pull to refresh (its own leaf).
- Gesture events (#22400).
