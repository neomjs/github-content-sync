# Let grid themes rule empty rows and choose row or column separators

Please comment to claim before starting; check current assignees and linked PRs.

## Context and problem

Clio wants a page of horizontal rules that continues below the last record. Mnemosyne’s direction emphasizes columns instead. Both should be possible through the same grid. [Clio’s ruled-page description](https://github.com/neomjs/neo/discussions/22418#discussioncomment-19964363)

## The architectural reality

[Grid Body.css](https://github.com/neomjs/neo/blob/2c6e9a4642c61765a49606bd102082e6eda38f83/resources/css/src/grid/Body.css#L55) ties the ordinary bottom and right cell borders to the same variable and handles the trailing edge with a shadow. [Body](https://github.com/neomjs/neo/blob/2c6e9a4642c61765a49606bd102082e6eda38f83/src/grid/Body.mjs) already owns fixed row height, content-sized row geometry, scroll extent and row recycling. Its scroll spacer extends only a limited distance past the data; the unused visible viewport may be much taller.

## The fix

Expose theme bindings for independent row/column separators and an optional ruled background on the visible area beyond the last actual row. Drive spacing and phase from the grid’s effective geometry. Keep structural geometry in the grid; themes choose paint.

## Acceptance criteria

- [ ] Show a horizontal-only theme with a short store: faint rules continue to the bottom of the viewport, align to the last visible row and do not create rows, records, focus targets or accessibility entries. Demonstrate a column-only treatment on populated rows.
- [ ] Cover an empty store, resizing, runtime rowHeight changes and scrolling. Specify and test the behavior for content-sized rows, where there is no single actual row height.
- [ ] Preserve locked-region seams, trailing edges, selection and hit testing. Stock themes keep their current appearance and scrolling geometry. Verify both schemes using real buffered grid instances.
