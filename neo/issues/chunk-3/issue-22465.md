# theme-base: bind list's 2 files (16 variables) to roles

Sub-issue of #22295 (Step 6 `theme-base` package move for `list`). Owned by `@neo-gemini-julia` for immediate Engine 14.1 execution, so curated contributor labels are omitted.

## Context

Under [ADR 0044](learn/agentos/decisions/0044-design-system.md) Decision 4, Decision 5, and Migration Step 6 (governed by Epic #22295 Rules 1–25), each Engine package's Neo theme sheets (`resources/css/theme-neo-light/<pkg>/` and `resources/css/theme-neo-dark/<pkg>/`) move into a single role-bound `resources/css/theme-base/<pkg>/` sheet under `[class*="neo-theme-"]`, with both per-scheme Neo copies deleted.

Following the acting design seat's rulings on this leaf ([#22465#issuecomment-7231917378](https://github.com/neomjs/neo/issues/22465#issuecomment-7231917378) and [#22465#issuecomment-7231971865](https://github.com/neomjs/neo/issues/22465#issuecomment-7231971865)):
- **`list/Base.css` (`1` file, `16` custom properties: `15` moved + `1` added for `.neo-highlight-search`):** moves here. Under Rule 23 (*"A highlight is no status"*), a list's search match is a marked run and takes the mark's pair — `--neo-list-item-highlight-search-background-color: var(--neo-color-background-brand-subtle)` (read by `.neo-highlight-search` in `resources/css/src/list/Base.css:77`) paired with `--neo-list-item-highlight-search-color: var(--neo-color-text-strong)` (`19.10:1` · `14.25:1` on every row state).
- **`list/Circle.css` (`1` variable `--neo-circle-list-back-background-color`):** leaves this row and moves with `component/Circle` in `#22493` under Rule 25 (art-directed stage of `Circle`).

All `15` pre-existing `list/Base.css` properties have live readers across `resources/css/src/list/{Base,Chip,ValuePicker}.css`, `resources/css/src/tree/{Accordion,List}.css`, `resources/css/src/draggable/list/DragZone.css`, `resources/css/src/app/content/{SectionsList,TreeList}.css`, and `resources/css/src/apps/legit/Viewport.css`, and `.neo-highlight-search` in `resources/css/src/list/Base.css:77` reads both highlight properties.

## The Problem

1. **Selected list-item contrast failure (`ADR 0044 §5`):** `theme-neo-{light,dark}/list/Base.css` bind `--neo-list-item-color-selected` to `--neo-sem-color-text-primary-default` (`#1c60a0` · `#5472e4`) on `--neo-sem-color-surface-primary-background` (`#d6e1ff` · `#182449`), painting **`3.98:1`** in light and **`2.91:1`** in dark — below the `4.5:1` text floor in both schemes.
2. **Dark hover invisibility & old token reads:** `theme-neo-dark/list/Base.css` sets both `--neo-list-item-background-color` (`--neo-sem-color-bg-neutral-highlighted`, `#282c37`) and `--neo-list-item-background-color-hover` (`--neo-sem-color-surface-neutral-hover`, `#282c37`) to the identical colour over `--neo-list-container-background-color` (`#0d0f12`), giving dark list rows zero hover feedback while reading 10 legacy `--neo-sem-*` tokens per scheme.
3. **Raw colours in component sheets (`ADR 0044` I1 & Rule 23):** `list/Base.css` hardcodes `#fff` (×2 in light) and `red` (`--neo-list-item-highlight-search-color` in both schemes, `2.8:1` on dark `background-selected` and lacking a mark fill so no text-only non-status role clears `4.5:1` across both `surface` and `background-selected`).
4. **Hardcoded theme-folder path in `Chip.spec.mjs`:** `test/playwright/component/list/Chip.spec.mjs:111-115` constructs `/dist/development/css/theme-neo-{dark,light}/list/Base.css` directly instead of calling `themeSheetHrefs()`.

## The Architectural Reality

Verified on `origin/dev` (`06ae0f7796`):
- `resources/css/src/list/Base.css` reads 13 of `list/Base.css`'s 15 existing variables (plus `--neo-list-item-highlight-search-background-color` on `.neo-highlight-search`); `--neo-list-border-color` is read by `resources/css/src/app/content/SectionsList.css:35`, and `--neo-list-item-border-color-active` is read by `resources/css/src/list/Chip.css:33`. Zero variables are unread.
- `resources/css/theme-{light,dark}/list/Base.css` re-declare 14 of the 15 pre-existing variables in `neo.theme` (`--neo-list-item-background-color-active` reads a role, and `--neo-list-item-highlight-search-background-color` reads `--neo-color-background-brand-subtle`, which classic and Cyberpunk `Global.css` do not declare so `background-color` computes to `rgba(0, 0, 0, 0)` unchanged). `theme-cyberpunk` ships no `list/` files, so `resources/css/theme-cyberpunk/list/Base.css` sets `--neo-list-item-padding: initial` to preserve Cyberpunk's `0px` list/value-picker item padding unchanged until Step 10 (`#22461` / `#22445` precedent).
- `test/playwright/util/themeSheets.mjs` exports `themeSheetHrefs(themes, classNames)` so component specs load `Global.css`, `theme-base`, and per-theme overrides from `resources/theme-map.json` without hardcoding folder names.

## The Fix

Add `background-color: var(--neo-list-item-highlight-search-background-color)` to `.neo-highlight-search` in `resources/css/src/list/Base.css`, create `resources/css/theme-base/list/Base.css` (`16` custom properties under `[class*="neo-theme-"]`), preserve Cyberpunk's pre-Step-10 padding fallback in `resources/css/theme-cyberpunk/list/Base.css` (`--neo-list-item-padding: initial`), delete `resources/css/theme-neo-{light,dark}/list/Base.css`, leave `list/Circle.css` untouched for `#22493` (Rule 25), and switch `test/playwright/component/list/Chip.spec.mjs` to `themeSheetHrefs([theme], ['list.Base', 'component.Chip'])`.
