# DateSelector marks yesterday as today after midnight

Self-assignment for the v14.1 defect gate. The failure has a deterministic production-path witness.

## Context

The post-merge Engine unit run on `ab98a1fb22` flagged `test/playwright/unit/form/field/DateAria.spec.mjs:189` as flaky. The current-day cell had no `aria-current` value. The hosted Playwright run began just before 00:00 UTC. [Hosted unit log](https://github.com/neomjs/neo/actions/runs/46085320832/job/140793605642)

## The Problem

Load the actual DateSelector module at 23:59:55 local time and rebuild the day view before and after midnight. In the forced UTC witness, Nov 27 carried `aria-current="date"` at 23:59:59. After rebuilding at 00:00:01 on Nov 28, Nov 27 stayed current, while Nov 28 could be selected and focused without the current-day marker. A DateSelector created with no value still used the date from module import.

## The Architectural Reality

Design authority: #5219 requires `aria-current="date"` on today’s cell, independently of the selected value. The public `DateSelector.value` default is today. `DateSelector` captures its date once at import and shares that snapshot between the public default and the marker. The unit test and DateField consumer use the same component. The Dialog theme merge and its parent have identical selector and date-test sources. [Default and module clock](https://github.com/neomjs/neo/blob/ab98a1fb22/src/component/DateSelector.mjs#L9-L15) · [Day-grid comparison](https://github.com/neomjs/neo/blob/ab98a1fb22/src/component/DateSelector.mjs#L838-L841) · [DateField picker](https://github.com/neomjs/neo/blob/ab98a1fb22/src/form/field/Date.mjs)

## The Fix

Sample the local day once in each day-grid build. Evaluate the implicit `value` when each selector initializes. Keep explicit selection and the Date-to-date-only conversion on their existing path. Add a deterministic local-midnight arm to the existing Date ARIA spec.

## Contract Ledger Matrix

| Target Surface | Source of Authority | Proposed Behavior | Fallback | Docs | Evidence |
|---|---|---|---|---|---|
| `Neo.component.DateSelector.value` | Existing config and `beforeSetValue` | An implicit value is that instance’s local day. Explicit values and subclass defaults still apply. | Existing explicit value handling | Config JSDoc | Construct after a controlled midnight |
| `DateSelector#createDayViewContent` | #5219 and its grid witness | Mark the local current day on each grid build with `aria-current="date"` and `neo-today`, independently of selection. | The displayed month may contain no current day | Method JSDoc | Rebuild with the same instance and selection across a controlled midnight |

## Acceptance Criteria

- [ ] A deterministic unit case advances the local clock across midnight, rebuilds the mounted day grid, and moves both current-day markers while preserving the committed selection.
- [ ] A picker that omits `value` takes the local day at construction. Explicit string and Date values still normalize and select the requested day.
- [ ] The Date ARIA, selector navigation and existing timezone tests pass.

## Out of Scope

Automatic updates to a grid that remains idle across midnight. No polling or new timer is required for a grid created or rebuilt after rollover.
