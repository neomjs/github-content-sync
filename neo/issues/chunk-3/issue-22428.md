# Retained dock tab headers keep Light after switching to Dark

## Context

Workstation preserves live tab chrome across its dock projection. Its theme switch must keep floating UI in the same scheme as the action that opened it. The product-palette demonstration in #22426 uses the main-window Close tooltip after a pane tear-out to check this. [Browser and worker evidence](https://github.com/neomjs/neo/issues/22365#issuecomment-7228773019)

## The Problem

On Engine `28c9e53cf8`, start Workstation in Neo Light, tear the Metrics pane out of the right-top tab stack, and switch the main window to Dark. Hover a retained main-window Close action. The DOM scope is Dark, but the toolbar, button, and body-mounted tooltip still report Light. A fresh hover after the theme change reproduces it. Immediately before the theme switch the worker reports `TabContainer.theme === null` and the same toolbar and button already hold Light. The popped-out Close tooltip also has a separate palette stylesheet issue that #22426 tracks.

## The Architectural Reality

`Reconciler.moveRetainedTabChrome` inserts the live tab container into a staged parent. `container.Base#createItem` sets an inherited theme to the destination parent's theme, which can be `null`. `container.Base#afterSetTheme` skips that transition, so descendants may retain the previous string. On the next flip, the former inherited value looks like an intentional child override. The tooltip has no own theme override and reads its target through `getTheme()`. [Retained tab move](https://github.com/neomjs/neo/blob/28c9e53cf8bf6a1ac11373445e0dbad86c03d05f/src/dashboard/dock/projection/Reconciler.mjs#L993) · [Theme setter](https://github.com/neomjs/neo/blob/28c9e53cf8bf6a1ac11373445e0dbad86c03d05f/src/container/Base.mjs#L302-L318)

Design authority: “Live items follow a theme change.” The same setter preserves a child that chose a different scope. Its adopted-instance contract is covered in `ItemTheme.spec.mjs`. The earlier pane-cache repair expressly left generic inheritance out of scope. [Pane-cache fix](https://github.com/neomjs/neo/issues/20850)

## The Fix

Reproduce a retained subtree moving from Light through a destination with no local theme, then applying Dark. Repair theme propagation at the first failed inherited transition. Keep the ordinary container/adoption path as the owner if the reproduction fails there, and use the Workstation tear-out as the integration witness. The worker's effective target theme and the tooltip's own theme class should agree with the new owning scope.

## Acceptance Criteria

- [ ] An adopted subtree with two levels of inherited theme follows Light → a parent with no local theme → Dark while retaining its component identities. A sibling with a deliberately different explicit theme keeps it.
- [ ] In the Workstation Metrics tear-out journey, hover the retained Close button in the main window after the Light → Dark switch. The tab header and button resolve Dark in the App Worker, and the real tooltip carries the Dark class and paints the Dark Workstation value.
- [ ] The popup still follows its owning window and the existing nested-theme and adopted-item tests pass.

## Out of Scope

Product palette stylesheet placement and replacing the popup's stock colors are part of #22426. This leaf keeps the existing rule for a child's explicit theme that is indistinguishable from the theme it inherited. [Adoption precedent](https://github.com/neomjs/neo/issues/18672)
