# theme-base: bind component's 23 files (174 variables) to roles

Owned by @neo-opus-grace: step 6 row `component` of #22295, filed under #22484 (rule 13). No curated labels: the row is in flight, and two of its parts wait on the design seat.

## Context

Row `component` of the [step-6 map](https://github.com/neomjs/neo/issues/22295#issuecomment-7217835670) (22 files, 165 variables, 23 old-token reads there). Measured on `dev` at `1dd6ec0c80`: **23 sheets, 174 declarations** per theme under `theme-neo-light/component/**` and `theme-neo-dark/component/**`. Every declaration has at least one reader in `src`.

## The Problem

- A theme generated with `--base theme-neo` gets none of these 174 variables, so its chips, date pickers, empty states, toasts, badges, markdown and splitters fall back to whatever `src` paints without them.
- Theme Neo declares each of them twice, and the dark copy reads retiring `--neo-sem-*` and hue names (`--neo-purple-*`, `--neo-gray-*`, `--neo-red-*`), while the light copy holds raw colours (`#1c60a0`, `lightblue`, `orange`).
- Several names paint more than one property, which rule 1 asks to bind by hand or split.
- 32 declarations are an art-directed palette, identical in both schemes, that no rule covers (below).

## The Architectural Reality

Design authority: "Every component variable is declared once, in `theme-base`, bound to roles." (`learn/agentos/decisions/0044-design-system.md`, decision 4), moved by the rules of #22295, one pull request per package.

- **Readers outside the package.** The `--neo-dateselector-*` names are also read by `src/date/SelectorContainer.css` (row `date`), `src/calendar/view/YearComponent.css` (row `calendar`) and `src/examples/calendar/birthdays`. `--neo-chip-*` is read by `src/list/Chip.css`. `--neo-status-badge-state-{error,success}-color` is read by `src/apps/form`. Their paint moves with this row.
- **Classic and Cyberpunk.** `theme-light` and `theme-dark` declare 22 of the 23 sheets (not `markdown/Component.css`); `theme-cyberpunk` declares five (`Carousel`, `Helix`, `Markdown`, `MonthYearSelector`, `Toast`). None of the three declares a colour role, so a role read in `theme-base` stays inert there, while a listed literal reaches every sheet a theme lacks. The equality run's scoped pass lists those reaches; each is declared in the pull request (rule 2).
- **Contrast** (rule 13, `npm run theme-contrast`, light · dark): `text-danger` on `background-danger-subtle` 6.59 · 7.48, `text-warning` on `warning-subtle` 6.20 · 7.45, `text-info` on `info-subtle` 6.01 · 7.60, `text-success` on `success-subtle` 5.80 · 7.76, `text-default` on `background-neutral-active` 14.67 · 13.32 and on `background-surface-raised` 19.19 · 13.01, `text-muted` on `background-surface` 9.23 · 7.17, `text-on-accent` on `background-accent` 5.20 · 5.20, `text-accent` on `background-surface` 4.98 · 7.05.

## The Fix

Create `resources/css/theme-base/component/**` (23 sheets) declaring the table below once under `[class*="neo-theme-"]`, delete the 46 sheets under `theme-neo-light/component/**` and `theme-neo-dark/component/**`, make the one split in `src/component/DateSelector.css`, and record it in the rename map (#22483).

### For the design seat (33, rule 13: no rule covers them)

1. **An art-directed stage (32).** `Circle` (10), `Clock` (4), `Gallery` (2), `Helix` (8), `MagicMoveText` (2), `Timer`'s `button-background-color`, `color-start` and `color-end`, `Video`'s `ghost-color`, and `Process`'s `arrow-color` and `icon-color` (both also read by JavaScript). They are literals, identical in both schemes except `Timer`'s button and `Video`'s ghost: mostly a dark stage with teal glows (`#61dfe5`, `rgba(73, 160, 154, .35)`, `linear-gradient(#468b95, #366b77)`).
   **My recommendation:** each stage is a dark island. Its root reads `color-scheme` from a component variable (`--neo-helix-color-scheme: dark`), so its variables bind to the ordinary roles (`background-canvas`, `text-default`, `border-default`), and the glows bind to the accent roles. `theme-neo/Global.css` names this case in its header ("a nested dark island needs color-scheme only"), and the translucent glows mix a role with `transparent`, which decision 4 allows for "a translucent treatment of its own". The cost: the teal becomes theme Neo's accent hue, declared on the frames.
   **The alternative:** theme Neo keeps a per-widget file with the art palette. Decision 4 keeps such a file for "where its design language deviates", and a stage that looks the same in every theme is no theme's deviation; the literals would also stay.
2. **A vendor canvas (1).** `monaco-editor-background-color` is `#fffffe` · `#1e1e1e`, Monaco's own `vs` and `vs-dark` canvas, so the wrapper's edge meets the editor without a seam. **My recommendation:** a listed vendor value, as another library's property keeps its name on a closed list (#22295, "The property prefix `--neo-` is the library's").
