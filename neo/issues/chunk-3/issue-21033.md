# Cut Engine v14.0.0 through the release PR

## Context

Engine 14 is the front-door release (`ROADMAP.md`, *Next: Engine 14 — The Front Door*; milestone v14.0), cut on Monday 2026-11-23, seven years to the day after the public release announcement. ## The Problem

Eight days before the cut, nothing tracked the cut itself: `ROADMAP.md` names a steward per cornerstone and none for the cut, and no record, notes or release leaf existed. Three things differ from 13.4.0:

- **No bump leaf.** #20664 merged: `prepare --version <semver>` sets the version in the release commit and drops the released notes there, so 13.4.0's separate bump PR (#20656) has no successor.
- **The number is read, not assumed.** The release is planned as 14.0.0 because a board, a scheduler and a Gantt chart join the engine's component families (#20874). It takes its number from the generated-app check on Friday 2026-11-20: Clio runs it on a tarball packed from `dev`, and I read it and post the reading on #20874. The receipts that run records are listed in #20874's comment `issuecomment-6858285843`. A family that misses rides the next cut.
- **The gate is observed on neomjs.com,** and the Portal reaches neomjs.com only through an Engine cut (`neomjs/pages` builds from the published package). So the gate's clauses tick after the deploy. A Portal built from `dev` shows the same pages before the cut, and the notes read them there first. A cornerstone that is not done stays open with its steward instead of holding the cut (`ROADMAP.md`, *How it runs*), and the notes say so.

## The Architectural Reality

`buildScripts/release/publish.mjs` releases in two phases joined by one human step:
- `prepare --version <semver> --ticket <leaf> --body-file <body>` checks that `dev` is at `origin/dev` and clean, that the version is newer than `package.json`'s, that `.github/RELEASE_NOTES/v<version>.md` exists and that no tag exists. It then sets the version, drops the released notes, stamps the note, runs `prepare.mjs` and `build-all`, commits to `release/v<version>` and opens a PR to `dev`.
- The operator merges that PR once `dev`'s required checks and CodeQL pass.
- `finish` squashes the merge onto `main` with the atomic-commit line, tags it and creates the GitHub release, whose event runs `npm-publish.yml` (Trusted Publishing).

Re-running a phase continues it (`releaseState.mjs`); `--rehearse` changes nothing.
