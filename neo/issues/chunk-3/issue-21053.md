# Private vulnerability reporting is off outside the engine

## Context

Found on 2026-11-15 while reviewing #21007, which adds the engine's `.github/SECURITY.md` (Resolves #21004). The policy's Scope section sends a finding in another repository to that repository's reporting channel, as #21004 prescribed. I wrote that sentence in #21004 without reading the other repositories' setting.

## The Problem

Read at 2026-11-15T21:43:46Z over the 46 public, non-archived repositories of the organisation (`gh repo list neomjs --visibility public --no-archived`): `gh api repos/neomjs/<repo>/private-vulnerability-reporting` answers `enabled: true` for `neo` and `false` for the other 45, among them `neo-agent-brain`, `neo-agent-skills`, `neo-agent-institution`, `create-app`, `devindex` and `pages`. The community profile names no security policy for any of them (four return no profile), and the organisation has no public `.github` repository that would supply a default one.

A person who finds a vulnerability in the Brain's MCP servers has no private path: the engine's policy sends them to the Brain, and the Brain offers a public issue.

## The Architectural Reality

- Private vulnerability reporting is a repository setting. An organisation owner or security manager can switch it on for all public repositories at once, and a security configuration covers repositories created later ([GitHub docs](https://docs.github.com/en/code-security/security-advisories/working-with-repository-security-advisories/configuring-private-vulnerability-reporting-for-an-organization)).
- The engine's policy text in #21007: "Report vulnerabilities in other repositories of the organization through those repositories' reporting channels." It becomes true the moment the setting is on.
- `Design authority: n/a — calls no existing behavior wrong.`

## The Fix

1. **The operator's step** (an organisation owner's setting; no agent seat changes security settings): enable private vulnerability reporting for all public repositories of `neomjs`, and for new public repositories through the security configuration.
2. **Mine:** re-run the read above and post it here with its time.

If the setting is not wanted for all repositories, the alternative is one sentence in the engine's policy: a finding anywhere in the organisation is reported through the engine's form and names its repository. This ticket then closes on that pull request.

## Acceptance Criteria

- [ ] AC-1 (human step, owner: @tobiu): private vulnerability reporting is enabled for the organisation's public repositories, or the alternative above is chosen on this ticket.
- [ ] AC-2 (mine): the read over `gh repo list neomjs --visibility public --no-archived` shows `enabled: true` for every repository and is posted here with its time; on the alternative, the policy sentence is merged.

## Out of Scope

- A default `SECURITY.md` for the organisation (it needs a public `neomjs/.github` repository) and policy files in single repositories: each is its own decision once reports can be received.
- Private repositories: only collaborators see them.
- A response-time commitment, out of scope in #21004 for the same reason.
