# theme-base: bind Menu’s 25 List and Panel variables to roles

Engine 14.1 package row under #22484. Owned for this cut, so contributor claim labels are omitted.

## Context

The design-system migration needs a shared Menu default before an app generated from theme Neo can paint its context menus and dropdowns. The same hooks feed Workstation and Fleet's product menu overrides.

## The Problem

`menu/List.css` and `menu/Panel.css` each have copies in both Neo scheme folders. A generated theme reads neither copy. The MenuList root also has the `neo-list` class, so generic List hover can out-rank Menu's own state even when the Menu hook exists.

## The Architectural Reality

Design authority: [ADR 0044, decisions 3–5](https://github.com/neomjs/neo/blob/ad0375467edb12c8224f0b20e18841b872b79f3f/learn/agentos/decisions/0044-design-system.md) and the package rules in #22295, especially radius (3), labelled boundaries (4), disabled roles (6), and elevation (18).

At `ad0375467e`, exact custom-property declaration matching (`git grep -n -E '^[[:space:]]*--neo-menu-'`, scoped to `menu/{List,Panel}.css` in each Neo scheme) finds 24 List hooks and one Panel hook per scheme. For example `--neo-menu-list-background-color` is read by `src/menu/List.css` under the MenuList root. `menu.Panel` supplies the outer border and suppresses the nested List border. Floating widgets already read the directional shadow hooks covered by #22493.

## The Fix

Put the two default sheets in `resources/css/theme-base/menu/` under the shared theme selector and delete both scheme copies. Give the painted outer edge `radius-small`. Use the existing alignment shadow path for floating menus. Preserve the legacy schemes' computed paint, including nested Classic scopes. For the hover collision, preserve generic hover where legacy sheets decline the Menu hook. Expanded-only state must not pick up an unrelated generic hover. Keep selected and disabled states ahead of hover.
