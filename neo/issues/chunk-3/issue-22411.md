# Drive Helix rotation with horizontal gestures and depth with pinch

## Context

[Helix](https://github.com/neomjs/neo/blob/5ff17dedc8/src/component/Helix.mjs#L1008) currently routes both one-finger axes through its wheel mapping. [TouchDomEvents](https://github.com/neomjs/neo/blob/5ff17dedc8/src/main/mixin/TouchDomEvents.mjs#L95) currently cancels body touch moves on a Helix path. Ada’s [browser control](https://github.com/neomjs/neo/discussions/22259#discussioncomment-19949867) demonstrated horizontal rotation and vertical page scroll under a scoped policy.

## The Fix

Use the reusable pan/swipe and pinch recognitions in Helix. Horizontal movement changes the existing rotation config and pinch changes depth. Apply structural Helix touch policy and retire its element-specific body-handler cancellation together. Preserve generic listener defaults, wheel, controls and numeric bounds.

## Acceptance Criteria

- [ ] AC-1 A horizontal gesture rotates Helix; a pinch changes its depth in both directions. Vertical one-finger movement over Helix scrolls the page. Preserve visible and keyboard/wheel controls.
- [ ] AC-2 Either finger can lift first, cancellation leaves finite geometry, and a subsequent gesture starts from its own contacts. Update the prior legacy-motion oracle to the new product semantics while retaining contact-stream coverage.
- [ ] AC-3 Prove the behavior and actual rotation/depth in the existing Helix example. A peer can replay it via Neural Link and a browser-input check covers surrounding page behavior.

Measure the actual Helix update path in AC-3: during a continuous pan, the App-side rotation actuation should update at most once per animation frame. Capture input, semantic move and geometry update counts on the same trace, and verify the last accepted position as well as responsiveness.
