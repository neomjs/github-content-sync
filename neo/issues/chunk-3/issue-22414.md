# Mobile components ship in 14.1, each with a phone example

Terminal predicate: on a phone, an app author can use six reusable Engine components: a floating action button, a swipeable sheet, a dialog form that becomes a sheet without losing its draft, row swipe actions with Undo, pull to refresh and bottom navigation. Each ships with a phone example and works by touch, by keyboard and through a visible control that needs no gesture.

Owned by @neo-opus-grace. Leaves are open to any peer after checking the assignee and linked PRs.

## Problem scope

The 14.1 scope includes mobile components and mobile examples beside the themes and the gesture events. Two sources set that scope: ROADMAP's 14.1 section (#22391, PR #22392) and [D#22259](https://github.com/orgs/neomjs/discussions/22259) G2, whose decision says the component stream "can start with the swipeable sheet and floating action button on existing Engine primitives". Today, on dev `28c9e53cf8`:

- **No floating action button.** `src/button/` holds Base, Effect, Menu, Segmented, Split and ThemeSwitcher. The mobile Grid example is about to place its own floating Edit action (#22398).
- **No sheet.** Dialog has drag and resize but no snap positions, and `trapFocus` defaults to false (`src/dialog/Base.mjs:166-169`). A floating component is placed off-screen until aligned (`resources/css/src/component/Base.css`), so a viewport-anchored sheet needs a first-paint check.
- **Nothing reacts to a horizontal swipe on a row**, and nothing pulls to refresh at a scroll boundary. `list.Buffered` recycles DOM rows, so an action must bind to a record, not a row (`src/list/Buffered.mjs`).
- **Navigation:** `tab.Container` supports `tabBarPosition: 'bottom'`, but no component switches destinations between a bottom bar on compact screens and a rail or drawer on larger ones while keeping route identity.

It is an Epic because six component families ship as separate one-PR leaves on different primitives, so peers can take them in parallel. They share the release checks below.

## Intended solution shape

- **Start on today's primitives, move to gesture events later.** Drags use `src/main/draggable/sensor/Pointer.mjs`, and activation uses Button and the existing selection models. A leaf switches to the events of [ADR 0045](https://github.com/neomjs/neo/pull/22412) once the gesture addon (#22400) lands; no leaf waits for it.
- **Placement.** Each component lives in the namespace of its interaction domain, the word a reader searches for (`button`, `sheet`, `navigation`, …). That choice is independent of its engine base class: `Neo.button.Segmented` lives in `button` and extends `Neo.toolbar.Base`. Structural rules sit in `resources/css/src/**`. Values come from the ADR 0044 roles for elevation, shape and motion, never literals in `src`.
- **The sheet is two components sharing one behavior.**
  - A persistent, non-modal Sheet with snap positions, velocity and nested content scrolling.
  - The modal form, which keeps the same Dialog, form provider and draft through a presentation change on a compact screen.
- **Row actions and Undo bind to the record key** captured at gesture start. A recycled or rebound row cancels the action. Undo is an actionable message compared against `component.Toast`.
- **Pull to refresh arms only at the scroll boundary** and offers an explicit Refresh control.
- **Bottom navigation keeps one destination identity** across bottom bar, rail and drawer, along with Back and deep links.
- **Release checks for every leaf**, from D#22259:
  - touch, keyboard and a visible alternative to any gesture (WCAG 2.5.1, 2.5.7);
  - a focus and IME check on any form inside;
  - nested scrolling;
  - first paint in the owning window;
  - record-backed outcomes where records exist;
  - a phone example under `examples/`, verified at 390 px width.

## Out of scope

- Gesture events and replay (#22400, ADR 0045).
- Material and product themes (#22359, #22295).
- The mobile Grid example's floating Edit action (#22398), which is a consumer of the floating action button.
- The D#22259 audit's other candidates: speed dial, selection action bar, full-screen search, touch date and time pickers, chips. Each gets a ticket when a consumer asks for it.

## Avoided traps

- One adaptive Dialog that also serves as the persistent sheet: it mixes modal focus rules into a non-modal surface.
- Row actions keyed by DOM row: a recycled row would act on another record.
- Gesture-only controls: they fail WCAG 2.5.1 and 2.5.7.
- A floating action button styled inside an example: the styling belongs to the component.
