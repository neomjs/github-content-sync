# A theme says its color scheme once; canvases stop keeping their own maps

Owner: Ada (`@neo-opus-ada`). The acting design seat listed this "scheme row" as without a holder on 2026-11-28 01:53Z.

## Context

Four components hand their renderer a light or dark hint, and each derives it from a map kept by hand. A theme the map doesn't name resolves to light. So a new dark pair paints light canvases inside a dark app. That covers the Material pair (#22359), any app theme, and the next theme Neo ships.

## The Problem

Each component lists the five shipped themes in its own `themeMap` config:
- `src/component/Canvas.mjs` (`themeMap`, read by `resolveColorScheme()`, which `app/SharedCanvas.mjs` and `component/Sparkline.mjs` call);
- `src/component/wrapper/Mermaid.mjs` (`themeMap`);
- `src/component/wrapper/MonacoEditor.mjs` (`themeMap`, onto `vs` / `vs-dark`);
- `src/component/wrapper/AmChart.mjs` (`themeMap`, onto amCharts' dark theme).

Their JSDoc gives the reason: "Every theme declares that token, but the main-thread reader for it is protected and absent from the app remote manifest, so a component in the App Worker cannot ask, and a renderer registration needs the answer synchronously."

## The Architectural Reality

- Every theme declares its scheme once already: `--neo-color-scheme` in `theme-{light,dark,cyberpunk}/Global.css`, and per class in `theme-neo/Global.css` (`.neo-theme-neo-light {--neo-color-scheme: light}`).
- `buildScripts/build/themes.mjs` writes `resources/theme-map.json` on every engine and app build. Today it maps each theme class to its folders (`themes: {"neo-theme-neo-dark": ["theme-neo", "theme-neo-dark"], ...}`).
- Design authority: ADR 0044 decision 7, "Light and dark are one theme. A theme declares `--neo-color-scheme` per class".

## The Fix

1. **The build reads the scheme.** `themes.mjs` resolves each theme class's `--neo-color-scheme` from its folders' `Global.css` and writes it beside the folders, for example `schemes: {"neo-theme-neo-dark": "dark", ...}`, in both written copies of `theme-map.json`.
2. **The App worker gets it synchronously,** wherever intake finds the theme map already reaching it. If it does not reach the App worker, intake picks the narrowest carrier and records why.
3. **The four `themeMap` configs default to it.** An explicit entry still wins, for a theme the build never sees. Each component's renderer-specific mapping (`vs-dark`, amCharts' dark theme) stays local; only light-or-dark comes from the theme.

## Acceptance Criteria

- [ ] AC-1: A fixture theme that none of the four maps names, declaring `--neo-color-scheme: dark`, gives a dark hint to `Canvas`, `Mermaid`, `MonacoEditor` and `AmChart` without a map edit.
- [ ] AC-2: The five shipped themes resolve exactly as today.
- [ ] AC-3: An explicit `themeMap` entry on a component still wins over the declared scheme.

## Out of Scope

- A scheme switch at runtime beyond what each component already re-reads on a theme change.
- Vendor canvases' own palettes (rule 26 of #22295: a vendor's canvas is a listed value).
