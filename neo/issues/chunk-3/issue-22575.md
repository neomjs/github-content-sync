# Ship the shared favicon with the compiled examples

## Context

The compiled WIP Limits Board paints and responds, but its tab icon returns 404. The independent 22-head integration rehearsal captured the same request in Production and ESM, and the published site also returns 404 at both distribution paths. The same source asset is served as SVG at the canonical root. [Published Production path](https://neomjs.com/dist/production/resources/images/logo/neo_logo_favicon.svg) · [Published ESM path](https://neomjs.com/dist/esm/resources/images/logo/neo_logo_favicon.svg) · [Source asset](https://neomjs.com/resources/images/logo/neo_logo_favicon.svg)

## The Problem

The exact native distribution census at dev `0e9fa32f2c` and its 22-head rehearsal finds 19 generated examples per mode whose HTML points to `resources/images/logo/neo_logo_favicon.svg` relative to the distribution. The asset exists in Engine sources and is absent from the Development, Production and ESM outputs. A WIP Limits page requests it in a fresh Chrome context. The source release tag already contains the same Board icon declarations.

## The Architectural Reality

Webpack’s Engine app-worker configs emit the bundled app pages, and the ESM build plan admits asset files. The existing [dist app assets helper](https://github.com/neomjs/neo/blob/0e9fa32f2c5d1f4793b0566aed0966909c467ff7/buildScripts/util/distAppAssets.mjs) serves all three mode families.

Design authority: the helper documents that a distribution has its own root and relative assets must be self-contained. The canonical main SVG already exists under Engine resources.

## The Fix

Carry that exact shared SVG into the native Engine distribution resource path from the existing asset emitters. Use the same relative path for all modes. Include a regression that proves the engine-owned SVG is emitted by both bundled app builds and the ESM plan.

Prescription checked: the native webpack app-worker configs already emit example HTML and their assets. The ESM graph already owns emitted asset files. The shared path belongs to their existing `distAppAssets.mjs` helper.

## Acceptance Criteria

- [ ] The native Development, Production and ESM builds emit the shared SVG at `resources/images/logo/neo_logo_favicon.svg` with the same bytes as the source.
- [ ] All 19 generated relative icon links resolve inside each distribution. A real request from a compiled example receives HTTP 200, SVG content type and the source bytes.
- [ ] A consuming workspace continues to use its own local resources and can build without an Engine root favicon input.

## Out of Scope

The scope is the existing Engine favicon referenced by standalone examples. The reference asset and the app-page URLs are already defined.
