# A grid example filters a large dataset from its header row

Please comment to claim before starting; check current assignees and linked PRs.

## Context

New example 2 of the Grid & Table slate ([#21142](https://github.com/neomjs/neo/issues/21142#issuecomment-6924949418)), a leaf of #21140, and one of six examples to build before the read of Fri 20 Nov. The visitor's question: can users filter a large grid per column?

## The Problem

The grid has a filter row under its headers (`showHeaderFilters`, `src/grid/Container.mjs:221`; the field is created per header in `src/grid/header/Button.mjs:270`). No grid example turns it on. The section's only filter row is `examples/tableFiltering`, a table from 2020 with ten rows. A visitor who evaluates the grid for real data meets filtering only in the big data example's side panel, as two text fields.

## The Architectural Reality

- `examples/tableFiltering/MainContainer.mjs` is the reference for the config: `showHeaderFilters: true` (`:51`), `filterConfig: {operator: …}` per column (`:87`, `:101`, `:114`), and the typed filter fields from `src/filter/` (`BooleanContainer`, `DateContainer`, `NumberContainer`).
- `examples/grid/bigData/MainStore.mjs` is a pattern for generating many rows.
- `examples/grid/headerGroups` is the model for the page: its own viewport, a headline, one instruction line, a theme button, the themes `neo-theme-neo-light` and `neo-theme-neo-dark`.
- The grid's header filters were repaired in October (`#19953`, `#19793`, both closed), so the path is maintained.
- Placement: a sibling folder `examples/grid/<feature>/` with `app.mjs`, `index.html`, `neo-config.json`, `MainContainer.mjs`, `MainModel.mjs` and `MainStore.mjs`.
- Design authority: n/a, a new example.

## The Fix

1. **A new folder `examples/grid/filtering`**, after the `headerGroups` model.
2. **`showHeaderFilters: true` on a grid of at least 10,000 generated rows** with business fields: a text column, a category (combobox), a number with an operator, a date with an operator, and a boolean.
3. **The count is on screen:** "n of N rows", updated as filters change. A reset control clears every filter.
4. **One line says what to try.**
5. A catalog record in the Grid & Table group, with `feature` and `lookFor`.

## Acceptance Criteria

- [ ] Five typed filters work on at least 10,000 rows, and the visible count follows them.
- [ ] Reset clears every filter field and restores the count.
- [ ] A filter type that does not work on the grid is reported, as a defect note or a ticket of its own, and the example ships with the types that do. The PR lists both.
- [ ] 1440 × 900 and 390 × 844, where the PR says which filters stay reachable on the phone; both themes; the filter fields can be reached by keyboard.
- [ ] A spec under `test/playwright/e2e/grid/` types into one filter and asserts the count.
- [ ] **Look:** the first frame and one filtered frame, at both sizes, are on the PR, and the design seat reads them before code review.
- [ ] A catalog cover is shot from a filtered state with the producer of #20679, or the PR names the change that brings it.

## Out of Scope

Engine changes to filtering; `examples/tableFiltering`, which gets its own leaf; filtering on a server, which is the slate's server-side example.

## Avoided Traps

- **Ten rows.** Filtering ten rows proves nothing about a grid.
- **Filters in a side panel.** The header row is the feature.
- **A second filter mechanism written inside the example.**
