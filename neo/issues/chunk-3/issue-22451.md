# A button's border reads border-strong where 14.0 read border-default

Owner: Ada (`@neo-opus-ada`). The design seat assigned the re-bind and ruled on it ([decision](https://github.com/neomjs/neo/issues/22295)).

## Context

The operator, comparing dev frames with the live examples on neomjs.com: *"black button borders? yikes."* Measured by computed style on the `dialog` example's Save button, a plain button:

| Theme Neo | Released 14.0 | `dev` `49e7e53866` |
|---|---|---|
| light | `#d3d7d2`, 1px | `neutral-500` `#7a839c`, 1px: reads near-black |
| dark | `#43495c`, 1px | `neutral-600` `#666f89`, 1px |

## The Problem

The Button pilot (#22351, PR #22420) bound a button's border to `border-strong`, the role that meets 3:1. On a row of buttons on a bar, the border then outweighs the labels. The 14.0.0 tag read `--sem-color-border-default` (`--gray-200: #D3D7D2`) for the same border.

## The Architectural Reality

Design authority: rule 4 of #22295, rewritten by the acting design seat. A boundary owes 3:1 only where it identifies the control. A button's label identifies it, so its border is a hairline on `border-default`. A field's edge keeps `border-strong`, because nothing inside its shape names it. Measured by the seat: `border-default` gives 1.46 on white and 1.99 on theme Neo's dark surface; the released values give 1.46 and 2.14.

## The Fix

In `resources/css/theme-base/button/Base.css`, six declarations move from `var(--neo-color-border-strong)` to `var(--neo-color-border-default)`, all together, while the fill keeps carrying hover:
- `--neo-button-border`, `--neo-button-border-active`, `--neo-button-border-hover`
- `--neo-button-secondary-border`, `--neo-button-secondary-border-hover`, `--neo-button-secondary-border-active`

## Acceptance Criteria

- [ ] AC-1: The six declarations read `border-default`. No other `theme-base/button` value changes.
- [ ] AC-2: Compared with the released 14.0 examples on neomjs.com, the plain and secondary button borders at rest, hover and pressed match the released grade in theme Neo light and dark. The table of values is in the pull request.
- [ ] AC-3: `npm run theme-equality` against a build of `dev` declares exactly the button-border rows, and the eight `check-theme-*` guards exit 0.
- [ ] AC-4: The pull request shows the dialog example in theme Neo light and dark as a released / `dev` / head triple.

## Out of Scope

- Field borders. They changed from 14.0 on purpose (rule 4).
- Classic themes, which keep their own button sheets.
