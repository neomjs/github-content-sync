## The Problem

A rotated tab needs its label's width plus 46 px (font `600 16px Source Sans 3`; the constant is 45.6 to 46.3 px across the five rendered tabs).

| Tab | Height | Source |
|---|---:|---|
| Featured | 107 px | measured |
| Grid & Table | 129 px | measured |
| Forms | 89 px | measured |
| Multi-Window | 142 px | measured |
| Calendar | 108 px | measured |
| Scheduler | 115 px | from the same font metrics |
| Gantt | 84 px | from the same font metrics |
| Board | 87 px | from the same font metrics |
| Components | 134 px | from the same font metrics |
| State & Data | 130 px | from the same font metrics |
| The build control | 156 px | measured |

Ten tabs need 1,125 px, with the build control 1,281 px. The rail is the viewport's height minus the 58 px header:

| Viewport | Rail | Families shown of ten |
|---|---:|---|
| 1920×1080 | 1,022 px | 7 (computed) |
| 1440×900 | 842 px | 5 (computed) |
| 1366×768 | 710 px | 4 (computed) |
| 1280×720 | 662 px | 3 (observed today with five families: Multi-Window and Calendar sit behind the overflow control) |

The computed rows reserve the build control and 48 px for the overflow control, the size read off the 1280×720 frame. No row sits within 39 px of a threshold.

At 1280×720 a stranger reads Featured, Grid & Table, Forms and a three-dot button. Nothing says that Calendar, Scheduler, Gantt, Board, Multi-Window, Components or State & Data exist. `Neo.tab.plugin.Overflow` keeps the active tab visible, so a visitor who lands on `/examples/gantt` sees Gantt and loses another family instead.

## The Architectural Reality

- `apps/portal/view/shared/TabContainer.mjs`: `tabBarPosition: 'left'` and `Neo.tab.plugin.Overflow` on the header toolbar, for News and Examples (#20599).
- `apps/portal/view/examples/TabContainer.mjs`: `familyDefinitions` is the one ordered source of family, title, route and icon; `buildModes` feed the control at the rail's foot (`'Build: ' + …`, #20690).
- `src/tab/plugin/Overflow.mjs`: headers beyond the bar's main-axis extent collapse behind one control; the active and the focused header are protected.
- Styles: `resources/scss/src/apps/portal/shared/TabContainer.scss`, `resources/scss/src/apps/portal/examples/List.scss`.
- Design authority: "One overview page per family on the portal at the kitchen-sink standard" (#20498, Intended solution shape 1). The rail's capacity was never decided. #20690 kept "the section's tab bar" as an avoided trap of that leaf, and #20599 put "the bar's visual design: rotated labels, icons" out of scope while noting that "each new tab still costs height".
