# Wait for a rendered popup target in the Workstation two-root drag test

## Context

On the 14.1 release path, the existing two-root Workstation test sometimes releases the held Feed tab as soon as the coordinator reports Metrics’ popup as the active target. The pane stays at its source and the worker reports `target-refused`. [Hosted shard](https://github.com/neomjs/neo/actions/runs/46128143863/job/140927266665)

## The Problem

The same signature ran on untouched `dev@0e9fa32f2c` in one of two attempts. A diagnostic copy reproduced it twice in three runs. The two failed releases had a current preview in the worker and an unsettled header proxy. The target DOM watcher observed neither the preview nor the header before release, and `commitDrop` was never entered. In the passing run, both appeared before release and the same-Group transfer committed. A separate exact `14.0.0` control passed twice.

## The Architectural Reality

The [existing positive control](https://github.com/neomjs/neo/blob/0e9fa32f2c5d1f4793b0566aed0966909c467ff7/test/playwright/e2e/workstation/WorkstationTwoRootsDragNL.spec.mjs#L503-L519) observes the active target and gesture token. [DragTarget](https://github.com/neomjs/neo/blob/0e9fa32f2c5d1f4793b0566aed0966909c467ff7/src/dashboard/dock/window/DragTarget.mjs#L380-L395) already exposes renderer settlement for the retained payload. Its drop guard correctly refuses an unsettled proxy.

Design authority: [ADR 0029 §2.3 and §2.8](https://github.com/neomjs/neo/blob/dev/learn/agentos/decisions/0029-docking-design.md) govern same-Group admission and the preview-to-operation path. The original rendered witness is `#18379`.

## The Fix

In the existing Workstation positive control, wait for the active target’s renderer settlement for the retained Feed payload. Recheck target, payload and gesture token before releasing. The locally repaired positive and corrupt-ownership arms passed twice each on untouched Engine source.

Prescription checked: `test/playwright/e2e/workstation/WorkstationTwoRootsDragNL.spec.mjs` owns the positive control’s timing. `DragTarget.awaitRemoteDragEmbodiment` already supplies exact target settlement.

- [ ] The two arms pass twice each in Chromium with no retries.
