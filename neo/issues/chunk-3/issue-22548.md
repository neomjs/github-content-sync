# Publish five mobile examples in the Portal catalog

## Context

The v14.1 mobile epic requires discoverable, runnable phone examples. On `dev@76d743e589`, the Portal has 171 catalog records, including Contact Editor. It does not yet list the five new standalone mobile examples. The [rehearsal](https://github.com/neomjs/neo/issues/22414#issuecomment-7234401723) built all 20 example targets, generated ten covers, and passed twenty 390 × 844 Portal launches in Production and ESM.

## The Problem

Visitors currently need a direct URL for the five examples. Several entry points start in the default Light scheme even after a Dark Portal launch. Catalog records need a working route and the two covers they reference.

## The Architectural Reality

The group JSON under `apps/portal/resources/data/examples/` owns discovery. Every card uses that record's four build targets and paired cover names. The entry module owns theme startup, and Adaptive Navigation already uses `resolveStartTheme(Neo.config)`. The standard capture producer records the compiled example's opening frame. Pages serves those cover bytes.

Design authority: [Mobile epic #22414](https://github.com/neomjs/neo/issues/22414) calls for a phone example for each mobile feature. [The prior catalog publication pass](https://github.com/neomjs/neo/issues/21934) places covers on Pages before enabling their records.

## The Fix

Add Adaptive Navigation and Floating Action Button under Buttons, Menus and Toolbars, Swipeable Sheet under Dialogs and Overlays, and List Swipe Actions and Pull to Refresh under Lists and Galleries. Retain every current record including Contact Editor. Make the four missing entry points honor the existing theme query. Refresh any changed Portal metadata with its existing generator. Use the standard capture tool to generate the Light and Dark cover pair for each record from the compiled release inputs.
