# A grid example shows the built-in cell types on one sheet

Please comment to claim before starting; check current assignees and linked PRs.

## Context

New example 3 of the Grid & Table slate ([#21142](https://github.com/neomjs/neo/issues/21142#issuecomment-6924949418)), a leaf of #21175 (the Grid & Table group, under #21140). The visitor's question: what can a cell be?

## The Problem

The grid ships 14 column types under `src/grid/column/`. Seven of them appear in no example and no app of this repository: `countryFlag`, `currency`, `githubOrgs`, `githubUser`, `icon`, `iconLink` and `linkedin` (searched on `dev` `c40689ef53` by `type: '<name>'` and by import path). No example uses more than five. A buyer who asks whether a cell can show a flag, a formatted amount, a sparkline or a link has to read the source to find out.

## The Architectural Reality

- `src/grid/column/`: `AnimatedChange`, `AnimatedCurrency`, `Component`, `CountryFlag`, `Currency`, `GitHubOrgs`, `GitHubUser`, `Icon`, `IconLink`, `Index`, `LinkedIn`, `Progress`, `Sparkline`, `Tree`, on `Base`. Each class's JSDoc says which record value it reads.
- A column takes its type by `type: '<name>'`, as `examples/grid/animatedRowSorting/Viewport.mjs:67` does with `progress`.
- `examples/grid/headerGroups` is the model for the page: its own viewport, a headline, one instruction line, a theme button, both themes.
- Placement: a sibling folder `examples/grid/<feature>/` with `app.mjs`, `index.html`, `neo-config.json`, `MainContainer.mjs`, `MainModel.mjs` and `MainStore.mjs`.
- The grid's guide is `learn/guides/datahandling/Grids.md`.
- Design authority: n/a, a new example.

## The Fix

1. **A new folder `examples/grid/cellTypes`**, after the `headerGroups` model.
2. **One sheet that needs the types**, at least 30 rows, for example a directory of open source contributors or of customers: an index, a person (`githubUser`), a country flag, an amount (`currency`), a value that ticks (`animatedCurrency` or `animatedChange`), a progress bar, a sparkline, an icon, a link with an icon, a LinkedIn link, organisations, and a button (`component`).
3. **Each header names its type**, for example "Revenue · currency", so a visitor maps the cell to the config.
4. **`tree` stays out.** It needs a tree store and has two cards of its own.
5. A new catalog record with the group `grid-table`, `feature` and `lookFor`, and `scope` if a type loads something from the network (an avatar).

## Acceptance Criteria

- [ ] At least twelve of the thirteen types other than `tree` are on the sheet, each in a column of its own whose header names the type.
- [ ] No cell is empty or broken at 1440 × 900 and at 390 × 844. Accounts and links resolve, and the data names nobody who is not public under that name already.
- [ ] One column's values change while the visitor watches.
- [ ] A spec under `test/playwright/e2e/grid/` opens the example and asserts one rendered cell per type.
- [ ] Both themes; the selection can be moved by keyboard.
- [ ] **Look:** the first frame at both sizes is on the PR, and the design seat reads it before code review.
- [ ] A catalog cover is shot from the default state with the producer of #20679, or the PR names the change that brings it.

## Out of Scope

New column types; changes to an existing type. A type that turns out broken is filed and left off the sheet, and the PR says so.

## Avoided Traps

- **A column per type on meaningless data.** The sheet is of something, and each type fits its column.
- **Twelve narrow columns that scroll off a phone.** The PR says how the sheet reads at 390 px.
