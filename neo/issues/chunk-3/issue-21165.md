# The tree grid at scale opens on its tree

Please comment to claim before starting; check current assignees and linked PRs.

## Context

Row 3 of the Grid & Table slate ([#21142](https://github.com/neomjs/neo/issues/21142#issuecomment-6924949418)), a leaf of #21140, and one of six examples to renew before the read of Fri 20 Nov.

## The Problem

`examples/grid/treeBigData` opens as ten collapsed rows named "Folder 1" to "Folder 10" above two thirds of empty screen: the generator creates every folder collapsed (`MainStore.mjs:202`). The tree column, the helper lines and the value banding that make it the strongest tree in the section appear only after a click. Its size (20,000 rows, depth 5; `MainStore.mjs:24`, `:46`) is in a panel behind a menu button. Rows are "Folder n" and "File n" with first names and random numbers.

## The Architectural Reality

- `examples/grid/treeBigData/`: `MainStore.mjs` (the generator), `GridContainer.mjs` (columns, `:54` to `:65`), `ControlsContainer.mjs` (sizes, Expand All, Collapse All, theme, banding, helper lines), `MainContainer.mjs`.
- The data lives in a `Neo.data.TreeStore`; the tree column is `type: 'tree'` (`src/grid/column/Tree.mjs`).
- Five files under `test/playwright/` load the folder: `e2e/grid/TreeBigData.spec.mjs`, `e2e/portal/ExamplesCatalogNL.spec.mjs`, `unit/apps/portal/view/examples/TabContainerController.spec.mjs`, `component/component/SplitterHeavyContent.spec.mjs` and `e2e/dashboard/DockHeavyContentSplitNL.spec.mjs`. `#18439` (closed) records that two e2e arms here were intermittent on hosted runners.
- Design authority: "Every renew and every new row is then filed as its own leaf under #21140" (#21142), row 3 of its Grid & Table table; the bar is the one #21140 names: "an example resets, works at phone width, in both themes, by keyboard".

## The Fix

1. **The default state shows the tree:** the first level expanded, or the first two branches to depth 2, so that the first frame shows nesting, helper lines and banding.
2. **The node count is on screen without the panel:** total nodes and visible rows.
3. **A hierarchy that means something.** The generator's levels take names from a domain, for example company, department, team and person, or region, country and site, and at least one numeric column is a measure that makes sense on every level. Size and determinism of the generator stay.
4. Specs change where they assume the collapsed start.

## Acceptance Criteria

- [ ] The first frame shows at least three levels with helper lines at 1440 × 900, and at least two at 390 × 844.
- [ ] Total and visible node counts are on screen without opening the panel.
- [ ] No row is named "Folder n" or "File n".
- [ ] Expand All, Collapse All and the size controls still work, and the five spec files pass (`npm run test-unit -- <file>`, `npm run test-e2e -- <file>`, `npm run test-components -- <file>`).
- [ ] Both themes.
- [ ] **Look:** the first frame at both sizes is on the PR beside today's frame, and the design seat reads the pair before code review.
- [ ] The catalog cover is re-shot from the new default state with the producer of #20679, or the PR names the change that brings it.

## Out of Scope

Changes to `TreeStore` or the grid; `examples/grid/tree`, which gets its own leaf; the workbench (#21143).

## Avoided Traps

- **Everything expanded at 20,000 rows.** A wall of rows says as little as ten folders.
- **Names from a list of random words.** The levels need a domain a reader recognises.
