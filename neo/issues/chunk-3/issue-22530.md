# Bind HighlightJs and its line numbers to theme-base roles

## Context

The [Material census by package](https://github.com/neomjs/neo/issues/22484#issuecomment-7233945527) identifies 23 HighlightJs utility properties among the open theme-base work. At `dev@76d743e589`, the Neo Light and Dark folders each carry 19 HighlightJs and four line-number properties.

## The Problem

The structural utility sheets consume these properties. A theme generated from consolidated `theme-neo` has the roles but cannot inherit the values from the legacy Neo folders. The current component test also links those legacy URLs directly.

## The Architectural Reality

[ADR 0044](https://github.com/neomjs/neo/blob/76d743e589440a8381d1875a92b1a346a0a821cc/learn/agentos/decisions/0044-design-system.md#L128-L134) assigns syntax families to existing roles. The worker-rendered Markdown path consumes the Engine sheets. The Portal Docs Source pane separately loads its vendor syntax palette, so it provides an independent compatibility check.

## The Fix

Bind the 23 properties in two `theme-base/util` sheets and retire the corresponding four legacy Neo sheets. Use the existing syntax-role table. Bring the highlighted gutter fill and separator choices to the design seat for the Light/Dark variants where the old treatment differs. Update fixtures that currently link the retired sheets and measure actual resolved browser colours.

## Contract Ledger

| Surface | Authority | Behavior | Evidence |
| --- | --- | --- | --- |
| HighlightJs colours | ADR 0044 syntax reuse | Keywords use danger, numbers and strings info, tags brand, comments muted, additions and deletions their subtle status backgrounds. Further syntax families use existing roles. | Computed colour and contrast on engine-highlighted content |
| Line gutter and highlighted line | Existing structural reader and the design-system step-6 rules | Resolve line numbering, separator and highlighted fill through theme-base in both schemes. Theme-specific declarations retain their override path. | Multiline content, line numbering and a real highlighted row |
| Theme delivery | #22484 | Stock Neo and generated themes resolve the same hooks from shared sheets. | Exact Light/Dark and generated-theme browser witnesses |

Prescription checked: `resources/css/theme-base/util` owns utility value bindings. Decision Record impact: aligned with ADR 0044.

## Acceptance Criteria

- [ ] Both utility sheets resolve all 23 existing properties through theme-base. Only their four legacy Neo copies retire.
- [ ] A real highlighted code block and line gutter paint in Neo Light and Dark. Verify syntax and highlighted-line contrast and record intentional paint changes.
- [ ] A fresh generated theme paints the same utility content in both schemes. The classic theme and standalone Docs Source checks retain their existing behavior.
- [ ] Theme guards and scoped equality pass. Frame evidence shows the whole relevant surface in Light and Dark.

## Out of Scope

Vendor grammar, parser, source-view routing and categorical palette changes.
