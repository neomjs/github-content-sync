# DateSelector throws when weekStartDay changes during a month slide

> **Reserved for @sloemo01**, who found it while writing #19006's month-grid witness (#19171). The maintainer team will not claim it. It is a natural next step from that spec: the red arm already half-exists there.

## Context

#19171's weekend arm moves `weekStartDay` first and the month second, and it waits for the sidebar's day names in between. Its comment explains why: run the other way round, the pair crashed. The PR works around the crash; this issue reports it.

Reproduced on #19171's head `f42ce1f9b3`, which changes no file under `src/`:
1. Mount the `calendar-month` component fixture.
2. Move `currentDate` from February to August 2027.
3. Immediately afterwards, set `weekStartDay: 1`.

The page throws `Cannot set properties of undefined (setting 'transform')`, and the fixtures' worker-error gate fails the test. The month grid itself ends correct, with row 6 starting on `2027-07-26`. Only the sidebar `DateSelector` throws.

## The Problem

A user who changes the week's first day in the calendar settings while the sidebar is still sliding to another month gets an uncaught error. The same applies to any code that moves both values back to back.

## The Architectural Reality

- `DateSelector#changeMonth` (`src/component/DateSelector.mjs:461`) starts a slide by wrapping the day view in an animation wrapper.
- `changeMonthTransitionCallback` (`:520-525`) later writes `me.vdom.cn[1].cn[0].style.transform`.
- `afterSetWeekStartDay` (`:397-399`) calls `recreateDayViewContent(false, false)`, which rebuilds the day view in place.

The likely mechanism is an inference, still to be confirmed by the red arm below: the rebuild lands while the slide is in flight, so the callback reads a node that is no longer the wrapper and has no `style`.

## The Fix

A config change during a month transition must not read or reshape the transition's vdom. Two plausible shapes:
- defer the day-view rebuild until `isUpdating` clears;
- have the callback re-resolve its wrapper and stand down when it is gone.

Choose from the red arm, not from this sketch.

## Acceptance Criteria

- [ ] A component arm that moves the month and then `weekStartDay` back to back is red before the fix: the page error above.
- [ ] After the fix, that arm is green: no page error, the month grid's row 6 starts `2027-07-26`, and the sidebar's day names start with Monday.
- [ ] #19171's weekend arm no longer needs its ordering: its comment is updated to point here.
