# Delete resources/content from the engine once its authored families and readers have moved

## Context

The operator decided on 2026-09-23 to delete the engine's `resources/content` fully. D#19051 (graduated 2026-09-24) puts the deletion last among #17416's leaves (item 5). The tree holds 17,929 tracked files (193 MB), last written by the retired data-sync pipeline on 2026-08-26. Its conversations now publish from `neomjs/github-content-sync`; its two authored families, release notes and concepts, need homes first.

## The Problem

Deleting the tree while anything still reads it turns stale data into failures:

- The next release stops at `publish.mjs` if the release notes have not moved (#19157).
- The pages deploy stops at its fail-loud content step (D#19051, comment 18580522).
- Every runtime reader still deriving the tree from `projectRoot`/`cwd`/`__dirname` breaks (#19158's census).

The order is the whole risk. Nothing mechanical holds it except this ticket's blockers.

## The Fix

Delete `resources/content` in one commit once the blockers close: the release notes have moved (#19157), the concepts have moved (#19093), the reader census's repoint leaves have landed and its guard is green (#19158), and pages builds from the corpus (neomjs/pages#10). Remove the retired writers in the same change: the data-sync pipeline workflow and scripts that still name the tree, found by the census.

## Acceptance Criteria

- [ ] **AC-1** `resources/content` is gone from `neo`, and `git ls-files resources/content` is empty.
- [ ] **AC-2** #19158's guard is green on the deletion commit, and the engine's CI, a pages build at the release tag and a `publish.mjs` dry run all pass.
- [ ] **AC-3** No retired writer of the tree survives: every census row marked "writer" is removed or repointed in the same change.

## Out of Scope

- The history rewrite that would remove the tree from past commits (not planned).
- Any reader repoint, which comes from #19158's leaves.

## The content-root guard is live, and this deletion is where its baseline ends

#19167 (merged, `eb58998343`) added `check-content-root-derivations`, a lint-staged hook plus the `Content Root Derivation Lint` CI job.
- **What it catches:** any new path into `resources/content` that engine code under `apps/`, `buildScripts/` or `src/` spells from literals. It holds the census's 34 literals in 12 files as `check-content-root-derivations-baseline.json`.
- **What this means for the PR that deletes the tree:**
  - The ratchet fails downward until the rows of every retired or repointed file leave the baseline, so this PR edits the baseline in the same commit. #19166 removes the generator rows first.
  - After the deletion, the remaining rows are path rules such as `check-package-contents`, `check-chore-sync` and `classify-test-scope`. They go with the tree, and the baseline should end empty.
  - The guard cannot see a path assembled from non-literal values. This deletion's post-merge build and the portal smoke test are what catch any reader of that kind.
- **Sunset:** once the baseline is empty, decide whether the guard stays as a zero-baseline check against the frozen path coming back, or retires, in which case its workflow and lint-staged entry go with it. Either is defensible; the decision belongs here, not in a later cleanup.
