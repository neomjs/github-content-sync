# A number field holding 0 hides its clear button

## Welcome 👋

Neo's text and number fields show a small ✕ "clear" button while they hold a value. Put `0` in a number field and the button disappears, so a user cannot clear a zero. The code *tries* to count `0` as a value; one token spoils it. A real bug with a one-line fix and a test: an ideal first PR.

This is a **good first issue** for Hacktoberfest 2026. It needs Node.js and a clone of this repository: no Docker, no AI setup.

> [!IMPORTANT]
> **Reserved for first-time Neo.mjs contributors.** The maintainer team will not claim, edit, or implement this issue through **2026-10-31**. Comment here to claim it, and ask anything on this issue.

**Set up once:** follow [Set up the engine from a clone](https://github.com/neomjs/neo/blob/dev/CONTRIBUTING.md#set-up-the-engine-from-a-clone), including `npm run bundle-browser-deps`: without it the unit suite selects zero tests.

## The bug

`src/form/field/trigger/Clear.mjs`, `getHiddenState()`:

```js
if (value === 0) {
    value = '0'
}
return !field.value || value.toString().length < 1
```

The first three lines turn `0` into `'0'` so that it counts as a value. The return statement then checks `field.value` (still `0`, which is falsy) instead of the local `value`, so a zero hides the button anyway. Measured on `dev` (2026-09-23), with a `NumberField` and `clearable: true`:

| `value` | clear button `hidden` | should be |
|---|---|---|
| `5` | `false` | `false` |
| `0` | **`true`** | `false` |
| `7` | `false` | `false` |
| `null` | `true` | `true` |

## Where things live

- Source: `src/form/field/trigger/Clear.mjs` (the field reaches it with `field.getTrigger('clear')`)
- New test file: `test/playwright/unit/form/field/trigger/Clear.spec.mjs` (the folder is new)
- Pattern to copy: `test/playwright/unit/form/field/InputWidth.spec.mjs` (creating a field in a unit test)
- Tip: a number field needs one main-thread stub while your tests run. Install it in `test.beforeAll`, only if it is missing, and remove it in `test.afterAll`, exactly as `test/playwright/unit/apps/colors/ViewportController.spec.mjs` does in its `test.beforeAll`: `const main = Neo.ns('Neo.main', true); if (!main.DomEvents) { main.DomEvents = {registerDisabledInputChars() {}, unregisterDisabledInputChars() {}}; /* delete it again in afterAll */ }`. Do not put it at the top of the file: another spec imports the real `DomEvents`, and `npm run test-unit` then stops with `Namespace collision in unitTestMode for Neo.main.DomEvents`.

## Done when

- [ ] The spec is written **first** and fails on the `0` row: paste that failing output in your PR.
- [ ] `getHiddenState()` checks the local `value`, so `0` shows the button.
- [ ] The spec covers every row above, plus a text field holding `''` (hidden) and holding `'x'` (shown).
- [ ] `npm run test-unit -- test/playwright/unit/form/field/trigger/Clear.spec.mjs` passes.
- [ ] `npm run test-unit` passes.
