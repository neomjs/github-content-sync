# The calendar month view shows no days when there are no calendars

> Reserved for @sloemo01, who found this while writing #19006's component-tier witness. The maintainer team will not claim it.

## Context

A month view with no calendars shows its header and an empty scroll area: no weeks and no days. @sloemo01 measured it in the component tier on #19006: `weekCount: 0, dayCount: 0`. Their comments there trace the chain.

## The Problem

Measured on `dev` at `64ff609`, with real `Calendars` / `Events` stores and the mounted `Neo.calendar.view.month.Component`, counting `neo-week` rows:

| calendars | events | weeks after mount |
|---|---|---|
| 0 | 0 | **0** |
| 1 | 0, store loaded | 18 |
| 1 | store never loaded | **0** |
| 1 | 1 | 18 |

A month grid should show its days whatever the data. Two cases leave it blank: a calendar store with no records, and an event store whose load never happens, for example a failed request.

## The Architectural Reality

`src/calendar/view/month/Component.mjs` builds the grid in `createContent()`. Every path that reaches it on first render first asks for a store count:

- `construct()` sets `needsEventUpdate` only when both stores have records;
- `afterSetMounted()` calls `createContent()` only when `needsEventUpdate` is set;
- `onEventStoreLoad()` builds only when the calendar store has records, and `onCalendarStoreLoad()` only when the event store has records.

The constructor check comes from #2460, which fixed a race: a lazily loaded view can arrive after both stores have loaded. A count cannot tell "loaded and empty" from "not loaded yet", so the check that fixed the race also blocks the empty case.

## The Fix

The days render on mount whatever the stores hold. Events still need both stores.

## Acceptance Criteria

- [ ] With no calendars and no events, the mounted month view renders 18 `neo-week` rows and 126 `neo-day` cells.
- [ ] With one calendar and an event store that has not loaded, the days render.
- [ ] With calendars and events loaded, the events render in their day cells, as before.
- [ ] An event whose calendar is not in the calendar store does not throw.
- [ ] A component-tier spec covers the no-calendar mount (@sloemo01's `calendar-month` fixture fits).
- [ ] `npm run test-components` and `npm run test-unit` pass.

## Out of Scope

- The week and year views use the same count check (`week/Component.mjs` `construct()`, `YearComponent.mjs` `construct()`). Whether they also render empty has not been measured.
- #19006's other assertions.

## Avoided Traps

- **Dropping the count checks outright.** `createWeek()` reads `calendarStore.get(record.calendarId).active`. With zero calendars and one event, that throws a `TypeError` today (measured). The events need the calendars, so the days are what must stop waiting.
- **Re-breaking #2460.** The view can be constructed after both stores have loaded, so a load listener alone never fires.
