# A form field's bottom margin depends on which stylesheet loaded last

## Context

This surfaced on 2026-09-25 while fixing the visual gate of neomjs/neo-agent-institution#212. A hidden card that created a TextField at boot moved the Agent OS Accounts form's fields by 5px each, and its golden by 9,975 px, with no change to that form. The cause is in the engine: two form rules of equal specificity, where stylesheet load order picks the winner. #212 avoided the trigger by creating its card on demand; the engine tie remains.

## The Problem

`resources/scss/src/form/Container.scss` gives every direct child `margin-bottom: 10px` through `.neo-form-container > *`. Two field roots set their own bottom margin at the same specificity, (0,1,0):
- `.neo-textfield` sets `margin-bottom: 5px` in `form/field/Text.scss`. Number, Date, Time and the other fields extending TextField inherit it.
- `.neo-file-upload-field` sets `margin-bottom: 2.5rem` in `form/field/FileUpload.scss`, which reserves space for its error message.

For those fields directly inside a form container, whichever stylesheet loaded later wins. Measured in the Agent OS app on Institution `dev` `d93f7db4f2` (Chromium, the visual config):
- `form/Container.css` at link index 77 and `form/field/Text.css` at 80: the fields get 5px.
- With a TextField created earlier elsewhere, Text.css moves to 29 and Container.css to 88: the same fields get 10px.

So one form renders two ways, depending on what else the app created first, hidden components included.

**History.** @tobiu's `a748a94664` (2020-01-08, "form.Container: basic styling") shipped the rule in one bundle. That bundle's `form/_all.scss` imported `field/Text` (line 10) before `Container` (line 13), so the container rule always won, and fields in a form were authored with a 10px bottom margin. Per-class theme files that load on first use turned that fixed order into a race.

## The Architectural Reality

- **Load order.** `Neo.component.Abstract#afterSetWindowId` calls `Neo.currentWorker.insertThemeFiles(windowId, proto)`. `Neo.worker.App#insertThemeFiles` inserts each class's theme files once per window, parents first, through `Neo.main.addon.Stylesheet.addThemeFiles`. Insertion order is therefore first-creation order, and `hidden` does not defer it.
- **Only the base rule ties.** The last-child rule `.neo-form-container > *:last-child` is (0,2,0) and wins in either order.
- **Precedent.** #14970 made a dock visibility rule independent of stylesheet order by raising one selector.

## The Fix

**Decision first, from @tobiu, who authored the rule:**
- **(A) The container governs: 10px, as authored (recommended).** Move `.neo-textfield`'s root margins into `:where(.neo-textfield)`. The container's spacing then always wins inside a form, standalone fields keep 5px, and layout stays with the parent.
  - `FileUpload`'s 2.5rem is functional (error space), so it keeps its specificity or moves the reserve inside the field.
  - This moves forms that render 5px today, the Agent OS Accounts golden included.
- **(B) The field governs: 5px, as the measured path renders today.** Wrap the container's base rule as `:where(.neo-form-container) > *` and keep the last-child rule as is.
  - Fewer pixels move.
  - Every child's own root margin keeps overriding the container's spacing.

Then add one line in the SCSS naming the decision, a regression witness, and the visual census below.

## Acceptance Criteria

- [ ] A field's bottom margin inside `.neo-form-container` is the same whichever of `form/Container.css` and the field's stylesheet loads first. The SCSS says in one line which rule governs and why.
- [ ] A regression witness loads the stylesheets in both orders. It asserts the same computed `margin-bottom` for a TextField child and a FileUpload child, and `0` for the last child. On current `dev` it is red in one of the two orders.
- [ ] The PR lists the examples and apps whose form spacing changes, with a before/after for at least one. The starting census is the 10 files under `examples/` and `apps/` that import `form/Container.mjs`.
- [ ] Post-merge, on the next neo pin bump in neomjs/neo-agent-institution: the Agent OS Accounts golden is re-captured if the chosen option moves it.

## Out of Scope

- Other equal-specificity ties in the theme; this ticket pins the measured one.
- When or how theme files load.

## Avoided Traps

- **Fixing the load order instead of the specificity.** Insertion follows creation order by design, so any app can reorder it.
- **`!important` or a doubled-class selector.**
- **Re-capturing goldens to match whichever order happened to run.**
