# Canvas worker per window group: a second root must not kill the first

## Context

A second main window of the same app (a no-opener root: a new tab, a bookmark, a second `index.html`) kills the first window's canvases in Chromium. Both roots share one canvas SharedWorker, and the first paint into a DOM canvas owned by another process kills that worker's host process (D#18730, measurement 2). @tobiu closed #18376 into D#18730: grouping workers per window group is the fix.

This ticket is the **graduated v13.2 crash slice** of D#18730: its fold `[DIVERGENCE_FOLDED @ DC 18564640]`, corrected at body 2026-09-23T09:35:41Z. The Discussion's wider heap-boundary question (B, D, E, F, OQ1–OQ4) stays open after the cut. Roadmap cornerstone 4's done signal is this ticket's acceptance: the two-root witness green, with both roots still painting.

## The Problem

`worker/Manager.mjs#createWorker` names every worker `neomjs-<kind>-worker`, so every window of an origin connects to **one** canvas SharedWorker. An opener popup shares its root's browsing-context group and process, so sharing with it is safe. An unrelated root does not, so sharing with it is fatal.

The app worker has the matching single point: `App#onRegisterPort` keeps one canvas port per worker *name* (`channelPorts[msg.origin]`). Under a per-group canvas worker, every group's canvas traffic would go to whichever group registered last (DC 18560992; confirmed independently by @neo-gpt-emmy).

## The Architectural Reality

- **Carrier rule, from the fold.** The canvas-group id lives in the window's own `sessionStorage`. It is honored only for a popup whose opener is live, which joins the opener's group, and for a boot reading `navigation.type === 'reload'`, which rejoins its stored group. Every other boot mints a fresh id and overwrites the copy: a duplicated tab, a session restore (`back_forward` in Chromium) or an inherited-id `navigate`. Falsifier receipts are in DC 18560016.
- **Startup order** (`dev@9dcc4ef088`). `core/Base#initRemote` waits for `connected`. `worker/Base#onConnected` fires it, then synchronously calls `Canvas#afterConnect`, which relays `registerPort`. `promiseRemotes` resumes a microtask later, so a group's `registerRemote` arrives over its new channel **after** its `registerPort`. A registered port is therefore *not* readiness (DC 18564605).
- **Send contract.** `Base#promiseMessage` mints its pending entry from the `Message` that `sendMessage` returns synchronously. Readiness must be settled **before** `promiseMessage`, never queued inside `sendMessage` (DC 18564414).
- **Departure.** `Base#removePort` records a departure before any listener hears of it, and `isDeparture()` needs both halves: `NEO_DEAD_PORT` plus a departed `windowId`.
- **Load failures** of a SharedWorker reach the page console (Chrome 152 logs `Failed to fetch a worker script.` for a 404 and for a module parse error), but no code learns of them: `onWorkerError` is bound on `worker.port`, and a MessagePort has no `error` event. `error` fires on the `SharedWorker` object. *(Corrected 2026-09-23: this line used to say the failure "reaches nobody" and deferred to #19092, which is now closed as not planned because that premise was false.)*
- **Unchanged by this slice:** the App, Data and VDom workers stay origin-wide, so `manager.Transaction` Groups and Neural Link routing do not move. ADR 0029 §2.1's one application heap and ADR 0020's shared App-Worker heap are preserved.

## The Fix

1. **Name the canvas worker per group** at `Manager#startWorker`, using the carrier rule, before the worker exists.
2. **Route per group in the app worker.** `onRegisterPort` keeps one canvas port per group and binds each channel's handler to its group. Canvas-bound sends resolve `windowId` → group → port.
   - A supplied `windowId` that names no connected window is always `NEO_UNROUTABLE`.
   - A **missing** `windowId` is `NEO_UNROUTABLE` only while more than one group is known. With a single known group it still sends.
   - Nothing ever falls back to another group.
3. **Readiness entry.** `Neo.worker.App#whenCanvasReady(windowId)` returns an awaitable. The per-group record `{booting | ready | failed}` stays internal, and a group is ready when its `Neo.worker.Canvas` registration arrives over its own channel. Canvas proxies (`RemoteMethodAccess#generateRemote`, origin `canvas`) await the same record, calling straight through once it is `ready`. `SharedCanvas#initAsync` and `Sparkline#initAsync` replace their `Neo.ns('Neo.worker.Canvas.loadModule')` polls with the entry.
4. **Failure and lifetimes.**
   - A load failure, observed by the group's main thread through this slice's own `error` listener on the `SharedWorker` object (a programmatic signal the console line does not give), or a start that stays silent past a bound, sets the record to `failed`, and the group's waits reject with `NEO_WORKER_START_FAILED`.
   - A caller's departure rejects only that caller's waits, with `NEO_DEAD_PORT` + `windowId`.
5. **Census.** Every app-worker call into a canvas remote passes `windowId`. Adapt argument contracts where needed, not just objects: `SharedCanvas` calls `renderer.setTheme(scalar)`, and cleanup calls carry no window identity.
6. **Dead canvas remotes** (DC 18559847 item 3). `DomAccess#getOffscreenCanvas` and `Canvas#retrieveCanvas` get `@deprecated`, because removing an exported remote is an API break. The `Manager` route `'message:getOffscreenCanvas'` to the undefined `DomAccess.onGetOffscreenCanvas` is deleted.

## Acceptance Criteria

- [ ] **Carrier rule:** a unit arm for every row of the fold's carrier table (root first load, opener popup and its reload, root F5, duplicated tab, session restore, no-opener popup, unrelated tab).
- [ ] **Routing:** unit arms for a registered group, an unknown supplied `windowId` (refused even with one group), a missing `windowId` with two groups (refused) and with one group (sends). No send ever reaches another group's port.
- [ ] **Readiness and the five outcomes** as unit arms: send, wait then send, departure (`isDeparture()` true), `NEO_UNROUTABLE`, `NEO_WORKER_START_FAILED` (load failure and bounded silent start).
- [ ] **Lifetimes:** a caller's departure cancels only its own waits and never rejects a live sibling on the same group. A group failure rejects that group's waits. `removePort`'s exact-port retirement holds through pending waits and channel replacement: late work from a departed caller is never sent through a surviving sibling, and never revives retired state.
- [ ] **Bootstrap arms:**
  - (1) A cold app worker with no `loadModule` proxy, whose canvas start fails or stays silent. `initAsync` reaches the bounded failure with no `TypeError` and nothing pending.
  - (2) A healthy group 1 plus a failed group 2. Group 2's components fail, and group 1's painted-liveness control still changes.
- [ ] **Census:** a predicate unit test holds that every app-worker call into a canvas remote passes `windowId`, including the adapted scalar and cleanup shapes.
- [ ] **The product witness** (e2e):
  - `NoOpenerRootRendererKill.spec.mjs` loses its `test.fail` and passes.
  - Two unrelated roots each paint after the other boots, in both directions, with the foreign control unchanged.
  - A same-group opener and popup still share.
  - A manual return while popups survive gets isolation (a fresh group; both paint), not a rejoin.
  - The lifecycle witness keeps main → canvas adoption (`DomAccess`) and the canvas → app acknowledgment in view.
- [ ] #19063's Group-tool witness passes unchanged.
- [ ] The two dead remotes carry `@deprecated`, and the dangling `Manager` route is gone.
- [ ] Existing canvas scenes and input keep working. No new performance claim is made.

## Out of Scope

- App, Data and VDom heaps per group (D#18730 row B), OQ1's manual-return **rejoin**, and any `manager.Transaction` Group change.
- A presenter or frame transport (row G, rejected: +9.4 ms/frame).
- Removing the two deprecated remotes; that waits for the next major.

## Avoided Traps

- **"A registered port means ready."** It does not: `registerRemote` follows `registerPort`.
- **Queueing inside `sendMessage`.** It would return a `Message` for a message it never sent.
- **Refusing every missing `windowId`.** That silently breaks single-window callers. The accepted contract refuses only when the omission is ambiguous.
- **Trusting a copied `sessionStorage` id.** A duplicate or a restore carries one, so only `reload` or a live opener admits it.
