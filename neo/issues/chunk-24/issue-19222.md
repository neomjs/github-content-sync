# Pre-release packs read a stale .npmignore and drop the Workstation

> **Correction, 2026-09-25 14:30Z. The premise changed; the original claim is kept below, struck.** The 13.2 *release* would ship the Workstation. `buildScripts/release/prepare.mjs` rebuilds `.npmignore`'s copy region from `.gitignore`, and `.gitignore` already carries the Workstation's three re-includes. Composed from `dev`, the release file adds 16 rules the committed copy lacks. The drop is real for every pack **before** the release step, because they read the committed file: CI's `check-package-contents`, an engine pinned by git commit (the Institution pins one), and #19047's dry run. That is the defect this ticket now covers.

## Context

#19047's AC-4 dry run, 2026-09-25: a scratch clone of `neomjs/pages` (`62cb7a2f`) with `neo.mjs` pinned to `github:neomjs/neo#f9a776c50c`, built by `node buildScripts/updateNeoVersion.mjs --force --engine-ref=f9a776c50c…` against the corpus pin `3894176e`. The build exits 0 and was not pushed. Served and loaded headless, the portal, a learn route and the dashboard dock demos all mount with no console errors. The Workstation returns 404 in every mode (`/apps/…`, `/dist/{development,production,esm}/…`), because the installed package's `apps/workstation/` holds only `README.md`. A git dependency installs through `npm pack`, which reads the committed `.npmignore`.

## The Problem

`.npmignore` is an authoritative header plus a copy of `.gitignore` below `# Original content of the .gitignore file`. The release step regenerates that copy, but between releases it goes stale, and every pack reads the stale one:

- **The package gate judges a different tarball.** `check-package-contents` runs `npm pack --dry-run` on the committed file, so its forbidden and required checks certify a file set the release will not publish. `findRulesLostOnRelease` covers one direction (a header rule a release would delete) and deliberately treats what the copy adds as the sync working.
- **Git-pinned consumers get a different package.** On `dev` today that is the Workstation missing, among 16 drifted rules.
- **A dry run cannot reproduce the release** through the ordinary install path.

## The Architectural Reality

- `buildScripts/util/npmIgnoreComposition.mjs#composeNpmIgnore` is the single composition, shared by the release step and the gate.
- Drift measured on `dev` (`composeNpmIgnore(dev .npmignore, dev .gitignore)` against the committed rules): +16 −1. The additions are the Workstation's three re-includes, `resources/data/reports/`, `.neo-ai-secrets`, `.neo-ai-data-parity`, `/opencode.jsonc`, `/.kimi-code/{mcp.json,config.toml}`, `.agents/skills`, `.claude/skills/`, `.claude/hooks/*` (plus its guard re-include), `.codex/hooks/`, and `.kimi-code/hooks/*` (plus its README). The removal is `resources/content/sandman_handoff.md`, which the header's `resources/content/` subsumes.

## The Fix

1. Commit the composition, so the committed file is what the release writes.
2. `check-package-contents` fails when they differ (`findReleaseDrift`: rules compared in order, because ignore files resolve last-match-wins) and prints the one-line sync command.
3. `checkPackageContents.spec.mjs`: arms for a missing rule, for order alone, for the in-sync case, and one reading the real files.

## Acceptance Criteria

- [ ] AC-1: `npm pack --dry-run` at the head lists all 28 tracked `apps/workstation/` files, with no forbidden entry and no missing required entry.
- [ ] AC-2: `check-package-contents` fails when the committed `.npmignore` differs from its release composition. The arm reading the real files is red on `dev` (+16 −1) and green at the head.
- [ ] AC-3: #19047's pages dry run, repeated against a `dev` commit that carries this, serves the four Workstation URLs with a mounted viewport. This is post-merge and recorded on #19047.
