# Seven examples throw on load and render nothing

Assigned to @bercedev, who claimed it first (#19923, #19924). One contributor per ticket: a second contributor picks another open good first issue.

## Context

Found by a headless sweep of all 158 `examples/**/index.html` and `apps/**/index.html` pages on the dev server (`dev` at `9771bebcb8`, 2026-10-20). The sweep recorded page errors, console errors, failed requests and duplicate ids; a control showed it catches errors thrown inside the App worker. These seven pages throw during construction and leave at most two DOM elements. Serving each page with every tracked file at `13.2.0` (request interception, same dev server) gives the same error, so they predate 13.3.

## The Problem

| Example | Error, with the top of its stack | Likely cause |
|---|---|---|
| `examples/calendar/weekview` | `Cannot read properties of null (reading 'setDate')` at `src/calendar/view/week/Component.mjs:837` ← `updateHeader` (`:967`) ← `construct` (`:257`) | `currentDate` arrives by `bind` (`:43`), so it is still null when `construct` builds the header |
| `examples/date/selectorContainer` | `Cannot read properties of null (reading 'format')` at `src/date/DayViewComponent.mjs:109` ← `createContent` ← `construct` (`:70`) | `intlFormatDay` arrives by `bind` (`:38`), so it is still null in `construct` |
| `examples/layout/form` | `child is not defined` at `src/layout/Form.mjs:60` | `applyChildAttributes(item)` still reads `child.ntype`, a name left over from before the rename to `item` |
| `examples/menu/panel` | `me.layout?.applyChildAttributes is not a function` at `src/container/Base.mjs:723` ← `menu/Panel.mjs:58` (`afterSetList`) | `insert` runs while `layout` is not yet a layout instance |
| `examples/popover` | `Cannot read properties of undefined (reading 'removeDom')` at `src/container/Base.mjs:248` (`afterSetIsVnodeInitializing`) | an entry of `items` is not a component instance yet, so it has no `vdom` |
| `examples/tablePerformance` | `table.createViewData is not a function` at `examples/tablePerformance/MainContainer.mjs:146` | the example calls a method the table no longer has |
| `examples/component/wrapper/openStreetMaps` | `Invalid class field 'maxZoom' … it shadows the config 'maxZoom'` (`src/core/Base.mjs`) | the example's `MapComponent` declares a class field over a config, which `Neo.create` refuses (the rule: `src/core/Base.mjs:102-104`) |

The "likely cause" column is from reading the stack and the named lines. Each fix confirms or corrects it.

## The Architectural Reality

- Bound configs (`bind`) arrive from a state provider after construction, so `construct` code that reads them sees their defaults.
- `container.Base` creates items and applies the layout during construction (`:519-524` and `:720-724`).
- `core.Base` refuses a class field that shadows a config, by design.

## The Fix

Per row: make construction tolerate a bound value that is not there yet (the date pair), use the right name (`layout/Form`), order layout creation before insertion or guard it (`menu/panel`), skip non-instances (`popover`), and bring the two examples up to today's API (`tablePerformance`, `openStreetMaps`). Fix in the engine where the engine is wrong, in the example where the example is.

## Acceptance Criteria

- [ ] AC-1: Each of the seven pages loads with no page error and renders its example.
- [ ] AC-2: Each engine fix (rows 1–5, where the engine is the cause) has a unit arm that is red before it.

## Out of Scope

- Pages that need an API key (`googleMaps`), an external library (`cesiumJS`) or a local Monaco build.
- Child apps that only render inside their parent app.
