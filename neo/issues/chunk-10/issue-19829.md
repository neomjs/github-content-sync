# Tree columns wrap their text in content-sized grids

## Context

The operator asked whether a tree grid works with content-sized rows. I checked with a scratch browser probe on dev `04ff2b09df` (deleted since):
- `wrapText` description columns grow their rows (62, 119, 176 px) and stack without gaps through expand, collapse and re-expand.
- A long tree label stays on one line with an ellipsis ("Base.mjs with a d…", 475 px of text in a 103 px box), and its row stays at 32 px.

The operator asked for tree-column wrapping in 13.3, with e2e tests.

## The Problem

`wrapText` has no effect on a tree column, for three reasons:
- `Row#applyRendererOutput` puts a `wrapText` column's content into the measured `.neo-grid-cell-text` block only for text or html renderer output (`src/grid/Row.mjs:320–326`). A component column's output, a vdom reference to its cell component, goes into the cell unwrapped (`:327–329`).
- `View#measureRowHeights` measures only cells whose first child is that block (`src/grid/View.mjs:965–973`), so the tree cell is never measured.
- The tree cell component styles its label `white-space: nowrap; text-overflow: ellipsis` (`resources/scss/src/grid/column/component/Tree.scss:41–47`).

## The Architectural Reality

- Design authority: content-sized rows and the `wrapText` column flag (#19661, #19662). A `wrapText` column's text wraps and sizes its row. `column.Tree` extends `column.Component`, so it inherits `wrapText` from `column.Base`.
- The off-screen pre-measurement (`measureOnly`) already skips component cells (`Row.mjs:206–210`). Tree rows are measured once mounted and use the estimate until then.

## The Fix

- The tree cell exposes the vdom of its label (`textVdom`). `View#measureRowHeights` measures a component cell through it, as it measures a text cell through its `.neo-grid-cell-text` block. It reads padding and borders per column, because a helper-lines tree cell has no vertical padding.
- The label wraps only in content-sized grids; everywhere else it keeps its one-line ellipsis. The indent and the toggle keep spanning the row, so the helper lines stay unbroken. A measured block around the whole tree cell would break them wherever another column is taller.
- `View#isShown` gets a component arm: the cell counts as shown once the component's last landed update rendered its root's classes and style, and its label, as its vdom describes them. The component's `needsVdomUpdate` cannot tell, because a row's update carries the component's vdom without clearing it. A filter left every re-bound tree cell flagged, and so unmeasured.
- When the tree cell's own update lands, it schedules the view's measure pass. That catches a cell skipped because its update lagged the row's.

## Acceptance Criteria

- [ ] In a content-sized grid, a `wrapText` tree column's long label wraps, and its row grows to fit it (e2e, browser-layout oracle).
- [ ] Expand, collapse and re-expand keep every row as tall as its tallest wrapped text, stacked without gaps (e2e).
- [ ] In a fixed-height grid, the tree label keeps its one-line ellipsis (e2e).
- [ ] A tree cell is measured through its label. A re-bound tree cell is not read before its own update lands, whether it gets a new label or the same label one level deeper, and is measured once that update lands (unit).
- [ ] The tree column's header filter keeps the matches with their ancestors, and the re-bound rows fit their new labels (e2e, unit).

## Out of Scope

- Pre-measuring the component cells of unseen rows.
