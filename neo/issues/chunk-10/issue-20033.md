# The overflow-menu spec snapshots the strip before the split reaches the DOM

## Context

A v13.3.1 AC-2 roving specimen ([D#19994 discussioncomment-19133550](https://github.com/neomjs/neo/discussions/19994#discussioncomment-19133550), cut record #20022). `WorkstationMaximizeOverflowMenuNL` › "docked control arm: clicking More tabs keeps the overflow menu open, focused, and partition-stable until selection" went red in a full `e2e/workstation` + `e2e/dashboard` run and is green alone. The `appliedHiddenIds` assertion passed. The visible-headers assertion failed: with the menu open, the DOM showed one header fewer while the plugin's `appliedHiddenIds` still equalled the pre-open set. The cut lead's triage: one ticket per cause.

**Observed** (Vega's run): the red and its signature. **Not retained:** which header vanished. **Inferred** (code read, below): the mechanism.

## The Problem

`waitForOverflowSettled` gates the pre-open snapshot on worker flags only: `measuring === false`, `projectQueued === false`, and a non-empty `appliedHiddenIds`. It then reads the DOM-visible headers.

Those flags do not mean the DOM holds the split. `Overflow#project` calls `applySplit`, which hides headers through `button.hidden = true`, a vdom update it does not await, and sets `appliedHiddenIds` synchronously. `project()` then releases `measuring` in its `finally`. On the common path nothing between `applySplit` and the `finally` awaits the owner's update; the only await is the conditional cluster re-measure. So the gate can pass while a header's removal is still in flight.

A snapshot taken in that window lists a header the worker already treats as hidden. When the delta lands (by then the menu is open), the visible list shrinks while `appliedHiddenIds` stays the same, which is exactly the observed signature. The spec's own pane-body click reveals focus-gated header actions, narrows the strip and triggers such a re-partition right before the snapshot. Full-run load widens the window enough to hit it; a solo run does not.

The alternative, a header leaving the strip without the applied set recording it (the #19989 class), is not excluded by observation, because the vanished header's identity was not retained. The fix's evidence has to discriminate.

## The Architectural Reality

- `src/tab/plugin/Overflow.mjs`: `applySplit` sets `button.hidden` / `button.show()` per header, then `me.appliedHiddenIds = [...hidden]`. `project()`'s `finally` sets `me.measuring = false`, and `publishProjectionState()` fires `overflowProjectionIdle`.
- `test/playwright/e2e/workstation/WorkstationMaximizeOverflowMenuNL.spec.mjs`: `waitForOverflowSettled` reads only the plugin's state; `assertOverflowMenuHoldsAndSelects` snapshots `preVisibleHeaders` from the DOM right after it.
- Precedent: #20020 / PR #20021 settled `WorkstationTabDragHeadersStayNL` on the DOM and the worker state together.
- An open menu parks projections (`queueOpenMenuProjection`), so nothing re-partitions underneath the open menu. The open-state reads are stable.

## The Fix

Spec-only. `waitForOverflowSettled` additionally polls until every header button's DOM visibility matches its membership in `appliedHiddenIds`: a hidden id has no rendered box, and every other id has one. Both arms use the helper, so both snapshot a landed split.

## Acceptance Criteria

- [ ] Both arms take their pre-open snapshot only after the DOM partition matches `appliedHiddenIds`.
- [ ] Under a load that widens the window (the page at 6× CPU throttle, the instrument #18721 used), the docked arm reproduces the visible-headers red on `dev` with the vanished header inside `appliedHiddenIds`, confirming the cause; with the fix it is green N/N. If the vanished header is outside the applied set, this ticket's premise is wrong and gets corrected here first.
- [ ] A disposition naming the cause is recorded on #20022 for the AC-2 line.

## Out of Scope

Whether `overflowProjectionIdle` / `whenProjectionIdle` should wait for the DOM. Both production consumers (the dock `MotionSignal` and the tab `SortZone` drag start) read that edge. It becomes its own ticket only if a falsifier shows a consumer harmed.
