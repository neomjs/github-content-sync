# RealWorld v1 renders unstyled and doubles its Popular Tags sidebar

## Context

Found by a headless sweep of every example and app on the dev server (`dev` at `9771bebcb8`, 2026-10-20). The 13.3 notes say both RealWorld apps work again (#19700, #19883, #19892). RealWorld2 does. RealWorld v1 loads articles and tags, but it renders unstyled and doubles its *Popular Tags* sidebar.

Observed in headless Chrome on `apps/realworld/index.html`:
- The page shows raw, unstyled HTML. Its only theme, `//demo.productionready.io/main.css`, now answers 404 with an HTML page, and Chrome blocks it (`ERR_BLOCKED_BY_ORB`).
- The sidebar is in the DOM twice under the same parent: 2 `.sidebar` nodes, 30 tag pills for 15 tags, 19 duplicate element ids.
- The comment form's placeholder avatar, `https://static.productionready.io/images/smiley-cyrus.jpg`, answers 404.
- Four leftover debug `console.log` calls write to the console (`HomeComponent.mjs:317`, `CommentComponent.mjs:159`, `ProfileComponent.mjs:223` and `:259`).

## The Problem

`HomeComponent#onConstructed` pushes the tag list's own `vdom` into its tree (`apps/realworld/view/HomeComponent.mjs:137`). The parent then renders the child's nodes as its own, and the child renders them again when its tags arrive, so the DOM gets two copies. `article/Component.mjs:183` embeds the comment form the same way. An article page shows one form today (checked), because nothing there updates the form beside its parent; the embed is the same defect waiting for that update.

## The Architectural Reality

- A container embeds a child component through `createVdomReference()` (`src/container/Base.mjs:523`, `:724`). A reference lets the child own its nodes; the parent's render keeps the child's place in the tree without expanding it.
- Red→green check: serving `HomeComponent.mjs` with `.push(me.tagList.createVdomReference())` instead of `.push(me.tagList.vdom)` gives 0 duplicate ids, 1 sidebar and 15 tag pills, with the 4 article previews unchanged (`dev`: 19 duplicates, 2 sidebars, 30 pills).
- The RealWorld project moved its shared theme into its repository: `realworld-apps/realworld`, `assets/theme/styles.css`, with `assets/media/default-avatar.svg` beside it. raw.githubusercontent serves files as `text/plain`, which a browser refuses as a stylesheet; jsDelivr serves the same file as `text/css` (28,850 bytes, checked at commit `ebbcdeb8d5`).

## The Fix

1. `apps/realworld/view/HomeComponent.mjs` and `apps/realworld/view/article/Component.mjs`: embed the tag list and the comment form with `createVdomReference()`.
2. `apps/realworld/index.html`: link the theme from jsDelivr, pinned to a `realworld-apps/realworld` commit.
3. `apps/realworld/view/article/CreateCommentComponent.mjs`: the placeholder avatar becomes the project's `default-avatar.svg`, pinned the same way.
4. Remove the four debug `console.log` calls.

## Acceptance Criteria

- [ ] AC-1: On the home view, the page has no duplicate ids, one *Popular Tags* sidebar, and one pill per tag.
- [ ] AC-2: The Conduit theme loads: the stylesheet request answers 200 as `text/css`, and the header renders styled.
- [ ] AC-3: An article page still shows one comment form, now embedded by reference, and its avatar loads.
- [ ] AC-4: Loading the home and article views writes no debug output to the console.

- Showing the signed-in user's own avatar in the comment form.
