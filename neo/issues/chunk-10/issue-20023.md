# v13.3.1 cut-prep: the release note, the version bump and the released-note drop

## Context

#20022 is the cut's record; its step 2 is this leaf. The cut is tomorrow morning (operator, 2026-10-22 23:00Z), so the note is authored tonight and the version lands in the morning, in one PR, the #19765 shape: `publish.mjs prepare` runs only from a clean `dev` at `origin/dev` whose `package.json` already names the new version, so this pass is a `dev` PR before the release PR, never inside it.

**Shape decision for a patch note** (lead, Tier 2, recorded here): the release-notes workflow asks for an epic with iterations for majors and minors; 13.3.1 is a patch cut 36 hours after 13.3.0 with one arc, so this leaf carries the note end to end instead of an epic, keeps the iteration banner until the cross-family review, and holds the bar the workflow sets (§5): a narrated note with one hero chapter, honest bounds and the Full Changelog tail, never a changelog dump, never a scope-shrinking "just a patch" framing.

## The Problem

- `package.json` reads 13.3.0, so `prepare` stops with "tag 13.3.0 already exists: bump package.json first".
- `.github/RELEASE_NOTES/v13.3.1.md` does not exist; `prepare`'s preflight errors without it.
- `PublishReleaseNoteOrphan.spec.mjs` requires every retained note to be at or above `package.json`'s version (Emmy's #19784 review found this the hard way at 13.3.0): tonight `v13.3.0.md` may stay beside the new note while the version is still 13.3.0; the morning's bump commit drops `v13.3.0.md` in the same commit.
- The note's scope numbers are counted now (34 pull requests merged into `dev` and 34 issues closed since 13.3.0 published at 2026-10-21 10:40:08Z, counted at 23:0xZ) and must be regenerated at the cut boundary and reconciled in the text.

## The Architectural Reality

- `buildScripts/release/publish.mjs`: `prepare` reads the version from `package.json` and the note from `.github/RELEASE_NOTES/v<version>.md`, drops older notes (`dropReleasedNotes`), stamps the note and opens the release PR; `finish` squashes to `main` and creates the GitHub release whose title is the note's first H1.
- Guards: `test/playwright/unit/buildScripts/release/PublishReleaseNoteOrphan.spec.mjs` and `ReleaseNoteFrontmatter.spec.mjs`; `npm run check-relative-links`.
- Release-notes workflow (`.agents/skills/release-notes/references/release-notes-workflow.md`): §1 iteration banner, §4 per-claim V-B-A and operator-confirmed designations, §5 the structural contract and the precedent set, §6 the staging-file lifecycle, §7 the cut-readiness checklist.
- Precedent: `v13.3.0.md` (header block, TL;DR, "in 2 Minutes", hero chapters, honest bounds, upgrading, Full Changelog with the GitHub-search counting line) and #19765/#19784 (the cut-prep pass).

## The Fix

One PR on `agent/<this>-v13-3-1-cut-prep` from `origin/dev`:

1. **Tonight:** `.github/RELEASE_NOTES/v13.3.1.md`, iteration banner on. Header block (Release Type: patch, per the operator; Stability and Upgrade Path lines), TL;DR, "13.3.1 in 2 Minutes", one hero chapter on the day of ordinary-use testing and the fixes it produced (tab overflow and maximize, popup drags and tear-outs, the 100k Matrix grid, the main-thread clip rect, persistence), the grid header-menu follow-ups from the first outside feedback, what the tests learned (D#19994, the gate, #20017's cross-window delta misroute found by the gate runs), honest bounds (the standing watch: #20009's trigger, the roving intermittents), upgrading from 13.3.0, and the Full Changelog grouped by surface with the counting line. Every number and claim anchored to its PR, issue or run.
2. **Morning, after the last fix merges:** bump `package.json` (and the lock's root version) to 13.3.1, drop `v13.3.0.md`, remove the banner, recount at the cut head and reconcile the text, re-request the review at that head.
3. Cross-family review on each head; the PR merges last before `prepare`.

- A grouped changelog as the note: §5 bans it; the groups support the narrative in the tail.
- "Just a patch" framing: §1 rule 4; the window has one deep arc and 34 pull requests, and the note says so with its anchors.
