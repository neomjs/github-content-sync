# Grid: height corrections keep the visible row and the pinning origin stable

## Context

This is leaf L4 of epic #19658, blocked by #19661 (the geometry model). When measured heights correct rows above the viewport, the visible record must not jump. Scroll corrections must also agree with `GridRowScrollPinning`, which reconciles the actual scroll position with the worker's acknowledged render origin.

## The Problem

A height correction above the anchor row moves every following offset. If `scrollTop` is not adjusted with the transforms, the view jumps. If it is adjusted outside the pinning addon's bookkeeping, pinning can double-displace rows or stay stuck after a thumb release.

## The Architectural Reality

- **The pinning addon:** `GridRowScrollPinning.applyPinning` computes the actual `scrollTop` minus the worker's last one (L117). `onDeltaUpdate` adopts the view's metadata (L159). Pinning can stay active after a thumb release until the worker catches up.
- **The pipeline:** existing scroll-to-fresh-rows takes 50–80 ms (D#19645 probe 6), which pinning already covers.

## The Fix

- **The anchor rule:** a correction above the anchor row adjusts the scroll offset in the same update as the transforms, through the pinning addon's acknowledged origin, never as an independent `scrollTop` write.
- **Thumb drags:** extent changes are held during an active thumb drag and settle at release or acknowledgement. The final row stays reachable before and after settlement.
- **The race spec** (Sophie, D#19645 18878897): during a thumb drag, deliver a height correction above the anchor and an older render acknowledgement in opposite orders, then release. Transforms, both extents and the acknowledged origin must converge without double displacement or stuck pinning.

## Acceptance Criteria

- [ ] A height correction above the visible record leaves that record's on-screen position unchanged; this is a spec.
- [ ] Sophie's ordering race passes in both delivery orders, with no double displacement and no stuck pinning; this is a spec.
- [ ] During a thumb drag the extent does not change, and after release it settles while the final row stays reachable.
- [ ] Reverse wheel scrolling over freshly measured rows shows no visible jump at the viewport, checked in an e2e.

## Out of Scope

Measurement itself (L2, L3), `AnimateRows` (L5), and the 100k journey (L6).

## Avoided Traps

- A `scrollTop` write outside the pinning bookkeeping.
- Correcting rows below the anchor by moving the viewport.
- Using browser scroll anchoring here: the grid already sets `overflow-anchor: none`, and the engine owns anchoring.
