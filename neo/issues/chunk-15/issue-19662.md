# Grid: content-sized cells measure their wrapped text in place

## Context

This is leaf L2 of epic #19658, blocked by #19661 (the geometry model). Mounted rows get their real heights by measuring the displayed text in place.

## The Problem

Content-sized mode needs each mounted row's natural height: the maximum across its declared wrapping text columns, in every body. The constrained outer row and cell are not a natural-content oracle, because cells inherit the row's height and rows are `contain: strict`.

## The Architectural Reality

- **The cell:** `.neo-grid-cell` is `display: flex`, `align-items: center`, `height: inherit`, `padding: 2px 10px 2px`, with 1px bottom and right borders, `border-box` (`Body.scss`).
- **The flex trap (epic review, Stage 4):** inside a flex cell, a block child is a flex item, and its automatic minimum width is its longest word. `overflow-wrap: break-word` then never breaks a long word, which overflows instead. D#19645 probe 2 showed that a flex cell missed 43 of 900 cases and a block cell missed 0.
- **The read:** `DomAccess.getLayoutRect({id: [...]})` measures transform-immune layout boxes in one batch with one forced layout.

## The Fix

- **Declared columns:** a column flag (name settled at intake, e.g. `wrapText: true`) declares a height-driving text column.
- **The text container:** in content-sized mode a declared cell renders its text in a block container with `white-space: normal`, `overflow-wrap: break-word` and `height: auto`. Either the cell becomes `display: block` in this mode, or the container gets `min-width: 0; flex: 1 1 auto`, so long words break.
- **The measurement:** after a mount or update, the App Worker requests the layout rects of the mounted text containers in one batch. It adds the cell's vertical padding and border, takes the maximum per row across columns and bodies, and feeds #19661's height setter.
- **The generation fence:** each request carries a view/record/layout generation (content, width and font context), and a response whose generation no longer matches is dropped. Recycled slots never write a stale record.

## Acceptance Criteria

- [ ] A declared column's wrapped text gives the row its natural height; the row height is the maximum across declared columns in all three bodies.
- [ ] A word longer than the column width breaks inside the cell instead of overflowing; this is a spec.
- [ ] A measurement that returns after the slot was recycled to another record, or after a width or content change, does not update geometry; this is a spec.
- [ ] Mounted rows need one batched layout read per update, not one per row.
- [ ] With the mode off, nothing in this leaf runs.

## Out of Scope

Rows and columns not yet mounted, measure-ahead, and font-arrival invalidation (L3); scroll correction (L4).

## Avoided Traps

- Measuring the constrained row or cell box, which only reports its imposed height.
- A per-row main-thread `ResizeObserver` that writes heights: the App Worker owns geometry, and main only reports observations.
- Calling a stateful renderer a second time just to size it.

- **AC-3:** unit › "a reply for a cell its row rendered again in the meantime is dropped…" holds the read in flight and changes the record. The fence is the cell's vdom node identity plus its width, since a re-render makes a new node. Mutation: without the fence the arm turns red.
- **AC-4:** one `getLayoutRect` batch covers the new text containers of all bodies per pass, and already measured nodes are not read again.
- **AC-5:** unit › "without contentSizedRows, a wrapText column renders and measures nothing".

Deltas I'll carry into the PR:
- Rows never get shorter than `rowHeight`, so columns that don't wrap keep their space.
- Heights are kept per column, so a column scrolled out horizontally keeps its share.
- A row's own update (a record change) triggers a pass too. Mutation-checked with an isolated arm.
- The cell chrome comes from one `getComputedStyle` read per pass.
- Toggling `wrapText` forgets the measured heights.
