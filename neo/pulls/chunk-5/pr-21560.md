Resolves #21559

`WorkstationCellEditingWindowMoveNL.spec.mjs` read its target cells once, right after a scroll or a window move settled `scrollTop`. The pooled rows render a few frames later, so on a loaded runner that single read could return `null`: three CI reds on PRs that cannot reach the spec (#21436, #21538, #21557). A new `waitForCell` helper polls the existing one-shot finders, and the four reads whose cell a test then uses go through it. The finders, the test steps and the engine are unchanged.

Evidence: L3 (headless Chromium at `dev` `32096957fc`: a probe that reads inside the post-scroll gap, plus local runs of the spec at this head) → L3 required (AC-2, AC-3). The flake itself only shows on loaded CI runners, so its absence after merge is the post-merge check.

Ticket intake (#21559, authored this session): Prescription checked: `test/playwright/e2e/workstation/WorkstationCellEditingWindowMoveNL.spec.mjs` — owns the concern. The read and its missing precondition both live in the spec; the engine already shows the rows the test clicks, a few frames later, and a poll on that DOM state needs no new engine signal.
