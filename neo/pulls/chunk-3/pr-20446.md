**Other information:**

`.neo-grid-header-button` is a nowrap flex row and its `.neo-button-text` had no overflow rule, so a label wider than its column kept painting into the next header. The label now gets the one-line ellipsis that content-sized cells already use (`column/component/Tree.scss`): `min-width: 0`, `overflow: hidden`, `text-overflow: ellipsis`, `white-space: nowrap`, and `flex: 0 1 auto` so it is the only child that shrinks. The sort glyph and the menu trigger keep their size. The chosen intent is recorded in one comment on the rule, as the issue asked.

A new component spec (`test/playwright/component/grid/HeaderTextEllipsis.spec.mjs`, fixture `apps/grid-header-ellipsis`) mounts two 90 px columns with composed labels next to a wide one and checks that each long label ends inside its own header and that the fitting label is left alone. A second test clicks the first header, waits for `neo-sort-asc` and asserts that the sort glyph's box lies inside the button's box while the label still ends in an ellipsis that stops before the glyph. Both fail on the old stylesheet (`overflow: visible`) and pass with the change. `HeaderFontSizeNarrowWindow`, `HeaderMenuShape` and `ColumnTrailingEdge` still pass.
