Resolves #22472

Tracked Grid values can opt into color and font style through `--neo-grid-cell-color-modified` and `--neo-grid-cell-font-style-modified`. The Grid retains its modified corner and selection fill. A native reset compares the supplied fields to their original baseline, including nested and calculated fields. Store value-change listeners receive the ordinary field deltas when values actually change. A separate baseline notification refreshes the mounted Grid or Table row.

Evidence: L3 (real Chromium Grid editing, selected and ordinary cell paint, pooled row rebinding and native reset).

size-guard-growth: src/data/Store.mjs — Seven code lines route native baseline acceptance through live and filtered Store projections without emitting a business-value change.

### 🔬 Depth Floor

**Challenge:** In stock, a modified cell in a RowModel- or CellRowModel-selected row keeps its selected colour only because of source order. Those rules tie the new modified rule at (0,4,0) specificity and come later in `grid/Body.css`. The e2e covers CellModel, whose rule is `!important`.

I measured the RowModel case. Base and head stock both paint the selected colour; with the opt-in, the author's colour and italic apply. Reordering the file would change this silently, which is worth one comment line the next time someone touches `Body.css`. No action now.

**Documented search:** I looked for three problems and found none.
- **A stock change through specificity.** Without layers, the new rule does override an app's `.app-negative {color}` on a modified cell. With the build's layer order (`src` in `neo.rules`, app and example sheets in `neo.apps`), the app rule wins in all three arms: base, head stock and head opt-in.
- **A filtered or lazy record publishing twice.** `getRow` reads the full population, and RecordFactory calls one Store. The unit case asserts exactly one event and an unchanged projection.
- **A Grid repaint gap when the value also changes.** Grid's `onStoreRecordChange` rebuilds the whole row, so skipping on `valueChanged` is sound. Table's patches only the edited cells, so Table always repaints.

**Rhetorical-Drift Audit:** Pass. The body, the `@summary` lines and the `@event` doc each say what the diff does.
