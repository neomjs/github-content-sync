Resolves #21188

A new example, `examples/grid/export`, after the `headerGroups` model: 300 seeded invoices (number, customer, date, amount, status) with a customer filter and sortable headers. "Show CSV" opens a read-only pane beside the grid with the first 20 lines of `toCsv()`; "Export CSV" downloads `invoices.csv` with `exportCsv()`; a Comma / Semicolon choice drives both. The pane follows the filter, a header sort and the delimiter while it is open. On a phone (≤ 700px) the pane stacks under the grid. No public API changes; `toCsv()` and `exportCsv()` are untouched.

What the export contains, as observed:
- **Amount:** shown as currency (`$6,143.50`), exported raw with two decimals (`6143.50`) through the column's `exportRenderer`, so a spreadsheet reads a number.
- **Date:** shown as `Jan 4, 2026`, exported as the ISO day the record holds (`2026-01-04`).
- **Formula-like cell:** INV-1004's customer `=SUM(B2:B9) Holdings` arrives as `'=SUM(B2:B9) Holdings`, in the pane and in the file.
- **Pinned column:** a column with `locked: 'end'` moves to the end of the CSV (lock-region order), as the Grids guide documents.
- **Hidden column:** a column with `hidden: true` is still exported (its header is not shown, its values are in the CSV). #20380 does not state a rule for hidden columns, so I read this as a gap rather than a contradiction and did not work around it; happy to file it as its own ticket if you want export to follow visibility.

The catalog record `grid-export` joins the `grid-table` group (`feature`, `lookFor`, cover image `devmode/grid-export-14.jpg`), with a cover recipe in `example-captures.json` and an `seo.json` entry. Rebased on `dev` after #21186 removed six Grid & Table records: the counts are recounted against that `dev`. `TabContainerController.spec.mjs`: 74 catalog records, 17 Grid and Table identities (Grid 15, Table 2), `grid-export` in the covered ids. `ExamplesCatalogNL.spec.mjs`: 17 Grid & Table cards (5 assertions and the cover-count comment). `seo.json`'s `/examples/grid` description now says 17, the value `getSeoJson()` generates; the committed file differs from the generator in no other route.

Evidence: L3 (e2e specs and a live run in Chromium at 1440 × 900 and 390 × 844, both themes, plus the cover produced with `buildScripts/docs/captureExamples.mjs`) -> L3 required (filter/sort/download specs, viewports, look). The cover is on `neomjs/pages` `main` (neomjs/pages#98, merged).
