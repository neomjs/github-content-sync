Resolves #20407

IssuesShowcase's accessibility test now waits for the four header menu triggers before it reads Chromium's accessibility tree. The menu plugin is imported lazily (`grid.header.Button#afterSetColumnMenu`). So the one-shot read could run after the first body row but before any trigger existed. All three reds since #20188 failed that way: `columnMenus` was `[]`, while every row, cell and toolbar assertion passed.

Evidence: L3 (Chromium e2e with a deterministic reproducer) → L3 required (the defect is a browser read racing a lazy module). Residual: none.
