Resolves #22575

Native Engine builds now carry the shared example favicon at the relative resource path their generated HTML already uses. Both bundled app builds use the shared asset helper, and the ESM graph admits the same canonical SVG as a native asset.

Evidence: L3 (all three native builds, every generated icon URL, and an actual Chrome request in each mode).

## AC Evidence

| Criterion | Evidence |
| --- | --- |
| AC-1 | The native Development, Production and ESM builds emit the source-identical SVG at `resources/images/logo/neo_logo_favicon.svg`. |
| AC-2 | All 19 generated links per mode resolve to the emitted path. Each WIP Limits Board made a real icon request in Chrome, received HTTP 200 as `image/svg+xml`, and painted its Board. |
| AC-3 | A physically installed Engine with the canonical Engine SVG removed still built an external workspace in all three modes. The consumer’s own conflicting SVG matched its source bytes in each output. |

## Deltas from ticket

None substantive. The shared asset helper owns the native bundled copy. The existing ESM plan owns its emitted file.

## Test Evidence

- `npm run build-all -- -e all -l no -t yes -w yes -p no` passed on Node 24.22.3. All 57 generated links resolved to the canonical file. The three Chrome requests returned the source SHA-256 `49447a5a324ddbdc85b2fbe345c67456273ce0441372d292079f6cb20c7aa5da`.
- The real ESM asset-emission fixture and bundled helper test ran with the static graph suite. All 33 unit cases passed.
- The previous 14.0.0 site’s distribution mirrors returned 404 in Production and ESM while the canonical source path returned 200. The generated consumer control with its own SVG used the ordinary all-mode build.
