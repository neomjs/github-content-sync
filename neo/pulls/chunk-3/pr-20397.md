Resolves #20379

Grid columns can now sit under a shared group header:
- **Groups in config.** A `columns` entry with its own `columns` array is a group, for example `{text: 'Q1', columns: [{dataField: 'jan'}, {dataField: 'feb'}, {dataField: 'mar'}]}`. `Neo.grid.Container#flattenColumns` turns it into its columns, in place and in order, before `columnDefaults` and `sortColumns` run. Each column carries the group as `headerGroup: {id, text}`, a new documented config on `grid.column.Base`. The group's `locked` replaces its columns' own, so a group never spans two regions. The grouped columns are copies, so the app's declaration survives a re-set and a full replacement.
- **The leaf header row doesn't change.** Sorting, resizing, filters, menus, drag and `aria-colindex` keep working on the same flat buttons.
- **A group row is projected above it.** The new `Neo.grid.header.GroupRow` is the Wrapper's first item while some column has a `headerGroup`. It holds one part per region toolbar. Each group cell is placed from its region body's `columnPositions`: it starts at its first column's `x` and spans its columns' widths. `Toolbar#passSizeToBody` re-projects the cells, so a resize or a reorder moves them with nothing measured twice.
- **CSS grid only while grouped.** The Wrapper switches to a two-row CSS grid, one column per region toolbar. The group row spans the first row as a `subgrid`, so each part sits exactly over its toolbar. Without groups there is no class, no group row, and the DOM is today's.
- **Scroll.** `GridHorizontalScrollSync` moves the centre part in the same frame as the centre header, through an id that stays stable for the grid's lifetime (`Container#getGroupHeaderPartId`).
- **Reorder.** The header SortZone refuses a swap across a group boundary, resolved through the column.
- **ARIA.** The group row is header row 1, made of `columnheader` cells with `aria-colspan` and a grid-wide `aria-colindex`. The leaf row becomes row 2. `Container#headerRowCount` is now the single source for `aria-rowindex` on the leaf row and on the body rows (`Row` no longer hard-codes `+ 2`), and for `aria-rowcount`.

Evidence: L3 (real-pointer e2e in Chromium against `examples/grid/headerGroups`) → L3 required (AC-2, AC-3, AC-6 are browser geometry and pointer gestures). Residual: none.

## Deltas from ticket

- **Placement** follows the intake and the design comment on #20379. The toolbar root is the leaf ARIA row, the scroll-sync node and the flex items root at once, so the group row lives beside the toolbars. `grid.header.Wrapper` owns it, and alignment comes from CSS grid with `subgrid`, not from width arithmetic.
- **Flex re-layout:** the example uses fixed widths, so there is no dedicated flex arm. Measured flex widths reach the cells through the same `Toolbar#passSizeToBody` re-projection that the resize arm exercises.
- **The reorder guard** reads the group from the column and puts `currentIndex` back on a refused swap. `onDragMove` advances that index before it asks for the swap, and the drop commits to it. The first version refused only the swap, and the e2e caught the drop still crossing.
- **Group cells take the leaf headers' theme variables**, so every theme styles both rows alike.
