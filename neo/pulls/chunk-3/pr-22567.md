Resolves #22432

Workstation now wears a product palette of theme Neo. `resources/css/theme-neo/apps/workstation/Global.css` re-values theme Neo's palette and three roles on its two theme classes. `Workstation.view.Viewport` names the file in `additionalThemeFiles`, and every window the product opens boots that viewport, so each window loads it, the pop-out included. The Close tooltip in a populated pop-out now paints Workstation's teal, where it painted theme Neo's blue. The main window's tooltip still paints the bridge until its `Workspace.css` block goes in its own leaf. No bridge line is removed.

Evidence: L3 (a whitebox spec drives a real pop-out window and reads painted tooltip colours after each runtime switch; frames and a painted-colour census of both windows, `dev` against head, in both schemes, plus the released main window) → L3 required (AC-4, AC-6).

## Deltas from ticket

- **Three roles are re-bound:**
  - `text-accent`: light to `accent-700`, because teal `accent-600` reads 4.26:1 on `accent-100`; dark to `accent-300`, per ruling (a).
  - `focus-ring`: dark to `accent-300`, per ruling (a).
  - `text-muted`: light to `neutral-700`. The ruling's knock-on applies: on the moved `800`, muted text stood only 1.43:1 from default text.
- **Two re-binds of my draft are dropped**, light `ground` to `neutral-100` and dark `ink` to `neutral-200`. Each fails a palette-gate pair, and the ruling says a role's floor wins over reproduction (point 5). The table records each reason.
- **The spec runs hosted.** It joins `ADAPTER_ELIGIBLE_SPECS` and `RUN_PATHS`. Like its pop-out siblings, it drives the page's own SharedWorker and needs no Bridge session and no Brain module. Off-socket, without a Brain checkout, it passes locally.
- **One unit case is updated.** The workspace case in `check-theme-palette.spec.mjs` now asserts the workspace's pair instead of a count of two: a workspace run also measures the Engine's own product palette, which now exists.
- **A correction on the design questions:** Q1–Q4 of my 03:42Z comment asked again what the 22:43Z ruling had already answered (points 4 and 5). Q5 follows point 5. The design seat can still overrule any row here.
