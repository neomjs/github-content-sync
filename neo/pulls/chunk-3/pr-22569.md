Resolves #22387

The Year view's week-number column no longer shows the wrong ISO week. `Neo.util.Date.getWeekOfYear` now returns the ISO 8601 week of the date's local calendar day, so the time zone and the time of day no longer change it, and the Year view labels each row with the ISO week of the row's fourth day (so Monday rows are no longer one week ahead). No config or API change; `getWeekOfYear` stays ISO.

Evidence: L2 (new unit specs failing on `dev` and passing on this branch under `playwright.config.unit-tz.mjs` in `Pacific/Kiritimati`, `Pacific/Niue` and `America/New_York`, plus the full `npm run test-unit`) -> L2 required (ticket ACs).

## Deltas from ticket
- The existing `getWeekOfYear follows ISO 8601 across the year boundary` case built its inputs with `Date.UTC(...)`. Those are a different calendar day in a zone west of UTC (for example `Date.UTC(2019, 11, 30)` is Dec 29 in `Pacific/Niue`), so under the new local-day rule they cannot pass in the tz tier. The same dates and expected weeks are now built as local dates.
- The new `YearComponent.spec.mjs` is added to the `testMatch` list of `playwright.config.unit-tz.mjs`, as `CONTRIBUTING.md` asks for specs that depend on local/UTC conversion.
- The Year view spec is a unit spec that calls `createMonthContent` and reads the week-number cell of each row; it needs no browser.
