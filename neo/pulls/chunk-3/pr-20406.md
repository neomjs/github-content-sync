Resolves #20403

A ComboBox given a shared Store now keeps that Store's record-change notifications working during and after field lifetime. Its private picker view receives a separate instance of the source Model class with the current schema, key and tracking configuration. The field owns and destroys this private Model when the view is replaced or retired; the source Model keeps its notification route.

Evidence: L2 (real Store/Model/field instances in the Engine's Node simulation) → L2 required (notification ownership, schema lookup and resource lifetime). Existing native ComboBox interaction controls also pass. No residual acceptance gates.

## Deltas from ticket

Simply dropping the Model was rejected: numeric DOM key `'7'` then misses numeric Store key `7`, and calculated field metadata disappears. The independent schema keeps both. Cleanup uses the field's existing ownership set and one private helper across replacement/destruction; Store and RecordFactory are unchanged.

The snapshot covers the Model's current fields, key and tracking configuration and retains its class methods. The broader question of arbitrary custom Model instance state remains outside this targeted picker snapshot.

## Test Evidence

On the original code, both passed-store and bound-store regressions failed: the source received only the before-field control, missing the existing/new record edits after attachment. With the repair they pass, including edit-after-destruction and private Model disposal. An isolated omission probe returned a string key and no record; the schema-preserving candidate returned numeric `7` and the shared record.
