Resolves #22474

Grid themes can set row and column separator colors independently and opt into rules below the last populated row. The Grid paints those rules inside its existing scroll extent. Locked-region seams and the clipped trailing edge still use the frame color.

Evidence: L3 (real Chromium grid in Neo Light and Neo Dark, including decoded screenshot pixels and interaction assertions).

## AC Evidence

| Acceptance criterion | Evidence |
| --- | --- |
| AC-1 | `EmptyRowRules.spec.mjs` verifies a horizontal-only short grid down to the visible edge, the column-only treatment, and identical hit targets, focusable descendants, and ARIA row count. |
| AC-2 | The same spec checks an empty store, live resize, an isolated row-height change, measured content-sized rows, and exact rule phase after ordinary and capped/paged scrolling. |
| AC-3 | The same spec checks default border fallback, pinned seams, the trailing edge, and selection across all three bodies in both schemes. |

## Deltas from ticket

Content-sized rows start the pattern at the measured end of the final row and use the configured minimum row height for each empty slot. Changing a fixed row height now reprojects existing rows through the Grid's existing refresh path. The regression showed that all three rows otherwise kept their old geometry after a height-only change.

## Test Evidence

Chromium passed 13 cases with this change and the approved Grid editing change at `b65c77a110` applied together on dev `0e9fa32f2c`. The run covered empty rules, record-shape editing, locked wrapping, and paged scrolling. The red control left the last DOM row at 84 px after the rule origin moved to 108 px. The repair brings both to 108 px and puts the first empty rule at y=143.

Six full-viewport Chromium captures at 1120×720 compared clean dev stock, candidate stock, and the opt-in treatment in each scheme. Both stock pairs differed by zero RGB pixels. The opt-in retained the same Grid bounds, scroll extent, and row count.

Frame critique: the ruled area keeps a single-pixel cadence. Locked dividers and the existing space to the right of the center columns remain visible in both schemes.

Hosted unit first exposed an extra early View update during content-sized measurement. Rule geometry is now staged into the existing View transaction. The original scrollbar order assertion passes unchanged, along with all 559 Grid unit cases and the 13 combined Chromium cases. Additional browser probes verified insert, remove, filter, a preloaded store replacement, external View style, and a partial remote load that used the reported total before the last chunk arrived.

The old hosted browser run also failed the Workstation two-root drop. The same test and `target-refused` signature reproduced on untouched dev `0e9fa32f2c` in one of two independent Chromium runs. The failure is separate from the Grid unit regression.

The two separator hooks are declared in `theme-base/grid/Body.css` and the empty-row hook is declared in `theme-base/grid/View.css`. Each default is `initial`, so existing fallback paint supplies the stock values. The combined build with #22561 maps Body and View to theme-base in Development, Production and ESM, and all 13 Chromium cases passed again.
