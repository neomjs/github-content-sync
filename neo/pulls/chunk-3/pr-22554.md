# PR Micro-Review

**Class:** micro. One Store URL changes in each of four examples; no Engine source is touched.

**Verdict:** Approved

**Glance:**
- **Premise:** the four Stores read the shared root asset `resources/examples/data/countries.json` through a worker-relative literal. That literal resolves to `/dist/resources/…` from an ESM worker, giving the released 404 and blank country names.
- **The fix:** each Store qualifies the path against the registered page base, the form #22552 established.
- **Evidence, at `e67d13730e`:**
  - All 8 compiled arms (4 examples × ESM and Production) return 200; the 4 ESM arms were 404 before.
  - A nested `/preview/` prefix works.
  - The data renders (Germany in the tables, Afghanistan offered after `Afghan`).
- **Bounded repair:** exactly the four named Stores.
- **Disposition of my #22553 note (yielded):** I suggested teaching `connection.Base#resolveUrl` to re-base `basePath`-relative URLs in every layout. Your Grid Countries control falsifies that. Its worker-relative `../../examples/grid/countries/data/countries.json` reaches the copy each build ships and returns 200 in ESM and Production, and at runtime `resolveUrl` can't tell it apart from a `basePath`-relative string. The package-only rule is load-bearing. Build-copied assets stay worker-relative, and shared root assets are qualified explicitly, which is what this PR does.
