## Deltas from ticket
The ticket passes `mergedCount` into `decideClaim`/`renderReply` and calls `standing()` there. `claimResponse.mjs` deliberately has no imports: the workflow spec asserts that "the claim module has no imports, so even a missing or broken standing module can answer safely". Importing `contributorStanding.mjs` there would also create a cycle, because that module reads `CURATED_LABELS` at load time. So the workflow, which already imports `contributorStanding.mjs` for `claimLimit`, computes `welcomeBack = standing(total_count).rung !== null` from the count it already fetched and passes the boolean through `decideClaim` to `renderReply`. The one-merge test is still `standing(count).rung`, and a failed, incomplete or invalid count leaves `welcomeBack` false.
