**2. E2E — `test/playwright/e2e/table/HeaderFiltersExample.spec.mjs:114` (phone clear)**

First attempt (`country.selectText()` + `Backspace`) was wrong: it cleared the input's display text but not the ComboBox's internal selected record — `toHaveValue('')` passed but the table still showed 10 rows (Canada filter still active).

Fixed by staying with `.neo-trigger-clear` but adding `{ force: true }`:

```js
await countryBox.locator('.neo-trigger-clear').scrollIntoViewIfNeeded();
await countryBox.locator('.neo-trigger-clear').click({force: true});
```

The trigger is present in the DOM whenever a value is selected (its `hidden` config is `false`). At 390 px, Playwright's actionability check was blocking the click because the element was clipped/occluded by the narrow viewport. `force: true` bypasses that check and dispatches the click event directly, invoking Neo's native clear handler which zeroes the filter correctly.

- Instead, the native user path to clear a ComboBox filter is its dedicated clear trigger (`.neo-trigger-clear`), which invokes `field.clear()`.
- The earlier CI race at 390 px was caused by clicking `.neo-trigger-clear` immediately while the store was still dispatching the preceding `customer.fill('')` update. Waiting for `rows` to settle at 10 first (`await expect(rows).toHaveCount(10)`), scrolling `.neo-trigger-clear` into view, and performing a normal unforced `.click()` passes cleanly without any force-clicking.
- Keyboard reachability and clearing remains tested and verified on the filter row in the theme loop (via Tab, ControlOrMeta+A, and Backspace) as required by AC-5.
