Resolves #19535

A popped-out window that closes while a landed pane's repaint frame is in flight no longer reads as a failed render. This fixes `WorkstationHeaderStatePopOutNL`, red on `dev` since #19534.
- **Before:** `PopupWorkspace#repaintLandedPane` reported every rejection on a surviving pane. A closing window rejects the frame with the worker's dead-port reason ("Worker port disconnected before reply"). The pane survives that, so the console carried a false failure, and the pop-out arms that read the console failed.
- **Now:** the catch asks the worker whether the rejection is that window's departure (`worker.Base#isDeparture`, as `Sparkline` does), and reports only a real failure. The layer still comes off either way, and a destroyed pane is still left alone.

Evidence: L3 (headless e2e on the regressed arms plus a unit arm) → L3 required (the AC's e2e arms). No residuals.
