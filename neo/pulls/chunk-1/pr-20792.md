Resolves #20779

🌿 A host can no longer call its renderer without saying which canvas it means.

`Neo.app.SharedCanvas` sends `canvasId` beside `windowId` with all seven remotes of `Neo.canvas.Base`, at its nine call sites. The graph the host started keeps the canvas id beside its renderer and window, so `clearGraph` names the canvas it started, also after the host moved to another window. No renderer changes: `Neo.canvas.Base` reads named fields only.

Related: #20667

Evidence: L3 (unit specs in CI, driving the real host lifecycle against a stub renderer, plus one real-browser run of the Portal home) → L2 required (every AC is a payload or JSDoc contract, observable in the unit tier). No residuals.

## AC Evidence
| AC-1 | CI-covered: `test/playwright/unit/app/SharedCanvasCanvasId.spec.mjs`, "all seven remotes carry canvasId beside windowId, at every call site". It pins the order of the ten calls the nine sites make. |
| AC-2 | CI-covered: same spec, "the clear names the canvas and window the host started, whatever the host reads afterwards". |

## Deltas from ticket
AC-3 says the existing specs pass unchanged, and that cannot hold. Three specs build a bare host with `Object.create(SharedCanvas.prototype)` (`PointerInput`, `GraphScene`, `DomEvents`), and a bare host cannot read its `id`; two specs pin the old payload with `toEqual` (`PointerInput`, `SharedCanvasAdmission`). With the source change alone, 8 tests in those four files were red. Each bare host now carries an own `canvasId`, and the pins include it. The scalar `setTheme` arm tests the renderer and is untouched. The rewording is proposed to the ticket's author in https://github.com/neomjs/neo/issues/20779#issuecomment-6804543614.

## Test Evidence
Red first: against the unchanged host the new spec failed 3 of 3 (no `canvasId` on `setTheme`, none on `clearGraph`, an `undefined` entry in the keyed renderer).

Real browser, Portal home on the dev server at `ff780505d2`: the header canvas and the hero canvas draw through the real remote layer with the added field, and the console holds no error. Seen once, in Chrome, light check only: no pointer or resize assertion.

Everything else runs in CI.

## Post-Merge Validation
None.

## Evolution
The two fields first sat behind one getter. `test/playwright/unit/worker/CanvasRemoteWindowId.spec.mjs` scans the tree for a literal `windowId` in every call into a canvas remote, so they are written out at each site and that guard is untouched.
