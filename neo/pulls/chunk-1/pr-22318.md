Resolves #22315

🌿 *An edit to release notes can no longer start before their skill has been read.*

A `Write` or `Edit` under `.github/RELEASE_NOTES/` or `learn/blog/` now waits until the session has read the governing skill payload since its last compaction. That is `release-notes-workflow.md` for notes and `blog-authoring-guide.md` for posts. The witness is the transcript itself: a main-thread `Read` of the payload after the last `compact_boundary` entry. Transcripts reach hundreds of megabytes, so the guard scans backward in 1 MB chunks, splits at newline bytes and stops at the first boundary it meets. Like its siblings it fails open on a malformed payload or an unreadable transcript. This is the Engine half of neomjs/neo-agent-skills#438 (PR neomjs/neo-agent-skills#481): it reaches the seats those ticket and review routes cannot, such as branch collaborators and resumed sessions.

Evidence: L3 (the committed hook run on two real session transcripts, plus the unit spec) → L3 required (AC-1 to AC-4). Residual: AC-5, Residual-Owner: #22265 (the 14.1 notes are the first edits it will gate).

Prescription checked: `.claude/hooks/bodyFileGuardHook.mjs` — owns the concern. The Engine's tracked guards police edits inside this repository, and the Brain's projected seat hooks carry seat-plane events, so the guard belongs beside its siblings. Pre-Flight (structural fast-path): `.claude/hooks/contentSkillGuardHook.mjs` lifts `bodyFileGuardHook.mjs`, and the spec lifts its spec; no novel directory choice.

## Deltas from ticket
- The guard's timeout is 5 s; its siblings use 2 s. The scan measured under 200 ms on a 320 MB transcript, but a session with no compaction and no read scans its whole transcript, and a timeout fails open.
- Only the `Read` tool counts. A payload read through Bash (`cat`, `sed -n`) is a partial witness at best, and the block reason names the file to read.

The first CI run flagged one flaky case: the spec made its fixture folder when the module loaded and removed it in `afterAll`, and under `fullyParallel` a worker can run `afterAll` and later take another test of the same file, so a fixture write hit `ENOENT`. `beforeAll` now makes the folder. Under `--workers=4 --repeat-each=5 --retries=0`, the old spec fails 3 of 40 with `ENOENT` and the new one passes 40 of 40.

Mutations, each run alone against the spec: dropping the chunk carry fails only the chunk-boundary test; letting a compaction boundary pass as neutral fails the witness and line-classification tests. ### 🔬 Depth Floor

- **Challenge**: Two minor non-blocking path-normalization subtleties in `.claude/hooks/contentSkillGuardHook.mjs`:
  1. In `classifyLine` (`L78` vs `L83`), line 83 normalizes `String(part.input?.file_path || '').replaceAll('\\', '/').endsWith(suffix)` for backslash paths, but the outer fast-path guard on line 78 checks `line.includes(suffix)` where `suffix` uses forward slashes (`skills/release-notes/references/release-notes-workflow.md`) — so a JSON-escaped Windows `file_path` (`C:\\...\\skills\\...`) would short-circuit at line 78 before reaching line 83. Gating line 78 on `path.posix.basename(suffix)` would keep the fast-path skip while making line 83's backslash normalization reachable if Windows Claude seats ever run.
