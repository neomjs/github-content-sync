Resolves #22282

The 18 bare colour literals in the eight structural files now read 14 component variables, named by the ticket's grammar. Each of the four full themes declares them with today's literal, in its file for that component, so the paint does not change. Each theme gains three files: `grid/column/AnimatedCurrency.css`, `grid/header/plugin/Menu.css` and `calendar/view/week/TimeAxisComponent.css`.

Evidence: L3 (a grid, a table and the calendar rendered in Chromium under both Neo themes, with computed values; the census on `dev` plus this PR's `src` change alone, and on this branch) → L3 required (AC-4).

## Test Evidence
A throwaway page, not committed, mounted a grid with `columnMenu`, a Progress and an AnimatedCurrency column, a table container and the calendar's week view, configured for both Neo themes, after a dev theme build. For the five mounted components, each Neo theme's file loaded, the three new ones included (read from `document.styleSheets`), with no console error. Computed in Neo Dark, then in Neo Light after switching the theme class; both themes gave the same values:

| Package | Read | Neo Dark and Neo Light | `dev` literal |
|---|---|---|---|
| grid | `--grid-cell-progress-box-shadow` | `0 2px 5px rgba(0, 0, 0, 0.25) inset` | the same |
| grid | `--grid-cell-animated-negative-background-color`, `-positive-` | `rgb(218 54 51 / 60%)`, `rgb(35 134 54 / 60%)` | the same |
| grid | `--grid-column-menu-box-shadow` | `0 4px 16px rgba(0, 0, 0, .25)` | the same |
| table | `::-webkit-scrollbar-track` `background-color` | `rgba(0, 0, 0, 0.1)` | `rgba(0,0,0,0.1)` |
| calendar | `.neo-c-w-timeaxis-item` `color` | `rgb(153, 153, 153)` | `#999` |

The grid rows read the variable, not the paint: the progress bar's `::-webkit-progress-bar` does not report through `getComputedStyle`, and the menu and the animation need a state the page did not drive. No frames: the paint does not change.
