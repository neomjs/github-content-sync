Resolves #19798

On a grid with locked columns, a sort left stale arrows on the locked headers, because the header-wide walks stopped at the center toolbar. The new `Wrapper#getToolbars()` lists every header toolbar from left to right. All header-wide walks now use it: the sort reset, the runtime `showHeaderFilters` / `sortable` / `useTriStateSorting` hooks, and three existing inline lists it replaces. A locked toolbar created after a runtime change takes the center toolbar's current values, not its construction configs.

Evidence: L2 (unit specs red on `dev`, a mutation, a live drive of the issues showcase) → L2 required (AC-1–AC-4).

## Deltas from ticket
- The clone path: `Neo.cloneNeoInstance` starts from construction configs, so a locked toolbar created after a runtime change (a column locked into an empty region) reverted that change. `updateHeaders` now hands the clone the center toolbar's current header-wide values. Ticket body updated.
