Resolves #19661

Grids get an opt-in `contentSizedRows` mode. Rows then take individual heights from one `Neo.grid.RowGeometry` per view: record-id-keyed heights over a `Float64Array` of prefix offsets, with a binary-search offset → row lookup. Every row-position consumer reads it: row heights and transforms, the start row, the visible and mounted rows, both scroll extents, and keyboard scrolling. Heights enter through `grid.View#setRowHeights`, the internal setter that measurement (#19662, #19663) will feed; here specs and a fixture drive it with synthetic heights. The mode is off by default, and a fixed-height grid keeps `index × rowHeight`. One input shared by both modes, the viewport height, is fixed as well (see Deltas).

Evidence: L3 (headless Chromium e2e on two fixtures, unit arms mutation-checked) → L3 required (AC-3 and AC-4 visibility is browser-observable). No residuals.

agent-preflight: not hosted here; class-module-scope, jsdoc-types, fixed-sleeps and file-size lints ran clean.

## Deltas from ticket

- **Viewport height** (ticket amended): `Container.passSizeToBody` measures the view. Container minus header and footer also counted the borders and the in-flow horizontal scrollbar (770px against a 751px view), so keyboard scrolling left the row it aligns to the bottom 19px out of sight, in fixed-height grids too.
- **Two refresh passes, not one rebuild per batch.** Resolving 100k record ids costs about 10 ms. D#19645 probe 5's 0.07 ms timed only the summing. So an order change runs the full pass, and a height batch patches its rows in place and sums again from the first changed one.
- **No start-row threshold in content-sized mode.** `View.syncBodies` re-syncs on every new start row, and the pool holds `ceil(viewport / minHeight)` visible rows. With mixed heights a row-count threshold lets the mounted rows outgrow the pool.
- **Rows detect their own moved geometry.** `Row#hasStaleGeometry` compares the rendered style with the geometry, so a height change re-renders the moved rows with cell recycling instead of a forced full render.
- **The geometry's store listeners use `order: 'before'`.** A body re-renders on the `load` the store fires for a sort, and has to read fresh offsets.
- **The full pass reads `store.items`.** `getAt()` hydrates every record of a lazy store it reads.
- **`setHeights` takes a `Map`.** Plain-object keys turn numeric record ids into strings.
- Out of scope, noted in defect-note `MESSAGE:1e6ae4ae`: the "on()/un() consume `scope`" comments in `View`, `Container` and `VerticalScrollbar` are stale, since `Observable` copies the object now.

- Grid unit specs are `NEO_TEST_SKIP_CI`-guarded, so their receipt is local, at `0a04e90e4e`: `npm run test-unit -- test/playwright/unit/grid/` → 188 passed. The `Neo.grid.RowGeometry` model arms are not guarded and run in CI.
- Mutation checks, each reverted afterwards:
  - visible end measured from the start row's offset → the tall-row arm fails;
  - pool `ceil − 1` → the pool arm fails (mounted 15 > pool 14);
  - listeners without `order: 'before'` → the listener-order and sort/filter arms fail;
  - no `hasStaleGeometry` → 7 arms fail;
  - the row-count threshold in content-sized mode → the pool arm fails (mounted 16 > pool 15).
- e2e negative control: with the old `availableHeight` derivation, both keyboard arms fail (content-sized at row 10, fixed at row 12).
