## Deltas from ticket
- **Cyberpunk keeps its paint too.** Out of scope as a design target, but it themes desktop, dashboard, gantt, scheduler and dialog, so its seven existing files get the new variables with today's value. `plugin/Resizable` gets a new Cyberpunk file as well: `dialog/Base` and the grid and table header buttons import it, so its handles render in Cyberpunk's gantt and scheduler grids. Six variables stay undeclared there, because no Cyberpunk app renders Range, LivePreview, the tree sort proxy, the circle list or Popover.
- **The `plugin` baseline row goes,** as the ticket allows. Its justification, "no chrome of its own", is false for Resizable (its handles) and Popover (its shadow), and both now have theme files, which the guard's burn-down rule (`check-theme-coverage.mjs`) requires the row to leave with.
- **The launcher icon's shadows keep their runtime part in `src`.** Each mixes the per-icon `--desktop-app-color`, which a theme-root declaration would resolve too early, so only the inset highlight colour becomes a variable.
- **`--desktop-app-window-glyph-color`, not `-icon-color`.** The latter already holds the dialog header icons' colour; the new one is the glyph on the app's colour tile.
- **Left as they are:** existing names outside the grammar (`--neo-gantt-summary-bg`, `--desktop-app-window-shadow` and others), because renames are out of scope. Also the literal inside the dashboard's `src`-level `--dock-reveal-shadow` default, which the census does not count as a structural literal.
