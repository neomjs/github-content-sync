Resolves #20776

The `AGENTS.md` filter that the install stage and every seat Start register now carries `smudge = cat` beside `clean` and `required`. Git applies a required filter in both directions. Since #20749, in a registered checkout, every git operation that wrote `AGENTS.md` into a working tree therefore failed: a new worktree, a branch switch, a pull across the merge.

A checkout now writes the stored pointer byte for byte, and the stage writes the rules over it as before. `required` stays, so `git add` still refuses when the clean command cannot run. A checkout registered before this fix gains the smudge on its next install or Start, because the stage checks every key it wants.

Evidence: L3 (real git in temporary repositories in CI, with a no-smudge control, and a live install in my seat checkout) → L3 required (AC-2); AC-4 is post-merge.
