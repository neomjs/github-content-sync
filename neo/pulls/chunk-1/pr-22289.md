Resolves #22286

Toggles the `readonly` boolean HTML content attribute via `node.toggleAttribute('readonly', ...)` in `Neo.main.DeltaUpdates#updateNode` (matching `DomApiRenderer#createDomTree`), while keeping live-state property writes (`checked`, `disabled`, `selected`, `muted`, etc.) unchanged and letting `DeltaUpdates#changeNodeName`'s existing `attributes` copy preserve `readonly` across tag replacements without writing `clone.readOnly` onto custom elements or non-form tags.

Evidence: L3 (live Chromium component + custom-element getter/retag + example page reload/checkbox E2E in CI + unit suite) → L3 required (AC-1, AC-2, AC-3). No pre-merge residuals.

Intake: `valid-as-written`. Prescription checked: `src/main/DeltaUpdates.mjs` — owns the concern (`Text#updateReadOnlyState` emits standard HTML `readonly` into VDOM; initial `StringFromVnode` and `DomApiRenderer` already handle `readonly`, while stage-4 in-place delta application indexed `node['readonly']`).
