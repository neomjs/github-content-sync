Resolves #20139

🌿 *No caller has to guess anymore when a grid's cell editor exists.*

`grid.Container#cellEditingReady` settles with the plugin that `cellEditing` creates behind its dynamic import. That is the shape the engine already uses for `menuListReady`, `headerFilterReady` and `transactionManagerReady`. The promise is `null` when the plugin was declared in `plugins` (the #18967 path) or editing was never enabled, so `await grid.cellEditingReady; grid.getPlugin('grid-cell-editing')` works for every grid. The unit spec's own 50×10 ms poll helper now awaits the promise instead.

Evidence: L2 (unit arms drive a real `grid.Container`, its dynamic import and the plugin) → L2 required (AC-1..AC-4: the plugin the promise settles with, one plugin under a double enable, `null` for a declared plugin, the suites green). No residuals.

agent-preflight: not hosted here; baseline `pr-body` runs in CI. Change class: capability.
