Resolves #20687

The main-thread dist builds now copy only what the runtime loads from `@fortawesome/fontawesome-free`: `css/all.min.css`, `webfonts/` and `LICENSE.txt`, instead of the whole package (5,839 files → 6). Both `webpack.config.main.mjs` configs read the list from one place, `buildScripts/webpack/fontAwesomeCopyList.mjs`, and a unit spec fails when the installed `all.min.css` references a file the list does not cover.

Evidence: L1 (unit spec) + L3 (local build and browser render on Windows 11) → L3 required (AC-1, AC-5). Residual: none.

## AC Evidence
| AC-1 | Outside-CI: `npm run build-all`; `dist/development` and `dist/production` `resources/fontawesome-free` each hold exactly `LICENSE.txt`, `css/all.min.css` and the 4 `webfonts/*.woff2` (receipt in Test Evidence) |
| AC-2 | CI-covered: `test/playwright/unit/buildScripts/FontAwesomeCopyList.spec.mjs` (every `url(...)` in `all.min.css` resolves to an existing file inside the list) |
| AC-3 | CI-covered: `test/playwright/unit/buildScripts/FontAwesomeCopyList.spec.mjs` (parses the installed `all.min.css` and fails on an uncovered reference) |
| AC-4 | CI-covered: both `buildScripts/webpack/*/webpack.config.main.mjs` import `FONTAWESOME_COPY_LIST` from `buildScripts/webpack/fontAwesomeCopyList.mjs` |
| AC-5 | Outside-CI: `fa-solid fa-house` rendered on `dist/production/apps/portal/index.html` behind `npm run server-start`, computed `font-family` shown (screenshot in Test Evidence) |

## Deltas from ticket
- `buildScripts/util/copyFolder.mjs` gains an optional `-i, --include <comma-separated paths>`; without it the copy is unchanged, so other callers are unaffected.
- An existing dist folder that already holds the full package keeps the stale files until it is deleted; the build does not clean it.

## Test Evidence
-  Mutation check: with `webfonts` removed from the list, the `url(...)` test fails (2 passed, 1 failed); restored, 3 passed .
- `npm run build-all` (Windows 11, Developer Mode on for the `prepare.mjs` symlink), file listing of both dist folders: 6 files each.
- Icon render on `dist/production/apps/portal/index.html` (computed `font-family` "Font Awesome 7 Free"), and `fa-solid-900.woff2` served 200 from `dist/production`:

### 🔬 Depth Floor

- **Challenge**: Two minor non-blocking edge cases noted for future callers of these utilities:
  1. **`sanitizeInput` on `copyFolder.mjs` `-i, --include <value>` (`buildScripts/util/copyFolder.mjs:10`):** `-s` and `-t` pass `sanitizeInput` (`value.replace(/^["']|["']$/g, '').trim()`), whereas `-i` parses the raw string and trims per comma-split item (`item.trim()`). For `${FONTAWESOME_COPY_LIST.join(',')}` there are no surrounding quotes, so behavior is exact across macOS, Linux, and Windows; if a future caller passes literal surrounding quotes without shell stripping (e.g. `['-i', '"css/all.min.css,webfonts"']`), the first and last split tokens retain outer quotes unless `sanitizeInput` is also passed to `.option('-i, --include <value>', ..., sanitizeInput)`.
  2. **Trailing-slash convention in `FONTAWESOME_COPY_LIST` (`FontAwesomeCopyList.spec.mjs:26`):** `isCovered` checks `relativePath === item || relativePath.startsWith(item + '/')`, assuming folder entries omit trailing slashes (`'webfonts'`, as written in `fontAwesomeCopyList.mjs:16`). Normalizing `item.replace(/\/+$/, '')` would tolerate `'webfonts/'` spellings as well if the list ever grows.
