Resolves #20720

Destroying an instance now cancels its pending delayable calls before removing its properties. This covers inherited and instance-configured methods. Debounce and throttle wrappers expose cancel(), matching buffer; cancelling also resets their timing state so the wrappers can be reused.

Evidence: Unit tests exercise all three acceptance criteria using controlled browser-style timers and a real GridContainer in Neo's single-thread test environment. No browser-rendered validation is claimed or required by this issue.

## AC Evidence

| Criterion | Coverage |

| AC-1: pending buffer, debounce and throttle calls do not run after destruction | DelayableDestroy.spec.mjs tests all three types with inherited and instance configuration, while a surviving sibling still executes normally. These run in the engine unit CI tier. |
| AC-2: debounce and throttle expose cancel() | The wrapper tests cover cancellation before use, repeated cancellation, clearing pending work and reuse. These run in the engine unit CI tier. |
| AC-3: destroying a grid during a scroll does not throw | The grid regression calls scrollManager.onContainerScroll(), destroys the grid, and advances past the scroll-end timer. This runs in the engine unit CI tier. |
