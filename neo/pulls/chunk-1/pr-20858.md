Resolves #20855

`recordChange.index` is now computed when a listener reads it, and `grid.Body` finds the changed record in its own row pool instead of asking the store for a second index scan. A field write no longer pays a store-wide scan before every listener, and a later listener sees the current position after an earlier listener re-sorts.

Change class: restoration (`fix`) — the event and the repaint keep their existing public behavior; the change removes the duplicate scans behind them.

Evidence: local source + unit + 1,000,000-row benchmark on Node v26.12.0. `npm run test-unit` → 6,998 passed, 3 skipped.

### Benchmark receipt

The ticket's reproducer at 1,000,000 flat rows:

```text
before: write near the start 4.6 µs | write near the end 147.4 µs | end + listener indexOf 295.5 µs
after:  write near the start 4.8 µs | write near the end   3.4 µs | end + listener indexOf 147.4 µs
```

The third column keeps one explicit `store.indexOf` in a listener; it now costs one scan instead of two.
