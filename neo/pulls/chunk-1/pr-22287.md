Resolves #22284

Both Neo themes now define the four variables that structural rules read and nothing declared. A `var()` without a fallback whose variable is undeclared is invalid at computed-value time, so each rule fell back silently, and differently by property. With this PR, `npm run theme-census` reports no unresolved structural read for the Neo pair beyond the six runtime-set properties. The classic pair stays with #22285.

| Variable | Read in | Today on `dev` | Neo Dark and Neo Light now |
|---|---|---|---|
| `--calendar-settings-header-color` | `calendar/view/SettingsContainer.css` | `color` is invalid, so the header inherits its text colour | `inherit`: paint unchanged (see Deltas) |
| `--list-border-color` | `app/content/SectionsList.css` (`img.avatar`) | the whole `border` shorthand is dropped, so the avatar has no ring | `var(--sem-color-border-default)`: the 1px ring renders |
| `--list-item-border-color-active` | `list/Chip.css` (navigator item) | `border-color` falls back to `currentcolor`, the text colour | `var(--sem-color-border-focus)`, the ring `.neo-chip:focus` already uses |
| `--menu-list-item-color-disabled` | `menu/List.css` (`.neo-disabled`) | `color` inherits, so a disabled item reads as enabled | `var(--sem-color-text-disabled)` |

Evidence: L3 (the widgets rendered in Chromium in both Neo themes, before on `dev` and after at this branch, with computed styles; the census on the branch) → L3 required (AC-1, AC-3).

## Deltas from ticket
- **The calendar header gets `inherit`, not a colour token.** A custom property set to `inherit` takes its parent's value of that property, and no ancestor declares one, so `color` stays invalid and the header inherits exactly as it does today. The Neo menu theme already writes `--menu-list-item-color: inherit` the same way. If the design seat would rather pin it to a token, `var(--sem-color-text-neutral-default)` is the candidate, with its own frame pair.
- **The avatar ring is new paint, as designed in #8535.** The rule has read `--list-border-color` since January, and no theme ever defined it. The ring shows in the Portal's "On this page" list for timeline actors (`apps/portal/view/content/Component.mjs:121`).
