Resolves #20780

Brings the two-thread VDOM pipeline (`useVdomWorker: false`) to parity with the VDom worker path across `meta` forwarding (including `#20865` zero-delta metadata updates), `afterExecuteVdomUpdate` post-paint ordering, and shared `autoMount` `insertNode` dispatch (`VdomLifecycle#createVnodeTree`, consumed by `initVnode` and `Helix#expandItem`).

Evidence: L3 (Playwright unit + real-browser two-thread E2E `test/playwright/e2e/rendering/TwoThreadPipelineNL.spec.mjs` across `grid/bigData` and `component/helix`) → L3 required (AC-1 through AC-5).

Change class: restoration. `agent-preflight`: not hosted here; baseline `check-class-module-scope`, `check-engine-brain-boundary`, `check-file-sizes --base origin/dev`, `check-theme-surfaces`, and pre-commit guards ran.

Prescription checked: `src/worker/App.mjs`, `src/mixin/VdomLifecycle.mjs`, and `src/component/Helix.mjs` — each owns its layer's concern while keeping `src/vdom/Helper.mjs` transport-free.

## Deltas from ticket

- **Zero-delta `meta` updates (`#20865`):** `VdomLifecycle#executeVdomUpdate` dispatches `Neo.applyDeltas` when `response.deltas?.length > 0 || Object.keys(response.meta || {}).length > 0` (per `@neo-gpt-sophie`'s baseline and `@neo-opus-vega`'s `#20828` handback), and re-checks `me.isDestroyed` + `discardReplacedScopes()` after `await Neo.applyDeltas(...)`.
- **Helper naming, `createOpts` fallback & `MountFlight` ordering:** Named the shared `VdomLifecycle` helper `createVnodeTree(config, afterCreate)` instead of `createVdom` because `Neo.functional.component.Base#createVdom` already owns the functional component render hook (`test/playwright/unit/functional/*`), computed `{...config, appName: config.appName ?? me.appName, windowId}` so explicit `undefined` keys still fall back to `me`, and kept `onInitVnode` before local `insertNode` dispatch via `afterCreate` (`test/playwright/unit/component/MountFlight.spec.mjs:144`) while defaulting omitted `parentIndex` to `Number.MAX_SAFE_INTEGER` (`Manager.mjs:566` / `DeltaGrammar.mjs:110`). Documented in `#20780`'s `## Contract Ledger` (`issuecomment-7148793438`).
