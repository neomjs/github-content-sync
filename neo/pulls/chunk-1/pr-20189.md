Resolves #20187

A grid with locked columns now presents one WAI-ARIA grid to assistive technology:
- **Columns are numbered grid-wide.** `Container#getAriaColumnOffset` adds the column count of the preceding regions to each cell and header button.
- **Each record is one row.** The lead region's row (start if present, else center) owns the other regions' rows for the same record through `aria-owns`, and those rows take `role="none"`. The header toolbars follow the same pattern (`Wrapper#syncAriaRows`).
- **The engine no longer reads ARIA back.** The header SortZone resolves the dragged column by `dataField`, and `Body#getRecordByRowId` reads the row's own `rowIndex`.

Evidence: L2 (unit, component and e2e, including Chromium's own accessibility tree via CDP; red-first on origin/dev) → L2 required (AC-1 to AC-4). Residual: AC-5 (a real screen-reader read on the deployed showcase), Residual-Owner: #20188, the sibling grid ARIA ticket, which needs the same read.

agent-preflight: not hosted here; the baseline `pr-body` and `substrate-size` checks run in CI. Change class: restoration (`fix`).

## Deltas from ticket
- The toolbar and menu-trigger placement (the old Fix item 4) moved to #20188. It affects every grid and restructures the header element.
- `Body#syncAriaRowOwns`: the start body renders before its siblings build their pools, and an unchanged lead row skips its next render. So each sibling re-syncs the lead rows' `aria-owns` after its own pass. The first unit run caught the missing ownership.
- `Body#getRecordByRowId` returns `null` for a hidden pool row (`rowIndex` -1); before, it read that row's stale `aria-rowindex`.
- `HeaderMenuShape.spec.mjs` pinned the old behavior (`colindex: ['1','2','1','2','1']`, three ARIA rows per record). It now expects 1–5 and counts rendered rows by `.neo-grid-row[data-record-id]`. The `RowCellIdMigration.spec.mjs` stubs gained the three new body/container members.
- `HeaderCellRectSync` and `HeaderResizeRectSync` (e2e) read a region body's first `[role="row"]`, which is now `null` outside the lead region. CI caught it on `9f6d6b2`. They now pick `.neo-grid-row[data-record-id]`, and pass locally: 1/1, and 6/6 with a seat-own Bridge port.
