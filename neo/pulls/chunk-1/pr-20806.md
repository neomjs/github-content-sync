Resolves #20773

## What

`NativeLifecycle#releaseSource` now recognizes the departed window as a readmit hold's connecting one: while the committed item still owns its key with no window, a repeated `readmit` answer places a **fresh hold record** — cancelling the departed rebind's pending `prepare` continuation, whose admission-object check then fails — with the new `closed` answer attached per #20147. Any other unbind answer hands the committed item to `released` with `committed: true`.

## The #20771 arm

Its interim assertion (admission cleared, nothing released) pinned this path as-is on `dev` for this ticket; this PR updates that arm to the fresh-hold contract, keeping its `unbound` sequence check (`['old', 'reloaded']`). The #20144, #20147 and #20770 arms pass unchanged.

const rehold = async (windows, preparing, beforeSecondRelease = () => {}) => {
    const vessel = await windows.acquire('view', {itemId: 'one'}), key = vessel.workspaceKey;
    manager.bind({...vessel, windowId: 'old'});
    await expect.poll(() => windows.getConnection('view', key)).not.toBeNull();

    release('old');

    manager.bind({...vessel, windowId: 'reloaded'});
    await expect.poll(() => windows.getAdmission('view', key)?.connectingWindowId).toBe('reloaded');
    beforeSecondRelease();
    release('reloaded');
    preparing.resolve(true);
    return {vessel, key}

test('after the re-hold the lineage binds again and is admitted as owned (#20773)', async () => {
    const windows = owner('root'), preparing = deferred(), released = [], bound = [];
    let prepares = 0;

        prepare : () => ++prepares === 2 ? preparing.promise : true,
