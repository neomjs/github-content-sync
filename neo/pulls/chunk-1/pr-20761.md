### What

Under the row selection model, a tree grid row announces `aria-expanded` but could only be opened or closed with the mouse. Following the WAI-ARIA treegrid pattern [QUARANTINED_URL: w3.org], `ArrowRight` now expands the single selected collapsed parent row and `ArrowLeft` collapses an expanded one.

- `Neo.selection.grid.RowModel`: registers `Left` and `Right` beside `Down` and `Up` (and removes them in `unregister()`); `onKeyDownLeft` / `onKeyDownRight` go through `canNavigate(data)` and then `toggleSelectedTreeNode(expand)`, which only acts in a tree grid with exactly one selected row.
- `Neo.grid.Container#toggleTreeNode(record, expand)`: the one home of the store call and the `expand` / `collapse` event. Returns `false` outside a tree grid, on a leaf, or when the record already is in the requested state.
- `Neo.grid.column.component.Tree#onToggleClick` now calls that method instead of carrying its own copy.
- `learn/guides/datahandling/TreeStore.md`: one sentence in the accessibility section names the two keys.
- `test/playwright/unit/selection/RowModelTreeKeys.spec.mjs`: covers AC-1 to AC-4 with a mock view, borrowing the real `toggleTreeNode`.

Out of scope, as the issue says: Tab reaching the rows, the cell models, moving the selection to parent/child, `Neo.tree.List`.

### What I saw in `examples/grid/tree` (AC-7)

`npm run server-start`, headless Chromium 158, 1024x768, click on the `src` row's "Type" cell, then the keys. Read from the DOM after each step:

| Step | `dev` (82458b0) | this branch |
|---|---|---|
| Page loaded | `aria-rowcount` 8, `src` row `aria-expanded="true"` | same |
| Row clicked, ArrowLeft | 8 / `true` (nothing) | **4 / `false`** |
| ArrowRight | 8 / `true` (nothing) | **8 / `true`** |
| ArrowRight again | 8 / `true` | 8 / `true` (no-op, already expanded) |
| ArrowDown | selection moves to `component` | selection moves to `component` (unchanged) |
