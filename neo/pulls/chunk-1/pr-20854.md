Resolves #20848

The field setter now hands the assigned value to `notifyChange()` as is, so `setRecordFields()` is the only place a written value is parsed. `record.field = value` and `record.set({field: value})` now store the same once-converted value, for flat and nested fields, and the interceptor sees the proposed value before conversion, as the `notifyChange()` JSDoc says.

Evidence: L1 (unit arms in `test/playwright/unit/data/RecordFactory.spec.mjs`) → L1 required (all ACs are unit-observable). Residual: none.

## AC Evidence
| AC-1 | CI-covered: `a field setter converts the assigned value once, like record.set() (#20848)` (flat `ms`, `convert: value => value * 1000`) |
| AC-2 | CI-covered: same spec, nested `address.zip` through its path setter |
| AC-3 | CI-covered: same spec, `recordChange` of the setter write is `{name, oldValue, value}` with the once-converted value and equals the `set()` event |
| AC-4 | CI-covered: `a field setter still leaves the record unchanged for a refused value (#20848)` (`maxLength`, `minLength`, `nullable: false`; data, version and events unchanged) |
| AC-5 | Both new specs fail on `dev` (setter gave `4000000`; the `maxLength` case stored `1000000` because the refused value's fallback was converted again) and pass with the fix. |
