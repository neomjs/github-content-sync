Resolves #20846

🌿 A store can no longer insist that every row it holds is one of its leaves.

`Store#modelOf(item)` (protected) answers the model a raw row derives its fields from and becomes a record of. It returns `this.model` unless a subclass overrides it. The four places a store turns a raw row into values or a record ask it: `createRecord()`, `hydrateRecord()`, `resolveField()` and `resolveRow()`. They ask for a raw row only. A record owns its fields, so `resolveField()` and `resolveRow()` answer a record before the selector runs.

A store that projects rows of its own shape answers those rows with their own model. The first such store is Pro's grouping store, with its group rows (neomjs/neo-pro#185). The leaf fields' `convert` and `type` then stop parsing computed aggregates. The answered model names the store as its `storeId`, as the store's own model does, so a change to its record reaches the store.

Change class: capability (`feat`). It adds a protected seam, and the default changes no store beyond the record read named under Deltas.

size-guard-growth: src/data/Store.mjs — the seam's 3 code lines take the file from 1000 to 1003; without it, each store holding rows of another shape would duplicate hydrateRecord's map replacement and TreeStore's healing

Nothing is deleted, because the seam prevents a duplication rather than replacing one: the first consumer, neomjs/neo-pro#185, overrides one 3-line method.

Evidence: L2 (unit arms on the real `Store` and `TreeStore`) → L2 required (every AC is unit-observable). Residual: none.

## Deltas from ticket

- A record passed to `resolveField()` answers `record[name]` for a name it holds and the path through it for any other. It no longer looks the name up in a model. One read differs on every store: a name that is a member of every record and no field of its model (`version`, `get`, `isRecord`) answers that member, where it answered `undefined`. The Engine and Pro never pass a record. DevIndex's status toolbar passes one for declared fields, which read as before.
- Out of scope, noted in defect-note `4566d652`. On `dev`, `TreeStore#get()` returns a second record for a node that `getChildren()` already hydrated in Turbo Mode. I measured it with a plain `TreeStore`, no override. The tree arm therefore asserts values through `get()`, not identity; AC-2's healing holds as it does for any other node.
