**Other information:**

- `buildScripts/docs/index/release.mjs`: a note without `publishedAt` no longer falls back to the file's birthtime; its entry is written without a `date`, so the index is the same on any machine. Stamped notes keep their `publishedAt`, and sorting is unchanged (by version).
- `apps/portal/model/Release.mjs`: `treeNodeName` labels a dated release as before and an undated release as `13.4.0 [unreleased]`. Major-version folders also have no date, so the check uses `isLeaf !== false`: the index writes folders with `isLeaf: false`, and leaves rely on the model's `true` default, which isn't applied when the store calculates from a raw item.
- New specs: `test/playwright/unit/buildScripts/docs/index/ReleaseIndex.spec.mjs` (AC-1, AC-3) and `test/playwright/unit/apps/portal/model/Release.spec.mjs` (AC-2). Three of the five cases fail on `dev` without the fix; all five pass with it via `npx playwright test -c test/playwright/playwright.config.unit.mjs <spec>`.
- The `lint-staged` checks pass on the changed files. The rest of `test/playwright/unit/buildScripts/docs`, `apps/portal` and `app/content` pass, except `LearnCorpusLinks` and `RebuildContentIndexesAndSeo`, which fail the same way on `dev` in my checkout (no content corpus).
