Resolves #20664

`publish.mjs prepare --version <semver>` now sets `package.json` and `package-lock.json` as the release commit's first step, ahead of the note drop, the stamp, `prepare.mjs` and `build-all`. The bump, the dropped note and the regenerated Portal release index land in one commit, so a cut needs no separate bump PR. `finish` reads the version from `origin/dev`, where the merged release PR put it. The change builds on the reviewed head of my PR #19828 (`031238d6f5`), which was never merged, re-derived against current `dev`.

Evidence: L2 (unit specs plus read-only `--rehearse` receipts against the live remote) → L4 required for AC-6 only (the next real cut, an open-ended post-merge check). Residual: AC-5's Skills half, Residual-Owner: neomjs/neo-agent-skills#327.

## Deltas from ticket

- A version that is not newer than `package.json`'s fails the build-step preflight instead of stopping before any read. A resumed `prepare` runs on its release branch, where `package.json` already carries the version, so an up-front check would refuse every resume. The ticket's ledger row and AC-1 now say so.
- The Skills release-notes workflow also asks for the manual bump (`release-notes-workflow.md:81/87/97/98`). Its fix is a paired PR under neomjs/neo-agent-skills#327, which merges after this one.
- `buildScripts/README.md`'s `prepare.mjs` row now says what the script does: it carries the version into the files that print it and rebuilds the Portal's release and label indexes.
