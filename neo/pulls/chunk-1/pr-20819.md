Resolves #20768

## What

- `week/EventDragZone#dragEnd` and `month/EventDragZone#dragEnd` commit drops via `record.set({endDate, startDate})` instead of `setSilent` + the manual `doSort()` workaround: `recordChange` now reaches subscribers and `Neo.state.Provider` record bindings, and the store re-sorts itself through `Store#onRecordChange`.
- The calendar `EventsStore` `startDate` sorter opts into `reapplyOnRecordChange: true` (the grid header-menu precedent), so the store re-applies sorters when a drag moves an event across the sorted field — the `#2392` machinery this ticket builds on.
- A drop back onto the starting slot (or an Escape cancel) changes no field and fires no `recordChange`; those paths still run one `updateEvents()` / `createContent()` pass to restore the view after proxy teardown. A moved drop re-renders through the store listeners instead of a redundant extra pass. The obsolete `#2392` `todo` comment is gone.
- Dropping without a `StateProvider` (standalone `eventStore`) no longer touches `owner.getStateProvider()` at all, so the AC-2 `TypeError` surface is removed.

## Verification

- `test/playwright/unit/calendar/` → **18 passed**; the `#2334` month-drag spec now also asserts the commit fires `recordChange` with `endDate`/`startDate` on the dragged record, and that a same-slot drop fires none while the view still restores.
- `npm run test-unit` → **6875 passed, 2 skipped**.
- `test/playwright/e2e/rendering/CalendarMonthEventDrag.spec.mjs` fails identically on clean `dev` in this checkout (its press-point measurement misses locally), so the pointer-level arms are left to CI runners.
