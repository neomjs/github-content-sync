Resolves #20748

`AGENTS.md` is a pointer in git and the generated rules in every installed checkout. Git keeps a short note, the operator's one-liner: the file is generated, `npm install` writes it, and a fork's agent can print the contributor rules with `npx`. The `agents-md` stage writes the maintainer rules into the same path at `prepare` and on every `seat:start`. A clean filter maps the working copy back to the pointer, so `git status` stays clean. It is Git LFS's pattern.
- **One path for every tool:** Claude, Codex, Antigravity and any other agent read `AGENTS.md`.
- **Visible:** scanners and directories that look for a root `AGENTS.md` still find it.
- **No commit on a bump:** a skills bump changes the rules a session loads without anyone committing a file. The tracked copy used to need a hand catch-up (#20739).

Evidence: L3 (unit specs, a real-git round trip of the filter, and `npm run prepare` / `npm run seat:start` run live in this Engine checkout) → L3 required (AC-1 to AC-6). The Fleet-driven Start is Post-Merge Validation.

## Deltas from ticket
- **`AGENTS.md` stays tracked, as a pointer; it is not untracked.** This follows the operator's input on discoverability, and it makes Skills #342/#343 unnecessary: a CI tree always holds the file, so `.claude/CLAUDE.md` never dangles.
- **No stage step writes file content to the index.** Git trusts a changed size without reading the file. So after each generation, the entry is re-set to its own blob, which clears the cached stat, and `git update-index -q --refresh` runs with no pathspec. The index re-reads the file through the filter, and nothing is staged.
- **The filter is required, and its registration fails closed.** The stage makes sure `clean` and `required = true` are registered before it writes, and stops when they cannot be. A filter that cannot run makes git refuse to store the file, never store it raw.
- **It composes with the Fleet's home projection** (neomjs/neo-agent-brain#644). The install and `seat:start` run before the preparer (`startAgentProvisioned.mjs:716` → `:760`), so the preparer finds the generated file and writes no home copy. Two Fleet changes follow under their own leaf: count `AGENTS.md` as Claude's project file, which must land before `.claude/CLAUDE.md` can go, and read the pointer marker as "not supplied", so that a failed generation still gets the home copy.

## Slot rationale (`/turn-memory-pre-flight`)
- **`AGENTS.md`, delivery only:** the loaded content is the generator's output, byte-equal at pin 1.3.3 to the tracked file it replaces (23,408 B), so the always-loaded delta is 0 B. The committed bytes shrink to the 328 B pointer.
- **Decay mitigation:** the loaded file can no longer lag the installed sections, and the pointer has nothing in it to go stale.
