Resolves #22173

The file server now serves managed pathname routes from their app's static shell, with optional root mounting through `neo.spaRoot`, `--spa-root` and `--no-spa-root`. Physical files and missing static assets retain priority; root-app aliases and managed trailing slashes redirect with their search intact. ESM and both webpack builds synchronize emitted `routerBasePath` and `<base href>` values. Hash apps keep their existing behavior. No HTML rewriting occurs while serving responses.

Evidence: L3 (real-browser deep-route boot, navigation, Back, bookmark/query and hash controls against the live file server) plus L2 (HTTP and real build-entry regression tests) → L3 required.

## Deltas from ticket

The ESM build entry point, `buildScripts/build/esmodules.mjs`, also needs a small wiring change to apply the HTML transform and supply the emitted app directory. The four named implementation modules alone cannot alter the HTML emitted by that caller.

Config discovery follows the requested path's ancestors and caches parsed configs by mtime/size, avoiding recursive scans. A nearer hash app remains a boundary that the root SPA cannot capture. Portal's source routing mode and root package configuration are unchanged; their migration stays with the sibling ticket.
