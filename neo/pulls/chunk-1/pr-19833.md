Resolves #19829

A `wrapText` tree column now wraps its labels in a content-sized grid, and its rows grow to fit them. In a fixed-height grid the label keeps its one-line ellipsis.

- **Measured element:** the tree cell exposes its label's vdom (`textVdom`). `View#measureRowHeights` measures it as it measures a text cell's `.neo-grid-cell-text`, and reads padding and borders per column, because a helper-lines tree cell has no vertical padding.
- **Helper lines:** only the label wraps. The indent and the toggle keep spanning the row, so the lines stay unbroken when another column is taller.
- **Shown-cell fence:** `View#isShown` gets a component arm. A component cell counts as shown once its last landed update rendered its root's classes and style, and its label, as its vdom describes them. Its `needsVdomUpdate` cannot tell: a row's update carries a cell component's vdom without clearing the flag, so after a filter every re-bound tree cell stayed flagged and unmeasured.
- **Trigger:** a tree cell's own landed update schedules the view's measure pass.
- **Release note:** the 13.3.0 note's content-sized section now covers tree columns. Its bounds no longer list tree stores as deferred; only measuring tree labels ahead of the scroll is.

Evidence: L2 (unit arms on the measurement, each red under its mutation) + L3 (e2e on a real tree grid, with the browser's layout as the oracle).
