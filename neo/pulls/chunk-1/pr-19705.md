Resolves #19657

The Brain-gated e2e tier now runs on every pull request to `dev`, and its red blocks merge like any other red: merge readiness refuses non-required failures. The shared scope classifier picks the population, so the tier never skips:
- **full**, on ten shards, when the change reaches the E2E impact boundary or edits the tier's workflow, and on every `dev` push;
- **smoke**, the eight `BRAIN_SMOKE` files on one shard, otherwise, because the Brain's `dev` tip can break the pairing even when the change cannot.

Each receipt names its tier, so a green smoke is never read as full-tier evidence. No smoke file may be capability-gated or quarantined, which leaves a smoke receipt no exclusion to explain; the unit tier enforces it.

Evidence: L2 (classifier and selection arms, each red under its mutation; the full unit suite) + L3 (this PR's own full-tier run; probe #19706's hosted smoke run, red through the real reporting path and refused by merge readiness). Ready once this head's own full-tier run is green.

## Deltas from ticket
- An edit to the tier's own workflow also selects full. It is the one change the impact boundary does not name but the tier always reaches.
- The classifier's `changes` job chooses the population and feeds the matrix, so a smoke run provisions one shard, not ten. Shard names carry the count (`1/1`, `N/10`), so a branch rule must never require a per-shard name; the merge gate is the any-red rule.
- The `changes` job grants `pull-requests: read`. The workflow's `contents: read` token would otherwise fail the classifier's file listing on every pull request. A unit arm now checks every caller.
