# PR Micro-Review

**Class:** contained. Two portal files: the controller learns which routes its own side nav asked for, and `GroupIndex` gains `syncFocus()` for every other route. No engine or VDom-path file is touched, and the change teaches no architectural concept.

**Verdict:** Approved

**Glance:** The claim (#22120) is that after a history Back, DOM focus stays on the walked link while `aria-current` and the Tab stop move, so the next ArrowRight opens the wrong page.

- **The fix:** settling a route decides its source. A route the side nav requested (`walk` / `enterCards` push it onto `indexRoutes`, and settlement drops entries up to the opened one) keeps today's path. Any other route resets `walking` and, only while the index already holds focus and no walk key is mid-press (`walkFrom`), sends focus to the open destination's Tab stop. It goes through `Navigator#navigateTo` with `fromTarget: me.id`, and on `dev` (`Navigator.mjs:322-336`) that only moves focus while it is still inside the index, so a user who has moved on is not pulled back. The find-query branch takes the same rule.
