Resolves #20046

One press on the tab overflow control of an unfocused Workstation pane now opens its menu. The press used to focus the pane, which revealed the focus-gated action rail beside the control and re-partitioned the strip under the pointer, so the release landed on a different button and no click fired anywhere; the second press opened the menu. The fix is a hold: the toolbar can keep a focus-gated reveal back for a named reason, and the overflow plugin holds it from the control's `mousedown` through the click and for as long as its menu is open, so nothing in the strip moves until the user is done with the menu; the owed reveal lands when the menu closes. A keyboard focus, a tab click, the hover-reveal option and the rail's order are unchanged. Also fixed on the way: the hidden measurement reveal restored a withheld action's style by deleting the key, which the vdom style merge never removes, and withdrew the node in the same update, so the vnode kept `visibility: hidden` for its next reveal; the restore now writes `null` and lands before the withdraw.
