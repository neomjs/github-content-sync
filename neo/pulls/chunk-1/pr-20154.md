Resolves #20126

🌿 Close a window or reload one, and the App worker keeps nothing for the window that is gone.

A departed window's `Neo.controller.Application` stayed in `Neo.apps`, with its main view in the component manager, for as long as the SharedWorker lived: one app per closed popup and one per main-window reload. `worker.App#onDisconnect` now reaps one task after `disconnect` fires, after every listener and the microtasks it queued. It destroys each app the window no longer hosts, and once the whole window has gone, its CSS map, config, addons and hidden tick go too. `Application#destroy` destroys its main view with whatever that tree still holds, and hands the window's `Neo.apps` slot to a sibling app.

The worker guide states the contract: a listener keeps a component by moving it out first, synchronously or in microtasks. The engine's own owners now keep it:
- A Group participant without a close policy — the root a warm reload of the main window adopts — leaves the departed tree at release, keeping its window id until the adoption.
- `holdReleasedVessel` detaches a held pane by its `windowId`, however deep a host nested it.
- `NativeLifecycle` sources release side by side, so one source's main-thread round trip never delays another's detach.

Evidence: L3 (local Chrome: `e2e/dashboard`, and a downstream dock application's full suite and leak census on this head) → L3 required (AC-1, a real window departure). No residuals.

## Deltas from ticket
- Julia's design read (issuecomment-6430478913) shaped the delivery: the reap lives in `worker.App`, `Application#destroy` gains its main view and the slot handover, per-window worker state goes with the window, `NativeLifecycle` fans out, and the held-pane detach follows `windowId`. One catch is not taken: skipping `revertFocus` and the native drag unregister inside a departed tree. Those calls reject as departures, which `worker.Base#onUnhandledRejection` already suppresses (`isDeparture`).
- My drift note (issuecomment-6430341113) was wrong that no dock path keeps a component in a departed tree. A participant without a close policy stayed there until a warm reload adopted it, so the reap destroyed the main workspace and the downstream main window could not boot after a reload. Detaching it headless instead stalled its refresh pipeline: a tear-out return after the reload never settled. Leaving the tree while keeping the window id is what the adoption itself did until now.
- `worker.App#removeAppFromThemeMap` is removed. It deleted `Neo.cssMap[appName.toLowerCase()]`, a key the map never has (it is keyed by `windowId`), and `Application#destroy` was its only caller. The window's entry now goes with the window.
- Two specs needed their fixtures fixed: `DockWorkspace.spec.mjs`'s vessel main view now carries its window id, as an Application's does, and `ThemeFileDeparture.spec.mjs`'s late load reads the worker's themes, because the departed window's config is now reaped.
