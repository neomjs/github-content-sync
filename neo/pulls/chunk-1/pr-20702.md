Resolves #20697

## What

A workspace whose `node_modules/neo.mjs` is a symbolic link builds an App worker without the workspace's apps: webpack resolves the package to its real path, and `workerContextRebasePlugin` reached the consumer workspace by arithmetic from there.

- `workerContextRebasePlugin` now rebases app-space roots onto the workspace the build started in. The request is resolved to its path inside the package and that relative path is re-pointed at the workspace root, which the configs already hold in `cwd`. The old `'../../' + request` prefix was correct only while the package sat two directories under the workspace.
- `mainAddonContextPlugin` made the same assumption for Main's `WS/` namespace (`../../../src/main/addon` from `<package>/src`). A linked package emitted an empty package fallback and the workspace addon was unreachable, so it computes that root from `cwd` too. Both are the same repair the issue asks for on the Data, Canvas and Main paths.
- `check-consumer-runtime-build.mjs` gains the arms that would have caught both: a consumer-mode App worker build asserting the workspace's app is in the graph and no app of the package is, and a linked arm that moves the package to `node_modules/.pnpm/neo.mjs@1.0.0/node_modules/neo.mjs` and links it back, then re-runs every arm.

## Out of scope, reported not hidden

`src/worker/App.mjs`'s shipped `webpackExclude` drops any path segment `node_modules/` not followed by `neo.mjs`, so a package resolved from `node_modules/.pnpm/.../node_modules/` is excluded by its own store path and a `--framework` App build reaches no app of the package. That is a defect in the exclude pattern rather than in the rebase, so the framework arm runs in the installed layout only; I can open a separate issue for it if that is useful.
