Resolves #20767

The week view built drop dates from each column's `YYYY-MM-DD` flag as a fixed UTC instant
(`new Date(flag + 'T12:00:00.000Z')`). In timezones at UTC+12 and beyond (e.g. `Pacific/Auckland`),
that instant is already the next local day, so `setHours()` placed the event one column after the
drop target. Both drop paths now build the date from the flag's year, month and day as local
midnight (`new Date(year, month - 1, day)`), matching the pattern in `month/EventDragZone.mjs`.

## Changes
- `src/calendar/view/week/EventDragZone.mjs`: the drop date (dragEnd) is built from the column's local day.
- `src/calendar/view/week/plugin/DragDrop.mjs`: the drag-to-create start date (`onColumnDragStart`) is built the same way.
- `test/playwright/e2e/rendering/CalendarMonthEventDrag.spec.mjs`: new test that drops an event in the
  week view under `Europe/Berlin` and `Pacific/Auckland` and checks it lands in the target column.
  The existing test is unchanged.

**With the fix:** in every run where the drop completed, the event landed in the target column in both

## Test stability (feedback welcome)
Locally (Windows 11, Chromium), the new test passes about 8/10 with `--repeat-each=5`. The remaining failures
are timing-related, not wrong dates:
- in `Pacific/Auckland`, the measured event's center is sometimes not hittable (`elementFromPoint` misses it);
- occasionally a drop is ignored and the event stays in its source column.

I added a warm-up Escape drag (like the existing test's 1a step), a poll on the press point, and waits after
the cancel. Happy to change the approach, or drop the e2e test in favour of a unit test, if you prefer.

## Post-Merge Validation
