## Problem

`Neo.button.Base` never rendered `aria-pressed`, so a button with `pressed: true` reads as a plain button to assistive technology and state changes stay silent (#20829). The engine's own `SearchToolbar` had to write the attribute by hand next to `set({pressed})`, and every app that wants an accessible toggle has to copy that.

Resolves #20829

## Root cause

`afterSetPressed` only toggled the `pressed` CSS class. Since `pressed_` defaulted to `false` and a plain button must not announce itself as a toggle, there was no way to render the attribute without putting `aria-pressed="false"` on every button.

## Fix

`pressed_` now defaults to `null` (plain button). `afterSetPressed` writes `aria-pressed="true"` / `"false"` for a Boolean value and removes the attribute for `null`, in the same update that toggles the class. Existing readers (`toolbar/Base.mjs` uses `!== true` / `!== undefined`) behave identically with a `null` default. `SearchToolbar` drops both manual `aria-pressed` writes and relies on the config.

## Testing

- New spec `test/playwright/unit/button/AriaPressed.spec.mjs` covers the plain (no attribute), pressed (`aria-pressed="true"`) and unpressed (`aria-pressed="false"`) states, plus the Boolean-to-null removal.
- Verified with a standalone Node run of the button vdom through `test/playwright/setup.mjs`: on unmodified `dev` the attribute is `undefined` in all four scenarios; with this patch it is `"true"` / `"false"` / removed / absent. The full unit suite (browser-free unit config) is left to CI; it needs `npm install`, which was not available in this environment.
