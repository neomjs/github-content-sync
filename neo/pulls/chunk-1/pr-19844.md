Resolves #19843

The engine e2e tier runs as four shards instead of three, so each shard's test step is back under the five-minute ceiling. Dev's push of `e161f623bf` timed shards 1 and 3 out at 5.1 minutes with every test passed. The workflow header's rule applies: a shard nearing the ceiling gets a sibling, never a higher ceiling.

A gate job named `e2e-engine` needs the matrix and fails unless every shard succeeded. Dev's ruleset `19087298` requires the shards by name (`e2e-engine (1/3)`, `(2/3)`, `(3/3)`), and those names carry the count that adding a sibling changes. Requiring the one gate context instead means the next shard needs no ruleset edit. The ceiling, the dispatch path and the selection stay as they are.

Evidence: L3 (this PR's own hosted run is the receipt) → L3 required (AC-2 and AC-3 are measured on that run). Residual: AC-4 (the operator's ruleset swap) and AC-5, Residual-Owner: #19652.
