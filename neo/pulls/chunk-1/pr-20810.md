## Problem

A live observable keeps calling a listener after the listener's scope instance has been destroyed (#20807): the handler then runs on an instance whose fields `destroy()` has deleted. A listener registered with `delay` also still ran after its scope was destroyed while the delay was pending.

## Root cause

`fire()` only drops a listener when its scope has no `id` (`cb.scope && !cb.scope.id`), but `core.Base#destroy()` intentionally keeps `_id` and keeps configs readable, so the test never fires for a destroyed Neo instance. `delayedCallback()` re-checked nothing once its timeout ran, so a delayed call executed on a destroyed scope too. (A destroyed firer was already guarded by `me.fire = Neo.emptyFn`; a live firer with a destroyed listener scope was the gap left open by #20720.)

## Fix

In `src/core/Observable.mjs`:

- `fire()` now treats a scope that `isDestroyed` like a scope without an `id`: the listener is removed from the registry and not called.
- `delayedCallback()` skips the call when `cb.scope?.isDestroyed` is true once the timeout has run.
- The comment above the `fire()` scope test names both cases.

## Testing

- Added `test/playwright/unit/core/ObservableDestroyedScope.spec.mjs` with three arms: a destroyed scope is no longer called by `fire` (red on `dev` before the fix), a delayed listener is not called when its scope is destroyed before the delay ends (red on `dev`), and a live scope plus a scope-less listener keep working (green before and after).
- Full unit tier passes locally (`npx playwright test -c test/playwright/playwright.config.unit.mjs`).

Resolves #20807
