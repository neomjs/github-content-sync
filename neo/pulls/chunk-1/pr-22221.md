Resolves #21965

`getItemRecordId()` took `vnodeId.split('__')[1]`. When the list id already has `__` (a functional component's `generateIds()` names an id-less child `<parentId>__<n>`), that segment is part of the list id, not the record id. So a click did not select anything. It now strips the list's own `${this.id}__` prefix. The same fix is in `list.Component`, which had the same split and picked the wrong record. Ids without the prefix keep the old path. No public API change.

Example, list id `my-parent__0`, record `b`:
- before: `getItemRecordId('my-parent__0__neo-record-2')` -> `'0'`; `store.get('0')` -> `undefined`; no selection, no `select` event
- after: -> `'neo-record-2'` (internal id), or `'b'` with `useInternalId: false`; record selected, `select` fires once with `{records: [record]}`
- `list.Component`, item id `my-parent__0__1` (index 1 = `b`): before -> `'a'` (wrong record), after -> `'b'`

Evidence: L2 (new unit spec red on dev, green on branch; related unit dirs green) -> L2 required (#21965 ACs are unit specs).
