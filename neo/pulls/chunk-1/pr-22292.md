Resolves #22290

Makes `Neo.form.field.Text#centerBorderElWidth_` reactive, guards scheduled and in-flight inline border measurements (`afterSetLabelPosition`, `afterSetLabelText`, `updateCenterBorderElWidth`) with a monotonic `#centerBorderRequestId` invalidated on explicit `centerBorderElWidth` writes and cut-out clears (`afterSetDisabled`, `onFocusLeave`, `afterSetMounted(false)`, `afterSetLabelPosition`), and stops `afterSetLabelPosition` from arming an unmounted `timeout(20)` timer at construction time so stale `708` (`{width: 1000}`) measurements never clobber newer inline border state.

Evidence: L2 (Playwright unit suite including deterministic deferred-timer/deferred-`getDomRect` spec and `--repeat-each=20` 4-worker stress run, plus Chromium `form/field/Text.spec.mjs` component suite) → L2 required (AC-1, AC-2, AC-3).

Micro-review eligible: bugfix-guard — 1-file request-generation guard on `Text#updateCenterBorderElWidth` + `afterSetLabelPosition` with deterministic unit regression spec (`pr-review-guide §6.4`).

*   **Patch Verdict:** Matches. `centerBorderElWidth_` becomes reactive so `beforeSetCenterBorderElWidth` bumps `#centerBorderRequestId` on every write; the four clears bump it too; `afterSetLabelPosition` arms its timer only when mounted and captures the id; `updateCenterBorderElWidth` checks the id before the request and again with `isDestroyed`, `mounted` and `labelPosition` after it, and leaves a disabled empty field's cut-out alone.
