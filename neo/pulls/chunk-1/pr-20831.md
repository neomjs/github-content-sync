Resolves #20830

`RecordFactory.applyPreparedFields(model, updates, seal)` applies declared non-key edits to existing records. It runs their native setters and converters, calls the optional synchronous seal, then publishes native field changes to the Store and record subscribers. A converter or seal can reject the batch before publication. StateProvider bindings subscribe through the same commit hook. The caller receives post-commit notification errors.

Evidence: L2. Real Store, Model and generated record instances exercise the complete data operation in the unit runtime.

## AC Evidence

| Criterion | Evidence |
| --- | --- |
| AC-1 | The unmodified parser and Date controls below establish the failure. The RecordFactory spec runs the replacement with both modification-tracking modes. |
| AC-2 | The spec verifies absent nested fields, calculated fields, foreign and detached records, key refusal, and synchronous admission. |
| AC-3 | Store subscribers read both settled rows. Native normalization produces the same old/new payload as ordinary `set`. Provider tests cover two scalar paths in one binding and two independent subscribers to a store-less record. A failed conversion restores data, versions and dirty state before retry. |
| AC-4 | The owning JSDoc documents the seal, native conversions, error reporting, `notifyChange` admission, and `observeRecord` subscriptions to committed changes. |

## Deltas from ticket

The factory owns publication. Binding formulas run after the prepared records have published their field deltas in one reactive batch. The Provider's per-record wrapper and its module-scope baseline exception were removed.

## Test Evidence

On the unmodified Engine, the first row listener read amounts 7 and 2 halfway through a two-row edit. A later parser failure left the second amount at 8. Replaying the first row's saved tags through `setSilent` threw because the parser accepts CSV text and the saved value is an array. A separate Date control restored the original Date object but advanced the version 2 → 3 → 4.

The successful-conversion differential failed on an intermediate implementation that compared raw input with stored output. For inputs `'7'` and `'c,d'`, the final writer matches ordinary `set` at both the stored values and the emitted fields.

On the first PR head the two-row binding stayed at `aB` after the records became `XY`. Connecting the publisher alone produced an intermediate `XB`. The batched implementation produced one `XY` update after the seal and none for the refused edit.
