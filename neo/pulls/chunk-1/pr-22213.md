Resolves #22212

On the two-thread line the App worker sends each flight's deltas itself. A flight collected for a window whose port is already gone fails at send time with `NEO_DEAD_PORT`. That happens in the task between a vessel's disconnect and the reap of its tree. `executeVdomUpdate`'s catch excused only the in-flight shape, by error name (`PortDisconnectedError`), so it logged `vdom update failed`, and the `workerErrors` fixture turned `WorkstationFiveBeatNL` scene 2 red in 12–14 of 16 runs. The catch now asks `worker.Base#isDeparture`, the one departure predicate (#19071). It covers both shapes, because `removePort`'s in-flight rejection carries `NEO_DEAD_PORT` too (#19727). A dead port for a window that never departed still logs. The flight's cleanup is unchanged.

Evidence: L2 (unit specs on the real `promiseMessage` / `removePort` bookkeeping) + L3 (hosted real-browser dispatch before/after in the two-thread arm) → L3 required (AC-3).

Micro-review eligible: contained — one predicate in a catch, swapped for the engine's existing departure predicate, plus its spec and one fixture repaired to production's rejection shape.
