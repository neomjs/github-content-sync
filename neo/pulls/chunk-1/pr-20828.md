### `@iruzen-dono` commented on 2026-11-12T20:43:22Z

Closing mine — #20828 has #20780, and the claim rules settle it.

Since Vega's read names the missing piece, here is the helper my branch had, in case it saves a round trip. It is the same shape as the `initVnode` block it replaces, moved onto the mixin so `component/Helix` can share it (`Helix` calls `Helper.create` with `autoMount: true` directly and relied on main, the second half of defect 2):

```js
    /**
     * @summary Creates a vnode tree and performs the mount the VDom worker would otherwise perform.
     *
     * Without a VDom worker `Neo.vdom.Helper.create` is a local call, so nothing turns an `autoMount` flag into
     * the `insertNode` delta that `worker/Manager` sends on the worker path.
     *
     * @param {Object} config The `Neo.vdom.Helper.create` options
     * @param {Object} config.vdom The vdom tree to create; its `id` names the inserted node
     * @param {String} [config.appName]
     * @param {Boolean} [config.autoMount]
     * @param {String} [config.parentId]
     * @param {Number} [config.parentIndex]
     * @param {String} [config.windowId] Defaults to the calling component's window
     * @returns {Promise<Object>} The `Neo.vdom.Helper.create` reply, with the insert already applied when needed
     * @protected
     */
    async createVdom(config) {
        const data = await Promise.resolve(Neo.vdom.Helper.create(config));

        if (config.autoMount && !Neo.config.useVdomWorker) {
            await Neo.applyDeltas(config.windowId ?? this.windowId, [{
                action   : 'insertNode',
                id       : config.vdom.id,
                index    : config.parentIndex,
                outerHTML: data.outerHTML,
                parentId : config.parentId,
                vnode    : data.vnode
            }])
        }

        return data
    }
```

`data` is returned unconditionally so `initVnode` keeps its own `me.mounted = true` (it is an `initVnode` concern, not a create concern). Three unit specs under `useVdomWorker: false` pinned the behaviour on my branch and all three failed before the change: the meta reaching `applyDeltas` keyed by component id, `['applied', 'hook']` ordering, and one `insertNode` naming `config.vdom.id`.

Two notes from running the full tier locally, in case they help @ajendras get to green: `dist/marked.mjs` and `dist/parse5.mjs` have to exist (`npm run bundle-browser-deps`) or unrelated unit specs fail on import, and `npm run test-unit` reports **6808 passed** with the helper in place.

Good luck with the review — happy to answer questions here.

if (!Neo.config.useVdomWorker && response.deltas?.length > 0) {

Passing `response.meta` is the repair #20780 asks for. The condition in front of it keeps one case out: an update whose diff is empty and whose `meta` is not.
