**Other information:**

### Problem
When a listener's scope instance is destroyed (`scope.destroy()`), subsequent `observable.fire()` calls continue invoking the listener callback because `scope.id` remains readable after destruction (`core.Base#destroy` preserves `_id`). Additionally, delayed callbacks scheduled via `delayedCallback` still run if the scope is destroyed during the pending timeout.

### Root Cause
1. `Observable#fire` checked `if (cb.scope && !cb.scope.id)` to drop listeners whose scope no longer exists. For destroyed `core.Base` instances, `id` remains defined while `isDestroyed` is set to `true`.
2. `Observable#delayedCallback` invoked `cb.fn.apply(cb.scope, args)` without checking whether `cb.scope.isDestroyed` settled to `true` while the timeout elapsed.

### Fix
1. In `Observable#fire`, check `if (cb.scope && (!cb.scope.id || cb.scope.isDestroyed))` and unbind the destroyed listener from `listeners[name]`.
2. In `Observable#delayedCallback`, guard invocation with `if (!cb.scope?.isDestroyed)`.
3. Added unit tests in `test/playwright/unit/core/ObservableDestroyedScope.spec.mjs` verifying:
   - Listeners with destroyed scope are dropped and not called by `fire()`.
   - Delayed callbacks with destroyed scope are suppressed.
   - Listeners with active scope and listeners without scope continue to be invoked normally.
