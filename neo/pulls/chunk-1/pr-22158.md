Resolves #22157

The engine page no longer opens with "The Application Engine for the AI Era". It is now "The Engine Agents Build On", and its first section says what a coding agent gets from the engine before the page explains why an engine is not a framework. This follows the operator's direction of 24 Nov: the old label read as persuading humans to dive into code instead of hitting hard on agents understanding the engine and building on it.

- **Title and lead.** The H1 is "The Engine Agents Build On". The bold lead becomes the page's meta description once `seo.json` regenerates. It says agents understand the engine, excel with it and build on it, and links the merged pull requests as the record.
- **New opening, "What an Agent Gets".** It covers JSON blueprints, live objects through the Neural Link, no build step in development, and many agents in one running app. A top-down Mermaid diagram draws the loop.
- **Nothing cut.** The old opening moves under a new heading, "Why an Engine, Not a Framework". The paradigm-shift sections that #20518 restored follow unchanged.
- **Nav label and render guard.** The nav label in `learn/tree.json` follows the title, and the route joins `LearnMermaidRender.spec.mjs`.

`seo.json` is untouched: `buildScripts/docs/seo/seoJson.mjs` derives the title and description from the H1 and lead, and the pipeline regenerates the file.

Evidence: L3 (the Portal rendered the page's diagram in the e2e render spec on a local server) → L3 required (AC-3). Residual: none.

CI jobs: +0 (a ROUTES entry in an existing spec)

ACTIONS touched: no. FRAMING touched: yes. The apex is unchanged; the Engine projection on this page now leads with agents, at the operator's direction.
