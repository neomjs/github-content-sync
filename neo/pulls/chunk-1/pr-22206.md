Resolves #21504

File Size Guard's base-to-HEAD size ratchet now runs in the shared baseline's `guards` job, as the `file sizes` guard. Engine's pin moves to neo-agent-skills `v2.9.0`, whose `guards` job hands every guard the PR's base commit (`BASE_SHA`, full history) and its live body (`BODY_FILE`). `file-size-guard.yml` is deleted, and `same-head-check-repair.yml` follows `PR Baseline` alone. On a PR that touches `.mjs` code, a push or a body edit now starts two fewer runner jobs.

Two consequences, both deliberate:
- **Size violations now block the merge.** `baseline / guards` is a required context, and File Size Guard was path-filtered and not required.
- **The `spec retirement` guard drops `--unshallow`.** `v2.9.0`'s full-depth checkout makes `git fetch --unshallow` fatal ("on a complete repository"). The fetch still works anonymously on this public repository. No other caller of the shared baseline uses `--unshallow`: neo-agent-brain, devindex and neo-agent-institution were checked.

Evidence: L2 (unit spec, plus local runs of the new guard command and the fetch) → L3 required (AC-2, the job counts of this PR's own push and body edit, recorded below). Residual: none.
