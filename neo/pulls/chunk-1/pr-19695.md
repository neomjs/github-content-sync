Resolves #19692

Content-sized rows now measure only cells that the DOM already shows as their vdom describes them: the same text at the same width, read from the vnode of the row's last landed update. A row that a silent pass recycled while the view's update waited for other rows' flights is skipped. It is read once its own update lands, instead of taking the height of the text it showed before. The private `#isShown` in `grid.View` holds the check, and `measureRowHeights` collects only cells that pass it.

Evidence: L3 (headless Chromium repro on the #19666 example, plus unit specs with a vnode-backed read stub) → L2 required (AC-1 is a unit spec, AC-2 suite-level). No residuals.

## AC Evidence
| AC-1 | CI-covered: `test/playwright/unit/grid/WrapTextMeasure.spec.mjs`, "a row whose vdom runs ahead of the DOM is read once its update lands" (another record), plus "a cell whose new width has not landed is read at that width once it does" (the width clause) |
| AC-2 | CI-covered: `WrapTextMeasure` and `AnchorCorrection`, unit and e2e, in the unit and e2e engine jobs |

## Deltas from ticket
- The fence also compares the width, not only the text: a pending column resize lags the DOM through the same deferral. It has its own unit test.

## Test Evidence
- **Repro** (the #19666 example, not on `dev`): jump to row 99996, then four rapid ArrowDowns at 1400×900. Without the fence, the final row ended at a stale 100px (its text needs 81px) in 18 of 20 headless runs. With the fence, it ended at 81px in 20 of 20.
- **Mutations:**
  - with the whole fence removed, the record test fails (65 vs 40: record 1's note read for record 152);
  - with only the text clause removed, the same test fails;
  - with only the width clause removed, the width test fails.
