### What changes

`Neo.button.Base` projects its toggle state onto `aria-pressed`, so a screen reader announces it — and a button that is not a toggle stays silent about it.

| File | Change |
|---|---|
| `src/button/Base.mjs` | `pressed_` defaults to `null` ("not a toggle"); `afterSetPressed` calls a new `syncAriaPressedState()`, which writes `aria-pressed` for a Boolean and removes it for `null` |
| `src/grid/SearchToolbar.mjs` | the case button declares `pressed: false` and drops both hand-written `aria-pressed` writes |
| `src/tab/header/EffectButton.mjs` | `aria-selected` reads `pressed === true`, which keeps its `false` default now that `pressed` can be `null` |
| `test/playwright/unit/button/AriaPressed.spec.mjs` | four vdom cases: plain, pressed at creation, toggled both ways, back to `null` |
| `examples/dashboard/dock/MainContainer.mjs` | the saved-perspective buttons declare `pressed: false` — they are toggles, so the untouched state is a state rather than an absence (the dock unit spec asserts `false` there) |

### Why `null` and not `false`

The ticket's architectural note is the whole decision: `pressed_` defaulted to `false`, so `afterSetPressed(false)` runs for every button at construction, and a plain button is indistinguishable from a toggle that is off. Writing `aria-pressed="false"` everywhere would announce every button as a toggle — the trap listed on the ticket. `null` is the third state the class was missing, and `typeof pressed === 'boolean'` is the discriminator.

I checked the `pressed` readers before moving the default:

- `toolbar/Base.mjs:472` reads `item.pressed !== true` — unchanged for `null`.
- `button/Effect.mjs:215` toggles the class from `this.pressed` — falsy for `null`, same class result.
- `tab/header/Button.mjs:147` reads `!this.pressed` — unchanged.
- `tab/header/EffectButton.mjs:65` was the one place whose output changed (`aria-selected: null`); it now reads `=== true`.
- `calendar`, `dashboard/dock/interaction/Rail` and `tab/Container` assign a Boolean explicitly.

`toJSON()` now serializes `pressed: null` for a plain button instead of `false`. No reader distinguishes the two, and the state is more honest.

### The write lives in the same transition as the class

`afterSetPressed` toggles `'pressed'` on `this.cls` and calls `syncAriaPressedState()` on the vdom root, the same shape `afterSetDisabled` / `syncNativeDisabledState` already uses. The unit case asserts both in one delta: `deltas[0].cls.add === ['pressed']` and `deltas[0].attributes['aria-pressed'] === 'true'`, so the two cannot drift.
