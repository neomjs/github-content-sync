## Problem

Resolves #20673

`Neo.grid.column.Base#dataField` is documented as changeable at runtime, and the grid's `columns` collection is keyed by `dataField`. After a change, the old key stayed in the collection's `Map`:

```js
grid.centerColumns[0].dataField = 'second';
grid.columns.get('second'); // null
grid.columns.get('first');  // the column
```

Eleven lookup sites in `src/grid` (`View`, `Body`, `Row`, `header/GroupRow`, `plugin/CellEditing`) call `columns.get(dataField)` and so stopped finding a re-pointed column.

## Root cause

`afterSetDataField()` re-keys `body.columnPositions` (the #9151 fix) but never the grid's own `columns` collection, although `Neo.grid.Container#createColumns()` builds it with `keyProperty: 'dataField'`. The column's `dataField` has already changed when the hook runs, so `Neo.collection.Base#updateKey()` cannot repair it: that method derives `oldKey` from the item, which now carries the new value.

## Fix

In `afterSetDataField()`, when `gridContainer.columns.get(oldValue)` is this column, delete the old key from the collection's `Map` and set the new key for the same instance — the same pattern the `columnPositions` block a few lines above uses. `columns.items` is not spliced, so the column keeps its position and the count is unchanged. No call site changes, no new dependency.

The new unit test in `test/playwright/unit/grid/DynamicColumn.spec.mjs` asserts both lookup directions, the count, the index, and the field order.

## Testing
