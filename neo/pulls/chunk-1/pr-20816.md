**Other information:**

The Portal SCSS still carried its own literal durations and easings, so `prefers-reduced-motion` never reached it. This PR routes every transition under `resources/scss/src/apps/portal/` through the vocabulary in `_motion.scss`:

| literal | token |
| --- | --- |
| `--portal-transition-duration: 300ms` (both neo themes) | `var(--motion-panel)` |
| `color 250ms`, `background-color 250ms`, `opacity 50ms`, `color 0.2s` (hover/focus feedback) | `var(--motion-fast)` |
| card hover `transform/box-shadow/border-color 0.2s–0.3s` | `var(--motion-base)` |
| cube `transform 800ms ease-in-out` | `var(--motion-stage)` |
| `ease` / `ease-out` / `ease-in-out` | `var(--ease-out-soft)` |

After the change `grep -E '[0-9](ms|s)\b|\bease' resources/scss/src/apps/portal/` returns nothing.

Verification: a new `test/playwright/e2e/portal/MotionTokens.spec.mjs` reads the computed `transition-duration` on the examples list and asserts `0.28s` (= `--motion-panel`) with a `cubic-bezier` timing function, and `0s` under `page.emulateMedia({reducedMotion: 'reduce'})`. On `dev` without the SCSS change both specs fail with `Received: "0.3s"`; with it, `2 passed`. Themes rebuilt with `npm run build-themes -- -n -e dev -t all`. Note: on this Windows checkout `check-theme-value-files` fails on an untouched `dev` as well (baseline keys use `/`, scanned paths use ``, so `dialog/Base.scss` reports as both new and stale); the other lint-staged tasks were run by hand and pass.
