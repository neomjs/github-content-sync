Resolves #20825

Tooltip now shares the existing component mount flight and records the latest show/hide intent. Repeated shows during one pending insertion create one node, and a hide before insertion finishes removes it when the flight lands. Timer, hover and alignment policies stay unchanged.

Evidence: L3 (real App → VDOM → Main → App insertion and retargeting controls) → L3 required. Residual: none for this close target.

## Deltas from ticket

No new runtime primitive. The existing delay-test prototype host now shadows the lifecycle fields used by the inherited primitive and returns a Promise from its mount mock. The new native spec is included in both adapter eligibility and Engine CI selection; its admission requires the hosted run to pass before merge.

## Test Evidence

Before the production edit, the focused units produced four behavioral failures: repeated shows sent three inserts, show-hide-show sent two, pending hide sent no landing removal, and a hidden flight remained mounted. The destruction and existing timer controls passed; the destruction arm is a lifecycle control, not a claim that one particular guard is its only protection.

The unchanged-source native run failed three of four cases: repeated show painted three Tooltip/Label nodes with duplicate IDs, pending hide was lost, and pending retarget painted two nodes. Ordinary mounted retargeting passed. The witness holds an actual Main insert message and later releases its original arguments unchanged; it never substitutes vnode, mounted, DOM or renderer state. Native insertion counts are the multiplicity oracle, since theme loading can legitimately re-enter `initVnode`.

Final regressions run in CI. The native witness uses the page's own dedicated App Worker through the off-socket Neural Link adapter, without a Brain checkout or Bridge.
