Resolves #22218

Apps that set `useVdomWorker: true` keep diffing in a separate worker. The new vnode travels directly to App, while Main receives the write set for the collecting window. App adopts the vnode after Main acknowledges the write. A no-op needs only the tree reply. The existing App-worker default and the initial mount protocol retain their behavior.

Decision Record impact: amends ADR 0043 to support the enhanced opt-in worker in the next minor. The next-release roadmap includes #22218. The implementation derives from [Julia’s benchmarked Arm C patch](https://github.com/neomjs/benchmarks/issues/15#issuecomment-7181288142). The ADR links the production-build results and records their limits.

Evidence: L3 (dedicated and two-window SharedWorker Chromium journeys, ordered unit controls and existing A/B/C device measurements) → L3 required.

## AC Evidence

| AC-2 | `ReplyLoss.spec.mjs` holds each reply in turn and checks that only their join resolves the original payload. A no-op takes one leg and metadata alone requires the DOM acknowledgement. The existing `YieldedMoveCoalescingNL` witness holds the targeted delta before Main applies it. |
| AC-3 | Negative controls cover clone failure before DOM dispatch, DOM rejection, window departure, direct-channel decoding failure, worker error, and either or both replies being lost. A 30-second bound releases a silent flight. Late replies cannot revive the rejected request. |
| AC-4 | The [matched three-way production matrix](https://github.com/neomjs/benchmarks/issues/15#issuecomment-7181288142) includes BigData streaming/scrolling and the 4× Main-thread sensitivity arm. ## Deltas from ticket

Channel publication waits for confirmation from the active VDom port. This fences a provisional transfer from a departing window and keeps the helper’s first update on the direct channel. The App request deadline covers loss of either leg. `create` and `autoMount` retain their existing Main relay.
