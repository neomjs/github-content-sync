Resolves #19841

A pane popped out with the header action no longer docks back into main when the pointer enters its window. `DragCoordinator` now records the origin each window last published (read from its `Neo.manager.Window` record, engine moves included). It starts a native title-bar gesture only from a changed origin. A window's first publication only sets its baseline, and a running gesture keeps every frame. So neither the viewport offset a first pointer sample measures nor a resize that keeps the origin reads as the OS dragging a vessel over main any more. The `PopOutSparklines` arm leaves the Brain quarantine, because its hosted symptom was this misread, reached through its resize.

Evidence: L3 (unit arms in CI; the e2e arms in the hosted Brain-gated tier; mutation and a CPU-throttled discriminator run headless on this branch, each red against dev's coordinator) → L3 required (AC-2 and AC-4 are real-browser pop-outs). Residual: #19841's Post-Merge Validation (the operator's hand check; the other five quarantine entries), Residual-Owner: #19655.

agent-preflight: not hosted here; the baseline jobs run in CI.

## Deltas from ticket

- The baseline is keyed by the window's `Neo.manager.Window` record in a `WeakMap`, so a departing window takes it along. The record is also the geometry the drop candidate already reads.
- Twelve unit arms published a stationary window as a drag frame. They now model the move: `nativeFrame` records the window a pixel away, then publishes, so every geometry an arm asserts is unchanged. The two `SortZone` arms do the same inline.
- AC-4 is narrowed to the Sparklines entry. The other five moved to the ticket's Post-Merge Validation.
