Resolves #22171

Documents opt-in `'pathname'` routing, `?search` parameter handling, `SharedWorker` `windowId` route formatting, and `fileServer.mjs` `spaRoot` behavior across the routing tutorial and getting-started guides. Pure documentation update with no runtime, build-script, or `learn/tree.json` changes.

- **`learn/tutorials/Routing.md`:** Added the `Opting Into Pathname Routing` section covering why `'hash'` remains the default, configuring `routerMode: 'pathname'`, `routerBasePath`, `routerIgnorePaths` (raw-pathname order before trailing-slash canonicalization), and `<base href>` across dev and `dist/*` builds (`rewritePathnameConfig` / `rewritePathnameHtml`), reading `value.hash` / `value.query` / `value.search` and mutating `?search` via `Neo.Main.editRoute` (including `null` deletion and array values), formatting per-window `SharedWorker` links via `Neo.util.String.toRouteHref(route, this.windowId)` and `Neo.windowConfigs[windowId]`, `fileServer.mjs` `spaRoot` / `--spa-root` / `--no-spa-root`, and the interactive human-routing vs. deployment-middleware hosting boundary.
- **`learn/gettingstarted/Setup.md`, `CreatingYourFirstApp.md`, and `Workspaces.md`:** Clarified that `npx neo-app` workspaces launch `buildScripts/server.mjs` (`fileServer.mjs` `run({open})`) with no `spaRoot` by default unless configured via `"neo": {"spaRoot": "..."}` or `--spa-root`, whereas `neomjs/neo` configures `"neo": {"spaRoot": "apps/portal"}` and accepts `npm run server-start -- --no-spa-root` for the root directory listing.
