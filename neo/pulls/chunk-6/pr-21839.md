Resolves #21271

A dialog with `keepInBoundary` stays inside its `boundaryContainerId` when that container changes size. It moves back by the smallest distance, and shrinks only along an axis it can no longer fit on, never below its `minWidth`/`minHeight` in px. A dialog that still fits gets no write, and a repeated size gets no measurement. The desktop turns it on for every app window, so a window you placed keeps its place when the browser or the workspace changes, until the workspace would cut it. The contract is the Contract Ledger on #21271.

Evidence: L4 (real-browser e2e on `examples/desktop/basic` plus unit specs for the guards) → L4 required (the ticket's interaction list is browser behaviour). Residual: none.

## Deltas from ticket
- `Neo.util.Rectangle#fitTo()` is new public API. The dialog reuses the private fit that `alignTo()` already had (#21115), so the clamp exists once.
- The ResizeObserver addon dispatched a `document.body` target under the body's empty `id`, so no listener heard it. It now dispatches under the id the target was registered with, which also holds without `useDomIds`.
- A move to the right edge left the window 2px outside the workspace: the drop lands 2px past the clamp that `main/addon/DragDrop.mjs` sets (x 962 for a clamp at 960). A `keepInBoundary` dialog now measures the drop with its container and lands inside; other dialogs keep the old drop. The clamp itself is out of scope, noted in a defect-note.
- `boundaryContainerId` is now reactive, so a new container moves the observation.
