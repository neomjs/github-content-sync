Resolves #19220

`Main#windowOpen` makes a popup's requested height its total height — the window takes the size of the widget it replaces, the content a little smaller. It built that resize from the newborn's own `outerWidth` and `innerHeight`. An unemulated Chrome answers `outerWidth 0` for a popup that has no frame yet (measured: `innerWidth 320, innerHeight 239, outerWidth 0, outerHeight 0` synchronously after `window.open`), so `resizeTo(0, 239)` landed on the platform's minimum width: the film's capture mode birthed every vessel at 146×239 while the emulated tour, whose metrics answer the request at once, saw 320×240. The resize now takes its numbers from the feature string (`Main.parseWindowFeatureSize`, `width`/`height` or their `inner*` spellings); a request that names no size is left as the platform made it. Same intent, same outcome under emulation, and a real window now matches it.

Evidence: L3 achieved (one headed capture-mode run on the film-stage display: both vessels 320×240 outer / 320×173 inner from first paint) → L3 required (AC-2). Residual: none for this ticket; the compose beat's remaining capture-mode cause is the follow origin, its own ticket (see #19220's Related).

agent-preflight: not hosted here; the CI baseline jobs ran.
