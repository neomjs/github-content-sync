Updates `lint-staged` from 17.5.1 to 17.6.0
<details>
<summary>Release notes</summary>
<p><em>Sourced from <a href="[QUARANTINED_URL: github.com]">lint-staged's releases</a>.</em></p>
<blockquote>
<h2>v17.6.0</h2>
<h3>Minor Changes</h3>
<ul>
<li>
<p><a href="[QUARANTINED_URL: redirect.github.com]">#1850</a> <a href="[QUARANTINED_URL: github.com]"><code>938d3f4</code></a> - Task functions like <code>{ title, task }</code> can now use a logger function <code>log()</code> to emit output while the task runs. By default, the output will only be visible if the task fails, unless the <code>--verbose</code> option was used. Additionally, when the task rejects, the error will be shown in the output.</p>
<pre lang="js"><code>import { defineConfig } from 'lint-staged/config'
<p>export default defineConfig({
'*': {
title: 'Fail if PDF files are committed',
task: async (filepaths, { log }) =&gt; {
const pdfFiles = filepaths.filter((f) =&gt; f.toLowerCase().endsWith('.pdf'))
if (pdfFiles.length &gt; 0) {
log('PDF files should not be committed: %s', pdfFiles)
throw new Error('Failed')
}
},
},
})
</code></pre></p>
</li>
<li>
<p><a href="[QUARANTINED_URL: redirect.github.com]">#1854</a> <a href="[QUARANTINED_URL: github.com]"><code>30562bc</code></a> - <em>lint-staged</em> now stages changes to <strong>all tracked files modified by tasks</strong>, including files that weren’t originally staged or didn’t match the configured globs. This can happen when your task has side-effects, or it's a function that ignores the staged files like <code>() =&gt; &quot;prettier --write .&quot;</code>.</p>
<p>If you have unstaged changes in a file and the task also edits that file, your unstaged changes will be staged too. Use <code>--hide-unstaged</code> to hide your changes while tasks run.</p>
</li>
</ul>
<h3>Patch Changes</h3>
<ul>
<li>
<p><a href="[QUARANTINED_URL: redirect.github.com]">#1860</a> <a href="[QUARANTINED_URL: github.com]"><code>4296532</code></a> - The assignment of staged files to <em>lint-staged</em> configuration files (when using multiple, for example in a monorepo) has been rewritten to be more efficient. As a reminder, each staged file is assigned to exactly one configuration (the closest one), even if that config doesn't match the file in its globs.</p>
</li>
<li>
<p><a href="[QUARANTINED_URL: redirect.github.com]">#1861</a> <a href="[QUARANTINED_URL: github.com]"><code>c45f28a</code></a> - Fix running parallel tasks for a single glob, when tasks are created by a function. Nesting one level of arrays inside an array of tasks will result in the inner tasks running in parallel. This behavior should now be consistent when creating tasks using functions. In the following example <code>eslint</code> and <code>prettier</code> will run in parallel (for all files, when any JS files are staged):</p>
<pre lang="js"><code>import { defineConfig } from 'lint-staged/config'
<p>export default defineConfig({
'*.js': () =&gt; [['eslint --max-warnings=0 .', 'prettier --list-different .']],
})
</code></pre></p>
</li>
<li>
<p><a href="[QUARANTINED_URL: redirect.github.com]">#1859</a> <a href="[QUARANTINED_URL: github.com]"><code>f0ea69d</code></a> - Various performance improvements from skipping redundant internal Git calls.</p>
</li>
<li>
<p><a href="[QUARANTINED_URL: redirect.github.com]">#1856</a> <a href="[QUARANTINED_URL: github.com]"><code>69d7d17</code></a> - Partially staged changes are hidden in a uniquely-named patch file to avoid multiple invocations of <em>lint-staged</em> overwriting it. This makes it safer to run <em>lint-staged</em> in multiple worktrees at the same time.</p>
</li>
</ul>
</blockquote>
