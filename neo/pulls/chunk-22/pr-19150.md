## What this is

`Neo.calendar.view.month.Component#construct` decided whether to build its grid from two store counts:

```js
if (me.calendarStore.getCount() > 0 && me.eventStore.getCount() > 0) {
    me.needsEventUpdate = true
}

me.needsEventUpdate && me.createContent(true);
```

`afterSetMounted` builds only behind that same flag, so a month with no calendars never reached `createContent` at all. Measured against a live server on `dev` at `18b473b6e8`:

```text
after mount      weeks 0   days 0   events 0
addCalendar      weeks 0   days 0
addEvent         weeks 18  days 126 events 1
```

The first two lines are the defect. The third line is the same component drawing correctly the moment a matched calendar/event pair arrives through `onEventStoreLoad`, which is what makes this a mount-path defect rather than a grid that cannot draw.

The days are the grid's frame, so they no longer wait on data: `construct` builds them unconditionally. Events keep needing their calendars, because `createContent` calls `createWeek` per row and `createWeek` reads each event's calendar for its color class. `Store#get` answers `undefined` for a missing key, so an event whose calendar is absent is now skipped rather than drawing a `neo-undefined` class.

That read becomes reachable for the first time with this fix, which is why the guard ships with it.

The #2460 race is untouched. That fix made a view constructed *after* both stores loaded build its events; it still does, through `onEventStoreLoad`.

Resolves #19149

## The witness

`test/playwright/component/calendar/MonthEmptyMount.spec.mjs`, four arms:

| arm | before | after |
|---|---|---|
| no calendars and no events draw 18 weeks / 126 cells | `0 / 0` | `18 / 126` |
| the 1st of the fixture month has its own day cell | red | attached |
| an orphan event does not reach a day cell | red | `0` events, days still drawn |
| a matched pair still reaches its day cell (control) | green | green |

Row counts are derived, not copied: `createContent` renders 18 weeks of 7 days, the continuous scrolling month rather than a calendar's 5 or 6 rows. The month view never calls `getWeeksOfMonth`.

The fixture is `component/apps/calendar-month/`, with the month child on a known id so the counts belong to that view alone. `driver.mjs` seeds the stores from inside the App Worker, because they live beside the component and `page.evaluate` cannot reach them.
