Resolves #19922

Guards `VdomLifecycle#mergeIntoParentUpdate` so a child only merges into an ancestor's pending VDOM update when `parent.windowId === me.windowId`, and evicts any already-merged child whose `windowId` diverged before `collectScopes` runs so it is neither marked collected nor claimed by the parent's flight and instead runs its own update flight.

Evidence: L4 (Playwright unit + Chromium browser e2e verified red on dev and green on branch) → L4 required (AC-1, AC-2, AC-3).
agent-preflight: not hosted here; baseline test-unit + e2eCiSelection + e2e ran.

## Deltas from ticket
Closed the `AC-3` late-`windowId`-change gap directly in `executeVdomUpdate` / `collectScopes` (`src/mixin/VdomLifecycle.mjs`) while preserving the synthetic `registerMerged` contract pinned by `a merged root in another window is excluded without borrowing its flight state` (`needsVdomUpdate === false` does not start a spurious flight).
