Resolves #22342

`simulate_event` and `nlApp.simulateEvent()` now deliver a touch event that names contacts. `EventSimulator#dispatchNative` turns the plain contact objects a worker sends into `Touch` instances of the dispatching window before it constructs the `TouchEvent`. The dispatch node names that window: its `Touch` constructor builds the contact and its document resolves a named target, and a `Touch` that any window built passes through as it is. Every given field passes through unchanged, and a contact targets the dispatch node unless it names another element id. The contract rows are in the [intake comment](https://github.com/neomjs/neo/issues/22342#issuecomment-7217111154); each is true of what ships.

Evidence: L3 (a Neural Link e2e builds real `Touch` objects in Chromium and reads the Helix in the App worker) → L3 required (AC-2). No residuals.

agent-preflight: not hosted here; `check-coding-guidelines`, `check-class-module-scope`, `check-jsdoc-types` and `check-whitespace` ran locally. Change class: `restoration`.

No consumer lines go away with this: the CDP test beside the new e2e arm stays as the browser-input arm, because synthetic input never scrolls natively and never takes pointer capture.

Review focus: (1) a contact whose `target` id resolves to nothing fails the dispatch instead of falling back to the dispatch node; (2) the unit realm has no `Touch`, so its arms run against stand-ins that state the platform's rule, and the e2e arm is the one that meets the real constructor.
