Resolves #22350

Theme Neo has its roles in a file. `resources/css/theme-neo/Global.css` declares the 85 palette names and the 109 roles of ADR 0044 for both Neo classes, light and dark in one file through `light-dark()`, and the theme build puts it in `@layer neo.roles`. The engine paints as before: on the tree merged with the rename, eight of the file's names are read outside it (the scheme, font smoothing and six motion roles), and each of those is declared elsewhere with the same value. A new guard, `check-theme-palette`, holds every palette to four rules: one lightness per grade across its slots, descending grades in each slot, 37 contrast floors per scheme, and the same palette and role names in every palette. It models no cascade and reads no condition, so it holds each name it measures, the palette entries and the colour roles, to one reading across every sheet under `resources/css`: one value per theme class, declared on the class itself, under no condition.

Evidence: L3 (unit specs, the guards and the matrix of refused forms at `c971d7e05a`, after the merge of `dev` with the rename; the headless Chromium control of those forms at `7d96d6e5b2`, whose palette sheet is the head's; a component spec, the computed-style equality run between two clean trees and a path-level control in three browser engines at `9260f0eb76`, since when the guard, its spec and a merge of `dev` changed; three builds and two frame pairs at `48d76fdf6b`, the token file is unchanged since) → L3 required (AC-4, AC-6). Residual: none.

CI jobs: +0 — the guard joins the existing `baseline / guards` list, the component spec the existing `components` shards.

## Deltas from ticket

- **Decision 2 of ADR 0044 is amended,** as ruled on the epic ([comment](https://github.com/neomjs/neo/issues/22295#issuecomment-7218629885)) after the Material draft showed what one shared table costs a second design language. The eleven lightness numbers are theme Neo's. The system binds the names, one lightness per grade across a palette's slots, the descent, and I8. So the guard compares a palette with itself and holds no table. The ADR's decision 2, its I8 line and its Status row say so, and `#22350`'s AC-2 is reworded. The recommendation (Mnemosyne) and the ruling (mine) come from one model family: this pull request's review is the amendment's first read from another.
- **I5's guard lands here, inside `check-theme-palette`.** The ADR gave the comparison of names between themes to a guard of step 2, and none existed; the Material pair (`#22359`) is the first second theme and found the gap. The comparison shares the palette guard's scan surface, reader and skip rule, so a second script would repeat the walk. The ADR's I5 line names the script and step 5.
- **The guard models no cascade, and refuses what it cannot resolve** (review round 1). It reads one declaration per name. A palette or colour-role name with two different values for one class fails, in whichever sheets under `resources/css` they sit, because specificity, layer and load order decide what paints and the guard knows none of them. The same value twice passes: both Neo classes declare `--neo-color-scheme` in two folders today.
- **The guard reads no condition, and it reads every palette entry** (review round 2). A declaration belongs to every theme class that its rule, or a rule around it, names, so a nested rule competes like a flat one. In a class that has a palette, a palette or colour-role name under an at-rule other than `@layer` fails as `[conditional]`, also with the value it has elsewhere: a name declared only there would be measured as if it always applied. A palette declared only under a condition is still a palette. No theme sheet declares a name that way today; reduced motion is collapsed once, in `src`. `rgb()` is read with commas throughout or with spaces and `/ alpha`: the parser and Chromium's `CSS.supports` agree on sixteen forms. Every `--neo-palette-` value is read as a colour, the eight extras included, because no measured pair reads `shade-3` or `shade-4`.
- **The guard reads every sheet, and holds what it measures to one reading** (the author's probe after round 2). Until `2b228edf3c` it read each mapped folder's `Global.css` and no other sheet, so the same override passed from a component file, from `src`, and under a selector that names no theme class. Now a palette or colour-role name has one value per theme class, declared on the class itself (`.neo-theme-x`, `:root .neo-theme-x`, or the root that holds it, bare or in one `:where()`), under no condition, and it resolves against such names only. Any other place under `resources/css` that declares or registers one fails as `[scope]`: a nested rule, a rule that reaches past its class, a registration. The guard reads a sheet as syntax alone: comments go, and a string or an unquoted `url()` is emptied, so nothing inside one hides a declaration or files it under another class; a string without its closing quote ends where its line ends, as a browser ends it (Mnemosyne's reads of `695c046e1d` and `ec3c4f1219`, as is the list of shapes). A sheet whose brackets do not balance fails as `[syntax]`: after `--probe: (} .a {);` Chromium drops the rest of the sheet, which ahead of the palette block leaves a page without one palette name (her read of `0dd8c8d658`). A measured name outside such a rule fails whether or not a palette is found: from `8689052ea7` to `0dd8c8d658` a palette block under a selector of another shape was found nowhere, and the guard reported no palette and passed (mine, found while reading my own commits). An escape that spells a name character is read written out. A colour role that no pair measures is read as a colour. A theme without a palette declares no colour role but the scheme, outside a condition; the acting design seat confirmed that constraint. Under a condition such a declaration still passes for a theme without a palette, which keeps the legacy exemption of round 2: the reviewer measured that at approval and accepted it as a limit of this change. No ticket was filed for it: the limit retires with the exemption when the last theme takes a palette, and it is recorded for the design seat [on the epic](https://github.com/neomjs/neo/issues/22295#issuecomment-7225947211), together with the one sentence of the guard's summary that is too wide until then. The stock tree already held all of it: its 135 measured declarations sit under eight headers of those shapes, and of the 194 names only `--neo-color-scheme` and `--neo-font-smoothing` are declared outside the palette sheet.
- **A scale role is not held to one reading** (Mnemosyne's counter-example, which I re-derived). Rounds 1 and 2 refused a second value and a condition for all 194 names. Decision 3 of the ADR keeps the reduced-motion collapse in `src`, and the rename's head (`#22358` at `d77d6cc908`) declares the seven motion roles in `src/Global.css` under an attribute selector, five of them again under `prefers-reduced-motion`. No verdict of this guard depends on a scale role, so `[cascade]`, `[conditional]` and `[scope]` key on the palette and colour-role names. Measured on that head's tree plus this palette sheet: a key on all 194 names fails those seven as `[scope]`, and the key of the head reports no failure.
