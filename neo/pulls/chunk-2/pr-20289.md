Resolves #20284

Routes `Neo.collection.Filter#decide` property lookups through `Neo.collection.Sorter.getValue(item, property)` so dotted filter paths resolve across `Collection`, `Store`, and `TreeStore` in both Record (`autoInitRecords: true`) and Turbo (`autoInitRecords: false`) Modes while preserving the one-read flat-property fast path. Also updates `Store#resolveField`, `Store#isFilteredItem`, and `TreeStore#filter` so raw items on models with complex fields resolve declared nested paths via `Neo.ns` without stamping flat dotted keys onto raw items, and soft-hydrate unhydrated tree nodes before evaluating filters.

Evidence: L1 (Playwright unit tests in Node.js) → L1 required (AC-1, AC-2, AC-3).

## Deltas from ticket
- `src/data/Store.mjs#resolveField`: when a model declares both a complex field (`hasComplexFields === true`) and a nested field (`user.score`), `resolveField` now falls back to `Neo.ns(fieldName, false, item)` when `item[fieldName]` is `undefined` on a dotted field and avoids stamping a flat `item['user.score']` property on raw items unless the nested field itself defines `calculate`, `convert`, `mapping`, or `defaultValue`.
- `src/data/Store.mjs#isFilteredItem` & `src/data/TreeStore.mjs#filter`: soft-hydration now keys off `!RecordFactory.isRecord(item) && me.model?.hasComplexFields` rather than `!me.autoInitRecords`, because `TreeStore#prepareAddedItems` intentionally ingests raw objects during `splice` before post-splice record hydration even when `autoInitRecords: true`.
- `agent-preflight`: not hosted here; baseline `npm run test-unit -- test/playwright/unit/collection test/playwright/unit/data` (346 passed) ran.
