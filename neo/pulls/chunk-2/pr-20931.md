>
> Moving a WebSocket into a browser SharedWorker collapses 3 open windows onto 1 TCP connection—yet fanning raw frames out over MessagePort or BroadcastChannel still leaves 3 windows paying 3x frame deserializations and holding 3 duplicate store copies on the same machine.
>
> Because Neo.mjs runs components and VDOM diffing off the main thread, apps/workstation keeps Neo.data.connection.WebSocket and the store inside one SharedWorker heap: two browser windows attach to one live socket (1 register handshake, 2 window_connected streams) and receive DOM deltas only for visible changes. Keeping that single socket alive across window lifecycles also surfaced two browser failure modes on dev that per-tab sockets hide—one caught in cross-family review on https://github.com/neomjs/neo/pull/18970.
