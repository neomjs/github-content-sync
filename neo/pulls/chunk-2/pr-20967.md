Resolves #20962

Both workflows of the contributor program asked for `issues: write` to comment on a pull request. GitHub refuses that there, so no merge comment and no heads-up note was ever posted; they now ask for `pull-requests: write`. That refusal was also the only thing keeping a contributor's comment off the team's own merges, so the merge comment now asks the repository's permission for an author who reads as outside, at a merge and on a dispatch, before any search.

Evidence: L3 (the branch's two workflows dispatched under the workflow's own token, nothing posted) → L4 required (AC-8: a real post and a real merge event). Residual: AC-8, Residual-Owner: #20953.
