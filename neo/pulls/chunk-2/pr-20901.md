Resolves #20900

On a narrow Portal viewport, two projections can arrive while the floating “More tabs” button’s first mount is waiting for theme files. Both can insert a node with the same ID. The overflow plugin now starts the first mount and any later remount through the same per-button guard. If the toolbar retires the button during insertion, cleanup runs after that insertion settles. A replacement can mount immediately.

Evidence: L2 (controlled mount timing and the real Chromium Portal journey) → L2 required. The [hosted report](https://github.com/neomjs/neo/actions/runs/43496333649/job/132134517793) showed the duplicate nodes. The unit controls reproduce the overlapping attempts in the plugin.

## AC Evidence

1. The first-mount regression invokes the component’s real theme deferral, requests another projection, and counts the pending callbacks. The base registered two. The repair registers one. Existing failure/retry and later-remount tests pass.
2. A delayed insertion test retires the old control before creating its replacement. When both settle, the old node is gone and only the replacement remains.
3. The three Portal phone/desktop scenarios ran three times in Chromium with their original strict selectors. All nine passed.

## Deltas from ticket

The fix is confined to `Neo.tab.plugin.Overflow` and its unit tests.

## Test Evidence

The Overflow unit suite passed 73 tests. Both new controls fail against an isolated copy of the previous `dev`. The delayed insertion control uses a tracked set of nodes and the browser check exercises the actual floating button.

### 🧠 Graph Ingestion Notes

*   **`[KB_GAP]`**: `isVnodeInitializing` does not span a theme-file deferral. The deferral branch of `initVnode` returns before the flag is set. A guard that reads the flag as "an attempt is in flight" misses that window; the attempt's own promise is the reliable handle.
*   **`[TOOLING_GAP]`**: One of three prior-art `query_raw_memories` calls returned `QUERY_PATH_DEGRADED` (chroma socket hang up). The other two returned no competing decision.
*   **`[RETROSPECTIVE]`**: An owner that starts an async attempt should hold the attempt, keyed by the thing attempted, not a Boolean on the owner. The `WeakSet` turns retire-during-attempt and replace-during-attempt into a destroy-after-settle rule.
