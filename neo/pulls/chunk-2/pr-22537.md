Resolves #22505

Related: #22368, #22445, #22506, #22438

Stretches `.neo-field-trigger` (`align: 'end'`, `align: 'start'`, and `NumberField` `50%`/`50%` spin buttons) and `.neo-input-wrapper` / direct `.neo-textfield-input` boxes to taller configured or flex-stretched field heights across `left`, `right`, `top`, `bottom`, and `inline` label positions, deletes the redundant `.neo-textarea .neo-field-trigger { height: inherit }` workaround, and disables unintended `vbox` `flex: 1` vertical stretching on `theme-equality` stage cells.

Evidence: L2 (headless Chromium component geometry + 5-theme computed-style equality across 81 components + Light/Dark before/after frame pairs) → L2 required (AC-1, AC-2, AC-3, AC-4).

## Deltas from ticket
- Omitted `min-height: var(--neo-textfield-input-height)` on `.neo-field-trigger` in `resources/css/src/form/field/trigger/Base.css` so themes with asymmetric active borders such as Material (#22438 / `#22505#issuecomment-7232456176`, `56px` outer → `55px` unfocused / `54px` focused interior) never force `.neo-input-wrapper` taller than its interior; added `&::before { line-height: 1 }` so `.neo-field-trigger` preserves `line-height: 26px` while keeping `FormContainer` `vbox` `flex: 1` fields at `72px`.
- Scoped `align-self: stretch` in `resources/css/src/form/field/Text.css` to `&:not(.neo-chipfield) > :is(.neo-input-wrapper, .neo-textfield-input)` so `ChipField` preserves its `31px` padded chip wrapper when `Chip.css` precedes `Text.css`, scoped `flex: 1 1 1px` to direct triggerless `&:is(.label-top, .label-bottom) > .neo-textfield-input`, and deleted the now-duplicate `.neo-has-character-count.label-inline > .neo-label-wrapper { height: 100% }` override.
