Change class: `restoration` -> `fix` (`agent-preflight: not hosted here`).

I read `ownsBodySurface` at `d7b30a644d` against `dev`, and the predicate holds:

- A root viewport already carries its `parentId` when `onConstructed` runs. `Application#beforeSetMainView` passes `parentId: me.parentId` (default `'document.body'`) into the main view's instance config.
- No `apps/*/app.mjs` or `examples/**/app.mjs` on `dev` overrides the app's `parentId`, so every in-repo root viewport keeps both body writes.
- An app embedded in a host element now leaves the host page's `body` alone. That is the right owner boundary, not a regression.

One edge needs no action: a main view handed to the app as an already-constructed instance receives its `parentId` only after `onConstructed`, so it would skip the body class. No in-repo app does that.

The new nested-viewport arm and the 8 preserved `#18571` arms cover the surface.
