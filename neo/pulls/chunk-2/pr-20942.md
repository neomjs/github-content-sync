### Problem
`Neo.app.content.Container` previously rendered `sidenav-container` (`<aside>`, `weight: 10`) and `splitter` (`weight: 20`) before `pageContainer` (`weight: 30`, default `<div>` tag), placing the sidebar navigation tree ahead of the primary article in DOM order without a `<main>` landmark.

### Solution
- Set `tag: 'main'` on `Neo.app.content.PageContainer` (`src/app/content/PageContainer.mjs`) so content routes render `<main class="neo-app-content-page-container ...">` wrapping `<article>` and `<nav>`.
- Update item weights in `Neo.app.content.Container` (`src/app/content/Container.mjs`) so `pageContainer` (`weight: 10`) and `page-sections-container` (`weight: 20`) mount before `splitter` (`weight: 30`) and `sidenav-container` (`weight: 40`).
- Preserve the visual left-to-right column order (`[sidenav-container | splitter | pageContainer | page-sections-container]`) using direct-child Flexbox `order` rules in `resources/scss/src/app/content/Container.scss`.
- Add `Neo.app.content.Splitter` (`src/app/content/Splitter.mjs`) and update `docs/output/class-hierarchy.json` so the content splitter targets `sidenav-container` while keeping the left-hand resize direction and `PageContainer` as its opposite neighbor.
