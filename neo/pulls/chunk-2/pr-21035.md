**What changed**

In Turbo Mode a re-add replaces the Structural Layer's entry while the visible projection keeps the object it already held. `Store#updateRows()` writes that visible raw row in place, so a later sorter or filter reprojection — which rebuilds the projection from the Structural Layer — restored the older value and the accepted batch was lost (`A readded` came back over `A batched`).

`TreeStore#writeRows()` now also writes each raw batch row's values onto the Structural Layer's current object for that key, through the same non-hydrating path `Store#writeRows()` writes the visible row (own-values restore, plain field writes, copied nested-field paths). Both layers then read one current value across structural and visible reprojection; a hydrated structural entry is the record the batch already published through, and the same-object case stays untouched.
