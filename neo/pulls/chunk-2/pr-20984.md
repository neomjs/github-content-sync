Resolves #20983

A remote Store's load params now reach an HTTP server in a form it can decode. `appendParams()` moved to `Neo.data.connection.Base` and JSON-encodes arrays and plain objects, so `sorters` and `filters` arrive as `[{"direction":"DESC","property":"score"}]` instead of `[object Object]`, and `null` and `undefined` are left out. `Xhr#read` and `Fetch#read` take `url` (this read's URL) and `headers` (request headers over `defaultHeaders`) as request config and compose every other param into the query. So a Fetch read now sends its page, page size, sorters and filters, and a `load({url})` override requests that URL on both connections.

Evidence: L2 (unit, over the real `Store#load` → `Pipeline#read` → `connection#read` path with stubbed transports) → L2 required (every AC is unit).

## Deltas from ticket
- **`headers` stay request config** on both reads (the ticket's Fix is revised to match): applied literally, the old bullet fails #20472's `PipelineFetchHeaders` component spec 0/2 and puts the bearer token in the URL (`/headers?headers=%7B%22authorization%22…`). `url` and `headers` are the two request-config params; every other param is query.
- **`PipelineCache.spec.mjs`'s route** ends in a wildcard: each Fetch read now carries its params (`?page=1`).
