Resolves #22351

🌿 *Theme Neo's light and dark Button were two files that could disagree; now there is one, it speaks only in roles, and a Button colour that no theme can reach has become unsayable.*

Theme Neo's Button variables are declared once, in `resources/css/theme-base/button/Base.css`, on `[class*="neo-theme-"]` in the `neo.base` layer, and both per-scheme copies are gone. Every value reads a role from `theme-neo/Global.css`, is a keyword, or is one of four listed optical offsets. Before the move, each variant re-values the generic variables on its own element, so `--neo-button-background-color` set inline now reaches every variant, and the classic and Cyberpunk values that read a generic variable hold what they resolved to ([the design seat's ruling](https://github.com/neomjs/neo/issues/22351#issuecomment-7221651866)). The classic pair and Cyberpunk keep their own Button files, which outrank theme-base by layer.

Evidence: L2 (computed-style equality across five themes and both scopes with every difference declared, the full component and unit tiers, the eight theme guards, the palette-bridge e2e, frame pairs) -> L2 required (#22351 AC-1 to AC-8).

## The template for the remaining moves (AC-8)
A package's move is one pull request with five parts:
1. **The variant rewrite first**, if the package has variants: each variant re-values the generic variables on its own element, and a theme value that reads a generic variable is resolved in the same PR (the equality run's scoped pass lists every one).
2. **`theme-base/<pkg>/<Cmp>.css`** written from a binding, both Neo copies deleted, the package's radius variables bound to the radius scale.
3. **The binding table**: variable, role, the token it replaces, the value before and after (below).
4. **Declared differences**: `npm run theme-equality -- --expected <file>` passes, each difference named by the change it comes from; an `rgb()` that now computes as the same colour in `oklch()` is declared notation-only.
5. **Frame pairs**: the package's example and one dense page, base against head, both schemes, plus a sheet of every variant and state.

Component specs link theme sheets through `themeSheetHrefs()` (what the loader fetches, read from the built theme map) and compare role colours through `toRgb()`, so a move edits no spec paths.

## Binding (AC-2)
156 variables: 62 bind to a role with the same value, 40 move a value, 38 are keywords, 8 are apart, 8 had no reader and are dropped. No value is a raw colour.
- **Apart**, the record's first revalidation trigger. The four optical offsets stay literals (`badge-margin-left` and `badge-margin-top` `-10px`, `glyph-margin` `1px 6px 0 0`, `tertiary-text-underline-offset` `3px`; design read point 3). The four ripples are a press layer with no role: the three neutral ones bind to `background-neutral-active` and the primary to its own white mix at 30 % (ADR 0044's one exception), the candidates design read point 2 names; the ripple sheet below shows them against today's `#8ba6ff` · `#435db1`.
- **Dropped**: `gradient-start-color`, `gradient-end-color`, `use-gradients` and the five `ghost-*-disabled`. Nothing reads them.
