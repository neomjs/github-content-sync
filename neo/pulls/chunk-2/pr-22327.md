Resolves #22326

Related: #22295

Reserves the `neo-theme-` CSS class prefix exclusively for declared theme classes (`collectThemeClassMap`) and `neo-theme-scope` per [`0044-design-system.md`](learn/agentos/decisions/0044-design-system.md) (§2.7, §2.10 I4 & I7). Renames `Neo.button.ThemeSwitcher` CSS classes (`neo-theme-switcher*` → `neo-themeswitcher*` across `src/button/ThemeSwitcher.mjs`, 14 structural stylesheets, `captureExamples`, and 13 Playwright specs), drops `super.afterSetUi` delegation so `ntype: "theme-switcher"` no longer stamps `neo-theme-switcher-ghost` at runtime, and wires `buildScripts/util/check-theme-class-prefix.mjs` into `lint-staged` and `pr-baseline.yml`.

Evidence: L3 (local Chromium component suite + 5-theme build + unit & CI-parity guards) → L3 required (AC-1, AC-2, AC-3).

`agent-preflight`: not hosted here; baseline `guards` and `PR baseline` ran locally.

## Deltas from ticket
- **Runtime `afterSetUi` discovery (`neo-theme-switcher-ghost`):** Adding a live Chromium assertion (`not.toHaveClass(/\bneo-theme-/)`) to `ThemeSwitcher.spec.mjs` revealed that `Neo.component.Base#afterSetUi` dynamically emits ``neo-${me.ntype}-${value}`` (`neo-theme-switcher-ghost` for `ntype: "theme-switcher"`, `ui: "ghost"`), which static string grep missed. Updated `ThemeSwitcher#afterSetUi` to apply `neo-button-${ui}` without calling `super.afterSetUi`, and extended `check-theme-class-prefix.mjs` (plus a unit test) to fail closed on any `ntype` starting with `theme` whose class does not override `afterSetUi` without `super.afterSetUi`.

## Test Evidence
- Non-CI local theme build receipt: `npm run build-themes -- -n -e dev -t all` compiled all `1,033` `dist/development/css` sheets cleanly (`0.49s`) with zero visual change; `git grep -n "neo-theme-switcher"` matches only the negative assertions in `test/playwright/unit/buildScripts/util/check-theme-class-prefix.spec.mjs`.
