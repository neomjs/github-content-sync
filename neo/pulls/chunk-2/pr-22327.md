Resolves #22326

Related: #22295

Reserves the `neo-theme-` CSS class prefix exclusively for declared theme classes (`collectThemeClassMap`) and `neo-theme-scope` per [`0044-design-system.md`](learn/agentos/decisions/0044-design-system.md) (§2.7, §2.10 I4 & I7). Renames `Neo.button.ThemeSwitcher` `ntype` (`theme-switcher` → `themeswitcher`) and CSS classes (`neo-theme-switcher*` → `neo-themeswitcher*` across `src/button/ThemeSwitcher.mjs`, 14 structural stylesheets, `captureExamples`, and 13 Playwright specs), and wires `buildScripts/util/check-theme-class-prefix.mjs` into `lint-staged` and `pr-baseline.yml`.

Merge order with #22308 (#22300): whichever of #22308 and #22327 merges second carries the `.neo-theme-switcher` → `.neo-themeswitcher` update in `buildScripts/util/themeEqualityMatrix.mjs` before it merges.

Evidence: L3 (local Chromium component suite + 5-theme build + unit & CI-parity guards) → L3 required (AC-1, AC-2, AC-3).

## Deltas from ticket
- **`ThemeSwitcher` `ntype` rename (`theme-switcher` → `themeswitcher`):** Live DOM verification (`not.toHaveClass(/\bneo-theme-/)`) surfaced that `Neo.component.Base#afterSetUi` derives ``neo-${me.ntype}-${value}`` at runtime (`neo-theme-switcher-ghost`). Per `@neo-opus-vega`'s Round-1 review (`PRR_kwDODSospM8AAAABarpYpg`), renamed `ntype` to `'themeswitcher'` (matching `baseCls` and sibling compound nouns `textfield`, `switchfield`, `selectfield`, `dateselector`), restored `super.afterSetUi` (`neo-themeswitcher-ghost`), updated the two Neural Link `{ntype: 'themeswitcher'}` queries in `StandaloneThemeSwitcher.spec.mjs` and `ExamplesCatalogTheme.spec.mjs`, and removed the file-level `afterSetUi` exemption from `check-theme-class-prefix.mjs` so `'theme'` / `'theme-*'` `ntype` values fail directly while `{ntype: 'themeswitcher'}` passes for both class definitions and consumers.
