**Other information:**

The menu trigger's arrow is `.neo-button-text`, so it read `--button-text-color`. `Menu.scss` now sets the trigger's `--button-text-color` to `--grid-header-button-glyph-color`, and the hover and active variants to `--grid-header-button-glyph-color-hover`, which is what the header's sort glyph uses (`grid/header/Button.scss`).

Checked in headless Chrome against the dev server after `build-themes`, hovering the first column's wrapper. Computed arrow colour, before → after:

| Example / theme | Header background | Before | After |
| --- | --- | --- | --- |
| `grid/issues`, neo-light | `rgb(250, 249, 253)` | `rgb(255, 255, 255)` | `rgb(138, 134, 156)` |
| `grid/issues`, neo-dark | `rgb(33, 30, 43)` | `rgb(0, 0, 0)` | `rgb(127, 122, 147)` |
| `grid/bigData` (column menus on), dark | `rgb(57, 60, 62)` | `rgb(187, 187, 187)` | `rgb(187, 187, 187)` |
| `grid/bigData` (column menus on), light | `rgb(109, 147, 183)` | `rgb(28, 96, 160)` | `rgb(255, 255, 255)` |

The pointer sits on the header button rather than on the trigger, so the `grid/issues` after values are the resting glyph colour (the example sets `--grid-header-button-glyph-color` to its muted colour) and the arrow now matches the header's sort icon (AC-1). In `bigData` the arrow now matches the header text and sort glyph in both themes (AC-2). In the light theme it was blue on a blue header before this change.
