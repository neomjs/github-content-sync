The Engine declares `postcss-selector-parser` only as a devDependency (`package.json:139`, `^7.1.7`); `buildScripts/create/theme.mjs:7` is its only `buildScripts` import; and the `neo-app` starter installs every package `themes.mjs` imports but not this one (create-app `tasks/createPackageJson.mjs:4-9`). So a generated workspace builds its themes and fails the generator, exactly as #22376 says. The generator's other imports are Node built-ins, `postcss` (a first-run package) and three local helpers that import only Node, so the parser is the one package missing. Both recipes carry the same line, and the Engine-checkout recipe is untouched. The pin is the floor of the Engine's `^7.1.7` while its lockfile runs 7.2.1; both are in range and your workspace run used 7.1.7, so it stands. What would keep it in step is the starter, not these docs: no generated script runs `create/theme.mjs`, so its parity check never reaches the parser.
