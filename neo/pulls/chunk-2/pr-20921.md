Resolves #20912

`GridDragScroll.onDragStart` now resolves the innermost registered view in the event path instead of the first registration in the map, handles a press only in the capture listener of that view (so one press arms one monitor and one timer), and starts a drag only when the pressed `.neo-grid-row`'s nearest `.neo-grid-view` is that registered view. A press in a nested grid scrolls the nested grid, a quick click there no longer throws from an orphaned timer, and a press on content a view hosts outside its rows (an input, an unregistered nested grid) keeps its native behaviour.

Evidence: L2 (unit spec with `EventTarget` stand-ins, plus a component spec that drives real pointer input in Chromium) → L2 required (the ticket's ACs name a component or e2e spec). Residual: none.

## Deltas from ticket
- The `grid-focus` fixture has no grid inside a grid, so the component spec builds the smallest real one per arm: a scrollable `neo-grid-view` with a tall `neo-grid-row`, in a cell of a visible plain row, registered with the addon after the outer grid. It keeps the inner row and its host row out of the fixture's `.neo-grid-row:nth-child(-n+3)` native drag sources.
- An extra unit arm covers a nested grid that is not registered (drag scrolling off): its rows do not scroll the outer grid.

Thanks, that was it: the row check fired. The Workstation's `grid-drag-scroll` cue presses the grid body element itself, not a row, so the new "nearest view around the pressed row" check returned early. A press now counts when it lands on the owning grid's rows or on one of its `.neo-grid-body` elements, and the nearest `.neo-grid-view` around that must still be the registered one, so inputs a view hosts outside its bodies and unregistered nested grids still start nothing.
