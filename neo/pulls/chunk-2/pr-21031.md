Resolves #21028

`Neo.grid.column.AnimatedChange` now follows its grid's store through a reactive `store_` config. `construct()` takes the parent grid's store through it, and `afterSetStore()` moves the `recordChange` listener from the old store to the new one; either may be `null`. `Neo.grid.Container#afterSetStore` hands the new store to the columns that declare a `store` config, beside the bodies, scrollbar, view and toolbars it already updates, so a plain column gains no property. A grid created without a store can now hold this column, and the column hears whichever store the grid holds. `onRecordChange()` now also asks the body that renders the column for the row (`bodyStart` or `bodyEnd` for a locked column), so a locked column animates too. `AnimatedCurrency` inherits all of it.

## Deltas from ticket
- Two arms beyond the ticket's list, both from its Contract Ledger: a store set to `null` ("`null` included"), and a plain column that gains no `store` ("a column without a `store` config is untouched").
- The locked-body defect (ticket point 3, AC-4) turned up when this column served a Gantt's locked task column. It is folded in as a second commit, and the ticket now carries it.
- `grid.destroy()` now releases the column's listener at once: `Container#destroy` sets `store = null` first, and that now reaches the columns. Before, `Observable#fire` dropped the entry at the next event.
- One listener object serves `un()` and `on()`, because `Observable` parses a copy since #14932. The comments in `Container#afterSetStore`, `VerticalScrollbar#afterSetStore` and `SearchToolbar#bindStore` that say a call consumes the object are stale: out of scope, noted in defect-note `MESSAGE:a05c54f5`.
