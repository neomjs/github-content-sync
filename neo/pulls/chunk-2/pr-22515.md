Resolves #22513

🌿 The tree list painted in the classic theme's grey and blue, and on dark in tokens the design system retires. Now its four variables read roles, and a theme built on Neo can no longer leave a tree uncoloured.

`resources/css/theme-base/tree/List.css` declares the four variables once. The list text reads `text-default`, and both indents read `space-4` (16px, unchanged). The menu item colour paints the collapse-all and expand-all glyphs, so by rule 17 (chrome is neutral) it reads `text-muted` where both schemes painted a blue. Both `theme-neo-{light,dark}/tree/List.css` are deleted. Cyberpunk declared none of the four, so a new `theme-cyberpunk/tree/List.css` declares them `initial`, and every reader keeps the fallback it had.

Evidence: L2 (the equality run across 5 themes with every moved value declared; frame pairs of `examples/tree` from built trees) → L2 required (#22513's ACs are equality and frame pairs). Residual: none.
