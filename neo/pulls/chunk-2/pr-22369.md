Resolves #22363

`merge-comment.yml` accepts `workflow_call`, so Brain and the Institution can post the same merge comment on their own merges. Its two modules now come from `neomjs/neo` at `job.workflow_sha` through the contents API, as in `claim-responder.yml`. The sparse checkout this replaces would have taken the caller's tree in a called run, where neither module exists. A failed fetch still warns and ends green, as the failed checkout did. In a called run `context.repo` names the caller, so the comment, the pull-request reads and the next issues are the caller's, while the org-wide count and the `pages` reads still name their own repository. Leaves B and C, the callers, follow in their repositories and pin this merge commit.

Evidence: L2 (spec arms red on base → green; the fetch commands run for real at `dev`'s SHA) → L2 required (AC-1 to AC-4). Residual: AC-5, Residual-Owner: #20892.
