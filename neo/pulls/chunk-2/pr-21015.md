### Summary

Resolves #20829

`Neo.button.Base` previously had a reactive `pressed_` config defaulting to `false`, and `afterSetPressed` toggled only the `pressed` CSS class. Consequently:
1. Assistive technology (screen readers) had no accessible toggle semantics because `aria-pressed` was never exposed by `button.Base`.
2. Plain buttons and unpressed toggles were indistinguishable at construction (`pressed === false` for every button), preventing `afterSetPressed` from safely projecting `aria-pressed="false"` without misidentifying plain action buttons as toggle buttons.
3. Components requiring toggle semantics (such as `src/grid/SearchToolbar.mjs`) had to manually manage `aria-pressed` directly on the VDOM alongside `set({pressed})`.

This PR changes `pressed_` to default to `null` (plain button). When `pressed` is explicitly configured or updated to a Boolean (`true` or `false`), `afterSetPressed` synchronizes `aria-pressed` onto the VDOM root in the same update cycle that toggles the `pressed` class. When `pressed` is `null`, `aria-pressed` is omitted. `src/grid/SearchToolbar.mjs` is simplified to configure its case-sensitivity toggle via `pressed: false` and drops manual VDOM attribute manipulation.

### Technical Approach & Implementation

1. **Reactive Configuration Default (`src/button/Base.mjs`, `src/button/Effect.mjs`)**:
   - Updated `pressed_` config definition to default to `null` (`@member {Boolean|null} pressed_=null`).
   - A button constructed without `pressed` remains a standard push button with neither the `pressed` class nor the `aria-pressed` attribute.
   - Initializing or setting `pressed: true` or `pressed: false` marks the button as a toggle button conforming to the WAI-ARIA Authoring Practices Guide (APG) button pattern.

2. **Attribute Synchronization in `afterSetPressed` (`src/button/Base.mjs`)**:
   - In `afterSetPressed(value, oldValue)`:
     * Evaluates `Neo.isBoolean(value)`. If true, sets `vdomRoot['aria-pressed'] = String(value)`.
     * If `null` or non-boolean, deletes `vdomRoot['aria-pressed']`.
     * Toggles the `'pressed'` CSS class via `NeoArray.toggle(cls, 'pressed', value === true)`.
     * Calls `me.cls = cls` and `me.update()` to guarantee that both the class and attribute deltas are dispatched synchronously in the same render transaction.

3. **VDOM Config Generation in `src/button/Effect.mjs`**:
   - In `getVdomCls()`, updated check to `NeoArray.toggle(vdomCls, 'pressed', this.pressed === true)`.
   - In `getVdomConfig()`, added `'aria-pressed': Neo.isBoolean(me.pressed) ? String(me.pressed) : null`. When `null`, the VDOM serializer omits the attribute completely.

4. **Engine Consumer Cleanup (`src/grid/SearchToolbar.mjs`)**:
   - Updated the `case` reference button configuration at line 67 to specify `pressed: false` and removed `'aria-pressed': 'false'` from its initial `vdom` declaration.
   - In `syncFromStore()`, dropped `caseButton.vdom['aria-pressed'] = String(filter?.caseSensitive === true);`, letting `caseButton.set({pressed: filter?.caseSensitive === true, disabled: !me.store})` manage both presentation and accessibility semantics automatically.

5. **Unit Verification (`test/playwright/unit/button/Base.spec.mjs`, `test/playwright/unit/grid/SearchToolbar.spec.mjs`)**:
   - Expanded `should handle pressed state change` in `Base.spec.mjs` to verify:
     * Plain button initial state has no `aria-pressed`.
     * `set({pressed: true})` emits a single delta containing both `cls.add: ['pressed']` and `attributes: {'aria-pressed': 'true'}`.
     * `set({pressed: false})` emits a single delta containing `cls.remove: ['pressed']` and `attributes: {'aria-pressed': 'false'}`.
     * `set({pressed: null})` deletes `aria-pressed` from the VDOM.
   - Added a dedicated test `should render aria-pressed semantics only for toggle buttons` verifying plain, unpressed toggle (`pressed: false`), and pressed toggle (`pressed: true`) initializations.
   - Updated `SearchToolbar.spec.mjs` to verify `case` button preserves `aria-pressed` synchronization without manual VDOM intervention.

### File-by-File Changes

- `src/button/Base.mjs`:
  * Default `pressed_` config to `null`.
  * Update `afterSetPressed` to project `aria-pressed` as a string Boolean onto `vdomRoot`, remove on `null`, and trigger `me.update()`.
- `src/button/Effect.mjs`:
  * Default `pressed_` config to `null`.
  * Update `getVdomCls` to evaluate `this.pressed === true`.
  * Add `'aria-pressed'` attribute in `getVdomConfig()` when `me.pressed` is Boolean.
- `src/grid/SearchToolbar.mjs`:
  * Add `pressed: false` to the `case` button config and remove manual `vdom['aria-pressed']`.
  * In `syncFromStore()`, remove manual `caseButton.vdom['aria-pressed']` assignment.
- `test/playwright/unit/button/Base.spec.mjs`:
  * Verify `aria-pressed` in `should handle pressed state change`.
  * Add test `should render aria-pressed semantics only for toggle buttons`.
- `test/playwright/unit/grid/SearchToolbar.spec.mjs`:
  * Verify `aria-pressed` state transitions on SearchToolbar `case` button.
