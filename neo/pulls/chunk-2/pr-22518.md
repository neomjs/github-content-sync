Resolves #22423

Related: #22414, #22405

A scrolling list can refresh from an eligible downward pan or from the same command on a visible Refresh button. Main maintains the scroll-top policy before a touch begins. App tracks the pull and holds one refresh until the listener’s work settles. The Field notes phone example uses a Buffered list and replaces its records from a request.

Evidence: L3 (trusted Chromium touch on a real list, held request, keyboard and production example) → L3 required. Residual: AC-4 physical phone browser chrome, Residual-Owner: #22414. Touch pull requires `CSS.supports('touch-action', 'pan-x pan-down pinch-zoom')` in the owning window. The exact probe returned true in headless Chromium 159.0.8154.6 and false in Playwright WebKit 27.2 and Firefox 159.0. The visible Refresh control shares `refresh()` and remains available in browsers that keep native scrolling.

## Deltas from ticket

`pan:start` can opt into `atScrollStart`. The Main registration owns the native boundary marker; the list plugin owns the preview and in-flight state. The refresh event carries `waitUntil(promise)`, so the owner can provide asynchronous work without a new event API. An example view observes that state to paint the indicator and supplies the keyboard and pointer control.

### 🔬 Depth Floor

**Challenge OR documented search (per guide §7.1):**

- **Challenge**: `observeDetachment()`'s document-wide `subtree` MutationObserver used to run only while a claim was active. Now `syncObserver()` keeps it for as long as any `atScrollStart` registration lives. On a phone page that also streams DOM deltas, such as a grid or a live feed, every batch then allocates records for a callback that scans the scroll hosts and calls `pruneClaims()`.
  - **Worth measuring, or narrowing:** the host's replacement could be watched on its parent alone.
  - **Not a requirement.**
- **Coordination:** this PR and #22499 conflict in `Gesture.mjs`'s field block and in `class-hierarchy.json`. The overlap is positional only: #22518 doesn't touch the transform code that #22499 moves into `src/main/gesture/Transform.mjs`, so whichever lands second merges mechanically.

**Findings:** The body describes a phone pull, but only Chromium can arm one. `syncPanScrollRegistration` tracks a host only where `CSS.supports('touch-action', 'pan-x pan-down pinch-zoom')` holds. In Playwright's engines that probe returns:

- **Firefox 159:** `false`.

On those two engines the pull never arms, and only the Refresh button works. That fallback is safe, and decision 7 leaves no policy that lets script own only the downward pull there. The reach is still a fact the body and the plugin must state (RA-1).
