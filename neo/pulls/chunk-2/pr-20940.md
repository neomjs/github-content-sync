Resolves #20928

Routes raw-row key extraction (`Store#getKey`), direct key lookups (`Store#get`, `TreeStore#get`, `TreeStore#getChildren`), and `TreeStore#splice` child `parentId` resolution through `Store#getCanonicalKey`, so raw items and hydrated records share one canonical key across `Collection#map`, `allItems.map`, `TreeStore#allRecordsMap`, and `TreeStore#childrenMap` in both Turbo Mode (`autoInitRecords: false`) and eager mode.

Evidence: L2 (Playwright unit suite + Node `v25.9.0` 100,000-row Turbo Mode ingestion benchmark) → L2 required (AC-1..AC-4).

## Deltas from ticket
- **`TreeStore#splice` child `parentId` canonicalization on `#allRecordsMap` miss:** When raw `{id: 1, parentId: null}` registers under canonical `'1'`, a child `{id: 2, parentId: 1}` misses `#allRecordsMap.has(1)` and would be auto-healed to `'root'` unless `parentId` falls back to `getCanonicalKey(parentId) ?? parentId` on a miss (`TreeStore.mjs:1120`). Guarding on `!#allRecordsMap.has(parentId)` keeps already-canonical trees at $O(1)$ without parser calls and leaves `:891` untouched so #20913 remains isolated.
- **`modelOf(item)` support, auto-stamped key healing, and `Store.mjs` baseline graduation:** `Store#getCanonicalKey(value, model=this.model)` accepts the row's `modelOf(item)` and reuses a frozen empty record (`emptyRecord`); `Store#hydrateRecord` retains a `rawPropertyKey` fallback for `Collection#splice`-stamped negative keys on keyless Turbo Mode rows while unifying `me` / `allItems` map healing (`src/data/Store.mjs` drops from `1,002` to `989` code lines and graduates from `buildScripts/util/file-size-baseline.json`).
- **`RecordFactory#parseRecordValue` scalar fast paths:** Skips `parseInt` when `Number.isSafeInteger(value)` already holds and skips regex HTML stripping when `!value.includes('<')`, keeping conversion rules owned by `RecordFactory` while trimming per-row parser overhead.
