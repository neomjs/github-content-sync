Resolves #4066

Clears `appName`, `parentId`, and `parentIndex` alongside `mounted = false` in `Neo.container.Base#removeAt` when `destroyItem` is `false` and `keepMounted` is `false`, before `layout.removeChildAttributes(item)` runs so layout style cleanup does not merge into the former parent's VDOM batch. Updates `Neo.dashboard.dock.interaction.Rail#releaseRevealPane` so parked reveal panes (whose `parentId` is now cleared on removal) still await `revealOverlay.paneSlot.promiseUpdate()`.

Evidence: L1 (Playwright unit tests in CI) → L1 required (container removeAt context reset and re-addition).

## AC Evidence
| AC | Evidence |
|---|---|
| `removeAt(index, false)` clears `appName`, `parentId`, and `parentIndex`, and re-adding the component restores them | `test/playwright/unit/container/RemoveAtClearContext.spec.mjs` (`2/2` passed) + `test/playwright/unit/vdom/RealWorldUpdates.spec.mjs` (`8/8` passed) |

## Deltas from ticket
- Preserves `keepMounted = true` during `insert()` atomic moves so `createItem()` still reads `item.parent` before applying the target container's `{appName, parentId, parentIndex, windowId}` batch.
- Runs the `!keepMounted` reset before `me.layout?.removeChildAttributes(item)` so layout style cleanup on the detached item does not merge into the former parent's VDOM update batch.
- Updates `src/dashboard/dock/interaction/Rail.mjs#releaseRevealPane` to fall back to `me.revealOverlay?.paneSlot?.promiseUpdate?.()` when releasing a parked reveal pane whose `parentId` was cleared on `slot.remove(child, false)`.
