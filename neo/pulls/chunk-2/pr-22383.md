Resolves #22382

🌿 *A prepared child's vnode can no longer pass for a DOM that Main never wrote.*

I5's strong rule stays: a component is mounted only once Main has written its vnode. Its container sentence named the wrong evidence, the vnode's existence. Euclid's Chromium control on #22381's exact head showed two supported paths in which a child prepared by `initVnode(false)` with `autoMount: false` has a vnode, is absent from its container's landed tree, and is mounted with no DOM. The sentence now names the landed tree, and says why neither a vnode nor `vnodeInitialized` proves it. The Status row records the correction.

**Where code and I5 differ until #22384:** #22381's guard, `Boolean(items[i].vnode)`, is narrower than the corrected I5. It lands as the measured Workstation repair (#22184). Euclid's two prepared-child paths, a floating leaf added silently while the first render is held and a leaf added from a `vnodeInitialized` listener, still mount with no DOM. #22384 records them and gates its code on a real `dev` flow.
