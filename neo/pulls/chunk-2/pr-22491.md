Resolves #22448

`npm run theme-release-compare` loads every theme-Neo surface twice:
- **Released:** neomjs.com, with a desktop Chrome user agent.
- **`dev`:** a built `dev` tree served on loopback.

It does so in every scheme the surface lists, each side in its own browser context. Each side reports the theme its main view painted. A page that ignores `?theme=` is switched through its own theme switcher.

Two sides in the requested scheme are compared element by element. Elements pair by group and label, and each differing property names the variable measured to own the `dev` value. A run that cannot be compared says why: `new`, `dev-failed`, `failed` or `scheme-unverified`.

The runner saves both frames, `report.json` and `report.md`. The report's contract is the Contract Ledger on #22448. The runner sits beside its sibling `theme-equality.mjs` in `buildScripts/util/`.

Evidence: L3 (a live run against neomjs.com and a built `dev` export, the positive control reproduced, and the review's controls rerun on the repaired runner) → L3 required (AC-1, AC-2).
