Resolves #22297

The theme build now puts every sheet into the cascade layer its folder names, and every built sheet starts with the order statement: `neo.vendor, neo.roles, neo.base, neo.theme, neo.rules, neo.apps`. Load order and `:where()` weight stop deciding between an engine sheet and an app's. The rest of the change prices what layers change, measured on rendered pages rather than listed:

- **Vendor sheets go into `neo.vendor`.** An unlayered sheet beats every layer, so Font Awesome's `.fas {width: 1.25em}` started overriding the Portal footer's glyph width. `DomAccess.loadStylesheet` still loads the sheet by `<link>`, then moves a same-origin sheet's rules into an adopted stylesheet inside `@layer neo.vendor`, since the engine's strict `style-src` refuses an inline `<style>`. Font Awesome and Highlight.js load through it, as Monaco, Mapbox, OpenLayers and Cesium already did. A swapped `href` (the Docs source view's theme toggle) refills the link's one adopted sheet. A cross-origin sheet stays unlayered.
- **Three engine `!important` invariants gained a variable.** An earlier layer's `!important` beats a later one's, so app rules that used to outrank one stopped applying. The variables:
  - The maximized dialog geometry reads `--dialog-maximized-*`.
  - The drag and grid-scroll pointer shields read `--drop-target-pointer-events` (registered, non-inheriting).
  - The tree list's folder icons read `--tree-list-folder-icon`.
  AppWindow, the email compose dialog, the webdesktop permission panel, the Meridian scheduler and the Trees example set those instead.
- **App rules that lost to an engine rule by weight or load order now win.** Workstation, the dashboard demos and the sitemap show it: their bars, rows and pane chrome now paint as their own sheets say (frames below). Rules that never applied and would break a layout or a test go instead.

Merged behind #22300 (`blocked_by`), now merged: AC-5 (b) is that run on this branch, green with every difference declared.

Decision Record impact: amends `adr:0044-design-system` (decision 6, I3, §4 step 2, §5), in this pull request.

## Deltas from ticket
- **Two layer names this leaf chose:** `neo.vendor` (first) and `neo.apps` (last). App and example sheets take `neo.apps` in a theme folder too, as [ruled](https://github.com/neomjs/neo/issues/22297#issuecomment-7208694167).
- **Vendor layer by loader, not in the vendor file.** Font Awesome and the editor and map sheets are third-party, so they cannot carry their own layer. One loader covers our Highlight.js files too: a layer has one writer, as the design seat [agreed](https://github.com/neomjs/neo/pull/22325#issuecomment-7213157394), and ADR 0044's vendor sentences take its wording.
- **Three hooks for engine `!important` invariants** (`--dialog-maximized-*`, `--drop-target-pointer-events`, `--tree-list-folder-icon`), plus the Legit tree hiding its icons by `display`, which no engine `!important` contests.
- **`src/Global.css` loses `i, em {font-style: italic}`:** it restated the UA default and, once layered, beat Font Awesome's `.fa {font-style: normal}`.
- Theme Neo's dialog header-button rule moved into `src`, where its layer keeps it above the button rules.
- **App rules that never applied, now restored to their shipped paint.**
  - CI found two. The Task Worker example's `input {min-height: 36px}` had never applied; its frames and e2e were reviewed at 25px, so the rule goes. The Portal release page's phone sidebar offset now applies only while the sidebar is closed, so the engine's expanded state opens it again.
  - The page comparison found three more. The big data grids' `display: block` on their controls panel collapsed its fit layout. The toast page's 2023 inline `padding: 50px 40px` sits in an unlayered `<style>`, which now beats every layer. All three go.
  - The desk example's pane `overflow: auto` now skips its grid pane, whose container clips.
- **Specs that read built CSS:** two now look inside the layer block. The palette bridge arm compares `justify-content` with the browser's own serialization of `flex-end`: Chromium 159 reports `flow-end`, which failed on `dev` too.
