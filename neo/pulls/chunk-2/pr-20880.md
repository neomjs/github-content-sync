Resolves #20778

An installed package can now ship a Canvas worker renderer. The package names the directories its renderers live in under `neo.canvasModules` in its `package.json`, and an application loads one with `Neo.worker.Canvas#loadModule({path: 'node_modules/<package>/<path>'})`. The same path works in raw development and in development and production builds, in the installed and the pnpm-linked layout. A build admits exactly the declared directories of the workspace's dependencies; every other installed package stays out of the worker.

How: `loadModule` imports a `node_modules/` path through the directory that holds the engine package, which is the workspace's `node_modules` once the engine is installed. Its authored exclude scans nothing, so the Engine's own build is unchanged. In a consumer build, the new `canvasModuleContextPlugin` points that root at the workspace's `node_modules` and admits the declared roots, so the context keys are `./<package>/…`. This follows the Main addon precedent: the manifest reader is now generic per key (`buildScripts/util/declaredPackageRoots.mjs`, renamed from `mainAddonPackages.mjs`), and the Main plugin's private admission became the shared `admitDeclaredRoots`. Each key admits into its own role's context only.

Evidence: L3 (consumer webpack builds in both modes and layouts in CI's consumer guard, plus a real-browser dev-mode witness outside CI) → L3 required (AC-2, AC-3). Residual: none.

## Deltas from ticket

- **Key name: `neo.canvasModules`,** scoped to `loadModule`'s `canvas/` reach. A generic worker key would invite admission into every worker context; a future worker that loads by path gets its own key through the same reader.
- **A dedicated import root, not a widened app-space context.** Widening the workspace-rooted context was measured on this branch first: `FAILED (4)`, because webpack rewrites `./node_modules/…` context elements into module requests that no longer match the context's `./` pattern.
- **Docs:** a "Shipping a renderer in a package" section in `learn/guides/advanced/CanvasArchitecture.md`, beside the Main addon section it mirrors, rather than the styling guide.
- **The ten other exclude sites keep their rule.** Each is an app-space root whose worker has no package consumer, and a key per role is added only with one.
  - `src/worker/Canvas.mjs:156`: the app's own `canvas.mjs` starting point.
  - `src/worker/App.mjs:429`: belongs to #20717.
  - `src/worker/Task.mjs:60`: task modules.
  - `src/worker/Data.mjs:103`, `:111`, `:119`, `:127`, `:196`, `:204`, `:212`: connections, parsers, normalizers and pipeline modules.
