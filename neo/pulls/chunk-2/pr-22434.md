Resolves #22427

🌿 A product's look used to live where no check could read it. Now it lives in the one file the check measures as a palette.

`check-theme-palette` reads `theme-<name>/apps/<app>/Global.css` as a product palette: for each theme class the file declares on, the theme's palette with the product's values on top, held to the names, lightness and contrast rules a theme's palette meets, and named in the passing line beside its theme. The file must sit in the folder whose own `Global.css` declares that class's palette, adds no name, keeps the scheme, and every other second declaration fails as before. Run from a workspace, the command reads the build's theme roots in override order (`themeCssRoots`), so a workspace's product palette is measured on the Engine's theme. ADR 0044 records where a product palette lives and how it travels (decision 8, I5, I8, §5).
