Resolves #20952

A component that departs (destroy, unmount) hands focus back only to a lost focus. A focus the user moved on before the worker's hand-back arrives stays where it is.

When a component departs, it now hands focus back through the target's own `focus()` with `restoreFrom`. The main thread waits for the departure to settle, and then focuses only a lost focus. Deciding and focusing happen in one main-side step, so a focus that arrives meanwhile is never taken back.

**Since #20961 (`3c9ef1039f`), dev no longer shows the ticket's visible case.** An activation now reconciles in place, so a tab press no longer rebuilds the shell, and the Workstation spec passes on dev without this change (3/3). That spec stays as the regression guard. The guard itself is still needed: on dev, a departure that lands after the user moved focus takes it back. The component arm below is red on `3c9ef1039f`.

Evidence: L3 (Chromium: the engine Workstation through the Neural Link fixture, plus a real-DOM component spec of the settle) → L3 required (AC-1 and AC-2 are browser focus outcomes). Residual: none.

## Deltas from ticket

- **The settle lives in `DomAccess#focus` (`restoreFrom`), not in a separate read.**
  - My first version settled in a separate read and focused from the worker afterwards.
  - That made Tab between cell editors lose its focus: the worker's focus arrived after the next editor's. Four `CellEditingExample` arms went red.
  - One main-side step fixed it: 30/30.
- **The settle cannot read DOM containment while the departure plays out.** A floating descendant can hold the departing component's focus outside its node, and leave before or after it. CI caught both orders:
  - A submenu holds its menu's focus as a DOM sibling (#18870), so the hand-back to the button was skipped. `component/button/Base.spec.mjs`: 15/15.
  - A date editor's picker floats on the body and leaves after the editor. The grid View never regained focus, and the late leave could end a suspended edit: `CellEditingPickerProjection` date/horizontal went red.
  - The read now settles once the departing element is gone with focus on the body, or at the timeout. A focus that still lives elsewhere at the timeout is the user's.
- **The moved-on arm moves focus before the hand-back arrives.** My first version moved it after the call, which dev's immediate focus also survives, so it passed on dev.
- **The unit arms test the worker half:**
  - destroy and unmount forward `restoreFrom`;
  - an explicit `revertFocus()` stays unguarded;
  - a text field forwards the guard to its input.
- **`Text#focus` and `Select#focus` forward the remaining `focus()` arguments.**
- **The show path (`afterSetHidden`) and `dialog.close()` keep the immediate `revertFocus()`.** They are explicit reverts, not departures.
