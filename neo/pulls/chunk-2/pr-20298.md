Resolves #2392

Local Stores can now keep an edited record in sorted order by enabling `reapplyOnRecordChange` on a sorter. Existing sorters retain their current edit behavior. The Store uses its existing complete sort before publishing the record's new index, including calculated/dotted fields and opaque comparator dependencies; remote and paged projections keep their existing policy.

Evidence: L2 (real Model/Store contract tests in the single-thread engine harness) → L2 required for this data-policy change. No installed-runtime or visual acceptance claim.

## AC Evidence

No structured ACs on #2392. The [intake contract](https://github.com/neomjs/neo/issues/2392#issuecomment-6655580648) is covered by `test/playwright/unit/data/StoreRecordSort.spec.mjs`: opt-in/default behavior, eager/lazy records, filtered membership, multi-sort and batched edits, virtual/calculated/dotted fields, lifetime guards, settled key maps, and hierarchical TreeStore sorting.

## Deltas from ticket

Automatic edit sorting is opt-in per sorter, matching the existing Filter option and preserving edit stability by default. `autoSort: false` still opts out. Custom comparators and virtual sort fields conservatively reapply on every record edit. A filter pass that already sorts is reused. TreeStore key-map updates now run inside the existing Store notification transaction through `updateKeyMaps`, so sorting cannot observe half-updated structural maps. This adds the requested capability; no existing consumer workaround was removed.
