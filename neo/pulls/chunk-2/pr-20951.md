Resolves #20947

Four small portal defects from the design read, in one PR.

### 1. The footer's Blog button opened a dead route
`FooterContainer.mjs` pointed the Blog button at `/blog`, which `ViewportController` does not know; the blog list lives at `/news/blog` (served by the `/news/{*itemId}` route). The button now routes to `/news/blog`. A unit spec (`test/playwright/unit/apps/portal/FooterRoutes.spec.mjs`, in the style of the existing `LearnRoutes.spec.mjs`) pins the route and checks the `/news/{*itemId}` pattern that resolves it.

### 2. Two places called Neo a framework
Per the project's rule that Neo is an application engine, never a framework:
- `resources/images/workers-focus.svg` labelled the engine **Framework** → **Engine**.
- `view/home/parts/Features.mjs` ended a card with "(other frameworks)" → "(conventional frameworks)", so the line now contrasts Neo's model with conventional frameworks instead of listing Neo among them.

To satisfy the acceptance criterion (`git grep -n -i "framework" -- apps/portal` returns no line that calls Neo a framework), three doc comments that referred to the engine as "the framework" were also updated to "the engine": `canvas/HomeCanvas.mjs`, `canvas/ServicesCanvas.mjs`, `view/news/TabContainerController.mjs`. After this change, the only remaining `framework` matches in `apps/portal` code are the `index.html` FAQ (which correctly explains Neo is an engine, *not* a framework) and the historical records under `resources/data/` (archived tickets/PRs/blog text).

### 3. Connect stripped referrers, duplicated a link, and under-named the cards (`view/services/Container.mjs`)
- Every link to `github.com/neomjs` now carries `rel: 'noopener'` instead of `rel: 'noopener noreferrer'`, so a visit from neomjs.com reaches GitHub with its source. Links to other sites (LinkedIn, and the new Slack/Discord below) keep `noreferrer`.
- "Ask in the discussions" opened the same discussions list as card 3's "Join the discussion"; it now opens the new-post form of the Q&A category (`.../discussions/new?category=q-a`).
- The intro above the cards named three of the four cards; it now names all four (build, project memory, the public work, and reaching the maintainers).

### 4. Connect now names the two chat rooms
Connect linked only GitHub and LinkedIn. Since the header/footer chat icons are hidden on a phone away from home, a phone visitor had no way to reach the rooms from Connect. Slack and Discord now sit beside the discussion links in the "Join the public development work" card, using the exact invite URLs the footer uses.

### Verification
- `node --check` passes on every edited `.mjs` and the new spec.
- Connect links verified individually: all five `github.com/neomjs` links are `noopener` only; LinkedIn/Slack/Discord keep `noreferrer`; the Q&A link resolves to the new-post form; the Slack/Discord URLs byte-match `FooterContainer.mjs`.
