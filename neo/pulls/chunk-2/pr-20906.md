Resolves #20893

A merged pull request from outside the team now gets one comment. It gives the author's standing and up to two open curated issues, with the label each shares with the merged work. At a new rung it also carries an invitation and a star. `contributorStanding.mjs` decides the words from data the workflow fetched. `merge-comment.yml` counts the author's earlier merges and posts once; any failure warns and ends green, an incomplete search answer included. The badge paragraph stays off until `BADGES_SINCE` is set. After that it is offered only for a merge since the launch, never to an account on the opt-out list of neomjs/pages, and to no one while that list cannot be read.

Evidence: L2 (the unit spec runs the workflow's script against a stand-in GitHub and pins the words verbatim) → L3 required (AC-9: the real dispatch and the first real comment). Residual: AC-9, Residual-Owner: #20892.

## Deltas from ticket

- **One candidate reads in the singular:** "#A is open and unclaimed; a comment on it claims it … if it is taken by then". The ticket gives only the two-issue form.
- **`decideMergeComment` takes `badgesSince`**, defaulting to `BADGES_SINCE`, so the spec covers each state of AC-3.
- **Searches run one at a time.** GitHub asks one client to make its requests serially, and the search endpoint's secondary limit refused this seat's token during this work. The spec pins the peak at one search.
- **The candidates come from two searches, one per curated label**, using the claim responder's query. The full-list link ORs both labels in one query.
- **The badge generator's contract is pinned here** (Mnemosyne's read of neomjs/pages#74). It reads `RUNGS`, `standing`, `BADGES_SINCE`, `badgeFolder`, `badgeLine` and the outside test, and the module's JSDoc names that reader.
  - Each reader checks out exactly this module and `claimResponse.mjs`, so a spec arm holds the module to that one import.
  - `badgeFolder` refuses a login GitHub would not issue and an id that is not a number: the two folder shapes the generator refuses.
  - The count carries `is:public`, as the generator's query does.
- **An incomplete search answer is refused.** A search can succeed with `incomplete_results`, and an undercount would read as a first merge, so the run warns and posts nothing.
- **A failed checkout or module load warns.** The checkout step continues on error and the modules load inside the guarded script, so neither leaves a red check on the merged pull request.
- **The badge follows what Pages writes.**
  - A merge before `BADGES_SINCE` names no badge, and a merge at the launch is offered it. The since-launch count is asked only when its range is not inverted.
  - After the launch the workflow reads `badges/optout.json` from neomjs/pages `main`: a JSON array of numeric account ids, for which the generator writes no folder.
  - A listed account is offered no badge. An unreadable list (404 until neomjs/pages#74 merges, or any other shape) offers none, with a warning.
  - `parseOptOut` reads the file's text. `decideMergeComment` takes `optOut` and defaults to the unread list, so a caller that reads none never promises a folder.
