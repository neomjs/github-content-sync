**Other information:**

The Portal boots `neo-theme-neo-dark` (`themes[0]`), but `viewport.theme` stays null until the first switch. `onSwitchTheme` fell back to a hardcoded light theme, so the first click "switched" to the dark theme that was already showing.

- `onSwitchTheme` now reads `viewport.getTheme()`, which falls back to the boot theme, so one click goes dark to light and a second goes back (AC-1).
- The icon logic moved out of `setTheme()` into `updateThemeSwitchIcon()`. `onConstructed` calls it when there's no stored theme and no dark preference, so a dark boot shows the sun instead of the static moon (AC-2). The OS-preference path is unchanged.

Tests: added specs to `ViewportController.spec.mjs` for a fresh dark boot, a fresh light boot, and the icon mapping. All 10 tests in the file pass, and the dark-boot spec fails without the fix.
