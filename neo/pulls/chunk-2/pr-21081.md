Resolves #21078

`Neo.draggable.list.SortZone` now reorders a store-bound list's records by drag and drop, in any layout. The main thread already hit-tests every `drag:move` and sends the result as `targetPath`, so the zone reads its slot from there and measures nothing itself: rows, columns and wrapped grids sort alike. During the drag only the owner's vdom previews the order, and the dragged item stays in place as a faded placeholder. A drop renumbers `sortField` across the record's siblings, hidden ones included, with one `store.updateRows()`, and the list renders the store's sort. `moveRecord()` is the one commit path, for pointer and keyboard. `list.Base#createItem()` now renders `neo-draggable` on non-header items, so the drag affordance survives filter and sort re-renders.

Evidence: L3 (Chromium on the local dev server, through the web desktop launcher on #21065's branch, with pointer events dispatched to the page's own Pointer sensor) → L3 required (AC-7). Residual: an OS-level mouse drag, Residual-Owner: #21061.

## Deltas from ticket

- `SortZone.scss` gives the sorting list's items `pointer-events: auto` while the list holds the placeholder. `DragProxyComponent.scss` makes every element inert during a drag, which would blind the hit test; the scheduler's tracks opt back in the same way.
- `list.DragZone` keeps its load-time cls pass, because `tree.DragZone` inherits it (`tree.List` renders its own items). For flat lists it is now a no-op.

## Test Evidence

- All 6 arms of the new spec fail on `dev` (`d940179245`) and pass here. `list/`, `draggable/`, `menu/`, `form/` and `tree/`: 437 passed. The full unit suite on #21065's branch, which carries this commit: 7450 passed, 2 skipped.
- Browser witness (Chromium, local dev server, the web desktop launcher): pointer events dispatched to the page's own Pointer sensor (a 160 ms hold, then 24 moves) dragged Mail onto Calendar's trailing half. Mid-drag the DOM read Messages, Calendar, Mail (placeholder) with the proxy over it, and `elementFromPoint` found the placeholder under the pointer. The release wrote the order and removed the proxy. Escape mid-drag restored the order and wrote nothing. No console errors.
- Why synthetic input: the browser pane's own drag releases inside the sensor's 100 ms mouse delay, so it only clicks. Synthetic pointers cannot take pointer capture, so the sensor stayed on its document listeners rather than its captured branch; both read the item under the pointer with `elementFromPoint`.
