Resolves #19898

A SharedWorker window that closes during its boot now gives back what it held, and both film tour arms leave quarantine. #19899's repair ships here too, because both arms need both repairs.

- **The tear-out slot (#19898):** `App#registerApp` binds the vessel's slot before it sends `registerAppName`, and `DomEvents#onBeforeUnload` disconnected only the app names the window had heard. A vessel closed in between never disconnected, so its slot stayed bound and every later vessel for that item was refused. A window that knows no app name now sends a window-wide `disconnect`. `onDisconnect` retires the port for it, and `disconnect` releases the binder. `registerApp` registers nothing for a port that has already gone, which covers a registration landing after the window left.
- **The theme counter (#19899):** `insertThemeFiles` lowered `countLoadingThemeFiles` only when a reply resolved. A departed window's reply rejects, so the count stayed up and held every `initVnode` and `updateVdom` in the App worker. The count now drops in `finally`.
- **The diag:** a hop failure prints the slot's binder, whether its port is live, and the theme files in flight.

Evidence: L2 (unit arms that run the real App worker in a child process over real `MessageChannel`s, red with the fixes reverted) → L3 required (AC-3: both film arms green on every attempt across ≥ 5 hosted runs). Residual: AC-3, Residual-Owner: this PR (hosted re-runs before review).

## Deltas from ticket
- **#19899 ships here.** Its AC-2 arms are in `ThemeFileDeparture.spec.mjs`: a load in flight when its window departs, and one sent after it left, each release the count, and a later update in a live window runs. #19899 closes by hand when this merges.
- **The port retires too.** The ticket asked only for a window-wide disconnect. `onDisconnect` would have fired `disconnect` without retiring the port, because `registerApp` had already put the app name on it, and the theme replies pending on that port would then never settle. `onDisconnect` without an `appName` now retires the port.
- **`registerApp` skips all three steps**, not only `admit`. Otherwise `onRegisterApp`'s fallback gives the departed app's name to another window's port with no names yet. The second arm pins it.
- **Not per-window counting.** It would change both vdom gates and the contract documented in `StylingAndTheming.md`. A crash without `beforeunload`, or Playwright's `page.close()`, still leaves a binder and pending replies. That is the next step if a film arm still parks; the new diag names it.
