## Deltas from ticket

1. **The badge form's first sentence** is "Contributors to Neo.mjs now have a badge, and the comment above did not name yours." The ticket's sentence ("The badges were not live when this pull request was merged") is false for an earlier contributor who merges between this merge and the posting run: that merge comment names no badge because it is no first merge.
2. **A merge comment names the badge only if it carries a badge address.** One that says "Your badge shows it within the hour" at a later rung still gets the badge form, since the address was never handed over.
3. **`failed` replaces `unreadable`** as an outcome, since a post can fail too. A refused post stops the run: going on would push against GitHub's limit on new content. A failed read still warns and goes on.
4. **`limit` stops the run** after that many notes, also without `post`, so a short rehearsal is cheap.
5. **An account is listed as failed, not guessed at,** when the ledger does not hold its current login (renamed since its badge was written, so it has no folder yet) or when its merged pull requests here fill more than one search page.
6. `decideHeadsUp` returns `{body, form}` and takes `badgesSince`, so null switches the note off like the badge.
7. The opt-out sentence links the new-issue page of neomjs/pages.
8. **`headsUpMarker` stays after the run.** `decideMergeComment` reads it, and the notes stay on their pull requests. The removal leaf says so.
9. Intake: I filed the ticket in an earlier session. The drift probe over `origin/dev` since its creation (15:11:46Z) has no intersection with its paths, so the full gate was not run. Prescription checked: `buildScripts/util/contributorStanding.mjs` — owns the concern (the words and both decisions; the workflow only fetches, and posts under the bot identity the marker test needs).

One finding is not in this diff and goes to the epic's record: an account the run cannot reach (merges in other public repositories only; 8 in the ticket's rehearsal) is not offered a badge by the merge comment either, because its next merge here is no first merge.
