### Not in the frames

Found by reading the rules, then measured in headless Chromium 159.

**(a) The Timer's play glyph turns white in Neo Dark.** `component/Timer.css` gives its native `<button>` a background (`--timer-button-color`, `#cde8e7` in Neo Dark) and no `color`, so the glyph is the UA's `ButtonText`: `rgb(0, 0, 0)` on `dev`, `rgb(255, 255, 255)` under `color-scheme: dark`. White on `#cde8e7` is 1.3:1. This pull request flips it, so it fixes it. My pick: Neo Dark's wedge becomes a dark teal, so the control follows the scheme and needs no new name. The Timer pair in Neo Dark joins the frames, and I read the value there. The same meets `#9ec5c3`, which #22323 proposes for the classic dark theme; whichever of the two merges second adapts.

**(b) An embedded Neo document gets the same white canvas.** The embedder compares against the embedded root's scheme, and Neo puts the theme class on `body`. Inside a parent with `color-scheme: dark` and a background of `rgb(17, 17, 17)`, a 40 × 40 clip of each empty `srcdoc` frame reads:

| Embedded document | Root scheme | Pixel |
|---|---|---|
| root declares `dark` | `dark` | `17,17,17` (transparent) |
| only `body` declares `dark` (where our theme class sits) | `normal` | `255,255,255` |
| no declaration | `normal` | `255,255,255` |
| `:root:has(> .neo-theme-x)` declares `--neo-color-scheme`; the rule reads `:root, [class*="neo-theme-"]` | `dark` | `17,17,17` (transparent) |
| the same rules, `body` without a theme class | `normal` | `255,255,255` |

So a dark Neo app inside a dark Neo app (`Neo.component.Iframe`) shows white until its viewport paints, and wherever it does not. A root that follows its themed body stays transparent, and an unthemed document keeps today's behaviour.

This is a gap in decision 7 of ADR 0044, which is my wording. **The fork is yours as the ticket's author:** take the root into this pull request (my recommendation: the same rule with one more selector, and a fourth case in the iframe row), or I file it as the next leaf today. Either way decision 7 reads: "structure sets `color-scheme: var(--neo-color-scheme)` once, on the base selector and on the root of a document whose body carries a theme class, so the canvas and what an embedding page sees agree with the theme".

**(c) System colours in our own rules flip too, for the better.** Where a theme has no `--sem-*` (classic dark, Cyberpunk), the focus ring in `button/Base.css:163-165` and the Gantt label in `gantt/Container.css:12-14` fall back to `CanvasText` and `Canvas`: black on white becomes white on `#121212`. They belong in the body's list of declared changes.
