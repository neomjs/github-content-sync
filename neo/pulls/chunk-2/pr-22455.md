Resolves #22453

A container item can declare the same theme as its parent and still keep it when the parent switches again. The existing `theme` config records whether a managed item chose its value. Changing the parent updates inheriting items, and assigning `null` to a managed item restores inheritance.

Evidence: L2 → L2 for the generic ownership contract, with the real component-column grid control on the [Material consumer draft](https://github.com/neomjs/neo/pull/22438). This PR uses the existing Neo Light and Neo Dark schemes.

## AC Evidence

| AC | Proof |
|---|---|
| AC-1 | `container/ItemTheme.spec.mjs` exercises dark → light → dark with an explicit island, its descendants and an inheriting sibling. Before the change on `ab98a1fb22`, the island ended dark. |
| AC-2 | Item config, class default, ntype, item defaults, same-value live assignment, move and clear controls run through the ordinary component and container setters. |
| AC-3 | Existing first-adoption and retained-item tests stay green. In the real grid control, switching themes kept the original 14 pooled rows without local carriers and the same 14 detached component-cell carriers. |

## Deltas from ticket

The generic fix is extracted from the Material build. A previously unmanaged prebuilt instance that first enters a container with the same theme keeps its existing first-adoption behavior.

## Test Evidence

The hosted Web Desktop shard reproduced a return-path regression: after Mail came back to its desktop, an inherited body stayed dark when the owner switched to light. `VesselEmbodiment.restore()` already inserts the same live body into its source container. Removing the extra direct theme assignment lets normal container adoption preserve ownership. The Chrome test covers an inherited body, a body explicitly set to its owner’s current theme, and a different local theme. [Original failing assertion](https://github.com/neomjs/neo/actions/runs/46087584781/job/140801259667)

On the release base and this candidate, the same application-worker sequence set the host to Neo Dark, Neo Light and back to Neo Dark. The candidate preserved the light island and its grandchild. The unconfigured sibling followed each change. The focused container, component, render-wrapper, dock and desktop tests passed. On the extracted branch, Chrome exercised the Big Data example in dark → light → dark: all 32 rows remained without a local theme class and all 32 component buttons retained their existing carriers. The Monaco hosted job exposed an ntype creation regression. The repaired head keeps the raw config null at creation and resolves the effective theme from the host; the original Monaco browser assertion and all 19 focused ownership/lookup units passed.
