Resolves #19186

A committed cross-popup conversion now says what its dispose did. The engine transaction's dispose effect (`NativeVesselTransaction.effectsFor().disposeVessel`) publishes a `dispose` receipt before the first retire call and amends it in place — `attempts`, `admitted`, the refusal class (`no-vessel` · `identity-mismatch` · `host-close-refused`) and whether the vessel's window was still alive when the close was refused — through the same `publishReceipt(key, receipt)` seam the park and restore receipts ride; the Workstation and Demo B map the third key to `lastVesselDisposeReceipt`. A close the host refused while the window still exists is retried exactly once after a macrotask; a window already gone, a missing entry or a mismatched name is never retried, so the park machine's one-call contract and the "never close twice" rule both hold. The native popup-over-popup commit arms read the receipt over the Neural Link beside the closure they already asserted — the same read the operator's hand run makes.
