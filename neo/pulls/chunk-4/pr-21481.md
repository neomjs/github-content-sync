Fixes #21466. Claimed and assigned before starting.

## What was wrong

`Carousel`'s root and its first child both carried `neo-carousel`, so the `height: 14rem` and `padding: 15px` rule applied twice. The root's inline height won on the root, but the child had no inline height and stayed fixed at 14rem — so moving the example's height slider resized an empty frame around a fixed slide area.

## Changes

- `src/component/Carousel.mjs`: the body child now carries `neo-carousel-body` instead of a second `neo-carousel`.
- `resources/scss/src/component/Carousel.scss`: root keeps the 14rem default, padding, and its own flex column; the body fills the root; `.neo-carousel-inner` uses `flex: 1 1 auto` instead of a fixed `height: 9rem`; `.neo-carousel-item` fills the inner area with `height: 100%`.
- Theme files untouched — they only set variables.

## Acceptance criteria

- **AC-1** — only the root carries `neo-carousel`; pinned by a new vdom assertion.
- **AC-2** — the inner area and slides grow with the root; pinned by an assertion on the SCSS source that the flex chain exists and the 9rem fixed heights are gone. With no `height` config, the root still supplies 14rem.
- **AC-3** — both assertions are in `test/playwright/unit/component/Carousel.spec.mjs`.

## Verification

- `Carousel.spec.mjs` + `CarouselThemeVars.spec.mjs` on current `main`: **8 passed**
- `npm run check-theme-surfaces`: pass (on the base used during development)

Note: this checkout's Husky pre-commit/pre-push hooks fail on stale baselines and an old fork `main`, both unrelated to this change. The applicable file-level checks (whitespace, parse, theme coverage) pass, and the tests above were run on the rebased branch.
