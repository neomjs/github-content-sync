Resolves #21273

`headerAlign` adds label-alignment control to `Neo.grid.header.Button`. Before this PR, a numeric column's `cellAlign: 'right'` moved its digits to the right edge but left the header label ~200 px away with no way to close that gap. The new config accepts `'auto'` (tracks `cellAlign` at runtime), `'left'` (default, no change to existing grids), `'center'`, and `'right'`. The CSS sets `flex-direction: row` and `justify-content: end` for right alignment; `justify-content: center` for center. A Windows-only path-separator bug in `check-theme-value-files.mjs` that blocked any CSS-file commit on Windows is fixed in the same commit.

Evidence: L2 (14 unit tests green locally; e2e spec written covering AC-1, AC-4, AC-5) → L3 required (AC-1 browser geometry). Residual: AC-1 e2e live geometry verification, Residual-Owner: CI.

## Deltas from ticket
- `buildScripts/util/check-theme-value-files.mjs` path-normalisation fix added: the checker used raw `path.relative()` output (backslashes on Windows) but the baseline JSON uses forward slashes, causing false `[stale-baseline]` / `[new-selector]` failures on every Windows CSS commit. Fixed with `.replaceAll('\\', '/')` on the two affected map calls. This is a pre-existing Windows-only CI-equivalent bug surfaced by our CSS file being staged; it touches no logic, only path string formatting.
- `afterSetHeaderAlign` guard (`if (oldValue !== undefined)`) removed so the class is applied at construction time, not only on runtime changes. Discovered by unit tests.
