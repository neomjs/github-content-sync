Resolves #20636

🌿 A pointer held still can no longer outwait the timer that was set to arm it.

`onPointerDown`'s timeout re-entered `onDistanceChange`, which re-measured `Date.now() - pointerDownTime >= delay`. The timer runs on a monotonic clock while `Date.now()` floors the wall clock at other millisecond edges, so an on-time timer can read `delay - 1`; I measured 11 of 1,500 10 ms timers. The check then declined, nothing re-armed, and a still pointer never started its drag. That is the `Pointer.spec.mjs:638` failure on `dev`, where the 5 s poll from #20625 waited for a start that was never coming. The timeout now passes `delayElapsed: true`, and the `pointermove` path keeps measuring.

Evidence: L2 (unit, with `Date.now` stubbed one millisecond short, failing before the fix) → L2 required for AC-1 and AC-2.

Micro-review eligible: bug fix — one condition and one call argument in one sensor, plus the test that pins it.
