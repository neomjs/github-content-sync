Resolves #21400

🌿 *A chart can no longer print its labels in white on a white page and still pass for drawn.*

An amCharts chart now draws its text in its Neo theme's colours. `wrapper.AmChart` resolves the amCharts theme from `getTheme()` through a `themeMap`, the shape the Monaco and Mermaid wrappers already use. It sends that theme with each create, and creates a mounted chart again when the theme changes. The AmCharts addon gives each chart its own theme list and leaves amCharts' global list empty between charts.

Evidence: L3 (browser-rendered fills measured in local Chrome against the page background) → L3 required (AC-1). No residuals.

## Deltas from ticket

- **Each chart keeps its own theme list.** The Fix asked the addon to clear the global list, apply the requested theme, then create. amCharts creates labels and legend items later, when the data arrives, and an object asks its parent for themes before the global list (`getCurrentThemes`, read in the running library). So the addon also writes the theme to `chart.themes`, and what the chart creates afterwards keeps the chart's theme even though the global list is empty again.
- **The COVID apps' theme button** swaps the theme class without setting `theme`, so a mounted chart is not told. That is unchanged here and filed as defect-note `5798d895`.
