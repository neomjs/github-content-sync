Resolves #21338

A new example under `examples/form/validation`: a sign-up form (full name, email, password and its repeat, a terms checkbox) whose fields validate as the visitor types or leaves them. Sign up stays disabled while anything is invalid, a list beside the button names the current problems of the fields the visitor has engaged with, and a valid sign-up shows the submitted values with the password masked. The portal catalog gains the record (its cover is still to be captured, so the card does not publish yet), the capture tile list gains the example, and `seo.json` gains the example's route.

Evidence: L1 (unit and e2e specs added for CI; the seo route output was verified against the repo's own generator locally) → L2 required (AC-4: frames at 1440 × 900 and 390 × 844 in both themes; AC-5: frames on this PR). Residual: AC-4 frames, AC-5 frames, Residual-Owner: #21329. ## Deltas from ticket
- The problem list names the errors of the fields the visitor has engaged with (typed in, left, or a submit attempt), mirroring when each field shows its own error. A field the visitor has not reached yet stays quiet, instead of the form opening with five problems before the first keystroke.
- The submitted-values display masks the password and shows its length only: a receipt is not a place to print a secret back.
- The record ships without a cover (`image: null`), so no group card publishes until the capture pipeline produces the cover. The example joins the `example-captures.json` tile list in this PR so that capture can run.
