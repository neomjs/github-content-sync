Resolves #20589

The news section gets a seventh tab, `#/news/videos`, listing the films in `videos.json`, newest first. Each item stays a facade, a lazily loaded `i.ytimg.com` preview with a play button, until a visitor clicks it. Only the active item renders the `youtube-nocookie.com` player, so at most one film plays. The search field filters the store by title and highlights the matches. A film the search hides stops, and clearing the search brings back its facade, not a restarted player.

Evidence: L3 (headless Chromium against the dev server, YouTube hosts stubbed; CI runs the same spec off-socket) → L3 required (AC-1 to AC-4). Residual: neomjs.com shows the tab only after the 13.4 publish, see Post-Merge Validation.

Change class: capability (`feat`). agent-preflight: not hosted here; the baseline PR jobs run in CI.

## Deltas from ticket
- The previews use native `loading="lazy"` rather than copying the Medium list's IntersectionObserver wiring. `loading` comes before `src` because the DOM renderer applies attributes in key order; a unit test pins that order.
- The search sets a `like` filter on the store's `name`, so `list.Base` re-renders, instead of Medium's per-item `display: none`.
- The iframe carries `referrerpolicy="strict-origin-when-cross-origin"`, as YouTube's own embed code does.
- `WorkflowScopeClassifier.spec.mjs` now checks for `#/news/blog` instead of any `#/news` route. The check guards the CI exclusion of `blog.json`, which the news/blog view alone reads. On `#/news/videos` the App Worker holds only the Videos store: no `BlogNeo` store and no blog view, measured through the Neural Link. So the exclusion still holds, and the narrowed check still catches the blog route.
