Resolves #21415

🌿 *A closed dialog can no longer leave its mask over the page it left.*

Closing a dialog by Escape or its close button, animated or not, now takes the modal mask along and puts focus back on the button that opened it. When a second dialog closes, the mask goes back below the first. `Neo.main.DomAccess#syncModalMask` no longer depends on whether a departing dialog's removal has landed. `dialog.Base` syncs before `destroy()`, instead of on a timer the destroyed instance never ran, and a mounting dialog places its own mask. A departing dialog hands focus to its `animateTarget` when focus entered it from the body. Escape runs the close button's path.

Evidence: L3 (unit arms for the mask, the close, Escape, the focus target and the mount; e2e on `examples/dialog`; red proofs against `dev`; the dialog consumers' e2e specs locally) → L3 required (AC-1..AC-5). Residual: none.

## Deltas from ticket

- **A non-animated modal dialog opened with no mask at all on `dev`:** `init()` synced it on a 100 ms timer that raced the mount. `afterSetMounted` syncs it now, and the timer is gone.
- **`syncModalMask` loses its recursion:** it re-entered for the topmost `.neo-modal` and would never return when that node was not displayed.
- **Fix item 3 is a seam:** `component.Base#getFocusReturnTarget()`, shared by `revertFocus()` and `revertFocusOnDeparture()`. `dialog.Base` overrides it with the `animateTarget` fallback. That seam is why the class is `feat`.
- **`examples/dialog/DemoDialog.mjs`** gets the same change as the main view: its Create Dialog 2 button stays enabled, and both lose a `reference` nothing reads any more.
- **A third path on `dev`:** Escape while the dialog still grows out of its button hid it inside its mount flight, so the example's button stayed disabled. The e2e spec has an arm for it, and the others wait for the show to land.
