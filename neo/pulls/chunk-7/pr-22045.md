Resolves #22043

Both comments cited a fixed 20-slot limit. GitHub sets the limit by plan and live load, and the runners are shared with every other run on the account, so a constant is the wrong thing to put in front of a reader deciding whether to add a shard.

- `test.yml`: another shard consumes capacity the next run needs and can lengthen queueing under load.
- `pr-baseline.yml`: the grouped guards hold one shared slot from the pool the plan and live load make available.
