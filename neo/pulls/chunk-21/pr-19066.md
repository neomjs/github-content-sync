Resolves #19065

The Neural Link e2e fixture now points every page at the fixture's own Bridge port. A route answers each `neo-config.json` with `neuralLinkUrl: ws://127.0.0.1:${aiConfig.port}`, so a seat that sets `NEO_NL_PORT` gets its pages and its agent on the same Bridge. That covers popups, and the contexts a test opens itself through `neuralLink.newContext()`. With the port unset, the rewrite targets the same `:8081` URL, so nothing changes. **Sharing one bridge stays the default.** That is how peers join the same app runtime and collaborate (@tobiu); this PR only makes a seat's opt-out work for e2e.

Evidence: L3 (headless Chromium, external Brain runtime, two bridges, whole-file Workstation runs on a seat port) → L3 required (AC-2 / AC-3).

## Deltas from ticket

- The route is installed unconditionally rather than only for a non-default port. That avoids a second `8081` literal, and the default rewrite is the identity.
- **`neuralLink.newContext(options)`**: a context a test opens itself skips the fixture's route. The three Workstation tests that open one (`:258`, `:364`, `:508`) loaded the default config, dialled `:8081` and timed out waiting for a session on the seat's port. The helper applies the same route, and the spec's four `browser.newContext()` sites now use it. No other NL spec opens its own context.
- `agent-preflight`: not hosted here.

## Test Evidence

- Concurrent runs (`:8081` + `:8091`): both 1/1.
- Mutation control on `:8091` with `dev`'s fixture: red, `waitForSession` timeout.
- `WorkstationTopologyGroupsNL` on `:8091`, before the `newContext` fix: 3 passed, 5 failed. Three of the failures were `waitForSession` timeouts (`:258`, `:364`, `:508`); the other two were Target-worker reds (`:300`, `:533`) that also fail on `:8081` and belong to #19067. After the fix: 8/8, 8/8, 8/8, with 0 `waitForSession` timeouts (57 s, 47 s and 41 s).
- The `:8091` bridge the runs spawned (from the runtime root) was stopped afterwards.
