Resolves #19039

Four arms went red-then-green-on-rerun across three tiers on 2026-09-21 and produced **no rate**, because the tiers they sit on have no way to measure one. `test-e2e.yml` has carried #18505's dispatch instrument since it was built; `test.yml` — which owns `unit`, `unit-tz` and `components` — never received it. A rerun is the opposite of a sample: it marks the run green and erases the observation that provoked it.

Evidence: L2 (the argument builder and both execution paths measured locally, including the denominator) → **L3 required** for AC-2's hosted receipt, which is unreachable pre-merge — see Post-Merge Validation. Residual: AC-2 hosted count, Residual-Owner: #19039 is the close target, so the residual is carried as post-merge validation below rather than transferred.

**Change class: `ci`, declared.** Zero-delta for `pull_request` and `push`; the dispatch path is new capability for a workflow, which is not product behaviour. `agent-preflight: not hosted here` (`ABSENT` in this `package.json`).

## What shipped

- `workflow_dispatch` with `specs` and `repeatEach` — **names taken unchanged from `test-e2e.yml`**, because a second vocabulary for the same measurement makes the tiers incomparable for no gain — plus a `suite` input, since this file is a matrix over three tiers where that one is a single tier.
- Dispatch-keyed `concurrency`, so two probes cannot cancel each other. That tier found this by having it happen mid-measurement; it is copied rather than re-derived.
- Inputs reach the shell as **environment**, never interpolated into `run:`. `${{ inputs.specs }}` spliced into a script is a command-injection surface, and "only maintainers can dispatch" is a mitigation rather than a fix.
- A probe-summary step that says what the run covered. A probe's green means *"this selection passed N times"*, never *"the tier is covered"* — saying so is the difference between a measurement and a run someone later mistakes for one.

## The bypass the ticket prescribed, and why there is none

#19039's AC-4 required forcing `matrix.run` true under dispatch, from @neo-opus-ada's warning that a dispatch carries no changed files, so the classifier would skip every gated step and the run would report **success having executed nothing**. That is exactly the right thing to warn about — it is the same silent-pass shape as `testIgnore` printing `Skipped: 0`.

I read `classify-test-scope.yml` before building it, and **it fails open**:

| gate | on `workflow_dispatch` | why |
|---|---|---|
| `matrix.run` ← `needs.changes.outputs.run_*` | **`true`** | `getChangedFiles()` matches neither the `pull_request` nor the `push` branch and returns `null`; the `!files` arm sets all three flags `true` with `skip_reason: 'changed files unavailable'` |
| `steps.head.outputs.current` | **`true`** | the step returns early with `'true'` for any non-`pull_request` event |

Both gates already pass, so no bypass is needed and none was added. **AC-4 is wrong and I have struck it on the ticket** rather than implementing against it. The warning still earned its place: it is why I read the classifier instead of assuming, and it became AC-2 — *a green dispatch does not satisfy this ticket, the executed count does.*

## Test Evidence

The argument builder is the part a green CI cannot exercise, since no dispatch can reach this branch. Simulated across every input combination, printing one bracketed token per argument so an empty string cannot hide:

```
unit       (no inputs)                     -> npm run test-unit --
components shard only                      -> npm run test-components -- [--shard=2/3]
components shard + repeat 19 + 1 spec      -> npm run test-components -- [--shard=2/3] [--repeat-each=19] [test/a.spec.mjs]
unit       repeat 5 + 2 specs              -> npm run test-unit -- [--repeat-each=5] [test/a.spec.mjs] [test/b.spec.mjs]
unit-tz    1 spec                          -> npm run test-unit-tz -- [test/c.spec.mjs]
```

Then the two that matter, run for real:

- **The unchanged path** — `npm run test-unit --` → **4365 passed**. The builder now emits a bare trailing separator where the old line emitted none, and that is the one difference every PR would hit.
- **The probe path** — `--repeat-each=2` on a one-test spec → **2 passed**. The denominator works.

One malformed control worth recording: I first tested the trailing separator as `npm run test-unit -- -- <spec>` — two separators, which the workflow never emits — and it ran the whole tier, i.e. the spec filter was swallowed. That is a true fact about a command this change does not produce, and it would have read as a regression.

`js-yaml` parses the file; both new `run:` blocks pass `bash -n`.
