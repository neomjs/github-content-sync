Both source PRs merged at their earlier heads, so two review findings landed after the merge and are not on `dev`. This carries them. No new work: it is the two commits from the reviews, cherry-picked onto current `dev`.

```
939bb01e  test(collection): drop describe.serial, which truncated the diagnosis (#19003)
c953b433  docs(collection): fix the second operator list, which was worse (#19016)
```

## Why they were left behind

`#19015` merged at `003d509` and `#19017` at `294a837`. Both review conversations continued past those heads and I pushed the follow-ups afterwards, so the merge carried the approved commits and not what came next. Git said so on push — *"git cherry-pick \<each commit the merged PR did not carry\>"* — and that advisory was correct rather than noise. `git merge-base --is-ancestor` confirms neither is on `dev`.

## What is in here

**The `.serial` removal** (Ada, measured, on #19015). `test.describe.serial` stops a block at its first failure, so the arms after it never run. Same head, one variable changed:

| | result |
| --- | --- |
| `describe.serial` | 1 failed, 2 did not run, 5 passed |
| `describe` | 1 failed, 7 passed |

Two arms of signal lost on every regression. Nothing in that file needs it — every arm is a pure static call or a fresh `Neo.create`.

**The second operator list** (Copilot, on #19017). This is the finding I had missed, and the copy is worse than the one the PR fixed: the `operator_` config documented eleven values against a real sixteen, listing `>=` **twice** while `<=` appeared **not at all**, and omitting `doesNotStartWith`, `endsWith`, `isDefined`, `isUndefined` and `startsWith`. It is now the sibling one-line form that `Text.mjs` uses for a `{String}` config.

## Verified

```

npm run test-unit -- test/playwright/unit/collection/
# → 41 passed
```

All three places that name the operators now carry the same sixteen values in the same order. Pre-commit hooks passed on both cherry-picks.

## Still open, not mine to close

Ada said on #19015 that the `describe.serial` inheritance is the tier's problem — 36 unit spec files carry it and 373 do not, and Ada proved it unnecessary in exactly one of them — and that a ticket would be filed for it rather than generalising from a single file. That ticket is the right home for the other 35, not this PR.
