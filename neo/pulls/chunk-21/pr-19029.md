Resolves #19027

A number and a string that does not coerce to one now have a defined order instead of reporting a tie. `5 > 'abc'` and `5 < 'abc'` are both `false`, so the comparator called them equal while still ordering `5` against `1` — an intransitive relation, and `Array.prototype.sort` is specified only for a consistent comparator. The emitted order was therefore a function of the element count and V8's algorithm rather than of the data.

Evidence: L2 (real comparator and real `Collection` sort through their production paths; no runtime surface CI cannot reach) → L2 required for #19027. Residual: none.

**Change class: `fix`, declared.** §3.1 rule 1 would read the new `Sorter.compareValues` as capability, and I am calling it restoration instead: the method carries no behaviour a caller could not already reach through `defaultSortBy`. It is the same rule hoisted so two existing callers stop duplicating it. Naming the judgment so it can be challenged rather than discovered. `agent-preflight: not hosted here` (Brain-hosted, `ABSENT` in this `package.json`); the baseline CI jobs carry its checks.

## The decision the ticket parked

#19027 asked for the direction question to be **decided, not inherited**. Two rules now sit ahead of the relational operators and they answer different questions:

| | applies to | follows `directionMultiplier`? |
|---|---|---|
| **Absence** (unchanged) | `null` / `undefined` | **No** — sinks on ASC and DESC alike |
| **Type rank** (new) | number vs non-coercing string | **Yes** — DESC puts such strings first |

"No value" is not a position in an ordering, so it does not flip with the ordering. A number and a string are both *present* values, so they pose an ordering question — inheriting the nullish behaviour here would quietly assert that a string is a kind of absence. Strings that coerce are untouched: `'10'` against `5` still compares as ten, because only a pair whose string side yields `NaN` reaches the rank.

## One rule, read twice, written once

The ticket's own framing is that the two comparators drifting **is** the defect class — an earlier nullish repair reached one path and not the other. So rather than adding the branch twice, both now read `Sorter.compareValues`: `Sorter#defaultSortBy` returns it directly, and `collection/Base.mjs#doSort` calls it in place of its inline block. The rule is added once and deleted twice; `doSort` loses eight lines and `defaultSortBy` loses nine.

`collection/Base.mjs` already imported `Sorter`, so this introduces no module and no new dependency edge — structural pre-flight is N/A.
