Refs #18376

The worker plane stops owning DOM canvases. A `component.Canvas` keeps its node, its context and its process; the Canvas Worker builds its own `OffscreenCanvas` for the same id, renders into that, and ships pixels back. No worker ever paints into a canvas belonging to a document it does not host — which is the renderer kill in #18376, made structurally unreachable rather than gated.

**Draft on purpose.** `Refs`, not `Resolves`: #18376's AC-2 is this contract, but AC-3 (two Workstation roots) and AC-6 (end-to-end cost against a named app baseline) are not delivered here, and a merge must not close the ticket early. @neo-opus-vega's call, and the piece-4 API leaf is still to file.

Evidence: L4 (real Chromium, both DPR arms, mutation-checked in three places, 6 passed at `--repeat-each=3`) → L4 required (every claim here is a runtime property; none is checkable by reading). Residual: AC-3 and AC-6, Residual-Owner: #18376.

## Deltas from ticket

**The transport is a transferable RGBA `ArrayBuffer`, not `createImageBitmap`.** AC-2 originally named the bitmap; @neo-gpt's matrix shows bitmap delivery fails foreign clients outside Chromium. Corrected on the ticket before implementing.

**Two things the contract implies that the ACs do not say, both found by measurement rather than reading:**

1. **The backing store must be sized.** All three portal canvases had the `300x150` HTML default against CSS boxes up to `1280x662`. `putImageData` writes device pixels at 1:1 and ignores canvas scaling, so a correct frame was clipped to its top-left corner and stretched over the element — and my first version of the witness spec passed it, because pixels were non-zero.
2. **Resize must be reconciled, not listened for.** The DPR-2 arm caught a canvas settling 4px after registration. Reconciling in the frame loop costs two property reads and cannot miss an edge; a listener misses an element that settles between registration and its first observed resize.

**Piece 5 landed rather than deferred.** I said the `waitForCanvas` poll should collapse and that failing to would be evidence against this shape. It collapses: `initGraph` runs from `afterSetOffscreenRegistered`, which is set only after the registration resolves, which resolves only after the producer confirms its canvas exists.

The API leaf this PR's Post-Merge Validation promised is filed: **#19046**, linked as a child of #18376.

It carries the three exported remotes — `DomAccess#transferCanvasToWorker`, `DomAccess#getOffscreenCanvas`, `worker.Canvas#retrieveCanvas` at `worker/Canvas.mjs:37` — plus the three unexported leftovers this PR strands, and `worker/Manager.mjs:183`'s route to `onGetOffscreenCanvas`, **which is defined nowhere in the tree** and has been broken longer than this work.

Verified on this head, and the distinction matters for what #19046 asks:

```
transferCanvasToWorker  0 in-tree code callers
getOffscreenCanvas      0  (the single hit is an archived tickets JSON, not code)
retrieveCanvas          0
```

Zero in-tree callers is not zero callers. `remote.app` is the App Worker's public surface, so an application outside this repository can still call `transferCanvasToWorker` today — which also means **the route to the renderer kill stays reachable by an external app until #19046 lands.** That is the argument for not leaving it open indefinitely, and it is stated there rather than here.

Deliberately not done in this PR: removing an exported remote is a breaking change and deserves its own decision, not tidy-up riding along in a feature branch.
