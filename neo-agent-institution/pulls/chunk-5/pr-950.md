Resolves #948

Home's merge count now opens the awaiting-merge list once the route has moved to Fleet. The door used to open the list while the shell still held Fleet off screen. The shell `tab.Container` keeps `removeInactiveCards: true`, so the fleet head's button had no DOM, and whenever the open beat the mount, the list never appeared. `ReadingSurfacesController#openMergeQueue` now waits for the button's `mountedPromise`. A hidden button has no list and is never mounted, so it answers `{opened: false}` at once.

The wait belongs to the visit that asked. The engine keeps a component's mount promise across an unmount, so `ViewportController#onHomeMergeQueueOpen` passes a signal from `visitSignal('/fleet')`, which aborts when the shell activates another keeper-view. The cockpit's `mountsWithinVisit` answers `false` when that signal aborts or the button hides before it mounts, and releases both listeners, so a later ordinary Fleet visit opens nothing.

Evidence: L2 (a headless real-browser Neural Link e2e against a loopback Fleet, under CPU throttling, plus units) → L3 required for AC-3 (the installed candidate). Residual: AC-3, Residual-Owner: #490.
