Updates `sass` from 1.105.2 to 1.106.1
<details>
<summary>Release notes</summary>
<p><em>Sourced from <a href="[QUARANTINED_URL: github.com]">sass's releases</a>.</em></p>
<blockquote>
<h2>Dart Sass 1.106.1</h2>
<p>To install Sass 1.106.1, download one of the packages below and <a href="[QUARANTINED_URL: katiek2.github.io]">add it to your PATH</a>, or see <a href="[QUARANTINED_URL: sass-lang.com]">the Sass website</a> for full installation instructions.</p>
<h1>Changes</h1>
<ul>
<li>
<p>Fix a bug where an attribute selector with an empty value (such as <code>[class=&quot;&quot;]</code>) would crash when serializing.</p>
</li>
<li>
<p>Don't crash when serializing a number with an empty unit. This is only possible through the JavaScript and Dart APIs or the embedded protocol.</p>
</li>
</ul>
<h3>Embedded Dart Sass</h3>
<ul>
<li>More robustly convert invalid value errors into <code>PARAMS</code> errors.</li>
</ul>
<p>See the <a href="[QUARANTINED_URL: github.com]">full changelog</a> for changes in earlier releases.</p>
<h2>Dart Sass 1.106.0</h2>
<p>To install Sass 1.106.0, download one of the packages below and <a href="[QUARANTINED_URL: katiek2.github.io]">add it to your PATH</a>, or see <a href="[QUARANTINED_URL: sass-lang.com]">the Sass website</a> for full installation instructions.</p>
<h1>Changes</h1>
<ul>
<li>
<p>Don't normalize CSS escapes in statement contexts that can contain interpolation. For example, <code>@f\6Fo</code> is now emitted as written rather than normalized to <code>@foo</code>.</p>
</li>
<li>
<p>Fix a bug where quotes would be removed from attribute selector values that contained backslashes.</p>
</li>
<li>
<p>Fix invalid source spans that could cause crashes when encountering a syntax error in selectors or media queries that also contain escape sequences.</p>
</li>
<li>
<p>Fix a bug where the indented syntax parser would crash when parsing a file where the first statement was indented <em>and</em> appeared after the first line.</p>
</li>
<li>
<p>Fix a bug that could cause crashes when encountering errors or warnings in interpolations that contain patterns like <code>// */</code>.</p>
</li>
<li>
<p><strong>Potentially breaking compatibility fix:</strong> CSS escape codes whose values are 0, for Unicode surrogates, or greater than the maximum allowed code point are now consistently normalized to U+FFFD REPLACEMENT CHARACTER in expression contexts. Previously, in some cases these were instead normalized to the normalized form of the original escape sequence, which violates the principle that all escape sequences for identical values should be normalized the same way. In other cases, these would simply throw errors.</p>
<p>As a special case, <code>\0</code> on its own will continue to be normalized to <code>\0 </code> to support historical CSS hacks.</p>
</li>
<li>
<p><strong>Potentially breaking bug fix:</strong> Throw an error for mixins and functions that have rest parameters which are the same as normal parameters. Previously, the positional parameters wouldn't be accessible and calling such a mixin or function with a named argument would crash the compiler.</p>
</li>
<li>
<p><strong>Potentially breaking bug fix:</strong> Fix various cases where using a CSS escape code at the beginning of an identifier would change parsing behavior versus using the character directly.</p>
</li>
<li>
<p><strong>Potentially breaking bug fix:</strong> When a number's unit is ambiguous with a numeric exponent, the unit is now serialized as an escape code rather than a literal <code>e</code> to avoid being interpreted as an exponent by CSS.</p>
</li>
<li>
<p><strong>Potentially breaking bug fix:</strong> Don't parse a CSS escape code for U+45 LATIN CAPITAL LETTER E or U+65 LATIN LOWERCASE LETTER E as an exponent in <code>@keyframes</code> percentage selectors.</p>
</li>
<li>
<p><strong>Potentially breaking bug fix:</strong> Properly normalize underscores written as CSS escape codes in variable, mixin, and function names.</p>
</li>
</ul>
