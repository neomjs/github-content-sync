Resolves #849

A boot refusal that says nothing against the stored PAT now comes back without one. For `plane-refused`, `plane-not-a-plane` and `plane-unreachable` the banner's one action reads Retry. The click calls the new `neoShell.retryPlane()`, and main runs the boot again in this process with the record it launched with: no credential window, no relaunch. `retryBrainBoot` (`harness/brain.mjs`) refuses a retry while a boot runs, after one came up, and while quitting. An accepted retry opens a new boot episode (`appLifecycle.beginBrainBoot`), so the old refusal leaves the banner while the boot runs again, and a second failure shows its own cause. The credential's two refusals and `organism-beside-plane` keep Connect. ADR 0034 §2.3 item 8 names the fourth capability.

Evidence: L2 (unit seams for the broker, the retry gate and the lifecycle episode, plus a Darwin visual capture of the banner) → L4 required (AC-6: on the installed FM, a refusal followed by Retry reaches `live`). `main.mjs`'s composition (`bootBrainSettled`, `retryBoot`) has no unit seam. Residual: AC-6, Residual-Owner: #516.
