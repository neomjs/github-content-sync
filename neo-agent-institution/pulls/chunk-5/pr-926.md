Resolves #925

Accounts reads the agent registry again whenever the roster turns `live`, so a boot before the Fleet serves no longer leaves Accounts empty for the app's lifetime, nor the cockpit's agent detail, which shares its Store. Until a read lands, the empty line says the Fleet has not answered instead of `No agents yet`.

Evidence: L2 (the real Panel, controller, StateProvider binding and Stores against a stubbed Fleet bridge) → L4 required (AC-4: row 5's H3 on an installed candidate, an operator-gated PAT revoke). Residual: AC-4, Residual-Owner: #424.

## Deltas from ticket

- **An empty first answer emits no Store event.** `store.data = []` on a never-loaded Store sets `isLoaded`, but `Collection#splice` fires `mutate` only when rows move, so nothing re-derived the line. `Controller#loadAgentDefinitions` now calls `syncDetail()` after an empty answer. Without it, a fresh install's empty registry would read "has not answered" forever.
- The empty component's static text moved into `syncDetail()`, its one owner.
- `e2e/agentos/Cockpit.spec.mjs` asserted `No agents yet` on a boot with no Fleet, so its registry read never lands. It now asserts the unanswered line, the truthful text for that state.
- Intake (self-authored, this session): `Prescription checked: apps/agentos/view/accounts/Panel.mjs — owns the concern`. Root provider leaves are declared for keeper-views to bind, and Home binds this one; the controller already owns the fenced reads.
