Resolves #788

Every engine `Splitter` inside the cockpit — the Memories reading split, the Activity observer split, the Mailbox split — now wears the dock's splitter tokens at rest, under the pointer and in a drag, instead of the engine theme's blue or purple bar. The FM declares its dock values on `.neo-dashboard-dock-splitter` itself (to beat the engine's `.neo-dashboard` defaults), so pane content never inherited them: that rule's selector now also names `.neo-splitter`, and one `.neo-splitter` rule in the cockpit scope maps the engine's tokens onto the dock's (background, hover color, no border, the dock's radius, no margins). The drag proxy mounts on `document.body` outside the cockpit root, so a body-level rule in `Viewport.scss` (the file that already owns the body-level menus) gives it the dock's active color; the FM tokens resolve there because they are declared on `:root .neo-theme-neo-*` and the proxy carries the skin's theme class. The Observatory sits outside the cockpit root and already carries the dock's values through its own copy; it is untouched (named on the ticket). No per-view rule, nothing in the engine.

Evidence: L3 (the visual suite: computed-style assertions red-first on the unmodified SCSS, real hover and a real drag, goldens) → L3 required (a token mapping is observable only as computed style and pixels). Residual: a pane torn out into its own window leaves the cockpit root and would wear the theme splitter again (inferred, unverified); the pane splitters stay the engine's 10 px against the dock's 6 px and keep the engine's 0.3 s hover transition, Residual-Owner: #505.

agent-preflight: not hosted here; `npm run build-themes -- -n -e dev -t all` → `npm run test-visual` alone → `npm run stamp-visual-baselines`; `npm run check-visual-baselines` "input identity matches the golden stamp".

## Deltas from ticket
The ticket asked for one mapping rule. Two findings widened it: the dock values are not inherited by pane content (the dock-token rule's selector widened), and the drag proxy lives outside the cockpit root (a body-level rule in `Viewport.scss`). The Observatory site in the ticket's premise was wrong and is out of scope; the ticket body carries both corrections. A new visual driver (`memoriesEnvelope.driver.mjs`) seeds the fixture plane's memories so the reading state is reachable; the arm runs at 1280×1000 because at 800 px tall the strip's grid body (129.5 px) is shorter than one 132 px row and renders no rows (captured as a defect-note, not promoted).
