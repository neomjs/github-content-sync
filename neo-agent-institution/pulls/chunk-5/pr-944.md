<h2>v2.1.7</h2>
<h2>Security fixes</h2>
<p>This release includes a fix for the following security issue:</p>
<h3><code>serveStatic</code> with <code>allowPercentInPath</code> still allows the double-decode middleware bypass</h3>
<p>Affects: <code>serveStatic</code> with <code>allowPercentInPath: true</code>. The fix for <a href="[QUARANTINED_URL: github.com]">GHSA-rmxm-3fg6-px4f</a> rejects a path containing <code>%</code>, but the <code>allowPercentInPath</code> option skipped that check entirely. A malformed percent sequence such as <code>/static/%%36%31dmin/secret.txt</code> was routed as <code>/static/%61dmin/secret.txt</code>, so middleware on <code>/static/admin/*</code> did not run, and <code>serveStatic</code> then decoded <code>%61</code> to <code>a</code> and served <code>static/admin/secret.txt</code>. The default configuration was already fixed in 2.1.3. <a href="[QUARANTINED_URL: github.com]">GHSA-fj57-4f93-cfw6</a></p>
<p><code>serveStatic</code> now accepts the second decode only when its result equals the routed path with <code>%25</code> replaced by <code>%</code>. File names containing a literal <code>%</code>, requested as <code>%25</code>, are served as before.</p>
<hr />
<p>The same fix ships in <code>hono</code> v4.13.18 (<a href="[QUARANTINED_URL: github.com]">GHSA-74fm-fwc7-3fwp</a>).</p>
<p><strong>Full Changelog</strong>: <a href="[QUARANTINED_URL: github.com]">[QUARANTINED_URL: github.com]</a></p>
<h2>v2.1.6</h2>
<h2>Security fixes</h2>
<p>This release includes fixes for the following security issues:</p>
<h3>Backslash in the request path is parsed as a path separator, bypassing path-based access control at a reverse proxy</h3>
<p>Affects: all requests. The raw request-target was passed to the WHATWG URL parser, which treats a backslash in the path as <code>/</code> and resolves <code>..</code> segments, so <code>/admin\secret</code> reached the application as <code>/admin/secret</code>. A reverse proxy that forwards the backslash unchanged applied its path-based rules to the original path. <a href="[QUARANTINED_URL: github.com]">GHSA-jpvv-r467-5p4w</a></p>
<p>A request whose path contains a raw backslash is now rejected with <code>400 Bad Request</code>, for HTTP/1.1, HTTP/2 and WebSocket upgrades. A percent-encoded backslash (<code>%5C</code>) and a backslash in the query string are still accepted.</p>
<h3>WebSocket upgrade request-target starting with <code>//</code> replaces the host in <code>c.req.url</code>, bypassing <code>Origin</code> checks</h3>
<p>Affects: <code>upgradeWebSocket</code>. The URL of an upgrade request was built by resolving the request-target against the <code>Host</code> header, so a request-target such as <code>//attacker.example/ws</code> set the host of <code>c.req.url</code> to a client-chosen value while routing still saw <code>/ws</code>. An application that compared <code>Origin</code> with the origin of <code>c.req.url</code> could be bypassed by a page on another site. <a href="[QUARANTINED_URL: github.com]">GHSA-7v5p-43qr-wch5</a></p>
<p>The host of upgrade requests now comes from the <code>Host</code> header, as for ordinary requests.</p>
<h3>Unhandled <code>ECONNRESET</code> on the socket during an asynchronous WebSocket upgrade crashes the process</h3>
<p>Affects: <code>upgradeWebSocket</code>. While the application handled an upgrade request, the socket had no error listener. A client that reset the connection during asynchronous middleware caused an unhandled <code>'error'</code> event and terminated the process. <a href="[QUARANTINED_URL: github.com]">GHSA-qv5m-9pm6-hqp3</a></p>
<p>Error and close events on the socket are now handled while the application runs, and a pending upgrade is released when the socket closes.</p>
