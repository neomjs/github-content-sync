Resolves #828

The cockpit now asks the shell's `verifyPlane` whether the plane still admits the launched PAT on three occasions, not one:
- a roster read that fails upstream, as before;
- a roster answer whose plane presence read is `degraded`, once per episode;
- a liveness-tick re-check every `planeCredentialRecheckInterval`: 300 s, the plane's PAT cache TTL.

Only the shell's answer writes or clears `planeCause`. A read that answers ends the episode but no longer clears the cause.

Two harness fixes let a held run witness this:
- `attachSmokePlane` records the launched plane as the product boot does, so the shell can answer there too;
- `walkControl remap` after a `revoke` re-admits the revoked token.

Evidence: L2 (unit: the cockpit trigger paths, the remap re-admission, and the launch-record composition the smoke arm uses) → L3 required (AC-4: the held-run re-walk of provocations 5–6 on an installed candidate). Residual: AC-4, Residual-Owner: #516.
