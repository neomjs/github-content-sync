Resolves #840

The Observatory's "Open on GitHub" now opens the page beside the app instead of in place of it. The cause was in the engine: `Neo.button.Base` rendered a url that arrives after the button is built without a `target`. neomjs/neo#20285 fixed that, merged as neomjs/neo#20287. This PR moves the lock onto that merge and extends the Observatory's NL e2e. The link must carry `target="_blank"`, its click must open a popup and leave the app on its page, and the control's tooltip must still hide when the pointer leaves.

Evidence: L2 (headless e2e on an isolated Neural Link Bridge; NL specs run outside CI) → L4 required (AC-2: the installed build opens an issue and a merged PR in the operator's browser and the window stays live). Residual: AC-2, Residual-Owner: #485.

## Deltas from ticket

- The engine half became its own leaf: neomjs/neo#20285, merged as neomjs/neo#20287.
- No harness change. With `target="_blank"`, the click reaches `setWindowOpenHandler`, which already hands an allowlisted `https:` host to the operator's browser.
- The lock's `neo.mjs` entry carries no `integrity` hash. npm 11.21's install-scripts gate skipped the engine's `prepare`, which is a no-op for a dependency build, so npm computed no hash. The pin is exact, and the next Dependabot bump restores the hash.
