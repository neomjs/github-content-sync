Resolves #794

The cockpit's vessel bookkeeping follows the engine's Group contract after neomjs/neo#20006: an item's vessel is addressed by the key the Group minted at admission, resolved through `keyOf` (`vesselKey(itemId)`), for every owner, admission and connection read and for the retirement; the key travels through the native-return park, reshow and dispose seams; a vessel's window is named with the key's suffix, so two live vessels of one pane never share a name. Two reads that had silently started returning the key instead of the item are fixed with it: dragging a vessel window's title bar back to main (`resolveNativeWindowDrag` read the item as the entry's key, so the drag resolved nothing) and the vessel window titles (`pushVesselTitles` titled windows "popup:detail"). The open-effect precondition ("only a singly-owned pane may embody") reads the owner records' items directly: the Group already holds the slot being opened as the item's newest record while the effect runs, so a `keyOf` read there can never see an older vessel — with the plain guard the cockpit opened a second window for an owned pane (unit arm `vessel.spec.mjs:211`). The four projection arms failed on a separate upstream change: neomjs/neo#19983 added the reactive `headerActionsShowOnHover_`, and the projection spec's prototype-spy host derives its dock configs by a name regex that missed it, so the inherited getter threw without `#configs` — one word in the regex. The unit fixtures and the N-window NL probe key by the minted key.

Evidence: L3 (unit: the five red arms red-first against the engine's dev tip, the whole tier green; NL e2e: the tear-out, N-window, pop-out, kinetic and permanence-row-4 vessel specs green on a source build against the same engine) → L3 required (a consumer-contract port: the Group's records are the witness).
