Resolves #847

A starting plane now reads as starting, at boot and at Connect, and a stored plane's login wait no longer gives up on its own. `probePlaneCredential` types a 5xx at either `initialize` as `unreachable`, because the plane's ingress answers 502 for its Memory Core until that listens. `bootFleetWithPlaneRecovery` loses its 180 s deadline: the wait ends only on an answer or on quit. It also keeps waiting when the plane refuses a just-spawned Fleet child as unreachable, which happens when a login restarts the plane's containers. From 3 min the pill reads `Agent OS not answering · N min` and names the action. `HARNESS_BRAIN_BOOT_FAILED` now carries `[cause]`.

Evidence: L3 (a real `caddy:2-alpine` running the Brain's `Caddyfile.local-agent-os` with no upstream, probed by the base and head probe) plus L2 unit seams → L4 required (AC-7: an installed FM across a macOS restart). Residual: AC-7, Residual-Owner: #516.
