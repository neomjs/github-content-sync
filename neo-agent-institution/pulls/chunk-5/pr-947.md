Resolves #946

A runtime-retirement pass can no longer hold the package and runtime-reference leases forever. Each read in `retireRuntimeGenerations` (payload verify, census) races a per-pass deadline (2 min) and the owner's abort. The `finally` then releases both leases, and the result names the step and generation the pass stopped in. A removal that has started is never abandoned: it deletes by path, so it finishes under both leases, and a halt takes effect at the next step. Teardown aborts the running pass and joins it within `closeTimeoutMs`, so an FM quit cannot hang behind it. `main.mjs` passes the signal and logs a halted pass once: `HARNESS_RUNTIME_MAINTENANCE_DEFERRED <reason> <step> <generation>`.

Evidence: L2 (unit specs on real sealed generations and real file leases, with a census that never settles and a real removal paused mid-flight) → L2 required (all four ACs are unit-observable). Install-time checks are under Post-Merge Validation.

## Deltas from ticket

- No timer pulse. The ticket first asked for one, but `assertCurrent()` already pulses at each step boundary, and a timer would make a stuck pass look alive to neomjs/neo-agent-brain#1667. The ticket body now says so.
- Teardown aborts the running pass instead of only bounding the wait, so a halted pass releases its leases before the FM exits.
- Removals are not bounded (Emmy's review). Racing a path-based deletion against the halt released custody under a running delete. A removal that itself never settles keeps custody; the observed hang came before any rename.
