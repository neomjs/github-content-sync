Resolves #841

The cockpit now reads the Fleet's start gate, which neomjs/neo-agent-brain#1472 puts on the roster DTO. Until now `LivenessController#loadRoster` dropped it. Behaviour:

- **Booting gate.** A relaunch that reaches the roster while the Fleet still verifies its runtime gets a state line naming that phase in the lifecycle's own sentence ("The Fleet is verifying its runtime: Start opens when it finishes") instead of a timeout. The roster re-reads on the next 15 s liveness pass rather than after a full minute, so the line clears and Start opens within one pass of the Fleet finishing.
- **Refused gate.** It names its refusal and keeps the ordinary cadence.
- **Precedence.** A cold roster, a daemon fault and a stale roster still outrank the gate line.
- **Target switch.** It resets the gate with the rest of the roster's truths.

Evidence: L2 (unit arms through the real bridge, roster loader, admission and banner derivation) → L4 required for AC-2 (an installed cold relaunch). Residual: AC-2, Residual-Owner: #424.

## Deltas from ticket

- The ticket asked for a roster within 15 s. The roster itself now answers in about 4 s (neomjs/neo-agent-brain#1469). What this PR bounds is the gate clearing: one 15 s pass, via `LivenessCadence.expedite` / `intervalsFor`.
- A refused gate gets its own line, "start refused", with the lifecycle's reason. AC-3 names only the boot phase, but the DTO carries both states.
- `TargetBinding.retireRoster` resets the gate, so a previous target's gate never survives a switch.
