<details>
<summary>Release notes</summary>
<p><em>Sourced from <a href="[QUARANTINED_URL: github.com]">fast-uri's releases</a>.</em></p>
<blockquote>
<h2>v3.1.9</h2>
<h2>Security</h2>
<p>This security release fixes four URI parsing and normalization vulnerabilities in fast-uri 3.x. Applications that process untrusted URI input should upgrade to v3.1.9.</p>
<ul>
<li><strong>Medium — URI scheme spoofing through percent-encoded schemes</strong> (<a href="[QUARANTINED_URL: github.com]">GHSA-w74x-v6f9-j3xg</a>, CVE-2026-110306): percent-encoded scheme input is now rejected instead of being decoded into a live scheme.</li>
<li><strong>Medium — Host confusion during domain-host canonicalization</strong> (<a href="[QUARANTINED_URL: github.com]">GHSA-wjr9-j795-jxcr</a>, CVE-2026-110180): malformed domain hosts containing ambiguous delimiters or stripped control characters are now rejected instead of being silently rewritten.</li>
<li><strong>Low — Incorrect relative-reference normalization</strong> (<a href="[QUARANTINED_URL: github.com]">GHSA-xhq7-xmqj-769h</a>, CVE-2026-110095): dot-segment removal now preserves the resolution semantics of relative references.</li>
<li><strong>Low — Scheme injection in suffix references</strong> (<a href="[QUARANTINED_URL: github.com]">GHSA-333x-w4r6-6crp</a>, CVE-2026-110725): first-segment colons in path-only suffix references are now escaped so the output is not reparsed as a scheme.</li>
</ul>
<p>Upgrade with:</p>
<pre lang="sh"><code>npm install fast-uri@3.1.9
</code></pre>

Updates `undici` from 6.29.0 to 6.29.1
<details>
<summary>Release notes</summary>
<p><em>Sourced from <a href="[QUARANTINED_URL: github.com]">undici's releases</a>.</em></p>
<blockquote>
<h2>v6.29.1</h2>
<h2>Security fixes</h2>
<h3>High severity</h3>
<h4>Denial of service via TLS 1.2 certificate-changing renegotiation</h4>
<p><strong>CVE-2026-87018 · <a href="[QUARANTINED_URL: github.com]">GHSA-qrxm-fqhp-jwvm</a></strong></p>
<p>A malicious or compromised HTTPS server could crash the Node.js process by initiating TLS 1.2 renegotiation and presenting a different, CA-trusted certificate whose hostname did not match the requested host. The resulting socket error reached an assertion in undici's HTTP/1.1 and HTTP/2 connection handling. This release handles post-connect certificate errors without terminating the process.</p>
<h4>TLS certificate validation bypass through dropped <code>Agent</code> options</h4>
<p><strong>CVE-2026-109383 · <a href="[QUARANTINED_URL: github.com]">GHSA-2m5v-pch6-74hx</a></strong></p>
<p><code>Agent</code> used a JSON-based clone for constructor options, which silently removed function-valued TLS options such as <code>checkServerIdentity</code>. Applications relying on custom certificate or public-key verification could therefore accept a certificate that the callback was intended to reject. This release preserves TLS options when creating per-origin dispatchers.</p>
<h4>Denial of service through excessive <code>Content-Encoding</code> values</h4>
<p><strong>CVE-2026-109869 · <a href="[QUARANTINED_URL: github.com]">GHSA-xjj6-f33q-929c</a></strong></p>
<p>A malicious HTTP server could crash the Node.js process by returning more than five content codings and closing the connection before sending the body. Although <code>fetch()</code> rejected the response, an error from an orphaned internal stream could remain unhandled. This release validates the content-encoding chain before creating the body stream and aborts oversized chains safely.</p>
<h3>Medium severity</h3>
<h4>Denial of service through unbounded EventSource parser state</h4>
<p><strong>CVE-2026-109924 · <a href="[QUARANTINED_URL: github.com]">GHSA-4qv8-2p9j-2685</a></strong></p>
<p>A malicious Server-Sent Events endpoint could exhaust process memory by sending many tiny <code>data:</code> fields without completing an event, or by splitting an unfinished line across many chunks. This release bounds retained EventSource parser state, including field counts, buffered chunks, unfinished-line length, and retained field data.</p>
<h4>Denial of service through unbounded automatic WebSocket PONG buffering</h4>
<p><strong>CVE-2026-109932 · <a href="[QUARANTINED_URL: github.com]">GHSA-9fm3-97px-rjf6</a></strong></p>
<p>A malicious WebSocket server could exhaust process memory by flooding the client with PING frames while not reading the automatic PONG responses. undici previously ignored socket backpressure and allowed the outbound queue to grow without bound. This release pauses frame parsing when PONG writes encounter backpressure and resumes after the socket drains.</p>

</ul>
