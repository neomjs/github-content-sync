<h2>v4.13.18</h2>
<h2>Security fixes</h2>
<p>This release includes fixes for the following security issues:</p>
<h3><code>validator()</code> skips validation for requests whose <code>Content-Type</code> parameters are formatted differently</h3>
<p>Affects: <code>validator('json')</code> and <code>validator('form')</code> in <code>hono/validator</code>. A <code>Content-Type</code> with whitespace before <code>;</code>, a trailing <code>;</code>, or an unusual parameter name was not recognized, so the validator saw an empty object while the handler could read all fields. This completes the fix for GHSA-4h7h-rv7c-7m2v. The validator now decides by the media type alone, as <code>c.req.parseBody()</code> does. GHSA-92p4-j3wq-jmqx</p>
<h3><code>bodyLimit()</code> keeps every transfer chunk of a request body in memory</h3>
<p>Affects: <code>bodyLimit()</code> in <code>hono/body-limit</code>. A body sent in very small transfer chunks was retained as one object per chunk, so a request within the configured limit could exhaust memory. The body is now buffered in one array bounded by <code>maxSize</code>. GHSA-39q9-qp46-w8xg</p>
<h3><code>mount()</code> and <code>app.mount()</code> forward a wrong path when a custom <code>getPath</code> adds a prefix</h3>
<p>Affects: <code>mount()</code> in <code>hono/mount</code> and <code>app.mount()</code> on 4.13.16 and 4.13.17. With a <code>getPath</code> that prepends a prefix such as the host name, one segment too many was removed from the forwarded path, so middleware scoped inside the mount prefix could be skipped. The prefix is removed from the routed path again. Paths that would change meaning when forwarded now get 400, and an optional regular expression parameter in a mount path throws. GHSA-h25j-2p75-qj33</p>
<h3><code>serveStatic()</code> serves a path that was decoded twice when <code>allowPercentInPath</code> is enabled</h3>
<p>Affects: <code>serveStatic()</code> in <code>hono/serve-static</code> and the runtime adapters, only with <code>allowPercentInPath: true</code>. A malformed percent escape in the request path was decoded a second time, so a path that middleware registered on the encoded form did not see could still reach a static file. The file path must now be the same as the routed path, and otherwise the response is 404. GHSA-74fm-fwc7-3fwp</p>
<hr />
<p>Users who rely on <code>validator()</code>, <code>bodyLimit()</code>, <code>mount()</code> with a custom <code>getPath</code>, or <code>serveStatic()</code> with <code>allowPercentInPath</code> are strongly encouraged to upgrade to this version.</p>
