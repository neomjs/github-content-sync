Resolves #917

The cockpit's state provider now keeps `shellTransport` and `presenceCapability` whole. `state.Provider#setData` drills an object into leaf paths and stops the bubble at a parent whose value is not an object. Both keys were declared `null`, so every write to them was dropped. They are now declared leaf-complete, the rule the Viewport provider already states ("a block declared null would stop the leaf bubble on its first real answer"). Their writers write the full key set every time (`BrainHealthRead.transportOf`, `FleetAdmission.presenceCapabilityOf`), so no key of a previous fact survives. A transport with no `phase` reads as no fact.

With the plane down at launch, the spine now reads `Agent OS starting · N s`, then #847's `Agent OS not answering · N min` from 180 s, never the roster's `fleet timed out`. The grid's presence chip receives the envelope for the first time.

Evidence: L2 (specs on the real cockpit `StateProvider` over the engine's `state.Provider`; controller and bridge faked) → L4 required (AC-4: the H1 re-walk on an installed candidate with the plane stopped at launch). Residual: AC-4, Residual-Owner: #424.

Change class: restoration (`fix`). agent-preflight: not hosted here; the shared `PR baseline` runs on open.
