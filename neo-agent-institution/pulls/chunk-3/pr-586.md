**RA-1: the identity is one literal argument, or there is no command.**
- `Participation.commandOf` offers a command only for a plain handle: an optional `@`, then letters, digits, `.`, `_` or `-`, starting with a letter or digit. Anything else gets no command and is never escaped, so the copied string carries exactly the identity the row names. Escaping was rejected deliberately: one quoting rule cannot hold for every shell an operator may paste into.
- Controls in the new `util/participation.spec`:
  - A plain handle tokenizes into exactly one `--identity` carrying the intended identity, in shell-inert words. The cases are `neo-preview`, `@neo-gpt-sophie` and `user.name_2`.
  - `agent-a --identity @agent-b` gets no command, and neither do its companions: quotes, whitespace, `;`, `$(id)`, backticks, `|`, `&`, a leading dash, a bare `@` and the empty string. The group then says "No command is offered: the seat's identity is not a plain handle."

**RA-2: where it runs follows the deployment the shell is bound to.**
- `Participation.instructionOf(record, planeBase)` offers the command only where the shell is attached to a plane (`boundAgentOsBind`'s `shellPlaneBase`, the shell's status):

  - "Run it on the plane host <host>, where its Memory Core runs (…)" for any other.
- The container is named only as the Docker case, not assumed.
- The shell's own plan (`planeBase: null`) runs the Brain as a host process with an environment a terminal command would not inherit. The view cannot name a command that reaches that graph, so it offers none and says why. An unparseable base reads the same.
- `detail/container.spec` "#568" tests the own plan, a loopback plane and a remote plane separately. A visual driver attaches the views to a plane. Golden `participation-own-plan` shows the group without a command, and the attached goldens were re-captured.
