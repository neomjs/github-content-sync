Accounts gets a **Repositories** card under the configuration card. It lists the seat's working repository, then its other repositories, and adds or removes them. Each change sends the seat's whole list as one `setRepos` through the existing configure round-trip. The Brain judges the list, and a refusal shows the Brain's own reason while the rows keep what the registry holds.

## Deltas from ticket
- **Container, not Component.** The card is `AgentOS.view.fleet.detail.AgentReposContainer`, because it extends `container.Base`, and `viewTopologyConformance` holds the suffix to the base family.
- **No add without a working repository.** The Fleet refuses other repositories until the seat has one, so the card disables its add row there and its empty line says why.
- **Owner per card.** The round-trip stays silent when a request is superseded by its own owner, which assumes one status sink per owner. The Repositories card passes itself as the owner, so a race with the configuration card paints `superseded` instead of latching `pending`. Its save statuses are kept apart from the configuration card's.
