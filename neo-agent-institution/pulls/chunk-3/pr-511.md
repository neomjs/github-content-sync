Resolves #501

The Agent Detail's fourth pane, Pull requests, used to say "source not wired" while the cockpit already held the answer: the open-work read behind the roster card's chip (#483). The pane now lists the pull requests whose next action the seat holds, worst first (`red` > `changes requested` > `review due`). Each row is a reference that links to the forge, over one line in the chip's own words (role · state · age). The rows are a `Neo.list.Base` bound to a Store of `HeldPullRequest` records, fed from the same answer. The pane's pill ages from the read's observation, and it reads stale as soon as the producer reports a failed refresh, however recent the observation. When the seat holds nothing, the pane says "no pull request waits on this seat". When the read has not answered, the pill says "not observed — open-work read unanswered" and no list renders.

There is one answer and one resolver. `OpenWorkSeat.held` returns the seat's rows, keyed `<repo>#<number>`, or `null` when the read has not answered. `summarize`, which the chip uses, now counts those same rows. `OpenWorkRead.seatOpenWork` writes both record fields (`openWork` for the chip, the new `openWorkHeld` for the pane) in one write at all three stamp sites. That way the card and the detail cannot drift within a tick.

Evidence: L2 (unit arms over real Stores and the real resolver, the NL drill e2e reading the mounted DOM against a landed answer, the full visual suite) → L4 for the installed cockpit, which is AC-5 after the next #12 cut. Residual: AC-5 only.
