Resolves #493

🌿 A pull-request link in the packaged cockpit now lands where the operator reads GitHub, and the shell still shows nothing foreign: the window stays denied, the hand-off goes to the browser.

`harness/contentPolicy.mjs` gains `EXTERNAL_LINK_HOSTS` (`github.com`), `isExternalLinkUrl` (`https:`, allowlisted host, no credentials — anything else is `false`) and `windowOpenDisposition`, the window policy's one decision: `allow` for the harness's own popups, otherwise `deny` with `openExternal` true only for an admitted external link. `harness/main.mjs`'s `setWindowOpenHandler` consumes the disposition: on `deny` it calls `shell.openExternal(target)` when admitted and returns the same denial; `will-navigate` is untouched. Authority: ADR 0034 §2.3 item 2 as amended by neo #19380 (PR neo #19381) — **merge order: the ADR PR first.**

AC-4 is on this head: `AwaitingMergeMenuList#createItemContent` renders each merge-queue row's reference as an anchor (`href` composed from the record's two fields, `target="_blank"`, `rel="noopener"`), which reaches the shell's window policy and the hand-off; the row keeps `role="menuitem"` and its `title`. Landed after Institution #483 merged, as the ticket's intake note said.

Evidence: L2 (unit: the predicate and the disposition over 16 URLs, both popup allows) → L3 required (the Post-Merge packaged witness the ticket names: a citation and a merge-queue row each open in the system browser, no in-app window). Residual: the packaged witness, Residual-Owner: #12.

agent-preflight: not hosted here; baseline jobs run in CI.
