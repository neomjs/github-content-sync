Resolves #416

🌿 The cockpit stops reading an inbox nobody has scrolled to, and the plane stops paying for it at every boot.

Since #40 the operator mailbox pane requested the next window the moment a window landed, until `hasMore` turned false. On the team plane that is 173 Memory Core pages over three minutes at every cockpit boot, one page per second, and every other read on the plane waited behind them: the Observatory's first `get_graph_scene` (row 3's first useful paint) outlived the client's deadline three times on 2026-10-02 07:35–07:38Z and completed in 11 s once the drain had ended. The pane now loads one window at boot and asks for the next only when the grid reaches the loaded end.

- **The pane** (`mailbox/Container.mjs`). `applySnapshot` projects and requests nothing. `onScrollEdge` fires `pageRequest` at the next offset under two gates: the last snapshot's `page.hasMore`, and one request in flight (`pendingOffset`, cleared by every landed snapshot). The relay and the cockpit's read are unchanged.
- **The seam** (`mailbox/Body.mjs`, new). The engine's `grid.Body` plus one event: after `updateMountedAndVisibleRows`, `scrollEdge {startIndex, endIndex, count, total}` once per entry into the store's last `bufferRowRange` rows, re-armed only by a change of the VISIBLE count, so a parked viewport is quiet and a short first page announces on first layout. The grid relays it. Interim: neomjs/neo#19356 landed the event on the engine's body (merged); the pin that carries it deletes this class (#429).
- **Continuation is deliberate.** A landed window the collapse filter hides entirely (fifty replies under one collapsed head: visible count unchanged, total moved) reveals no row, so it ends that gesture's reach and the pane asks for nothing more; the head's "+N earlier" count carries what arrived, and expanding the thread, the pane's own toggle, is how the operator continues into it, after which the edge asks for the next window as usual. Re-arming on the hidden total instead (tried at 680f6c2, withdrawn at Sophie's second read) walks a collapsed inbox window by window with no gesture: the boot drain under another projection. The total travels on the event as information.
- **Not changed.** The mirror adapter, the Memory Core's page cost (~1 s per 50 rows, defect-note 2026-10-02), the memories pane's own drain (same seam, separate leaf), the client timeout, the scene payload.

Evidence: L2 (unit: the pane's gate, the body's edge math on the engine's own method, the relay) + L3 local (Neural Link, Chromium, a 60-row fixture inbox: one boot read, one read at the announced edge, the append, nothing at the honest end) → L4 required for AC-6 (the installed FM at the operator's viewer: one `list_messages` page in the Memory Core log at boot, the first `get_graph_scene` under the deadline). Residual: AC-6, Residual-Owner: #312.
