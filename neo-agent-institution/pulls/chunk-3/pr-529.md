Resolves #527

🌿 The Observatory's side panel can no longer be a width the operator has to live with: they drag it between 280 px and half the body, and the session keeps it.

Built on #528's side panel, merged 2026-10-04 as `ea906aa`. This PR is one commit on `dev`.

The engine's `Splitter` sits between the canvas and the side panel and resizes the panel. Its bounds are the panel's CSS `min-width: 280px` and `max-width: 50%`, which the engine's main-thread drag clamps against, so no clamping code is added. Nothing stores the width, so a reload starts at the 320 px default. That is the design seat's decision for a single pane: a remembered inside waits for a second pane, then becomes an engine leaf. The splitter speaks the dock splitter's flat language and is the panel's edge, so the panel draws no second line.

Evidence: L2 (a real drag in the visual harness at this head) → L2 required (AC-1 to AC-3). Residual: AC-4, Residual-Owner: neomjs/neo-agent-institution#485

## Deltas from ticket

- AC-1 and AC-2 are visual arms, not unit arms: the engine clamps on the main thread against CSS, and the unit harness mounts no canvas. The ticket's ACs are amended to say so.
- The splitter is inserted with the canvas, and its half-body cap sits on `.fm-observatory-splitter + .fm-observatory-side`. Without a canvas worker there is no splitter and no cap, and the side panel is the whole body.
- **A pre-existing defect is fixed here** (round 1, Sophie): the no-canvas branch assigned `flex = 1` after the layout had copied flex into the style. The fallback panel therefore sat at 320 px of a 1552 px body, and had since that branch landed in #258. It now sets both, the idiom `syncSections` uses.
