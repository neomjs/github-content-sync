Resolves #415

A PR's Activity row now names its state and review verdict (`brain#739 · forge host · approved`, then `· merged`), and the row redraws when its event changes in place. Before, a review and a merge both just moved the row's time, so FM v1 row 4's two human gates were invisible (#414).

- `getPullRequestStatus(event)` reads the `pr-activity` payload the Brain already sends. `MERGED` or `CLOSED` name themselves. An open draft reads `draft`. Otherwise GitHub's `reviewDecision` gives the verdict, or, where the repository computes none, the Brain's `humanGateState` from the latest reviews. Anything it can't read adds nothing.
- `RowContainer` reacts to `lastRecordVersion`, the version `Neo.list.Buffered` stamps before every bind. An upserted event keeps its record instance, so `afterSetRecord` never fired and the row kept its first rendering until recycled. The row now redraws when the record it shows has moved past the version it last drew; a recycle still draws once. The store is unchanged.

Evidence: L2 (unit + visual, red-first) → L4 required for AC-5 (a real PR on the installed candidate). Residual: AC-5, Residual-Owner: #414.
