Resolves #506

The Memories view reads a memory whole. Selecting a session summary or a turn opens it in a reader beside the list: the summary's full text, or the turn's prompt, thought and response, each with a Copy action. While the reader is open, the list narrows to a rail. ↑/↓ move the selection, Escape closes the reading, and *Show all* reads every loaded record as one document whose rail follows the scroll. Room comes from the dock's own maximize. Nothing new is fetched, because the wire already carries every record whole.

Evidence: L3 (rendered in local Chromium against a real Fleet bridge server at the Brain pin; the design read ran on the dev server with fixture text at real lengths) → L3 required on the installed app (AC-6). Residual: AC6, Residual-Owner: #12.

Records arrive whole:
- `summary` comes from `get_all_summaries` via `SummaryService.listSummaries`. A real one on the plane is 1,148 characters (session `c4499e07`); the old card showed two lines of it.
- `prompt`, `thought` and `response` come from `get_session_memories` via `MemoryService.listMemories`, which returns `metadata.*` uncut (`ai/services/memory-core/MemoryService.mjs:1400-1402` at the Brain pin `fb40366`). `fleetSessionMemoriesSource` and `fleetMemoriesSource` pass the rows through.

## Deltas from ticket
- **AC-2:** *show all* reads the register as one document in the reader. Each record's header stays in view, and the rail's selection follows the scroll. The engine grid's fixed row lattice cannot grow a row in place. Agreed with the design seat.
- **AC-3:** *Take the main area* is the dock's existing Maximize plugin. It is on by default, presentation-only, and leaves saved perspectives untouched. The pane gets no mode of its own.
- **AC-4:** no full-record read by id, because records arrive whole.
- **Narrow regime, pane width ≤ 720 px:** the pane shows the list or the reader, never both. While reading, the rail collapses behind the reader's back breadcrumb.
- **Escape order:** with focus in the dock header, Escape restores a maximized node before the pane closes the reading (JSDoc on `ReadingController#onEscape`).
- **Structure:**
  - The reading orchestration is its own `ReadingController`. The pane goes from 608 to 690 lines, under the 900 warn.
  - The reader is `ReaderComponent`, per the suffix law.
  - The grids use the engine's `RowModel`, which closes the selection/keyboard residual the memories design page records.
