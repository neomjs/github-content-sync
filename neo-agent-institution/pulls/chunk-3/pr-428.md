Resolves #426

🌿 The operator can read their own inbox in the cockpit again, and nobody has to write before they can read.

The cockpit's operator mailbox rendered no rows at any window height: the compose form sat permanently under the inbox at its natural height (about 560 px) and the inbox was pinned to a 96 px floor, under one 84 px row, so the engine derived zero available rows (measured at 1280×720 and 1440×1800: a 48 px body in both). The mailbox design page already placed compose as a right-pinned affordance in the pane head; this PR ships that reveal.

- **The chip.** The inbox pane's head gains a `mailbox-head` reference (a slot for the host), and the operator host adds `✎ compose` there inside a `fm-pane-actions` group, so the pane-head law sizes it at chip scale (the law's own arm, "no button at a slab's scale", stays green).
- **The reveal.** `OperatorContainer.composeOpen_` (default `false`) keeps the form out of the layout (`hidden`, remove-DOM). The chip's handler is a string resolved against the host (a bare function handler runs against the button and toggles the wrong instance); the chip reads pressed while open; Escape inside the form folds it; a send never does.
- **The floor, from the lattice.** `.is-composing > .fm-mailbox-pane { min-height: calc(23px + 6px + 20px + 84px + 8px) }`: head + gap + the grid's own chrome + one row + slack, because the engine derives its row count from the measured body. Folded, no floor is needed: the inbox takes the strip.
- **Unchanged.** The compose intents, the recipient options, the identity-warning marker, the inbox read relay, #420's scroll edge.

Evidence: L2 (unit: the reveal's state machine through the button's own click path; the head slot) + L3 local (Neural Link, Chromium 1280×720: rows render, the chip reveals over one row of context, Escape folds; the two compose journeys open the reveal first; the visual law arm and the re-captured golden) → L4 required for AC-6 (row 4's installed sitting, #414). Residual: AC-6, Residual-Owner: #414.

## Deltas from ticket

- **One full row, not two, is the closed-state guarantee at 1280×720.** The ticket's AC-1 asked for two; the strip's own height bounds the count (grid 147 px → one row with 63 px to spare; two need 169). The AC is restated to the measured guarantee; the journey reads the engine's `availableRows` instead of a box whose height was the 4284 px scroll content (Sophie's evidence check on the first head).
- **The floor counts the grid's chrome.** The ticket's sum (head + row + rhythm ≈ 119 px) left a 71 px body, under one row; the engine reads the body, so the floor adds the grid's 20 px of chrome and 8 px of slack (141 px).
- **The chip lives in a `fm-pane-actions` group**, not bare in the head: the pane-head law sizes head verbs through that group, and a bare button rendered at slab scale.
