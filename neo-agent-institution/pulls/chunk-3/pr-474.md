Resolves #473

🌿 The folder that used to grow by one launchable copy per refresh now holds the one app in use, and "which build is installed" is no longer a question the version label is allowed to answer.

`harness/install.mjs` (`npm run install:mac`) is the last mile of the E6 packaging leg: it resolves the one bundle under `dist-artifacts/mac*/`, prints the installed, rollback and artifact receipts, copies the artifact beside the destination and renames it into place, and moves the displaced bundle to the single rollback slot under the app's own Application Support root — outside `/Applications`, replacing whatever held it, under a name without the `.app` suffix so Launch Services never registers it as another launchable copy. A running Neo Harness is a refusal (`--quit` is the only way it stops one, through the app's own quit addressed to the canonical bundle by path — every build shares one identifier and this machine had 17 registered copies — warning that launched peers stop too); an app running from a non-canonical path is refused by path; equal receipts end the run with nothing replaced; `--restore` swaps the slots back; `--dry-run` prints the plan. The `brain/fleet` custody files are hashed before and after and a change fails the run. The planner is pure and the executor's child-process runner is injectable, so the spec drives real renames on temp directories. The README's hand-copy procedure becomes the command.

Evidence: L2 (unit: pure planner + executor on real temp directories, the census through the real `ps`-text reader, both restore interruption boundaries, a corrupt staged copy, the two custody timings; against the live machine a `--dry-run` only — today's installed app is the #12 cut boundary) → L3 required (AC-1 and AC-5 against `/Applications`). Residual: AC-1/AC-5 live run (install AND restore), Residual-Owner: #12.

agent-preflight: not hosted here; baseline jobs run in CI.

The plan/execute split, stage-then-verify, the single rollback slot, the custody hash and the interrupted-restore recovery all read sound. Staging is also safe against a leftover `.installing`: `executePlan` removes it before `ditto`, so nothing merges.

One finding, measured on this machine today. **Leaving /Applications does not stop a copy from launching.** Spotlight lists 17 bundles with id `mjs.neo.harness`: `mdfind "kMDItemCFBundleIdentifier == 'mjs.neo.harness'"`. That's `/Applications/Neo Harness.app` plus the 13 relocated backups under `/Users/Shared/neo-harness-backups/` (16 GB) and 3 more under `/Users/Shared`. Every one of them is a launchable app with the same bundle id and version `0.0.1`, so:
- searching "Neo Harness" in Spotlight offers all of them, which is the operator's "too many versions" complaint in a different place;
- the id-based steps resolve through LaunchServices, which has 17 equal-version candidates to pick from: `quit` sends `tell application id "mjs.neo.harness"` (`install.mjs:207`), and `open -b` behaves the same way. Whether the quit reaches the running copy depends on that pick. I did not test it, because it would quit the operator's running app. Quitting by path removes the dependency.

Suggestions (non-blocking; the author decides):
1. **Quit by path**, not by id: target `/Applications/Neo Harness.app` itself, the one copy this leg owns.
2. **Keep the rollback unregistered.** After the move, run `lsregister -u` on the rollback slot, or store the slot under a non-`.app` name that `--restore` renames back, so the rollback is never a second launchable copy.

The relocated legacy backups belong to Emmy's #12 lane, not this PR.
