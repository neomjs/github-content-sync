### 🔬 Depth Floor

**Challenge OR documented search (per guide §7.1):**

- **Challenge** (non-blocking): `SeatRootContainer.sync()` writes `text`, `hidden` and `disabled` to the same child instances as separate assignments (`recheck`, `review`, `consent`, `feedback`). Each of those instances takes two update passes where one `set({...})` would batch them (core-idiom check 1). The System view's own `connection.hidden` / `connection.text` does the same, so this follows local precedent rather than breaking it.
- **Documented search, run as falsifiers.** I looked for three failure modes and found none:
  1. **A double destroy of the move Store.** `destroy()` destroys `moveStore` before `super.destroy()`, and `list.Base` defaults to `autoDestroyStore: true`. A throwaway spec at `7ebce5a2` built and destroyed the section: the store was destroyed once, with no error, because `SeatMoveList` sets `autoDestroyStore: false`. The spec was deleted.
  2. **A relaunch racing the old Fleet child into a `held` boot.** `relaunch` calls `app.quit()`, and `will-quit` awaits `teardownOwnedBrain()` before the final quit.
  3. **The broker's planning env reading a different registry from the boot's.** The registry keys on `fleet.dataDir`; the emptied agents-root override changes only the destination resolution.
