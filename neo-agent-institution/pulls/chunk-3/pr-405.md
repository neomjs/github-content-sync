Resolves #400

🌿 A Finder-launched FM now knows where the host wake receiver is, so "the Fleet was never told" is no longer a reason a seat it launched stays dark.

On each packaged launch, `main.mjs` settles the receiver once (`harness/wakeReceiver.mjs`) and passes it to the Fleet child, the receiver's only consumer. Settling tries three sources in order:
1. The launch environment, when it carries both `NEO_WAKE_RECEIVER_MANIFEST` and `NEO_WAKE_RECEIVER_BASE`.
2. Otherwise, the receiver's own LaunchAgent (`~/Library/LaunchAgents/com.neomjs.agent-os-wake.plist`). Its `--manifest` is the manifest path. Its `--port` becomes `http://host.docker.internal:<port>`, but only while the Fleet attaches to a plane on this host.
3. Otherwise, nothing.

The LaunchAgent is parsed strictly as a property list, and one that cannot be read is a named refusal, never a guess. A packaged launch that settles nothing clears both coordinates in the Fleet child's env, so an inherited half never reaches it. Every launch logs `HARNESS_WAKE_RECEIVER {origin, manifest, base, reason}`.

Evidence: L2 (unit specs over the settle order, the LaunchAgent reader against fixture plists on disk, and the env fragment; the `main.mjs` wiring and log line are pinned in `pack.spec.mjs`) → L4 required for AC-4 (an installed FM's freshly started seat woken by a peer). Residual: AC-4, Residual-Owner: #7.

## Deltas from ticket

- **The receiver joins the Fleet child's env, not `buildPackagedBrainEnv`.** The plane base it depends on is known only after the packaged profile resolves, and the packaged smoke shares that profile. AC-1 and AC-3 were restated in #400's body at implementation, with a dated note.
- **The LaunchAgent is parsed as a whole property list in JS, not through `plutil`.** CI runs on Ubuntu and has to run the adversarial fixtures. Only the XML declaration and the DOCTYPE may precede the root, and anything a plist reader would skip refuses. On this machine the real installed LaunchAgent reads the same port and manifest as `plutil -extract`. A binary plist is a named refusal that names `plutil -convert xml1`, which restores the XML the runbook installs.
- **A declined resolution exports `''` for both coordinates rather than omitting them.** `startBrainChild` merges `process.env` beneath its fragment, and its own JSDoc says a fragment can override an inherited variable but never remove one. The Brain reads `''` as undeclared. An unpackaged launch still inherits.
- **#400 carries a Contract Ledger** for this launch boundary: the coordinates, precedence and local-plane policy, the strict read and its refusals, and the log line.
- **Merge order with Brain neomjs/neo-agent-brain#705 is free.** The current Brain pin already reads `NEO_WAKE_RECEIVER_MANIFEST` (`fleet.wakeReceiverManifestPath`), so the installed Fleet's seat-arming read stops being "typed-unobserved" as soon as this lands. `NEO_WAKE_RECEIVER_BASE` is ignored until a pin carries that PR, and from then on the seats arm.
- **#400 is now a sub-issue of #7**, beside Grace's seat-root sibling #396. #7 holds 24 sub-issues.
- **No consumer deletion.** This is a new reader of a declaration that already exists; the runbook keeps installing the receiver.
