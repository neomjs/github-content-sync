Resolves #425

When a plane-attach boot is refused, the shell now asks the plane once with the same probe the connect card uses (`probePlaneCredential`). It types the refusal by the answer: `plane-unreachable`, `plane-credential-refused`, `plane-not-a-plane` or `plane-identity-changed`, with the plane's address as the detail. The spine banner speaks each in the card's own sentence and offers Connect. The fleet child's config advice (`fix fleet.planeBase / fleet.planeBearer…`) stays in the main log. It probes only a launch the stored record supplied, within one overall deadline. Anything the probe cannot tell apart keeps today's `plane refused`.

Evidence: L3 for the probe hop (the real probe against a dead port and against the live local plane with a bogus PAT) and L2 for the banner → L4 for an installed boot, the row-5 sitting. Residual: AC-1/AC-2 on an installed boot, Residual-Owner: #424.
