Resolves #495

🌿 The guard that stopped the first real install now fires only on what it was built to protect: the plane record, the fleet's own files, and which seats exist — never on the bundle the leg had just replaced, seen through a seat home's link.

`custodyDigest` is keyed on the userData root and hashes, without following any link: `plane.json` · `plane-bearer.bin` · `seat-root.json` when present; every depth-1 entry of `brain/fleet` — a regular file by bytes, a symlink by its target string, the `agents` directory by its sorted entry names, any other directory by name. The first real run (Emmy's #12 retry at `e1a9dbe`) proved the old digest wrong twice over: it walked the seat homes (53,945 files) and Node's recursive `readdirSync` followed their `.neo-ai-data` links into `/Applications/Neo Harness.app/…/organism/.neo-ai-data/`, so a correct swap read as a custody change and the relaunch was refused while 53,944 files and 118 links were physically unchanged. The plan's custody steps carry the userData root; README states the hashed set and that seat homes and link targets are not read. On the installed machine the new digest reads in 7 ms and is stable across two calls.

Evidence: L2 (unit: the falsifier as arms on a userData fixture with a seat home linking into an "organism" directory; executor custody arms re-keyed) + L3 read-only (the live digest, twice, stable) → L3 required (AC-5: the next `install:mac --quit` completes its comparison and relaunches). Residual: AC-5, Residual-Owner: #12.
