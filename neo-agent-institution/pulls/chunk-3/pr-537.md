Resolves #523

A walker can now hold the fixture-plane smoke open and walk the installed candidate's failures against a plane that is the run's own.

- **Hold:** `NEO_HARNESS_SMOKE_HOLD=1` acts only in the fixture-plane arm. Set anywhere else, the harness refuses before anything starts, so it never attaches to or takes over the organism on this machine. A held run stops after its plane observations, with the organism attached and the window open. It names its candidate and auth mode, and writes a walk manifest under its smoke root. Closing the window quits through `window-all-closed` → `will-quit`, the owned-Brain teardown that `exitTerminal` runs. That teardown closes the walk control first, so no plane request starts after it and the one in flight settles before the children drain.
- **Control:** `harness/walkControl.mjs` acts only on what that manifest names: the fixture plane id, the smoke root, and a registry inside that root once its links resolve. Token writes go to the resolved file.
  - `plane stop|start` goes through a control file the held run watches. The answer carries the handler's result, and a stop answers `ok` only once the plane's process group is gone.
  - `token revoke|remap` rewrites the fixture's seat-token registry, which the plane's verifier reads on its next request.
  - `cleanup` removes the smoke root once the run and both plane ports are gone.

Contract Ledger: on #523 (the flag, the manifest, the CLI, the accepted target, the stop answer, the control lifetime, cleanup).

Evidence: L2 (unit: real temp roots and the Brain's own seat-token helpers; a stand-in plane process on a real port) → L4 required for AC-4's and AC-7's held-run receipts (an installed candidate, cut A). Residual: AC-4, AC-7, Residual-Owner: #516.

## Deltas from ticket

- **The fixture plane's child is drain-owned, never a Brain claim** (`observeBrain: false`). Observed, a `plane stop` would have surfaced as the shell's `owned-child-termination` health, which a real remote plane outage never produces, so the walk would have recorded words the product never shows. In an ordinary smoke the child lives until teardown. The only change there is one diagnostic line at teardown (`HARNESS_UI_FLEET_CHILD plane: …`).
- **A held run seeds a second identity**, `@neo-harness-smoke-remap`, so a remap names another account the plane holds. A remap to any identity outside the graph is refused, because the plane would answer it as unknown, which is a different failure.
- **`walkControl.mjs` joins the packaged main's module set** (`electron-builder.yml`, and the closure list in `pack.spec.mjs`). Without it, the installed candidate this walk targets could not start.
- The plane's stop/start handle is `createPlaneProcess`, extracted so it is testable without booting a Memory Core.
