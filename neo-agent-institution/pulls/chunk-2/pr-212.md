Resolves #211

A packaged shell now attaches to a plane from its own record, and the cockpit offers to create that record. Until now a Finder double-click booted in own-mode ("NO INSTANCE", the sample roster), because the shell learned its plane only from the environment variables that the launcher script exports.

- **Boot seam** (`harness/planeConfig.mjs`, `main.mjs`): `plane.json` under `userData` names the plane base, and the viewer's PAT sits beside it encrypted by `safeStorage`, or is not stored at all. At boot the record joins the packaged env fragment as `NEO_FLEET_PLANE_BASE` + `NEO_FLEET_PLANE_BEARER`, the launcher's variables. A variable already set wins. The stored bearer never follows a plane base that came from somewhere else, and a plain-http base is refused unless it is loopback.
- **Broker pair** (ADR 0034 §2.3.8): `planeStatus()` reads whether a plane is configured. `attachPlane({planeBase})` has main prompt for the PAT in its own window (the existing `promptFleetCredential`), check it with one authenticated `GET` on the plane's MCP route (a bare 401 refuses), store it, and relaunch. Neither reply carries the PAT.
- **Card** (`view/PlaneSetupPanel.mjs`): inline under the top chrome, dismissible, and never a gate. It shows only in a packaged shell with no plane configured, and reaches main through a workspace main-thread addon (`WS/ShellPlane`), so there is no engine remote and no pin bump.

Evidence: L2 (unit arms over the record, the broker, the preload surface, the addon and the card; the packaged double-click needs the operator's machine) → L2 required (AC-3, AC-4) and L3 for AC-1. Residual: AC-1's live receipt, Residual-Owner: #12.

agent-preflight: not hosted here; the CI jobs ran.

## Deltas from ticket
- The PAT prompt runs from a shell-owned IPC handler, not through the Brain's `FLEET_CREDENTIAL_METHODS`: `promptFleetCredential`'s `method` only picks the label, so the fleet contract is untouched.
- The renderer reaches main through a workspace addon instead of an engine `Neo.Main` remote. `neoShell`'s existing calls are engine remotes, and a new one would need a neo change plus a pin bump.
- The card sits in the Viewport rather than the cockpit container, which is at 999 of `checkAppFileSizes`' 1,000 lines.
- Fix item 3 (the packaged smoke's fixture-plane arm) is proposed as its own leaf in issuecomment-5835819412: the harness smoke has no CI job, and a packaged fixture run writes to the login keychain of whoever runs it. The ticket's ACs are the author's to amend.
