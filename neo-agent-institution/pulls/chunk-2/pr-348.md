Resolves #347

🌿 Replacing the app no longer deletes part of the plane, and own mode no longer keeps two graphs.

`buildPackagedBrainEnv` now relocates the plane (`NEO_PLANE_DATA_ROOT`) and places all 27 members declared across the four Brain config bases' `PLANE_MEMBER_PATHS`. Nineteen of them had stayed inside the app bundle (census on #347). Among them was memory-core's graph, `NEO_MEMORY_DB_PATH`. It now names the same file as the orchestrator's `NEO_AI_DB_PATH`, which alone had moved before.

Both harness profiles also set `NEO_AI_DEPLOYMENT_MODE=local`. The Brain's `cloud` default had turned Chroma and the embed and message daemons off in own mode (Grace's find, AC-4).

Relocating the anchor switches on the Brain's own `assertPlaneMemberCoherence` for this profile, so a member added later without a placement fails boot instead of landing in the bundle. `brain.spec` runs that same check in CI.

Evidence: L2 (the Brain's configs resolved under the packaged env in a Brain child; no installed boot) → L4 required (AC-3 on an installed own-mode build). Residual: AC-3, Residual-Owner: #12.
