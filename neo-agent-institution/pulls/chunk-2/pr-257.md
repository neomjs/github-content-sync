Resolves #255

An open cockpit stops being the plane's heaviest caller. Each liveness read now comes due on its own interval (`AgentOS.util.LivenessCadence`), instead of all five reads riding one 15 s tick: roster and activity every 60 s; tasks, deployment state and Brain health every 120 s. The 15 s pass only checks which reads are due. A hidden cockpit issues nothing, and its return launches what fell due, once. At the defaults, ten minutes of passes launch 35 reads where the shared tick launched 200.

Evidence: L2 (unit arms drive the controller's real start / pass / visibility paths and the pure cadence; I did not run a second cockpit against a plane this tick already saturates) → L3 required (AC-1: the Memory Core call count with the cockpit open for 10 minutes). Residual: AC-1, Residual-Owner: #10.

## Deltas from ticket

- **No skip-a-turn backoff** (AC-3 reworded on the ticket to match). I built it literally, and it turned two existing arms red. One is the latch falsifier "a hung read must not suppress the probe that would notice recovery". With the 10 s bounded window under 60–120 s intervals, the skip bought nothing the cap does not already bound, and it delayed recovery detection by a full interval. Rationale and proposed AC-3 wording: https://github.com/neomjs/neo-agent-institution/issues/255#issuecomment-5849136819
- **Activity is polled at 60 s, not wake-driven.** The viewer wake stream carries only the operator's own wakes, not the fleet's activity, so it cannot replace the activity poll.
- **The system lane's instant** is now published on every pass that launches no deployment read, not only when that read hangs at the cap. The System view's picture keeps aging between its 120 s reads.
- **Three comment refs reworded** in the two e2e specs this PR touches (`RA-3`, `#23`). The archaeology gate audits whole changed files.
