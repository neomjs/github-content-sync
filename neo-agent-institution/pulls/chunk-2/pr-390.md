Resolves #388

When a harness's stdio reader goes away, `mainLog.install` now drops the terminal half quietly instead of raising an uncaught EPIPE per log line. Electron showed each of those as a modal dialog. `main.log` names the closed terminal once and keeps every line.

`harness/mainLog.mjs`: `install(target, terminal = [process.stdout, process.stderr])` attaches one persistent `'error'` listener per terminal stream. The first terminal error writes `HARNESS_TERMINAL_CLOSED <code>` to the file; later ones only drop.

Evidence: L3 (a real Electron 43.5.0 main, its stdio piped into a reader that exits at once). Residual: none.

| AC-4 | The same reproduction with a live reader (`\| cat`): 0 uncaught, all 40 lines on the terminal and in the file, no closed line. |

## Deltas from ticket

- **The file line has a name:** `HARNESS_TERMINAL_CLOSED <code>`, in main's `HARNESS_*` vocabulary. The ticket only asked for "one line naming the terminal error".
- **The existing tee arm passes `[]` as its terminal**, so the spec never attaches listeners to the worker's own streams.
