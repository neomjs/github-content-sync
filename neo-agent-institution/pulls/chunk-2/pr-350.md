Resolves #214

`npm run smoke:plane` proves the stored-plane boot end to end, on a checkout and on a packaged build. `harness/fixturePlane.mjs` starts the Brain's Memory Core in `seat-token` mode on a loopback port, with every plane member it claims under the smoke root. It seeds and mints one seat (`@neo-harness-smoke`) and serves it behind a loopback `/mc` ingress. The shell then attaches the way the cockpit does. The product probe names the seat's identity, and `writePlaneConfig` stores the record in the smoke's own `userData` through a stand-in whose key lives only in the run. The fleet child then boots `plane-attach` from that record through `readPlaneConfig`, `planeEnvFragment` and `resolveProductBrainPlan`. Every census sink now tests all the secrets main holds, and a diagnostic run owns its `userData` and its logs.

Evidence: L3 (real Electron, Memory Core and fleet child on this machine, checkout and packaged; no CI job runs the harness smoke) → L3 required (AC-1 to AC-4 are facts of a live boot). Residual: AC-4, Residual-Owner: #347

## Deltas from ticket
- **The seat needs a graph node.** On Brain `dev`, a seat binds a request only to an `AgentIdentity` its graph holds. The fixture therefore seeds its seat through the Brain's own `seedAgentIdentities` before the plane boots, and it runs the plane on a file-backed graph: `UNIT_TEST_MODE` would swap in `:memory:`.
- **The owner marker is hidden from every entry.** The Memory Core's CLI (commander) refuses `--neo-harness-owner`. Every supervised child now loads a `--import` data-URL preload that drops the marker from `process.argv`. `ps` still shows it right after the entry, and that is what the crash sweep verifies. Red-first: under the old argv, a real child printed the marker.
- **Two sinks the ticket did not name.** `HARNESS_PAGE` printed every renderer console message raw before any census; it is now redacted and recorded. A diagnostic run appended to the installed app's `main.log`, which already held a packaged smoke's result lines from 12:08Z today; it now logs under `<root>/logs`.
- **The leak arm never hands the renderer the bearer.** Its first shape threw the bearer inside renderer code built around it, and CodeQL flagged that construction. The renderer must never hold the credential in any case, so the arm enters each sink in main, and AC-3's renderer entry is the console sink.
- `resolveBrainPaths`' child runner is now `runBrainScript`, which the member resolver and the seeder share.
