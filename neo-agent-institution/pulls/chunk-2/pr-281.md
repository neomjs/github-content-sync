Resolves #280

Add agent now asks who launches the seat. The default is "It already runs in its own harness", which registers `launchOwner: 'external'` with no PAT:
- the PAT field hides in both forms;
- validation stops requiring it;
- the shell forwards the define as public intent without calling the credential provider.

"Fleet launches it" keeps today's PAT custody unchanged. The Brain pin moves to the merge of neomjs/neo-agent-brain#566, where an explicit launch owner stamps `launchOwnerSince` in the same write, so an external seat is refused a Start from birth.

Only the shell registers an external seat: its Fleet is that pinned Brain. A browser bridge may reach any Fleet server, and wire v1 reads the same on an older one, so there the registration fails closed before the write.

Evidence: L3 (unit and component arms, the pinned Brain's own registry in a child process, the visual suite on Darwin) → L3 required (AC-1 to AC-6). No residuals; the installed-shell pilot row is Post-Merge Validation.

## Deltas from ticket
- AC-5's arm sends the shell-forwarded intent through the pinned registry, not a hand-built one. The registry is a Neo singleton on the Brain root's own engine, so the arm runs it in a child process, booted the way the Brain daemons boot.
- The Accounts form's PAT field is `required` only for a Fleet-launched seat. `form.validate()` enforces `required`, so a hidden required field would have blocked every external add.
- The rail form renders its idle line directly on a choice change. `flowStatus` compares deep-equal, so re-assigning an equal object never re-ran `afterSet`.
- **Only the packaged shell's own Fleet registers an external seat (AC-6, from Euclid's two review rounds).** Wire v1 carries no ownership semantics, and an older registry stores an external row startable.
  - A browser bridge refuses before any write: `AddAgentFlow.canRegisterExternal` is true only for the shell, and `validateDefinePayload` enforces it.
  - Within the shell, only the Fleet it spawned from its bundled Brain proves the pin. A reused incumbent (same port, bearer and viewer) and a checkout's env-selected Brain do not.
  - The product boot's receipt carries `bundledFleet` (`provesBundledFleet`), and `fleetCapability` refuses an external define without it.
  - A server-advertised capability for the birth stamp would let every path prove it; that needs a Brain contract change and another pin.
  - The wording now says what the gate proves: "Fleet refuses to start it".
- **A refusal reads as itself.** A `refused` answer to a request with no credential in it renders its reason in both forms. Any other failure keeps the generic text, so nothing a server echoes near a PAT reaches the DOM.
- The Accounts sample is an existing peer, so loading it re-selects external, hides the PAT field even after a switch to Fleet, and its status says what adding it takes from this ingress.
