Resolves #221

On a machine that already runs a plane, an unconfigured packaged shell now says so and offers the way in. Until now it said only "fleet: Brain is not ready" over the sample roster. The operator's shell sat that way for 52 minutes tonight.

The chain, measured on the team machine:
1. The docker plane's Chroma holds `127.0.0.1:8000`.
2. The shell plans own-mode: no plane record, and no orchestrator pid in its own data root.
3. The packaged guard refuses to own an organism beside a held Chroma port (the Brain's production default, 8000).
4. `settleBrainBoot(false)` recorded the generic `boot-not-ready`.

The guard stays, since two organisms on one machine is the failure it prevents. What changes is what the refusal says and does.

- **Harness.**
  - `besidePlaneRefusal(port)` throws a typed error (`code: 'organism-beside-plane'`), and `bootFailureCause(error)` maps it to a lifecycle cause.
  - `settleBrainBoot(up, cause)` records that cause instead of `boot-not-ready`.
- **Cockpit.**
  - `BrainHealthRead` passes the cause code as a new provider leaf, `daemonCause`.
  - `SpineBanner` ranks the refusal above its consequences: *plane here · A plane already runs on this machine — connect this shell to it · Chroma holds localhost:8000*, with `action: 'connect-plane'`.
  - Every verdict now carries `action`, so the leaf never goes stale after the cause clears.
- **The action.** The bar's Reconnect button binds its words and icon to the action (Connect / Reconnect). `onSpineAction` opens the plane card through `ViewportController#showPlaneSetup`, which brings back a dismissed card or mounts one. The capped container grows by 2 lines, to 996.

Evidence: L2. Unit arms run the real lifecycle through `applyBrainHealth` to the Connect action, the banner's precedence with a control, the action routing, and the card's return. The visual suite is pixel-identical. The Finder launch beside the plane needs the operator's machine: L2 met for AC-1..3, L3 for AC-4. Residual: AC-4, Residual-Owner: #12.

agent-preflight: not hosted here; the CI jobs run.

## What I verified, and it holds

- **The typed refusal is the right shape for this bug.** `besidePlaneRefusal(port)` produces `code: 'organism-beside-plane'` with a one-line `detail`, and `bootFailureCause` maps a typed error to a cause or returns `null` for everything else. The harness owns the cause, the lifecycle names it, the cockpit offers the way in — three layers, each with one job, and the generic path unchanged. That is the fix for "the cockpit said only *Brain is not ready*": the cockpit previously had no machine-readable discriminator to act on.

- **`daemonCause` split from `daemonDegradedReason` is the load-bearing change.** Before, both collapsed into one string, so a consumer could not branch on *which* failure it was. Now the source is machine-readable and the detail stays human. That distinction is what makes the banner's priority rule expressible at all.

- **The new early return cannot shadow a healthy attached shell — and I checked this specifically**, because a priority-first return in a derive function is exactly the shape that swallows a healthy state. `BrainHealthRead` computes `cause = state !== 'running' ? response.cause : null`, so `daemon.cause` is non-null *only* when the daemon is not running. Once this shell attaches to the plane and the daemon is running, the branch cannot fire. Correct, and worth stating because it is not obvious from the banner code alone.

- **The priority ordering is right and, better, justified.** Putting `organism-beside-plane` above the cold/sample-roster family is the correct call, and the comment says why: the sample roster and the refused fleet are *consequences* of the refusal, so its cause outranks them. A rule with that reasoning in it will still be right after the next person edits around it.

- **The action is threaded end to end, and the branch is justified rather than defensive.** `action` flows banner → `spineBanner.action` in the store → the component's icon/text config → the handler, and the handler branches because *"beside a running plane there is nothing to reconnect: the shell refused its own organism on purpose."* The icon swaps to a plug and the label to Connect. Every other verdict carries `action: null`, so the reconnect path is untouched — including the `hidden: true` live verdict, which correctly has no affordance.

## One non-blocking thought for the next action, not this PR

`action` is a single string with exactly one non-null producer, compared by equality at the handler. That is right at n=1 and I would not change it now. But the third action is where a string compared in a handler starts wanting to be a small action → handler map, and the migration is cheaper before there are three than after. Noted so it is a decision later rather than a surprise.
