Resolves #278

The visual stamp kept one digest per scope, so every FM pull request rewrote the same line of `baseline-inputs.json`, and each merge conflicted every other open one. `baseline-inputs.txt` holds one entry per style-owning file instead: its path, its staged blob id on an indented line, then a blank line. A changed file moves only its blob line, fenced by its own path line and blank line. So pull requests that stamp different files merge cleanly, and the merged stamp is the merged inputs. The check names each drifted file. Commands and CI are unchanged.

Evidence: L2 (unit arms over the pure halves, plus real git merges in temp repos) + L3 (the CLI against this repo's own index, at 8d834b7) → L3 required for AC-1 and AC-2.

## Deltas from ticket
- **The entry shape.** The ticket prescribed `<blob> <path>` plus a blank line. Measured with git 2.53 on 14 add/remove/change pairs, that shape conflicts on 9: a file added or removed next to a changed one, and both ends of the list. Path, indented blob and blank line conflicts on 3: two files added in the same gap, a file added next to a removed one, and two neighbours removed. Each of the 3 is a file set that neither PR stamped. The same file changed in two PRs also conflicts, as it should. A fixed `# end of stamp` line fences the last entry without a blank line at EOF.
- **AC-1's letter.** Those 3 pairs touch different files and still conflict. Git conflicts on any two insertions at the same point, so no line-per-entry stamp avoids it. The header tells the author to re-stamp.
