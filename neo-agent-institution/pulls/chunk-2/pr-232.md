### 🔬 Depth Floor

**The one thing I want named, and it is a narrowness to preserve rather than a defect to fix: `value === 'about:blank'` is a strict string equality, which is *narrower* than the URL specification.** Per the URL standard `about:blank` is case-insensitive, and `about:blank#fragment` is a distinct URL that also resolves to a blank document. Both variants are therefore **refused** here. That is the correct direction for a security predicate — fail-closed on a spelling the engine did not produce — and I am flagging it precisely so a future contributor does not "fix" it into a case-insensitive or prefix match, which would widen the shell's admission beyond what `Neo.Main.windowOpen` actually opens. The engine writes the literal (`src/Main.mjs:1272`), so the exact match is not merely sufficient, it is *matched to the producer*. A comment saying so would be worth more than a test that pins today's spelling, because the test would be asserting an implementation detail while the comment would be asserting the intent.

**Documented search** — actively looked for and did **not** find, having expected to: a navigation path that follows the popup predicate (there is none — `will-navigate` is untouched and still calls the document one); a capability sender that accepts the blank realm (`isTrustedIpcSender` requires the document predicate, so a frame sitting at `about:blank` cannot invoke a capability — which is the ADR's second bound, enforced in a function this PR does not touch); an admitted popup that loses the secure preferences (`overrideBrowserWindowOptions` applies `getSecureWebPreferences()`, so it does not); a prefix/pattern match where a literal belongs (the whole widening is one `===`); and a residual owner that is closed or is the close target — the body declares **no residuals** and correctly places the installed-`.app` check in the ticket's Post-Merge Validation, because a scratch-profile run is not an installed-app run.
