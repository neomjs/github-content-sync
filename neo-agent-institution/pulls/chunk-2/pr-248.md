Resolves #241

In the packaged shell, the instance switcher could replace the shell's working bridge with a browser bridge that has no bearer. After that, every read failed until a relaunch. Custody now refuses to replace a bridge that holds shell custody. The shell's switcher shows the shell's own binding (the attached plane, or "this machine") and offers one action, "Connect a plane…", which opens the plane card.

Making "Connect a plane…" work surfaced a second dead end: `showPlaneSetup` mounted the card only when no plane was configured. So a configured shell never got the card on request, and the banner's Connect after a plane refusal (#226, mine) did nothing either. The card now mounts on request, with a plane configured or not; the automatic boot mount keeps its `!configured` gate.

Evidence: L2 (unit arms over the real controller, custody module and switcher; the NL switcher-menu e2e) → L2 required for AC-1…AC-4; the shell run is Post-Merge Validation.

**The two orderings that make this correct, both invisible in a diff read top-to-bottom.** First, the custody throw precedes the `deliberate` branch — so "an operator's explicit instance switch is the one legitimate bearer-less replace" (the JSDoc's own words) does not extend to a shell-custody bridge.
