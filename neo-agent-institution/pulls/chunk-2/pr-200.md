Resolves #199

Every button in the cockpit bar inherited the engine's touch scale — `--button-height: 48px`, `--button-padding: 0 16px`, `--button-min-width: 48px` — five 48 px boxes in a chrome row whose pane headers below are ~40 px and whose chips are 19. The bar's scope now re-values the five scale variables the engine's button reads at the element (`neo.mjs/resources/scss/src/button/Base.scss:22-28,94,106-107`): height 32, min-width 32, padding `0 var(--fm-space-3)`, radius 6, text 13 px. Every button in the bar takes the chrome scale through the engine's own rule — presets, Reconnect, the pop-out toggles, Start fleet — and the three per-selector `border-radius: 6px` lines go. The first conversion of the button family Grace measured on #13 (102 declarations that map to `--button-*` vars): a re-valuation on the scope instead of rules per selector.

# PR Micro-Review

**Class:** contained. The engine's own button scale is re-valued on one scope, three per-selector lines are removed, and the goldens show the smaller bar. No new mechanism.

**Verdict:** Approved

**Glance:** The premise holds at `f81afd8`: the bar's controls were the engine's 48 px touch boxes in a chrome row. I checked the mechanism against the engine at the Institution's pin, `87ac80a6`, because a var re-valuation only renders where the engine reads that var on that element:
- `.neo-button` reads `height`, `min-width`, `padding` and `border-radius` from the four `--button-*` vars (`button/Base.scss:17,22,27-28`), and `.neo-button-text` reads the fifth.
- The theme declares them on `:where(.neo-theme-neo-dark)`, an ancestor with zero specificity, so the bar's scope wins by inheritance. The probe's 32 px measurements show it.
- Since `.neo-button` itself takes `--button-border-radius`, dropping the three `border-radius: 6px` lines is safe, and the ripple wrapper (`:94`) now clips to the same 6 px.

On the default-shell golden the presets, Reconnect and Start fleet are compact and rounded. The only thing on the bar that sets its height is the two-row telltale, which is leaf 3 as the body says. CI is 10/10 and CLEAN.

A note for a later #13 leaf, not this one: `--button-text-font-size: 13px` picks a pixel, and the §04 type ladder says "a surface picks a ROLE, never a pixel". The engine's var takes a bare size, so consuming a role would take a rule on the bar's scope, `.neo-button-text { font: var(--fm-text-body) }`. `Viewport.scss` already carries pixel sizes too (`font-size: 12px` at `:119`, `:305`, `:401`), so a type-ladder leaf that folds them all onto roles is the place for it.
