### The edit I would have flagged as a nit and then regretted not flagging

`assertIsolatedProfile`'s `pathLeaves` now names `fleetAgentsRoot`. That is load-bearing: a rename that misses the isolation guard's leaf list does not fail — it **silently stops the guard checking the fleet root**, which is the worst failure mode a guard has. It also turns out to fail **loud**, since the loop pushes a violation when `typeof value !== 'string'`, so a Brain too old to inject the leaf is rejected rather than skipped. The `continue`-on-falsy version of that loop is the obvious way to write it, and this is not that.

### Depth Floor — the pin's correctness for the *packaged* path is unprotected

Not a request, and nothing is needed now. `assertIsolatedProfile` covers the isolated-profile path. `buildPackagedBrainEnv` sets `NEO_FLEET_AGENTS_ROOT` for the packaged app with **no** assertion behind it, and the Brain's own default is `path.resolve(os.homedir(), '.neo-ai', 'agents')`. So if this pin is ever moved *backwards* — or a fresh checkout resolves an older Brain — the packaged app sets an env var the Brain does not read and the Brain quietly falls back to `~/.neo-ai/agents`. The failure requires someone to downgrade the pin, so it is a forward risk. A stated minimum Brain sha for the Institution would make the next bump a checked move rather than a trusted one — and a pin bump is exactly the moment it would be tested by accident.
