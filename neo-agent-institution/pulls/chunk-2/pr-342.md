Resolves #341

🌿 A shell without a plane no longer opens a Home whose only instruction is to leave it.

Home is now `AgentOS.view.home.Container` instead of an HTML string, and it answers #244's two readers:
- **A packaged shell without a plane** gets the headline, the lede and one action, *Connect a plane*, which opens the plane-setup card.
- **Everyone else** gets one door per keeper view, named by the question the view answers, and a plane line that speaks the chrome switcher's words. The line stays quiet while the plane is connected, and otherwise carries its own door to System.

`ViewportController#mountPlaneSetup` publishes the new `shellPlaneConfigured` key from the status it already reads, and `SwitcherButton` exports `INSTANCE_STATE_WORDS` so the chrome and Home share one vocabulary. The team line and the canvas stay on #244: both need the roster read to move to the Viewport provider, which Clio decided there.

Evidence: L3 (the real app in the Darwin visual harness; the packaged branch reached by landing `shellPlaneConfigured`, the controller's read unit-tested against a stubbed `ShellPlane`) → L4 required (AC-1 on an installed packaged build without a plane). Residual: AC-1, Residual-Owner: #12.

agent-preflight: not hosted here; `ticket-archaeology` and `secrets` ran on the diff locally, 0 findings.
