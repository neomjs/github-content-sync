Resolves #219

The packaged shell now keeps its own log. Every line main prints also lands in `~/Library/Logs/neo-harness/main.log`, timestamped, so a Finder launch leaves its boot lines behind: `HARNESS_BRAIN_PLAN`, `HARNESS_BRAIN_MODE`, and the Brain children's lines. Until now those went to stdout only, which a Finder launch discards. That is why the operator's unconfigured shell sat at `boot-not-ready` tonight with no trace on disk.

- **`harness/mainLog.mjs`.**
  - `createMainLog({dir, secrets})` appends to `main.log`, rotates once to `main.log.1` past 1 MB, and stops quietly if it cannot write.
  - The redaction rule sits at the file boundary: a line carrying any secret main holds is written as `[secret-bearing line redacted]`. Those are the fleet bearer, the env plane bearer, and the plane record's bearer once the product boot reads it.
- **`main.mjs`.** At startup, main tees `console.log` / `warn` / `error` through the log, in packaged and checkout runs alike. If the platform refuses the logs path, main prints one `HARNESS_MAIN_LOG_UNAVAILABLE` line and boots without a file.
- **Packaging.** `mainLog.mjs` joins `electron-builder.yml`'s `files` and `pack.spec.mjs`'s module list.

Evidence: L2. The unit arms cover the file, the redaction, the rotation, the failure path and the console tee. A packaged launch writing the file needs the operator's machine, so it stays L3 → L2 met for AC-2..4, L3 for AC-1. Residual: AC-1, Residual-Owner: #7.

### 🔬 Depth Floor

**Challenge — redaction is all-or-nothing per line, and that is a latent diagnosability cost.** `write()` replaces the **entire line** with `REDACTED_LINE` when any known secret appears in it. That is the safe trade and I would not have it otherwise — a partial replacement can leave fragments if a secret is a substring of a longer token. But the log exists to explain a failed boot, and the lines most likely to carry a bearer are exactly the interesting ones: an attach failure logged as `Authorization: Bearer <pat> → 401` would land as `[secret-bearing line redacted]`, which tells the operator that *a* line was secret and nothing about the 401.

**I checked whether that is live today and it is not.** I grepped `harness/main.mjs`, `harness/brain.mjs` and `harness/planeConfig.mjs` at this head for any `console.*` call mentioning `Bearer` / `Authorization` / `token` / `pat` and found exactly one, and it is unrelated (`HARNESS_404`). So the reachable secret-bearing lines today are not the diagnostic ones, and the cost is **latent rather than current** — I am flagging it as a shape to be aware of, not a defect to fix.

If it ever does bite, the fix is per-secret in-place replacement rather than per-line, and the decision belongs with whoever first adds a bearer-carrying log line — best made there, with the real line in hand, rather than pre-emptively here.

**Documented search**: I looked for a window between acquiring a secret and being able to redact it (none — `storedPlaneBearer` is assigned on the line immediately after `readPlaneConfig` returns, with no logging in between, and `secrets` is read at write time so later lines are covered); for a second `install()` call site that would double-patch `console` (only the one at module top level); and for a second place the packaged-files list is asserted (`pack.spec.mjs:143`, correctly paired with the `electron-builder.yml` line — a new `harness/` module that is not in that list would be a silent packaging break, and the paired assertion is what prevents it).
