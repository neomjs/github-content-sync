Resolves #238

The tests own the sample fleet. `test/playwright/fixture/fleetSample.mjs` carries the eleven roster rows (a row factory, deep-equal to the app's JSON) and the six activity events. `test/playwright/fixture/FleetLanding.mjs` is the seam: loaded into the App worker once, it keeps one instance whose reactive `roster_` / `activity_` configs a spec sets from the page through `Neo.worker.App.setConfigs` (`landFleetRoster`, `landFleetActivity`, `landFleetSample` in the e2e fixtures). A landing hands its rows or events to the liveness owner's own admission — `admitRoster` / `admitActivity`, the methods `loadRoster` / `loadActivity` call after their generation fence and validation, whose rule lives in `AgentOS.util.FleetAdmission` — as the answer of the bridge in hand, so the owner treats it as the fleet's answer: the seed's late `load` reconciles back to it, a later landing reconciles instead of replacing, a failing read degrades it to `stale`, a profile switch retires it, and every step the admission gains (today: the operator posture, a resident CatchUp's missed read, the Golden Path read) the landing gets. The specs that read sample cards land the sample; the specs that possess the store with their own rows land those rows through the same seam and no longer wait on the seed's arrival; the unit and component specs that read the seed by path import the fixture module. The app's seed is untouched in this leaf; a parity arm pins the fixture to the app's JSON and module until #239 retires them.

Change class: test-side capability (`test`) plus one refactor of the liveness owner (the two admissions extracted, no behavior change). agent-preflight: not hosted here; the baseline jobs run.

Evidence: L2 (unit; the landing's own NL arms; the re-pointed NL specs; the Cockpit e2e; the RosterRefillSeam component spec) → L2 required. Residual: none of this leaf's. Reds the landing surfaced or met that are not this leaf's: `FleetGridScaleNL`'s shrink now runs through the live reconcile and exposes #249 (the folded idle residents survive a shrink), carried as `test.fail` naming the ticket; `FleetPermanenceMatrixRow4NL` is red on the dev head before this branch (the perspective writer refuses `activate: false` on an empty library), reproduced in a clean worktree at 61fabbb; `FleetMemoriesNL` "populated registers" and `FleetCockpitBarCompositionNL` (both widths) fail on size at dev `adad639f8e` (Ada's defect-note MESSAGE:6a209290) and this PR re-captures neither.
