When native startup outlasts the first roster deadline, a valid late completion now triggers one fresh roster read. The expired rows remain discarded. Only the initial unanswered shell read can recover, and newer reads, bridge/profile changes, liveness stop/restart, destruction, hidden state and the in-flight cap fence the retry. A failed or timed-out recovery returns to the ordinary cadence.

Joining windows retain the current entry-owned shell bridge, so a popup cannot cancel the primary's recovery by incidentally replacing its bridge. Live-window routing remains dynamic, and a fresh boot refreshes the pre-registration fallback.
