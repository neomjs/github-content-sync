Resolves #610

A running seat whose working checkout the last start did not prepare now reads `skills not verified` on its card. It is the quietest status line: the session folder, the admission, a refusal and a pending action all speak first, and a card that reads offline says nothing. Agent Detail's Repository pane lists each checkout's preparation, the working one first, each reason whole beneath its row. `AgentOS.util.SeatDependencies` words the Fleet's `dependencyOutcomes` once for the card, the pane and the Accounts Repositories card. Prepared means `installed` or `present`; every other state keeps its own word (Skipped, Canceled, Unverified, No preparation step, Installing, Failed).

A checkout's dependency row speaks over its clone outcome. The Fleet writes dependency rows before the launch and records clones after it, so a dependency row is never the older of the two, and a failed clone never has one of its own. While a Start installs, the clones are still the previous launch's, so the pane lists that start's rows alone. A clone with no install reported reads `Unverified · no dependency install reported`, never Prepared. The consumed rows are in [#610's Contract Ledger](https://github.com/neomjs/neo-agent-institution/issues/610).
