Resolves #754

Node 24.22.0 ships nodejs/node#64124: `cpSync` with `errorOnExist` now refuses an existing destination directory. Both owners stage `src`, so the product's `src` copy failed against the Brain's. Institution CI went red whenever its runner's toolcache Node was 24.22.0.
- **`copyTree`:** drops `errorOnExist` and its `ERR_FS_CP_EEXIST` catch. Its filter refuses a shipped file whose destination already exists (`pack: two owners stage the same path: <path>`). Shared directories merge on every Node line, and a file both owners stage is still refused.
- **CI:** both `setup-node` steps add `check-latest: true`, so every job runs the newest Node 24 patch and a Node change reaches all of them at once.

Evidence: L2 (the `pack.spec` arms in CI, on Node 24.22.0) → L2 required (AC-1, AC-2). Residual: none.

Prescription checked: `harness/pack.mjs` `copyTree` owns the concern. Its comment states the shared-directory rule, and pinning CI's Node instead would leave `predist` broken on any host whose Node carries the change.

Per §9 Strategic-Fit Step-Back:
- **Decision**: Approve
- **Rationale**: Node.js `v24.22.0` (`nodejs/node#64124`) changed `fs.cpSync` with `errorOnExist: true, force: false, recursive: true` to reject when a destination **directory** already exists (`ERR_FS_CP_EEXIST`), breaking `copyTree` (`harness/pack.mjs:684`) whenever the product's `src/` tree is copied into `stage/src/` after the Brain's `src/fleet` tree already created `stage/src/`. Moving the collision check into `copyTree`'s `filter(entry, destination)` for shipped files (`fs.statSync(entry).isFile() && fs.existsSync(destination)`) enforces the exact invariant stated in `copyTree`'s comment (shared directories merge across owners; file collisions fail loud with the stage-relative path) across all Node 24/25 lines, while adding `check-latest: true` to both `actions/setup-node@v7` steps in `.github/workflows/ci.yml` eliminates runner-image toolcache drift between jobs.
