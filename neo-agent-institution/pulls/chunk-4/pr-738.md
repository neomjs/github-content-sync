Resolves #737

🌿 An FM whose own handoff is broken can no longer block the build that fixes it.

After Quit, `prepareInstallContinuity().hold()` accepted only a sealed handoff or a vacant journal, and refused an unsealed journal whose issuer had exited. ADR 0034 §2.5's installed witness requires the opposite: an update after an unclean issuer exit completes, carrying the running generations stale. Now, when `holdLaunchAdmissionHandoff` refuses with `handoff-incomplete`, the installer holds the unsealed record under the journal's own issuer lease (`holdUncleanPredecessor`). The lease is free only once that issuer has exited, the record must match the issuer bound before Quit, and the hold re-verifies it before every slot mutation. Successor recovery is skipped, since an unclean record carries no recovery authority; the successor's boot crosses it stale, as every boot after an unclean exit already does. A live issuer, a later seal or a successor issuer still refuses.

Evidence: L2 (unit, real journals and the real issuer lease) → L3 required (AC-4, the installed update). Residual: AC-4, tonight's install over Brain 9cd1528b, receipt on #737 (Post-Merge).
