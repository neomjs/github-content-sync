🌿 *A merged Brain or Engine fix no longer waits for a pin ticket before the Institution runs it.*

The Institution now tracks the Brain and the Engine at `dev`: the operator's order of 2026-09-21, scheduled on 2026-10-09 ("bump now, de-pin next").

- `package.json` names both at `dev`. `npm ci` still installs the lock's last resolution, so `npm run resolve-org-dev` reinstalls both from `dev` without saving and names the installed revisions.
- CI runs that script in both jobs and checks the Brain out at `dev`.
- The visual stamp records the engine revision its goldens were captured against. The freshness check names a moved engine without failing, per the operator's call on this ticket.
- The packaged build records the Engine's installed revision beside its pin.

## Deltas from ticket

- **One cut per package** (review RA-1). With the specs at `#dev`, the lockless stage install would resolve `dev` on its own. `stageOrganism` now binds themes, the staged Engine, the copied Brain runtime and the Brain contract package to one resolved set, and fails closed on an unknown or mismatched revision.
- **The visual harness's own guard.** `test/playwright/visual/globalSetup.mjs` required the installed engine to equal the lock's, which blocks every capture once the engine tracks `dev`. It now names the engine it renders with. Its CSS-freshness check also covers the Engine's SCSS: a new engine on disk with an old theme build is the poisoned-golden path the old identity check guarded.
- **The install receipt.** `harness/install.mjs`'s receipt line prefers the Engine revision; a receipt written before this names the engine only in its pin.
