### RA-1 [ADDRESSED] at `3b14e02` — an empty window keeps the corpus, and the continuation stays honest

The open view now reads by its count, not by its window.
- **Empty means a complete zero.** `getQuestionsState()` returns `empty` only for `count === 0`; a positive count is `rows`, even when a window brings none.
- **Held rows survive.** An empty continuation extends the held corpus with nothing, so the held questions and the open detail stay.
- **Bounded continuation.** The scroll edge re-announces only when the visible count changes, so a window that shows no row could never be asked past. The pane now asks for the next window itself, through the same `pendingOffset` gate. The run is `EMPTY_WINDOWS = 3` in a row at most and restarts on a window with a row or a switch of list. Polls and the edge stay as they were, so the boot drain stays dead.
- **A count nothing could show says so.** While the next window is out the line reads `your open questions have not been read`. After the run it reads `3 open · none can be shown here`, never `nothing waits for your word`.

Your four controls are in `openQuestions.spec`, in two new arms:
- "a window can show none of the questions its count holds…" covers the middle projection hole (the held question and its detail stay, and the pane asks offset 2), then the empty final continuation after held rows (nothing discarded, nothing asked), then the switch (run and pending ask reset).
- "a first window that shows none of a positive count…" covers the empty first page (`rows` state, the next window asked), the bound (three asks, then the count line), and the genuine complete zero (`nothing waits for your word`).
