Resolves #736

`NEO_HARNESS_REHEARSAL=1` runs the Brain's seat journey (#1164) against a packaged candidate before it is installed. The run is windowless and happens in the isolated own-mode Brain smoke:
- Each desktop family Starts twice and keeps the operator's content.
- Each family survives an unclean Fleet restart, and the roster must offer Start again afterwards.

The exit code is the verdict. A receipt beside the artifact names:
- the candidate,
- every step with its reason,
- the isolation that kept the run off the operator's organism,
- the teardown.

Evidence: L3 (packaged candidates run on macOS in own-mode smoke roots with a run-owned Bridge port) → L3 required (AC-1's packaged run, AC-2 to AC-6).

## Deltas from ticket
The packaged runs found these, all fixed here:
- the stand-in probes only a Node it may use (`NEO_HARNESS_STAND_IN_NODE`), and every probe is bounded;
- a pinned runtime always answers as Node, because `ELECTRON_RUN_AS_NODE` is added after every caller's env;
- the smoke root is the temp dir's real path;
- a slow Fleet gets 90 s;
- a failed boot settles as the verdict;
- every rehearsal starts from an empty Fleet.

They also found a Brain defect, fixed separately: #1194 / neomjs/neo-agent-brain#1195 (a seat's configs copied the runtime root's read-only mode).

### 🔬 Depth Floor

**Challenge OR documented search (per guide §7.1):**

- **Challenge**: In `harness/main.mjs:1602-1618`, when `reboot` kills the initial `fleet` child with `SIGKILL` and spawns `next`, `registerBrainChild({child: next, ...next.neoHarnessIdentity, label: 'fleet'})` appends `next` to `brainState.children` while the first (exited) `fleet` entry remains in `brainState.children`. At teardown (`main.mjs:1629`), `appLifecycle.teardown()` runs `stopBrainChild` on both `fleet` entries (`brain.mjs:1367-1375`). Because the first `fleet` child already exited via `SIGKILL`, `stopBrainChild` takes the `child.exitCode !== null || child.signalCode !== null` fast path and returns `{exited: true, forced: false, groupEmpty: !isProcessGroupAlive(pid)}`, so `teardown.childrenStopped` remains `true` (`!report.forced`). However, if any process in the first `fleet`'s process group (`-first.pid`) were still alive at teardown, `stopBrainChild` would send `SIGINT` to `-first.pid` and wait up to `graceMs` (`5000 ms`) for a child whose `exit` event already fired. Non-blocking (and `#752` handles the detached Fleet-started Bridge separately), but pruning or replacing the dead `fleet` entry in `brainState.children` on `reboot` is a clean future tightening if a Fleet child ever spawns same-group helpers.
