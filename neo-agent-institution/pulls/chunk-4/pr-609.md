Resolves #608

A Fleet Start that outlives the cockpit deadline now reconciles when its actual answer arrives. The card says “no answer yet” while the outcome is unknown; a current success clears that message, and a refusal replaces it with the existing sanitized reason. Newer actions and replaced roster targets win over older replies. Start-all also updates its latest batch summary after late answers.

The existing adapter owns completion and attempt fencing; the existing liveness controller owns profile/record binding and roster refresh. No new service, wire field, retry or backend cancellation path is introduced. Local completion promises and current-attempt predicates never enter roster DTOs.

Evidence: L2 (deferred test bridge against the production adapter/controller with real Store records) → L2 required for the lifecycle source ACs. Isolated Chromium visual checks provide separate real-surface evidence. Residual: installed slow-Start witness on the existing parent.

### 🔬 Depth Floor

- **Challenge (non-blocking): the wait is now unbounded.** The adapter observes the bridge call until it settles. If a registry call never settles, the line stays "no answer yet" until a reload, and its closures keep the record and controller alive. That is fine if the bridge transport bounds every call. Name the layer that does in the adapter JSDoc, or state honestly that none does. Don't add a second timeout.
- **Nit: `!record.isDestroyed` in the adapter fence is inert.** Neo data records are a plain `class Record` (`src/data/RecordFactory.mjs:162`), not `core.Base`, so they never carry `isDestroyed`. Record liveness is the caller's `options.isCurrent`, which the liveness controller supplies. Drop the clause, or let the JSDoc say record liveness is the caller's fence.
