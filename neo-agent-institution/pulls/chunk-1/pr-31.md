Resolves #3

The Fleet list conversions render their visual contracts again — and the repair unearthed why they could not: **this repository's own SCSS was never compiling**. The `build-themes` script carried the engine-only `-f` flag, so `themes.mjs` silently skipped the entire consumer tree; it went unnoticed because the pre-removal engine pin still shipped an `apps/agentos` SCSS twin inside `node_modules`, which compiled in its place with stale rules (exit 0, no warning). Every consumer-side style repair was a no-op until this PR drops the flag and advances the engine pin past the twin (`17b59aad8f`).

## What changed

**Build truth (the enabler):** `-f` removed from `build-themes`; engine pin bumped. The consumer SCSS tree compiles for the first time in this repository (485 files incl. 33 app files; `resources/theme-map.json` regains the `apps.agentos` entries the runtime needs for per-class CSS loading).

**Activity stream (operator symptom set in the [claim comment](https://github.com/neomjs/neo-agent-institution/issues/3#issuecomment-5451104372)):**
- header renders as the designed single chrome bar again — the container had no `layout`, so the engine's vbox default stamped `neo-flex-direction-column` over the stylesheet's initial row direction; it now declares `hbox`;
- `itemHeight` 52 → 32, the golden density contract — 52 had been sized for the narrow two-line grammar, taxing every wide row 20px; the narrow grammar now fits two 13px lines inside the same pool height (a resize-driven per-breakpoint `itemHeight` stays available as a follow-up — `list.Buffered#afterSetItemHeight` exists);
- fixture payload texts modernized to the five-cell row contract (actor/recipient render in their own cells; the embedded actor names doubled on every row).

**Roster:** sort/filter cluster re-bound to the real Button anatomy the conversion introduced (`--button-height` token override, `.neo-button-text` font inherit, the actual `pressed` class) — the quiet ghost verbs return. `ResizeObserver` joined `mainThreadAddons`: **without it `list.plugin.Animate`'s fluid-column re-derivation never fired in the product** — card widths froze at mount geometry on every dock/pane resize.

**AgentCard containment (pathological matrix green at 294/319/320/328/360/720, both skins):** while a control round-trip is live, the second work line belongs to the status row — the lane clamps to one line (root cls + SCSS), and the status line is one-line-ellipsized with the full reason on the `title` receipt. A reason-carrying card now fits the uniform 126px row at every width, including the 44px-touch narrow head.

**Determinism (the capture environment was leaking machines into goldens):** visual + e2e configs pin `locale: en-GB` / `timezoneId: UTC` (context emulation binds worker-side `Intl`; `page.clock` does not reach the app worker — documented in the spec). The retired burst-spec expectation `'04:08 PM'` encoded its author's UTC-4 clock; it now asserts the record binding (regex + exact ISO `title`). The visual config also gains the `process.env.NEO_E2E_PORT` write-back the e2e config already had — without it every worker probed its own port and navigated to a server that never existed.

**AC-7, the Darwin drift signal:** `buildScripts/checkVisualBaselines.mjs` + a committed input-identity stamp beside the goldens + a CI step. It hashes the staged blob ids of the style-owning inputs (`apps/agentos`, `resources/scss`, the two capture specs, the locked engine resolution) and fails when they move past the stamp — a render-free freshness gate that never grants Ubuntu pixel authority. Refresh ritual: capture with `--update-snapshots`, stage, `npm run stamp-visual-baselines`.
