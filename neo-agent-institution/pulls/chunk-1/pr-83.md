Related: #10 (parent), #15536 (the card's design — the avatar-keeper invariant), #74 / PR #77 (the S5 journey that shows a faceless row first), #76 / PR #79 (where it was seen), #81 / PR #82 (this branch is stacked on its pin: the base retargets to `dev` when #82 merges)

A roster record without `avatarUrl` used to mount an `<img>` with no source, and Chrome painted its broken-image glyph over the alt text in the avatar circle — the one thing the card's identity column must never show. The avatar slot is now a keeper with two halves: the face image when the record carries a face, otherwise the name's initials on the family ink in the same slot — sized alike by every width mode, so the head row never reflows when a face resolves later. The `Image` hides through `removeDom` (a src-less `<img>` never reaches the DOM), the monogram carries the resident's name as its accessible name, and both halves flip in place on the live record — the pooled card instance never re-keys for a display-state change. The family class → ink mapping moves into one shared partial (`_family-ink.scss`) used by the rail and the monogram, so a new family lands once.

Evidence: L3 (the twelve synthesis goldens re-captured with a faceless row leading the roster and read by eye; unit arms on the instance; the NL battery under the Brain root) → L3 required (AC-1 and AC-3 are rendered appearance). Residual: none.

## Deltas from ticket

- **The mapping lives once.** The ticket named the family ink as "the visual vocabulary the card already speaks"; making the monogram speak it without a second copy of the five-line class → token mapping needed a shared partial, so `FamilyRailComponent.scss` and the card sheet both `@use '_family-ink'`. The compiled rail sheet is unchanged in effect (six family selectors as before).
- **The old "avatar-persists" arm is restated, not deleted.** It asserted `hidden === false` on the `<img>` after `avatarUrl: null` — the exact shape that painted the glyph. The operator invariant it cites ("a visible avatar at every card width") is now satisfied by the monogram; the arm reads that, plus the face returning in place.
- **The initials are an attribute, not a text node.** The first cut set the monogram's `text`; the battery caught it: a text node runs into the name for every text reader — the card read "ADAda", and `FleetMemoriesNL`'s roster locator (`hasText: /\bAda\b/`) lost its word boundary and timed out. The sheet now paints the initials from `data-initials` (`::before { content: attr(…) }`), the `aria-label` carries the resident's name, and the card's text stays the name alone. Pixels identical (the goldens did not move between the two cuts).
- **Image load failure (the optional item 3)** is not wired: `Neo.component.Image` has no error seam and the main-thread DOM event set carries no `error`; a 404 face still paints the glyph. Named here rather than half-built; it is its own leaf if it shows up.
- **The sub-narrow band (≤240px content)** sizes the monogram to 24px / 10px text by rule, mirroring the avatar; the matrix does not capture that band (it never did), so it is covered by SCSS, not by a golden.
