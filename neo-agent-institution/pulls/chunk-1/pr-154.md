Resolves #153

The Institution's build leaves the engine's framework mode: `-f` comes off `build-all`, `build-all-questions` and `build-threads`, and the workspace gets the root `ServiceWorker.mjs` that consumer mode resolves its `service` entry from (`webpack.config.worker.mjs:21` in the engine — a scaffolded workspace has one, this repo was never scaffolded). Measured while fixing it: framework mode did not merely bloat the output, **the production App worker did not contain `apps/agentos` at all** — the `importApp` context stayed rooted in the engine package.

Evidence: L3 (real builds from a clean `dist` and a real browser against `dist/production`, both modes) → L3 required (AC-2, AC-3, AC-4). Residual: none.

agent-preflight: not hosted here; the baseline jobs run in CI. Declared class: `restoration` → `fix`.

## Deltas from ticket

- **The ticket's premise was too mild.** It argued footprint and robustness; the production build of the product did not contain the product. The ticket body now says so, with the receipts above.
- **The docs app is out of reach and unchanged.** `dist/production/docs/index.html` fails identically in both modes (`Cannot find module './docs/app.mjs'`): the engine's `webpackInclude` for `importApp` — `/(?:apps|docs\/app|examples|src)\/.*app\.mjs$/` — cannot match a `docs/app.mjs` entry (`node -e`: `false` for the workspace path and for the engine's own). Defect-noted to the engine; AC-3 was narrowed to `apps/agentos` for that reason.
- `ServiceWorker.mjs` is named `AgentOS.ServiceWorker`, version `0.1.0` (the package version). No app enables it; its docblock says why it exists anyway.
- No CI workflow and no harness code calls these scripts (`grep` over `.github/workflows`, `harness`, `buildScripts`, `test`), so nothing else had to follow.

## Test Evidence

- Both builds and both boots as in the table; instrument note for a reader who repeats the boot check: `apps/agentos` runs SharedWorkers, so a docs page loaded first on the same origin poisons the agentos read — the control ran on a fresh origin (`127.0.0.1` vs `localhost`) with every tab of the other closed.
- `npm run check-visual-baselines`: the stamp is untouched by these two files.
