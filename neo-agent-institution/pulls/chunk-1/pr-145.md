<blockquote>
<h2>v1.63.0</h2>
<h2>🔒 Test locks</h2>
<p>Tests that access a shared resource — an external service, a global account setting — can now declare a named <code>lock</code>.
Tests that share a lock name never run concurrently, across files, workers and <a href="[QUARANTINED_URL: playwright.dev]">projects</a>, while
everything else keeps running in parallel:</p>
<pre lang="js"><code>test('update user settings', { lock: 'user-settings' }, async ({ page }) =&gt; {
  // never runs at the same time as other tests holding 'user-settings'
});
</code></pre>
<p>A test can hold multiple locks, and <a href="[QUARANTINED_URL: playwright.dev]">test.describe()</a> accepts a <code>lock</code> for the whole group.
Learn more about <a href="[QUARANTINED_URL: playwright.dev]">test locks</a>.</p>
<h2>🪟 Locate across frames</h2>
<p><a href="[QUARANTINED_URL: playwright.dev]">page.frameLocator()</a> and <a href="[QUARANTINED_URL: playwright.dev]">frame.frameLocator()</a> called without a selector search in any frame of the
subtree, so you no longer need to locate the iframe first:</p>
<pre lang="js"><code>// Finds the button in any frame on the page.
await page.frameLocator().getByRole('button').click();
</code></pre>
<p>The rest of the locator resolves inside a single frame, just like a regular locator, and an error is thrown when it
matches elements in several frames.</p>
<h2>👁️ Visible-only locators</h2>
<p>New <a href="[QUARANTINED_URL: playwright.dev]">locator.visible()</a> returns a locator that matches only visible elements. It is the recommended
replacement for the <code>:visible</code> CSS pseudo-class:</p>
<pre lang="js"><code>await page.locator('button').visible().click();
</code></pre>
<h2>🧾 Step params and subtitles</h2>
<p>Steps now carry structured data for reporters. Playwright API steps report the target locator and call arguments,
and <a href="[QUARANTINED_URL: playwright.dev]">test.step()</a> accepts <code>subtitle</code> and <code>params</code> options for your own steps:</p>
<pre lang="js"><code>await test.step('Login', async () =&gt; {
  // ...
}, { subtitle: 'as admin', params: { user: 'admin' } });
</code></pre>
<p>Reporters receive them via <a href="[QUARANTINED_URL: playwright.dev]">testStep.subtitle</a> and <a href="[QUARANTINED_URL: playwright.dev]">testStep.params</a>. For Playwright API</p>

  layout: dagre
---
</code></pre>
<p>or globally, <code>mermaid.initialize({ layout: 'dagre' })</code>.</p>

<ul>
<li>ELK is loaded as a separate chunk in the ESM builds, so it is only fetched when a diagram actually uses it. The single-file IIFE build (<code>mermaid.min.js</code>) inlines it and grows by roughly 500 kB gzipped.</li>
<li>The <strong>tiny</strong> build deliberately omits ELK to stay small, and falls back to dagre for diagrams that ask for an ELK layout. Its size is unchanged.</li>
<li><code>@mermaid-js/layout-elk</code> is no longer needed on normal builds — existing <code>mermaid.registerLayoutLoaders(elkLayouts)</code> calls keep working and can be removed. It is still published, and remains the way to add ELK to the tiny build.</li>
