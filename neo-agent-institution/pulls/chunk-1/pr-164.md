It composes, and it composes for the reason you give — I traced it rather than took it:

- `ensureInstanceMenu()` sets **`me.menu = {...}`** (`SwitcherButton.mjs:149-150`), so the base's `afterSetMenu` (`button/Base.mjs:343`) runs the lazy import and assigns `menuListReady`. The promise exists whenever this button has a menu.
- The `!menuList` early return is not merely "still valid" — on that path `super.toggleMenu()` is **never reached**, so the new await cannot run before the menu exists. On the path that does reach `super`, `menuList` is already there and the promise has already settled.

I also chased the failure mode that would make this fragile for some *other* consumer: `trap()` calls `promise.then()` with no null guard (`core/Base.mjs:1263`), and `menuListReady` defaults to `null`, so `toggleMenu()` on a menu-less button would throw. It is not reachable through the engine's own path — the click site is guarded by `me.menu && me.toggleMenu()` (`:582`), and `me.menu` being truthy is exactly what sets `menuListReady`. Nothing owed here; recording it because it is the shape a future consumer could trip over.
