Resolves #193

The harness's two theme builds now run the one argv a workspace may run — `-n -e dev -t all`, owned by `prepareAssets.mjs` as `THEME_BUILD_ARGS` and consumed by the pack stage through `themeBuildArgv()`. Before: `pack.mjs` passed `-f`, which is `--framework` (the engine builder then parses only the engine's SCSS, and the regenerated `resources/theme-map.json` carries no `apps.agentos` row), and `prepareAssets.mjs` rebuilt one theme per run (each run regenerates the map with only that theme for workspace classes). The App worker inserts CSS only for classes the map names, so either shape rendered the cockpit in the engine's default looks — the operator's "custom theming is completely missing inside the electron shell" of 2026-09-25. `prepareAssets` guards its top-level run so it is importable; `buildThemes` takes an injected spawn seam; `stageOrganism` takes a runner seam (`runFn`) for every child process it issues. A new spec pins the argv and the single spawn; `pack.spec.mjs` drives `stageOrganism` with a recording runner and pins its first child process — the call site, not only the helper (round 2: restoring the `-f` literal at the call site fails the arm).

Evidence: L2 (spec over the spawn seam) + L3 (the entry script rebuilding the map on this checkout and the window on the operator's display) → L3 required for AC-3/AC-4. No residual.
