## Deltas from ticket

- **The reason changed while building.** The ticket was filed on the reviewer's note that the engine now ships `dist/marked.mjs`. It does not, for us: a github-SHA install has **no `dist/` at all** (measured on the clean reinstall above) — the file I first cited had been written by my own `build-all` runs. So on every fresh clone and in CI the bridge's sunset condition was false and it still copied 476 KB. The copy served nothing: at this pin the engine's two Markdown modules import `dist/marked.mjs` (`src/component/Markdown.mjs:4`, `src/app/content/Component.mjs:2`; `grep -rlE "node_modules/marked"` over the engine's `src apps examples docs` → 0 files), and no file here imports them. The ticket body carries the corrected premise.
- `marked` stays in `dependencies`: the engine's `buildScripts/build/marked.mjs` (run by `build-all`) resolves it from the workspace root.
- Known and left alone, because nothing here needs it today: a future Markdown surface in this workspace would need `node_modules/neo.mjs/dist/marked.mjs`, which only `build-all` produces on a git install (`/node_modules/neo.mjs/dist/marked.mjs` → 404 in dev mode right after `npm install`).
