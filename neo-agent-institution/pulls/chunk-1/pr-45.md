## What

**The one data path, generalized (`RowsGrid` base):** every content mutation of either register flows through `applyBags` — derived display facts stamp into PLAIN bags before they become records (the store's data path renders during `add`; facts arriving later miss the first paint — measured on #41), and every projection creates fresh record identities, which is what re-seats the pooled cells. `extractBags` reads the corpus back for window extension. No record mutation exists anywhere in the view layer.

**`SummaryGrid` (browse):** headerless component column of pooled `SummaryRowComponent` cells (band eyebrow · head with title / DERIVED chip / native drill-open button · T5 meta with ISO `title` · co-author attribution · body). Owns two things: the viewer-calendar **band facts** (`today / yesterday / this week / earlier` — the first card of each band carries the eyebrow; stamped once at bag time, so grouping is decided exactly once) and the **delegated drill-open click** (engine `.neo-grid-row` `data.recordId` resolution, re-fired as the `cardOpen` pane intent — opening a session is pane intent, never grid state).

**`TurnGrid` (drill):** pooled `TurnRowComponent` cells — meta · the title line · bounded prompt. The title follows the sketch's measured law: the tweet-size `miniSummary` IS the title once the wire carries it (`SessionTurn` gains the forward-compatible field; producer exposure is neo-agent-brain#210), and the bounded `response` head stands in until then — never a phantom.

**The pane:** the coherence contract survives unchanged — the selected target keys the summary projection, the open session keys the drill, `offset > 0` extends only an accepted page zero of the same key, foreign envelopes are never adopted **and never drain**. The `more` / `older-turns` buttons retire; the pane **drains** both registers instead: exactly one follow-up read intent per newly-arrived accepted envelope while the producer's `total` says more corpus exists, **floored by rendered depth** so a repeated or echo-less answer costs one render, never a request loop. A remat from a PARTIAL owner-held snapshot resumes the drain (never a page-zero re-read); a complete one fires nothing. Refresh stays — an explicit re-read intent is not paging.

**Height-norm (the design-pass architecture, head 2):** the engine grid positions rows on a FIXED `rowHeight` lattice — variable card heights overlap cell content onto itself (measured in the mounted browser: ~180px cards stacked on the 32px default). Every cell of a register is therefore exactly ONE height: the band SLOT exists on every card (empty off boundaries — never a per-card extra line), attribution rides the single meta line ahead of the counters, titles ellipsis at one line, bodies clamp at two, and a titled turn (miniSummary) clamps its response to one context line so the prompt never clips mid-glyph. `SummaryGrid.rowHeight: 132` / `TurnGrid.rowHeight: 104` carry the SAME totals as the SCSS cell heights — each side names the other.

**SCSS:** all register rules live in the pane's `Container.scss` — a second design-pass finding recorded in place: the engine loads CSS per instantiated CLASS NAME, so a `memories/Grid.scss` maps to no class (`SummaryGrid`/`TurnGrid`) and silently never loads (the mailbox's `Grid.scss` works only because its class IS `mailbox.Grid`). Header-toolbar height-collapse (never `display: none` — the engine's flex-column measuring instrument), cell structure, band eyebrow, native-button voice. Zero font-size literals (greppable).
