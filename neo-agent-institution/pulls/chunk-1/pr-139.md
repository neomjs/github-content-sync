Resolves #138

The shared baseline called `reusable-pr-baseline.yml@7c9bd16f`, whose body hardcodes `SKILLS_VERSION: '0.1.3'`. Every gated job here therefore installed guards two releases old: a durable comment carrying a CSS colour literal or a numeric HTML entity failed in this repository while the identical line passed in `neomjs/neo`. Two consumers of one governance substrate disagreeing about the same rule is the defect `neomjs/neo#16553` exists to end.

The lockfile was the second stale pin, and I got that wrong in the ticket's first revision before measuring it — corrected there. A range **permits** a version; the lockfile **pins** one. `^0.1.3` had accepted 0.1.5 for eleven days and installed 0.1.3 throughout.

## Deltas

**Both pins move, and not redundantly — two different jobs read them.**

| job | how it resolves the guard | pin |
|---|---|---|
| `skills-materialized` | `npx --no-install …-materialize --check` — the **caller's** `node_modules` | the **lockfile** |
| `source-comment-archaeology`, `substrate-size`, `pr-body` | `npm install --prefix "$RUNNER_TEMP" neo-agent-skills@${SKILLS_VERSION}` | the **`uses:` SHA** |

Moving only the SHA would have left `skills-materialized` checking against the 0.1.3 materializer, and moving only the lockfile is what left `neomjs/neo` red this morning. One release, or the repository stays split against itself.

- `.github/workflows/shared-pr-baseline.yml` — `uses:` → `@27e151d9c427e07c674fcccaff1382d2a33d0b24`, and the adoption comment rewritten to name that coordinate. The old note dated itself 2026-09-04 and enumerated the moves that preceded it; a stale rationale beside a moved pin is how the next reader mis-dates the contract. Same four lines, no growth.
- `package.json` — the floor to `^0.1.5`. One line; the file's own 4-space formatting is untouched (`npm install` was run `--package-lock-only` first, and the hash verified after the full install).
- `package-lock.json` — `neo-agent-skills` → 0.1.5. The diff is that entry and nothing else; it also records the two binaries 0.1.5 adds.

The pin stays an exact commit. A pull request must not be able to weaken the gate it is judged by, and the price of that mechanism is exactly this reviewed line.

## Test Evidence

```

ticket-archaeology       0   0 file(s), 0 violations (changed vs origin/dev)
substrate-size           0   no substrate entry points — N/A
```

**Two of those three greens are honest only with their caveat, so here it is.**

The archaeology green is **vacuous**: this diff contains no auditable source file, so the guard measured zero files. The positive control is a base whose diff does carry `.mjs` — `--base origin/dev~8`, 38 changed `.mjs`, guard reports `33 file(s), 0 violations`, exit 0. That is the run which shows the instrument works in this repository at all.

The substrate-size N/A is likewise not a measurement of this change: the guard's own header names three of the five consumers as carrying no entry points, and this is one — no `AGENTS.md`, no `.agents/ANTIGRAVITY_RULES.md`, no `.claude/CLAUDE.md`. A wrong working directory produces the same all-N/A output, which is why the reusable workflow pins `working-directory` to `github.workspace`; this run was made from the checkout root.
