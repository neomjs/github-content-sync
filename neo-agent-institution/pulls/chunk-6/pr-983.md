Resolves #982

The Fleet installer counted a retained Antigravity wake sidecar as an off-canonical Fleet Manager because its executable lives inside a nested Electron Helper app. The installer now verifies the retained generation under the selected Fleet profile, then rereads the process list and rechecks that exact executable’s filesystem identity for planning, quit waiting and pre-mutation checks. A helper inside a package slot, a changed file, or an unverified path still counts. Verification is shared for helpers from the same generation within one invocation.

Evidence: L3 (real installer dry run against the running sidecars and disposable package-slot and runtime-generation tests) → L3 required. The actual installed update is owned by #732 and #12.

## AC Evidence

| Criterion | Receipt |
|---|---|
| AC-1 | A sealed-generation fixture includes the nested helper at its real macOS relative path twice. Both rows are excluded. |
| AC-2 | The same fixture retains the source bundle helper, a renamed app helper, a foreign path, an unverified generation, a symlink and a protected slot overlapping the selected runtime. Changing the helper’s mode invalidates its proof. |
| AC-3 | The CLI passes the same live reader into planning and execution. The executor also prepares it for programmatic calls. The suites cover a new app user appearing after Quit, including custody and reopen handling. |
| AC-4 | On this host the existing release refused two retained helpers in a read-only dry run. The fixed command generated the normal 13-step update plan with those sidecars still live. It did not execute the plan. |

## Deltas from ticket

No scope change. The repair is in the installer run from the checkout. The verified desktop bundle can be used as the existing artifact.
