Resolves #1031

The retirement pass verifies payloads before it takes the package and reference leases, so a verify that never settles now halts at the pass deadline holding neither. Seat Starts and installs no longer wait on it. Once the pass holds both leases, every read it waits on halts as `lease-deadline` at 10 s, below a Start's 20 s wait. That covers the census and the wake-artifact cleanup's scan, references and verify. A halt starts no further work. A removal already running finishes under both leases, and the halt then leaves with the removal's phase whether the removal succeeds or fails, for the last removal too. Without a halt, a failed removal keeps its filesystem error. Under both leases the pass decides again on fresh evidence and a census, and removes only a tree whose inode is the one captured before its verify. Consecutive deadline halts double the wait before the next pass, from the 60 s cadence up to 30 min; any other result resets it.

Evidence: L2 (unit specs on the real Brain lease, verifier and journal over sealed generations built by the production publisher; only the never-settling reads and the swapping verify are fakes) → L4 required (AC5: an installed FM build, operator-gated install). Residual: AC5, Residual-Owner: #633.

- From Euclid's Round 2: a removal is joined, never raced, through `joined(step, id, promise)` beside `bounded`. - The lease-free phase skips generations that unguarded evidence already retains, so a positively retained generation is still never verified. If that phase skips a generation that the leased phase then finds eligible, the leased phase retains it as `runtime-verify-deferred`; a later pass verifies it, and it is never removed unverified.
