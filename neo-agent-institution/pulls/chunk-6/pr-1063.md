<summary>Release notes</summary>
<p><em>Sourced from <a href="[QUARANTINED_URL: github.com]">plist's releases</a>.</em></p>
<blockquote>
<h2>plist@5.1.2</h2>
<h3>Patch Changes</h3>
<ul>
<li>8f9e91a: Fix uncontrolled resource consumption in the binary plist parser (incomplete fix for the 5.0.1 change). Objects are now cached by byte offset rather than object index, so offset table entries that alias one offset are parsed once, and objects must lie within the object area without overlapping one another's payload bytes. Previously a ~0.7 MB input could allocate gigabytes and crash the process.</li>
</ul>
<h2>plist@5.1.1</h2>
<h3>Patch Changes</h3>
<ul>
<li>1e9776b: Reject <code>__proto__</code> and non-string dictionary keys in the OpenStep and binary parsers, extending the CVE-2022-22912 guard that previously only covered XML input</li>
</ul>
<h2>plist@5.1.0</h2>
<h3>Minor Changes</h3>
<ul>
<li>821e16c: Add <code>headless</code> option to <code>build()</code> to omit XML declaration and DOCTYPE</li>
<li>e7c4025: Add <code>invalidCharReplacement</code> option to <code>build()</code> to replace characters that are not valid in XML. The browser <code>build()</code> now also throws on invalid XML characters by default, matching the Node <code>build()</code>.</li>
</ul>
<h3>Patch Changes</h3>
<ul>
<li>1b1212d: Preserve U+0085, U+2028 and U+2029 in strings and keys when parsing XML plists in Node, using XML 1.0 line-ending normalization to match the browser build</li>
</ul>
<h2>plist@5.0.1</h2>
<h3>Patch Changes</h3>
<ul>
<li>
<p>7780aec: Emit empty strings as <code>&lt;string/&gt;</code> in the browser <code>build()</code> to match the Node <code>build()</code> output</p>
</li>
<li>
<p>5d5a064: Escape carriage returns in the browser <code>build()</code> so strings and keys containing CR survive a round-trip</p>
</li>
<li>
<p>ac871e6: Fix uncontrolled resource consumption in binary plist parser. Objects referenced multiple times are now parsed only once, circular references are rejected, and trailer/offset table/object references are validated against the input bounds.</p>
</li>
<li>
<p>fcf0a9f: Preserve sub-second precision when serializing <code>Date</code> values in XML <code>build()</code></p>
<p>Both XML builders stripped any fractional-second group from a <code>Date</code>, so
non-zero milliseconds were silently dropped. The binary format keeps them, so
<code>build(parseBinary(bplist))</code> and <code>parse(build(date))</code> lost up to 999 ms.
Whole-second dates are still emitted without a <code>.000</code> fraction, unchanged.</p>
</li>
<li>
<p>2a85a82: Fix double indentation in browser <code>build()</code> output</p>
</li>
<li>
<p>e76f1ec: Add <code>default</code> condition to <code>exports</code> map for VSCode compatibility</p>
</li>
<li>
<p>ce9b503: Emit large integer-valued numbers (<code>|x| &gt;= 1e21</code>) as <code>&lt;real&gt;</code> instead of <code>&lt;integer&gt;</code>. <code>Number.prototype.toString()</code> renders them in exponential notation (<code>(1e21).toString() === &quot;1e+21&quot;</code>), which the <code>&lt;integer&gt;</code> parse path truncated at the <code>e</code>, silently corrupting the value on a <code>build</code> → <code>parse</code> round-trip.</p>
</li>
</ul>
<h2>plist@5.0.0</h2>
<h3>Major Changes</h3>
<ul>
<li>982349e: BREAKING: <code>null</code> values are now skipped during <code>build()</code>, matching <code>undefined</code> behavior and aligning with Apple's plist DTD which does not include a <code>&lt;null/&gt;</code> element. Parsing <code>&lt;null/&gt;</code> on read is still supported for backwards compatibility.</li>
</ul>
<h3>Minor Changes</h3>
<ul>
<li>592f243: Added binary plist (bplist00) support: <code>parseBinary()</code> and <code>buildBinary()</code> for reading and writing binary plists. <code>parse()</code> now auto-detects binary format.</li>
<li>8f0e2cc: Add browser-native implementations using <code>DOMParser</code> and <code>XMLSerializer</code> for parsing, and native DOM APIs for building XML. Bundlers that support the <code>&quot;browser&quot;</code> export condition (Vite, webpack, esbuild) will automatically use these lighter implementations, dramatically reducing bundle size by eliminating the <code>@xmldom/xmldom</code> and <code>xmlbuilder</code> dependencies.</li>
<li>754240c: Added OpenStep/ASCII plist parsing support via <code>parseOpenStep()</code>. <code>parse()</code> now auto-detects all three plist formats: XML, binary, and OpenStep.</li>
<li>3463937: Rewritten in TypeScript with full type declarations. Switched to vitest for testing and pnpm for package management.</li>
</ul>
