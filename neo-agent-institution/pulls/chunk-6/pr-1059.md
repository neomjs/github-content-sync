Resolves #922

Moves packaged runtime-generation verification and Fleet contract loading (`resolveLauncherRuntime` + `loadFleetRuntimeContracts`) off top-level module evaluation so the Electron cockpit window opens immediately with `fleet starting` on the spine, while `createBootTimer` logs every pre-window and post-window boot milestone (`HARNESS_BOOT_TIMING`) into `main.log`.

Evidence: L3 (packaged Neo Harness.app cold + warm launches on this machine under isolated custody) → L4 required (AC-1, AC-2 on /Applications installed candidate). Residual: AC-1, AC-2, Residual-Owner: #424.

Decision Record impact: aligned-with ADR 0034 §2.1, §2.3.

Change class: capability (`feat`) — `agent-preflight`: not hosted here; baseline `Shared PR Baseline` + `Institution CI` run on PR.

## Deltas from ticket

- `armStartingTransport` anchors the 15 s slow-boot clock at process start (`bootEpochMs`) rather than Fleet child spawn, and `logFleetStarting` words `HARNESS_BRAIN_FLEET_STARTING` by its actual phase (`runtime verification is still running`, `still waiting before the Fleet child starts`, or `still waiting while the Fleet child lives`) so `main.log` never claims a Fleet child before one spawns (`#739`).
- `resolveLauncherRuntime` forwards `fleetReadyAbort.signal` into `acquireHostRuntimeGeneration`, `bootProductBrain`, `bootUiFleetTransport`, and `bootSmokeBrain` each settle immediately as `up: false` when `fleetReadyAbort.signal.aborted` after `await ensureLauncherRuntime()` (before any seat-root move or child spawn), and `teardownBrain` awaits `runtimeBootstrapPromise` before calling `release()` (`#732`).
- Because the window opens before `resolveLauncherRuntime` settles, a refused packaged runtime no longer calls `app.exit(1)` before window creation: the cockpit window stays open with no child spawned, `brain-health` settles degraded (`transport: {phase: 'settled', up: false}`), `fleet-request` and `shell-plane-probe` reject with `fleet: runtime verification failed (...)`, and all six `shell-setup-*` channels return `{ok: false, reason: 'runtime-refused: runtime verification failed (...)'}` instead of falling back to `no-brain-root`.
- `seatRootBroker.status` continues answering immediately from `userData` without awaiting runtime verification; `setupBroker`, `seatRootBroker` (`plan`/`consent`), `seatRenameBroker`, and `fleetCapability` register all IPC channels before `createHarnessWindow` and resolve runtime modules lazily after sender validation.
